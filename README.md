## 各套文档的关系

- **`go/`** 解决「语言与运行时」：goroutine/GMP、内存、GC、并发、net/http、工程化。
- **`llm/`** 解决「平台与架构」：编排只占 15%，剩下 85% 是队列、限流、缓存、降级、计费、沙盒、记忆、可观测、数据回流、灰度。
- **`eng/`** 解决「功能怎么写不出错」：幂等、事务、限流熔断、消息、编排、存储、运维运营。
- **`algo/`** 解决「问题怎么被想出来」：五步解题法 + 150 个思维模型，是读源码前该有的肌肉记忆。
- **`architect/`** 解决「系统怎么被设计出来」：约束卡→领域→存储/读/写形态→换挡信号，再用 14 个真实系统证明这套方法能装配出东西。
- **`comp/`** 解决「零件内部为什么是这样」：把 ES/MySQL/Redis/Kafka 这些零件拆开，看数据物理形态 → 读写链路 → 架构边界，于是「它为什么快、为什么做不到、什么时候必须换」都变成推论。
- **`llm_base/`** 解决「一个普通人怎么判断和验收 AI」：把回答拆到「续写、工作台、抽样、权重、提议-执行」五个原语上，再讲清材料、权限、账单与评测；不写代码，四个案例交付到能直接用的程度。
- 交叉引用方式：`llm/` 章节里遇到语言细节，直接引 `../go/NN-xxx.md`，不重复讲。
