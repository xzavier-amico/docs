## 050.1 题目

**原题链接**：<https://leetcode.cn/problems/linked-list-cycle-ii/>

### 题意重述（把隐含条件补齐）

给你一个链表的头结点 `head`，如果链表中有环，请返回**环的入口结点**；如果无环，返回 `null`。题目用 `pos` 表示「尾结点连到了第 `pos` 个结点（0 索引）」，`pos = -1` 表示无环 —— 但**判题时不会把 `pos` 传给你的函数**，它只在你本地造数据时有用。

五个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **返回结点，不是下标** | 「返回……入口节点」 | 返回 `pos` 这个整数是错的；判题按结点身份比对 |
| **无环返回 `null`** | 「如果链表无环，返回 null」 | 忘了这条，无环时死循环 |
| **不允许修改链表** | 题目 note | 「走过的结点打个标记」这种解法会被判「修改了输入」 |
| **环可能从头部就开始** | `pos` 可以是 0 | 此时「头到入口的距离 a = 0」，第二阶段的循环一次都不执行 |
| **`0 <= 结点数 <= 10⁴`** | 数据范围 | 规模小；但要求空间 O(1)，所以哈希集合法只是「能过但不优」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= 结点数 <= 10⁴` | 很小 | 哈希集合（O(n) 空间）也能过；**考点是 O(1) 空间** |
| `-10⁵ <= Node.val <= 10⁵` | 值可重复 | **绝对不能靠值判断「是否来过」** —— 相同值可能在环外 |
| `pos` 不传参 | 关键 | 你必须真的用指针走，不能读 `pos` |
| 空间 O(1) | 进阶要求 | Floyd 判圈（龟兔赛跑）是唯一方案 |

> 💡 **量级 → 算法**：`10⁴` 说明「哈希集合能过」。**所以这题的分水岭不是能不能过，而是能不能做到 O(1) 空间**。这也是它被归为「中等」而非「简单」的原因：简单版（141）只问「有没有环」，快慢指针相遇即可；142 多问一句「入口在哪」，就需要**数学推导**。

### 示例

```text
输入：head = [3,2,0,-4], pos = 1        （尾结点 -4 连回下标 1 的结点 2）
输出：返回下标 1 的那个结点

输入：head = [1,2], pos = 0             （尾结点 2 连回头结点 1）
输出：返回下标 0 的结点（即 head 本身）

输入：head = [1], pos = -1
输出：null
```

### 我自造的七个反例（写完必须逐个跑）

```text
① []                      → 空链表，必须返回 null
② [1], 无环                → 单结点无环：fast.next 是 null
③ [1], 自环（pos=0）       → 单结点自环：入口就是自己
④ [1,2,3,4], pos=0        → 整条成环，入口是 head（a = 0，第二阶段零步）
⑤ [1,2,3,4], pos=3        → 只有尾结点自环（环长 b = 1）
⑥ [1,2,3,4,5], pos=1      → 一般情形，a = 1、b = 4
⑦ [7,7,7,7] 成环          → 全相等值：验证没有任何「靠值判断」的逻辑
```

第 ④ 和 ⑤ 是两个极端：`a = 0`（入口就在头，第二阶段 `p == slow` 立刻成立）与 `b = 1`（自环，快慢指针第一次就会在入口相遇）。**这两个极端必须实测**，因为它们让公式里的 `k` 与 `x` 退化成特殊值。

## 050.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（哈希集合记录走过的结点）

```text
seen = {}                       // 集合，存结点指针
p = head
while p != null:
    if p in seen: return p      // 第二次到达 → 这就是入口
    seen.add(p)
    p = p.next
return null
```

- 时间 O(n)，空间 **O(n)**。
- **它完全正确**，而且思路最直白：**第一个被重复访问的结点就是环入口**。
- 为什么不够？

1. **空间 O(n)**。`n = 10⁴` 时大约 80 KB，能过；但面试追问「能不能 O(1) 空间」时立刻失效。
2. **它没有用上题目最关键的结构信息**：环的形状。哈希法把链表当成「任意图」来处理，而链表有特殊结构（一条链 + 一个环），Floyd 判圈正是利用了这个结构。

> **一个容易被忽视的点**：哈希法在这里**不能**用「值」当 key（值会重复），必须用**结点指针/引用**当 key。Java 里 `HashSet<ListNode>` 依赖默认的 `Object.hashCode()`（即地址哈希），Go 里 `map[*ListNode]bool` 同理 —— 一旦你自己重写了 `equals`/`hashCode`（比如按 `val` 比），这题就错了。

### 第二步：卡点在哪

把问题翻译成一句话：

> **我需要判断「当前结点以前是否来过」，但我不允许额外空间。**

这是典型的「**用结构换空间**」场景：既然不能记录，就必须让**指针自己携带信息**。而两个速度不同的指针，恰好能在「有限步内必然相遇」这个性质上提供信息。

但这里有个认知门槛：**相遇点不是入口**。

```
      head
       ↓
  ①→②→③→④→⑤→⑥
        ↑        ↓
        └────────┘
        入口在 ③，但快慢指针第一次相遇可能在 ⑤ 或 ⑥
```

所以卡点其实是两个：

| 卡点 | 内容 | 突破 |
| --- | --- | --- |
| 卡点 1 | 怎么在 O(1) 空间里判断「有环」 | 快慢指针（速度 1 和 2），有环必相遇，无环则快指针先到 `null` |
| 卡点 2 | 相遇点 ≠ 入口，怎么从相遇点找回入口 | **代数**：设 a、b、x，推出 `a = kb - x` |

**卡点 2 才是本题的「中等」所在**。很多人能写出判圈，但写不出「相遇后怎么办」，于是背下「再从头走一遍」这句话 —— 而面试官一定会问「为什么」。

### 第三步：灵感的来源 —— 环上只有相对速度是重要的

**第一步观察（判圈）**：设 slow 每步走 1、fast 每步走 2。若存在环，slow 进环后，两者都在环上转，**相对速度 = 1 步/轮**，所以 fast 一定会「追上」slow（就像跑道上的套圈）。若不存在环，fast 会先撞到 `null`。

**第二步观察（找入口）**：把「相遇」这个事件写成等式。设：

- `a` = 头到环入口的距离（边数）
- `b` = 环长（边数）
- `x` = 从入口沿行进方向到**相遇点**的距离（边数，`0 ≤ x < b`）

那么：

- slow 走的总步数 = `a + x`
- fast 走的总步数 = `a + x + k·b`（`k ≥ 1`，多绕了 k 圈）
- 因为 fast 速度是 slow 的两倍：`2(a + x) = a + x + k·b`

化简：

```
a + x = k·b          ⟹          a = k·b − x
```

**这个等式的读法**：从「头」走到「入口」需要 `a` 步；而从「相遇点」沿行进方向走 `a` 步，恰好是「先走 `b − x` 步回到入口，再绕 `k − 1` 整圈回到入口」。

于是：**让一个指针 `p` 从头出发、让 `slow` 从相遇点出发，两者每次各走 1 步，走满 `a` 步后都停在入口 —— 它们必然在入口相遇。**

这就是「从头与相遇点同步走」的全部理由。它不是一个技巧，而是 `a = kb − x` 这个等式的直接翻译。

### 另一条路：为什么不用「速度 1 和 3」？

很多人会问：如果 fast 每次走 3 步呢？

- **判圈仍然有效**（相对速度 2，环上仍会追上）。
- 但**找入口的公式变得复杂**：`3(a+x) = a+x+kb ⟹ 2(a+x) = kb`，即 `a = kb/2 − x`。这时 `a` 不再等于「从相遇点走 a 步回到入口」的整齐形式，需要讨论 `b` 的奇偶性。
- **速度 1 和 2 是最优选择**，因为相对速度恰好是 1，使得 `a + x = kb` 这个等式「一步到位」。

> **可迁移的结论**：**快慢指针选 1 和 2，不是随便选的，是为了让等式最简。** 这个理由能说出来，比背结论强得多。

## 050.3 原理拆解

### 050.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 哈希集合（存结点指针） | O(n) | **O(n)** | 8 行 | 空间要求 O(1)；不能修改输入但可以额外存 |
| 走过的结点打标记（改 `val`） | O(n) | O(1) | 6 行 | **题目禁止修改链表**；且 `val` 范围有限，可能撞值 |
| **Floyd 判圈（速度 1 / 2）** ✅ | **O(n)** | **O(1)** | **14 行** | 几乎不会输；需要能推出 `a = kb − x` |
| 先求环长再定位 | O(n) | O(1) | 20 行 | 是 Floyd 的「手动版」，多一次遍历，等价但更长 |
| 快慢指针速度 1 / 3 | O(n) | O(1) | 14 行 | 公式变成 `2(a+x) = kb`，要讨论奇偶，易错 |

**为什么 Floyd 是最优**：唯一同时做到 O(n) 时间 + O(1) 空间 + 不修改输入的方案。

### 050.3.2 为什么这个做法是对的（完整代数推导）

这一节是本章的核心，**每一步都要能自己重写一遍**。

#### 第 0 步：符号定义

```
        head
         │  ← a 条边
         ▼
      ┌─────┐
      │ 入口 │ ←──────────────┐
      └─────┘                │
         │  ← x 条边（沿行进方向）│ b 条边
         ▼                   │
      ┌─────┐                │
      │相遇点│ ───────────────┘
      └─────┘
```

- `a`：head 到入口的边数（`a ≥ 0`）
- `b`：环上的边数，即环长（`b ≥ 1`）
- `x`：入口沿行进方向到相遇点的边数（`0 ≤ x < b`）
- `k`：fast 在环上比 slow 多绕的整圈数（`k ≥ 1`）

#### 第 1 步：第一次相遇时，slow 一定还没绕完一整圈

slow 进入环的那一刻，fast 已经在环上某处。此时 fast 与 slow 的「沿环距离」至多 `b − 1`（若重合则已相遇）。此后每轮 slow 前进 1、fast 前进 2，**相对速度 1**，所以最多再走 `b − 1` 步就会相遇。

因此 slow 在环内走过的边数 `x ≤ b − 1 < b`，即 `0 ≤ x < b`。这一步保证了后面的 `x` 有界，也保证了 `k` 的取值是「fast 绕的圈数」，不会混入 slow 自己的圈数。

#### 第 2 步：写等式

到相遇时刻：

- slow 走过的边数：`a + x`（环外 a 条 + 环内 x 条，且没绕圈）
- fast 走过的边数：`a + x + k·b`（同样走过 a + x，另外多绕了 k 整圈）
- 速度关系：`fast = 2 × slow`

所以：

```
2(a + x) = a + x + k·b
```

两边减去 `a + x`：

```
a + x = k·b                 …… (★)
```

因为 `a + x > 0`（只要链表非空），所以 `k ≥ 1`。

#### 第 3 步：把 (★) 变形为「从相遇点走 a 步会到入口」

由 (★)：`a = k·b − x`。

把它写成「从相遇点出发」的形式：

```
a = (k − 1)·b + (b − x)                    …… (★★)
```

读法：**从相遇点沿行进方向走 `a` 步 = 先走 `b − x` 步（回到入口）+ 再走 `(k−1)` 整圈（仍在入口）。**

#### 第 4 步：两个指针同时出发

- 指针 `p` 从 `head` 出发，每步走 1：走 `a` 步后到达**入口**。
- 指针 `slow` 从**相遇点**出发，每步走 1：由 (★★)，走 `a` 步后也到达**入口**。

两者步长相同、同时出发、都走 `a` 步，所以**第 `a` 步结束时必然在同一结点**。而在此之前它们不会相遇 —— 因为环外只有一条链，`p` 在环外时不可能与环内的 `slow` 重合（除非 `a = 0`，那时两者都在入口，直接返回）。

**因此「同步走直到 `p == slow`」得到的结点就是环入口。** ∎

#### 第 5 步：一个具体数字验证

取结点 `A → B → C → D → E → F → G`，并让 `G` 连回 `D`。于是 `head = A`、`入口 = D`、环为 `D→E→F→G→D`：

- `a = 3`（A→B、B→C、C→D 三条边）
- `b = 4`（环上四条边）
- slow 每步 1、fast 每步 2

| 步数 t | slow 所在 | fast 所在 | 说明 |
| --- | --- | --- | --- |
| 0 | A | A | 同起点 |
| 1 | B | C | |
| 2 | C | E | fast 已进环 |
| 3 | D（入环） | G | |
| 4 | E | E | **第 4 步相遇**（fast 共走 8 条边 = 2×4） |

第一次相遇在 t = 4，相遇点 `E`，故 `x = 1`（D→E 一条边）。代入 (★)：`a + x = 3 + 1 = 4 = k·b = 1 × 4` ✅，`k = 1`。

由 (★★)：`a = (1−1)·4 + (4−1) = 3`，即「从 E 走 3 条边」= E→F→G→D → **入口 D** ✅。而 `p` 从头走 3 条边：A→B→C→D → **入口 D** ✅。两者同时到达。

#### 第 6 步：三个退化情形

| 情形 | 参数 | 公式表现 | 代码表现 |
| --- | --- | --- | --- |
| 入口就在 head | `a = 0` | (★) 变成 `x = kb`，而 `0 ≤ x < b` 迫使 `x = 0`（或 `x = b` 即回到入口） | 第二阶段 `p == slow` 一开始就成立，直接返回 |
| 自环（`b = 1`） | `b = 1` | `a + x = k`，`x = 0`（自环上入口 = 相遇点） | 第一阶段第一轮就可能相遇 |
| 无环 | — | (★) 不成立 | fast 先到 `null`，循环退出，返回 `null` |

> **这一节要带走的东西**：`a + x = k·b` 这一个等式，同时给出了「相遇点在哪」和「入口怎么找」。**凡是看到「环 + 双指针」，第一反应应该是写这个等式**；它也是 287（寻找重复数）的正确性依据 —— 那题把「下标 → 值」当作 `next` 指针，构造出一条隐式的环形链表。

### 050.3.3 通用解题思路（可迁移的那一层）

**链表章的统一语言：哑结点 + 指针三件套（prev/cur/next）+ 先存后断。** 050 是「快慢指针三种关系」里的第二种：

| 关系 | 速度配置 | 用来解决 | 本章位置 |
| --- | --- | --- | --- |
| **定距** | 相同速度、固定间距 | 反向定位（倒数第 n 个） | 049 |
| **判圈** | 速度 1 : 2 | 是否有环 + 环入口 | 050 |
| **找中点** | 速度 1 : 2 | 链表中点 | 051 |

注意「判圈」和「找中点」用的是同一个速度配置，但**读法完全不同**：
- 判圈关注的是「**相遇**」这个事件（fast 追上 slow）。
- 找中点关注的是「**fast 到终点时 slow 在哪**」（不要求相遇）。

这是两个不同的观察角度。**同一个机械装置，两种用法** —— 这类「一具多用的工具」在算法里非常常见，值得单独记住。

而「环入口」的推导还有一层可迁移的方法论：

```
问题：无额外空间，怎么记住"来过"？
      ↓ 换一种"记"
用结构自身的信息（这里：两个指针的步数关系）作为"存储"
      ↓ 落地
写等式 → 化简 → 让等式直接对应一个操作
```

这套「**把判定问题化成等式，再让等式指导操作**」的思路，是很多 O(1) 空间技巧的共同来源（比如 287 的循环检测、141 的判圈、甚至链表找中点）。

属于同一模型的题：

| 题 | 用什么当 `next` | 结论 |
| --- | --- | --- |
| [LC 141 环形链表](https://leetcode.cn/problems/linked-list-cycle/) | 真实的 `next` | 只要「有没有环」，第一阶段足够 |
| [LC 142](https://leetcode.cn/problems/linked-list-cycle-ii/) | 真实的 `next` | 环入口，需要第二阶段 |
| [LC 287 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/) | `i → nums[i]` | 重复值 = 环入口，同构！ |
| [LC 457 环形数组是否存在循环](https://leetcode.cn/problems/circular-array-loop/) | `i → i + nums[i]` | 判圈 + 方向一致性 |
| [LC 876 链表的中间结点](https://leetcode.cn/problems/middle-of-the-linked-list/) | 真实的 `next` | 速度比 2:1 的另一种读法 |

### 050.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只问**有没有环**（141） | 不需要第二阶段 | 相遇即返回 `true`，代码少一半 |
| 求**环长** `b` | 需要额外一步 | 相遇后让一个指针绕一圈回到相遇点，数步数即 `b` |
| 求**环入口 + 环长 + 环外长度** | 三件事 | 入口给出 `a`（第二阶段步数），环长用上一条，总长 = `a + b` |
| 链表**可能被并发修改** | 快慢指针的前提失效 | 需要加锁或快照，Floyd 不适用 |
| **双向链表**有环 | 有 `prev` | 仍可用 Floyd；也可用哈希集合（因为可以双向走，但不改变复杂度） |
| 要求**不改变指针且不用额外空间** | 已满足 | Floyd 全程只读，是唯一满足的方案 |

## 050.4 图解推演

### 050.4.1 两个阶段的全景图

```text
结点：  A ──→ B ──→ C ──→ D ──→ E ──→ F ──→ G
                          ↑                    │
                          └────────────────────┘
   head = A，入口 = D，b = 4，a = 3（A→B→C→D 三条边）

阶段 1：判圈（slow 每步 1，fast 每步 2）
   t=0:  slow=A   fast=A
   t=1:  slow=B   fast=C
   t=2:  slow=C   fast=E
   t=3:  slow=D   fast=G      ← slow 刚进环，fast 绕了 1 圈多
   t=4:  slow=E   fast=E      ← 💥 相遇（fast 共走 8 条边 = 2 × 4）
   相遇点 = E，x = 1（D→E 一条边）

阶段 2：找入口（两者各走 1 步，各走 a = 3 条边）
   p    : A ──→ B ──→ C ──→ D
   slow : E ──→ F ──→ G ──→ D
                              ↑
                     第 3 步同时到达 D ✅
```

### 050.4.2 为什么「从相遇点走 a 步」会回到入口（ASCII 拆解）

```text
环（b = 4）：从入口 D 沿行进方向走 4 条边回到 D
   D ──1──→ E ──2──→ F ──3──→ G ──4──→ D
             ↑
          相遇点（离入口 x = 1 条边）

从相遇点 E 走 a = 3 条边：
   E ──→ F ──→ G ──→ D        ✅ 落在入口

把这 3 条边拆成 (b − x) + (k−1)·b：
   b − x  = 4 − 1 = 3   → 走 3 条边绕回 D
   (k−1)b = 0           → k = 1，不用额外绕圈

┌─────────────── 换成 k = 2 的情形 ─────────────────┐
│ 若 a = 7、b = 4、x = 1：                          │
│   a + x = 8 = 2·b  →  k = 2                       │
│   从 E 走 7 条边 = 先 3 条回 D，再 4 条整圈，仍在 D │
│   从 A 走 7 条边 = 也落在 D                        │
└──────────────────────────────────────────────────┘
```

> **一个必须养成的习惯**：`a`、`b`、`x` 一律按**边数**计数（数箭头，不数结点）。按结点数会因为「包含或不包含端点」差 1，而公式对差 1 极其敏感。上面这些图里每个数字都标了「几条边」，就是为了防止这个坑。

### 050.4.3 用位置编号再验一遍（纯算术，不含歧义）

设结点编号即位置，`head = 结点 0`，`入口 = 结点 3`，环为 `3→4→5→6→3`（`b = 4`）。那么 `a = 3`（0→1→2→3 是 3 条边）。

| t | slow 位置 | fast 位置 |
| --- | --- | --- |
| 0 | 0 | 0 |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 3 | 6 |
| 4 | 4 | 4 | ← 相遇，x = 4 − 3 = 1 |

验证 (★)：`a + x = 3 + 1 = 4 = 1 × b` ✅
验证 (★★)：从 4 走 `a = 3` 步 → 5 → 6 → 3 = 入口 ✅；`p` 从 0 走 3 步 → 1→2→3 = 入口 ✅

| 步 | `p` 位置 | `slow` 位置 | 是否相遇 |
| --- | --- | --- | --- |
| 0 | 0 | 4 | 否 |
| 1 | 1 | 5 | 否 |
| 2 | 2 | 6 | 否 |
| 3 | 3 | 3 | **是 → 返回结点 3** ✅ |

### 050.4.4 判圈失败的情形（无环）

```text
  ① ──→ ② ──→ ③ ──→ ∅

  t=0: slow=①  fast=①
  t=1: slow=②  fast=③
  t=2: slow=③  fast=∅      ← fast.next 为 null → 退出循环，返回 null

  注意循环条件必须是 fast != null && fast.next != null
  少判 fast.next：fast 在 ③ 时 fast.next.next 会 NPE
```

## 050.5 双语言实现

### 050.5.1 Java

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}

class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;
        // 必须同时判 fast 和 fast.next：fast.next.next 需要两级安全
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) { // 第一阶段：相遇
                ListNode p = head;
                while (p != slow) { // 第二阶段：头与相遇点同步走
                    p = p.next;
                    slow = slow.next;
                }
                return p; // 相遇处即环入口（依据 a = k·b − x）
            }
        }
        return null; // fast 走到尽头 → 无环
    }
}
```

**四处「为什么」**：

1. `while (fast != null && fast.next != null)`：`fast = fast.next.next` 一次跳两级，所以 `fast` 和 `fast.next` 都必须非空。**两个条件缺一不可。**
2. `slow == fast` 判的是**引用相等**（Java 的 `==` 对对象就是地址比较），正是我们要的「同一结点」。**绝不能用 `.equals()` 或比较 `val`。**
3. 第二阶段 `while (p != slow)`：`p` 走 `a` 步、`slow` 也走 `a` 步，两者在入口重合。循环体顺序无所谓（同时前进），但**不能先判后走**。
4. `return null` 放在循环外：无环时靠 `fast` 撞 `null` 退出，此时 `p`/`slow` 都没被初始化过，只能返回 `null`。

### 050.5.2 Go

```go
package main

type ListNode struct {
	Val  int
	Next *ListNode
}

// Floyd 判圈：先快慢指针相遇，再从头与相遇点同步走
func detectCycle(head *ListNode) *ListNode {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast { // 第一次相遇
			p := head
			for p != slow { // 头与相遇点同步走，相遇处即环入口
				p = p.Next
				slow = slow.Next
			}
			return p
		}
	}
	return nil
}
```

### 050.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 指针比较 | `slow == fast`（对象引用比较） | `slow == fast`（指针比较） | **两边都是地址比较，语义正确**；Java 若改成 `.equals()` 就错了 |
| 空值 | `null` | `nil` | 判空写法不同 |
| 循环写法 | `while (...)` | `for ... { }` | Go 的 `for` 兼作 while |
| 多变量初始化 | 两行 | `slow, fast := head, head` | Go 更紧凑 |
| 返回值 | `null` | `nil` | 一致 |
| 指针自增 | `fast.next.next` | `fast.Next.Next` | 注意字段大写 |

### 050.5.4 对拍测试（Go，2 万次随机 + 五个边界）

```go
package main

import (
	"math/rand"
	"testing"
)

// buildCycle 建一条带环链表：pos = -1 表示无环，否则尾结点连到第 pos 个结点
func buildCycle(a []int, pos int) (*ListNode, *ListNode) {
	if len(a) == 0 {
		return nil, nil
	}
	head := build(a)
	var entry *ListNode
	p := head
	for i := 0; p != nil; i, p = i+1, p.Next {
		if i == pos {
			entry = p
		}
		if p.Next == nil && pos >= 0 {
			p.Next = entry // 收尾成环
			break
		}
	}
	return head, entry
}

func build(a []int) *ListNode {
	dummy := &ListNode{}
	t := dummy
	for _, v := range a {
		t.Next = &ListNode{Val: v}
		t = t.Next
	}
	return dummy.Next
}

func TestDetectCycleRandom(t *testing.T) {
	r := rand.New(rand.NewSource(50))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(10)
		a := make([]int, n)
		for i := range a {
			a[i] = i // 值不重要，但保证可区分
		}
		pos := r.Intn(n + 1) // n 表示「无环」
		if pos == n {
			pos = -1
		}
		head, entry := buildCycle(a, pos)

		got := detectCycle(head)
		if pos < 0 {
			if got != nil {
				t.Fatalf("iter=%d 无环却返回了结点", iter)
			}
		} else if got != entry { // 必须比指针身份，不能比值
			t.Fatalf("iter=%d n=%d pos=%d 返回的不是环入口", iter, n, pos)
		}
	}
	// 五个边界
	if detectCycle(nil) != nil {
		t.Fatal("空链表必须返回 nil")
	}
	if detectCycle(build([]int{1})) != nil {
		t.Fatal("单结点无环")
	}
	h, e := buildCycle([]int{1}, 0)
	if detectCycle(h) != e {
		t.Fatal("单结点自环（b=1）")
	}
	h, e = buildCycle([]int{1, 2, 3, 4}, 0)
	if detectCycle(h) != e {
		t.Fatal("入口就是 head（a=0）")
	}
	h, e = buildCycle([]int{7, 7, 7, 7}, 2)
	if detectCycle(h) != e {
		t.Fatal("全相等值 + 环入口在中段")
	}
}
```

> **对拍的关键是「比指针身份」**：`got != entry` 才是正确判据。如果写成 `got.Val != entry.Val`，那么在「全相等值」的用例上，任何结点都「相等」，测试会假阳性。**链表题的参考实现必须比指针，不能比字段。**

## 050.6 复杂度与常见坑

### 050.6.1 复杂度推导

- **时间 O(n)**：
  - 第一阶段：slow 走过 `a + x` 条边。因为 `x < b` 且 `a + b ≤ n`（环外 + 环内总边数不超过结点数），所以 `a + x < a + b ≤ n+1`，即 O(n) 步。
  - 第二阶段：`p` 与 `slow` 各走 `a` 步，`a ≤ n`。
  - 合计 ≤ `2n + 1` 步。
  - **重要细节**：`fast` 走的步数是 slow 的 2 倍，所以「总边访问次数」约 `3n`，仍是 O(n)。
- **空间 O(1)**：`slow`、`fast`、`p` 三个指针，无任何容器。
- **为什么第一阶段一定在 O(n) 内结束**：若无环，`fast` 每轮前进 2，最多 `n/2` 轮撞到 `null`；若有环，slow 进环后至多 `b` 轮相遇。两者都是 O(n)。
- **对比哈希法**：时间同为 O(n)（哈希表均摊 O(1) 插入与查询），空间 O(n)。**所以本章的收益纯粹是空间。**

### 050.6.2 八个真实踩过的坑

1. **循环条件只写 `fast != null`** —— 无环且结点数为偶数时，`fast.next.next` 会 NPE。必须 `fast != null && fast.next != null`。
2. **用 `val` 比较相遇** —— `slow.val == fast.val` 在全相等值的链表上立刻「相遇」，结果完全错。必须比引用。
3. **第二阶段忘了让 `p` 和 `slow` **同时**前进** —— 只前进一个，要么死循环，要么落到错误结点。
4. **把相遇点当入口直接返回** —— 这是最常见的概念错误。相遇点只有 `a = 0` 时才等于入口。
5. **`a`、`b`、`x` 的计数口径混用（数点 vs 数边）** —— 推导时整体差 1，公式看似「差一点对」，实际推不出来。**统一用边数**。
6. **Java 里用 `Objects.equals(slow, fast)` 或自定义 `equals`** —— 若 `ListNode` 没重写 `equals`，行为等同于 `==`（碰巧对）；一旦重写（比如按 `val` 比）就错。**显式用 `==` 最安全。**
7. **无环时忘了返回 `null`** —— 函数末尾必须 `return null`，否则编译不过（Java）或返回零值（Go 返回 `nil` 恰好对，但依赖零值不清晰）。
8. **以为 slow 可能在环里绕了很多圈** —— 由第 1 步的论证，第一次相遇时 slow 在环内走过 `x < b`，**不超过一圈**。这一点是 `a + x = kb` 成立的前提，不能含糊。

### 050.6.3 面试官最爱追问的三个问题

**Q1：为什么相遇之后，从头和从相遇点同时走就一定在入口相遇？**
> 「设头到入口 a 条边、环长 b、入口到相遇点 x 条边。相遇时 slow 走了 a+x，fast 走了 a+x+kb（k ≥ 1，多绕 k 圈），而 fast 速度是 slow 的 2 倍，所以 2(a+x) = a+x+kb，化简得 a = kb − x = (k−1)b + (b−x)。这个式子说明：从相遇点沿行进方向走 a 步，等于先走 b−x 步回到入口、再绕 k−1 整圈回到入口，落点就是入口。而从头走 a 步也正好到入口。两个指针步长相同、同时出发，所以必然在入口相遇。」
>
> （如果面试官继续问「k 一定是 1 吗」：**不一定**。`k` 取决于 `a` 与 `b` 的相对大小，`a` 很大时可以 `k > 1`。但公式对任意 `k ≥ 1` 都成立，所以实现里不需要知道 `k`。）

**Q2：为什么快指针每次走 2 步，走 3 步行不行？**
> 「走 3 步也能判圈（相对速度 2，环上仍会追上），但找入口的公式会变成 `2(a+x) = kb`，即 `a = kb/2 − x`，需要讨论 b 的奇偶性，而且『从相遇点走 a 步』不再直接对应『走若干整圈回到入口』这种整齐形式。选 1 和 2 是为了让等式最简：相对速度为 1，得到 `a + x = kb`，一步到位。」

**Q3：如果要求同时返回环长和环外长度呢？**
> 「环外长度就是第二阶段的步数 `a`（同步走了多少步）。环长 `b` 可以在第一阶段相遇后让一个指针绕一圈回到相遇点数步数。两者相加就是总长度。也可以先求 `b`：相遇后让 slow 继续走、fast 停在原地，slow 回到相遇点所走的步数就是 `b`。三种信息都在这两个阶段里，不需要额外遍历。」
