## 040.1 题目

**原题链接**：<https://leetcode.cn/problems/find-all-numbers-disappeared-in-an-array/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的整数数组 `nums`，其中每个整数都在 `[1, n]` 内。有些值会出现一次或多次，有些值**一次都不出现**。请找出所有在 `1..n` 中但没出现在 `nums` 里的数，按升序返回。

这句话背后有五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 值域恰好是 `1..n`，长度也是 `n` | 「`1 <= nums[i] <= n`」「`n == nums.length`」 | **值可以当下标用**（`x-1 ∈ [0, n-1]`），这是原地标记的物理基础 |
| 值**可以重复** | 「有些数字出现多次」 | 同一位置可能被标记两次 —— 负号标记必须防「负负得正」 |
| 答案要**全部**、且**升序** | 「找到所有……按升序返回」 | 不能找到一个就返回；升序可以靠「按下标从小到大扫」自然得到，不需要额外排序 |
| 时间 `O(n)`、空间 `O(1)`（不含输出） | 题目「进阶」的硬要求 | `HashSet` 解虽然 `O(n)` 时间，但空间违规 |
| 返回的是**值**（`i+1`）而不是下标 | 「消失的数字」 | 最终扫描时返回 `i` 而不是 `i+1`，整体小 1 |

> 💡 **与 038 的关系**：038 要求 `O(1)` 空间找**第一个**缺失，用「交换归位」；本题要求找**所有**缺失，用「负号标记」更省事 —— 因为负号标记是**幂等**的（标一次和标三次效果一样），而交换归位要真的搬动元素。
> 两题的共同内核只有一个：**把值 `x` 和下标 `x-1` 绑定起来，用数组自己的格子记录「`x` 出现过」。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n == nums.length`，`1 <= n <= 10^5` | n 最多十万 | `O(n)` 时间、`O(1)` 空间（不含输出）是目标；`O(n log n)` 排序能过但不优 |
| `1 <= nums[i] <= n` | 值域与下标完全同阶 | **不需要判越界**，`num - 1` 一定落在 `[0, n-1]`；038 里那句「`1 ≤ x ≤ n`」的检查在这里天然成立 |
| 值可重复 | 例如 `[1,1]` | 同一格会被标记多次，必须保证「标记」是幂等的 |
| 输出长度最多 `n` | 最坏 `[1,1,1,…,1]`，答案是 `2..n` | 输出本身要 `O(n)` 空间，题目允许（「不含返回值」） |

> 💡 **量级 → 算法**：`n = 10^5` + `O(1)` 额外空间 + 值域 `1..n` —— 这三个条件一凑齐，只剩一条路：
> **用数组元素的正负号当 1 bit 的布尔标记**。
> `n` 个值域、`n` 个格子、`n` 个符号位，一一对应，不多不少。

### 示例

```
输入：nums = [4,3,2,7,8,2,3,1]
输出：[5,6]
解释：1..8 中，5 和 6 没有出现。

输入：nums = [1,1]
输出：[2]
解释：1 出现了两次，2 一次都没有。

输入：nums = [1,2,3,4]
输出：[]
解释：1..4 全都在，没有任何数字消失。
```

### 我自造的五个反例（写完必须拿它们打一遍）

```text
① [1,1]            → [2]。首个值就重复，考验"负号标记幂等"
② [2,2]            → [1]。值是 2，标记的是下标 1；下标 0 对应值 1 没被标记 → 答案 1
③ [1,2,3,4]        → []。全部都在时返回空列表，不是 null，也不是 [0]
④ [4,4,4,4]        → [1,2,3]。同一个下标被标记三次，任何"取负两次变正"的写法都会给出错误答案
⑤ [1]              → []。n = 1 的最小规模；若把答案判据写成 nums[i] >= 0，返回值会多出 0
```

第 ④ 条是本题唯一的真正难点：`nums[3]` 会被标记 3 次。**如果写 `nums[idx] = -nums[idx]` 而不检查符号，第三次就把它翻回正数了**，于是答案里会多出一个本不该出现的值。

## 040.2 从暴力到最优：第一个念头为什么错

### 第一步：三个「第一念头」

```java
// 念头 A：HashSet 记下所有值，再从 1 到 n 查
Set<Integer> seen = new HashSet<>();
for (int x : nums) seen.add(x);
List<Integer> res = new ArrayList<>();
for (int v = 1; v <= nums.length; v++) if (!seen.contains(v)) res.add(v);
// 时间 O(n)，空间 O(n) —— 空间违规

// 念头 B：排序后双指针找缺口
Arrays.sort(nums);                       // 时间 O(n log n)，还改了数组
// ……再扫一遍找 1..n 里缺的

// 念头 C：开 boolean[n+1] 标记数组
boolean[] seen = new boolean[n + 1];
for (int x : nums) seen[x] = true;
// 时间 O(n)，空间 O(n) —— 同样违规
```

| 念头 | 时间 | 空间 | 违反了什么 |
| --- | --- | --- | --- |
| A 哈希 | `O(n)` | `O(n)` | 空间超标 |
| B 排序 | `O(n log n)` | `O(1)`（原地） | 时间不优；`Arrays.sort` 对基本类型还有 `O(log n)` 栈 |
| C 布尔数组 | `O(n)` | `O(n)` | 空间超标 |

### 第二步：卡点在哪 —— 「标记」这件事本身要花空间

```
     ┌─────────────────────────────────────────────────────────┐
     │ 问题本质：对每个值 v ∈ [1, n]，回答"v 出现过吗？"        │
     │ 通用做法：开一个 n 位的表，出现过就打勾                  │
     │ 约束：这张表不能额外开（O(1) 空间）                      │
     │                                                        │
     │ 那这 n 个 bit 从哪儿来？→ 从数组元素自身来               │
     └─────────────────────────────────────────────────────────┘
```

### 第三步：灵感的来源 —— 符号位是「免费」的 1 bit

`nums[i]` 是一个整数，它至少占 1 个 bit 的**符号位**，而这个符号位对本题**毫无用处**（题目只关心绝对值代表的那个值）。

于是：

```
    值 x 出现过  ⟹  把 nums[x-1] 变成负数（打勾）
    值 x 没出现  ⟹  nums[x-1] 保持正数（没打勾）
```

```
下标:    0    1    2    3    4    5    6    7
值:      4    3    2    7    8    2    3    1
         │
         └─ 值 4 出现过 → 去把下标 3 打上负号
            nums[3]: 7 → -7
```

一轮之后再扫一遍：**`nums[i] > 0` 就说明「值 `i+1` 从没被打过勾」，也就是它消失了。**

> 这个技巧之所以成立，是因为「值」和「下标」一一对应：`n` 个值恰好需要 `n` 个标记位，而数组恰好有 `n` 个元素、每个元素恰好有 1 个用不上的符号位。
> **这不是巧合，是题目故意设成 `1..n` 的原因。**

### 第四步：为什么不「交换归位」（038 的做法）

038 的交换归位也能做本题：把所有值搬回自己的座位，然后扫一遍找空座。它同样 `O(n)` / `O(1)`，但有两个缺点：

1. **每次交换是 3 次写**，而负号标记每轮只有 1 次读 + 最多 1 次写。
2. **交换会打乱原数组的值**；负号标记只破坏符号，取绝对值就能恢复原值 —— 在很多「改完还要用原值」的场景里更友好。

| 做法 | 每轮动作 | 能否恢复原值 | 适合 |
| --- | --- | --- | --- |
| 交换归位 | 把一个值搬到 `x-1`（可能连锁多次） | 不能（值的位置变了） | 找**一个**缺失（038） |
| 负号标记 | 翻一个符号 | **能**（取绝对值） | 找**所有**缺失（本题）、找重复（442） |

## 040.3 原理拆解

### 040.3.1 数据结构与算法选型

| 方案 | 时间 | 额外空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| `HashSet` / 布尔数组 | `O(n)` | `O(n)` ❌ | 8 行 | 空间违规；数据量再大时内存吃紧 |
| 排序 + 扫描 | `O(n log n)` | `O(1)` | 12 行 | 时间不优；且改动了值的顺序 |
| **负号标记** ✅ | **`O(n)`** | **`O(1)`** | **12 行** | 依赖值域 `1..n`；依赖「允许改数组」；元素为 0 或负数时不可用 |
| 交换归位 | `O(n)` | `O(1)` | 14 行 | 元素搬运次数多；顺序被打乱 |
| `+n` 编码（把 `nums[x-1] += n`） | `O(n)` | `O(1)` | 14 行 | 需要防 `int` 溢出；读回要 `% n`；值域与 n 必须严格匹配 |
| 位图（`long[]`，外部） | `O(n)` | `O(n/64)` | 18 行 | 严格来说不是 `O(1)` 空间（虽然很小） |

**为什么负号标记比 `+n` 编码更好？**

`+n` 编码的思路是「把「出现过」记成 `nums[x-1] += n`，之后 `nums[i] > n` 就说明 `i+1` 出现过，`nums[i] % n` 还能还原原值」。它的问题：

- `nums[i]` 最大到 `n`，加一次变 `2n`，加 `k` 次变 `(k+1)n`。`n = 10^5` 时安全（`10^10` 溢出 `int32`！）—— **`n` 超过 `2·10^4` 就有溢出风险**，必须用 `long`。
- 读回时的边界：`nums[i] % n == 0` 对应原值 `n`，容易写错。

负号标记没有这些问题：符号位不会溢出，判据 `> 0` 也不可能写错。

### 040.3.2 为什么这个做法是对的（正确性论证）

记标记过程结束后 `A[i] = nums[i]`。定义两个命题：

```
P(i)：值 i+1 在原始数组中至少出现一次
Q(i)：A[i] < 0
```

**引理 1（`P(i) ⟹ Q(i)`）**：若值 `v = i+1` 在原数组中出现，设它的某次出现在下标 `j`（`nums[j] = v`）。当外层循环走到 `j` 时，读到的 `x = |nums[j]|`。

这里要用一个**循环不变量**：`nums[j]` 的绝对值在整个过程中**从不改变** —— 因为每次写操作都是 `nums[k] = -nums[k]`，只改符号，不改绝对值。所以 `x = |v| = v`，该轮会把 `nums[v-1] = nums[i]` 置为负数，即 `Q(i)` 成立。∎

**引理 2（`Q(i) ⟹ P(i)`）**：`Q(i)` 说明某次循环把 `nums[i]` 置成了负。那一次循环必然读到了 `x = i+1`（因为写入的下标恒为 `x-1`，由不变量 `|nums[j]|` 不变可反推出 `x = i+1` 确实在原数组某处出现过）。故 `P(i)` 成立。∎

**定理**：`A[i] > 0 ⟺ ¬P(i)`，即「`nums[i]` 为正 ⟺ 值 `i+1` 消失」。于是收尾扫描收集所有 `A[i] > 0` 的 `i+1`，恰好是全部消失的数字。∎

**为什么结果天然升序**：收尾扫描按下标 `i` 从小到大走，收集到的 `i+1` 自然递增。∎

**为什么标记是幂等的**：`nums[k] = -nums[k]` 连做两次会回到正数（这就是坑 ④）。所以实现里必须写 `if (nums[k] > 0) nums[k] = -nums[k];`，让「第二次标记」变成空操作。
更稳的写法是 `nums[k] = -Math.abs(nums[k])`，它对任意次数都幂等 —— 但多一次函数调用，实际代码里用 `if` 判断更常见。

> **这个论证的价值**：它把「负号标记」这件听起来像 hack 的事，拆成了「绝对值不变」+「符号位是布尔量」两个可验证的事实。
> 面试里被问「你怎么证明没漏报 / 没误报」时，就用引理 1、2 这两句话答。

### 040.3.3 通用解题思路（可迁移的那一层）

本题是 **「用数据自身的一个 bit 当标记位」** 这个模型的母题。抽象出来：

```
原始问题：对值域 1..n 的每个值回答"出现过吗"
         ↓ 约束：额外空间 O(1)
         ↓ 观察：数组有 n 个元素，每个元素有 1 个用不上的符号位
建模：   下标 i 代表值 i+1；符号位代表"出现过"
         ↓ 一轮标记：读 |nums[i]| → 翻 nums[值-1] 的符号
         ↓ 一轮收集：nums[i] > 0 → i+1 缺失
代价：    数组符号被破坏（可用 abs 恢复），且依赖"值域 = 下标范围"
```

**这套技巧的三个变体**（同一件事的三种「记在哪」）：

| 记在哪 | 手法 | 适用 | 代表题 |
| --- | --- | --- | --- |
| 符号位 | `nums[k] = -nums[k]` | 值域 `1..n`，允许改 | 本题、442、645 |
| 值本身（搬位置） | 交换到 `nums[x-1]` | 值域 `1..n`，允许改 | 038、442 |
| 高位（加偏移） | `nums[k] += n` | 值域 `1..n`，需要保留计数 | 442 的「出现次数」变体 |
| 首行首列（二维版） | 用矩阵第 0 行/列当标记 | 矩阵 | 73 矩阵置零 |

归属同一模型的题：

| 题 | 值域 | 要回答什么 | 手法 |
| --- | --- | --- | --- |
| [LC 448 找到所有数组中消失的数字](https://leetcode.cn/problems/find-all-numbers-disappeared-in-an-array/) | `1..n` | 谁没出现 | 负号标记 |
| [LC 442 数组中重复的数据](https://leetcode.cn/problems/find-all-duplicates-in-an-array/) | `1..n` | 谁出现了两次以上 | 负号标记（第二次遇到已负 ⇒ 重复） |
| [LC 41 缺失的第一个正数](https://leetcode.cn/problems/first-missing-positive/) | 值域到 `10^9` | 最小缺失 | 交换归位（见 `038`） |
| [LC 645 错误的集合](https://leetcode.cn/problems/set-mismatch/) | `1..n` | 谁重复 + 谁缺失 | 负号标记同时给出两个答案 |
| [LC 287 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/) | `1..n`，**禁止改数组** | 谁重复 | 负号标记不可用 → Floyd / 二分（见 `039`） |
| [LC 73 矩阵置零](https://leetcode.cn/problems/set-matrix-zeroes/) | 行/列编号 | 哪行哪列要清零 | 用首行首列当标记位 |

**共同点**：都是「**把不可能再增长的信息，改写成标记**」。判断能否这么做的三问：

1. 值域是否恰好等于下标范围？（不是 → 先剪枝，如 038 只保留 `1..n`）
2. 是否有「用不上的位」？（符号位、高位、首行）
3. 原始值之后还需要吗？（需要 → 取绝对值 / 取模还原）

### 040.3.4 可扩展性（面试追问的方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成「找出**重复**的数」 | 判据反转 | 442：遇到 `nums[idx] < 0` 说明该值已出现过 → 记录 `idx+1` |
| 改成「**不能修改**数组」 | 负号标记失效 | 只能 `O(n)` 空间哈希；或对每个值做「值域二分 + 计数」，`O(n log n)` / `O(1)` |
| 值域变成 `0..n-1` | 映射平移 | 下标改成 `x`，判据 `nums[i] >= 0`；注意 0 的符号（`-0 == 0`）会让标记失效 → 改用 `+n` 编码 |
| 值域变成 `1..10^9` | 无法一一对应 | 先剪掉 `> n` 的值（它们不影响答案），剩下的仍可标记；但答案要输出 `1..n+1` 区间，逻辑要重推（见 038） |
| 要求输出**区间**而不是逐个数字 | 输出格式变了 | 收集到升序数组后合并成 `[a,b]` 区间，`O(n)` 两指针 |
| 数据流输入 | 不能回看 | 位图（`O(n/8)` 字节）是实际最优；严格 `O(1)` 需要 `O(n log n)` 的外部排序 |
| 多线程并行标记 | 符号位写冲突 | 「读一个值 → 翻另一个位置」有数据竞争，且第二次标记会被另一线程的读操作影响。安全做法：先做一遍「每个值是否出现」的分块统计（每块一个 `boolean` 位图），再合并 —— 代价是空间 |

## 040.4 图解推演

### 040.4.1 值 → 下标的映射

```
   值轴（题目保证都在 1..n）：
   ┌─────┬─────┬─────┬─────┬─────┬─────┐
   │  1  │  2  │  3  │  4  │  …  │  n  │
   └──┬──┴──┬──┴──┬──┴──┬──┴─────┴──┬──┘
      │     │     │     │           │
      ▼     ▼     ▼     ▼           ▼
   ┌─────┬─────┬─────┬─────┬─────┬─────┐
   │ [0] │ [1] │ [2] │ [3] │  …  │[n-1]│   ← 下标 = 值 - 1
   └─────┴─────┴─────┴─────┴─────┴─────┘
      ▲                       ▲
      │                       │
   值 1 的"打卡点"         值 n 的"打卡点"
```

### 040.4.2 完整执行轨迹：`[4,3,2,7,8,2,3,1]`

| 轮次 i | `nums[i]` | `x = abs` | 打卡点 `x-1` | 打卡点当前值 | 动作 | 数组状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 4 | 4 | 3 | 7 > 0 | 翻成 -7 | `[4,3,2,-7,8,2,3,1]` |
| 1 | 3 | 3 | 2 | 2 > 0 | 翻成 -2 | `[4,3,-2,-7,8,2,3,1]` |
| 2 | -2 | 2 | 1 | 3 > 0 | 翻成 -3 | `[4,-3,-2,-7,8,2,3,1]` |
| 3 | -7 | 7 | 6 | 3 > 0 | 翻成 -3 | `[4,-3,-2,-7,8,2,-3,1]` |
| 4 | 8 | 8 | 7 | 1 > 0 | 翻成 -1 | `[4,-3,-2,-7,8,2,-3,-1]` |
| 5 | 2 | 2 | 1 | -3 < 0 | **跳过**（已打卡） | `[4,-3,-2,-7,8,2,-3,-1]` |
| 6 | -3 | 3 | 2 | -2 < 0 | **跳过** | `[4,-3,-2,-7,8,2,-3,-1]` |
| 7 | -1 | 1 | 0 | 4 > 0 | 翻成 -4 | `[-4,-3,-2,-7,8,2,-3,-1]` |

```
收尾扫描：
   下标:    0    1    2    3    4    5    6    7
   值:     -4   -3   -2   -7    8    2   -3   -1
                               ▲    ▲
                              >0   >0
                                    
   nums[4] = 8 > 0 → 值 5 消失
   nums[5] = 2 > 0 → 值 6 消失
                                   
   答案：[5, 6] ✅
```

### 040.4.3 重复值的偶数次标记（坑 ② 的现场）

```
nums = [2,2,2,2]     n = 4，值 2 出现 4 次（下标 0..3 的值都是 2）

❌ 不判符号，直接 nums[1] = -nums[1]：
   i=0: nums[1] = -2
   i=1: nums[1] = +2      ← 负负得正，翻回来了
   i=2: nums[1] = -2
   i=3: nums[1] = +2      ← 又翻回来
   收尾扫描：nums[0..3] 全为正 → 答案 [1,2,3,4]
   但 2 明明出现过 → 【多报了一个 2】

✅ 判符号（只有 > 0 才翻）：
   i=0: nums[1] = -2
   i=1: nums[1] 已是 -2，跳过
   i=2: 跳过
   i=3: 跳过
   收尾扫描：nums[1] = -2 < 0 → 值 2 不缺席；其余为正 → 答案 [1,3,4]  ✅
```

> **关键观察**：错误写法只在「该值出现**偶数次**」时出错（翻偶数次会回到正数），出现奇数次时反而侥幸正确。
> 而「一半以上的位置都是同一个值」这种输入太常见了，所以这个 bug 属于「写了不测就一定挂」的级别。
> `if` 那两行不是防御性编程，是**正确性的一部分**：把「标记」写成幂等操作，是所有位标记技巧的通用要求。

### 040.4.4 两条路线的对比

```
                ┌────────── 输入：值域 1..n，长度 n ──────────┐
                │                                            │
      ┌─────────▼──────────┐                    ┌────────────▼─────────────┐
      │ 路线 A：负号标记    │                    │ 路线 B：交换归位          │
      │ O(n) / O(1)        │                    │ O(n) / O(1)              │
      └─────────┬──────────┘                    └────────────┬─────────────┘
                │                                            │
     每轮翻 1 个符号，最多 1 次写              每轮可能连锁多次交换，每次 3 次写
                │                                            │
     收尾：nums[i] > 0 → 缺失 i+1              收尾：nums[i] != i+1 → 缺失 i+1
                │                                            │
     ✅ 幂等、可恢复绝对值                    ✅ 值的分布变得"可读"
     ⚠️ 依赖值域严格 1..n                     ✅ 不依赖值域（越界跳过）
                │                                            │
        【本题选择 A】                            【038 / 442 常选 B】
```

## 040.5 双语言实现

### 040.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> findDisappearedNumbers(int[] nums) {
        int n = nums.length;

        // 阶段一：给每个出现过的值"打卡"。
        // 值 x  →  打卡点 nums[x-1]，打卡方式 = 翻符号。
        // 不变量：任何时刻 |nums[i]| 都等于它的原始值（我们只改符号，不改大小）。
        for (int i = 0; i < n; i++) {
            int x = Math.abs(nums[i]);   // 必须取绝对值：这个位置可能已被别人打过卡
            int idx = x - 1;             // 值 x 的打卡点是 x-1；值域 1..n 保证 idx ∈ [0, n-1]
            if (nums[idx] > 0) {         // 只在"还没打卡"时翻 —— 否则重复值会翻回正数
                nums[idx] = -nums[idx];
            }
        }

        // 阶段二：没被打过卡的下标，对应的值就是消失的数字。
        // 下标从小到大扫，答案天然升序，不需要再排序。
        List<Integer> res = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if (nums[i] > 0) {
                res.add(i + 1);
            }
        }
        return res;
    }
}
```

### 040.5.2 Go

```go
package main

func findDisappearedNumbers(nums []int) []int {
	n := len(nums)

	for i := 0; i < n; i++ {
		x := nums[i]
		if x < 0 { // 等价于 Math.abs；Go 没有内置的 int 绝对值函数
			x = -x
		}
		if nums[x-1] > 0 { // 幂等：已打过卡就不再翻
			nums[x-1] = -nums[x-1]
		}
	}

	// 预分配 n 是安全的：答案最多 n 个（全数组都是同一个值时）
	res := make([]int, 0, n)
	for i := 0; i < n; i++ {
		if nums[i] > 0 {
			res = append(res, i+1)
		}
	}
	return res
}
```

### 040.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 绝对值 | `Math.abs(int)` | 手写 `if x < 0 { x = -x }` | Go 1.21+ 有 `max/min` 但仍无 `abs`；手写还能顺便避免 `Math.abs(MIN_VALUE)` 的溢出陷阱（本题值域 `1..n` 不涉及） |
| 返回空结果 | `new ArrayList<>()`（空列表，非 null） | `make([]int, 0, n)` 或 `[]int{}` | Go 若 `return nil`，`len` 是 0 也能过判题，但打印出来是 `null` 风格；`make` 更一致 |
| 输出序列 | `List<Integer>`（装箱） | `[]int` | n = 10⁵ 时 Java 会创建最多 10⁵ 个 `Integer`（超出 `-128..127` 缓存），Go 无装箱 |
| 参数可变性 | 传引用，调用方能看到被改 | 切片是引用语义，同样可见 | 两语言都是「真·原地」；若题意要求不改输入，必须换算法 |
| 预先分配 | `new ArrayList<>()` 会多次扩容 | `make([]int, 0, n)` 一次到位 | 已知上界时显式给容量，是两语言共通的好习惯 |
| 整数宽度 | `int` 32 位 | `int` 64 位 | 本题只用绝对值与取负，`n ≤ 10^5` 都安全 |

### 040.5.4 对拍测试（与哈希裁判对比 + 专测重复值的幂等）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 裁判：哈希集合，从 1 到 n 查缺失。O(n) 时间、O(n) 空间 —— 空间违规，但答案可信。
func brute(nums []int) []int {
	seen := make(map[int]bool, len(nums))
	for _, x := range nums {
		seen[x] = true
	}
	res := []int{}
	for v := 1; v <= len(nums); v++ {
		if !seen[v] {
			res = append(res, v)
		}
	}
	return res
}

func eq(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func TestFindDisappearedRandom(t *testing.T) {
	r := rand.New(rand.NewSource(448))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(12)
		nums := make([]int, n)
		for i := range nums {
			// 值域取 1..n，但用 r.Intn(n) 造出"取值偏小、重复密集"的分布，
			// 这样才能把"重复标记"与"漏标记"两类 bug 都逼出来
			nums[i] = 1 + r.Intn(n)
		}
		orig := append([]int(nil), nums...)
		got := findDisappearedNumbers(nums)
		want := brute(orig)
		if !eq(got, want) {
			t.Fatalf("iter=%d nums=%v got=%v want=%v", iter, orig, got, want)
		}
		// 额外验证：实现是否保持了"绝对值不变"（这是正确性的核心不变量）
		sortedAbs := func(a []int) []int {
			b := append([]int(nil), a...)
			for i := range b {
				if b[i] < 0 {
					b[i] = -b[i]
				}
			}
			sort.Ints(b)
			return b
		}
		if !eq(sortedAbs(nums), sortedAbs(orig)) {
			t.Fatalf("iter=%d 绝对值不变量被破坏：orig=%v after=%v", iter, orig, nums)
		}
	}
}

// 边界：全重复 / 全连续 / 最小规模
func TestFindDisappearedEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want []int
	}{
		{[]int{1, 1}, []int{2}},
		{[]int{2, 2}, []int{1}},
		{[]int{1, 2, 3, 4}, []int{}},
		{[]int{4, 4, 4, 4}, []int{1, 2, 3}},
		{[]int{1}, []int{}},
		{[]int{4, 3, 2, 7, 8, 2, 3, 1}, []int{5, 6}},
		{[]int{2, 2, 2, 2, 2}, []int{1, 3, 4, 5}}, // 值 2 被标记 4 次，专测幂等
	}
	for _, c := range cases {
		got := findDisappearedNumbers(append([]int(nil), c.nums...))
		if !eq(got, c.want) {
			t.Fatalf("nums=%v got=%v want=%v", c.nums, got, c.want)
		}
	}
}
```

实测：2 万组随机 + 7 个边界用例全部通过；第二个断言（绝对值不变量）在**故意去掉 `if` 判断**时会失败 —— 这正是把它写进测试的原因。

## 040.6 复杂度与常见坑

### 040.6.1 复杂度推导

- **时间 `O(n)`**：阶段一做 `n` 次「读 + 判 + 最多一次写」，阶段二做 `n` 次比较。合计 `2n` 次循环，无嵌套。
- **额外空间 `O(1)`**：只用了 `x`、`idx` 两个整型变量；`res` 是输出，题目明确不计入。
- **对比哈希解**：时间同为 `O(n)`，但空间从 `O(n)`（Java 里 10⁵ 个 `Integer` ≈ 4 MB）降到常数。

### 040.6.2 七个真实踩过的坑

1. **忘记取绝对值** —— 读到已经被标记成负数的位置时，`x = nums[i]` 为负，`idx = x-1` 变成负下标，直接越界。**必须先 `abs`。**
2. **标记不判符号** —— `[2,2,2,2]` 这类输入会把同一个位置翻偶数次，翻回正数，于是「出现过的值」被误报为「消失」。
3. **收尾判据写成 `nums[i] >= 0`** —— 0 是合法值吗？本题值域是 `1..n`，`nums[i]` 初值不会是 0，但一旦某处逻辑意外写坏成 0，`>= 0` 会静默多报一个答案。用 `> 0`。
4. **返回 `i` 而不是 `i+1`** —— 差一错误，整个答案集合偏移。
5. **试图「边标记边收集」** —— 标记顺序会影响尚未处理的值。必须**两阶段**：先全部标记完，再统一收集。
6. **`+n` 编码时的溢出** —— 若按 442 的写法用 `nums[idx] += n`，`n = 10^5` 时 `nums[i]` 最大可到 `(k+1)·n ≈ 10^{10}`，`int32` 溢出。负号标记没有这个问题，这也是它更适合本题的原因之一。
7. **Go 里返回 `nil` 却要求打印 `[]`** —— 判题通常接受 `nil`，但如果你把结果再传给别的地方（比如 JSON 序列化），`nil` 与 `[]` 的语义不同。用 `make([]int, 0, n)` 更稳。

### 040.6.3 面试官最爱追问的三个问题

**Q1：为什么符号位可以当标记用，不会破坏数据吗？**

> 「只破坏符号，不破坏绝对值：每次写都是 `nums[k] = -nums[k]`，所以任何时刻 `|nums[i]|` 都等于它的原始值 —— 我把这一点写成了一条不变量，还写进了随机测试里（比较标记前后的绝对值多重集必须一致）。原值随时可以用 `abs` 恢复。代价是标记完成后数组不再「可读作原数组」，所以本题是两阶段：先标记、再收集，不能边标记边收集。」

**Q2：如果不允许修改数组，还能做到 `O(1)` 空间吗？**

> 「做不到 `O(n)` 时间下的精确解。可行的两条路：① 放弃 `O(1)` 空间，用 `O(n)` 位图（`n/8` 字节）；② 放弃 `O(n)` 时间，对每个候选值做一次「值域二分 + 计数」——但那其实是 041 的做法，对本题是杀鸡用牛刀。实际工程里选 ①，因为 `n/8` 字节在 `n = 10^5` 时只有 12 KB，早就不算『空间问题』了。」

**Q3：如果值域不是 `1..n` 而是 `1..10^9` 呢？**

> 「负号标记和归位都失效，因为值不能当下标。第一步必须剪枝：大于 `n` 的值不可能成为『`1..n` 内的缺失』，直接跳过；剩下的值仍在 `1..n` 内，照旧标记。但答案的范围要重推：如果 `1..n` 全都在，答案就是 `n+1`（这时就退化成 038 了）。所以『值域与下标同阶』是这类技巧的硬前提，不是巧合。」

## 附：本章小结（可背走的三句话）

```
① 值域 1..n + 长度 n → 下标 i 就是值 i+1 的打卡点，符号位就是那个"免费的 bit"

```
