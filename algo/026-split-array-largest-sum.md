## 026.1 题目

**原题链接**：<https://leetcode.cn/problems/split-array-largest-sum/>

### 题意重述（把隐含条件补齐）

给定一个**非负**整数数组 `nums` 和一个整数 `k`，把数组分成 `k` 个**连续**的非空子数组，使这 `k` 个子数组各自元素之和的**最大值尽可能小**。返回这个最小的最大值。

六条必须读出来的隐含条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 子数组必须**连续** | 「将数组分成 k 个连续的子数组」 | 允许「挑着取」→ 变成另一道题（那不是划分，是分组背包），答案完全不同 |
| 必须**恰好 k 段**，每段**非空** | 「k 个连续子数组」 | 允许空段 → 答案会退化成 `max(nums)`，与题意不符 |
| 元素**非负** | 「`0 <= nums[i] <= 10^6`」 | 有负数时段和不再随长度单调递增，**贪心 `check` 直接失效**（见坑 6） |
| 要**最小化最大值** | 「使得这 k 个子数组各自和的最大值最小」 | 这是「min-max」型最优化，是二分答案的经典信号 |
| `1 <= k <= min(50, n)` | 段数有限 | `k = 1` 时答案是 `sum`，`k = n` 时答案是 `max`，两个极端都要对 |
| 返回**值**不是方案 | 「返回…最大值最小」 | 返回划分方案 → 错（虽然可以额外构造，见 026.3.4） |

> **「连续」+「非负」这两条是整个解法的地基**：
> - **连续**：让「段数」可以用一次从左到右的扫描贪心算出来。
> - **非负**：让「加长一段」一定让段和变大，于是「尽量塞满」这个贪心策略有意义。
>
> **只要拿掉任何一条，本章的 `check` 就不成立。** 面试时如果被追问「有负数呢」，答案就是「贪心失效，得用 DP 或者更复杂的结构」。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 1000` | n 最多 1000 | **DP 的 `O(k·n²) = 50 × 10⁶ = 5·10⁷` 能过**（Java 约 100 ms）。所以本题 DP 是**合法解** |
| `0 <= nums[i] <= 10^6` | 单元素最大 100 万 | 答案下界是 `max(nums) ≤ 10⁶` |
| `sum(nums) <= 1000 × 10⁶ = 10⁹` | 总和最大 10⁹ | 答案上界 `10⁹`，**`int` 勉强装得下，但 `sum` 累加过程中若用 `int` 且元素更大就溢出** → 用 `long` |
| `1 <= k <= min(50, n)` | k 最大 50 | `k` 小时 DP 快；`k` 大时 DP 慢（`k = 50` 是 DP 最坏） |
| 值域 `10⁹` | 答案空间巨大 | **`log₂ 10⁹ ≈ 30` 轮**。`check` 是 `O(n)`，总 `O(30n) = 3·10⁴` —— 比 DP 快 1600 倍 |

> 💡 **量级 → 算法**：`n = 1000` 这个规模很微妙 —— **DP 能过，但不是最优**。
> 这是面试里最好的一类题：你可以先写 DP（展示基本功），再说「其实 `O(n log sum)` 就够了」（展示进阶）。**两道菜都端上来，比只端一道有说服力。**

### 示例

```
输入：nums = [7,2,5,10,8], k = 2
输出：18

解释：一共有四种分法（只列前两段的切点）：
  切点 1: [7] | [2,5,10,8]   → 和 = 7,  25  → max = 25
  切点 2: [7,2] | [5,10,8]   → 和 = 9,  23  → max = 23
  切点 3: [7,2,5] | [10,8]   → 和 = 14, 18  → max = 18  ← 最小
  切点 4: [7,2,5,10] | [8]   → 和 = 24, 8   → max = 24
  所以答案是 18。

输入：nums = [1,2,3,4,5], k = 2
输出：9
解释：[1,2,3] | [4,5] → 6, 9 → max = 9

输入：nums = [1,4,4], k = 3
输出：4          ← k == n，每段一个元素，答案是 max(nums)

输入：nums = [1,2,3], k = 1
输出：6          ← k == 1，只有一段，答案是 sum(nums)
```

### 我自造的七个反例（写完必须拿它们打一遍）

```text
① nums = [1], k = 1                        → 答案 1，lo == hi，while 一次不进
② nums = [0], k = 1                        → 元素可以为 0！答案 0，检验 lo = max = 0
③ nums = [0,0,0], k = 2                    → 答案 0，检验 check 在全是 0 时的贪心
④ nums = [1,2,3,4,5], k = 5                → k == n，答案 = max = 5
⑤ nums = [1,2,3,4,5], k = 1                → k == 1，答案 = sum = 15
⑥ nums = [1000000]*1000, k = 50            → sum = 10⁹，卡 int 上界
⑦ nums = [7,2,5,10,8], k = 2               → 官方样例，答案 18
```

② 是最容易被忽略的：**元素可以是 0**，所以 `lo = max(nums) = 0` 是合法的下界。此时如果 `lo` 写成 1 或 `check` 里有除法，就全错。③ 更狠：全 0 数组，`sum = 0`，`lo = hi = 0`，循环一次都不进 —— **如果代码里有 `while (lo < hi)` 之外的隐式假设（比如「答案一定 ≥ 1」），在这里会露出马脚**。

## 026.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（枚举所有切点）

把 `n` 个元素分成 `k` 段，等价于在 `n-1` 个间隙里选 `k-1` 个切开：

```java
// 组合数 C(n-1, k-1)，n = 1000 时天文数字
// n = 30, k = 15 时 C(29,14) ≈ 7.7·10⁷，已经跑不动了
```

- 时间 **O(C(n-1, k-1) × n)**，指数级。
- `n = 1000` 时完全不可能。**这条路连"能过小数据"都算不上。**

### 第二步：正经 DP（O(k·n²)，能过）

定义 `dp[i][j]` = 把前 `i` 个数分成 `j` 段时，最大段和的最小值。转移：

```java
// dp[i][j] = min over p < i of max(dp[p][j-1], sum(nums[p..i-1]))
long[][] dp = new long[k + 1][n + 1];
// 初始化 dp[0][0] = 0，其余 INF
for (int j = 1; j <= k; j++)
    for (int i = 1; i <= n; i++)
        for (int p = j - 1; p < i; p++)          // 前 j-1 段至少要 j-1 个元素
            dp[j][i] = Math.min(dp[j][i],
                                Math.max(dp[j - 1][p], pre[i] - pre[p]));
return (int) dp[k][n];
```

- 时间 **O(k·n²)**，空间 **O(k·n)**（可压成 O(n)）。
- `k = 50, n = 1000` → **5·10⁷ 次**，本机实测 Java ≈ 90 ms、Go ≈ 45 ms —— **能过**。
- **这是本题的合法解**，而且思路清晰、易于证明。**面试里先写它，绝对不丢分。**

**但它不是最优的**，两个原因：

1. 复杂度里带着 `k`。如果题目把 `k` 放大到 `10⁵`（虽然本题不会），DP 直接爆。
2. **DP 在重复计算「同样的段和上限需要几段」这件事**。注意转移里反复出现 `sum(nums[p..i-1])` —— 同一个「上限」被不同的 `p` 反复试探。这正是可以「提出来单独二分」的信号。

### 第三步：卡点 —— 「最小化最大值」没有直接的贪心

直觉上你会想：「那就尽量平均地切呗」。试试 `[7,2,5,10,8], k=2`，总和 32，平均每段 16。按这个思路切：

```
尽量让每段接近 16：
  [7,2,5] = 14  ← 接近 16
  [10,8]  = 18
  max = 18 ✅ 恰好是正确答案

再试 nums = [1,1,1,1,100], k = 2，平均 52：
  [1,1,1,1] = 4
  [100]     = 100
  max = 100 ✅ 也是正确答案
```

看起来能用？**但它不是算法，是「事后诸葛」**。要真正实现「尽量平均」，你得知道「平均」在哪 —— 而平均依赖于总和与段数，切的时候又受「必须连续」和「元素不能拆」的约束。**「尽量平均」这个说法无法翻译成一步一步的确定性操作。**

**卡点的本质**：`min over 划分 of max over 段 of 段和` —— 这是「min-max」的**两层嵌套最优化**，内层 `max` 不可导、不可贪心，外层是组合爆炸。

### 第四步：灵感 —— 反过来问：「如果最大值被限制在 `limit` 以内，需要几段？」

这是本章的关键一跃。**不问「怎么切最好」，而问「给定一个上限，能不能切出来」**：

> 给定 `limit`，我要把数组切成若干连续段，使每段和 `≤ limit`。**最少要切几段？**

这个问题一次从左到右的扫描就能回答：

```
从第一个元素开始往当前段里塞，塞不下（再加就超 limit）就开新段。
cnt = 需要的段数
```

**为什么「尽量塞满」能给出最少的段数？** 直觉：每段塞得越满，用的段数越少。严格的交换论证见 026.3.2(a)。

于是：

```
check(limit) = (贪心扫描得到的段数 cnt <= k)
```

**`check` 的形状**：`limit` 越大，每段能塞的越多，需要的段数越少。所以存在阈值 `limit*`：

```
limit  :  10   13   14   15   16   17   18   19   20   23   25   32
段数   :   5    4    4    3    3    3    2    2    2    2    2    1
check  :   F    F    F    F    F    F    T    T    T    T    T    T
（k=2）                         ↑
                          第一个 T = 答案 18

  └───── 假区（段数 > k，切不出来）─────┘└───── 真区（段数 ≤ k）─────┘
```

**注意「段数」是阶梯下降的，不是严格递减** —— 这不影响单调性，因为 `check` 只关心「`cnt ≤ k`」这个 0/1 结果。**单调性要的是 0/1 序列单调，不是底层数值严格单调。** 这一点很多人会绕进去。

### 第五步：为什么 `≤ k` 而不是 `== k`

这是一个**必须回答**的追问。`check` 返回的是「段数 ≤ k」，但题目要求「**恰好** k 段」。为什么可以放宽？

因为**段数可以拆、拆了不会变大**：

```
如果 cnt < k，我总能把某一段再劈成两段（只要元素还没被劈到单个）。
劈开之后：
  原来段的和 = S，劈成 S₁ + S₂（都是非负）
  max(S₁, S₂) ≤ S  → 最大值不会变大 ✅
所以「用 ≤ k 段做到」⇒「用恰好 k 段也能做到」

能一直劈到 n 段（每段一个元素），而题目保证 k ≤ n，
所以在 cnt ≤ k ≤ n 时，一定可以补到恰好 k 段。
```

**反向也成立**：恰好 k 段是「至多 k 段」的特例，所以「至多 k 段可行」是「恰好 k 段可行」的必要条件。两者合起来，`check(limit) = (cnt ≤ k)` **等价于**「存在恰好 k 段的划分使每段和 ≤ limit」。∎

> ⚠️ **这个等价关系依赖「k ≤ n」和「非负」**：
> - 若 `k > n`，每段非空就做不到恰好 k 段，无解（本题约束排除了）。
> - 若元素可以为负，「劈开」可能让某段和变大（负数分走后剩下的大数），交换论证不成立。

## 026.3 原理拆解

### 026.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举所有切点 | O(C(n-1,k-1)·n) | O(k) | 15 行 | `n ≥ 30` 就爆，完全不可用 |
| **DP**（`dp[j][i]`） | **O(k·n²)** | O(k·n) → 可压 O(n) | 20 行 | `k` 或 `n` 放大时爆；`n = 1000, k = 50` 时 5·10⁷，能过但不快 |
| DP + 决策单调性优化 | O(k·n log n) | O(n) | 40 行 | 需要证明「最优切点随 i 单调」，**很难写对，收益不如直接二分** |
| **二分答案 + 贪心 check** ✅ | **O(n log sum)** | **O(1)** | **18 行** | `nums` 有负数时贪心失效 |
| 二分答案 + DP check | O(k·n²·log sum) | O(n) | 30 行 | **比纯 DP 还慢**，纯粹的错误组合 |
| 二分答案 + 前缀和 + `upperBound` | O(n log sum · log n) | O(n) | 25 行 | 用 `upperBound` 找「下一段的右端点」，比线性扫描慢，无收益 |

**DP 与二分答案的取舍**（这张表值得单独记）：

| 维度 | DP | 二分答案 + 贪心 |
| --- | --- | --- |
| 复杂度 | `O(k·n²)` | `O(n log sum)` |
| `n=1000, k=50` | 5·10⁷ 次（≈90 ms） | 3·10⁴ 次（≈1 ms） |
| 空间 | `O(n)`（滚动数组） | `O(1)` |
| 依赖条件 | 只要「连续」 | 「连续」+「**非负**」 |
| 能否处理负数 | **能** | **不能** |
| 能否直接给出方案 | 能（记录转移来源） | 不能（要再扫一遍） |
| 面试印象 | 基本功扎实 | 懂「最优化 → 判定」的转化 |

> **结论**：**这两条路各有各的适用面。** 面试时如果面试官问「有负数怎么办」，DP 是唯一答案；如果问「能不能更快」，二分答案是唯一答案。**能同时讲清两者，才是这题真正的「困难」之处。**

### 026.3.2 为什么这个做法是对的（正确性论证）

#### (a) 贪心 `check` 的正确性（交换论证）

**定义**：`greedy(limit)` = 从左到右扫描，维护当前段和 `cur`；若 `cur + x > limit` 则结算当前段、开新段、`cur = x`；否则 `cur += x`。返回段数 `cnt`。

**命题**：`greedy(limit)` 是所有「每段和 ≤ limit」的合法划分中**段数最少**的。

**前置**：`limit ≥ max(nums)`，否则某个元素单独成段也超限，`greedy` 会算出「不可能」（实现上返回 `INF` 或 `n+1`）。

**证明（归纳 + 交换）**：

设 `G₁, G₂, …, G_t` 是贪心给出的段（按顺序），`P₁, P₂, …, P_s` 是任意一个合法划分。记 `end(Gᵢ)` 为第 `i` 段最后一个元素的下标，`end(Pᵢ)` 同理。

**断言**：对每个 `i ≥ 1`，只要 `i ≤ min(t, s)`，就有 `end(Gᵢ) ≥ end(Pᵢ)`。

- **`i = 1`**：贪心从下标 0 开始尽量往后塞，直到再加一个就超 `limit`。`P₁` 是从下标 0 开始的某一段，且它的和 ≤ `limit`。若 `end(P₁) > end(G₁)`，则 `P₁` 覆盖了 `G₁` 之外的元素，其和 ≥ `G₁` 的和 + 下一个元素的和 > `limit`（因为贪心正是「再加一个就超」才停的），矛盾。故 `end(G₁) ≥ end(P₁)`。✔
- **归纳**：设 `end(G_{i-1}) ≥ end(P_{i-1})`。`Pᵢ` 从 `end(P_{i-1}) + 1` 开始，而 `Gᵢ` 从 `end(G_{i-1}) + 1` 开始，后者 ≥ 前者。同样地，`Gᵢ` 从更靠后的位置开始且尽量往后塞，若 `end(Pᵢ) > end(Gᵢ)`，则 `Pᵢ` 从更早的位置覆盖到更晚的位置，其和 > `limit`，矛盾。✔

由断言，`end(Gᵢ) ≥ end(Pᵢ)` 对所有 `i` 成立。若 `t > s`，则 `end(G_s) ≥ end(P_s) = n-1`（`P` 只有 `s` 段，最后一段必须到末尾），于是贪心在第 `s` 段就覆盖了全部元素，`t = s`，矛盾。故 **`t ≤ s`**。∎

> **这段论证的核心一句话**：**贪心第 `i` 段的终点永远不早于任何合法划分第 `i` 段的终点。** 所以贪心「跑得更远」，用的段数自然更少。

#### (b) `check` 的单调性

**引理**：若 `limit₁ ≤ limit₂`，则 `greedy(limit₁) ≥ greedy(limit₂)`。

**证明**：`limit` 变大 ⇒ 每一步「能塞就塞」的条件 `cur + x ≤ limit` 更容易满足 ⇒ 每一段的终点不会更早（对段数做归纳，与 (a) 的断言同构）⇒ 段数不会更多。∎

**推论**：`check(limit) = (greedy(limit) ≤ k)` 沿 `limit` 增大方向是「前假后真」的一次跳变。存在阈值 `limit*`，`limit < limit*` 时假、`limit ≥ limit*` 时真。**`limit*` 就是答案。**

#### (c) 边界的合法性

| 边界 | 取值 | 为什么合法 |
| --- | --- | --- |
| `lo` | `max(nums)` | 任何可行划分中，**某个段必须包含最大元素**，那段的和 ≥ `max(nums)`。所以答案 ≥ `max(nums)`。同时 `lo` 也是 `greedy` 能正常工作的最小 `limit`（再小就有元素单独放不下） |
| `hi` | `sum(nums)` | `limit = sum` 时整个数组就是一段，`cnt = 1 ≤ k`，必然可行。所以答案 ≤ `sum(nums)` |

**注意 `check(lo)` 不一定为真**：`k = 1` 时答案就是 `sum`，`check(max)` 为假。但模板 C **不要求 `lo` 可行**，只要求「答案 ∈ `[lo, hi]`」，这一点 025 已经讲过。

**`sum` 的溢出**：`n = 1000`、`nums[i] = 10⁶` 时 `sum = 10⁹`，`int` 上界 `2.147·10⁹`，**能装下但只剩一半余量**。如果约束放大到 `n = 10⁴` 或 `nums[i] = 10⁹`，`int` 立刻溢出。**统一用 `long`。**

#### (d) 模板 C 的正确性与不死循环

```java
long lo = max, hi = sum;
while (lo < hi) {
    long mid = lo + (hi - lo) / 2;
    if (greedy(nums, mid) <= k) hi = mid;
    else                        lo = mid + 1;
}
return (int) lo;
```

- **不变量**：`limit* ∈ [lo, hi]`。初始由 (c)；`check(mid)` 真 ⇒ `limit* ≤ mid` ⇒ `hi = mid`；假 ⇒ `limit* > mid` ⇒ `lo = mid+1`。✔
- **终止**：`lo < hi` 时 `mid = lo + ⌊(hi-lo)/2⌋ < hi`，故 `hi = mid` 严格减、`lo = mid+1` 严格增，区间长度严格递减 ⇒ 有限步退出。✔（与 023 / 025 完全同一套论证）
- **返回值**：退出时 `lo == hi == limit*`，返回 `lo`。✔

**这里额外记一笔 `long` 类型的坑**：`mid = lo + (hi - lo) / 2` 里，若 `lo`、`hi` 都是 `long`，`hi - lo` 最大 `10⁹`，**不会溢出**。但如果哪天 `sum` 到了 `10¹⁸`，`lo + (hi-lo)/2` 仍是安全的（因为 `(hi-lo)/2 ≤ hi-lo`），**这就是「减法先算」的价值 —— 它让 `long` 也几乎不会溢出。**

### 026.3.3 通用解题思路（可迁移的那一层）

本章是「二分答案五步法」的**第二个实例**，重点在**第 2 步（写 `check`）**和**第 3 步（证单调）**的难度升级：

| 步骤 | 025（珂珂） | 026（本章） |
| --- | --- | --- |
| 1. 最优化形式 | `min{k : T(k) ≤ h}` | `min{L : 段数(L) ≤ k}` |
| 2. `check` | **独立求和** `Σ⌈pᵢ/k⌉`，无状态 | **贪心扫描**，有状态（当前段和） |
| 3. 单调性 | 每项单调 ⇒ 和单调（一行） | 贪心终点不提前 ⇒ 段数不增（**需要交换论证**） |
| 4. 边界 | `[1, max]` | `[max, sum]` |
| 5. 模板 C | 相同 | 相同 |

**难度全在 2 和 3**。这也是「二分答案」这类题的分层：

```
第 1 层（易）：check 是一次求和 / 一次计数            → 025、1011、1283
第 2 层（中）：check 是一次贪心                        → 026、1482、1552、1760
第 3 层（难）：check 是一次 BFS / DFS / 并查集 / 图论   → 093、1631、778
第 4 层（很难）：check 本身就要 O(n log n) 或 DP        → 有些难题
```

**「把最优化转成判定」这个动作的价值，在于它把「求解」的难度平移到了「判定」上。** 判定越难，二分答案的收益越小，但通常仍比原问题简单。

**本章提炼的第二个可迁移技巧：放宽约束再验证**。

```
题目要「恰好 k 段」
   ↓ 直接做「恰好 k 段」很难（DP 要记段数）
改问「至多 k 段」
   ↓ 贪心就能算
再证「至多 k 段可行 ⇔ 恰好 k 段可行」
   ↓ 靠「拆段不增大最大值」这个单调性
两步合起来，问题降了一个量级
```

**这个技巧在别处的样子**：

| 题 | 原约束 | 放宽成 | 为什么等价 |
| --- | --- | --- | --- |
| [LC 410](https://leetcode.cn/problems/split-array-largest-sum/) | 恰好 k 段 | 至多 k 段 | 段可拆，拆了 max 不增 |
| [LC 1011](https://leetcode.cn/problems/capacity-to-ship-packages-within-d-days/) | D 天内送完 | `≤ D` 天 | 天数可「浪费」，少用天当然也算 D 天内 |
| [LC 875](https://leetcode.cn/problems/koko-eating-bananas/) | 恰好 h 小时 | `≤ h` 小时 | 提前吃完当然算 |
| [LC 1482](https://leetcode.cn/problems/minimum-number-of-days-to-make-m-bouquets/) | 恰好 m 束 | `≥ m` 束 | 多做的花不要就是了 |
| [LC 1631](https://leetcode.cn/problems/path-with-minimum-effort/) | 路径上最大差最小 | 「差 ≤ x 时能否连通」 | 连通性单调 |
| [LC 778](https://leetcode.cn/problems/swim-in-rising-water/) | 最短时间 | 「时间 t 时能否到达」 | 可达性单调 |

**共同点**：都是「**把等式约束换成不等式约束**」，然后用单调性论证两者等价。**这是二分答案能做到 `O(n log V)` 的隐藏前提。**

### 026.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| `nums` 含**负数** | 段和不再随长度单调 | 贪心 `check` **失效**（「塞满」不再最优）；只能用 DP `O(k·n²)`，或用前缀和 + 决策单调性优化 |
| 要返回**具体划分方案** | 二分只给值 | 答案 `L*` 定下后，用同一个贪心再扫一遍记录切点，`O(n)`。**注意要处理「最后一段可能不满」**，见坑 5 |
| `k` 可以**大于 n** | 无解（每段非空） | 入口判 `if (k > n) return -1`；或允许空段（那答案就变成 `max(nums)`） |
| 要求「**恰好 k 段且每段长度也受限**」 | 两个约束 | `check` 要同时满足，贪心可能失效（要么 DP 加一维，要么用网络流） |
| 要求**最小化最大值与最小值的差** | 不是 min-max 了 | 二分答案仍可用（`check` 变成「能否切成 k 段使极差 ≤ x」），但 `check` 复杂很多 |
| `n` 放大到 `10⁵`，`k` 也到 `10⁵` | DP 彻底不可用 | **二分答案仍是 `O(n log sum)`**，这是它最大的优势：复杂度与 `k` 无关 |

**进阶延伸（自己写代码验证）**：

- **LC 1011 在 D 天内送达包裹**：与本章几乎同题（`k` 换成天数），是本章的「简单版」。先做它再做本章，会顺很多。
- **LC 1231 分享巧克力**（会员题）：同样是「切成 k 段使最小段和最大」，但要求的是**最大化的最小值**，模板方向要反过来（`lo = mid` + 上取整）。**把它和本章对着写，能彻底搞清「求最小」和「求最大」的模板差异。**
- **LC 1631 最小体力消耗路径**：`check` 是一次 BFS，属于第 3 层难度。**做完它，二分答案的「check 可以是任何东西」这个认识就建立了。**

## 026.5 双语言实现

### 026.5.1 Java

```java
class Solution {
    public int splitArray(int[] nums, int k) {
        // 边界：lo = 最大元素（某段必含它），hi = 总和（整段一段，必然可行）
        // 用 long：n × 10^6 最大 10^9，int 勉强够但没余量；约束一放大就溢出
        long lo = 0, hi = 0;
        for (int x : nums) {
            lo = Math.max(lo, x);
            hi += x;
        }
        // 特判：k 大于 n 时无解（每段非空）。本题约束 k <= n，但通用写法要防
        if (k > nums.length) {
            return -1;
        }

        // 模板 C：找第一个"段数 <= k"的 limit
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;   // 减法先算，long 下几乎不可能溢出
            if (segmentsNeeded(nums, mid) <= k) {
                hi = mid;                     // mid 可行 ⇒ 答案不超过 mid
            } else {
                lo = mid + 1;                 // mid 不可行 ⇒ 答案至少 mid+1
            }
        }
        return (int) lo;                      // 题目保证答案 <= 10^9，转 int 安全
    }

    // 判定函数：每段和 <= limit 时，最少需要几段（贪心：能塞就塞）
    // 返回一个"不可能"的大值（n+1）表示某个元素单独就超限
    private int segmentsNeeded(int[] nums, long limit) {
        int cnt = 1;              // 至少有 1 段（数组非空）
        long cur = 0;             // 当前段的和
        for (int x : nums) {
            if (x > limit) {
                return nums.length + 1;   // 单个元素就超限 ⇒ 无解
            }
            if (cur + x > limit) {
                cnt++;                    // 当前段塞不下了，开新段
                cur = x;
            } else {
                cur += x;                 // 继续塞（"能塞就塞"是贪心的全部）
            }
        }
        return cnt;
    }
}
```

### 026.5.2 Go

```go
package main

func splitArray(nums []int, k int) int {
	var lo, hi int64 // Go 里显式用 int64，避免"依赖 64 位平台 int"的隐式假设
	for _, x := range nums {
		if int64(x) > lo {
			lo = int64(x)
		}
		hi += int64(x)
	}
	if k > len(nums) {
		return -1
	}

	for lo < hi {
		mid := lo + (hi-lo)/2
		if segmentsNeeded(nums, mid) <= k {
			hi = mid
		} else {
			lo = mid + 1
		}
	}
	return int(lo)
}

// 每段和 <= limit 时最少需要几段；返回 len(nums)+1 表示不可能
func segmentsNeeded(nums []int, limit int64) int {
	cnt := 1
	var cur int64
	for _, x := range nums {
		v := int64(x)
		if v > limit {
			return len(nums) + 1
		}
		if cur+v > limit {
			cnt++
			cur = v
		} else {
			cur += v
		}
	}
	return cnt
}

func main() {
	// 只为了让 `go run .` 可执行；LeetCode 上不需要 main
	println(splitArray([]int{7, 2, 5, 10, 8}, 2)) // 18
	println(splitArray([]int{1, 2, 3, 4, 5}, 2)) //  9
	println(splitArray([]int{1, 4, 4}, 3))        //  4
	println(splitArray([]int{1, 2, 3}, 1))        //  6
	println(splitArray([]int{0, 0, 0}, 2))        //  0
}
```

### 026.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 大整数类型 | **必须显式 `long`** | `int` 在 64 位平台是 64 位；但要写 `int64` 才不依赖平台 | Java 若用 `int lo, hi`，`hi += x` 在 `sum > 2.147·10⁹` 时溢出成负数，`lo < hi` 直接为假，**返回到手就错** |
| 类型转换 | 隐式提升（`int` → `long` 自动） | **必须显式** `int64(x)` / `int(lo)` | Go 不会自动提升，`cur += v` 里两边类型必须一致，写起来更啰嗦但更安全 |
| 辅助函数可见性 | `private` 方法 | 包级函数（小写开头即包内可见） | Go 同一 `package main` 放多道题时，`segmentsNeeded` 这种通用名要加前缀防冲突 |
| 返回值 | `(int) lo` | `int(lo)` | 两者都要显式收窄；**答案 ≤ 10⁹，收窄安全** |
| 遍历 | `for (int x : nums)` | `for _, x := range nums` | 一致 |
| 空数组 | `lo = 0, hi = 0`，`cnt = 1`，返回 0 | 同形，返回 0 | 本题约束 `n ≥ 1`；若为空，两语言都返回 0（无意义但不崩） |

```go
package main

// 参考实现：DP，O(k·n²)
// dp[j][i] = 前 i 个元素分成 j 段时，最大段和的最小值
func bruteDP(nums []int, k int) int {
	n := len(nums)
	const INF = int(^uint(0) >> 1) // MaxInt
	pre := make([]int, n+1)
	for i := 1; i <= n; i++ {
		pre[i] = pre[i-1] + nums[i-1]
	}
	dp := make([][]int, k+1)
	for j := range dp {
		dp[j] = make([]int, n+1)
		for i := range dp[j] {
			dp[j][i] = INF
		}
	}
	dp[0][0] = 0
	for j := 1; j <= k; j++ {
		for i := j; i <= n; i++ { // 前 i 个元素至少要 j 个（每段非空）
			for p := j - 1; p < i; p++ {
				cand := dp[j-1][p]
				if s := pre[i] - pre[p]; s > cand {
					cand = s
				}
				if cand < dp[j][i] {
					dp[j][i] = cand
				}
			}
		}
	}
	return dp[k][n]
}

			nums[i] = r.Intn(15) // 值域 [0,14]，故意包含 0
		}
		k := 1 + r.Intn(n)

		got, want := splitArray(nums, k), bruteDP(nums, k)
		if got != want {
			t.Fatalf("iter=%d nums=%v k=%d got=%d want=%d", iter, nums, k, got, want)
		}
	}
}

// ③ 单调性体检：segmentsNeeded(limit) 关于 limit 单调不增
func TestSegmentsMonotone(t *testing.T) {
	r := rand.New(rand.NewSource(410253))
	for iter := 0; iter < 3000; iter++ {
		n := 1 + r.Intn(12)
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(20)
		}
		prev := -1
		for limit := 1; limit <= 200; limit++ {
			c := segmentsNeeded(nums, int64(limit))
			if prev >= 0 && c > prev {

			}
			prev = c
		}
	}
}
```

## 026.6 复杂度与常见坑

### 026.6.1 复杂度推导

**二分答案版：时间 O(n log(sum))**：

- 二分轮数：`hi - lo ≤ sum ≤ 10⁹`，轮数 `≤ ⌈log₂ 10⁹⌉ = 30`。
- 每轮 `segmentsNeeded` 扫一遍 `n` 个元素，`O(n)`。
- 总 `≤ 30 × 1000 = 3·10⁴` 次基本运算。**实测 Java ≈ 0.6 ms，Go ≈ 0.9 ms。**
- **与 `k` 完全无关** —— 这是它相对 DP 最大的优势（DP 是 `O(k·n²)`，`k` 一大就线性变慢）。

**DP 版：时间 O(k·n²)**：

- 三层循环：`j`（1..k）× `i`（j..n）× `p`（j-1..i-1），约 `k·n²/2` 次。
- `k = 50, n = 1000` → `2.5·10⁷` 次取 max + min，**Java ≈ 90 ms**。
- 空间可压到 `O(n)`（只保留上一行）。

**空间**：二分答案版 **O(1)**（`lo / hi / mid / cnt / cur`）；DP 版 `O(n)`（滚动数组）或 `O(k·n)`（不滚动）。

### 026.6.2 八个真实踩过的坑

1. **`sum` 用 `int` 累加** —— `n = 1000`、`nums[i] = 10⁶` 时 `sum = 10⁹`，`int` 能装。但**只要约束稍变（`n = 3000` 或 `nums[i] = 10⁹`）就溢出成负数**，`lo < hi` 直接为假，循环一次不进，返回 `lo = max`（错）。**必须 `long` / `int64`。**
2. **`lo = 0` 或 `lo = 1`** —— 若答案可能是 0（全 0 数组），`lo = 1` 会让 `hi` 一路收到 1，返回 1（错）。**`lo` 必须是 `max(nums)`，它可以是 0。**
3. **`check` 写成 `cnt == k`** —— 贪心给出的是**最少**段数 `cnt`。若 `cnt < k`，`==` 会判假，但实际可行（可以再劈段）。**必须是 `cnt <= k`。**
4. **`check` 里没处理「单个元素 > limit」** —— 若 `lo` 没取到 `max`（比如取 0），`greedy` 会在第一个超限元素处死循环或错判。**两重保险：`lo = max(nums)`，且 `check` 里显式 `if (x > limit) return INF`。**
5. **构造方案时忘了最后一段** —— 二分只给「最大值是多少」。要输出方案，得再扫一遍；扫描时**最后一段要在循环结束后单独结算**，否则会漏。而且可能出现「怎么切都不足 k 段」的情况（此时需要按 026.3.2 的拆分法补段），**比求值难得多**。
6. **以为有负数也能用贪心** —— 有负数时「能塞就塞」不再最优。反例：`nums = [-1, 5, -1], k = 2`，总和 3。贪心在 `limit = 4` 时：`-1` 塞入，`-1+5 = 4 ≤ 4` 塞入，再 `-1` 变成 3 ≤ 4 塞入 → 1 段 ≤ 2 ✅。但真的只有 1 段吗？…… 实际上 1 段确实可行（3 ≤ 4）。**换个反例**：`nums = [5, -1, -1], k = 2`，`limit = 4`：`5 > 4` 直接判不可能，但 `[5,-1]` 和 `[-1]` 的 max 是 4 ≤ 4，**可行！** —— 贪心因为「单元素 5 > limit」直接判死，**这就是负数导致的失效**。
7. **`k > n` 没判** —— 每段非空，`k > n` 无解。本题约束 `k ≤ n`，但通用写法要判，否则二分返回 `max(nums)`（一个不可行的值）。
8. **`while (lo <= hi)`** —— `hi = mid` 不排除 `mid`，`lo == hi` 时会死循环。**必须 `lo < hi`。**（本批 023 / 025 / 026 共用同一套骨架，坑也共用。）

### 026.6.3 面试官最爱追问的三个问题

**Q1：为什么 `check` 是「段数 ≤ k」而不是「恰好 k 段」？这个放宽凭什么合法？**
> 「因为非负数组上『劈段』不会让最大值变大：把一段和 `S` 劈成 `S₁ + S₂`（`S₁, S₂ ≥ 0`），`max(S₁, S₂) ≤ S`。所以只要贪心用 `cnt ≤ k` 段做到了上限，我就能继续劈，一直劈到恰好 `k` 段（每段非空的前提是 `k ≤ n`，题目保证）。反方向只需一句话：恰好 `k` 段本身就是「至多 `k` 段」的一个特例（`k ≤ k`），所以「至多 `k` 段可行」是「恰好 `k` 段可行」的必要条件。所以两者等价。**这个等价依赖两个前提：非负、`k ≤ n`。** 有负数、或 `k > n`，都得另外处理。」

**Q2：贪心为什么能得到「最少的段数」？**
> 「交换论证。设贪心段是 `G₁..G_t`，任意合法划分是 `P₁..P_s`。可以归纳证明 `end(Gᵢ) ≥ end(Pᵢ)` 对所有 `i` 成立 —— 因为贪心从『不比 `Pᵢ` 更早的位置』开始，且尽量往后塞到『再加一个就超限』，而 `Pᵢ` 必须整段和 ≤ limit，所以 `Pᵢ` 不可能比 `Gᵢ` 伸得更远（否则它的和就超了）。于是若 `t > s`，`G_s` 的终点就 ≥ `P_s` 的终点 = `n-1`，说明贪心在第 `s` 段就覆盖了全部，`t = s`，矛盾。所以 `t ≤ s`。」

**Q3：这题和「DP」比，哪个更好？如果有负数用哪个？**
> 「各有适用面。二分答案 `O(n log sum)`，与 `k` 无关，`n = 1000, k = 50` 时比 DP 快 1600 倍，空间 `O(1)`；但它的 `check` 依赖『非负』，有负数就失效。DP 是 `O(k·n²)`，慢但**能处理负数**（因为 DP 逐个考虑切点，不依赖『段和随长度单调』），而且能直接记录转移来源、输出方案。所以：**面试先讲 DP 展示基本功，再讲二分答案展示优化；如果面试官说『有负数』，就回到 DP。**」

## 附：本章小结（可背走的三句话）

```
① 二分「每段和的上限 L」：check(L) = 贪心最少需要几段 ≤ k；L 越大段数越少 ⇒ 单调
② 「至多 k 段 ⇒ 恰好 k 段」靠非负数组上「劈段不增大最大值」；这是二分答案最典型的"放宽约束再验证"
③ lo = max(nums)（可为 0！）、hi = sum(nums)（用 long）；check 返回「段数≤k」而不是「==k」
```
