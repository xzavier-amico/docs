## 120.1 题目

**原题链接**：<https://leetcode.cn/problems/decode-ways/>

### 题意重述（把隐含条件补齐）

一条只含数字的字符串 `s`，按下面的映射表翻译成字母：

```
'A' -> "1"    'B' -> "2"    ...    'I' -> "9"
'J' -> "10"   'K' -> "11"   ...    'Z' -> "26"
```

问：**一共有多少种不同的翻译方法**。答案只需要「方案数」，不需要列出方案。

一句话就完了，但它藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **编码是 1~26，没有 "0" 这个字母** | 映射表只到 `'Z' -> "26"` | 把 `"0"` 当成一个合法字母 → `"0"` 会返回 1，正确是 0 |
| **两位编码必须在 10~26 之间** | 同上 | `"06"` 被当成 6 → 多算出一种非法方案 |
| **前导零的两位编码非法** | 字母从 `"1"` 开始 | `"06"` / `"00"` 都必须判为不可解码 |
| **问的是方案数，不是最长/最短** | 「请返回解码方法的总数」 | 想成「能不能解码」的布尔 DP，答案类型就错了 |
| **结果只需计数，不需取模** | 约束 `n ≤ 100` | 以为要 `% 1e9+7`（那是 LC 639 的要求），多写一行反而误导 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length <= 100` | n 最多 100 | `2^100 ≈ 1.27·10³⁰`，指数级递归**必然超时**；`O(n²)` 只有 10⁴ 次操作，`O(n)` 是 100 次 |
| `s` 只含数字 | 没有字母干扰 | 可以用 `s[i] - '0'` 直接取值，不用做字符集判断 |
| `s` **可能含前导零**（题面没说不能） | `"0"` / `"06"` 都是合法输入 | 必须显式处理「0 不能单独成字母」 |
| 答案规模 | 「题目保证答案是一个 32 位整数」 | 说明 `int` 够用；真正需要 `long` 的是它的加强版 LC 639（要取模） |

> 💡 **量级 → 算法** 的条件反射在这里再次生效：
> `n ≤ 100` 且问「方案数」→ 这是**计数型 DP** 的典型尺寸，因为方案数本身会指数增长，出题人要么限制 `n`、要么要求取模。
> **看到「方案总数」四个字，第一个念头应该是「按最后一步分类」，而不是「枚举所有切分」。**

### 示例

```text
输入：s = "12"
输出：2
解释："12" 可以拆成 "1"+"2"（AB）或 "12"（L）

输入：s = "226"
输出：3
解释："2"+"2"+"6"（BBF）、"22"+"6"（VF）、"2"+"26"（BZ）

输入：s = "06"
输出：0
解释："06" 不能是 "6"（前导零非法），也不能拆成 "0"+"6"（"0" 不是字母）
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① "0"        → 暴露「把 0 当合法单字符」的错误（正确 0，错解 1）
② "10"       → 暴露「只判 two <= 26 不判 two >= 10」的错误（"0" 会被当成单字符，
                于是 "10" 错算成 2）
③ "100"      → 暴露「两位解码后没有回头检查余下是否合法」的错误（正确 1，错解 2）
④ "11106"    → 暴露「递归不做记忆化」的性能问题，同时也是一个 DP 转移的完整演练
```

第 ② 条是全题最阴的坑：`two = s[i-2]*10 + s[i-1]`，`"10"` 的两位值是 `10`，通过 `10 <= 26`；但 `"06"` 的两位值是 `6`，也通过 `6 <= 26`。**不写 `two >= 10` 这一半，`"06"` 就被当成合法的 6 了。** 换句话说，判两位必须判**区间** `[10, 26]`，不能只判上界。

## 120.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的想法：从左往右扫，每个位置决定「取 1 位」还是「取 2 位」，走到底就是一种方案。

```text
f(i) = 从 s[i] 开始往后，能解出的方案数
     = 0                                         若 i == n（成功走到底）
     = 0                                         若 s[i] == '0'（0 不能起头）
     = f(i+1)                                    只取 1 位
     + f(i+2)  若 i+1 < n 且 10 <= s[i..i+1] <= 26  再取 2 位
```

- 时间：每层最多两个分支，深度 `n` → 上界 **O(2ⁿ)**，实际是斐波那契级 `O(φⁿ)`，`φ ≈ 1.618`。
- 空间：递归栈 `O(n)`。
- 具体数字：`n = 100` 时 `φ¹⁰⁰ ≈ 3.5·10²⁰` 次调用。按每秒 10⁹ 次估算要 **1.1 万年**。这不是「慢一点」，是**根本跑不完**。

### 第二步：卡点在哪

把递归树画出来，问题一眼可见。以 `s = "11106"` 为例（只看前 4 个字符的分支）：

```text
                        f(0) "11106"
                 ┌──────────┴──────────┐
            取1位│                     │取2位("11")
              f(1) "1106"            f(2) "106"
          ┌─────┴─────┐            ┌────┴────┐
     取1位│     取2位 │       取1位│   取2位 │
        f(2)      f(3)          f(3)      f(4)
        "106"     "06"          "06"      "6"
          │         │             │         │
          ▼         ▼             ▼         ▼
       ❌重复     = 0           = 0        = 1
       （f(2) 被算了两次，f(3) 被算了两次）
```

**卡点不是「分支太多」，而是「同一个 `f(i)` 被反复求值」。** `f(2)`、`f(3)` 在树的不同位置重复出现 —— 这正是**重叠子问题**的定义。

一个关键观察：`f(i)` 的**全部输入**只有下标 `i` 一个变量。既然输入只有一个整数，那么 `f` 的取值最多只有 `n+1` 种。**递归树有指数个结点，但不同的子问题只有 `n+1` 个 —— 指数级的浪费全部来自重复。**

### 第三步：灵感的来源 —— 把「函数」换成「表」

既然 `f(i)` 只有 `n+1` 种取值，就开一张长度 `n+1` 的表，从后往前填：

```
dp[i] = 从 s[i] 开始往后能解出的方案数
dp[n] = 1                     ← 空串算「一种方案」，这是所有计数 DP 的哨兵
dp[i] = dp[i+1]（若 s[i] != '0'）
      + dp[i+2]（若 s[i..i+1] 落在 10..26）
```

这就是「**记忆化搜索 = 递推**」的标准转化：**把递归的「从上往下问」改成「从下往上填」**。

### 第四步：为什么要反过来写成「前缀」形式

上面的 `dp[i]` 是**后缀**语义（「从 `i` 开始往后」）。它有个小麻烦：`dp[n] = 1` 这个哨兵的语义是「空后缀有 1 种解法」，初学时很容易和 `dp[0]` 搞混。

更常见、也更好写的写法是**前缀**语义：

```
dp[i] = s 的前 i 个字符（s[0..i-1]）的解法数
dp[0] = 1                                    ← 空前缀 1 种解法（什么都不选）
dp[i] = dp[i-1]   若 s[i-1] != '0'          ← 第 i 个字符单独成字母
      + dp[i-2]   若 10 <= s[i-2..i-1] <= 26  ← 最后两个字符合成一个字母
```

两个写法的**答案完全一样**，但前缀形式的三个好处很实在：

1. **下标与长度对齐**：`dp[i]` 里 `i` 就是「已经处理了几个字符」，循环 `for i in 1..n` 天然不越界。
2. **哨兵只有一个**：`dp[0] = 1`，`dp[1]` 由它推出，不需要为 `n = 1` 单独写分支。
3. **前导零判定更自然**：判断「0 单独出现」只需要看 `s[i-1]`，判断「两位合法」只需要看 `s[i-2]`、`s[i-1]`。

> **这就是本章要建立的第一个反射**：计数型一维 DP，**先想「最后一步是谁」，再决定用前缀还是后缀**。本题的「最后一步」就是「最后一个字母占了 1 位还是 2 位」，而「最后」天然对应前缀 DP。

## 120.3 原理拆解

### 120.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力递归（无记忆化） | O(φⁿ) | O(n) 栈 | 12 行 | `n ≥ 40` 就开始明显卡；`n = 100` 直接不可能 |
| 记忆化搜索（自顶向下） | O(n) | O(n) + O(n) 栈 | 20 行 | 递归深度受栈限制（本题 n ≤ 100 无碍，10⁵ 就爆栈） |
| 递推 + 一维数组（自底向上） | O(n) | O(n) | 15 行 | 想再省空间时被滚动数组比下去 |
| **递推 + 两个滚动变量** ✅ | **O(n)** | **O(1)** | **14 行** | 需要「输出所有方案」时不够用（那要回溯） |
| 回溯枚举所有方案 | O(方案数 × n) | O(n) | 25 行 | 方案数指数级，本题只问数量，用它是杀鸡用牛刀 |

**为什么滚动数组在这题「免费」**：转移只用到 `dp[i-1]` 和 `dp[i-2]` 两个值，更早的值填完就再也读不到了。所以两个变量 `prev2`、`prev1` 就够 —— 这不是「为了秀技巧」，而是**状态依赖的宽度只有 2** 的自然结果。

### 120.3.2 为什么这个做法是对的（正确性论证）

**命题**：设 `dp[i]` 为 `s[0..i-1]` 的解码方案数，则上面的转移方程给出的 `dp[n]` 恰好等于真实方案数。

**证明分三步：分类互斥、分类完备、无遗漏无重复。**

**（1）分类完备**：任何一个合法解码方案，其**最后一个字母**必然对应 `s` 的最后 1 个字符（单字符编码）或最后 2 个字符（双字符编码）—— 因为编码只可能是 1 位或 2 位（26 最多两位），所以「最后一块」的边界只有这两种可能。因此所有方案都落进这两类之一。

**（2）分类互斥**：一个方案的「最后一块」长度是 1 就**不可能**同时是 2。所以两类方案的交集为空。

**（3）两类各自的计数**：
- 「最后一块占 1 位」的方案，去掉最后一个字母后，前缀 `s[0..i-2]` 必须是一个合法解码 —— 这样的方案数恰为 `dp[i-1]`。但这个类非空的前提是 `s[i-1] != '0'`，因为 `"0"` 没有对应字母。
- 「最后一块占 2 位」的方案，去掉最后一个字母后，前缀 `s[0..i-3]` 必须是合法解码 —— 方案数恰为 `dp[i-2]`。这类非空的前提是两位数值在 `[10, 26]`。

两类的计数都是**双射**（每个前缀方案 + 固定的最后一块 ↔ 一个完整方案），所以直接相加不重不漏。

**（4）归纳**：`dp[0] = 1`（空串唯一方案是「什么都不解」，这是计数 DP 的空元）。假设 `dp[0..i-1]` 都正确，则由 (1)(2)(3) 得 `dp[i]` 正确。∎

> **`dp[0] = 1` 为什么不是 0**：这是初学者最大的困惑。`dp[0]` 不是「长度为 0 的串有几种方案」这个哲学问题，而是**为了让递推式在 `i = 2` 时成立**的一个约定：`"12"` 可以整体作为一个双字符编码，此时「去掉最后一块」剩下空串，空串必须贡献 1 种（唯一的空方案），总数才是 1（来自 `dp[2] = dp[1] + dp[0] = 1 + 1 = 2`）。如果 `dp[0] = 0`，`"12"` 会算成 1，漏掉「整体编码」这一种。

### 120.3.3 通用解题思路（可迁移的那一层）

先把这个系列统一的 **DP 四步法**（出处见 [`108-climbing-stairs.md`](108-climbing-stairs.md)）在本题上走一遍，后面 11 章都会复用这套语言：

| 步骤 | 要回答的问题 | 本题的答案 |
| --- | --- | --- |
| **① 状态定义** | `dp[...]` 一句话说清是什么 | `dp[i]` = `s` 前 `i` 个字符的解码方案数 |
| **② 转移方程** | `dp[i]` 从哪些更小的状态来 | `dp[i] = dp[i-1]·[s[i-1]≠'0'] + dp[i-2]·[10≤两位≤26]` |
| **③ 初始化与边界** | 最小的那些状态是谁、空输入怎么办 | `dp[0] = 1`；`dp[1] = 1` 若 `s[0]≠'0'` 否则 0 |
| **④ 遍历顺序与答案** | 谁能保证「用到时已经算好」 | `i` 从 1 递增到 `n`（依赖更小的下标）；答案 `dp[n]` |

四步里**最容易写错的是 ③**，最容易想不出来的是 ②。而 ② 的通用套路是：

```
把「一个方案的构造过程」拆成「最后一个决定」
         ↓
对所有可能的「最后一个决定」做互斥完备的分类
         ↓
每一类 = 一个更小的同类子问题（这就是转移）
```

本题的「最后一个决定」是「最后一个字母取 1 位还是 2 位」。把这个套路记住，遇到 `139 单词拆分`（最后一个单词取哪一段）、`132 分割回文串 II`（最后一段回文取哪一段）时，是同一套动作。

**属于同一模型的题**：

| 题 | 「最后一个决定」是什么 |
| --- | --- |
| [LC 70 爬楼梯](https://leetcode.cn/problems/climbing-stairs/) | 最后一步跨 1 阶还是 2 阶 |
| [LC 91 解码方法](https://leetcode.cn/problems/decode-ways/)（本题） | 最后一个字母占 1 位还是 2 位 |
| [LC 139 单词拆分](https://leetcode.cn/problems/word-break/) | 最后一个单词从哪儿切 |
| [LC 132 分割回文串 II](https://leetcode.cn/problems/palindrome-partitioning-ii/) | 最后一段回文从哪儿切 |
| [LC 746 使用最小花费爬楼梯](https://leetcode.cn/problems/min-cost-climbing-stairs/) | 最后一步从哪一级上来 |

**共同点**：都是「一维位置 + 有限种『最后一步』」→ 转移只回看常数个位置 → 时间 `O(n·k)`、空间可压到 `O(k)`。

### 120.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 数字里出现 `'*'`（可代表 1~9） | 一位 / 两位的合法性判定变成「按 `'*'` 分情况」 | 就是 [LC 639 解码方法 II](https://leetcode.cn/problems/decode-ways-ii/)，转移的**结构不变**，只是每类要乘以「`'*'` 的取值个数」 |
| 答案要求对 `10⁹+7` 取模 | 计数会溢出 | 每步相加后取模；Java 用 `long` 中转再转 `int`，Go 天然 64 位 `int` |
| 允许 3 位编码（1~999） | 「最后一块」从 2 种变成 3 种 | 转移加一项 `dp[i-3]`，滚动变量变 3 个；**结构完全没变** |
| 要**输出所有**解码方案 | 从「计数」变「枚举」 | 退回回溯：决策树 + 路径记录，复杂度 `O(方案数 × n)` |
| `n` 放大到 `10⁷` | 内存/时间吃紧 | `O(n)` 时间已最优（必须读一遍输入）；空间用两个变量已是 `O(1)` |
| 要求「字典序最小的解码」 | 从计数变构造 | 贪心：能取 1 位就取 1 位（但要注意 `"10"` 必须取 2 位），可用 DP 预处理合法性后正着贪心 |

**延伸验证（自己写代码跑）**：把 `dp` 从「两个变量」改回「一维数组」，打印 `dp` 全表，观察 `"11106"` 的 `dp` 序列 —— 你会看到 `1, 2, 3, 3, 3` 这样的形态，这就是「斐波那契被条件打断」的样子。

## 120.4 图解推演

### 120.4.1 `s = "226"` 的 DP 表逐格填

```
下标语义：dp[i] 管的是 s[0..i-1] 这 i 个字符
          s = [ '2'  '2'  '6' ]
                 ↑0    ↑1    ↑2

        i:   0     1     2     3
            ┌─────┬─────┬─────┬─────┐
   dp[ ]:   │  1  │  1  │  2  │  3  │
            └─────┴─────┴─────┴─────┘
              ▲     ▲     ▲     ▲
              │     │     │     └── dp[3] = dp[2](取'6') + dp[1](取"26") = 2 + 1 = 3
              │     │     └──────── dp[2] = dp[1](取'2') + dp[0](取"22") = 1 + 1 = 2
              │     └────────────── dp[1] = dp[0]('2' 合法)            = 1
              └──────────────────── 哨兵：空前缀 1 种方案
```

逐步推演表：

| 步骤 `i` | 末位字符 `s[i-1]` | 单字符合法？ | 末两位 `s[i-2..i-1]` | 双字符合法？ | `dp[i]` |
| --- | --- | --- | --- | --- | --- |
| 0 | — | — | — | — | **1**（哨兵） |
| 1 | `'2'` | 是（非 `'0'`） | 无 | — | `dp[0]` = **1** |
| 2 | `'2'` | 是 | `"22"` = 22 | 是（10..26） | `dp[1]+dp[0]` = **2** |
| 3 | `'6'` | 是 | `"26"` = 26 | 是（10..26） | `dp[2]+dp[1]` = **3** |

### 120.4.2 三个反例的轨迹（暴露三种写法错误）

```
❌ 反例 ①：s = "0"
   dp[0]=1
   i=1: s[0]=='0' → 单字符不合法，不加 dp[0]
        无两位 → dp[1] = 0                       ✅ 正确答案 0

❌ 反例 ②：s = "10"   （只判 two <= 26 的错误写法）
   i=1: s[0]='1' 合法 → dp[1] = 1
   i=2: s[1]='0' → 单字符不合法
        two = 10，若只判 two <= 26 → 不加 dp[0] 的写法会漏；若判 0<=two<=26
        且把 '0' 当单字符，则 dp[2] = dp[1] + dp[0] = 2          ❌ 错，正确 1
   正确写法：'0' 不能单字符；two=10 ∈ [10,26] → dp[2] = dp[0] = 1  ✅

❌ 反例 ③：s = "100"
   i=1: '1' → dp[1] = 1
   i=2: '0' 不能单字符；two="10"=10 合法 → dp[2] = dp[0] = 1
   i=3: '0' 不能单字符；two="00"=0 < 10 不合法 → dp[3] = 0          ✅ 正确 0
   （"100" 只能拆成 "10"+"0"，而 "0" 不是字母 → 0 种）
```

把这三条并排放，能看清一件事：**「前导零」的问题不是某一行写错了，而是必须同时在两个地方判 —— 单字符位置判 `!= '0'`，双字符位置判 `>= 10`。**

### 120.4.3 前缀 DP 与后缀 DP 的路线对比

```
                  ┌──────── 输入 s[0..n-1] ────────┐
                  │                                │
      ┌───────────▼───────────┐        ┌───────────▼───────────┐
      │ 路线 A：前缀 dp[i]     │        │ 路线 B：后缀 f(i)      │
      │ = 前 i 个字符的方案数   │        │ = 从 i 开始的方案数    │
      └───────────┬───────────┘        └───────────┬───────────┘
                  │                                │
        i: 1 → n（正着填）                 i: n-1 → 0（倒着填）
        依赖 dp[i-1], dp[i-2]             依赖 f(i+1), f(i+2)
                  │                                │
        答案 dp[n]                        答案 f(0)
                  │                                │
        ✅ 哨兵只有一个 dp[0]=1            ⚠️ 哨兵 f(n)=1，语义是"空后缀"
        ✅ 前导零判定落在一个位置           ⚠️ i+2 越界要单独判
                  │                                │
            【本章采用 A】                  【记忆化搜索常写 B】
```

两种写法**答案必然相同**，但 A 的边界更少、越界更少。**面试时如果先想到 B，写完之后建议口头补一句「也可以改写成前缀形式，少一个越界判断」，这是加分项。**

## 120.5 双语言实现

### 120.5.1 Java

```java
class Solution {
    public int numDecodings(String s) {
        int n = s.length();

        // prev2 = dp[i-2], prev1 = dp[i-1]
        // 初始等价于 i = 0 与 i = 1 两格：dp[0] = 1；dp[1] 只看 s[0] 是否为 '0'
        int prev2 = 1;
        int prev1 = s.charAt(0) == '0' ? 0 : 1;

        // 注意从 i = 2 开始：dp[1] 已经在上面算好了，
        // 如果从 i = 1 开始，会把 dp[1] 重复算一次并覆盖 prev2，导致 dp[i-2] 错位
        for (int i = 2; i <= n; i++) {
            int cur = 0;

            // 分支一：s[i-1] 单独作为一个字母。'0' 没有对应字母，所以必须排除
            if (s.charAt(i - 1) != '0') {
                cur += prev1;
            }

            // 分支二：s[i-2..i-1] 合成一个字母。必须判「区间」[10, 26]，
            // 只判 <= 26 会把 "06"(=6) 误判为合法，这是本题第一号 bug
            int two = (s.charAt(i - 2) - '0') * 10 + (s.charAt(i - 1) - '0');
            if (two >= 10 && two <= 26) {
                cur += prev2;
            }

            // 滚动：先存 prev1 再更新 prev1，顺序写反会让 prev2 拿到新的 prev1
            prev2 = prev1;
            prev1 = cur;
        }

        // n == 1 时循环没执行，prev1 就是 dp[1]，正确；
        // 题目保证 n >= 1，所以不需要处理空串
        return prev1;
    }
}
```

### 120.5.2 Go

```go
package main

func numDecodings(s string) int {
	n := len(s)
	if n == 0 {
		// 题面约束 n >= 1，这里只是让函数对空串也返回合法值（0 种方案）
		return 0
	}

	// prev2 对应 dp[i-2]，prev1 对应 dp[i-1]
	prev2 := 1
	prev1 := 0
	if s[0] != '0' {
		prev1 = 1
	}

	for i := 2; i <= n; i++ {
		cur := 0
		// s[i] 是 byte：本题字符集只有 ASCII 数字，用 byte 取字符既快又不会错
		if s[i-1] != '0' {
			cur += prev1
		}
		// 用 int 显式转出来再算两位数，避免 byte 相减后直接和 26 比较造成的可读性问题
		two := int(s[i-2]-'0')*10 + int(s[i-1]-'0')
		if two >= 10 && two <= 26 {
			cur += prev2
		}
		// Go 支持多重赋值，等价于 Java 里那条「用临时变量」的两步滚动
		prev2, prev1 = prev1, cur
	}

	return prev1
}
```

### 120.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 取字符 | `s.charAt(i)` 返回 `char`（16 位无符号） | `s[i]` 返回 `byte`（8 位） | 本题字符集是纯 ASCII 数字，两种都安全；若字符串含中文，Go 必须转 `[]rune` |
| 字符串长度 | `s.length()` 是方法 | `len(s)` 是内建函数（返回**字节数**） | 纯数字串两者一致；含多字节字符时 Go 的 `len` 会偏大 |
| 滚动赋值 | 必须用临时变量：`prev2 = prev1; prev1 = cur;` | 可写 `prev2, prev1 = prev1, cur` | Go 的多重赋值天然避免「顺序写反」的 bug，Java 写反了也不会报错，只会答案错 |
| 字符相减 | `char - '0'` 得到 `int` | `byte - '0'` 得到 `byte`，要 `int(...)` 提升 | Go 里不提升会在 `two` 超过 255 时… 本题最多 99，不会溢出，但混用类型编译不过 |
| 空串处理 | `s.charAt(0)` 会抛 `StringIndexOutOfBoundsException` | `s[0]` 会 panic | 两边都必须先判 `n == 0`（题面保证不出现，但防御性代码更稳） |

### 120.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：显式枚举「每个位置切 1 位还是 2 位」，指数级但绝对正确
func bruteDecode(s string) int {
	var dfs func(i int) int
	dfs = func(i int) int {
		if i == len(s) {
			return 1 // 成功走到末尾 = 一种方案
		}
		if s[i] == '0' {
			return 0 // 0 不能起头
		}
		cnt := dfs(i + 1) // 取 1 位
		if i+1 < len(s) {
			if v := int(s[i]-'0')*10 + int(s[i+1]-'0'); v >= 10 && v <= 26 {
				cnt += dfs(i + 2) // 取 2 位
			}
		}
		return cnt
	}
	return dfs(0)
}

func TestDecodeWaysRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20240120))

	// 先跑一批手写边界
	edge := []string{"0", "1", "9", "10", "06", "100", "226", "11106", "27", "301", "1201234"}
	for _, s := range edge {
		if got, want := numDecodings(s), bruteDecode(s); got != want {
			t.Fatalf("edge s=%q got=%d want=%d", s, got, want)
		}
	}

	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(14)
		b := make([]byte, n)
		for i := range b {
			// 值域 0~9，但刻意提高 0 与 1、2 的比例，让前导零与 26 边界高频出现
			switch r.Intn(4) {
			case 0:
				b[i] = '0'
			case 1:
				b[i] = byte('1' + r.Intn(2))
			default:
				b[i] = byte('0' + r.Intn(10))
			}
		}
		s := string(b)
		if got, want := numDecodings(s), bruteDecode(s); got != want {
			t.Fatalf("iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
	}
}
```

> **为什么值域要刻意偏向 `'0'`、`'1'`、`'2'`**：本题的 bug 全部藏在三个地方 ——「0 不能单字符」「两位必须 ≥ 10」「两位 ≤ 26 的上界由 `'2'` 后面的字符决定」。均匀随机的数字串里，`'0'` 只占 10%，很多错误要跑很久才暴露；加权之后 2 万次内必然命中。

## 120.6 复杂度与常见坑

### 120.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：循环从 `i = 2` 到 `n`，恰好 `n-1` 次迭代；每次迭代内是常数次算术（一次减法、一次乘加、两次比较），没有内层循环。所以总操作数 `≈ 5n`。**为什么不可能更快**：任何正确算法都必须至少读一遍 `s` 的每个字符（`'0'` 的信息只在字符本身），读入就是 `Ω(n)`。所以 `O(n)` 是**最优**，不是「还行」。
- **空间 O(1)**：只用了 `prev2`、`prev1`、`cur` 三个整型变量。**为什么能压到 O(1)**：转移的「回看宽度」是 2（只看 `i-1` 和 `i-2`），一旦算完 `dp[i]`，`dp[i-2]` 就永远用不到了。这是「**滚动数组的判据**」：**回看宽度 k → 保留 k 个变量**。
- 若改成 `dp` 数组：空间 `O(n)`。`n = 100` 时 400 字节，无所谓；但把同一套代码搬到 `n = 10⁷` 的场景，`O(n)` 的 `int[]` 是 40 MB，`O(1)` 是 8 字节 —— 差别在这里。

### 120.6.2 七个真实踩过的坑

1. **只判 `two <= 26` 不判 `two >= 10`** —— `"06"` 的两位值是 6，会被当成合法。这是本题第一大坑，`"10"`、`"100"`、`"06"` 三个反例都能打出来。
2. **把 `dp[0]` 初始化成 0** —— 那么 `"12"` 会算成 1（丢掉了「整体编码」），`"226"` 会算成 2（正确 3）。`dp[0] = 1` 是**为了让递推式成立**的约定，不是「空串有 1 种解码」的语义解读。
3. **循环从 `i = 1` 开始** —— 而此时 `prev1` 已经代表 `dp[1]`，再算一遍会把 `prev2` 冲掉，`dp[i-2]` 整体错位一格。正确起点是 `i = 2`。
4. **滚动赋值顺序写反** —— 先 `prev1 = cur` 再 `prev2 = prev1`，则 `prev2` 拿到的是新的 `prev1`（等于 `cur`），`dp[i-2]` 变成 `dp[i]`，`"226"` 会输出 5 而不是 3。Go 的多重赋值不会犯这个错，Java 会。
5. **`"0"` 单独输入时返回 1** —— 因为 `s[0] == '0'` 被漏判，递归/递推都走了「取 1 位」分支。修法：`dp[1] = (s[0] != '0') ? 1 : 0`。
6. **`n == 1` 时答案被返回两次错误值** —— 有人写了 `if (n == 1) return 1;` 直接短路，于是 `"0"` 返回 1。正确做法是让循环与初始值自然覆盖 `n == 1`（本章代码就是这样）。
7. **以为答案要取模** —— 本题 `n ≤ 100`，方案数是斐波那契级 `φ^100 ≈ 3.5·10²⁰`…… 等一下，这会超过 `int`！但题面写「题目数据保证答案是一个 32 位整数」，意思是**测试数据里不会出现超过 `int` 的答案**（大量 `'0'` 会把方案数压到 0/1）。真要做加强版（允许任意 `n`）必须取模，见 LC 639。

> 第 7 条值得停一下：**「题目保证答案在 int 范围内」是一个必须读到的约束**。同一道题的加强版若不保证，`int` 会静默溢出成负数，而不会报错 —— 这类 bug 在面试里非常致命，因为它「跑得通、答得错」。

### 120.6.3 面试官最爱追问的三个问题

**Q1：为什么 `dp[0]` 是 1 而不是 0？**

> 「因为它是**转移方程的边界条件**，不是对空串的语义判断。`"12"` 可以整体作为一个双字符编码，此时『去掉最后一块』剩下空串，空串必须贡献 1（唯一空方案），总数才是 2。如果 `dp[0] = 0`，`"12"` 会算成 1，漏掉整体编码这一种。这类哨兵在计数 DP 里是通用的：**所有『恰好用完』的计数问题，空状态的计数都是 1。**」

**Q2：能不能不判 `two >= 10`，直接在前面把 `'0'` 拦掉？**

> 「不能。`"06"` 的第一位是 `'0'`，确实能被单字符分支拦掉；但 `"226"` 里 `"22"`、`"26"` 都合法，而 `"30"` 的 `"30"` 是 30 > 26 不合法、`"10"` 的 `"10"` 是 10 合法 —— 判断两位合法性**唯一正确的依据是数值落在 `[10, 26]`**，`>= 10` 这一半正是为了排除 `"0x"` 这种前导零。少写一半，`"06"`、`"00"`、`"09"` 全部漏判。」

**Q3：如果字符串长度到 10⁷，你的代码还能用吗？**

> 「时间没问题，`O(n)` 已是下界。但有三处要改：① Java 的 `String.charAt` 在 `n = 10⁷` 时仍然可用，只是把 `String` 转成 `char[]` 会多一份内存，不如直接用 `charAt`；② 不需要 `O(n)` 数组，滚动两个变量已经 `O(1)`；③ 真正的瓶颈是**输入本身**——10⁷ 字符约 10 MB，读入占大头。如果答案要取模，每步取模即可，不影响复杂度。」
