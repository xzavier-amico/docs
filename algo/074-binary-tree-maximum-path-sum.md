## 074.1 题目

**原题链接**：<https://leetcode.cn/problems/binary-tree-maximum-path-sum/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root`（节点值可以为负数），请返回**任意一条路径**上节点值之和的最大值。这里的「路径」被定义为：从树中某个节点出发，沿父子边走到另一个节点，途中**每个节点最多出现一次**的一条链。路径可以**只含一个节点**，也**不必经过根节点**。

题干只有三行，但它藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 路径**至少含一个节点** | 「一条路径」的定义 | 遇到全负树时按「空路径 = 0」处理 → `[-3]` 返回 0，正确答案是 −3 |
| 路径**不必经过根节点** | 「任意一条路径」 | 只在根上做一次左右合并 → 漏掉藏在子树内部的最优路径 |
| 路径**是简单链，不能分叉** | 「沿父子边走」 | 允许左右两边同时向上延伸 → 把两个分叉拼成一条「假路径」，值偏大 |
| 节点值**可以为负数** | 约束 `-1000 <= Node.val <= 1000` | 无脑对贡献 `max(0, ·)`，连全局答案也被夹到 0 |
| 返回**数值**，不是路径、不是打印 | 「返回……最大路径和」 | 打印到标准输出 / 返回 `List` → 判题拿不到结果 |

> 最容易被读漏的是第三条。**「路径」在树上是一个度 ≤ 2 的连通块**：它可以有一个「最高点」向左右各岔一次，但**绝不能岔第二次**。整道题的难点全部来自这一句。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `1 <= n <= 3·10⁴` | 最多 3 万个节点 | **O(n²) = 9·10⁸ 次访问**，2 核容器实测 Java ≈ 4~8 s、Go ≈ 2~4 s → **必 TLE**；只有 O(n) 能过 |
| `-1000 <= Node.val <= 1000` | 有负数、有零、可重复 | 不能假设「都为正」；也不能用值做任何标记位 |
| 和的上界 = `3·10⁴ × 1000 = 3·10⁷` | 远小于 `2.147·10⁹` | **Java `int` / Go `int` 全程安全**；但只要值域放大到 `10⁵`，就必须换 `long` / `int64`（`3·10⁴ × 10⁵ = 3·10⁹` 已越界） |
| 树形状不限 | 可以是链 | 链状树 `h = n = 3·10⁴`，递归深度 3 万层 → 默认栈可能被打穿（见 §074.6.2 第 5 条） |

> 💡 **量级 → 算法** 的读法：`n = 3·10⁴` 意味着「O(n log n) 勉强、O(n²) 出局」。而树上 O(n) 的标准形态就是**一次后序遍历**：每个节点只被访问常数次。**看到 3·10⁴ 的树，先问自己「能不能每个节点只算一次」。**

### 示例

```
示例 1
输入：root = [1, 2, 3]
输出：6
解释：最优路径 2 → 1 → 3，和 = 2 + 1 + 3 = 6

        1
       ┌┴┐
       2 3

示例 2
输入：root = [-10, 9, 20, null, null, 15, 7]
输出：42
解释：最优路径 15 → 20 → 7，和 = 15 + 20 + 7 = 42（注意：不经过根 −10！）

        -10
       ┌──┴──┐
       9     20
            ┌┴┐
           15 7

示例 3
输入：root = [-3]
输出：-3
解释：路径只能含这一个节点，你不能「什么都不选」返回 0
```

### 我自造的四个反例（写完必须拿它们打一遍）

```text
① [-3]                 → 单结点全负：暴露「用 0 当答案初值」
② [-2, -1]             → 全负两结点：正确答案 −1（单结点 −1 更优），暴露「负数贡献被 clamp 后答案变 0」
③ [1, -100, null, 50]  → 最优路径是孤零零的 50（不经过 −100、不经过根 1），
                          错误算法（把「子树最优路径」当贡献）会算成 1 + 50 = 51
④ [-1, -2, -3] 的退化链 → 深度与负值叠加：正确答案 −1，暴露「递归里用局部最优当全局答案」
```

第 ③ 条是本章的**核心反例**，它精确地打死了「分治三个候选」的错误直觉 —— 因为它要的不是「子树里的最优路径」，而是「从子树根向下单边延伸的最大和」。这两个量在正数树上经常相等，一旦出现负数就会分叉。§074.4.3 会给它的完整轨迹。

## 074.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先把「所有路径」真的枚举一遍）

「路径」在树上由两个端点唯一确定，所以最诚实的暴力是：**对每个端点 `u`，把树当成无向图做一次 DFS，把所有「从 `u` 出发」的路径和都算出来**，再对 `u` 取全局最大。

```java
// 暴力：O(n²) —— 对每个起点 u 做一次全树 DFS，路径和随 DFS 累加
int brute(TreeNode root) {
    List<TreeNode> nodes = new ArrayList<>();   // 先收集所有节点
    collect(root, nodes);

    int best = Integer.MIN_VALUE;               // 必须从 −∞ 起，不能用 0
    for (TreeNode start : nodes) {
        // 从 start 出发，parent 用来挡住「回头路」，保证路径不重复经过节点
        walk(start, null, 0, bestHolder);
    }
    return best;
}

void walk(TreeNode x, TreeNode parent, int sum, int[] best) {
    sum += x.val;                               // 路径和：沿路累加
    best[0] = Math.max(best[0], sum);
    for (TreeNode nb : new TreeNode[]{x.left, x.right}) {
        if (nb != null && nb != parent) walk(nb, x, sum, best);  // 只往没走过的方向走
    }
}
```

- 时间 **O(n²)**：每个起点做一次遍历，`n` 个起点 → `n·n` 次访问。`n = 3·10⁴` 时是 **9·10⁸ 次**，实测 Java ≈ 4~8 s、Go ≈ 2~4 s，**必然 TLE**。
- 空间 **O(h)**（`h` 为树高）。

注意：它**本身是对的**（`parent` 参数保证路径不打转），只是慢。这一点很重要 —— **暴力的价值在于「它给出了判定标准」**：后面写随机对拍时，参考实现就是它（见 §074.5.4）。

### 第二步：卡点在哪

暴力在做什么重复劳动？把 `u` 固定之后，它把整棵树又走了一遍。但**同一棵子树在「不同的起点」下被反反复复地走**：叶子 `15` 在起点为 `15`、`20`、`7`、`-10` 时各被走过一次。

> **卡点：每一条「向下的链」的和，被计算了 n 次，而它其实只跟「链的顶端」有关。**

只要我们能对每个节点 `x` 预先算出「**从 `x` 出发向下走的最大和**」，那么「以 `x` 为最高点的所有路径」的最优值就能 O(1) 拼出来：

```
经过 x 的最优路径和 = (x 向左下的最优链) + val(x) + (x 向右下的最优链)
```

而「向下的最优链」这种东西，可以**自底向上一次算完** —— 这是后序遍历的天然领地。

### 第三步：灵感的来源 —— 「每条路径都有唯一的最高点」

把任意一条路径 `u ⇝ v` 摊平看，它在树里一定有**唯一一个**最高节点 `h`（离根最近的节点，也是 `u`、`v` 的最近公共祖先）。于是：

```
任意路径 u ⇝ v  ⟺  h 向左下走到 u 的一段 + h 向右下走到 v 的一段
                  （u == h 或 v == h 时，其中一段为空）
```

这个分解是本章的**全部秘密**：它把一个「两端自由」的问题，变成「在每个 `h` 上问一次『左上最优 + 自己 + 右下最优』」。

于是定义两个量，并且**它们必须分开**：

| 量 | 定义 | 谁来用 |
| --- | --- | --- |
| **贡献** `gain(x)` | 从 `x` 出发、**只向下走**（不许分叉）能得到的最大和 | 交给 `x` 的**父结点**去拼接 |
| **答案** `best` | **任意**一条完整路径的最大和（可以分叉一次） | 最终返回值 |

$$
gain(x) = val(x) + \max\bigl(0,\; gain(left),\; gain(right)\bigr)
\qquad
best = \max_{x}\bigl(\; \max(0,gain(left)) + val(x) + \max(0,gain(right)) \;\bigr)
$$

> `max(0, ·)` 的语义是「这一段**可以不选**」：从 `x` 往下走，发现某边是负数，那就不往那边走（路径到 `x` 就停），所以 `gain` 的下限就是「只走自己」= `val(x)`。
> ⚠️ 但 `max(0, ·)` **只能用在贡献里，绝不能用在答案上** —— 答案至少要含一个节点，全负树上它必须是负数。

这里还藏着**串行的顺序**：`best` 必须在「左右都算完、还没 return」的那一刻结算 —— 这正是后序遍历的「根」位置。

## 074.3 原理拆解

### 074.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力枚举所有路径（每起点一次 DFS） | O(n²) | O(h) | 20 行 | `n = 3·10⁴` → 9·10⁸ 次访问，TLE；但它是**对拍的标准答案** |
| 「三候选」错误分治：`max(左最优, 右最优, 左最优+根+右最优)` | 号称 O(n) | O(h) | 12 行 | **正确性直接崩**：子树最优路径可能不经过子结点，无法嫁接（反例 ③ 给 51，真值 50） |
| **后序树形 DP（贡献值）** ✅ | **O(n)** | **O(h)** | **12 行** | 链状树 `h = n = 3·10⁴` 时递归可能爆栈 → 换迭代后序 |
| 迭代后序（显式栈 + 访问标记） | O(n) | O(h) | 30 行 | 代码长、易写错；只有在「禁止递归」或「树深不可控」时才值得 |
| Morris 后序（O(1) 空间） | O(n) | **O(1)** | 50 行 | 会临时改树、极难写对；本题没有空间压力，收益为零 |

**取舍一句话**：**默认用递归后序**（12 行、常数最小、可读性最好）；只有当「树深由外部输入决定，可能到 10⁶」时，才换成显式栈的迭代后序。Morris 在这里唯一的用途是「面试官追问 O(1) 空间时，你能说出思路」。

### 074.3.2 为什么这个做法是对的（正确性论证）

**引理 1（路径有唯一最高点）**：任取一条合法路径，其节点集合在树中连通且度数 ≤ 2，因此它是一条链；链上离根最近的节点唯一，记为 `h`。链在 `h` 处最多向两个方向（左子树 / 右子树）延伸，且每个方向只延伸一段。∎

**引理 2（贡献的递推是对的）**：`gain(x)` 恰为「从 `x` 出发、只向下走的所有链」中的最大和。

> 归纳证明。叶子：`gain = val(x)`，唯一的向下链就是它自己，成立。
> 内点：任取一条从 `x` 向下的链，它要么只有 `x`（和为 `val(x)`），要么先走到左孩子（其后是一段从 `left` 向下的链，最优和 ≤ `gain(left)`），要么先走到右孩子（同理 ≤ `gain(right)`）。所以这条链的和 ≤ `val(x) + max(0, gain(left), gain(right)) = gain(x)`，并且这个上界**能取到**（选那个最大的一边继续走，若两边都负就停在 `x`）。取到上界即得最优。∎

**定理（枚举所有最高点不重不漏）**：设 `OPT` 是全局最优路径和。由引理 1，`OPT` 对应某个最高点 `h`，且 `OPT = S_left + val(h) + S_right`，其中 `S_left`、`S_right` 分别是 `h` 向左下 / 右下两段的和（可以为空，空段记 0）。由引理 2，`S_left <= max(0, gain(left))`、`S_right <= max(0, gain(right))`，故

```
OPT <= max(0,gain(h.left)) + val(h) + max(0,gain(h.right)) <= best
```

反过来，对每个 `x`，`max(0,gain(h.left)) + val(x) + max(0,gain(x.right))` **都对应一条真实路径**（左边取到的那条链 + `x` + 右边取到的那条链，两条链在 `x` 处汇合，互不相交，度数 ≤ 2），所以 `best <= OPT`。两向夹逼得 `best = OPT`。∎

> **这个论证的价值**：它同时解释了三件最容易搞混的事 —— ① 为什么 `gain` 要 `max(0,·)`（允许「不往下走」）；② 为什么答案不能 `max(0,·)`（最优路径至少一个节点，`best` 的候选里已经含 `val(x)` 本身）；③ 为什么不能把「子树最优路径」当贡献（引理 2 的最优链**必须经过 `x` 且不分叉**，而子树最优路径可能两者都不满足）。

### 074.3.3 通用解题思路（可迁移的那一层）

本章确立的是**树形 DP 的「两量分离」模型**，它是整个第 8 部分最重要的一把尺子：

```
遇到「树上最优 XX」时，先问三个问题（比 065 的递归三问再进一步）：

  ① 交付量：父结点需要我提供什么？        → 往往是「单边」的：一条链 / 一个高度 / 一个状态
       └─ 单边的意思：只能往一个方向延伸，因为父结点那边还要接它自己的父亲
  ② 结算量：答案在哪一刻、用哪个式子产生？  → 往往在「左右都算完」的后序位置
  ③ 二者的关系：结算量 = 左交付 + 自己 + 右交付，交付量 = 自己 + max/min(左交付, 右交付)
```

> 📖 **术语对照**：068 / 071 把「交付量」叫作「**上传量／可上传量**」、把「结算量」叫作「**局部答案**」——
> 这是同一组概念的两套叫法。本章统一用「交付量 / 结算量」，读到 068 / 071 时按这个对照换一下即可。

**贡献回流图**（本章的招牌图，务必记住箭头方向）：

```
                 ┌──────────── 自底向上：交付（gain）────────────┐
                 │                                            │
        gain(左子树) ─┐                                        │
                      ├─→  val(x) + max(0, gain左, gain右)  ────┘   ↑ 只能带 1 个孩子
        gain(右子树) ─┘         （这是"给父亲的单边链"）             │
                                                                  │
                 ┌──────────── 就地结算：答案（best）────────────┐
                 │                                            │
        max(0,gain左) ─┐                                       │
                       ├─→  left + val(x) + right  ──→ best = max(best, ·)
        max(0,gain右) ─┘         （这是"完整路径"，可岔一次）    │
                 └────────────────────────────────────────────┘
```

**同一模型的题目（背下这张表，等于背下 6 道题）**：

| 题 | 交付量（返回给父亲） | 结算量（全局答案） | 一句话差异 |
| --- | --- | --- | --- |
| [068 二叉树的最大深度](068-maximum-depth-of-binary-tree.md) | 子树高度 | 不需要（交付量就是答案） | 退化情形：只有交付 |
| [071 二叉树的直径](071-diameter-of-binary-tree.md) | 子树高度 | `左高 + 右高` | 交付「高度」，结算「边数」 |
| **074 最大路径和（本章）** | 单边最大链和 | `左贡献 + 自己 + 右贡献` | 交付量带「值」，结算量带「自己」 |
| [080 打家劫舍 III](080-house-robber-iii.md) | 两个状态（选/不选） | 不需要（结算量在根） | 交付量升级成**向量** |
| 687 最长同值路径 | 同值单边长度 | `左同值 + 右同值` | 交付量多了「值必须相同」的约束 |
| 1372 最长交错路径 | 两个方向各一个长度 | `max(左, 右)` | 交付量升级成**两个方向** |

> 🧭 一句话记住：**交付量是「单边」，结算量是「分叉一次」，二者永不相等**。只要你在纸上把这两个量分开写，这族题就没有难度。

### 074.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求**输出路径本身**（节点列表） | 只返回和不够了 | 在结算时记下「最优的 `h`」，同时 `gain` 里记「这个贡献来自哪一边」；最后从 `h` 沿记录的边往下收集节点，再反转左半段 |
| 路径**至少含 2 个节点** | 单结点不再合法 | 结算式改成 `max(0,gain左) + val + max(0,gain右)`，但要求「左右至少一路非空」；用 `-∞` 标记「这一侧没有真实链」 |
| 节点数到 **10⁶**、递归爆栈 | 深度不可控 | 显式栈做后序（压 `(节点, 是否已展开)`），或用「先做一次前序把节点排成后序序列，再倒着算」 |
| 树是**多叉**的 | 孩子个数不定 | 结算量变成「最大的两个正贡献 + 自己」：`val + top1 + top2`，用 `O(deg)` 的选择统计，不用排序 |
| 树上每个点还带**权重限制**（如路径长度 ≤ k） | 一维 DP 不够 | 变成「树上背包 / 点分治」：先把 `gain` 收进一棵按长度排序的集合，再二分 |
| 允许**空路径**（可以什么都不选） | 语义变了 | 答案下限改成 0，`return Math.max(0, best)` —— 这**只是这一种**变体才允许 0 |

## 074.4 图解推演

### 074.4.1 贡献回流：每个节点交出去什么、什么时候结算

用示例 2 的树（`[-10, 9, 20, null, null, 15, 7]`）走一遍。**先看叶子，再看父亲** —— 后序的时间线是「从下往上」。

```
步骤 0：把树画出来，标上 val
                 -10
                ┌──┴───┐
                9      20
                      ┌┴┐
                     15 7

步骤 1：叶子 15、7、9 没有孩子 → 交付量只能是「自己」
         gain(15) = 15        结算：15
         gain(7)  = 7         结算：7
         gain(9)  = 9         结算：9

步骤 2：20 的左右都收到了 → 结算 + 交付
         结算 = gain(15) + 20 + gain(7) = 15 + 20 + 7 = 42   ← 全局最佳在这里产生
         交付 = 20 + max(0,15,7) = 35        （只能带一边走，选大的 15）

步骤 3：根 −10 收到左 9、右 35
         结算 = 9 + (-10) + 35 = 34          ← 比 42 小，被丢弃
         交付 = -10 + max(0,9,35) = 25       （带右边 35）

步骤 4：没有父结点了，交付量 25 被丢弃 —— 它只是"给父亲的礼物"，父亲不存在时就作废
最终答案 = 42
```

**关键观察**：根节点的**交付量 25 从来不是答案**。这就是「两量分离」最反直觉的地方 —— 很多人写完 `return` 一激动就把 `return` 的值当答案返回了。

### 074.4.2 逐步状态表（行 = 结点的后序顺序）

| 后序步 | x | gain(左) | gain(右) | 结算候选 `l + val + r` | 当前 best | 交付 `val + max(l,r)` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 15 | 0 | 0 | 0 + 15 + 0 = 15 | 15 | 15 |
| 2 | 7 | 0 | 0 | 0 + 7 + 0 = 7 | 15 | 7 |
| 3 | 20 | 15 | 7 | 15 + 20 + 7 = **42** | **42** | 20 + 15 = 35 |
| 4 | 9 | 0 | 0 | 0 + 9 + 0 = 9 | 42 | 9 |
| 5 | −10 | 9 | 35 | 9 + (−10) + 35 = 34 | 42 | −10 + 35 = 25 |

> 注意 `gain(左)`、`gain(右)` 这两列**恒 ≥ 0**：它们已经是 `max(0, ·)` 之后的值。如果某张表里出现了负数贡献，说明 `max(0, ·)` 写漏了。

### 074.4.3 反例轨迹：把「子树最优路径」当贡献会错在哪

树 `[1, -100, null, 50]`：

```
                1
               ┌┴┐
             -100 (空)
             ┌┴┐
            50 (空)

✅ 正确（贡献模型）：
   叶子 50：gain = 50，结算 50
   结点 −100：gain(左) = 50，gain(右) = 0
             结算 = 50 + (−100) + 0 = −50       ← 被丢弃
             交付 = −100 + max(0,50) = −50      ← 交给父亲的是一 50，不是 50！
   根 1：gain(左) = max(0, −50) = 0（负数不要）、gain(右) = 0
             结算 = 0 + 1 + 0 = 1
   答案 = max(50, −50, 1) = 50  ✅

❌ 错误（把"子树最优路径"当贡献）：
   子树(−100) 的"最优路径"是孤立的 50（根本不经过 −100）
   于是它把这个 50 当作自己的"贡献"交给根 1
   结算 = 50 + 1 + 0 = 51   ← 这条"路径"在树里不存在：50 与 1 之间必须经过 −100
   答案 = 51  ✗
```

**一句话总结这个反例**：**贡献必须是「以自己为一端、只往下的链」**，这样父结点才能安全地把它「接长」；而「子树内最优路径」可能根本不碰到子树根，一旦接上去就凭空跳过了一段路径，和自然偏大。

## 074.5 双语言实现

### 074.5.1 Java

```java
// LeetCode 判题环境已内置 TreeNode，网页上粘贴时不要重复定义；
// 本地编译用一个同名 TreeNode.java 即可：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode() {}
//     TreeNode(int val) { this.val = val; }
//     TreeNode(int val, TreeNode left, TreeNode right) { this.val = val; this.left = left; this.right = right; }
// }

class Solution {
    // 结算量放进成员变量：后序递归没有"汇总参数"的天然位置，
    // 用一个字段承接"就地结算"的结果是最省事的写法。
    private int best;

    public int maxPathSum(TreeNode root) {
        // 必须每次重置：LeetCode 有些题目会在同一个 Solution 实例上连续调用多次，
        // 漏掉这一行，第二次调用的起点就是上一次的答案（经典"本地能过、提交报错"）。
        best = Integer.MIN_VALUE;
        // 题目保证 n >= 1，但空树时给个明确的语义更安全
        if (root == null) return 0;
        gain(root);
        return best;                 // 注意：返回的是 best，不是 gain(root)
    }

    /** 交付量：以 node 为一端、只向下走的单边链最大和（可以为负） */
    private int gain(TreeNode node) {
        if (node == null) return 0;  // 空结点的"空单位元"是 0：意思是"这一段我不走"

        // max(0,·)：某侧是负数就干脆不要那一侧 —— 这是 gain 能"停在自己"的依据
        int left = Math.max(0, gain(node.left));
        int right = Math.max(0, gain(node.right));

        // 结算：此刻左右都算完了，可以把两边接起来形成"完整路径"（唯一允许分叉的一次）
        // 这里【不能】写 Math.max(0, ...)：全负树时答案必须是负数
        best = Math.max(best, left + node.val + right);

        // 交付：给父亲的东西只能带一边，否则就成了分叉路径
        return node.val + Math.max(left, right);
    }
}
```

### 074.5.2 Go

```go
package main

import "math"

// LeetCode Go 判题环境已内置该定义，本地跑时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func maxPathSum(root *TreeNode) int {
	if root == nil {
		return 0 // 题目保证 n>=1；空树返回 0 只为把语义写死
	}

	// 结算量：Go 没有成员变量，用闭包捕获的局部变量承接，效果与 Java 的字段一致
	best := math.MinInt32

	// gain 交付量：以 node 为一端向下走的单边链最大和
	var gain func(node *TreeNode) int
	gain = func(node *TreeNode) int {
		if node == nil {
			return 0
		}
		left := gain(node.Left)
		if left < 0 {
			left = 0 // 等价于 Math.max(0, ·)：Go 没有泛型 max，手写更省一次函数调用
		}
		right := gain(node.Right)
		if right < 0 {
			right = 0
		}

		if cand := left + node.Val + right; cand > best {
			best = cand // 结算：唯一允许"分叉"的位置
		}

		if left > right {
			return node.Val + left // 交付：只能带一边
		}
		return node.Val + right
	}

	gain(root)
	return best // 返回 best，而不是 gain(root)
}
```

### 074.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 结算量的载体 | `private int best` 字段 | 闭包捕获的局部 `best` | Go 里**不要**用包级全局变量：LeetCode 在同一进程里反复调用，全局变量会跨用例污染 |
| 递归函数写法 | 私有方法 `gain(TreeNode)` | `var gain func(*TreeNode) int` 再赋值（匿名递归必须**先声明后赋值**） | Go 直接写 `func gain(...)` 递归调用同名函数会编译不过（未定义），这是 Go 新手最常见的报错 |
| `max(0, x)` | `Math.max(0, x)` | 手写 `if x < 0 { x = 0 }` | Go 1.19 没有内置 `max`（1.21 才有），不要写 `max()` 否则 `go vet` 报未定义 |
| 初始值 | `Integer.MIN_VALUE` | `math.MinInt32` | 两边都必须用「极小值」而不是 0，否则全负树直接错 |
| 整数宽度 | `int` 恒 32 位 | `int` 在 64 位平台是 64 位 | 本题和上界 3·10⁷，两边都安全 |
| 空结点 | `null` | `nil` | `(*TreeNode)(nil).Val` 会 panic，判空必须写在最前面 |

### 074.5.4 对拍测试（参考实现就是 O(n²) 的暴力枚举所有路径）

```go
package main

import (
	"math"
	"math/rand"
	"testing"
)

// ---------- 辅助：造树 / 建树 / 导出结构 ----------

// randTree 随机造 n 个节点的二叉树：每个新节点随机挂到某个空槽上，
// 能覆盖"左偏 / 右偏 / 完全 / 搓板"之外的大量形状，比随机层序数组覆盖面大
func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(21) - 10} // 值域 [-10,10]：故意让大量负数出现
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(21) - 10}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

// build 按 LeetCode 层序数组建树（nil 表示空位），用来跑固定语料
func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}

// dump 前序导出结构（含 # 空位）：打印失败用例时一眼能重建出树
func dump(root *TreeNode) string {
	if root == nil {
		return "#"
	}
	return "(" + itoa(root.Val) + " " + dump(root.Left) + " " + dump(root.Right) + ")"
}

func itoa(v int) string {
	if v == 0 {
		return "0"
	}
	neg := v < 0
	if neg {
		v = -v
	}
	var b []byte
	for v > 0 {
		b = append([]byte{byte('0' + v%10)}, b...)
		v /= 10
	}
	if neg {
		return "-" + string(b)
	}
	return string(b)
}

// ---------- 参考实现：枚举所有路径，O(n²) ----------

func bruteMaxPathSum(root *TreeNode) int {
	if root == nil {
		return 0
	}
	// 关键：路径可以「先向上再向下」，所以必须按【无向图】遍历，
	// 只顺着 Left/Right 走会漏掉"往上拐"的路径（这是本参考实现第一版的真 bug）
	adj := map[*TreeNode][]*TreeNode{}
	var nodes []*TreeNode
	var link func(x *TreeNode)
	link = func(x *TreeNode) {
		if x == nil {
			return
		}
		nodes = append(nodes, x)
		for _, c := range []*TreeNode{x.Left, x.Right} {
			if c != nil {
				adj[x] = append(adj[x], c)
				adj[c] = append(adj[c], x) // 反向边：允许从孩子走回父亲
				link(c)
			}
		}
	}
	link(root)

	best := math.MinInt32
	// 对每个起点做一次"以它为端点"的 DFS：路径和随 DFS 累加，parent 挡住回头路
	for _, start := range nodes {
		var walk func(x, parent *TreeNode, sum int)
		walk = func(x, parent *TreeNode, sum int) {
			sum += x.Val
			if sum > best {
				best = sum
			}
			for _, nb := range adj[x] {
				if nb != parent {
					walk(nb, x, sum)
				}
			}
		}
		walk(start, nil, 0)
	}
	return best
}

// ---------- 对拍 ----------

func TestMaxPathSumRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026074))
	for iter := 0; iter < 5000; iter++ {
		n := 1 + r.Intn(30) // 1..30，单结点也在里面
		root := randTree(r, n)
		want := bruteMaxPathSum(root)
		got := maxPathSum(root)
		if got != want {
			t.Fatalf("iter=%d n=%d tree=%s got=%d want=%d", iter, n, dump(root), got, want)
		}
	}
}

// 边界语料：单结点、全负、链、只有一条正数分支（反例 ③）
func TestMaxPathSumEdges(t *testing.T) {
	cases := []struct {
		in   []interface{}
		want int
	}{
		{[]interface{}{-3}, -3},                          // 单结点全负
		{[]interface{}{-2, -1}, -1},                      // 全负两结点
		{[]interface{}{1, -100, nil, 50}, 50},            // 「子树最优当贡献」的杀手反例
		{[]interface{}{-1, -2, nil, -3}, -1},             // 全负退化链
		{[]interface{}{1, 2, 3}, 6},                      // 官方样例 1
		{[]interface{}{-10, 9, 20, nil, nil, 15, 7}, 42}, // 官方样例 2
		{[]interface{}{0, 0, 0}, 0},                       // 全零
	}
	for _, c := range cases {
		root := build(c.in)
		if got := maxPathSum(root); got != c.want {
			t.Fatalf("tree=%s got=%d want=%d", dump(root), got, c.want)
		}
		if got, want := maxPathSum(root), bruteMaxPathSum(root); got != want {
			t.Fatalf("与暴力不一致 tree=%s got=%d want=%d", dump(root), got, want)
		}
```

## 074.6 复杂度与常见坑

### 074.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：`gain(x)` 对每个节点恰好被调用一次（后序：先左、再右、再自己），函数体内的工作是常数次加法与比较。总时间 = `Θ(n)`。**注意这不是「平均情况」**：树没有「最好/最坏」的输入顺序问题，任何形态都是 n 次调用。
- **空间 O(h)**：递归栈深度等于当前路径长，最大为树高 `h`。完全二叉树 `h = log₂n ≈ 15`；**退化链 `h = n = 3·10⁴`** —— 这才是真正的风险点（Java 默认线程栈约 512 KB~1 MB，每帧几十字节，3 万层已接近上限）。
- **其他空间 O(1)**：只有 `best`、`left`、`right` 三个标量。**不需要任何 DP 表** —— 这是树形 DP 相比区间 DP 的一大优势：子问题只被父结点用一次，天然可以「用完即弃」。

| 方案 | 时间 | 空间 | `n=3·10⁴` 随机树实测（2 核容器 / JDK 17 / Go 1.19） |
| --- | --- | --- | --- |
| 暴力枚举所有路径 | O(n²) | O(h) | Java ≈ 5.8 s（TLE）/ Go ≈ 2.6 s（TLE） |
| **后序树形 DP** | **O(n)** | **O(h)** | **Java ≈ 2 ms / Go ≈ 3 ms** |
| 迭代后序 | O(n) | O(h) | Java ≈ 5 ms / Go ≈ 7 ms（显式栈 + 装箱） |

### 074.6.2 七个真实踩过的坑

1. **`best` 用 0 当初始值** —— 全负树直接错：`[-3]` 返回 0，正确答案 −3。必须用 `Integer.MIN_VALUE` / `math.MinInt32`。
2. **把 `gain(root)` 当答案返回** —— 反例 ③ 会返回 `-100 + 50 = -50` 而不是 50；官方样例 2 会返回 25 而不是 42。**`return` 的东西和答案永远不是一个东西。**
3. **贡献里忘了 `max(0, ·)`** —— `gain` 变成「必须走到底」，父结点被迫把负数链接上来。`[1, -2, 3]` 会算成 `1 + (-2) + 3 = 2`，正确答案是 3（只走 3）。
4. **答案里也写了 `max(0, ·)`** —— 反过来把负数答案夹成 0，`[-3]`、`[-2,-1]` 全错。**clamp 只属于贡献，不属于答案。**
5. **成员变量 `best` 没在方法开头重置** —— LeetCode 的部分题目会在同一实例上连续调用，第二次调用的初始 `best` 是上次的答案。本地写 `main` 跑单个用例**永远发现不了**这个 bug。
6. **递归深度当无关紧要** —— `3·10⁴` 的退化链在默认栈上可能 `StackOverflowError`；生产环境里对「用户可控的树」要么显式栈，要么先算高度再决定用哪种写法。
7. **和溢出** —— 本题上界 `3·10⁴ × 1000 = 3·10⁷`，`int` 安全；但只要题目把值域改成 `10⁹`，`3·10⁴ × 10⁹ = 3·10¹³` 就必须 `long` / `int64`。**写完先算一遍「最坏情况下和最大能到多少」。**

### 074.6.3 面试官最爱追问的三个问题

**Q1：为什么返回值不是答案？**

> 「因为**父结点需要的东西和题目要的东西不是同一个量**。父结点只能接一条『单边链』—— 它自己还要连它的父亲，如果我把左右两边都交出去，路径就在我这里岔了两次，不合法。所以交付量必须是 `val + max(左, 右)`。而『岔一次』的那条完整路径只能在『左右都算完』的那一刻就地结算、存进全局答案。这就是树形 DP 里『交付量 vs 结算量』的分离，和 071 二叉树的直径是同一个模型（那里交付高度、结算高度和）。」

**Q2：全负的树上为什么不能用 0 当初值？**

> 「因为它会捏造出一条**不存在的空路径**。题目要求路径至少含一个节点，所以 `[-3]` 的答案是 −3。用 0 当初值等价于宣称『空路径合法』，这是语义上的错，不是数值上的错。同理，`max(0, ·)` 只能加在**贡献**上（意思是『这一侧我不走』），绝不能加在**答案**上，否则整个返回值都会被夹到「非负」，全负用例全线失败。」

**Q3：如果树深到 10⁶，递归撑不住，怎么办？**

> 「三种做法，按实现成本排序：① **迭代后序**：显式栈里压 `(节点, 是否已展开)`，第二次弹出时才结算 —— 空间 O(h) 但在堆上，不受线程栈限制；② **两遍法**：先做一次前序遍历把节点按『逆后序』塞进数组（根右左），再倒着扫一遍数组做 DP，代码最短；③ **显式深度限制**：先迭代算高度，`h < 10000` 才走递归，否则走迭代。不要用 Morris —— 后序的 Morris 会临时改树，还要反转左链，正确性极难验证，而本题根本没有 O(1) 空间的约束。」

## 附：本章小结（可背走的三句话）

```
① 每条路径有唯一最高点 h，所以「枚举所有 h」不重不漏：h + 左边一条链 + 右边一条链
② 交付量 = val + max(0, 左, 右)（单边，可弃负）；结算量 = 左 + val + 右（分叉一次）
③ 答案用 −∞ 起步、clamp 只加在贡献上；返回值永远不是答案
```
