## 144.1 题目

**原题链接**：<https://leetcode.cn/problems/powx-n/>

### 题意重述（把隐含条件补齐）

实现 `pow(x, n)`，即计算 `x` 的整数 `n` 次幂（`x` 是浮点数，`n` 是 32 位有符号整数）。不得使用库函数，且不需要考虑大数问题（结果超出 `double` 表示范围就按浮点规则变成 `Infinity` 或 `0`）。

题面短，但藏着六个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| `n` 的范围是 **`[−2³¹, 2³¹−1]`** | 「`-2³¹ <= n <= 2³¹-1`」 | **`-n` 在 `n = −2³¹` 时会溢出**（`int` 里 `−(−2³¹)` 还是 `−2³¹`），这是本题最经典的坑 |
| `n` 可以为**负** | 「`n` 是整数」 | 负指数要取倒数：`x^(−N) = (1/x)^N` |
| `x` 可以是 **0**，但此时 `n > 0` | 「要么 `x` 不为零，要么 `n > 0`」 | 约束保护了 `1/0`，但要意识到「`x = 0` 且 `n < 0`」是非法输入 |
| `x` 可以是 **负数** | 「`-100.0 < x < 100.0`」 | 奇数指数时符号为负，偶数指数时为正；不能先取绝对值 |
| 结果误差 **≤ 10⁻⁵** | 「结果在 `[-10^4, 10^4]` 内」时按相对误差判 | 浮点乘法有累积误差，但快速幂只做 `O(log n)` 次乘法，误差极小 |
| **不许调库** | 「不得使用库函数」 | `Math.pow` / `math.Pow` 都不允许（虽然是浮点实现，不解决整数指数问题） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n ∈ [−2³¹, 2³¹−1]` | 约 `±2.1·10⁹` | 「连乘 `|n|` 次」是 `2.1·10⁹` 次乘法，本机实测 Java ≈ 4 s、Go ≈ 2.5 s —— **必然 TLE**。看到 `10⁹` 这个量级，条件反射就是 **`O(log n)`** |
| `x ∈ (−100, 100)` | 底数是浮点 | 不能把结果当整数存；`2^1000` 早就超出 `double` 的整数精度，但仍可表示成浮点 |
| 结果落在 `[-10^4, 10^4]`（否则允许 `Inf`/`0`） | 真实的输入都被特意压过值域 | 说明判题不关心溢出成 `Inf`，只关心**算法结构** |
| 误差 `10⁻⁵` | 相对或绝对误差 | 最多 `log₂(2³¹) = 31` 次乘法，双精度误差在 `10⁻¹⁵` 量级，安全 |

> 💡 **量级 → 算法** 的一条硬规则：
> **只要运算满足结合律（乘法、矩阵乘、取模乘、字符串拼接……），看到 `n` 的量级到 `10⁹` 以上，就该把「重复 n 次」换成「按二进制倍增 log n 次」。**
> 这就是**快速幂**，它的近亲是「快速乘」（防溢出）、「矩阵快速幂」（求斐波那契）、「倍增 LCA」。

### 示例

```text
输入：x = 2.00000, n = 10       输出：1024.00000
输入：x = 2.10000, n = 3        输出：9.26100
输入：x = 2.00000, n = -2       输出：0.25000      ← 负指数：2⁻² = 1/4
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① x = 2.0,  n = -2147483648    → 真值 = 2^(−2³¹)，下溢为 0.0
                                 暴露：`int N = -n;` 溢出，N 还是负数 → 循环不进 → 返回 1.0（大错）
② x = 1.0,  n = -2147483648    → 答案 1.0
                                 注意：这个用例「看起来对」，因为 1 的任何次幂都是 1，
                                 它掩盖了 ① 的 bug。所以要挑 x ≠ ±1 的底数才能暴露问题
③ x = -1.0, n = -2147483648    → 答案 1.0（−1 的偶数次幂）
                                 暴露：把 `n` 当负数直接取绝对值的人，符号位判断会错
④ x = 0.00001, n = 2147483647  → 下溢为 0.0
                                 暴露：以为「快速幂一定不溢出」（浮点会下溢，只是不报错）
⑤ x = 0.0,  n = 5              → 0.0；x = 1.0, n = 0 → 1.0
                                 暴露：`base *= base` 时 base 已为 0，仍然是 0，正确；
                                 但 `n = 0` 忘了返回 1 的写法会返回 0
```

第 ② 条最阴险：**它能过很多人的 bug**。所以对拍时底数必须随机、且要包含 `x ∉ {−1, 0, 1}` 的值。

## 144.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的一版：乘 `|n|` 次。

```java
double ans = 1.0;
long N = Math.abs((long) n);        // 用 long 是为了不让 -2^31 溢出
for (long i = 0; i < N; i++) ans *= x;
return n >= 0 ? ans : 1.0 / ans;
```

- 时间 **O(|n|)**，空间 **O(1)**。
- `n = 2³¹ − 1` 时是 **2 147 483 647 次浮点乘法**。本机实测（2 核容器 / JDK 17 / Go 1.19）Java ≈ 4.2 s、Go ≈ 2.6 s —— **超时**（本题时限 1 s 量级）。
- 值域 `n = ±10⁹` 这个信息，已经在明示「线性不行」。

### 第二步：卡点在哪

把问题翻译成一句话：

> **我要算 `x` 自己乘自己 `n` 次，但 `n` 太大了。**

卡点不是「乘法慢」，而是**重复劳动**：算 `x^8` 的时候，我已经知道了 `x^4`，而我却又从头乘了 8 次。这正是 142 章那个思路的翻版——**用已知的答案推下一个答案**。

但这次有一个更强的手段：**不仅复用，还能「指数级复用」**。

### 第三步：灵感的来源 —— 平方一次，指数翻倍

观察：

```
x^1  = x
x^2  = (x^1)^2      ← 一次乘法，指数 ×2
x^4  = (x^2)^2      ← 一次乘法，指数 ×2
x^8  = (x^4)^2      ← 一次乘法，指数 ×2
...
x^(2^k) 只需要 k 次乘法
```

也就是说，**「底数平方」这个动作自带倍增效**：`k` 次平方就能覆盖到指数 `2^k`。而任何整数 `n` 都能写成二进制（一串 `2` 的幂之和）：

```
n = 13 = 1101₂ = 8 + 4 + 1
x^13 = x^8 · x^4 · x^1
```

于是「从低位往高位扫 `n` 的二进制位」：**每一位上，底数 `base` 就是 `x^(2^k)`；如果这一位是 1，就把 `base` 乘进答案**。总共 `log₂n` 轮，每轮至多两次乘法。

### 第四步：负数指数怎么办 —— 这里就是必考的溢出点

数学上 `x^(−N) = (1/x)^N`，所以「先把 `x` 换成 `1/x`，再把 `N` 取正」即可。**但 `N = −n` 这一步会溢出**：

```
n = −2³¹ = −2147483648
在 32 位有符号整数里：−n = 2147483648 装不下（int 上限 2147483647）
补码下 −(−2³¹) = −2³¹   ← 还是负数！
```

后果非常隐蔽：`while (N > 0)` 一次都不执行，**直接返回 1.0**。`x = 2.0, n = −2³¹` 的正确答案是 0.0（下溢），程序给 1.0，差得离谱。

**两种正确写法**：

| 写法 | 代码 | 说明 |
| --- | --- | --- |
| **转 `long` 再取负** ✅ | `long N = n; if (N < 0) { x = 1 / x; N = -N; }` | `long` 能装下 `2³¹`，`-N` 安全。之后循环用 `long` 变量 |
| 先加一再取负（不推荐） | `N = -(n + 1) + 1` | 数学上等于 `-n` 且不溢出，但可读性差、极易写错（`n = −2³¹` 时 `n+1` 是安全的，取负后加 1 正确） |

Go 里要额外小心：`int` 在 64 位平台是 64 位，`-n` **碰巧**安全；但一旦按 `GOARCH=386` 编译（或换到 32 位平台）就会静默溢出。所以 **Go 端也要显式 `int64`**，不能吃平台的便宜。

## 144.3 原理拆解

### 144.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 连乘 `|n|` 次 | **O(n)** | O(1) | 5 行 | `n` 到 `10⁹` 必然 TLE（本题 `n` 上限 `2.1·10⁹`） |
| 快速幂（递归分治） | O(log n) | **O(log n)** 栈 | 12 行 | 指数极大时递归深度成为常数上界（本题 31 层，无问题）；不便于「按位取模」变体 |
| **快速幂（迭代）** ✅ | **O(log n)** | **O(1)** | **10 行** | 需要额外想清楚「底数平方的时机」 |
| 按最高位递归（`x^n = x^{n/2}²·x^{n%2}`） | O(log n) | O(log n) | 10 行 | 与上面同构，只是把「指数二分」写成递归 |
| `Math.pow` / `math.Pow` | 库实现 | — | 1 行 | **题目禁止**；且它内部走的是 `exp/log` 或查表，不是整数快速幂 |

### 144.3.2 为什么这个做法是对的（正确性论证）

**命题（迭代快速幂的循环不变量）**：设原始指数为 `N₀ = |n| ≥ 0`，循环变量满足

```
base^exp · ans = x^N₀        （x 已按需换成 1/x）
```

- **初始化**：`exp = N₀`，`base = x`，`ans = 1`，于是 `x^{N₀} · 1 = x^{N₀}` ✓。
- **保持（`exp` 为奇数）**：执行 `ans *= base`、`exp -= 1`，此时 `base^{exp} · ans = base^{exp_old − 1} · ans_old · base = base^{exp_old} · ans_old = x^{N₀}` ✓。
- **保持（`exp` 为偶数）**：执行 `base *= base`、`exp /= 2`，此时 `(base²)^{exp_old/2} · ans = base^{exp_old} · ans = x^{N₀}` ✓。
- **终止**：`exp` 每轮严格减半（或减一后再减半），最终为 `0`；代入不变量得 `1 · ans = x^{N₀}`，所以 `ans = x^{N₀}` ✓。∎

**循环次数**：`exp` 每轮至少减半，所以不超过 `⌊log₂N₀⌋ + 1 ≤ 31` 轮（`N₀ ≤ 2³¹`）。∎

**命题（递归版）**：定义 `p(x, m) = x^m`（`m ≥ 0`）。对 `m` 做**强归纳**：

- `m = 0`：`p = 1 = x⁰` ✓。
- `m ≥ 1`：设对一切小于 `m` 的指数命题成立。`half = p(x, ⌊m/2⌋)`，由归纳假设 `half = x^{⌊m/2⌋}`。于是
  - `m` 为偶数：`⌊m/2⌋ = m/2`，`half² = x^m` ✓；
  - `m` 为奇数：`⌊m/2⌋ = (m−1)/2`，`half² · x = x^{m−1} · x = x^m` ✓。∎

**负指数的正确性**：`x^{−N} = 1 / x^{N} = (1/x)^{N}`（`x ≠ 0`），这一步是纯代数恒等式；题目约束保证 `x = 0` 时 `n > 0`，所以不会出现 `1/0`。∎

### 144.3.3 通用解题思路（可迁移的那一层）

**快速幂模型（倍增）**：

```
要算「同一个元素自己跟自己结合 n 次」的结果 F(n)
        ↓ 若结合律成立（a∗(b∗c) = (a∗b)∗c）
F(n) = F(⌊n/2⌋) ∗ F(⌊n/2⌋) ∗ (n 为奇数 ? 元素 : 单位元)
        ↓ 或者把 n 按二进制拆
n = Σ b_k 2^k  →  F(n) = Π (F(2^k))^{b_k}
        ↓ 于是底数自己平方着往上走
O(log n) 次运算
```

**本章的两个实现要都写得出来**（面试常要求「递归写完再改迭代」）：

迭代版的骨架是三个变量，位置不能换：

| 变量 | 含义 | 每轮怎么变 |
| --- | --- | --- |
| `base` | 当前这一位代表的 `x^(2^k)` | **每轮无条件平方** `base *= base` |
| `N`（或 `exp`） | 还没处理的指数 | 先看最低位，再 `N >>= 1` |
| `ans` | 已累乘的答案 | 只在 `N & 1 == 1` 时 `ans *= base` |

> **顺序陷阱**：`ans *= base` 必须发生在 `base *= base` **之前**。反过来的话 `ans` 拿到的是已经平方过的 `base`，指数会错位（这是最常见的实现 bug，见 §144.6.2 第 3 条）。

**同一模型的其他成员**：

| 题 / 场景 | 「元素」是什么 | 结合律 | 备注 |
| --- | --- | --- | --- |
| [LC 50 Pow(x, n)](https://leetcode.cn/problems/powx-n/) | 浮点数 | 乘法 | 本章 |
| [LC 372 超级次幂](https://leetcode.cn/problems/super-pow/) | 整数 + 模 | 模乘 | `n` 是**十进制字符串**，长度到 `10⁴` → 逐位降指数 + 费马小定理 |
| [LC 509 斐波那契数](https://leetcode.cn/problems/fibonacci-number/)（矩阵法） | 2×2 矩阵 | 矩阵乘法 | `O(log n)` 求第 `n` 项，`n` 可到 `10¹⁸` |
| 快速乘（防 `long long` 溢出） | 加法的「幂」 | 加法 | `a·b mod m` 用「加 + 倍增」避免 `__int128` |
| 倍增 LCA / 稀疏表 | 「跳 `2^k` 步后的祖先」 | 函数复合 | 同一套「`2^k` 倍增表」思想 |
| [LC 1922 统计好数字的数目](https://leetcode.cn/problems/count-good-numbers/) | 模幂 | 模乘 | 组合计数 + 快速幂，取模 |

### 144.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 结果要**取模**（`x^n mod m`） | 数值变成大整数 | 每次乘法后取模：`ans = ans * base % m`；注意 `base * base` 也可能溢出，若 `m` 到 `10¹⁸` 就需要「快速乘」或 `__int128` |
| `n` 是**十进制字符串**（`"2147483648"`，长度 `10⁴`） | 超出 `long` | 逐位降指数：`x^{ab} = (x^a)^b`，得 `ans = ans * x^digit` 后 `x = x^10`；配合费马小定理把指数对 `m−1` 取模 |
| `n` 是**负数且底数为 0** | 数学上无定义 | 约束里排除了；实作中应显式抛异常或返回 `Inf`，不要静默算 `1/0` |
| 底数是**矩阵** | 元素变成方阵 | 把 `*` 换成矩阵乘、`1` 换成单位矩阵，代码一字不改（这就是「模板化快速幂」） |
| 要算 **`x^n` 的前 `k` 位** | 只用对数不够 | 取 `log10` 得整数部分与小数部分，小数部分做 `10^frac`（浮点精度决定能取多少位） |
| 递归深度受限（某些语言栈很小） | 深递归爆栈 | 用迭代版：`O(1)` 空间，天然没有栈问题；本题 `log₂(2³¹) = 31` 层，任何语言都安全，但换到「`n` 是 `10¹⁸` 的十进制串」时迭代更稳 |

## 144.4 图解推演

### 144.4.1 把指数拆成二进制（`x^13`）

```
n = 13 = 1 1 0 1        （二进制，从高位到低位读）
         8 4 2 1
         │ │ │ └── 2⁰ 位 = 1  → 要乘 x^1
         │ │ └──── 2¹ 位 = 0  → 不要 x^2
         │ └────── 2² 位 = 1  → 要乘 x^4
         └──────── 2³ 位 = 1  → 要乘 x^8

x^13 = x^8 · x^4 · x^1
        ↑     ↑     ↑
      base=x^8 base=x^4 base=x（三个 base 都由「自己平方」得到）
```

### 144.4.2 迭代版逐步轨迹（x = 2.0，n = 13）

```
初始：  ans=1.0      base=2.0       N=13 = 1101
─────────────────────────────────────────────────────────
第1轮   N&1=1 → ans=1·2 =2         ← 收下 base=2¹
        base=2·2=4      N=13>>1=6  (110)
第2轮   N&1=0 → ans 不动(=2)        ← 6 的最低位是 0，跳过 2²
        base=4·4=16     N=6>>1=3   (11)
第3轮   N&1=1 → ans=2·16=32        ← 收下 base=2⁴
        base=16·16=256  N=3>>1=1   (1)
第4轮   N&1=1 → ans=32·256=8192    ← 收下 base=2⁸
        base=256·256    N=1>>1=0
─────────────────────────────────────────────────────────
N=0 → 返回 ans = 8192 = 2^13 ✓
```

**只花了 4 轮 6 次乘法**，而连乘要 13 次。`n = 2³¹` 时是 **31 轮**对 **21 亿次**。

### 144.4.3 关键变量的状态表

| 轮次 | `N`（二进制） | `N & 1` | `base`（= x^(2^k)） | `ans` | 说明 |
| --- | --- | --- | --- | --- | --- |
| 初始 | `1101` | — | 2 | 1 | 单位元 |
| 1 | `1101` | 1 | 2 | **2** | 收下 `2¹` |
| 2 | `110` | 0 | 4 | 2 | 跳过 `2²` |
| 3 | `11` | 1 | 16 | **32** | 收下 `2⁴` |
| 4 | `1` | 1 | 256 | **8192** | 收下 `2⁸` |
| 结束 | `0` | — | — | **8192** | `2^13` ✓ |

### 144.4.4 递归版的调用树（`x^10`）

```
                p(10)
                  │  half = p(5)
                  ▼
                p(5) ──── half = p(2)
                  │            │
                  ▼            ▼
                p(2) ────── half = p(1)
                  │              │
                  ▼              ▼
                p(1) ─────── half = p(0)
                                 │
                                 ▼
                               p(0) = 1        ← 基例
                  ▲              │
                  │  1²·x = x    │ 回代
                p(1) = x         │
                  ▲              │
                  │  x²          │
                p(2) = x²        │
                  ▲              │
                  │  (x²)²·x     │
                p(5) = x⁵        │
                  ▲              │
                  │  (x⁵)²       │
                p(10) = x¹⁰      │
```

深度 = `⌈log₂10⌉ + 1 = 5`，每层只算**一次**递归 + 至多两次乘法。

## 144.5 双语言实现

### 144.5.1 Java

**迭代版（推荐，提交用这版）**：

```java
class Solution {
    public double myPow(double x, int n) {
        // 必须先把 n 提升成 long：n = -2^31 时 -n 在 int 里还是 -2^31（补码没有对称的正数），
        // 会导致下面 while 一次都不进、直接返回 1.0。long 装得下 2^31，取负安全。
        long N = n;
        if (N < 0) {
            x = 1.0 / x;   // 负指数 → 变成正指数，底数取倒数（约束保证 x != 0）
            N = -N;        // 这一步只有 N 是 long 才安全
        }

        double ans = 1.0;  // 乘法的单位元
        double base = x;   // base 始终等于 x 的「当前二进制位对应的 2^k 次幂」

        while (N > 0) {
            if ((N & 1) == 1) {   // 这一位是 1 → 把 base 乘进答案
                ans *= base;
            }
            base *= base;         // 底数平方：为下一位准备（顺序必须在上面之后）
            N >>= 1;              // 处理下一位
        }

        return ans;
    }
}
```

**递归版（面试说「再写个递归」时用）**：

```java
class Solution {
    public double myPow(double x, int n) {
        long N = n;
        // 负指数先转成「底数取倒数 + 正指数」，转换时用 long 避免 -2^31 溢出
        return N >= 0 ? quickPow(x, N) : quickPow(1.0 / x, -N);
    }

    // 前提：exp >= 0。x^exp = (x^(exp/2))^2 · (exp 为奇数时再乘一个 x)
    private double quickPow(double base, long exp) {
        if (exp == 0) {
            return 1.0;              // 基例：任何数的 0 次幂都是 1（x 可以为 0，约定 0^0 = 1）
        }
        double half = quickPow(base, exp >> 1);   // 只递归一次：这里就是 O(log n) 的来源
        double sq = half * half;
        return (exp & 1) == 1 ? sq * base : sq;   // 奇数指数补乘一次底数
    }
}
```

### 144.5.2 Go

**迭代版**：

```go
package main

func myPow(x float64, n int) float64 {
	// 显式转 int64：Go 的 int 在 64 位平台是 64 位，-n 碰巧安全，
	// 但换成 32 位平台（GOARCH=386）就会和 Java 的 int 一样溢出。
	// 「位宽就是语义」的题必须用定宽类型，不能吃平台的便宜。
	N := int64(n)
	if N < 0 {
		x = 1 / x
		N = -N
	}

	ans := 1.0
	base := x
	for N > 0 {
		if N&1 == 1 {
			ans *= base
		}
		base *= base
		N >>= 1
	}

	return ans
}
```

**递归版**：

```go
package main

// myPowRec 是同一道题的递归写法，与迭代版逐步对照用。
// Go 允许定义函数类型的变量来做内部递归（不需要像 Java 那样写 private 方法）。
func myPowRec(x float64, n int) float64 {
	var quick func(base float64, exp int64) float64
	quick = func(base float64, exp int64) float64 {
		if exp == 0 {
			return 1.0
		}
		half := quick(base, exp>>1) // 每层只递归一次 → O(log n)
		sq := half * half
		if exp&1 == 1 {
			return sq * base
		}
		return sq
	}

	M := int64(n)
	if M < 0 {
		return quick(1/x, -M)
	}
	return quick(x, M)
}
```

### 144.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `int` 宽度 | 恒 **32 位**：`-(-2³¹)` **必然溢出** | 64 位平台 **64 位**：`-n` **碰巧安全** | Java 不加 `long` 一定错；Go 不加 `int64` 在 amd64 上「侥幸对」，换平台就错。**两端都应该显式提升** |
| 类型转换写法 | `long N = n;`（隐式提升） | `N := int64(n)`（显式转换） | Go 不允许隐式转换，写法更长但也更难写错 |
| `N & 1` 的类型 | `long & int` → `long`，比较写 `(N & 1) == 1` | `int64 & int` → `int64`，写法 `N&1 == 1` | 都能编译，但 Java 若写成 `(N & 1) == 1L` 更严谨 |
| 内部递归 | 需要 `private` 辅助方法 | 可以直接用函数变量（闭包） | Go 的写法更紧凑，但闭包捕获有一点点额外开销（本题规模下感觉不到） |
| 整数除法/右移 | `exp >> 1` 与 `exp / 2` 对非负等价 | 同 | 指数非负，两者都对；用 `>>` 更能表达「处理下一位」 |
| 除法基例 | `1.0 / x` 得 `double` | `1 / x` 中 `1` 是无类型常量，得 `float64` | Java 若写 `1 / x`（`int / double`）也能得 double，但写 `1.0` 更清晰 |

### 144.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math"
	"math/rand"
	"testing"

// 参考实现：直接调 math.Pow（题意不允许提交，但对拍时是完美的第三方真值）
func approx(got, want float64) bool {
	if math.IsNaN(got) || math.IsNaN(want) {
		return math.IsNaN(got) && math.IsNaN(want)
	}
	if math.IsInf(got, 0) || math.IsInf(want, 0) {
		return got == want // 同时为同号无穷才算一致
	}
	// 相对误差 + 绝对误差双判据：结果接近 0 时相对误差会失真
	return math.Abs(got-want) <= 1e-9 || math.Abs(got-want) <= 1e-9*math.Abs(want)
}

func TestMyPowRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20260217))
	for iter := 0; iter < 20000; iter++ {
		// 底数刻意覆盖三类：普通小数、±1 附近、0 附近（0 只在 n>0 时用，符合题目约束）
		var x float64
		switch iter % 3 {
		case 0:
			x = r.Float64()*2 - 1 // [-1, 1]
		case 1:

		default:

		}

		}
		n := r.Intn(1001) - 500 // [-500, 500]

			n = -n
		}

			t.Fatalf("iter=%d myPowRec(%v, %d) got=%v want=%v", iter, x, n, got, want)
		}
	}
```

## 144.6 复杂度与常见坑

### 144.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(log n)**：迭代版每轮执行一次 `N >>= 1`，所以轮数 = `⌊log₂|n|⌋ + 1`。`|n| ≤ 2³¹` 时最多 **32 轮**，每轮至多 2 次浮点乘法 → 至多 **64 次乘法**，与 `n` 的具体大小无关（`n = 1` 时 1 轮，`n = 2³¹−1` 时 31 轮）。
- **空间 O(1)**（迭代版）：只有 `N / base / ans` 三个标量。递归版是 **O(log n)** 栈空间，本题最多 32 层，约 `32 · 一个小栈帧`，这个开销可以当作不存在，但**要能在面试里说清这个差别**。
- **对比连乘**：`n = 2³¹−1` 时连乘 `2.1·10⁹` 次乘法 ≈ 4 s（TLE），快速幂 31 轮 ≈ 0.1 μs —— 差距约 **7 个数量级**。
- **精度**：快速幂只有 `O(log n)` 次乘法，误差累积 `O(log n · ε)`，其中 `ε ≈ 2.2·10⁻¹⁶`（双精度机器精度），31 次乘法后约 `7·10⁻¹⁵`，远小于题目要求的 `10⁻⁵`。**这就是为什么用快速幂不需要额外处理精度。**

### 144.6.2 七个真实踩过的坑

1. **`int N = -n;` 在 `n = −2³¹` 时溢出** —— 本题的头号坑，`N` 仍是负数，循环不执行，返回 `1.0`。修法：先 `long N = n;` 再取负。
2. **`x = 1 / x` 写成整数除法** —— 在 Java 里若 `x` 是 `int` 类型变量，`1 / x` 会做整数除法（`1/2 = 0`）。本题 `x` 是 `double`，`1 / x` 自动提升为浮点，安全；但在别的题里（比如自己写的矩阵快速幂）很容易踩。
3. **`base *= base` 与 `ans *= base` 顺序写反** —— 必须先「判断这一位 → 累乘 ans → 再平方 base → 右移」。若先平方，`ans` 拿到的是 `x^2` 而不是 `x`，指数整体错位。
4. **`if (N & 1 == 1)` 少写括号** —— Java / Go 中 `==` 的优先级高于 `&`，`N & 1 == 1` 会被解析成 `N & (1 == 1)`，`int & boolean` 在 Java 里直接编译错误，在 Go 里也是类型错误。必须 `(N & 1) == 1`。
5. **忘了 `n = 0` 返回 1** —— 任何数（含 0）的 0 次幂约定为 1。迭代版天然正确（`while` 不进，返回 `ans = 1.0`）；但手写递归版若基例写成 `exp == 1` 就会错。
6. **在 Go 里吃 `int` 64 位的便宜** —— 本地跑得好好的，换到 `GOARCH=386` 或 32 位平台（以及某些在线判题的 Go 环境配置）就溢出。**用 `int64` 显式声明意图。**
7. **对负数底数「先取绝对值再补符号」** —— 会造成 `x = −2, n = −2³¹` 这类输入上先算 `2^(2³¹)`（必为 `+Inf`），再取倒数得到 `0`，而正确答案是 `+0`（偶次幂为正）—— `0` 与 `-0` 在判题里虽然相等，但若中间算成 `-Inf` 再取倒数就会得到 `-0`，与期望的 `+0` 在严格比较下可能出问题。**结论：别取绝对值，让乘法自己处理符号。**

### 144.6.3 面试官最爱追问的三个问题

**Q1：为什么不直接乘 `n` 次？快速幂凭什么快？**

> 「因为乘法满足结合律，可以把 `n` 个相同因子重新分组。`x^13 = x^8 · x^4 · x^1`，而 `x^1, x^2, x^4, x^8` 只要 3 次平方就能全部拿到。于是总代价从 `n` 次乘法降到 `O(log n)` 次——`n = 2³¹` 时是 21 亿次 vs 31 轮。关键在于**复用**：算 `x^8` 时不再从头乘，而是在 `x^4` 的基础上平方一次。」

**Q2：`n` 是 `−2³¹` 的时候，你的代码为什么不崩？**

> 「因为我在第一行就把 `n` 提升成了 `long`：`long N = n;`。`−2³¹` 在 `int` 里没有对应的正数（补码范围是 `[−2³¹, 2³¹−1]`，正数少了 1 个），所以 `-n` 会溢出回 `-2³¹`；而 `long` 装得下 `2³¹`，取负得到正确的大正数。后面所有循环变量都用 `long`，就不会再溢出。Go 里我用 `int64`，理由相同——虽然 amd64 上 `int` 是 64 位碰巧安全，但那是平台的便宜，不是代码的正确性。」

**Q3：递归版和迭代版，选哪个？**

> 「数学上是同一个式子：`x^n = (x^{n/2})² · [n 奇 ? x : 1]`。递归版更好读，代码短，但用 `O(log n)` 栈空间；迭代版用 `O(1)` 空间，而且能直接套到「矩阵快速幂」「模幂」上（这三种只是把 `*` 换成别的运算，骨架完全一样）。**实际提交用迭代版**；如果面试官要求「把递归改写成迭代」，就是把 `half` 的返回值挪到变量里、把「指数减半」改成「指数右移一位」。」
