## 122.1 题目

**原题链接**：<https://leetcode.cn/problems/russian-doll-envelopes/>

### 题意重述（把隐含条件补齐）

给你 `n` 个信封，每个用 `[w, h]` 表示宽和高。**当且仅当**一个信封的宽和高**都严格大于**另一个信封时，才能把它套进去。问最多能套多少层（每个信封最多用一次）。

这道题的题干只有三行，但藏着五个判定条件，任何一条读错都会得到另一个答案：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 宽和高**都必须严格更大** | 「both the width and height are larger」，中文「都大于」 | 写 `>=` 时 `[[4,5],[5,5]]` 会答 2，正确 1 |
| **不能旋转**信封 | 题面只允许「套」，没有 90° 旋转的说法 | 若允许旋转（宽高可交换），`[[5,4],[6,6]]` 答案会变 —— LC 3633 是那个变体 |
| 每个信封**最多用一次** | 「You can put one envelope inside another」 | 允许重复用就会无限套 |
| 只要**层数**，不要具体组合 | 「return the maximum number of envelopes」 | 输出组合要额外记录前驱 |
| `n` 可到 `10^5`，宽高可到 `10^5` | 约束表 | **`O(n²)` 会 TLE**，这是本题被归为「困难」的真正原因 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= envelopes.length <= 10^5` | n 最大十万 | `O(n²) = 5·10⁹` 次比较 → **≈ 50 秒，必 TLE**；`O(n log n) ≈ 1.7·10⁶` 次 → 30 ms 级 |
| `1 <= w, h <= 10^5` | 值域不大 | 可以做值域数组 / 树状数组优化（`O(n log V)`），但排序 + 二分的常数更小 |
| 宽高都是正数 | 无 0 / 无负 | 不用考虑哨兵与负数比较 |
| 同一宽可能重复出现 | 题面没禁止 | **这就是排序陷阱的来源**（§122.2 第四步） |

> 💡 **量级 → 算法**：`10^5` + 「求最长链」= 必须 `O(n log n)`。而「最长链」在二维偏序上只有两条路：① 排序降维 + 一维 LIS；② 树状数组维护前缀 max。本题的经典解是 ①，因为它把「排序」这个 `O(n log n)` 的代价顺手当成了降维手段。

### 示例

```text
输入：envelopes = [[5,4],[6,4],[6,7],[2,3]]
输出：3
解释：能套成 [2,3] → [5,4] → [6,7]，三层
      注意 [6,4] 与 [6,7] 宽度相同，不能互相套

输入：envelopes = [[1,1],[1,1],[1,1]]
输出：1
解释：宽度相同且高度相同，任何两个都不能套

输入：envelopes = [[4,5],[4,6],[6,7],[2,3],[1,1]]
输出：4
解释：[1,1] → [2,3] → [4,5] → [6,7]（或 [4,6] → [6,7]，但 [4,5] 与 [4,6] 不能同时选）
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [[1,1],[1,1]]                    → 全等：答案 1，用来验「严格」二字
② [[4,5],[4,6],[6,7],[2,3],[1,1]]  → 同宽陷阱：正确 4；错误排序（宽高都升序）会答 5
③ [[2,3],[5,4],[6,7],[6,8]]        → 同宽但高度相差很大：若宽高都升序，会误把 [6,7],[6,8] 都算进去
④ [[1,1],[2,2],[3,3],[4,4]]        → 完美链：答案 4，验「回答长度」而不是「回答下标」
```

第 ② 条就是本章的核心反例，`§122.4.2` 会把它的错误轨迹逐步画出来。

## 122.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有子集

「最多能套几层」= 在一个有向图上找最长链。最直白的做法是枚举所有子集，判断它们能不能按某个顺序全部嵌套：

```text
for mask in [0, 2^n):                     # 每个信封选 / 不选
    if 选出的信封能按宽高双关键字严格递增排成一列:
        ans = max(ans, popcount(mask))
```

- 时间 **O(2ⁿ·n log n)**，`n = 10^5` 时毫无意义。
- 它唯一的价值是当对拍基准（§122.5.4）。

### 第二步：`O(n²)` —— 把「链」想成 DAG 的最长路

把每个信封看成一个顶点，若 `i` 能套住 `j` 就加边 `j → i`。因为「宽高都严格更大」是一个**严格偏序**，这个图**无环**，于是问题变成 **DAG 最长路**：

```text
按宽度排序后（能套的关系一定是从窄到宽）：
dp[i] = 1 + max{ dp[j] : j < i 且 w[j] < w[i] 且 h[j] < h[i] }
答案  = max dp[i]
```

- 时间 `O(n²)`，空间 `O(n)`。
- `n = 10^5` 时 `10^10/2 = 5·10⁹` 次「双关键字比较 + max」，按每秒 `10⁸` 次算 **≈ 50 秒** → **TLE**。这就是「困难」的判定线。

### 第三步：卡点在哪 —— 两个维度同时约束

对比 121 题（一维 LIS）：那里「能不能接上」只看 `nums[j] < nums[i]` 一个条件，于是可以把「同长度的最小结尾」压成一个 `tails` 数组。

现在有两个条件：`w[j] < w[i]` **且** `h[j] < h[i]`。**一个 `tails` 槽位装不下两个维度的代表元**。这是本题的真卡点：

> **不是「怎么二分」，而是「哪一维可以消失」。**

### 第四步：灵感的来源 —— 用排序把一维「吃掉」

注意一个不对称性：**宽度只要排好序，就自动满足「从窄到宽」**。于是：

```text
① 先按宽度升序排序   → 宽度这一维变成「下标顺序」，不需要再比较
② 再对「高度序列」求 LIS → 但必须让 LIS 里的高度严格递增
```

但这里有个**致命的陷阱**，也是这道题的真正考点：

> **若把宽度相同的信封按高度【升序】排列，它们的高度就会构成一段递增序列，被 LIS 算进去 —— 而它们明明不能互相嵌套！**

### 第五步：排序陷阱 —— 同宽必须按高度【降序】

正确的排序键是：

```text
第一关键字：宽度 w   升序  ↑
第二关键字：高度 h   降序  ↓      ← 只有在同宽时才起作用
```

为什么降序能修好它？看同宽的三个信封 `[[4,5],[4,6],[4,7]]`：

```text
✅ 正确排序（同宽高度降序）：  (4,7)  (4,6)  (4,5)
   高度序列 = [7, 6, 5] → 严格递减 → 任意两个都不构成递增对 → 最多选 1 个 ✅

❌ 错误排序（同宽高度升序）：  (4,5)  (4,6)  (4,7)
   高度序列 = [5, 6, 7] → 严格递增 → LIS 认为能连成 3 个 ❌（实际只能选 1 个）
```

**原理一句话**：`w` 相同的元素如果在高度上递减，那么**任何严格递增的高度子序列都不可能同时包含它们中的两个**（因为取下标靠后的那个必然高度更小，矛盾）。于是「同宽只能选一个」这条约束被排序**自动**满足了，不需要在 LIS 里额外加判断。

> ⚠️ 反过来，如果写成「宽升序、高升序」，那么同宽的信封在高度上也可能递增，LIS 就会把它们当成合法链 —— 这是本题 90% 的 WA 来源。

## 122.3 原理拆解

### 122.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举子集 | `O(2ⁿ n log n)` | `O(n)` | 25 行 | `n ≥ 25` 就用不了，只能对拍 |
| `O(n²)` DAG 最长路（双关键字） | `O(n²)` | `O(n)` | 12 行 | `n = 10^5` 时约 50 秒 → **TLE** |
| **排序（宽升/高降）+ 一维 LIS** ✅ | **`O(n log n)`** | `O(n)` | 20 行 | 三维及以上失效（要 CDQ 分治）；要输出方案需加前驱 |
| 排序（宽升）+ 树状数组按高度维护前缀 max | `O(n log n)` | `O(V)` 或 `O(n)`（离散化） | 40 行 | 代码量翻倍；但**能顺带统计方案数 / 支持动态插入** |
| 图论 + 拓扑排序 + DP | `O(n²)` 建边 | `O(n²)` | 50 行 | 边数 `O(n²)`，`n = 10^5` 内存就 40 GB |
| 排序（宽升/高降）+ LIS 的 **`O(n²)` 版** | `O(n²)` | `O(n)` | 12 行 | 同上；只在教学/对拍时用 |

**为什么选「排序 + LIS」**：它把「排序」这个本来要付的代价变成了降维工具，而且 `tails` 版 LIS 只有 12 行。树状数组版要处理离散化与「同宽不能同链」的时序问题（必须先按宽分组、整组查询完再插入），代码量与调试成本都高出一档。

### 122.3.2 为什么这个做法是对的（正确性论证）

设排序后的信封为 `e₀, e₁, …, e_{n-1}`（`w` 升序，同宽 `h` 降序），令 `H = [h₀, h₁, …, h_{n-1}]`，`L = len(LIS(H))`（严格递增）。记原始问题的答案为 `OPT`。

**引理 1（`H` 的任一严格递增子序列 ⇔ 一个合法嵌套链）**

- **(⇐) 链 ⇒ 递增子序列**：设 `e_{i₁}, e_{i₂}, …, e_{i_k}`（`i₁ < i₂ < … < i_k`）是一个合法链，即 `w` 与 `h` 都严格递增。按排序规则，宽度小的一定排在前（同宽内部高度递减，不可能出现两个同宽元素一前一后都满足 `h` 递增），所以它们在排序数组里的下标自然递增，且 `h_{i₁} < h_{i₂} < … < h_{i_k}`，于是是 `H` 的一个严格递增子序列。**长度 `k` 的链 ⇒ 长度 `k` 的递增子序列。**
- **(⇒) 递增子序列 ⇒ 链**：设 `i₁ < i₂ < … < i_k` 且 `h_{i₁} < … < h_{i_k}`。因为排序保证 `w_{i₁} ≤ w_{i₂} ≤ … ≤ w_{i_k}`，若某个相邻对宽度相等，则它们同宽；但同宽块内高度**严格递减**，而 `i₁ < i₂` 时同宽会给出 `h_{i₁} > h_{i₂}`，与递增矛盾。所以所有相邻对的宽度都**严格**递增，同理高度严格递增 ⇒ 这是一个合法链。**长度 `k` 的递增子序列 ⇒ 长度 `k` 的链。**

两条合起来给出 `OPT = L`。∎

> 🔑 **注意引理 1 的两个方向都依赖排序规则**。这正是「排序方向不能随便」的严格表述：若同宽按高度升序，「递增子序列 ⇒ 链」这一步就会断掉。

**引理 2（`tails` 的正确性）**：直接继承 121 题的结论 —— `tails[k]` 是「长度 `k+1` 的严格递增子序列的最小结尾」，`tails` 严格递增，用 `lower_bound` 替换，`len(tails)` 即 LIS 长度。

**边界**：空数组时 `tails` 为空、答案 0；只有一个信封时答案 1。`lower_bound` 的 `hi` 初值取有效长度 `len`，因此「全部更大 ⇒ append」的分支天然支持。

### 122.3.3 通用解题思路（可迁移的那一层）

本题属于 **「二维偏序上的最长链」** 模型，它有一条固定的三段式解法：

```text
① 明确偏序：i 能接在 j 后面 ⇔（第 1 维严格大）且（第 2 维严格大）
        ↓
② 排序吃掉一维：按第 1 维升序；【关键】对「第 1 维相等」的元素，第 2 维必须降序
   —— 目的：让「相等的第 1 维」在第二维上无法连成递增对
        ↓
③ 对第 2 维求严格递增 LIS（tails + lower_bound）
```

**模型迁移表**：

| 题 | 两个维度 | 排序键 | 容易踩的坑 |
| --- | --- | --- | --- |
| [LC 354 俄罗斯套娃信封](https://leetcode.cn/problems/russian-doll-envelopes/)（本题） | 宽、高 | 宽升、高降 | 同宽降序是**唯一**正确方向 |
| [LC 646 最长数对链](https://leetcode.cn/problems/maximum-length-of-pair-chain/) | 左端点、右端点 | 左升、右升（或按右端点贪心） | 允许**相等接续**时是 `>=`/`<=` 语义，要改比较符 |
| [LC 435 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/) | 起点、终点 | 按终点升序贪心 | 「不重叠」是 `start >= end`（非严格），贪心即可，不必 LIS |
| [LC 2054 两个最好的不重叠活动](https://leetcode.cn/problems/two-best-non-overlapping-events/) | 时间、价值 | 按结束时间升序 + 前缀 max | 只有两段，用「枚举第二段 + 查前缀最优」 |
| [LC 1691 堆叠长方体的最大高度](https://leetcode.cn/problems/maximum-height-by-stacking-cuboids/) | 三维 | 三维排序 + 变体 LIS | 允许旋转 ⇒ 先枚举 6 种姿态再排序 |

> 🔑 **一句话**：二维偏序题的第一动作是**问「能不能排序消掉一维」**，第二动作是**问「相等的那一维怎么排才不会误连」**。这两个问题的答案决定了 `O(n²) → O(n log n)` 是否成立。

### 122.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 允许**旋转**信封（宽高可交换） | 每个信封变两个候选 | 先把每个信封拆成 `(w,h)` 与 `(h,w)` 两个，再去重，然后照本题做；见 LC 1691 的思路 |
| 要**输出一条最长链** | 从长度变方案 | 回到 `O(n²)` 记录前驱，或用树状数组维护 `(长度, 前驱下标)` 二元组 |
| 要**统计最长链的条数** | 计数 | 树状数组维护 `(maxLen, count)`，比较时先比长度再累加计数 |
| 升到**三维**（宽、高、厚） | 排序只能消一维 | 排序 + **CDQ 分治**（分治 + 树状数组）压到 `O(n log² n)`；或直接 `O(n²)` 多维 DP |
| **动态插入**信封并随时问答案 | 不能一次排序 | 用树状数组/线段树按高度维护前缀 max，插入时查询并更新，`O(log V)` 每次 |
| 宽度可到 `10^9` | 值域大 | `tails` 方案**天然免疫**（它只比较不索引）；树状数组方案必须先离散化 |

**三维版本为什么要 CDQ 分治**（只给思路，不给完整实现）：三维排序后，对「第二维」做归并分治，用树状数组处理第三维的前缀 max —— 本质是把「排序消一维」这个动作再套一层，用 `O(log n)` 的分治层数换掉剩下的那一维。这也是「一维排序 + 一维 LIS」无法处理三维的原因：**排序只能消掉一个维度**。

## 122.4 图解推演

### 122.4.1 排序前后的对照（`envelopes = [[5,4],[6,4],[6,7],[2,3]]`）

```text
原始输入：
  ┌────────┬────────┬────────┬────────┐
  │ [5,4]  │ [6,4]  │ [6,7]  │ [2,3]  │
  └────────┴────────┴────────┴────────┘

排序：宽升序，同宽【高度降序】
  ┌────────┬────────┬────────┬────────┐
  │ [2,3]  │ [5,4]  │ [6,7]  │ [6,4]  │   ← 宽度 6 的两项：高度 7 在前、4 在后
  └────────┴────────┴────────┴────────┘
      w=2      w=5      w=6      w=6
  高度序列 H = [ 3 ,  4 ,  7 ,  4 ]
                            ▲      ▲
                            └──┬───┘
                     同宽块内 7 > 4：任何严格递增子序列
                     都不可能同时取到这两个位置

对 H 求严格递增 LIS：
  x=3  → tails=[3]
  x=4  → 无 >=4 → append → tails=[3,4]
  x=7  → 无 >=7 → append → tails=[3,4,7]
  x=4  → 第一个 >=4 是 4（下标 1）→ replace → tails=[3,4,7]
  答案 len(tails) = 3        ✅ [2,3] → [5,4] → [6,7]
```

### 122.4.2 错误排序的完整反例轨迹（本章最重要的一张图）

用反例 ②：`[[4,5],[4,6],[6,7],[2,3],[1,1]]`。

```text
❌ 错误排序：宽升序、同宽高度【升序】
  [1,1]  [2,3]  [4,5]  [4,6]  [6,7]
   H = [ 1 ,  3 ,  5 ,  6 ,  7 ]   → 严格递增，LIS = 5
   结果答 5：链被当成 [1,1]→[2,3]→[4,5]→[4,6]→[6,7]
                              ▲      ▲
                              └──┬───┘
                     【错在这里】[4,5] 与 [4,6] 宽度相同，根本套不进去！

✅ 正确排序：宽升序、同宽高度【降序】
  [1,1]  [2,3]  [4,6]  [4,5]  [6,7]
   H = [ 1 ,  3 ,  6 ,  5 ,  7 ]
   对 H 求 LIS：
     x=1 → tails=[1]
     x=3 → tails=[1,3]
     x=6 → tails=[1,3,6]
     x=5 → 第一个 >=5 是 6 → replace → tails=[1,3,5]
     x=7 → append → tails=[1,3,5,7]
   LIS = 4   ✅ [1,1]→[2,3]→[4,5]→[6,7]（或 [4,6] 版本）
```

把两次轨迹并排看，差别的唯一来源就是 `[4,5]` 与 `[4,6]` 的先后：**升序时它们是「递增高对」，降序时是「递减错对」**。

### 122.4.3 逐步推演表

| 步骤 | 当前信封 | 二分位置 `p` | 操作 | `tails` | `len` |
| --- | --- | --- | --- | --- | --- |
| 1 | `[1,1]` → h=1 | 0 | append | `[1]` | 1 |
| 2 | `[2,3]` → h=3 | 1（`len`） | append | `[1,3]` | 2 |
| 3 | `[4,6]` → h=6 | 2（`len`） | append | `[1,3,6]` | 3 |
| 4 | `[4,5]` → h=5 | 2（第一个 `≥5` 是 6） | replace | `[1,3,5]` | 3 |
| 5 | `[6,7]` → h=7 | 3（`len`） | append | `[1,3,5,7]` | **4** |

> 🔎 **第 4 步是「降序」生效的位置**：`[4,5]` 到来时把 `tails[2]` 从 6 压到 5，于是第 5 步的 `7` 才能接上。如果同宽按升序，第 3 步就会是 `[4,5]`（append 到 5），第 4 步 `[4,6]` 继续 append 到 6 —— `len` 白涨一格。

## 122.5 双语言实现

### 122.5.1 Java

```java
import java.util.Arrays;

class Solution {
    public int maxEnvelopes(int[][] envelopes) {
        // 排序规则是本解法唯一「有思想」的地方：
        //   宽升序 —— 宽小的排前面，天然满足「窄的能被宽的套」
        //   同宽时高【降序】—— 让同一宽度的信封在高度上递减，
        //                      任何严格递增的高度子序列都取不到两个同宽的
        //                      （取第二个必然高度更小，与递增矛盾）
        // 写成 a[1] - b[1]（升序）会让本题答案偏大，这是第一大 WA。
        Arrays.sort(envelopes, (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0])
                                                      : Integer.compare(b[1], a[1]));

        // 之后就是对「高度序列」求严格递增 LIS，与 121 题完全同构
        int n = envelopes.length;
        int[] tails = new int[n];
        int len = 0;
        for (int i = 0; i < n; i++) {
            int h = envelopes[i][1];
            int lo = 0, hi = len;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (tails[mid] < h) {
                    lo = mid + 1;
                } else {
                    hi = mid;      // 严格递增 ⇒ 相等时要替换，所以收缩到 mid
                }
            }
            tails[lo] = h;
            if (lo == len) {
                len++;
            }
        }
        return len;                // 空输入返回 0
    }
}
```

### 122.5.2 Go

```go
package main

import "sort"

func maxEnvelopes(envelopes [][]int) int {
	// 与 Java 版逐字对应的排序规则
	// 注意 Comparator 里不要写 a[1]-b[1] 之外的花活：
	// Go 的 sort.Slice 不稳定（pdqsort），所以「同宽降序」必须写进比较函数，不能靠输入顺序
	sort.Slice(envelopes, func(i, j int) bool {
		if envelopes[i][0] != envelopes[j][0] {
			return envelopes[i][0] < envelopes[j][0] // 宽升序
		}
		return envelopes[i][1] > envelopes[j][1] // 同宽：高降序
	})

	// 高度序列上的严格递增 LIS，用 tails 维护「每个长度对应的最小结尾」
	tails := make([]int, 0, len(envelopes))
	for _, e := range envelopes {
		h := e[1]
		// sort.Search 的谓词是「第一个使 f(i) 为 true 的下标」，这里即第一个 >= h
		p := sort.Search(len(tails), func(k int) bool { return tails[k] >= h })
		if p == len(tails) {
			tails = append(tails, h)
		} else {
			tails[p] = h
		}
	}
	return len(tails)
}
```

### 122.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维数组表示 | `int[][]`，`envelopes[i][0]` 是 `int` | `[][]int`，同样是切片 | 语义一致；但 Go 的 `[][]int` 每个内层切片头占 24 字节，`n = 10^5` 时内存比 Java 高 |
| 排序 API | `Arrays.sort(T[], Comparator)`，**稳定**（TimSort） | `sort.Slice` **不稳定**（pdqsort） | 本题排序键已唯一确定顺序（宽、高都相同则完全等价），稳定性不影响；但若「同宽同高但还有第三字段」，Go 必须把第三字段也写进比较函数 |
| 比较器写法 | `Comparator` 返回负数/0/正数，用 `Integer.compare` 避免溢出 | `less(i,j) bool` 返回布尔 | Go 的布尔比较器**不能**用 `a-b<0` 的思维直接翻译，容易写成「相等时返回 true」导致排序 panic |
| 二分 | 手写 `lower_bound` | `sort.Search(len, pred)` | Go 的 `Search` 传的是「谓词」，语义更一般但要理解「返回第一个 true」；本题谓词是 `tails[k] >= h` |
| 空输入 | `envelopes.length == 0` → 排序不报错，返回 0 | 同 | 本题约束 `n ≥ 1`；但 `tails := make([]int,0,n)` 对 0 长度也安全 |

### 122.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：排序后做 O(n^2) 的双关键字 DAG 最长路
// 注意它的排序用「宽升、高升」是可以的 —— 因为比较时要求【严格】
// 大于，同宽的两项永远无法互相接续，排序方向随便都能得到正确答案
func maxEnvelopesBrute(env [][]int) int {
	n := len(env)
	a := make([][2]int, n)
	for i := range env {
		a[i] = [2]int{env[i][0], env[i][1]}
	}
	// 冒泡排序（n 很小），宽升序、同宽高升序
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			if a[j][0] < a[i][0] || (a[j][0] == a[i][0] && a[j][1] < a[i][1]) {
				a[i], a[j] = a[j], a[i]
			}
		}
	}
	best := 0
	dp := make([]int, n)
	for i := 0; i < n; i++ {
		dp[i] = 1
		for j := 0; j < i; j++ {
			if a[j][0] < a[i][0] && a[j][1] < a[i][1] && dp[j]+1 > dp[i] {
				dp[i] = dp[j] + 1
			}
		}
		if dp[i] > best {
			best = dp[i]
		}
	}
	return best
}

func TestMaxEnvelopesRandom(t *testing.T) {
	edges := [][][]int{
		{},                             // 空
		{{1, 1}},                       // 单个
		{{1, 1}, {1, 1}},               // 全等 → 1
		{{5, 4}, {6, 4}, {6, 7}, {2, 3}},                       // 题面样例 → 3
		{{4, 5}, {4, 6}, {6, 7}, {2, 3}, {1, 1}},               // 同宽陷阱 → 4
		{{1, 1}, {2, 2}, {3, 3}, {4, 4}},                       // 完美链 → 4
		{{2, 3}, {5, 4}, {6, 7}, {6, 8}},                       // 同宽高度差大 → 3
		{{1, 15}, {7, 18}, {7, 2}, {7, 12}, {7, 19}},           // 一宽多高 → 2
	}
	want := []int{0, 1, 1, 3, 4, 4, 3, 2}
	for i, env := range edges {
		if got := maxEnvelopes(cloneEnv(env)); got != want[i] {
			t.Fatalf("edge %d env=%v got=%d want=%d", i, env, got, want[i])
		}
		if got := maxEnvelopesBrute(env); env != nil && got != want[i] {
			t.Fatalf("edge %d 暴力与预期不符 env=%v got=%d want=%d", i, env, got, want[i])
		}
	}

	r := rand.New(rand.NewSource(354354))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(12)
		env := make([][]int, n)
		for i := range env {
			// 值域刻意压到 [1, 6]：同宽 / 同高的组合大量出现，才能逼出排序方向的 bug
			env[i] = []int{1 + r.Intn(6), 1 + r.Intn(6)}
		}
		got := maxEnvelopes(cloneEnv(env))
		if w := maxEnvelopesBrute(env); got != w {
			t.Fatalf("iter=%d env=%v got=%d want=%d", iter, env, got, w)
		}
	}
}

// maxEnvelopes 会原地排序输入，所以对拍时必须传副本，否则第二次调用拿到的是已排序数据
func cloneEnv(env [][]int) [][]int {
	out := make([][]int, len(env))
	for i := range env {
		out[i] = []int{env[i][0], env[i][1]}
	}
	return out
}
```

> ⚠️ **这段测试自己踩过一个坑**：最初我直接 `maxEnvelopes(env)` 之后又用 `env` 去调暴力 —— 但 `maxEnvelopes` 内部 `sort.Slice` 会**原地修改切片**，暴力拿到的已经是排好序（且被降序打乱）的数据。虽然本题恰好答案不变，但这类「函数有副作用」在对拍里是隐藏杀手，所以 `cloneEnv` 是必须的。

## 122.6 复杂度与常见坑

### 122.6.1 复杂度推导（写结论不算本事，要能推）

- **排序 O(n log n)**：`Arrays.sort` 对对象数组用 TimSort（比较次数 ≈ `n log₂ n`）；Go 的 `sort.Slice` 用 pdqsort，平均 `n log n`，最坏也保证 `n log n`（有 fallback）。`n = 10^5` 时约 `1.7·10⁶` 次比较。
- **LIS O(n log n)**：每个元素一次二分，二分区间长度 `≤ 最终答案 L ≤ n`，总比较次数 `Σ log(len_i) ≤ n log n`。
- **总计 O(n log n)**，空间 `O(n)`（排序可能用 `O(log n)` 栈 + `tails` 的 `O(n)`）。
- **为什么 `O(n²)` 不行（定量）**：`n = 10^5` ⇒ `n(n-1)/2 ≈ 5·10⁹` 次双关键字比较；按每秒 `10⁸`~`10⁹` 次估算需要 **5~50 秒**，LeetCode 限制通常 1~5 秒。这不是「常数慢」，是**量级差**。
- **`O(n log n)` 是不是下界**：二维偏序最长链可以归约到「元素唯一性」，因此一般情况下的下界是 `Ω(n log n)`；本题达到下界。

### 122.6.2 七个真实踩过的坑

1. **同宽按高度【升序】排序** —— 本题第一大坑，`[[4,5],[4,6],[6,7],[2,3],[1,1]]` 会答 5（正确 4）。修法：`h` 降序。
2. **把降序写成 `a[1] - b[1]` 之外的样子（比如对 `h` 取负）导致溢出** —— `h ≤ 10^5` 时安全，但如果约束放大到 `-10^9`，`-h` 在 `Integer.MIN_VALUE` 上溢出。用 `Integer.compare(b[1], a[1])`。
3. **LIS 用了非严格比较（`<=`）** —— 那「同宽降序」这个技巧就失效了（递减序列在非严格语义下也能被算进去？不，反过来会让 `[4,6],[4,5]` 中的 5 无法替换 6 的位置，答案偏小；而若排序方向写反又用非严格，答案偏大）。**两条规则必须成对使用：宽升 + 高降 + 严格递增**。
4. **对 `w` 也做去重** —— 有人想「同宽只能选一个，那先去重只留最大的高度」。这是对的（保留同宽里最大的 `h` 即可），但去重后**必须仍然按 `h` 严格递增做 LIS**，且去重要在排序之后做。写错顺序会漏解。
5. **在 Go 里对 `[][]int` 用 `sort.Slice` 后忘了输入被修改** —— 同一次运行里重复调用同一份数据，结果会错。生产代码应复制或文档注明。
6. **比较器不满足严格弱序** —— 写成 `return envelopes[i][1] <= envelopes[j][1]`（相等时返回 `true`）在 Go 里会让 `sort` 报 `invalid comparator` 或产生未定义顺序；Java 的 TimSort 会抛 `IllegalArgumentException: Comparison method violates its general contract!`。
7. **以为「宽高都升序」只要 LIS 用严格比较就没问题** —— 严格比较只能挡住「同宽同高」，挡不住「同宽不同高」。本题的陷阱在**宽度相等时的连通性**，不在高度相等。

### 122.6.3 面试官最爱追问的三个问题

**Q1：为什么同宽要按高度降序，升序为什么错？**

> 「因为 LIS 只看高度序列的严格递增性，而『同宽不能互套』这条约束必须**在排序阶段就消灭掉**。同宽按高度降序后，同宽块内高度严格递减，任何严格递增子序列最多只能取到其中一个（取第二个必然高度更小，与递增矛盾）。若按升序，同宽块内高度递增，LIS 会把它们连成一条假的链。反例 `[[4,5],[4,6],[6,7],[2,3],[1,1]]`：升序答 5，降序答 4，后者正确。」

**Q2：能不能不用排序，直接做二维 DP 或者树状数组？**

> 「可以。二维 DP 是 `O(n²)`，`n = 10^5` 会 TLE。树状数组做法：按宽度分组、组内按高度降序，遍历时先对所有同宽元素查询『高度严格小于 h 的最大链长』，**等这一组全部查完再统一插入**，保证同宽不互连；复杂度 `O(n log n)`，但要先离散化高度。它比排序 + LIS 代码长一倍，唯一优势是能顺带统计方案数或支持动态插入。」

**Q3：如果有三个维度（宽、高、厚）怎么办？**

> 「排序只能消掉一维，剩下两维必须靠 CDQ 分治或二维树状数组。标准做法是：三维排序 + CDQ 分治（按第二维归并、用树状数组维护第三维的前缀 max），复杂度 `O(n log² n)`。面试里一般只要求说清『一维排序 + 一维 LIS 为什么只能处理二维』，能答出 CDQ 的名字与复杂度就够了。」
