## 056.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-valid-parentheses/>

### 题意重述（把隐含条件补齐）

给你一个只含 `(` 和 `)` 的字符串 `s`，返回**最长的有效（格式正确且连续）括号子串**的长度。

四个必须读出来的细节：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **是「子串」不是「子序列」** | 题面「连续子串」 | 按子序列做（可以跳过字符）→ `"()(()"` 会返回 4，正确是 2 |
| **只有一种括号** | 题面只含 `(` `)` | 这一点是本章能用「两次计数法」的根本原因；若有三种括号，只能走栈（见 `055.3.1`） |
| **答案可以是 0** | `""`、`"("`、`")"` 都合法输入 | 不处理空串 → 越界；把「找不到」初始化成 `-1` → 答案脏 |
| **长度必须是偶数** | 推论（一对括号长度 2） | 记录到奇数长度说明逻辑已经错了，可以当作断言用 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= s.length <= 3·10⁴` | n 最多 3 万 | **O(n³) 彻底不可用**：本机 Go 实测 `n=400` 的暴力已 **4.19 ms**，外推 `n=3·10⁴` ≈ **29 分钟**；`O(n²)` 是 `9·10⁸` 次操作，也很悬 |
| 只有两种字符 | 字符集 = 2 | 可以用计数器做 `O(1)` 空间的两次扫描 |
| 只要长度 | 不需要起点下标 | 若同时要「最长段的起止位置」，栈法是唯一不额外加代码的（栈顶就是左边界） |
| 单组用例、无多测 | `3·10⁴` 单次 | `O(n)` 一遍过；即使 `O(n)` 跑两遍也只有 `6·10⁴` 次迭代 |

> 💡 **量级 → 算法**：`3·10⁴` 这个数字在 LeetCode 里是**明确的信号**：`O(n²)` 会有 9 亿次操作、必然 TLE，所以**必须做到 `O(n)` 或 `O(n log n)`**。
> 看到「最长子串 + 括号」直接排除枚举子串的暴力，去想「怎么在一趟扫描里既维护合法性、又维护长度」。

### 示例

```text
输入：s = "(()"
输出：2
解释：最长有效子串是 "()"（下标 1~2）。★ 注意前缀那个孤立的 '(' 让"从头开始"的段永远不能闭合。

输入：s = ")()())"
输出：4
解释：最长有效子串是 "()()"（下标 1~4）。末尾多出来的 '(' ')' 被前面的 ')' 断开了。

输入：s = ""
输出：0

输入：s = "()(())"
输出：6
解释：整串都合法。
```

### 我自造的七个反例（写完必须拿它们打一遍）

```text
① ""              → 打「空串越界」：正确 0
② "("             → 打「答案初始化成 -1 / Integer.MIN_VALUE」
③ "(()"           → ★ 打「只做一次从左到右的计数」：正扫永远等不到 left==right，正确 2
④ "())"           → 打「只做一次从右到左的计数」：反扫漏掉它，正确 2
⑤ ")()())"        → 打「栈弹出后不更新哨兵」：正确 4
⑥ "()(()"         → 打「把子序列当子串」：正确 2（子序列会算成 4）
⑦ "(((("+")"*4    → 打「递归实现」：深度 4 万层直接爆栈
```

第 ③ 和第 ④ 条必须成对理解：**它们是「两次计数法为什么必须扫两遍」的最小证据**，缺一遍就在其中一个上错。`056.4.2` 会用图把这两条摆在一起。

## 056.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（枚举所有子串，用计数器验证）

「最长」的自然暴力：枚举所有偶数长度的子串，判断它是否合法，取最长。

```java
// 暴力：O(n³) —— 枚举 O(n²) 个子串，每个用 O(n) 验证
int ans = 0;
for (int i = 0; i < n; i++) {                  // 起点
    for (int j = i + 2; j <= n; j += 2) {      // 终点（长度必须偶数）
        int bal = 0;
        boolean ok = true;
        for (int k = i; k < j; k++) {          // 验证这一段
            bal += (s.charAt(k) == '(') ? 1 : -1;
            if (bal < 0) { ok = false; break; }
        }
        if (ok && bal == 0) ans = Math.max(ans, j - i);
    }
}
```

- 时间 **O(n³)**，空间 **O(1)**。
- 本机 Go 实测（最坏形态 `s = "((((..."`，短路不生效）：`n=100` **0.195 ms**、`n=200` **0.576 ms**、`n=400` **4.19 ms** —— 每翻倍约 **7~8 倍**，标准的 `n³` 斜率。外推 `n=3·10⁴` 约 **29 分钟**。

### 第二步：卡点在哪

把问题翻译成一句话：

> **对每个位置 `i`，我要知道「以 `i` 结尾的最长合法后缀有多长」。**

暴力的卡点是：它把「每个终点」都从头重扫了一遍 `O(n)`。而**相邻两个终点之间的信息几乎没变过**：多了一个字符而已。这跟 `001` 的「查找被做成线性」是同一类浪费，只是这里的浪费发生在「合法性判定」上。

再看一层：为什么「以 `i` 结尾的最长合法后缀」这么难维护？因为**合法性依赖「最近的未闭合左括号在哪里」**，而这个信息在字符层面是「跨距离」的 —— 你必须记住位置。

### 第三步：灵感的来源 —— 长度是「两个下标的差」

这是本题最关键的一个人工转化：

> **「长度」不是一种独立的状态，而是「当前位置」与「最近一个断点」之间的差。**

于是问题变成：**扫描时，怎么维护「最近一个断点」？**

- 断点是什么？就是**那些无法被匹配的字符**：
  - 一个多余的 `)`：它右边到「下一个断点」之间才可能有合法段；
  - 开头：如果整段从下标 0 开始就合法，那断点就是「下标 -1」这个虚构位置。
- 一旦把「断点」这件事想清楚，`下标 + 哨兵` 的写法就水到渠成了 —— 哨兵 `-1` 就是「下标 0 左边的那个假想断点」。

```
合法段长度 = i(当前) - 断点下标
                ↓
把「断点」和「未闭合的左括号」都放进同一个栈里，用下标表示
                ↓
栈里自底向上的结构： [最近断点, 未闭合左括号..., 栈顶 = 最近未闭合]
```

这就是栈解的全部秘密：**栈不是「存括号」，而是「存一串位置」，栈底那一格躺着断点。**

## 056.3 原理拆解

### 056.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举子串 + 计数验证 | O(n³) | O(1) | 12 行 | `n ≥ 2000` 就危险；本机 `n=400` 已 4.19 ms |
| 中心扩展（对每对相邻位置向两边扩） | O(n²) | O(1) | 15 行 | `n = 3·10⁴` → 9 亿次，必须 TLE |
| 动态规划（`dp[i]` = 以 `i` 结尾的最长合法长度） | O(n) | O(n) | 20 行 | 转移要处理 `dp[i-2]` 与 `dp[i-dp[i-1]-2]` 两个回跳，**边界写错率最高** |
| **栈（存下标 + 哨兵）** ✅ | **O(n)** | **O(n)** | **14 行** | 需要 `O(n)` 栈空间；但**它是唯一能顺手给出「最长段的起止下标」的** |
| **左右两次计数** ✅ | **O(n)** | **O(1)** | **18 行** | 需要扫两遍；只能求长度不能求位置；只在「单一括号类型」时成立 |

**实测对照**（Go 1.19，`n = 3·10⁴` 随机括号串）：

| 实现 | 耗时 / 次 | 备注 |
| --- | --- | --- |
| 栈（存下标 + 哨兵） | **0.167 ms** | 一遍扫描，`push/pop` 均摊 `O(1)` |
| 左右两次计数 | 0.511 ms | 两遍扫描、每字符 3 个分支；但空间 `O(1)` |
| 暴力 `O(n³)`（外推） | ≈ 29 分钟 | 完全相同的问题，差 7 个数量级 |

> **取舍怎么说（面试可直接背）**：**要空间**就选两次计数（`O(1)` 空间，代价是两遍扫描 + 拿不到位置）；**要位置、要可读性**就选栈（栈顶天然是左边界，一遍扫描）；**要「一遍过 + 不用额外空间」** 只有 DP 能凑合（但它仍是 `O(n)` 空间）。

### 056.3.2 为什么这个做法是对的（正确性论证）

#### 栈解：不变量 + 归纳

**不变量 `I(i)`**（处理完 `s[0..i-1]` 之后）：

> 栈中自底向上存着一串**严格递增的下标** `p_0 < p_1 < ... < p_k`，其中：
> ① `p_0` 是「最近一次无法匹配的位置」（初始为哨兵 `-1`，之后可能被某个多余的 `)` 覆盖）；
> ② `p_1 .. p_k` 是**尚未闭合的左括号**的下标，按出现顺序排列，`p_k` 最靠右；
> ③ 对任意 `t ∈ (p_0, i)`，`s[p_0+1 .. t]` 中 `(` 的个数始终不少于 `)` 的个数（即 `p_0` 之后到 `i-1` 还没有出现「右括号过剩」）。

**命题 1（记录的长度一定是合法段的长度）**：当算法在位置 `i` 读取 `)` 后栈非空，记录的 `i - stack.top` 中，`stack.top` 是此时最近的未闭合左括号下标（弹出之后的新栈顶），于是 `s[stack.top+1 .. i]` 内：
- 以 `(` 开头、`)` 结尾，首尾成对；
- 由不变量 ③（递归地成立），该段内任意前缀的 `(` 不少于 `)`；
- 首尾平衡。
故它是一个**合法子串**，其长度正是 `i - stack.top`。∎

**命题 2（不会漏掉最长的合法段）**：设 `[l, r]` 是任一合法子串，取最长者。考察算法扫到 `r` 的时刻：
- 由于 `[l,r]` 内部任意前缀都不出现「`)` 过剩」，且以 `)` 结尾，`s[r]` 一定是与 `s[l]` 或某个内部 `(` 闭合的那个 `)`。算法处理 `s[r]` 时弹出的正是与之配对的左括号下标 `q`（`q >= l`）。
- 弹出后，栈顶是什么？若 `q > l`，则 `s[l..q-1]` 是 `[l,r]` 内部的一段合法前缀，它自己会成对弹出，最终在某个时刻栈顶回到 `l-1`。若 `l == 0`，栈顶是哨兵 `-1`。
- 若 `l-1` 的位置是「多余的 `)`」，那它在扫描时已经被写入了栈底（覆盖了旧哨兵），所以栈顶恰为 `l-1`。
- 因此记录值 `= r - (l-1) = r - l + 1`，正是该合法段的长度。∎

> **这个论证的价值**：它同时解释了「哨兵为什么必须是 `-1`」（让 `l = 0` 的段也能算出 `r - (-1) = r+1` 这个长度）、「为什么会弹出后判空并把 `i` 压回去」（`i` 成为新断点），以及「为什么栈里必须存下标而不是字符」。三个最容易写错的地方，被同一个不变量管住了。

#### 两次计数法：一条严格的「捕获条件」引理

先定义**反射平衡**：设前缀和 `B(t) = #{ '(' in s[0..t] } - #{ ')' in s[0..t] }`，`M(t) = min_{0<=u<=t} B(u)`（并约定 `B(-1) = 0`）。带归零的正扫维护的计数器其实是

```
c(t) = B(t) - min(0, M(t))          ← 归零规则"right > left 就清零"的等价写法
```

于是**正扫在 `t` 处记录 `left == right` ⟺ `c(t) = 0` ⟺ `B(t) = min(0, M(t))`**。

对一个合法段 `[l, r]`（长度 `2p`），有 `B(r) = B(l-1)`，且段内 `B(t) >= B(l-1)`。代入上式可化出：

> **引理（正扫的捕获条件）**：正扫会在 `r` 处记录 `[l, r]` ⟺ `B(l-1) = M(l-1)` 且 `B(l-1) <= 0`。
> 也就是说：**正扫只能捕获「左侧没有多余左括号（`B(l-1) <= 0`）且 `l-1` 是运行最小值」的那一类合法段。**

对称地，把「反转 + 左右互换」这套镜像变换作用在同一个串上，就得到反扫的捕获条件：

> **引理（反扫的捕获条件）**：反扫会在 `l` 处记录 `[l, r]` ⟺ `B(r) = S(r)` 且 `B(r) <= B(n-1)`，其中 `S(r) = min_{v>=r} B(v)`。
> 也就是说：**反扫补上的正是「右侧没有多余右括号」的那一类。**

**两个引理合起来说明了「为什么必须两遍」**：正扫要求左侧干净，反扫要求右侧干净，而合法段完全可能「左侧脏、右侧干净」（`"(()"`）或「左侧干净、右侧脏」（`"())"`）—— 各由一个方向兜住。

**完备性**（把 `[l,r]` 取为最长合法子串后，上面两个条件不可能同时不成立）的完整情形合并步骤比较长，本节的做法是：**把这一步交给穷举验证** —— 本文的实现已在**全部 131071 个长度 `<= 16` 的括号串**上和 `O(n³)` 暴力逐一对比，结果完全一致（见 `056.5.4`）。这也是本书推荐的态度：**证到能说服自己，剩下的用穷举钉死。**

### 056.3.3 通用解题思路（可迁移的那一层）

**本章主题（与 055、057、058、059 共用）：栈里存的是「还没被解决的问题」——存什么、何时弹、弹出时结算了谁。**

| 三问 | 本题（056） | 与 055 的差别 |
| --- | --- | --- |
| **① 存什么** | 存**下标**：未闭合左括号的位置 + 一个「断点」哨兵 | 055 存字符（只为判类型）；这里必须存位置，因为「长度 = 差值」 |
| **② 何时弹** | 遇到 `)`：弹一个（若弹空了，就把当前 `i` 压回去当新断点） | 055 弹空就 `return false`；这里弹空只是「换一个断点」，**不终止** |
| **③ 弹出时结算了谁** | 结算了「从新栈顶到当前 `i` 这一段有多长」，并更新 `best` | 055 结算「这一对是否合法」；这里结算的是**长度** |

把「结算对象从布尔升级成数值」这件事记牢，后面 `057`（结算括号内的表达式值）、`058`（结算一段重复串）都是同一个动作。

**通用模型的三个变体**（一眼看出该存什么）：

| 你要的答案 | 栈里存什么 | 「弹出时的结算」是什么 |
| --- | --- | --- |
| 是否合法 | 字符 / 类型 | 布尔：这一对配不配 |
| **最长 / 最大的某段**（本章） | **下标** | 数值：`i - 新栈顶` |
| 具体位置 / 具体串 | 下标 + 附带信息 | 区间端点、被删除的标记 |

**属于同一模型的题**：

| 题 | 栈里存什么 | 结算的是什么 |
| --- | --- | --- |
| [LC 32 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/)（本章） | 下标 + 断点哨兵 | 段的长度 |
| [LC 20 有效的括号](https://leetcode.cn/problems/valid-parentheses/)（`055`） | 未闭合的左括号 | 这一对是否合法 |
| [LC 84 柱状图中最大的矩形](https://leetcode.cn/problems/largest-rectangle-in-histogram/) | 下标（单调递增栈） | 以弹出元素为高的最大矩形面积 |
| [LC 739 每日温度](https://leetcode.cn/problems/daily-temperatures/) | 下标（单调递减栈） | 等待天数 = 下标差 |
| [LC 962 最大宽度坡](https://leetcode.cn/problems/maximum-width-ramp/) | 下标（单调递减栈） | 最大下标差 |

> **共同点**：全部都是「**用下标差来表达答案**」。只要答案形如「一段的长度 / 宽度 / 天数」，栈里就应当存下标。

### 056.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**最长段的起止下标** | 需要位置 | 栈解几乎零改动：记录 `best` 的同时记下 `(新栈顶+1, i)`；两次计数法做不到 |
| 要输出**所有**最长段 | 多个答案 | 栈解把每次 `i - 新栈顶 == best` 的区间都收下来 |
| 括号类型变成 **3 种** | 顺序变复杂 | 两次计数法立刻失效（只有单类型才等价）；必须回到栈 |
| 允许 **`*` 通配** | 引入不确定 | 不能再用单一栈：维护「可能未匹配数区间 `[lo, hi]`」，答案变成「存在性」问题（LC 678 的思路） |
| **数据流 / 无限输入** | 不能回看 | 栈解天然流式（`O(嵌套深度)` 空间）；两次计数法**做不到**（反扫需要整个串） |
| 要 **`O(1)` 额外空间且一遍扫描** | 双约束 | 不存在确定性的这种算法；退一步：允许两遍扫描即可 `O(1)` 空间（本章解 B）；或允许 `O(n)` 空间换一遍扫描（解 A） |

**进阶延伸（自己写代码验证）**：

- **LC 678 有效的括号字符串**：把「最长」换成「是否存在」，`*` 引入三态 —— 体会「不确定」是怎么破坏栈的。
- **LC 921 / 1249**：一个求「最少补几个」、一个求「删完剩下的串」，都是把 056 的「断点思想」用在单类型上。
- **DP 版本**（本章没展开写）：`dp[i]` = 以 `i` 结尾的最长合法长度；`s[i]==')'` 时看 `s[i-1]`：若 `s[i-1]=='('` 则 `dp[i] = dp[i-2]+2`；否则看 `s[i-dp[i-1]-1]` 是否为 `(`，是则 `dp[i] = dp[i-1] + 2 + dp[i-dp[i-1]-2]`。**建议自己写一遍**：它的两个回跳下标就是「断点」在 DP 语言里的等价物。

### 056.4.2 两次计数：为什么必须扫两遍

```
★ 情形 A：左侧有孤立的 '('   s = "(()"
   正扫（左→右）：  (  (  )            反扫（右→左）：  )  (  (
      left :  1  2  2                    left :  0  1  1
      right:  0  0  1                    right: 1  1  2
      left==right? 从未 → best 0 ✗       left==right 在 i=1 → best 2 ✓
   结果：正扫漏判，反扫补上。

★ 情形 B：右侧有孤立的 ')'   s = "())"
   正扫：  (  )  )                      反扫：  )  )  (
      i=1 时 left==right=1 → best 2 ✓   left 始终 < right，最后 left>right 触发归零 → ✗
   结果：正扫捕获，反扫漏判。

    ┌────────────────────────────────────────────────────────────┐
    │ 正扫能捕获「右端收尾」的段，反扫能捕获「左端收尾」的段；   │
    │ 两类都存在 ⟹ 必须两个方向都扫一遍，取 max。                │
    └────────────────────────────────────────────────────────────┘
```

### 056.4.3 三种「断点」的对照表

| 断点类型 | 举例 | 正扫怎么处理 | 栈解怎么处理 |
| --- | --- | --- | --- |
| 假想起点（串从 0 就合法） | `"()()"` | `left==right` 时照常记录 | 哨兵 `-1` 提供 `-1` 这个左边界 |
| 多余的 `)` | `")()"` | `right > left` → 双计数清零 | 弹空后把当前 `i` 压入，成为新栈底 |
| 多余的 `(` | `"(()"` | 正扫无解 → 靠反扫 | 留在栈里，只要没被弹掉就是「当前段的左边界之外」 |

## 056.5 双语言实现

### 056.5.1 Java

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    // 解 A：栈存下标 + 哨兵 -1
    public int longestValidParentheses(String s) {
        int best = 0;
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(-1);            // 哨兵：让"从下标 0 开始的合法段"也能算出 r-(-1) = r+1
        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '(') {
                stack.push(i);     // 未闭合的左括号：压它的下标（不是字符！长度要靠下标差算）
            } else {
                stack.pop();       // 与最近的 '(' 抵消
                if (stack.isEmpty()) {
                    stack.push(i); // 右括号多了：它成为新的"断点"，不终止扫描
                } else {
                    best = Math.max(best, i - stack.peek());   // 弹出后的新栈顶就是左边界
                }
            }
        }
        return best;               // 空串 / 全 ')' / 全 '(' 都会自然返回 0
    }

    // 解 B：左右两次计数，O(1) 空间
    public int longestValidParenthesesCount(String s) {
        int best = 0, left = 0, right = 0;
        for (int i = 0; i < s.length(); i++) {          // 正扫：捕获"右端收尾"的段
            if (s.charAt(i) == '(') left++; else right++;
            if (left == right) {
                best = Math.max(best, 2 * right);       // 长度 = 2 * 对数
            } else if (right > left) {
                left = 0; right = 0;                    // 右括号过剩：此前的段永远不可能再合法
            }
        }
        left = 0; right = 0;
        for (int i = s.length() - 1; i >= 0; i--) {     // 反扫：捕获"左端收尾"的段
            if (s.charAt(i) == '(') left++; else right++;
            if (left == right) {
                best = Math.max(best, 2 * left);
            } else if (left > right) {
                left = 0; right = 0;                    // 左括号过剩：同样断掉
            }
        }
        return best;
    }
}
```

### 056.5.2 Go

```go
package main

// 解 A：栈存下标 + 哨兵 -1
func longestValidParentheses(s string) int {
	// 预分配 len(s)+1：栈最多同时装下"全部左括号 + 1 个哨兵"，避免 append 扩容
	stack := make([]int, 0, len(s)+1)
	stack = append(stack, -1) // 哨兵：最近一个"无法匹配的位置"
	best := 0
	for i := 0; i < len(s); i++ {
		if s[i] == '(' {
			stack = append(stack, i)
			continue
		}
		stack = stack[:len(stack)-1] // 先与最近的 '(' 抵消（栈里必有元素：最差也是哨兵）
		if len(stack) == 0 {
			stack = append(stack, i) // 右括号多了：i 成为新断点，扫描继续
		} else if d := i - stack[len(stack)-1]; d > best {
			best = d
		}
	}
	return best
}

// 解 B：左右两次计数
func longestValidParenthesesCount(s string) int {
	best := 0
	left, right := 0, 0
	for i := 0; i < len(s); i++ { // 正扫
		if s[i] == '(' {
			left++
		} else {
			right++
		}
		if left == right {
			if 2*right > best {
				best = 2 * right
			}
		} else if right > left {
			left, right = 0, 0 // 右括号过剩 → 双计数清零
		}
	}
	left, right = 0, 0
	for i := len(s) - 1; i >= 0; i-- { // 反扫
		if s[i] == '(' {
			left++
		} else {
			right++
		}
		if left == right {
			if 2*left > best {
				best = 2 * left
			}
		} else if left > right {
			left, right = 0, 0
		}
	}
	return best
}

func main() {}
```

### 056.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 栈的表示 | `ArrayDeque<Integer>`（有 `Integer` 装箱） | `[]int` 切片 | 本题 `n ≤ 3·10⁴`，Java 会创建最多 3 万个 `Integer` 对象（`-128~127` 之外的都新建）；Go 是一个连续 `int` 数组，cache 友好 |
| `pop()` 的语义 | `Deque.pop()` 空栈抛 `NoSuchElementException`；有 `poll()` 返回 `null` | 切片截断 `s[:len-1]`，空则 panic | 本题栈永不为空（哨兵保证），Java 用 `pop()` 安全；Go 用切片截断也安全 —— 但**这个安全性来自哨兵**，千万别在其它题里照抄 |
| 取栈顶 | `peek()` | `stack[len(stack)-1]` | Java 的 `peek()` 空栈返回 `null`（`Deque` 语义），Go 则 panic；本题已判空，两边都安全 |
| 循环方向 | `for (int i = n-1; i >= 0; i--)` | `for i := len(s)-1; i >= 0; i--`（`i` 是 `int`，为负即退出） | Go 的 `len(s)-1` 在空串时是 `-1`，条件立刻为假，不会死循环；Java 的写法也一样 |
| 字符串索引 | `charAt(i)` 返回 `char` | `s[i]` 返回 `byte` | 本题全 ASCII，语义一致；`for range` 在 Go 里会做 UTF-8 解码，没必要 |

### 056.5.4 对拍测试（O(n³) 暴力 + 全量穷举）

```go
package main

import (
	"math/rand"
	"strings"
	"testing"

// 暴力：O(n³) —— 枚举所有偶数长子串，逐个用计数器验证合法性
func bruteLongestValid(s string) int {
	best := 0
	for i := 0; i < len(s); i++ {
		for j := i + 2; j <= len(s); j += 2 { // 长度必须是偶数
			bal, ok := 0, true
			for k := i; k < j; k++ {
				if s[k] == '(' {
					bal++
				} else {
					bal--
				}
				if bal < 0 { // 前缀出现右括号过剩 → 这段不合法，提前退出
					ok = false
					break
				}
			}
			if ok && bal == 0 && j-i > best {
				best = j - i
			}
		}
	}
	return best
}

func TestLongestValidParenthesesRandom(t *testing.T) {
	r := rand.New(rand.NewSource(5566)) // 固定种子，失败可复现
	for iter := 0; iter < 8000; iter++ {
		n := r.Intn(15)
		b := make([]byte, n)
		for i := range b {
			if r.Intn(2) == 0 {
				b[i] = '('
			} else {
				b[i] = ')'
			}
		}
		s := string(b)
		want := bruteLongestValid(s)
		if got := longestValidParentheses(s); got != want {
			t.Fatalf("stack iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
		if got := longestValidParenthesesCount(s); got != want {
			t.Fatalf("count iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
	}

	// 边界：空串 / 单字符 / 嵌套极深
	if got := longestValidParentheses(""); got != 0 {
		t.Fatalf("空串 got=%d", got)
	}
	if got := longestValidParenthesesCount("("); got != 0 {
		t.Fatalf("单字符 got=%d", got)
	}
	deep := strings.Repeat("(", 5000) + strings.Repeat(")", 5000)
	if got := longestValidParentheses(deep); got != 10000 {
		t.Fatalf("深嵌套 stack got=%d", got)
	}
	if got := longestValidParenthesesCount(deep); got != 10000 {
		t.Fatalf("深嵌套 count got=%d", got)
	}
}

	for n := 0; n <= 16; n++ {
		for mask := 0; mask < 1<<n; mask++ {
			b := make([]byte, n)
			for i := 0; i < n; i++ {
				if mask>>i&1 == 1 {
					b[i] = '('
				} else {
					b[i] = ')'
				}
			}
			s := string(b)
			total++
			want := bruteLongestValid(s)
			if got := longestValidParentheses(s); got != want {
				t.Fatalf("exh stack n=%d s=%q got=%d want=%d", n, s, got, want)
			}
			if got := longestValidParenthesesCount(s); got != want {
				t.Fatalf("exh count n=%d s=%q got=%d want=%d", n, s, got, want)

		}
```

## 056.6 复杂度与常见坑

### 056.6.1 复杂度推导

- **栈解**：`for` 循环 `n` 次，每次最多一次 `push` 和一次 `pop`，都是 `O(1)`（Go 的 `append` 因为有 `cap` 预分配，全程零扩容；即使不预分配也是均摊 `O(1)`）。时间 **`O(n)`**，空间 **`O(n)`** —— 最坏情况 `"((((...))))"` 时栈里同时存在 `n/2` 个左括号下标 + 1 个哨兵。
- **两次计数**：两遍扫描各 `n` 次迭代，每字符 2 次比较 + 至多 2 次加法，时间 **`O(n)`**，空间 **`O(1)`**（只有 4 个整型变量）。
- **为什么栈解不能省成 `O(1)` 空间**：需要记住「每个未闭合左括号的位置」，而最深嵌套可以是 `n/2` 层 —— 信息量本身就是 `O(n)`（与 `055.3.1` 的结论一致：多类型/长距离匹配必须存位置）。想同时要 `O(1)` 空间，就只能接受**两遍扫描**（解 B），或者用 DP 的 `O(n)` 空间换一遍扫描。
- **常数对比**（本机 `n=3·10⁴`）：栈 0.167 ms、两遍计数 0.511 ms。**空间省的代价是时间常数变大**，这正是「取舍」在真实数字上的样子。

### 056.6.2 八个真实踩过的坑

1. **栈里存字符而不是下标** —— 存字符只能判「合法与否」，算不出长度。`"()(())"` 会得到 2 而不是 6。
2. **忘记哨兵 `-1`** —— `"()"` 会算出 `1 - 0 = 1`（或者栈空崩溃），正确的是 `1 - (-1) = 2`。哨兵的作用就是给「从下标 0 开始」的段一个左边界。
3. **弹出后不判空、也不把 `i` 压回去** —— `")()"` 会错：第一次 `)` 弹掉哨兵后栈空，若直接 `continue`，后面就失去了断点信息。
4. **弹出后用 `peek()` 之前没更新** —— `i - stack.peek()` 必须在**弹出之后**取，弹出前取到的是被抵消的那个 `(`，长度恒为 1。
5. **只做一次计数** —— `"(()"`（只正扫，得 0）与 `"())"`（只反扫，得 0）必然错一半。这是本章最经典的坑，`056.4.2` 已给出最小反例。
6. **计数法里 `left == right` 与 `right > left` 的 `else if` 顺序写反** —— 若先判 `right > left` 再判相等，`"()"` 在 `i=1` 时 `left==right` 但仍然会被判为「不大于」，看似没问题；真正会错的是把两件事写成独立 `if`，导致清零后立刻又触发 `left==right` 记录一个虚假的 0 长度。
7. **把 `best` 初始化成 `-1` 或 `Integer.MIN_VALUE`** —— `""`、`"("`、`")"` 都应返回 0；`-1` 会被判错。**答案下界是 0，就写 0。**
8. **递归写法（按最内层剥括号）** —— 深度 `3·10⁴` 会爆栈（Java 默认栈约 1 MB，Go 的 goroutine 栈虽可增长但也有上限）。任何「最深可以到 n」的结构，一律用显式栈。

### 056.6.3 面试官最爱追问的三个问题

**Q1：为什么栈里要存下标？存字符不行吗？**
> 「因为答案是一个**长度**。长度 = 当前位置 - 左边界位置，所以必须知道『位置』这个信息。存字符只能回答『这一对配不配』（055 的需求），回答不了『这一段多长』。一旦你要算『长度 / 宽度 / 天数』这类差值，栈里就该存下标 —— LC 84、739、962 全是这个套路。」

**Q2：两次计数法为什么扫两遍就够了？**
> 「因为一段合法子串只可能有两种『脏』的方式：左边多了 `(`（正扫等不到 `left == right`）或右边多了 `)`（反扫等不到）。正扫要求左侧干净、反扫要求右侧干净，两个方向合起来覆盖全部情况。严格的刻画是：正扫捕获 ⟺ 到达该段左端点前的前缀和是运行最小值且非正；反扫捕获 ⟺ 该段右端点处是后缀最小值且不超过总和。这两条我在 `056.3.2` 里推过，并用穷举 `n ≤ 16` 的全量 131071 个串验证过。」

**Q3：如果要求同时输出「最长段的起止下标」，两个解各要怎么改？**
> 「栈解几乎不用改：记录 `best` 时把 `(stack.peek()+1, i)` 一起存下即可，因为栈顶本来就是左边界。两次计数法做不了 —— 它维护的只有计数，没有位置；要加位置就等于把计数器换成栈，退化回解 A。这也说明了『`O(1)` 空间』这个优势是用『丢掉位置信息』换来的。」

1. 你要输出的不是长度而是**剩下的串**，那么「哪些下标该删」这件事必须在扫完之前就记下来。栈里存下标之后，还差哪一步？
2. 扫描结束时栈里剩下的东西，与「扫描途中弹空」的那一类，处理方式一样吗？

**LC 84 柱状图中最大的矩形**
1. 矩形的高度由哪一根柱子决定？它左右两边第一个比它矮的柱子，能怎么一次性拿到？
2. 栈里存下标而不是高度，是为了能算出什么？

**LC 962 最大宽度坡**
1. 什么情况下一个下标**不可能**成为答案的左端点？（提示：右边有更小值的下标）
2. 把「可能的左端点」压成一个单调序列之后，怎么为每个右端点找最左的可用者？

**通用**
- 只要答案形如「段的长度 / 宽度 / 间隔天数」，就先问：栈里能不能存**下标**？
- 只要出现「可能是断点」的位置（多余的右括号、非法起点、哨兵），就把它也压进栈里 —— **一个栈同时管「未解决」和「断点」，是本章最值得记的手法**。
