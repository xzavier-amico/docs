## 012.1 题目

**原题链接**：<https://leetcode.cn/problems/product-of-array-except-self/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的整数数组 `nums`，返回一个同样长度的数组 `ans`，其中 `ans[i]` 等于**「`nums` 中除 `nums[i]` 之外所有元素的乘积」**。

题目附了两条硬性限制，它们才是这道题的全部难点：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **不能用除法** | 「请不要使用除法」 | 你写 `total / nums[i]` → 违反题意；而且在 `nums[i] == 0` 时直接除零崩溃 |
| **必须在 O(n) 内完成** | 「请**不要**使用除法，且在 **O(n)** 时间复杂度内解决」 | 你写两层循环 → `n = 10⁵` 时是 `10¹⁰` 次乘法，必然超时 |
| **除数不含自身** | 「除 `nums[i]` 之外」 | 你把 `nums[i]` 也乘进去 → `ans[i]` 等于全数组乘积，全错 |
| **元素可以是 0 和负数** | `-30 <= nums[i] <= 30` | 你用「先算总积再除」→ 遇到 1 个 0 全变 0、遇到 2 个 0 无法区分；负数个数奇偶也要处理 |
| **答案保证在 32 位内** | 「题目数据保证数组之中任意元素的全部前缀元素和后缀的乘积都在 32 位整数范围内」 | 所以中途可以放心用 `int`；但这条保证是**题目给的**，不是「乘法天然安全」，换题就要换 `long` |
| **进阶：空间 O(1)** | 「你可以在 O(1) 额外空间复杂度内完成这个题目吗」 | 「输出数组**不算**额外空间」——这条注解决定了答案只能开一个 `ans` 数组，不能开 `left[]` 和 `right[]` |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `2 <= nums.length <= 10⁵` | n 最多 10 万 | O(n²) 是 **`10¹⁰` 次乘法**，秒级到十秒级，必挂；只接受 O(n) |
| `-30 <= nums[i] <= 30` | 绝对值很小 | 单个数小，但**乘起来会迅速变大**：全是 30 时 30⁵ ≈ 2.4·10⁷，30⁶ ≈ 7.3·10⁸，30⁷ 就溢出 int32。所以「保证在 32 位内」这条约束是**实质性**的，不是摆设 |
| 保证前缀/后缀积在 32 位内 | 中间量安全 | Java `int`、Go `int` 都够；**如果这条保证不存在，必须换 `long`** |
| n ≥ 2 | 不存在「除自身外没有元素」的情况 | `ans[i]` 永远至少含一个因子；但你自己写通用代码时仍要让 `n = 1` 返回 `[1]`（空积 = 1） |

> 💡 量级 → 算法：`n ≤ 10⁵` ⇒ 只能是 O(n) 或 O(n log n)。本题还有个额外信号：**「不能用除法」+「O(1) 空间」** 这两句话同时出现，等于在提示「你只有『从左扫一遍 + 从右扫一遍』这一条路」。

### 示例

```
输入：nums = [1, 2, 3, 4]
输出：[24, 12, 8, 6]
解释：ans[0] = 2·3·4 = 24
      ans[1] = 1·3·4 = 12
      ans[2] = 1·2·4 = 8
      ans[3] = 1·2·3 = 6

输入：nums = [-1, 1, 0, -3, 3]
输出：[0, 0, 9, 0, 0]
解释：只有 ans[2] 不含那个 0，所以只有它非零：(-1)·1·(-3)·3 = 9

输入：nums = [0, 0]
输出：[0, 0]
解释：ans[0] 只能看到 nums[1] = 0；ans[1] 只能看到 nums[0] = 0。两个 0 的情形是「先算总积再除」的死角。
```

### 我自造的四个反例（写完必须打一遍）

```text
① [0, 0]        → 暴露"总积 / nums[i]"：两个 0 时 0/0 无定义
② [1, 0]        → 只有一个 0 时，除 0 的下标以外，其余位置的答案都该是 0，而除 0 的位置该是 1
③ [-1, -1]      → 暴露"用绝对值/忽略符号"的写法
④ [1, 2]        → n = 2 的最小规模，暴露"ans[0] 没初始化为 1"和"先把 suf 乘上再赋值"
```

第 ④ 条要特别当心：`n = 2` 时第一趟循环 `for (i = 1; i < n; i++)` 只跑一次，`ans[0]` 的值必须**靠初始化**拿到 1。如果 `ans[0]` 是数组默认的 0，那么 `ans[0]` 最终恒为 0 —— 而样例 `[1,2,3,4]` 会立刻暴露；但如果你只测了 `[0,...]` 开头的用例，可能误以为「0 是对的」。

## 012.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```java
int[] ans = new int[n];
for (int i = 0; i < n; i++) {
    int p = 1;
    for (int j = 0; j < n; j++) {
        if (j != i) p *= nums[j];      // 除自身外全部乘一遍
    }
    ans[i] = p;
}
```

- 时间 **O(n²)**：`n(n-1) = 10⁵ × (10⁵-1) ≈ 10¹⁰` 次乘法（`n = 10⁵` 时）。
- 空间 **O(1)**（不计输出）。

`10¹⁰` 次乘法是什么概念：现代 CPU 每秒约 `10⁸ ~ 10⁹` 次「带内存访问的整数乘法」，10¹⁰ 次意味着**十秒到一分钟**。这不是「有点慢」，是「差三个数量级」。

### 第二步：第一个「聪明」念头，以及它为什么被题目堵死

看到「除自身外全部」，99% 的人第一反应是：

```
total = nums[0] * nums[1] * ... * nums[n-1]
ans[i] = total / nums[i]
```

这条路 **一行就够**，时间复杂度 O(n)，空间 O(1)。它错在三处，而且三处都是硬伤：

| 问题 | 具体反例 | 后果 |
| --- | --- | --- |
| **除零** | `[1, 0, 3]`：`total = 0`，`ans[1] = 0 / 0` | 整数除零 → 运行时崩溃；浮点 → `NaN` |
| **多个 0 无法区分** | `[0, 0]`：每个 `ans[i]` 都应是 0，但 `0/0` 无定义 | 需要额外统计 0 的个数并分支，代码从 1 行变 10 行 |
| **题目明令禁止** | 「请不要使用除法」 | 面试里这就是「没读题」 |

第三条最要命：**这不是「有没有更好的写法」的问题，而是「这条路被规则封了」**。而一旦除法被封，「撤销」这个动作就没了 —— 这正是本题和前两章的分水岭，见 §012.3.3。

### 第三步：卡点在哪

回到定义，把 `ans[i]` 这个乘积按位置拆成两段：

```
ans[i] = ( nums[0] · nums[1] · … · nums[i-1] )  ×  ( nums[i+1] · … · nums[n-1] )
          └──────────── 左前缀积 L[i] ────────┘     └──────── 右后缀积 R[i] ───────┘
```

暴力之所以慢，是因为**对每个 `i` 都从头把左半段重算一遍、从尾把右半段重算一遍**。而 `L[i]` 和 `L[i-1]` 只差一个因子：

```
L[0] = 1（空积）
L[i] = L[i-1] · nums[i-1]        ← 递推，一步一乘
R[n-1] = 1（空积）
R[i] = R[i+1] · nums[i+1]        ← 反向递推
```

**卡点不是「怎么乘」，而是「重复乘了同样的前缀」。** 一旦识别出「前缀积可以递推」，剩下的就是「怎么在只开一个输出数组的前提下，把两趟拼接起来」。

### 第四步：灵感的来源 —— 复用输出数组

两趟扫描的朴素写法要开两个数组 `L[]` 和 `R[]`（或一趟存 `L`、一趟边算边乘）。但题目说「输出数组不算额外空间」，于是有个非常自然的复用：

```
第一趟（从左到右）：ans[i] ← L[i]        （就地写进答案数组）
第二趟（从右到左）：ans[i] ← ans[i] · R[i]  （R[i] 用一个滚动变量 suf 维护）
```

因为第二趟是从右往左走，`R[i]` 恰好可以由 `R[i+1]` 一步推出，**不需要数组**。这就是 O(1) 额外空间的全部秘密：**两趟方向相反，所以两半都能用「滚动变量」维护**。

## 012.3 原理拆解

### 012.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 双重循环（每个 i 重乘一遍） | O(n²) | O(1) | 8 行 | `n = 10⁵` 时 10¹⁰ 次乘法，必挂 |
| 总积 + 除法 | O(n) | O(1) | 5 行 | **题目禁止**；且有 0 时除零、多个 0 无法区分 |
| 总积 + 0 的个数分支 | O(n) | O(1) | 20 行 | 仍然用了除法（违规）；且逻辑分支多、易错 |
| 左右两个前缀积数组 | O(n) | O(n) | 15 行 | 空间不满足进阶要求（多开一个 `R[]` 或 `L[]`） |
| **一趟左前缀 + 一趟右后缀（复用 ans）** ✅ | **O(n)** | **O(1)** | **12 行** | 完全不输：没有更快的可能（至少要读一遍每个元素） |

**为什么它是理论下界**：答案有 `n` 个值，仅「把答案写出来」就要 Θ(n)；每个 `nums[i]` 至少要参与一次乘法运算，又是 Θ(n)。所以 O(n) 已经是本题的**下界**，两趟扫描是最优解，不是「够用的解」。

### 012.3.2 为什么这个做法是对的（正确性论证）

记 `L[i] = ∏_{j<i} nums[j]`（空积为 1），`R[i] = ∏_{j>i} nums[j]`（空积为 1）。

**引理 1（第一趟之后）**：第一趟结束时 `ans[i] = L[i]`。
*证明*（对 `i` 归纳）：`ans[0]` 被显式赋为 1 = 空积 = `L[0]`。若 `ans[i-1] = L[i-1]`，则第 `i` 轮执行 `ans[i] = ans[i-1] * nums[i-1] = L[i-1] · nums[i-1] = L[i]`。∎

**引理 2（第二趟中 `suf` 的值）**：第二趟处理下标 `i` 时，循环体开始前 `suf = R[i]`。
*证明*（对 `i` 从 `n-1` 递减归纳）：初始 `suf = 1 = R[n-1]`。若在处理 `i+1` 时 `suf = R[i+1]`，则该轮末尾执行 `suf *= nums[i+1]`，得到 `R[i+1] · nums[i+1] = R[i]`，正好是下一轮（下标 `i`）开始前的值。∎

**定理**：算法结束时 `ans[i] = L[i] · R[i]`，即「除 `nums[i]` 外全部元素的乘积」。
*证明*：第二趟处理 `i` 时先做 `ans[i] *= suf`，由引理 1、2 得 `ans[i] = L[i] · R[i]`；之后 `ans[i]` 不再被修改。而 `L[i] · R[i] = ∏_{j<i} nums[j] · ∏_{j>i} nums[j] = ∏_{j≠i} nums[j]`（乘法结合律与交换律保证可以这样拆、这样拼，且**不需要任何除法**）。∎

> **注意论证里没有用到「元素非零」**，这正是它比除法方案强的地方：0 和负数都只是普通的因子。

### 012.3.3 通用解题思路（可迁移的那一层）

本题是 **「把『除自己以外』拆成『左半边 × 右半边』」** 这个模型的母题。它的可迁移形式是：

```
问题：对每个位置 i，求「除 i 之外所有元素的某种聚合」
     ↓ 观察
聚合可分解：ans[i] = f(左半边) ⊗ f(右半边)
     ↓ 观察
左半边 / 右半边各自可以递推 → 一趟从左、一趟从右
     ↓ 复用的关键
如果两趟方向相反，第二趟可以用滚动变量，不必再开数组
```

**为什么这题不能用 `011` 的哈希技巧？** 这是本批最重要的一条对照，值得单独说清：

| | 011 前缀和 | 012 前缀积 |
| --- | --- | --- |
| 聚合运算 | 加法 | 乘法 |
| 逆运算 | **减法**（`pre[j] - pre[i]`） | **除法**（被题目禁止，且 0 不可逆） |
| 所以 | 任意区间和都能由两个前缀和「撤销」出来 → 一遍扫描 + 哈希足够 | 无法「撤销」，只能**事后不可逆地累乘** → 必须两趟分别建好两半 |
| 空间 | O(n) 哈希表 | O(1)（复用输出） |

一句话：**前缀和是「可撤销」的，前缀积是「不可撤销」的**。可撤销 → 一遍扫描 + 查找；不可撤销 → 先把两半都备好，再合并。这个判据在 `014`（差分，可撤销的另一种形态）和 `016`（滑窗，出窗时要能撤销）里会反复出现。

属于同一「两趟 / 左右分解」模型的题：

| 题 | 左半维护什么 | 右半维护什么 | 合并方式 |
| --- | --- | --- | --- |
| [LC 238 除自身以外数组的乘积](https://leetcode.cn/problems/product-of-array-except-self/) | 左前缀积 | 右后缀积 | 相乘 |
| [LC 42 接雨水](https://leetcode.cn/problems/trapping-rain-water/) | 左最高 | 右最高 | 取 `min` 再减自身 |
| [LC 135 分发糖果](https://leetcode.cn/problems/candy/) | 左邻居约束 | 右邻居约束 | 取 `max` |
| [LC 152 乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/) | 从左起的前缀积 | 从右起的前缀积 | 取 `max`（处理负负得正） |
| [LC 845 数组中的最长山脉](https://leetcode.cn/problems/longest-mountain-in-array/) | 左侧上升长度 | 右侧下降长度 | 相加 |

**共同点**：都把一个「全局聚合」拆成两个「单向聚合」，再用两次线性扫描把两个方向都算出来。

### 012.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **允许用除法** | 0 的问题浮出水面 | 统计 0 的个数 `z`：`z ≥ 2` 全 0；`z == 1` 只有 0 的位置等于「非零元素总积」，其余为 0；`z == 0` 直接用 `total / nums[i]` |
| 要求「除自身外的**和**」 | 加法可撤销 | 一次遍历求总和，`ans[i] = total - nums[i]`，O(n) / O(1)，比乘法简单得多 |
| 元素很大，乘积溢出 | 32 位不够 | 换 `long` / `int64`；若仍溢出，用 `math/big`（Go）或 `BigInteger`（Java）；只要**取模**就换成模运算（每步 `% MOD`） |
| 要求**后缀积数组** `suf[i] = ∏_{j≥i}` | 只需一趟 | 从右往左滚动，O(n) / O(1)（复用输出） |
| 数组**动态变化**（区间乘、单点改） | 静态前缀积失效 | 乘法没有逆元（模意义下才有），需要**线段树**维护区间积；若模数是质数且元素非 0，可用逆元退化成前缀积 |
| 输出要求**原地**改 `nums` | 不能再开 `ans` | 与本题冲突（要保留原值做前缀积），需要 O(n) 备份；面试里要主动指出这个矛盾 |
| n = 1 的边界 | 「除自身外」没有元素 | 返回 `[1]`（空积），这是数学约定，不是特判 |

## 012.4 图解推演

### 012.4.1 左右分解的几何图

```
nums = [ 1 , 2 , 3 , 4 ]

             i=0        i=1        i=2        i=3
              │          │          │          │
   ┌──────────┼──────────┼──────────┼──────────┼──────────┐
   │  左前缀积 │    1     │    1     │    2     │    6     │   ← 从左往右扫出来的
   │  右后缀积 │   24     │   12     │    4     │    1     │   ← 从右往左扫出来的
   ├──────────┼──────────┼──────────┼──────────┼──────────┤
   │  ans[i]  │  1×24=24 │  1×12=12 │   2×4=8  │  6×1=6   │
   └──────────┴──────────┴──────────┴──────────┴──────────┘
                   ✅         ✅         ✅         ✅

   注意：左前缀积 [1,1,2,6] 中，第 i 项恰好跳过了 nums[i] 自己
        右后缀积 [24,12,4,1] 同理
        这就是"不含自身"的实现方式：**不是把自身除掉，而是压根没乘进来**
```

### 012.4.2 两趟扫描的指针方向

```
第一趟  ──────────────────────────────→
        ans[0]=1
        ans[1]=ans[0]*nums[0]=1
        ans[2]=ans[1]*nums[1]=2
        ans[3]=ans[2]*nums[2]=6
        ┌────┬────┬────┬────┐
   ans= │ 1  │ 1  │ 2  │ 6  │        左半段就绪
        └────┴────┴────┴────┘

第二趟  ←──────────────────────────────
        suf=1
        i=3: ans[3]*=1  → 6    suf*=nums[3] → 4
        i=2: ans[2]*=4  → 8    suf*=nums[2] → 12
        i=1: ans[1]*=12 → 12   suf*=nums[1] → 24
        i=0: ans[0]*=24 → 24   suf*=nums[0] → 24
        ┌────┬────┬────┬────┐
   ans= │ 24 │ 12 │ 8  │ 6  │        ✅
        └────┴────┴────┴────┘
          ↑ suf 是"右半段的滚动积"，始终保持为 ∏_{j>i} nums[j]
```

### 012.4.3 逐轮状态表（第二趟是重点）

| i | `nums[i]` | 第一趟后 `ans[i]` = `L[i]` | 第二趟开始前 `suf` = `R[i]` | `ans[i] *= suf` 后 | 本轮末尾 `suf *= nums[i]` |
| --- | --- | --- | --- | --- | --- |
| 3 | 4 | 6 | 1 | **6** | 4 |
| 2 | 3 | 2 | 4 | **8** | 12 |
| 1 | 2 | 1 | 12 | **12** | 24 |
| 0 | 1 | 1 | 24 | **24** | 24（不再使用） |

这张表要盯住两个细节：

1. **`suf` 在 `i` 行是 `R[i]`，而不是 `R[i]` 乘上 `nums[i]` 之后的值** —— 所以代码必须先 `ans[i] *= suf`，再 `suf *= nums[i]`。
2. 最后一行 `suf` 变成 24 之后没有下一轮，属于「多余的一次乘法」，不影响结果。

### 012.4.4 顺序写反的后果（最容易犯的错）

```
nums = [1, 2]        正确答案 = [2, 1]

✅ 先乘答案再更新 suf
   i=1: ans[1] = ans[1] * suf = 1 * 1 = 1     suf = 1 * nums[1] = 2
   i=0: ans[0] = ans[0] * suf = 1 * 2 = 2     suf = 2 * nums[0] = 2
   → [2, 1]  ✅

❌ 先更新 suf 再乘答案
   i=1: suf = 1 * 2 = 2                       ans[1] = 1 * 2 = 2   ← 把 nums[1] 自己乘进去了
   i=0: suf = 2 * 1 = 2                       ans[0] = 1 * 2 = 2
   → [2, 2]  ❌（ans[1] 应为 1）
```

```
┌────────────────── 一句话记住 ──────────────────┐
│ suf 的含义是"严格在 i 右边的乘积"                │
│ 一旦先 suf *= nums[i]，它就把 i 自己也包含了     │
│ 顺序不是风格问题，是定义问题                     │
└────────────────────────────────────────────────┘
```

## 012.5 双语言实现

### 012.5.1 Java

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] ans = new int[n];

        // 第一趟：ans[i] = nums[0..i-1] 的乘积
        // ans[0] 必须是 1（空积），不能依赖数组默认的 0——否则所有答案都会变 0
        ans[0] = 1;
        for (int i = 1; i < n; i++) {
            ans[i] = ans[i - 1] * nums[i - 1];
        }

        // 第二趟：从右往左，用 suf 维护 nums[i+1..n-1] 的乘积，直接乘进 ans
        int suf = 1;                       // 初始是空积 1，对应 i = n-1
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= suf;                 // 先乘：此时 suf 恰好不含 nums[i]
            suf *= nums[i];                // 后更新：把 nums[i] 加进"右侧"，供 i-1 使用
        }
        return ans;
    }
}
```

### 012.5.2 Go

```go
package main

func productExceptSelf(nums []int) []int {
	n := len(nums)
	ans := make([]int, n)

	// 第一趟：ans[i] = nums[0..i-1] 的乘积
	// Go 的 make 已经清零，同样必须显式把 ans[0] 设成 1（空积）
	ans[0] = 1
	for i := 1; i < n; i++ {
		ans[i] = ans[i-1] * nums[i-1]
	}

	// 第二趟：suf 维护 nums[i+1..n-1] 的乘积
	suf := 1
	for i := n - 1; i >= 0; i-- {
		ans[i] *= suf
		suf *= nums[i] // 顺序不能换：换了就把 nums[i] 自己乘进去了
	}
	return ans
}
```

### 012.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 数组初始化 | `new int[n]` 全 0 | `make([]int, n)` 全 0 | 都要**显式**把 `ans[0]` 设为 1；靠零值会得到全 0 |
| 返回类型 | `int[]` | `[]int` | LeetCode 判题签名固定，写错直接编译失败 |
| 倒序循环 | `for (int i = n-1; i >= 0; i--)` | `for i := n - 1; i >= 0; i--` | 语义一致；Go 没有 `i--` 的坑（它不是表达式） |
| 溢出 | `int` 恒 32 位，溢出**静默回绕** | `int` 在 64 位平台是 64 位，反而不容易溢出 | **同一段代码 Java 溢出、Go 不溢出** —— 跨语言验证时最容易误判「我的解法是对的」。要按**题目给的 32 位保证**来判断，不要按自己机器的结果判断 |
| 切片别名 | 无此概念 | 返回的 `[]int` 是新分配的底层数组 | 若复用入参 `nums` 的底层数组做原地改写，会污染调用方，别这么做 |
| 空积的写法 | 字面量 `1` | 字面量 `1` | 无差异，但都要在心里把它读成「单位元」 |

### 012.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：每个 i 都从零乘一遍（O(n²)），作为唯一真相
func brute(nums []int) []int {
	out := make([]int, len(nums))
	for i := range nums {
		p := 1
		for j := range nums {
			if j != i {
				p *= nums[j]
			}
		}
		out[i] = p
	}
	return out
}

func TestProductExceptSelfRandom(t *testing.T) {
	fixed := []struct {
		nums []int
		want []int
	}{
		{[]int{1, 2, 3, 4}, []int{24, 12, 8, 6}},
		{[]int{-1, 1, 0, -3, 3}, []int{0, 0, 9, 0, 0}}, // 单个 0
		{[]int{0, 0}, []int{0, 0}},                     // 多个 0：除法方案必死
		{[]int{1, 2}, []int{2, 1}},                     // n = 2 的最小规模
		{[]int{-1, -1}, []int{-1, -1}},                 // 负号
	}
	for _, f := range fixed {
		got := productExceptSelf(f.nums)
		for i := range f.want {
			if got[i] != f.want[i] {
				t.Fatalf("nums=%v got=%v want=%v", f.nums, got, f.want)
			}
		}
	}

	r := rand.New(rand.NewSource(12))
	for iter := 0; iter < 20000; iter++ {
		n := 2 + r.Intn(8)
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(7) - 3 // 值域 [-3,3]，0 与负数都高频出现
		}
		got, want := productExceptSelf(nums), brute(nums)
		for i := range want {
			if got[i] != want[i] {
				t.Fatalf("iter=%d nums=%v got=%v want=%v", iter, nums, got, want)
			}
		}
	}
}
```

> **为什么值域取 `[-3,3]`**：`0` 出现的概率是 1/7，20 个元素的数组里几乎必含 0，能持续压测「多个 0」这条分支；负数同时覆盖符号。

## 012.6 复杂度与常见坑

### 012.6.1 复杂度推导

- **时间 O(n)**：第一趟 `n-1` 次乘法，第二趟 `n` 次乘法 + `n` 次赋值，总计 `≈ 2n` 次基本操作。常数是 2，无法再降（每个元素在左半和右半各出现一次）。
- **空间 O(1)**（额外空间）：除输出数组 `ans` 外，只用了 `i`、`suf` 两个标量。题目明确「输出数组不算额外空间」，所以这是 O(1) 而不是 O(n)。
  - 如果面试官追问「连输出都不能算，那你到底用了多少内存」：答「**输入 O(n)、输出 O(n)、额外 O(1)**，所以峰值是 O(n)，但『额外』部分是常数」。

### 012.6.2 八个真实踩过的坑

1. **`ans[0]` 没有初始化为 1** —— 数组默认 0，导致第一趟把 0 一路传播下去，答案全 0。`[1,2,3,4]` 会立刻暴露，但只测含 0 的用例可能被误判为「正确」。
2. **`suf` 更新顺序写反** —— 先 `suf *= nums[i]` 再 `ans[i] *= suf`，等于把 `nums[i]` 自己乘了进去，`[1,2]` 会返回 `[2,2]`。
3. **试图用除法** —— 违反题意；即使面试官允许，也要处理「0 个 0 / 1 个 0 / 多个 0」三种情况，代码复杂度反超两趟扫描。
4. **溢出** —— 本题有 32 位保证；但如果没这条保证（比如 `nums[i] ≤ 10⁵`、`n = 10⁵`），`int` 必然溢出。**看到「乘积」二字就要条件反射地问「有没有溢出保证」**，没有就换 `long` / `int64`。
5. **开两个额外数组** —— `left[]` 与 `right[]` 都开，空间 O(n)，不满足「进阶 O(1)」；面试里这是**扣分项**，因为复用 `ans` 只需要想到「两趟方向相反」。
6. **修改了输入数组** —— 有人为了省空间把中间结果写回 `nums`，这会让调用方的数据被破坏。LeetCode 不检查，生产代码是事故。
7. **`n = 1` 没考虑** —— 本题约束 `n ≥ 2`，但通用代码应返回 `[1]`（空积）；写好这个边界能体现「空积 = 1」的理解。
8. **Go 里返回 `nil` 切片** —— `n ≥ 2` 时必须有 `n` 个元素，返回 `nil` 会直接判错。`make([]int, n)` 不能漏。

### 012.6.3 面试官最爱追问的三个问题

**Q1：为什么不能「先求总积再除」？**
> 「三层原因。① 题目明令禁止除法；② `nums[i] == 0` 时直接除零；③ 即使允许除法并且特判 0，也要统计 0 的个数并分三种情况写，分支比两趟扫描更多、更容易错。更本质地说：**乘法在整数上不可逆**（除了 0 的问题，还有溢出回绕），而前缀和依靠的加法是可逆的 —— 这决定了 238 必须两趟、560 可以一趟。」

**Q2：怎么做到 O(1) 额外空间？**
> 「关键是两趟方向相反。第一趟从左往右把左前缀积**就地写进输出数组**；第二趟从右往左，右后缀积只用一个滚动变量 `suf` 维护，因为 `R[i]` 由 `R[i+1]` 一步推出，不需要数组。两半合并时直接 `ans[i] *= suf`。额外空间只有两个标量。」

**Q3：如果数组里有 0，你的解还对吗？**
> 「对，而且不需要任何特判。因为我的解**从来不做除法**，0 只是一个普通的因子：`ans[i] = L[i] · R[i]`，只要 `i` 的左边或右边出现过 0，答案自然就是 0；如果整个数组只有 `nums[i]` 自己是 0，那 `L[i]` 和 `R[i]` 都不含 0，答案自然非零。`[0,0]` 和 `[-1,1,0,-3,3]` 都在对拍里钉住了。」
