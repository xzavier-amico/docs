## 146.1 题目

**原题链接**：<https://leetcode.cn/problems/rotate-image/>

### 题意重述（把隐含条件补齐）

给你一个 `n × n` 的矩阵（二维数组）表示一幅图像，请把它**顺时针旋转 90 度**。**必须原地修改**输入矩阵，不许返回新矩阵，也不许用 `O(n²)` 的额外空间。

四条必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 矩阵是**方阵** `n × n` | 「`n x n` 二维矩阵」 | 若按 `m × n`（非方阵）来写，转置会越界；非方阵旋转后尺寸会变，**根本不可能原地** |
| 方向是**顺时针** | 「顺时针旋转 90 度」 | 写成逆时针会是另一个答案（两者只差一次翻转方向） |
| **原地**修改 | 「你必须在原地旋转图像，这意味着你需要直接修改输入的二维矩阵」 | 新建一个矩阵再逐格填是「会做但没答到这题」的版本，空间 `O(n²)` |
| 不许**返回**新矩阵 | 「请不要使用另一个矩阵来旋转图像」 | Java 的 `void` 签名固定，返回新矩阵会判题失败 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 20` | 最多 400 个格子 | 任何 `O(n²)` 都极快；**这题完全不考时间，只考「原地」** |
| 元素范围不限（`-1000 ~ 1000`） | 值可以是任意数、可以全都相同 | 不能靠「值是唯一的」来定位元素；**全相同值的矩阵会掩盖坐标错误**（见 §146.1 反例） |
| 必须原地 | 题面明写 | 这把 `O(n²)` 空间的做法排除，只剩「成对交换」与「四格轮换」 |
| `n = 1` 合法 | 最小输入 | 单格矩阵旋转后不变，是最容易踩越界的最小用例 |

> 💡 **量级 → 算法** 之外，本章要建立另一种条件反射：**变换 → 坐标公式**。
> 遇到矩阵变换，第一步永远是**写出「新位置的元素来自哪个旧位置」的坐标映射**，第二步才是想「怎么原地实现它」。

### 示例

```text
输入：matrix = [[1,2,3],
                [4,5,6],
                [7,8,9]]
输出：          [[7,4,1],
                [8,5,2],
                [9,6,3]]

输入：matrix = [[5, 1, 9,11],
                [2, 4, 8,10],
                [13,3, 6, 7],
                [15,14,12,16]]
输出：          [[15,13, 2, 5],
                [14, 3, 4, 1],
                [12, 6, 8, 9],
                [16, 7,10,11]]
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① n = 1，matrix = [[7]]                → 仍是 [[7]]
                                          暴露：转置循环 j 从 i+1 开始写成了 i，或 n−1−i 越界
② n = 2，matrix = [[1,2],[3,4]]        → [[3,1],[4,2]]
                                          最小的一圈，四条边的交接最容易错
③ 全相同的元素 [[1,1],[1,1]]           → 不变
                                          暴露：坐标写错也不会被发现的「假通过」用例，所以真正的
                                          对拍必须用**全不相同的值**（n² 个互异数）
④ n = 3，对角线上是 1..3               → 对角元素旋转后不在对角线上
                                          暴露：误以为「对角元素不动」的直觉（只有旋转 180° 才保持对角）
```

第 ③ 条要特别记住：**用「全 1 矩阵」验证旋转，等于什么都没验证**。自己验证时用 `1, 2, 3, …, n²` 填满，坐标一错立刻显形。

## 146.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的做法：造一个同样大小的矩阵，按公式把值搬过去。

```java
int n = matrix.length;
int[][] res = new int[n][n];
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        res[j][n - 1 - i] = matrix[i][j];   // 旧 (i,j) → 新 (j, n−1−i)
for (int i = 0; i < n; i++) matrix[i] = res[i];
```

- 时间 **O(n²)**，空间 **O(n²)**（`n = 20` 时 400 个 `int`，1.6 KB，小到无所谓）。
- **算法完全正确**，坐标公式也值得背下来：**`(i, j) → (j, n−1−i)`**。
- 但它**违反题目唯一强调的那条约束**：必须原地。所以它只能当「对拍参考」，不能当答案。

### 第二步：卡点在哪

既然要原地，就必须让元素「在原来的空间里排好队」。这时候问题变成：

> **顺时针旋转对每个元素做的是什么置换？这个置换能不能拆成若干个「只用两个格子」的交换？**

- **一次交换**只要一个临时变量（`O(1)` 空间），天然满足原地要求。
- 而旋转本身是一个「四循环」：四个格子互相把值传给下一个。直接硬写需要小心地保存一个临时值、按正确顺序赋值（四次赋值，错一个顺序就丢数据）。

于是卡点非常具体：**能不能把「四格轮换」拆成两轮「两格交换」？**

### 第三步：灵感的来源 —— 旋转 = 转置 + 左右翻转

先写出**顺时针 90°** 的坐标公式：旧 `(r, c)` 搬到新 `(c, n−1−r)`。

再写出两个更简单的操作：

| 操作 | 坐标公式 | 需要几个临时变量 | 性质 |
| --- | --- | --- | --- |
| **转置**（沿主对角线镜像） | `(r, c) → (c, r)` | 1（交换一对） | **自逆**：做两次回到原样 |
| **左右翻转**（沿竖直中线镜像） | `(r, c) → (r, n−1−c)` | 1（交换一对） | **自逆**：做两次回到原样 |

把两者**复合**（先转置，再左右翻转）：

```
(r, c) ──转置──► (c, r) ──左右翻转──► (c, n−1−r)
```

**恰好就是顺时针 90° 的公式。** 于是「四格轮换」被拆成了「两轮两格交换」，而两格交换只需要一个 `tmp`。

```java
// 第一步：转置（只遍历上三角 i < j，否则交换两次回到原样）
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        swap(matrix[i][j], matrix[j][i]);

// 第二步：每一行左右翻转
for (int i = 0; i < n; i++)
    for (int l = 0, r = n - 1; l < r; l++, r--)
        swap(matrix[i][l], matrix[i][r]);
```

**两段双层循环，八个字：「转置 + 水平翻转」。这就是最优解。**

### 顺序能不能反？（能，但方向会变）

先左右翻转、再转置，复合出来是：

```
(r, c) ──左右翻转──► (r, n−1−c) ──转置──► (n−1−c, r)
```

也就是新 `(n−1−c, r)` 收到旧 `(r, c)`，等价于 **`(i, j)` 的值来自 `(j, n−1−i)`** —— 这是**逆时针** 90°。

> **所以「先转置后翻转」= 顺时针，「先翻转后转置」= 逆时针。** 顺序一换，答案就差一个方向，这是本章的第 2 号坑。

顺带把 180° 也归位：**上下翻转 + 左右翻转**（或「转置 + 转置 + 两次翻转」，但没人这么写）。

## 146.3 原理拆解

### 146.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（额外） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 新建矩阵按公式填 | O(n²) | **O(n²)** | 6 行 | **题目禁止**（必须原地）；只适合当对拍参考 |
| 逐层四格轮换（4-cycle） | O(n²) | **O(1)** | 12 行 | 四条赋值的顺序极易写错；不易扩展到非方阵 |
| **转置 + 水平翻转** ✅ | **O(n²)** | **O(1)** | **10 行** | 无；读起来最直观，是本章推荐解 |
| 水平翻转 + 转置 | O(n²) | O(1) | 10 行 | 得到的是**逆时针**，方向错了 |
| 每层用一个临时数组（`top` 行缓存） | O(n²) | O(n) | 15 行 | 空间不是最优，写法与 4-cycle 一样绕 |

> 两种 O(1) 空间的写法（4-cycle 与转置+翻转）**代价完全相同**，差别只在「人能不能一次写对」。**面试优先选转置+翻转**，然后主动说「另一种是逐层四格轮换，四条赋值的顺序是 `左上←左下←右下←右上←左上`」。

### 146.3.2 为什么这个做法是对的（正确性论证）

**命题 1（复合等价）**：对 `n × n` 矩阵，「先转置、再左右翻转」的复合置换等于顺时针旋转 90°。

**证明**：设旧元素在 `(r, c)`。

1. 转置后它到了 `(c, r)`（行列互换）。
2. 左右翻转把它从列 `r` 搬到列 `n − 1 − r`，行不变，所以到 `(c, n − 1 − r)`。
3. 而顺时针旋转 90° 的坐标公式正是 `(r, c) → (c, n − 1 − r)`：验证边界，左上角 `(0, 0)` 应到右上角 `(0, n−1)`，公式给出 `(0, n−1)` ✓；右上角 `(0, n−1)` 应到右下角 `(n−1, n−1)`，公式给出 `(n−1, n−1)` ✓。
4. 每格的目标位置唯一确定，两个置换逐格相同，所以整体相同。∎

**命题 2（原地交换不丢数据）**：

- **转置**：只遍历 `i < j` 的上三角，把 `(i, j)` 与 `(j, i)` 交换。每一对 `{(i,j), (j,i)}`（`i ≠ j`）**恰好被处理一次**；对角元素 `i == j` 不参与（`(i,i) → (i,i)` 是恒等）。因此每个元素要么不动、要么与它的「对偶」交换一次，**没有元素被覆盖两次、也没有元素被漏掉**。
- **左右翻转**：每行用 `l`、`r` 双指针向中间夹，`l < r` 时交换。同样的论证：每对 `{(i,l), (i,n−1−l)}` 恰好交换一次，中间的列（`n` 为奇数时 `l == r`）不动。

两个操作都是**由不重叠的二元交换组成**，用一个临时变量即可完成，因此额外空间是 `O(1)`。∎

**命题 3（转置与翻转都自逆）**：转置两次回到原样（`(r,c) → (c,r) → (r,c)`）；左右翻转两次回到原样。这条性质解释了为什么「先 A 后 B」与「先 B 后 A」只差方向：两个对合置换的复合与其逆序复合互为逆置换。∎

### 146.3.3 通用解题思路（可迁移的那一层）

**模型：把复杂置换分解成「自逆置换」的复合**

```
一个置换 P（旋转 90°）
        ↓ 拆成 P = A ∘ B，其中 A、B 都是「对合」（做两次 = 恒等）
转置 A：只交换上三角，天然 O(1) 空间
翻转 B：只交换每行的左右两侧，天然 O(1) 空间
        ↓ 于是 P 也只需要 O(1) 空间
```

这个模型的威力在于：**「对合」意味着交换成对出现，而成对交换永远只需要一个临时变量**。凡是能这样拆的变换，都能原地做。

同一模型的成员（以及「同一招换皮」的题）：

| 题 / 操作 | 分解成什么 | 关键点 |
| --- | --- | --- |
| [LC 48 旋转图像](https://leetcode.cn/problems/rotate-image/) | 转置 + 左右翻转 | 顺时针；反序复合得逆时针 |
| [LC 189 轮转数组](https://leetcode.cn/problems/rotate-array/) | **三次反转**：整体反 + 前 k 反 + 后 n−k 反 | 反转也是自逆置换，三次复合等于轮转 |
| [LC 344 反转字符串](https://leetcode.cn/problems/reverse-string/) | 双指针交换 | 最基础的对合操作 |
| [LC 151 反转字符串中的单词](https://leetcode.cn/problems/reverse-words-in-a-string/) | 反转整串 + 反转每个单词 | 与 189 同构的两次复合 |
| [LC 867 转置矩阵](https://leetcode.cn/problems/transpose-matrix/) | 单次转置 | 非方阵要新建矩阵（尺寸变化） |
| [LC 289 生命游戏](https://leetcode.cn/problems/game-of-life/) | 用「两位编码」原地记录旧状态与新状态 | 另一种「原地」技巧：复用格子的高位 |

### 146.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **逆时针** 90° | 方向翻转 | 先左右翻转再转置；或转置 + 上下翻转（两种写法等价） |
| **180°** | 两次 90° | 上下翻转 + 左右翻转，一趟两次双指针，仍 `O(1)` 空间 |
| 旋转 **k 次** | `k` 可能很大 | 先 `k %= 4`；`k = 0` 不动、`1` 顺时针、`2` 用 180°、`3` 用逆时针。**不要真的旋转 `k` 次** |
| 矩阵**非方阵** `m × n` | 尺寸变成 `n × m` | **原地不可能**（元素个数不变但形状变了，存储布局必须重排）。只能新建矩阵，空间 `O(mn)` |
| **只读**输入（不许改） | 只能返回新矩阵 | 那就老老实实新建，`O(mn)` 空间；此时公式 `res[j][n−1−i] = a[i][j]` 一行搞定 |
| 三维张量旋转 | 坐标公式变成三个下标 | 仍然先写坐标映射，再找「哪些坐标轴的对换是自逆的」；空间同样可以做到 `O(1)` |

## 146.4 图解推演

### 146.4.1 `4 × 4` 矩阵的完整变化

用 `1..16` 按顺序填满，坐标一错就能看出来：

```
            原始                       转置（沿主对角线镜像）
   ┌────────────────────┐      ┌────────────────────┐
   │  1   2   3   4     │      │  1   5   9  13     │
   │  5   6   7   8     │  ──► │  2   6  10  14     │
   │  9  10  11  12     │      │  3   7  11  15     │
   │ 13  14  15  16     │      │  4   8  12  16     │
   └────────────────────┘      └────────────────────┘
        ↑ 行号 r 固定              (r, c) 与 (c, r) 互换
          列号 c 变化                 主对角线上的 1,6,11,16 不动

            转置                       左右翻转（每行镜像）
   ┌────────────────────┐      ┌────────────────────┐
   │  1   5   9  13     │      │ 13   9   5   1     │
   │  2   6  10  14     │  ──► │ 14  10   6   2     │
   │  3   7  11  15     │      │ 15  11   7   3     │
   │  4   8  12  16     │      │ 16  12   8   4     │
   └────────────────────┘      └────────────────────┘
                                  每行用 l / r 双指针向内夹
```

**校验**：最终结果的第一行 `13 9 5 1`，正是原始矩阵**第一列从下往上读**——这就是「顺时针旋转」的直观含义。

### 146.4.2 四格轮换的轨迹（为什么它需要小心）

顺时针旋转下，四个格子互相传递值，形成一个 4-循环。以原始矩阵的四个角为例：

```
           (0,0)=1  ──────────────►  (0,3)
              ▲                          │
              │                          ▼
           (3,0)◄──────────────  (3,3)=4
             =13                       =4
              │
              └─── (3,0) 这一格收到的值是「原本在 (3,3) 的那个」

循环顺序（值往哪走）：
   值 1  (0,0) ──► (0,3)
   值 4  (0,3) ──► (3,3)
   值 16 (3,3) ──► (3,0)
   值 13 (3,0) ──► (0,0)
```

对应的四条赋值**必须逆序写**（从「最后一个接收者」开始），并先保存 `matrix[i][j]`：

```
tmp           = a[i][j];                 // 存左上，否则会被覆盖
a[i][j]       = a[n-1-j][i];             // 左上 ← 左下
a[n-1-j][i]   = a[n-1-i][n-1-j];         // 左下 ← 右下
a[n-1-i][n-1-j] = a[j][n-1-i];           // 右下 ← 右上
a[j][n-1-i]   = tmp;                     // 右上 ← 左上（用备份）
```

> **对比一下就知道为什么推荐转置+翻转**：上面 5 行里只要有 1 行下标写错，结果就静默错误；而转置+翻转的第二段只有「行内左右交换」这一种动作，写错的概率低一个量级。

### 146.4.3 逐步状态表（`n = 3`，转置阶段）

| 步骤 | 操作 | 被交换的两格 | 矩阵当前状态（每行） |
| --- | --- | --- | --- |
| 初始 | — | — | `1 2 3 / 4 5 6 / 7 8 9` |
| 1 | `(0,1)↔(1,0)` | 2 与 4 | `1 4 3 / 2 5 6 / 7 8 9` |
| 2 | `(0,2)↔(2,0)` | 3 与 7 | `1 4 7 / 2 5 6 / 3 8 9` |
| 3 | `(1,2)↔(2,1)` | 6 与 8 | `1 4 7 / 2 5 8 / 3 6 9` |
| 4 | 对角不动 | 1、5、9 | 转置完成 |
| 5 | 行 0 左右翻 | 1 与 7 | `7 4 1 / 2 5 8 / 3 6 9` |
| 6 | 行 1 左右翻 | 2 与 8 | `7 4 1 / 8 5 2 / 3 6 9` |
| 7 | 行 2 左右翻 | 3 与 9 | `7 4 1 / 8 5 2 / 9 6 3` ✓ |

## 146.5 双语言实现

### 146.5.1 Java

```java
class Solution {
    public void rotate(int[][] matrix) {
        int n = matrix.length;
        if (n <= 1) {
            return; // n = 1 时旋转是恒等变换；提前返回也顺手挡掉了 n = 0 的空矩阵
        }

        // 第一步：转置。只遍历上三角（j 从 i+1 开始）：
        // 若 j 从 0 开始，每对元素会被交换两次，等于没转置 —— 这是最隐蔽的错法。
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                int tmp = matrix[i][j];
                matrix[i][j] = matrix[j][i];
                matrix[j][i] = tmp;
            }
        }

        // 第二步：每一行左右翻转（竖直中线镜像）。
        // 每行用 l / r 双指针向中间夹，l == r 时（n 为奇数）中间那一列不动。
        for (int i = 0; i < n; i++) {
            for (int l = 0, r = n - 1; l < r; l++, r--) {
                int tmp = matrix[i][l];
                matrix[i][l] = matrix[i][r];
                matrix[i][r] = tmp;
            }
        }
    }
}
```

### 146.5.2 Go

```go
package main

func rotate(matrix [][]int) {
	n := len(matrix)
	if n <= 1 {
		return // 单行/单列（n = 1）与空矩阵直接返回
	}

	// 转置：matrix 是「切片的切片」，matrix[i] 是各自独立的底层数组，
	// 对 matrix[i][j] 的写入会立刻反映到实参上，这就是原地生效的原因。
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
		}
	}

	// 每行左右翻转：Go 支持多重赋值，交换不需要显式写 tmp（编译器会处理）
	for i := 0; i < n; i++ {
		for l, r := 0, n-1; l < r; l, r = l+1, r-1 {
			matrix[i][l], matrix[i][r] = matrix[i][r], matrix[i][l]
		}
	}
}
```

### 146.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维结构 | `int[][]` 是「数组的数组」，`matrix[i]` 是引用 | `[][]int` 是「切片的切片」，每行独立的底层数组 | 两者都能原地生效；但 Go 的 `range` 拿到的是**行切片的副本头**（仍指向同一底层数组），写元素安全，**赋值整行不安全** |
| 交换写法 | 必须显式 `int tmp = …` | 支持 `a, b = b, a` 多重赋值 | Go 少一行、少一个错点 |
| 空矩阵 | `matrix.length == 0` 时 `n = 0`，两层循环自然不执行 | `len(matrix) == 0` 也是 `n = 0`；但 `matrix[0]` 会 panic，**不要**在 n 未知时读 `matrix[0][0]` | 都应当先判 `n`，别先取元素 |
| 返回类型 | `void`（原地修改） | 无返回值 | 与题面「必须原地」严格对应 |
| 越界 | 抛 `ArrayIndexOutOfBoundsException` | panic | `n − 1 − i` 在 `i = 0` 时是 `n − 1`，是合法上界，别写成 `n − i` |

### 146.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 参考实现：新建矩阵按坐标公式填。思路与「转置+翻转」完全无关，
// 因此两者的 bug 不会同向。
func bruteRotate(a [][]int) [][]int {
	n := len(a)
	res := make([][]int, n)
	for i := range res {
		res[i] = make([]int, n)
	}
	for i := 0; i < n; i++ {
		for j := 0; j < n; j++ {
			res[j][n-1-i] = a[i][j] // 旧 (i,j) → 新 (j, n−1−i)
		}
	}
	return res
}

func cloneMatrix(a [][]int) [][]int {
	b := make([][]int, len(a))
	for i := range a {
		b[i] = append([]int(nil), a[i]...)
	}
	return b
}

func equalMatrix(a, b [][]int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if len(a[i]) != len(b[i]) {
			return false
		}
		for j := range a[i] {
			if a[i][j] != b[i][j] {
				return false
			}
		}
	}
	return true
}

func TestRotateRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20260219))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(8) + 1 // 1..8
		a := make([][]int, n)
		// 用互不相同的值（n² 个不同的数），这样任何坐标错误都会被抓到
		// —— 全相同的值会让错解「假通过」，见本章反例 ③。
		v := 0
		for i := 0; i < n; i++ {
			a[i] = make([]int, n)
			for j := 0; j < n; j++ {
				a[i][j] = v
				v++
			}
		}
		// 再随机打乱，避免「有序矩阵」掩盖问题
		for i := 0; i < n*n/2; i++ {
			x1, y1 := r.Intn(n), r.Intn(n)
			x2, y2 := r.Intn(n), r.Intn(n)
			a[x1][y1], a[x2][y2] = a[x2][y2], a[x1][y1]
		}

		orig := cloneMatrix(a)
		want := bruteRotate(a)

		got := cloneMatrix(a)
		rotate(got)
		if !equalMatrix(got, want) {
			t.Fatalf("iter=%d n=%d\ngot =%v\nwant=%v", iter, n, got, want)
		}

		// 旋转 4 次必须回到原样：这是「原地置换」的强不变量检查，
		// 它不依赖参考实现，只用「旋转的阶是 4」这个数学事实。
		for k := 0; k < 4; k++ {
			rotate(a)
		}
		if !equalMatrix(a, orig) {
			t.Fatalf("iter=%d n=%d 旋转 4 次没有回到原样", iter, n)
		}
	}
}

func TestRotateEdge(t *testing.T) {
	// 空矩阵（0 × 0）：题目约束 n ≥ 1，但工程代码必须不 panic
	empty := [][]int{}
	rotate(empty)
	if len(empty) != 0 {
		t.Fatalf("空矩阵不应被改变")
	}

	// 单行 / 单列（n = 1 的方阵）
	one := [][]int{{7}}
	rotate(one)
	if one[0][0] != 7 {
		t.Fatalf("1x1 应不变，got=%v", one)
	}

	// 2 × 2
	two := [][]int{{1, 2}, {3, 4}}
	rotate(two)
	if !equalMatrix(two, [][]int{{3, 1}, {4, 2}}) {
		t.Fatalf("2x2 got=%v", two)
	}

	// 3 × 3 题面示例
	three := [][]int{{1, 2, 3}, {4, 5, 6}, {7, 8, 9}}
	rotate(three)
	if !equalMatrix(three, [][]int{{7, 4, 1}, {8, 5, 2}, {9, 6, 3}}) {
		t.Fatalf("3x3 got=%v", three)
	}

	// 4 × 4 题面示例
	four := [][]int{{5, 1, 9, 11}, {2, 4, 8, 10}, {13, 3, 6, 7}, {15, 14, 12, 16}}
	rotate(four)
	if !equalMatrix(four, [][]int{{15, 13, 2, 5}, {14, 3, 4, 1}, {12, 6, 8, 9}, {16, 7, 10, 11}}) {
		t.Fatalf("4x4 got=%v", four)
	}
}

// 旋转 4 次回到原样：这是最便宜、最强的自检
func TestRotateFourTimesIdentity(t *testing.T) {
	r := rand.New(rand.NewSource(7))
	for iter := 0; iter < 2000; iter++ {
		n := r.Intn(7) + 1
		a := make([][]int, n)
		for i := range a {
			a[i] = make([]int, n)
			for j := range a[i] {
				a[i][j] = r.Intn(100)
			}
		}
		orig := cloneMatrix(a)
		for k := 0; k < 4; k++ {
			rotate(a)
		}
		if !equalMatrix(a, orig) {
			t.Fatalf("iter=%d 旋转 4 次没有回到原样", iter)
		}
	}
}
```

## 146.6 复杂度与常见坑

### 146.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n²)**：转置阶段遍历上三角，共 `n(n−1)/2` 对交换；翻转阶段每行 `⌊n/2⌋` 次交换，共 `n·⌊n/2⌋` 次。合计约 `n²` 次交换，每次 `O(1)`。注意**每个元素只被搬动两次**（一次转置、一次翻转），这是常数级的搬运次数，所以不可能比 `O(n²)` 更低——**输出本身就是 `n²` 个格子，任何正确的原地算法都至少要碰每个格子一次**。
- **空间 O(1)**：只用了一个 `tmp`（Go 里连 `tmp` 都不用，多重赋值由编译器处理）。没有递归、没有额外矩阵。
- **对比新建矩阵**：同样 `O(n²)` 时间，但空间 `O(n²)`（`n = 20` 时 400 个 `int` = 1.6 KB）。差距在 `n` 大时才有意义，但**题目考的是「能不能原地」，不是「快不快」**。
- **`n` 的边界**：`n = 1` 时两段循环的循环体一次都不执行（上三角为空、每行 `l >= r`），所以自动是恒等变换；`n = 0`（空矩阵）时也是恒等。这两个边界**不需要特判也能正确**——但特判能让代码意图更清楚。

### 146.6.2 七个真实踩过的坑

1. **转置的内层循环 `j` 从 0 开始** —— 每对元素被交换两次，等于完全没转置。必须 `j = i + 1`。
2. **顺序反了** —— 「先左右翻转再转置」得到的是**逆时针** 90°。写代码前先把坐标公式推一遍（`(r,c) → (c, r) → (c, n−1−r)` = 顺时针）。
3. **四格轮换的赋值顺序写错** —— 不先保存 `matrix[i][j]` 就开始覆盖，会导致两格的值相同（数据丢失）。这正是推荐「转置+翻转」的理由。
4. **`n − 1 − i` 写成 `n − i`** —— `i = 0` 时 `n − 0 = n` 越界。所有「镜像下标」都必须是 `n − 1 − x`。
5. **Go 里对 `range` 出来的行做整体赋值** —— `for _, row := range matrix { row = newRow }` 只改了副本头，原矩阵不变；要么改元素（`row[j] = …`，安全），要么用索引 `matrix[i] = …`。
6. **以为「对角线元素不动」** —— 只有转置与 180° 旋转会保持对角线；90° 旋转会把 `(i, i)` 搬到 `(i, n−1−i)`，对角元素**会离开对角线**。
7. **对非方阵套用原地旋转** —— `m × n` 旋转后是 `n × m`，形状变了，原地不可能实现，必须新建矩阵。

### 146.6.3 面试官最爱追问的三个问题

**Q1：为什么「转置 + 左右翻转」等于顺时针 90°？**

> 「写出坐标就够了：转置把 `(r, c)` 变成 `(c, r)`，左右翻转再把列号 `r` 映到 `n−1−r`，合起来是 `(r, c) → (c, n−1−r)`——这正是顺时针 90° 的坐标公式。而且两个操作各自都是『不重叠的成对交换』，所以额外空间只要一个临时变量。如果调换顺序，复合出来是 `(n−1−c, r)`，那是逆时针。」

**Q2：不借助转置，怎么直接原地做四格轮换？**

> 「旋转把每个元素送到一条四元环上：`(i,j) → (j, n−1−i) → (n−1−i, n−1−j) → (n−1−j, i) → (i,j)`。所以只需遍历矩阵的左上四分之一区域（`i < n/2`、`i ≤ j < n−1−i`），对每条环先存下左上角的值，然后按『接收者的顺序』倒着赋值四步。代价同样是 `O(n²)` 时间、`O(1)` 空间，但四条赋值的下标极容易写错，我一般选转置+翻转。」

**Q3：如果矩阵不是方阵呢？**

> 「`m × n` 顺时针旋转 90° 之后尺寸变成 `n × m`，元素个数虽然不变，但存储布局必须重排，所以**原地做不到**——除非允许返回一个形状不同的视图。实际做法是新建 `n × m` 的矩阵，按 `res[j][m−1−i] = a[i][j]` 填，时间 `O(mn)`、空间 `O(mn)`。这道题限定方阵，正是为了让『原地』成为可能。」
