## 005.1 题目

**原题链接**：<https://leetcode.cn/problems/container-with-most-water/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的整数数组 `height`，每个元素代表一条竖直的挡板，第 `i` 条挡板的两端分别在 `(i, 0)` 和 `(i, height[i])`。请找出**两条挡板**，使它们与 x 轴围成的容器**能装的水最多**，返回这个最大容量。

容量的计算方式（题目用文字描述，不给公式，这是第一个坑）：

```
容量 = min(height[i], height[j]) × (j - i)
         ↑                        ↑
      水会从矮的那边溢出        底边宽度
```

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **容器高度取两板较小值** | 「水会从较高的一端溢出」 | 用 `max` 或 `(h[i]+h[j])/2` 就全错 |
| **底边是下标差 `j - i`** | 图形 | 用「板的个数 `j-i+1`」会算大 |
| **不必装满到某条线** | 「找出两条线」 | 误以为要求「两板之间所有板都低于水面」→ 变成另一道题 |
| **两条板必须不同** | 「选出两条线」 | `i == j` 时容量为 0，不影响答案但会浪费 |
| **不要求两板相邻** | 图形 | 只在相邻板之间找 → 漏掉宽底大容量 |

> ⚠️ 最后一条是本题的题眼：**「宽」和「高」是一对矛盾量**。最宽的那对（`0` 和 `n-1`）不一定最高，最高的那对（两根最高的板）不一定宽。整道题就是在解这个二维权衡。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n == height.length`，`2 <= n <= 10^5` | 最多 10 万 | **O(n²) = 5·10⁹ 次**，按 10⁸/s 要 50 秒 → **必 TLE**；只能 O(n) 或 O(n log n) |
| `0 <= height[i] <= 10^4` | 高度上限 1e4 | 最大容量 = `1e4 × 1e5 = 1e9`，**刚好在 `int32` 上界 `2.147·10⁹` 之内**（留了 2 倍余量）；但若把 `h` 或 `n` 任意放大一倍，就要 `long` |
| 允许 `height[i] == 0` | 有 0 高 | 容量可以是 0；**初始化 `max` 用 0 是安全的**，但如果用 `-1` 当哨兵就要小心全 0 数组 |
| **元素顺序不可变** | 图形是「按位置竖起来的板」 | **不能排序**！排序会打乱「距离」这个维度 |

> 💡 **量级反推**：`n = 10^5` 是本题的硬门槛 —— O(n²) 死、O(n) 活。而 `n log n` 也在门槛内（约 `1.7·10⁶`），所以「排序类」的替代解法在**复杂度上**是允许的，只是它必须想办法保住位置信息（§005.3.1 会给出一个用排序的 O(n log n) 解，用来做交叉验证）。

### 示例

```
输入：height = [1,8,6,2,5,4,8,3,7]
输出：49
解释：选下标 1（高 8）和下标 8（高 7）
      容量 = min(8, 7) × (8 - 1) = 7 × 7 = 49

输入：height = [1,1]
输出：1
解释：min(1,1) × 1 = 1

输入：height = [4,3,2,1,4]
输出：16
解释：选两端（高 4 和高 4），min(4,4) × 4 = 16
      注意中间那些板全都更矮，任何一对中间的板宽度都更小、高度也不更高

输入：height = [1,2,1]
输出：2
解释：选 0 和 2：min(1,1) × 2 = 2；选 1 和 2：min(2,1) × 1 = 1
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [1,2,1]        → 暴露「只在相邻板之间找」：相邻最大只有 1，答案 2 需要跨过中间
② [4,3,2,1,4]    → 暴露「移动高的一侧」：移动右端 4 会让宽度变小、高度还不增加
③ [0,0]          → 暴露「用 -1 初始化 max」之外的边界：容量 0，返回 0
④ [40,100,100,40,40,40,40] → 暴露「只看最高的两根」：最高两根是下标 1、2，
                        容量 min(100,100)×1 = 100；而两端 min(40,40)×6 = 240 才是答案
```

第 ④ 条最能说明「矛盾量」的本质：**最高的两根板未必是最优解**，答案往往是「**够高**的前提下尽量宽」。下标 1、2 那对高度碾压全场，但宽度只有 1；两端那对高度只有 40，宽度却是 6，`40×6=240 > 100×1`。

## 005.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力

```java
// 枚举所有板对 (i, j)，i < j
int best = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        best = Math.max(best, Math.min(height[i], height[j]) * (j - i));
```

- 时间 **O(n²)**，空间 **O(1)**。
- `n = 10^5` 时 `n(n-1)/2 ≈ 5·10⁹` 次 —— **50 秒量级，必 TLE**。
- 暴力是**正确的**（枚举了所有板对），问题只在慢。这和三数之和不同：那里暴力还错，这里暴力只是慢。所以本题的推理负担全部落在「**为什么可以丢掉候选**」上。

### 第二步：卡点在哪

容量是两个变量的乘积：

```
area(i, j) = min(h[i], h[j]) × (j - i)
             └── 高 ──┘      └─ 宽 ─┘
```

想让它变大，就得让「高」或「宽」变大。而**从最宽的那一对出发**（`i = 0, j = n-1`），任何移动都会让宽**变小**（从 `n-1` 减到 `n-2`、`n-3`…）。所以：

> **宽度注定单调递减。既然宽只会变小，那唯一可能让面积变大的途径就是「高度变大」。**

这句话是本题全部灵感的来源。于是问题变成：**在宽度逐步缩小的过程中，怎么让高度有机会变大？**

如果当前这对是 `(h[l], h[r])` 且 `h[l] < h[r]`：

- 高度由 `h[l]` 决定（矮的那根）。
- 只要 `h[l]` 还在容器里，高度就永远 `<= h[l]`。
- 那么**把 `r` 往左移（换个更矮或更高的右板）毫无意义**：高度还是被 `h[l]` 卡死，宽度却变小了 —— **面积只会更小**。

结论：`h[l]` 这根矮板已经「**用尽**」了，它对任何未来的配对都不再可能贡献更好的结果。**可以永久丢掉它。**

```
┌──────────────────────────────────────────────────────────────┐
│ 核心一句话：宽度单调递减 → 只有「高度能变大」才可能翻盘         │
│             → 而高度被矮板卡死 → 矮板必须先被淘汰              │
└──────────────────────────────────────────────────────────────┘
```

### 第三步：灵感的来源 —— 「淘汰矮的，不是淘汰高的」

很多人第一次会想「那我把高的移走、换个更矮的？」—— 直觉告诉你不该这么做，但**面试官要的是证明，不是直觉**。下面给出正式版本的「淘汰论证」（也叫**支配论证 / 交换论证**）。

**命题**：设当前 `h[l] < h[r]`。则对任意 `k ∈ (l, r]`，都有 `area(l, k) <= area(l, r)`。

**证明**：

```
area(l, k) = min(h[l], h[k]) × (k - l)
           <= h[l] × (k - l)              （因为 min <= h[l]）
           <= h[l] × (r - l)              （因为 k <= r，且 h[l] >= 0）
           = min(h[l], h[r]) × (r - l)    （因为 h[l] < h[r]，min 就是 h[l]）
           = area(l, r)
```

∎

**这个不等式的含义**：一旦确定了「以 `l` 为左板」，那么**在最右端 `r` 时它的面积已经是最大的了**，任何「把右板往左挪」的尝试都只会更差。所以 `l` 这一整排候选（`(l, l+1), (l, l+2), ..., (l, r)`）里，最优的那个已经算过了。**`l` 可以整体淘汰。**

对称地，若 `h[l] >= h[r]`，则 `r` 那一整列候选的最优值就是 `area(l, r)`，淘汰 `r`。

> 📌 注意这个论证和 002/003/**004 的差别：那里是「当前这对**不满足** `== target`，所以排除一端」；这里是「当前这对**已经是**某一整排里最好的，所以这一整排不用再算了」。**前者是排除不可能，后者是排除已穷尽** —— 后者更难想，也更容易被面试官追问。

### 另一条路：排序 + 记录最远位置（O(n log n)，用来交叉验证）

有一个不常用的替代思路，很适合用来「对拍」自己对双指针的理解：

1. 把 `(height[i], i)` 按高度**降序**排序。
2. 依次处理，维护「已处理过的下标的最小值 `minIdx` 和最大值 `maxIdx`」。
3. 处理第 `t` 根板时，它作为「容器较矮那根」时能达到的最大宽度就是 `max(maxIdx, i) - min(minIdx, i)`，容量候选是 `height[i] × 这个宽度`。

**为什么对**：若最终答案的矮板是 `h[i]`，那么另一根板的高度必然 `>= h[i]`，即它在排序里排在 `i` 之前（已处理）。而宽度要最大，就该选已处理下标里离 `i` 最远的那个 —— 正好是 `minIdx` 或 `maxIdx`。

- 时间 **O(n log n)**，空间 **O(n)**。
- 它比双指针**慢且费空间**，但思路完全不同，是绝佳的对拍参照物（§005.5.4 就用它）。

## 005.3 原理拆解

### 005.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力枚举板对 | O(n²) | O(1) | 4 行 | n ≥ 10⁴ 就危险，10⁵ 必 TLE |
| **对撞双指针 + 淘汰矮板** ✅ | **O(n)** | **O(1)** | **8 行** | 容量函数必须满足「宽变小时高才可能补救」的单调结构；换成「面积 = 高之和 × 宽」就不成立了 |
| 排序 + 记录最远下标 | O(n log n) | O(n) | 20 行 | 需要额外 O(n) 空间；常数大；但**逻辑完全不同**，适合交叉验证 |
| 单调栈（下一个更高/更矮） | O(n) | O(n) | 30 行 | 本题不需要「区间内最值」，栈是杀鸡用牛刀；思路走偏 |

**为什么双指针是唯一正解**：它同时做到了「**零额外空间**」和「**线性时间**」，而且代码只有 8 行。这在算法题里是罕见的「三面全胜」。

### 005.3.2 为什么这个做法是对的（正确性论证）

需要证明：**算法返回的就是全局最大容量。**

**论证（用「淘汰集合」的不变量）**

> **不变量**：每一轮开始时，`[0, l)` 与 `(r, n-1]` 中的所有下标都已被**证明不可能**成为最优解的一端。

- **初始**：`l = 0, r = n-1`，两个空集，成立。
- **保持**：设当前 `h[l] < h[r]`。由 §005.2 的支配不等式，对所有 `k ∈ (l, r]` 都有 `area(l, k) <= area(l, r)`。而所有「以 `l` 为端点、另一端在 `[0, l)` 或 `(r, n-1]` 内」的组合，要么下标不合法（`< l`），要么早就被不变量排除。所以 **`l` 作为任一最优解的端点是不可能的**（除了 `(l, r)` 本身，而它已经被 `best` 记录）。于是把 `l` 加一，不变量保持。
- **终止**：`l` 只增、`r` 只减，`l == r` 时结束。此时所有下标对都已被排除，唯一没被排除的就是已经被记录的最优值。∎

**再补一个「那 `(l, r)` 自己会不会被漏掉」的问题**：不会。每轮循环**先**更新 `best = max(best, area(l, r))`，**再**移动指针。所以每一个「到达过的 `(l, r)`」都被计入。

> **这个论证的价值**：它把「贪心」变成了「**排除法**」—— 我们并不是在猜「移动矮的一定对」，而是在证明「移动矮的那一侧之后，被丢掉的那些候选里**不存在**更优解」。这两者在面试里是完全不同的档次。

**对称说明**：若 `h[l] >= h[r]`，把上文的 `l`/`r` 互换、`<` 换成 `>=`，命题逐字成立。所以「相等时移动哪边都行」——因为 `min(h[l], h[r])` 两边都等于对方，淘汰任一都是合法的。这也是一个常见的追问点（见 §005.6.3 Q2）。

### 005.3.3 通用解题思路（可迁移的那一层）

本题是 **「对撞双指针 + 支配关系淘汰」** 模型的原型：

```
问题：在 O(n²) 个「配对」上求 max f(i, j)，其中 f 依赖「距离」和「两端属性」
        ↓ 观察 1：从最宽处出发，任何移动都让「距离」单调变小
        ↓ 观察 2：当「距离」注定变小，f 若想变大，只能靠「两端属性」变好
        ↓ 观察 3：找出「谁在拖后腿」（本题是矮的那根），它不换掉就永远好不了
     淘汰：整批丢掉拖后腿那一端的全部候选（支配不等式保证安全）
        ↓ 每轮淘汰一个 → 总共 O(n) 轮
```

**与 002 的对照（这是本章最该记住的一张表）**：

| 维度 | 002 两数之和 II | 005 盛水容器 |
| --- | --- | --- |
| 目标 | 找到 `== target` 的一对 | 求 `max` |
| 指针移动的依据 | 当前 `s` 与 `target` 的**大小关系** | 两端高度的**大小关系** |
| 排除的是什么 | 「不可能等于 target」的候选 | 「不可能超过当前最优」的候选 |
| 论证工具 | 有序性 + 反证 | **支配不等式（不等式链）** |
| 能不能提前 `return` | 能（命中就返回） | **不能**（必须扫描完，因为最大值可能在任何位置） |

> ⚠️ 最后一行是个高频陷阱：很多人把「命中就返回」的习惯带过来，写成「某次面积没变大就 `break`」—— **错**。宽度在变小，面积可能先降后升，没有任何单调性。

属于同一模型的题：

| 题 | 「拖后腿」的那一端 | 支配关系 |
| --- | --- | --- |
| [LC 11 盛最多水的容器](https://leetcode.cn/problems/container-with-most-water/) | 矮的那根板 | `min(h[l],h[k])·(k-l) <= h[l]·(r-l)` |
| [LC 15 三数之和](https://leetcode.cn/problems/3sum/) | 和偏小/偏大的一端 | 由有序性直接给出 |
| [LC 42 接雨水](https://leetcode.cn/problems/trapping-rain-water/) | 两侧最大高度中较小的那个 | `water[i] = min(leftMax, rightMax) - h[i]` |
| [LC 977 有序数组的平方](https://leetcode.cn/problems/squares-of-a-sorted-array/) | 绝对值较大的一端 | 平方后从大到小可确定 |
| [LC 680 验证回文字符串 II](https://leetcode.cn/problems/valid-palindrome-ii/) | 第一次不匹配的两端（二选一） | 需要**两条分支各自验证** |

### 005.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 容量公式改成 `(h[i]+h[j]) × (j-i)` | 高度不再被矮板卡死 | **双指针的支配论证失效**！此时要枚举「最大 `h[i]-i`」等组合，用单调栈或排序 |
| 改成「求**最小**容量」 | 求 min 而非 max | 求 min 时双指针不成立（宽度最大处未必最小）；需要另想，通常是 O(n²) 下界 |
| 板可以**任意重排** | 位置可变 | 变成「排序后贪心」题：把最高的两根放最中间，然后逐步向两边放 |
| 求「容量第二大的板对」 | 要 Top-2 | 双指针只留一个 `best` 会丢信息，需要维护「候选集合」或直接用堆 |
| `height` 到 `±10⁹` | 容量 `1e9 × 1e5 = 1e14` | **必须 `long` / `int64`**；`Math.max(int,int)` 会静默截断 |
| **在线数据流**（板从右边不断追加） | 右端点动态变化 | 双指针失效（`r` 不确定）；可用「后缀最大值 + 二分」做到 O(log n) 每次查询 |

**进阶延伸（自己写代码验证）**：

- **LC 42 接雨水**：同样是「两端取 min」的双指针，但目标是「累加每个位置的贡献」而不是「一对的最大值」。下一章就是它。
- **LC 84 柱状图中最大的矩形**：把「两板之间的水」换成「连续区间内的最大矩形」，双指针不够用，必须上单调栈。
- **LC 407 接雨水 II**：二维版本，双指针升级成「优先队列 + 边界收缩」。

## 005.4 图解推演

### 005.4.1 主样例的完整轨迹

```
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
下标      0  1  2  3  4  5  6  7  8

第 1 轮  l=0(高1)  r=8(高7)
   面积 = min(1,7) × 8 = 8
   ┌──┬──┬──┬──┬──┬──┬──┬──┬──┐
   │▁ │█ │▅ │▂ │▄ │▃ │█ │▂ │▆ │    ← 柱高示意
   └──┴──┴──┴──┴──┴──┴──┴──┴──┘
    ↑l                       ↑r      h[l]=1 < h[r]=7  →  淘汰 l  →  l++
   best = 8

第 2 轮  l=1(高8)  r=8(高7)
   面积 = min(8,7) × 7 = 49   ✅ best = 49
   淘汰 r（h[r]=7 < h[l]=8）  →  r--

第 3 轮  l=1(高8)  r=7(高3)
   面积 = min(8,3) × 6 = 18
   淘汰 r（3 < 8）  →  r--

第 4 轮  l=1(高8)  r=6(高8)
   面积 = min(8,8) × 5 = 40
   相等 → 代码约定淘汰左端  →  l++

第 5 轮  l=2(高6)  r=6(高8)
   面积 = min(6,8) × 4 = 24      h[l] < h[r]  →  淘汰 l  →  l++

第 6 轮  l=3(高2)  r=6(高8)
   面积 = min(2,8) × 3 = 6       淘汰 l  →  l++

第 7 轮  l=4(高5)  r=6(高8)
   面积 = min(5,8) × 2 = 10      淘汰 l  →  l++

第 8 轮  l=5(高4)  r=6(高8)
   面积 = min(4,8) × 1 = 4       淘汰 l  →  l++  →  l == r，结束

最大容量 = 49 ✓
```

### 005.4.2 每一步淘汰了哪些候选（核心表格）

初始 `(l, r) = (0, 8)`。每一行记下「本轮的窗口、面积、以及淘汰掉谁」，最后一列是这一轮**成批作废**掉的候选配对：

| 轮 | l | r | h[l] | h[r] | area | best | 淘汰 | 本轮作废的候选 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 8 | 1 | 7 | 8 | 8 | `l=0` | `(0,1) … (0,8)` 共 8 个 |
| 2 | 1 | 8 | 8 | 7 | **49** | **49** | `r=8` | `(1,8) … (7,8)` 共 7 个 |
| 3 | 1 | 7 | 8 | 3 | 18 | 49 | `r=7` | `(1,7) … (6,7)` 共 6 个 |
| 4 | 1 | 6 | 8 | 8 | 40 | 49 | `l=1` | `(1,2) … (1,6)` 共 5 个 |
| 5 | 2 | 6 | 6 | 8 | 24 | 49 | `l=2` | `(2,3) … (2,6)` 共 4 个 |
| 6 | 3 | 6 | 2 | 8 | 6 | 49 | `l=3` | `(3,4) … (3,6)` 共 3 个 |
| 7 | 4 | 6 | 5 | 8 | 10 | 49 | `l=4` | `(4,5) (4,6)` 共 2 个 |
| 8 | 5 | 6 | 4 | 8 | 4 | 49 | `l=5` | `(5,6)` 共 1 个 |

**看最后两列**：初始一共 `C(9,2) = 36` 个板对，而 8 轮里被**单独检查过**的只有 8 个，剩下 28 个全部**成批作废**、一次都没算过。批的大小是 `8, 7, 6, 5, 4, 3, 2, 1`，加起来恰好 36 —— 也就是说**每一对候选都恰好落在一个批里，不重不漏**。

这就是 O(n) 的来源：**不是「少检查几个」，而是「一次作废一整排」。** 也正因为批大小在递减，`l` 和 `r` 各自最多走 `n` 步就必然相遇。

### 005.4.3 支配不等式的可视化

设 `h[l] = 2 < h[r] = 6`，`r - l = 5`。考虑 `l` 与中间某点 `k`（`k - l = 3`）的组合：

```
        h[l]=2                                   h[r]=6
          │                                        │
      ┌───┼────────────────────────────────────────┼───┐
    2 │███│                                        │   │  ← 水位由 h[l]=2 决定
      │███│                          h[k]=9        │   │
      │███│                            │           │   │
      │███│                            │           │   │
      └───┴────────────────────────────┴───────────┴───┘
        l  ──────── 宽 5 ───────────────────────── r
                       k（宽 3，但高度仍被 2 卡住）

area(l, r) = min(2,6) × 5 = 10
area(l, k) = min(2,9) × 3 = 6      ← 高板再高也没用，宽度缩了
不等式：min(2,9) × 3 <= 2 × 3 <= 2 × 5 = 10   ✔
```

**这张图就是「矮板必须被淘汰」的全部直观理由**：水位线由矮板画定，换任何更高的板都提升不了水位，而宽只会减小。

## 005.5 双语言实现

### 005.5.1 Java

```java
class Solution {
    public int maxArea(int[] height) {
        // 循环不变量：[0, l) 与 (r, n-1] 内的下标都已被证明不可能成为最优解的一端
        int l = 0, r = height.length - 1;
        int best = 0;   // 用 0 初始化：容量非负，全 0 数组返回 0 也正确

        // 必须是 l < r：l == r 时宽度为 0，容量为 0，继续没有意义
        while (l < r) {
            // 先算面积再移动指针：保证每一个"到达过的 (l, r)"都被计入 best
            // 高度上限 1e4、宽度上限 1e5 → 容量上限 1e9，int 安全（余量约 2 倍）
            int h = Math.min(height[l], height[r]);
            int area = h * (r - l);
            if (area > best) {
                best = area;
            }

            // 淘汰矮的那一端：
            // 若 h[l] <= h[r]，则以 l 为左板的全部候选，面积都被 h[l]*(r-l) 压住，
            // 最右端 (l, r) 已是其中最优 → l 这一整排无需再算
            // 相等时移动任一端都合法（两边的 min 都等于对方高度）
            if (height[l] <= height[r]) {
                l++;
            } else {
                r--;
            }
        }
        return best;
    }
}
```

### 005.5.2 Go

```go
package main

// maxArea 返回两板能围成的最大容量。变量名与 Java 版逐行对齐。
func maxArea(height []int) int {
	// 不变量：[0, l) 与 (r, n-1] 内的下标都已被证明不可能成为最优解的一端
	l, r := 0, len(height)-1
	best := 0

	for l < r {
		// Go 没有内建 min(int,int)（1.21 才有内建 min 泛型函数），
		// 这里手写三元表达式等价物；注意 min 在 1.19 是关键字以外还得自己写
		h := height[l]
		if height[r] < h {
			h = height[r]
		}
		// 本题量级（h<=1e4, 宽<=1e5）不会溢出 int；
		// 若 height 上限放大到 1e9，这里必须改成 int64
		if area := h * (r - l); area > best {
			best = area
		}

		// 淘汰矮的那一端（相等时动左端，与 Java 版保持完全一致的行为）
		if height[l] <= height[r] {
			l++
		} else {
			r--
		}
	}
	return best
}
```

### 005.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 两数取小 | `Math.min(a, b)` | 1.19 无内建 `min`（1.21 起有），要手写 `if` | Go 代码多 3 行；写错成 `Math.Min` 风格会编译失败（Go 的 `math.Min` 只接受 `float64`） |
| 浮点陷阱 | `Math.min(int,int)` 是整型重载 | 误用 `math.Min(float64(a), float64(b))` 会**丢精度**（> 2⁵³ 才丢，本题安全，但习惯不好） | 面试写 Go 时优先手写 `if`，避免隐式浮点转换 |
| 指针命名 | `int l, r` | `l, r := 0, len(height)-1`（短变量声明） | 语义一致 |
| 返回类型 | `int`（32 位） | `int`（64 位平台上 64 位） | 容量上限 `1e9` 两者都安全；但如果把 `best` 累加多个面积就可能不同 |
| 空/单元素输入 | 题面保证 `n >= 2` | 同上 | Go 对 `len == 0` 时 `len(height)-1 == -1`，`l < r` 为假，天然不崩；Java 的 `length-1` 同理 |

### 005.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// brute 枚举所有板对，O(n²)，绝对正确
func brute(h []int) int {
	best := 0
	for i := 0; i < len(h); i++ {
		for j := i + 1; j < len(h); j++ {
			area := h[i]
			if h[j] < area {
				area = h[j]
			}
			area *= j - i
			if area > best {
				best = area
			}
		}
	}
	return best
}

// bySort 是「按高度降序 + 记录已处理下标的最左/最右」的独立解法，
// 与双指针的思路毫无交集，用来当第二个参照物（O(n log n)）
func bySort(h []int) int {
	n := len(h)
	idx := make([]int, n)
	for i := range idx {
		idx[i] = i
	}
	// 按高度降序；高度相同时下标顺序无所谓
	sort.Slice(idx, func(a, b int) bool { return h[idx[a]] > h[idx[b]] })

	best := 0
	minIdx, maxIdx := n, -1
	for _, i := range idx {
		// 处理到 i 时，已处理的都是高度 >= h[i] 的板，
		// 它们都能当"另一根"（高度不会被 h[i] 卡住）
		if maxIdx >= 0 {
			d := maxIdx - i
			if i-maxIdx > d {
				d = i - maxIdx
			}
			if minIdx-i > d {
				d = minIdx - i
			}
			if i-minIdx > d {
				d = i - minIdx
			}
			if area := h[i] * d; area > best {
				best = area
			}
		}
		if i < minIdx {
			minIdx = i
		}
		if i > maxIdx {
			maxIdx = i
		}
	}
	return best
}

func TestMaxAreaRandom(t *testing.T) {
	r := rand.New(rand.NewSource(7))
	for iter := 0; iter < 20000; iter++ {
		n := 2 + r.Intn(30)
		h := make([]int, n)
		for i := range h {
			h[i] = r.Intn(21) // 0..20，含 0 与大量重复值
		}

		got := maxArea(h)
		want := brute(h)
		if got != want {
			t.Fatalf("iter=%d h=%v got=%d want=%d", iter, h, got, want)
		}
		// 第三个参照物交叉验证：两条完全不同的思路必须给出同一个答案
		if alt := bySort(h); alt != want {
			t.Fatalf("iter=%d h=%v bySort=%d want=%d（参照物互相矛盾，说明其中一方有 bug）",
				iter, h, alt, want)
		}
	}
}

// 钉住四个手推反例
func TestMaxAreaEdge(t *testing.T) {
	cases := []struct{ h []int; want int }{
		{[]int{1, 2, 1}, 2},
		{[]int{4, 3, 2, 1, 4}, 16},
		{[]int{0, 0}, 0},
		{[]int{40, 100, 100, 40, 40, 40, 40}, 240},
	}
	for _, c := range cases {
		if got := maxArea(c.h); got != c.want {
			t.Fatalf("h=%v got=%d want=%d", c.h, got, c.want)
		}
	}
}
```

> **为什么值得写 `bySort`**：双指针的支配论证是「推理型正确」，很难靠直觉验证。而 `bySort` 是「枚举型正确」，两者在 20000 组随机数据上逐一对齐，才算真正把「淘汰矮板是安全的」这件事钉死。**找第二把尺子验证第一把尺子，是本书推荐的验收习惯。**

## 005.6 复杂度与常见坑

### 005.6.1 复杂度推导

- **时间 O(n)**：`l` 从 `0` 单调增、`r` 从 `n-1` 单调减，每轮**恰好一个**指针移动一格，所以总轮数 `= (n-1) + 0` 至多 `n-1` 轮。每轮常数次操作 → `O(n)`。
  - 注意这是**严格**的：不像三数之和的内层要摊还分析，这里是「一轮移动一格」的硬上界。
- **空间 O(1)**：只用了 `l, r, best, h`（`h` 是中间量）。
- **对比 `bySort`**：`O(n log n)` 时间 + `O(n)` 空间。慢的原因不是多了个 `log` 就完了，而是排序的常数（比较器回调）远大于「一次比较 + 一次乘法」。
- **容量上限的精确计算**：`max area = max(height) × (n-1) = 10⁴ × (10⁵-1) ≈ 10⁹`。`int32` 上界 `2.147·10⁹`，余量约 2.1 倍。**这个余量很薄** —— 如果题目把 `height` 上限改成 `10⁵` 或 `n` 改成 `10⁶`，`int` 立刻溢出。

### 005.6.2 八个真实踩过的坑

1. **容量公式写错** —— 用 `max(h[l],h[r])` 或 `(h[l]+h[r])/2` 当高度。水会从矮边溢出，高度就是 `min`。
2. **移动高的一侧** —— 最容易犯的方向错误。移动高板时，宽度减一、高度不会增加（还是被矮板卡着），**面积必然不增**。等于白白浪费一次机会。
3. **`while (l <= r)`** —— `l == r` 时宽度 0，容量 0，多做一轮无害但说明边界没想清；更糟的是若写成 `l <= r` 且内部又用了 `height[l+1]` 之类会越界。
4. **提前 `break`** —— 有人认为「面积开始下降就可以停」。**错**：宽度单调减、高度是锯齿状变化，面积可以「降 → 升 → 降」。用例 `[1,100,1,1,1,100,1]` 就会让「一见下降就停」的写法返回 100 而不是 600。
5. **`best` 初始化为 `-1` 再除以什么** —— 全 0 数组时 `best` 应为 0。用 0 初始化最省事。
6. **`int` 溢出** —— 本题安全，但把 `height` 上限当 `10⁵` 处理（或做 LC 407 的二维版本）就会溢出。习惯上可以用 `long area = (long) h * (r - l)`，零成本。
7. **以为「必须让两根板都尽量高」** —— 这是把「高」和「宽」的权衡丢了。反例 `[40,100,100,40,40,40,40]`：最高的两根在下标 1、2，容量 `100×1 = 100`；而两端 `min(40,40)×6 = 240`。**只盯高度的写法会返回 100。**
8. **想在 O(n) 里同时保留「次优解」** —— 双指针每次只保留一个 `best`，天然拿不到 Top-2。若题目改成「第二大的容量」，这套淘汰法会**跳过**某些次优候选，必须换思路（维护候选集合或堆）。

### 005.6.3 面试官最爱追问的三个问题

**Q1：为什么移动矮的那一端是安全的？给我一个严格的理由。**
> 「设 `h[l] < h[r]`。对任意 `k ∈ (l, r]`：
> `area(l,k) = min(h[l],h[k])·(k-l) <= h[l]·(k-l) <= h[l]·(r-l) = area(l,r)`。
> 两步不等式的依据分别是 `min <= h[l]` 和 `k <= r`。所以「以 `l` 为左板」的所有候选里，最右端 `(l,r)` 已经是最大。既然它已经算过了，`l` 这一整排就可以作废。**注意这不是「贪心地认为矮板没用」，而是「证明以它为端点的最优值已经被取到了」。**」

**Q2：两端高度相等时，移动哪一边？会不会漏解？**
> 「两边都安全，不会漏。因为 `h[l] == h[r]` 时 `min` 无论以谁为准都等于对方的高度，上文的不等式对两侧同时成立。工程上习惯写 `<=` 移动左端，行为确定、便于复现。有人会想『相等时两边各试一次』，那是 O(n²) 的思路，没有必要。」

**Q3：如果容量公式改成 `(h[i] + h[j]) × (j - i)`，你的算法还对吗？**
> 「不对了。原公式里高度被 `min` 卡死，所以矮板是唯一的瓶颈；新公式里两根板都贡献高度，移动矮板的时候，另一根更高反而更有利，『淘汰矮板』的支配不等式
> `min(h[l],h[k])·(k-l) <= h[l]·(r-l)` 就变成了 `(h[l]+h[k])·(k-l) <= (h[l]+h[r])·(r-l)`，**这一步推不出来**（`k` 变小时宽度损失不一定小于高度增益）。
> 新公式要枚举 `max(h[i] - i)`、`max(h[i] + i)` 这类前缀极值再组合，或者用单调栈。**这道追问考的是「你知不知道自己的论证依赖哪一条性质」。**」

## 附：本章小结（可背走的三句话）

```
① 从最宽处出发，宽度只会变小 → 唯一翻盘机会是「高度变大」
② 高度被矮板卡死 → 矮板对任何未来配对都不再有用 → 淘汰它（有不等式为证）
③ 求最大值不能提前 break：面积会「降→升→降」，必须扫完
```
