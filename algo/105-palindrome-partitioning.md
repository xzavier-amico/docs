## 105.1 题目

**原题链接**：<https://leetcode.cn/problems/palindrome-partitioning/>

### 题意重述（把隐含条件补齐）

给你一个字符串 `s`，请将它分割成若干**回文子串**，返回 `s` 的所有可能分割方案。要求：

- 分割必须**恰好覆盖**整个字符串：从下标 0 切到 `n-1`，不漏字符、不重叠、不跳跃；
- 每一段都必须是**回文**（正着读反着读一样，单字符与空串也算回文，本题不产生空段）；
- 解集顺序任意，但不同方案不能重复。

一句话：「在字符串的 `n-1` 个空隙里选择性地切刀，使每一段都是回文，列出所有切法」。

五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **必须整段覆盖** | 「将 `s` 分割成一些子串」 | 少切一段（丢字符）或多切（跳过字符）都会得到非法方案；这由「下一层从 `i+1` 开始」结构保证 |
| **每段都要回文** | 「每个子串都是回文串」 | 只判首尾字符相同 → 输出非回文段（如 `"ab"`） |
| **解是「分割方案」不是「段数」** | 「返回 `s` 的所有可能分割方案」 | 只返回最少切数（那是 LC 132）→ WA |
| **`n ≤ 16`** | 约束 | 最大可能方案数 `2^(n-1) = 32768`，指数枚举可接受 |
| **只含小写英文字母** | 约束 | 可以按 `byte` 索引，不必担心 UTF-8 多字节（若含中文则必须转 `[]rune`） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length <= 16` | n 至多 16 | 最多 `2^15 = 32768` 个方案（全相同字符时达到）。本机实测 `s = "a"×16`：**Go ≈ 13.5 ms**（预处理版），解数 `32768` 与 `2^15` 吻合 |
| 切法总数 | `2^(n-1)` | `n-1` 个空隙，每个「切/不切」→ 正好 `2^(n-1)` 种切法。这就是搜索树上界 |
| 回文判断的代价 | 朴素 `O(len)` | 若每个结点都现算，总代价 `O(n·2^n)`；预处理后降到 `O(2^n)`（差 16 倍） |
| 输出规模 | `O(n·方案数)` | `n=16` 全相同时输出 32768 个方案、总字符数约 32 万，输出本身是主要开销 |

> 💡 **量级反推**：`n ≤ 16` 与「方案数 `2^(n-1)`」一起说明：**这题的复杂度下界由输出决定，优化空间只在「每个结点做多少事」**。所以真正的考点是「**回文判断能不能 O(1)**」，而不是「回溯怎么写」。

### 示例

```text
输入：s = "aab"
输出：[["a","a","b"],["aa","b"]]
解释："aab" 有两种切法：a|a|b 与 aa|b；而 "aa|b" 里的 "aa" 是回文。
      注意 ["a","ab"] 非法（"ab" 不是回文）。

输入：s = "a"
输出：[["a"]]

输入：s = "aba"
输出：[["a","b","a"],["aba"]]          ← 自造，两个方案

输入：s = "abc"
输出：[["a","b","c"]]                  ← 自造，只有一种（单字符都是回文）
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① "a"            → 1 个方案 [["a"]]，检验「start == n 收集」在 n=1 时成立
② "aa"           → 2 个方案：[a,a] 与 [aa]
③ "aaa"          → 4 个方案：a|a|a、a|aa、aa|a、aaa —— 正好 2^(3-1)
④ "ab"           → 1 个方案：a|b（"ab" 不是回文，所以不能整段）
⑤ "aab"          → 2 个方案 —— 官方样例
```

第 ③ 条是最有用的自检：**全相同字符时方案数必须是 `2^(n-1)`**。数不对就说明「漏切」或「多算」了某类切法。

## 105.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 —— 枚举所有切法，再逐段验证

`n-1` 个空隙，每个空隙「切」或「不切」，于是 `2^(n-1)` 种切法：

```text
for mask in 0 .. 2^(n-1)-1:
    按 mask 切分 s 得到若干段
    逐段判断是否回文（两指针向中间收，O(len)）
    全回文 → 收集
```

- 时间 `O(2^(n-1) · n)`（每段判断加起来最多 `O(n)`）；
- 空间 `O(n)`。
- **它是正确的**，而且 `n = 16` 时 `32768 × 16 ≈ 52 万` 次操作，确实能过。

那么它错在哪？

| 问题 | 具体说明 |
| --- | --- |
| **它枚举了「必然非法」的切法** | 例如 `"aab"` 上，切法 `a|a|b` 与 `aa|b` 合法；而 `a|ab`、`aab` 一进去就该被否掉。位掩码做不到「切到一半发现这段不是回文就停」，只能切完再验 |
| **它丢失了「前缀」结构** | 切分的合法性是**逐段可判**的：前 k 段都合法，才有可能继续。位掩码没有中间状态，无法剪枝 |
| **回文判断被重复计算** | 同一个子串 `s[0..1]` 会在许多切法里被反复判断。这是最容易被忽略的浪费 |

### 第二步：把「枚举切法」换成「逐段决定」

切分问题天然是**顺序决策**：先决定第一段切到哪，再决定第二段从哪切到哪，依次到底。于是它对应一棵「切分树」：

```text
结点 = (start, 已切出的段)
边   = 「切出 s[start..i] 这一段」（i 从 start 取到 n-1）
叶子 = start == n（整串恰好覆盖完）
```

这就是本章要引入的**第三种决策树**（前两种是 096 的集合型、101 的序列型）。它和定义 B（起点递增）几乎同构，唯一差别是：

| 维度 | 集合型（096/098） | 切分型（105） |
| --- | --- | --- |
| 边意味着 | 「选元素 `nums[i]`」 | 「切出**一段** `s[start..i]`，长度可变」 |
| 收集条件 | 每个结点（子集）/ `len == k` | **只有 `start == n`**（整串必须切完） |
| 剪枝 | 剩余数量 / 和值 | **本段必须是回文**（`pal[start][i]`） |
| 下一层起点 | `i + 1` | `i + 1`（同） |

### 第三步：卡点 —— 回文判断放在哪里、做几次

如果在 `for` 循环里现算 `isPal(s, start, i)`：

```text
结点数 × 每结点 O(n) 次回文检查 × 每次 O(n) 字符比较
= O(2^n) × O(n) = O(n·2^n)       （n = 16 时约 50 万次字符比较）
```

**这正是「第一个念头」那一行的浪费点：回文判断是 `O(n)` 的，而它会被调用指数次。**

改造的方向只有一个：**把回文判断从 `O(n)` 降成 `O(1)`**。而「子串 `s[i..j]` 是否回文」这个量满足**区间递推**：

```text
pal[i][j] = (s[i] == s[j]) && (j - i < 2 || pal[i+1][j-1])
```

含义：`s[i..j]` 回文 ⟺ 首尾字符相同，且「去掉首尾」后的子串也回文。这就是区间 DP 的经典形态（与 [`131` 最长回文子序列] 同源）。

### 第四步：预处理为什么能降到 O(1)，代价是什么

| 项 | 不做预处理 | 做预处理 |
| --- | --- | --- |
| 预处理时间 | 0 | `O(n²)` |
| 每次回文判断 | `O(n)`（最坏要比较 `n/2` 对字符） | **`O(1)`**（一次二维数组查表） |
| 回溯中的判断总次数 | `O(2^n)` 次（每个结点 ≤ `n` 条边） | 同 |
| 回溯总时间 | `O(n·2^n)` | **`O(2^n)`** |
| 额外空间 | 0 | `O(n²)` 的布尔表（`n=16` 时 256 个格子，可忽略） |

**为什么这一步划算**：把「每层每边一次线性扫描」换成「一次性把整张表算好」。因为**所有可能被问到的子串只有 `O(n²)` 个**（区间数 `n(n+1)/2`），而回溯会反复问其中一些。**用 `O(n²)` 的一次性代价，换掉指数次的重复工作——这就是预处理的价值。**

**填表顺序的讲究**：递推式用到 `pal[i+1][j-1]`（下一行、左一列），所以必须让 `i` **从大到小**遍历、`j` 从小到大。写反了就会用到还没算的格子，得到全 `false`。

## 105.3 原理拆解

### 105.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举 `2^(n-1)` 种切法 + 逐段判回文 | `O(n·2^(n-1))` | `O(n)` | 25 行 | 无法剪枝；每段回文反复重算；`n` 稍大就成瓶颈 |
| 回溯 + 每次现算回文 | `O(n·2^n)` | `O(n)` | 15 行 | 回文判断线性，`n` 大时浪费明显 |
| **回溯 + `pal[][]` 预处理** ✅ | `O(n² + n·方案数)` | `O(n²)` 表 + `O(n)` 栈 | **22 行** | 需要在回溯前跑一遍 DP；`s` 极大（`10^4`）时表会占 `10^8` 空间 |
| 回溯 + 中心扩展预处理 | `O(n²)` 预处理，同上一行 | `O(n²)` | 26 行 | 常数略小但代码更长；本质与 DP 等价 |
| 回溯 + Manacher 预处理 | `O(n)` 预处理 | `O(n)` | 45 行 | 本题 `n ≤ 16` 完全不值；Manacher 只在长串上划算 |
| DP 求**最少切数**（LC 132） | `O(n²)` | `O(n)` | 20 行 | **给不出所有方案**，只能给一个数 |

**为什么选「回溯 + `pal[][]`」**：题目要的是**所有方案**，所以必须有回溯；而回溯的性能上限由「每个结点的判断代价」决定，`pal[][]` 把它压到 `O(1)`。这是本部分「回溯 + 预处理」这一组合的标准形态。

### 105.3.2 为什么这个做法是对的（正确性论证）

**引理 1（切分树 ↔ 分割方案，双射）**

> 证明：
> **（单射）** 每条从根到叶子的路径，记录了「依次切出的段」，这些段首尾相接、恰好覆盖 `s[0..n-1]`（因为每次递归传 `i+1`，下一段从上一段的末尾之后开始；且 `start == n` 时才收集），所以它唯一确定一个分割方案。
> **（满射）** 给定任一合法分割方案 `s[p₀..p₁-1], s[p₁..p₂-1], …, s[p_{k-1}..n-1]`（`p₀ = 0`），按 `i = p₁-1, p₂-1, …` 依次取边即可走出一条路径；由于每段都是回文，每条边都通过 `pal[start][i]` 检查，因此这条路径不被剪掉。∎

**引理 2（剪枝只剪非法段）**：`pal[start][i] == false` 时跳过该边，不会丢掉任何解。

> 证明：该边代表「把 `s[start..i]` 作为下一段」。若它不是回文，则任何包含这一段的方案都不合法，因此该整棵子树里没有解。∎

**引理 3（收集时机正确）**：`start == n` 时收集，此时 `path` 中的段恰好是一个完整方案。

> 证明：由 `start` 的定义（下一段的起点），`start == n` 表示所有字符都已被覆盖；`path` 里每一段都通过了回文检查。∎

**引理 4（`pal[][]` 递推正确）**：按「`i` 从 `n-1` 到 `0`、`j` 从 `i` 到 `n-1`」的顺序填表，`pal[i][j]` 的值正确。

> 归纳证明：基例 `j - i < 2`（长度 1 或 2）。长度 1 时 `s[i] == s[i]` 恒真 → `pal = true`；长度 2 时 `pal = (s[i] == s[j])`，与回文定义一致。
> 归纳：长度 `≥ 3` 时，`pal[i][j] = (s[i]==s[j]) && pal[i+1][j-1]`。由遍历顺序，`i+1 > i` 且区间长度 `j-1-(i+1)+1 = j-i-1 < j-i+1`，所以 `pal[i+1][j-1]` 已在更早（`i` 更大）的轮次中算好。而「`s[i..j]` 回文 ⟺ 首尾相同且 `s[i+1..j-1]` 回文」是回文定义的直接等价改写。∎

**定理**：回溯输出恰好是所有合法分割方案，每个一次。∎

> **可迁移的一句话**：**「解的每一步都可以用一个局部谓词判定」的问题，都可以用「预处理出全部局部谓词」把单步判断降到 `O(1)`。** 104 的三方向数组是同一思想的另一种形态（谓词是「这条线被占了吗」，用布尔数组存）。

### 105.3.3 通用解题思路（可迁移的那一层）：切分树 + 预处理

```text
┌──────────── 切分型决策树的标准骨架 ────────────┐
│                                              │
│  dfs(start):                                 │
│    if (start == n) { 收集; return; }          │  ← 只有「切完」才是解
│    for (i = start; i < n; i++) {             │  ← 边：切出 s[start..i]
│        if (!pal[start][i]) continue;         │  ← ② 剪枝：本段必须合法
│        path.add(s[start..i]);                │  ← ③(a)
│        dfs(i + 1);                           │  ←     下一段从 i+1 开始
│        path.removeLast();                    │  ← ③(b)
│    }                                         │
│                                              │
│  预处理：pal[i][j] ← 区间 DP，O(n²)            │
│  为什么：把每层每边的 O(n) 判断降到 O(1)        │
└──────────────────────────────────────────────┘
```

**切分型的三个识别特征**（只要命中两个，就该套这个骨架）：

1. 解是「把一段序列**完整切**成若干块」；
2. 每块是否合法**只看块自己**（不看块的组合）；
3. 收集发生在「切到末尾」。

属于「切分型」这个模型的题：

| 题 | 每段的合法性谓词 | 预处理/优化 |
| --- | --- | --- |
| [LC 131 分割回文串](https://leetcode.cn/problems/palindrome-partitioning/) | 是回文 | `pal[][]` 区间 DP，`O(n²)` |
| [LC 93 复原 IP 地址](https://leetcode.cn/problems/restore-ip-addresses/) | 三部分：非空、无前导零、`0..255` | 无需预处理，`O(1)` 直接判 |
| [LC 140 单词拆分 II](https://leetcode.cn/problems/word-break-ii/) | 是字典里的词 | 单词集合 `HashSet`，`O(len)` 哈希 |
| [LC 472 连接词](https://leetcode.cn/problems/concatenated-words/) | 是「其他词的拼接」 | 复用「单词拆分」的 DP 判定 |
| [LC 282 给表达式添加运算符](https://leetcode.cn/problems/expression-add-operators/) | 数字段无前导零（符号由本层选择） | 边同时选「符号」与「数字段」 |
| [LC 1593 拆分字符串使唯一子字符串的数目最大](https://leetcode.cn/problems/split-a-string-into-the-max-number-of-unique-substrings/) | 段在集合中未出现过 | `HashSet` + 记忆化剪枝 |

### 105.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**最少切数** | 最优化 | LC 132：`dp[i] = min(dp[j] + 1)` over 回文 `s[j..i-1]`，`O(n²)`；或用「两次 DP」把回文表与切数表结合 |
| 只要**方案数** | 计数 | `f[i] = Σ_{j: pal[j][i-1]} f[j]`，`O(n²)`；不要枚举 |
| 要求**每段长度 ≥ 2** | 约束变化 | 在 `if (!pal[start][i])` 后加 `if (i == start) continue;` |
| 要求**字典序最小的方案** | 只要一个 | 贪心/DFS 返回首个找到的答案即可（因为按 `i` 升序展开，天然字典序） |
| `n` 涨到 `2000` | `O(n²)` 表变成 400 万格，可行但输出爆炸 | 只求最小切数或方案数；要输出方案时必须接受指数级输出 |
| `s` 含多字节字符 | 编码问题 | 先转 `[]rune`，所有下标按 rune 计；Go 里尤其要注意 `s[i]` 是 byte |

## 105.4 图解推演

### 105.4.1 `s = "aab"` 的切分树

```text
                        dfs(start=0, path=[])
        ┌──────────────────┬──────────────────┬──────────────────┐
  切 "a" (i=0)        切 "aa" (i=1)      切 "aab" (i=2)
   pal[0][0]=T         pal[0][1]=T        pal[0][2]=F ⊘ 剪枝
        │                   │                （"aab" 不是回文）
        ▼                   ▼
  dfs(1, ["a"])       dfs(2, ["aa"])
   ┌────────┴───────┐        │
 切"a"(i=1)   切"ab"(i=2)  切"b"(i=2)
  pal=T       pal[1][2]=F⊘  pal[2][2]=T
   │                            │
   ▼                            ▼
dfs(2,["a","a"])         dfs(3,["aa","b"]) ★
   │                       → 方案 ["aa","b"]
 切"b"(i=2) pal=T
   │
   ▼
dfs(3,["a","a","b"]) ★
   → 方案 ["a","a","b"]

★ 收集点：start == n == 3，共 2 个方案
⊘ 剪枝 2 处：都是「这一段不是回文」
```

**读图要点**：树上有 3 条边从根出发，但只有 2 条活下来；`pal[0][2]` 为假，所以「整串不切」这一支被剪。这说明**剪枝发生在「切出这一段」的那一刻**，而不是等到切完再验。

### 105.4.2 回文表的填表过程（`s = "aab"`）

按 `i` 从大到小、`j` 从小到大填：

| 填的顺序 | `i` | `j` | `s[i]` vs `s[j]` | 用到 `pal[i+1][j-1]` | `pal[i][j]` |
| --- | --- | --- | --- | --- | --- |
| 1 | 2 | 2 | `b == b` | 长度 1，基例 | **T** |
| 2 | 1 | 1 | `a == a` | 长度 1，基例 | **T** |
| 3 | 1 | 2 | `a != b` | 不用算 | **F** |
| 4 | 0 | 0 | `a == a` | 长度 1，基例 | **T** |
| 5 | 0 | 1 | `a == a` | 长度 2，基例 | **T** |
| 6 | 0 | 2 | `a != b` | 不用算 | **F** |

最终表（行 = `i`，列 = `j`）：

```text
        j=0    j=1    j=2
  i=0    T      T      F        ← pal[0][1]=T（"aa" 回文） 是仅有的「长回文」
  i=1    —      T      F
  i=2    —      —      T
```

回看决策树：`dfs(0)` 的三条边分别查 `pal[0][0]=T`、`pal[0][1]=T`、`pal[0][2]=F` —— 与树上的 ⊘ 完全对应。

### 105.4.3 预处理前后的判断代价对照（`n = 16`，全相同字符）

| 指标 | 现算回文 | 预处理 + 查表 |
| --- | --- | --- |
| 预处理 | 0 | `16²/2 = 136` 次格子计算 |
| 回溯结点数 | 65535 | 65535（同） |
| `isPal` 被调用次数（实测） | **65,535** | 0（改成查表） |
| 字符比较总次数（实测） | **109,217** | **0**（表已算好） |
| 端到端耗时（本机 Go，`"a"×16`，各跑一次并预热） | **16.6 ms** | **13.5 ms** |
| 解数 | 32,768 | 32,768（一致） |

**怎么读这张表**：字符比较次数从 **10 万** 降到 **0**（这正是「`O(n)` 判断 → `O(1)` 查表」的直接体现）；但端到端只快约 20%，因为剩下 13.5 ms 主要花在「拼字符串与拷贝结果切片」上——**输出 32768 个方案本身就是大头**。所以：**复杂度上的改善是实打实的（省一个 `n` 因子），而工程上的收益取决于「判断」在总耗时里的占比**。面试里要把这两件事分开说，含糊地说「快 16 倍」是不诚实的。

## 105.5 双语言实现

### 105.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<List<String>> partition(String s) {
        int n = s.length();

        // 预处理：pal[i][j] = s[i..j] 是否回文，O(n^2)
        // 为什么要预处理：回溯里每条边都要判一次回文，而可能的区间只有 O(n^2) 个
        boolean[][] pal = new boolean[n][n];
        for (int i = n - 1; i >= 0; i--) {          // i 必须从大到小：用到 pal[i+1][j-1]
            for (int j = i; j < n; j++) {           // j 从小到大
                // 首尾相同 + （长度 < 2 或 去掉首尾后仍回文）
                if (s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1])) {
                    pal[i][j] = true;
                }
            }
        }

        List<List<String>> res = new ArrayList<>();
        List<String> path = new ArrayList<>();
        dfs(s, 0, n, pal, path, res);
        return res;
    }

    /** start = 下一段的起点；切分树的全部状态就是它 */
    private void dfs(String s, int start, int n, boolean[][] pal, List<String> path, List<List<String>> res) {
        if (start == n) {                  // 整串都切完了 → 这是一个完整方案
            res.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < n; i++) {  // 边：切出 s[start..i]
            if (!pal[start][i]) {
                continue;                  // ② 剪枝：这一段不是回文，整支不可能有解
            }
            path.add(s.substring(start, i + 1));   // ③(a) 选择：注意 substring 是左闭右开
            dfs(s, i + 1, n, pal, path, res);      //     下一段从 i+1 开始（不重不漏）
            path.remove(path.size() - 1);          // ③(b) 撤销
        }
    }
}
```

### 105.5.2 Go

```go
package main

func partition(s string) [][]string {
	n := len(s)

	// 预处理：pal[i][j] = s[i..j] 是否回文
	// 题目保证只含小写字母，所以按 byte 索引安全（若含中文必须先转 []rune）
	pal := make([][]bool, n)
	for i := range pal {
		pal[i] = make([]bool, n)
	}
	for i := n - 1; i >= 0; i-- { // i 从大到小：递推用到 pal[i+1][j-1]
		for j := i; j < n; j++ {
			if s[i] == s[j] && (j-i < 2 || pal[i+1][j-1]) {
				pal[i][j] = true
			}
		}
	}

	res := make([][]string, 0)
	path := make([]string, 0, n)

	var dfs func(start int)
	dfs = func(start int) {
		if start == n { // 切完了 → 收集
			// 深拷贝：path 还会被其它分支改写
			res = append(res, append([]string(nil), path...))
			return
		}
		for i := start; i < n; i++ {
			if !pal[start][i] {
				continue // ② 这一段不是回文
			}
			path = append(path, s[start:i+1]) // ③(a) 选择：Go 的切片是左闭右开
			dfs(i + 1)                        //     下一段从 i+1 开始
			path = path[:len(path)-1]         // ③(b) 撤销
		}
	}
	dfs(0)
	return res
}
```

### 105.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 截取子串 | `s.substring(start, i+1)`（左闭右开） | `s[start:i+1]`（左闭右开） | 两边语义一致；**都容易写成 `i` 而不是 `i+1`**，那样会少一个字符 |
| 子串是否拷贝 | `substring` 在 Java 7+ **复制**字符数组 | Go 的 `s[a:b]` **共享**底层数组（字符串不可变，所以安全） | Go 里子串与原串共享内存，但因为字符串不可变，不会互相污染 —— 这是 Go 少数「切片别名无害」的场景 |
| 字符访问 | `s.charAt(i)` 返回 `char`（UTF-16） | `s[i]` 返回 `byte` | 本题只含小写字母，两者等价；含中文时 Go 必须转 `[]rune` |
| 二维表 | `boolean[n][n]` | `make([][]bool, n)` 再逐行 `make` | Go 的二维切片要手动初始化每一行，否则 `panic` |
| 结果里的 `path` | `new ArrayList<>(path)` | `append([]string(nil), path...)` | **都必须深拷贝**（§105.5.3 下方实测） |

#### ⚠️ Go 切片别名：本章的实测反例

本章的 `path` 是 `[]string`，与整型切片一样受别名影响。我实测 `s = "aab"`：

```text
不加拷贝（错误）  res = append(res, path)
  s="aab"  →  [[aa b b] [aa b]]
               ↑ 第一个方案本该是 [a a b]，被就地覆盖成 [aa b b]（长度和内容都脏）
  s="aba"  →  [[aba b a] [aba]]
  s="aaaa" →  [[aaaa a a a] [aaaa a a] [aaaa a a] [aaaa a] ...]   ← 8 个方案全脏

加拷贝（正确）  res = append(res, append([]string(nil), path...))
  s="aab"  →  [[a a b] [aa b]]        ✓
  s="aba"  →  [[a b a] [aba]]         ✓
  s="aaaa" →  [[a a a a] [a a aa] [a aa a] [a aaa] [aa a a] [aa aa] [aaa a] [aaaa]]   ✓

s = "a"（只有 1 个方案）
  不加拷贝：[["a"]]     ← 与正确结果一致，纯侥幸
```

**注意：本题的「子串」本身不会污染**（Go 字符串不可变，`s[a:b]` 共享底层数组也只读）。**要拷的只有 `path` 这个 `[]string` 切片头**——这两件事必须分清，否则容易误以为「既然子串共享内存，那整条路径也得拷贝子串」，那是不必要的。

```go
// 写法 1（推荐）：深拷贝切片头
res = append(res, append([]string(nil), path...))

// 写法 2：三下标截断，让「存进去那份」的 cap == len
//   挡不住 path 自己（cap > len 的头）往后写 —— 本章实测仍会污染
res = append(res, path[:len(path):len(path)])
```

### 105.5.4 对拍测试（写完必须跑）

参考实现用**「枚举全部 `2^(n-1)` 种切法 + 独立的两指针回文判断」**，与「切分树 + DP 预处理」完全独立。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 独立的两指针回文判断（不复用 pal 表）
func isPal(s string, i, j int) bool {
	for i < j {
		if s[i] != s[j] {
			return false
		}
		i++
		j--
	}
	return true
}

// 参考实现：位掩码枚举 2^(n-1) 种切法
func brutePartition(s string) [][]string {
	n := len(s)
	out := [][]string{}
	if n == 0 {
		return out
	}
	for mask := 0; mask < 1<<(n-1); mask++ {
		cur := []string{}
		start := 0
		ok := true
		for k := 0; k < n-1; k++ {
			if mask>>k&1 == 1 { // 在第 k 个空隙切一刀
				if !isPal(s, start, k) {
					ok = false
					break
				}
				cur = append(cur, s[start:k+1])
				start = k + 1
			}
		}
		if !ok {
			continue
		}
		if !isPal(s, start, n-1) {
			continue
		}
		cur = append(cur, s[start:n])
		out = append(out, cur)
	}
	return out
}

func normPart(res [][]string) [][]string {
	out := make([][]string, len(res))
	for i, r := range res {
		out[i] = append([]string(nil), r...)
	}
	sort.Slice(out, func(a, b int) bool {
		x, y := out[a], out[b]
		for k := 0; k < len(x) && k < len(y); k++ {
			if x[k] != y[k] {
				return x[k] < y[k]
			}
		}
		return len(x) < len(y)
	})
	return out
}

func eqStrs(a, b [][]string) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if len(a[i]) != len(b[i]) {
			return false
		}
		for k := range a[i] {
			if a[i][k] != b[i][k] {
				return false
			}
		}
	}
	return true
}

func TestPartitionRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026105))
	for iter := 0; iter < 4000; iter++ {
		n := 1 + r.Intn(12)
		b := make([]byte, n)
		for i := range b {
			b[i] = byte('a' + r.Intn(3)) // 只有 3 种字符 → 回文密集
		}
		s := string(b)
		got := normPart(partition(s))
		want := normPart(brutePartition(s))
		if !eqStrs(got, want) {
			t.Fatalf("iter=%d s=%q got=%v want=%v", iter, s, got, want)
		}
		// 额外校验：每个方案都必须真的切分整串且每段回文
		for _, plan := range got {
			join := ""
			for _, seg := range plan {
				if len(seg) == 0 || !isPal(seg, 0, len(seg)-1) {
					t.Fatalf("iter=%d s=%q 非法段 %q", iter, s, seg)
				}
				join += seg
			}
			if join != s {
				t.Fatalf("iter=%d s=%q 方案未完整覆盖: %v", iter, s, plan)
			}
		}
	}
}

func TestPartitionEdges(t *testing.T) {
	if got := len(partition("a")); got != 1 {
		t.Fatalf("a 得 %d 个", got)
	}
	if got := len(partition("aa")); got != 2 {
		t.Fatalf("aa 得 %d 个", got)
	}
	if got := len(partition("aaa")); got != 4 {
		t.Fatalf("aaa 得 %d 个", got)
	}
	if got := len(partition("ab")); got != 1 {
		t.Fatalf("ab 得 %d 个", got)
	}
	if got := len(partition("aab")); got != 2 {
		t.Fatalf("aab 得 %d 个", got)
	}
	// 全相同 n=16 → 2^15 个方案（上界）
	if got := len(partition("aaaaaaaaaaaaaaaa")); got != 1<<15 {
		t.Fatalf("a*16 得 %d 个，期望 %d", got, 1<<15)
	}
}
```

## 105.6 复杂度与常见坑

### 105.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(n² + n · 方案数)`，最坏 `O(n·2^(n-1))`。**

1. **预处理**：填 `n(n+1)/2` 个格子，每格 `O(1)` → `O(n²)`。
2. **回溯的结点数**：切分树的结点对应「若干段的拼接」，节点数不超过 `2^(n-1)`（`n-1` 个空隙各有切/不切两种，且每个结点对应一种「前缀切法」）。
3. **每个收集点的工作量**：拷贝 `path`，长度 ≤ `n` → `O(n)`。
4. **每次回文判断**：`O(1)`（查表）。

总计 `O(n² + n·方案数)`。全相同字符时方案数 `= 2^(n-1)`，退化为 `O(n·2^(n-1))`。

**空间**：预处理表 `O(n²)`，递归栈与 `path` 各 `O(n)` → `O(n²)`（不含输出）。输出 `O(n·方案数)`。

**与「现算回文」的对比**：把第 4 步从 `O(n)` 降到 `O(1)`，总复杂度从 `O(n²·2^(n-1))` 降到 `O(n·2^(n-1))` —— **省掉一个 `n` 因子**。`n=16` 时约 16 倍的理论差距（实测因常数原因约 2 倍，见 §105.4.3）。

### 105.6.2 七个真实踩过的坑

1. **`pal` 的填表顺序反了**（`i` 从小到大）—— 用到 `pal[i+1][j-1]` 时那个格子还是默认 `false`，整张表几乎全假，输出为空或少得离谱。**必须 `i` 从大到小。**
2. **基例写成 `j - i < 1`** —— 长度 2 的回文（如 `"aa"`）被漏判，`"aab"` 会少一个方案。正确是 `j - i < 2`。
3. **`substring(start, i+1)` 写成 `substring(start, i)`** —— 每段少一个字符，`join` 后不等于原串。Go 里对应 `s[start:i]` 也犯同样的错。
4. **收集条件写成 `start >= n - 1`** —— 会漏掉最后一段（最后一个字符还没被切出来）。必须 `start == n`。
5. **递归传 `start + 1` 而不是 `i + 1`** —— 每层只前进一个字符，「整段不切」的边消失，`["aa","b"]` 这类方案全丢。
6. **用 `isPal` 现算但不做任何缓存** —— 结果正确但慢；`n` 稍大（如 20+）时明显。题目 `n ≤ 16` 能过，但面试官追问「`n = 100` 怎么办」时要答得上预处理。
7. **Go 里 `res = append(res, path)`** —— 所有方案互相污染（§105.5.3 实测），而 `s = "a"` 永远测不出来。

### 105.6.3 面试官最爱追问的三个问题

**Q1：为什么预处理能把 `O(n)` 的判断降到 `O(1)`？**
> 「因为『子串是否回文』这个量只有 `O(n²)` 种可能（区间数 `n(n+1)/2`），而且它满足**区间递推**：`pal[i][j] = (s[i]==s[j]) && pal[i+1][j-1]`。于是可以 `O(n²)` 一次性把所有可能的询问都算好，之后每次判断退化成一次二维数组查表。这等价于「用空间换时间，但换的方向是『把指数次重复询问压成一次预处理』」。**如果谓词不满足递推（比如『这段是不是字典里的词』），就用哈希集合做 `O(len)` 判断，或对多串建 01-Trie。**

**Q2：能不能用记忆化搜索代替回溯？**
> 「可以求**方案数**或**最少切数**：`f(start) = Σ_{i: pal[start][i]} f(i+1)`，`O(n²)` 状态、`O(n)` 转移。但**要输出所有方案**时记忆化帮不上忙——不同方案的前缀不同，缓存 `start` 只能存「方案条数」，不能存「方案列表」（存了就是指数级内存）。所以「列方案」必须回溯；记忆化只适合「数方案 / 求最优」。

**Q3：如果字符串里有中文，你的代码还能跑吗？**
> 「不能直接用 `s[i]`。Go 里 `s[i]` 是**字节**，一个中文字符占 3 个字节，按字节切会产生非法 UTF-8；Java 里 `charAt` 是 UTF-16 单元，BMP 之外的字（如 emoji）占两个单元，也会切坏。正确做法是先 `[]rune(s)` / `s.toCharArray()` 转成码点数组，所有下标按码点计算，最后再拼回字符串。**这道题明确只含小写字母，所以按 byte/char 处理是安全的；但面试里被问到就必须能说出这个区别。**」

## 附：本章小结（可背走的三句话）

```text
① 切分树：结点 = start，边 = 切出 s[start..i]，收集在 start == n
② 回文预处理：pal[i][j] = s[i]==s[j] && (j-i<2 || pal[i+1][j-1])，i 必须从大到小填
③ 预处理把「每条边一次 O(n) 判断」压成 O(1) 查表，总复杂度省掉一个 n 因子
```
