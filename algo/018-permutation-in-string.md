## 018.1 题目

**原题链接**：<https://leetcode.cn/problems/permutation-in-string/>

### 题意重述（把隐含条件补齐）

给你两个字符串 `s1` 和 `s2`，判断 **`s2` 是否包含 `s1` 的某个排列**。换句话说：是否存在 `s1` 的一个排列，它是 `s2` 的**子串**。返回 `true` / `false`。

注意参数顺序：**`s1` 是短的、被排列的那个（模式串），`s2` 是长的、被搜索的那个（文本）**。写下标时经常写反，`017` 的顺序恰好相反（`(s, p)`），这两章要对照着记。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **「排列」= 多重集重排** | 排列的定义 | 你理解成「某种循环移位」→ 只检查循环移位会漏解（`s1="ab"`, `s2="xba"` 中 `"ba"` 是排列但不是移位） |
| **子串必须连续** | 「`s2` 的子串」 | 按子序列做 → 完全另一道题，答案偏大 |
| **`s2` 可能比 `s1` 短** | 约束里两者长度互相独立 | 不先检查 `len(s2) < len(s1)`，初始化循环访问 `s2[i]`（`i` 可到 `m-1 ≥ n`）就会越界 |
| **模式串可能有重复字符** | 一般性 | 用 `set` 去重 → `s1 = "aa"` 会把 `"a"` 判成合法 |
| **`s1`、`s2` 只含小写英文字母** | 约束 | `int[26]` 够用；假设大写会越界 |
| **要返回布尔，不是下标** | 签名 | 返回 `List<Integer>` → 类型错（那是 017） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s1.length, s2.length <= 10⁴` | n、m 最多 1 万 | 枚举 `s1` 的排列是 `m!`（`m = 10⁴` 时是天文数字），**必须走等价类** |
| `s1[i]`、`s2[i]` 是小写英文字母 | 26 个 | 频率向量是 26 维整数向量，可以放进 `int[26]` |
| 只问「是否存在」 | 布尔 | **可以提前返回**，最好情况 O(m)（第一个窗口就命中） |
| n 可能等于 m | 边界 | 只有一个窗口，此时问题退化成「两个串是不是异位词」（LC 242） |

> 💡 量级 → 算法：`m!` 这个数量级说明「枚举排列」在数学上就不可能 —— `m = 10` 就是 362 万，`m = 20` 就是 2.4·10¹⁸。
> 必须找到**把 `m!` 个对象折叠成 1 个代表元**的方法，那就是频率签名。

### 示例

```
输入：s1 = "ab", s2 = "eidbaooo"
输出：true
解释：s2 包含 "ba"，它是 "ab" 的排列。

输入：s1 = "ab", s2 = "eidboaoo"
输出：false
解释：s2 里所有长度为 2 的子串是 "ei","id","db","bo","oa","ao","oo"，没有一个是 "ab" 的排列。

输入：s1 = "adc", s2 = "dcda"
输出：true
解释：子串 "dca"（下标 0..2）与 "cd a" 同频；注意"adc" 本身没出现，但排列出现了。

输入：s1 = "abc", s2 = "ab"
输出：false
解释：s1 比 s2 长，不可能。
```

### 我自造的四个反例（写完必须打一遍）

```text
① s1="abc", s2="ab"     → 长度不足，必须提前返回 false（不是越界）
② s1="aa",  s2="a"      → 长度不足，同上；也检验"不用 set 去重"
③ s1="adc", s2="dcda"   → 排列出现但模式串本身没出现（"dca"）
④ s1="a",   s2="a"      → 最小规模，窗口数 = 1
```

第 ③ 条是本题最典型的思维陷阱：很多人第一反应是「在 `s2` 里找 `s1`」（`indexOf`），而题目要的是「找 `s1` 的任意排列」。`"adc"` 在 `"dcda"` 里确实没出现，但 `"dca"` 出现了。

## 018.2 从暴力到最优：第一个念头为什么错

### 第一步：两个错误的第一反应

**错误一：`s2.indexOf(s1) != -1`。** 这把「找排列」当成了「找原串」。`s1 = "adc"`, `s2 = "dcda"` 会返回 `false`，正确是 `true`。**漏掉了 `m! - 1` 种情况。**

**错误二：枚举 `s1` 的所有排列，逐个在 `s2` 里找。** 复杂度 `O(m! · n · m)` —— `m = 10` 时已经不可算，`m = 10⁴` 时是「宇宙寿命」级别。这条路**在数学上就死了**，不是「慢一点」。

```java
// 错误示范：只对极小规模可行
for (String perm : allPermutations(s1)) {      // m! 个
    if (s2.contains(perm)) return true;        // 每个 O(n·m)
}
```

### 第二步：卡点 —— 「排列」这个集合太大，但它们的**共同点**很小

`m` 个字符的所有排列有 `m!` 个，但它们**全都满足同一个性质**：

```
「是 s1 的某个排列」 ⇔ 「长度 = m 且每种字符出现次数与 s1 相同」
```

这就是**等价类**思想：把 `m!` 个字符串按「频率签名」折叠成 **1 个**等价类，然后用这个等价类去匹配。

于是问题变成：

> 在 `s2` 中，是否存在一个**长度恰好为 `m`** 的窗口，其 26 维频率向量与 `s1` 完全相同？

这一步转化是整道题的**全部智力活动**，剩下的都是工程。

### 第三步：为什么不枚举窗口起点 + 重建频率

那样是 `O(n · m)`。`n = m = 10⁴` 时是 `10⁸`，勉强能过但是不优雅。而且相邻窗口共享 `m-1` 个字符 —— 又是一次可以省掉的重复计算。

用 `017` 的滑动方式：**窗口长度固定为 `m`，每步出队一个、入队一个，O(1) 更新频率差。** 这就是「定长滑窗」的全部内容。

### 第四步：和 017 的关系 —— 同一份代码，两种收尾

把 `017` 的代码抄过来，只改三处：

| | 017 | 018 |
| --- | --- | --- |
| 命中时 | `ans.add(start)`，继续滑 | `return true`，**立即停** |
| 全部窗口都不命中 | `return ans`（空列表） | `return false` |
| 参数语义 | `(s, p)`：`s` 长、`p` 短 | `(s1, s2)`：`s1` 短、`s2` 长 |

**其余每一行都一样**：`diff[26]`、`nonzero`、`bump`、`if (n < m) return ...`、初始窗口的构造。

> 这就是为什么 017 和 018 必须放在一起读：**它们不是「两道相似的题」，而是「一道题的两种输出契约」**。理解了这一点，你在面试里遇到其中任意一道，都能顺手把另一道写出来，还能主动说「这题和 LC438 是同构的」—— 这句话本身就是加分项。

## 018.3 原理拆解

### 018.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| `s2.indexOf(s1)` | O(n·m) | O(1) | 1 行 | **语义就错了**：找的是原串不是排列 |
| 枚举 `s1` 的全部排列再搜 | O(m! · n · m) | O(m!) | 15 行 | `m ≥ 10` 就不可算 |
| 枚举窗口 + 排序后比较 | O(n · m log m) | O(m) | 8 行 | `n = m = 10⁴` 时 10⁹ 级，必挂 |
| 枚举窗口 + 重建 26 计数 | O(n · m) | O(26) | 12 行 | 同上是 O(n·m)，但常数小，`n = m = 10⁴` 时 `10⁸`，临界 |
| **定长滑窗 + `diff` + `nonzero`** ✅ | **O(n + m)** | **O(26)** | **25 行** | 字符集极大时要换 `map`；无其它短板 |
| 变长双指针（窗口内计数不超过 `s1`） | O(n) | O(26) | 18 行 | 正确但更容易写错；见 §018.4.4 |

**为什么「定长滑窗」比「枚举窗口重建计数」快一个数量级**：前者每步只碰 2 个字符，后者每步碰 `m` 个。当 `m` 接近 `n` 时（最坏情况 `m = n/2`），差距是 `n/2` 倍。

### 018.3.2 为什么这个做法是对的（正确性论证）

**引理 1（排列的等价特征）**：字符串 `w` 是 `s1` 的某个排列 ⇔ `|w| = |s1|` 且对每个字符 `c`，`count_w(c) = count_s1(c)`。

*证明*：
- （⇒）排列只是重排，长度与每个字符的出现次数都不变。
- （⇐）若两者的多重集相同，把 `s1` 的字符按 `w` 的顺序重新排列，就得到 `w` 本身（因为相同字符不可区分，多重集相同意味着可以逐字符配对）。∎

**引理 2（问题的等价改写）**：`s2` 包含 `s1` 的某个排列作为子串 ⇔ 存在 `i`，使窗口 `s2[i..i+m-1]` 的频率向量等于 `s1` 的频率向量。

*证明*：`s2[i..i+m-1]` 是一个具体字符串，由引理 1，它是 `s1` 的排列 ⇔ 频率向量相等。而「存在子串是排列」⇔「存在某个 `i` 使该子串是排列」。∎

**引理 3（滑动的正确性）**：初始化后 `diff[c] = count_s1(c) − count_{s2[0..m-1]}(c)`；每步「出窗 +1、入窗 −1」后，`diff` 等于新窗口的真实差值。
*证明*：与 `017` 的引理 2、3 完全一致（新窗口 = 旧窗口 − 出队字符 + 入队字符）。∎

**引理 4**：`nonzero == 0` ⇔ 当前窗口的 26 个计数与 `s1` 完全相同。
*证明*：`nonzero` 定义为 `diff` 中非零格的个数（`bump` 正确维护），所以 `nonzero == 0` ⇔ 所有 `diff[c] == 0` ⇔ 所有 `count` 相等。∎

**定理**：算法返回 `true` ⇔ `s2` 包含 `s1` 的某个排列作为子串。
*证明*：算法逐一检查 `n-m+1` 个窗口，每次 `nonzero == 0` 时返回 `true`。由引理 3、4，`nonzero == 0` ⇔ 该窗口频率等于 `s1` ⇔（引理 2）该窗口是 `s1` 的排列。窗口遍历完整，故充要。∎

> **这道题的证明比 016 短得多，原因很值得记**：因为「长度固定」，不存在「哪个左端点更好」的讨论，**没有最优化就没有最优性证明**。判断题永远比最优化题好证。

### 018.3.3 通用解题思路（可迁移的那一层）

本题是 **「等价类折叠 + 定长滑窗」** 的母题。可迁移的形式：

```
问题：判断"是否存在某个对象的某种重排"出现在序列中
     ↓ 第一步：把"重排"折叠成"频率签名"（等价类思想）
判断"是否存在长度 m 的子串，其签名等于目标的签名"
     ↓ 第二步：签名要能增量维护
定长滑窗，每步一进一出，O(1) 更新
     ↓ 第三步：把"签名相等"压成标量
nonzero == 0
```

**「等价类」是全书四把尺子之一**（见 `0-summary.md` §0）：当题目里出现「某个集合的任意一个」「所有排列」「忽略顺序」这类词，第一反应就该是**找等价类的代表元**。这里代表元是 26 维频率向量；在 [LC 49 字母异位词分组](https://leetcode.cn/problems/group-anagrams/) 里是排序后的字符串；在 [LC 249 移位字符串分组](https://leetcode.cn/problems/group-shifted-strings/) 里是「相邻字符差」序列。

**滑窗家族对照表**（本章与 017 共享第 3 行）：

| 章节 | 窗口长度 | 目标 | 维护的聚合量 | 动 left 的条件 | 收缩安全性来自 |
| --- | --- | --- | --- | --- | --- |
| [015](015-longest-substring-without-repeating-characters.md) | 变长 | 最长 | `last[c]` | 出现重复 | 左端点下界单调，可跳跃 |
| [016](016-minimum-window-substring.md) | 变长 | 最短 | `need[c]` + `missing` | 已覆盖 | 覆盖关于左端点单调 |
| [017](017-find-all-anagrams-in-a-string.md) | 定长 = m | 全部起点 | `diff[26]` + `nonzero` | 无需决策 | 长度固定 |
| **018** | **定长 = m** | **是否存在** | **`diff[26]` + `nonzero`** | **无需决策** | **长度固定** |
| [019](019-minimum-size-subarray-sum.md) | 变长 | 最短 | `sum` | `sum >= target` | 正数保证单调 |

**017 与 018 的逐项差异（本章必须讲清的那张表）**：

| 维度 | 017（LC 438） | 018（LC 567） |
| --- | --- | --- |
| 问法 | 「找到**所有**起点」 | 「**是否存在**」 |
| 返回类型 | `List<Integer>` / `[]int` | `boolean` / `bool` |
| 命中后的动作 | `ans.add(...)`，**继续滑完** | `return true`，**短路** |
| 全部未命中 | 返回空列表 | 返回 `false` |
| 参数顺序 | `findAnagrams(s, p)`：长串在前 | `checkInclusion(s1, s2)`：**模式串在前** |
| 初始窗口的哨兵 | `if (nonzero == 0) ans.add(0)` | `if (nonzero == 0) return true`（可省，因为循环前单独判断） |
| 最优时间复杂度 | Θ(n)（必须扫完才能收集全） | **O(m)**（首窗命中即返回）；最坏 O(n) |
| 维护的状态 | `diff[26]`、`nonzero` | **完全相同** |
| 证明难度 | 需要论证「不重不漏」 | 只需论证「当前窗口是否合法」 |

> **一句话**：018 是 017 的**短路版**，代码差异不超过 4 行。所以本章的重点不在算法，而在**「等价类」这个转化**和**「两道题的关系」**。

### 018.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求返回**排列出现的位置** | 布尔 → 列表 | 直接变成 017；或返回第一个位置（记录 `start` 后 `return`） |
| 要求「近似排列」（至多 `k` 处不同） | 谓词放宽 | 维护 `bad = Σ \|diff[c]\|`，`bad ≤ 2k` 即近似（每个不匹配字符贡献 2） |
| 字符集是 Unicode | `int[26]` 不够 | `HashMap<Character,Integer>` / `map[rune]int`；`nonzero` 的维护方式不变，但初始化要遍历 map |
| 排列的**长度可以不同**（要最长/最短的排列子串） | 窗口变长 | 先确定目标频率，再退化成 016 的「计数覆盖 + 恰好」问题；但「恰好」不满足滑窗单调性，见 992 的「至多相减」技巧 |
| `s2` 是数据流 | 无法回看 | 定长滑窗天然适配：只需保留窗口内 26 个计数和「出队字符」的环形缓冲（长 `m`） |
| 要求**最小窗口**含 `s1` 的所有排列之一 | 组合变化 | 变成「找最小的覆盖窗口」+ 集合匹配，通常需要枚举目标排列（不可行）或换思路（如 Aho-Corasick 多模式匹配） |

## 018.4 图解推演

### 018.4.1 从 `m!` 到 1：等价类折叠

```
s1 = "abc"    的 6 个排列：

  "abc"   "acb"   "bac"   "bca"   "cab"   "cba"
    └───────┴───────┴───────┴───────┴───────┘
                        ↓  折叠（按频率签名）
              {a:1, b:1, c:1}
                        ↓
   在 s2 上问：有没有长度 3 的窗口，频率也是 {a:1, b:1, c:1}？

  ┌────────────────────────────────────────────────────────┐
  │ m! 个对象 → 1 个代表元                                  │
  │ 这是"等价类"这把尺子最直接的一次应用                     │
  └────────────────────────────────────────────────────────┘
```

### 018.4.2 定长窗口的平移（`s1 = "ab"`, `s2 = "eidbaooo"`）

```
s2 =  e    i    d    b    a    o    o    o
      ┌────┬────┐
      │ e  │ i  │                    窗口 [0,1]，diff 非零 → 否
      └────┴────┘
           ┌────┬────┐
           │ i  │ d  │               窗口 [1,2]，否
           └────┴────┘
                ┌────┬────┐
                │ d  │ b  │          窗口 [2,3]，否
                └────┴────┘
                     ┌────┬────┐
                     │ b  │ a  │     窗口 [3,4]，nonzero == 0 → true ✅
                     └────┴────┘

  每一步：出队左边那个字符、入队右边那个字符，diff 只需改两格
```

### 018.4.3 状态表（`s1 = "ab"`，`s2 = "eidbaooo"`）

初始窗口 `[0,1] = "ei"`：`diff = {a:1, b:1, e:−1, i:−1}`，`nonzero = 4`。

| `i` | 出队 | `diff` 变化 | 入队 | `diff` 变化 | `nonzero` | 窗口 | 命中？ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 2 | e | −1 → 0（−1） | d | 0 → −1（+1） | 4 | `"id"` | 否 |
| 3 | i | −1 → 0（−1） | b | 1 → 0（−1） | 2 | `"db"` | 否 |
| 4 | d | −1 → 0（−1） | a | 1 → 0（−1） | **0** | `"ba"` | **是 → return true** |

> 与 017 的表结构一模一样，只有最后一列从「记录答案」变成「短路返回」。这就是「同构」的具体样子。

### 018.4.4 第二种写法：变长双指针

```
思路：窗口内"每种字符的计数都不超过 s1 的计数"，超了就左缩；
      收缩后如果窗口长度恰好 == m，则必然与 s1 同频 → return true

  right++ ; cnt[s2[right]]++
  while cnt[s2[right]] > need[s2[right]]:
        cnt[s2[left]]-- ; left++
  if right - left + 1 == m: return true   ← 长度够了且没超频，所以必然"恰好相等"
```

**为什么「长度 == m 且每个计数都不超」就等价于「计数恰好相等」**：窗口里一共 `m` 个字符，`s1` 也一共 `m` 个；若每个字符都不超过 `s1` 的计数，而总数又相同，那么每个字符**必须**都正好相等（否则总和会小于 `m`）。这是一个「总量约束 + 逐项上界 ⇒ 逐项相等」的论证，堪称本题最漂亮的一句推理。

我用**穷举**验证过它与暴力一致（所有长度 ≤ 4 的 `s1`、长度 ≤ 8 的 `s2`，字符集 `{a,b}`，共数万组，零不一致）。

**取舍**：

| | 定长滑窗（主） | 变长双指针（副） |
| --- | --- | --- |
| 代码长度 | 25 行（含 `bump`） | 18 行 |
| 决策点 | **零**（`left` 由 `right` 决定） | 有（`while` 收缩） |
| 正确性论证 | 只需求证「频率相等 ⇔ 命中」 | 还要多证一句「总量约束 + 上界 ⇒ 相等」 |
| 可迁移性 | 只能处理**定长**目标 | 能处理「长度不固定」的变体 |
| 推荐 | ✅ 面试首选 | 知道它存在即可 |

## 018.5 双语言实现

### 018.5.1 Java

```java
class Solution {
    public boolean checkInclusion(String s1, String s2) {
        int m = s1.length(), n = s2.length();
        if (n < m) return false;               // 模式串比文本长：不可能

        // diff[c] = count_s1(c) − count_window(c)
        // 初始窗口是 s2[0..m-1]
        int[] diff = new int[26];
        for (int i = 0; i < m; i++) {
            diff[s1.charAt(i) - 'a']++;
            diff[s2.charAt(i) - 'a']--;
        }

        int nonzero = 0;
        for (int v : diff) if (v != 0) nonzero++;
        if (nonzero == 0) return true;         // 第一个窗口就命中（对应 017 的 ans.add(0)）

        for (int i = m; i < n; i++) {
            // 出窗 s2[i-m]：窗口少一个 → diff +1
            nonzero += bump(diff, s2.charAt(i - m) - 'a', +1);
            // 入窗 s2[i]：窗口多一个 → diff −1
            nonzero += bump(diff, s2.charAt(i) - 'a', -1);
            // 与 017 唯一的实质差别：命中即短路，不再继续扫
            if (nonzero == 0) return true;
        }
        return false;
    }

    // 修改 diff[i] += d，返回"非零格子数"的变化量
    private static int bump(int[] diff, int i, int d) {
        int before = diff[i];
        diff[i] += d;
        if (before == 0 && diff[i] != 0) return 1;    // 从零跨出去
        if (before != 0 && diff[i] == 0) return -1;   // 跨回零
        return 0;
    }
}
```

### 018.5.2 Go

```go
package main

func checkInclusion(s1 string, s2 string) bool {
	m, n := len(s1), len(s2)
	if n < m {
		return false
	}

	// diff[c] = count_s1(c) − count_window(c)
	var diff [26]int
	for i := 0; i < m; i++ {
		diff[s1[i]-'a']++
		diff[s2[i]-'a']--
	}

	nonzero := 0
	for _, v := range diff {
		if v != 0 {
			nonzero++
		}
	}
	if nonzero == 0 {
		return true
	}

	for i := m; i < n; i++ {
		// int(...) 不能省：Go 里 byte−byte 仍是 byte，直接传 int 参数编译报错
		nonzero += bump(&diff, int(s2[i-m]-'a'), +1)
		nonzero += bump(&diff, int(s2[i]-'a'), -1)
		if nonzero == 0 {
			return true
		}
	}
	return false
}

// bump 修改 diff[i] += d，返回"非零格子数"的增量
func bump(diff *[26]int, i int, d int) int {
	before := diff[i]
	diff[i] += d
	if before == 0 && diff[i] != 0 {
		return 1
	}
	if before != 0 && diff[i] == 0 {
		return -1
	}
	return 0
}
```

### 018.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 布尔返回值 | `boolean` | `bool` | 签名要用对；LeetCode 的 Go 模板是 `func checkInclusion(s1 string, s2 string) bool` |
| `byte` 算术 | 无此问题，`char - 'a'` 提升为 `int` | `s2[i] - 'a'` 是 `byte`，传给 `int` 参数**编译失败** | 必须 `int(...)`；这是本章实测时唯一的编译错误来源 |
| 传定长数组 | `int[]` 是引用语义 | `[26]int` 是值类型，不传指针就整份拷贝 | 写 `&diff` + `*[26]int`；写错不报错，只是白拷贝 |
| 提前返回 | `return true` 直接在循环内 | 同 | 两语言一样，这是本题「短路」优势最直接的地方 |
| 字符串参数顺序 | `(String s1, String s2)` | `(s1 string, s2 string)` | 都要记住「模式串在前」，与 017 相反 |
| 整数宽度 | `int` 32 位 | `int` 64 位（平台相关） | `diff` 的值域是 `[−m, m]`，`m ≤ 10⁴`，两语言都安全 |

### 018.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举所有长度 m 的窗口，重新算 26 元组
func brute(s1, s2 string) bool {
	m := len(s1)
	if len(s2) < m {
		return false
	}
	sig := func(x string) [26]int {
		var c [26]int
		for i := range x {
			c[x[i]-'a']++
		}
		return c
	}
	want := sig(s1)
	for i := 0; i+m <= len(s2); i++ {
		if sig(s2[i:i+m]) == want {
			return true
		}
	}
	return false
}

// 变长双指针版（第二种解法），用来交叉验证
func checkInclusionVar(s1, s2 string) bool {
	m := len(s1)
	if len(s2) < m {
		return false
	}
	var need, cnt [26]int
	for i := 0; i < m; i++ {
		need[s1[i]-'a']++
	}
	left := 0
	for right := 0; right < len(s2); right++ {
		c := s2[right] - 'a'
		cnt[c]++
		for cnt[c] > need[c] {
			cnt[s2[left]-'a']--
			left++
		}
		if right-left+1 == m {
			return true
		}
	}
	return false
}

func TestCheckInclusionRandom(t *testing.T) {
	fixed := []struct {
		s1, s2 string
		w      bool
	}{
		{"ab", "eidbaooo", true},
		{"ab", "eidboaoo", false},
		{"adc", "dcda", true},   // 排列出现但原串没出现
		{"abc", "ab", false},    // m > n
		{"a", "a", true},        // 最小规模
		{"aa", "ab", false},     // 不可以用 set 去重
	}
	for _, f := range fixed {
		if got := checkInclusion(f.s1, f.s2); got != f.w {
			t.Fatalf("s1=%q s2=%q got=%v want=%v", f.s1, f.s2, got, f.w)
		}
		if got := checkInclusionVar(f.s1, f.s2); got != f.w {
			t.Fatalf("变长版 s1=%q s2=%q got=%v want=%v", f.s1, f.s2, got, f.w)
		}
	}

	r := rand.New(rand.NewSource(18))
	for iter := 0; iter < 30000; iter++ {
		n1 := 1 + r.Intn(4)
		n2 := r.Intn(13)
		b1 := make([]byte, n1)
		for i := range b1 {
			b1[i] = byte('a' + r.Intn(3)) // 只有 a/b/c：命中率高，能压测"命中"分支
		}
		b2 := make([]byte, n2)
		for i := range b2 {
			b2[i] = byte('a' + r.Intn(3))
		}
		a, b := string(b1), string(b2)
		want := brute(a, b)
		if got := checkInclusion(a, b); got != want {
			t.Fatalf("iter=%d s1=%q s2=%q got=%v want=%v", iter, a, b, got, want)
		}
		// 两个实现互相交叉验证：它们的错误模式不同，同时错同一个的概率极低
		if got := checkInclusionVar(a, b); got != want {
			t.Fatalf("变长版 iter=%d s1=%q s2=%q got=%v want=%v", iter, a, b, got, want)
		}
	}
}
```

> **为什么用两个实现互相交叉验证**：定长版依赖 `bump` 的跨零判断，变长版依赖 `while` 收缩的边界 —— 两者的 bug 模式完全不同。同时和暴力比，等于给同一个结论上了两道锁。

## 018.6 复杂度与常见坑

### 018.6.1 复杂度推导

- **时间 O(n + m)**：
  - 初始化：`m` 次计数 + 26 次扫表。
  - 滑动：最多 `n - m` 轮，每轮 2 次 `bump`。
  - **最好情况 O(m)**：如果第一个窗口就命中，直接 `return true`，连滑动都不做 —— 这是「只问存在性」带来的好处，017 拿不到。
- **空间 O(26) = O(1)**：`diff` 定长。没有输出数组，比 017 还省。

### 018.6.2 八个真实踩过的坑

1. **把题目理解成「在 `s2` 里找 `s1`」** —— `"adc"` / `"dcda"` 会返回 `false`。必须找**排列**。
2. **枚举排列** —— `m!` 不可算，这条路不是「慢」而是「不可能」，面试里说出来会被直接判定为没抓住等价类。
3. **用 `set` 判断覆盖** —— `s1 = "aa"` 时会把只含一个 `a` 的窗口判成合法。
4. **参数顺序搞反** —— `checkInclusion(s1, s2)` 是「模式串在前」，与 017 的 `findAnagrams(s, p)` 相反。写反了样例可能还过（对称的情况下），但语义已错。
5. **`n < m` 忘记提前返回** —— 初始化循环 `for (i = 0; i < m; i++)` 里访问 `s2.charAt(i)` 会越界（`i` 可以到 `m-1 ≥ n`）。
6. **忘记检查第一个窗口** —— 循环从 `i = m` 开始，`[0, m-1]` 这个窗口不在循环里。漏了会让 `s1 = s2` 的情况（如 `("abc","abc")`）返回 `false`。
7. **`bump` 判零逻辑写错** —— 用 `before * after < 0` 判「跨零」既会溢出又不覆盖 `0 → 非0`。正确判据是「`before == 0` 与 `after == 0` 恰好一个成立」。
8. **Go 里 `int()` 转换漏了** —— `bump(&diff, s2[i]-'a', -1)` 编译报 `cannot use ... byte as int`。这是本章唯一的编译期错误，`go vet` 会立刻抓到。

### 018.6.3 面试官最爱追问的三个问题

**Q1：这题和 LC438（找到所有字母异位词）有什么区别？**
> 「同一个算法，输出契约不同。017 要收集所有起点、必须扫完，返回列表；018 只要存在性、命中即 `return true`，返回布尔，最好情况 O(m)。维护的状态完全一样：长度 `m` 的窗口上 `diff = count_s1 − count_window` 和它的非零格子数。参数顺序上 017 是 `(长串, 模式串)`、018 是 `(模式串, 长串)`，这是唯一容易念错的地方。」

**Q2：为什么不能枚举 `s1` 的排列？**
> 「`m!` 增长太快：`m = 10` 就是 362 万，`m = 20` 是 2.4·10¹⁸，而题目 `m` 可以到 10⁴。更本质地说，**排列对本题而言是一个过大的表示**：我们只关心『是不是某个排列』，而判断这件事只需要频率向量，它与具体排列是 `m! : 1` 的关系。这就是用等价类压缩搜索空间的典型案例。」

**Q3：变长双指针版为什么也对？**
> 「它维护的窗口保证『每种字符的计数不超过 `s1` 的计数』。当窗口长度恰好等于 `m` 时，窗口里一共 `m` 个字符、`s1` 也一共 `m` 个，若每个字符都不超过上界而总数相同，那么每一项都必须正好相等。于是『长度到 `m` 且不超频』就等价于『频率恰好相等』。我用穷举验证过两种实现在所有小规模输入上一致。定长版更好写、更少决策点，所以我首选定长版。」
