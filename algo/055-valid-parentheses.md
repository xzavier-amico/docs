## 055.1 题目

**原题链接**：<https://leetcode.cn/problems/valid-parentheses/>

### 题意重述（把隐含条件补齐）

给定一个只由 `(` `)` `[` `]` `{` `}` 六种字符组成的字符串 `s`，判断它是否**有效**。有效的定义有三条，必须同时满足：

1. **左括号必须用相同类型的右括号闭合**（`(` 只能配 `)`）；
2. **左括号必须以正确的顺序闭合**（嵌套必须从内到外收尾，不能交叉）；
3. **每个右括号都必须有一个同类型左括号与之对应**。

看起来是三道送分题，但每一条都对应一个会被写错的实现：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **空字符串算有效** | 官方示例 `输入：s = ""  输出：true` | 循环前 `if (s.isEmpty()) return false` → 空串判错 |
| **「正确顺序」不是「数量相等」** | 定义第 2 条 | `([)]` 三种括号各一个，数量完全平衡，但交叉嵌套 → 必须 `false` |
| **右括号不能「赊账」** | 定义第 3 条 | `)(` 数量也平衡，但第一个字符就是右括号 → 必须 `false` |
| **长度一定为偶数才有救** | 推论（不是题面） | 长度奇数直接 `false`，能砍掉一半无效输入，是不能省的常数优化 |
| **字符集只有 6 种** | 约束 | 可以放心用 `switch`/`map`，不必处理任意字符；但真实工程里要处理 `""`、`''` 等，见 `055.3.4` |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length <= 10⁴` | n 最多 1 万 | **O(n²) 也能过**（本机 `n=2·10⁴` 的反复替换法只要约 11 ms），所以这题 AC 说明不了什么；考的是「你为什么能一次扫描就定论」 |
| 只有 6 种字符 | 字符集极小 | 可用 `switch` 或 `map[byte]byte`；不必建 Trie 或哈希 |
| 只要返回 `true/false` | 不需要位置、不需要修复 | 才能「提前 return」—— 发现第一个矛盾就结束，是 `O(n)` 最坏但常常远小于 n |
| 三种括号 | 不是一种 | **单类型才能用计数器**（见 `055.3.1`），三种类型必须用栈 |

> 💡 **量级 → 算法**：`n = 10⁴` 是个**故意给大的上界**，几乎所有解法都能过。
> 这题的正确读法是：**它在考「你能不能证明一次扫描就够了」**，而不是「你能不能通过」。

### 示例

```text
输入：s = "()"        输出：true
输入：s = "()[]{}"    输出：true       ← 平铺并列，不嵌套
输入：s = "(]"        输出：false      ← 类型不对
输入：s = "([])"      输出：true       ← 嵌套
输入：s = "([)]"      输出：false      ← ★ 数量全对，但交叉嵌套
输入：s = ""          输出：true       ← 空串有效
输入：s = "("         输出：false      ← 长度奇数，直接毙
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① ""            → 打「空串特判成 false」
② "("           → 打「忘记检查栈最后是否为空」（循环结束栈里还剩东西 → 非法）
③ "([)]"        → 打「只统计三种括号的计数」：三种计数全为 0，但必须 false
④ "){["         → 打「不判栈空就弹」：第一个字符就弹空栈 → 崩溃/越界
⑤ "{[()]}"      → 打「只用一张 map 做类型校验却搞反了方向」（'(' 映射到 ')' vs 反向）
⑥ 长度 1000 的 "((((...))))" → 打「递归实现」：栈深 1000，某些语言栈够、10⁵ 就不够了
```

第 ③ 条是本章的**分水岭**：它把「计数」和「顺序」这两件事彻底区分开。凡是「用三个计数器分别数 `()` `[]` `{}`」的写法，都会在 `"([)]"` 上翻车。

## 055.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最不需要想的结构是「**反复删除相邻的合法对**」：只要字符串里还有 `()`、`[]`、`{}` 这样的相邻对，就删掉，删到不能再删为止；最后剩空串就是有效。

```java
// 暴力：反复消灭相邻的合法对，直到不再变化。O(n²) 时间 / O(n) 空间
String cur = s;
boolean changed = true;
while (changed && !cur.isEmpty()) {
    changed = false;
    for (String p : new String[]{"()", "[]", "{}"}) {
        if (cur.contains(p)) {
            cur = cur.replace(p, "");   // 每次替换都要重建字符串
            changed = true;
        }
    }
}
return cur.isEmpty();
```

- 时间 **O(n²)**（最坏情况下每轮只消掉一对，共 `n/2` 轮，每轮 `O(n)`），空间 **O(n)**。
- 它**是对的**：任何合法的括号序列，其内部一定存在一对相邻的合法对（「最内层」），删掉它之后剩下的仍然合法 —— 这是归纳法的雏形，`055.3.2` 会把它写严。
- 本机 Go 实测（同一台机器，`n = 2·10⁴` 的 `"("*5000 + ")"*5000 + "()"*5000`）：反复替换法 **11.3 ms**（另一轮抖动到 42.3 ms），一趟栈 **0.40 ms** —— 差 **28 倍以上**，而且 `n` 每翻一倍差距再翻倍。

### 第二步：它为什么不够 —— 用数字说话

`n = 10⁴` 时 `O(n²)` 是 `10⁸` 量级的字符搬运，能过；但换三个场景立刻死：

1. **数据流场景**：括号是一个字符一个字符来的（Sublime、VS Code 的实时括号高亮），你不可能「回头重建整个字符串」。
2. **`n = 10⁶`**：`10¹²` 次搬运 —— 分钟级。
3. **它算不出「第一个出错的位置」**：反复替换是个「全局消消乐」，崩溃信息全丢了。真实 IDE 需要告诉你「第 7 个字符的 `]` 与第 5 个字符的 `(` 不匹配」，而两遍扫描的栈解天然带着位置。

### 第三步：卡点在哪

把问题翻译成一句话：

> **扫到右括号时，我要立刻知道「最近一个还没闭合的左括号」是什么类型。**

暴力的卡点是：它把「最近」这个问题交给了「字符串的物理相邻性」，于是每次删除都要重新扫全串。

而「**最近的、还没被处理的那个**」，在数据结构里有一个几乎量身定做的名字：**栈（后进先出）**。

### 第四步：灵感的来源 —— 括号的文法就是一棵树

括号序列之所以能被栈解决，是因为它的结构**天生是嵌套的（树形）**：

```
        输入 " { [ ( ) ] } "
                       ↑ 扫描到这里

     {                    ← 最外层，最早出现，最后闭合
       [                  ← 次外层
         (                ← 最内层，最近出现 → 必须最先闭合
           )
         ]
     }

"最近出现的左括号必须最先闭合"  ==  LIFO  ==  栈
```

于是栈的语义可以被一句话说清：

> **栈里装的是「已经出现、但还没被解决」的左括号。遇到右括号时，只有栈顶那一个才有资格与它配对。**

这个说法不只能解本题，它是整个第 7 部分（055–064）通用的一条主线，`055.3.3` 会把它做成表格。

## 055.3 原理拆解

### 055.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 反复删除相邻对 | O(n²) | O(n) | 10 行 | `n ≥ 10⁵`；数据流输入；需要报错位置 |
| 三个计数器分别计数 | O(n) | O(1) | 6 行 | **`"([)]"` 上直接错** —— 只能判「数量」，判不了「顺序」 |
| 计数器 + 三种独立校验 | O(n) | O(1) | 12 行 | 同上，顺序信息已经丢失，无法补救 |
| 递归（子串匹配 + 递归） | O(n) | O(n) 栈深 | 15 行 | 深度 `10⁵` 直接栈溢出；且字符串切片有额外拷贝 |
| **栈（存「期待的右括号」）** ✅ | **O(n)** | **O(n)** | **12 行** | 需要额外空间；`n` 极大且要求 `O(1)` 空间时无解（多类型括号没有 `O(1)` 空间的确定性算法） |
| 栈（存左括号 + `map` 查表） ✅ | O(n) | O(n) | 16 行 | 中规中矩；比上一行多一次哈希/查表，慢一点点 |

**为什么「三个计数器」必错**，画个图就清楚了：

```
s = "([)]"

计数器视角： ( :1   ):1   [:1   ]:1     ← 全部平衡，看不出问题
扫描视角：
  位置 0 '('  → 期待一个 ')'
  位置 1 '['  → 期待一个 ']'（此时最紧迫的是 ']'）
  位置 2 ')'  → 来了 ')'，但最紧迫的是 ']'  → ✗ 顺序错

┌───────────────────────────────────────────────┐
│ 「计数」丢掉的是「顺序」这个维度；            │
│ 而括号合法性恰恰定义在顺序上。                │
│ 所以 O(1) 空间的计数法对多类型括号无能为力。  │
└───────────────────────────────────────────────┘
```

> **只有一种括号时**（比如只含 `(` `)`），计数法是正确且 `O(1)` 空间的：任意前缀里 `)` 不得多于 `(`，且总数相等。这个结论在 [LC 32 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/) 里会以「左右两次计数」的形式复活（见 `056`）。**能不能降成计数器，取决于「有几种类型」**。

### 055.3.2 为什么这个做法是对的（正确性论证）

**循环不变量**（这是本章最该背走的东西）：

> **`I(i)`**：处理完 `s[0..i-1]` 之后，栈中自底向上依次是「尚未闭合的左括号」，且**它们的出现顺序与在字符串中一致**；栈顶是其中**最靠右**（最紧迫）的那一个。并且，若 `s[0..i-1]` 是某个合法序列的前缀，则栈中内容与「该合法序列在此处的未闭合栈」完全相同。

**命题 1（不误判）**：若算法返回 `true`，则 `s` 有效。

- 算法返回 `true` 只有一条路径：全程没有触发 `return false`，且最终 `stack.isEmpty()`。
- 全程不触发 `return false` 意味着：每个右括号被处理时，栈非空且栈顶正是它同类型的左括号，于是这一对 (左, 右) 构成合法配对，且从「最内层」向外的顺序闭合（栈顶永远是最内层）。
- 最终栈空意味着所有左括号都被配对完。
- 因此所有括号都被**同类型、正确嵌套顺序**地配对 —— 正是有效序列的定义。∎

**命题 2（不漏判）**：若 `s` 有效，则算法返回 `true`。

对长度 `n` 做归纳。设 `s` 有效。
- 取 `s` 中最靠左的那个右括号，位置 `k`。由有效序列的定义，`s[k-1]` 必是与之同类型的左括号（否则 `s[k-1]` 是右括号，比 `k` 更靠左，矛盾；若 `s[k-1]` 是不同类型的左括号，则这个右括号无法与它闭合，而左侧再没有右括号可以先行结算，也矛盾）。
- 算法扫到 `s[k]` 时，栈顶正是 `s[k-1]`（由不变量 `I(k)`：`s[k-1]` 是最靠右的未闭合左括号），于是它被正确弹出，不触发 `false`。
- 剩下的 `s'`（删去 `s[k-1..k]`）仍然有效，长度 `n-2`，由归纳假设，算法在剩余部分同样不触发 `false`，且末期栈与 `s'` 的未闭合栈一致。
- 由于 `s` 有效，`s` 处理完时未闭合栈必为空。∎

> **这两个命题合起来才叫「充要」**。面试里很多人只会说命题 1（「不误判」），而漏掉命题 2。命题 2 才是「为什么不漏判」—— 它依赖引理「有效序列中最靠左的右括号，其左边紧邻的一定是同类型左括号」，这个引理本身值得在纸上一画。

### 055.3.3 通用解题思路（可迁移的那一层）

**本章（以及 055–059 这一批）的统一主题：栈里存的是「还没被解决的问题」。写任何栈解，只要回答三句话就够了。**

| 三问 | 本题（055） | 说明 |
| --- | --- | --- |
| **① 存什么** | 存「还没闭合的左括号」（或它期待的右括号） | 存的是**未解决状态的压缩表示**，不是历史全量 |
| **② 何时弹** | 遇到右括号时弹一个 | 弹的时机 = 「当前输入让某个旧状态可以结案」的那一刻 |
| **③ 弹出时结算了谁** | 结算了「这对括号的配对关系」：一对 (左, 右) 被销账 | 结算的产物：一度「未解决」的问题被判定为合法 |

同一张表在后续章节的形态（先看，读完 056–059 再回来对一遍）：

| 题 | 存什么（未解决的问题） | 何时弹 | 弹出时结算了谁 |
| --- | --- | --- | --- |
| [LC 20 有效的括号](https://leetcode.cn/problems/valid-parentheses/)（本章） | 未闭合的左括号 | 遇到右括号 | 这一对括号是否合法配对 |
| [LC 32 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/)（`056`） | 未匹配的**下标**（含一个哨兵） | 遇到右括号且栈不空 | 栈顶下标之后到当前位置这一段的长度 |
| [LC 224 基本计算器](https://leetcode.cn/problems/basic-calculator/)（`057`） | 进入括号前的「累计值 + 符号」 | 遇到 `)` | 括号内的结果乘符号、加回外层累计值 |
| [LC 394 字符串解码](https://leetcode.cn/problems/decode-string/)（`058`） | 外层已拼好的前缀 + 待用的重复次数 | 遇到 `]` | 一段「前缀 + k 份内容」的新串 |
| [LC 232 用栈实现队列](https://leetcode.cn/problems/implement-queue-using-stacks/)（`059`） | 整批按「倒序」存起来的元素 | 出队且 `out` 为空时整批倒腾 | 一次倒腾结算了一整批元素的先后次序 |

**抽象成一句话的模型**：

```
一个问题「还没被解决」 ⟺ 它需要的后续信息还没到
        ↓
把「未解决的东西」压栈（只压它的最小充分描述）
        ↓
当后续信息到来（右括号 / ']' / ')' / 出队请求）→ 弹栈结算
        ↓
栈空 ⟹ 所有问题都被解决（这是最常用的合法性判据）
```

属于同一模型的题，还有一批「看起来不像括号」的：

| 题 | 未解决的问题 | 为什么也是栈 |
| --- | --- | --- |
| [LC 71 简化路径](https://leetcode.cn/problems/simplify-path/) | 已经走过的目录层级 | `..` 要回退上一层 = 弹栈 |
| [LC 150 逆波兰表达式求值](https://leetcode.cn/problems/evaluate-reverse-polish-notation/) | 还没凑够两个操作数的运算符 | 运算符在等它的操作数，凑够就结算 |
| [LC 946 验证栈序列](https://leetcode.cn/problems/validate-stack-sequences/) | 已压入但还没弹出的元素 | 用一次模拟验证「合法弹序」 |
| [LC 1190 反转每对括号间的子串](https://leetcode.cn/problems/reverse-substrings-between-each-pair-of-parentheses/) | 每个括号层里已累积的片段 | 遇 `)` 时把本层内容反转后交给外层 |

### 055.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**第一个错误的字符位置** | 从 bool 变位置 | 栈里改存**下标**；右括号类型不符时返回当前 `i` 与栈顶下标（这正是 `056` 的做法） |
| **允许通配符**（`*` 可当 `(`、`)` 或空） | 引入三态 | 不能再用单一栈：要维护「未匹配左括号数的区间 `[lo, hi]`」—— 见 [LC 678 有效的括号字符串](https://leetcode.cn/problems/valid-parenthesis-string/) |
| 问「**最少添加几个**括号才有效」 | 变成计数 | 弹不出时 `+1`（缺左括号），结束后栈剩余量也 `+1` —— 见 LC 921 |
| 问「**最少删除几个**」 | 同上但改判据 | 见 [LC 1249 移除无效的括号](https://leetcode.cn/problems/minimum-remove-to-make-valid-parentheses/) |
| **数据流 / 无限输入** | 不能存全量 | 栈天然适配：来一个字符处理一个，栈深 = 当前嵌套深度（有用的监控指标） |
| **每次弹栈的代价不能太大** | 需要 `O(1)` 空间 | 单类型可用计数器；多类型必须 `O(n)` 栈（这是信息论下界级别的结论，见 `055.3.1` 的图） |

## 055.4 图解推演

### 055.4.1 合法序列 `"([{}])"` 的完整轨迹

```
输入： (  [  {  }  ]  )
      0  1  2  3  4  5   ← 下标

┌──────┬──────┬─────────────────────┬──────────────┬────────┐
│ 步骤 │ 字符 │ 动作                │ 栈（底→顶）  │ 说明   │
├──────┼──────┼─────────────────────┼──────────────┼────────┤
│  0   │  (   │ push '('            │ (            │ 未闭合 │
│  1   │  [   │ push '['            │ ( [          │ 未闭合 │
│  2   │  {   │ push '{'            │ ( [ {        │ 未闭合 │
│  3   │  }   │ 栈顶 '{' 匹配 → pop │ ( [          │ 结算 1 │
│  4   │  ]   │ 栈顶 '[' 匹配 → pop │ (            │ 结算 2 │
│  5   │  )   │ 栈顶 '(' 匹配 → pop │ (空)         │ 结算 3 │
└──────┴──────┴─────────────────────┴──────────────┴────────┘
栈空 → return true
```

用图看「栈顶永远是最内层」这件事：

```
       (          ← 位置 0，栈底
        │
        [         ← 位置 1
         │
         {        ← 位置 2，栈顶 ← 下一个右括号必须先跟它配对
          ↑
        栈顶 ↑ 增长方向（push）   ↓ 收缩方向（pop）
```

### 055.4.2 失败案例 `"([)]"` 的轨迹

```
输入： (  [  )  ]
      0  1  2  3

┌──────┬──────┬──────────────────────────────────┬───────────┐
│ 步骤 │ 字符 │ 动作                             │ 栈（底→顶）│
├──────┼──────┼──────────────────────────────────┼───────────┤
│  0   │  (   │ push '('                         │ (         │
│  1   │  [   │ push '['                         │ ( [       │
│  2   │  )   │ 栈顶是 '['，与 ')' 不匹配 → ✗    │ —         │
└──────┴──────┴──────────────────────────────────┴───────────┘
return false     ← 三个计数器会在这一刻判 true，这就是计数法的死因
```

### 055.4.3 三种失败形态对照

```
① 类型不符          "([)]"         栈顶 '[' vs ')'      → 位置 2 处失败
② 右括号赊账        ")("           第一次 pop 时栈空    → 位置 0 处失败
③ 左括号没闭合      "(()"          扫描完栈里还留着 '('  → 结束时失败

    ┌───────────────────────────────────────────────────────┐
    │ 位置 ② 和 ③ 的判据，恰好是栈的两个"边界检查"：       │
    │   ②  pop 之前必须检查 isEmpty()                       │
    │   ③  循环结束后必须检查 isEmpty()                     │
    │ 写漏任何一个，都只在特定的输入上错 —— 这就是要背的。  │
    └───────────────────────────────────────────────────────┘
```

## 055.5 双语言实现

### 055.5.1 Java

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public boolean isValid(String s) {
        // 长度奇数一定不配对：这是"便宜且必对"的前置过滤，不要用 if (s.isEmpty()) 特判
        if ((s.length() & 1) == 1) return false;

        // 选 ArrayDeque 而不是 Stack：Stack 继承 Vector，每个方法都带 synchronized，
        // 单线程下纯属开销；ArrayDeque 的 push/pop 是 O(1) 且无锁
        Deque<Character> stack = new ArrayDeque<>();

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            // 栈里存"我期待的右括号"：省掉一次查表，也让匹配判断变成一次 ==
            if (c == '(') {
                stack.push(')');
            } else if (c == '[') {
                stack.push(']');
            } else if (c == '{') {
                stack.push('}');
            } else {
                // 右括号：栈空说明"赊账"，栈顶不同类型说明"交叉嵌套"，都必须 false
                // 这里用 || 的短路顺序很关键：isEmpty() 必须在 pop() 之前判断
                if (stack.isEmpty() || stack.pop() != c) return false;
            }
        }
        return stack.isEmpty();   // 还有没结算完的左括号 → 非法
    }
}
```

### 055.5.2 Go

```go
package main

func isValid(s string) bool {
	if len(s)%2 == 1 { // 奇数长度必然不配对
		return false
	}
	// Go 没有内置栈，用带初始容量的切片模拟：预分配 len(s) 避免 append 过程中扩容
	stack := make([]byte, 0, len(s))
	// 反查表：右括号 → 它要求的左括号。用 map 是为了后面 else 分支只写一处判断
	closeToOpen := map[byte]byte{')': '(', ']': '[', '}': '{'}

	for i := 0; i < len(s); i++ {
		c := s[i] // s[i] 是 byte：本题字符集全是 ASCII，用 byte 比 []rune 快且不分配
		if want, isCloser := closeToOpen[c]; isCloser {
			// 短路顺序同样关键：len(stack) == 0 必须先判断，否则 stack[...] 越界 panic
			if len(stack) == 0 || stack[len(stack)-1] != want {
				return false
			}
			stack = stack[:len(stack)-1] // 出栈：只移动长度，不释放内存
			continue
		}
		stack = append(stack, c)
	}
	return len(stack) == 0
}

func main() {}
```

### 055.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 栈的表示 | `ArrayDeque<Character>`（官方推荐）或 `Stack` | `[]byte` + `append` / 切片截断 | Go 的「出栈 = 缩短切片」是零分配操作；Java 的 `Stack` 带 `synchronized`，`ArrayDeque` 才是正解 |
| 字符类型 | `char` 是 16 位 UTF-16 单元 | `s[i]` 是 `byte`，`for range` 给的是 `rune` | 本题全 ASCII，两边都用「单字节」语义最省；用 `for range` 会多一层 UTF-8 解码 |
| 「不存在」的表示 | `Deque` 的 `pop()` 空栈抛 `NoSuchElementException` | 空切片取 `stack[-1]` 直接 panic（越界） | 两边都必须先判空；Java 的异常可被 `catch`，Go 的 panic 不 `recover` 就崩 —— 防御写法的必要性更高 |
| 查表 | `switch` 或 `Map<Character,Character>` | `map[byte]byte` 或 `switch` | Go 的 `map` 查找返回 `(value, ok)`，正好可以「一句话完成查表 + 判是否是右括号」 |
| 空字符串 | `"".length() == 0`，循环不执行，`isEmpty()` 为 true | `len("") == 0`，写法完全对称 | 空串在两种语言里都自然返回 `true`，**不需要特判** |

### 055.5.4 对拍测试（和「反复删除」暴力互证）

```go
package main

import (
	"math/rand"
	"strings"
	"testing"
)

// 暴力参考：反复删除相邻合法对，直到不动为止；剩空串即有效
func bruteIsValid(s string) bool {
	pairs := []string{"()", "[]", "{}"}
	changed := true
	for changed && len(s) > 0 {
		changed = false
		for _, p := range pairs {
			if strings.Contains(s, p) {
				s = strings.ReplaceAll(s, p, "")
				changed = true
			}
		}
	}
	return len(s) == 0
}

func TestValidParenthesesRandom(t *testing.T) {
	r := rand.New(rand.NewSource(7))
	alpha := []byte("()[]{}") // 六种字符等概率：会大量制造 "([)]" 这种交叉嵌套
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(9)
		b := make([]byte, n)
		for i := range b {
			b[i] = alpha[r.Intn(len(alpha))]
		}
		s := string(b)
		if got, want := isValid(s), bruteIsValid(s); got != want {
			t.Fatalf("iter=%d s=%q got=%v want=%v", iter, s, got, want)
		}
	}

	// 边界①：嵌套极深（10⁵ 层也不会爆，因为用的是显式栈而不是递归）
	deep := strings.Repeat("(", 1000) + strings.Repeat(")", 1000)
	if !isValid(deep) {
		t.Fatal("深嵌套应合法")
	}
	// 边界②：空串 / 单字符
	if !isValid("") || isValid("(") || isValid("]") {
		t.Fatal("空串与单字符判定错")
	}
}
```

> **为什么暴力选「反复删除」而不是「另一个栈实现」**：对拍的价值来自**两条独立路径**。如果两边都用栈，只差变量名，那测出来的只是「我抄得对不对」。反复删除法的正确性理由（最内层一定存在相邻合法对）和栈解完全不共享，这才叫真对拍。

## 055.6 复杂度与常见坑

### 055.6.1 复杂度推导

- **时间 O(n)**：`for` 循环恰好执行 `n` 次；每次内部只做一次 `map` 查找（均摊 `O(1)`）和一次 `push`/`pop`（`O(1)` 均摊 —— Go 的 `append` 偶发扩容，但均摊到每次是 `O(1)`；Java 的 `ArrayDeque` 也是均摊 `O(1)`）。
- **空间 O(n)**：最坏情况是 `"((((...))))"`，栈深 `n`。**注意这只是最坏界**：`"()()()..."` 的栈深恒为 1。所以「栈空间 = 当前嵌套深度」，这个量在监控里有实际意义。
- **为什么不是 `O(1)` 空间**：三种括号的类型信息必须被记住，否则 `"([)]"` 与 `"([])"` 无法区分 —— `055.3.1` 的图说明了计数法为什么丢信息。可以证明：任意只用 `O(1)` 空间的确定性算法都无法判定多类型括号的合法性（本质是「需要记忆的嵌套深度无界」）。
- **常数优化**：`len % 2 == 1` 早退可以把所有奇数长度输入变成 `O(1)`。这不是渐进优化，但在真实数据里能省一半时间。

### 055.6.2 七个真实踩过的坑

1. **只统计计数（`"([)]"` 判 true）** —— 最高频错误。三种括号各数一遍、都平衡就返回 true，丢掉的是「顺序」。
2. **`pop()` 前不判空** —— `")"` 这一个字符就能让 Java 抛 `NoSuchElementException`、Go 直接 panic。判空和 `pop` 的顺序写反也一样崩。
3. **循环结束后忘了 `return stack.isEmpty()`** —— `"(()"` 会返回 true。这是「右括号全配上了」与「左括号全闭合了」的区别，两件事都必须检查。
4. **空串特判成 `false`** —— 官方示例明确 `"" → true`。顺手写个 `if (s == null || s.isEmpty()) return false` 就挂了。
5. **`map` 方向搞反** —— 把 `')' → '('` 写成 `'(' → ')'`，代码「看起来对称」，实际在右括号分支永远查不到 key，于是所有输入都被当成左括号压栈。**判断方向的自检方法**：拿 `s = "()"` 单步走一遍。
6. **用 `Stack` 类而不是 `ArrayDeque`** —— 不是错，是慢：`java.util.Stack` 继承 `Vector`，`push/pop/peek` 全是 `synchronized` 方法。面试里被问「为什么不用 Stack」要能答「历史遗留 API，单线程下无谓加锁」。
7. **Go 里用 `for _, r := range s` 拿到 `rune` 后直接与 `')'` 比较** —— 本题能过（ASCII），但一旦字符集含中文注释符就会错位；且 `range` 有 UTF-8 解码开销。**字符类题目优先按 `byte` 索引**。

### 055.6.3 面试官最爱追问的三个问题

**Q1：为什么必须用栈，不能用计数器？**
> 「因为合法性定义在**顺序**上，而计数器抹掉了顺序。`"([)]"` 是最小的反例：三类括号各 1 个，全平衡，但交叉嵌套非法。只有当**括号类型只有一种**时，计数法才等价于栈 —— 那时『任意前缀 `)` 不多于 `(`，且总数相等』与『存在合法嵌套』是同一件事。这也是为什么 LC 32 能用两次计数解决（那里只有一种括号），而本题不行。」

**Q2：栈里存左括号还是存「期待的右括号」？**
> 「两者等价，差别在常数和可扩展性。存『期待的右括号』把匹配判断化简成一次 `==`，代码更短；存『实际左括号 + 反查表』在要输出错误信息时更有用（你能拿到第一个字符的类型和下标）。要返回**错误位置**时，两个都得升级成存**下标** —— 那正是 LC 32 的做法。」

**Q3：如果输入是数据流、长度无上限，怎么办？**
> 「栈的形态天然适配流式：来一个字符，`push` 或 `pop` 一次，`O(1)` 内存增量（严格说是 `O(当前嵌套深度)`）。真正会出问题的是**恶意输入**：`"((((((..."` 无限左括号会让栈无限增长。工程上要加两道闸：① 限制最大嵌套深度（比如 1000 层就报错）；② 边读边判，发现 `pop` 空栈就立即中止，不必读完整个输入。」
