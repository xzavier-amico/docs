>
> | 项 | LC 253 会议室 II | LC 2406 将区间分为最少组数 |

### 题意重述（把隐含条件补齐）

给你一个会议时间数组 `intervals`，其中 `intervals[i] = [start_i, end_i]` 表示第 `i` 个会议从 `start_i` 开到 `end_i`。请返回**至少需要多少间会议室**，才能让所有会议都不冲突地开完。

一句话就完了，但藏着五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **要的是「峰值同时占用数」，不是「总会议数」** | 「至少需要几间」 | 返回 `intervals.length` → 完全错，任何一串不重叠的会议都只需 1 间 |
| **端点相接的会议可以复用同一间** | 253 的官方口径 `[start, end)`（结束的那一瞬房间就空了） | 把 `[0,5]` 与 `[5,10]` 判成冲突 → `[[0,5],[5,10]]` 会返回 2，正确是 1 |
| **会议长度可以差别极大** | `0 <= start_i < end_i <= 10⁶` | 想「按时间点开数组做差分」的人会开一个 10⁶ 的数组（能过但很土），若上界到 10⁹ 就直接爆内存 → 必须**坐标压缩** |
| **`intervals` 可以为空** | `0 <= intervals.length` | 不判空 → 返回 `-1` 之类的脏值（正确是 0） |
| **`start_i < end_i` 严格成立** | 官方约束 | 出现 `start == end` 的零长会议时，三解的默认口径会打架（见 `035.6.2` 第 2 条） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= intervals.length <= 10⁴` | n 最多 1 万 | **O(n²) 会过但很丑**：本机 Go 实测暴力 `n=4000` 已 **56.2 ms**，外推 `n=10⁴` 约 **0.35 s**；`n=10⁵` 就是 35 s → TLE |
| `0 <= start_i < end_i <= 10⁶` | 时间轴宽 10⁶ | 「按秒开差分数组」空间 `O(max_end)`，本题勉强能用；一旦上界到 `10⁹` 就必须**只对端点做差分**（坐标压缩） |
| 端点都是整数 | 可比较、可排序 | 允许「事件排序 + tie-break」这种离散化写法，不必处理浮点 |
| 只需要一个整数 | 不需要输出方案 | 才能把问题压成「最大重叠数」；若要求「哪个会议进哪间房」则必须保留堆（见 `035.3.4`） |

> 💡 **量级 → 算法**：`n ≤ 10⁴` 是**故意给的宽松上界**，让 O(n²) 也能过 —— 所以这题在 LeetCode 上「AC」说明不了任何事，面试官真正想看的是「你能不能说清 `O(n log n)` 三种做法的取舍」。
> **看到「区间 + 最值」先想排序，看到「同时占用数」先想差分。**

### 示例

```text
输入：intervals = [[0,30],[5,10],[15,20]]
输出：2
解释：0~30 那间被长期占着；5~10 与 15~20 不重叠，可以挤在第 2 间里。
     峰值出现在 t ∈ [5,10)：此刻 2 个会议在开。

输入：intervals = [[7,10],[2,4]]
输出：1
解释：两段完全不重叠，一间房轮着用。

输入：intervals = [[0,5],[5,10]]
输出：1
解释：★ 关键样例 —— 端点相接算「不冲突」，因为 5 点整第一场已经结束。
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① []                                  → 打「不判空」：正确 0
② [[0,5],[5,10]]                      → 打「端点相接判成冲突」：正确 1（半开区间）
③ [[1,5],[2,6],[3,7],[4,8]]           → 打「只比较相邻区间」：正确 4（四段两两相交，不是 2）
④ [[0,5],[0,0]]                       → 打「零长会议」：按"占一个瞬间"口径正确 2
⑤ [[0,1],[0,1],[2,3]]                 → 打「返回堆的最终大小」：正确答案 2，但堆最后只剩 1
⑥ [[0,10],[1,2],[3,4],[5,6]]          → 打「贪心选最早的结束时刻」：正确 2（长会一直占着）
```

第 ⑤ 条最阴：`小顶堆` 解有个广为流传的写法 `return heap.size()`，在 `[[0,1],[0,1],[2,3]]` 上返回 **1**（正确答案 2），因为堆的最终大小只是「最后一个开始时刻的重叠数」，不是峰值。必须**在循环里取 max**。

## 035.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（逐时刻计数，先写出来，别急着优化）

最符合直觉的想法：**任意时刻的占用数，最多在某个会议的开始时刻取到**，所以枚举每个开始时刻，数一数此刻有几个会议正在开。

```java
// 暴力：O(n²) —— 对每个候选时刻 t，重扫全部会议
int ans = 0;
for (int[] probe : intervals) {
    int t = probe[0];                 // 候选时刻只取「某个会议的 start」
    int cnt = 0;
    for (int[] x : intervals) {
        if (x[0] <= t && t < x[1]) cnt++;   // 半开区间 [s, e)
    }
    ans = Math.max(ans, cnt);
}
```

- 时间 **O(n²)**，空间 **O(1)**（不复制输入的话）。
- **为什么候选时刻只取 `start` 就够了**：占用数这个函数是**分段常值**的，只在「某个 `start`」或「某个 `end`」处跳变；在 `start` 处只会变大，在 `end` 处只会变小。所以最大值一定在某个 `start` 处被取到 —— 这已经是一次「把连续问题离散化」的偷懒，暴力里就已经用上了。
- 本机 Go 实测（单线程）：`n=1000` **2.67 ms**、`n=2000` **12.4 ms**、`n=4000` **56.2 ms** —— 明显是 `n²` 的斜率（翻倍 → 4 倍）。外推 `n=10⁴` ≈ **0.35 s**。

**那为什么还要优化？两个必须说出口的理由：**

1. **约束只是现在宽松**。同一道题把 `n` 提到 `10⁵`（现实里的会议系统一天几万场会），`O(n²)` 就是 35 s，直接不可用。
2. **暴力在重复劳动**。每个候选时刻都把全部会议重扫一遍，而相邻两个时刻之间的重叠集合几乎没变 —— **差分** 就是把这种「没变」显式记下来。

### 第二步：卡点在哪

把问题翻译成一句话：

> **求一维时间轴上，被区间覆盖的点的最大覆盖次数（最大重叠数）。**

暴力的卡点是：**它把「覆盖数」当成「每次都要重新数一遍的量」，而没有意识到它是一个可以增量维护的量。**

一旦承认「可增量维护」，路线就分岔成两条，而且两条都只差一个「数据结构的形状」：

| 你选择的「增量维护」形态 | 得到的算法 |
| --- | --- |
| 事件序列 `+1 / -1`，沿时间轴累加 | **差分 / 事件扫描**（`O(n log n)`，排序主导） |
| 两条已排序的端点序列，双指针互相追赶 | **扫描线双指针**（`O(n log n)`，两次排序） |
| 只维护「当前占着的房间里最早空出来的那间」 | **排序 + 小顶堆**（`O(n log n)`，一次排序 + 堆） |

### 第三步：灵感的来源 —— 「堆里只留最早结束的那间」

真实世界里排会议室的贪心动作是这样的：

> 新会议来了，先看**有没有房间已经空出来**。要判断「有没有空房」，只需要知道**所有占用中房间里最早结束的那个结束时刻**。

「只关心所有元素里的最小值，而且允许随时插入、随时取出最小值」—— 这**就是小顶堆的定义**。于是：

```
排序（按 start 升序，保证"房间一定会先空出来再被复用"的判断方向一致）
  ↓
新会议 start_s：若 堆顶(最早结束) <= start_s → 弹掉（这间空出来了，复用）
  ↓
压入 end_e，堆大小就是此刻占用数，取 max
```

**这一步的关键观察是：不需要知道「哪间房给了哪个会议」，只需要知道「最早什么时候能有空房」。** 把「要决策的对象」从「n 个房间」压缩到「1 个堆顶」，复杂度就从 `O(n²)` 掉到 `O(n log n)`。

> 这正是本书反复出现的降维套路：**当你要在 n 个候选里挑一个时，问自己「我需要的那个候选有什么特征」，然后用只维护这个特征的结构。**

## 035.3 原理拆解

### 035.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力逐时刻计数 | O(n²) | O(1) | 8 行 | `n ≥ 10⁵`；`n=10⁴` 已 0.35 s（本机外推） |
| 按秒开差分数组 | O(n + T)，`T = max_end` | O(T) | 10 行 | 时间上界变大（`10⁹`）→ 内存直接爆；`T` 远大于 `n` 时纯浪费 |
| **差分 / 事件扫描** ✅ | **O(n log n)** | **O(n)** | 20 行 | 要输出「哪个会议进哪间房」时无能为力（只给了数，没给方案） |
| **扫描线双指针** ✅ | **O(n log n)** | **O(n)** | 20 行 | 同上；且要额外维护两个数组，复用现场时要注意 |
| **排序 + 小顶堆** ✅ | **O(n log n)** | **O(n)** | 22 行 | 常数比双指针大（每次 `log n` 的堆操作）；`n ≤ 10⁴` 时几乎无感，`n=10⁶` 时差距显现 |

**实测对照**（Go 1.19，同一台机器，`n = 10⁴` 随机区间、长度 1~600）：

| 实现 | 耗时 / 次 | 相对最慢 |
| --- | --- | --- |
| 扫描线双指针 | **2.38 ms** | 1.0×（最快） |
| 排序 + 小顶堆 | 3.30 ms | 1.4× |
| 差分 / 事件扫描 | 6.53 ms | 2.7×（事件是二元组，比较成本高） |
| 暴力逐时刻计数（外推） | ≈ 350 ms | ≈ 147× |

> **结论（面试可以直接这么说）**：**只求数量**，扫描线双指针最快（两次 `int` 排序，缓存友好）；**要求分配方案/输出具体房间号**，必须用小顶堆；**差分**是这题的「母模型」，写成事件数组能一行不改地迁移到 [LC 1094 拼车](https://leetcode.cn/problems/car-pooling/)、[LC 731 我的日程安排表 II](https://leetcode.cn/problems/my-calendar-ii/) 那类「带容量约束」的题上。

### 035.3.2 为什么这个做法是对的（正确性论证）

**命题**：设全部 `start` 的集合为 `S`，定义 `overlap(t) = #{ i : start_i <= t < end_i }`，则答案 `= max_{t ∈ S} overlap(t)`。

**第一步：最大值确实在某个 `start` 处取到。**
把时间轴按所有端点切成若干「原子段」，在每段内部 `overlap` 是常值。任取一段 `(a, b)`，其中 `a` 是某个端点：
- 若 `a` 是某会议的 `start`，则该段的值 `= overlap(a)`，已被 `S` 覆盖；
- 若 `a` 只是某些会议的 `end`，说明这一段是「若干会议结束之后」的状态，而该状态一定在更早的某个 `start` 处也出现过（时间轴最左端 `overlap = 0`，单调走过来的）。∎

**第二步：小顶堆解算出来的正是每个 `start` 处的 `overlap`。**
排序后依次处理第 `i` 个会议（`s_i` 升序），维护不变量：

> **不变量 `I(i)`**：处理完第 `i` 个会议后，堆中恰好是集合 `{ j ≤ i : e_j > s_i }` 的结束时刻（多重集）。

- **初始**：`i = 0`，堆里只有 `e_0`，且 `e_0 > s_0`（约束保证 `s < e`），成立。
- **保持**：处理 `i+1` 时，先弹掉所有 `e_j <= s_{i+1}` 的元素（这些会议在 `s_{i+1}` 之前已结束，不再占房）；此时堆里剩下的正是 `{ j ≤ i : e_j > s_{i+1} }`；再压入 `e_{i+1}`，得到 `{ j ≤ i+1 : e_j > s_{i+1} }`，`I(i+1)` 成立。
- 注意：**「弹掉所有」在代码里只写了「弹掉一个」** —— 这是合法的，因为堆顶是最小值：只要堆顶 `<= s_{i+1}` 就弹，用 `if` 弹一次就够了（一次新会议只会腾出、也只可能复用一个房间，弹多了反而错）。
- **终止**：由 `I(i)`，堆的大小 `= #{ j ≤ i : e_j > s_i } = overlap(s_i)`。对 `i` 取 max，由第一步即得答案。∎

**扫描线双指针的正确性**（不变量写法）：设 `i` 为下一个待处理的 `start` 下标、`j` 为下一个待处理的 `end` 下标。不变量：

> `cur = i - j`，并且 `cur` 恰是「在处理完 `starts[i-1]` 之后仍在进行的会议数」。

- 当 `starts[i] < ends[j]`，说明下一个事件是「开始」，`cur++`；
- 否则下一个事件是「结束」，`cur--`。
因为 `j <= i` 恒成立（不可能先结束一个还没开始的会议），所以 `j` 不会越界，两数组各自走完一遍即止。
唯一需要注意的就是 `starts[i] < ends[j]` 这个**严格小于**：它编码了「端点相接不算冲突」这半开区间语义。

**差分法的正确性**：答案等于事件序列（`start: +1`、`end: -1`，同刻 `-1` 在前）前缀和的最大值。这是「区间加一 + 单点求值」的离散化版本：每个会议等价于对 `[s, e)` 整体加一，答案就是全局最大值。∎

### 035.3.3 通用解题思路（可迁移的那一层）

**本章主题：同一个问题的三种「增量维护」形态，以及它们什么时候必须分开。**

```
             问题：一维时间轴上的最大重叠数
                          │
        ┌─────────────────┼──────────────────┐
        │                 │                  │
   「占用数」可以       「端点已排序」      「只需要最早的
    增量累加 → 差分       → 双指针互为事件    结束时刻」→ 小顶堆
        │                 │                  │
   O(n log n) 排序      O(n log n) 排序     O(n log n) 排序
   事件数组 2n 个        两次 int 排序       一次排序 + n 次堆操作
        │                 │                  │
   能给「每时刻占用数」  常数最小、代码最短    ✅ 能给出「哪个会议进哪间房」
```

三个解**互为验证**：写完一个，用另外两个对拍，是本章最省事的自检方式（见 `035.5.4`）。

属于同一模型的题（都是「区间 → 点上的加一 → 求最大/求和」）：

| 题 | 被差分的对象 | 与本题的关系 |
| --- | --- | --- |
| [LC 253 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/) | 时间轴 +1，求**最大**前缀和 | 母题 |
| [LC 2406 将区间分为最少组数](https://leetcode.cn/problems/divide-intervals-into-minimum-number-of-groups/) | 同上，但区间**闭合** | 免费替代练习；注意 tie-break 相反 |
| [LC 1094 拼车](https://leetcode.cn/problems/car-pooling/) | 站点上 `+num / -num`，求**每站是否超容量** | 同一套事件扫描，只是判据从「求 max」变成「与容量比」 |
| [LC 731 我的日程安排表 II](https://leetcode.cn/problems/my-calendar-ii/) | 时间轴 +1，判**是否出现 3 重预订** | 动态插入版：边插边判 `max <= 2` |
| [LC 1109 航班预订统计](https://leetcode.cn/problems/corporate-flight-bookings/) | 差分数组的标准模板题 | 若把「按秒开数组」写出来，就是这道题 |
| [LC 56 合并区间](https://leetcode.cn/problems/merge-intervals/) | 先排序再按左端点扫描 | 区间题的「入口动作」：排序 |

**共同点**：都是「把区间上的操作压成端点上的两个事件，然后一次前缀扫描解决一切」。

### 035.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要输出**具体的房间分配** | 从「求数」变「构造方案」 | 只用小顶堆不够（堆里丢了房间号）→ 堆里存 `(结束时刻, 房间号)`，弹出即复用，答案就是每次分配的房间号集合 |
| 求**最大重叠发生的时间段** | 要位置不只数值 | 差分法天然给出：记录取到最大值的时刻区间；双指针法要额外记录「上一次 cur 变大时的 t」 |
| **动态**增删会议（在线） | 输入是数据流 | 差分法失效（要重排序）→ 用「按 start 有序 + 按 end 有序」的两棵平衡树，或直接堆 + 延迟删除 |
| 只问「**k 间房够不够**」 | 判定问题 | 与求最大重叠等价：`maxOverlap <= k`；若只要「不够就早退」，扫描时 `cur > k` 即可返回 |
| 每个会议**有优先级**（高优先级可抢占） | 语义变了 | 变成「区间调度 + 抢占」，需要按优先级分层处理，不能再用单层最大重叠 |
| 会议**可拆分**（可在中途换房间） | 题目被弱化 | 答案退化：只要总时长、房间数、时间窗口一致即可，与「重叠」无关 —— 说明「不可拆分」才是本题的难点来源 |

**进阶延伸（自己写代码验证）**：

- **LC 2402 会议室 III**：房间有编号、优先用编号小的，还要统计「开最多会的那间」—— 是本题的「堆里存房间号」加强版。
- **LC 252 会议室**：只问「一个人能不能参加全部会议」，等价于「最大重叠数是否 `<= 1`」，即排序后检查相邻区间是否重叠，`O(n log n)` 一步到位。
- **LC 759 员工空闲时间**（会员题）：反过来求「所有员工都在的空闲区间」，是「多区间求交」而非「求最大重叠」。

## 035.5 双语言实现

### 035.5.1 Java

```java
import java.util.Arrays;
import java.util.PriorityQueue;

class Solution {
    // 方案 A（主推）：排序 + 小顶堆。堆里存"仍在使用中的会议的最早结束时刻"
    public int minMeetingRooms(int[][] intervals) {
        if (intervals.length == 0) return 0;          // 空输入：0 间房，不是 -1

        // 先复制一份，避免就地修改调用方的数组（LC 上无害，工程里是硬规矩）
        int[][] iv = new int[intervals.length][];
        for (int i = 0; i < intervals.length; i++) {
            int s = intervals[i][0];
            int e = intervals[i][1];
            if (e <= s) e = s + 1;      // 防御：零长会议按"占一个瞬间"处理
            iv[i] = new int[]{s, e};
        }
        // 按 start 升序；start 相同时按 end 升序，保证"先结束的先被复用"这个顺序稳定
        Arrays.sort(iv, (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0])
                                              : Integer.compare(a[1], b[1]));

        PriorityQueue<Integer> endHeap = new PriorityQueue<>();   // 默认小顶堆
        int peak = 0;
        for (int[] cur : iv) {
            // 只要最早结束的那间已经腾空（<= start），就复用它。
            // 用 if 而不是 while：一间房被腾出后占用数只减 1，多弹会少算房间
            if (!endHeap.isEmpty() && endHeap.peek() <= cur[0]) {
                endHeap.poll();
            }
            endHeap.offer(cur[1]);
            peak = Math.max(peak, endHeap.size());   // 堆大小 = 此刻占用的房间数
        }
        return peak;                                  // 不能用 endHeap.size() 代替（见 035.4.3）
    }

    // 方案 B：starts / ends 双数组排序 + 双指针（扫描线），常数最小
    public int minMeetingRoomsSweep(int[][] intervals) {
        int n = intervals.length;
        if (n == 0) return 0;
        int[] starts = new int[n];
        int[] ends = new int[n];
        for (int i = 0; i < n; i++) {
            int s = intervals[i][0];
            int e = intervals[i][1];
            if (e <= s) e = s + 1;
            starts[i] = s;
            ends[i] = e;
        }
        Arrays.sort(starts);
        Arrays.sort(ends);
        int i = 0, j = 0, cur = 0, best = 0;
        while (i < n) {                 // i 走完就停：剩下的 end 只会让 cur 变小
            if (starts[i] < ends[j]) {  // 严格小于：端点相接可以复用同一间房
                cur++;
                best = Math.max(best, cur);
                i++;
            } else {
                cur--;
                j++;
            }
        }
        return best;
    }

    // 方案 C：差分 / 事件扫描。+1 在 start，-1 在 end，同刻 -1 先结算
    public int minMeetingRoomsDiff(int[][] intervals) {
        int n = intervals.length;
        int[][] events = new int[2 * n][];
        for (int i = 0; i < n; i++) {
            int s = intervals[i][0];
            int e = intervals[i][1];
            if (e <= s) e = s + 1;
            events[2 * i] = new int[]{s, 1};
            events[2 * i + 1] = new int[]{e, -1};
        }
        // 同刻先处理 -1：等价于半开区间 [s, e)，端点相接不累加
        Arrays.sort(events, (a, b) -> a[0] != b[0] ? Integer.compare(a[0], b[0])
                                                   : Integer.compare(a[1], b[1]));
        int cur = 0, best = 0;
        for (int[] ev : events) {
            cur += ev[1];
            best = Math.max(best, cur);
        }
        return best;
    }
}
```

### 035.5.2 Go

```go
package main

import (
	"container/heap"
	"sort"
)

// 方案 A（主推）：排序 + 小顶堆
func minMeetingRooms(intervals [][]int) int {
	if len(intervals) == 0 {
		return 0
	}
	type iv struct{ s, e int }
	ivs := make([]iv, 0, len(intervals))
	for _, x := range intervals {
		s, e := x[0], x[1]
		if e <= s { // 防御：零长会议按"占一个瞬间"处理
			e = s + 1
		}
		ivs = append(ivs, iv{s, e})
	}
	// 稳定排好"开始时间"，后面才敢用"堆顶 <= 新 start"判断复用
	sort.Slice(ivs, func(i, j int) bool {
		if ivs[i].s != ivs[j].s {
			return ivs[i].s < ivs[j].s
		}
		return ivs[i].e < ivs[j].e
	})
	h := &endHeap{}
	peak := 0
	for _, cur := range ivs {
		if h.Len() > 0 && (*h)[0] <= cur.s { // 最早结束的那间已腾空 → 复用
			heap.Pop(h)                      // 只弹一个，弹多了会少算房间
		}
		heap.Push(h, cur.e)
		if h.Len() > peak {
			peak = h.Len()
		}
	}
	return peak
}

// Go 的小顶堆必须实现 heap.Interface 的 5 个方法（Java 的 PriorityQueue 只需 new 一下）
type endHeap []int

func (h endHeap) Len() int            { return len(h) }
func (h endHeap) Less(i, j int) bool  { return h[i] < h[j] }
func (h endHeap) Swap(i, j int)       { h[i], h[j] = h[j], h[i] }
func (h *endHeap) Push(x interface{}) { *h = append(*h, x.(int)) }
func (h *endHeap) Pop() interface{} {
	old := *h
	n := len(old)
	v := old[n-1]
	*h = old[:n-1]
	return v
}

// 方案 B：扫描线双指针
func minMeetingRoomsSweep(intervals [][]int) int {
	n := len(intervals)
	if n == 0 {
		return 0
	}
	starts := make([]int, n)
	ends := make([]int, n)
	for i, x := range intervals {
		s, e := x[0], x[1]
		if e <= s {
			e = s + 1
		}
		starts[i], ends[i] = s, e
	}
	sort.Ints(starts)
	sort.Ints(ends)
	i, j, cur, best := 0, 0, 0, 0
	for i < n {
		if starts[i] < ends[j] { // 严格小于 = 端点相接可复用
			cur++
			i++
			if cur > best {
				best = cur
			}
		} else {
			cur--
			j++
		}
	}
	return best
}

// 方案 C：差分 / 事件扫描
func minMeetingRoomsDiff(intervals [][]int) int {
	type event struct{ t, delta int }
	events := make([]event, 0, len(intervals)*2)
	for _, x := range intervals {
		s, e := x[0], x[1]
		if e <= s {
			e = s + 1
		}
		events = append(events, event{s, +1}, event{e, -1})
	}
	sort.Slice(events, func(i, j int) bool {
		if events[i].t != events[j].t {
			return events[i].t < events[j].t
		}
		return events[i].delta < events[j].delta // 同刻 -1 先：半开区间语义
	})
	cur, best := 0, 0
	for _, ev := range events {
		cur += ev.delta
		if cur > best {
			best = cur
		}
	}
	return best
}

func main() {}
```

### 035.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 堆的接入成本 | `new PriorityQueue<>()` 一行搞定，默认小顶堆 | 必须实现 `heap.Interface` 的 5 个方法 | Go 方案 A 多出 10 行样板；方案 B（双指针）零样板，这也是 Go 选手常选 B 的原因 |

| 空输入返回 | `return 0` | `return 0` | 两边都要显式判 `len == 0`，否则 `ends[0]`/`(*h)[0]` 越界 |

### 035.5.4 对拍测试（三解互证 + O(n²) 暴力基准）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力：O(n²) 逐时刻计数 —— 候选时刻取每个会议的 start（峰值必在其中）
func bruteMeetingRooms(intervals [][]int) int {
	if len(intervals) == 0 {
		return 0
	}
	best := 0
	for _, probe := range intervals {
		t := probe[0]
		cnt := 0
		for _, x := range intervals {
			s, e := x[0], x[1]
			if e <= s { // 与三个正解共用同一套零长会议口径
				e = s + 1
			}
			if s <= t && t < e {
				cnt++
			}
		}
		if cnt > best {
			best = cnt
		}
	}
	return best
}

func TestMeetingRoomsRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024)) // 固定种子，失败可复现
	for iter := 0; iter < 6000; iter++ {
		n := 1 + r.Intn(8)
		intervals := make([][]int, n)
		for i := range intervals {
			s := r.Intn(9)
			e := s + r.Intn(4) // ★ 故意包含 e == s 的零长会议
			intervals[i] = []int{s, e}
		}
		want := bruteMeetingRooms(intervals)
		if got := minMeetingRooms(intervals); got != want {
			t.Fatalf("heap  iter=%d intervals=%v got=%d want=%d", iter, intervals, got, want)
		}
		if got := minMeetingRoomsSweep(intervals); got != want {
			t.Fatalf("sweep iter=%d intervals=%v got=%d want=%d", iter, intervals, got, want)
		}
		if got := minMeetingRoomsDiff(intervals); got != want {
			t.Fatalf("diff  iter=%d intervals=%v got=%d want=%d", iter, intervals, got, want)
		}
	}
	// 极端样例：1000 个完全重叠的会议 → 必须 1000
	big := make([][]int, 0, 1000)
	for i := 0; i < 1000; i++ {
		big = append(big, []int{0, 1})
	}
	if got := minMeetingRooms(big); got != 1000 {
		t.Fatalf("big got=%d want=1000", got)
	}
}
```

> **为什么值域要设成 `[0, 8]` 而长度设成 `0~3`**：小范围才好频繁制造「端点撞在一起」和「零长会议」这两类边界。**随机测试的价值不在覆盖正常情况，而在高频制造边界。**
> **为什么三解都要跑**：它们是三条独立路径（堆 / 双指针 / 差分），任何一条写错 tie-break（`<` 写成 `<=`），都会被另外两条当场抓住 —— 这就是「一题多解」在工程上的真实收益。

## 035.6 复杂度与常见坑

### 035.6.1 复杂度推导

- **小顶堆**：排序 `O(n log n)`；每个会议做一次 `push`（可能再加一次 `pop`），各 `O(log n)`，合计 `O(n log n)`；循环里 `peek` 是 `O(1)`。总时间 `O(n log n)`，空间 `O(n)`（堆最多同时装下 n 个 end）。
- **扫描线双指针**：两次 `int` 排序 `O(n log n)`（常数极小），双指针扫描 `O(n)`。空间 `O(n)`（两个数组），若允许就地改输入则是 `O(1)` 额外空间以外仍要两个数组。
- **差分**：`2n` 个事件排序 `O(n log n)`，扫描 `O(n)`，空间 `O(n)`。
- **为什么不能用「按秒开数组」**：空间 `O(max_end)`，本题 `max_end ≤ 10⁶` 尚可（约 4 MB），但它是**伪多项式**复杂度 —— 时间上界一旦变成 `10⁹`，这个算法直接不可用。写「坐标压缩 + 差分」的版本才是通用解。
- **堆操作均摊**：`push`/`pop` 单次最坏 `O(log n)`，`n` 次操作总计 `O(n log n)`，无「均摊」的说法（这里每一步都是最坏界，不是均摊界）。

### 035.6.2 七个真实踩过的坑

1. **`return heap.size()` 而不是循环取 max** —— 最高频错误。`[[0,1],[0,1],[2,3]]` 会返回 1（正确 2），见 `035.4.3` 的推演。
2. **零长会议 `[t, t]`** —— LC 253 约束写了 `start < end`，但工程数据里「0 分钟会议」很常见。三解在零长会议上**默认口径并不一致**：双指针解 `/` 差分解会把它算成 0 间，堆解会算成 1 间。本文统一在入口做 `if (e <= s) e = s + 1`，让三解一致；面试被问到时，**先声明语义再写代码**比直接写更重要。
3. **`starts[i] < ends[j]` 写成 `<=`** —— `[[0,5],[5,10]]` 会返回 2（正确 1）。这一个字符就是「半开 vs 闭合」的全部区别，也是 LC 253 与 LC 2406 的分界线。
4. **弹堆时用了 `while`** —— 一次新会议只能复用一间房。`while (heap.peek() <= start) heap.poll()` 会把「本来还要占着的房间」也弹掉，`[[0,100],[1,2],[3,4],[5,6]]` 会算成 1（正确 2）。
5. **只比较「相邻两个区间是否重叠」** —— `[[1,5],[2,6],[3,7],[4,8]]` 会被算成 2，正确是 4。重叠不是传递的局部性质，必须扫全程。
6. **忘了 `intervals.length == 0`** —— Java 里 `ends[0]` 抛 `ArrayIndexOutOfBoundsException`，Go 里 `(*h)[0]` panic；`intervals = []` 的正确答案是 0。
7. **Java 排序用 `a[0] - b[0]` 做比较器** —— 端点最大到 `10⁶`，这里不会溢出；但只要有一题把值域放到 `±2³¹`，`a-b` 就会溢出成反向结果。**统一写 `Integer.compare(a[0], b[0])`** 是安全习惯。

### 035.6.3 面试官最爱追问的三个问题

**Q1：小顶堆里为什么只存 `end`，不存房间号？**
> 「因为题目只要数量。判断『能不能复用』只依赖『最早结束时刻』这一个标量，房间号是无关信息 —— 存了反而把状态从 1 个数膨胀成 1 个二元组。如果追问变成『输出每个会议分到第几间房』（LC 2402 的方向），就必须存 `(结束时刻, 房间号)`，此时堆的本质是『可用房间优先队列』，弹出来的就是可以直接复用的那一间。」

**Q2：扫描线双指针和差分事件法有什么区别？**
> 「数学上是同一个东西：都在点数轴上 ±1 事件的前缀和。差别在『怎么把事件排好序』—— 双指针把事件拆成两个已排序数组，靠 `i/j` 双向追赶隐含地完成归并，所以只要两次 `int` 排序、常数最小（本机 n=10⁴ 实测 2.38 ms vs 6.53 ms）；事件法显式构造 `2n` 个二元组再排一次，多出来的内存和比较开销在这种「只有加减」的场景下是纯浪费。但事件法的写法能直接迁移到『每个事件带不同增量』的题（如 LC 1094 拼车带人数），双指针法就不行了。」

**Q3：如果时间是浮点数 / 精度不确定，怎么办？**
> 「半开区间语义 `[s, e)` 在整数上靠『同刻 -1 先结算』来编码，浮点上没有『同刻』这个概念，但也不受影响 —— 因为排序只依赖比较，浮点比较仍然是全序（除 NaN）。真正的风险是**相等性判断**：浮点里 `[0, 5.0]` 与 `[5.0, 10.0]` 端点相等的概率极低但非零，业务上通常约定『时间精确到分钟』再转整数处理，把浮点问题彻底消灭在入口。」
