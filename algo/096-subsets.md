## 096.1 题目

**原题链接**：<https://leetcode.cn/problems/subsets/>

### 题意重述（把隐含条件补齐）

给你一个**元素互不相同**的整数数组 `nums`，请你返回该数组**所有可能的子集**（幂集），要求：

- 子集内部元素顺序不限，但**同一个子集只能出现一次**；
- 解集里不能包含重复的子集；
- 可以按**任意顺序**返回解集。

一句话：「把 `n` 个不同的东西，每个『拿或不拿』的所有组合方式全部列出来」。`n` 个元素，每个两种选择，所以答案的**数量**恒为 `2^n` —— 这一点必须先算出来，因为它直接决定了这题的时间下界。

四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **元素互不相同** | 「数组中的元素 **互不相同**」 | 这条是本题与 [097](097-subsets-ii.md) 的唯一差别；一旦有重复值，`[1,2]` 与「另一个 `2` 配 `1`」会产生两个**值相同**的子集，必须去重 |
| **空集算一个解** | 「所有可能的子集」 | 漏掉 `[]` 是最高频 WA。`n` 个元素共 `2^n` 个解，含空集与全集 |
| **输出方案集合，不是方案个数** | 「返回所有可能的子集」 | 只返回 `1 << n` 那个数字 → WA；也意味着时间下界是 `Ω(n·2^n)`（输出本身就这么大） |
| **顺序任意** | 「解集不能包含重复的子集。你可以按任意顺序返回解集」 | 不必为「字典序」额外写代码；但**对拍时**必须自己把结果规范化排序再比（见 §096.5.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 10` | n 至多 10 | `2^10 = 1024` 个解，任何 `O(n·2^n)` 的写法都不到 1 万次操作，本机实测 **Java ≈ 0.4 ms、Go ≈ 0.3 ms**。这个 `n ≤ 10` 是出题人给的暗号：**他在请你写指数级枚举** |
| `-10 <= nums[i] <= 10` | 值域极小 | 值域小到可以用「值 → 下标」做桶，但本题元素互不相同，值域大小不影响算法 |
| 解的数量 = `2^n` | 与元素无关 | 一个 `n = 20` 的输入就要输出 104 万个子集、约 2000 万个整数，**内存先炸**。所以约束不会放大到 20 |
| 元素互不相同 | 全排列成立 | 不需要任何去重逻辑 —— 这正是 096 适合当基准章的原因：**先把决策树本身写对，再叠加去重** |

> 💡 **量级反推**：`n ≤ 10` 与「答案是 `2^n` 个集合」这两条放在一起，等于告诉你：**这题不存在多项式解法，考的是枚举的「组织方式」而不是「优化」。** 面试里如果有人说「能不能用 DP 更快」，答案是：输出规模已经是 `Θ(n·2^n)`，不可能更快，DP 只能回答「有多少个」，不能回答「分别是哪些」。

### 示例

```text
输入：nums = [1,2,3]
输出：[[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]      ← 共 8 个 = 2^3，顺序任意

输入：nums = [0]
输出：[[],[0]]                                        ← 共 2 个 = 2^1

输入：nums = [1,2,3,4]  （自造，用于手推）
输出：16 个，其中长度分布为 1 + 4 + 6 + 4 + 1 = 16     ← 二项式系数行 C(4,k)
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [1]                → 暴露「漏空集」：正确应是 [[],[1]] 两个
② [1,2]              → 暴露「只收集叶子」：中间结点 [1]、[2] 也必须收集
③ [3,1,2]（乱序）    → 暴露「以为结果必须有序」：本题允许任意顺序，但若按值排序输出就要先 sort
④ [1,2,3] 长度分布    → 数一数输出里 |S|=0,1,2,3 各几个，应恰好 1,3,3,1
```

第 ② 条是本章的核心：**子集问题的解分布在决策树的「所有结点」上，不只在叶子上**。组合问题（098）的解才只在叶子上。这个区别决定了「收集」这一行写在哪。

## 096.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 —— 「用循环枚举」

绝大多数人第一反应是「那就套循环」：

```text
for i in 0..n:              // 选第一个元素
    for j in i+1..n:        // 选第二个
        for k in j+1..n:    // 选第三个
            ...
```

写到第三个循环就会发现：**循环层数由 `n` 决定，而代码里的 `for` 层数是写死的**。想枚举长度为 0、1、2、…、`n` 的所有子集，你得写 `n+1` 段结构相同的代码。这不是「写得丑」，而是**根本没有这个控制流**。

所以第一个念头的错误不是「复杂度高」，而是「**表达不出来**」。这类题必须换一种控制流：**递归**。

### 第二步：暴力但可行的写法 —— 位掩码

先给出一个「能跑」的暴力，作为后面所有对拍的基准：

```text
for mask in 0 .. (1<<n)-1:            // mask 的每一位 = 一个元素「拿/不拿」
    subset = []
    for i in 0..n-1:
        if mask >> i & 1:  subset.append(nums[i])
    ans.append(subset)
```

- 时间 `O(n·2^n)`，空间 `O(n)`（不算结果）。
- 它**正确**且**够快**（`n=10` 时 10240 次操作）。
- 那为什么还学回溯？三个理由，面试里必须能说出来：

| 理由 | 具体说明 |
| --- | --- |
| **位掩码只能解「每个元素二选一」** | 换成「每个元素可选 0~k 次」（099 组合总和）、「从 n 个里选 k 个」（098）、「切成若干段」（105），位掩码立刻失效 —— 因为选择的分支数不是 2 |
| **剪枝无处安放** | 098 要在「剩余元素不够凑满 k 个」时提前停，107 要在网格越界时提前停。位掩码是「先定死 mask 再展开」，**没有任何中间状态可以用来剪枝** |
| **它不产生中间解** | 子集题的答案就在树的中间结点上。位掩码每次都要从头展开全长 `n` 位，天然丢掉了「前缀」这个概念 |

> 📌 结论：**位掩码是「答案的编码」，回溯是「答案的生成过程」。** 编码只在这道题好用，生成过程可以搬到 12 道题上。本章的价值在后者。

### 第三步：卡点在哪 —— 「选择」这个概念没人定义过

把问题用自然语言重说一遍：

> 对每个元素，做一个「拿」或「不拿」的决定；把所有决定串起来，就得到一个子集。

这句话里藏着一个我们还没定义的对象：**「部分解」**。`[1]` 是部分解吗？当然是 —— 它是「已经决定拿 1，2 和 3 还没决定」的那个中间状态。那么：

- 结点 = 一个部分解（一串已经做过的决定）；
- 边 = 一次决定（拿 `nums[i]`，或者跳过它）；
- 叶子 = 所有决定都做完的状态。

于是「枚举所有子集」= 「遍历这棵树的**所有结点**」。**卡点从「怎么写循环」变成了「怎么定义结点和边」**，一旦定义清楚，代码就只有 6 行。

### 第四步：灵感的来源 —— 两种同样合法的「边」的定义

这是本章最值得记住的一点：**同一道题，决策树不是唯一的**。有两种定义都能枚举出全部子集，它们的差别正是整个第 10 部分的分水岭。

**定义 A（二叉决策树）**：结点 = `(下标 i, 已选集合)`，边 = 「不选 `nums[i]`」或「选 `nums[i]`」，然后 `i` 一定 `+1`。每个结点**恰好两条**出边。

**定义 B（起点递增枚举）**：结点 = `(起点 start, 已选集合)`，边 = 「选 `nums[i]`，其中 `i` 从 `start` 到 `n-1`」，递归时把起点推到 `i+1`。每个结点有 `n - start` 条出边。

```text
定义 A（二叉）                        定义 B（起点递增）
            (0,[])                            (0,[])
        ┌─────┴─────┐                    ┌──────┼──────┐
   不选1│           │选1              选1│   选2│      │选3
     (1,[])      (1,[1])              (1,[1]) (2,[2]) (3,[3])
     ┌──┴──┐     ┌──┴──┐              ┌──┴──┐   │
  不选2  选2  不选2  选2           选2│  选3│ 选3│
  (2,[]) (2,[2]) ...  ...        (2,[1,2]) (3,[1,3]) (3,[2,3])
   ...                                  │
  叶子：[] [2] [1] [1,2] ...       (3,[1,2,3])
  8 个叶子 = 8 个子集               每个结点都是一个子集
```

**两种定义的等价性**：A 的每个叶子对应一个长度为 `n` 的 0/1 串；B 的每条「根到结点」的路径对应一个严格递增的下标序列 `i₁ < i₂ < … < i_k`。两者通过「0/1 串 ↔ 其中为 1 的位置集合」建立双射。**所以它们枚举的是同一个集合族，只是遍历顺序不同。**

**那为什么 B 更常被用？** 因为 B 有一个 A 没有的性质：**每个结点本身就是答案**，不需要等到叶子；而且 B 的「下一层只能从 `i+1` 起」这条约束，天然保证「同一个集合不会被不同顺序枚举」——这一点在 097 的去重、098 的剪枝、099 的重复选取里都是基础的承重结构。

## 096.3 原理拆解

### 096.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 位掩码迭代 | `O(n·2^n)` | `O(n)` | 8 行 | 选择分支 ≠ 2（098/099/105）；需要剪枝；`n > 20` 时 `1<<n` 溢出 |
| 二叉决策树递归（定义 A） | `O(n·2^n)` | `O(n)` 栈 | 12 行 | 有重复元素时去重极难写（要靠 `used` 数组式判断）；无法写「剩余数量不足」剪枝 |
| **起点递增枚举（定义 B）** ✅ | `O(n·2^n)` | `O(n)` 栈 | **10 行** | 解与「顺序」有关时（101 全排列），起点递增会**漏掉大量解** |
| 递归 `f(n) = f(n-1) ∪ {S ∪ {a[n]}}` | `O(n·2^n)` | `O(n·2^n)` 中间结果 | 10 行 | 函数式写法，会复制大量中间集合，常数最大 |

**为什么「起点递增」是子集/组合类的默认选择**：它用一句话就把「不重不漏」编码进了结构里 —— **下一层的起点严格大于本层选的下标**，所以任何一组成员下标都是严格递增的，而任何子集都恰好有**一个**严格递增的下标序列。这个「规范形」就是正确性证明的核心（见 096.3.2）。

**为什么全排列不能用它**：全排列的解是 `[2,1,3]` 这种「顺序有意义」的序列，下标序列不必递增。用起点递增枚举只能生成 `[1,2,3]` 这一个排列。101 因此必须换成 `used` 数组（见 [101](101-permutations.md)）。

### 096.3.2 为什么这个做法是对的（正确性论证）

要证两件事：**（A）不漏**、**（B）不重**。我们为定义 B 建立完整的论证，这个论证模板会在 097–100、105 里反复出现。

**（A）不漏解**

设 `S` 是任意一个子集，把它写成下标集合 `{i₁ < i₂ < … < i_k}`（`k ≥ 0`，`k = 0` 是空集）。考察 `dfs(0, [])` 的执行：

1. 第一层循环 `i` 从 `0` 走到 `n-1`，所以一定会走到 `i = i₁` 这一支；
2. 进入后 `path = [nums[i₁]]`，递归调用 `dfs(i₁+1, …)`；
3. 在 `dfs(i₁+1, …)` 里，`i` 从 `i₁+1` 走到 `n-1`，所以一定会走到 `i = i₂`（因为 `i₂ > i₁`）；
4. 依此类推，第 `k` 层到达时 `path = [nums[i₁], …, nums[i_k]]`，而这正是 `S`。

所以 `S` 会在某个结点上被收集（定义 B 在每个结点收集，所以事实上在路径上的**每一个前缀**都会被收集，`S` 是最后一个）。∎

**（B）不重复**

**引理**：任意非空子集 `S` 对应的下标集合是唯一的（因为 `nums` 元素互不相同，`S` 里每个值只对应一个下标）。设其为 `i₁ < … < i_k`。

**断言**：`dfs` 中产生 `path = S` 的那条根到结点的路径，其下标序列必定就是 `i₁, …, i_k`。

反证：假设某条路径按下标 `j₁ < j₂ < … < j_k` 选取且值集合等于 `S`。由元素互不相同，值集合相等 ⟹ 下标集合相等 ⟹ `jₘ = iₘ`（排序后逐项相等）。∎

于是「路径 ↔ 子集」是**双射**，不重不漏同时成立。

> **这个论证的可迁移性**：它其实在说「**只要给每个解指定一个唯一的规范形（canonical form），并且让算法恰好枚举全部规范形，就不需要事后去重**」。097 的「同层去重」、100 的「排序后去重」、102 的 `!used[i-1]`，全都是在**构造并枚举规范形**。记住这一句，第 10 部分就通了一半。

另外还有一个「数量对」的校验：定义 B 的树有几条「根到结点」的路径？每条路径对应一个下标子集，所以正好 `2^n` 条，与答案数量吻合。**如果数出来的结果不是 `2^n`，代码一定错了。** 这是本章最便宜的自检手段。

### 096.3.3 通用解题思路（可迁移的那一层）

以下是本部分的**母定义**，097–107 直接引用，不再重复展开：

```text
┌──────────────────────── 回溯三件套 ────────────────────────┐
│                                                          │
│  ① 决策树  ：每个结点 = 一个部分解；每条边 = 一次选择       │
│              写码前先用纸画出三层，并回答两个问题：         │
│              (a) 结点里要记什么状态？                       │
│              (b) 从这个结点出发，有几种合法的边？           │
│                                                          │
│  ② 剪枝    ：在「展开边」之前就砍掉不可能通向解的分支       │
│              (a) 可行性剪枝：越界 / 和已超出 / 剩余不够     │
│              (b) 最优性剪枝：已不可能比当前最优更好         │
│              (c) 去重剪枝  ：同一层里等价的兄弟只走第一个   │
│                                                          │
│  ③ 状态恢复：选择 → 递归 → 撤销，三步必须成对出现           │
│              (a) 容器型：append / pop（Java remove(size-1)）│
│              (b) 标记型：board[r][c]='#' / 改回原字符       │
│              (c) 集合型：set.add / set.remove               │
│              ── 少写撤销 = 状态污染，后面所有分支全错       │
└──────────────────────────────────────────────────────────┘
```

统一骨架（定义 B，本章及 097/098/099/100/105 都用它）：

```text
void dfs(int start, path, ...) {
    if (满足收集条件) { ans.add(copy(path)); }      // 或 return，看解在结点还是叶子
    for (int i = start; i < n; i++) {                // 边：从这个结点出发的所有选择
        if (剪枝(i)) continue;                       // ② 剪枝
        path.add(nums[i]);                           // ③(a) 选择
        dfs(i + 1, path, ...);                       //     递归（i+1 是本模板的灵魂）
        path.removeLast();                           // ③(b) 撤销
    }
}
```

定义 A（二叉决策树）的骨架，本章也给出，因为它在 080 打家劫舍 III、114 分割等和子集里更顺手：

```text
void dfs(int i, path) {
    if (i == n) { ans.add(copy(path)); return; }     // 解只在叶子
    dfs(i + 1, path);                                // 边 1：不选 nums[i]（无需撤销，因为没改动）
    path.add(nums[i]);                               // 边 2：选 nums[i]
    dfs(i + 1, path);
    path.removeLast();                               // 撤销
}
```

**什么时候用哪个 —— 这张表要背下来：**

| 判据 | 用定义 A（选/不选） | 用定义 B（起点递增） |
| --- | --- | --- |
| 解是否只在叶子 | 是（所有元素都做过决定才算一个解） | 否（中间结点也是解，如子集） |
| 剪枝需求 | 只有「可行性」剪枝（如背包容量） | 有「剩余数量不足」「和超出」这类**可以提前停**的剪枝 |
| 「不能重复使用同一元素」怎么保证 | 靠 `i+1`（每条边都推进下标） | 靠 `i+1` 或 `i`（099 用 `i` 表示可重复） |
| 有重复元素时去重 | **难**：同值元素在树的不同层出现，要额外维护「本层是否用过该值」 | **易**：`i > start && nums[i]==nums[i-1]` 一行（097） |
| 典型题 | 080 打家劫舍 III、114 分割等和子集、494 目标和（选正/选负） | 078 子集、090 子集 II、077 组合、039 组合总和、131 分割回文串 |

> ⚠️ 一句话判据：**「解是『集合』还是『序列』」与「解在叶子还是在结点」决定了一切。** 集合 + 结点 → 定义 B；序列（有顺序）→ 两个都不够，要 101 的 `used` 数组。

| 题 | 决策树的边是什么 | 收集时机 |
| --- | --- | --- |
| [LC 78 子集](https://leetcode.cn/problems/subsets/) | 选 `nums[i]`，下一个从 `i+1` 起 | 每个结点 |
| [LC 90 子集 II](https://leetcode.cn/problems/subsets-ii/) | 同上 + 同层去重 | 每个结点 |
| [LC 77 组合](https://leetcode.cn/problems/combinations/) | 选 `nums[i]`，下一个从 `i+1` 起 | 仅 `len == k` 的结点 |
| [LC 39 组合总和](https://leetcode.cn/problems/combination-sum/) | 选 `c[i]`，下一个从 `i` 起（可重复） | 仅 `sum == target` |
| [LC 131 分割回文串](https://leetcode.cn/problems/palindrome-partitioning/) | 切下一段 `s[start..i]` | 仅 `start == n` |

### 096.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 元素**有重复** | 数组允许重复值 | 排序 + 同层去重，见 [097](097-subsets-ii.md)；核心是「同一层遇到相同值只走第一个」 |
| 只要**大小恰为 k** 的子集 | 收集条件变了 | 加 `if (path.size() == k) 收集并 return`，再加剪枝 `i <= n-(k-len)`，见 [098](098-combinations.md) |
| 只要**和等于 target** | 边带权 | 排序 + 前缀和剪枝，见 [099](099-combination-sum.md) / [100](100-combination-sum-ii.md) |
| 只要**方案个数**，不要方案 | 只数不构造 | 直接 `2^n`；带权时用 DP（114 分割等和子集），回溯会指数爆炸 |
| `n` 涨到 20~25，但仍要枚举 | 指数级无法避免 | 位掩码 + `Gosper's hack` 按「1 的个数」枚举，或 meet-in-the-middle 拆成两半 |
| 要求**字典序**输出 | 有序性约束 | 先 `sort(nums)`，再按 `i` 递增遍历，收集顺序天然是字典序（097/100/102 都靠这一步） |

**进阶延伸（自己写代码验证）**：

- **LC 784 字母大小写全排列**：每个字母「大写/小写」二选一，是二叉决策树的直系后代。
- **LC 401 二进制手表**：从 10 个灯里选 `k` 个亮 —— 就是 098 换了个外壳。
- **LC 320 列举单词的全部缩写**（会员题）：每个字符「保留 / 缩成数字」，并且相邻数字要合并 —— 决策树上的状态比子集多一个「上一个是不是数字」。

## 096.4 图解推演

### 096.4.1 定义 B 的完整决策树（`nums = [1,2,3]`）

```text
                              dfs(start=0, path=[])
                        ┌───────────┼───────────┐
                   选1  │       选2 │       选3 │
                        ▼           ▼           ▼
             dfs(1,[1]) ★    dfs(2,[2]) ★   dfs(3,[3]) ★
              ┌────┴────┐         │
         选2  │    选3  │    选3 │
              ▼         ▼         ▼
     dfs(2,[1,2])★  dfs(3,[1,3])★  dfs(3,[2,3])★
           │
      选3  │
           ▼
     dfs(3,[1,2,3]) ★

★ = 收集点。共 1(空集) + 3 + 3 + 1 = 8 个，等于 2^3。
每个 ★ 收集时都要 copy path，否则 8 个结果会共享同一个底层数组。
```

**关键观察**：树上一共有 8 个结点（含根），**每个结点都是答案**，路径长度就是子集大小。这就是为什么定义 B 的「收集」写在函数开头而不是循环之后。

### 096.4.2 定义 A 的决策树（同一输入）

```text
                     dfs(i=0, path=[])
              ┌────────────┴────────────┐
        不选1 │                          │ 选1
              ▼                          ▼
       dfs(1,[])                    dfs(1,[1])
        ┌─────┴─────┐              ┌─────┴─────┐
   不选2│        选2│         不选2│        选2│
        ▼           ▼              ▼           ▼
   dfs(2,[])  dfs(2,[2])    dfs(2,[1])  dfs(2,[1,2])
    ┌──┴──┐    ┌──┴──┐       ┌──┴──┐     ┌──┴──┐
 不选3 选3  不选3 选3     不选3 选3    不选3 选3
   []  [3]  [2] [2,3]      [1] [1,3]  [1,2] [1,2,3]
   ↑
   8 个叶子 = 8 个子集，中间结点不是答案（只有走到 i==n 才算数）
```

**对比结论**：两棵树的**叶子/结点集合完全相同**（8 个解），但形状不同 —— A 是满二叉树（`2^(n+1)-1` 个结点，其中一半是「无意义的中间态」），B 只有 `2^n` 个结点（**每个结点都有用**）。所以 B 的常数更小。

### 096.4.3 一次完整的执行轨迹（定义 B，逐行跟踪）

| 步骤 | 调用 | `path`（选择后） | 收集？ | 循环 `i` 的取值 | 撤销后 `path` |
| --- | --- | --- | --- | --- | --- |
| 1 | `dfs(0)` | `[]` | ✅ 收集 `[]` | i=0,1,2 | — |
| 2 | `dfs(1)` | `[1]` | ✅ 收集 `[1]` | i=1,2 | — |
| 3 | `dfs(2)` | `[1,2]` | ✅ 收集 `[1,2]` | i=2 | — |
| 4 | `dfs(3)` | `[1,2,3]` | ✅ 收集 `[1,2,3]` | 空（`start==n`） | 回退到 `[1,2]` |
| 5 | 回到 `dfs(1)`，`i` 推进到 2 | `[1,3]` | ✅ 收集 `[1,3]` | — | 回退到 `[1]` |
| 6 | 回到 `dfs(0)`，`i` 推进到 1 | `[2]` | ✅ 收集 `[2]` | i=2 | — |
| 7 | `dfs(2)`（第二次） | `[2,3]` | ✅ 收集 `[2,3]` | — | 回退到 `[2]` |
| 8 | 回到 `dfs(0)`，`i` 推进到 2 | `[3]` | ✅ 收集 `[3]` | — | 回退到 `[]` |

**注意第 5 步**：从 `dfs(3,[1,2,3])` 返回后，`path` 必须先变回 `[1,2]`（第 4 步的撤销），再变回 `[1]`（第 3 步的撤销），然后 `dfs(1)` 的循环才能把 `i` 推到 2 去选 `3`。**撤销的顺序必须与选择的顺序严格相反** —— 这就是「栈」的语义，`path` 本质是一个栈。

**如果少写一次撤销会怎样**：假设第 4 步返回后漏了 `path.pop()`，此时 `path = [1,2,3]`；接着 `dfs(1)` 的循环选 `3`，得到 `path = [1,2,3,3]` —— 收集出一个**不存在的子集**，而且后面的分支会在此基础上继续污染。**这就是「状态恢复」为什么是三件套里最不能省的一件：漏了它，错误不会当场报，而是安静地产生错误答案。**

## 096.5 双语言实现

### 096.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        // 预分配容量：解的数量恒为 2^n，避免 ArrayList 反复扩容
        // （n <= 10，1<<n 最大 1024，不会溢出）
        List<Integer> path = new ArrayList<>();
        dfs(nums, 0, path, res);
        return res;
    }

    /** start = 「本层允许选的最小下标」；它是定义 B 的全部状态，不需要额外参数 */
    private void dfs(int[] nums, int start, List<Integer> path, List<List<Integer>> res) {
        // 收集点写在最前面：定义 B 的每个结点都是一个合法子集（含空集）
        // 必须 new 一份拷贝：path 是同一个对象，直接 add(path) 会让所有结果指向它
        res.add(new ArrayList<>(path));

        for (int i = start; i < nums.length; i++) {
            path.add(nums[i]);                 // ③(a) 选择
            dfs(nums, i + 1, path, res);       // 递归：i+1 保证下标严格递增 → 每个子集只枚举一次
            path.remove(path.size() - 1);      // ③(b) 撤销；用 remove(int) 而不是 remove(Object)
        }
    }
}
```

### 096.5.2 Go

```go
package main

func subsets(nums []int) [][]int {
	// 解的数量恒为 2^n，一次性预分配，省掉多次扩容
	res := make([][]int, 0, 1<<len(nums))
	path := make([]int, 0, len(nums))

	var dfs func(start int)
	dfs = func(start int) {
		// 关键：必须深拷贝。append([]int(nil), path...) 会新分配底层数组；
		// 若直接 append(res, path)，所有结果会共享 path 的底层数组，
		// 递归结束后它们全变成最后一次写入的内容（详见 096.5.3 的实测）
		res = append(res, append([]int(nil), path...))

		for i := start; i < len(nums); i++ {
			path = append(path, nums[i]) // ③(a) 选择
			dfs(i + 1)                   // 递归：下一个起点严格大于 i
			path = path[:len(path)-1]    // ③(b) 撤销：切片缩回一位（不是清空！）
		}
	}
	dfs(0)
	return res
}
```

### 096.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 拷贝一份 path | `new ArrayList<>(path)` | `append([]int(nil), path...)` | **两边都必须拷**；Java 靠新对象，Go 靠新底层数组 |
| 撤销选择 | `path.remove(path.size()-1)` | `path = path[:len(path)-1]` | Java 有**重载陷阱**：`remove(int)` 删下标、`remove(Object)` 删值。`path` 是 `List<Integer>`，写 `remove(3)` 删的是**值 3**，必须用 `size()-1` 形式 |
| 切片的容量（cap） | 无此概念 | `append` 在 cap 足够时**原地写**，多个切片共享同一个数组 | 这是 Go 在本章唯一的真陷阱，见下方实测 |
| 递归写法 | 私有方法 + 参数传递 | 闭包 `var dfs func(int)` 先声明后赋值 | Go 的闭包让 `res`/`path` 变成捕获变量，少传两个参数；但闭包内的 `res = append(...)` 改的是**捕获的变量**而不是副本，语义正确 |
| 结果类型 | `List<List<Integer>>` | `[][]int` | Go 不需要“泛型擦除”层面的注意点；Java 不能写 `List<int[]>`（`int[]` 是对象但语义别扭） |

#### ⚠️ Go 切片别名：本章必须亲手验证的 bug

`append(res, path)` 与 `append(res, append([]int(nil), path...))` 的区别，不是「风格问题」，而是**对错问题**。我实测了两种写法（`n=3`，输入 `[1,2,3]`）：

```text
不加拷贝的版本（错误）：
  res = append(res, path)
  实测输出： [[] [1 2 3] [1 2 3] [1 2 3] [1 2 3] [1 2 3] [1 2 3] [1 2 3]]
  期望输出： [[] [1] [1 2] [1 2 3] [1 3] [2] [2 3] [3]]
  → 8 个结果全是最后一次写入的内容（严格说长度不同，但内容全被覆盖）

加上拷贝的版本（正确）：
  res = append(res, append([]int(nil), path...))
  实测输出： [[] [1] [1 2] [1 2 3] [1 3] [2] [2 3] [3]]    ✓
```

**为什么**：`path` 是一个 `[]int` 头 `{ptr, len, cap}`。`append(res, path)` 拷贝的是**这个头**，`ptr` 仍指向同一个底层数组。递归过程中 `path` 反复 `append`/缩容，写的一直是那块内存，于是所有结果都「看着」同一份数据。**`path` 长度在变、底层数组没变。**

两种正确写法，任选其一：

```go
// 写法 1：显式深拷贝（最直观，推荐）
res = append(res, append([]int(nil), path...))

// 写法 2：三下标切片截断容量，强制下次 append 重新分配
//   path[:len(path):len(path)] 的 cap == len，任何 append 都必然扩容 → 之后不再互相影响
//   但注意：这不解决「已存入的 res 元素指向同一数组」的问题，
//   因为此刻 res 里的元素仍然共享底层数组；它只保证「后续 append 不会再写进去」。
//   组合用法：res = append(res, path[:len(path):len(path)])
res = append(res, path[:len(path):len(path)])
```

> **判定标准**：只要一个 `[]T` 会被「存进结果」并且「之后还会被修改」，就必须拷贝或截断容量。`[][]int`、`[][]string`、`[]string` 全都适用 —— 104 的 N 皇后（存 `[]string`）、105 的切分（存 `[]string`）都会再遇到它。

### 096.5.4 对拍测试（写完必须跑）

对拍的关键是：**两边都先把结果规范化（每个子集内排序 + 整个结果集排序），再逐项比较**。否则即使集合相同，枚举顺序不同也会误判。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 参考实现：位掩码枚举（与回溯完全独立的思路）
func bruteSubsets(nums []int) [][]int {
	n := len(nums)
	res := make([][]int, 0, 1<<n)
	for mask := 0; mask < 1<<n; mask++ {
		cur := []int{}
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				cur = append(cur, nums[i])
			}
		}
		res = append(res, cur)
	}
	return res
}

// 规范化：子集内升序 + 结果集按字典序排序，使两种枚举顺序可比
func norm(subs [][]int) [][]int {
	out := make([][]int, len(subs))
	for i, s := range subs {
		c := append([]int(nil), s...)
		sort.Ints(c)
		out[i] = c
	}
	sort.Slice(out, func(a, b int) bool {
		if len(out[a]) != len(out[b]) {
			return len(out[a]) < len(out[b])
		}
		for k := range out[a] {
			if out[a][k] != out[b][k] {
				return out[a][k] < out[b][k]
			}
		}
		return false
	})
	return out
}

func TestSubsetsRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026096))
	for iter := 0; iter < 4000; iter++ { // 4000 次 > 要求的 3000 次
		n := 1 + r.Intn(10) // n ∈ [1,10]，覆盖上界
		nums := make([]int, n)
		seen := map[int]bool{}
		for i := 0; i < n; { // 造互不相同的元素（题意要求）
			v := r.Intn(21) - 10
			if !seen[v] {
				seen[v] = true
				nums[i] = v
				i++
			}
		}
		got := norm(subsets(nums))
		want := norm(bruteSubsets(nums))
		if len(got) != len(want) {
			t.Fatalf("iter=%d nums=%v 数量不符 got=%d want=%d", iter, nums, len(got), len(want))
		}
		for i := range got {
			if len(got[i]) != len(want[i]) {
				t.Fatalf("iter=%d nums=%v 第%d项长度不符 %v vs %v", iter, nums, i, got[i], want[i])
			}
			for k := range got[i] {
				if got[i][k] != want[i][k] {
					t.Fatalf("iter=%d nums=%v 第%d项内容不符 %v vs %v", iter, nums, i, got[i], want[i])
				}
			}
		}
	}
}
```

## 096.6 复杂度与常见坑

### 096.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(n · 2^n)`**。推导分三步：

1. 树上一共有多少个结点？每个结点对应一个子集，所以结点数 = 解数 = `2^n`。
2. 每个结点做多少工作？收集时拷贝 `path`，代价是当前路径长度 `k`。所有结点的路径长度之和 = `Σ_k C(n,k)·k` = `n · 2^(n-1)`（组合恒等式：`Σ k·C(n,k) = n·2^(n-1)`）。
3. 循环本身的开销：每个结点内的 `for` 迭代次数是 `n - start`，把整棵树加起来是 `O(n·2^n)` 量级，被第 2 步吸收。

所以总时间 `O(n·2^n)`。**注意 `n·2^(n-1)` 里的那个 `n` 来自「拷贝路径」，如果只数方案个数不拷贝，时间可以降到 `O(2^n)`** —— 这个差异在 098 的剪枝讨论里很关键。

**空间 `O(n)`（不含输出）**：

- 递归栈深度最多 `n`（`path` 最长 `n`），每帧常数大小 → `O(n)`；
- `path` 本身 `O(n)`；
- 输出 `O(n·2^n)` —— 这是题目要求的，不能算在算法额外空间里，但**内存限制会卡它**：`n=15` 时输出是 15·32768 ≈ 49 万个 int，约 4 MB，没问题；`n=20` 时约 2000 万个 int，80 MB，开始危险。

### 096.6.2 七个真实踩过的坑

1. **没拷贝 path 就存进结果** —— Java 里 8 个结果指向同一个 `ArrayList`，最后全变成 `[1,2,3]`（或全空）；Go 里因切片别名全部互相覆盖。修法：`new ArrayList<>(path)` / `append([]int(nil), path...)`。
2. **漏了空集** —— 把 `res.add(...)` 从函数开头挪到循环后面，空集就丢了。子集题的收集点在**结点**，不是叶子。
3. **`path.remove(Object)` vs `remove(int)`** —— `List<Integer>` 上写 `path.remove(nums[i])`，删的是**值为 `nums[i]` 的元素**，不是最后一个。必须 `remove(path.size()-1)`。
4. **递归传了 `start` 而不是 `i+1`** —— 写成 `dfs(start + 1, ...)` 会漏解（`[1,3]` 生成不出来）；写成 `dfs(i, ...)` 会死循环（`i` 不变，`path` 无限增长直到栈溢出）。正确是 `dfs(i+1, ...)`。
5. **Go 里 `path = path[:0]` 当撤销** —— 这是清空，不是撤销一位。循环体内用它会丢掉前面所有已选元素。
6. **把全局 `res` 当参数传却以为在改副本** —— Go 的切片是引用语义，`res` 在闭包里被 `append` 后如果重新分配，只有捕获变量能拿到新头；若把 `res` 作为**值参数**传给递归函数并 `append`，返回值必须接住（`res = dfs(...)`），否则丢失。
7. **误以为要按值排序输出** —— 题目说「任意顺序」，先 `sort` 只是让输出好看，会白白多 `O(2^n log 2^n)` 的时间；但**对拍时**又必须排序，两件事不要混。

### 096.6.3 面试官最爱追问的三个问题

**Q1：为什么这题一定要递归，不能迭代？**
> 「能迭代 —— 位掩码就是迭代，复杂度一样是 `O(n·2^n)`。但位掩码把『每个元素二选一』写死在了二进制位上，一旦选择的分支数不是 2（比如 098 选 `k` 个、099 可重复选取、105 切成若干段），位掩码就失效。递归的价值是**把『决策树的结构』和『遍历它的控制流』解耦**：换题只改『边怎么定义』和『剪枝怎么写』，遍历骨架不动。这就是为什么第 10 部分用回溯而不是位运算当主线。」

**Q2：为什么解在结点上，而不是叶子上？**
> 「因为子集问题的『部分解』本身就已经是一个合法解 —— `[1]` 不管后面 2、3 拿不拿，它都是一个子集。反过来在 098（选 `k` 个）里，`[1]` 不是解，必须凑满 `k` 个，所以收集点在叶子上。**判据是：部分解是否满足题目的合法性定义。** 满足就每个结点收集，不满足就只在叶子（或 `len == k` 的层）收集。」

**Q3：如果有重复元素呢？**
> 「元素重复会让『同一条路径』变成多条 —— `[1,2]` 与『另一个 2 配 1』值相同。修法是先排序，然后在**同一层**里遇到与前一个相同的值就跳过（`i > start && nums[i]==nums[i-1]`），跨层不跳。为什么跨层不能跳，正是 [097](097-subsets-ii.md) 要讲的：`[1,1]` 这个子集必须靠『上一层选第一个 1、这一层选第二个 1』才能生成。」
