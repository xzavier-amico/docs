## 009.1 题目

**原题链接**：<https://leetcode.cn/problems/sort-colors/>

### 题意重述（把隐含条件补齐）

给你一个只含 `0`、`1`、`2` 三种整数的数组 `nums`，请**原地**把它排序，使得相同值的元素相邻，并按 `0`、`1`、`2` 的顺序排列。

这道题真正的价值在它的**进阶要求**上（LeetCode 原文写得很清楚）：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **只能原地排序** | 「不能使用代码库中的排序函数」 | 直接 `sort` 一行就完事 —— 但这正是题目禁掉的 |
| **进阶：一趟扫描完成** | 「进阶：你能想出一个仅使用常数空间的一趟扫描算法吗？」 | 两趟扫描（计数排序）也能过，但**面试官要的是那一趟** |
| **常数额外空间** | 同上 | 用 `int[3]` 计数其实是「常数空间」，但**需要第二趟**才能写回 |
| **只有 0 / 1 / 2 三种值** | 题干 | 如果误以为是「任意整数」，就退化成通用排序，本题的全部技巧作废 |
| **返回值是 `void`** | 签名 | 返回新数组 → 判题机看不到结果 |

> ⚠️ 注意「三种值」这个约束有多强：**它让排序问题退化成「三分类」问题**。一旦你意识到「我不需要知道谁比谁大，只需要把三类分开」，就会明白为什么这题能用三个指针一趟解决 —— 而通用排序不可能。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n == nums.length`，`1 <= n <= 300` | 最多 300 | **任何复杂度都能过**，甚至 `O(n²)` 都行；所以这题的考点是「**一趟 + O(1) 空间**」这个硬要求 |
| `nums[i] ∈ {0, 1, 2}` | 三值 | 值域大小 3 → 计数排序只需 3 个桶；三指针只需 3 个下标 |
| 允许全部相同 | 如 `[2,2,2]` | 三个指针可能一步都不走，要能正确退出 |
| 输出 `void`，原地 | 题面 | 不能返回新数组 |

> 💡 **量级反推**：`n ≤ 300` 是个「虚假的宽松」—— 它在告诉你「别在复杂度上动脑筋，动脑筋的地方是**扫描次数**和**交换次数**」。这是面试题常见的设计手法：**把性能门槛拿掉，逼你去追算法本身的美感（一趟、O(1) 空间）。**

### 示例

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]

输入：nums = [2,0,1]
输出：[0,1,2]

输入：nums = [0]
输出：[0]
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [2,0,1]        → 第一步就要把 2 换到末尾，暴露「换完 i++」会跳过一个元素
② [2,2,2]        → 全 2：p2 一直左移，i 原地不动，暴露「循环条件写成 i < p2」时提前退出
③ [0,0,0]        → 全 0：p0 与 i 同步右移，暴露「交换后忘记 p0++」
④ [1,1,1]        → 全 1：三个指针同步，暴露「把 1 当成需要换的值」
⑤ [1,2,0]        → 最小规模的「三类都有且首元素是 1」，用来验 i 与 p0、p2 的交叉
```

第 ① 条最致命：`[2,0,1]` 的第一步把 `nums[0]` 与 `nums[2]` 交换，数组变成 `[1,0,2]`，此时 `nums[0]` 变成了 `1`（**一个从未被检查过的新元素**）。如果你的代码此时执行 `i++`，就会跳过这个 `1` 后面的 `0`，最终得到 `[1,0,2]` —— 错的。

## 009.2 从暴力到最优：第一个念头为什么错

### 第一步：最省事的做法 —— 直接排序

```java
// 一行解决，但题目明令禁止
Arrays.sort(nums);
```

- 时间 `O(n log n)`，空间 `O(log n)`（快排栈）。
- 题目禁止调用库函数，所以这是「面试里说出口就扣分」的答案。但它值得写在纸上，因为它给你一个**对拍的参照物**：任何解法跑完后，结果都应该等于排序后的结果。

### 第二步：计数排序（两趟，正解但不是最优）

```java
int[] cnt = new int[3];
for (int x : nums) cnt[x]++;          // 第一趟：计数
int w = 0;
for (int v = 0; v < 3; v++)           // 第二趟：按计数写回
    for (int k = 0; k < cnt[v]; k++)
        nums[w++] = v;
```

- 时间 `O(n + 3) = O(n)`，空间 `O(1)`（`cnt` 只有 3 个元素，是常数）。
- **它满足「O(1) 空间」，但不满足「一趟扫描」**。
- 关键在于：**它丢掉了「元素原来在哪」这个信息**，只保留了「每个值有几个」。所以在「元素是带载荷的对象」时（例如每个颜色还挂着一个 id），计数排序会**破坏同色元素之间的相对顺序**，而荷兰国旗分区虽然也不稳定，但它的交换是「有迹可循」的。

> 📌 这两趟为什么不够「漂亮」：**它读了数组两遍、写了数组一遍，而理论上只需要读一遍就能确定每个元素的最终位置。** 一趟扫描的解法一定得「边读边把元素放到最终位置」，这就逼出了三指针。

### 第三步：卡点在哪

要一趟完成，就必须在扫描的过程中**同时维护三类元素的边界**。定义三个区域：

```
[0, p0)        全是 0        ← 左边界内
[p0, i)        全是 1        ← 中段
[i, p2]        尚未检查       ← 扫描窗口
(p2, n-1]      全是 2        ← 右边界内
```

于是 `i` 是「当前正在看的元素」，`p0` 是「下一个 0 该放的位置」，`p2` 是「下一个 2 该放的位置」。

**每次看 `nums[i]`，只有三种情况**：

| `nums[i]` | 该做什么 | 为什么 |
| --- | --- | --- |
| `0` | 与 `nums[p0]` 交换，`p0++`，`i++` | 0 属于左区；换回来的值一定是 1（见下方论证），可以安全跳过 |
| `2` | 与 `nums[p2]` 交换，`p2--`，**`i` 不动** | 2 属于右区；换回来的值是**未检查过**的，必须重新看 |
| `1` | `i++` | 1 属于中区，当前位置已经正确 |

**全部难点集中在第四列**：「为什么和 `p0` 换完可以 `i++`，和 `p2` 换完就不行？」

### 第四步：灵感的来源 —— 「换回来的那个值，我知道是什么吗？」

这是本章最核心的一句自问。逐个分析：

```
情形 1：nums[i] == 0，与 nums[p0] 交换
   此时必有 p0 <= i。
   若 p0 == i：自己和自己换，nums[i] 仍是 0 → 归位，i++ 安全。
   若 p0 <  i：由不变量 [p0, i) 全是 1，所以 nums[p0] == 1。
              交换后 nums[i] = 1 —— 而 1 属于中区，位置本来就对 → i++ 安全。
   结论：换回来的值 ∈ {0(自己), 1} ，都是"已确定归属"的值 → i 可以前进。

情形 2：nums[i] == 2，与 nums[p2] 交换
   由不变量 (p2, n-1] 全是 2，但 nums[p2] 本身属于"未检查区"，
   它可能是 0、1、2 里的任何一个。
   交换后 nums[i] = 未知值 → i 绝不能前进，必须重新判断。
   结论：换回来的是"未知值"→ i 原地不动。
```

> **一句话记住**：**只有「换回来的一定是 1」时才能 `i++`。** 左端换回来的是 1（因为中间那段全是 1），右端换回来的是未知值（因为右区之外还没检查）。

这正是「荷兰国旗问题」（Dutch National Flag Problem，由 Dijkstra 提出）的经典解法，三个指针分别对应国旗的红、白、蓝三色。

## 009.3 原理拆解

### 009.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 扫描趟数 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 调库排序 | O(n log n) | O(log n) | — | 题目禁止；且浪费了「只有三值」的信息 |
| 计数排序（两趟） | O(n) | O(1) | **2** | 不满足「一趟」的进阶要求；同色元素相对顺序被彻底打乱 |
| 两趟分区（先 0 到头、再 2 到尾） | O(n) | O(1) | **2** | 同样是两趟；但思路比计数排序更接近正解 |
| **三指针（荷兰国旗）** ✅ | **O(n)** | **O(1)** | **1** | 值域必须很小（这里是 3）；若值域是 k，指针数会变成 k+1，实用性下降 |
| 通用快排的三路划分 | O(n log n) | O(log n) | — | 大材小用；但思想与本章完全一致（三路划分就是荷兰国旗） |

**为什么三指针是唯一「一趟 + O(1)」的解**：它把「元素该去哪」的判断**即时化**了 —— 每读一个元素就立刻把它送到对应的边界上，从不缓存、从不回读。计数排序必须先看完所有元素才知道边界，所以注定两趟。

### 009.3.2 为什么这个做法是对的（正确性论证）

**循环不变量**（每轮循环开始时成立）：

```
① nums[0 .. p0-1] 全是 0
② nums[p0 .. i-1] 全是 1
③ nums[p2+1 .. n-1] 全是 2
④ 0 <= p0 <= i <= p2+1
```

- **初始**：`p0 = 0, i = 0, p2 = n-1`。①② 的区间为空，③ 的区间 `[n, n-1]` 为空，④ 直接成立（三个下标都落在合法范围且 `p0 = i <= p2+1`）。
- **保持（`nums[i] == 0`）**：交换 `nums[i]` 与 `nums[p0]`，然后 `p0++, i++`。
  - 交换后 `nums[p0_old] = 0`，`p0` 加一 → ① 的区间扩大一格且仍全 0 ✓。
  - 换回的旧 `nums[p0]` 落到位置 `i`。由 ② 知 `nums[p0]` 是 1（当 `p0 < i`）；若 `p0 == i` 则是自交换。两种情况 `nums[i]` 都变成 `1`，随后 `i` 加一，`[p0_new, i_new)` = `[p0+1, i+1)` 全是 1 ✓。
  - ③ 不受影响；④ `p0` 与 `i` 同步加一，不等式保持 ✓。
- **保持（`nums[i] == 2`）**：交换 `nums[i]` 与 `nums[p2]`，然后 `p2--`，**`i` 不变**。
  - 交换后 `nums[p2_old] = 2`，`p2` 减一 → ③ 的区间扩大一格且全 2 ✓。
  - 换回的旧 `nums[p2]` 落到位置 `i`，它属于「未检查区」→ 它仍在窗口 `[i, p2]` 内（新的 `p2` 已减一），等待下一轮检查 → ④ 保持 ✓。
  - ①② 不受影响 ✓。
- **保持（`nums[i] == 1`）**：`i++`。位置 `i` 的值是 1，正好并入 ② 的区间 → ② 扩大一格；④ 保持 ✓。
- **终止**：`i > p2` 时窗口为空。此时由 ①②③：
  - `[0, p0)` 全 0；
  - `[p0, i)` 全 1，且 `i = p2+1`，所以 `[p0, p2+1)` 全 1；
  - `(p2, n-1]` 全 2。
  - 三段恰好覆盖 `[0, n-1]` 且不重叠 → **整个数组有序**。∎

> **这个论证最漂亮的地方**：它把「`i` 该不该动」这个容易写错的分支，变成了不变量 ② 的直接推论。**你不需要「记住」那条规则，你只需要问「换回来的值落在哪个区间里」。**

### 009.3.3 通用解题思路（可迁移的那一层）

本题是 **「原地多路分区（in-place multi-way partition）」** 模型的原型：

```
问题：把数组按某个判据分成 k 类，且要求原地 + 一趟
        ↓ 关键观察：k 类 → 只需要 k-1 个"边界指针" + 1 个扫描指针
        ↓ 每读一个元素，把它送到对应边界上（交换），然后更新边界
     模板（k = 3）：
        p0 = 0, p2 = n-1, i = 0
        while i <= p2:
            if 属于第 0 类:   swap(i, p0); p0++; i++
            elif 属于第 2 类: swap(i, p2); p2--      ← i 不动
            else:             i++
```

**这个方法最重要的两个应用**：

| 应用 | k | 说明 |
| --- | --- | --- |
| 本题（三色排序） | 3 | 教科书的入门版 |
| **快速排序的三路划分（3-way partition）** | 3 | 把 `< pivot` / `== pivot` / `> pivot` 分开；**大量重复元素时把快排从 O(n²) 救回 O(n log n)** |
| 按奇偶/正负分组 | 2 | 退化成两指针 |
| 按 k 个阈值分桶 | k+1 | 指针数线性增长，实际很少用（一般改用计数排序） |

**与「两指针分区」的对照**：

| 维度 | 两指针（LC 283 / 905） | 三指针（本章） |
| --- | --- | --- |
| 分类数 | 2 | 3 |
| 指针角色 | 读 + 写 | 左边界 + 扫描 + 右边界 |
| 从右往左的指针 | 无 | `p2`（关键差异） |
| 换回值是否已知 | 已知（就是被覆盖的那个 0） | **右侧未知，左侧已知** |
| 稳定性 | 283 稳定（快慢指针）；905 不稳定（对撞） | 不稳定 |

属于同一模型的题：

| 题 | 分类判据 | 指针数 |
| --- | --- | --- |
| [LC 75 颜色分类](https://leetcode.cn/problems/sort-colors/) | `== 0 / 1 / 2` | 3 |
| [LC 283 移动零](https://leetcode.cn/problems/move-zeroes/) | `== 0` / `!= 0` | 2（快慢） |
| [LC 905 按奇偶排序数组](https://leetcode.cn/problems/sort-array-by-parity/) | 奇 / 偶 | 2（对撞） |
| [LC 922 按奇偶排序数组 II](https://leetcode.cn/problems/sort-array-by-parity-ii/) | 偶数位 / 奇数位 | 2（双写指针） |
| [LC 2149 按符号重排数组](https://leetcode.cn/problems/rearrange-array-elements-by-sign/) | 正 / 负 | 2（双写指针） |
| [LC 912 排序数组](https://leetcode.cn/problems/sort-an-array/) | 三路快排 | 3（`lt / i / gt`，与本章完全同构） |

> 📌 最后一行值得特别注意：**快排的三路划分和本章的三指针是同一段代码**，只是判据从「等于 0/1/2」换成「小于/等于/大于 `pivot`」。学会一个就白拿另一个。

### 009.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 值域变成 `0..k-1`（k 很大） | 指针法退化 | 换计数排序 O(n + k) / O(k)；k 大到放不下就用哈希计数 |
| 值域只有 2 种 | 分类数 2 | 去掉 `p2`，退化成快慢指针 |
| **要求稳定**（同色元素保持原有先后） | 三指针做不到 | 「一趟 + O(1) 空间 + 稳定」三者不可兼得（见本节末尾的说明）；只能改用计数排序（两趟、O(k) 空间、稳定），或者接受不稳定 |
| 元素是**带载荷的对象** | 交换成本变高 | 改为「交换下标」或「交换指针」，避免大对象拷贝 |
| 要排序的是**链表** | 随机访问消失 | 三指针可行（`p0`/`i`/`p2` 变成链表指针），但「与前驱交换」很麻烦 → 通常改成「拆成三条链表再拼接」 |
| 数据**流式**输入 | 无法原地 | 只能计数（O(k) 空间），或维护三个队列 |

**关于稳定性的严格说明**（面试常被追问，值得想清楚）：

三指针**不稳定**：`[1,0]` → 交换 `nums[1]` 与 `nums[0]` 得 `[0,1]`，看上去没问题；但 `[0,1,2,0]` 里两个 `0` 的相对顺序会因交换而改变（第二个 0 被换到了第一个 0 之前）。

**「一趟 + O(1) 空间 + 稳定」在一般情况下是不可能的**（这是排序下界理论的一个推论：稳定排序若只能比较和交换，需要 Ω(n log n) 次操作）。

> **所以面试里如果被问「能不能稳定」，正确答案是**：先说明「一趟 + O(1) + 稳定」三者不能同时满足，再给出取舍 —— 要么用计数排序（O(k) 空间、两趟、稳定），要么接受不稳定（本章解法）。

## 009.4 图解推演

### 009.4.1 主样例的完整轨迹

```
nums = [2, 0, 2, 1, 1, 0]
        0  1  2  3  4  5
p0 = 0,  i = 0,  p2 = 5

图例： [0,p0) = 0 区    [p0,i) = 1 区    [i,p2] = 未检查    (p2,n-1] = 2 区

起始
┌───┬───┬───┬───┬───┬───┐
│ 2 │ 0 │ 2 │ 1 │ 1 │ 0 │
└───┴───┴───┴───┴───┴───┘
  ↑                   ↑
 p0,i                p2

第 1 步  nums[i]=2  →  swap(i, p2)，p2--，i 不动
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 2 │ 1 │ 1 │ 2 │
└───┴───┴───┴───┴───┴───┘
  ↑               ↑   ↑
 p0,i            p2  已定 2
        ↑ 换回来的 0 还没检查 → i 必须原地

第 2 步  nums[i]=0  →  swap(i, p0)，p0++，i++（p0==i，自交换）
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 2 │ 1 │ 1 │ 2 │
└───┴───┴───┴───┴───┴───┘
      ↑           ↑   ↑
     p0,i        p2
 已定 0

第 3 步  i=1，nums[1]=0  →  swap(1, 0)（都是 0，等价自交换），p0=1→2，i=2
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 2 │ 1 │ 1 │ 2 │
└───┴───┴───┴───┴───┴───┘
          ↑       ↑   ↑
         p0,i    p2

第 4 步  i=2，nums[2]=2  →  swap(2, 4)，p2=4→3，i 不动
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 1 │ 1 │ 2 │ 2 │
└───┴───┴───┴───┴───┴───┘
          ↑   ↑   ↑
         p0,i p2  已定 2
        ↑ 换回来的 1 还没检查

第 5 步  i=2，nums[2]=1  →  i++  （并入 1 区）
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 1 │ 1 │ 2 │ 2 │
└───┴───┴───┴───┴───┴───┘
          ↑   ↑   ↑
          p0  i   p2

第 6 步  i=3，nums[3]=1  →  i++  →  i=4 > p2=3，循环结束
┌───┬───┬───┬───┬───┬───┐
│ 0 │ 0 │ 1 │ 1 │ 2 │ 2 │
└───┴───┴───┴───┴───┴───┘
  全 0   │  全 1  │  全 2
结果 [0, 0, 1, 1, 2, 2] ✓
```

### 009.4.2 每一步的边界状态表

| 步 | i | p0 | p2 | nums[i] | 动作 | i 变了吗 | `[0,p0)` | `[p0,i)` | `(p2,n)` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 起始 | 0 | 0 | 5 | 2 | — | — | 空 | 空 | 空 |
| 1 | 0 | 0 | 5 | 2 | swap(i,p2), p2-- | **否** | 空 | 空 | `{2}` |
| 2 | 0 | 0 | 4 | 0 | swap(i,p0), p0++, i++ | 是 | `{0}` | 空 | `{2}` |
| 3 | 1 | 1 | 4 | 0 | swap(i,p0), p0++, i++ | 是 | `{0,0}` | 空 | `{2}` |
| 4 | 2 | 2 | 4 | 2 | swap(i,p2), p2-- | **否** | `{0,0}` | 空 | `{2,2}` |
| 5 | 2 | 2 | 3 | 1 | i++ | 是 | `{0,0}` | `{1}` | `{2,2}` |
| 6 | 3 | 2 | 3 | 1 | i++ | 是 | `{0,0}` | `{1,1}` | `{2,2}` |
| 结束 | 4 | 2 | 3 | — | i > p2 | — | `{0,0}` | `{1,1}` | `{2,2}` |

**第 1 步和第 4 步是「`i` 不动」的两处**，也是这道题唯一需要动脑的地方。**其余步骤都是机械的。**

### 009.4.3 「换回来的是什么值」—— 两种交换的对比图

## 009.5 双语言实现

### 009.5.1 Java

```java
class Solution {
    public void sortColors(int[] nums) {
        // 不变量（每轮循环开始时成立）：
        //   ① nums[0 .. p0-1]   全是 0
        //   ② nums[p0 .. i-1]   全是 1
        //   ③ nums[p2+1 .. n-1] 全是 2
        //   ④ p0 <= i <= p2+1
        int p0 = 0;                 // 下一个 0 该放的位置
        int i = 0;                  // 当前正在检查的位置
        int p2 = nums.length - 1;   // 下一个 2 该放的位置

        // i <= p2 而不是 i < p2：i == p2 时那一格还没检查过，必须处理
        while (i <= p2) {
            if (nums[i] == 0) {
                // 与左边界交换。换回来的值一定是 1（因为 [p0, i) 全是 1，
                // 或者 p0 == i 时是自己），1 的位置本来就对 → i 可以前进
                swap(nums, i, p0);
                p0++;
                i++;
            } else if (nums[i] == 2) {
                // 与右边界交换。换回来的值来自"未检查区"，可能是 0/1/2 任意一个
                // → i 绝不能前进，下一轮必须重新检查这一格
                swap(nums, i, p2);
                p2--;
            } else {
                // nums[i] == 1：已经在中段，位置正确
                i++;
            }
        }
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x];
        a[x] = a[y];
        a[y] = t;
    }
}
```

### 009.5.2 Go

```go
package main

// sortColors 原地把 0/1/2 三类分开。变量名与 Java 版逐行对齐。
func sortColors(nums []int) {
	// 不变量：
	//   ① nums[0..p0-1]   全是 0
	//   ② nums[p0..i-1]   全是 1
	//   ③ nums[p2+1..n-1] 全是 2
	//   ④ p0 <= i <= p2+1
	p0, i, p2 := 0, 0, len(nums)-1

	// i <= p2：i == p2 那一格也要检查
	for i <= p2 {
		switch nums[i] {
		case 0:
			// 换回来的必然是 1（或 p0==i 时的自己）→ i 前进
			nums[i], nums[p0] = nums[p0], nums[i]
			p0++
			i++
		case 2:
			// 换回来的值来自未检查区 → i 不动
			nums[i], nums[p2] = nums[p2], nums[i]
			p2--
		default:
			// 值为 1，已在中段
			i++
		}
	}
}
```

> ⚠️ **Go 的多重赋值在这里是「安全」的**：`nums[i], nums[p0] = nums[p0], nums[i]` 的右侧会**先把两个旧值都求出来**，再依次赋给左边。所以不会出现「第一次赋值把第二次要用的值覆盖掉」的问题。**但如果写成两句单元赋值（`nums[i] = nums[p0]; nums[p0] = nums[i]`），就变成了两个元素同值** —— 这是 Go 新手最常见的交换 bug。

### 009.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 交换 | 必须写 `swap` 辅助方法或临时变量 | `a, b = b, a` 一行 | Go 更短；但**必须理解多重赋值的求值顺序**，写成两句就错 |
| 分支写法 | `if / else if / else` | `switch nums[i] { case 0: ... }` | Go 的 `switch` 自带 `break`（不穿透），三种值正好对应三个 `case` + `default` |
| `switch` 里的 `i++` | — | 合法，`case` 之间自动跳出 | 不用担心漏 `break` 导致「执行完 case 0 又掉进 case 2」（C/Java 的老坑） |
| 返回值 | `void` | 无返回值 | 原地修改 |
| 数组/切片传参 | 数组是引用类型 | 切片改元素生效、改长度不生效 | 本题只改元素 → 都正确 |
| 空输入 | `n >= 1` 由题面保证 | 同 | `len == 0` 时 `p2 = -1`，`i <= p2` 为假，循环不执行，安全 |

## 009.6 复杂度与常见坑

### 009.6.1 复杂度推导

- **时间 O(n)**：这是本题最容易讲错的地方。注意 while 循环**不是**「每轮 i 前进一格」：
  - `nums[i] == 0`：`i` 前进 1，`p2 - i` 减少 1（窗口小了 1）。
  - `nums[i] == 2`：`i` 不动，`p2` 后退 1，窗口小了 1。
  - `nums[i] == 1`：`i` 前进 1，窗口小了 1。
  - **三种情况都让「窗口长度 `p2 - i + 1` 严格减 1」**，窗口初始为 `n`，所以**总轮数恰好 ≤ n**。故 `O(n)`。
- **空间 O(1)**：三个下标 + 一个交换临时变量。
- **交换次数**：每个 0 一次、每个 2 一次（可能自交换），1 不交换。最坏 `n` 次。
- **对比计数排序**：时间同为 O(n)，但计数排序要**读 n 次 + 写 n 次**，共 `2n` 次内存访问；三指针是 `n` 次读 + 最多 `n` 次交换（每次 3 次访问），最坏 `4n`。**所以三指针在「访问次数」上并不占优，它的优势是「一趟」这个语义要求。**

### 009.6.2 八个真实踩过的坑

1. **`nums[i] == 2` 时也 `i++`** —— 本章头号错误。`[2,0,1]` 上会把换回来的 `1`（原位置 2 的值）跳过，得到 `[1,0,2]`。
2. **循环条件写成 `i < p2`** —— `i == p2` 那一格永远不会被检查。用 `[1,2,0]` 试：`i=0` 是 1、前进到 `i=1`；`nums[1]=2` 与 `p2=2` 交换后数组变成 `[1,0,2]`、`p2=1`；此时 `i=1`、`p2=1`，`i < p2` 为假直接退出 —— 位置 1 的 `0` 永远没被处理，得到 `[1,0,2]`。**必须是 `i <= p2`。**
3. **`nums[i] == 0` 时忘记 `p0++`** —— 左边界不动，所有 0 都被塞到下标 0。用 `[1,0,0]` 试：第 1 个 0 换到下标 0 得 `[0,1,0]`，第 2 个 0 又换到下标 0（下标 0 已是 0，等于自交换），最后得到 `[0,1,0]` —— 错。
4. **误以为「与 `p2` 交换后 `i` 也不能前进，所以与 `p0` 交换后也不该前进」** —— 这两个情形不对称，理由见 §009.3.2。写代码时不要「对称化」。
5. **Go 里用两句赋值做交换** —— `nums[i] = nums[p0]; nums[p0] = nums[i]` 会让两处变成同一个值。必须用多重赋值。
6. **以为「可以用 `nums[i] > 1` 代替 `nums[i] == 2`」** —— 在本题成立（值域只有 0/1/2），但这是**依赖值域的写法**；如果题目改成「0/1/2/3」，`> 1` 会把 3 也当成 2。**用 `== 2` 更安全。**
7. **把三个指针的初值写成 `p0 = 0, i = 1, p2 = n-1`** —— `i` 从 1 开始会漏掉 `nums[0]`。
8. **想「先扫一遍数 0 和 2 的个数，再一趟填」** —— 那还是两趟（数一遍 + 填一遍）。真正的「一趟」必须是「边读边定位置」。

### 009.6.3 面试官最爱追问的三个问题

**Q1：为什么和右边界交换后 `i` 不能前进，和左边界交换后就能？**
> 「因为换回来的值的『已知程度』不同。与 `p0` 交换时，`[p0, i)` 这段全是 1，所以 `nums[p0]` 必然是 1（`p0 == i` 时是自己），换到 `i` 位置后 `nums[i] = 1`，1 本来就应该待在中段 → 位置已经正确，`i` 可以前进。与 `p2` 交换时，`nums[p2]` 属于尚未检查的区域，可能是 0/1/2 任何一个，换到 `i` 位置后必须重新判断 → `i` 不能动。**这条规则不是背的，是从不变量推出来的。**」

**Q2：这个算法稳定吗？如果要求稳定怎么办？**
> 「不稳定。交换会打乱同色元素之间的相对顺序，例如 `[0,1,2,0]` 里两个 0 的位置会互换。如果要求稳定，『一趟 + O(1) 空间 + 稳定』是做不到的（稳定排序若只靠比较与交换，下界是 Ω(n log n)）。现实取舍是：① 用计数排序（O(k) 空间、两趟、天然稳定）；② 或者给元素加一个原始下标作为次序键，用更重的排序。本题不要求稳定，所以用三指针。」

**Q3：如果值域是 `0..k-1`（k 由输入给出），你的解法怎么变？**
> 「指针数会变成 k+1 个（k-1 个边界 + 1 个扫描），代码里要维护一个指针数组，而且要按值的大小顺序处理边界，实现复杂度上升但思想不变 —— 本质是『基数分区』。不过实务上 k 大时不会用这个：计数排序 O(n+k) 更好，k 再大就用哈希计数或外部排序。**三指针的价值在于『k = 3 且要求一趟』这个特定场景，不是通用工具。**」

## 附：本章小结（可背走的三句话）

```
① 三指针切四段：[0,p0) 全 0，[p0,i) 全 1，[i,p2] 未检查，(p2,n-1] 全 2
② 与 p0 交换后 i++（换回的一定是 1）；与 p2 交换后 i 不动（换回的是未知值）
③ 每轮窗口长度严格减 1 → 总轮数 ≤ n → O(n) 一趟，空间 O(1)
```
