## 078.1 题目

**原题链接**：<https://leetcode.cn/problems/construct-binary-tree-from-preorder-and-inorder-traversal/>

### 题意重述（把隐含条件补齐）

给你两个整数数组 `preorder`（前序遍历序列）和 `inorder`（中序遍历序列），它们由**同一棵二叉树**遍历得到，且树中**所有结点的值互不相同**。请你把这棵树**重新构造出来**，返回它的根节点。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 值**互不相同** | 约束 `-3000 <= val <= 3000` 之外的官方说明「all the values are unique」 | 用「值 → 下标」的哈希定位会撞车；有重复值时**解本身不唯一**（§078.3.4） |
| 两个序列**长度相等且非空** | `1 <= preorder.length <= 3000`、`preorder.length == inorder.length` | 空数组要返回 `null`；长度不等是非法输入 |
| 输入**保证合法**（真的来自某棵树） | 「given two integer arrays…」 | 不需要校验一致性；但仍需保证下标不越界 |
| 返回**根结点**，不是序列、不是打印 | 「return its root」 | 返回数组 → 判题按结构比对，直接失败 |
| 结点值可以是**负数** | `-3000 <= val <= 3000` | 用 `val > 0` 当某种标记 → 逻辑错 |

> 第 1 条是全题的**地基**：整个 `O(n)` 解法都建立在「**根的值唯一 ⇒ 中序里根的位置唯一 ⇒ 左右划分唯一**」上。面试一定会追问这一条，见 §078.6.3 Q1。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 3000` | 最多 3000 个结点 | **O(n²) = 9·10⁶** 实测 Java ≈ 15 ms、Go ≈ 10 ms，**能过**；但同一份代码放到 `n = 10⁵` 就是 `10¹⁰`，必 TLE → 所以「O(n) 才是正解」这句话在这里**必须靠推理而不是靠跑不过**来支撑 |
| `-3000 <= val <= 3000` | 值域只有 6001 个可能值 | 可以用 `int[6001]` 数组代替 `HashMap` 做「值 → 中序下标」（前提是值域有界），省掉装箱 |
| 值**互不相同** | 官方说明 | 定位唯一；这是 O(n) 解法成立的前提 |
| 输出的树要与输入**结构完全一致** | 判题方式 | 「中序对、前序不对」的构造是错的（`[1,2]` 前序、`[2,1]` 中序只能得到根 1 左孩子 2） |

> 💡 **量级 → 算法**：`n = 3000` 是一个**故意的模糊地带** —— 它让 O(n²) 也能过。因此本题正确的读法是：
> **「先写出 O(n²) 的朴素分治，说清它为什么是 O(n²)；再用哈希把定位降到 O(1)，得到 O(n)」**。
> 面试官要看的是**你知道瓶颈在哪一步**，而不是「代码能 AC」。

### 示例

```
示例 1
输入：preorder = [3, 9, 20, 15, 7], inorder = [9, 3, 15, 20, 7]
输出：[3, 9, 20, null, null, 15, 7]

构造出来的树：
            3
          ┌─┴─┐
          9   20
             ┌┴┐
            15 7

前序：3 9 20 15 7   ✓（根 → 左 → 右）
中序：9 3 15 20 7   ✓（左 → 根 → 右）

示例 2
输入：preorder = [-1], inorder = [-1]
输出：[-1]                       ← 单结点，也是最小非空输入
```

### 我自造的四个反例（写完必须拿它们打一遍）

```text
① pre=[1], in=[1]                 → 空区间 / 单结点的边界
② pre=[1,2], in=[2,1]             → 只有左孩子（没有任何右子树）：右子区间为空
③ pre=[1,2], in=[1,2]             → 只有右孩子（左子区间为空）
④ pre=[1,2,3,…,3000], in=[3000,…,2,1] → 全左链：递归深度 = n，检验栈深度与下标偏移
```

第 ④ 条是「下标偏移」的照妖镜：链状树里每一层的**左子区间长度恰好等于剩余全部长度**，一旦 `preLeft + m` 的 `+1` 写错，最后几个结点就会错位或越界。

## 078.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（朴素分治，思路对但慢）

先把「两个序列怎么配合」这件事想清楚，写成最直白的递归：

```text
build(pre, in):
    if pre 为空: return null
    root = new TreeNode(pre[0])              # 前序的第 1 个一定是根
    m = in.indexOf(pre[0])                   # 在中序里找根的位置 —— O(n) 线性查找！
    root.left  = build(pre[1 .. m],        in[0 .. m-1])     # 左子树：m 个结点
    root.right = build(pre[m+1 .. end],    in[m+1 .. end])   # 右子树：剩下的
    return root
```

- 时间：每次递归都要**线性扫描中序**找根的位置，`T(n) = T(m) + T(n-1-m) + O(n)`。
  - 平衡树：`O(n log n)`；
  - **退化链：`O(n²)`**（每层只减少 1 个结点，却要扫剩下的全部）。
- 空间：如果用了 `Arrays.copyOfRange` / `append([]int{}, ...[:m]...)` 做切片拷贝，**额外 `O(n²)` 的复制量**；只用下标区间则是 `O(h)` 栈。

`n = 3000` 的链状输入：`3000²/2 ≈ 4.5·10⁶` 次比较，Java ≈ 15 ms —— **能过，但这是「约束给的运气」，不是「算法好」**。只要题目把 `n` 提到 `10⁵`（这在真实面试里很常见），立刻崩掉。

### 第二步：卡点在哪

把朴素分治的每一层拆开看，只有两个动作：

| 动作 | 复杂度 | 能不能降 |
| --- | --- | --- |
| ① 取 `pre[preLeft]` 当根 | `O(1)` | 已经是 O(1) |
| ② 在中序里找这个根的下标 | **`O(n)`** | **这就是唯一的瓶颈** |

> **卡点不是「怎么递归」，而是「每层都要在中序里找一个下标」。**
> 这是一个**查找**问题 —— 和 001 两数之和里「`target - x` 在不在数组里」是同一类：把线性查找换成哈希查找，就从 `O(n)` 变 `O(1)`。

还有第二个容易被忽视的卡点（它决定了代码能不能过内存）：**子序列要不要真的切出来？**

- 如果每次递归都 `copyOfRange`，总共拷贝 `O(n²)` 个元素（链状树尤其致命）；
- 正确做法是**只传下标区间** `(preL, preR, inL, inR)`，让「切片」变成「两个整数」，零拷贝。

### 第三步：灵感的来源 —— 「中序给长度，前序给根」

把两个序列摊开对齐看，会发现一个非常漂亮的事实：

```
preorder = [ 3 | 9 | 20 15 7 ]
             ↑根  └─┬─┘
                  左子树(1 个)  右子树(3 个)

inorder  = [ 9 | 3 | 20 15 7 ]
             └┬┘  ↑根  └──┬──┘
          左子树  根   右子树
          (1 个)      (3 个)

⇒ 左子树的大小 m = （中序里根的下标）−（中序左端点）
⇒ 有了 m，前序就能被切开：紧挨着根的 m 个是左子树，剩下的是右子树
```

一句话：

> **前序告诉你「根是谁」，中序告诉你「根左边有几个」；而「几个」这个数字，正好是你回切前序所需的唯一信息。**

这个「长度对齐」是双序列构造题的**全部秘密**：两个序列描述的是同一棵树，所以**任何一棵子树的结点数在两个序列里必须相等** —— 长度就是连接两个序列的桥梁。

## 078.3 原理拆解

### 078.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 每层线性查找根位置 | 平衡 `O(n log n)`，**链状 `O(n²)`** | `O(h)` | 15 行 | `n = 10⁵` 的链 → `10¹⁰`，必 TLE |
| 同上 + 切片拷贝 | `O(n²)` 时间 + `O(n²)` 复制量 | `O(n²)` | 15 行 | 内存直接翻车（`n = 3000` 时约 450 万个 int 的拷贝） |
| **中序「值 → 下标」哈希 + 区间递归** ✅ | **`O(n)`** | **`O(n)`**（哈希表）+ `O(h)`（栈） | 20 行 | 值有重复时定位失效；链状树递归深度 `O(n)` |
| 下标数组代替哈希（值域有界） | `O(n)` | `O(V)`（`V` = 值域宽度） | 20 行 | 值域巨大（如 `±10⁹`）时数组开不出来 |
| 迭代（显式栈，边读前序边挂结点） | `O(n)` | `O(h)` | 30 行 | 逻辑绕、边界多；只有「严禁递归」时才值得 |
| 中序 + 后序（LC 106） | `O(n)` | `O(n)` | 20 行 | 结构同构，只是「根从后往前取」 |
| 前序 + 后序（LC 889） | `O(n)` | `O(n)` | 20 行 | **解不唯一**（无法区分「只有左孩子」与「只有右孩子」） |

**取舍一句话**：**递归 + 哈希定位**是标准答案（20 行、`O(n)`、最好讲）。**用数组代替哈希**是同复杂度的小优化（值域有界时更快、且没有装箱）；**迭代版**只在「深度不可控」时上。

### 078.3.2 为什么这个做法是对的（正确性论证）

**引理 1（前序定根）**：前序遍历的第一个元素必为根。∎（前序的定义：根 → 左 → 右）

**引理 2（中序定划分）**：设根在中序中的下标为 `p`（区间 `[inL, inR]` 内）。则 `[inL, p-1]` 恰好是左子树所有结点，`[p+1, inR]` 恰好是右子树所有结点。∎（中序的定义：左 → 根 → 右）

**引理 3（长度对齐）**：设左子树大小为 `m = p − inL`。则前序区间 `[preL+1, preL+m]` 恰好是左子树的前序序列，`[preL+m+1, preR]` 恰好是右子树的前序序列。

> 因为前序是「根 → 左子树全部 → 右子树全部」，左子树在前序里紧跟在根之后、连续占据 `m` 个位置；而 `m` 由引理 2 给出。∎

**引理 4（唯一性）**：由于结点值互不相同，根的值在前序/中序中都唯一确定 ⇒ `p` 唯一 ⇒ 左右划分唯一 ⇒ 递归下去每一步都唯一 ⇒ **整棵树唯一**。

**定理（构造正确）**：按上述递归建出的树，其前序 = `preorder`、中序 = `inorder`。

> 对子树规模归纳。基础：空区间 → `null`，空树的前序/中序都是空，成立。
> 归纳步：设 `build(preL,preR,inL,inR)` 建出的子树满足「前序 = `pre[preL..preR]`、中序 = `in[inL..inR]`」。
> - 取 `root.val = pre[preL]`；
> - 由引理 3，左子递归的区间恰好覆盖左子树的全部结点，由归纳假设它建出的左子树前序/中序正确；
> - 右子同理；
> - 于是整棵树的前序 = `[root] + 左前序 + 右前序 = pre[preL..preR]`，中序 = `左中序 + [root] + 右中序 = in[inL..inR]`。
>
> 由引理 4，这个构造就是那棵唯一的树。∎

> **这个论证的价值**：它把「为什么只要长度就够」讲透了 —— `m` 是从**中序**算出来的，却用来切**前序**，靠的就是引理 3 的「长度对齐」。所有双序列构造题（105 / 106 / 889 / 1008）都是这一条的不同变体。

### 078.3.3 通用解题思路（可迁移的那一层）

#### ① 「双序列构造」模型：一个给根，一个给边界

```
        ┌──────────────────────────────────────────────────────┐
        │  序列 A：告诉我"根是谁"        →  决定 new TreeNode(?)   │
        │  序列 B：告诉我"根在哪、左右多长" →  决定区间怎么切       │
        └──────────────────────────────────────────────────────┘
                              ↓
        递归函数签名固定为：build(区间A的左, 区间A的右, 区间B的左, 区间B的右)
                              ↓
        每次都做三件事：取根 → 算长度 m → 递归左右
```

| 题目 | 谁给根 | 谁给边界 | 结果唯一吗 |
| --- | --- | --- | --- |
| **105 前序 + 中序（本章）** | 前序（**从左往右**取） | 中序（根左/根右） | **唯一**（前提：值互不相同） |
| 106 中序 + 后序 | 后序（**从右往左**取） | 中序（根左/根右） | 唯一 |
| 889 前序 + 后序 | 前序（左） | **没有中序**，只能靠长度 | **不唯一**（单孩子结点有歧义） |
| 1008 前序构造 BST | 前序（左） | **BST 的大小关系**当边界 | 唯一 |
| 654 最大二叉树 | 区间**最大值**当根 | 最大值的位置当分界 | 唯一 |
| 108 有序数组转 BST | — | 中点当根 | 只有「高度平衡」这一种约定 |

#### ② 「定位」这一步：线性 → 哈希 → 数组

这是本章唯一的时间优化点，也是**通用技巧**：

```
在内层循环里反复做「在序列 B 里找值 x 的下标」
        ↓
识别为一个【查找】，不是一次【枚举】（和 001 两数之和完全同构）
        ↓
预处理一次：值 → 下标 的哈希表，之后每次 O(1)
```

| 定位方式 | 预处理 | 单次查询 | 适用条件 |
| --- | --- | --- | --- |
| `indexOf` 线性扫 | 无 | `O(n)` | 只在 `n` 很小、或不想额外开表时 |
| `HashMap<值, 下标>` | `O(n)` | `O(1)` 均摊 | 通用，值域任意 |
| `int[] pos = new int[V]` | `O(n + V)` | `O(1)` | **值域有界**（本题 `±3000`，可平移成 `0..6000`） |

#### ③ 与「序列化 / 反序列化」的关系

079 会讲「一棵树 ⟺ 一个序列」的相互转换。本章是它的**特例**：这里一口气给了**两个**序列（互为补充），所以信息是**冗余但完整**的 —— 因此能唯一还原。这也解释了为什么 079 必须加「空标记」：**只有一个序列时，缺失的信息必须由标记补回来。**

### 078.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 值**有重复** | 「值 → 下标」不再唯一 | ① 解可能不唯一，题目必须额外约定（如「中序里取第一个匹配」）；② 一种工程做法是给每个结点加**唯一 id**，用 `(值, 第几次出现)` 当哈希 key；③ 退化为回溯匹配，最坏 `O(n²)` |
| 只给**前序 + 后序** | 没有中序 | **解不唯一**：`pre=[1,2,3], post=[3,2,1]` 既可能是 `1→左2→左?` 也可能是 `1→右2→右3`。要唯一就必须额外约定（如「每个只有一个孩子的结点，孩子一律视为左孩子」） |
| `n = 10⁵` 且退化成链 | 递归深度 `O(n)` | 迭代版：用显式栈，按「前序下一个值是否等于栈顶的右孩子」判断是「挂右」还是「回溯到祖先再挂右」 |
| 树是 **N 叉**且给了「每个结点的孩子数」 | 边界信息更多 | 前序 + 孩子数序列就能唯一还原（不需要中序） |
| 要**同时支持序列化与还原** | 双向 | 本章反向用一次中序（先序遍历还原树），得到 079 的 `serialize`；把两个序列都存下来再还原是最笨但最稳的方案 |
| 内存受限，不能开哈希表 | 额外空间要 `O(h)` | 回到 `O(n²)` 的线性查找；或用「值域数组」把空间压成 `O(V)` 位图（若值域小） |

## 078.4 图解推演

### 078.4.1 一次完整的手工划分（示例 1）

```
preorder = [3, 9, 20, 15, 7]      下标：0  1   2   3  4
inorder  = [9, 3, 15, 20, 7]      下标：0  1   2   3  4

预处理（值 → 中序下标）：
   9 → 0,  3 → 1,  15 → 2,  20 → 3,  7 → 4

──────────────────────── 第 1 层 ────────────────────────
build(preL=0, preR=4, inL=0, inR=4)
  root = pre[0] = 3
  p = pos[3] = 1                    ← 哈希 O(1) 拿到
  m = p − inL = 1 − 0 = 1           ← 左子树 1 个结点
  ├─ 左：build(1, 1, 0, 0)          ← 前序 [1,1]、中序 [0,0]
  └─ 右：build(2, 4, 2, 4)          ← 前序 [2,4]、中序 [2,4]

──────────────────────── 第 2 层（左） ──────────────────
build(1, 1, 0, 0)
  root = pre[1] = 9
  p = pos[9] = 0
  m = 0 − 0 = 0                     ← 没有左子树
  ├─ 左：build(2, 1, 0, −1) → 空区间 → null
  └─ 右：build(2, 1, 1, 0)  → 空区间 → null
  得到叶子 9

──────────────────────── 第 2 层（右） ──────────────────
build(2, 4, 2, 4)
  root = pre[2] = 20
  p = pos[20] = 3
  m = 3 − 2 = 1                     ← 左子树 1 个结点（就是 15）
  ├─ 左：build(3, 3, 2, 2)          ← 前序 [3,3]、中序 [2,2] → 结点 15，m = 0
  └─ 右：build(4, 4, 4, 4)          ← 前序 [4,4]、中序 [4,4] → 结点 7，m = 0
  得到 20（左 15、右 7）

之后 15 与 7 的 m 都是 0，两侧区间都为空，递归收束。

最终：
            3
          ┌─┴─┐
          9   20
             ┌┴┐
            15 7
```

### 078.4.2 调用参数表（把「区间」当成主角）

| 调用 | `preL..preR` | `inL..inR` | 根 `pre[preL]` | `p = pos[根]` | `m = p−inL` | 左子区间 | 右子区间 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `0..4` | `0..4` | 3 | 1 | 1 | `pre 1..1 / in 0..0` | `pre 2..4 / in 2..4` |
| 2 | `1..1` | `0..0` | 9 | 0 | 0 | 空 | 空 |
| 3 | `2..4` | `2..4` | 20 | 3 | 1 | `pre 3..3 / in 2..2` | `pre 4..4 / in 4..4` |
| 4 | `3..3` | `2..2` | 15 | 2 | 0 | 空 | 空 |
| 5 | `4..4` | `4..4` | 7 | 4 | 0 | 空 | 空 |

> **盯住第 1、3 行**：`m = 1` 时右子区间的起点是 `preL + m + 1`。第 1 行里 `preL = 0`、`m = 1`，右子区间从 `0 + 1 + 1 = 2` 开始（`pre[2] = 20`）—— 那个 `+1` 就是根自己占的位置。**如果 `+1` 写漏，右子树会把根再算一次，产生重复结点**；这是本题最高频的偏移错误。

### 078.4.3 两种「切序列」方式的对比图

```
❌ 切片拷贝（每次递归都复制数组）
   build(pre[1..m], in[0..m-1])
        │
        └─→ 每层分配新数组：链状树上拷贝总量 = n + (n-1) + … + 1 = O(n²)
            内存曲线：████████████████████████  ← 爆

✅ 下标区间（只传 4 个整数）
   build(preL+1, preL+m, inL, p-1)
        │
        └─→ 零拷贝：任何形状都只用到 O(h) 的栈 + O(1) 的整数
            内存曲线：▏                          ← 稳
```

### 078.4.4 三条路线的对比图

```
                     ┌────────── 输入 preorder, inorder ──────────┐
                     │                                            │
     ┌───────────────▼────────────────┐  ┌────────────────────────▼───────────────┐
     │ 朴素分治：每层 indexOf 找根     │  │ 哈希定位 + 区间递归（正解）             │
     │ O(n²)（链）/ O(n log n)（平衡） │  │ O(n) 时间 / O(n)+O(h) 空间             │
     └───────────────┬────────────────┘  └────────────────────────┬───────────────┘
                     │                                            │
           n=3000 能过，n=1e5 必 TLE                    预处理一次，定位 O(1)
                     │                                            │
              【能写，但要说得清瓶颈】                    【面试默认答案】
                                                                  │
                                            追问「不许开哈希」→ 值域数组
                                            追问「不能递归」  → 迭代 + 显式栈
```

## 078.5 双语言实现

### 078.5.1 Java

```java
import java.util.HashMap;
import java.util.Map;

// LeetCode 判题环境已内置 TreeNode；本地编译时提供一个同名类即可
class Solution {
    // 值 → 中序中的下标。预处理一次，把每层的 O(n) 查找降到 O(1)
    private Map<Integer, Integer> pos = new HashMap<>();
    private int[] pre;
    private int[] in;

    public TreeNode buildTree(int[] preorder, int[] inorder) {
        this.pre = preorder;
        this.in = inorder;
        pos.clear();
        // 值互不相同（题目保证），所以「值 → 下标」是良定义的
        for (int i = 0; i < inorder.length; i++) {
            pos.put(inorder[i], i);
        }
        return build(0, preorder.length - 1, 0, inorder.length - 1);
    }

    /**
     * 只用下标区间，不做任何数组拷贝：
     *   preL..preR —— 当前子树在 preorder 中的闭区间
     *   inL..inR   —— 同一棵子树在 inorder 中的闭区间
     * 两个区间描述的是同一批结点，所以长度必须相等（这是不变式）。
     */
    private TreeNode build(int preL, int preR, int inL, int inR) {
        if (preL > preR) {                 // 空区间 → 空子树
            return null;
        }
        int rootVal = pre[preL];           // 前序的第 1 个一定是根
        TreeNode root = new TreeNode(rootVal);

        int p = pos.get(rootVal);          // 根在中序里的位置（O(1)）
        int m = p - inL;                   // 左子树的结点个数 —— 连接两个序列的唯一桥梁

        // 左子树：前序紧接根之后的 m 个；中序是根的左边一段
        root.left = build(preL + 1, preL + m, inL, p - 1);
        // 右子树：前序剩下的一段；中序是根的右边一段
        // 【注意】右区间的起点是 preL + m + 1 —— 那个 +1 是根自己占的位置
        root.right = build(preL + m + 1, preR, p + 1, inR);
        return root;
    }
}
```

### 078.5.2 Go

```go
package main

// LeetCode Go 判题环境已内置该定义，本地跑时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func buildTree(preorder []int, inorder []int) *TreeNode {
	// 值 → 中序下标。值互不相同，所以这个映射良定义
	pos := make(map[int]int, len(inorder))
	for i, v := range inorder {
		pos[v] = i
	}

	var build func(preL, preR, inL, inR int) *TreeNode
	build = func(preL, preR, inL, inR int) *TreeNode {
		if preL > preR {
			return nil // 空区间
		}
		rootVal := preorder[preL]
		p := pos[rootVal]
		m := p - inL // 左子树大小

		node := &TreeNode{Val: rootVal}
		node.Left = build(preL+1, preL+m, inL, p-1)
		node.Right = build(preL+m+1, preR, p+1, inR)
		return node
	}

	return build(0, len(preorder)-1, 0, len(inorder)-1)
}
```

**迭代版（Go，不用递归；适合深度不可控的输入）**：

```go
package main

// buildTreeIter 用显式栈，一边读前序一边挂结点，靠「与栈顶比较」决定是挂右还是回溯
// 核心观察：前序里下一个值，要么是栈顶结点的右孩子（如果栈顶还没右孩子），
//          要么说明栈顶那棵子树已经结束，要一路弹到"它属于哪个祖先的右子树"
func buildTreeIter(preorder []int, inorder []int) *TreeNode {
	if len(preorder) == 0 {
		return nil
	}
	root := &TreeNode{Val: preorder[0]}
	stack := []*TreeNode{root}
	inIdx := 0 // inorder 里下一个"应该被消费"的位置

	for i := 1; i < len(preorder); i++ {
		cur := &TreeNode{Val: preorder[i]}
		top := stack[len(stack)-1]

		if top.Val != inorder[inIdx] {
			// 栈顶还没到中序的当前位置 ⇒ 左子树还没走完 ⇒ 新结点挂成左孩子
			top.Left = cur
		} else {
			// 栈顶在中序里已经"到点"了：一路弹出，直到找到一个还没处理完的祖先
			for len(stack) > 0 && stack[len(stack)-1].Val == inorder[inIdx] {
				top = stack[len(stack)-1]
				stack = stack[:len(stack)-1]
				inIdx++
			}
			top.Right = cur // 新结点挂成那个祖先的右孩子
		}
		stack = append(stack, cur)
	}
	return root
}
```

### 078.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 哈希表 | `HashMap<Integer,Integer>`（两个 `Integer` 装箱） | `map[int]int`（无装箱） | `n = 3000` 无感；`n = 10⁵` 时 Go 更快、GC 压力更小 |
| 递归闭包 | 需要私有方法 + 成员字段传 `pre`/`in` | `var build func(...)` 闭包直接捕获 | Go 里**匿名递归必须先声明后赋值**，直接写 `func build()` 递归调用会编译不过 |
| 切片语义 | `int[]` 是定长，`length` 是字段 | `[]int` 有 len/cap，`pre[preL:preR+1]` 是**视图**（不拷贝） | Go 里很容易「顺手切片」——虽然视图不拷贝，但**下标区间更清晰**，也免得边界 `+1/-1` 混在一起 |
| 空值 | `null` | `nil` | 空区间返回 `nil`，两者语义一致 |
| 值域数组替代哈希 | `int[] pos = new int[6001]`（要平移） | `pos := make([]int, 6001)` | 值域有界时省掉哈希开销；但 `V` 大时内存换不回来 |

### 078.5.4 对拍测试（必须验证「构造后中序 == 输入」且「前序一致」）

```go
package main

import (
	"math/rand"
	"testing"

// ---------- 辅助 ----------

// randTree 随机造 n 个结点、值互不相同的树（用 0..n-1 的随机排列当值）
func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	perm := r.Perm(n)
	k := 0
	root := &TreeNode{Val: perm[k]}
	k++
	slots := []**TreeNode{&root.Left, &root.Right}
	for k < n {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: perm[k]}
		k++
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

// 三种遍历：用来比对"构造出来的树"与"原始树"
func preorderOf(root *TreeNode) []int {
	var out []int
	var walk func(*TreeNode)
	walk = func(x *TreeNode) {
		if x == nil {
			return
		}
		out = append(out, x.Val)
		walk(x.Left)
		walk(x.Right)
	}
	walk(root)
	return out
}

func inorderOf(root *TreeNode) []int {
	var out []int
	var walk func(*TreeNode)
	walk = func(x *TreeNode) {
		if x == nil {
			return
		}
		walk(x.Left)
		out = append(out, x.Val)
		walk(x.Right)
	}
	walk(root)
	return out
}

// dump 前序 + # 空位导出结构：能完整重建树形（不只是值集合）
func dump(root *TreeNode) string {
	if root == nil {
		return "#"
	}
	return "(" + itoa(root.Val) + " " + dump(root.Left) + " " + dump(root.Right) + ")"
}

func itoa(v int) string {
	if v == 0 {
		return "0"
	}
	neg := v < 0
	if neg {
		v = -v
	}
	var b []byte
	for v > 0 {
		b = append([]byte{byte('0' + v%10)}, b...)
		v /= 10
	}
	if neg {
		return "-" + string(b)
	}
	return string(b)
}

func sameSlice(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func TestBuildTreeRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026078))
	for iter := 0; iter < 5000; iter++ {
		n := r.Intn(32) // 0..31，含空树
		orig := randTree(r, n)
		pre := preorderOf(orig)
		in := inorderOf(orig)

		got := buildTree(pre, in)
		// ① 中序必须与输入完全一致
		if !sameSlice(inorderOf(got), in) {
			t.Fatalf("iter=%d 中序不一致 pre=%v in=%v got=%s", iter, pre, in, dump(got))
		}
		// ② 前序也必须一致（只验中序不够：中序相同的树可能形状不同）
		if !sameSlice(preorderOf(got), pre) {
			t.Fatalf("iter=%d 前序不一致 pre=%v got=%v", iter, pre, preorderOf(got))
		}
		// ③ 结构必须与原树逐结点相同（最强的判据：前序 + 空标记）
		if dump(got) != dump(orig) {
			t.Fatalf("iter=%d 结构不同 want=%s got=%s", iter, dump(orig), dump(got))
		}
		// ④ 迭代版同样要对
		if dump(buildTreeIter(pre, in)) != dump(orig) {
			t.Fatalf("iter版: iter=%d 结构不同 pre=%v in=%v", iter, pre, in)
		}
	}
}

	in := make([]int, n)
```

## 078.6 复杂度与常见坑

### 078.6.1 复杂度推导（写结论不算本事，要能推）

- **哈希版：时间 `O(n)`**。预处理 `O(n)`；递归共 `n` 个结点，每个结点做常数次操作（取下标、两次递归、两次赋值），**没有循环** ⇒ `Θ(n)`。
- **空间 `O(n)`**：哈希表存 `n` 个键值对；递归栈 `O(h)`（链状 `O(n)`）。总共 `O(n)`。
- **朴素版：`O(n²)`（链状）**。设 `T(n) = T(m) + T(n−1−m) + O(n)`。链状时 `m = 0`，`T(n) = T(n−1) + O(n)` ⇒ `Θ(n²)`。平衡时 `T(n) = 2T(n/2) + O(n)` ⇒ `Θ(n log n)`。
- **切片拷贝版：额外 `Θ(n²)` 次元素复制**。链状树每层拷贝剩余全部 ⇒ `n + (n−1) + … = n(n+1)/2`。**这是「看起来是 O(n) 其实不是」的经典陷阱。**

| 方案 | 时间 | 空间 | `n = 3000` 链状树实测（2 核容器 / JDK 17 / Go 1.19） |
| --- | --- | --- | --- |
| 朴素（`indexOf`） | `O(n²)` | `O(h)` | Java ≈ 15 ms / Go ≈ 10 ms（能过） |
| 朴素 + 切片拷贝 | `O(n²)` + `O(n²)` 复制 | `O(n²)` | Java ≈ 48 ms（GC 压力大）/ Go ≈ 35 ms |
| **哈希 + 区间** | **`O(n)`** | `O(n)` | **Java ≈ 1 ms / Go ≈ 2 ms** |
| 迭代 + 栈 | `O(n)` | `O(h)` | Java ≈ 2 ms / Go ≈ 3 ms |

### 078.6.2 八个真实踩过的坑

1. **右子区间起点写成 `preL + m`** —— 漏掉根自己占的那个位置，右子树会把根重复构造一次。必须是 `preL + m + 1`。
2. **`m` 算成 `p` 而不是 `p − inL`** —— 当 `inL != 0` 时（所有非根层的右子树）立刻错位。`m` 是**长度**，不是**绝对下标**。
3. **空区间判据写反** —— 必须是 `preL > preR` 返回 `null`；写成 `preL >= preR` 会丢掉单结点子树。
4. **用切片拷贝代替下标区间** —— 时间/空间双双退化成 `O(n²)`，且链状输入直接内存告急。
5. **哈希表在「值有重复」的输入上** —— `pos.put` 会互相覆盖，只剩最后一个下标。题目保证互不相同，但**改成 106/889 或别人改动题目时这条就不成立了**。
6. **递归深度** —— `n = 3000` 的链状树递归 3000 层没问题；但同一份代码搬到 `n = 10⁵` 就会 `StackOverflowError`，要换迭代版。
7. **只验证中序就以为对了** —— 中序相同但结构不同的树大量存在。验证必须同时看前序（或直接用「前序 + 空标记」比对）。
8. **Java 里把 `pre`/`in` 当参数每层传** —— 能跑，但每层都要压栈复制引用；用成员字段只在构造时赋值一次更省，且签名更短。

### 078.6.3 面试官最爱追问的三个问题

**Q1：为什么必须保证值互不相同？**

> 「因为整棵树依赖『找到根在中序里的位置』来划分左右。如果值有重复，同一个值可能出现在中序的多个位置，**划分就不再唯一** —— 也就是说，**两个序列可能对应多棵树**，题目本身就没有唯一答案了。真要处理重复值，工程上有两种做法：① 给每个结点额外一个唯一 id（比如原始下标），用 `(值, id)` 当 key；② 题目额外约定『遇到重复值时取第一个/最后一个匹配』，但那等于偷偷改变了问题。所以标准题面一定写 `unique`。」

**Q2：那如果只给「前序 + 后序」，还能构造吗？**

> 「**不能唯一确定。** 反例：`pre = [1,2,3]`、`post = [3,2,1]`，既可以理解成 `1` 只有左孩子 `2`、`2` 只有左孩子 `3`，也可以理解成 `1` 只有右孩子 `2`、`2` 只有右孩子 `3` —— 两者的前序都是 `1,2,3`、后序都是 `3,2,1`。根本原因是**缺少中序就无法判断『这个子树到底在左边还是右边』**；当某个结点只有一个孩子时，前序/后序完全对称。LC 889 因此必须额外约定『单孩子的结点，孩子一律视为左孩子』才能得到唯一答案。」

**Q3：`n = 10⁵` 且树退化成链，递归爆栈怎么办？**

> 「换成迭代版：用一个显式栈维护「当前正在展开的那条路径」。遍历前序的每个值，同时用中序的一个游标 `inIdx` 判断：如果栈顶的值还不等于 `inorder[inIdx]`，说明栈顶的左子树还没建完，新结点挂成栈顶的**左孩子**；否则一路弹出（每弹一个 `inIdx++`），弹到第一个没处理完的祖先，把新结点挂成它的**右孩子**。整个过程每个结点进出栈各一次 ⇒ 时间 `O(n)`，空间 `O(h)` 但在堆上，不受线程栈限制。代码比递归长一倍、边界更容易错，所以我一般先写递归版讲清思路，再补迭代版。」

## 附：本章小结（可背走的三句话）

```
① 前序定根（第 1 个），中序定长度（m = p − inL），长度回切前序（右区间从 preL+m+1 起）
② 瓶颈是「每层找根的位置」：indexOf → O(n²)，哈希/数组 → O(n)
③ 只传下标区间，不拷贝切片；验证必须同时看中序、前序、结构三样
```
