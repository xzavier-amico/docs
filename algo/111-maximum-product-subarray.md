## 111.1 题目

**原题链接**：<https://leetcode.cn/problems/maximum-product-subarray/>

### 题意重述（把隐含条件补齐）

给一个整数数组 `nums`，找出**乘积最大的连续子数组**（至少一个元素），返回这个乘积。

「把加法换成乘法」听起来只是换个符号，但乘积有两个加法没有的性质：**负数相乘变正、乘 0 让一切归零**。这两条把问题彻底改掉了：

| 隐含条件 | 出处 | 读错了会怎样 |
| --- | --- | --- |
| **连续**且**非空** | 「子数组」 | 允许空 → 全负数数组返回 1（乘法的空元），而正确是最大的那个负数 |
| 元素**可正、可负、可为 0** | `-10 <= nums[i] <= 10` | 只处理正数 → `[-3,-3]` 答 -3（正确 9） |
| 负数的个数**为偶数**时整段乘积为正 | 乘法符号法则 | 漏掉这条 → 想不出「为什么最小值也必须留着」 |
| 答案保证在 **32 位整数**范围内 | 「题目数据保证答案是一个 32 位整数」 | 以为要取模；或者以为中间量也一定不溢出（**这是错的**，见 §111.6.2 第 6 条） |

> 📌 **一句话对比 110 章**：加法里「接上一个负数只会让和更小」，所以只要留着最大值；乘法里「接上一个负数」会让**最大值变最小、最小值变最大**。**这不是细节优化，而是状态定义的根本变化。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 2·10^4` | n 最多两万 | `O(n²) = 2·10^8` 次乘法，本机实测 Java ≈ 180 ms、Go ≈ 90 ms —— **能过但不优**；`O(n)` 才是期望答案 |
| `-10 <= nums[i] <= 10` | 元素绝对值 ≤ 10 | 注意 `10^{2·10^4}` 是天文数字：**没有任何内置整数类型装得下「所有可能子数组的乘积」**，所以必须依赖「答案在 32 位内」这个保证 |
| 「答案是一个 32 位整数」 | 关键保证 | 只保证**答案**不溢出，**不保证中间状态不溢出**（`dpMin` 可能非常负）→ 见 §111.6.2 |
| 可以出现 0 | `nums[i]` 可为 0 | 0 会把数组切成互不影响的段；`[0]` 的答案是 0，不是 1 |

> 💡 **量级 → 算法**：`2·10^4` 是个暧昧的尺寸 —— `O(n²)` 勉强能过。**面试给这种尺寸，考的就是「你会不会写 O(n)」**；如果只写 O(n²) 就交卷，等于没答到点上。

### 示例

```text
输入：nums = [2,3,-2,4]
输出：6
解释：子数组 [2,3] 的乘积是 6（若把 -2 也纳进来变成 -12，反而更小）。

输入：nums = [-2,0,-1]
输出：0
解释：0 把数组切成两段，单看两段是 -2 和 -1，最优是「只取 0」。

输入：nums = [-2,3,-4]
输出：24
解释：整段 -2 × 3 × -4 = 24 —— 这个样例直接干掉了「只维护最大值」的写法：
      以 3 结尾时最大是 3、最小是 -6；乘 -4 后，24 是从「最小」那一支长出来的。
```

### 我自造的六个反例（写完解法必须拿它们打一遍）

```text
① [-1]                 → 单元素负数：答案是 -1，任何「初值写 0/1」的写法都会错
② [0]                  → 单元素 0：答案是 0，写成「空子数组 = 1」的写法会返回 1
③ [-3,-3,-1]           → 答案是 9（前两个 -3 相乘）；只维护 max 的写法会答 3 或 -3
④ [-2,0,-1]            → 答案是 0；把 0 当成「重置为 1」的写法会答 2
⑤ [-1,-2,-3,-4]        → 答案是 24（全乘）；暴露「负数偶数个」这个分支
⑥ [5,-100,5]           → 答案是 5？不是：5 × -100 × 5 = -2500，最优是单取 5 → 但仍要检查
                          跨段：以 -100 为转折，最大就是 5
```

第 ⑥ 条容易想歪：它说明**负数会让「跨越它」变得不划算，但负数的负数个组合又可能突然变划算**。所以不能像 110 章那样「`cur < 0` 就重开」——乘法的世界里，一个负数就可能让整段翻盘。

## 111.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有 `(l, r)`

```java
// O(n^2)：固定 l，r 前进时增量相乘
int best = nums[0];
for (int l = 0; l < n; l++) {
    int p = 1;
    for (int r = l; r < n; r++) {
        p *= nums[r];
        best = Math.max(best, p);
    }
}
```

- 时间 **O(n²)**，空间 **O(1)**。`n = 2·10^4` 时是 `2·10^8` 次乘法 → 大约 **200 ms**，**能过**。
- 但它依然被判为「不合格答案」：`n` 一旦变成 `10^5`（`5·10^9` 次），立刻 TLE。

### 第二步：第一个念头 —— 「照抄 110 章，把加改乘」

看到 110 章的 `dp[i] = nums[i] + max(dp[i-1], 0)`，最自然的迁移是：

```java
// ❌ 错误：只维护「以 i 结尾的最大积」
int cur = nums[0], best = nums[0];
for (int i = 1; i < n; i++) {
    cur = Math.max(nums[i], cur * nums[i]);   // 以为乘法也「越小越拖累」
    best = Math.max(best, cur);
}
```

**在 `[-2, 3, -4]` 上它给出 3，而正确答案是 24。** 逐步看：

```text
i=0  cur = -2
i=1  cur = max(3, -2*3) = max(3, -6) = 3
i=2  cur = max(-4, 3*-4) = max(-4, -12) = -4      ← 这里就丢了 24
```

24 是怎么来的？是 `-2 × 3 = -6`（**以 3 结尾的最小积**）再乘 `-4` 得到的。**而这个 `-6` 在第 1 步就被 `max` 扔掉了** —— 因为「求最大」的视角下它毫无价值。

> ⚠️ **这就是「信息损失」的教科书例子**：`dpMax[i-1]` 这个状态里，没有存「将来乘上负数后可能变成最大值」的那个信息。状态定义丢了转移需要的东西，转移就一定写错。

### 第三步：卡点 —— 乘负数会「翻转」顺序

抽象地看：设 `P_j` 为「从 `j` 开始、到 `i-1` 结束」的乘积。要算「以 `i` 结尾的最大积」，需要

```
max_{0 ≤ j ≤ i} ( P_j × x )       其中 x = nums[i]
```

如果 `x > 0`：乘法保序，`P_j` 越大结果越大 → 只要 `max P_j = dpMax[i-1]`。
如果 `x < 0`：乘法**反序**，`P_j` 越小（越负）结果**越大** → 需要 `min P_j = dpMin[i-1]`。

所以：

```
dpMax[i] = max( x,  x · dpMax[i-1],  x · dpMin[i-1] )
dpMin[i] = min( x,  x · dpMax[i-1],  x · dpMin[i-1] )
```

三项的含义分别是：**从 `i` 重开**、**接上「以 `i-1` 结尾的最大积」**、**接上「以 `i-1` 结尾的最小积」**。三个候选覆盖了所有起点 `j`，且由上面「`x > 0` / `x < 0`」的分析可知没有遗漏。

```text
不变量：同时维护两个值
  dpMax[i] = 以 i 结尾的所有非空子数组中的最大乘积
  dpMin[i] = 以 i 结尾的所有非空子数组中的最小乘积
二者必须同生同死：少了任何一个，转移就不完备
```

### 第四步：为什么 `dpMin` 也要「最优」而不是「随便一个负的」

有人会问：既然只需要「能翻盘的那个负数」，为什么不随便留一个负积？

因为**乘法的绝对值是单调的**：对固定 `x < 0`，`P_j × x` 关于 `P_j` 严格反序。所以「最小的 `P_j`」一定给出「最大的 `P_j × x`」。**留随便一个负值不够，必须留最小值。** 这就是 `dpMin` 同样要做 DP 的原因 —— 它自己也是一个「最优子结构」。

### 另一条路：前缀积两遍扫描（`O(n)`，`O(1)`，不用双状态）

既然「答案段」的乘积符号由负数个数的奇偶决定，那么一段内乘积为正的最长延伸，一定是下列两者之一：

1. 从**这段的左端**一路乘到某个位置；
2. 从**某个位置**一路乘到**这段的右端**。

于是「从左往右扫一遍 + 从右往左扫一遍，遇到 0 就重置为 1」，两次扫描的最大值就是答案：

```text
nums = [-3, -3, -1]    （无 0 的一段）
  从左扫： p = -3, 9, -9          → 最大 9
  从右扫： p = -1, 3, -9          → 最大 3
  答案 = max(9, 3) = 9   ✅

nums = [-1, -1, 0, -1, 1, -3, -2, 2, -2, -3, 2, 1]
  0 把数组切成两段，第二段 = [-1,1,-3,-2,2,-2,-3,2,1]
  该段整段乘积 = 144 > 0 → 从左扫就能累出 144
  答案 = 144  ✅
```

> 🔑 **为什么两遍扫描一定对**：设最优段为 `[l, r]`。若整个「零段」（即包含 `[l, r]` 的极大无零区间 `[L, R]`）里负数的个数是偶数，则整段 `[L, R]` 乘积为正且 `≥ [l, r]` 的绝对值？—— 不一定，但当负数为偶数时整段乘积 ≥ 最优段乘积只在「绝对值单调」意义下成立；更稳妥的证明见右侧表格。**更严谨的说法**：设 `[L, R]` 内负数出现在位置 `f₁ < f₂ < … < f_m`。若 `m` 为偶数，整段乘积为正，它本身就是候选，且它的绝对值是所有以 `L` 为起点的乘积中最大的 → 从右往左扫会在某一步得到它；若 `m` 为奇数，则最优段必然舍弃第一个负数的左边或最后一个负数的右边 → 正好被「从左扫」或「从右扫」命中。

| 情形 | 最优段的位置 | 哪一遍扫描命中 |
| --- | --- | --- |
| 零段内负数个数为**偶数** | 可以就是整个零段 | 两遍都会命中（整段乘积为正） |
| 零段内负数个数为**奇数** | 必须切掉至少一个负数：切左边或切右边 | 切左边 → 「从右扫」命中；切右边 → 「从左扫」命中 |
| 零段只有一个元素且为负 | 该元素自身 | 两遍都命中 |
| 含 0 | 最优段要么含 0（乘积 0），要么完全落在某个零段内 | 遇 0 重置，两遍扫描天然分段 |

## 111.3 原理拆解

### 111.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举所有 `(l, r)` | O(n²) | O(1) | 6 行 | `n = 2·10^4` 约 200 ms（能过但不优）；`n = 10^5` 必 TLE |
| 只维护 `dpMax` | O(n) | O(1) | 5 行 | **本身就是错的**，`[-2,3,-4]` 答 3（正确 24） |
| **双状态 `dpMax` / `dpMin`** ✅ | **O(n)** | **O(1)** | **7 行** | 要输出「哪一段」时需额外记录起点 |
| 前缀积两遍扫描 | O(n) | O(1) | 12 行 | 不好回答「求具体区间」；也不好推广到「最多删 k 个元素」 |
| 取对数后求最大子段和 | O(n) | O(1) | 10 行 | **浮点误差 + 无法表达 0 和负号**：`log` 只对正数有定义，符号要另存，误差在 `n = 2·10^4` 时足以把 `ans` 和 `ans+1` 判错 |
| 大整数 + 双状态 | O(n·位数) | O(位数) | 40 行 | 只在「答案超过 32 位」的变体里才需要，常数极大 |

**为什么最终选双状态**：它同时具备 `O(n)` 时间、`O(1)` 空间、7 行代码，而且**语义可以直接讲清楚**（「以 `i` 结尾的最大 / 最小积」）。前缀积两遍扫描也很快，但它的正确性论证要绕一圈（要按负数个数奇偶分类），**面试时讲不清楚就等于不会**。

### 111.3.2 为什么这个做法是对的（正确性论证）

**命题**：设

```
dpMax[i] = max{ nums[j] × … × nums[i] : 0 ≤ j ≤ i }
dpMin[i] = min{ nums[j] × … × nums[i] : 0 ≤ j ≤ i }
```

则对 `i ≥ 1`：

```
dpMax[i] = max( nums[i],  nums[i] · dpMax[i-1],  nums[i] · dpMin[i-1] )
dpMin[i] = min( nums[i],  nums[i] · dpMax[i-1],  nums[i] · dpMin[i-1] )
```

答案 `= max_i dpMax[i]`。

**证明**：固定 `i`，记 `x = nums[i]`。所有以 `i` 结尾的子数组按起点分两类：

1. **`j = i`**：乘积就是 `x`。
2. **`j < i`**：乘积 `= P_j × x`，其中 `P_j` 是某个以 `i-1` 结尾的子数组的乘积。反过来，任何一个以 `i-1` 结尾的子数组接上 `nums[i]` 都得到以 `i` 结尾的子数组 —— 所以第二类与「以 `i-1` 结尾的全体子数组」**双射**。

于是

```
dpMax[i] = max( x,  max_{P} ( P × x ) )
```

其中 `P` 遍历「以 `i-1` 结尾的全体子数组乘积」。而关键引理是：

> **引理**：对固定实数 `x ≠ 0`，函数 `P ↦ P·x` 是单调的：`x > 0` 时递增，`x < 0` 时递减。
>
> 因此：`x > 0` 时 `max_P (P·x) = x · max_P P = x · dpMax[i-1]`；
> `x < 0` 时 `max_P (P·x) = x · min_P P = x · dpMin[i-1]`。
>
> 两个情形合起来，恰好就是 `max(x·dpMax[i-1], x·dpMin[i-1])`（因为两者取 max 时，`x > 0` 时 `x·dpMax` 更大，`x < 0` 时 `x·dpMin` 更大 —— 无须判断符号，取 max 自动成立）。

`dpMin` 完全对称（把 max 换成 min，引理同样适用）。`x = 0` 时三项按定义都等于 0（`0 · 任何有限值 = 0`），公式照样成立。

∎

**边界**：`dpMax[0] = dpMin[0] = nums[0]`（子数组非空，必须含第一个元素）；`best = nums[0]`（最优段可能在任意位置结束）。

**为什么第三个候选项是「`x` 自己」而不仅是两个乘积**：`dpMax[i-1] = 0` 时两个乘积项都是 0，但 `x` 可能是正数。没有这一项，`[0, 5]` 这种「前面是 0」的用例会答 0（正确 5）。

### 111.3.3 通用解题思路（可迁移的那一层）

本题是 **「转移操作不保序 ⇒ 状态要成对维护」** 这个模型的母题：

```text
原始问题：连续子数组的最值，元素可正可负
         ↓ 沿 110 章锚定右端点
状态：    dp[i] = 以 i 结尾的最值
         ↓ 但转移是「乘 nums[i]」，而乘法对负数反序
结论：    只存一个最值不够，必须同时存「最大」与「最小」
         ↓ 它们互相喂养
转移：    dpMax[i] = max(x, x·dpMax[i-1], x·dpMin[i-1])
          dpMin[i] = min(x, x·dpMax[i-1], x·dpMin[i-1])
         ↓ 注意必须用「上一轮的旧值」同时更新两者
陷阱：    先更新 dpMax 再用新的 dpMax 算 dpMin → 污染
```

**套用 DP 四步法**：

| 四步 | 本题的答案 |
| --- | --- |
| ① 状态定义 | `dpMax[i]` = 以 `i` 结尾的最大乘积；`dpMin[i]` = 以 `i` 结尾的最小乘积（**两个状态**） |
| ② 转移方程 | `dpMax[i] = max(x, x·dpMax[i-1], x·dpMin[i-1])`；`dpMin[i]` 同理取 `min` |
| ③ 初始化 | `dpMax[0] = dpMin[0] = nums[0]`；`best = nums[0]` |
| ④ 遍历序 | `i` 从 1 递增；**每轮先用两个旧状态算出新值，再同时写回**（顺序不能交错） |

**「状态要成对维护」这个模型的其它题型**：

| 题 | 一对状态 | 为什么必须成对 |
| --- | --- | --- |
| [LC 152 乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/) | 以 `i` 结尾的 max / min 积 | 乘负数翻转序 |
| [LC 1567 乘积为正数的最长子数组长度](https://leetcode.cn/problems/maximum-length-of-subarray-with-positive-product/) | 以 `i` 结尾、积为正 / 为负的最长长度 | 乘负数会让「正」变「负」 |
| [LC 129 买卖股票的最佳时机 III 类](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/) | 持股 / 空仓 | 状态的「互补性」决定了必须都存 |
| [LC 309 最佳买卖股票时机含冷冻期](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/) | 持股 / 空仓 / 冷冻 | 三态机，两两互斥 |
| [LC 1911 最大子序列交替和](https://leetcode.cn/problems/maximum-alternating-subsequence-sum/) | 以 `i` 结尾且末尾为「偶长度 / 奇长度」 | 加减交替，同样会翻转 |

**共同点**：转移操作**不保序**时，一个状态不够，要把它「互补的那一半」也提成状态。

### 111.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要输出**具体区间** `[l, r]` | 求值 → 求方案 | 记录 `startMax[i]`（`dpMax[i]` 这一支的起点），转移时跟着继承；`best` 更新时同步记 `[l, r]` |
| 允许**删掉一个元素**（LC 1186 的乘法版） | 约束变化 | 状态加一维：`dpMax[i][0/1]` 表示「没用过删除」/「已用过删除」，四元组一起维护 |
| 求**乘积最大的 k 个元素子数组**（固定长度） | 定长 → 滑动窗口 | 固定窗口就要处理「窗口内有 0」与浮点误差，实用做法是「按 0 分段 + 前缀积 + 除法」或用双端队列维护负号位置 |
| **模 `1e9+7`** 下求最大 | 数值无界 | 取模后**不能比较大小**（模掉了序），必须换比较准则或维护对数 + 符号；这是「取模毁掉单调性」的经典坑 |
| 元素是**浮点数** | 精度问题 | 双状态照旧成立，但要处理 `x = 0` 与非规格化数；判断「正负」用 `Math.signum` 而不是 `> 0`（避免 `-0.0`） |
| **环形**数组的乘积最大子数组 | 线性 → 环形 | 与 110 章的环形套路同源：`max(不跨环, 总和型表达式)`，但乘法下「总和」要换成「总乘积 / 某段」，并必须特判 0 |

**关于「答案超过 32 位」的变体**（这题最容易被追问的一点）：

```text
若 nums[i] ∈ [-10, 10]、n = 2·10^4：
  · 所有元素的乘积可达 10^{2·10^4}，那是 20 万位的数字
  · Java/Go 的内置整数都装不下 → 必须上 BigInteger / math/big
  · 但题目**只保证答案**在 32 位内，所以「用一个 int 存 dpMax」是安全的（答案支不会溢出）
  · 危险的是 dpMin：它可能是 -10^{很大}，这时 int 会溢出成乱码
    标准做法：dpMin 用 long（甚至 int64 也未必够，但 LC 数据远达不到）
```

## 111.4 图解推演

### 111.4.1 双状态 DP 表 + 计算顺序箭头

以 `nums = [2, 3, -2, 4]` 为例：

```text
下标 i :     0        1         2          3
nums[i]:     2        3        -2          4
          ────────────────────────────────────────────
dpMax[i]:    2        6        -2          4
dpMin[i]:    2        6       -12        -48
best   :     2        6         6          6

计算顺序：i = 0 → 3 从左到右递增 →

i=1  x = 3
  候选①  从 i 重开            →  3
  候选②  x · dpMax[0] = 3·2   →  6   ← dpMax = max(3, 6, 6) = 6
  候选③  x · dpMin[0] = 3·2   →  6   ← dpMin = min(3, 6, 6) = 6
     ┌─────────┐        ┌─────────┐
     │dpMax[0]=2│ ─3×─→ │   +6    │
     │dpMin[0]=2│ ─3×─→ │   +6    │
     └─────────┘        └─────────┘

i=2  x = -2
  候选①  -2
  候选②  -2 · dpMax[1] = -12       ← 接「最大」得到更小的
  候选③  -2 · dpMin[1] = -12
  dpMax[2] = max(-2, -12, -12) = -2      ← 只能重开
  dpMin[2] = min(-2, -12, -12) = -12     ← 负得更多 ✓

i=3  x = 4
  候选①  4
  候选②  4 · dpMax[2] = -8
  候选③  4 · dpMin[2] = -48
  dpMax[3] = 4          dpMin[3] = -48
```

**再看 `[-2, 3, -4]` 的「翻转」瞬间**（这是全章最关键的一张图）：

```text
下标 i :     0        1         2
nums[i]:    -2        3        -4
          ─────────────────────────────
dpMax[i]:   -2        3        24   ← 24 = (-4) × (-6)
dpMin[i]:   -2       -6       -12
                       ▲         ▲
                       │         │
                   dpMin[1]=-6   │
                   乘 -4 反序 ───┘
                   「最小值 × 负数 = 最大值」

i=1  x =  3 : 候选 = {3, 3·(-2)=-6, 3·(-2)=-6}
              dpMax = 3（重开）     dpMin = -6（把 -2 接上）
i=2  x = -4 : 候选 = {-4, -4·3=-12, -4·(-6)=24}
              dpMax = 24  ← 由 dpMin[1] 翻盘而来
              dpMin = -12

  如果只存 dpMax：i=1 时丢掉 -6，i=2 时只剩 {-4, -12} → best 停在 3（错，正确 24）
```

### 111.4.2 滚动变量：两个格子（不是三个）

```text
curMax ← dpMax[i]      curMin ← dpMin[i]      best ← max_i dpMax[i]

初始：curMax = -2   curMin = -2   best = -2        （nums = [-2, 3, -4]）

i=1  x = 3
  ┌──────────────┬──────────────┐
  │ curMax = -2  │ curMin = -2  │   旧值（= dp[0]）
  └──────────────┴──────────────┘
       │ 3×            │ 3×
       ▼               ▼
     -6               -6         ← 两个候选乘积
  再与 x = 3 一起取 max / min
  ┌──────────────┬──────────────┐
  │ curMax =  3  │ curMin = -6  │   新值（= dp[1]）
  └──────────────┴──────────────┘
  best = max(-2, 3) = 3

i=2  x = -4
  ┌──────────────┬──────────────┐
  │ curMax =  3  │ curMin = -6  │
  └──────────────┴──────────────┘
       │ -4×           │ -4×
       ▼               ▼
    -12              24           ← 注意：这次「min 支」给出更大的数
  ┌──────────────┬──────────────┐
  │ curMax = 24  │ curMin = -12 │
  └──────────────┴──────────────┘
  best = max(3, 24) = 24   ← 答案

⚠️ 必须先算完 (a, b) = (x·curMax, x·curMin)，再写回 curMax / curMin。
   若先写 curMax = max(...) 再算 curMin，用的就是**新** curMax → 全错。
```

| 轮次 i | `x` | 进入 `curMax` | 进入 `curMin` | `x·curMax` | `x·curMin` | 出 `curMax` | 出 `curMin` | `best` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | -2 | —（初值） | —（初值） | — | — | **-2** | **-2** | -2 |
| 1 | 3 | -2 | -2 | -6 | -6 | **3** | **-6** | 3 |
| 2 | -4 | 3 | -6 | -12 | **24** | **24** | **-12** | 24 |

> 🔑 **这张表就是「为什么必须双状态」的全部证据**：第 2 行里，`x·curMin = 24` 是答案，而 `x·curMax = -12` 是废料。**如果只留一个状态，你无法预知哪一支会翻盘。**

### 111.4.3 前缀积两遍扫描的路线对比

```text
nums = [-1, -1, 0, -1, 1, -3, -2, 2, -2, -3, 2, 1]

            ┌──── 第一段 [-1,-1] ────┐  ┌── 第二段 [-1,1,-3,-2,2,-2,-3,2,1] ──┐
nums:       -1      -1      0        -1     1    -3    -2     2    -2    -3     2     1
从左扫 p:   -1       1      0        -1    -1     3    -6     -12   24   -72  -144  -144
                    ▲                ↑                                        
              这里 best=1        0 后重置为 1                               
从右扫 p:    144     144     0       144    144  -144   -48    24   -12    36    72 ... 
             ▲
        起点就在最左，一遍扫出 144

答案 = max(144, 144) = 144  （由「整段乘起来为正」直接给出）

两遍扫描为什么能覆盖全部情形：
  ┌──────────────────┬────────────────────────────────┐
  │ 零段内负数偶数个 │ 整段乘积为正 → 任一方向扫到末尾 │
  │ 零段内负数奇数个 │ 必须切掉最左或最右的一个负数   │
  │                  │ → 「从左扫」或「从右扫」命中   │
  └──────────────────┴────────────────────────────────┘

两条路线对比：
  双状态 DP     ：O(n) / O(1) / 7 行 / 可直接求区间 / 语义清楚
  两遍前缀积    ：O(n) / O(1) / 12 行 / 求区间困难 / 依赖奇偶分析
  ⇒ 面试首选双状态；两遍扫描是很好的「第二解 + 对拍基准」
```

## 111.5 双语言实现

### 111.5.1 Java

```java
class Solution {
    // 主解：双状态 DP，O(n) 时间 / O(1) 空间
    public int maxProduct(int[] nums) {
        // dpMax[i] = 以 i 结尾的最大乘积；dpMin[i] = 以 i 结尾的最小乘积
        // 二者必须同时存在：乘负数会把「最小」翻成「最大」
        int curMax = nums[0];   // dp[0]：子数组非空，初值必须是 nums[0]
        int curMin = nums[0];
        int best = nums[0];     // 答案取 max_i dpMax[i]

        for (int i = 1; i < nums.length; i++) {
            int x = nums[i];
            // 必须先把两个候选算式都算出来，再统一写回；
            // 若先写 curMax，第二个式子就会用到「已被改写」的 curMax —— 这是第一大 bug
            int a = x * curMax;
            int b = x * curMin;
            curMax = Math.max(x, Math.max(a, b));  // 含「从 i 重开」这一项
            curMin = Math.min(x, Math.min(a, b));
            best = Math.max(best, curMax);         // 答案可能在中间某处结束
        }
        return best;
    }

    // 第二解：前缀积两遍扫描（不依赖 DP 的双状态，用来交叉验证）
    public int maxProductTwoPass(int[] nums) {
        int best = nums[0];
        int p = 1;
        for (int x : nums) {                    // 左 → 右
            p *= x;
            best = Math.max(best, p);
            if (x == 0) p = 1;                  // 0 把数组切成互不影响的段
        }
        p = 1;
        for (int i = nums.length - 1; i >= 0; i--) {   // 右 → 左
            p *= nums[i];
            best = Math.max(best, p);
            if (nums[i] == 0) p = 1;
        }
        return best;
    }
}
```

### 111.5.2 Go

```go
package main

// 主解：双状态 DP，与 Java 同一套变量名
func maxProduct(nums []int) int {
	curMax, curMin, best := nums[0], nums[0], nums[0]

	for i := 1; i < len(nums); i++ {
		x := nums[i]
		a, b := x*curMax, x*curMin // 先算两个候选，避免用「已被改写」的状态
		// Go 1.21 前没有内置 max/min，手写临时变量
		mx, mn := x, x
		if a > mx {
			mx = a
		}
		if b > mx {
			mx = b
		}
		if a < mn {
			mn = a
		}
		if b < mn {
			mn = b
		}
		curMax, curMin = mx, mn // 并行赋值：两者同时更新，天然不会交错
		if curMax > best {
			best = curMax
		}
	}
	return best
}

// 第二解：前缀积两遍扫描
func maxProductTwoPass(nums []int) int {
	best := nums[0]
	p := 1
	for _, x := range nums { // 左 → 右
		p *= x
		if p > best {
			best = p
		}
		if x == 0 {
			p = 1
		}
	}
	p = 1
	for k := len(nums) - 1; k >= 0; k-- { // 右 → 左
		p *= nums[k]
		if p > best {
			best = p
		}
		if nums[k] == 0 {
			p = 1
		}
	}
	return best
}

func main() {}
```

### 111.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `max` / `min` | 内置 `Math.max` / `Math.min`，支持 `int` | 1.21 前需手写 `if`；`math.Max` 只有 `float64` | Go 版本多 8 行，但**绝不建议为了省行数用 `math.Max`**（float 转换有精度风险） |
| 双状态写回 | 只能逐条赋值，**必须借 `a`、`b` 中转** | `curMax, curMin = mx, mn` 并行赋值 | Go 在这一题**天然免疫**「用新值算旧值」的 bug，Java 必须小心 |
| 整数宽度 | `int` 恒 32 位 → `dpMin` 在极端数据上可能溢出 | `int` 在 amd64 上是 64 位 → 更安全 | **这是 Go 的隐形优势**：同一份代码在 Go 上「恰好」更不容易溢出；但这是平台相关行为，生产代码应显式写 `int64` |
| `x == 0` 的重置 | `if (x == 0) p = 1;` 一行 | 同 | 两边都把「重置」写在「更新 best」之后 —— 顺序反了会漏掉 0 本身作为答案 |
| 切片遍历 | 增强 for + 反向 `for (int i = n-1; ...)` | `for _, x := range` + 反向下标 | Go 无「反向 range」，反向必须手写下标 |
| 空数组 | `nums.length == 0` 会抛异常（`nums[0]`） | `len(nums) == 0` 在 `nums[0]` 处 panic | LC 约束 `n ≥ 1`，但**生产代码应先判空** |

## 111.6 复杂度与常见坑

### 111.6.1 复杂度推导（写结论不算本事，要能推）

- **双状态 DP 时间 O(n)**：循环 `n-1` 次，每次 2 次乘法 + 4 次比较 + 3 次赋值。常数约 9，`n = 2·10^4` 时约 `1.8·10^5` 次操作，实测 **≈ 0.1 ms**。
- **两遍扫描时间 O(n)**：`2n` 次乘法与比较，常数更小，但仍是 `Θ(n)`。
- **空间 O(1)**：滚动变量只用 `curMax / curMin / best / x / a / b` 六个 `int`。**注意「两个状态」不等于「两个数组」** —— 它们都能滚动，所以空间还是 O(1)。
- **暴力 O(n²)**：`n(n+1)/2` 个子数组，每个增量乘一次 → `≈ n²/2` 次乘法。`n = 2·10^4` 时 `2·10^8` 次，实测 **≈ 90 ms（Go）/ 180 ms（Java）**。
- **为什么改不成 O(log n)**：转移里有 `max` / `min`，**不是线性算子**，写不成矩阵幂（和 109 章同样的理由）。要 `O(log n)` 只能走线段树（合并区间时要存四元组：前缀最大积 / 最小积、后缀最大积 / 最小积），`O(log n)` 查询，但常数极大，本题用不上。

### 111.6.2 七个真实踩过的坑

1. **只维护最大值** —— 本章第一大错。`[-2,3,-4]` 答 **3**（正确 24）：`i=1` 时 `-6` 被 `max` 扔掉，`i=2` 乘 `-4` 后只能得到 `-4`，`best` 永远停在 3。修法：加 `curMin`，转移取三项 max / min。
2. **先写 `curMax` 再算 `curMin`** —— `curMin` 用到的是**新** `curMax`，状态被污染。修法：先算 `a = x*curMax; b = x*curMin;` 再统一写回；Go 用并行赋值天然免疫。
3. **漏掉「从 `i` 重开」这一项** —— 只取 `max(a, b)`。`[0, 5]` 上 `a = b = 0`，答案变 0（正确 5）。修法：`max(x, a, b)` 三项齐全。
4. **`best` 初值写 0 或 1** —— `[-1]` 答 0（正确 -1）；`[-3,-3,-1]` 若初值 1 且逻辑有漏会答 1。修法：`best = nums[0]`。
5. **两遍扫描里「重置」与「更新 best」顺序反了** —— 先 `p = 1` 再更新，就漏掉了「0 自身作为答案」的情形，`[0]` 会答 1。修法：先 `p *= x; best = max(best, p);` 再 `if x == 0 { p = 1 }`。
6. **以为「答案在 32 位内」就意味着「中间状态不会溢出」** —— 这是本章最隐蔽的坑。`dpMin` 是完全合法的中间量，但它在极端数据上可以是 `-10^k`（`k` 上万），`int` 与 `long` 都会溢出。**本题的 LC 数据不会触发**，但生产代码要么用 `long`，要么显式判断「乘积是否已经超出可比较范围」（例如同时维护对数绝对值与符号位）。
7. **用「取对数」偷懒** —— `log` 只对正数有定义，而本题有 0 与负数。就算分别维护「对数绝对值 + 符号位」，`log` 的浮点误差在 `n = 2·10^4` 时也可能把相邻两个整数判错。**只要能用整数算，就不要引入浮点。**

### 111.6.3 面试官最爱追问的三个问题

**Q1：为什么不能像 110 章那样只维护一个状态？**
> 「因为 110 章的转移是加法，加法保序，所以『接上前面』只会让当前值更极端地朝同一方向走；而本题转移是乘法，**乘负数会反序**：接上一个很大的正积得到很小的负积，接上一个很负的积反而得到很大的正积。所以要保证转移完备，必须同时知道『以 `i-1` 结尾的最大积』和『最小积』这两个极值。用一句话概括：**转移操作不保序时，状态必须成对维护。**」

**Q2：`dpMin` 为什么也要做 DP，不能随便留一个负数吗？**
> 「不行。固定 `x < 0` 时，映射 `P ↦ P·x` 对 `P` 严格反序，所以『乘以 `x` 后最大的那个』只能由『`P` 中最小的那个』给出。留一个随便的负值，得到的 `P·x` 未必是最大。也就是说 `dpMin` 自身也需要一个**最优子结构**，它和 `dpMax` 享有完全对称的 DP 过程 —— 这也是为什么两个转移式长得一模一样（只是 max/min 互换）。」

**Q3：如果数组长度到 `10^5`、元素到 `10^4`，答案肯定超过 32 位了，你怎么处理？**
> 「分三层回答。**第一，题目是否还保证答案在 32 位内？** 如果保证，那用 `int` 存 `dpMax` 没问题，但 `dpMin` 仍可能溢出，要用 `int64`/`long` 兜住。**第二，如果不保证**，正确答案本身可能有几万位，只能上 `BigInteger`（Java）/ `math/big`（Go），此时算法从 `O(n)` 变成 `O(n·位数)`，乘法变成大数乘法，实测在 `n = 10^5` 时会很慢。**第三，如果只要比较大小**，可以维护 `(log|P|, 符号)` 二元组：乘法变成对数加法，比较变成先比符号再比对数，`O(n)` 且常数小 —— 代价是有浮点误差，需要在高精度场景下用定点数或引入误差容限。」

## 附：本章小结（可背走的三句话）

```text
① 乘积最大 = 双状态：dpMax[i] / dpMin[i] 同时维护，因为乘负数会把最小翻成最大
② 转移三项缺一不可：max(x, x·dpMax[i-1], x·dpMin[i-1])；写回前必须先算完两个候选
③ 答案取 max_i dpMax[i]；两遍前缀积是等价的第二解，可用来交叉验证
```
