## 003.1 题目

**原题链接**：<https://leetcode.cn/problems/3sum/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`，请找出**所有**满足 `nums[i] + nums[j] + nums[k] == 0` 且**下标互不相同**的三元组 `[nums[i], nums[j], nums[k]]`，返回这些三元组组成的列表，**答案中不可以包含重复的三元组**。

四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **下标互不相同**（`i ≠ j ≠ k`） | 「下标 `i != j`、`i != k`、`j != k`」 | 允许同一个元素用两次 → `[0,0,0]` 会被 `i=j=k` 造出来 |
| **按值去重，不是按下标去重** | 「不可以包含重复的三元组」 | `[-1,0,1]` 出现两次 → WA。注意：`nums = [-1,0,1,0]` 里两个 `0` 可以各用一次，产生**同一个**三元组，只输出一次 |
| **输出所有解，不是任一组** | 「找出所有…三元组」 | 找到一组就 `return` → 漏解 |
| **三元组内部顺序不重要** | 输出是「三元组」而非有序排列 | 返回 `[1,0,-1]` 与 `[-1,0,1]` 视为重复 → 必须自己定一个规范顺序 |

> ⚠️ 最后一条是最容易想歪的：**题目没说「三元组要排序」，但「重复三元组不能出现」等价于「必须先给三元组定一个规范的表示」**。排序数组正好给了这个规范：`a[i] <= a[j] <= a[k]`。这就是为什么这题几乎只能用「先排序」。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `3 <= nums.length <= 3000` | n 至多 3000 | **O(n²) = 9·10⁶**：本机 2 核容器实测（JDK 17 / Go 1.19，n=3000 随机数据）**Java ≈ 1.3 ms、Go ≈ 0.4 ms**，完全安全；**O(n³) ≈ 4.5·10⁹** 按 10⁸ 次/秒算要 40 秒以上，必 TLE |
| `-10^5 <= nums[i] <= 10^5` | 单个元素 ±1e5 | 三个相加最坏 ±3·10⁵，**Java 的 `int` 安全**；但如果题目放大到 `±10^9`，三个相加就到 `±3·10⁹`，必须换 `long` |
| 答案数量级 | 最坏 O(n²) 个 | 例如全 0 数组只有 1 个解；但构造 `[-m..m]` 型数组时解数可达 O(n²)，**输出本身就要 O(n²) 时间**，不可能更快 |
| **允许重复值** | 值域小、n 也小 | 重复值密集 → **去重逻辑是本题的主战场** |

> 💡 **量级反推**：`n = 3000` 这个数字本身就是出题人给的暗号 —— 它刚好让 O(n²) 通过（9·10⁶），又刚好让 O(n³) 死掉（2.7·10¹⁰）。**看到 n ≈ 3000，条件反射就是「双层枚举 + 第三个数用查找」**。这也是你在面试里应该主动说出口的第一句话。

### 示例

```
输入：nums = [-1, 0, 1, 2, -1, -4]
输出：[[-1, -1, 2], [-1, 0, 1]]
解释：
  nums[0] + nums[1] + nums[2] = -1 + 0 + 1 = 0
  nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0   ← 与上一行是同一个三元组，只输出一次
  nums[0] + nums[3] + nums[4] = -1 + 2 + (-1) = 0

输入：nums = [0, 1, 1]
输出：[]
解释：唯一的三元组 0+1+1 = 2 ≠ 0

输入：nums = [0, 0, 0]
输出：[[0, 0, 0]]
解释：三个 0 各用一次，是合法的；只输出一次
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [0,0,0,0]              → 暴露「外层不去重」：会输出 4 次 [0,0,0]
② [-2,0,1,1,2]           → 暴露「内层命中后不跳过重复」：[-2,1,1] 会输出两次
③ [1,2,-2,-1]            → 暴露「先排序但忘记结果也要按规范序」：长度 4 小于 5，靠边界活
④ [-1,0,1,2,-1,-4,-2,-3,3,0,4] → 多解密集，暴露「漏解」（外层用 while 而不是 for 时容易跳错）
```

第 ① 条是最经典的：**四个 0 只有一种三元组**。如果你的代码输出 4 次，说明你在「值层面」没有去重，只是在「下标层面」保证了不重复使用。

## 003.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```java
// 暴力：枚举所有 i < j < k
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        for (int k = j + 1; k < n; k++)
            if (nums[i] + nums[j] + nums[k] == 0) 收集(nums[i], nums[j], nums[k]);
```

- 时间 **O(n³)**，空间 **O(1)**（不算结果）。
- `n = 3000` 时 `C(3000,3) ≈ 4.5·10⁹` 次 —— 比「2.7·10¹⁰」更准确的说法是组合数，但结论一样：**TLE**。
- 就算换成 `n = 300`，它还有第二个致命问题：**结果里全是重复三元组**，你不得不再做一次 O(k²) 的去重（或者对每组排序后塞进 `Set`）。所以暴力不但慢，还**错**。

> 📌 这里要先建立一个意识：**「暴力 + 事后去重」的复杂度是 O(n³ + k log k)，而「排序 + 双指针 + 边枚举边去重」是 O(n²)。前者在任何 n 上都不是对手，因为它的常数还更大。**

### 第二步：卡点在哪

把三重循环重写成「固定两个、查第三个」：

```
固定 i, j  →  需要 nums[k] == -(nums[i] + nums[j])
```

这就已经是 001 的形状了（找 `target - x`）。于是有两条路：

| 思路 | 复杂度 | 卡点 |
| --- | --- | --- |
| 固定 `i`，内层用**哈希**找 `-(a[i]+a[j])` | O(n²) 时间 / O(n) 空间 | 能过，但**去重极难写对**：哈希只告诉你「值存不存在」，不告诉你「这个值是不是已经用过了」 |
| 固定 `i`，内层用**排序 + 双指针** | O(n²) 时间 / O(1) 空间 | 需要先排序（O(n log n)，被 O(n²) 吸收），难点变成**三层去重** |

真正让哈希方案输掉的不是复杂度，而是**去重**。举个例子：`nums = [-2, 0, 1, 1, 2]`，固定 `i` 指向 `-2`，内层哈希会先找到 `(0, 2)`，再找到 `(1, 1)` —— 这是两个不同的解，没问题；但换一个 `-2` 的副本（`[-2, -2, 0, 1, 1, 2]`）时，同一个解会被整套重复一遍。要压掉它，你必须**把三元组排序后塞进 `Set<List<Integer>>`**，这就带来了 O(k) 的空间和 k 倍的哈希开销。

**卡点从「找解」变成了「枚举的规范化」**：只要保证「每个解只在唯一的一个枚举位置上产生」，就不需要事后去重。**排序 + 双指针正好提供了这样一个规范枚举。**

### 第三步：灵感的来源 —— 排序把枚举变成「字典序生成」

排序之后，任何一个解都可以唯一地写成 `a <= b <= c`。于是「枚举所有解」等价于「**按字典序生成所有满足 `a <= b <= c` 且 `a+b+c = 0` 的三元组**」。而字典序枚举有一个巨大的好处：

```
当前枚举到 (a[i], a[j], a[k])：
  若和偏小 → 想让下一个候选变大 → 只能把「最小能变的位置」变大 → j++
  若和偏大 → 想让下一个候选变小 → 只能把 k 变小 → k--
```

这就是 002 的对撞双指针，只不过现在 `a[i]` 是固定的常数项。**换句话：003 = 对每个 `i`，解一次「两数之和 = -a[i]」的 002。**

### 另一个关键观察：剪枝的边界

排序后还有一个副作用：**可以提前终止**。

- 若 `a[i] > 0`：因为 `a[i] <= a[j] <= a[k]`，三个数全正，和不可能为 0 → **整个外层循环可以 `break`**。
- 若 `a[i] + a[i+1] + a[i+2] > 0`：最小的三个都超 0 → 后面所有 `i` 都不行 → `break`（可选剪枝）。
- 若 `a[i] + a[n-1] + a[n-2] < 0`：最大的两个配上 `a[i]` 都不够 → 这个 `i` 无解 → `continue`（可选剪枝）。

第一条是**必须说出来的**，它是「为什么这题能比 O(n²) 更快地跑完实际数据」的主要理由。

## 003.3 原理拆解

### 003.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 去重难度 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 三重暴力 + 事后 `Set` 去重 | O(n³ + k log k) | O(k) | 低（但常数巨大） | n ≥ 300 就 TLE；本题直接不可用 |
| **固定 `i` + 内层哈希 + `Set` 去重** | O(n²) | **O(n + k)** | **高**（要靠 `Set<List>` 兜底） | 空间吃紧；`List` 作为 HashMap key 的哈希开销大 |
| 固定 `i` + 内层双指针 + 原地去重 ✅ | **O(n²)** | **O(1)**（不算结果） | 中（三处 `skip` 要写对） | 输入不允许改变（只读流）时不能原地排序 |
| 排序 + 三指针（i, j, k 同向） | O(n²) | O(1) | 高 | 三个指针的移动规则互相耦合，实际写出来更容易错 |

**为什么双指针版在「空间」上赢**：哈希版要为每个 `i` 重建一张表（或用一张表 + 计数），空间 O(n)；双指针版只用 `i, j, k` 三个下标。「不重复使用同一个元素」这条约束，双指针用 `j = i+1` 起点天然满足，而哈希要额外判断。

### 003.3.2 为什么这个做法是对的（正确性论证）

正确性要证两件事：**（A）不漏解；（B）不重复**。

**（A）不漏解**

排序后设 `a` 为有序数组。任取一个真实解，把它的三个值按序写成 `(x, y, z)`，`x <= y <= z`，`x+y+z=0`。设 `i` 是 `x` 在 `a` 中的**第一次出现**位置。

1. 外层循环一定会在 `i` 处执行一次内层（因为 `a[i]` 是 `x` 的首个出现，不会被「跳过重复」的 `continue` 拦掉）。
2. 内层是 002 的双指针，起点 `l = i+1`、`r = n-1`。由 002 的循环不变量：**只要解 `(y 的位置, z 的位置)` 落在 `[i+1, n-1]` 内，双指针一定能找到它**。
3. `y >= x` 且 `z >= y`，所以 `y`、`z` 在数组中的位置必然 `> i`（`x` 的首个出现位置之后，因为 `a` 非递减，所有 `>= x` 的值都不会出现在 `i` 之前）。

所以 `(x, y, z)` 会被 (1)(2)(3) 联合保证找到。∎

> ⚠️ 这里有个微妙点必须强调：**为什么 `l` 从 `i+1` 开始，而不是 `0`？** 因为任意解都可以重排成 `a <= b <= c`，`a` 由外层负责，内层只需要找 `b, c` 且 `b, c >= a`。若从 `0` 开始，`i=j=k` 或重复使用同一个元素就无法排除。

**（B）不重复**

三处 `skip` 各管一层：

| 位置 | 代码 | 管住什么 | 若缺失 |
| --- | --- | --- | --- |
| 外层 | `if (i > 0 && a[i] == a[i-1]) continue;` | 相同的第一元只枚举一次 | `[0,0,0,0]` 输出 4 次 `[0,0,0]` |
| 内层命中后左 | `while (l < r && a[l] == a[l+1]) l++;` | 命中后相同第二元只算一次 | `[-2,0,1,1,2]` 中 `[-2,1,1]` 输出两次 |
| 内层命中后右 | `while (l < r && a[r] == a[r-1]) r--;` | 命中后相同第三元只算一次 | `[0,-1,1,1]` 中 `[-1,0,1]` 输出两次 |

**为什么「命中后才去重」是对的（而不是每轮开头就去重）**：`a[j] + a[k]` 的大小随 `j` 增大、`k` 减小而单调，所以对固定的 `a[i]`，**同一个 `(a[j], a[k])` 值对至多产生一次命中**。只有「命中之后」，`l` 和 `r` 才有必要一起跳到下一个不同值；否则会在同一对值上反复命中。反过来说，如果「每轮开头就跳过相同值」，也能得到正确答案，只是会漏掉「同一值不同下标」的合法组合 —— 比如 `[-2,1,1]` 用的就是两个不同的 `1`，跳早了会丢掉这个解。

**为什么外层去重要「和前一个比」，而不是「和后一个比」**：和前一个比是「**我已经在 `i-1` 位置枚举过这个值了**」的判断，语义上更直接；和后一个比（`a[i] == a[i+1]` 就跳过）是等价写法，但要在循环末尾多写一行，且容易在 `i == n-1` 时越界。

### 003.3.3 通用解题思路（可迁移的那一层）

本题是 **「n 数之和」降维法** 的第一个实例：

```
k 数之和：a1 + a2 + ... + ak = target
   ↓ 排序后固定 a1（外层循环，含去重）
(k-1) 数之和：a2 + ... + ak = target - a1
   ↓ 固定 a2
...
2 数之和：ap + aq = target'   ← 用双指针 O(n) 解决（002）
```

层级与复杂度：

| 题 | 固定几层 | 最后几数用双指针 | 时间 |
| --- | --- | --- | --- |
| 两数之和（167） | 0 层 | 2 数 | O(n) |
| 三数之和（15） | 1 层 | 2 数 | O(n²) |
| 四数之和（18） | 2 层 | 2 数 | O(n³) |
| k 数之和 | k-2 层 | 2 数 | O(n^(k-1)) |

**这个模型的价值**：它告诉你「每往下降一维，复杂度就要乘一个 n」，所以能降到 2 数就别停。同时它解释了为什么 18 之后的题都用**哈希 + 分组**（如 LC 454 四数相加 II）：那里是 4 个**独立数组**，可以「两两分组」把 O(n⁴) 一次压到 O(n²)。

属于同一模型的题：

| 题 | 降维方式 | 去重要点 |
| --- | --- | --- |
| [LC 15 三数之和](https://leetcode.cn/problems/3sum/) | 固定 1 个 + 双指针 | 1 处外层 + 2 处内层 |
| [LC 18 四数之和](https://leetcode.cn/problems/4sum/) | 固定 2 个 + 双指针 | 2 处外层 + 2 处内层，且要防溢出 |
| [LC 16 最接近的三数之和](https://leetcode.cn/problems/3sum-closest/) | 固定 1 个 + 双指针 | **不需要去重**（只求一个最值） |
| [LC 259 较小的三数之和](https://leetcode.cn/problems/3sum-smaller/) | 固定 1 个 + 双指针**数个数** | 不需要去重（数的是下标的组合） |
| [LC 923 三数之和的多种可能](https://leetcode.cn/problems/3sum-with-multiplicity/) | 固定 1 个 + 双指针 + 乘法原理 | 按**下标**计数，反而不能去重 |

> 注意后两行是个反向陷阱：**「去重」不是三数之和的通性，而是「按值输出唯一解」这个特定需求的产物**。LC 923 要求按「下标三元组」计数，去重就是错的。看题先看「输出的是值还是下标」。

### 003.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**一组**解 | 可以提前 `return` | 命中最外层就直接返回；复杂度仍是 O(n²) 最坏（可能无解） |
| 求**最接近** 0 的三数之和 | 目标从 `==` 变成「绝对值和最小」 | 指针移动仍靠单调性，但**不去重、不剪枝**，因为每个候选都可能是答案（LC 16） |
| 数组**不能修改** | 不能原地排序 | 复制一份再排序，空间 O(n)；或者放弃排序走哈希 + `Set` 去重，空间 O(n) 也更慢 |
| 值域放大到 `±10^9` | 三数相加溢出 | Java 用 `long s = (long) a[i] + a[j] + a[k]`；Go 64 位平台安全，但写 `int64` 更稳 |
| 要求输出**下标三元组**（不按值去重） | 排序会丢原下标 | 备份 `(值, 原下标)`，或在结果里回填下标；去重逻辑全部作废 |
| 数据量放大到 `n = 10^5` | O(n²) 不够 | **无解**——输出可能就有 O(n²) 个。若只要「是否存在」，可退化成「枚举 `i` + 167」，仍是 O(n²)，只能用 FFT/卷积做近似加速 |

**进阶延伸（自己写代码验证）**：

- **LC 16 最接近的三数之和**：把「等于」换成「差最小」，体会**去重代码整体消失**带来的简化。
- **LC 259 较小的三数之和**：命中不再是「一组解」，而是「一段连续的 `k`」，要用**数个数**而不是收集。这是「双指针做计数」的重要变体。
- **LC 454 四数相加 II**：四个独立数组，用哈希把 O(n⁴) 打成 O(n²)，对照本章理解「什么时候该降维、什么时候该分组」。

## 003.4 图解推演

### 003.4.1 主样例的完整轨迹

```
nums = [-1, 0, 1, 2, -1, -4]
排序后 a = [-4, -1, -1, 0, 1, 2]
下标(0-based) 0   1   2  3  4  5

════════ i = 0  (a[0] = -4)，需要两数和 = 4 ════════
 l=1          r=5
┌────┬────┬────┬────┬────┬────┐
│ -4 │ -1 │ -1 │  0 │  1 │  2 │
└────┴────┴────┴────┴────┴────┘
  ↑i    ↑l                  ↑r     s = -4 + (-1) + 2 = -3 < 0  →  l++
        →                       ←
 s = -4 + (-1) + 2 = -3 < 0  →  l++      (l 移到下标 3)
 s = -4 +  0   + 2 = -2 < 0  →  l++      (l 移到下标 4)
 s = -4 +  1   + 2 = -1 < 0  →  l++      (l=5，l>=r 退出)
 → i=0 无解

════════ i = 1  (a[1] = -1)，需要两数和 = 1 ════════
 l=2          r=5
┌────┬────┬────┬────┬────┬────┐
│ -4 │ -1 │ -1 │  0 │  1 │  2 │
└────┴────┴────┴────┴────┴────┘
       ↑i    ↑l              ↑r     s = -1 + (-1) + 2 = 0  ✅ 命中 [-1,-1,2]
             →                ←
 命中后：l 跳到下一个不同的值（下标 3 的 0），r 跳到下标 4 的 1
 s = -1 + 0 + 1 = 0  ✅ 命中 [-1,0,1]
 命中后：l→4, r→3，l>=r 退出

════════ i = 2  (a[2] = -1)，与前一个相同 → continue（去重）════════
════════ i = 3  (a[3] = 0 > 0? 否，0 不大于 0，继续) ════════
 l=4, r=5   s = 0 + 1 + 2 = 3 > 0 → r-- → l>=r 退出
════════ i = 4  (a[4] = 1 > 0) → break（剪枝）════════
```

### 003.4.2 三处去重各自拦下了什么

用 `nums = [-2, 0, 1, 1, 2]`（排序后 `[-2, 0, 1, 1, 2]`）单个 `i` 的执行看内层去重：

| 轮 | l | r | a[l] | a[r] | s | 动作 | 输出 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 4 | 0 | 2 | 0 | 命中，然后 l 跳过重复的 `1`，r 跳过重复的 `2` | `[-2,0,2]` |
| 2 | 2 | 3 | 1 | 1 | 0 | 命中，l 跳过第二个 `1`，r 跳过第一个 `1` | `[-2,1,1]` |
| 3 | 3 | 2 | — | — | — | `l >= r` 退出 | — |

若把「命中后跳重复」删掉，第 1 轮之后 `l` 停在 2（另一个 `1`? 不，下标 2 是 `1`，下标 3 也是 `1`）—— 就会把 `[-2,1,1]` 输出两次。

```
数组:  -2   0   1   1   2
        i   ↑l      ↑r          命中 [-2,0,2]
            └─ l 向右跨过所有 1 ─┐
                                └→ l=2? 若已跳过则 l 到 3
```

用一个更直观的「值域扫描图」表示内层要覆盖的 `(j,k)` 集合：

```
        k=1   k=2   k=3   k=4
 j=1 │   ✗  ─── ✗  ─── ✅(0,2)          ← 第一段
 j=2 │        ✗  ─── ✅(1,1)            ← 第二段
 j=3 │              ✗                   ← (1,2)? 已被 l>=r 挡住
 ✗ = 和不为 0     ✅ = 命中
```

内层双指针从右上角 `(1,4)` 出发向左/向下走，**恰好每条反对角线只走一遍**，这就是 O(n) 的来源。

### 003.4.3 三条路线对比图

```
                  ┌──────────── 输入 nums（可能含大量重复值）────────────┐
                  │                                                    │
      ┌───────────▼────────────┐                     ┌────────────────▼─────────────────┐
      │ 路线 A：排序 + 双指针    │                     │ 路线 B：固定 i + 哈希 + Set 去重    │
      │ O(n²) / O(1) 额外空间   │                     │ O(n²) / O(n + k)                 │
      └───────────┬────────────┘                     └────────────────┬─────────────────┘
                  │                                                   │
     ① 排序定下「a<=b<=c」的规范                      ① 每个 i 重建哈希表

                  │                                                   │
         【本题选 A】                                  【输入不可改 / 只要一组解时考虑 B】
```

## 003.5 双语言实现

### 003.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        // 排序是全部正确性的地基：它同时给了「枚举规范序」和「双指针单调性」两件东西
        Arrays.sort(nums);
        int n = nums.length;
        List<List<Integer>> res = new ArrayList<>();

        // 外层只到 n-3：再往后凑不出三个数（i < n-2 与 i <= n-3 等价）
        for (int i = 0; i < n - 2; i++) {
            // 去重第 1 层：相同的第一元只枚举一次。
            // 与 i-1 比较而非 i+1，是因为"前一个已经枚举过同值"的语义更直接
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            // 剪枝：排序后若最小元素都 > 0，后面全正，三数之和必 > 0
            if (nums[i] > 0) {
                break;
            }

            int l = i + 1, r = n - 1;
            while (l < r) {
                // 值域最多 ±10^5，int 累加安全；若放大到 ±10^9 必须改成 long
                int s = nums[i] + nums[l] + nums[r];
                if (s == 0) {
                    res.add(Arrays.asList(nums[i], nums[l], nums[r]));

                    // 去重第 2 层：命中后把 l 推过所有与 nums[l] 相同的值，
                    // 否则同一个第二元会再配出相同的三元组
                    while (l < r && nums[l] == nums[l + 1]) {
                        l++;
                    }
                    // 去重第 3 层：同理推过相同的第三元
                    while (l < r && nums[r] == nums[r - 1]) {
                        r--;
                    }
                    // 命中后两个指针都要动：只动一个会卡在同一对值上死循环
                    l++;
                    r--;
                } else if (s < 0) {
                    l++;   // 和偏小 → 只能让中间这个变大
                } else {
                    r--;   // 和偏大 → 只能让右端变小
                }
            }
        }
        return res;
    }
}
```

### 003.5.2 Go

```go
package main

import "sort"

// threeSum 返回所有和为 0 的不重复三元组。变量名与 Java 版逐行对齐。
func threeSum(nums []int) [][]int {
	// 原地排序：Go 的 sort.Ints 直接改传入的切片。
	// 注意这会修改调用方的数据，竞赛/面试都接受；生产代码应先 copy 一份
	sort.Ints(nums)
	n := len(nums)

	// 用空切片而不是 nil：LeetCode 对两者都接受，
	// 但 append 到 nil 切片同样合法，且 json 序列化时 [] 比 null 更符合期望
	res := [][]int{}

	for i := 0; i < n-2; i++ {
		// 去重第 1 层：相同第一元只枚举一次
		if i > 0 && nums[i] == nums[i-1] {
			continue
		}
		// 剪枝：最小元素都 > 0，后面不可能凑成 0
		if nums[i] > 0 {
			break
		}

		l, r := i+1, n-1
		for l < r {
			// Go 的 int 在 64 位平台是 64 位，本题不会溢出
			s := nums[i] + nums[l] + nums[r]
			switch {
			case s == 0:
				// 必须新建切片字面量：如果复用同一个底层数组，
				// 后续修改会污染已经 append 进去的结果（Go 切片共享底层数组的经典坑）
				res = append(res, []int{nums[i], nums[l], nums[r]})

				// 去重第 2、3 层
				for l < r && nums[l] == nums[l+1] {
					l++
				}
				for l < r && nums[r] == nums[r-1] {
					r--
				}
				// 两个指针同时向内收，避免卡在同一对值上
				l++
				r--
			case s < 0:
				l++
			default:
				r--
			}
		}
	}
	return res
}
```

### 003.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 排序 API | `Arrays.sort(int[])`（双轴快排，**改原数组**） | `sort.Ints([]int)`（pdqsort，**改原切片**） | 两者都原地改；若调用方还要用原数组，必须自己 `clone()` / `append([]int(nil), nums...)` |
| 结果容器 | `List<List<Integer>>` | `[][]int` | Go 是「切片的切片」，每个内层切片是独立 header |
| 追加三元组 | `Arrays.asList(...)` | `[]int{...}` | **Go 里必须每次新建**，复用同一个变量会因共享底层数组而互相覆盖；`Arrays.asList` 每次都新建 `ArrayList`，没这个问题 |
| 装箱 | `List<Integer>` 有装箱，`int` → `Integer` | `[]int` 无装箱 | n=3000 时差异不明显；结果集大时 Go 更快 |
| 提前退出 | `break` / `continue` | `break` / `continue`（语义相同） | Go 的 `break` 只跳出 `switch` 或最近一层循环，**在 `switch` 里想跳外层循环要用 label** |
| 空结果 | 返回空 `ArrayList` | 返回 `[]int{}` 或 `nil` | LeetCode 两者都接受；`nil` 在 `len()` 上等价于 0，安全 |

### 003.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"fmt"
	"math/rand"
	"sort"
	"testing"
)

// brute 用三重循环枚举所有 i<j<k，把三元组排序后塞进 set 去重
// 这是「最笨但绝对正确」的参照物：不排序原数组，不去重逻辑，纯粹按值规范化
func brute(nums []int) map[string]bool {
	set := map[string]bool{}
	n := len(nums)
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			for k := j + 1; k < n; k++ {
				if nums[i]+nums[j]+nums[k] == 0 {
					t := []int{nums[i], nums[j], nums[k]}
					sort.Ints(t) // 把三元组本身排序，作为去重的规范 key
					set[fmt.Sprint(t)] = true
				}
			}
		}
	}
	return set
}

// toSet 把结果规范化成同样的 key 集合；同时检查每组内部是否有序（证明我们按规范序输出）
func toSet(res [][]int) (map[string]bool, bool) {
	set := map[string]bool{}
	for _, t := range res {
		if len(t) != 3 {
			return nil, false
		}
		if !(t[0] <= t[1] && t[1] <= t[2]) {
			return nil, false // 顺序不规范
		}
		key := fmt.Sprint(t)
		if set[key] {
			return nil, false // 重复输出
		}
		set[key] = true
	}
	return set, true
}

func TestThreeSumRandom(t *testing.T) {
	r := rand.New(rand.NewSource(42))
	for iter := 0; iter < 20000; iter++ {
		n := 3 + r.Intn(12) // 3..14，暴力 O(n³) 仍可跑
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(9) - 4 // 值域 [-4,4]：重复值密集，专逼去重
		}

		// 必须传副本：threeSum 会原地排序，直接传 nums 会让 brute 拿到排好序的数组，
		// 虽然结果不变，但掩盖了「是否真的原地改了数据」这一事实
		got := threeSum(append([]int(nil), nums...))
		want := brute(nums)

		set, ok := toSet(got)
		if !ok {
			t.Fatalf("iter=%d nums=%v 结果不规范或重复: %v", iter, nums, got)
		}
		if len(set) != len(want) {
			t.Fatalf("iter=%d nums=%v 解数不符 got=%d want=%d", iter, nums, len(set), len(want))
		}
		for k := range want {
			if !set[k] {
				t.Fatalf("iter=%d nums=%v 漏解 %s", iter, nums, k)
			}
		}
	}
}

func TestThreeSumEdge(t *testing.T) {
	cases := [][]int{
		{0, 0, 0, 0},
		{-2, 0, 1, 1, 2},
		{0, 1, 1},
		{0, 0, 0},
	}
	for _, c := range cases {
		got := threeSum(append([]int(nil), c...))
		set, ok := toSet(got)

		}

		if len(set) != len(want) {
			t.Fatalf("nums=%v got=%v want=%v", c, got, want)
		}
	}
}
```

## 003.6 复杂度与常见坑

### 003.6.1 复杂度推导

- **排序**：`O(n log n)`。
- **外层**：`i` 从 `0` 到 `n-3`，共 `O(n)` 次。
- **内层**：`l` 只增、`r` 只减，总移动量 ≤ `n`，故单次内层 `O(n)`。
- **总时间**：`O(n log n) + O(n)·O(n) = O(n²)`。
  - **注意**：不是 `O(n² log n)`。内层的双指针不是二分，是「每个元素至多被 `l` 或 `r` 扫过一遍」。
- **空间**：`O(1)`（不算结果数组）。Java 的 `Arrays.sort(int[])` 用双轴快排 + 少量栈空间，`O(log n)`；Go 的 `sort.Ints` 是 pdqsort，也是 `O(log n)` 栈。若把结果算进去，是 `O(k)`，`k` 为解的个数。
- **最坏解数**：`k = O(n²)`，例如 `nums = [-m, ..., -1, 0, 1, ..., m]` 型的构造。此时**输出本身就吃掉 O(n²)**，算法的时间下界不可能低于它。

### 003.6.2 八个真实踩过的坑

1. **忘掉任一层去重** —— 三处 `skip` 少一处就 WA。自造 `[0,0,0,0]` 与 `[-2,0,1,1,2]` 各测一次，两分钟能定位。
2. **命中后只动一个指针** —— `if (s == 0) { res.add(...); l++; }` 而忘了 `r--`，会在 `l` 走到 `r` 之前反复命中同一对值。虽然最终靠 `l < r` 退出，但会产生重复解。
3. **`l` 从 `0` 开始** —— 内层必须 `l = i + 1`，否则 `i`、`j`、`k` 可以重合，`[0,0,0]` 会被构造成非法解。
4. **`s < 0` 时移动 `r`** —— 方向反了。和偏小要让中间值变大（`l++`），和偏大要让右端变小（`r--`）。这类错误在 `[1,2,-3]` 这种三元组上会直接返回空。
5. **剪枝写成 `if (nums[i] >= 0) break;`** —— `nums[i] == 0` 时，`[0,0,0]` 是合法解，必须继续。正确条件严格是 `> 0`。
6. **去重时数组越界** —— `while (nums[l] == nums[l+1]) l++;` 少了 `l < r` 保护，在 `[0,0,0]` 上 `l+1` 会越界。**`while` 里的双条件不能省。**
7. **Go 里复用同一个切片追加** —— `t := make([]int,3)` 放在循环外，每轮改 `t[0..2]` 再 `append`，结果所有行都指向同一个底层数组，最后全部变成最后一组。必须每次 `[]int{...}` 新建。
8. **以为结果要为每个三元组排好序** —— 因为原数组已排序、且 `i < l < r`，输出天然是 `a[i] <= a[l] <= a[r]`，**不需要再排**。多写一次 `sort` 只是浪费，不会错。

### 003.6.3 面试官最爱追问的三个问题

**Q1：为什么要先排序？不排序能做吗？**
> 「排序买到两样东西：① **枚举规范**——任何解都能唯一写成 `a <= b <= c`，于是『按值去重』变成『跳过相邻相同值』这件机械的事；② **单调性**——内层才能用双指针，把 O(n) 的第三层压成 O(1) 摊还。不排序也能做：固定 `i`、`j`，用哈希找 `-(a[i]+a[j])`，时间同样 O(n²)，但结果要去重就得把三元组排序后塞进 `Set`，空间变成 O(n+k)，常数也更大。所以『有序』是把 O(n) 空间买成 0 空间的交易。」

**Q2：时间复杂度到底是多少？内层双指针会不会让它变成 O(n² log n)？**
> 「是 O(n²)。外层 O(n) 次，每次内层双指针的 `l` 只增、`r` 只减，两个指针的总移动次数不超过区间长度 n，所以单次内层是 O(n)。乘起来 O(n²)。这里容易犯的错是把「内层看上去有个 while」当成二分。」

**Q3：如果数组里有 10⁵ 个数，但这题还要求输出所有三元组，怎么办？**
> 「先认清输出规模：解的个数本身可能是 O(n²)，所以任何算法都不可能快过 O(n²)。这题 n 给 3000 就是因为 9·10⁶ 是「能过」的上限。若真的放大到 10⁵ 且只要『是否存在』，那可以退化成『枚举 i + 167 双指针』仍是 O(n²)，实际不可行；工程上会改用**按值分桶 / FFT 卷积求三数和为 0 的方案数**，或者干脆承认这是 O(n²) 下界问题、用并行/分片来处理。」

- 看到「输出所有不重复的组合」，先问：**我给组合定规范序了吗？** 定了规范序，去重就退化成「跳过相邻相同值」。
- 每加一层循环，都要问一遍：这一层的「重复」由谁负责压掉？
