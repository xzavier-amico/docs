## 095.1 题目

**原题链接**：<https://leetcode.cn/problems/reconstruct-itinerary/>

### 题意重述（把隐含条件补齐）

给你一份航线列表 `tickets`，`tickets[i] = [from_i, to_i]` 表示一张「从 `from_i` 飞往 `to_i`」的机票。所有机票都属于同一个人，他**从 `"JFK"` 出发**，必须**恰好使用所有机票各一次**，规划出一份行程。如果存在多种合法行程，返回**按字典序最小**的那一份机场序列。

它藏了六个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **每张票恰好用一次** | 「所有机票必须恰好使用一次」 | 这不是「找一条路」，是「走遍所有边」——欧拉路径，不是最短路 |
| **起点固定是 `"JFK"`** | 「从 JFK 出发」 | 不能从别的点开始；起点决定了欧拉路径的「出度 = 入度 + 1」 |
| **答案是机场序列，长度 = 票数 + 1** | 「返回行程」 | 返回边数会少一个；`n` 张票对应 `n+1` 个机场 |
| **字典序比较针对整条序列** | 「字典序最小的行程」 | 不是「每一站都贪心最小」就自动最小（要配合后序，见 §095.3.2） |
| **机票可以重复** | 约束没排除重复 | 同一对城市可能有多张票 → **多重图**（多重边图），不能用 `set` 去重 |
| **数据保证至少有一条合法行程** | 「如果存在多种…」的隐含前提 | 所以不用返回空，但**不代表**可以随便走（走法错会走进死胡同） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= tickets.length <= 300` | 最多 300 张票 | `O(n!)` 全排列死定（`8! = 40320`，`13! ≈ 62 亿`）；`O(E log E)` 是唯一体面的复杂度 |
| `from_i.length == to_i.length == 3` | 城市名固定 3 个大写字母 | 可以用「26³ = 17576」编码成整数加速，但没必要 |
| `from_i` 全大写 | 字典序即 ASCII 序 | Java 的 `String.compareTo` 与 Go 的 `<` 都是字典序，直接用 |
| `from_i != to_i` | 没有自环 | 省掉一类边界，但多重边仍要处理 |
| 起点一定出现在票里 | 数据保证 | 不用处理「JFK 没有任何出边」以外的空结果 |

> 💡 **量级 → 算法**：`n ≤ 300` 是「**必须多项式**」的强信号。而「每条边恰好走一次」把问题限定成了**欧拉路径**——它有线性时间的经典算法（Hierholzer），配上排序/堆就是 `O(E log E)`。**看到「恰好用一次 / 全部用完」，先想欧拉，而不是想搜索。**

### 示例

```
输入：tickets = [["MUC","LHR"],["JFK","MUC"],["SFO","SJC"],["LHR","SFO"]]
输出：["JFK","MUC","LHR","SFO","SJC"]
解释：JFK→MUC→LHR→SFO→SJC，每张票用一次。

输入：tickets = [["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]
输出：["JFK","ATL","JFK","SFO","ATL","SFO"]
解释：注意另一个合法行程 ["JFK","SFO","ATL","JFK","ATL","SFO"] 也存在，
      但 "ATL" < "SFO"，所以答案取以 ATL 开头的那个。

输入：tickets = [["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]
输出：["JFK","NRT","JFK","KUL"]
解释：如果第一步贪心选了字典序更小的 "KUL"，就再也回不来（KUL 没有出边），
      剩下的票全废。正确答案必须**先走 NRT 绕一圈，把 KUL 留在最后**。
```

### 我自造的五个边界（写完代码必须拿它们打一遍）

```text
① [["JFK","AAA"]]                          一张票 → ["JFK","AAA"]
② [["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]  贪心陷阱（见上）
③ [["JFK","AAA"],["AAA","JFK"],["JFK","AAA"],["AAA","JFK"]]
   重复票：答案 ["JFK","AAA","JFK","AAA","JFK"]（多重图必须支持重复边）
④ [["JFK","AAA"],["AAA","BBB"],["BBB","AAA"],["AAA","JFK"]]
   欧拉回路（起终点都是 JFK）→ ["JFK","AAA","BBB","AAA","JFK"]
   注意这里 AAA 必须被访问两次、BBB 一次：**点可以重复，边不行**
⑤ [["JFK","AAA"],["JFK","ZZZ"],["AAA","JFK"],["ZZZ","JFK"]]
   → ["JFK","AAA","JFK","ZZZ","JFK"]（先走小的 AAA）
```

第 ② 条是本章的照妖镜：**它证明「每一步都选最小的目的地」这种纯贪心是错的**，必须配合后序插入。

## 095.2 从暴力到最优：第一个念头为什么错

### 第一个念头 A：「枚举所有票的排列，取字典序最小的合法序列」

```
for perm in permutations(tickets):     # 最多 300! 种
    if perm[0].from != "JFK": continue
    if 整条链能串起来: 记录序列
return 字典序最小的那个
```

正确，但 `300!` 是个连「用宇宙寿命跑」都不够的数。即使缩到 `n = 13`，`13! ≈ 62 亿`，也已经不可接受。**它只能当小规模对拍 oracle**（本章 §095.5.4 就这么用）。

### 第一个念头 B：「每一步都选字典序最小的目的地，直接走到底」

这是最自然、也最坑的贪心。用反例 ② 打它：

```
tickets = [["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]
JFK 的出边：KUL、NRT，字典序 KUL < NRT

贪心第一步选 KUL → 到 KUL 后发现它没有任何出边 → 卡死，
还剩 NRT→JFK 没用 → 行程非法 ❌

正解：JFK → NRT → JFK → KUL ✅（把 KUL 这一站留到最后）
```

**失败模式**：最小目的地可能是一张「单程票」，走进去就出不来了。也就是说，**「小」不等于「安全」**。

### 第一个念头 C：「先判桥，非桥优先，没得选才走桥」（Fleury 算法）

这是欧拉路径的教科书算法：每一步都在剩余图里判断「这条边是不是桥（割边）」，**非桥优先**，只有出边全是桥时才选桥。它是对的，但每走一步都要跑一次割边判定（`O(E)`），总体 `O(E²)`，`E = 300` 时是 `9·10⁴`，能过；`E = 10⁵` 时是 `10¹⁰`，直接死。

更关键的是：**这题要「字典序最小」，每次还得在候选里排序，判桥的成本还要乘上排序因子**，代码会变得又长又慢。

### 卡点在哪

一句话：

> **我要一条「走遍所有边、且每一步尽量小」的路径。纯贪心会在死胡同处翻车，而「先判桥」的代价太高。**

### 灵感的来源 —— Hierholzer：**别怕走进死胡同，死胡同就该排在最后**

Hierholzer 的核心观察极其漂亮：

> 如果我沿着边一路走，**直到走不动为止**，那么「走不动」的那个点，必然是整条欧拉路径的**终点**（或某个必须排在末尾的位置）。

于是策略变成：

```
dfs(u):
    while u 还有没用的出边:
        取一条出边 (u,v) 并标记已用
        dfs(v)                  ← 先深入，把 v 那边的边都用完
    # 到这里，u 的所有出边都用完了
    把 u 追加到路线末尾            ← 后序插入（postorder）
```

最后把整条路线**逆序输出**。在反例 ② 上跑一遍：

```
dfs(JFK): 取 KUL（最小）→ dfs(KUL)：无出边 → 追加 KUL     路线 = [KUL]
           取 NRT      → dfs(NRT)：取 JFK → dfs(JFK)：无出边（票已用光）
                                                    → 追加 JFK   路线 = [KUL, JFK]
                         → 追加 NRT                            路线 = [KUL, JFK, NRT]
       → 追加 JFK                                              路线 = [KUL, JFK, NRT, JFK]
逆序 → [JFK, NRT, JFK, KUL]  ✅
```

**注意看**：贪心第一步真的选了 `KUL`（最小的那条），但因为它没有出边，`KUL` 被追加在最前面，**逆序后跑到了最后面**。这就是「后序插入」的全部魔法——**死胡同自动被推到终点位置，不需要显式判桥**。

## 095.3 原理拆解

### 095.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 全排列枚举 | `O(n!)` | `O(n)` | 25 行 | `n ≥ 11` 就不可接受；只能当 oracle |
| DFS 回溯（试最小目的地，失败回退） | 最坏 `O(n!)` | `O(n)` | 40 行 | 绝大多数输入上仍是指数级；只在「解极少」时侥幸快 |
| Fleury（显式判桥，非桥优先） | `O(E²)` | `O(E)` | 70 行 | `E = 10⁵` 时 `10¹⁰`；且「字典序最小」还要额外排序 |
| **Hierholzer + 邻接表排序 + 指针** | `O(E log E)` | `O(V+E)` | 45 行 | 排序后要按下标从前往后取（从后往前取会变成「最大优先」） |
| **Hierholzer + 最小堆** ✅ | **`O(E log E)`** | `O(V+E)` | 55 行（Go 要写堆） | 常数略大；但「随时取最小」语义最直白，也不怕中途动态加边 |
| Hierholzer + 邻接矩阵 + 字母扫描 | `O(E · 26³)` | `O(26⁶)`（太大） | 50 行 | 城市数一多矩阵就爆；本题城市数受限于 `26³` 才勉强可行 |
| 迭代版 Hierholzer（显式栈） | `O(E log E)` | `O(V+E)` | 55 行 | 代码更绕；但 `E` 大到 `10⁶` 时能避免递归深度问题 |

**「排序 + 指针」与「最小堆」的取舍**：

| 维度 | 排序 + 指针 | 最小堆 |
| --- | --- | --- |
| 复杂度 | `O(E log E)`（一次性排序） | `O(E log E)`（`E` 次出堆，每次 `log`） |
| 常数 | 更小（排序 + 顺序访问） | 更大（每次堆调整） |
| 代码 | `sort` 后维护一个下标 | Java：`PriorityQueue`；Go：手写 5 个方法 |
| 语义 | 「预先排好、按顺序消费」 | 「随时要最小的」——与题意最贴合，也最容易讲清 |
| 何时更优 | 边集在开始时完全确定（本题就是） | 边是动态加入的 |

> 面试里两个都写出来最好：**「排序 + 指针」是工程写法，「最小堆」是语义直译**。本书的 Go 版用 `container/heap`，因为「字典序最小」这个需求天然就是「随时取最小」，而 Java 的 `PriorityQueue<String>` 默认就是字典序。

### 095.3.2 为什么这个做法是对的（正确性论证）

#### 定理一：Hierholzer（后序插入 + 逆序输出）一定产出一条欧拉路径

**前提**：图（可有重边的有向图）存在从 `s` 出发的欧拉路径，即：`s` 的出度比入度大 1，其余点入度 = 出度，且所有带边的点都在同一个弱连通块里。

**证明**（对递归结构做归纳）。记 `R(u)` 为「调用 `dfs(u)` 全过程中按后序追加的序列」。我要证明：**`reverse(R(u))` 是一条从 `u` 出发、恰好用掉 `dfs(u)` 消耗的全部边、每个点出现次数与边数匹配的合法路径**。

设这次调用从 `u` 依次弹出了边 `e_1 = (u,v_1), e_2 = (u,v_2), …, e_k = (u,v_k)`（这是它自己这一层弹出的全部出边，顺序与取边顺序一致）。每次弹出 `e_i` 后立刻递归 `dfs(v_i)`，其产出为 `R(v_i)`（注意 `R(v_i)` 的**最后**一个元素一定是 `v_i`，因为 `dfs(v_i)` 结束时才追加自己）。于是

```
R(u) = R(v_1) ++ R(v_2) ++ … ++ R(v_k) ++ [u]
```

逆序：

```
reverse(R(u)) = [u] ++ reverse(R(v_k)) ++ reverse(R(v_{k-1})) ++ … ++ reverse(R(v_1))
```

现在验证它是一条合法路径：

1. **相邻性**：`reverse(R(v_k))` 的第一个元素是 `R(v_k)` 的最后一个元素 = `v_k`，而 `(u, v_k) = e_k` 是一条真实边 ✅。之后在 `reverse(R(v_k))` 内部，由归纳假设它是合法的路径；它的末尾是 `R(v_k)` 的第一个元素……接着 `reverse(R(v_{k-1}))` 的第一个元素是 `v_{k-1}`。**相邻性在块与块之间需要额外说明**：`reverse(R(v_k))` 的最后一个元素是 `R(v_k)` 的首元素，即「`dfs(v_k)` 中第一个被弹出的边的目标」，而 `dfs(v_k)` 的第一个被弹出的边就是 `(v_k, v_{k-1})`……

   更稳的写法是把归纳做在「**边**」上而不是「点」上：定义 `T(u)` = 「`dfs(u)` 消耗的边的有序序列」。由递归结构，`T(u) = (u,v_1) ++ T(v_1) ++ (u,v_2) ++ T(v_2) ++ … ++ (u,v_k) ++ T(v_k)`——**等等，这样写恰好是正序**，而算法输出的 `reverse(R(u))` 是反的。所以真正的说法是：

   ```
   reverse(R(u)) 对应的边序列 = (u,v_k) ++ T'(v_k) ++ (u,v_{k-1}) ++ T'(v_{k-1}) ++ … ++ (u,v_1) ++ T'(v_1)
   ```

   其中 `T'(v_i)` 是 `dfs(v_i)` 子调用消耗边的**反序**。由归纳假设，`T'(v_i)` 是一条从 `v_i` 出发的合法路径，并且它**结束于** `(v_i, v_{i-1})` 那个方向……这一步的细节用一个更强的归纳假设更省事：

   > **强化归纳假设**：`reverse(R(u))` 是一条从 `u` 出发、用掉 `dfs(u)` 全部边的合法路径，**并且它的终点是调用开始前 `u` 的入边来源**（即整条路径「接回」了 `u` 应该接的位置）。

   在这个强化假设下，块与块的拼接立刻成立：`reverse(R(v_i))` 从 `v_i` 出发、用掉 `dfs(v_i)` 的全部边、最后回到 `v_i` 在该层的「入口」——而 `dfs(v_i)` 的第一个出边正是 `(v_i, v_{i-1})`（因为 `v_{i-1}` 就是它下一层的入口），于是 `reverse(R(v_i))` 的末尾正好是 `v_{i-1}`，能接上 `(u, v_{i-1})` 的目标 `v_{i-1}` ✅。

2. **覆盖性**：`dfs(u)` 消耗的边 = `e_1..e_k` 加各子调用消耗的边；而拼接式里恰好是这些边的全体，每条一次（因为每条边只被 `Pop` 一次，弹出即标记为已用）。

3. **总长度**：点数 = 边数 + 1，与欧拉路径的定义一致。

所以 `reverse(R("JFK"))` 是一条从 `JFK` 出发、用尽所有边的合法路径。∎

> 上面这段的**直观版**（面试口述足够）：**每条边被用掉时，它的目标点 `v` 的整个子行程会在 `u` 之前被追加完；逆序之后，于是 `u` 总是紧挨着它为「最后一条出边」做的子行程。**「后序」保证了「父节点总在子行程之后出现」，「逆序」把这个关系翻过来，正好对上路径的方向。

#### 定理二：按字典序最小取边 + 后序插入 ⇒ 字典序最小的行程

先讲清楚「为什么贪心取最小边是安全的」。关键是把「安全」拆成两种情形：

**引理（安全选择）**：设当前在点 `u`，剩余未用的边集为 `E'`，且 `E'` 里还存在一条从 `u` 出发、用尽 `E'` 的欧拉路径。令 `(u, v)` 是 `u` 剩余出边中**目的地字典序最小**的那一条。则只有两种可能：

| 情形 | 含义 | 算法的行为 | 是否最优 |
| --- | --- | --- | --- |
| **A：走得通** | 存在一条用尽 `E'` 的行程，第一步就是 `(u,v)` | `dfs(v)` 会把 `v` 一侧的边用尽并**回到** `u`，于是 `(u,v)` 出现在这段行程的开头 | 以最小目的地开头，**必然字典序最小** ✅ |
| **B：走不通** | 走 `(u,v)` 之后就再也回不到 `u`（`(u,v)` 是剩余图里的**桥**） | `dfs(v)` 的子行程会把 `v` 追加得最靠前，**逆序后 `v` 落到行程末尾**；`u` 的其他出边由更内层的调用先用掉 | 「把桥留到最后」= Fleury 的非桥优先，**是唯一可行的排法** ✅ |

情形 A 的「回来」不是假设而是可证的：若 `u` 不是整条行程的终点，那么它有入有出，任何一条以 `u` 为起点的行程在用掉 `(u,v)` 之后必须还能回到 `u` 才能继续用 `u` 的其它出边；反过来若回不来，则 `u` 的其它出边永远用不上，说明这条行程非法。

**这张表就是「后序插入」的全部效力**：它把 Fleury 里需要显式判定的「这条边是不是桥」自动落实了——**桥 ⇒ 走过去会死 ⇒ 死胡同端点在后序里被最先追加 ⇒ 逆序后排在最后**，一条链走完，不需要任何判桥代码。

**定理二的证明思路（交换论证）**：设算法输出 `A`，`B` 是任意另一条合法行程，且 `B` 在字典序上严格小于 `A`。取第一个不同的位置 `i`（`i ≥ 1`，因为两者都以 `JFK` 开头），记 `B[i] = b < a = A[i]`。所有合法行程在位置 `0..i-1` 上必须相同（`i` 是最小差异位置），所以位置 `i` 处的选择发生在**同一段前缀之后、面对同一份剩余边集**。

1. 由引理，算法在那一刻的行为只有两种：情形 A（取最小边，且取完还能走通）或情形 B（最小边是桥，被延后到末尾）。在情形 A 下 `a` 是当时所有可用出边里最小的，`b < a` 不可用（否则算法会选 `b`），矛盾；在情形 B 下最小的边被自动排到了末尾，`a` 是「去掉那条桥之后」可用的最小边，同样不可能存在更小且可用的 `b`。
2. 因此不存在让行程在位置 `i` 接上 `b` 的合法走法，与「`B` 合法且 `B[i] = b`」矛盾。∎

> **这条论证里必须记住的两句**：① **「每次取最小」保证了只要某条小边还能排在当前位置，算法就一定用它**；② **「后序插入」保证了被延后的只能是「非留到最后不可」的边**——也就是桥。两句合起来，就得到字典序最小。

#### 定理三：本题的解一定存在且形如「入度出度差 1」

有向图存在从 `s` 出发的欧拉路径的充要条件：

| 条件 | 说明 |
| --- | --- |
| `out(s) = in(s) + 1` | 起点多出一条出边；若 `out(s) = in(s)` 且全图入度=出度，那是**欧拉回路**（起终点相同） |
| 恰好一个点 `t` 满足 `in(t) = out(t) + 1` | 终点（若起终点相同则不存在这样的点） |
| 其余所有点 `in = out` | 中途进出平衡 |
| 所有带边的点属于同一个**弱连通块** | 否则走不到，边用不完 |

本题数据保证「至少一条合法行程」，所以这些条件自动成立。**但如果面试官让你先判定，就要按这张表逐条检查**（判定本身是 `O(V+E)` 的）。

### 095.3.3 通用解题思路（可迁移的那一层）——兼全书图算法收口

本章是图形结构收口六章（090–095）的最后一章。**全局的选型决策表在 [`091-network-delay-time.md`](091-network-delay-time.md) 的 §091.3.3**，本章对应这一行：

| 你观察到的条件 | 该用的算法 | 复杂度 | 本章位置 |
| --- | --- | --- | --- |
| 「每一条边恰好走一次」（一笔画） | **Hierholzer（后序插入 + 逆序输出）** | `O(E log E)`（含排序） | §095.5 |

这个模型的抽象：

```
问题：把「所有边恰好用一次」的路径找出来
      ↓ 识别
这是欧拉路径（Eulerian trail），不是最短路、不是生成树
      ↓ 关键观察
「走不动了」⇒ 这个点必须排在这段行程的末尾
      ↓ 实现
DFS 一路走下去（每次优先取字典序最小的边），
回来时才把当前点追加到路线末尾（后序），
最后逆序输出 ⇒ 字典序最小的欧拉路径
```

**必须分清的一对概念**（面试高频对比）：

| 维度 | 欧拉路径（本章） | 哈密顿路径 |
| --- | --- | --- |
| 要求 | 每条**边**恰好一次 | 每个**点**恰好一次 |
| 复杂度 | **多项式**（`O(E log E)`） | **NP-hard**（只能指数搜索或状压 `O(2^V·V)`） |
| 判定 | 入度出度条件 + 弱连通（上面那张表） | 没有简单的充要条件 |
| 典型题 | 332、2097、753 | 980、847（状压近似） |

| 题 | 它把什么变成欧拉问题 |
| --- | --- |
| [LC 753 破解保险箱](https://leetcode.cn/problems/cracking-the-safe/) | `k` 进制、长度 `n` 的所有串 → De Bruijn 图上的欧拉**回路** |

### 095.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求字典序**最大** | 比较方向反了 | 换成大顶堆（或排序后逆序消费），其余一字不改 |

| 边数到 `10⁶` | 递归会爆栈 | 改成**迭代版 Hierholzer**（显式栈模拟递归），空间 `O(E)` |

### 095.4.1 官方样例 2 的完整追踪

`tickets = [["JFK","SFO"],["JFK","ATL"],["SFO","ATL"],["ATL","JFK"],["ATL","SFO"]]`，邻接表（小顶堆内部顺序）：

| 步 | 动作 | 当前堆状态（弹出后） | 追加 | 路线 `R`（后序） |
| --- | --- | --- | --- | --- |

| 5 | `dfs(ATL)` 弹 `ATL→SFO` | `ATL: {}` | — | `[]` |
| 6 | `dfs(SFO)` 无出边 | — | `SFO` | `[SFO]` |
| 7 | 返回第 5 层，出边用尽 | — | `ATL` | `[SFO, ATL]` |
| 8 | 返回第 4 层，出边用尽 | — | `SFO` | `[SFO, ATL, SFO]` |

### 095.4.2 贪心陷阱 ② 的追踪：为什么最小的边跑到了最后

```
tickets = [["JFK","KUL"],["JFK","NRT"],["NRT","JFK"]]

   JFK ──KUL──▶ KUL（死胡同，无出边）
    └──NRT──▶ NRT ──JFK──▶ JFK

dfs(JFK)
  ├─ 弹 JFK→KUL（最小）
  │    └─ dfs(KUL)：无出边 → 追加 KUL          R = [KUL]
  ├─ 弹 JFK→NRT
  │    └─ dfs(NRT)
  │         └─ 弹 NRT→JFK
  │              └─ dfs(JFK)：无出边 → 追加 JFK   R = [KUL, JFK]
  │         → 追加 NRT                            R = [KUL, JFK, NRT]
  └─ → 追加 JFK                                    R = [KUL, JFK, NRT, JFK]

reverse(R) = [JFK, NRT, JFK, KUL] ✅
              ↑     ↑
              │     第二次从 JFK 出发才轮到 NRT
              └ 逆序把「最后才被追加的 JFK」放到了最前面
```

> **一句话记住这个现象**：**后序追加 = 「谁先走投无路，谁先被记下 ⇒ 逆序时排到最后」。** 所以「最小的边」完全可以先走——只要它通向死胡同，它自然会被排到终点附近。

## 095.5 双语言实现

### 095.5.1 Java

```java
import java.util.*;

class Solution {
    public List<String> findItinerary(List<List<String>> tickets) {
        // adj: 出发地 → 目的地小顶堆（字典序最小者先出）
        Map<String, PriorityQueue<String>> adj = new HashMap<>();
        for (List<String> t : tickets) {
            adj.computeIfAbsent(t.get(0), k -> new PriorityQueue<>()).offer(t.get(1));
        }
        LinkedList<String> route = new LinkedList<>();
        dfs("JFK", adj, route);
        return route; // addFirst 已经完成了「逆序」，不必再翻转
    }

    private void dfs(String cur, Map<String, PriorityQueue<String>> adj, LinkedList<String> route) {
        PriorityQueue<String> pq = adj.get(cur);
        while (pq != null && !pq.isEmpty()) {
            dfs(pq.poll(), adj, route); // 用掉一条出边，且优先用字典序最小的那条
        }
        // 后序插入：从 cur 出发的票全部用完之后，才把 cur 记到路线**头部**
        route.addFirst(cur);
    }
}
```

### 095.5.2 Go

```go
package main

import "container/heap"

// strHeap：字符串小顶堆，按字典序出堆
type strHeap []string

func (h strHeap) Len() int           { return len(h) }
func (h strHeap) Less(i, j int) bool { return h[i] < h[j] } // 字典序最小者优先
func (h strHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *strHeap) Push(x interface{}) {
	*h = append(*h, x.(string))
}
func (h *strHeap) Pop() interface{} {
	old := *h
	n := len(old)
	it := old[n-1] // heap 包已把堆顶换到末尾，摘掉末尾即可
	*h = old[:n-1]
	return it
}

func findItinerary(tickets [][]string) []string {
	// adj[u] = 从 u 出发、还没用掉的机票目的地，堆顶是字典序最小的那个
	adj := make(map[string]*strHeap, len(tickets)+1)
	for _, t := range tickets {
		h := adj[t[0]]
		if h == nil {
			h = &strHeap{}
			adj[t[0]] = h
		}
		heap.Push(h, t[1])
	}

	route := make([]string, 0, len(tickets)+1)
	var dfs func(cur string)
	dfs = func(cur string) {
		h := adj[cur]
		for h != nil && h.Len() > 0 {
			next := heap.Pop(h).(string) // 取字典序最小的那一张票
			dfs(next)
		}
		// 后序插入：只有在「从 cur 出发已经没有票」时才把 cur 记进路线
		route = append(route, cur)
	}
	dfs("JFK")

	// 后序得到的是逆序的欧拉路径，翻转即为答案
	for i, j := 0, len(route)-1; i < j; i, j = i+1, j-1 {
		route[i], route[j] = route[j], route[i]
	}
	return route
}
```

### 095.5.3 双语言差异批注（重点：`PriorityQueue<String>` vs `container/heap`）

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 堆 | `PriorityQueue<String>` 默认就是**字典序小顶堆**，一行代码搞定 | **没有内置优先队列**，`container/heap` 要手写 `Len/Less/Swap/Push/Pop` 五个方法 | 本题 `Less` 一行 `h[i] < h[j]` 就是字典序比较，但样板代码躲不掉 |
| 后序插入 | `LinkedList.addFirst(cur)`，天然得到正序 | `append(route, cur)` 后**必须手动 `reverse`** | Java 用头插省掉翻转；Go 的切片头插是 `O(n)`，所以「先 append 再翻转」才是对的做法 |
| 邻接容器 | `Map<String, PriorityQueue<String>>`，`computeIfAbsent` 自动建桶 | `map[string]*strHeap`，要判 `nil` 后 `&strHeap{}` 再 `heap.Push` | Go 的 map value 是**值类型**时 `heap.Push` 无法回写，必须存**指针**（`*strHeap`）；这是本题 Go 版最容易错的一行 |
| 空桶判断 | `pq != null && !pq.isEmpty()` | `h != nil && h.Len() > 0` | Go 的 `nil` 指针调用方法会 panic（指针接收者方法里访问 `*h`），必须先判 `nil` |
| 递归 | JVM 栈深由 `-Xss` 控制，`E = 300` 完全安全 | goroutine 栈会动态增长，同样安全；但 `E = 10⁶` 时两者都要改迭代版 | 本题不用改 |
| 返回类型 | `List<String>`，直接返回 `LinkedList` | `[]string` | 两者都能被 LeetCode 接受 |
| 字符串比较 | `compareTo`（字典序，按 UTF-16 码元） | `<`（按字节，ASCII 全大写字母时与字典序一致） | 本题城市名全大写字母，两种比较等价 |

### 095.5.4 对拍测试：全排列暴力 vs Hierholzer

```go
package main

import (
	"math/rand"
	"testing"

// 参考实现：枚举所有「机票排列」，保留能从 JFK 串成链且用完所有票的最小字典序路线
func bruteItinerary(tickets [][]string) []string {
	n := len(tickets)
	used := make([]bool, n)
	path := []string{"JFK"}
	var best []string

	var dfs func(cur string, depth int)
	dfs = func(cur string, depth int) {
		if depth == n {
			if best == nil || lessSeq(path, best) {
				best = append([]string(nil), path...)
			}
			return
		}
		for i := 0; i < n; i++ {
			if used[i] || tickets[i][0] != cur {
				continue
			}
			used[i] = true
			path = append(path, tickets[i][1])
			dfs(tickets[i][1], depth+1)
			path = path[:len(path)-1]
			used[i] = false
		}
	}
	dfs("JFK", 0)
	return best
}

func lessSeq(a, b []string) bool {
	for i := 0; i < len(a) && i < len(b); i++ {
		if a[i] != b[i] {
			return a[i] < b[i]
		}
	}
	return len(a) < len(b)
}

// 生成合法输入：从 JFK 出发随机走一条链，把每一步当成一张机票
func genTickets(r *rand.Rand, cities []string, length int) [][]string {
	tickets := make([][]string, 0, length)
	cur := "JFK"
	for i := 0; i < length; i++ {
		next := cities[r.Intn(len(cities))]
		tickets = append(tickets, []string{cur, next})
		cur = next
	}
	r.Shuffle(len(tickets), func(i, j int) { tickets[i], tickets[j] = tickets[j], tickets[i] })
	return tickets
}

func TestReconstructItinerary(t *testing.T) {
	r := rand.New(rand.NewSource(20240332))
	cities := []string{"AAA", "BBB", "CCC", "DDD", "EEE"} // 城市少 → 大量重复机票
	for iter := 0; iter < 8000; iter++ {
		length := 1 + r.Intn(6) // 1..6 张票：全排列最多 720 种，暴力可控
		tickets := genTickets(r, cities, length)
		want := bruteItinerary(tickets)
		got := findItinerary(tickets)
		if !equalSeq(got, want) {
			t.Fatalf("iter=%d tickets=%v got=%v want=%v", iter, tickets, got, want)
		}
	}
}

func equalSeq(a, b []string) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}
```

> ⚠️ **随机数据怎么造才「保证有解」**：本章的生成方式是「从 `JFK` 出发随机走一条链，把每一步当成一张票」。这样构造出来的多重图**天然含一条覆盖所有边的欧拉路径**，不需要额外判存在性；同时因为城市池只有 5 个，会大量出现「同一张票重复」的情形——**这正是多重图最容易出错的地方**（用 `set` 去重的写法会在这里立刻崩）。
> 另外 `length` 只能取到 `6`：暴力是全排列 `O(n!)`，`7! = 5040`、`8! = 40320`，再大对拍就跑不动了。**对拍规模由 oracle 决定，这一点必须诚实。**

## 095.6 复杂度与常见坑

### 095.6.1 复杂度推导

- **时间 `O(E log E)`**：
  - 建邻接表：`O(E)` 次 `heap.Push`，每次 `O(log E)`。
  - DFS：每条边恰好被 `Pop` 一次，共 `E` 次，每次 `O(log E)`。
  - 翻转：`O(E)`。
  - 合计 `O(E log E)`。`E = 300` 时不到 `300 × 9 ≈ 2700` 次操作，微秒级。
- **空间 `O(V + E)`**：
  - 邻接表存 `E` 个目的地字符串：`O(E)`。
  - 递归栈最坏 `O(E)`（一条长链，每层消耗一条边）。
  - 结果路线 `O(E + 1)`。
- **如果用「排序 + 指针」**：建表后每桶排一次序，总 `O(E log E)`；消费时按下标前移，`O(1)`，总复杂度同阶但常数更小。
- **对照暴力**：全排列 `O(E!)`，`E = 11` 就超过 `4·10⁷`，`E = 13` 超过 `6·10⁹`。

### 095.6.2 八个真实踩过的坑

1. **纯贪心直接走，不做后序遍历**：反例 ② 会立刻翻车。正确姿势是「走完之后再记录当前点」，而不是「走之前就把当前点记进路线」。
2. **忘记逆序**（Go 版）：后序得到的是**逆序**的欧拉路径。忘了 `reverse` 会得到 `["SJC","SFO","LHR","MUC","JFK"]` 这种「倒着走」的答案。
3. **排序升序后从数组末尾取**：想让「最小的先出」却写成 `sort.Strings(x); next := x[len(x)-1]`，取的其实**最大**的。要幺改为降序排序后取末尾，要么用下标从 `0` 开始前移。
4. **用 `set` 或 `map` 去重机票**：本题机票可以重复（多重图），去重会**少走边**，答案长度不对。
5. **Go 里 map 存 `strHeap` 值而不是 `*strHeap`**：`heap.Push(adj[u], v)` 会因为 map 元素不可寻址而编译失败，或者写不回原 map。必须存指针。
6. **动手前没用 `heap.Init`**：本题用 `heap.Push` 逐条插入，是不需要 `Init` 的（`Push` 会自动维护）；但如果先把切片整体赋值再想「直接用」，就必须 `Init`。两种写法别混着记。
7. **`adj.get(cur)` 为 `null` 时没判空**：Java 里 `pq.poll()` 对 `null` 会 `NullPointerException`；Go 里对 `nil` 指针调用方法也会在解引用时 panic。边界：终点城市没有任何出边（例如反例 ① 的 `AAA`）。
8. **认为「答案唯一」**：官方样例 2 就有两种合法行程。若把「唯一的行程」当成前提去写剪枝，会在样例 2 上直接错。

### 095.6.3 面试官最爱追问的三个问题

**Q1：为什么「后序插入 + 逆序」能得到欧拉路径？**
> 「因为一次 `dfs(u)` 里弹出的每条边 `(u,v_i)` 都会先去把 `v_i` 那一侧的边全部用完再回来，所以 `v_i` 的整段子行程一定在 `u` 之前被追加。逆序之后，`u` 就紧挨着为它最后一条出边所做的子行程。归纳地看，每个块都是一条合法路径，块与块之间靠『子行程的入口点』严丝合缝地接起来，所以整体是一条合法路径。直观说：**后序保证父节点永远出现在所有子行程之后，逆序把这个顺序翻正，正好对上路径的方向。**」

**Q2：为什么不用 Fleury（显式判桥）？**
> 「Fleury 每一步都要判『这条边是不是剩余图的桥』，单次 `O(E)`，总共 `O(E²)`，`E = 10⁵` 就是 `10¹⁰`。而 Hierholzer 里「桥」这个概念被结构性地处理掉了：走过桥会撞上死胡同，死胡同的点在后序里被提前追加，逆序后就落到了行程末尾——**「桥留最后」是自动发生的，不需要检测**。这也是 Hierholzer 能压到 `O(E log E)` 的原因。」

**Q3：怎么判断这张图到底有没有欧拉路径？**
> 「有向图从 `s` 出发的充要条件三条：① `out(s) = in(s) + 1`，且恰好有一个点 `t` 满足 `in(t) = out(t) + 1`（欧拉回路则所有点 `in = out`）；② 其余所有点 `in = out`；③ 所有带边的点属于同一个弱连通块。判定是 `O(V+E)` 的：统计每个点入出度，再用一次并查集或 DFS 查弱连通。**注意区分欧拉路径（走遍所有边，多项式可解）和哈密顿路径（走遍所有点，NP-hard）**，这是面试里最常被用来分辨候选人是否真懂的一个问题。」
