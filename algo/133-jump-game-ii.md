## 133.1 题目

**原题链接**：<https://leetcode.cn/problems/jump-game-ii/>

### 题意重述（把隐含条件补齐）

给你一个非负整数数组 `nums`，你从下标 `0` 出发，站在下标 `i` 时**最多**可以向右跳 `nums[i]` 步（可落到 `i+1 … i+nums[i]` 中任意一个合法下标）。**保证一定能到达**最后一个下标 `n-1`。求到达 `n-1` 所需的**最少跳跃次数**。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **保证可达** | 「假设你总是可以到达数组的最后一个位置」 | 可以省掉「不可达」分支；但写库函数时仍要防（见 §133.6.2 坑 4） |
| **初始站在 0，`0` 次跳** | 「你从下标 0 出发」 | `n == 1` 时答案是 `0`，不是 `1` |
| **每跳的步数自由** | 「最多可以跳 `nums[i]` 步」 | 误以为必须跳满 → `[1,1,1]` 会算错 |
| **只能向右** | 「跳到 `i+1 … i+nums[i]`」 | 允许向左时，层不再是前缀，整章结构失效 |
| **求最少次数，不要求方案** | 「返回…最小跳跃次数」 | 若要方案，需要额外记录前驱 |

> 注意第 2 行：`n == 1` 的答案是 `0`。这是本题最高频的边界错误，因为「跳 0 次」不符合直觉，写代码时很容易落到 `1`。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 10^4` | n 最多 1 万 | O(n²) BFS/DP = 10⁸，能过但很勉强；O(n) 分层才是目标（改成 `10^5` 时 O(n²) 必死） |
| `0 <= nums[i] <= 1000` | 单步最远 1000 | 「显式建边」的边数是 `n · 1000 = 10^7`，**内存和时间都吃紧**，这正是「隐式图」的动机 |
| `nums[i]` 可为 `0` | 有死点 | 层可能在某一轮**不再扩张**；因为保证可达，这只会在已到终点时发生 |
| 保证可达 | 无需处理 `-1` | 但仍要能解释「什么时候会不可达」（见 §133.6.3 Q2） |

> 💡 **量级反推**：`n = 10^4`、`nums[i] ≤ 1000` 这一对数字很关键 —— 显式建图的边上界是 `10^7`，`int` 邻接表约 40 MB，`BFS` 也要扫 `10^7` 条边。**这题想让你看到的是「图存在，但不必建」**。

### 示例

```
输入：nums = [2, 3, 1, 1, 4]
输出：2
解释：0 → 1（跳 1 步）→ 4（跳 3 步），共 2 跳

输入：nums = [2, 3, 0, 1, 4]
输出：2
解释：0 → 2 → 4（0 到 2 是 2 步跳，2 到 4 是 2 步跳）

输入：nums = [0]
输出：0            ← 单元素：起点即终点
```

### 我自造的四个反例

```text
① [0]              → 答案 0（不是 1）
② [1,1]            → 答案 1（必须恰好跳一次）
③ [1,2,3]          → 答案 2；用来抓「贪心地每次都跳到最远」的错误写法：
                     从 0 只能到 1，从 1 可以直接到 2，答案 2 ✓
④ [5,0,0,0,0,1]    → 答案 1；用来抓「每步跳到延伸最远的位置」的错误直觉
⑤ [2,0,0]          → 答案 1：nums[0]=2，一次跳两步直接落在下标 2
                     用来抓「必须恰好跳 nums[0]=2 步到下标 2 之外的越界」写法
```

> 第 ③ 条值得多看一眼：很多人会写「每步跳到 `i+nums[i]` 最大的位置」，在 `[2,3,1,1,4]` 上它第 1 步选下标 1（`1+3=4` 最大），恰好正确；但 `[7,0,9,6,9,6,6,7,9,9,2]` 这类输入里，「跳到延伸最远的位置」并不是最优的（真正最优可能落在同层的别处）。**「跳到最远」不是本题的贪心，「整层一起提交」才是。**

## 133.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 把跳跃看成一张图，然后 BFS

「最少跳跃次数」听起来就是**无权图最短路**：

- 顶点：`0 … n-1`；
- 边：从 `i` 到 `i+1, …, i+nums[i]`（最多 1000 条出边）；
- 求 `0 → n-1` 的最短距离。

```text
dist[0] = 0, 其余 = ∞
BFS：
  for u in 队列:
      for v in u+1 .. min(n-1, u+nums[u]):
          if dist[v] == ∞: dist[v] = dist[u] + 1; 入队
```

- 时间 **O(n · nums[i]) = O(n²)** 量级（最坏 `10^4 × 1000 = 10^7` 条边），空间 **O(n²)** 如果显式建表、O(n) 若不建表。
- 另一条等价暴力是 DP：`dp[j] = min(dp[j], dp[i] + 1)`，`j ∈ [i+1, i+nums[i]]`，同样 **O(n²)**。

两者在本约束下都能通过（`10^7` 次操作约几十毫秒）。**那问题在哪？**

1. **约束会变**：`n = 10^5` 时边数是 `10^8`，显式建表要几百 MB；而即使不建表，逐条扫边也变成 `10^8` 次循环，在 Java 里接近 1 秒，很容易被判为超时。
2. **大量重复劳动**：BFS 里 `u = 0` 弹出的是一条长链 `1,2,…,nums[0]`；`u = 1` 又是一条几乎重合的长链。**同一个下标被反复看到，只是第一次有用。**

### 第二步：卡点在哪

把 BFS 的「层」画出来，会看到 BFS 的本质结构：

```text
层 0：0
层 1：0 能一步到达的所有下标 → 一段连续区间 [1, nums[0]]
层 2：层 1 里所有下标能到达的位置之并 → 仍是连续区间
…
```

**卡点不是「怎么求最短路」，而是「层与层之间的并集长什么样」。** 一旦发现「每层是一个区间，且层层相套（前缀）」，就没有必要再逐个顶点做 BFS —— 你只需要记录**每层的最右端**。

### 第三步：灵感的来源 —— 132 的 `far` 会「换代」

把 132 的贪心跑一遍，盯着 `far` 看：

```text
nums = [2, 3, 1, 1, 4]
i=0  far: 0 → 2        ← 这一轮把 far 推到 2，这是「1 次跳跃」能到的最远处
i=1  far: 2 → 4        ← far 又变了？不，1+3=4 > 2，所以推到 4
```

这里有个细节：`i=1` 时 `far` 从 2 涨到 4，但这并不意味着「跳 2 次」—— 它仍然是 1 次跳跃能到的最远处（从 0 一步跳到 1，再由 1 一步跳到 4，那是 2 跳）。

正确的划分方式是：**「当前这一层覆盖到哪」和「下一层能覆盖到哪」是两个不同的量**。

- `curEnd` = 当前这一层（已经「提交」的层）覆盖到的最右下标；
- `curFar` = 扫过 `[0, curEnd]` 这一整段时，所有位置能延伸到的最大值 —— 这是**下一层的右端**。

当 `i` 走到 `curEnd` 时，说明这一层已经全部看完，`curFar` 就是下一层的边界：**提交一层**（`jumps++`），把 `curEnd` 换成 `curFar`。

```
不变量（本章核心）：curEnd = E_jumps
                   其中 E_k = 「用 ≤ k 次跳跃能到达的最右下标」
```

这就是「隐式 BFS 分层」：**没有队列、没有 `dist` 数组，但做的事情和 BFS 一模一样** —— 逐层扩张，层数就是答案。

## 133.3 原理拆解

### 133.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 显式建图 + BFS | O(n²) | O(n²) | 20 行 | `nums[i]` 大（1e5）时内存爆；`n = 1e5` 时时间爆 |
| 不建图的 BFS（队列 + `dist`） | O(n²) | O(n) | 15 行 | 同上，时间爆；`dist` 数组可以省掉（BFS 层序天然给距离），但仍要逐边扫 |
| DP（`dp[j] = min(dp[j], dp[i]+1)`） | O(n²) | O(n) | 8 行 | `n ≥ 1e5`；且完全是暴力思维，面试不加分 |
| **隐式 BFS 分层（`curEnd` + `curFar`）** ✅ | **O(n)** | **O(1)** | **10 行** | 允许向左跳时失效（层不再是前缀） |
| 二分 + 预处理（区间跳跃表） | O(n log n) | O(n) | 30 行 | 复杂度反而更差，纯属炫技 |

**为什么「隐式分层」比「显式 BFS」快一个量级**：显式 BFS 的每层都要枚举「层内每个顶点的每条出边」，同一段区间被反复扫描；分层法则只对每个下标做**一次** `max` 更新，因为它知道「这一整段已经全部可达，只需要它们的最右延伸」。

### 133.3.2 为什么这个做法是对的（正确性论证 · 下界 / 不变量）

先把算法写清楚：

```text
if n == 1: return 0
jumps = 0; curEnd = 0; curFar = 0
for i = 0 .. n-2:                      # 注意上界是 n-2
    curFar = max(curFar, i + nums[i])
    if i == curEnd:
        jumps++                         # 提交一层
        curEnd = curFar
        if curEnd >= n-1: break
return jumps
```

**定义**（本章的骨架）：

```
E_k = max{ p : p 可以从 0 出发、用「不超过 k 次」跳跃到达 }      （k ≥ 0）
S_k = { p : p 可以「不超过 k 次」跳跃到达 }
```

由定义，`E_0 = 0`（`0` 次跳跃只能待在原点），`S_0 = {0}`。

**引理 1（前缀性）**：对一切 `k ≥ 0`，`S_k = [0, E_k]`，并且 `E_0 ≤ E_1 ≤ E_2 ≤ …`（单调不减）。

*证明（对 k 归纳）*：

- **基础 `k = 0`**：`S_0 = {0} = [0, 0]`，`E_0 = 0`。
- **归纳步**：设 `S_k = [0, E_k]`。由定义

  ```
  S_{k+1} = S_k ∪ { p : 存在 j ∈ S_k，使得 j < p ≤ j + nums[j] }
  ```

  即 `S_{k+1} = [0, E_k] ∪ ( ⋃_{j ≤ E_k} [j+1, j+nums[j]] )`。
  记 `E_{k+1} = max{ j + nums[j] : 0 ≤ j ≤ E_k }`。取达到该最大值的 `j*`（若最大值小于 `E_k`，则 `E_{k+1}` 取 `E_k`，此时 `S_{k+1} = S_k`，结论成立）。
  任取 `p` 满足 `E_k < p ≤ E_{k+1}`：由 `p ≤ E_{k+1} = j* + nums[j*]` 且 `p > E_k ≥ j*`，得 `p ∈ [j*+1, j*+nums[j*]] ⊆ S_{k+1}`。
  反过来，任何 `j ≤ E_k` 给出的新位置都 `≤ j + nums[j] ≤ E_{k+1}`，且 `> j`。
  于是

  ```
  S_{k+1} = [0, E_k] ∪ (E_k, E_{k+1}] = [0, E_{k+1}]
  ```

  单调性 `E_{k+1} ≥ E_k` 由 `[0, E_k] ⊆ S_{k+1} = [0, E_{k+1}]` 直接得到。∎

**引理 2（算法算的就是 `E_k`）**：在循环过程中，**已扫描的下标集合恒为 `[0, curEnd]`**，且 `curEnd = E_jumps`；当 `i` 走到 `curEnd` 时，`curFar = E_{jumps+1}`。

*证明（对「提交次数」归纳）*：

- **`jumps = 0` 时**：`curEnd = E_0 = 0`，扫描集合是 `{0} = [0, 0]`，成立。
- **归纳步**：设当前 `curEnd = E_k`，且 `[0, E_k]` 已全部扫描。此时 `curFar = max{ j + nums[j] : j ≤ E_k } = E_{k+1}`（引理 1 的构造式）。在 `i = curEnd` 那一轮，`curFar` 刚好吸入了 `i = E_k` 这一项，于是 `curFar` 正是上式，提交后 `curEnd = E_{k+1}`、`jumps = k+1`，扫描集合继续从 `E_k + 1` 延伸到 `E_{k+1}`，仍是连续前缀。∎

**引理 3（层数就是答案 · 下界与上界）**

最少跳跃次数

```
ans = min{ k ≥ 0 : E_k ≥ n-1 }
```

- **下界（任何方案都至少要 k 跳）**：若存在 `t` 次跳跃到达 `n-1` 的方案，则 `n-1 ∈ S_t = [0, E_t]`，故 `E_t ≥ n-1`，即 `t ≥ min{k : E_k ≥ n-1}`。配合 `E_k` 单调，这个集合是「上闭集」，所以「最少步数 ≥ ans」。
- **上界（ans 步可行）**：若 `E_k ≥ n-1`，则 `n-1 ∈ [0, E_k] = S_k`，即存在不超过 `k` 跳的方案。

两边夹住，得 `ans = min{k : E_k ≥ n-1}`。∎

**定理**：算法输出的 `jumps` 恰为 `ans`。

*证明*：由引理 2，第 `k` 次「提交」之后 `curEnd = E_k`、`jumps = k`；算法在第一次出现 `curEnd ≥ n-1` 时立刻 `break`，即第一次出现 `E_jumps ≥ n-1` 时停下，此时 `jumps = min{k : E_k ≥ n-1} = ans`（引理 3）。若循环自然结束（没触发 `break`），说明最后一次提交已覆盖终点，结论相同。∎

> **为什么循环上界写 `i <= n-2`**：第 `n-1` 个位置不需要再起跳。若写成 `i <= n-1`，在最后一层提交时 `curFar` 可能被 `n-1 + nums[n-1]` 污染，但因为它随后立刻 `break`，结果不变 —— 属于「能跑对但语义混乱」的写法。**语义清晰优先。**

> **这个论证的价值**：它把「贪心」翻译成了两个可验证的事实 ——
> ① 层是前缀（引理 1，纯集合运算，不依赖任何直觉）；
> ② 答案 = 第一次覆盖终点的层号（引理 3，上下界夹逼）。
> 这就是「凭什么敢贪」的答案。

### 133.3.3 通用解题思路（可迁移的那一层）

本题是 **「隐式图上的 BFS 分层」** 模型：图存在、边很多、但**每一层的顶点集是连续区间**，于是 BFS 退化成「边界跳跃」。

```
原始问题：无权图最短路（顶点 n 个，边 O(n·nums[i]) 条）
         ↓ 发现边是「指向右边一段连续区间」
建模：    分层求 S_k；再做集合运算发现 S_k = [0, E_k]
         ↓ 层是前缀 ⇒ 只需记录每层的右端
算法：    curEnd / curFar 双指针推进，每「提交」一次 = BFS 走一层
收益：    时间 O(n)、空间 O(1)，且不需要真的建图
```

**它与 132 的关系（必须讲清）**：

| 维度 | 132 跳跃游戏 | 133 跳跃游戏 II |
| --- | --- | --- |
| 问的问题 | 能不能到？（存在性） | 最少几步？（最短路长度） |
| 核心量 | `far` = 所有可达位置的最右延伸 | `curEnd` = **已提交层**的右端；`curFar` = **下一层**的右端 |
| 对应 BFS | 只关心「BFS 能不能覆盖终点」 | 关心「BFS 在第几层覆盖终点」 |
| 算法差异 | 一个变量单调增长 | 两个变量：`curFar` 长、`curEnd` 追；`curEnd` **追上**时计一层 |
| 复杂度 | O(n) / O(1) | O(n) / O(1) |

一句话：**132 的 `far` 是 133 里 `curFar` 的终点值；133 多做的事只是「在 `i == curEnd` 时把 `curFar` 提交成新一层」。** 可以把 133 的代码看成「132 的循环里插了三行」。

> ⚠️ 这也解释了为什么不能用「每步跳到延伸最远的位置」：那不是 BFS，那是「贪心选一个最优点」，而本题的正确结构是「**整层同时提交**」。BFS 层里任何一个位置的延伸都可能成为下一层的右端，你不能只挑一个。

### 133.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成「**输出一条最优路径**」 | 要决策序列 | 层提交时记 `from[curEnd] = 那个使 curFar 最大的下标`，回溯即可；空间 O(n) |
| **每跳有代价**（`cost[i]`） | 无权 → 带权 | 分层失效，退化为 Dijkstra（或 DP，若允许重复访问则要谨慎） |
| 允许**向左跳** | 层不再是前缀 | 只能 BFS + `visited`，O(n) 空间 |
| 要求**恰好 k 跳** | 加一维状态 | `dp[i][k]`，或分层 BFS 记录「第 k 层能否覆盖终点」 |
| 输入是**数据流** | 无法回头 | `curEnd/curFar` 只需前缀信息，天然适配（但需要 `n` 已知才能判终点） |
| 不保证可达 | 需要 `-1` | 当 `curFar == curEnd` 且 `curEnd < n-1` 时即不可达，立即返回 `-1`（见 §133.6.3 Q2） |

**进阶延伸（自己写代码验证）**：

- **LC 1024 视频拼接**：同样是「用最少的片段覆盖 `[0, T]`」，但片段必须首尾相接 —— 分层 BFS 的另一个化身。
- **LC 1326 灌溉花园的最少水龙头数目**：把「区间覆盖」的分层 BFS 再走一遍，可以彻底固化这个模型。
- **LC 1345 跳跃游戏 IV**：同值下标之间也能跳，图变成「稠密」，但用「同值只扩展一次」的技巧仍能压到 O(n) —— 体会「隐式图」与「剪边」的关系。

## 133.4 图解推演

### 133.4.1 分层扩张图

```text
nums = [2, 3, 1, 1, 4]        n = 5，目标下标 4

下标      0     1     2     3     4
nums      2     3     1     1     4

从 0 出发（层 0）：●
   ↓ 一步能到
层 1 覆盖 [1, 2]：○─────○
   ↓ 从层 1 里任何位置再跳一步能到
层 2 覆盖 [3, 4]：○─────○（4 = 终点 ✓）

每一层的覆盖范围（都是前缀的一部分，层层外扩）：
  层 0   ┌●───────────────────────────────┐  curEnd = 0
  层 1   │● ─ ─ ─ ─┐                      │  curEnd = 2
  层 2   │● ─ ─ ─ ─ ─ ─ ─ ─ ─┐            │  curEnd = 4  ≥ n-1 → 停
         └────────────────────────────────┘
          0   1   2   3   4
```

### 133.4.2 逐轮状态表（`nums = [2,3,1,1,4]`）

| 轮次 i | nums[i] | i == curEnd ? | curFar | curEnd | jumps | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 起始 | — | — | 0 | 0 | 0 | 第 0 层只覆盖下标 0 |
| 0 | 2 | **是** | 2 | 2 | **1** | 提交第 1 层：覆盖到 2 |
| 1 | 3 | 否 | 4 | 2 | 1 | `1+3=4`，下一层可到 4 |
| 2 | 1 | **是** | 4 | 4 | **2** | 提交第 2 层：覆盖到 4 ≥ n-1 → break |
| — | — | — | — | — | 2 | 返回 2 ✓ |

> 盯住第 3 行：`i = 1` 时 `curFar` 已经涨到 4，但 `curEnd` 还是 2，**这一层还没走完**，所以不能提前计层。这正是「两个变量」存在的理由。

### 133.4.3 与 132 的代码对照图

```text
        132（一个变量）                    133（两个变量）
  ┌──────────────────────────┐    ┌──────────────────────────┐
  │ far = 0                  │    │ jumps=0, curEnd=0, curFar=0│
  │ for i:                   │    │ for i < n-1:              │
  │   if i > far: false      │    │   curFar = max(curFar,…)  │
  │   far = max(far, i+nums) │    │   if i == curEnd:         │
  │   if far >= n-1: true    │    │       jumps++             │
  └──────────────────────────┘    │       curEnd = curFar     │
        ▲                         │       if curEnd>=n-1: brk │
        │                         └──────────────────────────┘
        └──────── far 的最终值 == curEnd 的最终值 ────────┘
                  区别只在于：中途要不要「计层」
```

## 133.5 双语言实现

### 133.5.1 Java

```java
class Solution {
    public int jump(int[] nums) {
        int n = nums.length;
        // 起点即终点：0 次跳跃。这一行漏了就是本题最高频的 WA。
        if (n == 1) {
            return 0;
        }

        int jumps = 0;   // 已经「提交」的层数 = 目前使用的最少跳跃次数
        int curEnd = 0;  // 当前这一层覆盖到的最右下标，语义上等于 E_jumps
        int curFar = 0;  // 扫过 [0, curEnd] 后，下一层能延伸到的最右下标 = E_{jumps+1}

        // 只扫到 n-2：站在 n-1 时不需要再起跳，多扫一轮只会污染 curFar 的语义。
        for (int i = 0; i < n - 1; i++) {
            if (i + nums[i] > curFar) {
                curFar = i + nums[i];
            }

            // i 走到当前层右端 ⇒ 本层已全部考察完，curFar 就是下一层边界 → 提交
            if (i == curEnd) {
                jumps++;
                curEnd = curFar;
                // 一旦下一层已经能覆盖终点，层数就是答案；继续扫不会让 jumps 变小
                if (curEnd >= n - 1) {
                    break;
                }
            }
        }
        return jumps;
    }
}
```

### 133.5.2 Go

```go
package main

func jump(nums []int) int {
	n := len(nums)
	if n == 1 {
		return 0 // 起点即终点，0 次跳跃
	}

	jumps := 0
	curEnd := 0
	curFar := 0

	// 与 Java 完全同构：Go 的 for 条件里直接写 i < n-1 即可。
	for i := 0; i < n-1; i++ {
		if i+nums[i] > curFar {
			curFar = i + nums[i]
		}
		if i == curEnd {
			jumps++
			curEnd = curFar
			if curEnd >= n-1 {
				break
			}
		}
	}
	return jumps
}
```

### 133.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 数组长度 | `nums.length` | `len(nums)` | 无影响 |
| 三元/分支 | `if … else` | 只有 `if` | 两语言都写成 `if` 更好，可读性一致 |
| 整数宽度 | `int` 恒 32 位 | `int` 是 64 位（64 位平台） | `i + nums[i]` 在本题都安全；若 `nums[i]` 放大到 `2·10^9`，Java 溢出、Go 不溢出，**别依赖这种差异** |
| `break` 标签 | 单层循环直接 `break` | 同样单层 `break` | 一致；若把两层循环嵌套，Go 需要 `break outer` 标签，Java 需要带标签的 `break` |
| 返回值 | `int` | `int` | 一致 |

### 133.5.4 对拍测试（DP 作为判据）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考 1：O(n²) 的 DP。dp[j] = 到达 j 的最少跳数。
// 它与分层法共享同一个数学定义，但展开路径完全不同 → 适合当判据。
func bruteJumpDP(nums []int) int {
	const INF = 1 << 30
	n := len(nums)
	dp := make([]int, n)
	for i := 1; i < n; i++ {
		dp[i] = INF
	}
	for i := 0; i < n; i++ {
		if dp[i] == INF {
			continue
		}
		for j := i + 1; j < n && j <= i+nums[i]; j++ {
			if dp[i]+1 < dp[j] {
				dp[j] = dp[i] + 1
			}
		}
	}
	return dp[n-1]
}

// 暴力参考 2：显式 BFS（队列），用来交叉验证 DP 本身没写错。
func bruteJumpBFS(nums []int) int {
	n := len(nums)
	dist := make([]int, n)
	for i := range dist {
		dist[i] = -1
	}
	dist[0] = 0
	q := []int{0}
	for len(q) > 0 {
		u := q[0]
		q = q[1:]
		for v := u + 1; v < n && v <= u+nums[u]; v++ {
			if dist[v] == -1 {
				dist[v] = dist[u] + 1
				q = append(q, v)
			}
		}
	}
	return dist[n-1]
}

func TestJumpRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024133))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(12)
		nums := make([]int, n)
		// 保证可达：最后一个位置必须能被「前面某处」够到。
		// 做法：先随机生成，再把 nums[n-2] 设成至少 1，并让前面的值整体偏小，
		// 这样「不可达」的比例不高，但边界依旧密集。
		for i := range nums {
			nums[i] = r.Intn(3)
		}
		nums[n-1] = 0 // 终点不需要出边，置 0 让随机性更集中在前 n-1 个位置
		if n >= 2 && nums[n-2] == 0 {
			nums[n-2] = 1
		}
		// 只测可达的输入（本题保证可达），用 DP 判断可达性
		if bruteJumpDP(nums) >= 1<<30 {
			continue
		}
		got, want := jump(nums), bruteJumpDP(nums)
		if got != want {
			t.Fatalf("iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
		if alt := bruteJumpBFS(nums); alt != want {
			t.Fatalf("BFS 与 DP 不一致 nums=%v bfs=%d dp=%d", nums, alt, want)
		}
	}
}

// 边界：单元素、全 1、全 0（不可达）、一步到终点。
func TestJumpEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{[]int{0}, 0},
		{[]int{1, 1}, 1},
		{[]int{2, 0, 0}, 1},
		{[]int{1, 1, 1, 1}, 3},
		{[]int{5, 0, 0, 0, 0, 0}, 1},
		{[]int{1, 2, 3}, 2},
	}
	for _, c := range cases {
		if got := jump(c.nums); got != c.want {
			t.Fatalf("nums=%v got=%d want=%d", c.nums, got, c.want)
		}
	}
}
```

> ⚠️ 注意 `TestJumpRandom` 里的 `continue`：本题**保证可达**，所以随机数据里「不可达」的样本必须跳过（用 DP 判断），否则会拿 `jump` 的未定义行为去比 —— 这是「对拍判据必须与题目约束对齐」的又一个例子（001 章踩过同类坑）。

## 133.6 复杂度与常见坑

### 133.6.1 复杂度推导

- **时间 O(n)**：`i` 从 `0` 走到 `n-2`，每轮 O(1)；`i == curEnd` 的提交最多发生 `jumps` 次，而 `jumps ≤ n-1`。**关键在于每个下标只被「看」一次**：不像显式 BFS 那样，一个下标会被它左边若干个顶点反复枚举到。
- **空间 O(1)**：只有 `jumps / curEnd / curFar / i / n` 五个标量。连 `dist` 数组都不需要，因为层数天然就是距离。
- **对照**：`dp` 版 O(n²) 时间 O(n) 空间；`n = 10^4` 时是 `5·10^7` 次比较，`n = 10^5` 时是 `5·10^9` —— 差两个数量级。

### 133.6.2 六个真实踩过的坑

1. **贪心没有证明 = 猜** —— 这题最容易「写对但说不清」。`curFar` 与 `curEnd` 为什么必须分开？为什么不能在 `curFar` 更新时就 `jumps++`？答不出，就等于在赌；只要把输入改成「允许向左跳」，同一段代码立刻错，而你还会以为它是对的。
2. **`n == 1` 返回 `0` 写成 `1`** —— 最高频 WA。特判或者让循环自然不执行都能解决，但要**显式**说明。
3. **`curFar` 一更新就 `jumps++`** —— 把「下一层」当「当前层」。`[2,3,1,1,4]` 上会得到 3（正确是 2）。判据：**只有 `i == curEnd` 时才允许提交**。
4. **不保证可达时没有兜底** —— 若把本题代码抄给「不保证可达」的变体，`curFar == curEnd` 会让循环永远停在原地（因为 `curEnd` 不再增长，而 `i` 会越过它继续跑）。正确做法：提交后发现 `curEnd == 旧 curEnd && curEnd < n-1` 就返回 `-1`。
5. **循环上界写成 `i < n`** —— 通常结果仍对（因为 `break` 保护），但语义混乱：站在 `n-1` 时 `nums[n-1]` 是「终点之后的跳跃」，把它算进 `curFar` 会让你更难解释不变量。写成 `i < n-1`。
6. **用「每步跳到延伸最远的位置」实现** —— 这不是本题的正确答案（见 §133.2 第三步的警告）。它看起来对、在小样例上对，但它是「选一个最优下一步」，而正确做法是「整层一起提交」。这类错误在面试里极难自证。

### 133.6.3 面试官最爱追问的三个问题

**Q1：这题和 132 的 `far` 有区别吗？**

> 「有。132 只有一个 `far`，它单调增长到「最终能到的最远处」，只回答存在性。133 必须把 `far` 拆成两个角色：`curEnd` 是**已提交层**的右端（保证 `[0, curEnd]` 都能在 `jumps` 步内到达），`curFar` 是**下一层**的右端。`i == curEnd` 时才提交，这就是 BFS 的一层。数学上一句话：132 问 `E_k ≥ n-1` 是否成立，133 问最小的那个 `k`。」

**Q2：如果数组不保证可达，怎么改？**

> 「提交一层后若 `curEnd` 没有增长（`curFar == curEnd`）且还没到终点，说明 BFS 无法继续扩张，即终点不可达 → 返回 `-1`。这个判据和 132 的『`i > far` 就失败』是同一件事的两种写法：132 用位置撞墙，133 用层数不再扩张。」

**Q3：为什么不需要 `visited` 数组？**

> 「因为层是连续前缀（引理 1）。普通 BFS 需要 `visited` 是怕同一顶点被多次入队；这里『入队』这件事被压缩成了『右边界外扩』，下标一旦进入 `[0, curEnd]` 就永远在内，天然不重复。`visited` 的语义被『前缀』这个结构吃掉了 —— 这是隐式图题省空间的通用手法（LC 1345 的『同值只扩展一次』也是同一思路）。」

## 附：本章小结（可背走的三句话）

```text
① 最少跳跃次数 = 无权图最短路 = BFS；而这张图的每一层恰好是前缀 [0, E_k]
② curEnd 是「已提交层」，curFar 是「下一层」，i == curEnd 时才 jumps++
③ 正确性 = 前缀引理（层是前缀） + 上下界夹逼（ans = 最小的 k 使 E_k ≥ n-1）
```
