## 019.1 题目

**原题链接**：<https://leetcode.cn/problems/minimum-size-subarray-sum/>

### 题意重述（把隐含条件补齐）

给你一个**全是正整数**的数组 `nums` 和一个正整数 `target`，找出**和大于等于 `target`** 的**连续子数组**中长度最小的那个，返回它的长度；如果不存在，返回 `0`。

这道题的题面里藏了一个「看起来只是数据范围」、实际上是**算法正确性前提**的约束：`1 <= nums[i]`。整章的核心就是它。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **元素全是正数** | `1 <= nums[i] <= 10⁴` | 一旦允许负数，滑窗**静默错**（见 §019.2 的反例），正确率不再是 100% |
| **子数组必须连续** | 「子数组」 | 你按子序列做（排序后取前 k 大）→ 完全另一道题 |
| **条件是「≥ target」，不是「=」** | 「总和大于等于」 | 写成 `==` 会漏掉大量解；`while` 条件写 `>` 会多算一格 |
| **要长度，不是子数组** | 「返回其长度」 | 返回 `int[]` → 类型错 |
| **不存在时返回 0** | 「如果不存在符合条件的子数组，返回 0」 | 返回 `-1` 或 `MAX_VALUE` → 判错 |
| **`target` 是正整数** | `1 <= target` | 不需要处理 `target = 0`（那会让空子数组成为答案） |
| **可能有单元素就满足** | 一般性 | `nums[i] >= target` 时要能返回 1（`while` 无法处理会被卡住） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= target <= 10⁹` | target 可以很大 | 允许「整个数组的和都不够」的情形 → 必须返回 0，不能返回 `n` |
| `1 <= nums.length <= 10⁵` | n 最多 10 万 | 子数组总数 `5·10⁹`，O(n²) 是 `10¹⁰` 次加法，必挂 |
| `1 <= nums[i] <= 10⁴` | **全正** | ①前缀和严格递增 → 可以二分；②窗口和关于左端点单调 → 滑窗成立 |
| 最大可能和 | `10⁵ × 10⁴ = 10⁹` | 恰好塞进 `int32`（上限 2.147·10⁹），但已经用掉一半，**换题就要 `long`** |

> 💡 量级 → 算法：`n = 10⁵` 只接受 O(n) 或 O(n log n)。
> 而「最短的连续区间满足某单调性质」这个形状，指向**变长滑窗**；前提「全正」正好提供了它需要的单调性。
> 如果面试官把 `nums[i]` 改成可以为负，O(n) 滑窗立刻失效，正确的 O(n) 解法会变成**前缀和 + 单调双端队列**（LC 862）。

### 示例

```
输入：target = 7, nums = [2,3,1,2,4,3]
输出：2
解释：子数组 [4,3] 的和是 7，长度 2，是最短的。
      注意 [2,3,1,2] 的和也是 8 ≥ 7，但长度 4，不是答案。

输入：target = 4, nums = [1,4,4]
输出：1
解释：单个 4 就满足。

输入：target = 11, nums = [1,1,1,1,1,1,1,1]
输出：0
解释：总和是 8 < 11，不存在。
```

### 我自造的五个反例（写完必须打一遍）

```text
① target=4,  nums=[1,4,4]         → 单元素满足，检验 while 能否在长度 1 时正确退出
② target=11, nums=[1,1,1,1,1,1,1,1] → 无解返回 0
③ target=7,  nums=[7]             → n=1 且恰好等于 target
④ target=15, nums=[1,2,3,4,5]     → 整段和恰好等于 target，答案 = n
⑤ target=7,  nums=[1,2,3,-6,7]    → 允许负数时的反例：滑窗返回 5，正确答案是 1
```

第 ⑤ 条不是本题的合法输入（本题保证正数），但它是我**故意保留**的「毒药用例」：只要你的实现里没有任何依赖正数的假设（比如用排序、二分前缀和），它就会在这条用例上暴露。我用它实测了滑窗版：**返回 5，而正确答案是 1**。这个反例在 §019.2 会完整展开。

## 019.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来）

```java
int best = 0;
for (int i = 0; i < n; i++) {
    int sum = 0;
    for (int j = i; j < n; j++) {
        sum += nums[j];                       // 内层边扩边加，省掉第三层
        if (sum >= target) {                  // 一旦够大，就不必再往右（正数只会更大）
            if (best == 0 || j - i + 1 < best) best = j - i + 1;
            break;                            // ← 这个 break 依赖"全正"！
        }
    }
}
```

- 时间 **O(n²)**：最坏 `n(n+1)/2` 次内层迭代，`n = 10⁵` 时是 **5·10⁹** 次加法，必挂。
- 空间 **O(1)**。

注意这一版已经用到了「全正」这个性质：**一旦 `sum >= target` 就 `break`**，因为继续往右加只会更大。如果没有这个性质，连 `break` 都是错的。

### 第二步：它为什么不够 —— 每个左端点的右端点都在重复前进

```
target = 7, nums = [2,3,1,2,4,3]

i=0：加到下标 3 得 sum=8 ≥ 7，长度 4，break
i=1：加到下标 4 得 sum=10 ≥ 7，长度 4，break     ← 右端点从 3 又走到 4
i=2：加到下标 4 得 sum=7 ≥ 7，长度 3，break      ← 右端点还是 4
i=3：加到下标 5 得 sum=9 ≥ 7，长度 3，break
i=4：加到下标 5 得 sum=7 ≥ 7，长度 2，break      ← 答案
```

看出问题了吗：`i` 从 0 挪到 1 时，**右端点根本不用回退**。因为「`[1, 4]` 的和 ≥ target」蕴含「`[0, 4]` 的和 ≥ target」（全正数，更大的窗口和只会更大）。所以右端点一旦到达 4，就可以一直往前。

**这正是滑窗的入口**：两个指针都只往右走，总移动 `2n` 次。

### 第三步：卡点 —— 什么时候动左指针

滑窗的两个阶段：

```
阶段 1（扩张）：right++，sum += nums[right]
阶段 2（收缩）：只要 sum >= target：
                ① 用当前长度更新 best（先记！）
                ② sum -= nums[left]; left++
```

对比 `016`（最小覆盖子串）：

| | 016 | 019 |
| --- | --- | --- |
| 阶段 2 的触发条件 | `missing == 0`（已覆盖） | `sum >= target`（够了） |
| 阶段 2 里维护什么 | `need[c]` 计数 | 一个标量 `sum` |
| 阶段 2 退出条件 | 不再覆盖 | `sum < target` |
| 共同点 | **都是「可行就更优」**，答案在收缩**之前**记 | 同左 |

一个记法：**求最短的滑窗，答案在「动 left 之前」记；求最长的滑窗（015），答案在「修完之后」记。**

### 第四步：正数前提到底做了什么 —— 用反例说话

假设允许负数：`nums = [1, 2, 3, -6, 7]`，`target = 7`。

```
正确答案（暴力）：只有 [7] 这个子数组的和 ≥ 7 且最短 → 长度 1
```

滑窗会怎么走？

```
right=0: sum=1
right=1: sum=3
right=2: sum=6
right=3: sum=0    ← 加上 -6，和反而变小了
right=4: sum=7 ≥ 7 → 记录长度 5（窗口 [0,4]）
         收缩：sum -= nums[0] = 1 → 6 < 7，停（left=1）

结果：5
正确答案：1
```

**错得毫无征兆**：代码没有任何异常，只是答案错了。为什么错？因为在 `right = 4` 时，让 `sum ≥ 7` 的**最短窗口其实是 `[4, 4]`**（只含 `7`），但滑窗从 `left = 0` 开始收缩，减到 `left = 1` 时 `sum` 就掉到 6 以下了 —— 它**永远走不到 `left = 4`**，因为中间那几个位置的和不满足单调性。

用图看更清楚：

```
全正数：sum 关于 left 单调递减
  sum
   9 │●
   8 │ ╲
   7 │  ╲●──────  ← 跨过 target 线之后就再也上不来
   6 │   ╲
     └────┬──────→ left
         7              "一旦 < target，就永远 < target" → 可以放心停

有负数：sum 关于 left 不单调
  sum
   7 │    ●          ●
   6 │   ╱ ╲        ╱
   5 │  ╱   ╲______╱   ← 跨过负数后，和会"反弹"回去
     └──┬─────────────→ left
        1    3        5    "停了"并不代表后面没有可行解 → 会漏解
```

> **一句话**：滑窗的安全性完全建立在「**可行性关于左端点单调**」上。本题由「全正」保证；没有它，就必须换工具（前缀和 + 单调队列，LC 862）。

## 019.3 原理拆解

### 019.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 双重循环（枚举左端点 + 右扩） | O(n²) | O(1) | 10 行 | `n = 10⁵` 时 5·10⁹ 次，必挂 |
| 双重循环 + 前缀和 | O(n²) | O(n) | 12 行 | 同上，还多了空间 |
| **变长滑窗** ✅ | **O(n)** | **O(1)** | **10 行** | 有负数时**静默错**；需要知道「收缩到哪」的判据 |
| 前缀和 + 二分（每个右端点二分左端点） | O(n log n) | O(n) | 15 行 | 常数比滑窗大；但**思路更通用**（能处理「和 ≥ k」「和 > k」等变体） |
| 前缀和 + 单调双端队列 | O(n) | O(n) | 30 行 | 只有**允许负数**时才需要它（LC 862）；本题属于杀鸡用牛刀 |
| 排序后取最大的 k 个 | — | — | — | **语义就错了**：子数组必须连续 |

**滑窗 vs 前缀和 + 二分的取舍**：

```
滑窗：O(n) / O(1)，代码 10 行，但依赖"正数"这个前提，且只能回答"最短"
二分：O(n log n) / O(n)，代码 15 行，同样依赖"正数"（前缀和要单调），
      但更容易推广：把 check 换成"和 > target"、"和的平方 ≥ x"都能用
```

面试里的推荐答法：**先给滑窗，再补一句「也可以用前缀和 + 二分，O(n log n)，好处是不依赖窗口语义」**。这句话能同时展示「会写」和「知道边界」。

### 019.3.2 为什么这个做法是对的（正确性论证）

**引理 1（窗口和关于左端点单调）**：固定 `r`，函数 `f(l) = sum(nums[l..r])` 关于 `l` 单调递减。
*证明*：`f(l) − f(l+1) = nums[l] ≥ 1 > 0`。∎

**引理 2（可行左端点构成前缀区间）**：固定 `r`，集合 `S(r) = { l : sum(nums[l..r]) ≥ target }` 是一个**前缀区间** `[0, L(r)]`（可能为空）。
*证明*：由引理 1，若 `sum(nums[l..r]) ≥ target`，则对任意 `l' < l`，`sum(nums[l'..r]) ≥ sum(nums[l..r]) ≥ target`。∎

于是「以 `r` 结尾的最短可行子数组」就是 `[L(r), r]`，长度为 `r − L(r) + 1`。

**引理 3（算法在每轮记录了 `L(r)`）**：收缩循环从某个 `left` 开始，每次先更新 `best` 再 `left++`；由引理 2，循环会在 `left = L(r) + 1` 时因 `sum < target` 退出，所以**最后一个被记录的 `left` 恰好是 `L(r)`**（若 `S(r)` 非空）。
*证明*：循环每轮的 `sum` 都满足 `≥ target`（即 `left ∈ S(r)`），且 `left` 逐次加一；退出时 `left ∉ S(r)`，由前缀区间性质得 `left = L(r)+1`。∎

**定理**：算法返回的长度是全局最小。
*证明*：由引理 3，对每个 `r`，算法在 `left = L(r)` 时记录了长度 `r − L(r) + 1`，这正是「以 `r` 结尾的最短可行子数组」的长度。全局最优解必是某个 `r` 结尾的最短者，故 `best` 取到全局最小。`best` 保持初值时说明 `S(r)` 对一切 `r` 为空，即无解，返回 0 正确。∎

**附带说明「为什么 `while` 用 `>=`」**：条件是「和 ≥ target」，`sum == target` 时窗口已经可行，必须记录并继续尝试收缩（可能还有更短的）。用 `>` 会漏掉「恰好等于」的所有情况（示例 1 的答案 `[4,3]` 就是恰好等于 7）。

### 019.3.3 通用解题思路（可迁移的那一层）

本题是 **「变长滑窗 · 求最短 · 单调性前提」** 的母题。它把前三章埋下的问题**逼到了台面上**：

```
滑窗能不能用，只取决于一件事：
    固定右端点后，"可行左端点"是不是一个前缀区间？
    是  → 滑窗 O(n)
    否  → 换前缀和 + 哈希（011）或前缀和 + 单调队列（862）
```

**本批五道滑窗题的收口对照表**（这张表就是本部分的「总纲」）：

| 章节 | 窗口长度 | 目标 | 维护什么 | 动 left 的条件 | 安全性来源 | 前提 |
| --- | --- | --- | --- | --- | --- | --- |
| [015](015-longest-substring-without-repeating-characters.md) | 变长 | 最长 | `last[c]` | 出现重复 | 左端点下界单调 | 无（重复位置可解析求出） |
| [016](016-minimum-window-substring.md) | 变长 | 最短 | `need[c]` + `missing` | 已覆盖 | 覆盖关于左端点单调 | 无 |
| [017](017-find-all-anagrams-in-a-string.md) | 定长 | 全起点 | `diff[26]` + `nonzero` | 无决策 | 长度固定 | 无 |
| [018](018-permutation-in-string.md) | 定长 | 存在性 | 同 017 | 无决策 | 长度固定 | 无 |
| **019** | **变长** | **最短** | **`sum`** | **`sum ≥ target`** | **窗口和关于左端点单调** | **全正数** |

**从 015 到 019 的一条线**（这就是本部分想让你带走的东西）：

```
015  窗口里维护"无重复"          → 收缩是"修复"，因为重复必须被排除
016  窗口里维护"覆盖计数"        → 收缩是"优化"，因为目标是更短
017  窗口长度被钉死              → 不需要收缩，整体平移
018  与 017 同构                 → 同上
019  窗口里维护"一个和"          → 收缩是"优化"，前提是全正
      ↓
共性：滑窗 = 一个"能增量维护 + 能增量撤销"的窗口 + 一条"可行性单调"的性质
      ↓
没有单调性 → 前缀和 + 哈希（011）/ 单调队列（862）/ 二分（020–027）
```

**与前缀和家族的关系**：`011` 用「前缀和之差」解决「和为 k 的子数组」（**有负数**），本题用滑窗解决「和 ≥ target 的最短子数组」（**全正**）。两者是同一族问题的两条分支：

| | 011 和为 K 的子数组 | 019 长度最小的子数组 |
| --- | --- | --- |
| 元素符号 | 有负数 | **全正** |
| 条件 | `= k` | `≥ target` |
| 单调性 | 无 | 有 |
| 工具 | 前缀和 + 哈希计数 | 变长滑窗 |
| 复杂度 | O(n) / O(n) | **O(n) / O(1)** |
| 若强行互换 | 滑窗 → 错 | 哈希 → 能做但多花 O(n) 空间 |

### 019.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **允许负数**，求「和 ≥ target 的最短」 | 单调性崩塌 | 前缀和 + **单调双端队列**：维护 `pre` 递增的候选下标队列，对每个 `j` 从左弹出满足 `pre[j] − pre[front] ≥ target` 的下标并更新答案（LC 862） |
| 允许 **0** | 单调性变成「非严格」 | 滑窗**仍然正确**（`sum` 关于 `left` 单调不增），但「最短」可能因为 0 而有多解；复杂度不变 |
| 求「和 ≤ target 的最长子数组」 | 条件方向反了 | 全正时同样可滑窗（`sum > target` 时左缩，边收缩边记最长）；若无正数约束，这个问题会显著变难，不再是滑窗或二分能解决的范畴 |
| 要求返回**子数组本身** | 需要端点 | 记录 `bestL`、`bestLen`，最后切片；不影响复杂度 |
| `target` 极大（超过总和） | 无解 | 累加判断即可，滑窗天然返回 0（`best` 保持初值） |
| `nums` 是**数据流** | 只能向前 | 滑窗天然适配（只需维护 `sum` 与一个能回退的队列）；但「最短」需要对每个 `right` 立即给出答案，仍是 O(1) 摊还 |
| 要求「和恰好等于 target」且全正 | `=` 而非 `≥` | 滑窗仍可用（和单调），也可以用前缀和 + 二分；但 011 的哈希法在**有负数**时才是必需的 |
| 二维版本（子矩阵和 ≥ target 的最小面积） | 矩阵 | 固定上下边界压成一维，再对每列前缀和做滑窗/二分，O(min(m,n)² · max(m,n) · log) |

## 019.4 图解推演

### 019.4.1 双指针的移动轨迹

```
target = 7，nums = [2, 3, 1, 2, 4, 3]

初始：left = 0, right = 0, sum = 0, best = ∞

right 一路右扩到下标 3：
   ┌───┬───┬───┬───┬───┬───┐
   │ 2 │ 3 │ 1 │ 2 │ 4 │ 3 │
   └───┴───┴───┴───┴───┴───┘
     ↑               ↑
   left            right
   sum = 2+3+1+2 = 8 ≥ 7
   → 记录 长度 4
   → 收缩：sum -= 2 → 6 < 7，停；left = 1

right = 4（加入 4）：
   ┌───┬───┬───┬───┬───┬───┐
   │ 2 │ 3 │ 1 │ 2 │ 4 │ 3 │
   └───┴───┴───┴───┴───┴───┘
         ↑           ↑
       left        right
   sum = 3+1+2+4 = 10 ≥ 7
   → 长度 4，不更新
   → 收缩：sum -= 3 → 7 ≥ 7 → 长度 3，更新 best = 3
   → 收缩：sum -= 1 → 6 < 7，停；left = 3

right = 5（加入 3）：
   ┌───┬───┬───┬───┬───┬───┐
   │ 2 │ 3 │ 1 │ 2 │ 4 │ 3 │
   └───┴───┴───┴───┴───┴───┘
             ↑       ↑
           left    right
   sum = 2+4+3 = 9 ≥ 7
   → 长度 3，不更新
   → 收缩：sum -= 2 → 7 ≥ 7 → 长度 2，更新 best = 2 ✅
   → 收缩：sum -= 4 → 3 < 7，停；left = 5

答案 = 2（子数组 [4, 3]）
```

### 019.4.2 逐轮状态表

| `right` | `nums[right]` | 扩后 `sum` | `sum ≥ target`？ | 收缩过程（长度） | 本轮后 `left` | `best` |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 2 | 2 | 否 | — | 0 | ∞ |
| 1 | 3 | 5 | 否 | — | 0 | ∞ |
| 2 | 1 | 6 | 否 | — | 0 | ∞ |
| 3 | 2 | 8 | **是** | 记 4；减 2 后 sum=6 < 7，停 | 1 | 4 |
| 4 | 4 | 10 | **是** | 记 4；减 3 后 sum=7 → 记 3；减 1 后 sum=6 < 7，停 | 3 | 3 |
| 5 | 3 | 9 | **是** | 记 3；减 2 后 sum=7 → 记 2；减 4 后 sum=3 < 7，停 | 5 | **2** |

> 盯住 `right = 4` 这一行：**一次扩张触发了两次收缩、记了两个长度**。这就是「`while` 而不是 `if`」的理由 —— 只要还满足条件，就要继续尝试更短的窗口。

### 019.4.3 前綴和 + 二分：第二条路

```
pre = [0, 2, 5, 6, 8, 12, 15]      （严格递增，因为有全正这个前提）

对每个右端点 j（1..n），要找最大的 i 使 pre[j] - pre[i] >= target
即 pre[i] <= pre[j] - target
因为 pre 递增 → 二分找"最后一个 <= pre[j]-target 的 i"

  j=4: pre[4]=8, 目标 8-7=1 → 最后一个 <=1 的 pre 下标是 0 → 长度 4-0=4
  j=5: pre[5]=12, 目标 5    → 最后一个 <=5 的 pre 下标是 1 → 长度 5-1=4
  j=6: pre[6]=15, 目标 8    → 最后一个 <=8 的 pre 下标是 4 → 长度 6-4=2 ✅

  ┌──────────────────────────────────────────────────────────┐
  │ 二分的前提也是"全正"：pre 必须单调递增                     │
  │ 一旦有负数，pre 不单调，二分立刻失效（这也是 862 要换单调队列的原因）│
  └──────────────────────────────────────────────────────────┘
```

### 019.4.4 负数反例的完整轨迹（为什么滑窗会错）

```
target = 7，nums = [1, 2, 3, -6, 7]      ← 本题不允许，但用来暴露前提

right=0  sum=1        < 7
right=1  sum=3        < 7
right=2  sum=6        < 7
right=3  sum=0   ← 加上 -6 后和变小！        < 7
right=4  sum=7        ≥ 7  → 记录窗口 [0,4]，长度 5
         收缩：sum -= 1 → 6 < 7，停；left=1     ← 再也走不到 left=4

滑窗返回 5，正确答案 1（窗口 [4,4]，只含那个 7）

   ┌──────────────────────────────────────────────────────────┐
   │ 错因：从左往右收缩时，sum 掉到 target 以下就"停"了          │
   │       但在负数存在时，"掉下去"之后还可能"弹回来"           │
   │       于是 left=1..4 这些真正的候选位置从未被检查           │
   └──────────────────────────────────────────────────────────┘
```

## 019.5 双语言实现

### 019.5.1 Java

```java
class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0, sum = 0;
        int best = Integer.MAX_VALUE;      // 哨兵：表示"还没有找到任何可行窗口"

        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];            // 阶段 1：无条件右扩

            // 阶段 2：只要还够大，就尝试更短的窗口
            // 用 while 不是 if：一次扩张可能触发多次收缩（right=4 那轮就是两次）
            while (sum >= target) {        // 必须是 >=：条件是"大于等于"
                best = Math.min(best, right - left + 1);  // 先记答案，再移出
                sum -= nums[left];         // 移出左端（nums[left] 是正数，sum 必减）
                left++;
            }
            // 循环退出时 sum < target，且 left 已是"使窗口仍可行的最大左端点 + 1"
        }
        // best 没被更新过 → 没有任何子数组的和 ≥ target
        return best == Integer.MAX_VALUE ? 0 : best;
    }
}
```

### 019.5.2 Go

```go
package main

func minSubArrayLen(target int, nums []int) int {
	left, sum := 0, 0
	best := 1<<31 - 1 // 哨兵

	for right := 0; right < len(nums); right++ {
		sum += nums[right]

		for sum >= target {
			if right-left+1 < best {
				best = right - left + 1
			}
			sum -= nums[left]
			left++
		}
	}

	if best == 1<<31-1 {
		return 0
	}
	return best
}
```

### 019.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 哨兵值 | `Integer.MAX_VALUE` | `1<<31 - 1` | 都要在最后判「是否仍为哨兵」再返回 0；直接返回哨兵会判错 |
| 若用 `long` 累加 | `long sum = 0` + `(int)` 强转 | `int64` | 本题 `10⁹` 安全，但 `1<<31 - 1` 的写法在 Go 里是 `int`，若改成 `int64` 要同步改哨兵 |
| 溢出边界 | `int` 32 位，`10⁵ × 10⁴ = 10⁹` 安全 | `int` 64 位（平台相关） | **不要依赖 Go 的 64 位 `int`**：换成 32 位平台（如 wasm/386）就会溢出。跨平台写 `int64` |
| 循环写法 | `for (int right = 0; ...)` | `for right := 0; ...` | 一致；Go 的内层 `for sum >= target` 不需要括号 |
| 返回长度 | `int` | `int` | 一致；长度为 0 表示无解，注意不要返回 `-1` |

### 019.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举左端点，右扩到第一次 sum >= target
func brute(target int, a []int) int {
	best := 0
	for i := range a {
		s := 0
		for j := i; j < len(a); j++ {
			s += a[j]
			if s >= target && (best == 0 || j-i+1 < best) {
				best = j - i + 1
			}
		}
	}
	return best
}

// 第二条路：前缀和 + 二分（要求全正，pre 才递增）
func solveBinary(target int, a []int) int {
	n := len(a)
	pre := make([]int, n+1)
	for i, x := range a {
		pre[i+1] = pre[i] + x
	}
	best := 0
	for j := 1; j <= n; j++ {
		want := pre[j] - target // 需要 pre[i] <= want
		// 找最后一个 <= want 的下标 i ∈ [0, j-1]
		lo, hi := 0, j-1
		idx := -1
		for lo <= hi {
			mid := (lo + hi) / 2
			if pre[mid] <= want {
				idx = mid
				lo = mid + 1
			} else {
				hi = mid - 1
			}
		}
		if idx >= 0 && (best == 0 || j-idx < best) {
			best = j - idx
		}
	}
	return best
}

func TestMinSubArrayLenRandom(t *testing.T) {
	fixed := []struct {
		target int
		a      []int
		want   int
	}{
		{7, []int{2, 3, 1, 2, 4, 3}, 2},
		{4, []int{1, 4, 4}, 1},                  // 单元素满足
		{11, []int{1, 1, 1, 1, 1, 1, 1, 1}, 0},  // 无解
		{7, []int{7}, 1},                        // n = 1
		{15, []int{1, 2, 3, 4, 5}, 5},           // 整段恰好满足
	}
	for _, f := range fixed {
		if got := minSubArrayLen(f.target, f.a); got != f.want {
			t.Fatalf("target=%d a=%v got=%d want=%d", f.target, f.a, got, f.want)
		}
		if got := solveBinary(f.target, f.a); got != f.want {
			t.Fatalf("二分版 target=%d a=%v got=%d want=%d", f.target, f.a, got, f.want)
		}
	}

	r := rand.New(rand.NewSource(19))
	for iter := 0; iter < 30000; iter++ {
		n := 1 + r.Intn(12)
		a := make([]int, n)
		for i := range a {
			a[i] = 1 + r.Intn(6) // 题目约束：全正
		}
		tg := 1 + r.Intn(25)
		want := brute(tg, a)
		if got := minSubArrayLen(tg, a); got != want {
			t.Fatalf("iter=%d a=%v t=%d got=%d want=%d", iter, a, tg, got, want)
		}
		if got := solveBinary(tg, a); got != want {
			t.Fatalf("二分版 iter=%d a=%v t=%d got=%d want=%d", iter, a, tg, got, want)
		}
	}
}
```

## 019.6 复杂度与常见坑

### 019.6.1 复杂度推导

- **时间 O(n)**：`right` 走 `n` 步；`left` 单调不减，全程最多走 `n` 步。内层 `while` 的每次迭代都让 `left` 加一，所以内层总迭代次数 `≤ n`，总计 `≤ 2n` 次加法。
  - **不要因为嵌套而误判成 O(n²)**：判据永远是「指针总移动量」，不是「循环层数」。
- **空间 O(1)**：只有 `left`、`sum`、`best` 三个标量。这是本题比 011（O(n) 哈希表）漂亮的地方 —— **单调性换来了空间**。
- **二分版**：时间 O(n log n)（每个右端点一次二分），空间 O(n)（前缀和数组）。

### 019.6.2 八个真实踩过的坑

1. **`while (sum > target)`** —— 漏掉「恰好等于」的情形。示例 1 的答案 `[4,3]` 和就是 7，写成 `>` 会返回 3。
2. **`best` 初值用 0 并直接参与 `min`** —— `Math.min(0, len)` 恒为 0，答案永远是 0。必须用 `MAX_VALUE` 或另设标志位。
3. **最后忘把哨兵翻译成 0** —— 返回 `Integer.MAX_VALUE` / `1<<31-1`，判题直接错。
4. **用 `if` 代替 `while`** —— 每次扩张只收缩一次，会漏掉「一次扩张后可以连续缩两三次」的情况（示例 1 的 `right=4` 那轮就是两次）。答案偏大但不报错。
5. **先移出再记录** —— 记录时窗口已经不满足条件，长度偏小（这是「假的最优」）。必须**先记、再移出**。
6. **以为「子数组」可以不连续** —— 排序取最大 k 个会得到「任意选」的答案，和题意完全不同。
7. **`sum` 溢出** —— 本题上界 `10⁹` 安全；但若 `nums[i]` 上限是 `10⁹`、`n = 10⁵`，和到 `10¹⁴`，Java `int` 静默溢出、Go 在 32 位平台也会溢出。**看到「累加」先算上界**。
8. **在负数输入上也用滑窗** —— 本题不会出现；但面试官很可能现场改条件（「现在允许负数了」）。如果没有准备好「单调性崩塌」这个答案，就会卡住。

### 019.6.3 面试官最爱追问的三个问题

**Q1：为什么这题可以用滑动窗口，而「和为 K 的子数组」（LC 560）不行？**
> 「差别在单调性。本题元素全正，所以固定右端点后『窗口和关于左端点单调递减』，可行左端点是一个前缀区间 —— 收缩时一旦掉到 `target` 以下就可以停。LC 560 允许负数，移出一个负数会让和变大，可行性不再单调，左指针一旦越过某个位置就可能漏掉后面的解。所以 560 必须用前缀和 + 哈希。**判断标准只有一条：固定右端点后，可行左端点是不是前缀区间。**」

**Q2：如果现在允许负数，怎么改？**
> 「滑窗失效，但 O(n) 仍然可达：前缀和 + **单调双端队列**。对每个 `j`，维护一个 `pre` 值递增的下标队列；每次先从左端弹出满足 `pre[j] − pre[front] ≥ target` 的下标并更新答案（弹出后它不可能再贡献更短的） ，再把 `j` 从右端压入、并弹掉所有 `pre` 值 ≥ `pre[j]` 的下标（它们既更靠左又更大，永远不可能更优）。总复杂度 O(n)。这就是 LC 862。」

**Q3：为什么「先记录、再移出」而不是反过来？**
> 「因为窗口在『移出之前』是可行的，『移出之后』可能就不可行了。我们要记录的正是『刚好还可行的那一版』，也就是最短的那个。写成先移出，记录的是 `[left+1, right]`，但如果它已经不满足条件，这个长度就是**假的**。这和 016 里『先记答案再收缩』是同一条规则：**求最短的滑窗，答案在收缩之前取。**」

**Q4（延伸）：如果要求「和恰好等于 target」的最短子数组，全正数？**
> 「同样可以滑窗：和单调，`sum > target` 就左缩、`sum == target` 就记录。也可以前缀和 + 二分。而在**有负数**时，最短的「和恰好等于 target」需要前缀和 + 哈希存『首次出现下标』，但那求的是**最长**。这两件事要分清：哈希天然适合『最长』（存首次下标），求『最短』要存『末次下标』且必须边扫边更新。」
