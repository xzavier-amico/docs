## 097.1 题目

**原题链接**：<https://leetcode.cn/problems/subsets-ii/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`，它**可能包含重复元素**。请返回该数组所有**不重复的子集**（幂集），要求：

- 解集里**不能包含重复的子集**（两个子集元素完全相同就算重复，与它们来自哪几个下标无关）；
- 子集内部元素顺序不限，解集顺序也不限；
- 空集算一个解。

与 [`096`](096-subsets.md) 相比，只有一处输入条件变了：`互不相同` → `可能重复`。但这一处变化让答案的**结构**从「`2^n` 个下标子集」塌缩成「`∏(cnt_v + 1)` 个值子集」——这是本题所有设计的出发点。

四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **数组可能含重复值** | 「整数数组 `nums`，其中可能包含重复元素」 | 直接搬 096 的模板会输出重复子集：`[1,2,2]` 会得到两个 `[1,2]`（分别来自下标 `{0,1}` 与 `{0,2}`） |
| **去重按「值」而不是按「下标」** | 「返回该数组所有**不重复**的子集」 | 若按「下标集合不同」判断，`{0,1}` 与 `{0,2}` 都算不同 → 输出里出现两份 `[1,2]` → WA |
| **空集与全集都要有** | 「所有可能的子集」 | 漏掉 `[]` 是最高频 WA；`[1,1]` 的全集 `[1,1]` 也必须出现一次（不能因为是重复值就不给） |
| **顺序任意** | 「解集不能包含重复的子集，你可以按任意顺序返回」 | 不必为字典序写额外代码；但**对拍时必须先规范化再比**，否则枚举顺序不同会误判（见 §097.5.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 10` | n 至多 10 | `2^10 = 1024`，指数级枚举的上界依旧温和；本机实测 **Java ≈ 0.5 ms、Go ≈ 0.4 ms**。这个 `n ≤ 10` 是出题人明说「请写回溯」 |
| `-10 <= nums[i] <= 10` | 值域只有 21 个可能值 | 值域极小 → 「按值分组计数」是可行路线（§097.3.4 会用它做扩展），但本题用排序即可 |
| 答案数量 = `∏(cnt_v + 1)` | 由值频决定 | `[1,2,2]` 是 `2×3 = 6` 个；全相同时 `[2,2,2] → 4` 个，而 096 的模板会生成 `8` 个 → **重复率可以高到 `2^n / (n+1)`** |
| 每个值最多出现几次 | 未限制，最坏 n 次 | 「全相同元素」是本题必须单独验的边界（见 §097.5.4 的 `TestSubsetsIIEdges`） |

> 💡 **量级反推**：`n ≤ 10` 说明这题的时间下界仍是输出规模，考的是**枚举的组织方式**；真正新增的考点不是速度，而是**不重不漏**。面试里说「我用 set 去重也能过」在同题上确实能 AC，但下一句一定会被问「那如果要求 `O(1)` 额外空间去重呢」——这就是本章要回答的问题。

### 示例

```text
输入：nums = [1,2,2]
输出：[[],[1],[1,2],[1,2,2],[2],[2,2]]                  ← 6 个 = (1+1)(2+1)
      注意 [1,2] 只出现一次，虽然它有两个下标来源 {0,1} 与 {0,2}

输入：nums = [0]
输出：[[],[0]]                                          ← 2 个 = 2^1，与 096 一致

输入：nums = [4,4,4,1,4]（自造，全同 + 一个异类）
输出：共 (4+1)×(1+1) = 10 个：[] [1] [1,4] [1,4,4] [1,4,4,4] [1,4,4,4,4]
                             [4] [4,4] [4,4,4] [4,4,4,4]
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [1,1]              → 最小时的最小重复：答案必须是 [[],[1],[1,1]] 三个，不是四个
② [1,1,1]            → 答案 4 个：[] [1] [1,1] [1,1,1]；096 模板会给 8 个
③ [1,2,2]            → 检验「跨层相同值不能跳」：[1,2,2] 必须存在
④ [2,1,2]（乱序）    → 不排序就去重一定错：两个 2 不相邻，i-1 比较失效
```

第 ③ 条是本章的核心：`[1,2,2]` 这个子集必须能生成，所以**跨层的相同值绝对不能跳**。第 ④ 条说明「排序」不是可选项而是前置条件——去重靠的是「相同值在数组里相邻」这个物理事实。

## 097.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 —— 「096 模板 + set 去重」

有 096 的基础，最省事的写法是：模板一字不改，收集时把结果塞进 `Set<List<Integer>>`，最后转回 `List`：

```text
void dfs(int start, path):
     seen.add(copy(path))                 // 用哈希集合兜住重复
     for i in start..n-1:
         path.add(nums[i]); dfs(i+1); path.removeLast()
```

- 时间 `O(n·2^n)`（还多了一次每个解的哈希计算 `O(k)` 与插入）；
- 空间 `O(n·2^n)` 的 set。
- 它**能 AC**（`n ≤ 10` 时 1024 个候选，去重后 ≤ 1024 个）。**所以第一个念头的错误不是「跑不过」，而是「不该这么想」。**

三个必须自己说出来的理由：

| 理由 | 具体说明 |
| --- | --- |
| **它没有减少任何搜索** | 全相同输入 `[2,2,…,2]`（n=10）时，模板会走完 `2^10 = 1024` 条路径，而正确答案只有 `11` 个。也就是说 **99% 的计算是为了生成重复品再扔掉**。这不是剪枝，这是「先污染后治理」 |
| **去重成本与答案规模脱钩** | set 的每个 key 是一个 `List<Integer>`，哈希要遍历整个 list：`O(k)`。总代价从 `O(n·2^n)` 变成 `O(n·2^n)` 的常数更大版本；而正确做法把**搜索树本身**缩小到 `∏(cnt_v+1)` 个结点 |
| **它经不起追问** | 「如果只允许 `O(n)` 额外空间？」「如果要求按字典序输出且不重复？」「如果数据量大到输出只有几千个但路径有几百万条？」——set 方案全部无法回答，因为它们都要求「先枚举再删」 |

> 📌 一句话：**set 去重是「结果层的补丁」，同层去重是「结构层的约束」。** 前者让错误发生后再修补，后者让错误根本不发生。第 10 部分从 096 到 107，每一章都在练后者。

### 第二步：卡点在哪 —— 「重复」到底发生在树的哪个位置

先把重复从「结果」翻译回「过程」。以 `nums = [1,2,2]`（**已排序**）为例，画出 096 的决策树：

```text
                        dfs(start=0, [])
          ┌──────────────────┼──────────────────┐
      选1 │              选2 │              选2'│      ← 下标 1 与下标 2，值相同
          ▼                  ▼                  ▼
   dfs(1,[1])          dfs(2,[2])          dfs(3,[2])   ★ 与左边那个 [2] 完全同构
    ┌─────┴─────┐            │
选2 │       选2'│          选2'│
    ▼          ▼              ▼
 dfs(2,[1,2]) dfs(3,[1,2])  dfs(3,[2,2])
    │            ▲
选2'│            └── 与 dfs(2,[1,2]) 产出的 [1,2] 重复 ✗
    ▼
 dfs(3,[1,2,2]) ★
```

把树按「同一层、同一个父结点」切成若干「兄弟组」，规律立刻显形：

- 根结点下的三个兄弟 `选1 / 选2 / 选2'` —— 后两个**值相同**，它们展开出的整棵子树**完全同构**（都是「从下标 2 之后继续挑」，可挑的东西只有 `2`）→ 第二棵子树产出的每个答案，第一棵都有。
- `dfs(1,[1])` 下的两个兄弟 `选2 / 选2'` —— 同样同构。
- 但 `dfs(2,[2])` 下再选 `2'` 得到的 `[2,2]` **是合法答案**，它在别处没有出现过。

**卡点因此非常精确**：重复只来自「**同一层、同一父结点下，两个值相同的兄弟**」；而「**不同层之间取相同值**」是合法的、必须保留的。

### 第三步：灵感的来源 —— 把「不等价」变成「可判定」

为什么同一层的两个相同值兄弟等价？因为从这个结点出发，**可用候选只由 `start` 决定**（定义 B 的全部状态就是 `start`）。两个兄弟选了同样的值 `v` 之后：

1. 它们的 `path` 值内容相同；
2. 它们的递归参数相同（都是 `i+1` 之后的区间，且因为值相同，「后面还能拿什么」的可能性完全一致）。

**状态相同 → 子树同构 → 只需走一次。** 这就是 096 §3.2 里那句「给每个解指定唯一的规范形，并让算法恰好枚举全部规范形」的具体落地：

> 规范形 = 「对每个值 `v`，如果它在本层要被选，必须选**本层遇到的第一个未被跳过的那个 `v`**」。

于是规则只有一行：

```text
if (i > start && nums[i] == nums[i-1]) continue;    // 同层重复值 → 只走第一个
```

`i > start` 的作用是把「本层第一个候选」排除在这条规则之外：只有当 `i` 已经越过 `start`，它才可能是一个「重复的兄弟」。

**排序为什么是前提**：`nums[i] == nums[i-1]` 只有在相同值**物理相邻**时才成立。`[2,1,2]` 不排序的话，下标 2 的 `2` 与下标 1 的 `1` 比较，判断失败 → 去重失效。这就是反例 ④。

## 097.3 原理拆解

### 097.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 096 模板 + `Set<List<Integer>>` 去重 | `O(n·2^n)`，常数含哈希 | `O(n·2^n)` | 12 行 | 重复率高的输入（全相同）白跑 99%；不允许额外空间的追问；要字典序时 set 打乱了顺序 |
| 位掩码 + set 去重 | `O(n·2^n)` | `O(n·2^n)` | 12 行 | 与上一行同样的问题；且 `n > 20` 时 `1<<n` 溢出 |
| 先数频次，按「每个值取 0..cnt 个」枚举 | `O(n·∏(cnt+1))` | `O(n)` + 频次表 | 20 行 | 答案顺序不是字典序；值域大时频次表退化（本题值域小才合适） |
| **排序 + 同层去重（定义 B）** ✅ | `O(n·2^n)` 上界，实际 `O(n·∏(cnt+1))` | `O(n)` 栈 | **11 行** | 输入不允许修改（需先拷贝 O(n) 空间）；值域大到排序昂贵（本题 `n ≤ 10` 无此忧） |

**为什么选最后一行**：它是 096 模板的**一行增量**，且这一行同时完成三件事——不重（剪掉同构兄弟）、不漏（第一个兄弟仍然走）、保持着 096 已经验证过的骨架（收集在结点、递归传 `i+1`、成对撤销）。**换题成本最低的实现，通常比「另起一套更聪明的结构」更不容易写错。**

### 097.3.2 为什么这个做法是对的（正确性论证）

设排序后的数组为 `nums[0..n-1]`。把**每种不同的值**看作一个「值组」，记值 `v` 的出现次数为 `cnt_v`，其出现位置为连续区间 `[L_v, R_v]`。答案的正确数量是 `∏_v (cnt_v + 1)`。

**引理 1（规范形唯一）**：任何一个子集（按值计）唯一地对应一个「每种值取 `c_v` 个」的向量 `(c_v)_v`，其中 `0 ≤ c_v ≤ cnt_v`。反过来这个向量唯一确定子集。

> 证明：子集是值多重集，`c_v` 就是值 `v` 在其中的重数。值与重数一起唯一确定了多重集。∎

**引理 2（算法只产生规范路径）**：算法生成的每一条路径，其下标序列对每个值 `v` 恰好是「该值的第 1 个、第 2 个、… 第 `c_v` 个出现」。

> 证明（对「值组」归纳）：考察值组 `v` 的最左位置 `L_v`。在某个结点上，「本层的候选区间」是 `[start, n-1]`。
> ① 若 `L_v ≥ start`，则本层第一个值为 `v` 的候选就是 `nums[L_v]`（因为 `v` 的出现是连续的、且 `L_v` 是其中最小的下标）。跳过规则只会跳过 `i > start` 且与前驱同值的候选，因此**被跳过的 `v` 一定是「本层第二个及之后的 `v`」**，第一个 `v` 永远不被跳过。
> ② 于是若某条路径第一次选 `v`，选到的必然是 `nums[L_v]`；此后递归的 `start = L_v + 1`，值 `v` 的第二个出现 `L_v + 1` 满足 `i == start`，`i > start` 为假 → **不被跳过**，可以继续选；第三个同理（`start = L_v + 2`）。
> ③ 若某条路径**不**选 `v`（`v` 不在本子树里），则本层所有 `v` 都会被跳过（除第一个以外被规则跳过；而第一个虽然不被跳过，却对应「选了 `v`」这个分支，与「不选」是不同分支），所以不会产生「选了第 2 个 `v` 却没选第 1 个」的非法路径。
> 归纳即得：路径对每个值取的是「前 `c_v` 个出现」。∎

**引理 3（不重）**：两条不同的路径产生不同的子集。

> 由引理 2，路径 ↔ 向量 `(c_v)` 是单射（路径的 `path` 就是那个多重集）。而引理 1 说向量 ↔ 子集是双射。复合得「路径 → 子集」是单射。∎

**引理 4（不漏）**：对任意 `(c_v)` 向量，存在一条路径生成它。

> 对值组按 `L_v` 递增依次决策：在每个值组的结点上选 `[L_v, L_v + c_v - 1]` 这 `c_v` 个下标（引理 2 的 ② 保证这些边都未被剪掉），若 `c_v = 0` 就不进这条边。所有值组处理完就得到该向量对应的路径。∎

**定理**：算法输出的解集 = 全部子集，且每个恰好一次。

> 引理 3（不重）+ 引理 4（不漏）。∎

> **这个论证的模板价值**：`i > start && nums[i]==nums[i-1]` 之所以对，是因为它把「每层从重复值里挑第一个」变成了**规范形的一部分**。100（组合总和 II）与 102（全排列 II）用的是同一个思想，只是规范形的表述换了一种（102 用的是 `used[i-1]`，见 [`102-permutations-ii.md`](102-permutations-ii.md)）。

**一个便宜的自检**：手工输入全相同的 `[2,2,2]`，正确答案 4 个；如果代码给出 8 个，说明去重没生效；如果给出 3 个（少了 `[2,2]` 或 `[2]`），说明**跨层也跳了**（把 `i > start` 写成了无条件跳过）。

### 097.3.3 通用解题思路（可迁移的那一层）

**同层去重**是本章要装进工具箱的那一件。先把它与「跨层相同值」的区别钉死在图上：

```text
                    dfs(start=0, path=[])           ← 层 0
          ┌───────────────┬───────────────┐
        i=0             i=1             i=2
      nums=1          nums=2          nums=2
      走 ✓            走 ✓          跳过 ✗   ← i>start && nums[i]==nums[i-1]：同层第 2 个 2
          │               │
          ▼               ▼
   dfs(start=1)     dfs(start=2)
   ┌──────┴──────┐        │
  i=1         i=2      i=2 = start
 nums=2     nums=2     nums=2
 走 ✓     跳过 ✗        走 ✓   ← i == start：跨层的相同值必须保留，否则 [2,2] 消失
```

三句话记住这张图：

1. **同一层**的重复值 = 「从同一个父结点出发，做了等价的选择」→ 子树同构 → 只走第一个。
2. **不同层**的重复值 = 「同一个值的第 1 次、第 2 次、… 选取」→ 落在不同的多重集里 → 都要走。
3. 判定「同层」的唯一变量是 `start`：`i > start` 说明 `i` 不是本层的第一个候选；`i == start` 说明它是，且它总是代表「这个值在本层第一次出现」。

通用骨架（与 096 完全相同，只在 `for` 里多一行）：

```text
void dfs(int start, path, ...) {
    ans.add(copy(path));                        // 收集在结点
    for (int i = start; i < n; i++) {
        if (i > start && nums[i] == nums[i-1]) continue;   // ②(去重剪枝)
        path.add(nums[i]);                      // ③(a)
        dfs(i + 1, path, ...);
        path.removeLast();                      // ③(b)
    }
}
```

属于「排序 + 同层去重」这个模型的题：

| 题 | 决策树的边 | 去重行的位置 |
| --- | --- | --- |
| [LC 90 子集 II](https://leetcode.cn/problems/subsets-ii/) | 选 `nums[i]`，下一层从 `i+1` | `for` 循环开头 |
| [LC 40 组合总和 II](https://leetcode.cn/problems/combination-sum-ii/) | 选 `c[i]`，下一层从 `i+1` | `for` 循环开头，**外加固有剪枝** |
| [LC 47 全排列 II](https://leetcode.cn/problems/permutations-ii/) | 每一层都可以选任意未用元素 | 靠 `used[i-1]` 判断，语义等价但写法不同 |
| [LC 15 三数之和](https://leetcode.cn/problems/3sum/) | 双指针，但外层 `i` 也要去重 | 「第一个数」的 `i > 0 && nums[i]==nums[i-1]`，本质同一件事 |

### 097.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**大小恰为 k** 的不重复子集 | 收集条件变紧 | 收集点改成 `len == k` 并 `return`，再加 `i <= n-(k-len)` 剪枝（见 [`098-combinations.md`](098-combinations.md)），去重行不动 |
| 只要**和等于 target** 的子集 | 边带权 | 排序 + 同层去重 + `sum > target` 提前 `break`，见 [`100-combination-sum-ii.md`](100-combination-sum-ii.md) |
| 元素**可重复使用** | 递归传 `i` 而非 `i+1` | 同层去重**必须去掉**（否则 `[2,2]` 这类「同一值反复用」会被误剪）；见 [`099-combination-sum.md`](099-combination-sum.md) |
| 只要**方案个数**，不要方案 | 只数不构造 | 直接 `∏(cnt_v+1)`，`O(n)` 数频次后连乘，回溯是浪费 |
| 值域**极大**（比如 `10^9`） | 频次桶失效 | 仍可用排序 + 同层去重；只是不能再走「按值分组计数」的路线 |
| 输入**不允许修改** | 排序会破坏入参 | 先 `copy` 一份再排序，额外 `O(n)` 空间；或在原数组上排序并在返回前还原 |

## 097.4 图解推演

### 097.4.1 `nums = [1,2,2]` 的完整决策树（含剪枝标记）

```text
                          dfs(start=0, [])  ★收录 []
                ┌──────────────┬──────────────┐
             i=0            i=1            i=2
             选1            选2           ⊘ 剪枝(i>0 && nums[2]==nums[1])
                │              │
                ▼              ▼
        dfs(1,[1]) ★      dfs(2,[2]) ★
        ┌───────┴───────┐      │
      i=1             i=2    i=2 == start
      选2            ⊘ 剪枝    选2
        │                     │
        ▼                     ▼
  dfs(2,[1,2]) ★      dfs(3,[2,2]) ★
        │
   i=2 == start
      选2
        │
        ▼
  dfs(3,[1,2,2]) ★

★ 收录点共 6 个：[] [1] [1,2] [1,2,2] [2] [2,2]
⊘ 剪枝共 2 处，都落在「同一层、同一父结点、值相同」的位置
```

**关键观察**：剪掉的 2 个分支如果保留，会多出 `[2]`（第二份）与 `[1,2]`（第二份）——正好是两个重复项。树的结点从 096 的 `8` 个降到 `6` 个，降幅与重复率一致。

### 097.4.2 逐行执行轨迹（`nums = [1,2,2]`）

| 步 | 进入的调用 | `path` | 收录 | 循环 `i` / 判定 | 撤销后 `path` |
| --- | --- | --- | --- | --- | --- |
| 1 | `dfs(0)` | `[]` | `[]` | i=0 走；i=1 走；i=2 剪枝 | — |
| 2 | `dfs(1)` | `[1]` | `[1]` | i=1 走；i=2 剪枝（`2==2` 且 `i>start`） | — |
| 3 | `dfs(2)` | `[1,2]` | `[1,2]` | i=2：`i==start` → 走 | — |
| 4 | `dfs(3)` | `[1,2,2]` | `[1,2,2]` | 空循环（`start==3`） | `[1,2]` |
| 5 | 回 `dfs(2)` 结束 | — | — | 撤销 `[1,2]` 的 2 | `[1]` |
| 6 | 回 `dfs(1)` 结束 | — | — | 撤销 `[1]` 的 1 | `[]` |
| 7 | `dfs(0)` 的 i=1 | `[2]` | `[2]` | i=2：`i>start` 且同值 → 剪枝 | — |
| 8 | `dfs(2)` 的 i=2 | `[2,2]` | `[2,2]` | `i==start` 走完 | 全部回退到 `[]` |

**第 5、6 步是「状态恢复」的考场**：从 `[1,2,2]` 回来后，`path` 必须**逐层**退回 `[1,2]` → `[1]` → `[]`。少退一层，第 7 步选 `2` 时就会得到 `[1,2,2]`——一个内容正确但**重数错**的子集，而且这种错误不会报异常，只会安静地污染输出。

### 097.4.3 「同层跳 / 跨层不跳」的对照表

| 场景 | `i` 与 `start` | `nums[i]` 与前驱 | 结论 | 为什么 |
| --- | --- | --- | --- | --- |
| 根结点选第一个 `2`（`i=1`） | `i > start(0)` | 与前驱 `1` 不同 | **走** | 值首次出现在本层 |
| 根结点选第二个 `2`（`i=2`） | `i > start(0)` | `==2`（前驱是 `2`） | **剪** | 与 `i=1` 的兄弟同构，子树完全重复 |
| `[1]` 下选 `2`（`i=1`） | `i > start(1)` 为假（`i == start`） | 与前驱 `1` 不同 | **走** | 本层第一个候选 |
| `[1]` 下选第二个 `2`（`i=2`） | `i > start(1)` | `==2` | **剪** | 同层兄弟同构 |
| `[2]` 下再选 `2`（`i=2`） | `i == start(2)` | `==2` | **走** | 跨层：这是「同一值的第 2 次选取」，产出 `[2,2]`，别处没有 |

## 097.5 双语言实现

### 097.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> subsetsWithDup(int[] nums) {
        // 排序是去重的前提：只有相同值物理相邻，nums[i]==nums[i-1] 才有意义
        Arrays.sort(nums);

        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        dfs(nums, 0, path, res);
        return res;
    }

    /** start = 本层允许选的最小下标；它就是定义 B 的全部状态 */
    private void dfs(int[] nums, int start, List<Integer> path, List<List<Integer>> res) {
        // 收集点在结点：子集问题的每个部分解都是合法答案
        // 必须 new 一份：path 是同一个对象，直接 add(path) 会让所有结果共享它
        res.add(new ArrayList<>(path));

        for (int i = start; i < nums.length; i++) {
            // ② 去重剪枝：i > start 说明 i 不是本层第一个候选（即它是某个兄弟的等价物）
            // 此时若与前一个值相同，兄弟的子树与本分支完全同构 → 整枝跳过
            if (i > start && nums[i] == nums[i - 1]) {
                continue;
            }
            path.add(nums[i]);                  // ③(a) 选择
            dfs(nums, i + 1, path, res);        //     递归：下一层从 i+1 起
            path.remove(path.size() - 1);       // ③(b) 撤销：remove(int) 删下标
        }
    }
}
```

### 097.5.2 Go

```go
package main

import "sort"

func subsetsWithDup(nums []int) [][]int {
	// 排序是去重的前提，必须先做；本题允许修改入参，若不允许要先拷贝
	sort.Ints(nums)

	res := make([][]int, 0)
	path := make([]int, 0, len(nums))

	var dfs func(start int)
	dfs = func(start int) {
		// 深拷贝一份再存：append(res, path) 只会拷切片头，
		// 之后 path 继续 append/缩容会写同一块底层数组，把已存的结果改掉
		res = append(res, append([]int(nil), path...))

		for i := start; i < len(nums); i++ {
			if i > start && nums[i] == nums[i-1] { // ② 同层去重
				continue
			}
			path = append(path, nums[i]) // ③(a) 选择
			dfs(i + 1)                   //     递归
			path = path[:len(path)-1]    // ③(b) 撤销：缩回一位，不是清空
		}
	}
	dfs(0)
	return res
}
```

### 097.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 排序 | `Arrays.sort(nums)`（双轴快排，原地） | `sort.Ints(nums)`（pdqsort，原地） | 两边都直接改入参；若入参不可改要先拷贝 |
| 拷贝 `path` | `new ArrayList<>(path)` | `append([]int(nil), path...)` | **两边都必须拷**，理由见下 |
| 撤销 | `path.remove(path.size()-1)` | `path = path[:len(path)-1]` | Java 有重载陷阱：`remove(int)` 删下标、`remove(Object)` 删值。在 `List<Integer>` 上写 `remove(2)` 删的是**值 2** |
| 去重判定的类型 | `nums[i] == nums[i-1]`（`int` 比较） | 同左 | 若元素换成 `Integer`，Java 必须用 `equals`，而 Go 无此问题 |
| 结果集类型 | `List<List<Integer>>` | `[][]int` | 对拍时两边都要「内部排序 + 外部排序」规范化 |

#### ⚠️ Go 切片别名：本章亲手验证的反例

`append(res, path)` 与 `append(res, append([]int(nil), path...))` 的差别是**对错问题**，不是风格问题。我在 `/tmp/alias` 里用 n=3、输入 `[1,2,3]` 实跑了两版，输出如下：

```text
不加拷贝（错误）：
  [[] [1] [1 2] [3 3 3] [3 3] [3] [3 3] [3]]
深拷贝（正确）：
  [[] [1] [1 2] [1 2 3] [1 3] [2] [2 3] [3]]
```

注意错误版本的**前三个结果看着是对的**——这正是它最阴的地方：`path` 长度还小的时候 `append` 会扩容、每次换新数组，所以暂时没事；等 `path` 的 `cap` 长到 `4` 之后，后续所有写入都落在**同一块**底层数组上，于是前面存过的结果被就地改写成了 `[3 3 3]` 之类的非法内容。**这种 bug 不会 panic、不会越界，只会给出错答案。**

还要说清一件常被误解的事：

```go
// 096 §5.3 提到的第二种写法：三下标截断，让「存进去的那份」cap == len
res = append(res, path[:len(path):len(path)])
```

它的作用只是**封住存进 `res` 的那个切片头的容量**——之后如果对**这个头**做 `append`，必然重新分配，不会写回原数组。但在标准回溯模板里，后续写入走的是**另一个头** `path`（`len` 变小了、`cap` 仍是 4），而 `cap > len` 的头照样会原地写。所以我实跑这份「三下标版」得到的结果与不加拷贝完全一致：

```text
三下标截断（在标准回溯模板里仍然错误）：
  [[] [1] [1 2] [3 3 3] [3 3] [3] [3 3] [3]]
```

**结论（本章的操作规程）**：

1. 只要一个 `[]T` 会被**存进结果**、并且**之后还会被 `append`**，就必须用 `append([]T(nil), x...)` 深拷贝；
2. `path[:len(path):len(path)]` 只在「存进去之后，再没有任何 `cap > len` 的同数组切片头会写这块内存」时才够用（例如你把它立刻交付给调用方、自己改用一份全新切片继续）；
3. 判定口诀：**看谁还会写这块内存，而不是看谁在读它。**

### 097.5.4 对拍测试（写完必须跑）

对拍判据：**两边都先把结果规范化**（每个子集内升序 + 结果集按「长度优先、逐项」排序）再比较。参考实现用**位掩码枚举 + `set` 规范化去重**，与回溯完全独立。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 参考实现：位掩码枚举全部 2^n 个下标子集，再用 map 做「值级」去重
func bruteSubsetsII(nums []int) [][]int {
	n := len(nums)
	seen := map[string]bool{}
	out := [][]int{}
	for mask := 0; mask < 1<<n; mask++ {
		cur := []int{}
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				cur = append(cur, nums[i])
			}
		}
		sort.Ints(cur) // 规范化：值相同 → 排序后字面量相同，才能用字符串当 key
		key := ""
		for _, v := range cur {
			key += string(rune(v+100)) + ","
		}
		if !seen[key] {
			seen[key] = true
			out = append(out, append([]int(nil), cur...))
		}
	}
	return out
}

func normII(subs [][]int) [][]int {
	out := make([][]int, len(subs))
	for i, s := range subs {
		c := append([]int(nil), s...)
		sort.Ints(c)
		out[i] = c
	}
	sort.Slice(out, func(a, b int) bool {
		if len(out[a]) != len(out[b]) {
			return len(out[a]) < len(out[b])
		}
		for k := range out[a] {
			if out[a][k] != out[b][k] {
				return out[a][k] < out[b][k]
			}
		}
		return false
	})
	return out
}

func TestSubsetsIIRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026097))
	for iter := 0; iter < 4000; iter++ { // 4000 > 要求的 3000
		n := 1 + r.Intn(10)
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(5) - 2 // 值域只有 5 个值 → 重复密集，专治去重 bug
		}
		got := normII(subsetsWithDup(append([]int(nil), nums...)))
		want := normII(bruteSubsetsII(nums))
		if len(got) != len(want) {
			t.Fatalf("iter=%d nums=%v 数量 %d != %d", iter, nums, len(got), len(want))
		}
		for i := range got {
			if len(got[i]) != len(want[i]) {
				t.Fatalf("iter=%d nums=%v 第%d项长度 %v vs %v", iter, nums, i, got[i], want[i])
			}
			for k := range got[i] {
				if got[i][k] != want[i][k] {
					t.Fatalf("iter=%d nums=%v 第%d项 %v vs %v", iter, nums, i, got[i], want[i])
				}
			}
		}
	}
}

// 边界：单元素 / 全相同 / 最小重复
func TestSubsetsIIEdges(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{[]int{1}, 2},
		{[]int{1, 1}, 3},
		{[]int{1, 1, 1}, 4},
		{[]int{2, 2, 2, 2, 2, 2, 2, 2, 2, 2}, 11},
		{[]int{1, 2, 2}, 6},
		{[]int{-1, -1, 0}, 6},
	}
	for _, c := range cases {
		if got := len(subsetsWithDup(append([]int(nil), c.nums...))); got != c.want {
			t.Fatalf("nums=%v 解数 %d，期望 %d", c.nums, got, c.want)
		}
	}
}
```

## 097.6 复杂度与常见坑

### 097.6.1 复杂度推导（写结论不算本事，要能推）

**时间上界 `O(n · 2^n)`，实际 `O(n · ∏(cnt_v + 1))`。**

1. 决策树的结点数：去掉剪枝分支后，每个结点对应一个「向量 `(c_v)` 的前缀」，所以结点数 = `∏_v (cnt_v + 1)`。全相同时是 `n+1`，全不同时退化回 `2^n`。
2. 每个结点做多少工作：收集时拷贝 `path`，代价是路径长度 `k ≤ n`；归纳可得总拷贝代价是 `O(n · ∏(cnt_v+1))`。
3. 每个结点内的 `for` 迭代次数是 `n - start ≤ n`，被第 2 步吸收。
4. `sort` 的 `O(n log n)` 在 `n ≤ 10` 时小于主项，量级上被吸收。

**空间 `O(n)`（不含输出）**：递归深度 ≤ `n`，`path` 长度 ≤ `n`，外加 `sort` 的 `O(log n)` 栈。输出 `O(n · ∏(cnt_v+1))` 是题目要求，不计入额外空间。

### 097.6.2 七个真实踩过的坑

1. **忘了排序** —— `[2,1,2]` 上 `nums[i]==nums[i-1]` 判断失效，输出重复子集。修法：`sort` 放在 `dfs` 之前。
2. **把 `i > start` 写成 `i > 0`** —— 于是跨层相同值也被剪，`[2,2]`、`[1,1]` 这类正确解消失。用 `[1,1]` 单测（答案必须是 `[[],[1],[1,1]]`）立刻暴露。
3. **把 `i > start` 写成 `i >= start`** —— 恒真，等于「本层第一个也跳过」，一个分支都走不动，只输出 `[[]]`。
4. **用 `set` 去重却忘了深拷贝 `path`** —— `set` 里塞的还是同一个 `ArrayList` 引用，最后 set 里只剩一份（或内容全变成最后一次的值）。Java 必须 `new ArrayList<>(path)`。
5. **Go 里用「值」当 `map` 的 key 拼字符串时没加分隔符** —— `[1,11]` 与 `[11,1]` 拼成同一个 key `"111"`，去重把不同子集合并了。要用 `strconv.Itoa` + 逗号分隔，或直接用 `fmt.Sprint(cur)`。
6. **以为「答案个数一定小于 `2^n`」就加了错误的剪枝** —— 例如「值相同就 `break`」而不是 `continue`：`break` 会把本层后面**不同的值**也一起砍掉（因为数组已排序，`break` 意味着「后面的我都不要」），直接漏解。
7. **`continue` 与 `break` 混用** —— 本题应 `continue`（跳过这一个兄弟，后面还有别的值）；100（组合总和 II）里当数组有序且和已超限时才可以 `break`。两者的判据是「后面的候选还有没有救」。

### 097.6.3 面试官最爱追问的三个问题

**Q1：为什么 `i > start` 就能保证是「同层」？**
> 「因为定义 B 的结点状态只有 `start`——它是本层允许选的最小下标。`i` 从 `start` 开始遍历，所以 `i == start` 恰好是『本层第一个候选』，`i > start` 是『后续候选』。后续候选如果与前一个值相同，说明它和刚走完的那个兄弟选了同样的值、并且递归参数 `i+1` 也落在同样的候选区间上，两棵子树同构，只需保留一棵。跨层的相同值 `i == start` 不会被跳过，因为那一层它是该值的第一次选取。」

**Q2：能不能不排序就做？**
> 「可以，但要换一套判定：不排序时相同值不相邻，`nums[i]==nums[i-1]` 失效。替代方案是用 `map[int]bool` 记录『本层已经枚举过哪些值』——每层进入时清空、退出时无需恢复（它是每层私有的），遇到已出现过的值就跳过。时间同为 `O(n·∏(cnt+1))`，但每层多一个 map 的常数，且失去了字典序输出。**排序 + `i>start` 是常数最小、代码最短的版本**，所以是默认答案。」

**Q3：如果要求结果按字典序输出呢？**
> 「排序后的回溯本身**就是**字典序：每一层都按值升序展开，先收录短前缀再深入，正好是『先按第一个元素分组，组内按第二个元素分组』。若还要求长度优先，就要在收集后按 `(len, 逐项)` 排序，或改成按长度递增枚举（`for k in 0..n` 每个长度跑一次 `dfs`）。」
