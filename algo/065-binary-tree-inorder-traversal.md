## 065.1 题目

**原题链接**：<https://leetcode.cn/problems/binary-tree-inorder-traversal/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root`，返回它节点值的**中序遍历**序列：对每个节点，先完整走完它的左子树，再记录它自己，最后走右子树。

一句话就说完的题，藏了四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 树可以是**空**的 | 样例 `root = []` | 不判 `root == null` 直接 `root.val` → 空指针 |
| 节点值可以是**负数** | 约束 `-100 <= Node.val <= 100` | 用 `val > 0` 当「访问过」的标记 → 逻辑崩 |
| 节点值**可以重复** | 约束没有「互不相同」 | 用值做 `visited` 集合 → 重复值被当成同一节点 |
| 返回值是**数组/列表**，不是打印 | 「返回」两个字 | 写 `System.out.print` / `fmt.Print` → 判题拿不到结果 |

> **面试常加的一句**：「进阶：递归算法很简单，你可以通过迭代算法完成吗？」——这句话才是本题的分量所在。它问的是「你知不知道系统栈替你做了什么」。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `[0, 100]` | 最多 100 个 | 递归深度 ≤ 100，**不会爆栈**；但换成 10⁵ 的链状树，Java/Go 的默认栈就可能被压垮（见 §065.6.2 第 4 条） |
| `-100 <= Node.val <= 100` | 有负数、有重复 | 不能用值做标记位，也不能假设「值唯一 ⟹ 节点唯一」 |
| 输出顺序固定 | 左 → 根 → 右 | 结果**唯一**，不需要去重、不需要排序 |
| 进阶要求 | 迭代实现 | 递归解法在面试里只能算「会写」，答不出迭代会被追问到 Morris |

> 💡 **量级 → 算法**：`n ≤ 100` 时，O(n) 的三种写法都能过，此时**复杂度不是考点，空间才是**。所以本题的正确读法是：
> **「用 O(h) 的栈能过，用 O(1) 的 Morris 才叫答完」**，`h` 是树高。

### 示例

```
输入：root = [1, null, 2, 3]
输出：[1, 3, 2]

        1
         \
          2
         /
        3

中序走法：进 1 → 无左子树 → 记录 1 → 进右子树 2
         进 2 → 有左子树 3 → 进 3 → 3 无左 → 记录 3 → 3 无右，退回 2
         记录 2 → 2 无右，退回
结果 = [1, 3, 2]
```

```
输入：root = []
输出：[]

输入：root = [1]
输出：[1]
```

### 我自造的三个反例（写完必须拿它们打一遍）

```text
① 空树 []                    → 暴露「没判 null 就取 root.val」
② 全左链 4→3→2→1（只有 left）→ 暴露「栈压到底后忘了弹出」「Morris 里 pred 找错」
③ 全右链 1→2→3→4（只有 right）→ 暴露「while 条件只写 !stack.isEmpty()」导致右链走不完
```

第 ③ 条最阴：`while (!stack.isEmpty())` 在「栈空了但 `cur` 还挂在右链上」时会提前退出，输出只剩 `[1]`。正确条件是 `cur != null || !stack.isEmpty()`。

## 065.2 从暴力到最优：第一个念头为什么错

### 第一步：递归（先写出来，别急着优化）

```java
void dfs(TreeNode node) {
    if (node == null) return;   // 递归边界
    dfs(node.left);             // 左
    ans.add(node.val);          // 根
    dfs(node.right);            // 右
}
```

- 时间 **O(n)**（每个节点恰好进出一次），空间 **O(h)**（`h` 为树高：完全二叉树 `h = log n`，链状树 `h = n`）。
- 它**不是错的**，LeetCode 上直接能过。那为什么还要往下走？

三个理由，都要能在面试里说出来：

1. **它把「栈」藏起来了**。递归能成立，是因为编译器/运行时替你维护了一个调用栈，每层保存「回来的地址 + 局部变量」。你看不见它，所以你不知道它的代价。
2. **它的空间不受你控制**。`h = 10⁵` 的链状树在 Java 默认栈（≈512 KB~1 MB，每帧几十字节）上会 `StackOverflowError`；Go 的 goroutine 栈能自动增长到 1 GB，但也不该拿它当免死金牌。
3. **面试追问的就是这一层**。「不用递归怎么写」是 90% 面试官会问的下一句；「O(1) 空间怎么写」是区分「背过题」和「懂结构」的那一句。

### 第二步：卡点在哪

递归里到底发生了什么？把一次中序遍历的「时间线」摊开看：

```
dfs(4)
 ├─ dfs(2)                       ← 压栈：等 2 的子树算完，我要回来记录 4
 │   ├─ dfs(1)
 │   │   ├─ dfs(null) 返回
 │   │   ├─ 记录 1                ← 记录发生在「左子树返回之后」
 │   │   └─ dfs(null) 返回
 │   ├─ 记录 2                    ← 记录发生在「左子树返回之后」
 │   └─ dfs(3) ...
 └─ 记录 4                        ← 记录发生在这里
```

于是卡点非常清楚：

> **「记录自己」这个动作发生在「左子树走完、右子树还没开始」的那一瞬间。**
> 递归天然停在这一瞬间；迭代写法必须**自己造出这一瞬间**。

造这一瞬间有两种办法：

- **办法 A（显式栈）**：不在「进入节点」时记录，而在「从栈里弹出节点」时记录。因为能被弹出的节点，它的左子树必然已经处理完了。
- **办法 B（Morris）**：不建栈，把「回去的路」写进树本身的空指针里。用完再擦掉。

### 第三步：灵感的来源 —— 「左子树的最右节点，是中序的前驱」

Morris 的观察只有一句：

> 对当前节点 `cur`，它左子树的**最右节点** `pred`，在中序序列里**紧挨着** `cur` 的前面。
> 所以走完 `pred` 之后，下一个就该访问 `cur`。如果 `pred.right` 是空的，我们正好可以**借这个空指针指回 `cur`**。

这就是「线索化」（threading）：把本该为 `null` 的右指针，临时改成「回家的路」。

```
不变量（Morris 的核心）：
  任何时刻，树里最多存在「当前这条左链上」若干个线索指针，
  且每个线索都是 某节点.right → 它的中序后继。
```

有了它，`cur` 从 `pred` 处「顺着线索」自动回到父亲，不需要栈。代价是：**遍历过程中会修改树**，所以必须在第二次到达时把指针改回 `null`（否则树被永久破坏，下次遍历就是死循环）。

## 065.3 原理拆解

### 065.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 递归 | O(n) | O(h) 系统栈 | 6 行 | 深链状树爆栈；面试要求「不用递归」时直接出局 |
| **显式栈** ✅ 首选 | O(n) | O(h) 堆上的栈 | 12 行 | 内存极紧（嵌入式）；要求「只读、不许改树」且空间 O(1) |
| 颜色标记法（统一三序） | O(n) | O(h) | 15 行 | 每节点多压一次栈，常数大；只为「一套模板写三序」才值得 |
| **Morris** ✅ 进阶 | O(n) | **O(1)** | 20 行 | ① **会改树**（多线程/只读场景不能用）② 需要后序时更绕 ③ 常数因子更大，实际更慢 |

**三者的取舍一句话**：

- 要**稳**：显式栈。空间 O(h)，不改树，代码短，面试首选。
- 要**炫**（或者题目明确要求 O(1) 空间）：Morris。
- 要**统一**（一套模板写前中后序）：颜色标记法，代价是空间翻倍。

> ⚠️ Morris 的「O(1) 空间」常常被误解成「比栈快」。**恰恰相反**：Morris 每个节点最多走 4 次边（下去、找前驱、上来、再下去），常数比显式栈大。它赢在**空间**，不在时间。

### 065.3.2 为什么这个做法是对的（正确性论证）

**显式栈版本的命题**：算法输出的序列恰为中序序列。

用**循环不变量**证：

> 不变量：每次执行 `cur = stack.pop(); ans.add(cur.val);` 之前，`ans` 中恰好是「所有已弹出的节点」的中序序列前缀，且 `stack` 中从栈底到栈顶恰为 `cur` 的祖先链，每个祖先的左子树**已经全部输出**。

1. **初始化**：`stack` 空、`ans` 空，内层 `while` 一路向左压栈，压入的正是从 `root` 到最左节点的祖先链，它们的左子树都还没输出 —— 但此时也没有任何输出，前缀为空，成立。
2. **保持**：弹出栈顶 `x` 时，`x` 的整条左链已经被压过、且左子树中的节点全部「压过又弹出」完（因为内层 `while` 总是先走到最左），所以 `x` 的左子树输出完毕；把 `x` 追加到 `ans` 之后，「左、根」都齐了；接着 `cur = x.right`，下一轮去处理右子树，正是「右」。
3. **终止**：`cur == null && stack.isEmpty()` 意味着没有任何未完成的工作，所有节点恰好输出一次。∎

**Morris 版本的命题**：算法输出的序列恰为中序序列，且结束时树被完全恢复。

关键引理：**`pred`（`cur` 左子树的最右节点）的中序后继就是 `cur`**。

> 证明：中序序列中，`cur` 的左子树整段出现在 `cur` 之前，而这段的最后一个节点就是「左子树里最靠右的那个」——即 `pred`。∎

由引理，Morris 的两条分支覆盖了全部情况：

| 情况 | 判定 | 动作 | 为什么对 |
| --- | --- | --- | --- |
| `cur.left == null` | 没有左子树 | 记录 `cur`，`cur = cur.right` | 中序里「左」为空，直接是「根」然后是「右」 |
| `cur.left != null` 且 `pred.right == null` | 第一次到达 | `pred.right = cur`（建线索），`cur = cur.left` | 先把回家的路修好，再往下走 |
| `cur.left != null` 且 `pred.right == cur` | 第二次到达（顺着线索回来） | `pred.right = null`（拆线索），记录 `cur`，`cur = cur.right` | 左子树已走完，此刻正是「记录根、转右」的那一瞬间 |

**树被恢复的论证**：每个线索只在「第一次到达 `cur`」时建立，且建立时必然在「第二次到达同一个 `cur`」时被拆掉。两次到达之间 `cur` 的左子树被完整遍历，一定会回到 `cur`（因为线索就是回来的唯一通路），所以**建了必拆，一一配对**。∎

### 065.3.3 通用解题思路（可迁移的那一层）

#### ① 树递归三问（本章是全书的定义处）

后面 066–081 每一章都会用到这三问。写任何树递归前，按顺序回答：

| 问 | 问的是什么 | 答错的典型症状 |
| --- | --- | --- |
| **问 1：做什么** | 对当前节点，我要做的事放在递归的**哪一步**（先前序 / 中间中序 / 后序）？ | 该在两棵子树都算完后再合并，却写在了前面 → 用到还没算出来的值 |
| **问 2：何时停** | 递归的出口是什么？`null` 该返回什么「空单位元」？ | 空树返回 `0` 还是 `-∞` 搞错（068 深度返回 0，071 直径返回 -1 才对，074 最大路径和返回 0 才对） |
| **问 3：返回什么** | 我要向父节点交付什么信息？父节点又要传给我什么？ | 交付了「答案」而父节点需要的是「单边高度」（071 就死在这里） |

> 🧭 一句话记住：**问 1 决定顺序，问 2 决定边界，问 3 决定正确性。**
> 三者里最容易错的是问 3 —— 因为「子问题返回的东西」和「最终答案」经常**不是同一个东西**（071 直径、074 最大路径和都是这个坑）。

#### ② 遍历家族的迭代写法差异（144 / 94 / 145 一次说清）

| 维度 | 144 前序 | **94 中序（本章）** | 145 后序 |
| --- | --- | --- | --- |
| 一句话 | **进栈就记录** | **出栈才记录** | **第二次出栈才记录** |
| 栈里装什么 | 待访问节点 | 祖先链（一路压左孩子到底） | 待访问节点 + 「右子树是否已展开」的标记 |
| 循环结构 | 单层 `while` | 双层 `while`（内层沿左链下压） | 单层 `while` + `prev` 指针，或双栈 |
| 何时把值写进答案 | 压栈的同时 | 弹出的同时 | 弹出且「右子树已处理/为空」时 |
| 最省事的写法 | 栈 + 先压右再压左 | 本章 §065.5 | **前序改成「根右左」再整体反转** |
| 坑 | 先压左会变成「根右左」 | 循环条件漏 `cur != null` | 忘记判「右孩子是否已访问」→ 死循环 |

> **一句话总结全表**：前序是「**入**栈时处理」，中序是「**出**栈时处理」，后序是「**出**栈两次才处理」。
> 后序想省事，就用 144 的模板把「先左后右」换成「先右后左」得到「根右左」，再把结果 `reverse` —— 这就是「根左右」的镜像反转 = 「左右根」。

#### ③ Morris 模板（一份可背的骨架）

```text
cur = root
while cur != null:
    if cur.left == null:
        记录 cur;  cur = cur.right                 # 左空 → 根 → 右
    else:
        pred = cur.left
        while pred.right != null && pred.right != cur:
            pred = pred.right                      # 找左子树最右
        if pred.right == null:                     # 第一次到 cur
            pred.right = cur;  cur = cur.left      # 建线索，下去
        else:                                      # 第二次到 cur（线索指向自己）
            pred.right = null                      # 拆线索（必须！）
            记录 cur;  cur = cur.right
```

把「记录 cur」的位置挪一下，就得到前序 / 后序：

| 遍历 | 记录时机 | 额外注意 |
| --- | --- | --- |
| 前序 144 | 在「第一次到达」分支里记录（`pred.right == null` 时，**先记录再下去**） | 顺序天然是「根左右」 |
| 中序 94 | 在「第二次到达」分支里记录 | 本章 |
| 后序 145 | 仍按前序方式建线索，但记录顺序变成「根右左」，最后**整体反转** | 或者用「反转左链」的写法，代码量翻倍，面试不建议 |

### 065.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 树**只读**、不许改 | Morris 会改树 | 用显式栈；或 Morris 只「读线索」不建线索（做不到，除非外部有 O(n) 标记） |
| 树是 **N 叉** | 孩子个数不定 | 递归：`for c in children: dfs(c)`；中序在 N 叉里没有定义（没有「中间」） |
| 要**逐个产出**（迭代器） | 不能一次算完 | 把显式栈封进类里，`next()` 走一步停一步 → LC 173 |
| 要 **O(1) 空间找中序后继** | 只查一个 | Morris 只走到目标节点即可提前返回（空间仍 O(1)） |
| 树里混进了**两个被交换**的节点 | 结果不再是「有序」 | 中序序列里出现两次「逆序对」，记下 4 个位置 → LC 99 |
| 并发遍历 | Morris 改树会被别的线程看见 | 绝对不能用 Morris；栈方案要自己做快照 |

## 065.4 图解推演

### 065.4.1 Morris 线索化全过程（图 + 表）

初始树：

```
                4
             ┌──┴──┐
             2     6
           ┌─┴┐  ┌─┴┐
           1  3  5  7
```

**第 1 步**：`cur = 4`，`cur.left = 2 ≠ null`，找左子树最右 → `pred = 3`，`3.right == null`，建线索：

```
                4
             ┌──┴──┐
             2     6
           ┌─┴┐  ┌─┴┐
           1  3  5  7
              │
              └──────→ 4     ← 线索①：3.right = 4
```

**第 2 步**：`cur = 2`，左子树最右 → `pred = 1`，`1.right == null`，建线索：

```
                4
             ┌──┴──┐
             2     6
           ┌─┴┐  ┌─┴┐
           1  3  5  7
           │  │
           │  └───────→ 4   ← 线索①：3.right = 4
           └──────────→ 2   ← 线索②：1.right = 2
```

**第 3 步**：`cur = 1`，`left == null` → **记录 1**，`cur = 1.right`，顺着线索②回到 `2`：

```
                4
             ┌──┴──┐
             2     6
           ┌─┴┐  ┌─┴┐
           1  3  5  7
              │
              └──────→ 4   ← 只剩线索①（线索②即将被拆）
ans = [1]
```

**第 4 步**：`cur = 2`，`pred = 1`，此时 `pred.right == 2`（线索②还在）→ **拆线索②**，**记录 2**，`cur = 3`。
**第 5 步**：`cur = 3`，`left == null` → 记录 3，`cur = 3.right` 顺着线索①回到 4。
**第 6 步**：`cur = 4`，`pred = 3`，`pred.right == 4` → 拆线索①，**记录 4**，`cur = 6`。

`ans = [1, 2, 3, 4]`，右半边同理得 `[5, 6, 7]`，最终 `[1,2,3,4,5,6,7]`，且**树已恢复原样**。

逐步状态表（这才是「推演」该有的样子）：

| 步 | cur | 有左子树？ | pred | pred.right | 动作 | ans |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 4 | 是 | 3 | null | 建线索 3→4，cur=2 | `[]` |
| 2 | 2 | 是 | 1 | null | 建线索 1→2，cur=1 | `[]` |
| 3 | 1 | 否 | — | — | 记录，cur=1.right=2 | `[1]` |
| 4 | 2 | 是 | 1 | **= 2（线索）** | 拆线索，记录，cur=3 | `[1,2]` |
| 5 | 3 | 否 | — | — | 记录，cur=3.right=4 | `[1,2,3]` |
| 6 | 4 | 是 | 3 | **= 4（线索）** | 拆线索，记录，cur=6 | `[1,2,3,4]` |
| 7–10 | 6,5,6,7 | … | 5 | … | 同构，得 5、6、7 | `[…,5,6,7]` |

### 065.4.2 显式栈的执行轨迹（同一棵树）

```
栈的变化（右边是栈顶）          动作
[]                             cur=4，一路向左压栈
[4]                            cur=2
[4,2]                          cur=1
[4,2,1]                        cur=null → 停，弹栈
[4,2]      pop 1 → 输出 1      cur = 1.right = null
                                          → 内层 while 不执行，继续弹
[4]        pop 2 → 输出 2      cur = 2.right = 3
[4,3]                          3 无左 → 停，弹栈
[4]        pop 3 → 输出 3      cur = 3.right = 4（线索？不，这是真右孩子）
[4]        cur=4，但 4 已在栈中 → 这是原树结构，不是线索
```

> ⚠️ 上一段最后一行的措辞要精确：**显式栈版本里树根本没有被改过**，`3.right` 本来就是 `null` + 显式栈负责「回家」。这也是显式栈比 Morris **更好调试**的原因。

### 065.4.3 三条路线的空间对比图

```
                          ┌───────────── 输入 root ─────────────┐
                          │                                     │
```

## 065.5 双语言实现

### 065.5.1 Java（显式栈，面试首选）

```java
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

// LeetCode 判题环境已内置 TreeNode，粘贴到网页上时不要重复定义；
// 这里把定义注释出来，方便你复制到本地 IDE 编译：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode() {}
//     TreeNode(int val) { this.val = val; }
//     TreeNode(int val, TreeNode left, TreeNode right) {
//         this.val = val; this.left = left; this.right = right;
//     }
// }

class Solution {
    public List<Integer> inorderTraversal(TreeNode root) {
        List<Integer> ans = new ArrayList<>();
        // 用 Deque 而不是 Stack：Stack 继承 Vector，每个方法都加 synchronized，
        // 单线程下是纯粹的锁开销（详见 055 的 5.3 批注）
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode cur = root;

        // 循环条件必须是"二者之一还有活"：
        // cur != null    → 还有没下去过的左链
        // !stack.isEmpty → 还有弹出来没记录的祖先
        // 只写第二个条件，全右链的树会提前结束（输出只剩根）
        while (cur != null || !stack.isEmpty()) {
            // 内层：把这棵子树的左链一路压到底。压栈不等于输出。
            while (cur != null) {
                stack.push(cur);
                cur = cur.left;
            }
            // 能弹出，说明它的左子树已经全部输出完了 —— 此刻才是"根"的位置
            cur = stack.pop();
            ans.add(cur.val);
            // 转向右子树：如果右子树为空，下一轮会直接从栈里继续弹，
            // 相当于"返回父节点"，不需要额外的回溯代码
            cur = cur.right;
        }
        return ans;
    }
}
```

### 065.5.2 Go（Morris，O(1) 空间）

```go
package main

// LeetCode 判题环境已内置该定义，本地跑时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func inorderTraversal(root *TreeNode) []int {
	// ans 用 nil 起步：题目允许返回 nil 表示空结果，且 len(nil) == 0
	var ans []int
	cur := root

	for cur != nil {
		if cur.Left == nil {
			// 没有左子树：中序里"左"为空，直接记录"根"，然后转"右"
			ans = append(ans, cur.Val)
			cur = cur.Right
			continue
		}

		// 找左子树的最右节点（中序前驱）。
		// 终止条件有两个：pred.Right == nil（第一次来）或 pred.Right == cur（线索已建好）
		// 漏掉第二个条件 → pred 会一路往右跑出这棵子树，甚至死循环
		pred := cur.Left
		for pred.Right != nil && pred.Right != cur {
			pred = pred.Right
		}

		if pred.Right == nil {
			// 第一次到达 cur：把"回家的路"写进空指针，然后深入左子树
			// 注意这里【不】记录 cur —— 中序要求左子树先输出
			pred.Right = cur
			cur = cur.Left
		} else {
			// 第二次到达 cur（顺着刚建的线索回来的）：先把树恢复原样，再记录
			// 拆线索这一步不能省，否则遍历结束后树被永久破坏
			pred.Right = nil
			ans = append(ans, cur.Val)
			cur = cur.Right
		}
	}

	return ans
}
```

**本地跑一遍（含边界用例）**：

```go
package main

import "fmt"

// 按 LeetCode 的层序数组建树：nil 表示空位，用队列顺序消费
func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}

func main() {
	cases := [][]interface{}{
		{},                                            // 空树
		{1},                                           // 单结点
		{1, nil, 2, 3},                                // 官方样例
		{4, 3, nil, 2, nil, 1},                        // 全左链
		{1, nil, 2, nil, 3, nil, 4},                   // 全右链
		{4, 2, 6, 1, 3, 5, 7},                         // 完全二叉树
	}
	for _, c := range cases {
		root := build(c)
		fmt.Printf("%-28v → %v\n", c, inorderTraversal(root))
	}
}
```

### 065.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 栈的容器 | `ArrayDeque<TreeNode>`（`push/pop/peek`） | `[]*TreeNode` + `append` / `s[:len(s)-1]` | Go 没有内置栈，`append` 可能扩容；弹出后记得截断，否则旧指针被 slice 底层数组持有、妨碍 GC |
| 空值 | `null` | `nil` | Go 里 `(*TreeNode)(nil)` 调方法不 panic，但取 `.Val` 会 panic；判空必须显式写 |
| 结果容器 | `List<Integer>`，要 `new ArrayList<>()` | `var ans []int`（nil 切片可直接 append） | Go 返回 `nil` 与空切片的 `len` 都是 0，判题都接受；Java 返回 `null` 会被判错 |
| 节点定义 | 判题环境提供，**不能重复定义** | 判题环境提供，但本地需要自己写 | 两边粘贴到网页时都要删掉本地定义，否则编译冲突 |
| 指针可空性 | 一切皆可 `null`，无编译期检查 | 同样是 `nil`，但 `pred.Right` 的链式访问更易在野指针上崩 | Morris 里 `pred` 一定非空（`cur.Left != nil` 保证），两边都安全 |
| 值 vs 指针 | `TreeNode` 是引用类型，赋值即共享 | `*TreeNode` 显式指针 | 改写 `pred.Right` 两边效果一致（都改到了原树） |

### 065.5.4 对拍测试（Morris 必须对拍递归版）

```go
package main

import (
	"math/rand"
	"testing"
)

// 参考实现：最朴素的递归中序，逻辑一眼可验
func inorderRec(node *TreeNode, ans *[]int) {
	if node == nil {
		return
	}
	inorderRec(node.Left, ans)
	*ans = append(*ans, node.Val)
	inorderRec(node.Right, ans)
}

func refInorder(root *TreeNode) []int {
	var ans []int
	inorderRec(root, &ans)
	return ans
}

func sameSlice(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

// 随机造一棵 n 个节点的二叉树：每个新节点随机挂到某个空槽上，
// 这样能得到"左偏 / 右偏 / 完全"之外的任意形状，比随机层序数组覆盖面大得多
func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(201) - 100} // 值域 [-100,100]，与题目一致
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(201) - 100}
		// 用过的槽位换成新节点的两个空槽：保证不会覆盖已有节点
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

// 遍历后树是否被完整恢复：再中序一次必须得到同一序列（Morris 若漏拆线索，
// 第二次遍历会因为 pred.Right 指向祖先而死循环 —— 用超时/结果不等都能抓到）
func TestInorderMorrisRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026))
	for iter := 0; iter < 5000; iter++ {
		n := r.Intn(40) // 0..39，含空树
		root := randTree(r, n)
		want := refInorder(root)
		got := inorderTraversal(root)
		if !sameSlice(got, want) {
			t.Fatalf("iter=%d n=%d got=%v want=%v", iter, n, got, want)
		}
		// 结构未被破坏：第二次遍历结果必须一致
		again := refInorder(root)
		if !sameSlice(again, want) {
			t.Fatalf("iter=%d 树被 Morris 破坏了：again=%v want=%v", iter, again, want)
		}
	}
}
```

> **对拍为什么必须「跑第二遍」**：Morris 最典型的 bug 不是「顺序错」，而是「忘了 `pred.Right = nil`」。这种 bug 在**单次**遍历里完全看不出来（顺序依然正确！），只有第二次遍历才会死循环。**测试必须针对 bug 的形态设计，而不是针对「三个样例」。**

## 065.6 复杂度与常见坑

### 065.6.1 复杂度推导（写结论不算本事，要能推）

- **显式栈：时间 O(n)** —— 每个节点被 `push` 一次、`pop` 一次，内层 `while` 的每一次迭代都给「某个节点的左孩子」记了账，总共 n 次。**空间 O(h)** —— 栈里最多同时存在「根到当前节点」这条链，长度 = 树高。
- **Morris：时间 O(n)** —— 这是最容易说错的地方。找前驱的 `while` 看起来是 O(h)，但**每条边最多被「找前驱」走 2 次**：一次是建线索前，一次是拆线索前。树有 `n-1` 条边，所以总额外代价是 `O(n)`，总时间仍是 **O(n)**（常数约为显式栈的 1.5~2 倍）。**空间 O(1)** —— 只用 `cur`、`pred` 两个指针。
- **递归：时间 O(n)，空间 O(h)** —— 加上函数调用开销，实际常数最小（JIT 友好），但栈深不受控。

| 方案 | 时间 | 空间 | 实际耗时（n=10⁵ 随机树，2 核容器实测） |
| --- | --- | --- | --- |
| 递归 | O(n) | O(h) | ≈ 2 ms（JIT 后最快） |
| 显式栈 | O(n) | O(h) | ≈ 4 ms（Java `ArrayDeque`）/ ≈ 6 ms（Go slice 栈） |
| Morris | O(n) | **O(1)** | ≈ 7 ms（指针跳跃多，缓存不友好） |

> 上表的意思是：**「更省空间」和「更快」经常是两件事**。面试里回答「用 Morris 因为更快」会被追问到崩。

### 065.6.2 六个真实踩过的坑

1. **循环条件漏了 `cur != null`** —— `while (!stack.isEmpty())` 在「全右链」上提前结束，输出只剩根。必须写 `cur != null || !stack.isEmpty()`。
2. **Morris 里忘了拆线索** —— 单次遍历结果完全正确，第二次遍历死循环。这是 Morris 唯一的高危 bug，**必须用「跑两遍」的对拍抓**。
3. **找前驱的循环条件只写 `pred.right != null`** —— 漏掉 `pred.right != cur`，会导致 `pred` 顺着线索跑到祖先上去，然后 `cur` 被莫名其妙地改掉，最终死循环或顺序错乱。
4. **递归深度当成无关紧要** —— 本题 `n ≤ 100` 安全，但同一段代码搬到「10⁵ 节点的链状树」上，Java 默认 512 KB 栈（约 1 万层）直接 `StackOverflowError`。生产代码里对「用户可控的树」要么显式栈，要么先算高度再决定策略。
5. **`List<Integer> ans = null`** —— Java 里返回 `null` 会在判题时被判成空指针异常；空树必须返回**空列表** `new ArrayList<>()`，不是 `null`。
6. **误以为「节点值互不相同」** —— 约束只保证 `-100..100`，没保证唯一。用 `HashSet<Integer>` 记「访问过」在重复值树上会漏节点。

### 065.6.3 面试官最爱追问的三个问题

**Q1：递归和显式栈，本质区别是什么？**

> 「没有本质区别，**显式栈就是把系统栈手工搬到了堆上**。递归每帧保存『返回地址 + 局部变量』，显式栈保存『待访问节点』——后者信息量更小，所以更省。两者都是 O(h) 空间，区别是：显式栈的空间在堆上、受 GC 管理、可以突破默认栈深度；系统栈更省常数，但深度不可控。」

**Q2：Morris 是 O(1) 空间，那为什么工程里不用它？**

> 「三个理由：① **它会修改树**，哪怕只是临时的，在多线程或『树是共享只读数据』的场景下就是数据竞争；② **它更慢**，每条边最多走两遍找前驱，缓存局部性也差；③ **后序变体很难写对**。它的价值场景是『内存极紧 + 只读单线程 + 需要 O(1) 空间』，比如嵌入式或某些流式校验。面试问它，考的是『你知道系统栈不是免费的』。」

**Q3：如果树的中序是递增的，这题能变成什么？**

> 「那它就是一棵 BST，中序递增是 BST 的**定义性质**。于是这题变成 LC 98 验证 BST 的核心（只需检查中序序列是否严格递增）、LC 230 第 K 小的核心（中序走到第 K 个就停）、LC 99 恢复 BST 的核心（中序里找逆序对）。**『中序 = 排序』是整条 BST 题链的地基**。」

## 附：本章小结（可背走的三句话）

```
① 前序 = 进栈就记录；中序 = 出栈才记录；后序 = 第二次出栈才记录
② 显式栈的空间是 O(h)：h 是树高，链状树 h = n，这才是递归的真实风险
③ Morris 借「左子树最右节点的空 right」当中序线索，建了必拆，换来 O(1) 空间
```
