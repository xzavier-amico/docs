## 027.1 题目

**原题链接**：<https://leetcode.cn/problems/median-of-two-sorted-arrays/>

### 题意重述（把隐含条件补齐）

给定两个**升序**数组 `nums1`（长 `m`）和 `nums2`（长 `n`），返回这两个数组合并后的**中位数**。要求时间复杂度 `O(log(m+n))`。

六条必须读出来的隐含条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 两个数组**各自**升序 | 「正序数组」 | 只保证各自有序，**没有任何跨数组的大小关系** —— 这正是要二分划分的原因 |
| 中位数定义：**偶数长度取中间两个的平均** | 「如果…是偶数，则中位数是中间两个数的平均值」 | 返回整数 / 返回较大的那个 → 错。**返回类型必须是 `double`** |
| `m + n >= 1` | 「`0 <= m, n <= 1000`，`1 <= m + n`」 | 至少有一个元素，不用处理「两个都空」 |
| 数组**可以为空** | `0 <= m` 且 `0 <= n` | `nums1 = [], nums2 = [1]` 必须返回 `1.0`。**空数组是本章第一号边界** |
| 元素可能**重复** | 没有「互不相同」的保证 | 划分条件里只能用 `<=` / `>`，不能假设严格 |
| 要求 `O(log(m+n))` | 「时间复杂度应该为 O(log (m+n))」 | 「归并两个数组再取中间」是 `O(m+n)`，明文禁止 |

> **第五条（可以有重复）非常关键**：划分条件是 `A[i-1] <= B[j]` 与 `B[j-1] <= A[i]`，**用的是 `<=`**。如果你在某处写成 `<`，在 `A = [1], B = [1]` 这种输入上就会出现「找不到合法划分」，然后返回一个错误的值。**重复值是本章隐藏最深的坑。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `m, n <= 1000` | 规模很小 | 归并取中间 `O(m+n) = 2000` 次，实测 Java ≈ 0.01 ms —— **能过**。所以这题和 022/023/024 一样：**考的是复杂度，不是通过率** |
| `1 <= m + n` | 至少一个元素 | 不用处理全空 |
| `-10^6 <= nums[i] <= 10^6` | 值域小 | 哨兵可以安全地用 `±(1<<30)`，不会与真实值撞车 |
| 要求 `O(log(m+n))` | 硬性 | 二分划分 `O(log min(m,n))`。`m = n = 1000` → **10 轮** |
| 返回 `double` | 中位数可能是 `x.5` | 平均时**必须用浮点除法**，且两数相加要为 `long` 防溢出（虽然本题值域不会） |

> 💡 **量级 → 算法**：`m + n = 2000` 时
> - 归并排序合并：`O((m+n) log(m+n)) ≈ 22,000` 次
> - 归并双指针（不用排序）：`O(m+n) = 2000` 次
> - 找第 k 小（二分 k）：`O(log(m+n))` 次
> - **划分二分：`O(log(min(m,n))) = 10` 次**
>
> 从 2000 到 10，是 200 倍。而且随着规模增大，差距会变成 `O(n)` 与 `O(log n)` 的鸿沟 —— **这才是题目要求 `O(log)` 的真正理由**。

### 示例

```
输入：nums1 = [1,3], nums2 = [2]
输出：2.00000
解释：合并后是 [1,2,3]，中位数是 2（总长 3，奇数）

输入：nums1 = [1,2], nums2 = [3,4]
输出：2.50000
解释：合并后是 [1,2,3,4]，中位数是 (2+3)/2 = 2.5（总长 4，偶数）

输入：nums1 = [], nums2 = [1]
输出：1.00000         ← 空数组

输入：nums1 = [2], nums2 = []
输出：2.00000         ← 对称的空数组

输入：nums1 = [1,1], nums2 = [1,1]
输出：1.00000         ← 全相同（重复值），划分条件必须用 <=
```

### 我自造的七个反例（写完必须拿它们打一遍）

```text
① nums1 = [],  nums2 = [1]                  → 空数组，返回 1.0
② nums1 = [],  nums2 = [1,2,3,4]            → 空数组 + 偶数总长，返回 2.5
③ nums1 = [1], nums2 = [1]                  → 全相同，返回 1.0（划分必须用 <= 而不是 <）
④ nums1 = [1,2], nums2 = [3,4]              → 偶数总长，(2+3)/2 = 2.5，检验浮点除法
⑤ nums1 = [3], nums2 = [1,2]                → 短数组在右，检验 swap / 二分范围
⑥ nums1 = [-5,-3,-1], nums2 = [-4,-2]       → 负数，检验哨兵会不会和真实值混淆
⑦ nums1 = [1,2,3,4,5,6], nums2 = [7]        → 两数组长度差 5 倍，检验 j 的越界边界
```

③ 最阴：`A = [1], B = [1]`，`half = (1+1+1)/2 = 1`，`i ∈ [0, 1]`。

- `i = 0, j = 1`：`aLeft = -∞`，`aRight = 1`，`bLeft = 1`，`bRight = +∞`。判 `bLeft > aRight`？`1 > 1` 为假（这里必须是 `>`，不能是 `>=`）。所以划分合法，`maxLeft = max(-∞, 1) = 1`，总长偶数 2，`minRight = min(1, +∞) = 1`，中位数 `(1+1)/2 = 1.0` ✅
- 如果判据写成 `bLeft >= aRight`，就会判「i 太小」，`lo = 1`；`i = 1, j = 0`：`aLeft = 1, aRight = +∞, bLeft = -∞, bRight = 1`。判 `aLeft > bRight`？`1 > 1` 也为假（如果这里也写成 `>=` 就判 `hi = 0`，然后在 `lo=1, hi=0` 时退出，返回兜底的 `0.0`）。**两个判据必须都用严格不等号 `>`，绝对不能用 `>=`。**

⑦ 检验 `j` 的边界：`m = 6 (nums1), n = 1 (nums2)`，会先 swap 成 `A = [7] (m=1), B = [1..6] (n=6)`。`half = (1+6+1)/2 = 4`，`i ∈ [max(0, 4-6), min(1, 4)] = [0, 1]`。**如果 `lo` 的 `max(0, half-n)` 写成 `half-n`，就是 `-2`，`i` 可能取到负数，`nums1[i-1]` 越界。** 这是本章最经典的崩溃点。

## 027.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（合并后排序，或归并后取中间）

```java
int[] all = new int[m + n];
System.arraycopy(nums1, 0, all, 0, m);
System.arraycopy(nums2, 0, all, m, n);
Arrays.sort(all);                                  // O((m+n) log(m+n))
int t = m + n;
return (t % 2 == 1) ? all[t/2] : (all[t/2 - 1] + all[t/2]) / 2.0;
```

- 时间 **O((m+n) log(m+n))**，空间 **O(m+n)**。
- `m = n = 1000` 时 2000 个元素排序，Java ≈ 0.15 ms —— **能过**。
- **但它是浪费的**：两个数组**已经各自有序**，`sort` 完全无视了这个信息，把「合并」这个 O(m+n) 就能做完的事做成了 O(n log n)。

### 第二步：合格但违规的解法 —— 归并双指针

既然各自有序，那就用 008（合并两个有序数组）的双指针归并，边走边数，走到第 `(m+n)/2` 个就停：

```java
int i = 0, j = 0, cnt = 0;
int prev = 0, cur = 0;
while (cnt <= (m + n) / 2) {
    prev = cur;
    if (j >= n || (i < m && nums1[i] <= nums2[j])) cur = nums1[i++];
    else                                          cur = nums2[j++];
    cnt++;
}
return ((m + n) % 2 == 1) ? cur : (prev + cur) / 2.0;
```

- 时间 **O(m + n)**，空间 **O(1)**。
- `m = n = 1000` → **约 1000 次迭代**，实测 Java ≈ 0.01 ms。
- **这是本题第二好的解法，也是面试里最该先写出来的「保底解」** —— 它简单、正确、容易讲清。
- 但它仍然是 `O(m+n)`，**不满足题目要求**。而且当 `m + n = 10⁹` 时，它要跑 5 亿次。

> 💡 **面试策略**：直接说「我能 O(m+n) 做，但题目要 O(log)，所以我要用划分二分」—— **这句话本身就是加分项**，因为它证明你知道两个解法的分界线在哪。

### 第三步：卡点 —— 「中位数」这个定义没法直接用

中位数的定义是「排序后位于中间的数」。问题在于：

- 你想知道中位数，就得知道「合并后的数组长什么样」；
- 要知道合并后长什么样，就得合并，那是 `O(m+n)`；
- **要 `O(log)`，就不能合并。**

**所以必须换一个不依赖「合并结果」的中位数刻画。** 这是本章最核心的一步。

### 第四步：灵感 —— 中位数 = 「把全体元素切成左右两半的那把刀」

关键观察：**中位数只跟「左半有哪些元素」有关，跟「左半内部怎么排」无关。**

具体地说，设总长 `T = m + n`，令 `half = ⌈T/2⌉ = (T+1)/2`（整数除法）。那么：

> 中位数 = 「**全体元素中最小的 `half` 个**」里的**最大值**（`T` 为奇数时就是它本身；`T` 为偶数时，还要再和「第 `half+1` 小」取平均）。

**为什么？** `T` 为奇数时 `half = (T+1)/2`，第 `half` 小就是正中间那个。`T` 为偶数时 `half = T/2`，第 `half` 小和第 `half+1` 小是中间两个。✔

于是问题变成：

> **怎么在「不合并」的前提下，找出「最小的 `half` 个元素」并定位其中最大的那个？**

答案：**在两个数组上各切一刀**。

```
在 A 上切在 i 处：A 贡献 i 个元素给左半（A[0..i-1]）
在 B 上切在 j 处：B 贡献 j 个元素给左半（B[0..j-1]）

要求 i + j = half                       ← 左半元素个数刚好

并且 max(左半) <= min(右半)             ← 左半确实是最小的 half 个
```

**第二条件是关键**。如果左半的最大值 ≤ 右半的最小值，那么左半的每个元素都 ≤ 右半的每个元素，左半就**真的是**最小的 `half` 个（因为它的元素个数正好是 `half`）。

而 `i` 和 `j` 由一条约束绑在一起：**`j = half - i`**。所以整个问题只剩**一个自由变量 `i`**。

### 第五步：为什么可以二分 `i`

因为「`i` 切得对不对」这件事，**随着 `i` 增大是单调变化的**：

```
i 太小  ⇒  A 贡献的元素太少，B 得贡献很多
        ⇒  B 的左半最大值 B[j-1] 可能比 A 的右半最小值 A[i] 还大
        ⇒ 违反「左半 ≤ 右半」⇒ 需要 i 增大

i 太大  ⇒  A 贡献的元素太多
        ⇒  A 的左半最大值 A[i-1] 可能比 B 的右半最小值 B[j] 还大
        ⇒ 违反「左半 ≤ 右半」⇒ 需要 i 减小

i 正好  ⇒  两个违反都不发生  ⇒  找到了
```

**这段推理就是二分的全部**。它把一个「枚举 `i`（`O(m)` 种可能）」的问题变成了 `O(log m)`。

### 第六步：为什么在**短**数组上二分

`i` 的范围是 `[0, m]`，`j = half - i` 的范围会被 `i` 挤出去。要保证 `0 ≤ j ≤ n`：

```
j ≥ 0  ⇔  i ≤ half
j ≤ n  ⇔  i ≥ half - n

合并：i ∈ [max(0, half - n), min(m, half)]
```

**这个区间一定非空**（因为存在合法划分），但它的**宽度**取决于谁更短：

| 情形 | 区间宽度 | 二分轮数 |
| --- | --- | --- |
| `m = 10`, `n = 10⁶` | `i ∈ [0, 10]`，宽度 11 | `log₂ 11 ≈ 4` |
| 若在长数组 `B` 上二分 | `j ∈ [?]`，宽度可达 `10⁶` | `log₂ 10⁶ ≈ 20` |
| `m = n = 1000` | 宽度 ≤ 1001 | 最多 10 轮 |

**所以「在短数组上二分」不是为了正确性，是为了复杂度 `O(log min(m,n))`。** 这一点在本题 `m, n ≤ 1000` 时看不出差别，但它是这道题「难度标为困难」的原因之一 —— **面试官就想听你把这一句说出来。**

## 027.3 原理拆解

### 027.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 合并 + 排序 | O((m+n)log(m+n)) | O(m+n) | 6 行 | 无视「已有序」；`m+n = 10⁶` 时比归并慢 20 倍 |
| 归并双指针 | O(m+n) | O(1) | 15 行 | **明文要求 O(log)**；`m+n = 10⁹` 时 5 亿次迭代 |
| 找第 k 小（每次砍掉 `k/2`） | O(log(m+n)) | O(1) | 30 行 | 逻辑比划分更绕（要处理「一个数组被砍空」），**常数更大**；但它是 `O(log)` 的合法解 |
| **划分二分（在短数组上）** ✅ | **O(log min(m,n))** | **O(1)** | **25 行** | 边界条件多（4 个哨兵 + 2 个判据），**写错一处就崩或死循环** |
| 划分二分（在长数组上） | O(log max(m,n)) | O(1) | 25 行 | 正确但更慢；若 `lo/hi` 的范围没夹紧，还会越界 |
| 二分答案（值域二分 + 计数） | O(log V · log n) | O(1) | 30 行 | 本题值是整数，能做；但要额外处理「第 k 小的值」与「中位数可能取平均」两件事，**反而更复杂** |

**「找第 k 小」和「划分二分」的关系**：两者都是 `O(log)`，但思路完全不同。

| 维度 | 找第 k 小 | 划分二分 |
| --- | --- | --- |
| 二分对象 | 「第几小」这个序号 `k` 的削减过程 | 短数组上的**切点** `i` |
| 每轮做什么 | 比较 `A[k/2-1]` 与 `B[k/2-1]`，砍掉较小一侧的 `k/2` 个 | 比较 `A[i-1]` 与 `B[j]`，调整 `i` |
| 终止条件 | `k == 1` 或某个数组耗尽 | 两个划分条件同时满足 |
| 边界处理 | 「某数组剩下的不够 `k/2` 个」要特判 | 「`i` 或 `j` 顶到 0 / 长度」用哨兵 |
| 难度 | 中（要考虑数组耗尽） | 中高（要考虑 4 个哨兵） |

**两者都值得会，但面试首选划分二分** —— 因为它对「中位数」这个语义的表达更直接（中位数本来就是一个「划分」），而且不需要为奇数/偶数写两套逻辑（`half` 的取整方式统一处理了）。

### 027.3.2 为什么这个做法是对的（正确性论证）

#### (a) 记号与划分的定义

设 `A = nums1`（长 `m`）、`B = nums2`（长 `n`），`T = m + n`，`half = ⌈T/2⌉ = (T+1)/2`。

对任意 `i ∈ [0, m]`，令 `j = half - i`（要求 `0 ≤ j ≤ n`）。定义：

```
左半 L = A[0..i-1] ∪ B[0..j-1]        共 i + j = half 个元素
右半 R = A[i..m-1] ∪ B[j..n-1]        共 T - half 个元素

约定哨兵：A[-1] = B[-1] = -∞，A[m] = B[n] = +∞
```

**划分条件**：

```
(P)  A[i-1] <= B[j]        // 左半 A 的最大 ≤ 右半 B 的最小
(Q)  B[j-1] <= A[i]        // 左半 B 的最大 ≤ 右半 A 的最小
```

#### (b) 引理 1：划分条件 ⟺ 「左半全 ≤ 右半」

**命题**：`(P) ∧ (Q)` ⟺ `max(L) ≤ min(R)`。

**证明**：

- `max(L) = max(A[i-1], B[j-1])`（两个数组各自升序，左半的最大值必是两段末尾之一）。
- `min(R) = min(A[i], B[j])`（同理，右半的最小值必是两段开头之一）。

`max(A[i-1], B[j-1]) ≤ min(A[i], B[j])` 展开成四个不等式：

| 不等式 | 是否自动成立 |
| --- | --- |
| `A[i-1] ≤ A[i]` | ✅ 由 A 升序 |
| `A[i-1] ≤ B[j]` | ❌ 这就是 (P) |
| `B[j-1] ≤ A[i]` | ❌ 这就是 (Q) |
| `B[j-1] ≤ B[j]` | ✅ 由 B 升序 |

所以四个不等式等价于 (P) ∧ (Q)。∎

> 💡 **这个引理的用处**：它把「左半全 ≤ 右半」这个全局性质，化成了**两次比较**。所以 `check` 是 `O(1)` 的，二分每轮只花常数时间。

#### (c) 引理 2：两个谓词各自单调，且合法划分一定存在

在合法范围 `i ∈ [max(0, half-n), min(m, half)]` 内，记 `j = half - i`，两个谓词是：

- `P(i)`：`A[i-1] ≤ B[j]`（`i = 0` 时 `A[-1] = -∞`，恒真）
- `Q(i)`：`B[j-1] ≤ A[i]`（`j = 0` 时 `B[-1] = -∞`，恒真；`i = m` 时 `A[m] = +∞`，恒真）

**引理 2a（`P` 前真后假）**：若 `P(i)` 为假，则对任意 `i' ≥ i`（仍在合法范围内），`P(i')` 也为假。

**证明**：`i' ≥ i` ⇒ `A[i'-1] ≥ A[i-1]`（A 升序）、`j' = half - i' ≤ j` ⇒ `B[j'] ≤ B[j]`（B 升序）。于是

```
A[i'-1]  ≥  A[i-1]  >  B[j]  ≥  B[j']
```

即 `P(i')` 假。∎

> 直观：`i` 越大，`A` 拿得越多（左边越容易被顶高），`B` 拿得越少（右边越容易被压低），`P` 越来越难成立。

**引理 2b（`Q` 前假后真）**：若 `Q(i)` 为真，则对任意 `i' ≥ i`（仍在合法范围内），`Q(i')` 也为真。

**证明**：`i' ≥ i` ⇒ `j'-1 = half-i'-1 ≤ j-1` ⇒ `B[j'-1] ≤ B[j-1]`（B 升序）、`A[i'] ≥ A[i]`（A 升序）。于是

```
B[j'-1]  ≤  B[j-1]  ≤  A[i]  ≤  A[i']
```

即 `Q(i')` 真。∎

> 直观：`i` 越大，`B` 的左半最大值越低、`A` 的右半最小值越高，`Q` 越来越容易成立。

**引理 2c（合法划分存在）**：至少存在一个 `i` 使 `P(i) ∧ Q(i)` 同时成立。

**证明（归并视角）**：把 `A`、`B` 归并成有序数组 `C`（长 `T`），取 `C` 的前 `half` 个元素组成左半 `L*`。设这 `half` 个元素中来自 `A` 的有 `i*` 个、来自 `B` 的有 `j* = half - i*` 个。

- 归并保持各数组内部的相对顺序，所以 `L* = A[0..i*-1] ∪ B[0..j*-1]`。
- `L*` 是 `C` 的前 `half` 个 ⇒ `L*` 的每个元素都 `≤` 右半的每个元素 ⇒ 由引理 1，`P(i*) ∧ Q(i*)` 成立。
- 显然 `0 ≤ i* ≤ m`、`0 ≤ j* ≤ n`，故 `i*` 落在搜索区间 `[max(0, half-n), min(m, half)]` 内。

所以 `i*` 就是一个合法划分点。∎

> **这个证明给了一个很好的心理图像**：合法划分就是「归并后前 `half` 个元素在各原数组里的分布」。它顺带说明：**合法划分可能不唯一**（当存在相等的跨界元素时，`i` 可以左右挪动一格而两个条件仍成立），但**任意一个合法划分给出的中位数都相同** —— 因为 `max(L)` 就是第 `half` 小、`min(R)` 就是第 `half+1` 小，这两个值由数组内容唯一决定，与选哪个 `i` 无关。

**这三条引理合起来就是二分的许可证**：

| 观察到 | 所以 |
| --- | --- |
| `P(i)` 假 ⇒ 所有 `i' ≥ i` 的 `P` 都假（2a） | `hi = i - 1` 不会丢掉合法划分 |
| `Q(i)` 假 ⇒（2b 的逆否）所有 `i' ≤ i` 的 `Q` 都假 | `lo = i + 1` 不会丢掉合法划分 |
| 合法划分一定存在（2c） | 二分不会「找不到」，兜底的 `return` 不可达 |

#### (d) 引理 3：由合法划分算中位数

设 `(i, j)` 是合法划分，`maxL = max(A[i-1], B[j-1])`，`minR = min(A[i], B[j])`。

- **`T` 为奇数**：`half = (T+1)/2`，第 `half` 小就是中位数。由 `L` 是最小的 `half` 个，第 `half` 小 `= max(L) = maxL`。中位数 `= maxL`。✔
- **`T` 为偶数**：`half = T/2`，中位数 `= (第 half 小 + 第 half+1 小) / 2 = (maxL + minR) / 2`。✔

#### (e) 二分的正确性与不死循环

```java
int lo = Math.max(0, half - n), hi = Math.min(m, half);
while (lo <= hi) {
    int i = lo + (hi - lo) / 2;
    int j = half - i;
    if (A[i-1] > B[j])      hi = i - 1;   // P 假 ⇒ i 太大
    else if (B[j-1] > A[i]) lo = i + 1;   // Q 假 ⇒ i 太小
    else return ...;                       // 两个条件都成立
}
```

**不变量**：存在某个合法划分点 `i* ∈ [lo, hi]`。

- **初始**：由引理 2，存在 `i* ∈ [max(0,half-n), min(m,half)] = [lo, hi]`。✔
- **保持**：
  - 若 `A[i-1] > B[j]`，即 `P(i)` 假。由 `P` 单调不增，所有 `i' ≥ i` 都使 `P` 假，故 `i* < i`，即 `i* ∈ [lo, i-1]`，代码 `hi = i-1`。✔
  - 若 `B[j-1] > A[i]`，即 `Q(i)` 假。由 `Q` 单调不减，所有 `i' ≤ i` 都使 `Q` 假，故 `i* > i`，即 `i* ∈ [i+1, hi]`，代码 `lo = i+1`。✔
- **终止**：两个分支都把 `mid` 排除（`±1`），区间严格缩小；若两个条件都成立则直接返回。所以循环要么在有限轮内返回，要么 `lo > hi` 退出。∎

**不死循环论证（本章最需要讲清的一点）**：

1. `i = lo + ⌊(hi-lo)/2⌋`，当 `lo ≤ hi` 时 `lo ≤ i ≤ hi`，`i` 一定落在区间内。
2. `hi = i - 1` ⇒ `hi` 严格小于原来的 `hi`（因为 `i ≥ lo`，`i-1 < hi` 当 `lo ≤ hi` 时成立：若 `lo == hi` 则 `i = lo = hi`，`hi = i-1 = lo-1 < lo`，区间变空）。
3. `lo = i + 1` ⇒ `lo` 严格大于原来的 `lo`。
4. **两个分支都是 `±1`，没有 `i = mid` 这种「原地踏步」的更新**，所以区间长度 `hi - lo` 每轮至少减 1（实际是减半）。

**结论：本章用的是 020 的闭区间模板 A，它的死循环风险为零。** 这一点非常重要 —— 很多人在 027 上写 `while (lo < hi)` + `lo = i`，然后在 `lo == i` 时死循环。**用「命中即返回 + 全 ±1」的写法，从根上避开了这个陷阱。**

> ⚠️ **但代价是「必须能找到」，所以兜底 `return` 那一行理论上不可达**。Go 要求函数有返回值，Java 也是。写 `return 0.0;` 并注释「不可达」是标准做法。**如果你希望它更严谨，可以写成 `throw new IllegalStateException()`，但 LeetCode 上返回 0.0 更省事。**

#### (f) 哨兵为什么安全

`A[-1]` 用 `-∞`、`A[m]` 用 `+∞`。只要 `-∞ < 任何真实值 < +∞`，所有比较结论都与「不存在该元素」的语义一致：

- `A[i-1] > B[j]` 当 `i = 0` 时：`-∞ > B[j]` 恒假。语义上「A 的左半为空，不可能有元素超过 B 的右半」—— **正确**。
- `B[j-1] > A[i]` 当 `j = 0` 时：`-∞ > A[i]` 恒假。语义上「B 的左半为空，不可能有元素超过 A 的右半」—— **正确**。
- `A[i-1] > B[j]` 当 `j = n` 时：`+∞`，若 `A[i-1]` 是真实值则恒假。语义上「B 的右半为空，不存在『B 的右半最小』这个东西，所以不可能违反」—— **正确**。

**取值**：本题 `|nums[i]| ≤ 10⁶`，所以用 `-(1<<30)` / `(1<<30)`（约 `±1.07·10⁹`）足够，且 `int` 装得下。**不要用 `Integer.MIN_VALUE` / `MAX_VALUE` 去做算术**（比如 `maxL + minR`），那会溢出 —— 本章代码只把它们用于**比较**，求平均时才转 `long`。

### 027.3.3 通用解题思路（可迁移的那一层）

本章提炼出二分的**第六条方法论**：**「二分一个划分」**。

```
问题：两个有序序列的某个「位置统计量」（中位数 / 第 k 小 / 分位数）
   ↓ 直接合并是 O(m+n)，不行
问：这个统计量能不能用「把两个序列各切一刀」来刻画？
   ↓ 能：切点 (i, j) 满足 i+j = half，且左半全 ≤ 右半
   ↓ 而 j = half - i 把二维的切点降成**一维**
剩一个自由变量 i
   ↓ 「i 切得对不对」随 i 单调变化（P 单调不增、Q 单调不减）
   ↓ 二分 i，O(log min(m,n))
```

**这套方法与前面五章的关系**（本批的完整谱系）：

| 章 | 二分的对象 | 单调性来自 | 复杂度 |
| --- | --- | --- | --- |
| 020 | 数组下标 | 数组升序 | `O(log n)` |
| 021 | 数组下标（两次） | 谓词 `>=` / `>` 一次跳变 | `2·O(log n)` |
| 022 | 数组下标 | 分段单调（一半有序） | `O(log n)` |
| 023 | 位置（最小值在哪） | 「是否跨过断点」0/1 单调 | `O(log n)` |
| 025 | **答案值** | `check(答案)` 单调 | `O(n log V)` |
| 026 | **答案值** | 贪心段数单调 | `O(n log V)` |
| **027** | **划分位置 `i`** | 两个谓词反向单调，在 `i` 处交叉 | `O(log min(m,n))` |

**注意 027 的独特之处**：它的单调性不是「一个谓词」，而是**两个方向相反的谓词**：

```
P(i) : 真 真 真 真 假 假 假 假       ← 前真后假（i 越大越难成立）
Q(i) : 假 假 假 假 真 真 真 真       ← 前假后真（i 越大越容易成立）

                交叉重叠区 = [i_Q, i_P] = 合法划分的集合
                     ▲
              二分收敛到这里
```

**「两个反向单调的谓词交叉」是很多划分型问题的共同结构**：

| 题 | 谓词 P | 谓词 Q | 二分对象 |
| --- | --- | --- | --- |
| [LC 4](https://leetcode.cn/problems/median-of-two-sorted-arrays/) | `A[i-1] <= B[j]` | `B[j-1] <= A[i]` | 短数组切点 `i` |
| [LC 719 找出第 k 小的距离对](https://leetcode.cn/problems/find-k-th-smallest-pair-distance/) | 距离 ≤ x 的对数 ≥ k | — | 距离值 `x`（二分答案） |
| 两个有序数组的**第 k 小** | `A[i-1] <= B[j]` | `B[j-1] <= A[i]` | 同本章（`half` 换成 `k`） |
| **带权**中位数 / 分位数 | 权重前缀和 ≤ 一半 | 同上 | 切点 |
| 两个有序数组的**下四分位数** | 同构 | 同构 | 切点（`half` 换成 `⌈T/4⌉`） |

### 027.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 求**第 k 小**而不是中位数 | `half` 换成 `k` | 完全同构：`j = k - i`，`i ∈ [max(0, k-n), min(m, k)]`，条件不变 |
| 三个 / `K` 个有序数组的中位数 | 划分从 2 维升到 `K` 维 | 二分仍然可用（在最短的那个上二分，其余用 `half - i` 分摊），但要**保证分摊是合法的**，实现复杂度陡增；**`K` 较大时不如用堆做多路归并（`O(K + half log K)`）** |
| 数据**流式**输入（不断加入新数） | 无法预知长度 | 用**对顶堆**维护中位数（029 之后的 LC 295），`O(log n)` 插入、`O(1)` 查询 |
| 数组**动态修改** | 二分失效（每次修改要重排） | 平衡 BST / 树状数组 + 二分，或分块 |
| 只要**判断中位数是否 ≥ x** | 不需要精确值 | 计数：`A` 中 ≥ x 的个数 + `B` 中 ≥ x 的个数，看是否 ≥ `⌈T/2⌉`。这是「值域二分」的另一条路 |
| **浮点数**数组 | 划分逻辑不变 | 但「第 k 小」的语义要小心（相等元素的处理）；哨兵要换成 `±math.Inf` |

**进阶延伸（自己写代码验证）**：

- **LC 295 数据流的中位数**：用两个堆（大顶 + 小顶）维护中位数。**它是本章的「动态版」** —— 静态用二分，动态用堆，这是数据结构的经典分工。
- **LC 378 有序矩阵中第 K 小的元素**：值域二分 + 按行计数。**它和本章是「第 k 小」的两种不同打法**（一个二分值、一个二分划分）。
- **LC 719 找出第 k 小的距离对**：二分距离值 + 双指针计数。**做完本章再做它，会发现「二分答案」和「二分划分」的区别一目了然。**

### 027.4.3 两个谓词的交叉图（二分的本质）

```
i 的可能取值：  lo=0    1     2     3     4=hi
                 │     │     │     │     │
P(i): A[i-1]<=B[j]   T     T     T     F     F
                              ↑
                         P 在这里失效（i=3,4）

Q(i): B[j-1]<=A[i]   F     F     F     T     T
                              ↑
                         Q 从这里开始成立（i=3,4）

    ┌──────────────────────────────────────────────┐
    │ P 前真后假，Q 前假后真 —— 两个方向相反的谓词    │
    │ 它们的"重叠区"就是合法划分的集合               │
    │   i ∈ [i_Q, i_P]                             │
    │ 二分从两端逼近，找到一个重叠点即可             │
    └──────────────────────────────────────────────┘

本图（A=[1,3,5,7], B=[2,4,6], half=4）实际的真值：

  i=0: j=4 → j>n(=3) 越界，不在搜索范围内
  i=1: j=3, A[0]=1 <= B[3]=+∞ ✅ P真;  B[2]=6 <= A[1]=3? 假 → Q假  ⇒ lo=2
  i=2: j=2, A[1]=3 <= B[2]=6 ✅ P真;  B[1]=4 <= A[2]=5 ✅ Q真  ⇒ 命中，返回 max(3,4)=4
```

### 027.4.4 完整二分的收缩轨迹

```
A = [1, 3, 5, 7]   B = [2, 4, 6]
T = 7   half = 4   lo = max(0, 4-3) = 1   hi = min(4, 4) = 4

第 1 轮  lo=1              hi=4
          │                 │
          ▼                 ▼
   i:     0    1    2    3    4
                ↑
            i = 1+(4-1)/2 = 2
          j = 4 - 2 = 2

   A[0..1] = [1,3]      A[2..3] = [5,7]
   B[0..1] = [2,4]      B[2..2] = [6]

   P: A[1]=3 <= B[2]=6  ✅
   Q: B[1]=4 <= A[2]=5  ✅
   ⇒ 命中！

   T = 7 为奇数 ⇒ 中位数 = max(A[1], B[1]) = max(3, 4) = 4.0 ✅

   （这一轮就命中了，因为 i=2 恰好是答案；
     如果没命中，会按上面的规则收 lo 或 hi，最多再走 2 轮）

   ┌────────────────────────────────────────────┐
   │ 区间长度: 4 → 2 → 1 → 0（最坏情况）          │
   │ 每轮至少减半 ⇒ 轮数 = ⌈log2(hi-lo+1)⌉       │

```

### 027.4.5 偶数总长的例子

```
A = [1, 2]   B = [3, 4]
T = 4, half = (4+1)/2 = 2     答案应为 (2+3)/2 = 2.5

lo = max(0, 2-2) = 0,  hi = min(2, 2) = 2

第 1 轮  i = 0+(2-0)/2 = 1,  j = 1

   A:  ┌────┐┌────┐           i=1
       │ 1  ││ 2  │
       └────┘└────┘
        A左    A右
   B:  ┌────┐┌────┐           j=1
       │ 3  ││ 4  │
       └────┘└────┘
        B左    B右

   P: A[0]=1 <= B[1]=4  ✅
   Q: B[0]=3 <= A[1]=2  ❌  → i 太小，lo = 2

第 2 轮  lo=2  hi=2  i = 2,  j = 0

   A:  ┌────┬────┐            i=2（A 全在左半）
       │ 1  │ 2  │
       └────┴────┘
   B:  ┌────┐┌────┐           j=0（B 全在右半）
       │ 3  ││ 4  │
       └────┘└────┘

   P: A[1]=2 <= B[0]=3  ✅
   Q: B[-1]=-∞ <= A[2]=+∞  ✅（哨兵让"B 左半为空"自动成立）
   ⇒ 命中！

   T = 4 为偶数
   maxL = max(A[1], B[-1]) = max(2, -∞) = 2
   minR = min(A[2], B[0]) = min(+∞, 3) = 3
   中位数 = (2 + 3) / 2.0 = 2.5 ✅
```

### 027.4.7 三种解法的复杂度对比

```
      ┌──────────────── 输入：两个升序数组 ────────────────┐
      │                                                  │
  ┌───▼────────────┐  ┌──────────────▼───────┐  ┌────────▼─────────────┐
```

## 027.5 双语言实现

### 027.5.1 Java

```java
class Solution {
    // 哨兵：题目值域 |nums[i]| <= 10^6，用 ±(1<<30) ≈ ±10.7 亿足够，
    // 且 int 装得下（不用 Integer.MIN_VALUE/MAX_VALUE 是为了避免后续算术溢出）
    private static final int NEG_INF = -(1 << 30);
    private static final int POS_INF = 1 << 30;

    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        // 让 A 是较短的那个：二分区间宽度 = min(m,n)+1，复杂度 O(log min(m,n))
        if (nums1.length > nums2.length) {
            int[] tmp = nums1;
            nums1 = nums2;
            nums2 = tmp;
        }
        int m = nums1.length, n = nums2.length;
        int[] A = nums1, B = nums2;

        // half = 左半应有的元素个数，向上取整：奇数时中位数正好落在左半最大值上，
        // 这样奇偶两种情况可以共用同一套 maxL / minR
        int half = (m + n + 1) / 2;

        // i = A 贡献给左半的个数。j = half - i 必须落在 [0, n]：
        //   j >= 0  =>  i <= half
        //   j <= n  =>  i >= half - n
        // 再与 i 本身的 [0, m] 取交集
        int lo = Math.max(0, half - n);
        int hi = Math.min(m, half);

        // 模板 A（闭区间）：命中即返回，两个分支都是 ±1 => 区间严格收缩 => 不会死循环
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;
            int j = half - i;

            // 用哨兵表达"这一段为空"，使 4 种越界情形都不需要单独 if
            int aLeft  = (i == 0) ? NEG_INF : A[i - 1];
            int aRight = (i == m) ? POS_INF : A[i];
            int bLeft  = (j == 0) ? NEG_INF : B[j - 1];
            int bRight = (j == n) ? POS_INF : B[j];

            if (aLeft > bRight) {
                // A 的左半最大 > B 的右半最小 => A 拿多了 => i 要减小
                // 严格 > 而不是 >=：相等是合法划分（有重复值时全靠这一点）
                hi = i - 1;
            } else if (bLeft > aRight) {
                // B 的左半最大 > A 的右半最小 => B 拿多了 => i 要增大（A 多拿，B 少拿）
                lo = i + 1;
            } else {
                // 划分合法：左半恰好是最小的 half 个元素
                int maxLeft = Math.max(aLeft, bLeft);
                if (((m + n) & 1) == 1) {
                    return maxLeft;              // 奇数：第 half 小就是它
                }
                int minRight = Math.min(aRight, bRight);
                // 转 long 再加：两道保险（本题值域安全，但模板要能搬到任意值域）
                return ((long) maxLeft + minRight) / 2.0;
            }
        }
        return 0.0;   // 不可达：引理 2 保证一定存在合法划分
    }
}
```

### 027.5.2 Go

```go
package main

const (
	negInf = -(1 << 30)
	posInf = 1 << 30
)

func findMedianSortedArrays(nums1 []int, nums2 []int) float64 {
	if len(nums1) > len(nums2) {
		nums1, nums2 = nums2, nums1
	}
	m, n := len(nums1), len(nums2)
	A, B := nums1, nums2

	half := (m + n + 1) / 2

	lo := half - n
	if lo < 0 {
		lo = 0
	}
	hi := half
	if hi > m {
		hi = m
	}

	for lo <= hi {
		i := lo + (hi-lo)/2
		j := half - i

		aLeft, aRight := negInf, posInf
		if i > 0 {
			aLeft = A[i-1]
		}
		if i < m {
			aRight = A[i]
		}
		bLeft, bRight := negInf, posInf
		if j > 0 {
			bLeft = B[j-1]
		}
		if j < n {
			bRight = B[j]
		}

		if aLeft > bRight {
			hi = i - 1 // A 拿多了
		} else if bLeft > aRight {
			lo = i + 1 // B 拿多了
		} else {
			maxLeft := aLeft
			if bLeft > maxLeft {
				maxLeft = bLeft
			}
			if (m+n)%2 == 1 {
				return float64(maxLeft)
			}
			minRight := aRight
			if bRight < minRight {
				minRight = bRight
			}
			return float64(maxLeft) / 2.0 + float64(minRight)/2.0
		}
	}
	return 0 // 不可达：合法划分一定存在
}

func main() {
	println(findMedianSortedArrays([]int{1, 3}, []int{2}))    // 2
	println(findMedianSortedArrays([]int{1, 2}, []int{3, 4})) // 2.5
	println(findMedianSortedArrays([]int{}, []int{1}))        // 1
	println(findMedianSortedArrays([]int{1, 1}, []int{1, 1})) // 1
}
```

> 💡 **`float64(maxLeft)/2.0 + float64(minRight)/2.0` 这个写法**：它等价于 `(maxLeft + minRight) / 2`，但**先转浮点再相加，永远不会整型溢出**。如果值域放宽到 `±2³¹`，`maxLeft + minRight` 在 Go 的 64 位 `int` 上仍安全，但在 Java 的 `int` 上会溢出 —— 所以本章 Java 版用了 `((long) maxLeft + minRight) / 2.0`，Go 版用了「各除一半再相加」。**两种写法都正确，任选一种并说清为什么。**

### 027.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 交换数组 | `int[] tmp = nums1; nums1 = nums2; nums2 = tmp;` | `nums1, nums2 = nums2, nums1` | Go 的多重赋值一行搞定；Java 必须三行。**两种都不用复制元素，只换引用** —— 复制会多 `O(m+n)` 空间，白送劣势 |
| 哨兵 | `private static final int` | 包级 `const` | 都是编译期常量，无运行时开销 |
| 三元表达式 | 有 `? :` | **没有**，必须 `if` | Go 版求 `aLeft / bLeft` 时多写了几个 `if`，**代码更长但更不容易看错** |
| 掩码求奇偶 | `((m + n) & 1) == 1` | `(m+n)%2 == 1` | `& 1` 更快但 `%2` 更清楚；Go 版用 `%2` 是为了可读性 |
| 整型溢出 | `int` 32 位，`maxLeft + minRight` 要转 `long` | `int` 在 64 位平台是 64 位，但**跨平台不一致** | 本章 Java 用 `(long)` 强转，Go 用「各除一半再相加」，**绕开类型宽度差异** |
| 返回值 | `double` | `float64` | 一致；注意 Go 里 `float64(int)` 是显式转换，不会自动提升 |
| 不可达分支 | `return 0.0;`（可以不带原因） | `return 0`（也可以，但 Go 编译器要求所有路径有返回值） | **两语言都必须写这一行**，否则编译失败 |

```go
func bruteMedian(a, b []int) float64 {
	all := make([]int, 0, len(a)+len(b))
	all = append(all, a...)
	all = append(all, b...)
```

## 027.6 复杂度与常见坑

### 027.6.1 复杂度推导

**时间 O(log min(m,n))**：

- 二分区间宽度 `hi - lo + 1 ≤ min(m, n) + 1`（因为 `i ∈ [0, m]`，而 `A` 是较短的，所以 `m = min`）。
- 每轮 `O(1)`：4 次哨兵判断 + 2 次比较 + 2 次 max/min。
- 轮数 `≤ ⌈log₂(min(m,n)+1)⌉`。`m = n = 1000` → **10 轮**。`m = n = 10⁶` → **20 轮**。
- **总时间 `O(log(min(m,n)))`，与 `max(m,n)` 完全无关** —— 这就是「在短数组上二分」的全部价值。

**空间 O(1)**：`m, n, half, lo, hi, i, j, aLeft, aRight, bLeft, bRight, maxLeft, minRight` —— 全是个位数个变量。**没有合并、没有复制数组**（`swap` 只换引用）。

### 027.6.2 十个真实踩过的坑（本章是全批最多的一章）

1. **`lo` 的 `max(0, half - n)` 漏掉 `max(0, ...)`** —— `half - n` 可以是负数。`m = 1, n = 6` 时 `half = 4`，`half - n = -2`，`i` 可能取到 `-2`，`A[i-1]` 直接越界崩。**必须 `max(0, ·)`。**
2. **`hi` 的 `min(m, half)` 漏掉 `min(m, ...)`** —— `half` 可以大于 `m`。`m = 1, n = 6` 时 `half = 4 > m = 1`，`i` 可能取到 4，`A[i]` 越界。**必须 `min(m, ·)`。**
3. **没把短数组换到前面** —— 不换也能出正确答案（因为 `lo/hi` 夹紧了），但**复杂度变成 `O(log max(m,n))`**，而且区间宽度的公式推导会变（此时 `i` 是长数组的切点，`j` 可能更容易越界）。**必须 swap。**
4. **判据用 `>=` 而不是 `>`** —— `A[i-1] >= B[j]` 会在「相等」时误判成「i 太大」，把合法划分排除掉。在 `A = [1], B = [1]` 上就跑不进 `else` 分支，最终返回兜底的 `0.0`。**两个判据都必须是严格 `>`。**
5. **`maxLeft` 和 `minRight` 只在 `else` 分支里算** —— 有人在 `if (aLeft > bRight)` 分支里也去算 `maxLeft`，此时 `aLeft` 可能比 `bLeft` 大得多，算出来的不是答案。**只有两个条件都满足时，`max(L)` 和 `min(R)` 才有意义。**
6. **奇偶判断用 `m + n` 还是 `half`** —— 奇偶看的是 `m + n`，不是 `half`。`half = (m+n+1)/2` 对奇偶都成立，但「返回 `maxL` 还是平均值」必须由 `(m+n) % 2` 决定。**搞混会在偶数时返回整数，丢掉 `.5`。**
7. **平均写成 `(maxLeft + minRight) / 2`（整数除法）** —— `(2+3)/2 = 2`，丢掉 `.5`。**必须 `/ 2.0`。**
8. **平均值整型溢出** —— `maxLeft + minRight` 在 Java 的 `int` 上，若两者都接近 `2³¹-1` 就溢出成负数。本章值域安全，但**模板要能搬**。用 `((long) maxLeft + minRight) / 2.0` 或「各除一半再相加」。
9. **`while (lo < hi)` + `lo = i` / `hi = i`** —— 严格来说，本模板下 `hi = i` 是安全的（`i < hi`），但 `lo = i` 在 `hi = lo+1` 时会死循环。**本章用的是「命中即返回 + 全 `±1`」的模板 A，从根上避免了这个问题；如果你要改成 `lo < hi` 版本，请务必把 `lo = i` 换成 `lo = i + 1`。**
10. **空数组没考虑** —— `A = []` 时 `m = 0`，`lo = max(0, half - n) = 0`，`hi = min(0, half) = 0`，`i = 0, j = half`。此时 `aLeft = NEG_INF`、`aRight = POS_INF`，条件自动满足，直接进 `else` 分支。**哨兵让空数组免于特判 —— 但前提是 `lo/hi` 算对了。**

### 027.6.3 面试官最爱追问的三个问题

**Q1：为什么 `i` 和 `j` 只用二分 `i` 就够了？`j` 为什么不用二分？**
> 「因为左半的元素个数是固定的 `half`。`i` 是 `A` 贡献的个数，`j` 必须是 `half - i`，**没有自由度**。所以二维的切点 `(i, j)` 被一条线性约束降成了一维，只剩一个自由变量 `i`。这是本题能把 `O(m+n)` 压到 `O(log)` 的根本原因 —— **降维，而不是更聪明的搜索**。」

**Q2：为什么要在较短的数组上二分？**
> 「两个原因。① **复杂度**：二分区间宽度是 `min(m,n)+1`，所以在短数组上二分是 `O(log min(m,n))`，在长数组上是 `O(log max(m,n))`。`m=10, n=10⁶` 时差 4 倍。② **边界更少**：在短数组上二分时，`j = half - i` 更容易落在 `[0, n]` 内（因为长数组「装得下」），越界情形更少。**严格来说正确性不依赖这一点**（因为 `lo/hi` 已经夹紧了），但工程上明显更稳。」

**Q3：这两个判据 `A[i-1] > B[j]` 和 `B[j-1] > A[i]` 为什么一定能二分？如果两个同时违反了怎么办？**
> 「它们**不可能同时违反**。如果 `A[i-1] > B[j]`，因为 `A` 升序有 `A[i] ≥ A[i-1]`，所以 `A[i] > B[j]`；而 `B` 升序有 `B[j-1] ≤ B[j]`（若 `j-1 ≥ 0`），所以 `B[j-1] < A[i]`，也就是第二个判据**自动满足**。反之亦然。**所以两个判据是互斥的，二分每轮最多走一条分支，方向明确。**
> 另外，两个谓词各自单调：`A[i-1] ≤ B[j]` 是「前真后假」，`B[j-1] ≤ A[i]` 是「前假后真」，它们的重叠区就是合法划分的集合。合法划分一定存在（可以用「归并后前 `half` 个元素各自的来源个数」构造出来），所以二分一定能收敛到一个重叠点。」

## 附：本章小结（可背走的三句话）

```
① 中位数 = 把两个数组各切一刀，使左半恰好 half 个元素且左半全 ≤ 右半；j = half - i 把切点降成一维
② 「i 切得对不对」随 i 单调（P 前真后假、Q 前假后真），所以在短数组上二分 i，O(log min(m,n))
③ 用哨兵 ±(1<<30) 消灭 4 种越界；判据用严格 >；偶数取平均时先转 long / 各除一半再相加
```

## 附：第 3 部分（020–027）收官小结

八章下来，二分这一族可以压成一张表：

| 章 | 二分的对象 | 单调性从哪来 | 复杂度 | 一句话记忆 |
| --- | --- | --- | --- | --- |
| 020 | 数组下标 | 数组升序 | `O(log n)` | 区间长度严格递减 = 不死循环 |
| 021 | 下标（两次） | 谓词 `>=` / `>` 一次跳变 | `2 log n` | `==` 不是单调谓词，`>=` 才是 |
| 022 | 下标 | 分段单调，至少一半有序 | `O(log n)` | 先判哪半有序，再判值域 |
| 023 | 位置 | 「是否跨过断点」0/1 | `O(log n)` | 与永远有代表性的右端比 |
| 024 | （非二分）| 行列双单调 ⇒ 阶梯 | `O(m+n)` | 从鞍点一角出发，一步扔一行/列 |
| 025 | 答案值 | `check(k)` 可行即永远可行 | `O(n log V)` | 最优化 → 判定 |
| 026 | 答案值 | 贪心段数单调 | `O(n log V)` | 「至多 k 段」⇔「恰好 k 段」 |
| 027 | 划分位置 | 两个反向单调谓词交叉 | `O(log min(m,n))` | 各切一刀，`j = half - i` 降维 |

**三套模板的最终形态（全批通用）**：

```
A 闭区间 [lo,hi]   ：while lo <= hi；命中即 return；两支全 ±1        —— 找具体值 / 找划分（020 / 022 / 027）
B 左闭右开 [lo,hi) ：while lo <  hi；hi = mid / lo = mid+1；返回 lo   —— 找分界点 / lowerBound（021 / 024）
C 二分答案 [lo,hi] ：while lo <  hi；check(mid) ? hi = mid : lo = mid+1 —— 最小化可行值（023 / 025 / 026）
铁律：mid 下取整 ⇒ 禁写 lo = mid（要写就得上取整）；hi = mid 时循环条件必须 lo < hi
```
