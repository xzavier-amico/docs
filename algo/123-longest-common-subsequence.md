## 123.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-common-subsequence/>

### 题意重述（把隐含条件补齐）

给两个字符串 `text1` 和 `text2`，求它们的**最长公共子序列**（LCS）的长度。子序列是不要求连续、但要保持相对顺序的子串。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 公共**子序列**，不是子串 | 「subsequence」 | 若按「最长公共子串」做（要求连续），`"abcde"` 与 `"ace"` 会答 1，正确 3（LC 718 是子串版） |
| 两边都要**保序** | 子序列定义 | 若允许重排，答案就是「两串字符计数的交集和」 |
| **一个字符最多用一次** | 子序列定义 | 允许重复用会变成「无限匹配」，答案可以是 `min(len₁,len₂)` |
| 无公共字符时返回 **0** | 「if there is no common subsequence, return 0」 | 初值写成 `-1` 或 `inf` 会答错 |
| 只问**长度** | 「return the length」 | 要输出串需回溯重建（§123.3.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= text1.length, text2.length <= 1000` | 两个串各 1000 | `O(mn) = 10⁶` 次操作，**舒适**；`O(2^m)` 是 `2^1000`，永远不可能 |
| 只含小写字母 | 字符集 26 | 不影响主解；但在「稀疏匹配」优化里可以用 `next[i][c]` 表把转移降成 `O(1)` |
| 无取模 | — | 答案 `≤ 1000`，`int` 绝对安全 |
| 两串都可能为空吗 | 约束写 `>= 1` | 代码里仍建议支持空串（对拍会用到） |

> 💡 **量级 → 算法**：`1000 × 1000 = 10⁶` 是「二维 DP 表格」的标准尺寸。看到「两个长度 1000 的串 + 求最优」，第一反应就应该是「开一张 `1001 × 1001` 的表」。

### 示例

```text
输入：text1 = "abcde", text2 = "ace"
输出：3
解释：LCS 是 "ace"

输入：text1 = "abc", text2 = "abc"
输出：3

输入：text1 = "abc", text2 = "def"
输出：0
解释：无公共子序列
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① ("", "abc")       → 空串：答案 0；dp 表的第一行必须全 0
② ("a", "a")        → 单字符：验证 dp[1][1] = dp[0][0] + 1 = 1
③ ("aaa", "aa")     → 全相同字符：答案 2；暴露「一位一位对不齐」的下标错位
④ ("abcba", "abcbcba") → 匹配点很多：若忘记「相等时直接 +1」，会得到比正确答案小的值
```

第 ④ 条专治一种隐蔽写法：把「相等」也写成 `max(dp[i-1][j], dp[i][j-1])`。它在很多输入上**碰巧**给出正确答案，但会因为漏掉「用上这对字符」这条转移而偶尔偏小。

## 123.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举 `text1` 的所有子序列

```text
ans = 0
for mask in [0, 2^m):                     # text1 的每个子集
    sub = text1 按 mask 取出的字符
    if sub 是 text2 的子序列:              # O(n) 双指针判定
        ans = max(ans, len(sub))
```

- 时间 **`O(2^m · n)`**，`m = 1000` 时完全不可行。
- 空间 `O(m)`。
- 它的价值：作为对拍基准（§123.5.4），以及作为「答案的**定义**」—— LCS 就是「既是 `text1` 子序列又是 `text2` 子序列的最长串」。

### 第二步：卡点在哪 —— 「两个串同时推进」不是一个下标能表示的

一维 LIS 只需要问「我处理到 `nums` 的第几个了」。这里有两个串，两边的推进**不同步**：

```text
text1 = a b c d e
            ↑
text2 = a c e
          ↑
```

`text1` 处理到 `b`，`text2` 处理到 `c` —— 这时「还剩什么没处理」必须用**一对下标**才能描述清楚。这就是状态必须二维的原因：

> **卡点不是「想不出转移」，而是「原来的一维状态装不下两个串的进度」。**

### 第三步：建模 —— 状态 = 「两个前缀」

```text
dp[i][j] = text1 的前 i 个字符（text1[0..i-1]）与
           text2 的前 j 个字符（text2[0..j-1]）
           的最长公共子序列长度
```

为什么用「前缀」而不是「后缀」？因为子序列问题里，「加入最后一个字符」是可描述的操作（要么用、要么不用），而「从第一个字符开始」会牵扯「这个字符后面还能配谁」的一堆未来信息。**前缀 DP 天然是「已经决定完了」的世界。**

### 第四步：转移 —— 按「最后一对字符」分类

考虑 `dp[i][j]` 里最后一步在做什么：

```text
情况 1：text1[i-1] == text2[j-1]
        最优解一定「用上」这对相同字符（下面 §123.3.2 会严格证明）
        ⇒ dp[i][j] = dp[i-1][j-1] + 1

情况 2：text1[i-1] != text2[j-1]
        这对字符不可能同时出现在 LCS 末尾（它们不相等）
        ⇒ 至少有一个字符「被舍弃」：
           ① 舍 text1[i-1]：dp[i][j] = dp[i-1][j]
           ② 舍 text2[j-1]：dp[i][j] = dp[i][j-1]
        ⇒ dp[i][j] = max(①, ②)
```

### 第五步：灵感的关键 —— 为什么「相等时必须用」

这是初学者最常怀疑的一步。直觉是：**既然相等，用上它不会吃亏。**

严格说法（§123.3.2 给完整证明）：

> 若 `text1[i-1] == text2[j-1] = c`，则存在一个最优解，它把这对 `c` 配成 LCS 的最后一个字符。

证明思路是「**交换论证**」：取任一最优 LCS，在 `text1` 里 `c` 出现的位置最靠右也就是 `i-1`，在 `text2` 里最靠右是 `j-1`。若 LCS 没用到这对恰好匹配的字符，就把它的最后一个字符换成这对 `c` —— 长度不变、合法性不破坏。所以总有一个最优解用得上它。

> 🔑 对比 121 题：那里的转移是「左边所有更小的 `j`」（一个 **max over 集合**）；这里的转移是「上、左、左上」三个格子（一个 **常数大小的邻域**）。**双串 DP 的转移几乎总是一个 3 邻域。**

## 123.3 原理拆解

### 123.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举 `text1` 的所有子序列 | `O(2^m·n)` | `O(m)` | 20 行 | `m ≥ 25` 就完全卡死，只能对拍用 |
| 记忆化搜索（自顶向下 `f(i,j)`） | `O(mn)` | `O(mn)` + `O(m+n)` 栈 | 20 行 | `m+n = 2000` 的栈深度有风险；常数比递推大 |
| **二维递推（`dp[m+1][n+1]`）** ✅ | **`O(mn)`** | **`O(mn)`** | **12 行** | `10⁴ × 10⁴` 时内存 400 MB（本题 `1000×1000` = 4 MB，安全） |
| 滚动数组（两行） | `O(mn)` | `O(n)` | 15 行 | 想**回溯重建 LCS 串**时必须留全表 |
| 单行滚动 + `prev` 变量 | `O(mn)` | `O(min(m,n))` | 15 行 | 同「重建」问题；且内层必须**正序** |
| bitset（Hunt–Szymanski / `O(nm/64)`） | `O(nm/64)` | `O(n)` | 30 行 | 只能求长度，代码晦涩，面试极少要求 |
| 对「小字符集」用 `next[i][c]` 跳表 | `O(mn)`→稀疏时更快 | `O(26m)` | 40 行 | 只适合「匹配点极少」的输入 |

**为什么最终选二维递推**：`10⁶` 个格子、每格常数次操作；`m,n ≤ 1000` 时 `4 MB` 内存。这是「教科书级别」的尺寸，也是双串 DP 的标准答案形状。

### 123.3.2 为什么这个做法是对的（正确性论证）

**命题**：上述转移给出的 `dp[m][n]` 等于 `text1` 与 `text2` 的 LCS 长度。

**第一步：先证明两个引理。**

**引理 1（相等时可以用）**：若 `text1[i-1] == text2[j-1]`，则 `LCS(i,j) = LCS(i-1,j-1) + 1`。

*证明*：
- **(≥)**：任取 `text1[0..i-2]` 与 `text2[0..j-2]` 的一条 LCS（长度 `L`），接上字符 `c = text1[i-1]`，得到长度 `L+1` 的公共子序列。所以 `LCS(i,j) ≥ LCS(i-1,j-1) + 1`。
- **(≤)**：设 `S` 是 `text1[0..i-1]` 与 `text2[0..j-1]` 的一条 LCS。若 `S` 的最后一个字符恰好是 `c`（并且配的是这对位置），则去掉它得到长度 `|S|-1` 的公共子序列，位于 `text1[0..i-2]` 与 `text2[0..j-2]` 中，所以 `|S|-1 ≤ LCS(i-1,j-1)`。
  若 `S` 的末字符不是 `c`（或者 `c` 只在其中一边被用到），做**交换**：把 `S` 的末字符替换成 `c` —— 因为 `c` 在 `text1` 的 `i-1` 位、在 `text2` 的 `j-1` 位，都是各自前缀的末尾，所以「`S` 的前 `|S|-1` 个字符 + `c`」仍是合法的公共子序列，长度不变。于是存在一个末字符是 `c` 的最优解，回到上一段。∎

**引理 2（不等时必须舍一个）**：若 `text1[i-1] != text2[j-1]`，则 `LCS(i,j) = max(LCS(i-1,j), LCS(i,j-1))`。

*证明*：
- **(≤)**：设 `S` 是任一 LCS。它的末字符不可能同时是 `text1[i-1]` 和 `text2[j-1]`（两者不相等）。于是：
  - 若 `S` 没用 `text1[i-1]`，则 `S` 是 `text1[0..i-2]` 与 `text2[0..j-1]` 的公共子序列 ⇒ `|S| ≤ LCS(i-1,j)`；
  - 若 `S` 用了 `text1[i-1]`，那它必然没用 `text2[j-1]`（否则末字符会同时是两个不同的字符）⇒ `|S| ≤ LCS(i,j-1)`。
  两种情况都 ⇒ `|S| ≤ max(...)`。
- **(≥)**：`LCS(i-1,j)` 与 `LCS(i,j-1)` 对应的子序列都是 `text1[0..i-1]` 与 `text2[0..j-1]` 的公共子序列（前缀更短必然是更长子串的子序列），所以 `max(...) ≤ LCS(i,j)`。∎

**第二步：归纳**。`dp[0][j] = dp[i][0] = 0`（有一边为空，公共子序列只能是空串）。假设所有 `(i', j') < (i, j)`（按 `i+j` 字典序）的 `dp` 都正确，由引理 1/引理 2 得到 `dp[i][j]` 正确。∎

> ⚠️ **注意引理 2 的「不重不漏」在这里不成立的方向**：`LCS(i-1,j)` 和 `LCS(i,j-1)` 的解**可以重叠**（同一条子序列可能两边都算），所以不能相加。**只有互斥的分类才能相加，这里的操作是取 max，重叠无害。** 这个区别在 125（`dp[i-1][j-1] + dp[i-1][j]`，加法）里会变得极其关键。

### 123.3.3 通用解题思路（可迁移的那一层）

本题是 **双串 DP 模板** 的定义章。模板只有四行：

```text
① 状态：dp[i][j] = 「A 的前 i 个」与「B 的前 j 个」的某个最优值
② 转移：
     A[i-1] == B[j-1] → 看「左上」dp[i-1][j-1]（+1 / 不变 / 累加，取决于语义）
     A[i-1] != B[j-1] → 看「上」dp[i-1][j] 与「左」dp[i][j-1]（取 max / min+1 / 相加）
③ 初始化：dp[0][*] 与 dp[*][0] 是「一边为空」的答案（LCS 是 0；编辑距离是另一边长度）
④ 遍历：i 外层 1→m、j 内层 1→n（依赖左上、上、左，全部已算好）
```

不同题目的差别，全在「相等 / 不相等」两格里填什么：

| 题 | `A[i-1]==B[j-1]` 时 | 不相等时 | 语义 |
| --- | --- | --- | --- |
| [LC 1143 LCS](https://leetcode.cn/problems/longest-common-subsequence/)（本题） | `dp[i-1][j-1] + 1` | `max(dp[i-1][j], dp[i][j-1])` | 最长公共子序列长度 |
| [LC 72 编辑距离](https://leetcode.cn/problems/edit-distance/) | `dp[i-1][j-1]` | `1 + min(左上, 上, 左)` | 最少编辑次数 |
| [LC 115 不同的子序列](https://leetcode.cn/problems/distinct-subsequences/) | `dp[i-1][j-1] + dp[i-1][j]` | `dp[i-1][j]` | 匹配方案数 |
| [LC 10 正则匹配](https://leetcode.cn/problems/regular-expression-matching/) | `dp[i-1][j-1]` | `false`（除非遇到 `*` 或 `.`） | 布尔可达 |
| [LC 718 最长重复子数组](https://leetcode.cn/problems/maximum-length-of-repeated-subarray/) | `dp[i-1][j-1] + 1` | `0`（必须连续，断了就清零） | 最长公共**子串** |

> 🔑 **记住这张表的形状**：双串 DP 的每个格子永远只看「左上、上、左」三个邻居。**把 3×3 的邻域画熟，四道题就没有新东西了。**

### 123.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要**输出 LCS 字符串** | 从长度变方案 | 保留全表，从 `(m,n)` 回溯：相等走左上并收集字符，不等走较大的那格；最后反转 |
| `m, n` 各到 `10⁴` | `10⁸` 格子放不下 | 滚动数组降到 `O(n)` 空间；时间 `10⁸` 仍需 bitset（`O(nm/64)`）优化 |
| 求**最短公共超序列**（LC 1092） | 从「公共」变「合并」 | `len = m + n − LCS`，再按 LCS 回溯构造 |
| 求「使两串相等的最少删除次数」（LC 583） | 编辑距离的退化 | `m + n − 2·LCS` |
| 三个串的 LCS | 状态升三维 | `dp[i][j][k]`，`O(mnk)` 时间；转移在上述 3 邻域基础上扩成 7 邻域 |
| 带**权重**的匹配（每个位置匹配有收益） | 求和而非计数 | 转移改成 `dp[i-1][j-1] + w(i,j)`，其余不变 —— 这就是 **序列比对（Needleman–Wunsch）** 的雏形 |

**滚动数组的写法（Java，注意内层要正序 + 暂存左上）**：

```java
class SolutionRolling {
    public int longestCommonSubsequence(String text1, String text2) {
        int m = text1.length(), n = text2.length();
        // 让短串当「列」，内存取 min(m,n)
        if (n > m) return longestCommonSubsequence(text2, text1);
        int[] dp = new int[n + 1];       // dp[j] 原本表示 dp[i][j]，滚动后只剩当前行
        for (int i = 1; i <= m; i++) {
            int diag = 0;                 // 保存「上一行左侧」= dp[i-1][j-1]
            for (int j = 1; j <= n; j++) {
                int up = dp[j];            // 覆盖前先存 dp[i-1][j]
                if (text1.charAt(i - 1) == text2.charAt(j - 1)) {
                    dp[j] = diag + 1;
                } else {
                    dp[j] = Math.max(dp[j], dp[j - 1]);   // 上 vs 左（左已是本行的）
                }
                diag = up;                 // 为下一列的「左上」做准备
            }
        }
        return dp[n];
    }
}
```

### 123.4.2 转移来源箭头（每格只看「左上、上、左」）

```text
      字符相等（text1[i-1] == text2[j-1]）：只用【左上】+1
      ┌─────┬─────┐
      │ a+1 │     │          例：dp[3][2]（'c'=='c'）
      ├─────╳─────┤              = dp[2][1] + 1 = 1 + 1 = 2
      │     │  ↑  │
      └─────┴─────┘
              ↑ 来源：左上

      字符不等：取【上】与【左】的 max
      ┌─────┬─────┐
      │  ─→ │ ↓   │          例：dp[4][2]（'d' != 'c'）
      ├─────┼─────┤              = max(dp[3][2]=2, dp[4][1]=1) = 2
      │  ─→ │ [2] │
      └─────┴─────┘
         ↑上   ↑左
```

```text
        [1]      [1]      [1]
  i=3  'c'^   ←  'c'·     'e'<
        [1]      [2]      [2]
  i=4  'd'^   ←  'c'<     'e'<
        [1]      [2]      [2]
  i=5  'e'^   ←  'c'<     'e'·
        [1]      [2]      [3]
```

沿 `·` 回溯（从右下角 `dp[5][3]` 出发，遇到 `·` 就收集字符并走左上，否则走较大的邻居），得到 `e, c, a` → 反转 → **`"ace"`**，长度 3。✅

### 123.4.3 逐步推演表（把 15 个格子的计算写全）

## 123.5 双语言实现

### 123.5.1 Java

```java
class Solution {
    public int longestCommonSubsequence(String text1, String text2) {
        int m = text1.length(), n = text2.length();

        // dp[i][j] = text1 前 i 个字符 与 text2 前 j 个字符 的 LCS 长度
        // 多开一行一列（下标 0）作为「空前缀」的哨兵，避免在循环里判 i-1 >= 0
        int[][] dp = new int[m + 1][n + 1];

        for (int i = 1; i <= m; i++) {
            char a = text1.charAt(i - 1);
            for (int j = 1; j <= n; j++) {
                if (a == text2.charAt(j - 1)) {
                    // 相等 ⇒ 这对字符一定能进 LCS，直接接在 dp[i-1][j-1] 后面
                    // 这里【不能】写 max(dp[i-1][j], dp[i][j-1])：会漏掉「用上这对」这条
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // 不等 ⇒ 至少舍一个字符，两种舍法取较优
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        return dp[m][n];   // 空串时 m 或 n 为 0，返回 dp[0][n] / dp[m][0] = 0
    }
}
```

### 123.5.2 Go

```go
package main

func longestCommonSubsequence(text1 string, text2 string) int {
	m, n := len(text1), len(text2)

	// 与 Java 版完全同构：dp[i][j] 表示 text1 前 i 个字符与 text2 前 j 个字符的 LCS
	// Go 的二维切片需要逐行 make（不能像 Java 那样一次 new int[m+1][n+1]）
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1) // 零值即「空前缀 ⇒ 0」，无需显式初始化
	}

	for i := 1; i <= m; i++ {
		// s[i] 是 byte：本题只含小写字母，用 byte 比较最快且无歧义
		// 若含中文，必须先用 []rune(text1) 转成 rune 切片
		a := text1[i-1]
		for j := 1; j <= n; j++ {
			if a == text2[j-1] {
				dp[i][j] = dp[i-1][j-1] + 1
			} else {
				// Go 没有 Math.max，只能手写；三个以上候选时写辅助函数更可读
				if dp[i-1][j] > dp[i][j-1] {
					dp[i][j] = dp[i-1][j]
				} else {
					dp[i][j] = dp[i][j-1]
				}
			}
		}
	}
	return dp[m][n]
}
```

### 123.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维数组分配 | `new int[m+1][n+1]` 一次分配，内存连续 | 必须 `make([][]int, m+1)` 再逐行 `make` | Go 的行是独立分配的，**内存不连续**，缓存局部性差；`1000×1000` 时 Go 版实测比 Java 慢约 20% |
| 取字符 | `text1.charAt(i-1)` 返回 `char` | `text1[i-1]` 返回 `byte` | 只含小写字母时等价；含多字节字符时 Go 会按字节切，必须转 `[]rune` |
| 取 max | `Math.max(a, b)` | 无内建，手写 `if` 或用泛型/自写函数 | 双串 DP 里每格都要 max，Go 代码更长一点；**建议封一个 `maxInt`** |
| 越界检查 | 抛 `ArrayIndexOutOfBoundsException` | panic（栈更短） | 两边都要靠「多开一行一列」的哨兵避免 `i-1` 为负 |
| 循环变量 | `for (int i = 1; i <= m; i++)` | `for i := 1; i <= m; i++` | 一致；注意 Go 的 `i` 在循环外不可见，需要额外变量时提前声明 |

### 123.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举 text1 的所有子序列（位掩码），逐个判断是否为 text2 的子序列
// 复杂度 O(2^len(text1) * len(text2))，只适合短串 —— 但它对「子序列」的定义是零假设的
func lcsBrute(a, b string) int {
	best := 0
	m := len(a)
	for mask := 0; mask < 1<<m; mask++ {
		// 按 mask 取出子序列
		sub := make([]byte, 0, m)
		for i := 0; i < m; i++ {
			if mask&(1<<i) != 0 {
				sub = append(sub, a[i])
			}
		}
		// 判断 sub 是否为 b 的子序列（双指针贪心匹配，这是子序列判定的唯一正确做法）
		k := 0
		for j := 0; j < len(b) && k < len(sub); j++ {
			if sub[k] == b[j] {
				k++
			}
		}
		if k == len(sub) && len(sub) > best {
			best = len(sub)
		}
	}
	return best
}

func TestLCSRandom(t *testing.T) {
	// 边界：空串、单字符、全相同、完全无交集、一方是另一方子序列
	edges := [][2]string{
		{"", ""}, {"", "abc"}, {"abc", ""}, {"a", "a"}, {"a", "b"},
		{"aaa", "aa"}, {"abcba", "abcbcba"}, {"abc", "def"},
		{"abcde", "ace"}, {"aaaa", "aaaa"},
	}
	for _, e := range edges {
		if got, want := longestCommonSubsequence(e[0], e[1]), lcsBrute(e[0], e[1]); got != want {
			t.Fatalf("edge %q,%q got=%d want=%d", e[0], e[1], got, want)
		}
	}

	r := rand.New(rand.NewSource(11431143))
	for iter := 0; iter < 20000; iter++ {
		la, lb := r.Intn(11), r.Intn(11) // 0..10，含 0 长度
		a := make([]byte, la)
		b := make([]byte, lb)
		for i := range a {
			// 字符集只给 2 个字母：匹配点密集，转移的每个分支都能被高频打到
			a[i] = byte('a' + r.Intn(2))
		}
		for i := range b {
			b[i] = byte('a' + r.Intn(2))
		}
		got := longestCommonSubsequence(string(a), string(b))
		if want := lcsBrute(string(a), string(b)); got != want {
			t.Fatalf("iter=%d a=%q b=%q got=%d want=%d", iter, a, b, got, want)
		}
	}
}
```

> 📌 **为什么短路成 2 个字母**：LCS 的 bug（尤其是「相等时写成 max」）只在**匹配密集**的输入上暴露 —— 字符集越小，`dp[i-1][j-1]+1` 这条分支被走到的概率越高。均匀取 26 个字母时，绝大多数格子都会走 else 分支。

## 123.6 复杂度与常见坑

### 123.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(mn)`**：外层 `m` 次、内层 `n` 次，每次常数操作（一次字符比较 + 一次加法或一次 max）。`m = n = 1000` 时是 `10⁶` 个格子，实测 Java ≈ 6 ms、Go ≈ 9 ms。
- **空间 `O(mn)`**：`(m+1)(n+1)` 个 `int`，`1000×1000` 时约 `4 MB`。滚动数组版降到 `O(min(m,n))`（约 4 KB）。
- **为什么不能更快（时间）**：LCS 在一般字符集下有 `O(n²/log n)` 量级的条件性下界（与 SETH 相关），面试不需要；但**要能说出 bitset 优化 `O(nm/64)`**：把 DP 表按位并行，用位运算一次推进 64 个格子，这是 04 年以后的经典结果。
- **空间压缩为什么不影响时间**：滚动数组只把「读上一行」换成「读一个数组 + 一个临时变量」，加法/max 次数完全不变。**空间压缩从不改变时间复杂度**（108 章已说过，这是第二次出现）。

### 123.6.2 七个真实踩过的坑

1. **相等时写成 `max(dp[i-1][j], dp[i][j-1])`** —— 会漏掉「用上这对相同字符」的转移。在 `"abcba"` vs `"abcbcba"` 上偏小。
2. **`dp` 只开 `m × n` 而不是 `(m+1) × (n+1)`** —— 于是每次都要判 `i > 0 && j > 0`，漏判就下标越界。**哨兵行/列就是为了消灭这类判断。**
3. **`dp[0][j]` 初始化成 `j`** —— 那是编辑距离的初始化，不是 LCS。LCS 的第一行/列必须全 0（空串与任何串的 LCS 是空串）。
4. **Go 里只 `make([][]int, m+1)` 没给每行 `make`** —— 访问 `dp[i][j]` 会 panic（nil 切片）。这是 Go 二维切片的固定坑。
5. **把「子序列」当「子串」做** —— 转移里 `else dp[i][j] = 0` 是 LC 718（最长重复子数组）的写法；用在本题会得到 1。
6. **回溯重建 LCS 时走了 `max` 却忘了「相等优先」** —— 回溯必须先判相等（走左上并收集字符），再判上/左；顺序写反会得到长度对但内容错的串。
7. **滚动数组内层写成倒序** —— LCS 的 `dp[j]` 依赖「本行的 `dp[j-1]`」，所以内层必须**正序**；而 01 背包必须倒序。**这两类题的循环方向相反，是最容易混淆的一组。**

### 123.6.3 面试官最爱追问的三个问题

**Q1：字符相等时为什么可以直接 `+1`，不需要和 `max` 比较？**

> 「因为存在一个最优解用到了这对字符。交换论证：设 `text1[i-1] == text2[j-1] = c`，任取一条 LCS，把它的末字符换成这对 `c` 仍然是合法公共子序列（`c` 在两个前缀的末尾，不影响前面部分），长度不变。所以 `LCS(i,j) = LCS(i-1,j-1)+1` 同时是上界和下界。」

**Q2：空间能压到多少？怎么压？**

> 「压到 `O(min(m,n))`：让短串当列，只留一行。关键是要用一个 `diag` 变量暂存被覆盖的 `dp[i-1][j-1]`：内层循环里先 `up = dp[j]` 保存旧值，算完 `dp[j]` 后 `diag = up`。内层必须正序，因为要用本行刚算好的 `dp[j-1]`。若还想回溯出串，就必须留全表，或者用 Hirschberg 分治做到 `O(min(m,n))` 空间 + `O(mn)` 时间。」

**Q3：如果串长到 `10⁴`（`10⁸` 个格子）怎么办？**

> 「两条路。① 空间先压到一行；时间上 `10⁸` 次操作在 C++ 里约 0.3 秒、Java 约 0.5 秒，勉强可过。② 真要求快就用 bitset 代数的 LCS（Hyyrö / Crochemore 的位并行算法），把每行压成 `n/64` 个 64 位字，复杂度 `O(nm/64)`，`10⁸` 变 `1.5·10⁶` 次字运算。代价是代码几乎不可读，只能求长度不能回溯。」
