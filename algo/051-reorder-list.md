## 051.1 题目

**原题链接**：<https://leetcode.cn/problems/reorder-list/>

### 题意重述（把隐含条件补齐）

给你单链表的头结点 `head`，请把它重排成：`L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …`，即**首、尾、次首、次尾**交替。

注意：**不能只改结点里的值**，必须**实际交换结点**（题目原话是「不能只是单纯的改变节点内部的值，而是需要实际的进行节点交换」）。函数**返回 `void`**，要**原地**改这条链。

五个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **必须动指针，不能只改值** | 题目 note | 抄值重排能 AC，但面试会被打回；且结点带卫星数据时结果错 |
| **返回 `void`，原地修改** | 函数签名 | 不能返回一条新链；必须把原链改造成目标形态 |
| **交替顺序固定：先首后尾** | `L0 → Ln → L1 → Ln-1` | 反过来（先尾）是另一道题 |
| **奇数个结点时中间那个放最后** | `[1,2,3,4,5] → [1,5,2,4,3]` | 3 是最中间，它单独收尾，不是被跳过 |
| **`1 <= 结点数 <= 5·10⁴`** | 数据范围 | 规模足够大，**O(n) 空间能过但不算优**；递归/数组都会被追问 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= 结点数 <= 5·10⁴` | 5 万 | O(n) 与 O(n log n) 都能过；**但要求 O(1) 空间**，这正是考点 |
| `1 <= Node.val <= 1000` | 有重复值 | 不能靠值定位「第几个」 |
| 空间 O(1)（进阶） | 经典追问 | 三合一原地解法（找中点 + 反转 + 合并） |
| `void` 返回值 | 签名 | 不能靠「返回新链」偷懒 |

> 💡 **量级 → 算法**：`5·10⁴` 是一个**足够大到不让你随便用 O(n) 空间**、又**足够小到常数优化无关紧要**的规模。所以这题的设计意图非常明确：**逼你做到「原地 + O(n) 时间 + O(1) 空间」**。而做到这一点的唯一途径，就是把三个 O(1) 空间的子技巧串起来。

### 示例

```text
输入：head = [1,2,3,4]
输出：      [1,4,2,3]
解释：L0=1, L3=4, L1=2, L2=3 → 1,4,2,3

输入：head = [1,2,3,4,5]
输出：      [1,5,2,4,3]
解释：1, 5, 2, 4, 3（中间的 3 最后落单）

输入：head = [1]
输出：      [1]
```

### 我自造的七个反例（写完必须逐个跑）

```text
① []                  → 空链表（本题 n ≥ 1，但工具函数要能处理）
② [1]                 → 单结点：一步都不该动
③ [1,2]               → 两结点：1,2 已经是目标形态
④ [1,2,3]             → 奇数 3 个：中点切分后前半 [1,2]、后半 [3]
⑤ [1,2,3,4]           → 偶数 4 个：前半 [1,2]、后半 [3,4]（反转后 [4,3]）
⑥ [1,2,3,4,5,6]       → 偶数 6 个：验证「后半段长度等于前半段」
⑦ [7,7,7,7,7]         → 全相等值：如果实现靠值定位会完全失效
```

第 ④ 和第 ⑤ 条决定了「中点怎么切」：**前半段长度必须 ≥ 后半段**，否则合并时 `q` 会先耗尽而 `p` 还剩两个结点，尾部就接不上。这个细节是本章第一个坑。

## 051.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（抄进数组，双指针重建）

```text
vals = []
for p in list: vals.append(p)
i = 0; j = len(vals)-1
p = head
while i <= j:
    if p is not null: p.val = vals[i]; p = p.next   // 首
    i++
    if p is not null and i <= j: p.val = vals[j]; p = p.next  // 尾
    j--
```

- 时间 O(n)，空间 **O(n)**。
- **它能 AC**，但题目明确写了「不能只是单纯的改变节点内部的值，而是需要实际的进行节点交换」。所以这条路**在面试里是零分**，判题机能过只是因为 LeetCode 无法检查（它只比对最终序列）。

### 第二步：卡点在哪

把目标序列拆开看：`L0, Ln, L1, Ln-1, L2, Ln-2, …`

它其实是**两条链交替**的结果：

```
前半段（正序）：  L0 → L1 → L2 → …
后半段（倒序）：  Ln → Ln-1 → Ln-2 → …
交替拼接：        L0, Ln, L1, Ln-1, L2, Ln-2, …
```

所以卡点只有两个：

| 卡点 | 内容 | 突破 |
| --- | --- | --- |
| 卡点 1 | 「后半段」在链表里是**倒着**的，无法从尾往前走 | 把后半段**反转**，倒序变正序 |
| 卡点 2 | 怎么把一条链切成「前半 / 后半」两段 | **快慢指针找中点**，然后断开 |

这两个卡点各对应一个已经解决的问题（044 反转、049 找中点）。所以本题的「灵感」不是发明新东西，而是**认清它是一道复合题**。

### 第三步：灵感的来源 —— 三步分解

```
① 找中点：快慢指针，slow 停在「前半段最后一个」
         ↓
② 反转后半：复用 044 的四句模板
         ↓
③ 交替合并：把后半段的结点逐个插进前半段的缝隙
```

用一句话描述合并的动作：**`p` 在前半段走，`q` 在（反转后的）后半段走，把 `q` 插到 `p` 后面，然后两者各前进一步。**

```
p: 1 → 2 → 3
q: 6 → 5 → 4

第 1 次：把 6 插到 1 后面 → 1 → 6 → 2 → 3
第 2 次：把 5 插到 2 后面 → 1 → 6 → 2 → 5 → 3
第 3 次：把 4 插到 3 后面 → 1 → 6 → 2 → 5 → 3 → 4
```

注意这是**「插入」而不是「挑选」**——它和 047 的有序归并不同：047 每次只挂一个结点到 `tail` 后面（尾部追加），而这里要**把 `q` 塞进 `p` 和 `p.next` 中间**（中间插入）。这个区别决定了合并代码的形状。

### 另一条路：为什么不能「递归」

有人会想到递归：先递归到中点，再在回溯时交替拼接。它能做，但需要额外传递「后半段的头」和「已拼接到哪」，代码比三步法长一倍，且空间变成 O(n) 栈。**本题没有必须递归的理由，直接三步法。**

另一条常见的偷懒路线是**双端队列**（`ArrayDeque` 两头取）：把所有结点入队，然后左右交替弹出重连。时间 O(n)、空间 O(n)，代码很短，但空间不达标。可以作为「面试里先说思路、再优化」的过渡答案。

## 051.3 原理拆解

### 051.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 抄值到数组，双指针写回 | O(n) | O(n) | 12 行 | **题目明令必须动指针**；面试零分 |
| 双端队列两头取 | O(n) | O(n) | 15 行 | 空间要求 O(1) |
| **找中点 + 反转 + 合并** ✅ | **O(n)** | **O(1)** | **30 行** | 几乎不会输；分三步，每步都要处理边界 |
| 递归（回溯时拼接） | O(n) | O(n) 栈 | 25 行 | 5·10⁴ 个结点时栈溢出 |
| 先整体反转，再交替摘取 | O(n) | O(1) | 35 行 | 需要额外的断链与还原逻辑，反而更绕 |

**为什么三步法最优**：O(n) 时间、O(1) 空间、每一步都能独立验证。**这是「复合题」的典型最优形态：把复杂度分摊到三个简单的 O(1) 子过程上。**

### 051.3.2 为什么这个做法是对的（正确性论证）

分三步论证，每步一个小命题。

#### 命题 1（找中点）：循环结束时 `slow` 是前半段的最后一个结点，且前半段长度 ≥ 后半段

快慢指针取 `slow = head, fast = head`，循环条件 `fast.next != null && fast.next.next != null`，每次 `slow` 走 1、`fast` 走 2。

- **快指针每次前进 2，所以它走过的结点数是 slow 的 2 倍。** 循环结束时 `fast` 满足「`fast.next == null` 或 `fast.next.next == null`」，即 `fast` 位于最后一个或倒数第二个结点。
- 设结点数 `n`。若 `n` 为奇数 `2k+1`：`fast` 最终停在最后一个结点（位置 `2k`），`slow` 走过 `k` 步，停在位置 `k` —— 正好是中间那个，前半段有 `k+1` 个结点（含中点），后半段有 `k` 个。
- 若 `n` 为偶数 `2k`：`fast` 最终停在倒数第二个结点（位置 `2k-1` 前的 `2k-2`）……用步数算更清楚：`slow` 走 `k-1` 步，停在位置 `k-1`，前半段 `k` 个结点，后半段 `k` 个。

两种情况下，**前半段长度都 ≥ 后半段长度**，且 `slow.next` 就是后半段的头。∎

> **为什么要「前半 ≥ 后半」**：合并时 `p` 走前半、`q` 走后半，循环条件是 `q != null`。若后半比前半长，最后 `q` 还剩结点没地方插；若前半 ≥ 后半，`q` 一定先耗尽，`p` 剩下的（最多 1 个）自然成为表尾。**这个不等关系是合并能安全终止的前提。**

#### 命题 2（反转）：调用 044 的模板后，`second` 是原后半段的反转，且长度不变

直接引用 044.3.2 的不变量证明：迭代三指针把每条边反向，头尾互换。∎

#### 命题 3（合并）：交替插入后，链的序列恰为 `L0, Ln, L1, Ln-1, …`，且无环、无丢结点

设前半段为 `p1 → p2 → … → pa`，反转后的后半段为 `q1 → q2 → … → qb`（`a ≥ b`，`a - b ∈ {0, 1}`）。注意 `q1 = Ln`、`q2 = Ln-1`、……

**循环不变量**（第 k 轮开始前）：

> 已构造出的链形如 `p1, q1, p2, q2, …, pk, qk` 再接 `p_{k+1} → … → pa`；`p` 指向 `p_{k+1}`，`q` 指向 `q_{k+1}`。

**保持**：记 `nextP = p.next`、`nextQ = q.next`（**先存后断**）。执行

```
p.next = q;        // pk 后面接 qk
q.next = nextP;    // qk 后面接 p(k+1)
p = nextP; q = nextQ;
```

得到 `…, pk, qk, p_{k+1}, …`，`p` 指向 `p_{k+1}`、`q` 指向 `q_{k+1}`。不变量保持。

**终止**：`q == null` 时所有 `q` 都已插入，链为 `p1, q1, …, pb, qb, p_{b+1}, …, pa`。因为 `a - b ∈ {0,1}`，所以要么没有剩余（`a = b`），要么只剩 `pa` 一个（`a = b+1`），而它已经是表尾（`p` 的 `next` 在最后一轮被设成 `nextP = null`）。序列正是 `L0, Ln, L1, Ln-1, …`。∎

**无环**：每轮最多改两条边（`p.next`、`q.next`），且改完后 `p` 段的所有结点都排在 `q` 段之前，`q.next` 指向的 `nextP` 一定在 `p` 段中更靠后的位置 —— 严格单调，不可能回指。∎

**不丢结点**：每个结点恰好被「挂上」一次；`nextP`、`nextQ` 在改写前已保存，所以两条链的剩余部分都不会失联。∎

> **三个命题合起来**，就是完整的正确性证明。**复合题的证明就应该这样拆**：不要试图一口气论证「重排正确」，而是分别证明「切得对」「反得对」「拼得对」。

### 051.3.3 通用解题思路（可迁移的那一层）

**链表章的统一语言：哑结点 + 指针三件套（prev/cur/next）+ 先存后断。** 051 是这套语言的「总复习」：它同时用到了哑结点思想（本题实际不需要 dummy，因为头不变）、三件套（反转用 `prev/cur/nxt`，合并用 `p/q/nextP/nextQ`）、以及先存后断（合并时先存 `nextP`、`nextQ`）。

它教的是另一层能力 —— **复合题分解（problem decomposition）**：

```
陌生题：把链重排成 L0, Ln, L1, Ln-1, ...
      ↓ 观察目标序列的结构
发现：= 前半段正序 与 后半段倒序 交替
      ↓ 拆成"已经会了"的子问题
① 怎么拿到前半段？      → 找中点（049 的快慢指针）
② 怎么把后半段变成正序？ → 反转（044 的四句模板）
③ 怎么交替拼接？        → 插入式合并（047 的变体）
      ↓ 每步都要处理"接缝"
接缝：找中点后必须断开；合并时先存后断；结束时 p 剩下的自然收尾
```

**判断一道题是不是复合题的信号**：

| 信号 | 例子 |
| --- | --- |
| 目标形态能用「两段/三段已知形态交替或拼接」描述 | 051（正序 + 倒序交替）、143 类变体 |
| 题目要求的操作需要「反向访问」但结构不支持 | 051（要从尾往前走）→ 反转 |
| 需要先知道「一半在哪」才能继续 | 051 → 找中点 |

属于同一模型的题：

| 题 | 拆成哪几步 |
| --- | --- |
| [LC 143 重排链表](https://leetcode.cn/problems/reorder-list/) | 找中点 + 反转 + 交替合并 |
| [LC 234 回文链表](https://leetcode.cn/problems/palindrome-linked-list/) | 找中点 + 反转 + 逐点比较（可选：再反回来） |
| [LC 86 分隔链表](https://leetcode.cn/problems/partition-list/) | 两条 dummy 链收集 + 拼接 |
| [LC 328 奇偶链表](https://leetcode.cn/problems/odd-even-linked-list/) | 两条链分别收集 + 拼接 |
| [LC 148 排序链表](https://leetcode.cn/problems/sort-list/) | 找中点 + 归并（052） |
| [LC 25 K 个一组翻转](https://leetcode.cn/problems/reverse-nodes-in-k-group/) | 探路 + 反转 + 接缝（046） |

> **一句话**：**链表章的后半部分，考的几乎都是「把前面的单点技巧组合起来」。** 051 是这道门槛的第一个明确信号。

### 051.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成 `Ln, L0, Ln-1, L1, …`（先尾后首） | 交替顺序反转 | 反转后从 `q` 起步合并；或把前半段反转 |
| 要求**成环**（首尾相接） | 多改一条边 | 最后让表尾指向 `head`；注意别让判题序列化死循环 |
| 每 **k** 个一段交替（不是 2 段） | 分组 | 先按 k 切段，再按「段首、段尾、段首次…」重排 |
| 不能改指针，只能改值 | 语义降级 | 数组重排 + 写回，O(n) 空间 |
| **双向链表** | 有 `prev` | 直接双端交替：一头一尾同时走，O(n) 一趟，无需反转 |
| 只要求「前半与后半交替」但**顺序不限** | 约束放宽 | 仍是三步法，只是合并不需要严格交替 |

## 051.4 图解推演

### 051.4.1 三步全景（`[1,2,3,4,5]`）

```text
原始：
   1 ──→ 2 ──→ 3 ──→ 4 ──→ 5 ──→ ∅

① 找中点：slow 走 1 步、fast 走 2 步，循环条件 fast.next && fast.next.next
   slow=1, fast=1
   slow=2, fast=3
   slow=3, fast=5     ← fast.next == ∅ → 停
        ↑
       slow（前半段最后一个）

   1 ──→ 2 ──→ 3 ┄┄→ 4 ──→ 5 ──→ ∅
               ↑
         slow.next 是后半段头；必须断开！

② 反转后半 [4,5] → [5,4]
   1 ──→ 2 ──→ 3 ──→ ∅        5 ──→ 4 ──→ ∅
                               ↑
                             second

③ 交替合并：把 second 的结点逐个插到前半段的缝里

   初始： p=1, q=5
   第 1 次：nextP=2, nextQ=4
            1.next = 5;  5.next = 2;  p=2, q=4
            1 ──→ 5 ──→ 2 ──→ 3 ──→ ∅

   第 2 次：nextP=3, nextQ=∅
            2.next = 4;  4.next = 3;  p=3, q=∅
            1 ──→ 5 ──→ 2 ──→ 4 ──→ 3 ──→ ∅

   第 3 次：q == ∅ → 循环结束，3 天然是表尾

结果：1 → 5 → 2 → 4 → 3 ✅
```

### 051.4.2 中点落点与切分（奇数 / 偶数各一张）

```text
n 为奇数（n = 5）：
   1 → 2 → 3 → 4 → 5
           ↑
          slow
   前半：1,2,3（3 个）      后半：4,5（2 个）      前半 = 后半 + 1

n 为偶数（n = 4）：
   1 → 2 → 3 → 4
       ↑
      slow
   前半：1,2（2 个）        后半：3,4（2 个）      前半 = 后半

n = 3：
   1 → 2 → 3
       ↑
      slow
   前半：1,2（2 个）        后半：3（1 个）        前半 = 后半 + 1

n = 2：
   1 → 2
   ↑
  slow
   前半：1（1 个）          后半：2（1 个）        前半 = 后半
```

**规律**：`前半 = ceil(n/2)`，`后半 = floor(n/2)`。所以循环条件 `fast.next != null && fast.next.next != null` 天然给出「前半不少于后半」。

### 051.4.3 合并阶段的指针状态表（`[1,2,3,4,5]`）

| 轮 | `p` | `q` | `nextP` | `nextQ` | 改的两条边 | 链（从头） |
| --- | --- | --- | --- | --- | --- | --- |
| 初始 | 1 | 5 | — | — | — | `1→2→3`, `5→4` |
| 1 | 1 | 5 | 2 | 4 | `1.next=5`，`5.next=2` | `1→5→2→3` |
| 2 | 2 | 4 | 3 | ∅ | `2.next=4`，`4.next=3` | `1→5→2→4→3` |
| 结束 | 3 | ∅ | — | — | — | `1→5→2→4→3` ✅ |

### 051.4.4 忘掉「断开」会怎样（成环的真相）

```text
不做 slow.next = null：

   1 ──→ 2 ──→ 3 ──→ 4 ──→ 5 ──→ ∅
               ↑       │
               └───────┘   ← 反转后半时，4.next 被改成 ∅，但……

反转 [4,5] 之前，若后半段仍是 3→4→5 的一部分：
   reverse(3.next = 4) 只看到 4→5，反成 5→4，而 3.next 仍指着 4
   合并时：1→5→2→4→3，然后 3.next 仍指向 4（因为 4 是它的原后继！）

   结果：1 → 5 → 2 → 4 → 3 ─┐
                        ↑    │
                        └────┘   💥 成环，判题机序列化死循环 → TLE / OOM
```

> **这是本章最容易踩、也最难查的坑**：小数据（n ≤ 3）时 3 恰好是表尾，`3.next` 本来就该指向某处，成环或不成都可能「看起来对」；`n = 5` 才会明显爆炸。**写完必须跑 n = 5 和 n = 6。**

## 051.5 双语言实现

### 051.5.1 Java

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}

class Solution {
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) {
            return; // 0 或 1 个结点，形态已符合要求
        }

        // ① 找中点：fast 每次走 2 步，slow 停在「前半段最后一个」
        ListNode slow = head;
        ListNode fast = head;
        while (fast.next != null && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }

        // ② 断开 + 反转后半段
        ListNode second = slow.next;
        slow.next = null; // 不断开的话，反转会把前半段也连进去，形成环
        second = reverse(second);

        // ③ 交替合并：把后半段结点逐个插进前半段的缝隙
        ListNode p = head;
        ListNode q = second;
        while (q != null) {           // q 一定先耗尽（前半 >= 后半）
            ListNode nextP = p.next;  // 先存：马上要改 p.next
            ListNode nextQ = q.next;  // 先存：马上要改 q.next
            p.next = q;               // p 后面接 q
            q.next = nextP;           // q 后面接 p 原来的后继
            p = nextP;
            q = nextQ;
        }
    }

    private ListNode reverse(ListNode head) {
        ListNode prev = null;
        ListNode cur = head;
        while (cur != null) {
            ListNode nxt = cur.next;
            cur.next = prev;
            prev = cur;
            cur = nxt;
        }
        return prev;
    }
}
```

**五处「为什么」**：

1. `while (fast.next != null && fast.next.next != null)`：这样 `slow` 停在**前半段最后一个**（而不是「中点之后」）。如果写成 `while (fast != null && fast.next != null)`，`slow` 会停在 `ceil(n/2)` 位置，前半段反而比后半段**短**，合并时 `q` 会剩下结点。
2. `slow.next = null` 不可省：见 051.4.4，不写就成环。
3. `while (q != null)` 而不是 `while (p != null && q != null)`：由「前半 ≥ 后半」，`q` 一定先空；用 `q != null` 足够且最简单。
4. `nextP`、`nextQ` 必须先存：`p.next = q` 会覆盖 `p` 的后继，`q.next = nextP` 会覆盖 `q` 的后继。这就是「先存后断」。
5. 函数是 `void`：不能返回新链，所以只能原地改；好处是不会有人误用返回值。

### 051.5.2 Go

```go
package main

type ListNode struct {
	Val  int
	Next *ListNode
}

// 三合一：找中点 → 反转后半 → 交替合并
func reorderList(head *ListNode) {
	if head == nil || head.Next == nil {
		return
	}

	// ① 找中点：slow 停在「前半段的最后一个」，前半段长度 >= 后半段
	slow, fast := head, head
	for fast.Next != nil && fast.Next.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
	}

	// ② 切开 + 反转后半段
	second := slow.Next
	slow.Next = nil // 必须断开，否则反转后会和前半段成环
	second = reverseList(second)

	// ③ 交替合并：把 second 的结点逐个插到前半段的缝隙里
	p, q := head, second
	for q != nil {
		nextP, nextQ := p.Next, q.Next // 先存后断
		p.Next = q
		q.Next = nextP
		p, q = nextP, nextQ
	}
}

// 复用 044 的迭代反转
func reverseList(head *ListNode) *ListNode {
	var prev *ListNode
	cur := head
	for cur != nil {
		nxt := cur.Next
		cur.Next = prev
		prev = cur
		cur = nxt
	}
	return prev
}
```

### 051.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 返回 `void` | `public void reorderList(...)` | `func reorderList(...)`（无返回值） | 一致：都要求原地改 |
| 多重赋值 | 只能分开写 `p = nextP; q = nextQ;` | 可写 `p, q = nextP, nextQ` | Go 更紧凑；**注意 `:=` 与 `=` 的区别**：这里 `p`、`q` 已存在，必须用 `=` |
| 辅助函数 | `private ListNode reverse(...)` 同类内 | 顶层 `func reverseList(...)` | Go 里若与别处同名会冲突（本题自建文件需注意） |
| 判空 | `head == null \|\| head.next == null` | `head == nil \|\| head.Next == nil` | 一致，**顺序不能反** |
| 字段命名 | `.val` / `.next` | `.Val` / `.Next` | 大写首字母 |
| 原地修改的可见性 | 改的是对象内部，调用方能看到 | 同理（指针） | 一致 |

### 051.5.4 对拍测试（Go，2 万次随机 + 八个边界）

```go
package main

import (
	"math/rand"
	"testing"
)

func build(a []int) *ListNode {
	dummy := &ListNode{}
	t := dummy
	for _, v := range a {
		t.Next = &ListNode{Val: v}
		t = t.Next
	}
	return dummy.Next
}

func dump(h *ListNode) []int {
	out := []int{}
	steps := 0
	for p := h; p != nil; p = p.Next {
		out = append(out, p.Val)
		steps++
		if steps > 100000 {
			panic("疑似成环")
		}
	}
	return out
}

// 暴力参考：切片上「首尾交替」重排
func bruteReorder(a []int) []int {
	n := len(a)
	out := make([]int, 0, n)
	i, j := 0, n-1
	for i <= j {
		out = append(out, a[i])
		i++
		if i <= j {
			out = append(out, a[j])
			j--
		}
	}
	return out
}

func TestReorderListRandom(t *testing.T) {
	r := rand.New(rand.NewSource(51))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(13) // 含 0 和 1
		a := make([]int, n)
		for i := range a {
			a[i] = r.Intn(5) // 大量重复值
		}
		h := build(a)
		reorderList(h)

		want := bruteReorder(a)
		got := dump(h)
		if len(got) != len(want) {
			t.Fatalf("iter=%d a=%v got=%v want=%v", iter, a, got, want)
		}
		for i := range got {
			if got[i] != want[i] {
				t.Fatalf("iter=%d a=%v got=%v want=%v", iter, a, got, want)
			}
		}
	}
	// 八个边界（含奇偶两种长度）
	cases := []struct{ a, want []int }{
		{nil, nil},
		{[]int{1}, []int{1}},
		{[]int{1, 2}, []int{1, 2}},
		{[]int{1, 2, 3}, []int{1, 3, 2}},
		{[]int{1, 2, 3, 4}, []int{1, 4, 2, 3}},
		{[]int{1, 2, 3, 4, 5}, []int{1, 5, 2, 4, 3}},
		{[]int{1, 2, 3, 4, 5, 6}, []int{1, 6, 2, 5, 3, 4}},
		{[]int{7, 7, 7, 7, 7}, []int{7, 7, 7, 7, 7}},
	}
	for i, c := range cases {
		h := build(c.a)
		reorderList(h)
		got := dump(h)
		if len(got) != len(c.want) {
			t.Fatalf("边界 %d: a=%v got=%v want=%v", i+1, c.a, got, c.want)
		}
		for j := range got {
			if got[j] != c.want[j] {
				t.Fatalf("边界 %d: a=%v got=%v want=%v", i+1, c.a, got, c.want)
			}
		}
	}
}
```

> **两个测试设计要点**：① `dump` 带 10 万步上限 —— 本章最容易犯的错是「忘记断开中点」导致成环，没有上限的话测试会挂死；② 边界表里同时给了 `n = 5` 和 `n = 6`，**成环 bug 恰好在这两个长度上从「碰巧对」变成「明显错」**，是必须覆盖的中等规模。

## 051.6 复杂度与常见坑

### 051.6.1 复杂度推导

- **时间 O(n)**：
  - 找中点：`fast` 走 `n/2` 步，O(n)。
  - 反转后半：后半段长度 `floor(n/2)`，O(n)。
  - 交替合并：后半段长度 `floor(n/2)`，每轮常数操作，O(n)。
  - 三段相加：`n/2 + n/2 + n/2 = 1.5n`，仍是 O(n)。
- **空间 O(1)**：`slow`、`fast`、`second`、`p`、`q`、`nextP`、`nextQ`，共 7 个指针；没有新分配任何结点（`reverse` 内部只有 `prev`、`cur`、`nxt`）。
- **为什么不能更快**：任何解法都必须访问每个结点至少一次（要改它的位置），所以 Ω(n) 是紧的。**本题已经达到时间下界与空间下界。**
- **对比数组法**：时间同为 O(n)，空间 O(n)。**收益纯粹在空间。**

### 051.6.2 八个真实踩过的坑

1. **忘了 `slow.next = null`** —— 反转时把前半段也卷进去，合并后成环。表现为「小数据碰巧对、`n = 5` 开始超时」。
2. **中点循环条件写错** —— 写成 `while (fast != null && fast.next != null)` 会让前半段比后半段短，合并时 `q` 剩结点，结果尾部多出一截或顺序错。
3. **合并循环条件写成 `while (p != null && q != null)`** —— 看似安全，但如果中点切分错了（见 ②），尾部结点会被丢掉。
4. **`nextP` 没先存** —— `p.next = q` 之后 `p.next` 已是 `q`，再取 `nextP = p.next` 就拿到 `q`，链表错乱甚至自环。
5. **`q.next = nextP` 写成了 `q.next = p`** —— `p` 此时已被 `p = nextP` 推进过（如果调整了语句顺序），`q` 会指回自己或指错位置。
6. **只改了值没改指针** —— 题目明令禁止；判题机能过，面试零分。
7. **想 `return` 新头** —— 签名是 `void`，不能返回。所有修改必须是原地副作用。
8. **对 `n = 1` / `n = 2` 没提前返回** —— `n = 1` 时 `slow.next` 是 `null`，`reverse(null)` 返回 `null`，合并循环不执行，结果其实正确；但 `n = 2` 时若不提前返回也正确。**虽然能过，仍然建议提前返回**，因为它让「后半段至少 1 个结点」这个前提更清晰，也省掉一次无意义的反转。

### 051.6.3 面试官最爱追问的三个问题

**Q1：为什么要把后半段反转，而不是想办法从后往前走？**
> 「因为单链表只有 `next`，不存在从尾部往前走的能力。要做到『交替取首、取尾』，就必须让『尾』变得可以从前面访问。反转后半段正好把『倒序的后半段』变成『正序的后半段』，于是两条都是正序链，交替合并就是标准的双指针推进。这样做空间是 O(1)，比抄进数组或双端队列的 O(n) 更优。」

**Q2：中点为什么用快慢指针，而不是先求长度再走一半？**
> 「先求长度是两趟：一趟数长度、一趟走到 n/2。快慢指针是一趟。虽然复杂度同为 O(n)，但快慢指针少一次遍历，而且不需要保存长度这个中间量。更重要的是，`fast.next && fast.next.next` 这个条件天然给出『前半段不少于后半段』，正好是合并阶段需要的保证 —— 这一点是求长度法不会自动提供的。」

**Q3：如果链表有 5 万个结点，你的实现在哪里最可能出问题？**
> 「最可能是成环而不是性能。5 万次递归必爆栈，所以我用迭代；而迭代里唯一的成环风险是『忘记断开中点』和『合并时搞错 nextP』。这两处都会让链变成环状，判题机序列化时死循环。所以我的自测一定会跑 `n = 5` 和 `n = 6` 这两个长度，并在 `dump` 里加上步数上限 —— 成环 bug 在这两个长度上从『碰巧对』变成『明显错』。」
