## 007.1 题目

**原题链接**：<https://leetcode.cn/problems/move-zeroes/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`，请把**所有 `0` 移动到数组末尾**，同时**保持所有非零元素的相对顺序不变**，并且**必须原地操作**（不能返回新数组）。

三条要求，缺一条就变成另一道题：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **必须原地** | 「必须在原数组上操作」 | 另开数组 `res` 再 `copy` 回去 → 空间 O(n)，面试判为「没做到要求」 |
| **非零元素相对顺序不变**（**稳定性**） | 「保持非零元素的相对顺序」 | `[1,2,0,3]` 变成 `[3,1,2,0]` → WA |
| **把 0 挪到末尾，等于把非零元素压缩到前面** | 题干 | 只想到「找 0 再交换」会写出 O(n²) 的冒泡式交换 |
| **返回值是 `void`** | 签名 | 「返回新数组」在本地能跑，在判题机上直接判错 |
| 元素**可能有负数** | 值域 `±2³¹` | 用「`> 0` 判非零」→ 负数被当成 0 挪到末尾 |

> ⚠️ 第三条是本题的**唯一难点**。如果没有「稳定性」这条要求，题目会退化成「把数组分成两堆」—— 从两端各放一个指针、遇到 0 就跟尾部交换即可，O(n) 且更直观。**正是因为要稳定，才只能用「同向快慢指针」。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 10^4` | 最多 1 万 | O(n²) = 10⁸，能过但没必要；**O(n) 是这题唯一该给的答案** |
| `-2^31 <= nums[i] <= 2^31 - 1` | 全 int 范围 | 判非零必须写 `!= 0`；`> 0` 会把负数当零 |
| `nums` 可含任意多个 0 | 包括全 0 | 全 0 时 `slow` 一直不动，扫描完即可，要能正确处理 |
| 原地 + O(1) 额外空间 | 题面 | 不能新建数组；交换用临时变量即可 |

> 💡 **量级反推**：`n = 10^4` 这种规模说明出题人**根本不在意时间复杂度**，他们在意的是「**你有没有用 O(1) 空间做到稳定压缩**」。这是简单题里常见的设计：**约束宽松，但要求明确**。面试里如果你只答「另开个数组」，技术上能过，实际上是零分。

### 示例

```
输入：nums = [0,1,0,3,12]
输出：[1,3,12,0,0]
解释：非零元素 1,3,12 保持原相对顺序，0 全部聚到末尾

输入：nums = [0]
输出：[0]

输入：nums = [-1,0,-2,0,3]
输出：[-1,-2,3,0,0]
解释：负数不是零，必须留在前面；判 `> 0` 的写法会输出 [3,0,0,0,0] 之类的结果
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [-1,0,-2,0,3]     → 暴露 `nums[i] > 0` 把负数误判成零
② [0,0,0,1]         → 暴露「slow 初始化成 1」或「先 slow++ 再写」
③ [1,0,0]           → 暴露「扫描完后忘了把尾部补零」（覆盖式写法的典型 bug）
④ [4,2,4,0,0,1,2]   → 非零元素有重复值，暴露「用值判等做交换」的写法把两个 4 换乱
```

第 ③ 条专打「覆盖式」写法：它把非零元素往前搬，但**不会自动把尾巴清零**，必须补一个 `for (; slow < n; slow++) nums[slow] = 0;`。而「交换式」写法没有这个问题。

## 007.2 从暴力到最优：第一个念头为什么错

### 第一步：最直觉的错法 —— 遇到 0 就往后冒泡

```java
// 错法：从左往右扫，遇到 0 就一路交换到末尾
for (int i = 0; i < n; i++) {
    if (nums[i] == 0) {
        for (int j = i; j + 1 < n; j++) {
            int t = nums[j]; nums[j] = nums[j + 1]; nums[j + 1] = t;
        }
    }
}
```

- 时间 **O(n²)**（每个 0 都要搬运一整段），空间 O(1)。
- 它是**稳定的**（相对顺序确实保住了），但慢。
- `n = 10^4` 且全 0 时是 `10⁸` 次交换 —— 能过，但这是「用最笨的方式满足要求」。**面试里这么写会被追问「能不能 O(n)」。**

### 第二步：第二个错法 —— 两端对撞交换

从 005/006 带过来的手感会诱导你写这个：

```java
// 错法：左指针找 0，右指针找非 0，交换
int l = 0, r = n - 1;
while (l < r) {
    while (l < r && nums[l] != 0) l++;
    while (l < r && nums[r] == 0) r--;
    if (l < r) { swap(nums, l, r); l++; r--; }
}
```

- 时间 **O(n)**、空间 **O(1)**、原地 —— **前三条全满足**。
- 但它**打破了稳定性**：`[0,1,0,3,12]` 会变成 `[12,1,3,0,0]`（尾部那个 12 被拽到了最前面）。**WA。**

> 📌 这是本题最重要的一课：**「对撞双指针」和「快慢双指针」是两种完全不同的工具。**
>
> | 工具 | 移动方式 | 天然保住什么 | 典型题 |
> | --- | --- | --- | --- |
> | 对撞双指针 | 一左一右相向而行 | **不保证顺序**，只保证「两端都被处理过」 | 002 / 005 / 006 |
> | 快慢双指针 | 同向而行，快指针读、慢指针写 | **天然稳定**：写入顺序 = 读取顺序 | **007（本章）** / 010 / 008 |

### 第三步：卡点在哪

把要求翻译成一句话：

> **把所有非零元素「按原顺序」挤到数组最前面，剩下的位置填 0。**

「按原顺序挤到最前面」这句话里藏着一个关键结构：**如果我从左往右扫一遍，每遇到一个非零元素就把它放到「下一个空位」上，那么它们的相对顺序天然就保住了** —— 因为我放入的顺序，就是我读到的顺序。

于是我们需要且只需要一个变量：**「下一个空位在哪」**。这个变量就是慢指针 `slow`。

```
slow 的含义：nums[0 .. slow-1] 已经放好了全部"已读到的非零元素"
             下一个非零元素应该写到 nums[slow]
```

### 第四步：灵感的来源 —— 「读」与「写」分离

整个算法只有一句话：

```
for fast = 0 .. n-1:
    if nums[fast] != 0:
        nums[slow] = nums[fast]   （或 swap）
        slow++
```

**为什么这一定稳定**：`fast` 是从左往右扫描的，遇到非零就按遇到的次序写到 `slow`。第 `k` 个被写下的非零元素，就是原数组里第 `k` 个非零元素。**「读到的次序 = 写下的次序」，稳定性是构造出来的，不是事后验证出来的。**

**为什么这一定原地且 O(1) 空间**：只多了 `slow`、`fast` 两个下标变量。

剩下的唯一问题是「尾巴上的 0 从哪来」，这产生两个变体：

| 变体 | 写入方式 | 尾巴的 0 怎么来 | 交换次数 |
| --- | --- | --- | --- |
| **交换式** ✅ | `swap(nums[slow], nums[fast])` | 被换到后面的 0 **自动**落到 `[slow, fast)` 区间 | 与非零元素个数相同 |
| 覆盖式 | `nums[slow] = nums[fast]` | 必须**手动补零** | 0 次交换，但要多写一个循环 |

两个变体都正确。**交换式少一个循环、更不容易漏补零；覆盖式写入更少（不需要读回旧值）。** 本章主解给交换式（更不容易错），§007.3.4 讨论覆盖式的取舍。

## 007.3 原理拆解

### 007.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 稳定 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 遇 0 冒泡到末尾 | O(n²) | O(1) | ✅ | n ≥ 10⁴ 且 0 多时明显慢；面试扣分 |
| 两端对撞交换 | O(n) | O(1) | ❌ | **本题不可用**（破坏稳定性） |
| 另开数组再拷回 | O(n) | **O(n)** | ✅ | 违反「原地」要求 |
| **快慢指针 + 交换** ✅ | **O(n)** | **O(1)** | ✅ | 在「只读数组」场景下不可用（需要写） |
| 快慢指针 + 覆盖 + 补零 | O(n) | O(1) | ✅ | 容易忘补零；0 较少时写入次数更少 |
| 统计 0 的个数再重排 | O(n) | O(1) | ✅ | 需要两遍扫描（先数、再写），本质与覆盖式相同 |

**为什么「快慢指针」是唯一正解**：它同时满足「O(n) 时间」「O(1) 空间」「稳定」三个条件，而其他方案至少丢掉一个。

### 007.3.2 为什么这个做法是对的（正确性论证）

以**交换式**为准（覆盖式在 §007.3.4 单独论证）。

**循环不变量**（在每轮 `fast++` 之后、下一轮开始之前成立）：

```
① nums[0 .. slow-1] 恰好是原数组中「前 fast 个元素里的全部非零元素」，且顺序与原数组一致；
② nums[slow .. fast-1] 全是 0；
③ slow <= fast。
```

- **初始**：`slow = fast = 0`。区间 `[0, -1]` 与 `[0, -1]` 都是空的，① ② 空真；③ 成立。
- **保持（`nums[fast] == 0`）**：本轮不写。`fast` 加一后，`[slow, fast-1]` 这个区间比之前多了一个 0（就是刚扫过的这个），② 保持；① 不变（没有新增非零元素）；③ 由 `slow <= fast` 且 `fast` 增大而保持。
- **保持（`nums[fast] != 0`）**：交换 `nums[slow]` 与 `nums[fast]`。
  - 交换前，由 ② 知 `nums[slow] == 0`（若 `slow == fast` 则无需交换，因为 `nums[slow]` 就是 `nums[fast]` 本身 —— 这时 ② 的区间是空的）。
  - 交换后 `nums[slow]` 变成这个新的非零元素，`slow` 加一，于是 ① 的区间扩大到包含它，且它排在所有旧非零元素之后 → **顺序保持**。
  - `nums[fast]` 变成 0，正好落入新的 `[slow, fast]` 区间（因为 `slow` 已经加一，旧 `slow` 位置现在是 `fast` 之前的位置？需要仔细看）：
    - 若 `slow < fast`：交换后 `nums[fast] = 0`，`fast` 加一后区间 `[old slow+1, fast]` 里最后一个是这个 0 → ② 保持。
    - 若 `slow == fast`：交换是自交换（无操作），`fast` 与 `slow` 同时加一，`[slow, fast-1]` 仍为空 → ② 空真。
- **终止**：`fast == n`，由 ① 知 `nums[0..slow-1]` 是全部非零元素；由 ② 知 `nums[slow..n-1]` 全是 0（因此时 `fast-1 == n-1`）。这正是题目要求的形态。∎

> **这个论证的价值**：它同时证明了「稳定」「原地」「正确」三件事，而且**没有用到任何关于元素值的额外假设**（除了「`0` 与「非 `0`」的二分），所以值是负数、是极大值、是重复值，全都不影响。

### 007.3.3 通用解题思路（可迁移的那一层）

本题是 **「原地删除 + 尾部填充」** 模型的原型，通常叫**快慢指针 / 读写指针 / 压缩**：

```
问题：从数组里删掉某些元素（本题删的是"非零元素之前的空位"这个视角）
        ↓ 关键观察：删除后的结果 = 保留下来的元素按原顺序挤到前面
        ↓ 于是只需要一个「写指针」，它的位置 = 已保留元素的个数
     模板：
        slow = 0
        for fast in 0..n-1:
            if 保留(nums[fast]):
                nums[slow] = nums[fast]     （或 swap）
                slow++
        （可选）把 [slow, n) 填成"删除后的占位值"
```

**这个模板的三个可调参数**：

| 参数 | 本题取值 | 换成别的题 |
| --- | --- | --- |
| 「保留」的条件 | `nums[fast] != 0` | LC 26：`nums[fast] != nums[slow-1]`；LC 27：`nums[fast] != val` |
| 写入方式 | `swap` | LC 26/27：直接赋值（因为重复值/目标值不需要保留） |
| 尾部填充 | 交换已自动完成 | LC 26/27：不需要（题目只要求返回新长度） |

属于同一模型的题：

| 题 | 「保留」的条件 | 尾部处理 |
| --- | --- | --- |
| [LC 283 移动零](https://leetcode.cn/problems/move-zeroes/) | `x != 0` | 交换自动补 0 |
| [LC 26 删除有序数组中的重复项](https://leetcode.cn/problems/remove-duplicates-from-sorted-array/) | `x != nums[slow-1]` | 不处理，返回 `slow` |
| [LC 27 移除元素](https://leetcode.cn/problems/remove-element/) | `x != val` | 不处理，返回 `slow` |
| [LC 80 删除有序数组中的重复项 II](https://leetcode.cn/problems/remove-duplicates-from-sorted-array-ii/) | `x != nums[slow-2]` | 不处理，返回 `slow` |
| [LC 905 按奇偶排序数组](https://leetcode.cn/problems/sort-array-by-parity/) | `x` 是偶数（**但不能用快慢指针**，因为不要求稳定） | 对撞双指针即可 |

> 📌 最后一行是个值得注意的对照：**905 不要求稳定性，所以对撞双指针就够了，而且更快（交换次数少）**。而 283 要求稳定性，必须快慢指针。**同一句「把某类元素挪到一边」，稳不稳定决定了用哪种双指针。**

### 007.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 不用交换，只允许「写入」 | 覆盖式 | `nums[slow++] = nums[fast]`，最后 `for (; slow < n; slow++) nums[slow] = 0;`。**必须补零** |
| 要求「把 0 挪到**前面**」 | 方向反转 | 从右往左扫，慢指针从 `n-1` 递减；或者把判据换成「保留非零」并反向写 |
| 数组**只读** | 不能原地 | 只能另开数组 → O(n) 空间；此时「原地」这个卖点消失 |
| 要挪的是「所有**偶数**」 | 判据换成 `x % 2 == 0` | 完全同构；注意 `x % 2` 对负数的结果是 `-1`，判等要用 `== 0` |
| 要求「0 之间保持相对顺序」 | 0 都相同，无意义 | 该要求恒成立，不影响解法 |
| **数据流**输入 | 无法原地 | 只能边读边写到一个输出流，本质是同一套快慢指针，只是 `slow` 变成了「输出流的位置」 |

**覆盖式的正确性（补充论证）**

覆盖式把 `nums[slow] = nums[fast]` 之后**不动** `nums[fast]`，所以扫完后 `[slow, n)` 里是「旧数据 + 也可能有残留的非零值」。因此**必须**补一段 `nums[slow..n-1] = 0`。它和交换式的关系是：

```
交换式：把 0 换到后面     → 尾部天然是 0，无需补
覆盖式：把非零搬到前面     → 尾部是"旧数据"，必须显式清零
两者写下的非零序列完全相同（都是按读到的次序），所以稳定性都成立
```

> **什么时候选覆盖式**：当「交换」比「赋值」贵的时候（例如元素是大结构体、交换要三次读写）。本题元素是 `int`，交换与赋值的代价几乎相同，所以**选更不容易出错的交换式**。

## 007.4 图解推演

### 007.4.1 交换式的完整轨迹

```
nums = [0, 1, 0, 3, 12]
        0  1  2  3   4      ← 下标

起始  slow=0, fast=0
┌───┬───┬───┬───┬────┐
│ 0 │ 1 │ 0 │ 3 │ 12 │
└───┴───┴───┴───┴────┘
  ↑
 slow
 fast

第 1 轮  fast=0  nums[0]=0      → 不是非零，跳过
┌───┬───┬───┬───┬────┐
│ 0 │ 1 │ 0 │ 3 │ 12 │
└───┴───┴───┴───┴────┘
  ↑   ↑
 slow fast          （slow 停在 0，因为还没有非零元素被写下）

第 2 轮  fast=1  nums[1]=1 ≠ 0  → swap(nums[0], nums[1])，slow++
┌───┬───┬───┬───┬────┐
│ 1 │ 0 │ 0 │ 3 │ 12 │
└───┴───┴───┴───┴────┘
      ↑   ↑
     slow fast       （0 被换到了 fast 位置，即 [slow, fast) 区间里）

第 3 轮  fast=2  nums[2]=0      → 跳过
┌───┬───┬───┬───┬────┐
│ 1 │ 0 │ 0 │ 3 │ 12 │
└───┴───┴───┴───┴────┘
      ↑       ↑
     slow    fast

第 4 轮  fast=3  nums[3]=3 ≠ 0  → swap(nums[1], nums[3])，slow++
┌───┬───┬───┬───┬────┐
│ 1 │ 3 │ 0 │ 0 │ 12 │
└───┴───┴───┴───┴────┘
          ↑       ↑
         slow    fast

第 5 轮  fast=4  nums[4]=12 ≠ 0 → swap(nums[2], nums[4])，slow++
┌───┬───┬───┬───┬────┐
│ 1 │ 3 │ 12│ 0 │ 0  │
└───┴───┴───┴───┴────┘
              ↑       ↑
             slow    fast=5（扫描结束）

结果 [1, 3, 12, 0, 0] ✓   非零元素顺序与原数组一致，尾部自动全是 0
```

### 007.4.2 每一步的不变量状态表

| 轮 | fast | nums[fast] | 动作 | slow | `[0, slow)` 内容 | `[slow, fast)` 内容 |
| --- | --- | --- | --- | --- | --- | --- |
| 起始 | — | — | — | 0 | 空 | 空 |
| 1 | 0 | 0 | 跳过 | 0 | 空 | `[0]` → 一个 0 |
| 2 | 1 | 1 | 交换 0↔1 | 1 | `[1]` | `[0]` 一个 0 |
| 3 | 2 | 0 | 跳过 | 1 | `[1]` | `[0,0]` 两个 0 |
| 4 | 3 | 3 | 交换 1↔3 | 2 | `[1,3]` | `[0,0]` 两个 0 |
| 5 | 4 | 12 | 交换 2↔4 | 3 | `[1,3,12]` | `[0,0]` 两个 0 |

**这张表就是不变量的实测**：左边 `[0, slow)` 永远「已读部分的非零元素，按原序」；右边 `[slow, fast)` 永远「全是 0，个数恰好等于已读到的 0 的个数」。

```
            已处理区 [0, fast)                    未处理区
   ┌───────────────────────────┬──────────────────┐
   │ 非零（按原序） │  全 0     │  尚未扫描         │
   └───────────────────────────┴──────────────────┘
   0             slow          fast              n-1
                 └── 这段长度 = 已看到的 0 的个数 ──┘
```

### 007.4.3 对撞双指针为什么破稳（反例轨迹）

```
nums = [0, 1, 0, 3, 12]

l=0 找 0 → l 停在 0
r=4 找非 0 → r 停在 4（值 12）
swap → [12, 1, 0, 3, 0]     ← 12 被拽到了最前面！
        l=1, r=3

┌────┬───┬───┬───┬────┐        ┌────┬───┬───┬───┬────┐
│ 0  │ 1 │ 0 │ 3 │ 12 │   →    │ 12 │ 1 │ 0 │ 3 │ 0  │
└────┴───┴───┴───┴────┘        └────┴───┴───┴───┴────┘
 ↑l              ↑r              ↑   ↑   ↑   ↑    ↑
                                 12  1   0   3    0
                                 非零元素顺序：原本 1,3,12 → 现在 12,1,3  ❌
```

**结论**：对撞双指针「从后往前搬」等价于**把最后面的非零元素搬到最前面**，稳定性必然被破坏。**这是 005/006 的双指针手感在这道题上第一次失效。**

### 007.4.4 两条路线对比图

```
                    ┌───────── 输入 nums（要求原地 + 稳定）─────────┐
                    │                                            │
      ┌─────────────▼──────────────┐          ┌──────────────────▼─────────────────┐
      │ 快慢指针（同向，读/写分离）  │          │ 对撞指针（相向，两端交换）           │
      │ O(n) / O(1) / 稳定 ✅       │          │ O(n) / O(1) / 稳定 ❌               │
      └─────────────┬──────────────┘          └──────────────────┬─────────────────┘
                    │                                            │
     fast 读、slow 写，写入顺序 = 读取顺序            左找 0、右找非 0，交换
     稳定性由构造保证                              尾部非零被搬到头部 → 顺序反转
                    │                                            │
          【本题选它：要求稳定】                    【905 奇偶分组不要求稳定，用它更快】
```

## 007.5 双语言实现

### 007.5.1 Java

```java
class Solution {
    public void moveZeroes(int[] nums) {
        // slow = 「下一个非零元素应该写到哪里」
        // 循环不变量：nums[0..slow-1] 是已扫描部分里的全部非零元素（按原序），
        //            nums[slow..fast-1] 全是 0
        int slow = 0;

        for (int fast = 0; fast < nums.length; fast++) {
            // 必须写 != 0 而不是 > 0：值是负数时它也是非零元素，要留在前面
            if (nums[fast] != 0) {
                // 交换而不是直接赋值：交换把 0 "顺带" 推到 fast 位置，
                // 尾部天然是 0，省掉"最后补零"这一步（赋值式容易漏）
                int tmp = nums[slow];
                nums[slow] = nums[fast];
                nums[fast] = tmp;
                slow++;
            }
        }
        // 返回类型是 void：题目要求原地修改，不要 return 新数组
    }
}
```

**备解：覆盖式（少一次写回，但必须补零）**

```java
// 类名用 SolutionOverwrite 而不是 Solution：同一份文件里两个类同名会编译失败
class SolutionOverwrite {
    public void moveZeroes(int[] nums) {
        int n = nums.length;
        int slow = 0;

        // 第一遍：把非零元素按原序写到前面（不交换，直接覆盖）
        for (int fast = 0; fast < n; fast++) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast];
            }
        }

        // 第二遍：从 slow 到末尾全部补 0 —— 这一步不可省！
        // 少了它，尾部残留的是"被覆盖后没人管的旧值"，例如 [1,0,0] 会变成 [1,0,0]
        // 看着对，但 [0,0,0,1] 会变成 [1,0,0,1]（最后一个 1 没被清掉）
        while (slow < n) {
            nums[slow++] = 0;
        }
    }
}
```

### 007.5.2 Go

```go
package main

// moveZeroes 原地把 0 移到末尾，保持非零元素的相对顺序。
// 返回 void：Go 里就是没有返回值，调用方直接看传入的切片被修改
func moveZeroes(nums []int) {
	// 不变量：nums[0..slow-1] 是已扫描部分里的全部非零元素（按原序），
	//         nums[slow..fast-1] 全是 0
	slow := 0

	for fast := 0; fast < len(nums); fast++ {
		if nums[fast] != 0 {
			// Go 的多重赋值：右侧先全部求值，再赋值，所以不需要临时变量。
			// 这一点比 Java 少一行，但语义必须理解清楚 ——
			// 写成 nums[slow] = nums[fast]; nums[fast] = nums[slow] 就错了（两处都变成同一个值）
			nums[slow], nums[fast] = nums[fast], nums[slow]
			slow++
		}
	}
}
```

**备解：覆盖式**

```go
package main

func moveZeroesOverwrite(nums []int) {
	n := len(nums)
	slow := 0

	for fast := 0; fast < n; fast++ {
		if nums[fast] != 0 {
			nums[slow] = nums[fast]
			slow++
		}
	}

	// 尾部补零：Go 的切片没有内建 fill，只能循环
	for slow < n {
		nums[slow] = 0
		slow++
	}
}
```

### 007.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 交换写法 | 需要临时变量 `int tmp` | 多重赋值 `a, b = b, a` | Go 少一行；但**多重赋值的顺序语义**要理解（右值先全部求值），写成两次单元赋值会出错 |
| 原地修改的「传参」 | 数组是引用类型，直接改 `nums[i]` 生效 | 切片是「指针 + 长度 + 容量」的值传递，**改元素生效**，但 `append` 改变长度**不会**传回调用方 | 本题只改元素、不改长度 → 两种语言都正确；若改成「删除并缩容」就要注意切片语义 |
| 返回值 | `void` | 无返回值 | 调用方看原对象 |
| 补零 | 可以 `Arrays.fill(nums, slow, n, 0)` | 只能 `for` 循环（Go 1.21 起有 `clear`，只用于清零全切片，不能从中间开始） | Java 一行，Go 三行 |
| 边界 | `nums.length == 0` 时循环不执行 | `len(nums) == 0` 同理 | 两者都安全，不需要特判 |
| 判零 | `nums[fast] != 0` | 同 | 两语言都**不能写 `> 0`** |

### 007.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// brute 用「另开数组」的笨办法算出目标形态 —— 违反原地要求，但绝对正确，
// 正好当作参照物：它把非零元素按序收集，后面补齐 0
func brute(nums []int) []int {
	res := make([]int, 0, len(nums))
	for _, x := range nums {
		if x != 0 {
			res = append(res, x)
		}
	}
	for len(res) < len(nums) {
		res = append(res, 0)
	}
	return res
}

func equal(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func TestMoveZeroesRandom(t *testing.T) {
	r := rand.New(rand.NewSource(283))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(12) // 0..11，含空数组
		nums := make([]int, n)
		for i := range nums {
			if r.Intn(10) < 5 { // 一半概率是 0，制造"大量 0"与"全 0"
				nums[i] = 0
			} else {
				nums[i] = r.Intn(11) - 5 // 含负数，专打 `> 0` 判零
			}
		}
		want := brute(nums)

		// 交换式
		got1 := append([]int(nil), nums...)
		moveZeroes(got1)
		if !equal(got1, want) {
			t.Fatalf("iter=%d moveZeroes(%v)=%v want=%v", iter, nums, got1, want)
		}

		// 覆盖式
		got2 := append([]int(nil), nums...)
		moveZeroesOverwrite(got2)
		if !equal(got2, want) {
			t.Fatalf("iter=%d moveZeroesOverwrite(%v)=%v want=%v", iter, nums, got2, want)
		}
	}
}

// 钉住四个手推反例
func TestMoveZeroesEdge(t *testing.T) {
	cases := [][]int{
		{},
		{0},
		{0, 0, 0, 1},
		{1, 0, 0},
		{-1, 0, -2, 0, 3},
		{4, 2, 4, 0, 0, 1, 2},
	}
	for _, c := range cases {
		want := brute(c)
		got := append([]int(nil), c...)
		moveZeroes(got)
		if !equal(got, want) {
			t.Fatalf("moveZeroes(%v)=%v want=%v", c, got, want)
		}
	}
}
```

> **测试设计说明**：一半概率给 0、值域含负数，是为了同时压住两个经典 bug ——「`> 0` 判零」和「尾部残留旧值」。20000 轮随机 + 6 个手推反例，基本可以认为「这段代码没有边界问题」。

## 007.6 复杂度与常见坑

### 007.6.1 复杂度推导

- **时间 O(n)**：`fast` 从 `0` 走到 `n-1`，恰好 `n` 轮，每轮最多一次交换（三次赋值）→ 常数次操作。总操作数 ≤ `3n` 次写入。
- **空间 O(1)**：只有 `slow`、`fast`、`tmp` 三个标量。
- **写入次数**（面试加分点）：
  - 交换式：每个非零元素一次交换 = 3 次写；零元素 0 次写。总计 `3k`（`k` = 非零个数）。
  - 覆盖式：每个非零元素 1 次写 + 每个 0 一次写（补零阶段）= `k + (n-k) = n` 次写。
  - 当 `k` 接近 `n`（0 很少）时覆盖式更快；当 `k` 很小（0 很多）时交换式更快。**这就是「同一复杂度、不同常数」的典型例子。**

### 007.6.2 七个真实踩过的坑

1. **用 `> 0` 判非零** —— `[-1,0,-2,0,3]` 会把负数全挪到后面。必须 `!= 0`。
2. **用对撞双指针** —— 能过「0 全在末尾」的样例，但在 `[0,1,0,3,12]` 上直接把 12 拽到最前面，破坏稳定性。
3. **覆盖式忘了补零** —— `[0,0,0,1]` 会变成 `[1,0,0,1]`（最后一个位置残留旧的 1）。**必须补 `while (slow < n) nums[slow++] = 0;`**。
4. **`slow` 初始化错** —— 写成 `int slow = 1` 或「先 `slow++` 再写」会让第一个非零元素被跳过或错位。
5. **返回了新数组** —— 题目签名是 `void`，你把结果 `return` 出去等于什么都没做（LeetCode 只看传入的那个数组）。
6. **Go 里用两次单元赋值代替多重赋值** —— `nums[slow] = nums[fast]; nums[fast] = nums[slow]` 会让两处都变成同一个值（第二次赋的是已经被覆盖的值）。必须 `nums[slow], nums[fast] = nums[fast], nums[slow]`。
7. **以为「交换一定比赋值慢」** —— 本题两者都是 O(1) 操作，差别只在写次数。**不要为了「省一次写」而引入「忘补零」的风险。**

### 007.6.3 面试官最爱追问的三个问题

**Q1：为什么不能用两端对撞的双指针？**
> 「因为题目要求『非零元素相对顺序不变』。对撞双指针的做法是『左端找 0、右端找非零、交换』，这等价于**把最右边的非零元素搬到最前面**，顺序必然被破坏 —— 例如 `[0,1,0,3,12]` 第一步就会把 12 换到下标 0。快慢指针能保住稳定性，因为它的写入顺序就是读取顺序：第 k 个被写下的非零元素，正是原数组第 k 个非零元素。」

**Q2：你的算法做了多少次写操作？能更少吗？**
> 「交换式是最多 `3k` 次写（`k` 为非零个数，每次交换 3 次写），零元素完全不写。覆盖式是 `n` 次写（`k` 次搬非零 + `n-k` 次补零）。所以 0 很少时覆盖式更省，0 很多时交换式更省。如果真的追求写次数，可以统计 `k` 后只搬非零、再一次性 `fill` 尾部 —— 但那已经是两遍扫描了。**本题元素是 `int`，两种都是常数级差异，选更不容易错的交换式更划算。**」

**Q3：如果要删除的不是 0，而是「所有等于 `val` 的元素」，代码怎么改？还要不要交换？**
> 「把判据 `nums[fast] != 0` 换成 `nums[fast] != val` 就行，但**不需要交换**了 —— 因为被删掉的元素不要求保留，「删除后新长度之外的内容无所谓」（LC 27 的题面就是『超出新长度的部分不重要』）。这时直接 `nums[slow++] = nums[fast]` 覆盖即可，也不用补零。**283 之所以需要交换/补零，是因为它要求整个数组的最终形态都正确，而 26/27 只要求前 `slow` 个位置正确。**」
