## 028.1 题目

**原题链接**：<https://leetcode.cn/problems/sort-an-array/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`，请把它按升序排列后返回。

题目额外要求（这一句在题干最后，但它是本题的全部难度来源）：

> **你必须在不使用任何内置函数的情况下解决问题，时间复杂度为 O(n log n)，空间复杂度尽可能小。**

把它翻译成四条硬约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **不能调库** | 「不使用任何内置函数」 | 写 `Arrays.sort(nums)` 一行过题，面试直接结束——面试官要看的是划分与合并的过程 |
| **必须 O(n log n)** | 题干末句 | 冒泡 / 插入 / 选择排序都是 O(n²)，`n = 5·10⁴` 时本机实测插入排序 **417 ms**，`n = 10⁵` 就 **1594 ms**，规模再涨就 TLE |
| **空间尽可能小** | 「空间复杂度尽可能小」 | 归并排序要 O(n) 缓冲；面试官通常接着问「能不能 O(1) 额外空间」——那就只剩快排与堆排 |
| **允许重复元素** | 数据范围里没写「互不相同」 | 两路划分在全相同数组上退化成 O(n²)（§028.2 有实测），必须三路划分或随机化 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 5·10⁴` | n 最多 5 万 | `n log₂n ≈ 5·10⁴ × 16 = 8·10⁵` 次比较；而 `n²/4 ≈ 6·10⁸` 次移动。两者差 **750 倍**，正好是本题「必须手写」的原因 |
| `-5·10⁴ <= nums[i] <= 5·10⁴` | 值域只有 **10⁵ 宽** | 这说明**计数排序也能过**（本机 n=10⁵ 只用 1.0 ms）。但值域窄是这道题数据的巧合，不是问题的本质；面试官把范围改成 `-10⁹ ~ 10⁹` 时计数排序立刻失效 |
| 需要返回新数组或原地 | 判题按返回值比对 | `sortArray` 返回值必须是排好序的数组；原地改 + 返回同一个引用也可以 |
| 追问「常数级空间」 | 题干末句 | 堆排序是唯一「严格 O(1) 额外空间 + 最坏 O(n log n)」的经典选择 |

> 💡 **量级 → 算法** 的条件反射在这里第一次真正发力：
> `n ≤ 2·10³` → 插入排序就够；`n ≤ 10⁵` → 必须 O(n log n)；`n ≤ 10⁷` 且值域窄 → 计数 / 基数排序；`n` 大到内存放不下 → 外部排序（多路归并）。
> **看到「排序」二字，第一反应不该是「调库」，而是「值域多宽、能不能进内存、要不要稳定」。**

### 示例

```text
输入：nums = [5, 2, 3, 1]
输出：[1, 2, 3, 5]

输入：nums = [5, 1, 1, 2, 0, 0]
输出：[0, 0, 1, 1, 2, 5]      ← 有重复值，且重复值必须全部保留
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [1,1,1,...,1]（5 万个 1）      → 打「两路划分」：全相同时每次只切掉 1 个元素，退化成 O(n²)
② [1,2,3,...,n]（已升序）        → 打「固定取首元素当 pivot」：每次划分 1 : n-1，递归深度 n，栈溢出
③ [n,...,2,1]（已降序）          → 与 ② 对称，也要防守
④ [0,1,0,1,0,1,...]（只有两值）  → 打「三路划分写错 lt / gt 更新顺序」的版本
⑤ []、[7]（空与单元素）          → 打「递归没写终止条件」和「建堆时 i = n/2 越界」
```

其中 ① 是最容易被忽视的：LeetCode 上「第 100 个测试点全是同一个数」是这类题的经典狙击位。

## 028.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```go
// 插入排序：把 a[i] 插到前面已排好的 a[0..i-1] 里的正确位置
for i := 1; i < n; i++ {
    v := a[i]
    j := i - 1
    for j >= 0 && a[j] > v {
        a[j+1] = a[j]
        j--
    }
    a[j+1] = v
}
```

- 时间 **O(n²)**（随机数据下平均 `n²/4` 次移动），空间 **O(1)**，而且是**稳定**的。
- 本机实测（Go 1.19.8 / 2 核容器）：`n = 5·10⁴` → **417 ms**，`n = 10⁵` → **1594 ms**。注意这个增长：n 翻倍，时间翻 **3.8 倍**，正好是 `n²` 的形状。
- `n = 5·10⁴` 的 417 ms 在 LeetCode 的松时限下**可能真的能过**。但这是运气，不是算法：同一份代码搬到「10⁷ 行日志按时间排序」的场景就是 20 分钟。

### 第二步：卡点在哪 —— 比较排序的下界

这里必须讲一个比「优化代码」更根本的东西：**任何基于两两比较的排序，最坏情况都至少要 `Ω(n log n)` 次比较。**

论证只有三行（决策树）：

```
n 个元素的排列有 n! 种 → 排序算法必须能区分这 n! 种输入
每次比较只有「是 / 否」两个结果 → 深度为 h 的二叉树最多 2^h 个叶子
所以 2^h ≥ n!  →  h ≥ log₂(n!) ≈ n log₂n - 1.44n
```

也就是说：**插入排序慢不是因为写得丑，而是因为它离下界还差一个 n 的因子。** 想达到下界，就必须让每一次比较都「尽量排除掉一半可能性」——这就直接指向了分治。

### 第三步：三种达到下界的思路，以及它们各自的退化点

| 思路 | 一句话 | 合并/划分的代价 | 退化点 |
| --- | --- | --- | --- |
| **归并** | 排好两半，再线性合并 | 合并 O(n)，共 log n 层 | 需要 O(n) 缓冲；不稳定写法会把相等元素换序 |
| **快排** | 选 pivot 分两堆，再各自递归 | 划分 O(n)，平均 log n 层 | 划分不均时层数退化成 n；全相同元素时两路划分退化 |
| **堆排** | 建堆，反复取堆顶放到末尾 | 下沉 O(log n)，共 n 次 | 常数大、缓存不友好；**不稳定** |

三条路线都达到 `O(n log n)`，所以「谁更好」不是复杂度问题，而是**常数、稳定性、空间、以及最坏情况**的取舍 —— 这张取舍表就是 §028.3.1。

### 第四步：灵感的来源 —— 「逆序对」才是排序真正在消除的东西

把「排序」换个说法：**数组里每一对 `i < j` 且 `a[i] > a[j]` 的元素，都是一个逆序对；排好序 = 逆序对清零。**

于是三种算法做的事可以统一描述：

```
冒泡：每次相邻交换消掉 1 个逆序对            → 逆序对最多 n²/2 个，所以 O(n²)
归并：合并两段时，右边每个元素「跨过」左边多少个 → 一次合并能批量消掉 O(n) 个逆序对
快排：一次划分把「大于 pivot」的全部甩到右边   → 一次划分批量消掉一大批
堆排：每次把当前最大值送到末尾               → 一次下沉定位一个元素的最终位置
```

**这个视角的价值**：它解释了为什么归并排序能顺手数出逆序对（LC 493 的核心），也解释了为什么快排在「几乎有序」的数组上极快（逆序对少 → 划分虽然不均但总量小）。

### 另一条路：计数排序（这题能过，但不该作为答案）

值域只有 `[-5·10⁴, 5·10⁴]`，宽 10⁵，所以：

```text
开一个长度 100001 的计数数组 → 扫一遍 nums 计数 → 从小到大把值按次数吐出来
时间 O(n + V)，空间 O(V)，本机实测 n=10⁵ 仅 1.0 ms
```

它比三种比较排序都快 10 倍，**但它不是这道题想考的东西**，原因有二：

1. **它依赖值域**。面试官把 `nums[i]` 改成 `-10⁹ ~ 10⁹`，计数数组就是 8 GB，直接崩。
2. **它完全绕开了「比较」这个考点**。手写排序考的是划分、合并、堆调整，计数排序一个都不涉及。

> ⚠️ 这是本书反复出现的判断标准：**「能过」和「是答案」是两件事。** 面试里先说「值域窄可以用计数排序 O(n+V)」，再说「但通用解是 O(n log n) 的比较排序，我实现三路快排」，这个顺序才是加分项。

## 028.3 原理拆解

### 028.3.1 数据结构与算法选型

**六种候选的横向对比**（数据来自本机实测与教科书结论）：

| 方案 | 平均时间 | 最坏时间 | 额外空间 | 稳定 | 什么时候会输 |
| --- | --- | --- | --- | --- | --- |
| 插入排序 | O(n²) | O(n²) | O(1) | ✅ | `n > 2000`；但**小区间（< 12）最快**，所以它是快排的收尾手段 |
| 冒泡排序 | O(n²) | O(n²) | O(1) | ✅ | 全场景都输，只用来教学 |
| 归并排序 | O(n log n) | O(n log n) | **O(n)** | ✅ | 内存吃紧；链表排序反而最适合它 |
| 三路快排 | O(n log n) | O(n²)（随机化后期望 O(n log n)） | O(log n) 栈 | ❌ | 需要**稳定**时；需要**最坏情况保证**时 |
| 堆排序 | O(n log n) | **O(n log n)** | **O(1)** | ❌ | 缓存不友好，实测比快排慢 40%~50%；需要稳定时 |
| 计数 / 基数 | O(n + V) | O(n + V) | O(V) | ✅ | 值域宽（`10⁹`）或值是浮点 / 字符串时 |

**「什么时候选哪个」的决策表**（本部分的统一口径，029–035 都会引用它）：

| 输入特征 / 需求 | 选它 | 理由 |
| --- | --- | --- |
| 只要最快，允许最坏情况 | **三路快排 + 随机 pivot** | 实测最快：随机数据 `n=10⁵` 只要 7.6 ms，比归并快 25%、比堆排快 34% |
| 重复元素多（值域窄） | **三路快排** | 等值区一次成段，实测「全相同」`n=10⁵` 只用 **0.091 ms**（归并 0.71 ms、堆排 0.30 ms） |
| 要求**稳定** | **归并排序** | 只有归并能同时做到 O(n log n) + 稳定；`a[mid] <= a[mid+1]` 的短路还能把近似有序输入压到 O(n) |
| 要求**最坏 O(n log n) 且 O(1) 空间** | **堆排序** | 唯一同时满足这两条的经典算法；代价是常数最大 |
| 数据在**链表**上 | **归并排序** | 链表不能随机访问，快排的分区与堆排的下标寻址都失效（见 034 / LC 148） |
| 值域窄且知道范围 | 计数 / 基数排序 | O(n+V)，但这题不该用它（见 §028.2 末） |
| 内存放不下 | 外部排序（多路归并） | 分块排序落盘 + k 路归并，见 §028.6.3 |

**为什么「三路快排」而不是「两路（Lomuto / Hoare）快排」**：这是本题唯一必须讲透的细节。

两路划分把数组切成「`< pivot`」和「`≥ pivot`」两块。当数组**全部元素相同**时，`< pivot` 那块是空的，每次划分只确定 1 个元素的位置，递归 `n` 层 → `O(n²)`。三路划分多出一个「`== pivot`」的中间段，全相同时**一次划分就把整段确定下来**，直接结束。

实测（本机，Go，故意用朴素两路划分）：

| 数据形态 | 朴素两路（首元素 pivot）n=10³ | n=2·10³ | n=4·10³ | 增长倍数 |
| --- | --- | --- | --- | --- |
| 随机 | 0.052 ms | 0.099 ms | 0.212 ms | ×1.9 / ×2.1（≈ n log n） |
| 全相同 | 0.692 ms | 2.319 ms | 9.050 ms | ×3.4 / ×3.9（**≈ n²**） |
| 已升序 | 0.473 ms | 2.628 ms | 8.185 ms | ×5.6 / ×3.1（**≈ n²**） |

n 翻倍、时间近乎翻 4 倍，这就是 O(n²) 的指纹。而换成本章的三路快排后，同样三种形态在 `n = 10⁵` 上分别只要 **7.6 / 0.091 / 3.9 ms**。

### 028.3.2 为什么这个做法是对的（正确性论证）

**（1）三路划分的不变量**

`partition3(a, lo, hi)` 把 `pivot = a[lo]` 作为基准，用三个下标 `lt / i / gt` 维护下面这个不变量：

```
┌───────────┬────────────┬──────────────┬──────────────┐
│  a[lo..lt) │ a[lt..i)   │ 未检查        │ (gt..hi]     │
│   < pivot  │  == pivot  │ (i..gt]      │   > pivot    │
└───────────┴────────────┴──────────────┴──────────────┘
                ↑           ↑              ↑
                lt          i              gt
```

每次循环做一件事，且只做一件：

- `a[i] < pivot` → 和 `a[lt]` 交换，`lt++`、`i++`。「小于区」长大一格，且换出去的 `a[lt]` 原本是 `== pivot`，放到 `i` 位置仍满足「等于区」的定义。
- `a[i] > pivot` → 和 `a[gt]` 交换，`gt--`，**`i` 不动**。换过来的 `a[gt]` 从未被检查过，必须留在 `i` 位置下一轮再判。
- `a[i] == pivot` → `i++`，直接并入等于区。

循环在 `i > gt` 时结束，此时三段覆盖整个 `[lo, hi]`，不变量成立。∎

> 最容易写错的就是第二条里的「`i` 不动」。写成 `i++` 会让换过来的元素被跳过、永远不参与比较，结果是数组**没有排好但也不报错**——这类 bug 只能靠对拍抓出来。

**（2）快排整体的正确性（强归纳）**

命题：`quickSort(a, lo, hi)` 返回后 `a[lo..hi]` 升序。

- 基础：`hi - lo < 12` 时走插入排序，插入排序正确。`lo >= hi` 时不做事，正确。
- 归纳：设划分返回 `[lt, gt]`，则 `a[lo..lt-1]` 全部 `< pivot`，`a[lt..gt]` 全等于 `pivot`，`a[gt+1..hi]` 全部 `> pivot`。递归排好左右两段后，左段每个元素 `< pivot` ≤ 中段 ≤ 右段每个元素 `> pivot`，故整段升序。∎

（注意归纳的**依据是长度**：左右两段都严格短于原段——因为中段至少含 `pivot` 一个元素，所以递归一定终止。）

**（3）归并的稳定性**

合并时用 `buf[j] < buf[i]`（**严格小于**）才取右段。相等时取左段，且左段元素原下标更小，所以相等元素的相对顺序被保留 → 稳定。若写成 `<=`，相等时先取右段，稳定性立刻丢失（这是 §028.6.2 的第 3 条坑）。

**（4）堆排序的两条不变式**

- 建堆结束后：`a[i] >= a[2i+1]` 且 `a[i] >= a[2i+2]`（大顶堆性质）。
- 第 `k` 轮（`end = n-1, n-2, …`）开始前：`a[0..end]` 是堆，`a[end+1..n-1]` 已是全局最大的若干个且有序。每轮把 `a[0]`（堆中最大）换到 `a[end]`，再对 `a[0..end-1]` 下沉恢复堆性质 → 不变量保持，最终整体升序。∎

### 028.3.3 通用解题思路（可迁移的那一层）

本题是 **「分治 + 线性合并」** 这个模型的母题：

```
原始问题：把 n 个元素排好序
          ↓ 分（把问题切成互不相交的两半）
子问题：  把左半排好 + 把右半排好
          ↓ 治（用 O(n) 的代价把两个有序段拼成一个有序段）
合并：    双指针归并 / 原地分区 / 堆顶弹出
          ↓ 代价分析：T(n) = 2T(n/2) + O(n) → O(n log n)
```

同一模型下的题：

| 题 | 「分」的方式 | 「合并」的方式 |
| --- | --- | --- |
| [LC 912 排序数组](https://leetcode.cn/problems/sort-an-array/) | 按中点 / 按 pivot | 归并 / 划分 |
| [LC 23 合并 K 个升序链表](https://leetcode.cn/problems/merge-k-sorted-lists/) | 链表分成两半 | 两两归并（见 `034`） |
| [LC 148 排序链表](https://leetcode.cn/problems/sort-list/) | 快慢指针找中点 | 归并（链表天然适合） |
| [LC 493 翻转对](https://leetcode.cn/problems/reverse-pairs/) | 同归并排序 | 合并时顺带统计跨段逆序对 |
| [LC 315 计算右侧小于当前元素的个数](https://leetcode.cn/problems/count-of-smaller-numbers-after-self/) | 同归并排序 | 合并时记录「右边有几个更小的」 |
| [LC 88 合并两个有序数组](https://leetcode.cn/problems/merge-sorted-array/) | 不分 | 逆向双指针合并（避免覆盖） |

**共同点**：都是「把 O(n²) 的两两比较，换成 O(n) 的一次归并/划分」。**识别信号**：题目里出现「两两之间的关系」「比它小的有多少个」「第 k 小」时，先想能不能排序或归并。

### 028.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 数据在**链表**上 | 不能随机访问 | 归并排序（自顶向下或自底向上），快排的分区失去意义 |
| **稳定**是硬要求 | 快排/堆排出局 | 归并排序；或「值 + 原下标」一起比较，把任意排序改造成稳定 |
| **最坏** O(n log n) 且 O(1) 空间 | 快排不行、归并不行 | 堆排序；或内省排序（introsort：快排 + 深度超限转堆排） |
| **几乎有序**的输入 | 插入排序 O(n) | 用插入排序或「归并 + 已有序短路」，实测归并在已升序输入上比随机快 **14 倍** |
| **内存放不下** | 不能一次读入 | 外部排序：分块排序落盘 + k 路归并（用堆维护 k 个文件的最小值） |
| **多线程 / 分布式** | 单机算力不够 | 归并排序天然可并行（两半独立），快排的划分是串行瓶颈；MapReduce 的 shuffle 本质就是分布式归并 |

## 028.4 图解推演

### 028.4.1 三路划分的指针运动

以 `a = [4, 2, 4, 1, 4, 3]`、`pivot = 4`（已换到 `a[lo]`）为例，`lt=0, i=1, gt=5`：

```text
初态   [4]  2   4   1   4   3
        lt,i              gt
       （[lo,lt) 空，[lt,i) 空，(gt,hi] 空）

step1  a[i]=2 < 4 → 交换 a[lt]、a[i]（自己换自己），lt=1, i=2
       [4]  2   4   1   4   3
            lt  i          gt
         └─< 4─┘└─== 4─┘└─未检查─┘

step2  a[i]=4 == 4 → i=3
       [4]  2   4   1   4   3
            lt      i      gt

step3  a[i]=1 < 4 → 交换 a[1]、a[3]，lt=2, i=4
       [4]  1   4   2   4   3
                lt      i  gt

step4  a[i]=4 == 4 → i=5
       [4]  1   4   2   4   3
                lt         i,gt

step5  a[i]=3 < 4 → 交换 a[2]、a[5]，lt=3, i=6（i > gt，结束）
       [4]  1   3   2   4   4
                    └lt──┘└gt

结果：[0,3) 是 {4,1,3}? —— 注意 pivot 本身在 a[0]，它会在最后一次「小于交换」中被换出去
```

这里要特别说明一步容易看错的地方：`pivot` 是**值**的副本，`a[lo]` 在第一次「小于」交换时就可能被换走，等值元素会陆续归入 `[lt, i)` 区间，最终 `a[lt..gt]` 恰好是全等于 `pivot` 的那一段。对 `[4,2,4,1,4,3]` 的最终结果是 `[3,1,2,4,4,4]`，等值区是下标 `[3,5]`。

### 028.4.2 快排的递归树：为什么「先递归短边」能把栈压到 O(log n)

```text
             [0..n-1]
            /        \
       [0..k]        [k+1..n-1]        假设划分极度不均：左 1 个、右 n-2 个
        /   \            |
     [0]   [1]        [k+2..n-1]       ← 如果总是先递归「长边」，栈深 = n
                          |
                       ...             → n = 5·10⁴ 时 Java 默认栈爆掉（StackOverflowError）

改为「先递归短边、长边用 while 循环消掉」后：
  递归深度 = 每次至少缩小一半的那条路径 = O(log n)
  长边不进栈，只是把 lo/hi 改一改继续循环
```

### 028.4.3 堆排序的下沉与「取顶放尾」

```text
建堆后的大顶堆（数组形式）：[9, 7, 8, 3, 6, 5, 2]
                    9
                  /   \
                 7     8
                / \   / \
               3   6 5   2

第 1 轮：交换 a[0]、a[6] → 9 归位到末尾
   [2, 7, 8, 3, 6, 5 | 9]      对 a[0..5] 下沉 2：
        2                          7                        7
      /   \        →            /   \         →          /   \
     7     8                   2     8                  5     8
    / \   /                   / \   /                  / \   /
   3   6 5                   3   6 5                  3   6 2
   ↓ 交换 2 与 7            ↓ 交换 2 与 5            ↓ 2 无子，停止
   [7,2,8,3,6,5|9]         [7,5,8,3,6,2|9]

第 2 轮：交换 a[0]、a[5] → 7 归位
   [2, 5, 8, 3, 6 | 7, 9]  … 继续，直到 end == 0
```

关键点是 `siftDown(a, i, n)` 的第三个参数 `n`：它必须等于**当前堆的有效长度**。写成整个数组长度是最高频的堆排 bug —— 已排好的尾部会被重新卷进堆里，结果既错又慢。

### 028.4.4 三份实现的实测对比（必看：这决定你面试时报哪一个）

**Go 1.19.8 / 2 核容器 / 单位 ms / 每种组合跑 5 次取最快**

| 算法 | 数据形态 | n = 10⁴ | n = 10⁵ | 备注 |
| --- | --- | --- | --- | --- |

**Java 17 / 同一台机器 / 同一批数据形态**

| 算法 | 随机 n=10⁴ | 随机 n=10⁵ | 全相同 n=10⁵ | 已升序 n=10⁵ |
| --- | --- | --- | --- | --- |
| 三路快排 | 1.405 | **9.920** | **0.195** | 5.810 |
| 归并排序 | 0.993 | 12.298 | 0.682 | 0.683 |
| 堆排序 | 0.904 | 10.474 | 0.395 | 6.485 |

**从这两张表能读出四件事**（面试时报这些结论，而不是报「都差不多」）：

1. **随机数据上快排最快**，比归并快 25%~35%，比堆排快 30%~50%。原因是它的内存访问是**顺序的**（划分时一路往前扫），而归并要在 `buf` 与 `a` 之间来回搬，堆排的 `2i+1` 跳着访问，缓存命中率最低。
2. **重复元素越多，三路快排的优势越大**。全相同输入上它比归并快 **7.8 倍**（Go：0.091 vs 0.714）。
3. **已有序输入上归并最快**（0.720 ms）：`a[mid] <= a[mid+1]` 这个短路让每层合并都立刻返回，总代价退化成 O(n) 的递归开销。这条短路只有 3 行，收益是 14 倍。
4. **堆排唯一不可替代的地方是空间**：它的实测最慢，但它额外空间是 O(1)，且最坏也是 O(n log n)。**只要面试官说「内存紧张」或「不允许最坏 O(n²)」，就得换成它。**

### 028.4.5 一个反直觉的实测：三数取中反而更慢

很多人（包括我第一版）会在快排里用「三数取中」代替随机 pivot，理由是「取中位数更接近真中位数，划分更均匀」。**实测结果相反**：

| 数据形态 | 三数取中（只比较、不写入）n=10⁵ | 随机 pivot n=10⁵ | 三数取中 n=10⁶ | 随机 pivot n=10⁶ |
| --- | --- | --- | --- | --- |
| 随机 | 12.107 ms | **7.380 ms** | 88.1 ms | **89.5 ms**（持平） |
| 已升序 | 21.463 ms | **3.955 ms** | **671.8 ms** | 49.6 ms |
| 已降序 | 15.926 ms | **3.939 ms** | **487.4 ms** | 108.1 ms |

已升序输入上，三数取中在 `n = 10⁶` 时慢了 **13.5 倍**，而且规模翻倍时间翻 2.8 倍 —— 已经不是 `n log n` 的形状。原因如下：

```text
一次划分之后，「已升序」的数组被搅成了「近似旋转」的结构：
  [中位数, 1, 2, 3, ..., 0, 中位数+1, ...]
再取 a[lo]、a[mid]、a[hi] 三个位置的中位数 → 恰好是「次小值」
   → 划分成 1 : (n-2)，几乎最差
这种「被一次划分制造出来的伪有序结构」会一层层重复，三数取中反复被骗
```

**随机 pivot 没有这个弱点的原因**：它不依赖数据的位置分布，任何固定的采样规则都可能被数据的残余结构骗到，而随机采样不会。

> 这就是本章最想传达的一条工程经验：**防守退化输入，要靠随机化，而不是靠「更聪明的采样」。** 换句话说：不要试图猜数据长什么样，直接让对手猜不到你选哪个 pivot。

## 028.5 双语言实现

### 028.5.1 Java

```java
import java.util.concurrent.ThreadLocalRandom;

class Solution {

    // ============ 解法一：三路快排（随机 pivot） ============
    public int[] sortArray(int[] nums) {
        quickSort(nums, 0, nums.length - 1);
        return nums;
    }

    private void quickSort(int[] a, int lo, int hi) {
        while (lo < hi) {
            // 小区间换插入排序：< 12 个元素时三路划分的固定开销大于收益
            if (hi - lo < 12) {
                insertionSort(a, lo, hi);
                return;
            }
            // 随机 pivot：唯一能挡住「构造好的最坏输入」的手段
            int p = ThreadLocalRandom.current().nextInt(lo, hi + 1);
            swap(a, lo, p);

            // 三路划分：[lo, lt) < pivot，[lt, gt] == pivot，(gt, hi] > pivot
            int pivot = a[lo];
            int lt = lo, i = lo + 1, gt = hi;
            while (i <= gt) {
                if (a[i] < pivot) {
                    swap(a, lt++, i++);
                } else if (a[i] > pivot) {
                    swap(a, i, gt--);      // 换过来的元素还没看过，i 不前进
                } else {
                    i++;                   // 相等元素不进任何一侧，直接跳过
                }
            }

            // 先递归短边、循环长边 → 栈深 O(log n)，不长成一条 n 深的链
            if (lt - lo < hi - gt) {
                quickSort(a, lo, lt - 1);
                lo = gt + 1;
            } else {
                quickSort(a, gt + 1, hi);
                hi = lt - 1;
            }
        }
    }

    private void insertionSort(int[] a, int lo, int hi) {
        for (int i = lo + 1; i <= hi; i++) {
            int v = a[i], j = i - 1;
            while (j >= lo && a[j] > v) {
                a[j + 1] = a[j];
                j--;
            }
            a[j + 1] = v;
        }
    }

    private void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }

    // ============ 解法二：归并排序（稳定） ============
    public int[] sortArrayMerge(int[] nums) {
        if (nums.length > 1) {
            int[] buf = new int[nums.length];   // 只分配一次，递归里复用
            mergeSort(nums, buf, 0, nums.length - 1);
        }
        return nums;
    }

    private void mergeSort(int[] a, int[] buf, int lo, int hi) {
        if (lo >= hi) return;
        int mid = lo + (hi - lo) / 2;
        mergeSort(a, buf, lo, mid);
        mergeSort(a, buf, mid + 1, hi);
        if (a[mid] <= a[mid + 1]) return;       // 已经接得上，跳过合并（近似有序时快 14 倍）

        System.arraycopy(a, lo, buf, lo, hi - lo + 1);
        int i = lo, j = mid + 1;
        for (int k = lo; k <= hi; k++) {
            if (i > mid) {
                a[k] = buf[j++];
            } else if (j > hi) {
                a[k] = buf[i++];
            } else if (buf[j] < buf[i]) {
                a[k] = buf[j++];               // 严格小于才取右边 → 稳定
            } else {
                a[k] = buf[i++];
            }
        }
    }

    // ============ 解法三：堆排序（原地 O(1)） ============
    public int[] sortArrayHeap(int[] nums) {
        int n = nums.length;
        for (int i = n / 2 - 1; i >= 0; i--) siftDown(nums, i, n);   // 建堆 O(n)
        for (int end = n - 1; end > 0; end--) {
            swap(nums, 0, end);                 // 堆顶（最大值）归位到 end
            siftDown(nums, 0, end);             // 注意第三个参数是 end，不是 n
        }
        return nums;
    }

    private void siftDown(int[] a, int i, int n) {
        while (true) {
            int big = i;
            int l = 2 * i + 1, r = 2 * i + 2;
            if (l < n && a[l] > a[big]) big = l;
            if (r < n && a[r] > a[big]) big = r;
            if (big == i) return;               // 已比两个孩子都大，停下
            swap(a, i, big);
            i = big;
        }
    }
}
```

### 028.5.2 Go

```go
package main

import (
	"fmt"
	"math/rand"
	"sort"
	"time"
)

// ============ 解法一：三路快排（随机 pivot） ============
// 注意：LeetCode 只提交 sortArray 及其被调用的函数，main 是本地的自检入口
func sortArray(nums []int) []int {
	quickSort(nums, 0, len(nums)-1)
	return nums
}

func quickSort(a []int, lo, hi int) {
	for lo < hi {
		// 小区间换插入排序：递归到 12 个元素以下时，三路划分的固定开销大于收益
		if hi-lo < 12 {
			insertionSort(a, lo, hi)
			return
		}

		// 随机取 pivot。注意 Go 1.20 之前全局 rand 的种子固定是 1，
		// 理论上可以被构造数据打中；线上代码应改用 rand.New(rand.NewSource(time.Now().UnixNano()))
		p := lo + rand.Intn(hi-lo+1)
		a[lo], a[p] = a[p], a[lo]

		lt, gt := partition3(a, lo, hi)

		// 先递归较短的一段，较长的一段用循环消掉 → 栈深 O(log n)
		if lt-lo < hi-gt {
			quickSort(a, lo, lt-1)
			lo = gt + 1
		} else {
			quickSort(a, gt+1, hi)
			hi = lt - 1
		}
	}
}

// partition3 返回等值区的左右边界：a[lo..lt-1] < pivot，a[lt..gt] == pivot，a[gt+1..hi] > pivot
func partition3(a []int, lo, hi int) (int, int) {
	pivot := a[lo] // 调用方已把选中的 pivot 换到 lo
	lt, i, gt := lo, lo+1, hi
	for i <= gt {
		if a[i] < pivot {
			a[lt], a[i] = a[i], a[lt]
			lt++
			i++
		} else if a[i] > pivot {
			a[i], a[gt] = a[gt], a[i]
			gt--
			// 这里 i 不前进：换过来的 a[gt] 还没被检查过
		} else {
			i++ // 相等元素原地不动，直接跳过
		}
	}
	return lt, gt
}

func insertionSort(a []int, lo, hi int) {
	for i := lo + 1; i <= hi; i++ {
		v := a[i]
		j := i - 1
		for j >= lo && a[j] > v {
			a[j+1] = a[j]
			j--
		}
		a[j+1] = v
	}
}

// ============ 解法二：归并排序（稳定） ============
func sortArrayMerge(nums []int) []int {
	if len(nums) > 1 {
		buf := make([]int, len(nums)) // 只分配一次，递归里复用
		mergeSort(nums, buf, 0, len(nums)-1)
	}
	return nums
}

func mergeSort(a, buf []int, lo, hi int) {
	if lo >= hi {
		return
	}
	mid := lo + (hi-lo)/2
	mergeSort(a, buf, lo, mid)
	mergeSort(a, buf, mid+1, hi)

	// 两段已经「接得上」就不必合并：对近似有序输入，这一步让复杂度接近 O(n)
	if a[mid] <= a[mid+1] {
		return
	}

	copy(buf[lo:hi+1], a[lo:hi+1])
	i, j := lo, mid+1
	for k := lo; k <= hi; k++ {
		if i > mid {
			a[k] = buf[j]
			j++
		} else if j > hi {
			a[k] = buf[i]
			i++
		} else if buf[j] < buf[i] {
			// 严格小于才取右边：相等时先取左边，这就是「稳定」的全部来源
			a[k] = buf[j]
			j++
		} else {
			a[k] = buf[i]
			i++
		}
	}
}

// ============ 解法三：堆排序（原地 O(1)） ============
// 这里故意不用 container/heap：它是「在切片上套一层接口」，而 LC912 要求原地排序，
// 直接用下标寻址的 siftDown 常数最小（用了反而多一层 interface 装箱）
func sortArrayHeap(nums []int) []int {
	n := len(nums)
	// 1) 建堆：从最后一个非叶结点往前下沉，总代价 O(n) 而不是 O(n log n)
	for i := n/2 - 1; i >= 0; i-- {
		siftDown(nums, i, n)
	}
	// 2) 反复把堆顶（当前最大值）换到末尾，再对缩小后的堆下沉
	for end := n - 1; end > 0; end-- {
		nums[0], nums[end] = nums[end], nums[0]
		siftDown(nums, 0, end) // 第三个参数是 end：已排好的尾部不能再进堆
	}
	return nums
}

// siftDown 让 a[i] 在大小为 n 的大顶堆里沉到正确位置（迭代写法，省掉递归）
func siftDown(a []int, i, n int) {
	for {
		big := i
		if l := 2*i + 1; l < n && a[l] > a[big] {
			big = l
		}
		if r := 2*i + 2; r < n && a[r] > a[big] {
			big = r
		}
		if big == i {
			return // 已经比两个孩子都大，停止
		}
		a[i], a[big] = a[big], a[i]
		i = big
	}
}

				row[idx] = float64(best.Microseconds()) / 1000.0
			}
			fmt.Printf("%-6s %-10s %10.3f %10.3f\n", name, gname, row[0], row[1])
		}
	}
}
```

### 028.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 随机数来源 | `ThreadLocalRandom.current().nextInt(lo, hi+1)`，无锁 | `rand.Intn(n)` + 偏移；`math/rand` 全局源在 1.20 前固定种子 | Java 天然线程安全；Go 想并发用要自己 `rand.New` 一份，别共享全局源 |
| 数组传递 | 传引用，`nums` 就是原数组 | 切片是「指针 + 长度 + 容量」三元组 | Go 里 `append([]int(nil), src...)` 才是真拷贝；`src[:]` 只是别名，改了原数组也跟着变 |
| 批量拷贝 | `System.arraycopy`（JVM intrinsic，最快） | `copy(dst, src)`（编译成 `memmove`） | 归并的缓冲拷贝两边都是一条指令级操作，别手写 for 循环 |
| 交换 | 需要辅助方法 `swap(a,i,j)` | 支持 `a[i], a[j] = a[j], a[i]` 多重赋值 | Go 少一层函数调用（会被内联）；Java 的 `swap` 也会被 JIT 内联，差别不大 |
| 堆 | `PriorityQueue` 内置，`siftDown` 是私有的 | `container/heap` 要自己实现 5 个方法 | 028 的堆排是**原地**排序，两边都不该用容器堆；到 031/033 才需要 |
| 递归深度 | 默认栈约 512 KB ~ 1 MB，深递归直接 `StackOverflowError` | goroutine 栈从 2 KB 起可动态增长到 1 GB | Go 对深递归更宽容，**但这不该成为写深递归的理由**：`O(log n)` 栈是设计出来的，不是环境兜住的 |
| 计时 | `System.nanoTime()` | `time.Now()` / `time.Since` | 两边都要「多次取最快」+ 预热，否则第一行数据全是 JIT / 冷缓存噪声 |

## 028.6 复杂度与常见坑

### 028.6.1 复杂度推导（写结论不算本事，要能推）

**三路快排**

- 期望时间 `O(n log n)`：随机 pivot 下，任意一次划分落在中间 50% 区间的概率是 1/2，所以「连续 k 次都切在边缘」的概率是 `2^-k`；期望递归层数 `O(log n)`，每层总扫描量 `O(n)`。更严格的做法是对 `T(n) = T(k) + T(n-1-k) + n` 取期望，得 `E[T(n)] ≤ 2n ln n ≈ 1.39 n log₂n`。
- 最坏 `O(n²)`：每次划分都是 `1 : n-1`（随机化后攻击者无法构造，但理论上仍存在）。
- 空间 `O(log n)`：先递归短边保证栈深；**若先递归长边，最坏栈深是 `O(n)`**。
- 全相同输入：一次划分把整个数组变成等值区，`T(n) = O(n)` —— 这是三路划分相对两路划分的全部价值。

**归并排序**

- 时间 `O(n log n)`：`T(n) = 2T(n/2) + O(n)`，由主定理（`a=2, b=2, d=1`）得 `Θ(n log n)`。递归树有 `log₂n` 层，每层合并总量 `n`。
- 空间 `O(n)`：`buf` + `O(log n)` 栈。**自底向上归并可以做到 `O(1)` 额外空间**（只改循环变量，不递归），这也是 LC 148 链表排序的常用写法。
- 稳定性来自合并时的 `buf[j] < buf[i]`（严格小于）。

**堆排序**

- 建堆 `O(n)`：直觉上每次下沉 `O(log n)`、共 `n/2` 次，看着是 `O(n log n)`；但高度为 `h` 的结点只有 `n/2^(h+1)` 个，总代价 `Σ n·h/2^(h+1) = O(n)`。
- 排序 `O(n log n)`：`n-1` 次「换顶 + 下沉」，每次 `O(log n)`。
- 空间 `O(1)`：这是它唯一的、也是决定性的优势。

### 028.6.2 八个真实踩过的坑

1. **两路划分 + 全相同元素 → O(n²)**。实测 `n=4·10³` 的全 1 数组要 9.05 ms 且呈平方增长。修法：三路划分（本章做法），或随机化 + 「等于 pivot 的元素随机分到两侧」。
2. **先递归长边 → 栈溢出**。`n = 5·10⁴` 的有序输入配固定 pivot，递归深度 5 万层，Java 直接 `StackOverflowError`。修法：先递归短边 + `while` 消长边。
3. **归并写成 `buf[j] <= buf[i]` 取右边 → 不稳定**。本题不检查稳定性，所以这个 bug 在 LC912 上「测不出来」，但搬到 LC 148 / 生产线上的多键排序就出错。**测不出来的 bug 最危险。**
4. **每次 `merge` 都 `new` 一个临时数组**。`n = 10⁵` 会分配 `log n ≈ 17` 层 × 平均 `n/2` 个元素，GC 压力直接把 10 ms 变成 60 ms。修法：`buf` 在外层分配一次传进去。
5. **堆排 `siftDown` 的第三个参数写成 `n`**。已排好的尾部被重新卷进堆，结果错误且变慢。正确写法是传 `end`（Java 版与 Go 版都标注了这一行）。
6. **建堆从 `i = n/2` 开始**。`n/2` 是最后一个叶子的下标，它没有孩子，多做一次空转；应该是 `n/2 - 1`（Go 里 `n/2-1` 在 `n<2` 时是 `-1`，循环条件 `i >= 0` 用 `int` 时安全，但用 `size_t` / 无符号类型会死循环）。
7. **`rand` 没播种 / 播种在循环里**。Go 1.20 之前不 `rand.Seed` 就固定种子 1；Java 每次 `new Random()` 在纳秒级连续调用时可能拿到同一个种子。修法：Go 用 `rand.New(rand.NewSource(time.Now().UnixNano()))`，Java 用 `ThreadLocalRandom`。
8. **以为 `Arrays.sort(int[])` 是稳定排序**。Java 对**基本类型**用双轴快排（不稳定、无对象开销），对**引用类型**用 TimSort（稳定）。LeetCode 判题只看数值，所以这个区别在刷题时看不出来，但它决定了你在业务代码里能不能直接 `Arrays.sort(pairs)`。

### 028.6.3 面试官最爱追问的三个问题

**Q1：为什么工程里快排用得比归并多，尽管两者都是 O(n log n)？**
> 「三个原因：① **常数与缓存**——快排的划分是顺序扫描，归并要在两个数组间来回搬，实测同样的数据快排快 25%~35%；② **空间**——快排 `O(log n)` 栈，归并要 `O(n)` 缓冲；③ **原地**——快排不需要额外的大数组。反过来说，只要要求**稳定**或数据在**链表 / 外存**上，归并立刻反超，因为链表归并不需要随机访问，而快排的分区需要。」

**Q2：随机化之后，快排的最坏情况还存在吗？**
> 「理论上存在：随机数仍然可能连续选中极端值，概率约 `2^-n` 量级，实际可以视为不存在。但工程上还有两条补充防守：① **内省排序（introsort）**——记录递归深度，超过 `2·log₂n` 就切换成堆排序，把最坏情况钉死在 `O(n log n)`（C++ `std::sort` 就是这么做的）；② **三路划分**——专门防守「大量重复元素」这种不靠随机性、而是靠数据本身就让两路划分退化的输入。所以完整的答案不是「随机化就够了」，而是「随机化 + 三路划分 + 深度上限」。」

**Q3：如果数据有 100 GB，内存只有 16 GB，怎么排？**
> 「外部排序：① **分块**——每次读 16 GB 以内在内存里排好，写成有序的临时文件（run）；② **多路归并**——用一个小顶堆维护这 `k` 个文件当前的头元素，每次弹出最小的写进输出文件，弹完再从对应文件读下一个。时间 `O(n log n)`（多一层 `log k` 常数），空间 `O(块大小 + k)`。这里 `k` 不能太大（每个文件要占一个读缓冲），所以常做**多轮归并**：先 100 路合并成 10 个文件，再 10 路合并成 1 个。」
