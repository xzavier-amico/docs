## 044.1 题目

**原题链接**：<https://leetcode.cn/problems/reverse-linked-list/>

### 题意重述（把隐含条件补齐）

给你单链表的头结点 `head`，请把整条链表**原地反转**，返回反转后的头结点。

一句话的题干，藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **单链表，只有 `next`** | 「单链表」 | 想「从后往前遍历」是不可能的，只能改 `next` 的指向 |
| **必须原地反转** | 「反转链表」这个动词 | 新建一条链、头插法复制一遍能 AC，但面试官下一句就是「能不能不新建结点」 |
| **不能只交换 `val`** | 指针题的默认约定 | 有些题解把值倒序写回原结点，`[1,2,3]` 也能变 `[3,2,1]`，但结点身份没变；一旦结点还挂着别的引用（图、缓存）就全错 |
| **空链表是合法输入** | `0 <= 结点数` | `head == null` 时直接 `head.next` 会 NPE |
| **结点数 ≤ 5000** | 数据范围 | 递归写法深度 = n，5000 层在 Java 默认栈（约 1 MB）里刚好卡在能过的边缘，1e5 就 StackOverflow |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= 结点数 <= 5000` | 很小 | 任何 O(n) 都过；**这题的评分点不在时间，在空间** |
| `-5000 <= Node.val <= 5000` | 有负数、可能全相等 | 别用「值当哨兵」，也别假设值唯一 |
| 返回值是**新头结点** | 不是长度、不是数组 | 反转后原头变成尾巴，必须返回原尾 |
| 空间期望 O(1) | 面试追问的默认要求 | 迭代三指针是正解；递归是 O(n) 栈空间，要主动说明 |

> 💡 **量级 → 算法**：`n ≤ 5000` 说明出题人根本没打算用规模卡你。链表题的规模通常给得很宽松（5000、10⁴、10⁵），**因为链表题的难点是「指针别丢、别成环」，不是「复杂度」**。所以在链表章里，判断一个解法好坏的第一标准是「**改了几条边、有没有临时变量兜底**」。

### 示例

```text
输入：head = [1,2,3,4,5]
输出：      [5,4,3,2,1]

输入：head = [1,2]
输出：      [2,1]

输入：head = []
输出：      []
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① []                → head == null，任何 head.next 都会崩
② [1]               → 单结点：prev 初值 null 直接当答案返回，不能返回 head
③ [1,2]             → 最短的「需要真的改一条边」的输入
④ [7,7,7,7,7]       → 全相等：如果实现里用值做判断（"遇到相同值就停"）会死循环
⑤ 长度 5000 的链      → 递归写法在这里逼近栈上限，必须实测
```

第 ④ 条最阴：有人为了「顺便去重」写了 `if (cur.val != nxt.val)` 之类的判断，在全是相等值的链上 `next` 永远不改，直接超时。

## 044.2 从暴力到最优：第一个念头为什么错

### 第一步：两个「能过题但不合格」的暴力

**暴力 A：把值抄进数组，倒着写回**

```text
vals = []
for p in list: vals.append(p.val)
p = head
for i = n-1 downto 0: p.val = vals[i]; p = p.next
```

- 时间 O(n)，空间 **O(n)**。
- 它「能 AC」，因为 `[1,2,3]` 反转后每个位置的值确实变了。
- **但它没有反转链表，只是反转了值。** 如果把结点想象成带 `id` 的对象，反转后 `id` 顺序完全没变。工程里这意味着「持有原结点的外部引用全部失效」。

**暴力 B：新建一条链，头插法**

```text
newHead = null
for p in list:
    node = new Node(p.val)
    node.next = newHead
    newHead = node
```

- 时间 O(n)，空间 **O(n)**（n 个新结点）。
- 它真的反转了结构，但**没有原地**。内存翻倍，且原链变成垃圾。

### 第二步：为什么它们不够 —— 用数字说话

`n = 5000` 时，方案 A 多一个 5000 元素的数组（约 20 KB），方案 B 多 5000 个结点（约 120 KB）。在 LeetCode 上都是「能过」。

**那为什么还要 O(1)？** 三个理由，都要能在面试里说出来：

1. **追问一定会来。** 「空间能不能 O(1)？」是 LC206 的标准第二问，答不出来等于只做了一半。
2. **规模会变。** 同一道题放到 10⁸ 个结点的场景（比如日志链、内存块链），O(n) 额外空间直接 OOM。
3. **链表题的本质是「改指针」，不是「搬数据」。** 出题人想看你操作 `next`，不是操作 `val`。

### 第三步：卡点在哪

把问题翻译成一句话：

> **要让 `b.next = a`，可做完这一步，`b` 原来指向的 `c` 就再也找不到了。**

这就是全部难点。单向链表里，`next` 是**唯一的路标**。你一旦把 `a.next` 从 `b` 改成别的，`b` 之后的整条链就变成了「没有入口的孤岛」——除非你**提前**把入口存进变量。

```
改指针之前的链：
    a ───→ b ───→ c ───→ d ───→ ∅
    ↑
  唯一入口

执行 a.next = 别的东西之后：
    a ┄┄→ ✗            b ───→ c ───→ d ───→ ∅
                       ↑
                 找不到入口了（b 只被 a.next 指着）
```

所以卡点不是「怎么反转」，而是「**反转的副作用是丢失后续链，怎么在丢失前留一手**」。

### 第四步：灵感的来源 —— 三个变量就够

只要引入两个变量：

- `prev`：已经反转好的那段的头（初始 `null`）
- `nxt`：`cur` 的下一站（**在改 `cur.next` 之前**先存下来）

于是每一步变成四句固定动作：

```
① nxt  = cur.next     // 先存后断：把下一站记下来
② cur.next = prev     // 掰箭头
③ prev = cur          // prev 右移一格
④ cur  = nxt          // cur 右移一格
```

> **这四句就是本章要背走的东西**，也是 045（区间反转）、046（K 个一组）、051（重排链表）、052（归并）里反复出现的同一个动作序列。**链表章的统一语言是「哑结点 + 指针三件套（prev/cur/next）+ 先存后断」**：哑结点负责消灭「头结点被改」的特判，三件套负责在只有单向指针的前提下不丢路，先存后断负责让「掰箭头」这件事变得可逆。

### 另一条路：递归

递归把「`prev` 这个变量」换成「**函数调用栈**」：

```
reverse(head):
    if head == null or head.next == null: return head
    newHead = reverse(head.next)     // 先把后面整段反好
    head.next.next = head            // 让原后继指回自己
    head.next = null                 // 自己成为新尾巴
    return newHead
```

它同样正确，但空间是 **O(n)（栈帧）**。`n = 5000` 时 Java 默认栈能扛住，`n = 10⁵` 就崩。所以：

- **面试写迭代**（O(1) 空间，且没有栈溢出风险）。
- **递归要会写**，因为它是「链表 + 递归」这一类题（如 024 两两交换、025 K 个一组递归版）的思路源头，而且能一句话讲清「反转 = 反转后面 + 修一条边」。

## 044.3 原理拆解

### 044.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 抄值到数组再写回 | O(n) | O(n) | 6 行 | **结点身份必须保持**时全错；被追问原地就露馅 |
| 新建链 + 头插 | O(n) | O(n) | 8 行 | 内存受限；要求原地；原链还要被别人用 |
| 递归 | O(n) | **O(n) 栈** | 6 行 | n 很大（≥10⁵）栈溢出；不允许改函数签名时麻烦 |
| **迭代三指针** ✅ | **O(n)** | **O(1)** | **8 行** | 几乎不会输；唯一代价是「写错就丢链」 |
| 用栈倒序 | O(n) | O(n) | 10 行 | 纯炫技，没有任何优势 |

**为什么迭代三指针是唯一推荐**：它是唯一同时满足「O(n) 时间 + O(1) 空间 + 不改值 + 不新建结点」的写法，而这四条正好是面试的四个追问方向。

### 044.3.2 为什么这个做法是对的（正确性论证）

**循环不变量**（写在注释里，面试也这么说）：

> 每轮循环开始前：`prev` 指向「原链表前 k 个结点反转后」的头；`cur` 指向「原链表第 k+1 个结点」；并且 **`prev` 段与 `cur` 段之间没有任何边相连**。

**初始化**（k = 0）：`prev = null`（空前缀反转后还是空），`cur = head`（第 1 个结点）。成立。

**保持**（第 k 轮，设 `p = cur`）：

1. 记 `nxt = p.next`。因为前缀只有 k 个结点，`p` 是第 k+1 个，它的原后继就是第 k+2 个。
2. 令 `p.next = prev`。此时「前 k+1 个结点」被反转并串成 `p → … → 原第 1 个 → null`，头是 `p`；`cur` 段（原第 k+2 个起）仍是原样，且与 `p` 段断开。
3. `prev = p`，`cur = nxt`。不变量在新 k+1 上成立。

**终止**：`cur == null` 表示原链表已经全部搬进前缀，此时 `prev` 是反转后的头，也是原链表的尾。返回 `prev` 正确。∎

**再证「不会成环」**：每次 `cur.next = prev` 之后，`cur` 段的头是 `nxt`，而 `prev` 段里所有结点的 `next` 都指向「更靠前的结点」或 `null`，不可能指回 `cur` 段。所以两段永远不相交，最终拼成一条无环链。∎

> **这个论证的价值**：它同时解释了「为什么 `nxt` 必须先存」（第 1 步必须在第 2 步之前）和「为什么最后返回 `prev` 而不是 `cur`」（终止时 `cur` 已经是 null）。

### 044.3.3 通用解题思路（可迁移的那一层）

**链表章的统一语言：哑结点 + 指针三件套（prev/cur/next）+ 先存后断。**

```
原始问题：把一条单向链的箭头全部反向
         ↓ 识别卡点
卡点：    单向链表只有 next，改一条边就丢后续
         ↓ 引入两个变量
关键：    prev 记录"已处理部分"，nxt 记录"未处理部分的入口"
         ↓ 固定动作序列
模板：    nxt = cur.next; cur.next = prev; prev = cur; cur = nxt
         ↓ 外层的通用壳
外壳：    dummy 消灭头结点特判；循环结束时 prev/cur 停在正确答案上
```

四个零件各管一件事，这套语言在链表章通用：

| 零件 | 解决什么问题 | 本章用在哪 |
| --- | --- | --- |
| **哑结点 `dummy`** | 头结点可能被修改 / 被删除，特判太多 | 044 用不到（头一定变），045/046/047/049 必用 |
| **`prev`** | 「已处理部分」的入口 | 反转后的新头 |
| **`cur`** | 「正在处理」的结点 | 当前要掰箭头的结点 |
| **`nxt`（先存）** | 改边之后仍能继续走 | 唯一防止丢链的手段 |

属于同一模型的题：

| 题 | 被复用的部分 | 多加了什么 |
| --- | --- | --- |
| [LC 92 反转链表 II](https://leetcode.cn/problems/reverse-linked-list-ii/) | 整段反转 | 区间边界定位 + 接回 |
| [LC 25 K 个一组翻转链表](https://leetcode.cn/problems/reverse-nodes-in-k-group/) | 整段反转 | 分组探路 + 组间接缝 |
| [LC 24 两两交换链表中的节点](https://leetcode.cn/problems/swap-nodes-in-pairs/) | K = 2 的特例 | 无 |
| [LC 143 重排链表](https://leetcode.cn/problems/reorder-list/) | 反转后半段 | 找中点 + 交替合并 |
| [LC 234 回文链表](https://leetcode.cn/problems/palindrome-linked-list/) | 反转后半段 | 比较 + （可选）复原 |

### 044.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只反转**前 k 个** | 提前停 | 循环条件从 `cur != null` 改成计数器 `< k`；见 045 |
| **每 k 个**一组反转 | 多一层分组 | 先探路再反转，见 046 |
| 反转**区间** `[m, n]` | 头可能不变 | 必须上哑结点，见 045 |
| 要求**不能改 `next`**，只能改 `val` | 结构冻结 | 用栈/数组存值再回填，O(n) 空间 |
| **双向链表**反转 | 多一个 `prev` | 遍历一遍，交换每个结点的 `prev`/`next`，再换头尾 |
| **数据流**（边读边反转） | 不能二次遍历 | 三指针天然适配：来一个掰一个 |
| 反转后要能**再反回来** | 需要逆操作 | 再调一次 `reverseList` 即可（反转是对合运算，做两次等于没做） |

## 044.4 图解推演

### 044.4.1 三个指针逐步右移（以 `[1,2,3]` 为例）

```text
初始状态：prev = ∅，cur = 1
        prev            cur
         ↓               ↓
        ∅          1 ───→ 2 ───→ 3 ───→ ∅

第 1 轮：nxt = 2（先存）
        ① cur.next = prev  →  1 指向 ∅
        ② prev = 1        ③ cur = 2
                prev        cur
                 ↓           ↓
        ∅ ←── 1        2 ───→ 3 ───→ ∅
        （已反转段：1）  （未处理段：2→3）

第 2 轮：nxt = 3（先存）
        ① cur.next = prev  →  2 指向 1
        ② prev = 2        ③ cur = 3
                        prev  cur
                         ↓     ↓
        ∅ ←── 1 ←── 2     3 ───→ ∅

第 3 轮：nxt = ∅（先存，cur 已是最后）
        ① cur.next = prev  →  3 指向 2
        ② prev = 3        ③ cur = ∅
                              prev   cur
                               ↓      ↓
        ∅ ←── 1 ←── 2 ←── 3        ∅

循环结束：cur == ∅，返回 prev = 3（新头，也是原链的表尾）
```

### 044.4.2 每一轮的四条语句与状态表

| 轮次 | `cur.val` | ① `nxt` | ② `cur.next` 改成 | ③ `prev` | ④ `cur` | 反转完成的前缀 |
| --- | --- | --- | --- | --- | --- | --- |
| 初始 | 1 | — | — | ∅ | 1 | 空 |
| 1 | 1 | 2 | ∅ | 1 | 2 | `1→∅` |
| 2 | 2 | 3 | 1 | 2 | 3 | `2→1→∅` |
| 3 | 3 | ∅ | 2 | 3 | ∅ | `3→2→1→∅` |
| 结束 | ∅ | — | — | **3** | ∅ | 返回 3 |

### 044.4.3 为什么「先存后断」是必须的（反例轨迹）

```text
❌ 顺序颠倒：先断后存

  初始：prev=∅，cur=1，1.next = 2
  执行 1.next = prev(∅)

        ∅ ←── 1      ✗ 2 和 3 彻底失联

  再执行 nxt = cur.next  →  nxt = ∅（错！本该是 2）
  于是 cur = ∅，循环结束，返回 prev = 1
  最终结果：[1]  ← 后面两个结点被垃圾回收吃掉了

┌──────────────── 一句话总结 ────────────────┐
│ 改 next 之前，next 是通往后续的唯一路标；      │
│ 改完之后它就是历史了，必须先抄一份。          │
└────────────────────────────────────────────┘
```

### 044.4.4 迭代 vs 递归：两条路线对比

```text
                    ┌────────── 输入 head ──────────┐
                    │                              │
        ┌───────────▼───────────┐      ┌───────────▼───────────┐
        │ 迭代三指针             │      │ 递归                   │
        │ O(n) 时间 / O(1) 空间  │      │ O(n) 时间 / O(n) 栈空间 │
        └───────────┬───────────┘      └───────────┬───────────┘
                    │                              │
        prev 变量显式右移                 prev 由调用栈隐式提供
        掰箭头顺序：从前往后              掰箭头顺序：从后往前（回溯时）
                    │                              │
        ✅ 无栈溢出风险                    ❌ n ≥ 10⁵ 会 StackOverflow
        ✅ 面试首选                        ✅ 是「链表+递归」系列的思想源头
```

## 044.5 双语言实现

### 044.5.1 Java

```java
// LeetCode 判题环境已提供 ListNode，本地自建时保留这份定义
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}

class Solution {
    // 迭代：prev / cur / nxt 三指针右移
    public ListNode reverseList(ListNode head) {
        ListNode prev = null; // 反转后 prev 就是新头
        ListNode cur = head;
        while (cur != null) {
            ListNode nxt = cur.next; // ① 先存：断链前必须记住下一站
            cur.next = prev;         // ② 后断：箭头掉头
            prev = cur;              // ③ prev 右移
            cur = nxt;               // ④ cur 右移
        }
        return prev;                 // cur 一定为 null，prev 停在原尾巴
    }

    // 递归：先反后面，再处理「自己 ↔ 原后继」这一条边
    public ListNode reverseListRec(ListNode head) {
        if (head == null || head.next == null) {
            return head; // 空链或单结点，反转后还是自己
        }
        ListNode newHead = reverseListRec(head.next);
        head.next.next = head; // 原后继指回自己
        head.next = null;      // 自己是新尾巴，必须置空，否则成环
        return newHead;
    }
}
```

**三处「为什么」**：

1. `prev` 初值是 `null` 而不是 `head`：因为反转后原头要变成尾巴，尾巴的 `next` 必须是 `null`。
2. `return prev` 而不是 `return head`：循环结束时 `head` 已经是尾巴，返回它会得到一条只有自己的链。
3. 递归里 `head.next = null` 不能省：不置空的话，原头（新尾巴）的 `next` 仍然指着第二个结点，整条链成环，LeetCode 判题时序列化会超时。

### 044.5.2 Go

```go
package main

// ListNode 是链表结点的统一定义（LeetCode 判题环境已提供，本地自建）
type ListNode struct {
	Val  int
	Next *ListNode
}

// 迭代：三指针 prev / cur / nxt
func reverseList(head *ListNode) *ListNode {
	var prev *ListNode // nil 就是"空前缀"，Go 的零值正好是我们要的初值
	cur := head
	for cur != nil {
		nxt := cur.Next // ① 先存
		cur.Next = prev // ② 后断
		prev = cur      // ③ prev 右移
		cur = nxt       // ④ cur 右移
	}
	return prev
}

// 递归：reverseListRec(head.Next) 返回反转后的新头
func reverseListRec(head *ListNode) *ListNode {
	if head == nil || head.Next == nil {
		return head
	}
	newHead := reverseListRec(head.Next) // 先把后面这段反好
	head.Next.Next = head                // 让后继指回自己
	head.Next = nil                      // 自己是新尾巴，必须断
	return newHead
}
```

### 044.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 「空指针」的写法 | `null` | `nil` | 语义相同；Go 里 `var prev *ListNode` 的零值就是 `nil`，不用显式赋 |
| 声明位置 | 循环内 `ListNode nxt = ...` | 循环内 `nxt := ...` | Go 的 `:=` 只在循环体内生效，每轮都是新变量，和 Java 行为一致 |
| 判空顺序 | `head == null \|\| head.next == null` | `head == nil \|\| head.Next == nil` | 短路求值两边都有，**顺序不能反**，否则空链时取 `.next` 崩 |
| 函数 vs 方法 | 类内方法，`this` 隐含 | 顶层函数，无接收者 | 结构体方法在本章用不上；054 才会用到 `(c *LRUCache)` |
| 递归栈 | 默认约 1 MB，约 1e4 层 | goroutine 栈从 2 KB 起动态增长，可到 GB 级 | **n = 10⁵ 时 Java 递归崩、Go 递归可能活**，但都不该在生产里这么写 |
| 返回值 | 必须显式 `return` | 必须显式 `return` | 无差异 |

### 044.5.4 对拍测试（Go，2 万次随机 + 边界）

```go
package main

import (
	"math/rand"
	"testing"
)

func build(a []int) *ListNode {
	dummy := &ListNode{}
	t := dummy
	for _, v := range a {
		t.Next = &ListNode{Val: v}
		t = t.Next
	}
	return dummy.Next
}

func dump(h *ListNode) []int {
	out := []int{}
	for p := h; p != nil; p = p.Next {
		out = append(out, p.Val)
		if len(out) > 100000 {
			panic("疑似有环")
		}
	}
	return out
}

func TestReverseListRandom(t *testing.T) {
	r := rand.New(rand.NewSource(44))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(12) // 含 0（空链表）
		a := make([]int, n)
		for i := range a {
			a[i] = r.Intn(5) // 值域很小，制造大量相等值
		}
		want := make([]int, n)
		for i := range a {
			want[n-1-i] = a[i]
		}
		got := dump(reverseList(build(a)))
		if len(got) != len(want) {
			t.Fatalf("iter=%d a=%v got=%v want=%v", iter, a, got, want)
		}
		for i := range got {
			if got[i] != want[i] {
				t.Fatalf("iter=%d a=%v got=%v want=%v", iter, a, got, want)
			}
		}
		// 递归版跑同一批数据
		if got2 := dump(reverseListRec(build(a))); len(got2) != len(want) {
			t.Fatalf("rec iter=%d a=%v got=%v want=%v", iter, a, got2, want)
		}
	}
	// 边界：空、单结点、全相等
	if reverseList(nil) != nil {
		t.Fatal("空链表必须返回 nil")
	}
	if got := dump(reverseList(build([]int{7}))); len(got) != 1 || got[0] != 7 {
		t.Fatal("单结点失败")
	}
	if got := dump(reverseList(build([]int{2, 2, 2}))); len(got) != 3 {
		t.Fatal("全相等失败")
	}
}
```

> **对拍的价值**：`dump` 里那个 `len(out) > 100000` 的 panic 是刻意加的 —— 反转写错最容易产生**环**，如果不设上限，测试会挂死在死循环里而不是给你一条清晰的失败信息。**链表题的测试工具必须自带环检测。**

## 044.6 复杂度与常见坑

### 044.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：每轮循环恰好处理一个结点，`cur` 每轮右移一次，最多走 n 步；循环体内是 4 次赋值，常数时间。总操作数 `4n + 1`。
- **空间 O(1)**（迭代）：只用了 `prev` / `cur` / `nxt` 三个指针变量，与 n 无关。
- **空间 O(n)**（递归）：递归深度 = n 层，每层一个栈帧（约几十字节），Java 实测 `n = 5000` 用掉约 300 KB 栈，`n = 2·10⁴` 就接近默认栈上限。
- **为什么迭代不会漏结点**：`nxt` 在改边前已捕获下一站，`cur` 的移动完全依赖 `nxt`，不依赖刚被改掉的 `cur.next`。这是「不漏」的全部依据。

### 044.6.2 七个真实踩过的坑

1. **`return head` 而不是 `return prev`** —— 最经典。`head` 反转后是尾巴，返回它等于返回 `[1]`。
2. **先断后存** —— `cur.next = prev` 写在 `nxt = cur.next` 前面，n ≥ 2 时丢链，只剩第一个结点。
3. **递归忘了 `head.next = null`** —— 只有两个及以上结点时才会成环，`[1]` 和 `[1,2]` 都测不出来，`[1,2,3]` 才崩。判题机上表现为「超出内存 / 序列化超时」。
4. **循环条件写成 `cur.next != null`** —— 最后一个结点永远不反转，`[1,2,3]` 输出 `[2,1,3]`。
5. **`prev` 声明在循环里** —— `ListNode prev = null;` 写进 `while` 体内，每轮重置，最后返回 null。
6. **认为「交换 val」也算反转** —— 面试官追问「结点带其它字段」或「有外部引用」时立刻失效。
7. **递归跑 10⁵ 长度** —— 本地小数据全过，线上 Java StackOverflowError。链表题规模给到 5000 就是为了让递归「刚好能过」，别把它当安全。

### 044.6.3 面试官最爱追问的三个问题

**Q1：为什么必须先保存 `next`？**
> 「因为单向链表里 `next` 是通往后续结点的唯一路标。`cur.next = prev` 一执行，`cur` 原来指向的 `nxt` 就没有任何引用了，后面的整条链变成孤岛。所以顺序只能是『先抄一份路标（`nxt = cur.next`），再改路（`cur.next = prev`），最后沿抄下来的路标前进（`cur = nxt`）』。」

**Q2：递归和迭代怎么选？**
> 「空间上迭代 O(1) 明显更优，所以我默认写迭代。递归的价值在于表达力：`reverse(head) = reverse(head.next) + 修一条边`，这个『先处理子问题，再修接缝』的结构正是 25 题（K 个一组）递归版、24 题（两两交换）的基础。但递归深度等于链长，Java 默认栈大约 1e4 层，n = 10⁵ 会 StackOverflow，生产代码一律迭代。」

**Q3：如果要求「不能改 `next`，只能改 `val`」怎么办？**
> 「那就必须用 O(n) 额外空间：把值按顺序抄进数组，再倒序写回；或者用栈。复杂度变成时间 O(n) / 空间 O(n)。这个约束下不存在 O(1) 的解法，因为『反转』这个语义只能靠重排元素实现，而重排 n 个元素至少需要一个能随机访问的容器——链表本身不提供。」

## 附：本章小结（可背走的三句话）

```text
① 反转 = 三指针右移，固定四句：nxt=cur.next → cur.next=prev → prev=cur → cur=nxt
② 先存后断：改 next 之前 next 是唯一路标，改完就没了
③ 返回 prev 不是 head；递归能写但要能说出 O(n) 栈的代价
```
