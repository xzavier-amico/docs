## 062.1 题目

**原题链接**：<https://leetcode.cn/problems/largest-rectangle-in-histogram/>

### 题意重述（把隐含条件补齐）

给定 `n` 个非负整数 `heights[i]`，代表直方图中每根柱子的高度，**每根柱子的宽度都是 1**，且相邻柱子紧贴。请在这个直方图内部找出一个**面积最大的矩形**，返回它的面积。

一句话说完，但它藏着六个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **矩形必须由「连续的一段柱子」构成** | 「直方图内」+ 柱宽为 1 | 跳过中间的矮柱去拼两段，就是非法矩形 |
| **矩形的高度取这一段的最小高度** | 矩形不能悬空、不能超过任何一根柱子 | 取平均值或最大值都会得到一个「根本不存在的矩形」 |
| **宽度恒为 1 是白送的信息** | 「相邻柱子宽度为 1」 | 宽度 = 下标差；若柱子宽度不等，就要先做前缀和求宽（见 §062.3.4） |
| **高度可以是 0** | `0 <= heights[i]` | 一根 0 高的柱子会把直方图**彻底切断**；全 0 时答案是 0 |
| **答案可能等于 0** | 全 0 输入 | `best` 初始化为 0 即可；初始化为 -1 也没错，但别在最后 `return 0` 硬编码 |
| **返回面积，不返回区间** | 「返回最大的矩形面积」 | 想输出 `(left, right, height)` 时要注意：最大面积可能对应**多个**矩形 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= heights.length <= 10⁵` | n 最大十万 | **O(n²) 必死**：枚举左右端点是 `n(n+1)/2 ≈ 5·10⁹` 个区间。本机实测 `n = 5·10³` 的暴力已需 **12 ms**，按平方外推到 `n = 10⁵` 约 **4.8 s**；单调栈只要 **1.6 ms** |
| `0 <= heights[i] <= 10⁴` | 高度不超过一万 | 最大面积 `10⁵ × 10⁴ = 10⁹ < 2.147·10⁹`，**int 刚好安全**。但这条要能说出来：如果高度放大到 `10⁹`，`h × w` 立刻溢出，必须换 `long` |
| 返回类型 `int` | 与上一条一致 | LeetCode 的签名就是 `int`，说明出题人**刻意**把上界卡在 int32 之内 |
| 允许 `heights[i] == 0` | 非负 | 0 是最好的天然分隔线，也是最好的**哨兵值**（§062.3.3 会用到这一点） |

> 💡 **量级 → 算法**：`n = 10⁵` 是「每个位置只允许被常数次访问」的硬指标。而本题的结构是「每个位置都在被反复问同一个问题（我左右能延伸多远）」—— **这正是单调栈要消灭的重复计算**。

### 示例

```
输入：heights = [2, 1, 5, 6, 2, 3]
输出：10
解释：最大的矩形是以高度 5 为高，覆盖下标 2、3 两列 → 5 × 2 = 10

        │
     6  │        ┌─┐
     5  │      ┌─┼─┤
     4  │      │ │ │
     3  │      │ │ │     ┌─┐
     2  │  ┌─┐ │ │ │  ┌─┼─┤
     1  │  │ │ │ │ │  │ │ │
        └──┴─┴─┴─┴─┴──┴─┴─┴──
下标:      0   1   2   3   4   5
                └───┬───┘
              5 × 2 = 10  ← 区间 [2,3] 的最小高度是 5

输入：heights = [2, 4]
输出：4

输入：heights = [6, 2, 5, 9, 5, 8, 4, 3, 6]
输出：16          ← 提示：不是最简单的那些组合，自己手推一遍
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [2, 2, 2]            → 6    （不是 4，也不是 2）
   暴露「相等高度互相弹出」：若相等也弹，且宽度写错，会得到 4 甚至 2

② [0, 2, 0]            → 2
   暴露「0 高柱子切断直方图」：跨过下标 0 和 2 的矩形高度只能是 0

③ [1, 2, 3, 4, 5]      → 9    （= 3 × 3，下标 2..4）
   暴露「收尾不把栈弹空」：整个数组单调递增，答案只在最后收尾时才被结算

④ [5, 4, 3, 2, 1]      → 9    （= 3 × 3，下标 0..2）
   暴露「左边界的默认值」：最小值在下标 4，它左侧没有任何更矮的柱子，左边界必须是 -1

⑤ [2, 1, 5, 6, 2, 3]   → 10   （题面样例，本部分最该手推的一例）
   它同时包含「弹出 1 根」「连弹 2 根」「收尾连弹 3 根」三类动作
```

第 ③ 和第 ④ 条是一对镜像：**递增序列的答案永远在收尾时结算，递减序列的答案永远在第一次弹出时结算**。把这两个极端各跑一遍，才能确认你的「左边界 -1」和「收尾弹空」都没写错。

## 062.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的写法是枚举所有区间 `[l, r]`，边扩展边维护最小高度：

```java
// 暴力：固定左端点 l，向右扩展，随时更新区间最小高度
int best = 0;
for (int l = 0; l < n; l++) {
    int minH = heights[l];
    for (int r = l; r < n; r++) {
        minH = Math.min(minH, heights[r]);   // 区间 [l, r] 的最小高度
        best = Math.max(best, minH * (r - l + 1));
    }
}
```

- 时间 **O(n²)**（`n(n+1)/2 ≈ 5·10⁹` 次区间更新），空间 **O(1)**。
- 本机实测（2 核容器 / JDK 17 / Go 1.19，同机对比）：

| n | 暴力 O(n²) | 单调栈 O(n) | 倍数 |
| --- | --- | --- | --- |
| 2·10³ | 2.14 ms | 18.6 µs | 115× |
| 5·10³ | 12.0 ms | 43.2 µs | 278× |
| 2·10⁴ | ≈ 190 ms（外推） | 295 µs | 640× |
| 10⁵ | **≈ 4.8 s**（外推） | **1.60 ms** | **≈ 3000×** |

- 为什么不能靠「常数小」蒙过去：`n` 翻 10 倍，时间翻 100 倍。`n = 10⁵` 时它不是「慢一点」，是**慢三个数量级**。

### 第二步：卡点在哪

把暴力翻译成一句话：

> **最大的矩形，一定可以描述成「以某根柱子的高度 `h[i]` 为高，向左右尽量延伸」的形状。**

为什么？因为任意一个矩形的高度等于它覆盖区间内的**最小高度**，而「最小值」一定被某根柱子取到。所以「所有矩形」这个 `O(n²)` 的集合，可以被**压缩成 n 个候选**：每个柱子贡献一个候选矩形。

于是每个候选只需要回答一个问题：

```
以 h[i] 为高，向左最多能延伸到哪里？向右最多能延伸到哪里？
—— 答案：向左到「第一个比 h[i] 矮的柱子」的右边一格，
        向右到「第一个比 h[i] 矮的柱子」的左边一格。
```

记 `left[i]` = 左边第一个**更矮**的下标（没有则 -1），`right[i]` = 右边第一个**更矮**的下标（没有则 n），那么

```
area[i] = h[i] × (right[i] - left[i] - 1)
```

**卡点不是「怎么算面积」，而是「这 2n 个边界怎么在 O(n) 内一起求出来」**。暴力的浪费就在这里：`[5,4,3,2,1]` 里，每根柱子都要「往右看到底」才能确认没有更矮的，`O(n)` 次重复劳动叠成了 `O(n²)`。

### 第三步：灵感的来源 —— 边界是「被弹出的那一刻」定稿的

回忆 061 学会的那句话：**栈里存下标、栈内保持单调、弹出时结算被弹出者的答案**。在这里：

```
栈内让高度单调递增（矮的在下，高的在上）。
扫描到 i 时，只要 h[i] 比栈顶矮，栈顶那根柱子的「右边界」就确定了 = i，
因为它右边第一个更矮的柱子终于出现了。

而它的「左边界」呢？—— 把栈顶弹掉之后，新的栈顶就是它左边第一个更矮的柱子。
```

一句话：

> **一根柱子的左右边界，恰好是它「被弹出」的那一刻同时获得的两样东西：右边界 = 当前下标 i，左边界 = 弹出后的新栈顶。**

这就是「弹出时结算」在本题的精确含义 —— 在 061 里它只负责产出一个数字（右边第一个更大者的距离），到这里它变成了一条**同时产出两个边界**的流水线。

### 第四步：把两个分支用「哨兵」灭掉（工程上的一步）

上面的描述有两个丑陋的边界情况：

1. **栈空了怎么办？** 弹出栈顶后如果栈空了，说明左边没有更矮的柱子 → 左边界是 `-1`。代码里就要写 `left = stack.isEmpty() ? -1 : stack.peek()`。
2. **扫描结束后栈里还剩东西怎么办？** 那些柱子的右边界是 `n`（右边没有更矮的）。要么写第二段 `while` 循环收尾，要么……

**哨兵（sentinel）** 一次性解决这两个问题：在数组**最左和最右各补一根高度为 0 的柱子**。

- 最左的 0：它永远比任何柱子矮、永远不会被弹出 → **栈永不为空**，`left` 永远合法，`-1` 那个分支消失。
- 最右的 0：它比所有柱子都矮 → 扫描到它时，**栈会被彻底弹空**，收尾那段循环消失。

```
原始:   [ 2 , 1 , 5 , 6 , 2 , 3 ]
加哨兵: [0, 2 , 1 , 5 , 6 , 2 , 3 , 0]
        ↑                            ↑
   左哨兵: 栈永不为空            右哨兵: 收尾自动弹空
```

> **为什么选 0 当哨兵**：题目保证 `heights[i] >= 0`，所以 0 一定 `<=` 所有真实高度，既不会成为任何矩形的「有效高度」，也一定能触发弹出。用 `-1` 当哨兵反而会让「高度必须非负」这条约束失效（`-1` 参与乘法会算出负数面积）。**哨兵值的选取必须服从题目的值域。**

## 062.3 原理拆解

### 062.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| A 枚举所有区间（边扩展边取 min） | O(n²) | O(1) | 8 行 | `n = 10⁵` 约 4.8 s，必 TLE |
| B 枚举每根柱子的高度 + 向左右暴力延伸 | O(n²) | O(1) | 10 行 | 与 A 同阶；但**它是对的思路**，只是边界求法太慢 |
| C 分治（以区间最小值切分，递归左右） | 平均 O(n log n)，**最坏 O(n²)** | O(log n) 栈深 | 30 行 | 输入有序时退化（每层只切掉 1 根），且需要 RMQ 找最小值 |
| D 单调递增栈（无哨兵） | O(n) | O(n) | 20 行 | 需要「栈空 → 左边界 = -1」和「收尾弹空」两处分支，容易漏 |
| **E 单调递增栈 + 双哨兵** ✅ | **O(n)** | **O(n)** | **16 行** | 要额外开 `n+2` 的数组（可原地复用）；值域必须允许 0 当哨兵 |
| F 笛卡尔树（Cartesian Tree） | O(n) | O(n) | 45 行 | 建树后再 DP；代码量 3 倍，只有需要「反复查询子区间」时才值得 |

**为什么选 E**：

- 与 C 相比：C 的分治本质是「以最小值为轴一路切下去」，而单调栈恰好就是**这棵分治树的一次线性构造**（F 的笛卡尔树），把「递归 + 找最小值」压成了一次扫描。C 的最坏情况（有序数组）正是 E 的最优情况。
- 与 D 相比：E 只多了两根哨兵柱，却消灭了两个分支。**分支越少，边界 bug 越少** —— 这是本书反复出现的工程判据。

**关于 `<` 与 `>`（等高的处理）**：本章用 `while (h[栈顶] > h[i])`，即**等高不弹**，栈内高度**非递减**。也可以改成 `>=`（等高也弹）。两种写法都能得到正确答案，但含义不同 —— 这是本题最容易讲不清的地方，§062.3.2 会用一整段把它讲透。

### 062.3.2 为什么这个做法是对的（正确性论证）

先固定记号：加哨兵后数组记作 `h[0..n+1]`，其中 `h[0] = h[n+1] = 0`，`h[i+1] = heights[i]`。栈存**下标**，扫描完成后弹出下标 `j` 时，记 `left = ` 弹出后的新栈顶，`i` = 当前下标。

**命题 1（合法性）：算法算出的每一个 `h[j] × (i - left - 1)` 都对应一个真实存在于直方图中的矩形。**

**证明**：先建立一条关于栈的不变量：

> **(S)** 若 `p`、`q` 是栈中**相邻**的两个下标（`p` 在 `q` 下面），则区间 `(p, q)` 内每根柱子的高度都 `>= h[q]`。

**（S）成立的理由（反证）**：设存在 `t ∈ (p, q)` 使 `h[t] < h[q]`。`t` 必须在 `q` 入栈之前就离开了栈 —— 否则它会一直夹在 `p`、`q` 之间，破坏两者的相邻性。而「离开栈」只可能是被某个更矮的下标 `y` 弹出（弹出条件是 `h[栈顶] > h[当前]`），即 `h[y] < h[t]`，且 `t < y <= q`（`y` 不可能大于 `q`，因为 `q` 那时还没入栈）。若 `y = q`，则 `h[q] < h[t]`，与 `h[t] < h[q]` 矛盾；于是 `y < q`，并得到一条链

```
h[q]  >  h[t]  >  h[y]  >  h[y']  >  …        下标严格递增、高度严格递减
```

这条链必然终止于某个**在 `q` 入栈时仍在栈中**的下标 `z`，且 `h[z] < h[q]`。而 `q` 入栈时会把栈里所有高度 `> h[q]` 的元素弹掉，`z` 因为更矮而**留下来** —— 于是 `z` 夹在 `p` 与 `q` 之间，与「`p`、`q` 相邻」矛盾。故（S）成立。∎

有了（S）就可以分别看两侧：

1. 区间 `(left, j)`：`left` 是**弹出 `j` 之后的新栈顶**，也就是 `j` 入栈时压在它下面的那个元素 —— 这个位置一旦确定就再也不会变（栈只从顶部弹出，`j` 不先走，它下面那个就走不了）。取 `p = left`、`q = j` 代入（S），立刻得到 `(left, j)` 内每根柱子高度都 `>= h[j]`。
2. 区间 `(j, i)`：`j` 从入栈一直留到被 `i` 弹出。若存在 `t ∈ (j, i)` 使 `h[t] < h[j]`，那么 `t` 入栈时会把栈里所有比它高的元素弹掉 —— 其中必然包含 `j`（栈内高度自底向顶非递减，`j` 以及它上方的元素都不比它矮），于是 `j` 会在 `t` 时刻被弹走，与「`j` 在 `i` 时刻才被弹」矛盾。故 `(j, i)` 内高度都 `>= h[j]`（相等时不弹，正符合 `>` 这个弹出条件）。

两端都 `>= h[j]`，故以 `h[j]` 为高、横跨 `(left, i)` 的矩形完全落在直方图内部。宽度为开区间 `(left, i)` 内的整数个数 `= i - left - 1`。∎

**命题 2（不漏最优解）：设最优矩形高度为 `H`、覆盖区间 `[l, r]`。存在一根柱子 `m`，使得算法为 `m` 算出的面积 `>= H × (r - l + 1)`。**

**证明**：取 `m` = `[l, r]` 中**高度恰为 `H` 的、最靠左**的那根柱子（一定存在：`H` 是区间最小高度，必然被某根柱子取到）。

- `[l, m)` 内的柱子高度都 `> H`（因为 `m` 是最靠左的等高柱子），`(m, r]` 内的柱子高度 `>= H`。
- `m` 的**右边界**：`m` 被弹出的下标 `i` 是它右边第一个 `h < h[m] = H` 的位置。由于 `(m, r]` 内都 `>= H`，所以 `i >= r + 1`。
- `m` 的**左边界**：弹出后的新栈顶 `left` 是左边第一个 `h <= h[m] = H` 的位置。由于 `[l, m)` 内都 `> H`，所以 `left <= l - 1`。

于是 `m` 贡献的宽度 `i - left - 1 >= (r+1) - (l-1) - 1 = r - l + 1`，即 `area[m] >= H × (r - l + 1) = 最优解`。而由命题 1，`area[m]` 又是一个合法矩形的面积，不会超过最优解 —— 两者相等。∎

> **这里藏着一个非常尖锐的细节，值得单独说清**：上面证明里，右边界是「第一个 `h < h[m]`」（严格更矮），左边界却是「第一个 `h <= h[m]`」（**不更矮**）—— 不对称！
> 原因就来自弹栈条件 `h[栈顶] > h[i]`：等高不弹，所以「弹出事件」只由**严格更矮**触发（右边界严格），而「新的栈顶」是最上面一个没被弹走的元素，等高者会留在栈里（左边界非严格）。**正因为左边界会被等高柱截断，证明里才必须挑「最靠左的等高柱」**，让左侧截断落空。
>
> 如果把条件换成 `h[栈顶] >= h[i]`，两个边界的不对称方向就整体翻转：右边界变成「第一个 `h <= h[j]`」，左边界变成「第一个 `h < h[j]`」，此时证明要挑「最靠右的等高柱」。
> **两种写法都能算对最大面积，但它们对「等高柱子归属」的约定不同 —— 一旦题目从「求最大值」变成「求总和」，混用就会重复计数（见 LC 907）。**

**命题 3（每个柱子只被弹出一次 → O(n)）：整个算法的总代价是 O(n)。**

**证明**：

1. 扫描共 `n + 2` 次迭代，每次迭代**恰好压入一个下标**，故入栈总次数 `= n + 2`。
2. 内层 `while` 的每一次迭代都**恰好弹出一个下标**，且弹出去的下标**永不回栈**。入栈总数是 `n + 2`，所以出栈总数 `<= n + 2`。
3. 因此内层 `while` 的**总执行次数** `<= n + 2`，与外层相加得 `O(n)`。∎

```
            ┌────────────────────────────────────────────┐
            │  入栈 n+2 次  →  出栈 ≤ n+2 次  →  总 O(n)   │
            │  「每个下标只被判一次死刑」，没有第二次机会   │
            └────────────────────────────────────────────┘
```

### 062.3.3 通用解题思路（可迁移的那一层）

061 建立了本批的统一判定语言，062 把它**升级成双向边界版**：

| 章 | 结构里存什么 | 单调性 | 弹栈条件 | 弹出时结算什么 |
| --- | --- | --- | --- | --- |
| 060 | 这一层的最小值 | 辅助栈单调不增 | `pop` 时同步弹 | 上一层的最小值自动恢复 |
| 061 | 下标 | 温度单调不增 | `栈顶 < 当前` | 被弹出者的答案 `i - j`（**右边界**） |
| **062** | 下标 | **高度单调非递减** | `栈顶 > 当前` | **同时**取到右边界 `i` 与左边界 `新栈顶`，算 `h[j] × (i - left - 1)` |
| 063 | 每行累加出的高度 | 每行各自维护 | 同 062 | 把 062 整段复用 |
| 064 | 下标 | 数值单调递减（队列） | 队首过期 / 队尾被支配 | 队首即当前窗口最大值 |

从 062 还能抽出两个**可以单独迁移**的技巧：

```
┌── 技巧 1：哨兵（用数据消灭分支）─────────────────────────────┐
│ 在最左/最右补上「一定比所有元素都极端」的假元素。              │
│ 作用：把「空栈」「收尾」这类边界分支变成正常数据流。           │
│ 判据：哨兵值必须落在题目允许的值域内，且不会污染答案。          │
└────────────────────────────────────────────────────────────┘

┌── 技巧 2：宽度 = 右边界 - 左边界 - 1（开区间的元素个数）────────┐
│ (left, i) 内的整数个数 = i - left - 1。                        │
│ 记错一格是本题最高频的错误，详见 §062.4.3 的逐格示意图。        │
└────────────────────────────────────────────────────────────┘
```

### 062.3.4 可扩展性（面试追问的七个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要**输出**最大矩形的位置而不是面积 | 返回 `(left, right, h)` | 弹栈那一刻三个量都在手上，直接记录；注意可能有多个最大解 |
| 柱子的**宽度不等** | 宽度不再是下标差 | 先做宽度的前缀和 `W[i]`，宽度 = `W[i] - W[left+1]`；算法骨架不变 |
| 高度可达 `10⁹`（会溢出） | `h × w` 溢出 int | 用 `long` 累乘；Go 用 `int64`（注意 `int` 在 32 位平台只有 32 位） |
| 变成**二维**矩阵 | 求全 1 的最大矩形 | 逐行累加高度 → 每行调用一次本题（第 063 章） |
| 要求「**所有**子数组的最小值之和」 | 从「取 max」变成「求和」 | 仍是这 2n 个边界，但对每个元素用 `(j - left) × (right - j)` 算「以它作为最小值的区间数」，注意等高只能算一次（LC 907） |
| 直方图会被**动态修改**（改高度 + 查询） | 静态扫描失效 | 换线段树 / 笛卡尔树维护；单调栈只能处理「一次成型」的静态数组 |
| 空间要求 O(1)（不许开栈） | 栈不能开 | 用「Morris 式」的指针技巧在原数组上原地模拟栈会破坏数据；更现实的答案是把 `heights` 当栈用（只在下标空间里做文章），或退一步接受 O(n) |

### 062.4.3 「宽度 = `i - left - 1`」的逐格示意图（本题最高频的 off-by-one）

以 i=5、j=3（`h=5`）为例：`left = 2`，`i = 5`。

```
下标:      0     1     2     3     4     5     6
h:        0     2     1     5     6     2     3
                        │     └──┬──┘     │
                      left      被算进     i
                     (h=1)      的 2 格   (h=2，触发弹出的"更矮者")

             ◄──── 不算 ────► ◄── 算 ──► ◄── 不算 ──►
                        left   2     3     i
                        
        开区间 (left, i) = {2 前面一格?, 不 —— 是 {3, 4} 两个下标}
        
        元素个数 = 4 - 2 = 2  ← 误写成 i - left 会得到 3，多算一格
        正确式子 = i - left - 1 = 5 - 2 - 1 = 2 ✓
```

```
┌──────────── 记忆法 ─────────────┐
│ 左边界和右边界本身都不算进宽度，     │
│ 所以「两端各减一格」：i - left - 1    │
│ 在 [2,2,2] 上写成 i-left，会得 9     │
│ 而不是 6 —— 一格之差，答案 50% 偏差  │
```

### 062.4.4 反例 ①：[2, 2, 2] 的等高处理（两种约定都对）

```
h（加哨兵）= [0, 2, 2, 2, 0]，下标 0..4

【约定一：等高不弹（本章代码，条件 `栈顶 > 当前`）】
i=0 → 栈[0]
i=1 → h[0]=0 > 2 ? 否 → 栈[0,1]
i=2 → h[1]=2 > 2 ? 否 → 栈[0,1,2]
i=3 → 否 → 栈[0,1,2,3]
i=4（哨兵 0）：
      弹 3：left=2，宽 = 4-2-1 = 1，面积 2      ← 被等高柱截断，宽度只有 1
      弹 2：left=1，宽 = 4-1-1 = 2，面积 4
      弹 1：left=0，宽 = 4-0-1 = 3，面积 6  ★   ← 最靠左的等高柱拿到满宽
  最大 = 6 ✓（这就是 §062.3.2 命题 2 里"挑最靠左的等高柱"的现实版）

【约定二：等高也弹（条件 `栈顶 >= 当前`）】
i=1 → 弹 0? h[0]=0 >= 2 ? 否 → 栈[0,1]
i=2 → h[1]=2 >= 2 ? 是 → 弹 1：left=0，宽 = 2-0-1 = 1，面积 2 …（依次向右传递）
i=4 → 弹 3：left=0，宽 = 4-0-1 = 3，面积 6  ★
  最大 = 6 ✓（这次是"最靠右的等高柱"拿到满宽）

结论：两种约定都能算对「最大面积」，
      但"谁拿到满宽"不同 —— 求总和时这个差别会让你重复计数！
```

## 062.5 双语言实现

### 062.5.1 Java

```java
class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        // 两侧哨兵：h[0] = h[n+1] = 0。
        // 左哨兵让栈永远非空（弹出后 st[top] 一定合法，不用判 -1）；
        // 右哨兵高度比所有真实柱子都矮，保证收尾时全部弹空（不用写第二段 while）。
        int[] h = new int[n + 2];
        System.arraycopy(heights, 0, h, 1, n);

        int[] st = new int[n + 2]; // 存下标，高度从栈底到栈顶单调非递减
        int top = -1;
        int best = 0;

        for (int i = 0; i < h.length; i++) {
            // 严格大于才弹：等高不弹，让等高平台由"最靠左"的那根统一结算满宽
            while (top >= 0 && h[st[top]] > h[i]) {
                int j = st[top--];              // 右边界 = i，左边界 = 弹出后的新栈顶
                int width = i - st[top] - 1;    // 左右边界都不算进宽度，故再 -1
                int area = h[j] * width;
                if (area > best) {
                    best = area;
                }
            }
            st[++top] = i;
        }
        return best;
    }
}
```

### 062.5.2 Go

```go
package main

// largestRectangleArea 两侧加哨兵 + 单调递增栈（等高不弹）。
// 栈里存下标；弹出下标 j 时，它的「右边界」是当前 i，「左边界」是弹出后的新栈顶。
func largestRectangleArea(heights []int) int {
	n := len(heights)
	// 哨兵：左侧高度 0 保证栈永不为空（省掉判空），右侧高度 0 保证收尾时全部弹空
	h := make([]int, n+2)
	copy(h[1:], heights)

	st := make([]int, 0, n+2) // 存下标
	best := 0
	for i := 0; i < len(h); i++ {
		for len(st) > 0 && h[st[len(st)-1]] > h[i] {
			j := st[len(st)-1]
			st = st[:len(st)-1]
			width := i - st[len(st)-1] - 1 // 弹出后栈一定非空（左哨兵托底）
			if area := h[j] * width; area > best {
				best = area
			}
		}
		st = append(st, i)
	}
	return best
}
```

### 062.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 复制带哨兵的数组 | `new int[n+2]` + `System.arraycopy(...,1,n)` | `make([]int, n+2)` + `copy(h[1:], heights)` | 两语言都是 O(n) 一次拷贝；Go 的 `copy` 目标切片 `h[1:]` 天然对齐偏移 1 |
| 栈的实现 | `int[]` + `top`（本章），或 `ArrayDeque<Integer>` | `[]int` + `append` / `[:len-1]` | Java 用 `ArrayDeque` 会在每次 `push` 装箱 `Integer`；`10⁵` 次操作能感到差异 |
| **弹出后的新栈顶** | `st[top]`（`top` 已减过，指针自然指向新栈顶） | `st[len(st)-1]`（切片已缩短） | 两语言写法不同但语义一致；Go 这一行**必须在 `st = st[:len(st)-1]` 之后**，顺序写反就用到自己 |
| int 溢出 | `int` 恒 32 位：`10⁵ × 10⁴ = 10⁹` 安全 | `int` 在 64 位平台是 64 位；32 位平台只有 32 位 | 本题都安全，但 Go 里若把高度放大到 `10⁹` 就必须显式 `int64` |
| 空数组保护 | `n = 0` 时 `new int[2]` 仍成立，循环 2 次全弹空返回 0 | `make([]int, 2)` + `copy` 同样安全 | 靠哨兵天然兜住，不需要 `if (n == 0) return 0` |
| 切片容量 | 无对应概念 | `make([]int, 0, n+2)` 预分配，避免 `append` 扩容 | 大规模时预分配能省掉几次内存拷贝 |

### 062.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// brute O(n^2)：枚举左边界，向右扩展并维护区间最小高度
func brute(h []int) int {
	best := 0
	for l := 0; l < len(h); l++ {
		minH := h[l]
		for r := l; r < len(h); r++ {
			if h[r] < minH {
				minH = h[r]
			}
			if a := minH * (r - l + 1); a > best {
				best = a
			}
		}
	}
	return best
}

func TestLargestRectangleRandom(t *testing.T) {
	r := rand.New(rand.NewSource(84))
	for iter := 0; iter < 9000; iter++ { // 9000 组随机直方图
		n := 1 + r.Intn(50)
		h := make([]int, n)
		for i := range h {
			// 70% 落在 [0,3]：制造大量等高与 0，专打「等高弹出」和「宽度差一」两类 bug
			if r.Intn(10) < 7 {
				h[i] = r.Intn(4)
			} else {
				h[i] = r.Intn(100)
			}
		}
		if got, want := largestRectangleArea(h), brute(h); got != want {
			t.Fatalf("iter=%d h=%v got=%d want=%d", iter, h, got, want)
		}
	}
}
```

## 062.6 复杂度与常见坑

### 062.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：见 §062.3.2 命题 3。核心是「**用入栈次数给出栈次数封顶**」：
  - 外层循环 `n + 2` 次，每次压入一个下标 → 入栈总数 `n + 2`；
  - 内层 `while` 每轮弹出一个下标，弹出去的永不回栈 → 出栈总数 `<= n + 2`；
  - 两者相加 `O(n)`。**注意这是严格的 O(n)，不是「平均 O(n)」** —— 最坏输入（严格递增）也只是「一直压栈，最后一次性弹空」，总次数仍是 `2n` 级别。
- **空间 O(n)**：栈最多 `n + 2` 个下标；哨兵数组 `n + 2` 个 int。Java 是 `(n+2) × 4 B × 2 ≈ 800 KB`（`n = 10⁵`），完全可控。
- **对比分治**：分治的时间是 `T(n) = T(k) + T(n-1-k) + O(n)`（`k` 为最小值位置），最好 `O(n log n)`、最坏 `O(n²)`（`k` 恒为 0 或 `n-1`）。**单调栈相当于把这棵树用 O(n) 一次建好**，这就是它严格更优的原因。

### 062.6.2 八个真实踩过的坑

1. **宽度写成 `i - left`** —— 每根柱子都多算一格。`[2,2,2]` 会返回 9 而不是 6。**记法**：左右边界都不在矩形内，所以 `-1`。
2. **收尾忘记弹空** —— 严格递增序列（如 `[1,2,3,4,5]`）的答案只在收尾结算，漏了会返回 5 而不是 9。**修法**：加右哨兵，或老老实实补一段 `while (top >= 0)`。
3. **栈空时不判空就取 `st[top]`** —— 无左哨兵且弹出后栈空时，`st[-1]` 在 Java 抛 `ArrayIndexOutOfBoundsException`，在 Go 里 `st[-1]` 直接 panic（更糟：某些写法会读到脏数据）。**修法**：加左哨兵，或显式判 `top < 0 → left = -1`。
4. **弹出后忘记「新栈顶」才是左边界** —— 用「被弹出者的下标」当左边界，宽度永远是 1（`[2,1,5,6,2,3]` 返回 6 而不是 10）。
5. **`<` 与 `>` 混用** —— 弹栈条件写 `>=`、宽度公式按 `>` 的口径推导，在等高平台上就会重复或漏算。求最大值两种约定都能对，但**求总和（LC 907）时混用就会重复计数**。写之前先决定约定，并在注释里写清「等高归谁」。
6. **哨兵值选成 `-1` 或 `Integer.MIN_VALUE`** —— `-1` 参与 `h[j] × width` 会算出负数面积；`MIN_VALUE` 更糟。**哨兵必须落在题目允许的值域内**，本题选 0（题目保证非负）。
7. **`h[j] * width` 溢出** —— 本题 `10⁴ × 10⁵ = 10⁹ < 2.147·10⁹` 恰好安全，但这是**题目给的运气**。若高度放大到 `10⁹`，必须换 `long`（Java）/ `int64`（Go）。
8. **想用「排序」或「前缀和」绕过** —— 面积与**位置相邻性**强相关，排序会破坏结构；前缀和只能帮你算「宽度之和」（柱宽不等时有用），没法帮你定位「第一个更矮的柱子」。

### 062.6.3 面试官最爱追问的三个问题

**Q1：为什么加哨兵？只加右边那个行不行？**

> 「两根哨兵各消灭一个分支。**左哨兵**（高度 0）永远不会被弹出，所以栈永不为空，`弹出后的新栈顶` 一定合法 —— 省掉『栈空 → 左边界取 -1』这个分支。**右哨兵**比所有真实柱子都矮，扫描到它时栈会被彻底弹空 —— 省掉『收尾再弹一遍』这段循环。
> 只加右哨兵也能跑，但弹出后可能出现空栈，就得写 `left = stack.isEmpty() ? -1 : stack.peek()`；只加左哨兵则要补收尾循环。两根都加，循环体里就一句 `if` 都不需要额外写。哨兵是『用数据消灭分支』这个思路最便宜的实例。」

**Q2：复杂度为什么是 O(n)？内层 `while` 一次可能弹很多下。**

> 「用入栈次数给出栈次数封顶。一共压入 `n + 2` 个下标，每个下标弹出后永不回栈，所以整个算法里 `while` 的总执行次数不超过 `n + 2`。这和外层循环相加就是 O(n)。最坏输入是严格递增的直方图：前半程一次都不弹（一直压栈），最后一个哨兵一口气弹空 —— 但那次『弹空』把账一次结清了，总次数仍是 2n 量级。这类题的复杂度证明不需要摊还势能函数，只要数一数『每个元素被弹出几次』。」

**Q3：如果要输出所有最大矩形的位置，或者求「所有子数组的最小值之和」，你的解法还够吗？**

> 「都够，因为弹栈那一刻三个量（`j`、`left`、`i`）同时在手上。
> ① **输出位置**：直接把 `(left+1, i-1, h[j])` 记下来，取面积最大的那些；注意可能有多组解，要收集而不是只留一个。
> ② **最小值和（LC 907）**：把『取 max』换成『计数』——每根柱子 `j` 作为最小值贡献的区间数是 `(j - left) × (right - j)`，乘上 `h[j]` 累加。但这里有个陷阱：**等高柱子会被两个方向都算一遍**，所以必须用『一侧严格、一侧非严格』的约定（比如左边界取 `<`、右边界取 `<=`），保证每个区间只被它的『最左最小元素』认领一次。这就是我刚才强调『等高归谁』必须事先定好的原因。」

## 附：本章小结（可背走的三句话）

```
① 所有矩形可以压缩成 n 个候选：以每根柱子为高，向左右顶到第一个更矮的柱子
② 单调递增栈一次扫描同时求出两个边界：右边界 = 触发弹出的 i，左边界 = 弹出后的新栈顶
③ 双哨兵是「用数据消灭分支」：左哨兵托底防越界，右哨兵收尾自动弹空；总代价 O(n) 靠"入栈次数给出栈次数封顶"
```
