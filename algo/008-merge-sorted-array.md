# 008. LC88 合并两个有序数组（Merge Sorted Array）

> **一句话**：这道题真正考的是「**当正向写入会覆盖尚未读取的数据时，把写入方向反过来就免费得到了缓冲区**」，不是「会写归并排序的 merge」。

## 008.1 题目

**原题链接**：<https://leetcode.cn/problems/merge-sorted-array/>

### 题意重述（把隐含条件补齐）

给你两个**非递减**有序数组 `nums1` 和 `nums2`，以及它们的有效元素个数 `m` 和 `n`。要求把 `nums2` 合并进 `nums1`，使 `nums1` 成为一个**非递减**的有序数组。

最关键的隐藏信息在数组长度上：

```
nums1.length == m + n     ← nums1 的尾部有 n 个"空位"，通常填着 0
nums2.length == n
```

也就是说，**`nums1` 自带 `n` 个空位，这 n 个空位就是题目白送给你的缓冲区**。这一点决定了整道题的解法走向。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **结果必须放进 `nums1`** | 「合并后的数组不应由函数返回」 | 返回新数组、或把 `nums1` 指向别处 → 判题机看不到结果 |
| **`nums1` 尾部的 `n` 个元素是占位符** | `nums1.length == m + n` | 把它们当成有效数据参与排序 → 结果多出 n 个值 |
| **只处理前 `m` 个** | 「`m` 表示 `nums1` 中元素的数目」 | 用 `nums1.length` 当有效长度 → 把 0 也排进去 |
| **有序（非递减）** | 题干 | 丢掉有序性就退化成「合并后排序」，O((m+n)log(m+n)) |
| **`m` 可以为 0** | 约束 | 不特判会越界（`i = m-1 = -1`） |
| **元素可达 `±10^9`** | 约束 | 比较时无溢出风险（只比较不相加），但别做 `a+b` 之类的操作 |

> ⚠️ 「尾部有空位」这件事是本题的**题眼**。很多人第一反应是「归并排序的 merge 我会写」，然后写下正向双指针，跑样例 `[1,2,3,0,0,0]` 时发现 **`nums1` 的元素被覆盖了**。真正的解法只有一句话：**从后往前写。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `nums1.length == m + n`，`1 <= m + n <= 200` | 总量至多 200 | **任何复杂度都能过**，所以这题的考点完全不在时间，而在「**O(1) 空间 + 原地 + 不覆盖**」 |
| `0 <= m, n <= 200` | 允许单边为空 | 必须处理 `m = 0` 与 `n = 0` 两个边界 |
| `nums1.length == m + n` 且 `nums2.length == n` | 长度关系 | 逆向写入的**位置**能精确算出来：`w = m + n - 1` |
| `-10^9 <= nums1[i], nums2[i] <= 10^9` | int 范围内 | 只做比较不做加法，**无溢出风险**（对比 004 四数之和要 `long`） |

> 💡 **量级反推**：`m + n ≤ 200` 说明**这题根本不考复杂度**。它考的是三件工程能力：① 读懂「长度 = 有效长度 + 空位」这种隐含约定；② 想清楚「写入会不会覆盖未读数据」；③ 把边界（`m=0` / `n=0`）一次写对。**面试里这种「简单但边界密」的题，反而是筛人最狠的。**

### 示例

```
输入：nums1 = [1,2,3,0,0,0], m = 3, nums2 = [2,5,6], n = 3
输出：[1,2,2,3,5,6]
解释：需要合并的分别是 [1,2,3] 和 [2,5,6]

输入：nums1 = [1], m = 1, nums2 = [], n = 0
输出：[1]
解释：nums2 为空，nums1 不用动

输入：nums1 = [0], m = 0, nums2 = [1], n = 1
输出：[1]
解释：nums1 的"有效部分"是空的，尾部的 0 只是占位符，必须被 nums2 覆盖
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① m=0,  nums1=[0],       nums2=[1]        → 暴露「忘记处理 m=0」：i=-1 越界
② n=0,  nums1=[1],       nums2=[]         → 暴露「循环条件写 while (i>=0 || j>=0)」时多写一次
③ nums1=[4,5,6,0,0,0], nums2=[1,2,3]      → 暴露「正向双指针」：nums1[0] 被 nums2[0] 覆盖后，4 就丢了
④ nums1=[1,2,3,0,0,0], nums2=[2,5,6]      → 有相等元素 2，暴露「比较用 >= 还是 >」对稳定性的影响
```

第 ③ 条是本章的**核心反例**，请务必亲手跑一遍正向写法：`nums1 = [4,5,6,0,0,0]`、`nums2 = [1,2,3]`，正向归并第一步就把 `nums1[0] = 4` 覆盖成 `1`，而 `4` 还没被读走 —— **数据丢失，且结果看起来「差不多对」**，这类 bug 最难查。

## 008.2 从暴力到最优：第一个念头为什么错

### 第一步：最直觉的错法 —— 正向归并（会覆盖）

归并排序里的 `merge` 长这样，很多人条件反射地照搬：

```java
// 错法：正向双指针，边读边往 nums1 前面写
int i = 0, j = 0, w = 0;
while (i < m && j < n) {
    if (nums1[i] <= nums2[j]) nums1[w++] = nums1[i++];
    else                      nums1[w++] = nums2[j++];
}
while (j < n) nums1[w++] = nums2[j++];
```

- 时间 **O(m + n)**，空间 O(1) —— **看起来完美**。
- 但它在 `nums1 = [4,5,6,0,0,0]`、`nums2 = [1,2,3]` 上会得到 `[1,2,3,0,0,0]`：因为 `w` 追上了 `i`，`nums1[0]` 被写入的时刻，`nums1[0]` 的原值 `4` 还没被读出来。

```
正向写的灾难现场（nums1=[4,5,6,_,_,_], nums2=[1,2,3]）：

第 1 步  i=0(4) j=0(1)  →  写 nums1[0] = 1
        ┌───┬───┬───┬───┬───┬───┐
        │ 4 │ 5 │ 6 │   │   │   │
        └───┴───┴───┴───┴───┴───┘
          ↑i
          ↑w
        ┌───┬───┬───┬───┬───┬───┐
        │ 1 │ 5 │ 6 │   │   │   │      ← 4 被覆盖，永久丢失
        └───┴───┴───┴───┴───┴───┘
              ↑i    ↑w
```

**根因**：`w`（写指针）从 0 开始，`i`（读指针）也从 0 开始，**写位置 <= 读位置**，所以写的动作会踩到还没读的数据。

### 第二步：两条修补路线

| 修补方式 | 做法 | 代价 |
| --- | --- | --- |
| 先备份 `nums1[0..m-1]` | 复制到临时数组，再正向归并回 `nums1` | **O(m) 额外空间** —— 题目明摆着给了空位，用额外空间是浪费 |
| **从后往前写** | `w` 从 `m+n-1` 开始，`i`、`j` 从各自末尾开始 | **O(1) 空间**，且天然不覆盖 |

第二条为什么可行？因为 **`nums1` 最大的元素要么在 `nums1[m-1]`，要么在 `nums2[n-1]`** —— 而 `nums1` 的末尾正好是空的！**最大的元素放在最末尾，这个位置一定是安全的。**

### 第三步：卡点在哪

卡点不是「怎么归并」，而是「**写的位置和读的位置会不会打架**」。把它写成一句话：

> **写入位置 `w` 必须永远 >= 尚未读取的 `nums1` 元素的最大下标 `i`。**

从后往前写时，`w` 与 `i` 的关系可以精确算出来（这是本章最漂亮的一步）：

```
处理到某一步时，nums1 未读部分有 i+1 个元素（下标 0..i），
nums2 未读部分有 j+1 个元素（下标 0..j），
已写入部分有 (m+n-1) - w 个元素。

由"元素总数守恒"：
    (i+1) + (j+1) + (已写入数) = m + n
    →     w = i + j + 1
```

于是 `w - i = j + 1 >= 1 > 0`，即 **`w >= i + 1`，写位置永远严格大于读位置**。

> 📌 **这一行 `w = i + j + 1` 就是逆向合并正确的全部理由。** 它说明「写指针永远在未读的 `nums1` 元素右边至少一格」，所以**永远不会覆盖**。而正向写时，`w` 与 `i` 的关系是 `w = (已写入数) <= i`，恰好反了。

### 第四步：灵感的来源 —— 「用空位当缓冲区」

课本里归并排序要额外 O(n) 空间，是因为**两个数组都要完整读一遍**、没法在同一个数组里就地合并。

而本题把「目标数组」和「来源数组之一」做成了同一个对象，并且**源数组的尾部恰好有 `n` 个空位**。于是：

```
归并的上界性质：两个有序序列里最大的元素，一定在某个序列的末尾
        ↓
它应该被放在结果的末尾 → 结果末尾正好是空位 → 直接写，安全
        ↓
每次从末尾取走一个最大元素，空位就"往左挪一格"
        ↓
空位永远是"目标位置的右侧" → 不需要任何额外缓冲区
```

**这就是「逆向思考」在数组题里的第一次出场，后面 LC 1089 复写零、LC 977 平方数组都会用到同一招。**

## 008.3 原理拆解

### 008.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 拼起来再排序 | O((m+n)log(m+n)) | O(log n) 栈 | 3 行 | 完全浪费了「两边都有序」这个前提；面试直接扣分 |
| 正向归并（不备份） | O(m+n) | O(1) | 8 行 | **数据被覆盖，错误** |
| 备份 `nums1` + 正向归并 | O(m+n) | **O(m)** | 12 行 | 空间不达标；拷贝本身也是 O(m) 开销 |
| **逆向三指针** ✅ | **O(m+n)** | **O(1)** | **8 行** | `nums1` 尾部**没有**空位时不可用（此时只能备份或换结构） |
| 从 `nums2` 逐个插入 `nums1` | O(m·n) | O(1) | 10 行 | 每次插入要搬移整段，`m` 大时平方级 |

**为什么逆向三指针是唯一「最优」**：时间是归并的下界 `O(m+n)`（每个元素至少要读一次），空间是 `O(1)`，代码只有 8 行。**它同时踩中了「最优时间」「最优空间」「最短代码」三个点。**

### 008.3.2 为什么这个做法是对的（正确性论证）

**循环不变量**（每轮循环开始时成立）：

```
① nums1[w+1 .. m+n-1] 已经是从大到小顺序的"合并结果的尾部"，
   且其中的每一个元素都 >= 剩余未处理元素（nums1[0..i] 与 nums2[0..j]）中的任意一个；
② nums1[0..i] 与 nums2[0..j] 恰好是还没合并的全部元素；
③ w = i + j + 1，因此 w >= i + 1（写位置永远不越过未读的 nums1）。
```

- **初始**：`i = m-1, j = n-1, w = m+n-1`。① 的区间 `[m+n, m+n-1]` 为空，空真；② 全数组都是未合并的；③ `w = (m-1)+(n-1)+1 = m+n-1` ✓。
- **保持**：比较 `nums1[i]` 与 `nums2[j]`，取较大者写到 `nums1[w]`。
  - 为什么「较大者就该放在 `w`」：`nums1[i]` 是 `nums1` 未读部分的最大值，`nums2[j]` 是 `nums2` 未读部分的最大值，所以两者较大者就是**全部未处理元素中的最大值**，而它应该排在合并结果的最后一个空位 —— 也就是 `w`。
  - 写完后 `w` 减一，被取走的那一侧下标也减一，①②③ 全部保持（③：`i` 或 `j` 减一，`w` 也减一，等式不变）。
  - **写入位置 `w >= i+1` 由 ③ 保证，所以 `nums1[w]` 的写入不会破坏 `nums1[0..i]` 这个待读区间。**
- **终止**：循环在 `j < 0` 时结束。此时 `nums2` 全部合并完，`nums1[0..i]` 剩下的元素本来就是有序的、且都在 `nums1` 里正确的位置上（因为 `w == i`），**不需要再搬**。∎

**两个边界的说明**：

| 情形 | 行为 | 为什么对 |
| --- | --- | --- |
| `n == 0`（`nums2` 空） | 循环体一次都不执行 | `nums1` 本来就是答案 |
| `m == 0`（`nums1` 无有效元素） | 每轮 `i = -1`，条件 `i >= 0` 为假，总是取 `nums2[j]` | 相当于把 `nums2` 从后往前复制到 `nums1` 尾部 |
| `nums1` 剩余元素比 `nums2` 大 | 走 `nums1[w--] = nums1[i--]` | 此时 `w > i`，是「把元素往右挪」，安全 |
| 两边元素相等 | 取哪边都行 | 相等元素的相对次序不影响「非递减」这个要求（若要稳定，应取 `nums1` 的，见 §008.6.3） |

### 008.3.3 通用解题思路（可迁移的那一层）

本题是 **「逆向填充：用尾部空位当缓冲区」** 模型的原型：

```
问题：把 A 合并进 B 的原地操作，B 的尾部有足够空位
        ↓ 观察：合并结果的最大元素必在两序列末尾
        ↓ 结论：从后往前填，写入位置永远在"未读数据"的右边
     模板：
        i = A 末尾, j = B 有效末尾, w = 目标末尾
        while (j >= 0):                       ← 只判 B 是否耗尽
            if (i >= 0 && A[i] > B[j]) target[w--] = A[i--]
            else                        target[w--] = B[j--]
```

**这个模板的三条变体**：

| 变体 | 触发条件 | 典型题 |
| --- | --- | --- |
| 目标数组尾部有空位 | 本题 | LC 88 合并两个有序数组 |
| 需要**倒着填**结果数组 | 「从大到小填」更自然 | LC 977 有序数组的平方 |
| 需要**从右往左写**避免覆盖未读数据 | 写指针可能追上读指针 | LC 1089 复写零 |

属于同一模型的题：

| 题 | 从后往前写的原因 |
| --- | --- |
| [LC 88 合并两个有序数组](https://leetcode.cn/problems/merge-sorted-array/) | 目标数组尾部有空位，正向写会覆盖未读的 `nums1` |
| [LC 977 有序数组的平方](https://leetcode.cn/problems/squares-of-a-sorted-array/) | 平方后的最大值在两端，结果应从大到小填 |
| [LC 1089 复写零](https://leetcode.cn/problems/duplicate-zeros/) | 从左往右写会把后面的元素挤掉；先反向试算长度，再从右往左写 |
| [LC 21 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/) | **不需要**逆向：链表节点不可覆盖，正向 + 哑结点即可 |
| [LC 4 寻找两个正序数组的中位数](https://leetcode.cn/problems/median-of-two-sorted-arrays/) | 不合并，用二分划分，是「合并」的 O(log) 版本 |

> 📌 注意第 4 行：**链表合并反而是正向的**，因为链表没有「覆盖」问题，插入只要改指针。**「逆向」不是归并的通性，而是「数组 + 原地」这个组合逼出来的。**

### 008.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| `nums1` 尾部**没有**空位 | 无缓冲区 | 只能备份（O(m) 空间）或新建数组；本题的技巧失效 |
| 要求合并后**稳定**（相等时保留 `nums1` 在前） | 比较符改成 `>=` | `nums1[i] >= nums2[j]` 时取 `nums1`，保证 `nums1` 的元素不被「后来者」插到前面 |
| 要合并**三个**有序数组 | 多一个指针 | 三方比较取最大，仍然 O(总长) |
| 要合并**k 个** | k 指针取最大 | 朴素 O(k·N)，用堆优化到 O(N log k)（即 LC 23） |
| 只要**中位数**，不要完整结果 | 不必合并 | 二分划分（LC 4），O(log min(m,n)) |
| 内存极小、只能顺序访问 | 无法随机访问尾部 | 逆序不可行，只能走「外部归并」思路落盘 |

**稳定性的细节**：题目只要求「非递减」，不要求稳定。但如果你想让相等的元素保持「`nums1` 在前」，把比较写成 `nums1[i] >= nums2[j]`（而不是 `>`）即可 —— 相等时优先取 `nums1`。这在真实工程里（例如「按时间戳排序的两份日志合并」）是有意义的。

## 008.4 图解推演

### 008.4.1 主样例的完整轨迹

```
nums1 = [1, 2, 3, 0, 0, 0]   m = 3
nums2 = [2, 5, 6]            n = 3

起始  i=2(值3)  j=2(值6)  w=5
┌───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 0 │ 0 │ 0 │
└───┴───┴───┴───┴───┴───┘
  ↑i          ↑w
              ↑j（nums2 的 6 在 j=2）

第 1 轮  nums1[2]=3 vs nums2[2]=6  →  6 大  →  nums1[5]=6，j--, w--
┌───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 0 │ 0 │ 6 │
└───┴───┴───┴───┴───┴───┘
  ↑i      ↑w   ↑j

第 2 轮  nums1[2]=3 vs nums2[1]=5  →  5 大  →  nums1[4]=5，j--, w--
┌───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 0 │ 5 │ 6 │
└───┴───┴───┴───┴───┴───┘
  ↑i  ↑w  ↑j

第 3 轮  nums1[2]=3 vs nums2[0]=2  →  3 大  →  nums1[3]=3，i--, w--
┌───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 3 │ 3 │ 5 │ 6 │      ← 注意：这是"把 3 往右挪一格"，不是复制
└───┴───┴───┴───┴───┴───┘
  ↑i  ↑j      ↑w

第 4 轮  nums1[1]=2 vs nums2[0]=2  →  相等，取 nums2（`>` 的写法）
        nums1[2]=2，j--, w--
┌───┬───┬───┬───┬───┬───┐
│ 1 │ 2 │ 2 │ 3 │ 5 │ 6 │
└───┴───┴───┴───┴───┴───┘
  ↑i          ↑w
 j = -1  →  循环结束

剩余 nums1[0..1] = [1,2] 原地不动，就是最终答案
结果 [1, 2, 2, 3, 5, 6] ✓
```

### 008.4.2 三指针状态表（含 `w` 与 `i` 的安全距离）

| 轮 | i | j | w | nums1[i] | nums2[j] | 取谁 | 写入位置 | **w - i** |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 起始 | 2 | 2 | 5 | 3 | 6 | — | — | **3** |
| 1 | 2 | 2 | 5 | 3 | 6 | nums2 | `nums1[5]=6` | **3** |
| 2 | 2 | 1 | 4 | 3 | 5 | nums2 | `nums1[4]=5` | **2** |
| 3 | 2 | 0 | 3 | 3 | 2 | nums1 | `nums1[3]=3` | **1** |
| 4 | 1 | 0 | 2 | 2 | 2 | nums2 | `nums1[2]=2` | **1** |
| 5 | 1 | -1 | 1 | 2 | — | 结束 | — | — |

**最后一列是全章最该盯住的数字**：`w - i` 始终 `>= 1`（表中最小是 1），这就是「写入永不覆盖未读数据」的直接证据。而正向写时这个差值会变成 `<= 0`：

```
正向写：w 与 i 的关系
   第 1 轮：w=0, i=0 → w - i = 0    ← 就在同一格！写入 = 覆盖
```

### 008.4.3 正向 vs 逆向的覆盖关系图

```
════════ 正向写（w 从左往右）════════
┌───┬───┬───┬───┬───┬───┐
│ 4 │ 5 │ 6 │   │   │   │
└───┴───┴───┴───┴───┴───┘
  ↑i
  ↑w          i 与 w 同向出发，w 追着 i 跑 → 写下去的瞬间就把 i 踩了

════════ 逆向写（w 从右往左）════════
┌───┬───┬───┬───┬───┬───┐
│ 4 │ 5 │ 6 │   │   │   │
└───┴───┴───┴───┴───┴───┘
  ↑i                 ↑w
              i 与 w 相背而行 → 距离越拉越大（w-i 从 3 到 1）→ 永不覆盖
```

用一张「相对位置」图总结：

```
        左端                                        右端
         ┌──────────────┬──────────────────────────┐
正向写：  │ 已写 │ 未读 i │        空位              │   ← w 在 i 左边，会覆盖
         └──────────────┴──────────────────────────┘
         ┌──────────────┬──────────────────────────┐
逆向写：  │ 未读 i │已写区 w│（写指针从右往左推进）    │   ← w 在 i 右边，安全
         └──────────────┴──────────────────────────┘
```

## 008.5 双语言实现

### 008.5.1 Java

```java
class Solution {
    public void merge(int[] nums1, int m, int[] nums2, int n) {
        // i 指向 nums1 有效部分的末尾，j 指向 nums2 的末尾，w 指向合并结果的末尾
        // 不变量：nums1[w+1 .. m+n-1] 已按从大到小填好，
        //        且 w = i + j + 1 → w >= i+1 → 写入永不覆盖未读的 nums1[0..i]
        int i = m - 1;
        int j = n - 1;
        int w = m + n - 1;

        // 循环条件只看 j >= 0：
        // j < 0 说明 nums2 已经全部合并完，剩下的 nums1[0..i] 本来就在正确位置（w == i），
        // 不需要再搬。这也顺带解决了 m == 0 的情形（此时 i = -1，永远走 else 分支）
        while (j >= 0) {
            // 必须判 i >= 0，否则 nums1[i] 会下标越界
            // 用 > 而不是 >=：相等时优先取 nums2（保持简单；见下方差异批注里的"稳定性"讨论）
            if (i >= 0 && nums1[i] > nums2[j]) {
                nums1[w--] = nums1[i--];
            } else {
                nums1[w--] = nums2[j--];
            }
        }
        // 返回类型是 void：题目要求原地改 nums1，不要返回新数组
    }
}
```

### 008.5.2 Go

```go
package main

// merge 把 nums2 合并进 nums1，原地修改 nums1。变量名与 Java 版逐行对齐。
func merge(nums1 []int, m int, nums2 []int, n int) {
	// i / j 是两侧的读指针，w 是写指针，三者都从右往左走
	i, j, w := m-1, n-1, m+n-1

	// 只判 j >= 0：nums2 耗尽后，nums1 剩下的前缀已经在正确位置
	for j >= 0 {
		// i >= 0 必须判：nums1 的有效部分可能先耗尽
		if i >= 0 && nums1[i] > nums2[j] {
			nums1[w] = nums1[i]
			w--
			i--
		} else {
			nums1[w] = nums2[j]
			w--
			j--
		}
	}
	// Go 里切片是值传递，但底层数组共享 —— 修改元素能传回调用方，
	// 所以这种"原地修改"写法在 Go 里是有效的（注意：不能通过 append 改变长度来影响调用方）
}
```

### 008.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 原地修改是否生效 | 数组是引用类型，直接生效 | 切片是「指针 + len + cap」的值传递，**改元素生效**，但 `append` 后不会更新调用方的 len | 本题只改元素、不改长度 → 都正确 |
| 有效的「末尾」 | `m - 1`（靠参数 `m`） | 同样靠参数 `m`（**不能用 `len(nums1)-1`**） | Go 里切片的 `len` 是 `m+n`，容易误用；一旦写成 `len(nums1)-1` 就会把占位的 0 当成有效数据 |
| 自减写法 | `nums1[w--] = nums1[i--]` | Go **不支持** `w--` 作为表达式（只有 `w--` 语句，没有前置/后置的返回值） | Go 里必须拆成两条语句，代码长 2 倍；这是最容易「从 Java 抄过来编译不过」的一处 |
| 多重赋值 | 无 | 可以写 `nums1[w], w, i = nums1[i], w-1, i-1` | 可行但**可读性差**，本节刻意展开写，便于对照 |
| 越界行为 | 抛 `ArrayIndexOutOfBoundsException` | 抛 `panic: index out of range` | 都是运行时崩溃，边界写错会立刻暴露 |
| 空切片 | `new int[0]`，题意下不会出现 | `nil` 切片 `len` 为 0，`nums2` 为 nil 时循环不执行 | 安全 |

> ⚠️ **Java 转 Go 的头号编译错误**：`nums1[w--] = ...` 在 Go 里直接报 `syntax error`。Go 的 `--` 只是语句，不是表达式，**没有返回值**。

### 008.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// brute 用最笨但绝对正确的办法：把两段拼起来排序
// 它丢掉了「两边都有序」这个前提，所以慢，但作为参照物足够
func brute(nums1 []int, m int, nums2 []int, n int) []int {
	res := make([]int, 0, m+n)
	res = append(res, nums1[:m]...)
	res = append(res, nums2[:n]...)
	sort.Ints(res)
	return res
}

func equal(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func TestMergeRandom(t *testing.T) {
	r := rand.New(rand.NewSource(88))
	for iter := 0; iter < 20000; iter++ {
		m := r.Intn(8) // 0..7，含 m=0
		n := r.Intn(8) // 0..7，含 n=0
		if m+n == 0 {
			m = 1 // 题面保证 m+n >= 1
		}

		a := make([]int, m)
		for i := range a {
			a[i] = r.Intn(21) - 10 // 值域 [-10,10]：重复值密集，逼出"相等时取谁"的分支
		}
		sort.Ints(a)

		b := make([]int, n)
		for i := range b {
			b[i] = r.Intn(21) - 10
		}
		sort.Ints(b)

		// 构造符合题面的 nums1：前 m 个有效，后面 n 个占位 0
		nums1 := make([]int, m+n)
		copy(nums1, a)

		want := brute(nums1, m, b, n)

		got := append([]int(nil), nums1...)
		merge(got, m, b, n)

		if !equal(got, want) {
			t.Fatalf("iter=%d m=%d nums1=%v nums2=%v got=%v want=%v", iter, m, nums1, b, got, want)
		}
	}
}

// 钉住四个手推反例
func TestMergeEdge(t *testing.T) {
	type c struct {
		nums1 []int
		m     int
		nums2 []int
		n     int
	}
	cases := []c{
		{[]int{0}, 0, []int{1}, 1},                      // m = 0
		{[]int{1}, 1, nil, 0},                           // n = 0
		{[]int{4, 5, 6, 0, 0, 0}, 3, []int{1, 2, 3}, 3}, // 正向写会丢数据的用例
		{[]int{1, 2, 3, 0, 0, 0}, 3, []int{2, 5, 6}, 3},
	}
	for _, x := range cases {
		want := brute(x.nums1, x.m, x.nums2, x.n)
		got := append([]int(nil), x.nums1...)
		merge(got, x.m, x.nums2, x.n)
		if !equal(got, want) {
			t.Fatalf("nums1=%v m=%d nums2=%v n=%d got=%v want=%v", x.nums1, x.m, x.nums2, x.n, got, want)
		}
	}
}
```

> **测试设计说明**：`brute` 刻意用「拼接 + 排序」而不是另一个归并，这样它和被测代码**不共享任何逻辑**，一旦被测代码写错（比如正向覆盖、或把 `len(nums1)` 当有效长度），两边必然对不上。**参照物要和被测物「尽量不像」，否则一起错就发现不了。**

## 008.6 复杂度与常见坑

### 008.6.1 复杂度推导

- **时间 O(m + n)**：每轮循环**恰好**写入一个元素、并把 `w` 减一；`w` 从 `m+n-1` 走到 `0`，所以循环至多 `m+n` 轮。每轮是常数次比较与赋值。
  - 注意循环**实际**轮数等于 `n`（因为只判 `j >= 0`），但每一轮可能取的是 `nums1` 的元素。所以「读取次数 ≤ m + n，写入次数 = n + (被搬走的 nums1 元素数) ≤ m + n」。
- **空间 O(1)**：只有 `i, j, w` 三个下标。
- **对比「拼起来排序」**：`O((m+n)log(m+n))`。当 `m+n = 200` 时差别看不出来，但当 `m+n = 10⁶` 时是 `2·10⁷` vs `10⁶` 的差距。
- **对比「备份 + 正向归并」**：时间同为 O(m+n)，但空间 O(m)，且多一次 O(m) 的拷贝（实测常数还更大）。

### 008.6.2 七个真实踩过的坑

1. **正向归并** —— 本章头号错误。`nums1 = [4,5,6,0,0,0]`、`nums2 = [1,2,3]` 上会得到 `[1,2,3,0,0,0]`（丢了 4、5、6）。
2. **把 `len(nums1)` / `nums1.length` 当有效长度** —— `nums1` 的长度是 `m+n`，有效部分只有前 `m` 个。用全长会初始化 `i = m+n-1`，把占位的 0 也当成数据。
3. **循环条件写成 `while (i >= 0 && j >= 0)`** —— 那么 `nums2` 里剩下的小元素（比 `nums1` 所有剩余元素都小）**不会被写入**，结果尾部残留旧数据。必须只判 `j >= 0`。
4. **循环条件写成 `while (i >= 0 || j >= 0)`** —— 当 `i < 0` 时若还去读 `nums1[i]` 就越界；必须靠 `i >= 0 &&` 短路保护。
5. **忘了判 `i >= 0`** —— `nums1` 的有效部分先耗尽（例如 `m=0`），`nums1[-1]` 直接崩。
6. **Go 里写 `nums1[w--]`** —— 编译不通过（Go 的 `--` 不是表达式）。必须拆成两条语句。
7. **以为「必须处理 `m == 0` 的特判」** —— 其实 `i = -1` 时 `i >= 0` 为假，自动走 `else` 分支，**天然正确**。加特判不算错，但说明没看穿不变量的保护范围。

### 008.6.3 面试官最爱追问的三个问题

**Q1：为什么从后往前？从前往前不行吗？**
> 「从前往前会把 `nums1` 里尚未读取的元素覆盖掉。精确地说，正向写时写指针 `w` 与读指针 `i` 都从 0 出发，`w <= i` 恒成立，所以写的动作会踩到还没读的数据。逆向写时，由元素数守恒可得 `w = i + j + 1`，于是 `w - i = j + 1 >= 1` —— **写位置永远严格大于读位置**，永远不会覆盖。而逆向可行的前提是『`nums1` 尾部有 `n` 个空位』，这正是题目白送的缓冲区。」

**Q2：如果 `nums1` 尾部没有空位，你怎么办？**
> 「那就没有 O(1) 空间的原地解了 —— 因为合并结果需要 `m+n` 个位置，而 `nums1` 只有 `m` 个有效位置。只能：① 申请新数组，O(m+n) 空间；② 或者申请 `min(m,n)` 大小的临时缓冲，把较小的一侧先拷出来，再做原地归并（这是经典的就地归并技巧，但实现复杂度高、常数大）。这也是为什么 LC 88 要特意把尾部做成空位 —— **它把一道需要 O(n) 空间的题，变成了一道 O(1) 空间的题。**」

**Q3：相等元素该怎么处理？会不会影响结果？**
> 「不影响正确性，因为题目只要求『非递减』，相等元素谁在前谁在后都满足。但影响**稳定性**：如果希望相等的元素保持『`nums1` 的在前』（例如两份按时间排序的日志合并，`nums1` 是旧数据、希望旧数据排前），就把比较写成 `nums1[i] >= nums2[j]`，相等时优先取 `nums1`。反过来写 `>` 就是『相等时优先取 `nums2`』。这是一个一句话就能说清、但很多人从没想过的细节。」

## 附：本章小结（可背走的三句话）

```
① 逆向三指针：i=m-1, j=n-1, w=m+n-1，每次把较大的那个写到 nums1[w]
② 为什么安全：w = i + j + 1 → w - i = j + 1 >= 1，写位置永远在未读数据右边
③ 循环只判 j >= 0；剩下的 nums1 前缀本来就在正确位置，不需要再搬
```
