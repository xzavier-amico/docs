## 099.1 题目

**原题链接**：<https://leetcode.cn/problems/combination-sum/>

### 题意重述（把隐含条件补齐）

给你一个**无重复元素**的整数数组 `candidates` 和一个目标整数 `target`，找出 `candidates` 中所有**和为目标数**的组合，要求：

- **同一个数字可以被重复选取**（这是本题与 098/100 的分水岭）；
- 组合内部顺序无关，解之间不能重复；
- 解集顺序任意。

一句话：「从一堆面额里凑出总额，每种面额可以用任意张」。这其实就是「找零钱的所有方案」，只是换了个说法。

四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **元素可重复使用** | 「candidates 中的 **同一个** 数字可以 **无限制重复** 被选取」 | 写成 `dfs(i+1)` 就退化成 100 的题型，`[2,2,2]` 这类解直接消失 |
| **`candidates` 元素互不相同** | 「candidates 中的数字 **互不相同**」 | 所以本题**不需要**同层去重；一旦有重复值就必须换成 100 的写法 |
| **保证答案数量有限** | 「如果至少一个数字的被选数量不同，则两种组合是不同的」+ `target ≤ 500`、`candidates[i] ≥ 1` | 因为每个数最小是 1，`target` 有限 → 递归深度有限，**不会无限递归**。若允许 0 或负数，本题会变成无限解 |
| **组合、不是排列** | 「组合」 | `[2,3]` 与 `[3,2]` 只能出现一次 → 必须靠「起点不减」定序 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= candidates.length <= 30` | n 至多 30 | `2^30` 的全子集枚举不可行；但本题**不是子集问题**，而是「多重集」问题 |
| `2 <= candidates[i] <= 200` | 每个数至少 2 | 递归深度 ≤ `target/2`（最坏 `250`），栈不会爆；同时也说明「元素不会为 0」→ 不会死循环 |
| `1 <= target <= 500` | 目标不大 | 递归深度上界 `250`，答案数量（题目保证）远小于 `150` 个 |
| 答案个数 < 150 | 出题人显式保证 | 这是**关键信息**：说明搜索树会被剪得很干净，不要担心输出爆炸 |

> 💡 **量级反推**：这题的规模信号不在 `n` 上（30 不算大），而在 **`target ≤ 500` 与「答案 < 150 个」** 上。前者给了递归深度上界，后者说明「和值剪枝」会把搜索树砍到很小。**看到这两个数字，就该想到「带和值剪枝的回溯」而不是「全子集枚举」。**

### 示例

```text
输入：candidates = [2,3,6,7], target = 7
输出：[[2,2,3],[7]]
解释：2+2+3 = 7；7 = 7。注意 [2,2,3] 里 2 用了两次。
      而 [2,3,2]、[3,2,2] 是同一个组合，不允许重复出现。

输入：candidates = [2,3,5], target = 8
输出：[[2,2,2,2],[2,3,3],[3,5]]

输入：candidates = [2], target = 3（自造）
输出：[]                       ← 目标不可达：只能凑出偶数
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [2], target = 3        → 目标不可达，必须返回空而不是死循环
② [1], target = 1        → 最小可用输入，答案 [[1]]
③ [1], target = 5        → 唯一解 [1,1,1,1,1]：检验「深度可以到 target/1」
④ [7,3,2], target = 7    → 未排序版本：剪枝依赖有序（break），乱序会漏解
⑤ [2,4,6], target = 6    → 同时含 [2,2,2] 与 [6]；检验「可重复」与「不重复用同一个下标」不冲突
```

第 ① 条和第 ④ 条是本题最常见的两个失败点：**不可达时要能干净返回**；**剪枝 `break` 必须建立在排序之后**。

## 099.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 A —— 「每个数取几张」的多重循环

最直白的想法：对每个 `candidates[i]`，枚举它取 `0, 1, 2, …` 张，凑出 `target` 即可。

```text
for c0 in 0 .. target/candidates[0]:
  for c1 in 0 .. target/candidates[1]:
    for c2 in 0 .. target/candidates[2]:
      ...
      if Σ ci*candidates[i] == target: 记下这组 (ci)
```

问题与 096 §2 完全一样：**循环层数 = `n`，而 `n` 是运行时才知道的**。`n = 30` 就要写 30 层嵌套。控制流表达不出来，必须换递归。

### 第一步'：第一个念头 B —— 位掩码

```text
for mask in 0..(1<<n)-1: 统计 mask 里元素的和 ...
```

它在本题**从根上失效**：位掩码的一位只能表达「取 0 次还是 1 次」，而本题需要「取几次」。`[2,2,3]` 需要 `2` 这个元素被「取 2 次」，位掩码里没有这第三个状态。这就是 096 §2 那张表里说的「**位掩码只能解『每个元素二选一』**」。

### 第二步：卡点在哪 —— 「还能不能再选它」这个状态没地方放

在 098 里，结点状态是 `(start, len)`：`start` 表示「本层最小可选下标」，并且每次递归都推到 `i+1`，于是「每个下标最多用一次」被结构性地保证了。

本题要「同一个数字重复用」，那么「`i+1`」这个约定就必须破掉。可问题来了：

- 如果直接传 `start`（每次都从 0 开始），`[2,3]` 与 `[3,2]` 会同时出现 → **重复**；
- 如果传 `i+1`，`[2,2,3]` 生成不出来 → **漏解**。

**卡点非常精确：既要允许「重复选同一个」，又要禁止「换顺序重排」。** 这两件事看似矛盾，但有一个恰到好处的取舍：

```text
dfs(i)      → 这一层选了 i，下一层可以从 i 开始（含 i 自己）→ 可重复，且下标永不回退 → 不重
dfs(i + 1)  → 这一层选了 i，下一层从 i+1 开始                → 每个下标最多一次
dfs(0)      → 每层都从 0 开始                                 → 顺序任意 → 大量重复解
```

### 第三步：灵感的来源 —— 「下标单调不减」

把解写成一个**非递减**的下标序列：`i₁ ≤ i₂ ≤ … ≤ i_k`（注意这里是 `≤`，而 098 是 `<`）。

- 「非递减」保证了 `[2,3]` 只能以「先选下标 0 的 2、再选下标 1 的 3」出现一次；`[3,2]` 需要下标序列 `1,0`，递减，永远生成不出来。
- 「允许相等」保证了 `[2,2,2]` 可以出现：下标序列 `0,0,0`。
- 而「非递减下标序列」这件事，在代码里就是一个字：递归时传 `i` 而不是 `i+1`。

```text
dfs(start=0) ──选 i=0(值2)──▶ dfs(start=0) ──选 i=0(值2)──▶ dfs(start=0) ...
                                    │
                                    └──选 i=1(值3)──▶ dfs(start=1) ...      ← 起点前进，不再回头
```

**这就是 096 §3.2 那句「给每个解指定唯一的规范形」的第二次实践**：这次的规范形不是「下标严格递增」，而是「下标非递减」。规范形变了，`i+1` 就变成了 `i`。

### 第四步：第二个技巧 —— 和值剪枝

只靠 `i` 与 `i+1` 的差别，代码是对的但会很慢：`[1], target=500` 要一路递归到 500 层，`[[1,1,…]]` 一条路走完还行，但 `[1,2], target=500` 会有大量「走到底才发现和超了」的分支。

排序之后加两条剪枝：

```text
① 若 sum == target  → 收集并 return（不再继续加，因为加任何数都超）
② 若 sum >  target  → 直接 return / 在循环里 break（因为 candidates 已升序，
                        后续的候选只会更大，本层后面的分支全都不可能）
```

`break` 与 `return` 的区别值得单独说：**循环内 `break` 只砍掉「本层后面的兄弟」，不影响上一层继续尝试别的候选**；而 `return` 砍掉整个结点。本题两者都能用（因为 `sum > target` 对整个结点成立），但 `break` 更精确——它只表达「后面的都不用试了」，我们不需要放弃整个结点（该结点其实已经无事可做，所以两者等价）。

## 099.3 原理拆解

### 099.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 位掩码枚举 | — | — | — | **根本无法表达「取多次」**，直接淘汰 |
| `n` 层嵌套循环枚举「每种取几张」 | `O(∏(T/c_i + 1))` | `O(n)` | 无法写 | 循环层数由 `n` 决定，`n` 是运行时参数 |
| 完全背包 DP | `O(n·target)` | `O(target)` | 15 行 | **只能给出方案数 / 最少张数，给不出具体方案**（要输出方案就得记录路径，退化为回溯） |
| BFS（把 sum 当图结点） | `O(n·target)` | `O(target²)` 记录路径 | 25 行 | 要保存「到每个 sum 的所有路径」，内存是方案数级别的，比回溯更差 |
| **回溯 + `dfs(i)` + 和值剪枝** ✅ | `O(S)`（S = 搜索树结点数） | `O(target/min)` 栈 | **13 行** | 答案数量本身爆炸时（本题题目保证 < 150，不会发生）；`target` 到 `10^4` 时深度过大 |

**为什么选最后一行**：题目要的是**方案本身**，不是方案数，因此 DP 直接出局（它答不出「分别是哪些」）。而在所有「枚举方案」的方案里，回溯是唯一能**同时**做到「不重不漏」（靠下标非递减）和「提前止损」（靠和值剪枝）的结构。

### 099.3.2 为什么这个做法是对的（正确性论证）

**引理 1（不重）**：算法产生的每条路径，其下标序列非递减；而任何一个多重集 `Σ c_i · candidates[i] = target` 唯一对应一个**非递减**下标序列（把值 `candidates[i]` 重复 `c_i` 次，按 `i` 升序排列）。

> 证明：设某条路径的下标序列为 `j₁ ≤ j₂ ≤ … ≤ j_k`（递归传 `i` 保证这一点：下一层的起点是上一层选的 `i`，所以下一个下标 `≥ i`）。这样的序列唯一确定每个下标出现的次数 `c_i`，从而唯一确定一个组合。反之给定 `(c_i)`，非递减序列就是 `c_i` 个 `i` 按序拼接，唯一。∎

**引理 2（不漏）**：对任意满足 `Σ c_i · candidates[i] = target` 的 `(c_i)`，存在一条路径生成它。

> 归纳构造：从 `dfs(0, sum=0)` 出发，按下标从小到大处理。对每个 `i`，如果 `c_i > 0`，就在当前结点连续走 `c_i` 次「选 `i`」这条边（因为递归传 `i`，每走一次后起点仍是 `i`，所以这条边一直可用），`sum` 增加 `c_i · candidates[i]` 后仍 `≤ target`，因此每一步都不会被剪枝打断；当 `sum == target` 时恰好收集。∎

**引理 3（剪枝安全）**：`candidates` 升序时，若在某个结点处 `sum + candidates[i] > target`，则本层所有 `i' ≥ i` 的分支都不可能产出解。

> 证明：`candidates` 升序 ⟹ `candidates[i'] ≥ candidates[i]` ⟹ 选 `i'` 之后 `sum' = sum + candidates[i'] ≥ sum + candidates[i] > target`；而所有候选都是正数（`candidates[i] ≥ 2`），`sum` 只增不减，所以后续无论怎么选都 `> target`，永远回不到 `target`。∎

于是 `break` 不丢解。

**定理**：算法输出恰好是全部合法组合，每个一次。

> 引理 1（不重）+ 引理 2（不漏），引理 3 只砍掉无解分支。∎

> **为什么必须有 `candidates[i] ≥ 1`**：若允许 0 或负数，`sum` 不再单调增，引理 3 的「只增不减」失效，搜索树可能有**无限深**的分支（一直加 0 或加负数再凑回来），本题会变成「无限解集」。这是「约束里的数字不是装饰」的典型例子。

### 099.3.3 通用解题思路（可迁移的那一层）：`dfs(i)` vs `dfs(i+1)`

这是本章要装进工具箱的核心对照。**两个版本共享同一棵树、同一套剪枝，只差递归参数**：

```text
┌──────────────────── 一个参数的两种世界 ────────────────────┐
│                                                          │
│  dfs(i + 1)   →  「这一位用完了，后面的下标不能再选」        │
│                  规范形：下标【严格递增】i₁ < i₂ < … < i_k   │
│                  每个下标最多出现 1 次                        │
│                  典型题：096 子集 / 097 子集II / 098 组合     │
│                          / 100 组合总和II                    │
│                                                          │
│  dfs(i)       →  「这一位可以再用，也可以往后走」            │
│                  规范形：下标【非递减】i₁ ≤ i₂ ≤ … ≤ i_k     │
│                  每个下标可以出现多次                        │
│                  典型题：099 组合总和（本题）                 │
│                                                          │
│  dfs(0)       →  「每层都可以从头挑」                        │
│                  规范形：无（任何顺序都合法）                 │
│                  会产生 [2,3] 与 [3,2] 两份 → 必须另加去重     │
│                  典型题：101 全排列 / 102 全排列II（改用 used）│
└──────────────────────────────────────────────────────────┘
```

**099 与 100 的对照（本章与下一章的分界线）**：

| 维度 | 099 组合总和 | 100 组合总和 II |
| --- | --- | --- |
| 输入元素 | **互不相同** | **可能重复** |
| 每个下标能用几次 | 任意次 | **最多 1 次** |
| 递归参数 | `dfs(i)` | `dfs(i+1)` |
| 同层去重 | 需要的场合不存在（值不重复，那一行永不触发） | **必须**：`i > start && c[i]==c[i-1] → continue` |
| 剪枝 | `sum > target` → `break`（数组已排序） | 同上 |
| 为什么不能互换 | 换成 `dfs(i+1)` 会漏掉 `[2,2,2]` | 换成 `dfs(i)` 会把同一个 2 用多次，输出重复解 |

一句话记住：**`i+1` 管「不许复用」，同层去重管「不许重复值」，两者是两条独立的约束，缺哪条补哪条。**

统一骨架（本章版）：

```text
void dfs(int start, int sum, path) {
    if (sum == target) { ans.add(copy(path)); return; }   // 收集：恰好凑满
    for (int i = start; i < n; i++) {
        if (sum + c[i] > target) break;                   // ② 可行性剪枝（c 已升序）
        path.add(c[i]);                                   // ③(a)
        dfs(i, sum + c[i], path);                         //     递归：传 i → 可重复
        path.removeLast();                                // ③(b)
    }
}
```

属于「可重复选取」这个模型的题：

| 题 | 「可重复」怎么体现 | 额外约束 |
| --- | --- | --- |
| [LC 39 组合总和](https://leetcode.cn/problems/combination-sum/) | `dfs(i)` | 和恰为 `target` |
| [LC 40 组合总和 II](https://leetcode.cn/problems/combination-sum-ii/) | 不允许 → `dfs(i+1)` | 有重复值 + 只能用一次 |
| [LC 322 零钱兑换](https://leetcode.cn/problems/coin-change/) | DP 里正序遍历（完全背包） | 求**最少张数**，不要方案 |
| [LC 518 零钱兑换 II](https://leetcode.cn/problems/coin-change-ii/) | DP 里正序遍历 | 求**方案数**，不要方案 |
| [LC 216 组合总和 III](https://leetcode.cn/problems/combination-sum-iii/) | 不允许 | 个数 + 和值双约束 |
| [LC 377 组合总和 Ⅳ](https://leetcode.cn/problems/combination-sum-iv/) | DP 里外层遍历和 | **顺序不同算不同**→ 与本题相反，是排列 |

### 099.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**方案数**，不要方案 | 输出退化成一个数字 | 完全背包：`dp[0]=1`、`dp[s] += dp[s-c[i]]`，外层遍历物品，`O(n·target)`。**答案可能与回溯完全相同，但快 3 个数量级** |
| 每个数**只能用一次** | 输入语义变化 | 递归传 `i+1`；若还有重复值，必须加同层去重 → 就是 100 |
| 「顺序不同算不同」（`[2,3]` 与 `[3,2]` 都算） | 排列语义 | 变成 LC 377：DP 外层遍历和、内层遍历物品；回溯则是 `used` 数组版本 |
| 要求**最少张数**的方案 | 最优化 | 先用 DP 求最少张数 `m`，再回溯时只接受 `len == m` 的方案（最优性剪枝） |
| `candidates` 含**负数或 0** | 单调性破坏 | 必须显式限制「每个数最多用 `k` 次」并加 `visited` 去重，否则搜索树无限深。这是本题最危险的变体 |
| `target` 涨到 `10^5` | 深度爆炸 | 回溯不可行，只能 DP 求数 / 求方案数；要输出具体方案时用「DP 表 + 记忆化路径重构」 |

## 099.4 图解推演

### 099.4.1 `candidates = [2,3,6,7], target = 7` 的决策树

```text
                       dfs(start=0, sum=0, path=[])
        ┌───────────────┬───────────────┬───────────────┬──────────────┐
      i=0(2)          i=1(3)          i=2(6)          i=3(7)
      sum=2           sum=3           sum=6           sum=7 ✅收集 [7]
        │               │               │
   ┌────┼────┐      ┌───┴───┐       i=2: 6+6=12>7 ⊘break
 i=0(2) i=1(3) i=2(6) i=1(3) i=2(6)  （本层第 1 个候选就超 → 整层放弃）
 sum=4  sum=5  ⊘break sum=6  ⊘break
   │      │              │
   │      └─i=1: 5+3=8>7 ⊘  └─i=1: 6+3=9>7 ⊘break
   │         （无 [2,3,3]）
┌──┼────┐
i=0(2)  i=1(3)
sum=6   sum=7 ✅收集 [2,2,3]
   │
 i=0: 6+2=8>7 ⊘break（无 [2,2,2,…]）

★ 根到 i=0 的那条边（值 2）下面，i 依然从 0 开始 → 2 才能被连选两次、三次
⊘ break：c 升序，sum + c[i] > target 时本层后面的候选（值更大）全部放弃
```

把真正产出答案的两条路径描出来：

```text
路径之一（连选 3 次 2 再补 3）：
  dfs(0,0) ─选2→ dfs(0,2) ─选2→ dfs(0,4) ─选3→ dfs(1,7) ✅ [2,2,3]
                                                └─ 4+3 = 7，恰好命中

路径之二（一步到位）：
  dfs(0,0) ─选7→ dfs(3,7) ✅ [7]
                     └─ 7+? 已等于 target → 收集后立刻 return

被剪掉的两处典型分支：
  dfs(0,4) 的 i=2（值 6）：4+6 = 10 > 7 → break，本层后面的候选全部放弃
  dfs(0,6) 的 i=0（值 2）：6+2 = 8  > 7 → break，不会出现 [2,2,2,2]
```

### 099.4.2 两个版本的执行轨迹对照（`candidates=[2,3]`, `target=5`）

| 版本 | 递归参数 | 生成的候选解 | 结果 | 说明 |
| --- | --- | --- | --- | --- |
| A | `dfs(i)` | `[2,3]` 能从「先 2 后 3」生成，`[3,2]` **不能**（下标会回退到 0） | ✅ 正确 | 非递减规范形 |
| B | `dfs(i+1)` | 只能生成 `[2,3]`，`[2,2,…]` 全部消失 | ❌ 漏解 | 退化成「每个元素一次」 |
| C | `dfs(0)` | 生成 `[2,3]` 与 `[3,2]` 两份 | ❌ 重复 | 无规范形 |

### 099.4.3 剪枝的量化效果（实测：把 `break` 换成 `continue`）

我用同一个模板跑了四组输入，只改一个字符（`break` ↔ `continue`），统计「循环迭代次数 / 递归调用次数」：

| 输入 | 解数 | `continue`（不 break） | `break` | 省下的迭代 |
| --- | --- | --- | --- | --- |
| `[2,3,6,7], t=7` | 2 | 27 / 10 | **16 / 10** | 11 |
| `[2,3,5], t=8` | 3 | 22 / 13 | **19 / 13** | 3 |
| `[1,2], t=10` | 6 | 40 / 36 | 40 / 36 | 0 |
| `[2,3], t=23` | 4 | 64 / 56 | **63 / 56** | 1 |

**两个必须看懂的观察**：

1. **`break` 只省「循环迭代」，不省「递归调用」**——因为 `sum + c[i] > target` 这个判断本来就写在**递归之前**，被剪掉的候选从来不会产生调用。所以本题的 `break` 是常数级优化，真正把树变小的仍是「传 `i` + 传 `sum` 让判断发生在更上层」。
2. **`[1,2], t=10` 那一行完全没变**：因为候选里 `1+2` 永远不超限，`break` 从未触发。**这说明剪枝的效果强依赖输入分布**，所以「我加了个剪枝」这句话必须配上具体数据才可信。

真正省下大头的剪枝在 100（同层去重，直接把等价的整棵子树砍掉）与 104（列/对角冲突，第一层就砍掉大部分棋盘）。

## 099.5 双语言实现

### 099.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        // 排序是 break 剪枝的前提：只有升序才能「一旦超了就放弃本层后面所有候选」
        Arrays.sort(candidates);

        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        dfs(candidates, 0, 0, target, path, res);
        return res;
    }

    /** start = 本层最小可选下标；sum = 当前 path 的和 */
    private void dfs(int[] c, int start, int sum, int target, List<Integer> path, List<List<Integer>> res) {
        if (sum == target) {
            res.add(new ArrayList<>(path));   // 深拷贝：path 还会被后续分支改写
            return;                           // 已凑满，再加任何正数都会超
        }

        for (int i = start; i < c.length; i++) {
            // ② 可行性剪枝：c 升序 → 当前候选已超，后面更大的候选必然也超
            //    用 break 而不是 continue：后续候选全都不可行，没必要再进循环
            if (sum + c[i] > target) {
                break;
            }
            path.add(c[i]);                              // ③(a) 选择
            // 递归传 i（不是 i+1）：同一个下标可以再选 → 「可重复使用」
            // 同时 i 不回退 → 下标序列非递减 → [3,2] 这种换序重复不会产生
            dfs(c, i, sum + c[i], target, path, res);
            path.remove(path.size() - 1);                // ③(b) 撤销
        }
    }
}
```

### 099.5.2 Go

```go
package main

import "sort"

func combinationSum(candidates []int, target int) [][]int {
	sort.Ints(candidates) // break 剪枝的前提

	res := make([][]int, 0)
	path := make([]int, 0)

	var dfs func(start, sum int)
	dfs = func(start, sum int) {
		if sum == target {
			// 必须深拷贝：path 的底层数组还会被后续分支反复复写
			res = append(res, append([]int(nil), path...))
			return
		}
		for i := start; i < len(candidates); i++ {
			if sum+candidates[i] > target {
				break // 升序 → 后面更大的候选全都不可行
			}
			path = append(path, candidates[i]) // ③(a) 选择
			dfs(i, sum+candidates[i])          //     递归传 i：可重复使用同一个下标
			path = path[:len(path)-1]          // ③(b) 撤销
		}
	}
	dfs(0, 0)
	return res
}
```

### 099.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 结果里的 `path` | `new ArrayList<>(path)` | `append([]int(nil), path...)` | **都必须深拷贝**；本题一条路径可长达 `target/min = 250` 个元素，切片别名污染更严重 |
| 撤销 | `path.remove(path.size()-1)` | `path = path[:len(path)-1]` | Java 的 `remove(int)` 是删下标；误写 `remove(c[i])` 删的是**值** |
| 排序 | `Arrays.sort(candidates)` | `sort.Ints(candidates)` | 两边都原地改入参；本题允许（LeetCode 不校验入参） |
| 和值的类型 | `int`（`target ≤ 500`） | `int`（64 位平台是 64 位） | 都安全；若 `target` 放大到 `10^9`+，累加要用 `long`/`int64` |
| 递归参数个数 | 显式传 `sum` | 闭包捕获 + 传 `sum` | Go 里也可以把 `sum` 放在闭包外层，但**放在参数里更安全**：撤销时不用手工回退 `sum` |

#### ⚠️ Go 切片别名：本章的实测反例

本题因为路径可以很长，「不拷贝」的后果比前几章更难看：结果切片的**长度**都是坏的。我在 `/tmp/alias4` 实跑了 `candidates=[2,3,7], target=7`：

```text
不加拷贝（错误）  res = append(res, path)
  [[7 3 3] [7]]
  ↑ 第一项本该是 [2 2 3]：内容被覆盖成 [7 3 3]，
    连长度都不对（3 对得上，但值是脏的——底层数组已被后来的分支复写）

加拷贝（正确）  res = append(res, append([]int(nil), path...))
  [[2 2 3] [7]]        ✓

c=[2,3,5], target=8
  不加拷贝：[[5 5 3 2] [5 5 3] [5 5]]     ← 三项的长度分别是 4、3、2，长度都被改了
  加拷贝  ：[[2 2 2 2] [2 3 3] [3 5]]     ✓
```

**为什么长度都会错**：`append(res, path)` 存的是一个**定格的 `len`**，这本身不会变；但被打印时读的是 `ptr` 指向的数组内容，而回溯过程中 `path` 反复加长/缩短，同一块内存里先后住过 `[2,2,3]`、`[2,2]`、`[2]`、`[3]`、`[7]` 等不同内容，于是「定格的长度 + 变化的内容」拼出了完全非法的切片。

```go
// 写法 1（推荐）：显式深拷贝
res = append(res, append([]int(nil), path...))

// 写法 2：三下标截断，让「存进去那份」的 cap == len
//   它只保护「通过这个头」的后续 append，挡不住 path 自己这个 cap > len 的头
//   本题实测仍会污染，所以请把它当成「辅助加固」而不要当成替代品
res = append(res, path[:len(path):len(path)])
```

### 099.5.4 对拍测试（写完必须跑）

参考实现用**「按候选值枚举使用次数」的独立递归**（不复用 `dfs(i)` 的思路），专门用来抓「可重复/不可重复」写错的问题。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"

// 参考实现：对每个候选值独立枚举使用次数 0..target/c，凑满即收集
func bruteCombSum(c []int, target int) [][]int {
	cands := append([]int(nil), c...)
	sort.Ints(cands)
	out := [][]int{}
	cur := []int{}
	var rec func(idx, rest int)
	rec = func(idx, rest int) {
		if rest == 0 {
			out = append(out, append([]int(nil), cur...))
			return
		}
		if idx == len(cands) {
			return
		}
		// 用 0 次、1 次、2 次 …… 直到超过 rest
		for cnt := 0; cnt*cands[idx] <= rest; cnt++ {
			for k := 0; k < cnt; k++ {
				cur = append(cur, cands[idx])
			}
			rec(idx+1, rest-cnt*cands[idx])
			for k := 0; k < cnt; k++ {
				cur = cur[:len(cur)-1]
			}
		}
	}
	rec(0, target)
	return out
}

func normCS(res [][]int) [][]int {
	out := make([][]int, len(res))
	for i, r := range res {
		c := append([]int(nil), r...)
		sort.Ints(c)
		out[i] = c
	}
	sort.Slice(out, func(a, b int) bool {
		if len(out[a]) != len(out[b]) {
			return len(out[a]) < len(out[b])
		}
		for k := range out[a] {
			if out[a][k] != out[b][k] {
				return out[a][k] < out[b][k]
			}
		}
		return false
	})
	return out
}

	r := rand.New(rand.NewSource(2026099))
	for iter := 0; iter < 4000; iter++ {
		n := 1 + r.Intn(5)
		seen := map[int]bool{}
		c := []int{}
		for len(c) < n { // 题目保证互不相同
			v := 1 + r.Intn(9)
			if !seen[v] {
				seen[v] = true
				c = append(c, v)
			}
		}
		target := 0 + r.Intn(20) // 含 target = 0 的边界

		want := normCS(bruteCombSum(c, target))
		if len(got) != len(want) {
			t.Fatalf("iter=%d c=%v t=%d 数量 %d != %d", iter, c, target, len(got), len(want))
		}
		for i := range got {
			if len(got[i]) != len(want[i]) {
				t.Fatalf("iter=%d c=%v t=%d 第%d项 %v vs %v", iter, c, target, i, got[i], want[i])
			}
			for k := range got[i] {
				if got[i][k] != want[i][k] {
					t.Fatalf("iter=%d c=%v t=%d 第%d项 %v vs %v", iter, c, target, i, got[i], want[i])
```

## 099.6 复杂度与常见坑

### 099.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(S · target/min)`，其中 `S` 是搜索树的结点数；最坏上界 `O(n^{⌊T/m⌋})`。**

推导分三步：

1. **树有多深**：每层至少加 `m = min(candidates) ≥ 1`，所以深度 `≤ ⌊T/m⌋`。
2. **每层有几个分支**：最多 `n` 个。因此结点数上界 `Σ_{d=0}^{⌊T/m⌋} n^d = O(n^{⌊T/m⌋})`。这是**指数级**的，也是为什么「答案 < 150」这条保证如此重要——真实结点数远小于这个上界。
3. **每个收集点的工作量**：拷贝 `path`，长度 `≤ T/m`。

于是总时间 `O(S · T/m)`。**剪枝把 `S` 从理论上界压到「与答案数量同阶」**：每条被保留的根到叶路径都对应一个解，而题目保证解 `< 150` 个。

**空间 `O(T/m)`（不含输出）**：递归深度 `≤ ⌊T/m⌋`，`path` 长度同阶。`target = 500`、`m = 2` 时是 250 层——不会爆栈，但也是本部分最深的递归之一。

### 099.6.2 七个真实踩过的坑

1. **递归传了 `i+1`** —— 退化成「每个元素只能用一次」，`[2,2,3]` 消失。修法：改成 `dfs(i, ...)`。这是本题最高频的错。
2. **递归传了 `start`（而不是 `i` 或 `i+1`）** —— 下标可以回退，`[2,3]` 与 `[3,2]` 都出现 → 重复解，且搜索树可能周期性膨胀。
3. **忘了排序却用了 `break`** —— `[7,3,2], target=7` 时，`i=1`（值 3）走到 `sum=3`，下一层 `i=1` 又是 3，`3+3=6 ≤ 7` 继续，再 `+3 = 9 > 7` 就 `break`，但后面的 `2`（下标 2）**本可以凑成 7**，被 `break` 一起砍掉 → 漏解。**`break` 只在升序时正确。**
4. **收集后忘了 `return`** —— `sum == target` 之后继续加正数，永远 `> target`，白跑（若剪枝写对则被 `break` 挡住，但多一层无用递归）。
5. **`sum` 作为闭包变量却没有回退** —— Go 里如果把 `sum` 放在闭包外层用 `sum += x` 修改、撤销时忘了 `sum -= x`，后续分支全带错的和。**把 `sum` 当参数传是最稳的写法。**
6. **`target = 0` 的语义** —— 官方约束 `target ≥ 1`，但代码天然会返回 `[[ ]]`（空组合和为 0）。若被追问「`target=0` 该返回什么」，答案要按题目语义说清楚：**空组合的和是 0，所以 `[[]]` 是对的**；若题目要求非空组合，则要在收集处加 `len(path) > 0`。
7. **Go 里 `res = append(res, path)`** —— 切片别名，所有结果指向同一数组（§099.5.3 实测）。

### 099.6.3 面试官最爱追问的三个问题

**Q1：为什么传 `i` 就能做到「可重复」又「不重复解」？**
> 「传 `i` 让下标序列**非递减**：允许相等 → 同一下标可以用多次（可重复）；不允许回退 → 任何组合只能按值从小到大排列出现一次（不重）。这两件事是同一个约束的两面。如果传 `start`（每层从头），下标可以回退，`[2,3]` 和 `[3,2]` 都会出现；如果传 `i+1`，下标严格递增，同一个元素用不了第二次。」

**Q2：这题能不能用 DP？**
> 「求**方案数**可以用完全背包 `O(n·target)`；但本题要**方案本身**，DP 必须额外记录路径，重构路径的代价与方案数同阶，反而比回溯差。所以：**「要数」用 DP，「要列出」用回溯**。这也是 518（零钱兑换 II）与本题输入几乎相同、解法却完全不同的原因。」

**Q3：`target = 500`、`candidates = [1]` 时递归 500 层，会不会栈溢出？**
> 「不会。500 层对 JVM 默认栈（约 512KB~1MB，每帧几十字节到几百字节）绰绰有余，LeetCode 上这类题递归到几千层才有风险。真要更稳，可以改成显式栈迭代，但代码复杂度会明显上升。**真正该担心的是指数级的结点数，而不是深度**——本题靠「答案 < 150」这条保证才安全。」

```text
③ 「要数用 DP，要列出用回溯」：322/518 与本题输入相同、解法不同，原因在此
```
