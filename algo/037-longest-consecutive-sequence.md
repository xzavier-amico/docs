## 037.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-consecutive-sequence/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`（**无序**，可能含重复值与负数），求**最长的连续整数序列的长度**。要求算法 `O(n)`。

「连续整数序列」指的是形如 `x, x+1, x+2, …, x+k` 这样的一串值，它们的**数值**连续，但在数组里的**下标**可以任意分散。

这句话背后有五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 序列只要求「值连续」，**不要求下标连续** | 题面「不需要在数组中连续」 | 误做成「最长连续子数组」→ 变成 LC 674，答案完全不同 |
| 数组**无序** | 输入示例 `[100,4,200,1,3,2]` | 不能直接一次线性扫描；要么排序，要么哈希 |
| 可能**有重复值** | 约束只说了范围，没说互不相同 | `[1,1,2]` 的答案是 2 而不是 3；不去重就会多算 |
| 值域含**负数**、可达 `±10^9` | `-10^9 <= nums[i] <= 10^9` | 不能用「值当下标」的布尔数组（要 20 亿格内存），也不能整体偏移 |
| 要求 **`O(n)`** | 「请你设计并实现时间复杂度为 `O(n)` 的算法」 | 排序解 `O(n log n)` 虽然能过，但**不满足题目要求**，面试里必须给出线性解 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= nums.length <= 10^5` | n 最多十万 | 排序 `O(n log n) ≈ 1.7·10⁶` 次比较，本机 Java ≈ 18 ms、Go ≈ 12 ms，**能过**；但线性解只要 `O(n)` |
| 单次 `contains` 若线性扫描 | 每次 `O(n)` | 最坏 `O(n²) = 10^10`，必超时。**哈希把这一步压成均摊 O(1)** |
| `-10^9 <= nums[i] <= 10^9` | 值域宽 2·10⁹ | 桶 / 计数数组都不可行（20 亿格 × 1 字节 = 2 GB）。哈希表只存实际出现的 n 个数 |
| `nums.length` 可以为 **0** | 空数组合法 | 必须返回 0；`max` 的初值要取 0 而不是 1 |
| 答案最大是 n（去重后更小） | 全数组连续时答案为 n | 循环里 `len` 从 1 开始（起点自己算一个），别漏 |

> 💡 **量级 → 算法**：n = 10⁵ 有两种活法 —— `O(n log n)` 排序，或者 `O(n)` 哈希。
> 本题的特殊之处是：**约束直接写了「O(n)」**。所以排序解只是「能过测试的起点」，不是「答案」。
> 这也是本章的主线：**一个看起来必须 O(n²) 的「扩展」动作，靠「只在起点扩展」变成了均摊 O(n)。**

### 示例

```
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长连续序列是 [1,2,3,4]，长度 4。注意 100、200 各自成段，长度都是 1。

输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
解释：0..8 全部出现（0 出现了两次），长度 9。

输入：nums = []
输出：0
```

### 我自造的五个反例（写完必须拿它们打一遍）

```text
① []                        → 必须返回 0（不是 1，也不能崩）
② [1]                       → 返回 1：单元素自己就是长度 1 的连续段
③ [1,1,2]                   → 返回 2。用「数组长度」当答案会得 3，用「去重后的集合」才对
④ [1,2,0,1]                 → 返回 3（0,1,2）。重复的 1 不能把长度撑大
⑤ [9,1,4,7,3,-1,0,5,8,-1,6] → 返回 7（-1..5）。负数段与正数段并存，且 -1 重复
```

第 ③ 条是本题最高频的错误来源：**答案取决于「值集合」，而不是「数组」。** 一旦意识到这点，`Set` 就是天然的容器，重复值问题自动消失。

## 037.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的写法是「对每个数，看它能不能往右接」：

```java
// 暴力：对每个 x，用线性查找问「x+1 在不在数组里」，一路问到断
int best = 0;
for (int x : nums) {
    int cur = x, len = 1;
    while (containsLinear(nums, cur + 1)) {   // O(n) 的查找
        cur++;
        len++;
    }
    best = Math.max(best, len);
}
```

- 时间 `O(n²·L)`（L 为连续段长度，最坏 `O(n³)`：每个起点都要走完整个段，每次走一步还要线性查找一次），空间 `O(1)`。
- 在「全数组连续」这种最坏输入上（`n = 10⁵`），每个起点都要扩展到段尾，总步数是 `1+2+…+n ≈ 5·10⁹` 步，每步还带一次 `O(n)` 查找 —— 这不是「慢一点」，是「跑到天亮」。

### 第二步：第一步优化 —— 把「查找」换成哈希

`containsLinear` 是明确的浪费。把 `nums` 灌进 `HashSet`，查找变成均摊 `O(1)`：

```java
Set<Integer> set = new HashSet<>();
for (int x : nums) set.add(x);

int best = 0;
for (int x : set) {
    int cur = x, len = 1;
    while (set.contains(cur + 1)) { cur++; len++; }
    best = Math.max(best, len);
}
```

- 时间 `O(n + n·L)`：外层 n 次，内层最坏仍要走完整个段。
- 在「全数组连续」时，总步数仍是 `1+2+…+n ≈ 5·10⁹` —— **哈希只解决了「查找」，没解决「重复扩展」**。
- 这就是本题的核心卡点：**同一个连续段被从头到尾走了 n 遍。**

### 第三步：卡点在哪

把暴力翻译成一句话：

> **对每个 `x`，我都问一次「以 `x` 开头能延伸多长」。**

问题在于：一个长度为 `L` 的连续段里有 `L` 个元素，暴力会为这 `L` 个元素各算一次「延伸长度」，而它们算出来的答案高度重叠 —— 从 `1` 开始算得到 `[1..4]`，从 `2` 开始算得到 `[2..4]`，从 `3` 开始算得到 `[3..4]`。

**重复劳动的量级是 `O(L²)`，而真正必要的信息只有「这一整段有多长」。**

### 第四步：灵感的来源 —— 「只从起点扩展」

关键观察：

```
整段 [1,2,3,4] 里，只有 1 是「这一段的最小值」
             ↓
只有 1 满足「1-1 = 0 不在集合里」
             ↓
于是：对每个 x，先问一句「x-1 在不在集合里？」
     在 → x 不是起点 → 直接跳过（一个元素都不扩展）
     不在 → x 是起点 → 从这里向右扩展，把这个段一次性走完
```

```
┌──────────────────────────────────────────────────────────────┐
│ 剪枝规则：只有 x-1 ∉ set 的元素才触发 while 扩展              │
│                                                              │
│ 效果：每个连续段只被完整走一次，且只由它的最小元素触发        │
└──────────────────────────────────────────────────────────────┘
```

这个剪枝的妙处在于：它**不是**「少做一点」，而是**让总工作量从 `O(ΣL²)` 掉到 `O(ΣL) = O(n)`**。

### 第五步：为什么复杂度还是 O(n)（这是本题最容易被面试官追问的点）

很多人会本能地反驳：「外层一个 `for`、内层一个 `while`，这不就是 `O(n²)` 吗？」

**不是。要按「每个元素被访问几次」来算，而不是看循环嵌套的层数。**

对任意元素 `v`，它可能被访问的两个时机：

| 时机 | 触发条件 | 每个元素最多发生几次 |
| --- | --- | --- |
| 外层 `for` 扫到它 | 无条件 | **1 次**（`for` 遍历集合每个元素一次） |
| 内层 `while` 访问它 | 它属于某个段 `[s, …, s+L-1]`，且 `s-1 ∉ set`，且当前正在从 `s` 扩展 | **1 次**（一段只有一个起点，起点只触发一次扩展） |

两条合计：**每个元素最多被访问 2 次**，总工作量 ≤ `2n`，即 `O(n)`。

> 更形式化地说：把集合按「连续关系」划分成若干互不相交的极大段 `S₁, S₂, …, Sₘ`，`Σ|Sᵢ| = n`（去重后）。
> 每个段 `Sᵢ` 恰好有 1 个起点（它的最小值），且只有这个起点能通过 `x-1 ∉ set` 的检查。
> 于是 `while` 的总迭代次数 = `Σ(|Sᵢ| - 1) ≤ n`。**这就是「均摊」二字的落点：不是每次 while 都便宜，而是所有 while 加起来便宜。**

## 037.3 原理拆解

### 037.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力（线性查找扩展） | `O(n³)` | `O(1)` | 6 行 | n ≥ 10³ 就废；仅用于说明问题 |
| 排序 + 一次扫描 | `O(n log n)` | `O(1)`~`O(n)` | 12 行 | **题目明确要求 O(n)**；且要处理重复值（`nums[i] == nums[i-1]` 时不能 `len++`） |
| 哈希集 + 只从起点扩展 ✅ | **`O(n)`** | `O(n)` | 10 行 | 需要把所有值放进内存；值域再大也不怕，但**内存是硬约束**时不行 |
| 哈希集 + 边删边扩展 | `O(n)` | `O(n)` | 12 行 | 也是 `O(n)`，常数更小（已访问的元素从集合里删掉），但代码更容易写错 |
| 哈希表存「段长」并合并 | `O(n)` | `O(n)` | 20 行 | 每个值存「以它为端点的段长」，插入时合并左右邻段。能在线回答「当前最长」，适合**数据流** |
| 并查集 | `O(n·α(n))` | `O(n)` | 25 行 | 本质是「值相邻则连边」，实现重；只在需要动态合并 / 查询连通性时才有优势 |

**排序解 vs 哈希解，怎么取舍？**

| 维度 | 排序 + 扫描 | 哈希集 + 起点扩展 |
| --- | --- | --- |
| 时间 | `O(n log n)` | `O(n)` |
| 空间 | 原地排序 `O(1)`（但会改输入）或拷贝 `O(n)` | `O(n)` |
| 是否改输入 | 原地排序会改 | 不改 |
| 常数 | 排序的常数小，n = 10⁵ 时实测只差几毫秒 | 哈希有装箱 / 分配开销 |
| 面试答法 | 「能过，但不满足题面的 O(n) 要求，作为 fallback 提一句」 | 「正解」 |

> ⚠️ **别被「实测差不多」骗了**：n = 10⁵ 时两者都只要十几毫秒，看不出差距。但把 n 放大到 10⁷，`n log n` 比 `n` 多出约 `23` 倍的比较次数，差距就出来了。
> **复杂度是「随 n 增长的趋势」，不是「当前这台机器上的毫秒数」。**

### 037.3.2 为什么这个做法是对的（正确性论证）

**定义**：把 `nums` 去重后得到集合 `S`。若 `x ∈ S` 且 `x-1 ∉ S`，称 `x` 是**起点**。从 `x` 出发、不断加 1 能到达的最大值记为 `end(x)`，段长 `L(x) = end(x) - x + 1`。

**引理 1（每个极大段恰有一个起点）**：设 `[s, e]` 是 `S` 的一个极大连续段（即 `s-1 ∉ S`、`e+1 ∉ S`、区间内每个整数都在 `S` 中）。则 `s` 是起点，而区间内任何 `y > s` 都满足 `y-1 ∈ S`，不是起点。∎

**引理 2（从起点扩展得到整段）**：若 `x` 是起点，则 `while` 循环依次访问 `x+1, x+2, …, e`，循环结束时 `len = e - x + 1 = L(x)`。因为段内每个整数都在 `S` 中，循环不会提前停；又因为 `e+1 ∉ S`，循环恰好停在 `e`。∎

**定理（算法输出正确答案）**：设 `ans = max{L(x) : x 是起点}`。

1. **`ans ≤ 真实答案`**：`L(x)` 是从 `x` 开始的真实连续段长度，当然不超过最长段长度。
2. **`ans ≥ 真实答案`**：设最长段为 `[s, e]`，由引理 1，`s` 是起点；由引理 2，算法在 `s` 处得到 `len = e - s + 1` = 真实答案。所以 `ans` 至少取到这个值。

两者合并，`ans` 恰为答案。∎

**再证复杂度**（§037.2 第五步的严格版）：由引理 1，起点的个数 = 极大段的个数 `m`；由引理 2，每个起点触发的 `while` 迭代 `L(x) - 1` 次。总迭代 `Σᵢ(Lᵢ - 1) = ΣᵢLᵢ - m ≤ n`。外层遍历 `|S| ≤ n` 次，每次 `contains` 均摊 `O(1)`。总时间 `O(n)`。∎

> **这个论证的价值**：它把「看起来两层循环」的直觉纠正过来了 —— 复杂度的账要记在**元素**头上，不是记在**循环**头上。
> 这个思维方式可以平移到所有「双指针 / 单调栈 / 并查集路径压缩」的均摊分析里：**都是「每个元素一生只被处理常数次」。**

### 037.3.3 通用解题思路（可迁移的那一层）

本章的主题是**「用下标（或值）当哈希」**与**「剪枝的正确姿势」**。本题属于后者，但用的是同一个底层动作：**把「在不在」这件事从线性查找变成 O(1) 查询。**

```
原始问题：在一堆无序的值里，找最长的「值连续」段
         ↓ 观察 1：段是"值"的性质，与下标无关
         ↓ 观察 2：一个段被它的最小元素唯一确定
优化：    用 HashSet 支持 O(1) 的「x-1 / x+1 在不在」
         ↓ 剪枝：只在 x-1 ∉ set 时扩展
         ↓ 记账：每个元素最多进 while 一次 → 总 O(n)
代价：    O(n) 空间
```

**可迁移的三条经验**：

| 经验 | 说法 | 同类题 |
| --- | --- | --- |
| **用「唯一代表元」避免重复枚举** | 每个等价类只从一个代表元开始处理 | 本章（段的最小值）、LC 49（每个等价类一个 key）、LC 200（每个岛一个入口） |
| **把「在不在」交给哈希** | 值域大且稀疏 → 哈希；值域小且连续 → 布尔数组 | LC 1、LC 217、LC 219 |
| **均摊分析记账到元素上** | 「每个元素被访问几次」比「几层循环」可靠 | 单调栈（每个下标进出各一次）、KMP、并查集 |

### 037.3.4 可扩展性（面试追问的方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**具体的那一段**（不只长度） | 输出变了 | 记录 `bestStart` 与 `bestLen`，最后从 `bestStart` 生成；不要在循环里反复构造列表 |
| 数据是**流式**的（边来边问当前最长） | 不能先建全表 | 用「哈希表存段长」：`len[x]` 表示包含 `x` 的段长。插入 `x` 时取 `left = len[x-1]`、`right = len[x+1]`，`total = left + right + 1`，并更新**两个端点**的段长。均摊 `O(1)` |
| 允许多台机器 / 内存放不下 | 分布式 | 按值域分桶（例如 `x div 10^6`）到不同机器，再处理跨桶边界的段拼接；或者按值域外部排序后单机扫描 |
| 值域很小（`0 <= nums[i] < n`） | 不需要哈希 | 用 `boolean[n]` 或位图（`long[n/64]`），空间从 `O(n)` 降到 `n/8` 字节 |
| 改成「**下标连续**的最长递增段」 | 语义变了 | 那就是 LC 674，一次线性扫描即可，不需要哈希（因为不要求值域连续，只要求相邻下标值 +1） |
| 改成「允许差 1 以内」（`|a-b| <= 1`） | 变成和谐序列 | LC 594：统计每个值的频次，答案 = `max(cnt[x] + cnt[x+1])`，也是哈希 |
| 要求「连续段的**元素个数**（含重复）」 | 语义变了 | 需要额外统计频次：段长 = `Σ cnt[x]`，哈希 value 从「存在」变成「计数」 |

## 037.4 图解推演

### 037.4.1 谁有资格当起点

```
nums = [100, 4, 200, 1, 3, 2]        set = {1, 2, 3, 4, 100, 200}

   值轴：
   ────┬────┬────┬────┬─────────┬──────────┬─────→
      -1    0    1    2    3    4    …    100   200
                 └────┴────┴────┘        │      │
                 一个极大段 [1..4]      单点    单点

   逐个检查「x-1 在不在 set」：
   ┌──────┬─────────────┬────────┬──────────────────────────┐
   │  x   │ x-1 ∈ set ? │ 是起点 │ 动作                     │
   ├──────┼─────────────┼────────┼──────────────────────────┤
   │  1   │ 0   ✗       │  是    │ 向右扩：2,3,4 → len=4    │
   │  2   │ 1   ✓       │  否    │ 跳过（0 次扩展）         │
   │  3   │ 2   ✓       │  否    │ 跳过                     │
   │  4   │ 3   ✓       │  否    │ 跳过                     │
   │ 100  │ 99  ✗       │  是    │ 101 不在 → len=1         │
   │ 200  │ 199 ✗       │  是    │ 201 不在 → len=1         │
   └──────┴─────────────┴────────┴──────────────────────────┘
                                        best = max(4,1,1) = 4
```

### 037.4.2 访问次数账本（O(n) 的证据）

| 元素 | 外层 for 访问 | 作为 while 的"下一步"被访问 | 合计 |
| --- | --- | --- | --- |
| 1 | 1（起点，触发扩展） | 0（它是起点，没人把它当"下一步"） | 1 |
| 2 | 1（非起点，跳过） | 1（被 1 的扩展访问） | 2 |
| 3 | 1 | 1（被 2 的扩展访问） | 2 |
| 4 | 1 | 1（被 3 的扩展访问） | 2 |
| 100 | 1（起点） | 0 | 1 |
| 200 | 1（起点） | 0 | 1 |

总计 9 次访问，`2n = 12`，`9 ≤ 12`。**这就是「每个元素最多被访问 2 次」的具体样子。**

对比暴力（不剪枝）在同一输入上的账本：

```
从 1 扩：访问 2,3,4          → 3 步
从 2 扩：访问 3,4            → 2 步
从 3 扩：访问 4              → 1 步
从 4 扩：无                  → 0 步
                合计 6 步（= L(L-1)/2 = 4·3/2）
```

段长 `L` 时暴力是 `L(L-1)/2`，剪枝后是 `L-1`。**当 `L = n` 时，前者 `5·10⁹`，后者 `10⁵` —— 差 5 万倍。**

### 037.4.3 两条路线的执行对比

```
                    ┌──────────── 输入 nums（无序、含重复）────────────┐
                    │                                                  │
        ┌───────────▼────────────┐                    ┌────────────────▼─────────────┐
        │ 路线 A：排序 + 扫描    │                    │ 路线 B：哈希集 + 只从起点扩展 │
        │ O(n log n) / O(1)~O(n) │                    │ O(n) / O(n)                  │
        └───────────┬────────────┘                    └────────────────┬─────────────┘
                    │                                                  │
        sort → 相邻差 1 则 len++，                  set.add 全部 → for x in set:
        差 >1 则重开一段；                               if x-1 ∉ set: 向右扩
        差 = 0（重复）必须跳过                            （非起点直接跳过）
                    │                                                  │
        ✅ 代码短、常数小、不改输入时空间 O(n)      ✅ 满足题面 O(n)、不改输入
        ❌ 不满足题面 O(n)；原地排序会改输入        ❌ 空间 O(n)、哈希有常数开销
                    │                                                  │
             【fallback 方案】                                  【本题正解】
```

## 037.5 双语言实现

### 037.5.1 Java

```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int longestConsecutive(int[] nums) {
        // 用 Set 而不是数组：值域 [-1e9, 1e9]，数组当下标要 20 亿格，必然爆内存。
        // Set 顺带完成了去重 —— 答案取决于"值集合"，重复值不该撑大长度。
        Set<Integer> set = new HashSet<>(nums.length * 2);
        for (int x : nums) {
            set.add(x);
        }

        int best = 0;                       // 空数组时直接返回 0，不能用 1 初始化
        for (int x : set) {                 // 遍历 Set 而不是数组：天然跳过重复值
            // 剪枝：x-1 在集合里说明 x 不是某段的起点，直接从它扩展是重复劳动。
            // 这一行是 O(n) 与 O(n²) 的分界线。
            if (set.contains(x - 1)) {
                continue;
            }
            int cur = x;
            int len = 1;                    // 起点自己算 1 个
            while (set.contains(cur + 1)) { // 均摊 O(1)：所有 while 加起来最多 n 次
                cur++;
                len++;
            }
            best = Math.max(best, len);
        }
        return best;
    }
}
```

### 037.5.2 Go

```go
package main

func longestConsecutive(nums []int) int {
	// map[int]struct{}：value 用零大小类型，比 map[int]bool 省内存
	// （bool 也要占一个字节；10^5 个键时差 100 KB，量级虽小但是个习惯）
	set := make(map[int]struct{}, len(nums))
	for _, x := range nums {
		set[x] = struct{}{} // 重复写入同一个 key 是幂等的，天然去重
	}

	best := 0
	for x := range set {
		// 剪枝：x-1 存在 → x 不是段起点 → 跳过
		if _, ok := set[x-1]; ok {
			continue
		}
		cur, length := x, 1
		for {
			if _, ok := set[cur+1]; !ok {
				break
			}
			cur++
			length++
		}
		if length > best {
			best = length
		}
	}
	return best
}
```

### 037.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 集合类型 | `HashSet<Integer>` | `map[int]struct{}` | Go 没有内置 Set，只能拿 map 模拟；`struct{}` 是零大小类型 |
| 查找写法 | `set.contains(x-1)` | `_, ok := set[x-1]` | Go 必须用 `ok`；如果写成 `if !set[x-1]` 也能跑（零值 false），但一旦换成 `map[int]int` 就会静默出错 |
| 装箱 | `Integer` 对象，`-128..127` 走缓存，其余每次 `add` 可能新建对象 | 无装箱，`int` 直接是 key | n = 10⁵ 时 Java 约多分配 10⁵ 个对象（≈1.6 MB），面试可提「用 `int[]` 排序更快但违背 O(n)」 |
| 遍历顺序 | `HashSet` 顺序由哈希决定，**稳定但不保证** | **刻意随机化**（每次 `range` 顺序不同） | 两语言都必须保证「结果与遍历顺序无关」——本题的 `max` 天然满足 |
| `len` 变量名 | `len` 不是关键字，可作变量名 | `len` 是内置函数，**不能作变量名** | Go 侧用了 `length`，这是编译错误与否的区别 |
| 整数溢出 | `x+1` 在 `x = 2^31-1` 时溢出 | `int` 是 64 位，`10^9+1` 安全 | 本题值域只有 `±10^9`，两语言都安全；若值域到 `2^31-1`，Java 的 `x+1` 会绕成负数，可能误命中 `-2^31` |

### 037.5.4 对拍测试（哈希解 vs 排序解）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 参考实现：排序 + 扫描。逻辑最直白，几乎不可能写错，适合当裁判。
func longestConsecutiveBrute(nums []int) int {
	if len(nums) == 0 {
		return 0
	}
	a := append([]int(nil), nums...)
	sort.Ints(a)
	best, cur := 1, 1
	for i := 1; i < len(a); i++ {
		if a[i] == a[i-1] {
			continue // 重复值：不打断也不增长
		}
		if a[i] == a[i-1]+1 {
			cur++
		} else {
			cur = 1 // 断了，从当前元素重新起一段
		}
		if cur > best {
			best = cur
		}
	}
	return best
}

func TestLongestConsecutiveRandom(t *testing.T) {
	r := rand.New(rand.NewSource(7))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(15) // 允许 n = 0，专测空数组
		nums := make([]int, n)
		for i := range nums {
			// 值域只取 -5..5：段短但重叠多，重复值密集，最容易暴露"忘记去重"
			nums[i] = r.Intn(11) - 5
		}
		got := longestConsecutive(nums)
		want := longestConsecutiveBrute(nums)
		if got != want {
			t.Fatalf("iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
	}
}

// 专门钉住几个手算过的边界
func TestLongestConsecutiveEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{nil, 0},
		{[]int{}, 0},
		{[]int{1}, 1},
		{[]int{1, 1, 2}, 2},
		{[]int{1, 2, 0, 1}, 3},
		{[]int{9, 1, 4, 7, 3, -1, 0, 5, 8, -1, 6}, 7},
		{[]int{100, 4, 200, 1, 3, 2}, 4},
	}
	for _, c := range cases {
		if got := longestConsecutive(c.nums); got != c.want {
			t.Fatalf("nums=%v got=%d want=%d", c.nums, got, c.want)
		}
	}
}
```

实测：2 万组随机数据 + 边界用例全部通过。

> **裁判为什么用排序解**：它和哈希解的**思路完全不同**（一个靠相邻差、一个靠集合查找），错误不会「同源」，对拍才有意义。
> 如果裁判也写哈希，你复制粘贴时漏掉的剪枝，裁判同样会漏 —— **对拍的价值来自「实现路径的独立性」。**

## 037.6 复杂度与常见坑

### 037.6.1 复杂度推导

- **时间 `O(n)`**：
  - 建集合：n 次 `add`，均摊 `O(1)`，共 `O(n)`。
  - 外层：遍历 `|S| ≤ n` 个元素，每个做一次 `contains(x-1)`，`O(1)`。
  - 内层：由 §037.3.2 的引理 1、2，总迭代次数 `Σ(Lᵢ - 1) ≤ n`。
  - 合计 `O(n)`。**注意这里没有任何 `log`，也没有「平均情况」的假设** —— 即使哈希碰撞很差，也只是常数变大。
- **空间 `O(n)`**：集合最多存 n 个不同的值。Java 的 `HashMap/HashSet` 有 0.75 装载因子，实际容量约 `1.33n`；Go 的 map 每个桶存 8 个键，也有额外开销。所以「空间 O(n) 但常数不小」，n = 10⁵ 时 Java 约 4~6 MB。

### 037.6.2 七个真实踩过的坑

1. **忘了 `x-1 ∉ set` 这个剪枝** —— 代码能过小数据，在「全数组连续」时退化成 `O(n²)`。n = 10⁵ 时约 `5·10⁹` 次集合查询，本机 Java 要跑 30 秒以上。**这是本题唯一的必考点，漏了就等于没做。**
2. **用数组当下标（计数桶）** —— 值域是 `[-10⁹, 10⁹]`，`boolean[2·10⁹]` 要 2 GB；用 `HashMap` 偏移也会在极端值上溢出。
3. **忘记去重** —— 遍历原数组并「用见过的次数累加长度」时，`[1,1,2]` 会得 3。正确做法是遍历 `Set`（或排序时跳过相等项）。
4. **`best` 初始化为 1** —— 空数组返回 1 而不是 0。
5. **`len` 初始化为 0** —— 起点自己也算一个元素，`len = 1` 才对；否则单点段（`[100]`）会得 0。
6. **Go 里把变量命名为 `len`** —— `len` 是内置函数名，`len := 1` 直接编译失败。Java 里 `len` 可用，跨语言抄代码时最容易在这一行卡住。
7. **边遍历边删除集合元素** —— 有写法是「扩展时把访问过的元素从集合删掉」以减小常数：Java 里在 `for (int x : set)` 中 `set.remove` 会抛 `ConcurrentModificationException`（除非用 `iterator.remove()`）；Go 的 `range` 中删除是**允许的**，但语义容易让人误判。**初版别做这个优化。**

### 037.6.3 面试官最爱追问的三个问题

**Q1：你这两层循环，凭什么说是 O(n)？**

> 「按元素记账，不按循环层数记账。每个元素只可能被访问两次：一次是外层 `for` 扫到它；一次是它所属连续段的起点向内扩展时把它当『下一步』。而一个段只有一个起点（只有最小值满足 `x-1` 不在集合里），所以每个元素进入 `while` 最多一次。总工作量 ≤ 2n。形式化地：把集合划分成极大段 `S₁..Sₘ`，`while` 总迭代 = `Σ(|Sᵢ|-1) ≤ n`。」

**Q2：如果数组有重复元素，答案会变吗？**

> 「不变。答案只取决于**值的集合**。`[1,1,2]` 的集合是 `{1,2}`，最长段长 2，重复的 1 不提供任何新值。所以正确做法是先 `Set` 去重（`add` 幂等），或者排序后遇到相等项 `continue` 而不是 `len++`。反过来说，如果题目要的是『连续段里的**元素个数**（含重复）』，那就是另一道题了，需要频次统计。」

**Q3：内存放不下整个数组怎么办？**

> 「分两种：① **数据只在磁盘上** —— 外部排序后单机扫描，`O(n log n)` 时间、`O(块大小)` 空间；② **多机** —— 按值域分桶（比如 `x div 10⁶`）把数分发到不同机器，每台机器内部求段长，再处理跨桶的**边界段拼接**（记录每台机器的最小段与最大段，看相邻桶的边界值是否相接）。这时哈希解反而比排序解更难分布，因为哈希把值域打散了，而『连续』恰恰是值域局部的性质 —— **这也是选型时要看数据布局的原因。」**
