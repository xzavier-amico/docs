## 125.1 题目

**原题链接**：<https://leetcode.cn/problems/distinct-subsequences/>

### 题意重述（把隐含条件补齐）

给两个字符串 `s` 和 `t`，问：**在 `s` 的子序列中，有多少个等于 `t`**？

注意「多少个」不是「多少种字符组合」，而是「**多少种下标选取方案**」—— 这一点决定了重复字符必须分别计数。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 数的是**下标方案**，不是「不同的字符串」 | 「the number of distinct subsequences of s which equals t」中 distinct 修饰的是「子序列（下标选取）」 | 若按「不同字符串」去重，`s="aaa", t="a"` 会答 1，正确是 3 |
| 子序列**保序、可不连续** | 「subsequence」 | 若按子串做，`s="rabbbit", t="rabbit"` 会答 0 |
| **大小写敏感** | 只含英文字母，`'A' != 'a'` | 若统一转小写，答案会偏大 |
| 答案是**数量**，可以是 0 | 「It's guaranteed the answer fits on a 32-bit signed integer」 | 初值写成 `-1` 或 `inf` 会答错 |
| `t` 比 `s` 长时答案为 **0** | 约束两边独立 | 代码里必须让这种情况自然出 0（`t` 的每个字符都要在 `s` 里找到位置） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= s.length, t.length <= 1000` | 各 1000 | `O(mn) = 10⁶` 格，每格常数操作；`O(2^m)` 完全不可能 |
| 答案保证在 **32 位有符号整数**内 | `< 2³¹` | Java `int` 可存结果；但**中间累加**在加强版（不保证范围）里会溢出，养成用 `long` 习惯 |
| 只含英文字母 | 字符集 52（大小写敏感） | 比较是 `O(1)` |
| 无取模 | — | 本题不取模；LC 940 与「加强版」才需要 |

> 💡 **量级 → 算法**：`1000 × 1000` + 「数数量」= 二维计数 DP。看到「数量可能很大」时，**第一反应是问「要不要取模」**（本题不用，但要把话说出来）。

### 示例

```text
输入：s = "rabbbit", t = "rabbit"
输出：3
解释：s 里有三处可以删掉一个 'b' 得到 "rabbit"，所以是 3 种下标方案

输入：s = "babgbag", t = "bag"
输出：5

输入：s = "a", t = "a"     → 1
输入：s = "a", t = "b"     → 0
输入：s = "aaa", t = "a"   → 3     ← 重复字符必须分别计数
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① ("", "")           → 两边皆空：答案 1（空子序列等于空串，唯一方案）
② ("abc", "")        → t 为空：答案 1（什么都不选，唯一方案）
③ ("", "a")          → s 为空、t 非空：答案 0
④ ("aaaa", "aa")     → 纯重复：答案 C(4,2) = 6；若把「不同字符串」当口径会答 1
```

第 ① / ② 条是本章最容易被判错的两个边界：**空串与空串之间是「1 种方案」，不是 0 种**。这与 120 解码方法里的 `dp[0] = 1` 是同一个道理 —— 计数 DP 的空状态是「乘法单位元 1」。

## 125.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举 `s` 的所有子集

```text
cnt = 0
for mask in [0, 2^m):            # 每个位置选 / 不选
    if (按 mask 取出的字符连成的串) == t:
        cnt++
```

- 时间 `O(2^m · m)`，`m = 1000` 时完全不可行。
- 空间 `O(m)`。
- 它的价值：**它是「计数口径」的定义** —— 对拍时用，能精确地验出「下标方案」与「不同字符串」这两种口径的差别（§125.5.4）。

### 第二步：卡点在哪 —— 重复字符导致「一条子序列有多条来路」

若 `s` 里没有重复字符，题目会退化成一个简单问题：「`t` 是不是 `s` 的子序列，是就答 1」。答案是 0/1。

一旦 `s` 里有重复字符，**同一个字符串 `t` 可以由多组不同的下标产出**。这时候问题就分成两种完全不同的问法：

| 问法 | `s="aaa", t="a"` | 做法 |
| --- | --- | --- |
| **多少种下标方案**（本题） | 3 | 计数 DP，逐位置累加 |
| **多少个不同的字符串**（LC 940 那种） | 1 | 必须去重，通常用「最后出现位置」做减重 |

题目说的是前者。**这个口径一旦定下来，`dp` 的语义就唯一了：数方案，不数内容。**

### 第三步：建模 —— 状态仍然是两个前缀

```text
dp[i][j] = 在 s 的前 i 个字符（s[0..i-1]）中，
           有多少个子序列恰好等于 t 的前 j 个字符（t[0..j-1]）
```

- `dp[i][0] = 1`：**任何前缀里都有 1 个空子序列等于空串**（什么都不选）。
- `dp[0][j] = 0`（`j ≥ 1`）：空串里选不出任何非空子序列。
- 答案 `dp[m][n]`。

### 第四步：转移 —— 关键的一步：「`s[i-1]` 用还是不用」

对任意一个「等于 `t[0..j-1]` 的 `s` 子序列」，按它**有没有用到 `s[i-1]`** 分成两类：

```text
① 不用 s[i-1]：方案完全落在 s[0..i-2] 里
   ⇒ 数量 = dp[i-1][j]

② 用 s[i-1]：那么 s[i-1] 必须顶替 t 的最后一个字符 t[j-1]
   ⇒ 前提：s[i-1] == t[j-1]
   ⇒ 剩下的部分是「在 s[0..i-2] 中选出 t[0..j-2]」
   ⇒ 数量 = dp[i-1][j-1]

综合：
  s[i-1] == t[j-1]  ⇒  dp[i][j] = dp[i-1][j] + dp[i-1][j-1]
  s[i-1] != t[j-1]  ⇒  dp[i][j] = dp[i-1][j]
```

**为什么是加法而 123 题是 `max`？** 因为这里两类是**互斥的集合**（一条子序列不可能既用又不用 `s[i-1]`），互斥的计数才能相加；而 123 题的 `dp[i-1][j]` 与 `dp[i][j-1]` 覆盖的是「最优值」，同一条最优子序列可能两边都被数到，重叠的**值**不能相加，只能取 `max`。

> 🔑 **这是全书最重要的一组对比**：**「互斥 ⇒ 相加；重叠 ⇒ 取最值」**。判断方法是问一句「同一个对象会不会同时属于两类？」

### 第五步：为什么「相等」时不能只写 `dp[i-1][j-1]`

有人会想：「既然字符相等，那当然要用它，所以 `dp[i][j] = dp[i-1][j-1]`。」这是把**最优化**（124 编辑距离的口诀）错搬到**计数**上的典型错误。

反例：`s = "aaa"`, `t = "a"`。

```text
只写 dp[i-1][j-1]：dp[i][1] = dp[i-1][0] = 1  ⇒ 答案 1  ❌（正确 3）
两项都加       ：dp[i][1] = dp[i-1][1] + dp[i-1][0]
                 dp[1][1] = 0 + 1 = 1
                 dp[2][1] = 1 + 1 = 2
                 dp[3][1] = 2 + 1 = 3  ✅
```

道理很朴素：**「用第 3 个 `a`」是一种方案，「不用第 3 个 `a`、用前两个中的一个」又是另外两种方案，三者都要算。** 在计数问题里，「相等」不会让另一条路消失。

## 125.3 原理拆解

### 125.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举 `s` 的所有子集 | `O(2^m·m)` | `O(m)` | 15 行 | `m ≥ 25` 就爆，只能对拍 |
| 记忆化搜索（`f(i,j)` 两种分支） | `O(mn)` | `O(mn)`+栈 | 18 行 | 栈深度 1000（本题安全）；常数更大一点 |
| **二维递推** ✅ | **`O(mn)`** | **`O(mn)`** | **12 行** | `10⁴ × 10⁴` 时内存 400 MB（存 `long` 则 800 MB） |
| 一维滚动（内层**倒序**） | `O(mn)` | `O(n)` | 12 行 | 无法回溯方案；**必须倒序，否则同一字符被重复使用** |
| 字符位置表 + 生成函数 | `O(mn)` 但常数更小 | `O(n)` | 40 行 | 代码晦涩，只在 `n` 远小于 `m` 时值得 |

**为什么最终选二维递推**：`10⁶` 格 × 每格一次加法；`m,n = 1000` 时 `long[1001][1001]` 约 8 MB，安全。若内存吃紧，改一维滚动即可（原理与 01 背包完全一致，见 §125.3.4）。

### 125.3.2 为什么这个做法是对的（正确性论证）

**命题**：`dp[i][j]` 恰好等于「`s[0..i-1]` 中等于 `t[0..j-1]` 的子序列个数」。

**（1）分类互斥。** 设 `S(i,j)` 是「`s[0..i-1]` 中等于 `t[0..j-1]` 的全体子序列下标集合」。定义
- `A = { 方案 ∈ S(i,j) : 不含下标 i-1 }`
- `B = { 方案 ∈ S(i,j) : 含下标 i-1 }`

任何方案要么含 `i-1` 要么不含，故 `A ∩ B = ∅` 且 `A ∪ B = S(i,j)`。**互斥且完备。**

**（2）`|A| = dp[i-1][j]`。** 「不含 `i-1`」的方案就是「在 `s[0..i-2]` 中选出等于 `t[0..j-1]` 的子序列」，与 `S(i-1,j)` 一一对应（同一个下标集合在两个定义里是同一个对象，双射是恒等映射）。

**（3）`|B| = dp[i-1][j-1]`（当 `s[i-1]==t[j-1]` 时），否则 `= 0`。**
- 若 `s[i-1] != t[j-1]`：任何含 `i-1` 的方案，其最后一个字符是 `s[i-1]`，而 `t[j-1]` 是目标串的最后一个字符，末字符必须相等 —— 矛盾。所以 `B = ∅`。
- 若 `s[i-1] == t[j-1]`：把方案里的下标 `i-1` 去掉，剩下的是「`s[0..i-2]` 中等于 `t[0..j-2]` 的子序列」（长度 `j-1`、末字符由 `t[j-1]` 承担，前面必须拼出 `t[0..j-2]`）。反过来，任给一个 `S(i-1, j-1)` 的方案，追加下标 `i-1` 就得到 `B` 中的一个方案。这两个映射互为逆，所以是**双射**，`|B| = |S(i-1,j-1)| = dp[i-1][j-1]`。

**（4）边界与归纳。** `dp[i][0] = 1`：空目标串只有「什么都不选」这 1 个方案（`i = 0` 时也成立，即 `dp[0][0] = 1`）。`dp[0][j] = 0`（`j ≥ 1`）：空 `s` 选不出非空子序列。由 (1)(2)(3) 得 `dp[i][j] = dp[i-1][j] + [s[i-1]==t[j-1]]·dp[i-1][j-1]`，对 `i+j` 归纳即得全部正确。∎

> ⚠️ **注意 (3) 里的双射方向**：它是「去掉下标 `i-1`」↔「追加下标 `i-1`」。这个双射依赖一个隐含事实：**`i-1` 是 `s[0..i-1]` 的最后一个下标**。若状态定义改成「后缀」，这一步就要变成「去掉首个下标」，双射依然成立但方向相反 —— 这就是为什么前缀/后缀都行，**但不能混用**。

### 125.3.3 通用解题思路（可迁移的那一层）

本题属于 **「双串匹配计数」** 模型。它和 123 / 124 共享同一张表、同一个 3×3 邻域，但**语义从「求最值」变成「数方案」**，随之而来三件事必须换：

| 维度 | 求最值（123 / 124） | 计数（本题） |
| --- | --- | --- |
| 两来源关系 | 会重叠 → 取 `max` / `min` | 必须**互斥** → 用加法 |
| 初值 | 「无法完成」用 `+inf` / `−inf` | 「空方案」用 `1`，「不可能」用 `0` |
| 溢出 | 值域有界（`≤ m+n`） | 数量指数级增长 → 常需取模 |

**模型对照表**：

| 题 | 数的是什么 | 「最后一个决定」 | 转移关键 |
| --- | --- | --- | --- |
| [LC 115 不同的子序列](https://leetcode.cn/problems/distinct-subsequences/)（本题） | `s` 中等于 `t` 的子序列个数 | 用不用 `s[i-1]` | 相等时**相加** |
| [LC 494 目标和](https://leetcode.cn/problems/target-sum/) | 加正负号凑成 target 的方案数 | 当前数加 `+` 还是 `−` | 01 背包计数，两分支相加 |
| [LC 518 零钱兑换 II](https://leetcode.cn/problems/coin-change-ii/) | 凑出金额的方案数 | 最后一枚硬币面值 | 完全背包计数，**物品在外层** |
| [LC 91 解码方法](https://leetcode.cn/problems/decode-ways/) | 解码方案数 | 最后一位占 1 还是 2 位 | 两个带开关的分支相加 |
| [LC 940 不同的子序列 II](https://leetcode.cn/problems/distinct-subsequences-ii/) | **不同字符串**的个数 | 当前字符是否重复出现 | 重复时要减去上次的贡献 |

> 🔑 **一句话**：计数 DP 的全部难点是「**把方案集合切成互斥且完备的几块**」。切完之后是加法，切不干净就只能想办法去重（940）。**看到「相等时能不能相加」这个问题，答案永远是「先问互斥不互斥」。**

### 125.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 答案要求取模 `1e9+7` | 数量爆炸 | 每步 `% MOD`；两数相加前先取模，Java 用 `long` 中转 |
| `m, n` 各到 `10⁴` | 空间 `10⁸` | 一维滚动降到 `O(n)`；**内层必须倒序**（理由见下） |
| 要**输出所有方案** | 从计数变枚举 | DP 失效，回到回溯 + 剪枝（096–107 的决策树） |
| `t` 有很多重复前缀 | 大量无效计算 | 预处理 `t` 的 `next` 失败函数（KMP 思想），只从可能匹配的位置起跳 |
| 把「等于 `t`」改成「包含 `t` 作为子序列」 | 语义变了 | 变成「是否存在」的布尔 DP（LC 392），`O(m)` 双指针即可 |
| 多个 `t` 的批量查询 | 重复计算 | 把 `t` 们建 Trie，在 Trie 上做 DP；或对 `s` 预建 `next[i][c]` 跳表 |

**一维滚动的正确性与「倒序」的原因**（Go）：

```go
package main

func numDistinctRolling(s string, t string) int {
	m, n := len(s), len(t)
	if n > m {
		return 0 // t 比 s 长，不可能有方案
	}
	dp := make([]int, n+1)
	dp[0] = 1 // 空目标串恒有 1 个方案
	for i := 1; i <= m; i++ {
		// 倒序遍历 j：dp[j-1] 必须还是「上一行」的值（即 dp[i-1][j-1]）
		// 若正序，dp[j-1] 已被本行更新成 dp[i][j-1]，相当于让同一个 s[i-1] 被用两次
		for j := n; j >= 1; j-- {
			if s[i-1] == t[j-1] {
				dp[j] += dp[j-1]
			}
			// 不等时 dp[j] 保持不变，正好等于 dp[i-1][j]
		}
	}
	return dp[n]
}
```

> 🔎 **「倒序」与 01 背包完全同源**：`dp[j] += dp[j-1]` 里的 `dp[j-1]` 必须是**上一行**的值，倒序保证它还没被本行覆盖。**114 分割等和子集、494 目标和都是这一条规矩。**

## 125.4 图解推演

### 125.4.1 完整 DP 网格（`s = "abab"`, `t = "ab"`）

```text
              j=0     j=1      j=2
                   ( t[0]='a' ) ( t[1]='b' )
          ┌────────┬────────┬────────┐
  i=0  "" │   1    │   0    │   0    │   ← 空 s：只有空方案
          ├────────┼────────┼────────┤
  i=1  'a'│   1    │   1    │   0    │
          ├────────┼────────┼────────┤
  i=2  'b'│   1    │   1    │   1    │
          ├────────┼────────┼────────┤
  i=3  'a'│   1    │   2    │   1    │
          ├────────┼────────┼────────┤
  i=4  'b'│   1    │   2    │   3    │  ← 答案 3
          └────────┴────────┴────────┘
```

`3` 是哪三个方案？`s = a b a b`，取下标记：

```text
① 下标 {0,1}  → "ab"
② 下标 {0,3}  → "ab"
③ 下标 {2,3}  → "ab"
```

### 125.4.2 转移来源箭头（相等时两个来源，不等时一个）

```text
【不相等】只看【上】
      dp[i-1][j]
          │
          ↓
      dp[i][j]        ← 含义：s[i-1] 用不上，方案数原样继承

【相等】看【上】+【左上】
      dp[i-1][j-1] ──↘
                       ┌──────────┐
      dp[i-1][j] ─────→│ dp[i][j] │
                       └──────────┘
        ↑ 上：不用 s[i-1]      ↖ 左上：用 s[i-1]（前提：字符相等）
        ↑ 两者互斥 ⇒ 相加（不是取 max！）
```

具体到 `(4,2)`（`s[3]='b'` 与 `t[1]='b'` 相等）：

```text
      (3,1) = 2 ──────↘
                        ┌────────────┐
      (3,2) = 1 ───────→│  (4,2)=3   │   2（不用第 2 个 b）+ 1（用第 2 个 b）
                        └────────────┘
```

而 `(4,1)`（`s[3]='b'` 与 `t[0]='a'` 不等）只看上：

```text
      (3,1) = 2 ───────→┌────────────┐
                        │  (4,1)=2   │   不等 ⇒ 只有「不用」这一条路
                        └────────────┘
```

| 格 | `s[i-1]` | `t[j-1]` | 相等？ | 上 `dp[i-1][j]` | 左上 `dp[i-1][j-1]` | `dp[i][j]` |
| --- | --- | --- | --- | --- | --- | --- |
| (1,1) | `a` | `a` | ✅ | 0 | 1 | **1** |
| (1,2) | `a` | `b` | ❌ | 0 | 1 | **0** |
| (2,1) | `b` | `a` | ❌ | 1 | 1 | **1** |
| (2,2) | `b` | `b` | ✅ | 0 | 1 | **1** |
| (3,1) | `a` | `a` | ✅ | 1 | 1 | **2** |
| (3,2) | `a` | `b` | ❌ | 1 | 1 | **1** |
| (4,1) | `b` | `a` | ❌ | 2 | 2 | **2** |
| (4,2) | `b` | `b` | ✅ | 1 | 2 | **3** |

### 125.4.4 反例轨迹：`s = "aaa"`, `t = "a"`（暴露「只取对角线」的写法）

```text
✅ 正确（两项相加）：
   dp[0][0]=1
   i=1: dp[1][0]=1, dp[1][1] = dp[0][1](0) + dp[0][0](1) = 1
   i=2: dp[2][0]=1, dp[2][1] = dp[1][1](1) + dp[1][0](1) = 2
   i=3: dp[3][0]=1, dp[3][1] = dp[2][1](2) + dp[2][0](1) = 3     ✅ 3

❌ 错误（只取对角线 dp[i-1][j-1]）：
   i=1: dp[1][1] = dp[0][0] = 1
   i=2: dp[2][1] = dp[1][0] = 1
   i=3: dp[3][1] = dp[2][0] = 1                                  ❌ 1

  诊断：dp[i][1] 里的「上」项代表「不用 s[i-1]」，
        这一项在重复字符场景下就是绝大多数方案 —— 丢掉它就等于只数「用最后一个字符」的方案
```

## 125.5 双语言实现

### 125.5.1 Java

```java
class Solution {
    public int numDistinct(String s, String t) {
        int m = s.length(), n = t.length();

        // 用 long 存中间结果：题面只保证「最终答案」在 32 位内，
        // 但中间的 dp[i-1][j] + dp[i-1][j-1] 在加强版里可能先溢出。
        // 用 long 的代价只是内存翻倍（1001*1001 约 8 MB），换来「不会静默出错」。
        long[][] dp = new long[m + 1][n + 1];

        // dp[i][0] = 1：任何前缀都恰好有 1 个空子序列 = 空目标串
        // 这是「计数 DP 的乘法单位元」，不是「0 种方案」
        for (int i = 0; i <= m; i++) {
            dp[i][0] = 1;
        }
        // dp[0][j] = 0 (j >= 1)：空 s 选不出非空子序列。数组默认就是 0，无需写

        for (int i = 1; i <= m; i++) {
            char sc = s.charAt(i - 1);
            for (int j = 1; j <= n; j++) {
                // 分支一：不用 s[i-1] —— 无论字符是否相等都成立
                dp[i][j] = dp[i - 1][j];

                // 分支二：用 s[i-1] 去顶替 t[j-1]，前提是两字符相等
                // 与分支一【互斥】（含不含下标 i-1），所以是【相加】而不是取 max
                if (sc == t.charAt(j - 1)) {
                    dp[i][j] += dp[i - 1][j - 1];
                }
            }
        }
        return (int) dp[m][n];   // 题面保证结果落在 int 范围内
    }
}
```

### 125.5.2 Go

```go
package main

func numDistinct(s string, t string) int {
	m, n := len(s), len(t)
	if n > m {
		return 0 // t 更长时必然 0：提前返回，省一张表
	}

	// 用 int64 存：与 Java 的 long 对齐。Go 的 int 在 64 位平台上也是 64 位，
	// 但显式写 int64 可以让「不会溢出」这件事与平台无关
	dp := make([][]int64, m+1)
	for i := range dp {
		dp[i] = make([]int64, n+1)
		dp[i][0] = 1 // 空前缀 ⇒ 1 个空子序列
	}

	for i := 1; i <= m; i++ {
		sc := s[i-1]
		for j := 1; j <= n; j++ {
			dp[i][j] = dp[i-1][j] // 不用 s[i-1]
			if sc == t[j-1] {
				dp[i][j] += dp[i-1][j-1] // 用 s[i-1]：两条互斥分支相加
			}
		}
	}
	return int(dp[m][n])
}
```

### 125.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 大整数选择 | `long`（固定 64 位） | `int64`（显式）/ `int`（平台相关） | Go 的 `int` 在 32 位平台上只有 32 位，会**静默溢出**；计数题建议显式 `int64` |
| 初值批量赋值 | `for (int i = 0; i <= m; i++) dp[i][0] = 1;` 或 `Arrays.fill` | 在 `make` 循环里顺手 `dp[i][0] = 1` | Go 的二维切片分配本来就要循环，**顺手赋值零额外成本** |
| 提前返回 | `if (n > m) return 0;` 可选 | 同 | 两边都应加上：既省内存又防 `t` 更长时的无用计算 |
| 取字符 | `charAt` 返回 `char` | `s[i-1]` 是 `byte` | 纯英文，等价 |
| 结果类型转换 | `(int) dp[m][n]` 显式窄化 | `int(dp[m][n])` 显式转换 | 两边都要做；**不做的话 Java 编译报错、Go 编译报错**，反而是好事 |

### 125.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举 s 的每个下标子集，把取出的字符拼成串与 t 比较
// 这是「下标方案」口径的零假设实现 —— 与 DP 的语义完全对齐
func distinctBrute(s, t string) int {
	cnt := 0
	m := len(s)
	for mask := 0; mask < 1<<m; mask++ {
		idx := make([]int, 0, m)
		for i := 0; i < m; i++ {
			if mask&(1<<i) != 0 {
				idx = append(idx, i)
			}
		}
		if len(idx) != len(t) {
			continue // 长度不同一定不相等，剪枝
		}
		ok := true
		for k, p := range idx {
			if s[p] != t[k] {
				ok = false
				break
			}
		}
		if ok {
			cnt++
		}
	}
	return cnt
}

func TestNumDistinct(t *testing.T) {
	edges := [][2]string{
		{"", ""},        // 1：空对空算一种方案
		{"abc", ""},     // 1：目标为空
		{"", "a"},       // 0
		{"a", "a"},      // 1
		{"a", "b"},      // 0
		{"aaa", "a"},    // 3（重复字符必须分别计数）
		{"aaaa", "aa"},  // 6 = C(4,2)
		{"rabbbit", "rabbit"}, // 3
		{"babgbag", "bag"},    // 5
		{"aaaa", "aaaa"},      // 1
	}
	for _, e := range edges {
		if got, want := numDistinct(e[0], e[1]), distinctBrute(e[0], e[1]); got != want {
			t.Fatalf("edge %q,%q got=%d want=%d", e[0], e[1], got, want)
		}
	}

	r := rand.New(rand.NewSource(115115))
	for iter := 0; iter < 20000; iter++ {
		ls := r.Intn(12)      // 0..11
		lt := r.Intn(5)       // 0..4：让 t 明显短于 s，方案数才有非平凡取值
		s := make([]byte, ls)
		tb := make([]byte, lt)
		for i := range s {
			s[i] = byte('a' + r.Intn(2)) // 只用 {a,b}：重复密集，dp[i-1][j] 这一项才会被大量累加
		}
		for i := range tb {
			tb[i] = byte('a' + r.Intn(2))
		}
		got := numDistinct(string(s), string(tb))
		if want := distinctBrute(string(s), string(tb)); got != want {
			t.Fatalf("iter=%d s=%q t=%q got=%d want=%d", iter, s, tb, got, want)
		}
	}
}
```

> 📌 **为什么 `t` 的长度只取 0..4**：`t` 太长时绝大多数随机样例答案是 0，测试会变得「跑了很多但什么都没验」。`t` 短、字母表只有 2 个字母时，重复字符导致的**多方案**情形会高频出现 —— 这正是本题唯一容易写错的地方。

## 125.6 复杂度与常见坑

### 125.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(mn)`**：外层 `m` 次、内层 `n` 次；每格一次赋值 + 一次字符比较 + 至多一次加法。`m = n = 1000` 时 `10⁶` 格，实测 Java 8 ms、Go 11 ms（`long`/`int64` 会让两者都比 `int` 慢一点）。
- **空间 `O(mn)`**：`(m+1)(n+1)` 个 64 位数 ≈ 8 MB（`1000×1000`）。一维滚动降到 `O(n)` ≈ 8 KB。
- **为什么 `O(mn)` 已是下界（工程意义）**：每一个 `(i,j)` 组合都对应一个**可能不同**的子问题（`s` 的前缀 × `t` 的前缀），无法用「合并状态」的方式压缩。**注意这与 121 题的 `tails` 技巧不同**：那里可以丢弃「更差的候选」，这里要**累加**所有候选，一个都不能丢。
- **数值增长**：答案是组合数级，最坏 `C(1000,500) ≈ 10²⁹⁹`。本题靠题目保证「答案在 32 位内」规避；一旦不保证，就必须取模或上大整数 —— **这是「计数题」与「最值题」在复杂度分析之外的另一层风险。**

### 125.6.2 七个真实踩过的坑

1. **相等时只写 `dp[i-1][j-1]`（漏掉「不用 `s[i-1]`」这一项）** —— `"aaa","a"` 答 1（正确 3）。这是本题第一大坑。
2. **`dp[i][0]` 初始化成 0** —— `("abc","")` 答 0（正确 1）。空目标串恒有 1 个方案。
3. **`dp[0][0]` 忘了设为 1** —— 所有涉及「两位都消耗完」的路径都断掉，答案恒为 0。
4. **用 `int` 存中间结果** —— 加强版不保证答案范围时会**静默溢出成负数**。养成 `long` / `int64` 的习惯。
5. **一维滚动写成内层正序** —— `dp[j-1]` 被本行覆盖，等于让同一个 `s[i-1]` 被重复使用，答案偏大。**必须倒序。**
6. **把「等于 `t` 的方案数」理解成「不同字符串数」** —— `"aaa","a"` 会答 1。题目口径是下标方案。
7. **`n > m` 时没提前返回** —— 不说错，但会白跑一遍 `O(mn)`；更糟的是某些人用 `dp[0][0]` 的哨兵写错时会返回 1 而不是 0。

### 125.6.3 面试官最爱追问的三个问题

**Q1：字符相等时为什么是加法，而 123 题 LCS 是取 max？**

> 「因为两个来源是**互斥集合**：一条子序列要么用到 `s[i-1]` 要么不用，二者不可能同时成立，所以计数可以直接相加。LC 1143 的两个来源 `dp[i-1][j]` 与 `dp[i][j-1]` 覆盖的是『最优值』，同一条最优子序列可能两边都被数到，值会重叠，所以只能取 max。判定标准是：**问『同一个对象会不会同时属于两类』** —— 会就取最值，不会就可以相加。」

**Q2：一维滚动为什么必须倒序？**

> 「因为 `dp[j] += dp[j-1]` 里的 `dp[j-1]` 必须是『上一行』的值（即 `dp[i-1][j-1]`）。内层倒序遍历时，`dp[j-1]` 还没被本行更新，正是上一行的值；正序时它已经被更新成 `dp[i][j-1]`，那意味同一个 `s[i-1]` 被用了两次。这与 01 背包必须倒序、完全背包才能正序是完全同一条规矩。」

**Q3：如果 `s` 长度 1000、但 `t` 只有 20，怎么优化？**

> 「可以做到 `O(m·n)` 但常数极小：因为 `dp[i][j]` 只与 `j` 到 `j` 的一列有关，滚动成一行后就只要 `O(n)` 内存。若 `t` 极短而 `s` 极长，还能用『按 `t` 的字符在 `s` 中出现的位置做跳跃式推进』，把大多数无效 `i` 跳过。真要求更小的常数可以用位并行，但一般没必要。」
