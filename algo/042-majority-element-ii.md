## 042.1 题目

**原题链接**：<https://leetcode.cn/problems/majority-element-ii/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的数组 `nums`，找出**所有**出现次数**严格大于 `⌊n/3⌋`** 的元素，顺序不限。

七个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 阈值是 **`> ⌊n/3⌋`**，不是 `≥` | 题面 | `[1,1,2,2,3,3]`（n=6，阈值 2）里每个值都恰好 2 次，答案是**空**。写成 `≥` 会返回 `[1,2,3]` |
| 答案**最多 2 个** | 抽屉原理 | 3 个值各 `> n/3` 会让总和 `> n`，不可能。这决定了「2 个候选够用」 |
| 答案**可能一个都没有** | 同上反例 | **不保证存在** ⇒ 候选必须校验，这是与 169 最大的区别 |
| 顺序不限 | 「你可以按任意顺序返回答案」 | 不必排序；对拍时必须先排序再比 |
| 返回值是**值**的列表 | 题名 | 别返回下标 |
| `1 <= n <= 5·10^4` | 约束表 | `O(n²)` 是 `2.5·10⁹`，必超时；`O(n log n)` 能过 |
| 「进阶」要求 `O(1)` 空间 | 「尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法」 | 哈希计数不达标；这才逼出「2 个候选的投票」 |

> ⚠️ **「不保证存在」这一条改变了算法结构**：169 是「找到候选 → 直接返回」，229 是「找到候选 → **再数一遍** → 过滤」。
> 漏掉校验，`[1,2,3,4]` 会返回 `[3,4]`（两个都是垃圾）。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 5·10^4` | n 最多五万 | `O(n)` 与 `O(n log n)` 都过；重点在空间 |
| `-10^9 <= nums[i] <= 10^9` | 值域 20 亿 | 不能拿值当下标；候选初值也不能依赖「值 ≥ 0」 |
| 答案 ≤ 2 个 | 数学事实 | 只需 `O(1)` 个槽位 → 空间能做到 `O(1)` |
| 阈值 `n/3` | 题面 | 每次抵消要消掉 **3** 个互不相同的元素（不是 2 个） |

> 💡 **量级 → 算法**：这里的关键不是 `n`，而是「**答案个数的上界**」。
> `> n/k` 的元素最多 `k-1` 个 —— 这个上界直接决定了「需要几个槽位」，也就决定了空间复杂度。
> 所以本章的思维模型可以一句话概括：**阈值定上界，上界定空间。**

### 示例

```
输入：nums = [3,2,3]
输出：[3]
解释：n = 3，阈值 1；3 出现 2 次 > 1 ✓，2 出现 1 次不满足。

输入：nums = [1]
输出：[1]

输入：nums = [1,2]
输出：[1,2]
解释：n = 2，阈值 0；两个值各出现 1 次 > 0，都算。
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① [1,1,2,2,3,3]      → []。恰好 n/3 不算，专治"写成 ≥"
② [1,2,3,4]          → []。四个值各 1 次，n/3 = 1，1 > 1 不成立；专治"忘记校验"
③ [1,1,1,2,2,3]      → [1]。只有 1 过半（3 > 2）；专治"计数器当成真实频次"
④ [1,1,2,2,2,3,3,3]  → [2,3]。n = 8，阈值 2；2 与 3 各 3 次，1 只有 2 次
⑤ [0,0,0]            → [0]。值是 0：候选初值若用 0 当"空"，就会把 0 当成没设置
⑥ [1,1,2]            → [1,2]？不 —— n = 3，阈值 1；1 出现 2 > 1 ✓，2 出现 1 不 > 1 → 答案 [1]
```

第 ② 和第 ⑤ 条最能抓 bug：前者暴露「不校验」，后者暴露「用 0 当哨兵」。

## 042.2 从暴力到最优：第一个念头为什么错

### 第一步：三个「第一念头」

```java
// 念头 A：哈希计数，收集所有 count > n/3 的
Map<Integer, Integer> cnt = new HashMap<>();
for (int x : nums) cnt.merge(x, 1, Integer::sum);
List<Integer> res = new ArrayList<>();
for (var e : cnt.entrySet()) if (e.getValue() > nums.length / 3) res.add(e.getKey());
// 时间 O(n)，空间 O(n) —— 空间不达标

// 念头 B：排序后扫描连续段
Arrays.sort(nums);
// 扫出每个值的出现次数，超过 n/3 的收进结果
// 时间 O(n log n)，空间 O(1)~O(log n) —— 时间不最优

// 念头 C：对每个候选值再数一遍（先找出"可能的候选"）
// 问题：怎么在 O(1) 空间里找出"可能的候选"？—— 这正是要解决的问题
```

| 念头 | 时间 | 额外空间 | 问题 |
| --- | --- | --- | --- |
| A 哈希 | `O(n)` | `O(n)` | 空间不达标 |
| B 排序 | `O(n log n)` | `O(1)`~`O(log n)` | 时间不最优；改输入 |
| C 先选候选再数 | `O(n)` | `O(1)` | **候选怎么选**？猜不出来 |

### 第二步：卡点 —— 169 的代码「复制两遍」为什么不行

最诱人的错误是：跑两遍 169 的投票，第二遍把第一遍的候选「删掉」再跑。

```java
// ❌ 直觉但错误：先投出一个多数派，再把它从数组里"屏蔽"后投第二个
int first = majorityElement(nums);       // 可能是垃圾（本题不保证存在）
// 然后把 first 全部改成某个不存在的值……需要额外空间，而且 first 是垃圾时全错
```

两个致命问题：

1. **本题不保证存在**。第一遍投票可能返回一个只出现 1 次的普通元素。
2. **「删除」需要额外结构**，或者改数组（题面不禁止改，但会破坏后续校验）。

### 第三步：灵感的来源 —— 一次消掉「三个互不相同的元素」

169 的抵消是「**两个不同的数配对消掉**」。为什么有效？因为多数派的数量**超过所有对手之和**，一对一换它换不完。

推广到 `n/3`：答案的数量 `c > n/3`，而**其它所有元素加起来最多 `n - c < 2n/3`**。所以：

```
一次消掉 3 个"互不相同"的元素
      ↓
每个答案最多被消掉 1 份（因为 3 个值互不相同，答案最多占 1 个位置）
      ↓
一共最多能做 ⌊n/3⌋ 次这样的消除
      ↓
答案剩余 ≥ c - n/3 > 0   →   答案一定还在残留里
```

```
   ┌────────────────────────────────────────────────────────┐
   │ 每消一组（3 个不同值），答案的"存款"最多减少 1          │
   │ 而总组数 ≤ n/3 < c = 答案的存款                        │
   │ → 存款永远取不完 → 残留里必有答案                       │
   └────────────────────────────────────────────────────────┘
```

### 第四步：把「三消」写成 O(1) 空间 —— 两个槽位

和 169 一样，我们没法真的记录「谁和谁消了」。但可以观察到一个不变量：

**抵消过程中，残留的元素最多只有两种不同的值。**

为什么？因为每次「三消」都要求三个值**互不相同**：如果残留里已经有 3 种不同的值，那么再来一个第 4 种值时，就可以让这 4 个值里的 3 个互相消掉……更直接地看实现：我们用两个槽位，槽位空着就占位，两个槽位都非空且新值不等于任何一个时，两个槽位各减 1（相当于「新值 + 槽1 + 槽2」三个不同值一起消掉）。

于是状态只有 `(cand1, cnt1, cand2, cnt2)` 四个变量：

```
for x in nums:
    if cnt1 > 0 and x == cand1:      cnt1 += 1        # 归到槽 1
    elif cnt2 > 0 and x == cand2:    cnt2 += 1        # 归到槽 2
    elif cnt1 == 0:                  cand1 = x; cnt1 = 1   # 槽 1 空，占位
    elif cnt2 == 0:                  cand2 = x; cnt2 = 1   # 槽 2 空，占位
    else:                            cnt1 -= 1; cnt2 -= 1  # 三消：x 与两个候选各消一个
```

```
三消的示意（x 与 cand1、cand2 三者互不相同）：

   槽1: [cand1] ──┐
   槽2: [cand2] ──┼──→  一起扔掉（消耗 3 个互不相同的元素）
   新值:   x     ──┘
```

> **为什么不是「cnt1 与 cnt2 都减 1 就完事」**：减 1 只是**记账**；它对应的事实是「`x`、`cand1`、`cand2` 这三个具体的元素被配成一组消掉了」。记账之所以能代替实际消除，是因为我们只关心「残留里还有哪些值」。

### 第五步：为什么必须校验，而 169 不用

`cnt1` / `cnt2` **不是真实频次**，只是「残留计数」。看一个例子：

```
nums = [1,2,3,4]   n = 4，阈值 n/3 = 1

x=1: cnt1=0 → cand1=1, cnt1=1
x=2: cnt2=0 → cand2=2, cnt2=1
x=3: 都不等，两槽非空 → cnt1=0, cnt2=0   （三消：1、2、3 消掉）
x=4: cnt1=0 → cand1=4, cnt1=1

候选集合 = {4}，但 4 只出现 1 次，1 > 1 不成立 → 4 不是答案
```

所以候选集合只是「**嫌疑名单**」，必须再扫一遍数真实次数。169 之所以能省，是因为题目**保证**多数派存在，而「保证存在 + 定理」推出候选必为多数派；本题没有这个保证。

```
┌──────────────────────────────────────────────────────────────┐
│ 摩尔投票给出的永远是"候选"，不是"答案"。                       │
│ 只有当"答案集合非空且上界为 k-1"时，候选集合才可能是超集；      │
│ 必须有一步 O(n) 的校验把它收紧成答案。                         │
└──────────────────────────────────────────────────────────────┘
```

## 042.3 原理拆解

### 042.3.1 数据结构与算法选型

| 方案 | 时间 | 额外空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 哈希计数 | `O(n)` | `O(n)` | 8 行 | 空间不达标；不同值极多时内存吃紧 |
| 排序 + 扫描连续段 | `O(n log n)` | `O(1)`~`O(log n)` | 15 行 | 时间不最优；改输入 |
| 排序 + 只查 3 个位置 | `O(n log n)` | `O(1)` | 6 行 | 仍要排序；只在「最多 2 个答案」时成立 |
| **两槽摩尔投票 + 校验** ✅ | **`O(n)`** | **`O(1)`** | **20 行** | 需要「答案上界 `k-1`」这个前提；候选必须校验 |
| Misra-Gries（`k-1` 槽通用版） | `O(n·k)` | `O(k)` | 30 行 | `k` 大时时间线性变差；本题 `k=3` 无所谓 |
| 位统计（逐位判） | `O(32n)` | `O(1)` | 20 行 | 只能判「某个 bit 是否属于多数派」，多个答案时无法分离 |

**「排序 + 只查 3 个位置」是什么？**

排序后，任何出现次数 `> n/3` 的值必定在 `nums[n/3]`、`nums[2n/3]` 这两个位置上出现（因为它的连续块长度 `> n/3`，必然覆盖这两个采样点之一）。所以只需检查这两个值，再各数一次即可。

它比「扫描所有连续段」短，但**结论依赖「最多 2 个答案」**；一旦阈值改成 `n/5`（最多 4 个答案），采样点就要换成 4 个 —— 和摩尔投票的 `k-1` 槽是同一条推广线。

### 042.3.2 为什么这个做法是对的（正确性论证）

**引理 1（答案最多 2 个）**：若三个不同的值都满足「出现次数 `> n/3`」，则三者之和 `> n`，超过数组总长，矛盾。∎

**引理 2（不变量）**：处理完前 `i` 个元素后，可以把这 `i` 个元素**划分**成：

- `t` 个三元组，每组内三个值**互不相同**（"已抵消"），
- `cnt1` 个值为 `cand1` 的元素，
- `cnt2` 个值为 `cand2` 的元素，

且满足 `i = 3t + cnt1 + cnt2`，并且「`cnt1 > 0` 且 `cnt2 > 0` 时 `cand1 ≠ cand2`」。

*归纳证明*（对 `i` 归纳）：

- `i = 0`：`t = 0, cnt1 = cnt2 = 0`，成立。
- 读入 `x`，分五种情况，逐一核对划分仍然成立：
  1. `cnt1 > 0` 且 `x == cand1`：把 `x` 放进第二组，`cnt1 + 1`。
  2. `cnt2 > 0` 且 `x == cand2`：把 `x` 放进第三组，`cnt2 + 1`。
  3. `cnt1 == 0`：令 `cand1 = x, cnt1 = 1`（此时第二组为空，直接占位）。
  4. `cnt2 == 0`：令 `cand2 = x, cnt2 = 1`。
  5. 其它：此时 `cnt1 > 0, cnt2 > 0`，且由条件 `cand1 ≠ cand2`、`x ≠ cand1`、`x ≠ cand2`，于是 `{x, cand1, cand2}` 是三个互不相同的值 → 新增一个三元组，`t + 1, cnt1 - 1, cnt2 - 1`。

  五种情况都保持 `i' = 3t' + cnt1' + cnt2'`，且不会让两个非空槽位变成同一个值（情况 3、4 只在对应槽为空时占位，而空槽的另一槽即使同值也不违反「非空时不同」）。∎

**定理（候选集合包含所有答案）**：设值 `a` 出现 `c_a > n/3` 次。

1. 由引理 2，`n = 3t + cnt1 + cnt2`，所以 `t ≤ n/3`。
2. 每个三元组内三个值互不相同，所以 `a` 在每个三元组里**最多出现 1 次** → 被消掉的 `a` 至多 `t ≤ n/3 < c_a` 个。
3. 因此至少有 `c_a - t > 0` 个 `a` 残留在「第二组或第三组」里 —— 而这两组的值只可能是 `cand1` 或 `cand2`，对应的计数必须为正。
4. 所以 `a ∈ {cand1, cand2}`（且该候选的残留计数 > 0）。∎

**推论（校验是充分的）**：校验阶段对 `cand1`、`cand2` 各数一次真实频次，只保留 `> n/3` 的。由定理，真正的答案都在候选里，所以不会漏；校验条件本身保证不会多报。两者合并 = 恰好是答案集合。∎

> **这个证明比 169 的更容易被问住**，因为多了一层「三元组」的划分。记住它的骨架：
> **每次三消最多带走答案的 1 份；总三消次数 ≤ n/3 < 答案份数；所以答案必然残留。**

### 042.3.3 通用解题思路（可迁移的那一层）

本题是 **「阈值定上界、上界定槽位、抵消定候选、校验定答案」** 这个模型的母题：

```
原始问题：找出所有出现次数 > n/k 的元素
         ↓ 步骤 1：上界 —— 这样的元素最多 k-1 个（否则总和 > n）
         ↓ 步骤 2：槽位 —— 开 k-1 个 (candidate, count) 槽
         ↓ 步骤 3：抵消 —— 新值不等于任何候选、且所有槽都非空时，全部槽位 -1
         ↓           （等价于「一次消掉 k 个互不相同的元素」）
         ↓ 步骤 4：校验 —— 每个候选再数一次真实频次，保留 > n/k 的
代价：    O(n·k) 时间、O(k) 空间；k 是常数时就是 O(n)/O(1)
```

**「计数抵消」的本质**（本章最该带走的一句话）：

| 说法 | 含义 |
| --- | --- |
| 计数器不是频次 | 它只记录「这个值在残留里还有几份」 |
| 减 1 不是"扣分" | 它对应「一个具体元素被配进了一组抵消」 |
| 为什么槽位是 `k-1` | 因为「`k` 个互不相同的值」一组才消得掉，而答案最多 `k-1` 个 |
| 为什么必须校验 | 抵消只保证「答案不会被消光」，不保证「残留的都是答案」 |

归属同一模型的题：

| 题 | 阈值 | 槽位 | 差异 |
| --- | --- | --- | --- |
| [LC 169 多数元素](https://leetcode.cn/problems/majority-element/) | `> n/2` | 1 | 保证存在 → 免校验（见 `041`） |
| [LC 229 多数元素 II](https://leetcode.cn/problems/majority-element-ii/) | `> n/3` | 2 | 不保证存在 → 必须校验 |
| [LC 1287 有序数组中出现次数超过 25% 的元素](https://leetcode.cn/problems/element-appearing-more-than-25-in-sorted-array/) | `> n/4` | 3（理论） | 数组有序 → 只需比较相隔 `n/4` 的两个位置，不需要投票 |
| [LC 1157 子数组中占绝大多数的元素](https://leetcode.cn/problems/online-majority-element-in-subarray/) | 区间内 `> 50%` | 1 | `(cand, cnt)` 可合并 → 线段树支持区间查询 |
| [LC 2780 合法分割的最小下标](https://leetcode.cn/problems/minimum-index-of-a-valid-split/) | 两侧各 `> 50%` | 1 | 先求全局多数派，再线性扫描分割点 |
| [LC 451 根据字符出现频率排序](https://leetcode.cn/problems/sort-characters-by-frequency/) | 不设阈值 | — | 需要完整频次，抵消法不适用（反例：说明「阈值」是前提） |

### 042.3.4 可扩展性（面试追问的方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 求 `> n/4` 的所有元素 | 最多 3 个 | 3 个槽位；每次「四消」（4 个互不相同的值一起减）；结尾校验 |
| 求 `> n/k` 的所有元素（`k` 为输入） | 最多 `k-1` 个 | Misra-Gries：`k-1` 个槽、每轮 `O(k)` 查找，时间 `O(nk)`、空间 `O(k)` |
| **必须一遍流式**（不能二次校验） | 无法数真实频次 | 只能输出「重元素」的近似解（Misra-Gries 保证：任何 `> n/k` 的元素一定在结果里，但会有误报）；精确解不可能 |
| 要求答案**有序** | 输出格式 | 最后对最多 2 个元素排序，`O(1)` |
| 数组**极长**（`n = 10^9`） | 内存 | 投票天然流式；`cnt` 需要 `long`（`int` 上限 2.1·10⁹ 接近边界） |
| 区间查询「某区间内 `> n/3` 的元素」 | 需可合并结构 | 把 `(c1,n1,c2,n2)` 定义成可合并状态，线段树 `O(log n)` 查询；合并规则与扫描规则同构 |
| 多机分布式归并 | 各分片独立投票 | 合并两个状态：同候选则计数相加；不同候选则按「抵消」规则互相削减 —— 因为抵消满足结合律 |

## 042.5 双语言实现

### 042.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> majorityElement(int[] nums) {
        int n = nums.length;

        // 两个槽位。cand1/cand2 只是"候选值"，cnt1/cnt2 是"残留计数"（不是真实频次）
        // 不变量：cnt1>0 且 cnt2>0 时 cand1 != cand2；
        //         已处理的前缀可划分为 (若干个互不相同的三元组) + cnt1 个 cand1 + cnt2 个 cand2
        int cand1 = 0, cnt1 = 0;
        int cand2 = 0, cnt2 = 0;

        for (int x : nums) {
            if (cnt1 > 0 && x == cand1) {
                cnt1++;
            } else if (cnt2 > 0 && x == cand2) {
                cnt2++;
            } else if (cnt1 == 0) {
                cand1 = x;
                cnt1 = 1;          // 槽 1 空，占位
            } else if (cnt2 == 0) {
                cand2 = x;
                cnt2 = 1;          // 槽 2 空，占位
            } else {
                // 三消：x、cand1、cand2 三者互不相同，各消掉一份
                cnt1--;
                cnt2--;
            }
        }

        // 校验：候选只是"嫌疑名单"，必须数真实频次。
        // 这一步不能省 —— 本题不保证答案存在，[1,2,3,4] 会给出垃圾候选。
        cnt1 = 0;
        cnt2 = 0;
        for (int x : nums) {
            if (x == cand1) {
                cnt1++;
            } else if (x == cand2) {
                // 用 else if 而不是独立的 if：万一两个候选偶然相等（槽位被占满前可能残留旧值），
                // 也不会把同一个值数两次
                cnt2++;
            }
        }

        List<Integer> res = new ArrayList<>(2);
        if (cnt1 > n / 3) res.add(cand1);
        if (cnt2 > n / 3) res.add(cand2);
        return res;
    }
}
```

### 042.5.2 Go

```go
package main

func majorityElement(nums []int) []int {
	n := len(nums)

	var cand1, cand2 int
	var cnt1, cnt2 int

	for _, x := range nums {
		switch {
		case cnt1 > 0 && x == cand1:
			cnt1++
		case cnt2 > 0 && x == cand2:
			cnt2++
		case cnt1 == 0:
			cand1, cnt1 = x, 1
		case cnt2 == 0:
			cand2, cnt2 = x, 1
		default:
			cnt1-- // 三消：与两个候选各消一份
			cnt2--
		}
	}

	// 校验真实频次
	cnt1, cnt2 = 0, 0
	for _, x := range nums {
		if x == cand1 {
			cnt1++
		} else if x == cand2 {
			cnt2++
		}
	}

	res := make([]int, 0, 2)
	if cnt1 > n/3 {
		res = append(res, cand1)
	}
	if cnt2 > n/3 {
		res = append(res, cand2)
	}
	return res
}
```

### 042.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 分支结构 | `if / else if / else` 链 | `switch { case ... }` | Go 的无表达式 `switch` 按顺序匹配，等价于 `if-else` 链；写错成带 `fallthrough` 就是灾难 |
| 返回空结果 | `new ArrayList<>(2)` | `make([]int, 0, 2)` | 两语言都返回「空集合」而不是 `null`/`nil`；Go 若返回 `nil`，`len` 也是 0，判题能过但语义不同 |
| 多变量赋值 | 分开写 | `cand1, cnt1 = x, 1` | Go 的多重赋值更紧凑；Java 只能一行一个 |
| 变量声明默认值 | 局部变量**必须显式初始化** | 零值自动初始化 | Java 若不写 `= 0` 会编译失败；Go 的 `var` 声明自动是 0 —— 这正是「0 作为候选值」的隐患来源 |
| 判题签名 | `List<Integer>` | `[]int` | LeetCode 对两语言的返回类型要求不同；Go 侧不能返回 `[]interface{}` |
| 排序校验的替代 | `Arrays.sort` | `sort.Ints` | 若改用「排序 + 采样」，两语言都要注意原地排序会改输入 |

```go
package main

import (
	"math/rand"
	"sort"
	"testing"

// 裁判：哈希计数，收集所有 count > n/3 的值并排序
func brute(nums []int) []int {
	cnt := make(map[int]int, len(nums))
	for _, x := range nums {
		cnt[x]++
	}
	res := []int{}
	for v, c := range cnt {
		if c > len(nums)/3 {
			res = append(res, v)
		}
	}
	sort.Ints(res)
	return res
}

func eqSorted(a, b []int) bool {
	x := append([]int(nil), a...)
	y := append([]int(nil), b...)
	sort.Ints(x) // 题目允许任意顺序，比较前必须规范化
	sort.Ints(y)
	if len(x) != len(y) {
		return false
	}
	for i := range x {
		if x[i] != y[i] {
			return false
		}
	}
	return true
}

func TestMajorityElementIIRandom(t *testing.T) {
	r := rand.New(rand.NewSource(229))
	zero, one, two := 0, 0, 0 // 统计答案个数为 0/1/2 的用例各有多少，确认覆盖面
	for iter := 0; iter < 30000; iter++ {
		n := 1 + r.Intn(15)
		nums := make([]int, n)
		for i := range nums {
			// 值域只有 1..4：重复密集，答案个数会在 0/1/2 之间自然分布
			nums[i] = 1 + r.Intn(4)
		}
		got := majorityElement(nums)
		want := brute(nums)
		if !eqSorted(got, want) {
			t.Fatalf("iter=%d nums=%v got=%v want=%v", iter, nums, got, want)
		}
		switch len(want) {
		case 0:
			zero++
		case 1:
			one++
		case 2:
			two++
		}
	}
	t.Logf("覆盖：答案 0 个 %d 次，1 个 %d 次，2 个 %d 次", zero, one, two)
	if zero == 0 || two == 0 {
		t.Fatalf("覆盖不足：必须有 0 个答案与 2 个答案的用例")
	}
}

func TestMajorityElementIIEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want []int
	}{
		{[]int{3, 2, 3}, []int{3}},
		{[]int{1}, []int{1}},
		{[]int{1, 2}, []int{1, 2}},

		{[]int{1, 2, 3, 4}, []int{}},                 // 全垃圾候选，专测校验
		{[]int{1, 1, 1, 2, 2, 3}, []int{1}},          // 只有 1 过半
		{[]int{1, 1, 2, 2, 2, 3, 3, 3}, []int{2, 3}}, // 两个答案
		{[]int{0, 0, 0}, []int{0}},                   // 值 0：候选初值不能用 0 当"未设置"
		{[]int{1, 1, 2}, []int{1}},
	}
	for _, c := range cases {
		got := majorityElement(c.nums)
		if !eqSorted(got, c.want) {

		}
	}
}
```

## 042.6 复杂度与常见坑

### 042.6.1 复杂度推导

- **时间 `O(n)`**：
  - 投票阶段一次遍历，每轮常数次比较（`k = 3`，槽位固定 2 个，所以是常数）。
  - 校验阶段再一次遍历。
  - 合计 `2n` 轮，`O(n)`。
  - 推广到 `n/k` 时是 `O(n·k)`：每轮要在 `k-1` 个槽里查找，`k` 不是常数就不能当常数看待。
- **额外空间 `O(1)`**：4 个整型变量 + 长度 ≤ 2 的输出。
- 对比：哈希解 `O(n)` 空间（n = 5·10⁴ 时 Java 约 2~3 MB），排序解 `O(n log n)` 时间。

### 042.6.2 八个真实踩过的坑

1. **忘记校验** —— 最高频错误。`[1,2,3,4]` 会返回 `[4]`（或 `[3,4]`，取决于分支顺序），而正确答案是空。
2. **校验时用两个独立的 `if` 而不是 `else if`** —— 当 `cand1 == cand2`（槽位未占满时的残留旧值可能相同）时，同一个值会被数两次，`cnt2` 偏大导致误报。写成 `else if` 天然去重。
3. **阈值写成 `>= n/3`** —— `[1,1,2,2,3,3]` 会返回 `[1,2,3]`。必须严格大于。
4. **只开一个槽做 169 的投票** —— 本题最多两个答案，一个槽只能留住一个，另一个被抵消掉再也回不来。
5. **`cnt1 == 0` 与 `x == cand1` 的判定顺序颠倒** —— 若先写 `if (x == cand1) cnt1++`（不加 `cnt1 > 0`），在 `cnt1 == 0` 时会把一个「已经抵消掉的旧候选」重新计 1，而它其实应该让位给新值。两版结果在多数输入上一致，但在 `[1,2,3,4]` 这类输入上会分叉。
6. **三消时只减一个（`cnt1--` 忘了 `cnt2--`）** —— 变成了「两消」，答案可能被消光。`[1,1,2,2,2,3,3,3]` 会漏掉一个答案。
7. **用「排序 + 查 `nums[n/3]`、`nums[2n/3]`」却忘了 `n < 3` 的越界** —— `n = 1` 时 `nums[1]` 越界。
8. **把 `cnt1` / `cnt2` 当成真实频次直接输出** —— 输出会是「残留量」而不是「出现次数」；本题返回值是值本身，但若追问「频次」，必须重新数。

### 042.6.3 面试官最爱追问的三个问题

**Q1：为什么两个候选就够了？**

> 「因为最多只有 2 个值能同时满足『出现次数 > n/3』。如果存在 3 个不同的值都超过 `n/3`，它们的总次数就超过 `n`，超过数组长度，矛盾。这是抽屉原理的直接推论。更一般地，求 `> n/k` 的元素最多 `k-1` 个，所以 `k-1` 个槽位就够 —— **阈值决定上界，上界决定空间**。」

**Q2：校验这一步能不能省？**

> 「不能。169 能省是因为题目保证多数派存在，于是『保证存在』+『不变量』推出候选必为多数派。本题没有这个保证，候选只是嫌疑名单：`[1,2,3,4]` 最后 `cand1 = 4`、`cnt1 = 1`，但 4 只出现一次。校验是 `O(n)` 时间、`O(1)` 空间的，不影响渐复杂度，没有理由省。」

**Q3：计数器 `cnt1` 到底代表什么？为什么减 1 是对的？**

> 「它代表『这个值在『剩余未配对』的元素里还有几份』，不是真实频次。减 1 不是扣分，而是表示『一个具体的元素被配进了一组三消』：当新值 `x` 同时不等于两个候选、且两个槽位都非空时，`x`、`cand1`、`cand2` 这三个值互不相同，正好可以配成一组消掉。这就是把『消除三个互不相同的元素』这个操作，用两次自减来记录。因为每次三消最多带走答案的一份，而三消总次数 ≤ `n/3` < 答案份数，所以答案一定还残留在某个槽里。」

```
① 阈值 > n/3 ⟹ 答案最多 2 个 ⟹ 两个槽位；(x ≠ 两候选且都非空) 时两槽各减 1 = 三消
② 每次三消最多带走答案 1 份，三消总次数 ≤ n/3 < 答案份数 → 答案必残留在候选里
③ 候选 ≠ 答案：必须再扫一遍数真实频次，> n/3 才收；校验用 else if 防同一值数两次
```
