## 098.1 题目

**原题链接**：<https://leetcode.cn/problems/combinations/>

### 题意重述（把隐含条件补齐）

给定两个整数 `n` 和 `k`，返回范围 `[1, n]` 中所有可能的 **`k` 个数的组合**，要求：

- 组合内部顺序**不重要**（`[1,2]` 与 `[2,1]` 是同一个组合，只能出现一次）；
- 组合之间不能重复；
- 解集顺序任意。

和 [`096`](096-subsets.md) 相比，输入更「干净」了——没有数组，只有两个数字；但要求更「紧」了——**不是任意子集，而是大小恰好为 `k` 的子集**。这个「恰好」把解从「决策树的每个结点」挪到了「深度恰好为 `k` 的那些结点」，于是「剪枝」第一次成为本题的主角。

四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **恰好 `k` 个数** | 「所有可能的 `k` 个数的组合」 | 在结点上无条件收集会输出全部子集（`2^n` 个），全错 |
| **组合、不是排列** | 「组合」 | `[1,2]` 与 `[2,1]` 同时出现 → 重复；必须用「下一层起点 `i+1`」定序 |
| **值域是 `[1, n]`** | 「返回范围 `[1, n]` 中」 | 用 `0..n-1` 当下标再 `+1` 是常用写法，但输出里必须是 `1..n`，错一位就全错 |
| **顺序任意** | 「你可以按任何顺序返回答案」 | 不用为此额外排序；但对拍时必须自己规范化（见 §098.5.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 20` | n 至多 20 | 全子集是 `2^20 = 1048576`，勉强能跑但要 `100 万 × 20` 次写入 ≈ 2000 万次操作；**正确答案只有 `C(20,10) = 184756` 个**，说明「枚举全部子集再筛」浪费了 5.7 倍。本机实测（n=20,k=10）：带剪枝 **Java ≈ 9 ms、Go ≈ 7 ms** |
| `1 <= k <= n` | `k` 可能等于 `n` | `k == n` 时答案只有 1 个（`[1..n]`），剪枝必须允许这条路走完 → 上界 `i <= n-(k-len)` 不能写成 `i < n-(k-len)` |
| `k == 1` | 退化情形 | 答案是 `n` 个单元素组合；剪枝上界退化成 `i <= n-1`，即整层都走 |
| 答案数量 = `C(n,k)` | 最大 `184756` | 输出规模就是这个量级，时间下界 `Ω(k·C(n,k))`；任何「先枚举 2^n」的方案都已被下界打败 |

> 💡 **量级反推**：`n ≤ 20` 是「指数可接受」的信号，但更关键的信息藏在 `k` 里——**答案规模是 `C(n,k)`，不是 `2^n`**。当 `k` 远离 `n/2` 时两者差好几个数量级（`k=2, n=20` 时 `C = 190` 而 `2^20 = 1048576`，差 5500 倍）。**「剪枝」就是把这个差距赚回来。**

### 示例

```text
输入：n = 4, k = 2
输出：[[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]        ← 6 个 = C(4,2)

输入：n = 1, k = 1
输出：[[1]]                                        ← 边界：n=k=1

输入：n = 4, k = 4（自造）
输出：[[1,2,3,4]]                                  ← 边界：k=n，只有一条路径能活
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① n=1, k=1          → 剪枝上界写成 i < n-(k-len) 会输出 []，漏掉唯一解
② n=4, k=4          → 收集点若写成「len==k 但没 return」，会继续往下钻出空分支
③ n=3, k=2          → 答案必须是 3 个：[1,2] [1,3] [2,3]；出现 [2,1] 说明没传 i+1
④ n=5, k=1 与 n=5, k=5 → 两个极端（全走 / 全收），是剪枝上界的两个端点
```

第 ① 条最容易错：剪枝的边界是 `<=` 而不是 `<`。第 ② 条意味着收集后必须 `return`——否则 `path.size() == k` 之后还会继续往 `path` 里塞元素，产出长度大于 `k` 的非法解。

## 098.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 A —— 「096 的模板不改，最后筛」

手里有 096 的模板，最自然的做法是「先把全部子集都生成出来，再挑出长度为 `k` 的」：

```text
void dfs(int start, path):
     if (path.size() == k) ans.add(copy(path));        // 顺手筛一下
     for i in start..n-1:
         path.add(v[i]); dfs(i+1); path.removeLast();
```

它**正确**，复杂度是 `O(n·2^n)`。问题在于这个量级被浪费在哪里：

| n | k | `2^n`（走过的结点上界） | `C(n,k)`（真正的答案数） | 浪费倍数 |
| --- | --- | --- | --- | --- |
| 10 | 5 | 1,024 | 252 | 4.1× |
| 20 | 10 | 1,048,576 | 184,756 | 5.7× |
| 20 | 2 | 1,048,576 | 190 | **5,519×** |
| 20 | 1 | 1,048,576 | 20 | **52,429×** |

也就是说：**当 `k` 很小或很大时，96% 以上的搜索是纯浪费**。而且 `n` 只要从 20 涨到 25，`2^25 = 3355 万` 就开始进入秒级 TLE 区间，而 `C(25,2) = 300` 连一毫秒都不用。**「能过」和「对」是两件事。**

### 第二步：第一个念头 B —— 位掩码 + 筛长度

```text
for mask in 0 .. (1<<n)-1:
    if popcount(mask) != k: continue
    收集 mask 里为 1 的位置
```

- 时间 `O(2^n · n/64)` 级别的判断 + `O(k·C(n,k))` 的收集；
- 与念头 A 同病：**枚举的总量由 `n` 决定，而答案的总量由 `n` 和 `k` 共同决定**。
- 它还丢掉了「前缀」这个概念，所以**没法剪枝**（096 §2 已经论证过这一点）。

### 第三步：卡点在哪 —— 「不可能凑满」这件事什么时候能知道

在定义 B 的树上，一个结点的状态只有 `(start, len)`，其中 `len = path.size()`。从这个结点出发，最理想的情况是「把后面所有候选全拿走」，此时最终长度是：

```text
len + (n - start)        ← 还能拿 n-start 个
```

如果这个上界都**不到** `k`，那么这整棵子树**一个解都不会产出**。这就是本题唯一的剪枝信息，而它只依赖两个数字：

```text
还差 need = k - len 个     vs     还剩 n - start 个
```

卡点因此非常具体：**不是「怎么枚举组合」，而是「什么时候可以确定「再怎么拿也不够」」。** 一旦把这个判断下沉到循环里，就得到本章的核心公式。

### 第四步：灵感的来源 —— 把「够不够」写进循环上界

不要写成「进入递归后再判断 `if (len + (n - start) < k) return;`」——那只是常数的优化（省掉一趟空递归）。真正省时间的是**让 `for` 循环不再进入那些注定失败的分支**：

考察本层循环的候选 `i`（0-based 下标，值 `i+1`，取值 `start .. n-1`）。选它之后还剩 `k - len - 1` 个要选，而 `i+1 .. n-1` 一共只有 `n - 1 - i` 个候选。要求：

```text
n - 1 - i  >=  k - len - 1      ⟺      i <= n - (k - len)
```

于是循环上界从 `n-1` 收紧到 `n - (k - len)`：

```text
for (int i = start; i <= n - (k - path.size()); i++)
```

**这一个 `<=` 省掉的东西有多大**：以 `n=20, k=2` 为例，第一层原来要考虑 20 个候选，现在只需考虑 `i <= 20-2 = 18` 个（下标 0..18，即值 1..19）；第二层每个结点只需考虑「到 `n-1` 之前」的 1 个…整棵树的结点数从 `2^20` 量级掉到恰好 `C(20,2)=190` 个叶子 + 中间结点。**这不是常数优化，是把指数换成组合数。**

## 098.3 原理拆解

### 098.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 096 模板收集后筛 `len == k` | `O(n·2^n)` | `O(n)` | 10 行 | `k` 远离 `n/2` 时浪费 3~5 个数量级；`n` 涨到 25 就 TLE |
| 位掩码 + `popcount` 筛选 | `O(2^n)` 次判 popcount | `O(n)` | 12 行 | 同上，且无法剪枝、`n > 63` 时位运算放不下 |
| 递归 + 进入后判「不够就 return」 | `O(n·C(n,k))` 常数偏大 | `O(n)` | 11 行 | 空递归仍会发生：每个不可行分支都要压栈一次、返回一次 |
| **递归 + 剩余数量剪枝（改循环上界）** ✅ | `O(k·C(n,k))` | `O(n)` 栈 | **11 行** | `n` 大到 `C(n,k)` 本身爆炸（那是题目要求的输出规模，无法再降） |
| 字典序后继迭代（`next_combination`） | `O(k·C(n,k))` | `O(k)` | 20 行 | 需要自己处理「末位翻转、进位」，指针逻辑比回溯难写；103 会讲这个思路 |

**为什么选第四行**：它把「不可行」编码进了**循环边界**，于是不可行分支连一次函数调用都不发生。第三行只是把浪费从「递归内部」搬到「递归入口」，两者相差一个常数因子，但思想层次不同——**前者是结构层的剪枝，后者是补丁层的判断**。

### 098.3.2 为什么这个做法是对的（正确性论证）

**（A）不重**

由 096 §3.2 的论证：每条路径的下标序列严格递增（`dfs(i+1)` 保证），因此一个组合只能由**唯一**的递增下标序列产生。`[1,2]` 只能来自「先选 1、再选 2」，不可能来自「先选 2、再选 1」。∎

**（B）不漏（关键是证明剪枝不丢解）**

**引理（剪枝的安全性）**：设当前结点 `(start, len)`，某候选下标 `i` 满足 `i > n - (k - len)`。则从「选 `i`」出发的任何路径长度都 `< k`，不可能产出解。

> 证明：选 `i` 之后，`path.size() = len + 1`，后续只能从 `i+1 .. n-1` 里再选，最多 `n - 1 - i` 个。最终长度上界：
> `(len + 1) + (n - 1 - i) = len + n - i`。
> 代入 `i > n - (k - len)` 即 `i ≥ n - k + len + 1`，得
> `len + n - i ≤ len + n - (n - k + len + 1) = k - 1 < k`。∎

于是被剪掉的分支**全都不含解**，剪枝不丢解。而未被剪掉的部分，与原模板（上界 `n-1`）完全一致，由 096 的「不漏」论证，所有合法组合都会被枚举到。∎

**（C）收集时机**

收集条件 `path.size() == k` 必须**立刻 `return`**：因为路径长度恰好为 `k` 时已经是一个合法解，而任何继续往下的路径长度都 `> k`（本题不允许多于 `k` 个），所以没有继续展开的必要。这一步同时承担了「可行性剪枝」的角色。

> **三段论证合起来的可迁移结论**：**剪枝的正确性只需证明「剪掉的分支里没有解」，不需要证明更多。** 这句话在 099（和超限就 `break`）、100（同层去重 + 超限 `break`）、104（列/对角冲突）里反复使用。

### 098.3.3 通用解题思路（可迁移的那一层）

本章要装进工具箱的是 **剩余数量剪枝**。把它的推导固定成三步：

```text
┌──────────────── 剩余数量剪枝的三步推导 ────────────────┐
│                                                        │
│  ① 算「还差多少」   need = k - path.size()              │
│  ② 算「还剩多少」   从 i 到末尾共 n - i 个（0-based）    │
│  ③ 令 ② ≥ ① 解出 i 的上界： i <= n - need               │
│     ── 把上界写进 for 的条件，而不是进递归后再判断        │
│                                                        │
│  检查端点：need == 0 时上界是 n（此时应已 return）       │
│           need == n - start 时只剩 i == start 一条边     │
└────────────────────────────────────────────────────────┘
```

**边界对照（最容易写错的一行）**：

| 写法 | `n=1,k=1` 时 | 是否正确 | 原因 |
| --- | --- | --- | --- |
| `for (i = start; i < n - (k - len); i++)` | 只走 `i < 1-1 = 0` → 一次都不进 | ❌ 漏解 | 把「恰好够」当成了「不够」 |
| `for (i = start; i <= n - (k - len); i++)` | `i <= 0` → 走 `i=0` | ✅ | 「够」也要走 |
| `for (i = start; i <= n - (k - len) + 1; i++)` | `i <= 1` → 走到越界 | ❌ 崩溃 | 1-based 与 0-based 混用 |

统一骨架（与 096 相同，收集点上移到了 `len == k`）：

```text
void dfs(int start, int len, path, ...) {
    if (len == k) { ans.add(copy(path)); return; }          // 收集：只在「恰好 k 个」
    int maxStart = n - (k - len);                           // ② 剪枝：把上界算好
    for (int i = start; i <= maxStart; i++) {               // 边：i 从 start 到 maxStart
        path.add(i + 1);                                    // ③(a) 选择（0-based 下标 → 1-based 值）
        dfs(i + 1, len + 1, path, ...);
        path.removeLast();                                  // ③(b) 撤销
    }
}
```

属于「组合 + 数量约束」这个模型的题：

| 题 | 「还差多少」是什么 | 「还剩多少」是什么 |
| --- | --- | --- |
| [LC 77 组合](https://leetcode.cn/problems/combinations/) | `k - len` 个元素 | `n - i` 个候选 |
| [LC 216 组合总和 III](https://leetcode.cn/problems/combination-sum-iii/) | 差的元素个数 **和** 差的和值（**双剪枝**） | 可用数字的个数与最大值之和 |
| [LC 40 组合总和 II](https://leetcode.cn/problems/combination-sum-ii/) | 差的和值 `target - sum` | 剩余元素之和（可做上界剪枝） |
| [LC 39 组合总和](https://leetcode.cn/problems/combination-sum/) | 差的和值 | 剩余元素里最小值的倍数关系 |
| [LC 17 电话号码的字母组合](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/) | 剩余位数 | 剩余数字个数（两者相等，剪枝退化） |

### 098.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 组合**允许重复元素**（`[1,1]` 合法） | 每次选择后可再选自己 | 递归传 `i` 而不是 `i+1`（见 [`099-combination-sum.md`](099-combination-sum.md)）；剪枝上界不再成立（可以无限取），改靠「和超限」剪枝 |
| 结果要求**字典序** | 有序输出 | 排序后的回溯天然字典序；或直接用 `next_combination` 迭代（103 的手法） |
| 只要**方案个数** | 只数不构造 | 直接算 `C(n,k)`：`O(k)` 乘法并防溢出；回溯是浪费 |
| `n` 涨到 `10^5` 而 `k` 很小（比如 `k=2`） | 输出仍有 `O(n²)` | 只能换「双指针/双层循环」直接构造，回溯的常数与栈开销不划算 |
| 枚举**第 m 个**组合（不枚举全部） | 只取一个 | 组合的**词典序号**可用「逐位确定 + 组合数」直接跳转，`O(n·k)` |
| 元素带权，要求和 `≤ target` | 边带权 | 排序 + 前缀和上界剪枝（剩余元素之和都不够就砍） |

## 098.4 图解推演

### 098.4.1 `n=4, k=2` 的决策树（剪枝前后对比）

```text
不剪枝（上界 n-1）                        剪枝（上界 n-(k-len)）
   dfs(start=0,len=0)                        dfs(start=0,len=0)  need=2 → i<=2
  ┌───┬───┬───┬───┐                          ┌───┬───┬───┐
 i=0 i=1 i=2 i=3                            i=0 i=1 i=2   ⊘ i=3 被剪
  ▼   ▼   ▼   ▼                              ▼   ▼   ▼
 [1] [2] [3] [4]                            [1] [2] [3]
  │   │   │   │                              │   │   │
需要2层：每个都往下                    need=1 → i<=3     │
 i=1..3                              ┌────┬────┬────┐   │
  [1,2][1,3][1,4]  ✓                  [1,2][1,3][1,4]    │
 i=2..3     [2,3][2,4] ✓                    ...         │
 i=3        [3,4] ✓                                     ▼
 i=4 无       ↓ 空递归                             [3,4] ✓   （i<=3）
  [4,?] 空 ← 白跑一趟
```

**被剪掉的分支为什么不可能是解**：`i=3` 意味着值 `4`，选它之后 `len=1`，还需要 1 个，但后面没有候选了 → 长度永远到不了 2。剪枝公式 `i <= 4-2 = 2` 把这一整支提前排除。

### 098.4.2 逐层轨迹表（`n=5, k=3`）

| 深度 | `len` | `need = k-len` | `start` | 循环 `i` 范围（`i <= n-need`） | 本层产出的候选值 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 3 | 0 | `0..2` | 1, 2, 3 |
| 1（选了 1） | 1 | 2 | 1 | `1..3` | 2, 3, 4 |
| 2（选了 1,2） | 2 | 1 | 2 | `2..4` | 3, 4, 5 |
| 3（选了 1,2,3） | 3 | 0 | — | 收集 `[1,2,3]` 并 `return` | — |

**注意第 3 行**：到了 `len=2` 时上界 `i <= 5-1 = 4`，即值 `3,4,5` 都可以——正好是「选完它就到 3 个」的所有可能。**上界随 `len` 增大而增大，这就是「剪枝越来越松」的直觉**：越接近终点，越多候选是可行的。

### 098.4.3 剪枝到底省了多少（结点计数）

| `n, k` | 不剪枝的策略树结点数（无收集约束） | 剪枝后结点数 | 降幅 |
| --- | --- | --- | --- |
| 4, 2 | 1+4+12 = 17 | 1+3+3 = 7 | 2.4× |
| 10, 5 | `Σ_{i=0..5} C(10,i)·(...)` ≈ 638 | 与答案同阶（252 叶子） | 2.5× |
| 20, 2 | ≈ 400 万次函数调用 | 191 | **2 万倍** |

第三行是本章的杀手锏：`k=2` 时剪枝把「不可能凑满」的分支在第一层就砍掉了 17/20，第二层再砍掉大部分，最终只剩 `C(20,2)=190` 条路径。

## 098.5 双语言实现

### 098.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        dfs(0, n, k, path, res);
        return res;
    }

    /** start = 本层允许选的最小「0-based 下标」；值 = 下标 + 1 */
    private void dfs(int start, int n, int k, List<Integer> path, List<List<Integer>> res) {
        // 收集点在「恰好 k 个」的结点；return 是必须的，否则会继续塞出长度 > k 的非法解
        if (path.size() == k) {
            res.add(new ArrayList<>(path));
            return;
        }

        // ② 剩余数量剪枝：还差 need 个，而 i..n-1 共 n-i 个候选
        //    要求 n-i >= need  ⟺  i <= n - need
        //    这一步把「注定凑不满」的候选直接从循环边界排除，连递归调用都不发生
        int need = k - path.size();
        int maxStart = n - need;

        for (int i = start; i <= maxStart; i++) {
            path.add(i + 1);                  // ③(a) 选择：下标 i 对应数值 i+1
            dfs(i + 1, n, k, path, res);      //     递归：下一层从 i+1 起（保证组合不重复）
            path.remove(path.size() - 1);     // ③(b) 撤销
        }
    }
}
```

### 098.5.2 Go

```go
package main

func combine(n int, k int) [][]int {
	res := make([][]int, 0)
	path := make([]int, 0, k)

	var dfs func(start int)
	dfs = func(start int) {
		if len(path) == k {
			// 深拷贝：否则所有结果共享 path 的底层数组，最后全变成同一条路径
			res = append(res, append([]int(nil), path...))
			return
		}

		// ② 剩余数量剪枝：n-i >= need ⟺ i <= n-need
		need := k - len(path)
		maxStart := n - need

		for i := start; i <= maxStart; i++ {
			path = append(path, i+1) // ③(a) 选择
			dfs(i + 1)               //     递归
			path = path[:len(path)-1] // ③(b) 撤销：缩回一位
		}
	}
	dfs(0)
	return res
}
```

### 098.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 结果里的 `path` | `new ArrayList<>(path)` | `append([]int(nil), path...)` | **都必须深拷贝**；`res = append(res, path)` 在 `k ≥ 3` 时必然出错 |
| 撤销 | `path.remove(path.size()-1)` | `path = path[:len(path)-1]` | Java 的 `remove(2)` 在 `List<Integer>` 上删的是**值 2**，必须用 `size()-1` |
| 预分配 | `new ArrayList<>()` 或 `new ArrayList<>(C(n,k))` | `make([]int, 0, k)` + `make([][]int, 0, …)` | `path` 的容量定成 `k` 可以完全避免 append 扩容（这对 Go 的切片别名尤其重要，见下） |
| 闭包 vs 方法 | 私有方法，参数逐个传 | `var dfs func(int)` 闭包捕获 `n/k/path/res` | Go 少传四个参数；`res` 必须是被**捕获的变量**（`res = append(...)` 改的就是它） |
| 整数默认值 | 无（必须赋初值） | `path` 是 nil 切片，`append` 可用 | `[]int(nil)` 与 `make([]int,0,k)` 都能 `append`，后者少几次扩容 |

#### ⚠️ Go 切片别名：本章的实测反例

因为 `path` 的容量被定成了 `k`，`path` 从第一层到第 `k` 层**始终在同一个底层数组上写**，所以这个 bug 在本题是「全军覆没」级别的。我在 `/tmp/alias3` 里实跑了两种写法：

```text
n=4, k=2  不加拷贝（错误）  res = append(res, path)
  [[3 4] [3 4] [3 4] [3 4] [3 4] [3 4]]
  ↑ 6 个结果全是最后一次写入的内容；期望是 [[1 2] [1 3] [1 4] [2 3] [2 4] [3 4]]

n=4, k=2  加拷贝（正确）  res = append(res, append([]int(nil), path...))
  [[1 2] [1 3] [1 4] [2 3] [2 4] [3 4]]        ✓

n=5, k=3  不加拷贝
  [[3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5] [3 4 5]]

n=4, k=4  不加拷贝
  [[1 2 3 4]]                                   ← 看起来"对"！因为只有 1 个解，无处可错
```

第三行是最值得记住的一句：**`k == n` 时这个 bug 完全隐形**。所以「用 `n=4,k=4` 手测通过」不能证明切片用法正确——这正说明为什么必须跑随机对拍（§098.5.4），而且对拍必须覆盖 `k < n` 的情形。

两种正确写法：

```go
// 写法 1（推荐）：显式深拷贝，每次分配新底层数组
res = append(res, append([]int(nil), path...))

// 写法 2：三下标截断 —— 只封住「存进去那份」的容量，cap == len
//   前提：存进去之后，不能再有 cap > len 的同数组切片头写这块内存
//   实测在本题模板里仍然出错（n=4,k=2 得到 6 个 [3 4]），因为 path 自己就是那个头
res = append(res, path[:len(path):len(path)])
```

> **判定标准**：只要一个 `[]T` 会被**存进结果**、并且**之后还会被 `append`**，就必须深拷贝。

### 098.5.4 对拍测试（写完必须跑）

参考实现用**位掩码 + `popcount == k`**，与回溯完全独立。

```go
package main

import (
	"math/bits"
	"math/rand"
	"sort"
	"testing"
)

// 参考实现：枚举全部 2^n 个掩码，只保留 popcount == k 的
func bruteCombine(n, k int) [][]int {
	out := [][]int{}
	for mask := 0; mask < 1<<n; mask++ {
		if bits.OnesCount(uint(mask)) != k {
			continue
		}
		cur := []int{}
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				cur = append(cur, i+1)
			}
		}
		out = append(out, cur)
	}
	return out
}

func normComb(res [][]int) [][]int {
	out := make([][]int, len(res))
	for i, r := range res {
		out[i] = append([]int(nil), r...)
	}
	sort.Slice(out, func(a, b int) bool {
		for k := 0; k < len(out[a]) && k < len(out[b]); k++ {
			if out[a][k] != out[b][k] {
				return out[a][k] < out[b][k]
			}
		}
		return len(out[a]) < len(out[b])
	})
	return out
}

func TestCombineRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026098))
	for iter := 0; iter < 4000; iter++ {
		n := 1 + r.Intn(12)
		k := 1 + r.Intn(n)
		got := normComb(combine(n, k))
		want := normComb(bruteCombine(n, k))
		if len(got) != len(want) {
			t.Fatalf("iter=%d n=%d k=%d 数量 %d != %d", iter, n, k, len(got), len(want))
		}
		for i := range got {
			if len(got[i]) != k {
				t.Fatalf("iter=%d n=%d k=%d 第%d项长度 %d", iter, n, k, i, len(got[i]))
			}
			for j := range got[i] {
				if got[i][j] != want[i][j] {
					t.Fatalf("iter=%d n=%d k=%d 第%d项 %v vs %v", iter, n, k, i, got[i], want[i])
				}
			}
		}
	}
}

func TestCombineEdges(t *testing.T) {
	if got := len(combine(1, 1)); got != 1 {
		t.Fatalf("n=1,k=1 得 %d", got)
	}
	if got := len(combine(4, 4)); got != 1 {
		t.Fatalf("n=4,k=4 得 %d", got)
	}
	if got := len(combine(5, 1)); got != 5 {
		t.Fatalf("n=5,k=1 得 %d", got)
	}
	if got := len(combine(20, 10)); got != 184756 {
		t.Fatalf("n=20,k=10 得 %d", got)
	}
	if got := len(combine(20, 2)); got != 190 {
		t.Fatalf("n=20,k=2 得 %d", got)
	}
}
```

## 098.6 复杂度与常见坑

### 098.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(k · C(n,k))`。**

1. 剪枝之后，决策树的**每一条根到叶子的路径长度都是 `k`**，且每条路径对应一个不同的组合 → 叶子数正好 `C(n,k)`。
2. 树是一棵「组合树」：内部结点是某些前缀。可以证明它的结点总数是 `O(k·C(n,k))`（每个结点都至少对应一个叶子，且同一深度的结点数被叶子数控制；更精确地，深度 `d` 的结点数是 `C(n,d)` 减去被剪掉的，总和 `≤ k·C(n,k)`）。
3. 每个叶子做一次 `O(k)` 的拷贝。

所以总时间 `O(k·C(n,k))`。**若只数方案个数不拷贝，时间能降到 `O(C(n,k))`** —— 拷贝是唯一带 `k` 因子的开销。

**空间 `O(k)`（不含输出）**：递归深度恰为 `k`（剪枝后不会再更深），`path` 长度 ≤ `k`。输出 `O(k·C(n,k))`。

**对比不剪枝**：不剪枝时深度可以到 `n`，时间 `O(n·2^n)`。`n=20, k=2` 时是 `20·10^6 = 2·10^7` vs 剪枝后的 `2·190 = 380`，差了 5 万倍。

### 098.6.2 七个真实踩过的坑

1. **剪枝写成 `<` 而不是 `<=`** —— `n=1, k=1` 时输出 `[]`。修法：把「恰好够」的情形算作可行。
2. **收集后忘了 `return`** —— 继续往下递归，产出长度 `> k` 的非法解（在 `n=4,k=2` 会多出 `[1,2,3]` 之类）。
3. **1-based 与 0-based 混用** —— 循环用 `i <= n-(k-len)` 但 `path.add(i)`（忘了 `+1`），输出里出现 `0`；或者上界多 `+1` 导致数组越界。
4. **递归传 `start+1` 而不是 `i+1`** —— 得到所有组合的「连续段」，答案错误（`[1,3]` 生成不出来）。
5. **递归传 `i` 而不是 `i+1`** —— 元素可重复使用，输出 `[1,1]`、`[2,2]` 这类非法解，且因为上界随 `len` 增大，循环可能永远进得去（配合 `k` 有限才终止）。
6. **Go 里 `res = append(res, path)`** —— 切片别名，结果被后续路径就地改写（见 §098.5.3 的实测）。
7. **预分配写成 `make([][]int, 0, k)`** —— 容量按 `k` 给，而解的数量是 `C(n,k)`，会白白扩容 `log(C(n,k))` 次；正确是 `C(n,k)` 或干脆不预分配。

### 098.6.3 面试官最爱追问的三个问题

**Q1：这个剪枝是「必要的」还是「只是优化」？**
> 「是**优化**，但它把复杂度从 `O(n·2^n)` 换成了 `O(k·C(n,k))`，在 `k` 远离 `n/2` 时差 3~5 个数量级，所以它是本题从『能过』到『正确量级』的分界线。它不改变答案的正确性——引理只证明『被剪掉的分支里没有解』，因此不剪也能得到相同答案，只是慢。」

**Q2：为什么上界写进 `for`，而不是在递归开头判 `if (len + (n - start) < k) return;`？**
> 「两者都能减少无用的展开，但位置决定了省下的是什么。写在递归开头，调用与返回的开销还在：每个不可行分支仍要压栈、进函数、判一次、返回。写进 `for` 条件，这些候选连一次函数调用都不会发生。更本质地说：**剪枝应该尽量往树的上层推**——在最早能判断的位置砍，省下的子树最大。」

**Q3：如果 `n = 100, k = 3`，你还会写回溯吗？**
> 「不会。`C(100,3) = 161700` 个答案本身没问题，但回溯的每个答案都要 `O(k)` 拷贝 + 递归开销，而三重循环 `for i<j<k` 更直接、常数更小、还不用管切片/列表的拷贝。**回溯的价值在『层数由参数决定』的场合**；层数固定且很小（`k ≤ 3`）时，嵌套循环反而更简单。如果 `k` 也是参数，那还是回溯。」
