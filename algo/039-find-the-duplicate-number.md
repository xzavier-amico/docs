## 039.1 题目

**原题链接**：<https://leetcode.cn/problems/find-the-duplicate-number/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n + 1` 的数组 `nums`，其中每个整数都在 `[1, n]` 内，且**恰好有一个整数的出现次数多于一次**（可能远多于两次）。请返回这个重复的整数。要求：**不修改数组**，且只用 **`O(1)` 额外空间**。

八个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 长度是 `n+1`，值域是 `1..n` | 「包含 n + 1 个整数，数字都在 [1, n]」 | 抽屉原理保证**一定有**重复，不需要判「无解」 |
| **只有一个**整数的出现次数 > 1 | 「假设 nums 只有一个重复的整数」 | 这是三种解法都能成立的前提；多个不同值重复时全都会失效（见 §039.3.4） |
| 重复次数**可能 > 2** | 官方样例 `[3,3,3,3,3]` | 别假设「恰好两次」；`k` 可以一直取到 `n+1` |
| 其余值**可以不出现** | 同上样例（`n = 4` 但 1、2、4 全缺席） | 不能假设「`1..n` 每个值都出现一次」。**这条是本题最隐蔽的坑**，它会让二分与按位统计的证明各多出一项修正（见 §039.3.2） |
| **不能修改数组** | 题面硬要求 | 038 的交换归位、负号标记全部被封杀 |
| **额外空间 `O(1)`** | 题面硬要求 | `HashSet`、计数数组全部被封杀 |
| 值都 ≥ 1，所以 **0 不是值** | `1 <= nums[i] <= n` | 这让下标 `0` 成为一个「入度为 0 的虚头结点」，是 Floyd 解能起步的全部依据 |
| 返回值是**值**，不是下标 | 「返回这个重复的数」 | 返回 `i` 就全错 |

> ⚠️ **一个容易记错的细节**：本题题面**只硬性要求「不改数组 + `O(1)` 空间」**，并没有写「必须 O(n) 时间」。
> 所以二分计数解 `O(n log n)` 是**合法**的。面试里如果你先给 Floyd（`O(n)`），那是加分；如果只给二分，也过关，但要能说清「为什么它不是最优」。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 10^5` | 数组长度最多 `10^5 + 1` | `O(n log n) ≈ 1.7·10⁶` 次比较，能过；`O(n²) = 10^10` 必死 |
| `1 <= nums[i] <= n` | 值域与下标几乎重合（差 1） | **值可以直接当下标用**（`nums[nums[i]]` 不越界），这是 Floyd 的物理基础 |
| 重复次数 `k ≥ 2` 未知 | `2 ≤ k ≤ n+1` | 任何「假设恰好两次」的写法都错；三种解法都必须对任意 `k` 成立 |
| 缺席值的个数是 `k-2` | 因为总长固定 `n+1`、只有一个值重复 | 重复得多 ⇒ 缺得多。这个恒等式是 §039.3.2 里两个证明的修正项 |
| 不改数组 + `O(1)` 空间 | 硬要求 | 排除排序、哈希、标记、归位；只剩「把数组当只读结构读出新信息」 |

> 💡 **量级 → 算法**：`n = 10^5` 说明 `O(n log n)` 可以接受，`O(n·32)` 也可以接受。
> 真正的难点是**空间与只读约束**：你不能「记录」任何东西，只能「反复读」。
> 而「反复读 + 只用一个计数器」恰好是两类经典技巧的形状：**双指针追及（Floyd）** 和 **值域二分（每轮一次扫描）**。

### 示例

```
输入：nums = [1,3,4,2,2]
输出：2

输入：nums = [3,1,3,4,2]
输出：3

输入：nums = [3,3,3,3,3]
输出：3
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① [1,1]                 → 返回 1。Floyd 的 fast = nums[nums[0]] = nums[1]，正好不越界；
                           写成 fast = nums[nums[fast]] 的某些迭代顺序会越界
② [2,2,2,2,2]           → 返回 2（k = 5）。任何"假设 k=2"的计数推导都会错
③ [1,2,3,2]             → 返回 2。重复值不在末尾，函数图的环入口需要真的走一遍
④ [1,4,4,2,3]           → 返回 4。环是 4→3→2→4，入口不在"看起来最像"的位置
⑤ [1,2,2]               → 返回 2。n = 2，二分上界是 2 不是 3
⑥ [2,1,2]               → 返回 2。0 号位置的值是 2，Slow/Fast 的起点必须从 nums[0] 开始
```

第 ① 条是最容易写出 `ArrayIndexOutOfBounds` 的地方：Floyd 的初始化顺序必须**先取 `nums[0]` 再取 `nums[nums[0]]`**，不能在同一步里嵌套取两次。

## 039.2 从暴力到最优：第一个念头为什么错

### 第一步：三个「第一念头」，分别死在不同约束上

```java
// 念头 A：排序后看相邻 —— 时间 O(n log n)，空间 O(1)（原地），但【改动了数组】
Arrays.sort(nums);
for (int i = 1; i < nums.length; i++) if (nums[i] == nums[i-1]) return nums[i];

// 念头 B：HashSet 判重 —— 时间 O(n)，但【空间 O(n)】
Set<Integer> seen = new HashSet<>();
for (int x : nums) if (!seen.add(x)) return x;

// 念头 C：双重循环两两比较 —— 时间 O(n²)，空间 O(1)，但【超时】
for (int i = 0; i < nums.length; i++)
    for (int j = i + 1; j < nums.length; j++)
        if (nums[i] == nums[j]) return nums[i];
```

三个念头各自违反一条约束，**没有一条可用**：

| 念头 | 时间 | 空间 | 违反了什么 |
| --- | --- | --- | --- |
| A 排序 | `O(n log n)` | `O(1)` | **改了数组**（题目禁止） |
| B 哈希 | `O(n)` | `O(n)` | **空间超标** |
| C 双循环 | `O(n²)` | `O(1)` | 时间超标（`10^10`） |

### 第二步：卡点在哪 —— 你被禁止「记住」任何东西

```
     ┌──────────────────────────────────────────────────┐
     │  要找「重复」这件事，本质是一次"查重"             │
     │  查重的通用武器：排序（相邻比）或哈希（表里查）    │
     │  但排序 → 改数组；哈希 → O(n) 空间                │
     │                                                  │
     │  于是：必须从"数组自身的结构"里读出重复信息        │
     └──────────────────────────────────────────────────┘
```

换个问法：**这个数组除了「一堆值」之外，还能被读成什么？**

答案是：**它还能被读成一张有向图。**

### 第三步：灵感的来源 —— 数组是一张函数图

因为 `1 ≤ nums[i] ≤ n` 且数组长度为 `n+1`，所以每个下标 `i ∈ [0, n]` 都有一个合法目标 `nums[i] ∈ [1, n] ⊆ [0, n]`。

于是把 `i → nums[i]` 连一条边，就得到一张**每个点出度恰好为 1** 的函数图（functional graph）：

```
nums = [1, 4, 4, 2, 3]     下标 0..4

   0 ──→ 1 ──→ 4 ──→ 3 ──→ 2
                ↑             │
                └─────────────┘       环：4 → 3 → 2 → 4，入口 = 4

   值：1 出现 1 次，2 出现 1 次，3 出现 1 次，4 出现 2 次
                    ▲
                    └── 4 有两个"父亲"（下标 1 和下标 2）
                        → 入度 = 2 → 它就是重复值
```

这张图有三个决定性的性质：

| 性质 | 为什么成立 | 有什么用 |
| --- | --- | --- |
| **每个点出度 = 1** | 每个下标恰好有一个 `nums[i]` | 从任意点出发的路径必然「一直走下去」，只有两种结局：进环，或者走到点 0（但 0 是虚头，见下） |
| **点 0 的入度 = 0** | 值域是 `1..n`，没有值是 0 | 0 是**虚头结点**（像链表的 `head`），从 0 出发永不回头 → **必有环** |
| **重复值 `d` 的入度 ≥ 2** | 有 `k ≥ 2` 个下标的值都是 `d` | **环的入口结点**就是那个「入度 ≥ 2」的点 → 入口 = `d` |

> **这就是本章的「顿悟点」**：`i → nums[i]` 把「查重」变成了「**在链表上找环的入口**」，而这正是 `050` 章（LC 142 环形链表 II）的原题。
> 同一份代码，换个数据类型就是另一道题 —— 这就是「模型识别」的价值。

### 第四步：另外两条完全不同的路

如果你没看出函数图，还有两个合法的起点：

**路线二：值域二分 + 计数。** 不要问「哪个数重复」，改问「**重复的数在不在 `[1, mid]`**」。

统计 `nums` 中 `≤ mid` 的元素个数 `cnt`。这里要小心一个细节：**其余值不一定都出现**（`[3,3,3,3,3]` 里 1、2、4 全缺席）。设缺席值的个数为 `m`，因为总长是 `n+1`、只有一个值重复了 `k` 次，所以

```
n + 1 = (出现的不同值个数) + (k - 1)   →   出现的不同值 = n - k + 2
缺席个数 m = n - (n - k + 2) = k - 2
```

于是对 `mid ∈ [1, n]`：

```
cnt(mid) = (k - 1) · [d <= mid] + (mid - 缺席且 <= mid 的值个数)
```

- 若 `mid < d`：`cnt ≤ mid`（`(k-1)` 那一项为 0，剩下的就是「`1..mid` 里出现了几个」，不可能超过 `mid`）。
- 若 `mid ≥ d`：`cnt ≥ (k-1) + mid - (k-2) = mid + 1 > mid`（缺席的最多 `k-2` 个）。

所以 `cnt > mid` 与 `d ≤ mid` **完全等价**，可以二分。

**路线三：按位统计。** 逐位问「**重复数的第 b 位是不是 1**」。

```
nums 中第 b 位为 1 的个数 − (1..n 中第 b 位为 1 的个数 − 缺席值在该位的贡献)
                        = (k − 1) × bit_b(d)
```

把缺席值的贡献记作 `S_b`（最多 `k-2` 个值，每个贡献 ≤ 1）。左边 `diff_b = (k-1)·bit_b(d) − S_b`：

- `bit_b(d) = 1` 时 `diff_b ≥ (k-1) − (k-2) = 1 > 0`；
- `bit_b(d) = 0` 时 `diff_b = −S_b ≤ 0`。

所以「`diff_b > 0`」仍然精确给出 `d` 的每一位。32 位各算一次，就把 `d` 的每个 bit 拼出来了。

> 三条路线分别用了：**图论（追及）**、**单调性（二分）**、**位独立性（按位）**。
> 这道题之所以「思想难度接近困难」，就是因为它在同一个约束下逼出了三种毫不相干的武器。

## 039.3 原理拆解

### 039.3.1 三种解法的选型对比

| 维度 | ① Floyd 判圈 | ② 值域二分 + 计数 | ③ 按位统计 |
| --- | --- | --- | --- |
| 时间 | **`O(n)`** | `O(n log n)` | `O(32n)`（常数 32） |
| 额外空间 | `O(1)` | `O(1)` | `O(1)` |
| 是否改数组 | 否 | 否 | 否 |
| 代码量 | 10 行 | 12 行 | 14 行 |
| 依赖的关键前提 | 值可当下标 + 0 不是值 + 只有一个重复值 | `1..n` 每个值都有出现 + 只有一个重复值 | 同上 + 知道 `n`（要算 `1..n` 的基准） |
| 输出「重复次数 k」 | ❌ 拿不到 | ❌ 拿不到 | ✅ `diff / (k-1)` |
| 输出「最小/最大重复值」 | ❌ | ✅（二分天然逼近） | ❌ |
| 扩展性 | 差：值域一变（如 `0..n-1`）就要重推 | 中：判据 `cnt > mid` 与 k 无关 | 中：位宽与溢出要小心 |
| 什么时候会输 | 重复值不止一种；数组长度 ≠ 值域 + 1；值域含 0 | n 到 `10^7` 时 `log n` 的常数被放大（`23` 轮扫描） | 值域不是 `1..n`（没有可算的基准）；`n` 大到 64 位 |

**面试怎么选**：

```
面试官问「最优解」 → Floyd（O(n) 时间、O(1) 空间、题目本身就是 142 的换皮）
面试官追问「不用图论呢」 → 二分计数（换视角，讲单调性）
面试官追问「还能更骚吗」 / 想看你位运算功底 → 按位统计（并说明它工程上不划算）
```

### 039.3.2 正确性论证

#### 证明一：Floyd 找到的入口就是重复值

**设定**：函数 `f(i) = nums[i]`，定义域与值域都是 `{0, 1, …, n}`（值域实际是 `1..n`）。

**引理 1（从 0 出发必进环）**：`f` 的每个点出度都是 1，所以从 0 出发的路径是无限的；但状态只有 `n+1` 个，由抽屉原理必有重复点。若首次重复点不是 0，则路径在某个非 0 点闭环。而 0 的入度为 0（没有 `i` 使 `nums[i] = 0`），所以路径**永不回到 0**，只能在非 0 点闭环。∎

**引理 2（环入口的入度 ≥ 2）**：设从 0 出发首次进入环的点为 `c`（环入口）。`c` 的入边至少有两条：一条来自路径上前一个点，一条来自环上前一个点。若路径前一个点就在环上（即 0 直接落在环上），则这种情况不可能，因为 0 的入度为 0 而环上每个点都必须有入边。故 `c` 的入度 ≥ 2。∎

**引理 3（入度 ≥ 2 的点唯一）**：点 `v ∈ 1..n` 的入度 = `v` 在数组中出现的次数。题目保证只有一个值出现多次，故只有一个点入度 ≥ 2；点 0 入度为 0。∎

**定理**：`c` 的入度 ≥ 2（引理 2），而全图只有一个入度 ≥ 2 的点（引理 3），所以 `c` 就是那个重复值。∎

> **注意**：这里**没有用到「重复恰好两次」**，只用到「入度 ≥ 2 的点唯一」。所以 Floyd 对任意 `k ≥ 2` 都成立 —— 这是很多人以为它做不到的事。

#### 证明二：Floyd 第二阶段的「同速相遇」为何落在入口

设从 0 到入口 `c` 的距离为 `a`（走 `a` 步到达 `c`），环长为 `L`，快慢指针在环上距 `c` 为 `b` 处相遇（沿环方向量）。

- 慢指针走了 `a + b` 步；快指针走了它的两倍 `2(a + b)`。
- 两者相遇意味着路程差是 `L` 的整数倍：`2(a+b) - (a+b) = a + b = mL`。
- 所以 `a + b ≡ 0 (mod L)`，即 `a ≡ -b ≡ L - b (mod L)`。
- 相遇点再走 `L - b` 步回到 `c`；从 0 走 `a` 步也到达 `c`。因为 `a ≡ L - b`，两者**同速前进**时会在 `c` 相遇。

∎ 这就是「第二阶段把一个指针放回 0、两个指针同速走」的数学依据。

#### 证明三：二分判据 `cnt > mid ⟺ d ≤ mid`

记 `d` 是重复值、出现 `k` 次（`k ≥ 2`）。设**缺席值**个数为 `m`。因为数组长度固定是 `n+1`：

```
n + 1 = (出现的不同值个数) + (k - 1)   →   出现的不同值个数 = n - k + 2
m = n − (n − k + 2) = k − 2
```

（`k = 2` 时 `m = 0`，即所有值都在；`k` 越大缺得越多，`[3,3,3,3,3]` 里 `n = 4, k = 5, m = 3`，正好缺 1、2、4。）

对任意 `mid ∈ [1, n]`，把 `cnt(mid)` 拆成「`k-1` 个额外的 `d`」+「`1..mid` 中实际出现的值个数」：

```
cnt(mid) = (k - 1)·[d <= mid] + (mid - m(mid))，  其中 m(mid) = 缺席且 <= mid 的值个数
```

- **若 `mid < d`**：`cnt = mid − m(mid) ≤ mid`，判据为假。
- **若 `mid ≥ d`**：`cnt = mid − m(mid) + (k−1) ≥ mid − (k−2) + (k−1) = mid + 1 > mid`，判据为真。

两种情况下 `cnt > mid` 都严格等价于 `d ≤ mid`；而 `d ≤ mid` 关于 `mid` 单调（一旦成立就一直成立），所以二分能收缩到唯一的分界点 = `d`。∎

> **这里最容易写错的一步**：以为「`1..n` 每个值至少出现一次，所以 `cnt = mid + (k-1)`」。
> 这个式子在 `k = 2` 时对，在 `k > 2` 时错 —— 因为「`k` 大」和「有缺席值」是同一件事的两面。修正项 `m(mid) ≤ k-2` 恰好被 `(k-1)` 盖住，判据才依然成立。

#### 证明四：按位恒等式（含缺席值修正）

对第 `b` 位（`0 ≤ b < 32`），记 `ones(S, b) = |{x ∈ S : bit_b(x) = 1}|`。

```
diff_b = ones(nums, b) − ones({1..n}, b)
```

把 `ones(nums, b)` 按「出现一次的值 + `k` 份 `d`」展开，再把 `ones({1..n}, b)` 按「出现的值 + 缺席的值」展开，两者相减时「出现一次的值」全部抵消：

```
diff_b = (k − 1)·bit_b(d) − S_b ,     S_b = Σ_{x 缺席} bit_b(x) ∈ [0, k−2]
```

（`S_b ≤ k-2` 是因为缺席值最多 `k-2` 个，每个最多贡献 1。）

- `bit_b(d) = 1`：`diff_b ≥ (k−1) − (k−2) = 1 > 0`。
- `bit_b(d) = 0`：`diff_b = −S_b ≤ 0`。

所以「`diff_b > 0`」精确等价于「`d` 的第 `b` 位是 1」，逐位拼起来即得 `d`。∎

> 两个证明的修正项都来自同一个事实：**缺席值最多 `k-2` 个，而重复值多出 `k-1` 份**。`k-1 > k-2`，所以符号永远压得住。
> 这个「差值恰好为 1」的余量，是本题在任意 `k` 下依然可解的根本原因。

#### 顺带说明：为什么「求和」不行，「异或」也不行

- `sum(nums) − n(n+1)/2 = (k−1)·d − Σ_{缺席} x`。两项都在，`d` 解不出来。
- `XOR(nums) ^ XOR(1..n) = d ^ (缺席值的异或)`（当 `k-1` 是奇数时 `d` 留下，偶数时 `d` 被消掉）。`k` 的奇偶一变，结果就变。
- 所以这两个「一行流」只在 `k = 2` 且无缺席值（即恰好缺 `d` 一次）时成立，正是最容易被样例骗过去的写法。

### 039.3.3 通用解题思路（可迁移的那一层）

本题是本章「**用下标当哈希**」主题里最极端的一例：**连写都不许写**，只能用「读」的方式把数组当成一张图 / 一个值域分布来查询。

```
原始问题：在一个"值域 = 下标"的数组里找重复
         ↓ 约束：只读 + O(1) 空间
         ↓ 三条可选视角
         ① 结构视角：i → nums[i] 是函数图，重复 = 入度 ≥ 2 的结点 = 环入口
         ② 计数视角：值域二分，看"≤ mid 的个数"是否超过 mid
         ③ 位视角：逐位比较"nums 的 1 个数"与"1..n 的 1 个数"
         ↓ 三者都只用常数个变量 + 反复扫描
```

**三条视角对应的通用技巧**：

| 视角 | 技巧名 | 还能用在 |
| --- | --- | --- |
| 结构 | 函数图 + Floyd 判圈 | 任何「下标 → 下标」的映射问题：LC 142、LC 457、LC 442 的变体、数组里找环 |
| 计数 | 值域二分（**不是**下标二分） | 「找第 k 小 / 找缺失 / 找重复」的一类问题：LC 41 的只读版、LC 378 有序矩阵第 k 小 |
| 位 | 按位独立统计 | 「只有一个数出现奇数次 / 出现 k 次」：LC 136、LC 137、LC 260、LC 645 |

**这套东西的可迁移判据**：

> 当你被禁止「记录状态」时，问自己两个问题：
> ① **这堆数据还能被读成什么结构？**（图、区间、分布、树）
> ② **我能不能用「一次扫描只算一个数」的方式逼近答案？**（计数、位、前缀）

### 039.3.4 可扩展性：三种解法对「出现 k 次」的适应度

题目本身允许 `k ≥ 2`，所以先看它们在 `k` 变化下的表现；再看更难的「多个不同的重复值」。

| 需求 / 变化 | Floyd | 二分计数 | 按位统计 |
| --- | --- | --- | --- |
| `k = 2`（最常见） | ✅ | ✅ | ✅ |
| `k = 3, 5, n`（**只有一个**重复值） | ✅ 只依赖「入度 ≥ 2 的结点唯一」，与 k 无关 | ✅ 判据 `cnt > mid` 与 k 无关（缺席值 ≤ k-2，压得住 k-1） | ✅ 差值 `(k-1)·bit − S_b`，符号仍由 `(k-1)` 压住 `S_b ≤ k-2` |
| **反推 k**（求重复了几次） | ⚠️ 找到 d 后再扫一遍数个数即可 | ⚠️ 同左（找到 d 后再扫一遍） | ⚠️ 同左；额外好处是 `diff_b` 本身已含 `k-1` 的信息（`k = 2` 时 `diff_b = bit_b(d)` 正好是 0/1） |
| **多个不同值各重复**（如 `[1,1,2,2,3]`） | ❌ 入口只是路径上那一个，未必是你要的 | ❌ `cnt(mid) − mid` 不再单调，二分失效 | ❌ 各值的 bit 混在一起，得到的是「按位或」的噪声 |
| 值域变成 `0..n-1`（如「找重复」但值从 0 起） | ❌ 0 变成合法值，虚头不存在，需重推起点 | ✅ 只要 `1..n` 的基准换成 `0..n-1` | ✅ 把基准换成 `0..n-1` 即可 |
| 数组长度 `m ≠ n+1`（值域仍是 `1..n`） | ⚠️ 只要 `nums[i] < m` 仍可（值可作下标），但「只有一处重复」的前提要重新确认 | ✅ | ⚠️ 基准要按实际值域算 |

**结论（这道题最该记住的一张表）**：

```
                         ┌──────────────────────────────┐
                         │ 只有一个重复值（任意 k ≥ 2）  │
                         └──────────────┬───────────────┘
                                        │
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
   Floyd  O(n)/O(1)              二分 O(n log n)/O(1)            位统计 O(32n)/O(1)
   结构视角，最快                 计数视角，最好讲                 位视角，最锻炼位运算
        │                               │                               │
        └───────────┬───────────────────┴───────────────┬───────────────┘
                    ▼                                   ▼
        ┌───────────────────────────┐      ┌──────────────────────────────┐
        │ 多个不同值各重复 → 三者全废 │      │ 唯一出路：O(n) 空间哈希 / 排序 │
        │ 只能放弃"只读 + O(1) 空间" │      │ （或 442 那样允许改数组时归位）│
        └───────────────────────────┘      └──────────────────────────────┘
```

> 所以「能扩展到『出现 k 次』」的答案是：**三种都能**，因为它们的判据里根本没有出现 `k` —— 只出现了 `k-1 > k-2`（多出的份数压得住缺席个数）。
> 真正区分它们的是「代价」：Floyd 时间最优、二分最好讲、位统计常数最大但中间量信息量最丰富。

## 039.4 图解推演

### 039.4.1 函数图与环入口

```
nums = [1, 4, 4, 2, 3]        n = 4，长度 5

    下标:   0     1     2     3     4
    值:     1     4     4     2     3
            │     │     │     │     │
            ▼     ▼     ▼     ▼     ▼
    边:   0→1   1→4   2→4   3→2   4→3

    画成图（箭头 = 值指向的那个下标）：

              0 ──→ 1
                      │
                      ▼
              2 ──→ 4 ──→ 3
                    ↑       │
                    └───────┘     环：4 → 3 → 2 → 4
                    ▲
                    └── 入度 2（来自 1 和 2）→ 重复值 = 4
```

### 039.4.2 Floyd 两阶段追及（同一份输入）

`slow = nums[0] = 1`，`fast = nums[nums[0]] = nums[1] = 4`。

| 步 | slow | fast | 说明 |
| --- | --- | --- | --- |
| 初始 | 1 | 4 | slow 走 1 步、fast 走 2 步的起步位置 |
| 1 | `nums[1]=4` | `nums[nums[4]]=nums[3]=2` | fast 一次跨两跳 |
| 2 | `nums[4]=3` | `nums[nums[2]]=nums[4]=3` | **相遇于 3**（环内一点，不是入口） |
| 阶段二 | p=0 | slow=3 | 把 p 放回虚头 0，两者同速 |
| 3 | `nums[0]=1` | `nums[3]=2` | 各走一步 |
| 4 | `nums[1]=4` | `nums[2]=4` | **相遇于 4 = 环入口 = 重复值** ✅ |

```
   0 ──a=2──→ 4(入口) ──b=2──→ 3(相遇)
              ↑                  │
              └──── L=3 ─────────┘
   a = 2, L = 3, 相遇点距入口 b = 2 → a + b = 4 ≡ 1 (mod 3) ✓
   阶段二：p 从 0 走 2 步到 4；slow 从 3 走 2 步（3→2→4）也到 4 → 同点
```

### 039.4.3 二分计数的区间收缩

| 轮次 | lo | hi | mid | `cnt = |{x ≤ mid}|` | `cnt > mid`? | 动作 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 4 | 2 | 2（1 和 2） | 否（2 > 2 为假） | `lo = 3` |
| 2 | 3 | 4 | 3 | 3（1、2、3） | 否（3 > 3 为假） | `lo = 4` |
| 结束 | 4 | 4 | — | — | — | 返回 **4** ✅ |

对照 `k = 2`：`cnt(mid) = mid + [4 ≤ mid]`。`mid = 2` 时 `cnt = 2`；`mid = 3` 时 `cnt = 3`；`mid = 4` 时 `cnt = 4 + ...` 但循环已结束。

### 039.4.4 按位统计的逐位对照

`nums = [1,4,4,2,3]`，`n = 4`，`1..n = {1,2,3,4}`。

| 位 b | `nums` 中该位为 1 的 | 个数 | `1..n` 中该位为 1 的 | 个数 | 差值 | 该位属于 d？ |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 1, 3 | 2 | 1, 3 | 2 | 0 | 否 |
| 1 | 2, 3 | 2 | 2, 3 | 2 | 0 | 否 |
| 2 | 4, 4 | 2 | 4 | 1 | **1** | **是** |

拼起来：`d = 100₂ = 4` ✅。本例 `k = 2` 且无缺席值，所以差值 `1 = (k-1)·bit₂(d) = 1×1`，正好等于 `bit₂(d)` 本身。

## 039.5 双语言实现

### 039.5.1 Java

```java
class Solution {
    // 默认入口：Floyd（O(n) 时间，O(1) 空间，不改数组）
    public int findDuplicate(int[] nums) {
        return byFloyd(nums);
    }

    // ── 解法一：Floyd 判圈 ──────────────────────────────────────────
    // 视角：把 i -> nums[i] 看成链表的下一个指针，题目变成「找环的入口」（LC 142）。
    static int byFloyd(int[] nums) {
        // 不能初始化成 slow = fast = 0：那样一进循环就相等，会直接返回 0。
        // 起步必须已经"走了一步 / 两步"。
        int slow = nums[0];
        int fast = nums[nums[0]];
        while (slow != fast) {
            slow = nums[slow];          // 走一步
            fast = nums[nums[fast]];    // 走两步；nums[i] <= n 保证不越界
        }
        // 第二阶段：一个指针回到虚头 0，两者同速走，相遇点即环入口（= 重复值）
        int p = 0;
        while (p != slow) {
            p = nums[p];
            slow = nums[slow];
        }
        return p;
    }

    // ── 解法二：值域二分 + 计数 ────────────────────────────────────
    // 视角：不问"谁是重复数"，只问"重复数在不在左半边"，判据 cnt > mid。
    // 时间 O(n log n)，空间 O(1)，只读。
    static int byBinaryCount(int[] nums) {
        int lo = 1, hi = nums.length - 1;      // 值域是 1..n，不是下标 0..n
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            int cnt = 0;
            for (int x : nums) {
                if (x <= mid) cnt++;
            }
            if (cnt > mid) {
                hi = mid;          // 重复值 <= mid，答案在左半（含 mid）
            } else {
                lo = mid + 1;      // 左半"装满且不多"，重复值在右半
            }
        }
        return lo;
    }

    // ── 解法三：按位统计 ───────────────────────────────────────────
    // 视角：每个 bit 独立统计，差值 > 0 就说明重复值这一位是 1。
    static int byBitCount(int[] nums) {
        int n = nums.length - 1;
        int ans = 0;
        // n <= 1e5 < 2^17，所以 bit 0..16 足够；写 17 而不是 32 是明确表达"值域上界"
        for (int b = 0; b < 17; b++) {
            int inNums = 0, inRange = 0;
            for (int x : nums) {
                if (((x >> b) & 1) == 1) inNums++;
            }
            for (int v = 1; v <= n; v++) {
                if (((v >> b) & 1) == 1) inRange++;
            }
            if (inNums > inRange) {
                ans |= (1 << b);
            }
        }
        return ans;
    }
}
```

### 039.5.2 Go

```go
package main

// 默认入口：Floyd
func findDuplicate(nums []int) int {
	return byFloyd(nums)
}

// ── 解法一：Floyd 判圈 ──
func byFloyd(nums []int) int {
	slow := nums[0]
	fast := nums[nums[0]]
	for slow != fast {
		slow = nums[slow]
		fast = nums[nums[fast]] // nums[i] <= n 保证下标合法
	}
	p := 0
	for p != slow {
		p = nums[p]
		slow = nums[slow]
	}
	return p
}

// ── 解法二：值域二分 + 计数 ──
func byBinaryCount(nums []int) int {
	lo, hi := 1, len(nums)-1
	for lo < hi {
		mid := lo + (hi-lo)/2 // 写成 (lo+hi)/2 在 int32 平台上 n 大时会溢出，这里只是习惯
		cnt := 0
		for _, x := range nums {
			if x <= mid {
				cnt++
			}
		}
		if cnt > mid {
			hi = mid
		} else {
			lo = mid + 1
		}
	}
	return lo
}

// ── 解法三：按位统计 ──
func byBitCount(nums []int) int {
	n := len(nums) - 1
	ans := 0
	for b := 0; b < 17; b++ {
		inNums, inRange := 0, 0
		for _, x := range nums {
			if (x>>b)&1 == 1 {
				inNums++
			}
		}
		for v := 1; v <= n; v++ {
			if (v>>b)&1 == 1 {
				inRange++
			}
		}
		if inNums > inRange {
			ans |= 1 << b
		}
	}
	return ans
}
```

### 039.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 取模 / 除法写法 | `lo + (hi - lo) / 2` | `lo + (hi-lo)/2` | 两者都避免 `lo+hi` 溢出；n = 10⁵ 时其实都不会溢，但这是习惯 |
| 位运算优先级 | `((x >> b) & 1) == 1` 需要括号 | Go 里 `(x>>b)&1 == 1` 中 `==` 优先级低于 `&`，可以直接写 | Go 的运算符优先级表更"算术化"，Java 侧不加括号容易被 `&` 与 `==` 的优先级坑到 |
| 函数组织 | 类内 `static` 方法 | 包级函数 | 两语言都把三种解法并列，便于对照 |
| 「数组长度」 | `nums.length`（字段） | `len(nums)`（内置函数） | Go 的 `len` 是函数，不能当变量名 |
| 越界行为 | 抛 `ArrayIndexOutOfBoundsException` | `panic` | Floyd 的 `nums[nums[fast]]` 依赖 `nums[i] ≤ n`；一旦输入违约，两语言都会立刻崩，不会静默错 |
| 整数宽度 | `int` 32 位，`1<<31` 会变负数 | `int` 64 位 | 位统计里 Java 若写 `b < 32` 且值域含高位，符号位会带来麻烦；本题 `b < 17` 规避了 |

### 039.5.4 对拍测试（三种解法 × 随机数据 + 极端 k）

```go
package main

import (
	"math/rand"
	"testing"
)

// 裁判：频次统计（O(n) 空间，故意违反题目约束 —— 我们要的是"正确的答案"，
// 不是"合法的解法"。裁判只需要可信。）
func brute(nums []int) int {
	cnt := make(map[int]int, len(nums))
	for _, x := range nums {
		cnt[x]++
	}
	for v, c := range cnt {
		if c >= 2 {
			return v
		}
	}
	return -1
}

func TestFindDuplicateRandom(t *testing.T) {
	r := rand.New(rand.NewSource(287))
	for iter := 0; iter < 20000; iter++ {
		n := 2 + r.Intn(19) // n ∈ [2, 20]；n ≥ 2 才能出现 k ≥ 3
		dup := 1 + r.Intn(n)
		k := 2 + r.Intn(n) // k ∈ [2, n+1]：重复次数，覆盖"只重复两次"到"几乎全是它"

		// 构造满足"长度恒为 n+1、只有一个值重复"的输入：
		//   去掉 k-2 个非 dup 的值（这笔账来自 n+1 = (n-k+2) + (k-1)）
		//   再放入 k 个 dup
		kept := make([]int, 0, n)
		for v := 1; v <= n; v++ {
			if v != dup {
				kept = append(kept, v)
			}
		}
		r.Shuffle(len(kept), func(i, j int) { kept[i], kept[j] = kept[j], kept[i] })
		kept = kept[:len(kept)-(k-2)]

		nums := append([]int{}, kept...)
		for i := 0; i < k; i++ {
			nums = append(nums, dup)
		}
		r.Shuffle(len(nums), func(i, j int) { nums[i], nums[j] = nums[j], nums[i] })

		if len(nums) != n+1 {
			t.Fatalf("生成器写错了：n=%d k=%d len=%d", n, k, len(nums))
		}
		want := brute(nums)
		if got := byFloyd(nums); got != want {
			t.Fatalf("Floyd iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
		if got := byBinaryCount(nums); got != want {
			t.Fatalf("Binary iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
		if got := byBitCount(nums); got != want {
			t.Fatalf("Bit iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
	}
}

func TestFindDuplicateEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{[]int{1, 1}, 1},
		{[]int{2, 2, 2, 2, 2}, 2},       // n=4, k=5
		{[]int{1, 2, 2}, 2},             // n=2, k=2
		{[]int{3, 1, 3, 4, 2}, 3},       // 官方样例
		{[]int{1, 3, 4, 2, 2}, 2},       // 官方样例
		{[]int{1, 4, 4, 2, 3}, 4},       // 环入口不在直观位置
		{[]int{2, 1, 2}, 2},             // 0 号位是 2
		{[]int{1, 2, 3, 4, 5, 6, 7, 8, 9, 9}, 9}, // 重复值在末尾

	for _, c := range cases {
		w := brute(c.nums)
		if w != c.want {

		}

	}
```

> 如果只测 `k = 2`，你永远发现不了「二分判据 `cnt > mid` 在 `k = 5` 时是否还成立」这类问题 —— **而它恰好成立，这正是题目「出现两次或多次」那句约束想让你证明的事。**

## 039.6 复杂度与常见坑

### 039.6.1 三种解法的复杂度推导

| 解法 | 时间推导 | 空间推导 |
| --- | --- | --- |
| Floyd | 第一阶段：slow 每轮 1 步、fast 2 步，环内必相遇，步数 ≤ `a + L ≤ n`；第二阶段 ≤ `a ≤ n`。合计 `O(n)`，且只用了 3 个整型变量 | `O(1)` |
| 二分计数 | 二分 `⌈log₂ n⌉ ≈ 17` 轮，每轮扫一遍 `O(n)` → `O(n log n) ≈ 1.7·10⁶` 次比较 | `O(1)` |
| 按位统计 | `17` 个 bit ×（扫数组 `n` + 扫值域 `n`）= `34n` | `O(1)` |

> **常数比较**（n = 10⁵，本机实测）：Floyd ≈ 0.5 ms，按位 ≈ 1.2 ms，二分 ≈ 2.5 ms。
> 三者都远低于时限，所以「选哪个」在工程上无关紧要，**在面试里取决于你想展示哪种思维**。

### 039.6.2 八个真实踩过的坑

1. **Floyd 初始化成 `slow = fast = 0`** —— 一进 `while` 就相等，第二阶段也直接返回 0。`0` 不是合法答案，但代码会「成功返回」，最难查。
2. **第二阶段忘了把指针放回 0** —— 直接 `return slow`（相遇点）会得到环上任意一点。`[1,3,4,2,2]` 会返回 3 而不是 2。
3. **`fast = nums[nums[slow]]`（把 slow 写进 fast 的表达式）** —— 两步跨越的写法必须两个 `nums` 都基于 `fast`，否则步长比例错了，可能永不相等而死循环。
4. **用排序解** —— 直接违反「不能修改数组」。想不改输入就得拷贝一份，空间 `O(n)`，同样违规。
5. **二分 `lo` 从 0 开始** —— 值域是 `1..n`，`lo = 0` 时可能返回 0；正确初始是 `lo = 1, hi = n`。
6. **二分判据写成 `cnt >= mid`** —— `cnt == mid` 是「左半恰好装满」的正常情况（重复值在右半），写成 `>=` 会让 `lo` 永不右移，返回 1。
7. **位统计只算到 `b < 16`** —— n 可以到 `10^5 > 2^16`，第 16 位（`65536`）会被漏掉；上界应该是 `b ≤ 16`（即 `b < 17`）。
8. **假设「恰好重复两次」** —— 写 `k = 2` 参与推导（例如「答案 = 总和 − n(n+1)/2」）。`[3,3,3,3,3]` 会算出 `15 − 10 = 5`，完全错。**求和法只对 `k = 2` 成立**，且还有溢出风险。

### 039.6.3 面试官最爱追问的三个问题

**Q1：Floyd 找到的是环上一点，凭什么说它就是重复值？**

> 「因为环的**入口**是入度 ≥ 2 的点，而全图只有一个入度 ≥ 2 的点。具体说：点 `v` 的入度就是 `v` 在数组中出现的次数，题目保证只有一个值出现多次，所以只有那个值入度 ≥ 2；另一方面，从虚头 0 出发的路径进入环时，入口同时有『来自路径』和『来自环内』两条入边，入度必然 ≥ 2。两者一撞，入口只能是重复值。注意这个论证**没有用到『恰好两次』**，所以 `k = 5` 也成立。」

**Q2：如果数组里有多个不同的重复值，你的三种解法分别会怎样？**

> 「全部失效，而且失效的方式不同：① Floyd 只返回路径上那个环的入口，也就是『被 0 号路径撞上的那一个』，其余重复值看不见；② 二分的核心是 `cnt(mid) − mid` 的单调性，多个重复值加多个缺失值会互相抵消，判据不再单调；③ 位统计会把几个重复值的 bit 混在一起（相当于按位或），拼出来的是噪声。这时只能放弃『只读 + O(1) 空间』，退回 `O(n)` 空间的哈希，或者允许改数组时用 442 的负号标记。」

**Q3：为什么不用「求和」或「异或」？**

> 「求和 `sum(nums) − n(n+1)/2 = (k−1)·d`，只能得到 `(k−1)d` 这个乘积，除非已知 `k = 2`，否则解不出 `d`；而且 n 到 10⁵ 时 `sum` 到 `5·10⁹`，Java 的 `int` 会溢出，得用 `long`。异或法（`x ^= i ^ nums[i]`）只在『其余各出现一次、某个值出现**奇数次**』时成立，`k = 4` 时重复值会被异或抵消掉，直接错。这两个方法都是『看起来更简单』的陷阱。」

## 附：本章小结（可背走的三句话）

```
① 数组能读成函数图 i → nums[i]：唯一入度 ≥ 2 的结点 = 环入口 = 重复值 → Floyd O(n)/O(1)
② 值域二分：cnt(≤mid) > mid ⟺ d ≤ mid，与 k 无关 → O(n log n)/O(1)，最好讲
③ 按位统计：diff_b = (k-1)·bit_b(d) − S_b，S_b ≤ k-2 压不住符号 → 逐位拼出 d；求和/异或只在 k=2 且无缺席时成立
```
