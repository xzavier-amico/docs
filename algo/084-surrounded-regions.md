## 084.1 题目

**原题链接**：<https://leetcode.cn/problems/surrounded-regions/>

### 题意重述（把隐含条件补齐）

给你一个 `m × n` 的矩阵 `board`，元素为 `'X'` 或 `'O'`。请把**所有被 `'X'` 完全围绕的 `'O'` 区域**就地改成 `'X'`。

这里「完全围绕」有一个非常精确的等价定义，必须自己补出来：

> 一个 `'O'` 不被围绕 **当且仅当** 它所在的 `'O'` 四连通分量**接触到了矩阵的边界**。

换句话说：**任何在四条边上（第 0 行、第 m-1 行、第 0 列、第 n-1 列）的 `'O'`，以及任何能沿 `'O'` 走到边界的 `'O'`，都不会被改**。

| 隐含条件 | 出处 | 读漏了会怎样 |
| --- | --- | --- |
| **「围绕」只看四方向** | 相邻性沿用网格惯例 | 允许对角相连会把逃得掉的区域判成被围住 |
| **边界上的 `'O'` 永远安全** | 「任何边界上的 `'O'` 都不应该被替换成 `'X'`」 | 漏掉这一点，全 `'O'` 的矩阵会被清成 `'X'` |
| **就地修改，返回值是 `void`** | 函数签名 `void solve(char[][])` | 返回一个新矩阵会判错（LeetCode 检查的是 `board` 本身） |
| **只有 `'X'` 和 `'O'` 两种字符** | 题面限定 | 所以你**可以**引入第三种标记字符 `'#'` 而不丢失信息——这是本题能用 `O(1)` 额外空间的关键 |
| **`m, n` 可能为 1** | 约束 `1 ≤ m, n ≤ 200` | 单行/单列时**所有格子都在边界上**，答案永远是「什么都不改」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `m == board.length` | 1 ≤ m ≤ 200 | 总格数 `N = m·n ≤ 4·10⁴` |
| `n == board[i].length` | 1 ≤ n ≤ 200 | 同上 |
| 元素只有 `'X'` / `'O'` | 二值 + 一个可借用的第三态 | 允许原地标记 |
| 时间限制约 1 s | — | `O(N) = 4·10⁴` 免费；`O(N²) = 1.6·10⁹` **超时** |

> 💡 **量级 → 算法**：`N ≤ 4·10⁴`，`O(N)` 是目标。注意 `4·10⁴` 比 082 的 `9·10⁴` 小，但这种「尺寸稍小」的设计恰恰是为了让**错误的 `O(N²)` 在边界上挣扎**：`1.6·10⁹` 卡在 1~2 秒之间，本机可能「侥幸过」，评测机稍慢就 TLE。**不要用这种边缘用例去赌自己对了。**

### 示例

```text
输入：board = [
  ['X','X','X','X'],
  ['X','O','O','X'],
  ['X','X','O','X'],
  ['X','O','X','X']
]
输出：[
  ['X','X','X','X'],
  ['X','X','X','X'],
  ['X','X','X','X'],
  ['X','O','X','X']
]
解释：(1,1),(1,2),(2,2) 组成的三格区域四邻接都不触边界 → 被吃掉；
      (3,1) 位于最后一行，是边界格 → 永久安全。

输入：board = [['X']]
输出：[['X']]           ← 1×1 的 'X'，什么都不做

输入：board = [['O']]
输出：[['O']]           ← 1×1 的 'O' 就是边界格 → 保留

输入：board = [['O','O','O']]
输出：[['O','O','O']]   ← 单行输入，三个格子全在边界上 → 全都改不了

输入：board = [
  ['X','X','X'],
  ['X','O','X'],
  ['X','X','X']
]
输出：全 'X'            ← 中间那一格离边界一格，四邻都是 'X' → 被吃掉
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① board = [['O']]                       → 单格即边界，输出必须还是 'O'
② 3×3 全 'O'                            → 全部保留（每个格子都能走到边界）
③ [['X','O','X'],
   ['O','X','O'],
   ['X','O','X']]                       → 中心的 'X' 不动；四个 'O' 全在边界上 → 全保留
④ [['O','X','O'],
   ['X','O','X'],
   ['O','X','O']]                       → 只有中心的 'O' 被吃掉，四个角上的 'O' 保留
```

第 ④ 条是本章最好的检验用例：它同时含「逃得掉」和「被吃掉」两类格子，而且第 `(1,1)` 那个 `'O'` 的四邻全是 `'X'`——任何写成「判断四邻是否都是 `'X'`」的错解，在 ③④ 上会表现出完全相反的偏差。

## 084.2 从暴力到最优：第一个念头为什么错

### 第一个念头：逐格判断「我是不是被 `'X'` 围住了」

最自然的写法是：遍历每个 `'O'`，判断它是否被围住；如果是，改成 `'X'`。

```java
// 出生版：对每个 'O' 单独判断它能不能走到边界
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (board[i][j] == 'O' && !canReachBorder(i, j))   // canReachBorder 是 O(N) 搜索
            board[i][j] = 'X';
```

- 时间 **O(N²)**：`canReachBorder` 本身就是一次完整洪水填充，而你对每个 `'O'` 都调一次。
- 代入 `N = 4·10⁴`：`(4·10⁴)² = 1.6·10⁹` 次格子访问。**这个量级正好落在 1~2 秒的模糊地带**——本机可能「跑过了」，但你无法向面试官证明它不会在某台慢机器上 TLE。
- 更要命的是，它**每判断一个格子都要把整片区域重走一遍**，同一片「三格小区域」会被走 3 遍，一片 1 万格的区域会被走 1 万遍。

> ⚠️ 这个「差点能过」的暴力比必然超时的暴力更危险：它会让你误以为找到了解法。**判断标准应该是复杂度，不是本地跑一次的结果。**

### 第二个念头：只从「四个角」灌水

有人做过类似的题（比如「从角出发标记能到达的格子」），于是写成「从四个角开始 DFS」。

**这不够。** 反例直接给出来：

```text
board = [
  ['X','O','X'],
  ['X','X','X'],
  ['X','O','X']
]
(0,1) 和 (2,1) 都是边界上的 'O'，它们**不经过四个角**，只经过第 0 行与第 2 行的中间。
只从角出发 → 这两格没被标记 → 被错误地改成 'X'
```

正确做法是：**从四条边上的所有格子出发**，不是从四个角。

### 卡点在哪：你要判定的谓词是「全局」的

把问题翻译成一句话：

> **对每个 `'O'`，问「它所在的分量有没有碰到边界」。**

卡点有两层：

1. **「分量」是全局信息**：单看一个格子和它的四个邻居，永远看不出「它能不能走 200 步到边界」。
2. **谓词的方向选错了**：`「被围住」` 要求你对「每个格子」都回答一次；而 `「逃得掉」` 是**同一个东西的补集**，只需要**一次**全局搜索就能标记出所有逃得掉的格子。

### 灵感的来源：把谓词取反，让「一次搜索」回答「所有格子」

设 `S` = 所有 `'O'` 格子，`E` = 能走到边界的 `'O'` 格子集合（Escaped）。那么答案要求的操作是：

```text
对 S \ E 的所有格子，改成 'X'
```

关键观察：**`E` 可以用一次多源搜索完整算出来**——

- 起点集合 = 四条边上所有 `'O'`（**多源**，不是单个源）；
- 从起点出发，只沿 `'O'` 走（不穿过 `'X'`）；
- 能到达的格子，全部属于 `E`。

于是算法变成三步：

```text
① 灌水：从四条边的 'O' 出发，把能到达的 'O' 标记成 '#'
② 清场：把所有仍是 'O' 的格子改成 'X'      （这些是 E 的补集，即被围住的）
③ 还原：把所有 '#' 改回 'O'                  （逃掉的格子必须保持原样）
```

**这三步的顺序不能换**，§084.6 会讲为什么。

### 不变量

```
不变量 I：灌水结束时，board 中字符为 '# '的格子集合，
         恰好等于 {能沿四邻接的 'O' 路径走到边界的格子}；
         字符仍为 'O' 的格子，恰好等于 {被围住的格子}。
```

## 084.3 原理拆解

### 084.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐格 `canReachBorder`（暴力） | O(N²) | O(N) | 30 行 | `N ≥ 10⁴` 就贴到超时边缘；本题 `1.6·10⁹` |
| **反向多源 DFS（递归）** ✅ | **O(N)** | O(N) 递归栈 | **20 行** | `m,n = 200` 时最坏深度 `4·10⁴` → Java 爆栈 |
| **反向多源 BFS** ✅（大输入首选） | **O(N)** | O(N) 队列 | 28 行 | 队列要存坐标对，写法稍长 |
| 反向 BFS + 双向收录 | O(N) | O(N) | 30 行 | 无收益，只是常数更小 |
| 并查集（边界建虚拟节点） | O(N·α) | O(N) | 50 行 | 静态题里纯属过度设计；但「边界」这个概念可以顺手做成虚拟根，思路漂亮 |

**选型结论**：

> 「这题我写**反向多源 BFS**：`N` 最大 `4·10⁴`，递归深度最坏也是 `4·10⁴`，Java 默认栈有风险，所以不用递归。多源的意思是**把所有边界 `'O'` 一次性入队**，这样整张图只扫一遍，不会出现『一个区域被灌多次』。」

```
              ┌──────── 判定「被围住」的两条路 ────────┐
              │                                        │
    ┌─────────▼──────────┐              ┌──────────────▼─────────────┐
    │ 正向：逐个格子判     │              │ 反向：一次灌水判整个补集     │
    │ canReachBorder(O(N)) │             │ 从四条边的 'O' 同时出发      │
    └─────────┬──────────┘              └──────────────┬─────────────┘
              │                                        │
      O(N) 个格子 × O(N)                    1 次多源搜索 = O(N)
      = O(N²) = 1.6·10⁹ ❌                  标记 # → O→X → #→O ✅
```

### 084.3.2 为什么这个做法是对的（正确性论证）

**先把「被围绕」严格定义清楚**（这是所有论证的前提）：

> 定义：`'O'` 格子 `c` **逃得掉** ⟺ 存在一条从 `c` 到某个边界格的路径，路径上每一步都是四邻接、且路径上所有格子都是 `'O'`。
> 定义：`c` **被围绕** ⟺ `c` 逃不掉。

**引理 1（灌水标记的集合 = 逃得掉的集合）。** 设 `E` 为逃得掉的 `'O'` 集合，`M` 为灌水后被标成 `'#'` 的集合。则 `M = E`。

- `E ⊆ M`：设 `c ∈ E`，则有一条 `c = c₀, c₁, …, c_k = b` 的全 `'O'` 路径，`b` 是边界格。`b` 在起点集合里，因此被标记 `'#'`。对路径做归纳：若 `cₜ` 被标记，则它的邻居 `c_{t-1}` 是 `'O'`，会被同一次搜索继续扩展并标记。故 `c = c₀ ∈ M`。
- `M ⊆ E`：灌水只从边界 `'O'` 出发，且只沿 `'O'` 走，所以任何被标记的格子 `c` 都有一条「从边界格走到 `c` 的全 `'O'` 路径」（把 DFS/BFS 的父指针链反过来读）。由定义，`c ∈ E`。∎

**引理 2（`E` 是若干完整分量的并集）。** 因为「逃得掉」只依赖连通性：若 `c ∈ E` 且 `c'` 与 `c` 在同一 `'O'` 分量，则把 `c` 到边界的路径前面接上 `c'` 到 `c` 的路径，得到 `c'` 也能逃掉。所以 `c' ∈ E`。∎

**定理（算法输出正确）。** 三步之后：

1. 对 `c ∈ E`（逃得掉）：它在第 ① 步被标 `'#'`，第 ② 步的判据是 `== 'O'`，不会命中；第 ③ 步把它还原成 `'O'`。**输出仍是 `'O'`，符合题意。**
2. 对 `c ∉ E`（被围绕）：它在第 ① 步没被标记，仍是 `'O'`，第 ② 步被改成 `'X'`。**输出是 `'X'`，符合题意。**
3. `'X'` 格子从头到尾没被第 ② 步的 `== 'O'` 命中，也没被标 `'#'`，保持 `'X'`。∎

**终止性**：每个格子最多被标记一次（标记后不再是 `'O'`，不会再次入队），队列有限。∎

> **注意第 2 点的强度**：它说的是「剩下的 `'O'` 按定义就是被围绕的」，**不需要**再对每个格子做任何检查。这正是「补集」带来的红利——**你只付出了一次全局搜索的成本，却得到了关于每一个格子的结论**。

### 084.3.3 通用解题思路（可迁移的那一层）

先把网格三要素写死：

| 要素 | 本题的答案 | 说明 |
| --- | --- | --- |
| **顶点（vertex）** | 每个格子 `(i, j)` | 与前两章一致 |
| **边（edge）** | `(i,j) — (i',j')` 当且仅当**四邻接且两侧都是 `'O'`** | 注意：**只有 `'O'` 之间才有边**。`'X'` 是「墙」，图本身是断开的 |
| **状态（state）** | `'X'`（墙）/ `'O'` 未逃（暂定被围）/ `'#'` 已逃（已确认为安全） | 三种状态，第三态 `'#'` 是**约定出来的**——因为原题只用两个字符，我们白拿了一个可用位 |

抽象成模型：

```
补集反向模型（Complement / Reverse Reachability）
  直接问："哪些格子满足性质 P？"   → 需要对每个格子回答一次 → 易退化成 O(N²)
  反过来问："哪些格子满足 ¬P？"    → 通常一次多源搜索就能全部标出 → O(N)
  结论：答案 = 全集 \ (被标记的补集)
```

为什么这个转化在这题上成立：因为 `¬P`（逃得掉）是**从固定源集合出发的可达性**，而可达性天生适合从源出发的一次搜索。而 `P`（被围住）是「不可达」，它没有自然的搜索方向。

同类题（都属于这个模型）：

| 题 | 补集是什么 | 一次搜索的源 |
| --- | --- | --- |
| [LC 130 被围绕的区域](https://leetcode.cn/problems/surrounded-regions/) | **逃得掉**的 `'O'` | 四条边上的 `'O'` |
| [LC 1254 统计封闭岛屿的数目](https://leetcode.cn/problems/number-of-closed-islands/) | **接触边界**的 `0` | 四条边上的 `0` |
| [LC 1020 飞地的数量](https://leetcode.cn/problems/number-of-enclaves/) | **能走到边界**的 `1` | 四条边上的 `1` |
| [LC 417 太平洋大西洋水流问题](https://leetcode.cn/problems/pacific-atlantic-water-flow/) | **能流入某片洋**的格子 | 与洋相邻的两条边 |
| [LC 542 01 矩阵](https://leetcode.cn/problems/01-matrix/) | 到最近的 `0` 的距离 | **所有** `0`（多源） |

> **本书里「反向」的另一个典型**：[`008-merge-sorted-array.md`](008-merge-sorted-array.md) 用**从后往前**的双指针避免覆盖——那里的反向是为了**保护尚未使用的空间**；这里的反向是为了**把难判定的谓词换成好判定的补集**。同一个词，两种用法，要能区分。

### 084.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成**八连通** | 允许对角逃出 | 方向表 4 → 8；注意此时 ③④ 两个反例的答案会变 |
| 返回**被吃掉的格子数** | 不改结果，只改输出 | 第 ② 步里累加计数，`O(1)` 增加 |
| 要求 `board` **保持不变**、返回新矩阵 | 不能就地改 | 先 `deep copy`，空间 `O(N)`；或在 `copy` 上做三步 |
| 矩阵**大到装不下内存** | 无法一次全图 | 按行分块 + 并查集维护「块边界上哪条连通链接触到了外面」，本质是外存版可达性 |
| 只允许 **`O(1)` 额外空间** | 不能用队列/visited | 用 `board` 自身当标记（本题正好允许，因为字符集有两值 + 可借一个第三态）；但递归/队列的**栈**仍不是 `O(1)`，严格意义下这题需要「用输入当工作区」的技巧 |
| 要**输出每块被吃区域的面积** | 需要记录分量 | 第 ② 步扫到 `'O'` 时再触发一次洪水填充并统计面积（与 083 同构），但必须**先标记再统计** |

## 084.4 图解推演

### 084.4.1 三步走：灌水 → 清场 → 还原

```text
初始 board（m=4, n=4）
        j=0   j=1   j=2   j=3
      ┌─────┬─────┬─────┬─────┐
 i=0  │  X  │  X  │  X  │  X  │   ← 边界行
      ├─────┼─────┼─────┼─────┤
 i=1  │  X  │  O  │  O  │  X  │
      ├─────┼─────┼─────┼─────┤
 i=2  │  X  │  X  │  O  │  X  │
      ├─────┼─────┼─────┼─────┤
 i=3  │  X  │  O  │  X  │  X  │   ← 边界行
      └─────┴─────┴─────┴─────┘
        ↑                 ↑
      边界列            边界列

① 灌水：四条边上只有 (3,1) 是 'O'，从它出发；它的四邻是 X/X/X → 只能标记自己
        j=0   j=1   j=2   j=3
      ┌─────┬─────┬─────┬─────┐
      │  X  │  X  │  X  │  X  │
      ├─────┼─────┼─────┼─────┤
      │  X  │  O  │  O  │  X  │   ← (1,1)(1,2)(2,2) 仍是 'O'
      ├─────┼─────┼─────┼─────┤
      │  X  │  X  │  O  │  X  │
```

### 084.4.3 正向 vs 反向的搜索次数对比

```text
正向（每个 'O' 各搜一次）              反向（多源一次搜完）
────────────────────────────────      ────────────────────────────────
for each 'O':                           queue ← 所有边界 'O'
    BFS(can reach border?)              BFS 一次，标记所有可达格子
────────────────────────────────      ────────────────────────────────
搜索次数 = 'O' 的个数                  搜索次数 = 1
总成本   = O(N²) = 1.6·10⁹            总成本   = O(N) = 4·10⁴

  ○──→○   ○──→○                          ●═══════════╗
  │      │     每次都要               ●═══╝    一次灌满  ║
  ○──→○   ○──→○   重走整片区域         ●═══════════════╝
```

## 084.5 双语言实现

### 084.5.1 Java

```java
import java.util.ArrayDeque;

class Solution {
    private int m, n;
    private static final int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    public void solve(char[][] board) {
        if (board == null || board.length == 0 || board[0].length == 0) return;

        m = board.length;
        n = board[0].length;

        // ① 从四条边出发灌水。注意是"四条边上的每一个格子"，
        //    不是四个角——角上的 'O' 只是边界 'O' 的一个子集
        for (int i = 0; i < m; i++) {
            bfs(board, i, 0);       // 左边界
            bfs(board, i, n - 1);   // 右边界
        }
        for (int j = 0; j < n; j++) {
            bfs(board, 0, j);       // 上边界
            bfs(board, m - 1, j);   // 下边界
        }

        // ②③ 一趟扫描同时完成清场与还原。
        //     顺序很重要：'O' → 'X' 必须先判断，因为 '#' 此时还是 '#'，
        //     两种判据互不干扰；反过来先还原 '#' 就会污染 'O' 的判据
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (board[i][j] == 'O') {
                    board[i][j] = 'X';   // 逃不掉 → 被吃掉
                } else if (board[i][j] == '#') {
                    board[i][j] = 'O';   // 逃得掉 → 复原
                }
            }
        }
    }

    private void bfs(char[][] board, int si, int sj) {
        // 起点不是 'O' 就不用灌（包括已经是 '#' 的、以及 'X' 的）
        if (board[si][sj] != 'O') return;

        board[si][sj] = '#';                       // 入队即标记，避免同一格被重复入队
        ArrayDeque<int[]> q = new ArrayDeque<>();
        q.add(new int[]{si, sj});

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            for (int[] d : DIRS) {
                int ni = cur[0] + d[0], nj = cur[1] + d[1];
                // 出界 或 不是未标记的 'O' → 不扩展
                if (ni < 0 || ni >= m || nj < 0 || nj >= n || board[ni][nj] != 'O') continue;
                board[ni][nj] = '#';
                q.add(new int[]{ni, nj});
            }
        }
    }
}
```

### 084.5.2 Go

```go
package main

func solve(board [][]byte) {
	if len(board) == 0 || len(board[0]) == 0 {
		return
	}
	m, n := len(board), len(board[0])

	// 队列用"两个切片索引"实现，避免 q[1:] 反复移动底层数组
	var bfs = func(si, sj int) {
		if board[si][sj] != 'O' {
			return
		}
		board[si][sj] = '#'
		queue := [][2]int{{si, sj}}
		for head := 0; head < len(queue); head++ {
			ci, cj := queue[head][0], queue[head][1]
			// 四邻展开：写成显式四次判断，省掉方向数组的间接寻址
			if ci > 0 && board[ci-1][cj] == 'O' {
				board[ci-1][cj] = '#'
				queue = append(queue, [2]int{ci - 1, cj})
			}
			if ci+1 < m && board[ci+1][cj] == 'O' {
				board[ci+1][cj] = '#'
				queue = append(queue, [2]int{ci + 1, cj})
			}
			if cj > 0 && board[ci][cj-1] == 'O' {
				board[ci][cj-1] = '#'
				queue = append(queue, [2]int{ci, cj - 1})
			}
			if cj+1 < n && board[ci][cj+1] == 'O' {
				board[ci][cj+1] = '#'
				queue = append(queue, [2]int{ci, cj + 1})
			}
		}
	}

	// ① 四条边上的所有格子都当一次潜在源
	for i := 0; i < m; i++ {
		bfs(i, 0)
		bfs(i, n-1)
	}
	for j := 0; j < n; j++ {
		bfs(0, j)
		bfs(m-1, j)
	}

	// ②③ 清场与还原
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			switch board[i][j] {
			case 'O':
				board[i][j] = 'X'
			case '#':
				board[i][j] = 'O'
			}
		}
	}
}
```

### 084.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 队列容器 | `ArrayDeque<int[]>`（比 `LinkedList` 快） | `[][2]int` + `head` 下标 | Java 每次 `new int[]{i,j}` 都有对象分配；Go 的 `[2]int` 是值类型，无堆分配（`append` 可能扩容） |
| 字符类型 | `char`，`'O'` 是 16 位 | `byte`，`'O'` 是 `byte` 常量 | 判等写法一致；Go 里 `board[i][j] == "O"` 会编译报错（字符串 vs byte），能提前拦住错误 |
| `switch` 写法 | 支持 `char` 的 `switch` | `switch board[i][j]` 支持，但 `case 'O':` 需要常量 | 两边都好写；Go 不用 `break`，更不容易漏 |
| 闭包 vs 方法 | `private void bfs(...)` 可直接当方法 | 匿名函数必须赋值给变量，且不能递归引用自身名字（这里不需要递归） | Go 里写成 `var bfs = func(...)` 是标准做法 |
| 参数传递 | 数组是引用，就地修改生效 | 切片是引用（底层数组共享），就地修改同样生效 | 两者都满足「就地修改」的签名要求；但 Go 若在 `bfs` 里 `append` 到 `board` 本身会改切片头，所以**只改元素不改结构**是安全线 |

## 084.6 复杂度与常见坑

### 084.6.1 复杂度推导

- **时间 O(mn)**：
  - 灌水阶段：每个格子最多入队一次（入队前判 `== 'O'`，入队即改 `'#'`），出队时检查 4 个邻居，合计 `≤ 4mn` 次判空 + `mn` 次入队 → `O(mn)`。
  - 四条边的循环：`2m + 2n` 次 `bfs` 调用，其中绝大多数立刻返回（起点不是 `'O'`），仍然 `O(m + n) ≤ O(mn)`。
  - 清场/还原：一次全图扫描 `O(mn)`。
  - 合计 `O(mn)`。
- **空间**：队列最坏存 `O(mn)` 个坐标；若用递归 DFS，栈深 `O(mn)`。**额外空间不是 `O(1)`**——`'#'` 标记省掉的是 `visited` 数组，不是队列本身（§084.3.4 追问里会讲这件事）。

### 084.6.2 七个真实踩过的坑

1. **②③ 顺序颠倒**：先写 `if ('#' → 'O')` 再写 `if ('O' → 'X')`，第二遍会把刚还原的 `'O'` 全部吃掉，输出全 `'X'`。**必须让 `'O' → 'X'` 的判据在 `'#'` 还原之前生效**，或者用两趟独立循环。
2. **只用四个角当源**：§084.4.2 的图就是反例，(0,1) 这种「边界中间」的 `'O'` 会被漏掉。
3. **用 `'X'` 当标记**：把逃掉的格子标成 `'X'`，之后就分不清「原本的墙」和「标记过的格子」，还原阶段无法工作。必须引入第三态（`'#'`/`'1'`/`'Y'` 都行）。
4. **递归爆栈**：`m = n = 200` 时最坏深度 `4·10⁴`，Java 默认栈会 `StackOverflowError`。这题要用 BFS 或显式栈。
5. **单行/单列输入**：`m == 1` 或 `n == 1` 时**所有**格子都在边界上，答案必须是「什么都不改」。任何「先清场再灌水」的顺序错误都会在这里暴露成全 `'X'`。
6. **`bfs` 起点没判 `'O'`**：直接 `board[si][sj] = '#'` 会把 `'X'` 改成 `'#'`，最后又被还原成 `'O'`，凭空长出一片陆地。
7. **入队与标记分离**：先入队、出队时才标记，会导致同一格从多个邻居重复入队，队列膨胀到 `O(4N)`，且（在按面积统计的变体里）会重复计数。

### 084.6.3 面试官最爱追问的三个问题

**Q1：为什么反向灌水比正向判断好？**
> 「因为『被围绕』是一个**不可达性**谓词：它说『不存在通往边界的路径』。不可达性没有自然的搜索方向，只能对每个格子各搜一次，`O(N²)`。而它的补集『逃得掉』是**从固定源集合出发的可达性**，一次多源搜索就能把所有逃得掉的格子标出来，`O(N)`。代价是要多做一次『取补集』的清场扫描，仍然是 `O(N)`。这是典型的『难判定的谓词，去判定它的补集』。」

**Q2：能不能做到 `O(1)` 额外空间？**
> 「标记 `'#'` 这一步确实是 `O(1)` 额外空间——我们借用了字符集里的第三个值，没有开 `visited`。但搜索本身的**队列或递归栈**仍然要 `O(N)`。要做到真正的 `O(1)` 额外空间，需要一种『不需要待办队列的遍历』，比如把边界格当作起点、用类似 Morris 遍历的思路缓存回退信息——在这题上得不偿失。实际面试里我会说：**额外空间 `O(N)`，其中 visited 被压掉了，只剩队列。**」

**Q3：如果输入不允许修改，怎么办？**
> 「那就先复制一份 `board`，在副本上做三步，然后**把副本的内容写回原数组**——注意 LeetCode 的签名是 `void solve(char[][])`，必须就地生效。空间从 `O(N)`（队列）变成 `O(N)`（副本 + 队列），量级不变但常数翻倍。另一种做法是：预先收集所有边界 `'O'` 的坐标，用 `visited` 布尔数组代替 `'#'` 标记，这样原数组只在最后一步被写一次。」
