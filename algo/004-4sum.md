## 004.1 题目

**原题链接**：<https://leetcode.cn/problems/4sum/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的整数数组 `nums` 和一个整数 `target`，请找出**所有**满足 `nums[a] + nums[b] + nums[c] + nums[d] == target` 且 `a < b < c < d` 的四元组，返回它们组成的列表，**答案中不可以包含重复的四元组**。

和 003 相比，题干只多了一个数，但隐含条件多了一条致命的：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **四个下标严格递增** `a < b < c < d` | 「`a, b, c, d` 互不相同」 | 允许同一元素复用 → `[2,2,2,2], target=8` 返回 `[0,0,0,0]` |
| **按值去重** | 「不可以包含重复的四元组」 | `[1,1,1,3,3,3]` 会输出多次 `[1,1,3,3]` |
| **输出所有解** | 「找出所有」 | 找到一组就 `return` → 漏解 |
| **元素值域 `±10^9`** | 约束表 | **四个数相加最坏 `±4·10⁹`**，超出 `int32` 上界 `2.147·10⁹` → **溢出成负数**，判定完全错乱 |
| **`n` 只有 200** | 约束 | 允许 O(n³)；但 O(n⁴) 是 `1.6·10⁹`，危险 |

> ⚠️ 「四数之和」是本书里**第一个「溢出比算法更容易错」的题**。三数之和的值域是 `±10⁵`（和 `±3·10⁵`，int 安全），四数之和直接跳到 `±10⁹`。你从 003 抄代码过来，算法一字不改，**结果全错**，而且错得毫无提示：`s` 变成一个负数，于是「和偏大」被判成「和偏小」，指针朝反方向跑。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 200` | n 至多 200 | **O(n³) = 8·10⁶ → 安全**；**O(n⁴) = 1.6·10⁹ → 秒级超时**。所以正解必须是「两层固定 + O(n) 双指针」 |
| `-10^9 <= nums[i] <= 10^9` | 单值 ±1e9 | 两数相加已达 `±2·10⁹`（刚好卡在 int32 边界内，**运气**）；三数 `±3·10⁹`、四数 `±4·10⁹` **必然溢出** |
| `-10^9 <= target <= 10^9` | 目标 ±1e9 | 与元素同量级，所以「和」与 `target` 的比较必须用 `long`，否则差值也溢出 |
| 答案可能为空 | 允许多解也可能无解 | 不能假设 `res` 非空；Go 返回 `nil` 切片、Java 返回空 `List` 都要能过 |

> 💡 **量级反推**：`n = 200` 是出题人给的第二个暗号 —— 它刚好让 O(n³) 舒服（8·10⁶），又刚好让 O(n⁴) 死（1.6·10⁹）。把 003 的 `n = 3000 → O(n²)` 和这里的 `n = 200 → O(n³)` 放在一起看，你会得到一个通用公式：**k 数之和的正解复杂度就是 `O(n^(k-1))`，而题目给的 n 永远刚好卡在「这个复杂度舒服、再高一档就死」的位置**。

### 示例

```
输入：nums = [1,0,-1,0,-2,2], target = 0
输出：[[-2,-1,1,2], [-2,0,0,2], [-1,0,0,1]]

输入：nums = [2,2,2,2,2], target = 8
输出：[[2,2,2,2]]
解释：5 个 2 里任选 4 个都是同一个四元组，只输出一次

输入：nums = [1000000000,1000000000,1000000000,1000000000], target = -294967296
输出：[]
解释：这是 LeetCode 官方给的溢出用例。4·10⁹ = 4000000000，超出 int32 上界后
      溢出成 4000000000 - 2^32 = -294967296 —— 恰好等于 target！
      用 int 累加会错误地返回 [[1e9,1e9,1e9,1e9]]
```

> 第三个示例请务必记住：**出题人专门造了一个「溢出后恰好等于 target」的用例**来打 int 累加。这不是巧合，这是钓鱼。

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [2,2,2,2,2], 8          → 暴露「只做 i 层去重，j 层不去重」：输出 5 次 [2,2,2,2]
② [1,1,1,3,3,3], 8        → 暴露「去重条件写成 j > 0」：j 从 i+1 开始时会把合法解的兄弟误杀
③ [1e9,1e9,1e9,1e9], -294967296 → 暴露 int 溢出（上面的官方钓鱼用例）
④ [-3,-2,-1,0,0,1,2,3], 0 → 8 个数、多解密集，暴露「剪枝写太狠导致漏解」
```

第 ② 条的细节值得说清：`j` 的去重必须写成 `j > i + 1 && nums[j] == nums[j-1]`，**而不是** `j > 0`。因为 `j = i+1` 是「`i` 之后的第一个位置」，它前面那个 `nums[i]` 可能和 `nums[j]` 相等（如 `[1,1,1,3,3,3]` 里 `i=0, j=1` 都是 `1`）—— 这时 `nums[j] == nums[j-1]` 成立，但 `j` 是这一层的**首个**候选，绝不能跳过。

## 004.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力

```java
// 四重循环：C(200,4) ≈ 6.5·10^7 —— 咦，好像也不多？
for (int a = 0; a < n; a++)
  for (int b = a+1; b < n; b++)
    for (int c = b+1; c < n; c++)
      for (int d = c+1; d < n; d++)
        if (nums[a]+nums[b]+nums[c]+nums[d] == target) 收集四元组;
```

先算准数：`C(200,4) = 200·199·198·197 / 24 ≈ 6.47·10⁷`。按 10⁸ 次/秒的保守估计是 0.65 s；LeetCode 的判题机通常能扛住，**但这仍然不是正解**，理由有三：

1. **常数与开销**：每次内层要 3 次加法 + 1 次比较 + 数组访问，实际是 3 亿次操作级别，在 Java 上会因为边界检查（bounds check）进一步放大。
2. **结果全是重复的**：暴力在**下标层面**枚举，输出天然含大量重复四元组（`[2,2,2,2,2]` 会输出 5 次），你还得再做 O(k log k) 去重。
3. **约束会变**：n 改成 1000（合情合理），`C(1000,4) ≈ 4.1·10¹⁰` —— 4 分钟起步。

> 📌 记住这个判断习惯：**暴力能过 ≠ 暴力是正解**。面试考的是「你能不能在 30 秒内说出 `O(n^(k-1))` 这个结构」，而不是「你的代码有没有 TLE」。

### 第二步：卡点在哪

把四重循环改写成「固定两个、查两个」：

```
固定 a, b  →  需要 nums[c] + nums[d] == target - nums[a] - nums[b]
```

这就是 **002 的两数之和**，而且是「数组已排序 + 要一对下标 + 不许重复用元素」的版本 —— 完全就是 167/002 的题面。所以：

```
四数之和(18) = 外层两层固定 + 内层一次 002
三数之和(15) = 外层一层固定 + 内层一次 002
```

复杂度从 `O(n⁴)` 掉到 `O(n³)`。

**卡点一：去重从「3 处」变成「4 处」**

| 层 | 去重条件 | 保护谁 |
| --- | --- | --- |
| `i` | `i > 0 && nums[i] == nums[i-1]` | 相同的第一元只枚举一次 |
| `j` | `j > i+1 && nums[j] == nums[j-1]` | 相同的第二元（在同一 `i` 下）只枚举一次 |
| 命中后 `l` | `while (l<r && nums[l]==nums[l+1]) l++` | 相同的第三元 |
| 命中后 `r` | `while (l<r && nums[r]==nums[r-1]) r--` | 相同的第四元 |

注意第二行的 `j > i+1`，这是本题最容易写错的一行（见 §004.1 反例 ②）。

**卡点二：溢出**

`nums[i] + nums[l] + nums[r] + nums[j]` 四项各 `±10⁹`，和最大 `+4·10⁹`、最小 `-4·10⁹`，而 Java 的 `int` 上界是 `2³¹ - 1 = 2147483647 ≈ 2.147·10⁹`。溢出后：

```
+4·10⁹  →  4·10⁹ - 2³² = -294967296   （变负！）
-4·10⁹  →  -4·10⁹ + 2³² = 294967296   （变正！）
```

后果是**比较方向反了**：本应「和偏大 → `r--`」，溢出成负数后变成「和偏小 → `l++`」，指针朝错的方向跑，最终**返回错解而不是崩溃**。这是最危险的一类 bug：静默错误。

修法只有一个：**累加和比较全程用 `long`**。

```java
long s = (long) nums[i] + nums[j] + nums[l] + nums[r];   // 第一个操作数转 long，后续自动提升
if (s == target) ...        // target 是 int，会自动提升为 long 比较，安全
```

> ❌ 写成 `long s = nums[i] + nums[j] + nums[l] + nums[r];` 是**错的** —— 右边四个 `int` 先按 `int` 算完（已经溢出），再赋给 `long`，溢出已经发生了。**必须至少有一个操作数在加法之前就是 `long`。**

### 第三步：灵感的来源 —— 剪枝让 O(n³) 的常数塌下来

排序之后，对任何一层固定，都能立刻判断「这一层的所有剩余候选都不可能达标」：

| 层 | 乐观上界（最大可能和） | 悲观下界（最小可能和） | 动作 |
| --- | --- | --- | --- |
| `i` | `nums[i] + nums[n-1] + nums[n-2] + nums[n-3]` | `nums[i] + nums[i+1] + nums[i+2] + nums[i+3]` | 上界 `< target` → `continue`；下界 `> target` → `break` |
| `j` | `nums[i] + nums[j] + nums[n-1] + nums[n-2]` | `nums[i] + nums[j] + nums[j+1] + nums[j+2]` | 同上 |

这些剪枝不改变最坏复杂度 `O(n³)`，但能把「全正数数组 + 小 target」这类输入从 8·10⁶ 次降到几百次。**面试里说得出「上界/下界剪枝」，比只说得出「双指针」高一个档次。**

## 004.3 原理拆解

### 004.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 去重难度 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 四重暴力 + 事后 `Set` | O(n⁴ + k log k) | O(k) | 低 | n ≥ 100 就 TLE；本题不可用 |
| **排序 + 两层固定 + 双指针** ✅ | **O(n³)** | **O(1)** | 中（4 处 skip） | 输入不可改（只读流）时得复制数组，空间 O(n) |
| 排序 + 一层固定 + 内层「两数和」哈希 | O(n³) | O(n) | **高** | 哈希只回答「值在不在」，去重仍需 `Set` 兜底；空间翻倍 |
| 两两分组哈希（pair-sum map） | O(n²) 建表 + O(n²·?) 查 | **O(n²)** | 高 | 本题是**单数组**、要求下标互异 → 同一下标可能被两个 pair 复用，还要处理「pair 之间下标冲突」，实现极易出错 |
| 通用 k-sum 递归 | O(n^(k-1)) | O(k) 栈 | 中 | k 大时常数爆炸；但通用性好 |

**为什么「两两分组哈希」在本题输**：那套打法在 **LC 454 四数相加 II** 里是无敌的（四个**独立**数组，`(a,b)` 的下标自然不和 `(c,d)` 冲突）。但本题是单数组，一个下标可能同时出现在两个 pair 里（`(0,1)` 和 `(1,2)` 共享下标 1），必须额外判重；而且 `O(n²)` 的表在 `n = 200` 时是 4 万个 entry，**比直接 O(n³) 的 8·10⁶ 次简单加法还贵**。这就是「同一套技巧换个输入结构就从最优变最差」的典型。

### 004.3.2 为什么这个做法是对的（正确性论证）

**（A）完备性（不漏解）**

排序后，任取一个真实解，按值升序写成 `(p, q, r, s)`。设 `i` 是 `p` 在数组中的**首次**出现位置，`j` 是 `q` 在 `[i+1, n)` 中的**首次**出现位置。

1. 外层 `i` 不会跳过 `i`：去重条件只在 `i > 0 && nums[i]==nums[i-1]` 时触发，而 `i` 是首次出现，不满足。
2. 第二层 `j` 不会跳过 `j`：去重条件 `j > i+1 && nums[j]==nums[j-1]`；`j` 是 `[i+1, n)` 内 `q` 的首次出现，若 `j == i+1` 条件直接为假；否则 `nums[j-1] < nums[j]`（首次出现），也为假。所以 `j` 一定会被枚举。
3. 内层双指针从 `l = j+1, r = n-1` 出发。由 002 的循环不变量：**只要解 `(r 的位置, s 的位置)` 落在 `[j+1, n-1]` 内，双指针一定能命中**。而 `r >= q >= p`、`s >= r`，它们在数组中的位置必然 `> j`。

故 `(p,q,r,s)` 必被找到。∎

**（B）去重（不重复）**

- 若两个四元组的值相同，则它们按值升序后完全一致，于是 `(p, q)` 相同。
- `i` 层去重保证「相同的 `p` 只贡献一个 `i`」；`j` 层去重保证「在同一个 `i` 下，相同的 `q` 只贡献一个 `j`」。
- 剩下的 `(r, s)` 由内层双指针枚举，而 003 已经证明：对固定的 `(i, j)`，内层去重保证「相同的 `(r, s)` 值对只命中一次」。

三步合起来：**同一个值四元组只能由唯一的 `(i, j)` 组合、在那唯一一次命中中产出**。∎

> **这套论证的结构值得背下来**：`k` 数之和的去重正确性 = 「按值升序后的规范形唯一」+「每一层只取该值的首次出现」。它可以机械地推广到任意 `k`。

**（C）溢出不影响正确性（前提是用 `long`）**

`long` 是 64 位，最大值 `9.22·10¹⁸`。四个 `±10⁹` 的数相加最坏 `±4·10⁹`，远在范围内；`target` 也提升为 `long` 比较。所以「和与 target 的比较」是**数学上精确的**，前面基于单调性的论证全部成立。∎

### 004.3.3 通用解题思路（可迁移的那一层）

这就是 **n 数之和的递归降维模板**：

```
ksum(nums, start, k, target, path):
    if k == 2:
        双指针 l=start, r=n-1，边找边去重，命中就收集 path + [nums[l], nums[r]]
        return
    剪枝：用最小的 k 个数与最大的 k 个数夹逼 target，整层不可能就 return
    for i in start .. n-k:
        if i > start && nums[i] == nums[i-1]: continue     ← 去重
        path.push(nums[i])
        ksum(nums, i+1, k-1, target - nums[i], path)
        path.pop()
```

复杂度：`O(n^(k-1))`，栈深 `k-2`。

| k | 题 | 固定层数 | 时间 | n 的暗号 |
| --- | --- | --- | --- | --- |
| 2 | [LC 167](https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/) | 0 | O(n) | 3·10⁴ |
| 3 | [LC 15](https://leetcode.cn/problems/3sum/) | 1 | O(n²) | 3000 |
| 4 | [LC 18](https://leetcode.cn/problems/4sum/) | 2 | O(n³) | 200 |
| 4（独立数组） | [LC 454](https://leetcode.cn/problems/4sum-ii/) | 分组哈希 | O(n²) | 200 |

> 📌 注意最后一行：**同样是「四个数」，输入结构一变（四个独立数组 vs 单个数组），最优解的复杂度从 O(n³) 变成 O(n²)**。这是本书反复强调的「算法匹配输入结构」。

### 004.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**一组**解 | 可提前 `return` | 命中即返回；最坏仍 O(n³)（可能无解） |
| 求**四元组个数**（按值去重后） | 不需要输出内容 | 把 `res.add` 换成计数器，省掉 O(k) 空间 |
| 求**下标四元组个数**（可重复值算不同） | **不能去重** | 去掉所有 `skip`；LC 454 的思路更合适 |
| **五个数**之和 | 再降一维 | O(n⁴)，`n` 会缩到 50 以内；递归模板直接套 |
| 值域放大到 `±10¹⁸` | 4 个相加超出 `int64` | 必须用 `BigInteger`（Java）/ `math/big`（Go），或改用哈希避免累加 |
| 数组**不允许排序** | 丢失单调性 | 退回「两层固定 + 内层哈希 + `Set` 去重」，O(n³)/O(n) |

**进阶延伸（自己写代码验证）**：

- **LC 454 四数相加 II**：四个独立数组，两两分组哈希。对照本章体会「为什么同样 O(n²) 的思路在这里才成立」。
- **LC 923 三数之和的多种可能**：按下标计数，去重全部作废 —— 理解「去重是需求，不是通性」。
- **LC 1 / 15 / 18 的递归统一实现**：自己写一个 `ksum(k)`，跑 `k=2,3,4,5` 对拍，你会对「降维」有肌肉记忆。

## 004.4 图解推演

### 004.4.1 主样例的完整轨迹

```
nums = [1, 0, -1, 0, -2, 2], target = 0
排序后 a = [-2, -1, 0, 0, 1, 2]
下标(0-based) 0   1   2  3  4  5
```

```
════════ i = 0 (a[0] = -2)，需要三数和 = 2 ════════
  j = 1 (a[1] = -1)，需要两数和 = 3
      l=2                r=5
  ┌────┬────┬────┬────┬────┬────┐
  │ -2 │ -1 │  0 │  0 │  1 │  2 │
  └────┴────┴────┴────┴────┴────┘
    ↑i    ↑j   ↑l              ↑r     s = -2-1+0+2 = -1 < 0  → l++
                →               ←
      s = -2-1+0+2 = -1 < 0          → l++   (l=4, 值 1)
      s = -2-1+1+2 =  0  ✅ 命中 [-2,-1,1,2]
      命中后 l→5, r→4，l>=r 退出

  j = 2 (a[2] = 0)，需要两数和 = 2
      l=3            r=5
  ┌────┬────┬────┬────┬────┬────┐
  │ -2 │ -1 │  0 │  0 │  1 │  2 │
  └────┴────┴────┴────┴────┴────┘
    ↑i         ↑j   ↑l         ↑r     s = -2+0+0+2 = 0  ✅ 命中 [-2,0,0,2]
                     →          ←
      命中后 l 跳过重复的 0（下标 2→3），r 退一格 → l=4, r=4，退出

  j = 3 (a[3] = 0)，与 a[2] 相同 → j 层去重 continue

════════ i = 1 (a[1] = -1)，需要三数和 = 1 ════════
  j = 2 (a[2] = 0)，需要两数和 = 1
      s = -1+0+0+1 = 0  ✅ 命中 [-1,0,0,1]
  j = 3 (a[3] = 0)，与 a[2] 相同 → continue

════════ i = 2 (a[2] = 0)，需要三数和 = 0 ════════
  j = 3，l = 4，r = 5：s = 0+0+1+2 = 3 > 0 → r-- → 退出，无解

════════ i = 3 (a[3] = 0) → i 层去重 continue
════════ i = 4 (a[4] = 1)：j 只能到 5，凑不出 4 个数 → for 条件结束
```

结果：`[[-2,-1,1,2], [-2,0,0,2], [-1,0,0,1]]` ✓

### 004.4.2 四层去重各自的「守卫范围」

```
        ┌──────────────────────────────────────────────────────────┐
        │  i 层：i > 0 && a[i]==a[i-1]  → 相同的第一元只留一个       │
        │      （连续 3 个 -2，只枚举第 1 个）                       │
        ├──────────────────────────────────────────────────────────┤
        │  j 层：j > i+1 && a[j]==a[j-1] → 相同第二元只留一个        │
        │      ⚠️ 是 i+1 不是 0：i 之后首个 j 必须放行               │
        ├──────────────────────────────────────────────────────────┤
        │  l 层：命中后 while(a[l]==a[l+1]) l++  → 跳过相同第三元    │
        │  r 层：命中后 while(a[r]==a[r-1]) r--  → 跳过相同第四元    │
        │      ⚠️ while 里必须带 l < r，否则 [0,0,0,0] 上越界        │
        └──────────────────────────────────────────────────────────┘
```

用 `nums = [1,1,1,3,3,3], target = 8` 验证四层去重是否都在工作：

| 组合（下标） | 值四元组 | 会被输出吗 | 由谁拦住 |
| --- | --- | --- | --- |
| (0,1,3,4) | [1,1,3,3] | ✅ 唯一一次 | 它的 `(i,j) = (0,1)` 是首次出现 |
| (0,1,3,5) | [1,1,3,3] | ❌ | 内层 `r` 跳过相同第四元 |
| (0,2,3,4) | [1,1,3,3] | ❌ | `j` 层：`j=2 > i+1=1` 且 `a[2]==a[1]` |
| (1,2,4,5) | [1,1,3,3] | ❌ | `i` 层：`i=1 > 0` 且 `a[1]==a[0]` |

**一行一个守卫，四行合起来把 6 种下标组合压成 1 个值四元组。**

### 004.4.3 int 溢出到底把指针带到了哪个方向（必须看懂这张图）

```
正确的比较（long）：
  s = 4·10⁹  →  s > target  →  r--   ✔ 让和变小

溢出后的比较（int）：
  4·10⁹ mod 2³² = -294967296
  s = -294967296 → s < target(= -294967296)?  恰好相等 → 误命中！
  若 target 换成 0：s = -294967296 < 0  →  l++   ✘ 该让和变小时却让和变大
                                          ↓
                                   指针朝反方向跑，越跑越"对不上"
```

```
       正确路径                          溢出路径
   s = +4e9 (>t)                     s = -2.9e8 (<t)
        │                                 │
        ▼                                 ▼
      r-- (和变小)                      l++ (和变大)
        │                                 │
        ▼                                 ▼
   逼近 target                       远离 target → 最终返回空/错解
```

> **所以「四数之和」这个题的真正考点，一半在算法，一半在「你有没有把 `long` 写对位置」。** `long s = (long) a + b + c + d` 里的那个强制转换，是本题代码里最重要的一个字符。

### 004.4.4 与 003 的结构对照

| 维度 | 003 三数之和 | 004 四数之和 |
| --- | --- | --- |
| 固定层 | 1 层（`i`） | 2 层（`i`, `j`） |
| 内层 | 双指针 `l=i+1, r=n-1` | 双指针 `l=j+1, r=n-1` |
| 去重处 | 3 处 | **4 处** |
| 累加类型 | `int` 够（±3·10⁵） | **必须 `long`**（±4·10⁹） |
| 时间 | O(n²) | O(n³) |
| 题目给的 n | 3000 | 200 |
| 额外剪枝 | `a[i] > 0` 就 `break` | **两层都要「上下界夹逼」** |

## 004.5 双语言实现

### 004.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> fourSum(int[] nums, int target) {
        Arrays.sort(nums);              // 一切正确性的地基：规范序 + 单调性
        int n = nums.length;
        List<List<Integer>> res = new ArrayList<>();

        // 元素值域 ±1e9，四个相加最坏 ±4e9，超出 int32 上界（2.147e9）。
        // 把 target 先提升成 long：后面所有比较都用 long，避免任何隐式回退
        long t = target;

        for (int i = 0; i < n - 3; i++) {
            // 去重第 1 层
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }
            // 剪枝：以 i 为最小元时的「最小可能和」与「最大可能和」，都要用 long 算
            long minI = (long) nums[i] + nums[i + 1] + nums[i + 2] + nums[i + 3];
            if (minI > t) {
                break;                  // 最小的组合都超了，i 再大只会更超
            }
            long maxI = (long) nums[i] + nums[n - 1] + nums[n - 2] + nums[n - 3];
            if (maxI < t) {
                continue;               // 最大的组合都不够，这个 i 无解，换下一个
            }

            for (int j = i + 1; j < n - 2; j++) {
                // 去重第 2 层：注意下界是 i+1 而不是 0。
                // j == i+1 是该层首个候选，即便与 nums[i] 同值也必须放行
                if (j > i + 1 && nums[j] == nums[j - 1]) {
                    continue;
                }
                // 第二层的夹逼剪枝（同 i 层，固定 nums[i] 后只剩三个可变元）
                long minJ = (long) nums[i] + nums[j] + nums[j + 1] + nums[j + 2];
                if (minJ > t) {
                    break;
                }
                long maxJ = (long) nums[i] + nums[j] + nums[n - 1] + nums[n - 2];
                if (maxJ < t) {
                    continue;
                }

                int l = j + 1, r = n - 1;
                while (l < r) {
                    // 关键：(long) 必须作用在第一个操作数上。
                    // 写成 long s = nums[i] + nums[j] + nums[l] + nums[r]; 会先按 int 溢出再赋值
                    long s = (long) nums[i] + nums[j] + nums[l] + nums[r];
                    if (s == t) {
                        res.add(Arrays.asList(nums[i], nums[j], nums[l], nums[r]));

                        // 去重第 3、4 层：命中后跳过相同的第三、第四元
                        while (l < r && nums[l] == nums[l + 1]) {
                            l++;
                        }
                        while (l < r && nums[r] == nums[r - 1]) {
                            r--;
                        }
                        l++;
                        r--;
                    } else if (s < t) {
                        l++;            // 和偏小 → 让中间元变大
                    } else {
                        r--;            // 和偏大 → 让右端变小
                    }
                }
            }
        }
        return res;
    }
}
```

### 004.5.2 Go

```go
package main

import "sort"

// fourSum 返回所有和为 target 的不重复四元组。
// 变量名与 Java 版逐行对齐，便于对照。
func fourSum(nums []int, target int) [][]int {
	sort.Ints(nums) // pdqsort，原地排序
	n := len(nums)
	res := [][]int{}

	// Go 的 int 在 64 位平台是 64 位，本身不会溢出；
	// 但显式转 int64 有两个好处：① 32 位平台（GOARCH=386/arm）也正确
	// ② 代码本身成为注释，读者一眼看到「这里有溢出风险」
	t := int64(target)

	for i := 0; i < n-3; i++ {
		if i > 0 && nums[i] == nums[i-1] {
			continue
		}

		minI := int64(nums[i]) + int64(nums[i+1]) + int64(nums[i+2]) + int64(nums[i+3])
		if minI > t {
			break
		}
		maxI := int64(nums[i]) + int64(nums[n-1]) + int64(nums[n-2]) + int64(nums[n-3])
		if maxI < t {
			continue
		}

		for j := i + 1; j < n-2; j++ {
			// 去重第 2 层：下界是 i+1，不是 0
			if j > i+1 && nums[j] == nums[j-1] {
				continue
			}

			minJ := int64(nums[i]) + int64(nums[j]) + int64(nums[j+1]) + int64(nums[j+2])
			if minJ > t {
				break
			}
			maxJ := int64(nums[i]) + int64(nums[j]) + int64(nums[n-1]) + int64(nums[n-2])
			if maxJ < t {
				continue
			}

			l, r := j+1, n-1
			for l < r {
				s := int64(nums[i]) + int64(nums[j]) + int64(nums[l]) + int64(nums[r])
				switch {
				case s == t:
					// 每次新建切片：复用同一个底层数组会让已收集的结果互相覆盖
					res = append(res, []int{nums[i], nums[j], nums[l], nums[r]})

					for l < r && nums[l] == nums[l+1] {
						l++
					}
					for l < r && nums[r] == nums[r-1] {
						r--
					}
					l++
					r--
				case s < t:
					l++
				default:
					r--
				}
			}
		}
	}
	return res
}
```

### 004.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 整数宽度 | `int` **恒 32 位** → 必须 `(long)` 强转 | `int` 在 64 位平台是 64 位 | **同一份算法，Java 不转必挂官方溢出用例，Go 不转在 amd64 上能过** —— 这类「本地过、判题挂 / 换个平台就挂」的差异最阴 |
| 强转写法 | `(long) a + b + c + d`（一个操作数足够） | `int64(a) + int64(b) + ...`（Go **没有隐式提升**，逐项转换更直白但更啰嗦） | Java 可以只转一个；Go 必须显式，否则 `int64 + int` 直接编译错误 |
| 结果容器 | `List<List<Integer>>` + `Arrays.asList` | `[][]int` + `[]int{...}` | Go 每次 `[]int{...}` 都是新底层数组，天然安全；Java 的 `asList` 返回定长 `List`，**不能 `add`**（本题不 add，安全） |
| 空结果 | `new ArrayList<>()` | `nil` 或 `[][]int{}` | 两者 LeetCode 都接受；`[]` 与 `null` 在 JSON 层不同，工程代码里倾向返回空切片 |
| 排序 | `Arrays.sort(int[])` 双轴快排 | `sort.Ints` pdqsort | 都不稳定，但本题只关心值 → 无影响 |
| 溢出检查 | 可配 `Math.addExact` 抛异常（调试时好用） | 无内建检查；调试可用 `math.MaxInt64` 手算 | 面试时提一句「我会在调试期用 `addExact` 定位溢出」是加分项 |

```go
package main

import (
	"fmt"
	"math/rand"
	"sort"
	"testing"

// brute 四重循环 + 三元组排序去重，是绝对正确的参照物
func brute(nums []int, target int) map[string]bool {
	set := map[string]bool{}
	n := len(nums)
	for a := 0; a < n; a++ {
		for b := a + 1; b < n; b++ {
			for c := b + 1; c < n; c++ {
				for d := c + 1; d < n; d++ {
					if nums[a]+nums[b]+nums[c]+nums[d] == target {
						t := []int{nums[a], nums[b], nums[c], nums[d]}
						sort.Ints(t)
						set[fmt.Sprint(t)] = true
					}
				}
			}
		}
	}
	return set
}

func toSet(res [][]int) (map[string]bool, bool) {
	set := map[string]bool{}
	for _, q := range res {
		if len(q) != 4 {
			return nil, false
		}
		for k := 0; k+1 < 4; k++ {
			if q[k] > q[k+1] {
				return nil, false // 结果未按规范序输出
			}
		}
		key := fmt.Sprint(q)
		if set[key] {
			return nil, false // 重复四元组
		}
		set[key] = true
	}
	return set, true
}

func TestFourSumRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024))
	for iter := 0; iter < 20000; iter++ {
		n := 4 + r.Intn(9) // 4..12，暴力 C(12,4)=495 可跑
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(11) - 5 // 值域 [-5,5]：重复值密集，专逼四层去重
		}
		target := r.Intn(21) - 10

		// 传副本：fourSum 会原地排序，不能让 brute 拿到排好序的数组
		got := fourSum(append([]int(nil), nums...), target)
		want := brute(nums, target)

		set, ok := toSet(got)
		if !ok {
			t.Fatalf("iter=%d nums=%v target=%d 结果不规范或重复: %v", iter, nums, target, got)
		}
		if len(set) != len(want) {
			t.Fatalf("iter=%d nums=%v target=%d 解数不符 got=%d want=%d", iter, nums, target, len(set), len(want))
		}
		for k := range want {
			if !set[k] {
				t.Fatalf("iter=%d nums=%v target=%d 漏解 %s", iter, nums, target, k)
			}
		}
	}
}

	nums := []int{1000000000, 1000000000, 1000000000, 1000000000}
	target := -294967296 // = 4e9 mod 2^32

	got := fourSum(append([]int(nil), nums...), target)
	if len(got) != 0 {
		t.Fatalf("溢出用例：期望无解，实际 %v", got)
	}

	// 再验一个「真的等于」的：4 个 1e9 的和是 4e9，超出 int 范围，
	// 所以这里改用 long target —— 但 LeetCode 的 target 也是 int，
	// 所以这种输入在题面里根本不存在，只能靠 0 和负数构造。下面用 2e9 内的安全例子：
	safe := []int{500000000, 500000000, 500000000, 500000000}

	}
```

## 004.6 复杂度与常见坑

### 004.6.1 复杂度推导

- **排序**：`O(n log n)`。
- **两层固定**：`i` 有 `O(n)` 种、`j` 有 `O(n)` 种 → `O(n²)` 个「固定组合」。
- **内层双指针**：每个固定组合下，`l` 只增、`r` 只减，总移动 ≤ `n` → 单次 `O(n)`。
- **总时间**：`O(n³)`。剪枝不改变最坏界（构造全 0 数组 + `target=0` 时剪枝也不生效，因为上下界都跨过 0）。
- **空间**：`O(1)`（不算结果）；排序栈 `O(log n)`；结果 `O(k)`，`k` 为解的个数。
- **最坏解数**：`k = O(n³)`？不 —— 对固定值域，四元组个数上界是 `O(n³)`（固定三个，第四个由等式确定），但在 `n=200` 且值域 `±1e9` 的随机输入下远小于此。真正的构造型最坏是「大量相同值」：如 200 个 0、`target=0`，答案是 1 个（去重后），但**枚举过程**仍要跑满 `O(n³)`。

### 004.6.2 九个真实踩过的坑

1. **`int` 累加溢出** —— 本题 1 号杀手。官方专门给了 `[1e9,1e9,1e9,1e9], target=-294967296` 这个用例。修法：`long s = (long) nums[i] + ...`。
2. **`long s = nums[i] + nums[j] + nums[l] + nums[r];`** —— 看起来用了 `long`，实际右边先按 `int` 算完再赋值，**溢出已经发生**。这是最隐蔽的一种「假修复」。
3. **`j` 层去重写成 `j > 0`** —— 在 `[1,1,1,3,3,3]` 上会把 `j = i+1` 的合法首候选误杀，导致漏解。必须是 `j > i + 1`。
4. **`i` 层循环边界写成 `i < n`** —— 后面凑不出 4 个数，虽然不会错（内层条件会挡住），但会多跑无意义的循环；写 `i < n - 3` 更清晰。注意 `n < 4` 时 `n - 3` 可能为负，`i < 负数` 在 Java/Go 里都是「不进循环」，天然安全。
5. **命中后只移动 `l` 或只移动 `r`** —— 会在同一对值上反复命中，产生重复解。
6. **`while` 跳重复时漏掉 `l < r`** —— `[0,0,0,0]` 上 `nums[l+1]` 越界 panic。Java 抛 `ArrayIndexOutOfBoundsException`，Go 抛 `panic: index out of range`。
7. **剪枝条件方向写反** —— `min > target` 应 `break`（后面更不可能），`max < target` 应 `continue`（这个 `i` 无解）。写反会**漏解**，且只在特定数据上暴露。
8. **Go 里复用切片追加** —— 在循环外 `buf := make([]int,4)`，每轮改 `buf` 再 `append(res, buf)`，结果所有行都指向同一份数据，最后全变成最后一组。
9. **忘了「结果内部天然有序」这件事** —— 因为 `i < j < l < r` 且数组已排序，输出必是 `a[i] <= a[j] <= a[l] <= a[r]`，**不需要再排**。多写一次 `sort` 只是浪费（但不会错）。

### 004.6.3 面试官最爱追问的三个问题

**Q1：为什么这里一定要用 `long`？三数之和为什么不用？**
> 「因为值域变了。三数之和的元素是 `±10⁵`，三个相加 `±3·10⁵`，远小于 `int` 上界 `2.147·10⁹`，安全。四数之和的元素是 `±10⁹`，四个相加 `±4·10⁹`，**超过 `int` 上界**，会回绕成符号相反的数。后果不是崩溃而是**静默错解** —— 比较方向反了，指针朝错方向走。修法是把 `(long)` 强加在第一个操作数上，让整个表达式在 64 位里算。」

**Q2：能不能用哈希把 O(n³) 优化到 O(n²)？**
> 「在**单个数组**上不行。两个 pair 的哈希要保证四个下标互不相同，而 `(0,1)` 和 `(1,2)` 会共享下标 1，必须额外判冲突，最坏退化成 O(n³) 且实现极复杂；同时 `O(n²)` 的表在 `n=200` 时是 4 万 entry，比 8·10⁶ 次简单加法还贵。但如果换成**四个独立数组**（LC 454），下标天然不冲突，两两分组哈希就能做到 O(n²)/O(n²) —— 所以关键不是『哈希快』，而是『输入结构允不允许分组』。」

**Q3：如果要求 k 数之和（k 由输入给出），你怎么写？**
> 「用递归降维：`ksum(start, k, target)`。`k == 2` 时退化成对撞双指针并收集结果；否则枚举 `i`，去重后递归 `ksum(i+1, k-1, target - nums[i])`。每层入口先做上下界剪枝：最小的 `k` 个数之和 > target 就 `break`，最大的 `k` 个数之和 < target 就 `continue`。复杂度 `O(n^(k-1))`，栈深 `k-2`。这个模板的好处是 k=3、k=4 的代码完全一样，只是参数不同。」
