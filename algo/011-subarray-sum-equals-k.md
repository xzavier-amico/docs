## 011.1 题目

**原题链接**：<https://leetcode.cn/problems/subarray-sum-equals-k/>

### 题意重述（把隐含条件补齐）

给你一个**整数数组** `nums`（注意：可以有负数、可以有 0）和一个整数 `k`，请统计并返回**和恰好等于 `k` 的连续子数组**的个数。

四句话背后藏着四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **子数组必须连续** | 「子数组」的固定含义 | 你把它当子序列（可跳着选）做 → 完全另一道题，答案偏大 |
| **子数组非空** | 子数组的定义（`i <= j`） | `nums=[0], k=0` 时你多算一个长度 0 的「空子数组」→ 返回 2，正确是 1 |
| **要的是个数，不是下标** | 「统计并返回…个数」 | 你返回 `List<int[]>` → 类型错；同时意味着**不需要去重**，重复的窗口各算一次 |
| **元素可以是负数** | `-1000 <= nums[i]` | 你按「全是正数」用了滑动窗口 → 结果**静默错**（见 §011.2 第三条） |
| **前缀和可能相同** | 有负数 + 有 0 | 你用「前缀和 → 下标」的 map → 后来的同值前缀和把前面的覆盖掉，**漏解**；必须存**次数** |

最后一条是全题最容易被看漏的地方：`001` 里 `map` 存的是「值 → 下标」，本题必须换成「值 → **出现次数**」。这一个 value 语义的变化，就是 `001` 到 `011` 的全部跨度。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 2·10⁴` | n 最多 2 万 | 子数组总数 `n(n+1)/2 = 2.0·10⁸`。O(n²) 要跑 2 亿次内层累加，**在 1 秒的判题预算里是赌博**；O(n) 才是本题想要的 |
| `-1000 <= nums[i] <= 1000` | 单元素绝对值 ≤ 1000 | 前缀和最大 `2·10⁴ × 1000 = 2·10⁷`，**int32 装得下**（上限 2.147·10⁹），Java `int` / Go `int` 都安全 |
| `-10⁷ <= k <= 10⁷` | k 也在 int 范围 | `pre - k` 最小到 `-3·10⁷`，仍然安全；**但如果 `nums[i]` 的量级放大到 10⁹，这里必须换 `long`** |
| 答案个数上界 | `n(n+1)/2 = 2·10⁸` | 计数用 `int` 恰好不溢出；如果 n 放大到 10⁵（子数组 5·10⁹ 个），**计数必须用 `long`** |

> 💡 量级 → 算法：`n ≤ 2·10⁴` 是一个**尴尬区间**——O(n²) 的 2 亿次操作「可能过、可能不过」，取决于判题机。面试里看到这种量级，正确姿势是**先把 O(n²) 说出来并标注「临界」，再给 O(n) 并说明它为什么必要**。

### 示例

```
输入：nums = [1, 1, 1], k = 2
输出：2
解释：[1,1]（下标 0..1）与 [1,1]（下标 1..2），两段都合法，各算一次。

输入：nums = [1, 2, 3], k = 3
输出：2
解释：[3]（下标 2..2）与 [1,2]（下标 0..1）。

输入：nums = [1, -1, 0], k = 0
输出：3
解释：[1,-1]、[0]、[1,-1,0]。← 负数与 0 同时出现，这一组就能打死「滑窗」和「前缀和当下标」两种错解。
```

### 我自造的四个反例（写完必须拿它们打一遍）

```text
① [0], k = 0            → 暴露「空子数组被算进答案」（先存后查 / 循环边界写错）
② [1,-1,0], k = 0       → 暴露「有负数还敢用滑窗」和「前缀和只存下标」
③ [1,2,3], k = 3        → 暴露「忘记哨兵 cnt{0:1}」：只有 [3] 会被数到，[1,2] 丢了
④ [-1,-1,1], k = 0      → 暴露「前缀和是负数时用数组当下标」（负下标越界）
```

第 ③ 条是最阴的：漏掉哨兵时，**所有从下标 0 开始的合法子数组都会凭空消失**，而样例 `[1,1,1], k=2` 恰好不覆盖这种情况（它的两个答案都不从 0 开始），于是你在样例上全绿、在隐藏用例上挂掉。

## 011.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的写法是枚举左右端点，内层边扩边累加：

```java
int ans = 0;
for (int i = 0; i < n; i++) {
    int sum = 0;
    for (int j = i; j < n; j++) {
        sum += nums[j];          // 内层边扩边加，省掉第三层循环
        if (sum == k) ans++;
    }
}
```

- 时间 **O(n²)**：内层总次数 `n(n+1)/2`，`n = 2·10⁴` 时是 **`2.0·10⁸` 次**加法与比较。
- 空间 **O(1)**。

它为什么不够，用数字说话：

| n | 内层次数 `n(n+1)/2` | 量级感受 |
| --- | --- | --- |
| 2·10³ | 2.0·10⁶ | 轻松 |
| 2·10⁴（本题上限） | **2.0·10⁸** | 临界，取决于判题机与语言 |
| 10⁵ | 5.0·10⁹ | 必然超时（十亿级操作） |
| 10⁶ | 5.0·10¹¹ | 分钟级，没有讨论价值 |

**注意「内层边扩边加」已经是一次优化了**（把 O(n³) 降到 O(n²)）。很多人以为这就是终点了，因为「子数组本来就是连续的，枚举端点天经地义」。真正的问题是：

> 内层循环在做的事，是「对每个 `i`，重新从 `i` 累加到 `j`」。当 `i` 从 0 变成 1 时，前一次积累的信息被**全部丢弃**了。

### 第二步：卡点在哪

把「区间和」这三个字拆开看。设

```
pre[0] = 0
pre[j] = nums[0] + nums[1] + ... + nums[j-1]      （j = 1..n）
```

那么 `nums[i..j-1]` 的和就是 `pre[j] - pre[i]`。「和等于 k」于是变成：

```
pre[j] - pre[i] = k        ⇔        pre[i] = pre[j] - k        （要求 i < j）
```

**卡点瞬间变了**：原来是「枚举一对端点 (i, j)，判断区间和」，现在是「**对每个 `j`，问『历史前缀和里有多少个等于 `pre[j] - k`』**」。

这和 `001` 是同一个句式：

| | 001 两数之和 | 011 和为 K 的子数组 |
| --- | --- | --- |
| 要满足的等式 | `a + b = target` | `pre[j] - pre[i] = k` |
| 固定一端后的查找目标 | `target - a` | `pre[j] - k` |
| 哈希表的 key | 数值 | 前缀和 |
| 哈希表的 value | 下标（答案要下标） | **出现次数**（答案要个数） |
| 「先查后存」保证什么 | 不和自己配对 | 子数组非空（`i < j`） |

### 第三步：灵感的来源 —— 「边扫边登记前缀和」

和 `001` 一模一样的一步：**答案是一对下标 `(i, j)` 且 `i < j`，所以扫到 `j` 时 `i` 一定已经被扫过了**。于是只要在扫描过程中把「见过的前缀和 → 出现次数」记下来，到 `j` 时一次查表就能知道「有多少个 `i` 满足条件」——注意是**多少个**，不是「有没有」。

```
不变量：进入第 j 轮循环前，cnt 中恰好是 pre[0..j-1] 这 j 个前缀和的出现次数，
        其中 pre[0] = 0 的初始计数为 1（哨兵）
```

这个不变量同时解释了三件事：为什么要有 `cnt{0: 1}`（哨兵就是 `pre[0]`）、为什么是「先查后存」（保证只查到 `i < j`）、为什么 value 是次数（同一个前缀和可能出现多次，每次都是不同的合法 `i`）。

### 另一条路：滑动窗口，以及它为什么在这题里必然错

「连续子数组 + 求和」的组合，第一反应往往是滑动窗口（本部分 015–019 的主角）。但滑窗能成立需要一个**单调性前提**：

> 窗口右端固定时，「窗口是否满足条件」随左端右移**单调变化**（一旦不满足，再往右只会更不满足）。

全是正数时，这个前提成立：窗口右移左端，和一定变小。**本题允许负数，和会忽大忽小**，单调性直接崩塌。看一个具体反例：

```
nums = [1, -1, 1],  k = 1

正确解（暴力）：[1]（下标 0）、[1]（下标 2）、[1,-1,1]（下标 0..2） → 3 个

滑窗式思考：right=0 时 sum=1 恰好等于 k，于是"收缩左端"把 1 移出，
           sum 变成 0，left 前进到 1 —— 而 [1,-1,1] 这个合法答案需要 left 回到 0，
           左指针"只进不退"，于是这个答案永久丢失。
```

> 记住这条判据：**「区间」+「求和」+「有负数」→ 前缀和；「区间」+「求和/计数」+「全非负」→ 滑窗**。这条判据在本批 019（长度最小的子数组）里会再出现一次，那里我会给出滑窗在负数下的**静默错**实例。

## 011.3 原理拆解

### 011.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 三重循环（枚举 i, j, 再求和） | O(n³) | O(1) | 6 行 | 永不选它，纯粹作为「起点」写在纸上 |
| 双重循环（边扩边加） | O(n²) | O(1) | 6 行 | n ≥ 2·10⁴ 时是 2 亿次操作，临界；n ≥ 10⁵ 必挂 |
| 前缀和数组 + 双重循环 | O(n²) | O(n) | 10 行 | 比上一条更差：多了 O(n) 空间，却没变快 |
| **前缀和 + 哈希计数** ✅ | **O(n)** | **O(n)** | **8 行** | 值域极大且内存受限（要外部排序）；前缀和可能到 10¹⁸ 时要用 `map[int64]` |
| 滑动窗口 | —（不成立） | — | — | **本题有负数，单调性不成立**，见 §011.2 末尾 |
| 前缀和 + 有序数组 + 二分 | O(n log n) | O(n) | 20 行 | 每次插入要维护有序（`TreeMap`），常数比哈希大，且同样要处理重复计数 |

**为什么是哈希而不是排序 + 二分**：我们需要「历史前缀和里等于 `pre - k` 的个数」，这是一个**等值计数查询**。排序后确实能二分定位，但每轮都要插入一个元素并保持有序，`TreeMap` 的单次操作是 O(log n)，总 O(n log n)，还多了比较开销。哈希把它降到均摊 O(1)——**这就是 `001` 的核心结论在这里的复用**。

### 011.3.2 为什么这个做法是对的（正确性论证）

**命题**：对每个 `j ∈ [1, n]`，算法累加到 `ans` 上的数值，恰好等于「**以 `j-1` 结尾的、和等于 `k` 的子数组个数**」。

**证明**：以 `j-1` 结尾的子数组形如 `nums[i..j-1]`，`0 ≤ i ≤ j-1`，它与 `i` 一一对应（左端点决定子数组）。而

```
sum(nums[i..j-1]) = pre[j] - pre[i]
```

所以「和等于 k」⇔「`pre[i] = pre[j] - k`」，且要求 `i ≤ j-1`，即 `i < j`。

- **不多算**：第 `j` 轮查表发生在「把 `pre[j]` 登记进 `cnt`」之前（先查后存），所以表里只有 `pre[0..j-1]`，查到的每个 `i` 都满足 `i < j`，对应一个非空子数组。
- **不少算**：若 `i` 满足条件，由不变量它的计数已在表中，`cnt[pre[j] - k]` 一定把它数进去。
- **每个 `j` 相互独立**：不同 `j` 对应的子数组右端点不同，必不相同，故跨轮次不会重复计数。

三句话合起来：累加量 = 以 `j-1` 结尾的合法子数组数；对 `j` 求和即得全部合法子数组数。∎

**再证「哨兵」不可省**：`i = 0` 对应「从下标 0 开始的子数组」，此时 `pre[0] = 0` 必须在表里。`cnt{0: 1}` 不是「技巧」，它是 `pre[0]` 这条**真实存在**的前缀和。把它想成「技巧」的人，往往在别的题里把哨兵漏掉。

### 011.3.3 通用解题思路（可迁移的那一层）

本题是 **「区间聚合问题 → 前缀差 + 等值查找」** 模型的母题：

```
原始问题：数一数有多少个 [i, j] 使 sum(i..j) = k
         ↓ 引入前缀和，把"区间"换成"两点之差"
降维成：  数一数有多少对 (i, j), i < j 使 pre[i] = pre[j] - k
         ↓ 固定 j，识别为"在历史集合里做等值计数"
优化：    哈希表存"前缀和 → 出现次数"，边扫边登记
代价：    O(n) 空间；换来 O(n) 时间
```

**本批（011–019）的统一家谱**——同一族技术，靠「能不能撤销」和「有没有单调性」分家：

| 模型 | 维护的量 | 增量操作 | 能否撤销 | 成立前提 | 章节 |
| --- | --- | --- | --- | --- | --- |
| 前缀和（只读） | `pre[i]` | 累加 | 不需要撤销 | 查询多、更新无 | 013 |
| 前缀和 + 哈希 | 历史前缀和的**计数** | 累加 + 登记 | 不撤销 | **有负数也对** | 011 |
| 差分 | `diff[i]` | 区间两端各改一次 | 天然互为逆运算 | 先批量改、最后一次性还原 | 014 |
| 变长滑窗 | 窗口内的聚合量 | 进窗 `+`、出窗 `-` | **必须能撤销** | 可行性关于窗口长度单调 | 015 / 016 / 019 |
| 定长滑窗 | 窗口内的频率 | 一进一出，成对 | 必须能撤销 | 窗口长度固定 | 017 / 018 |

这张表就是本部分的「总开关」：拿到一道区间题，先问两个问题——**①能不能撤销？（能 → 滑窗）②有没有单调性？（没有 → 前缀和 + 哈希）**。本题答案：能撤销，但**没有单调性**，所以走前缀和 + 哈希。

属于同一模型的题：

| 题 | 等式的形状 | key 的设计 |
| --- | --- | --- |
| [LC 560 和为 K 的子数组](https://leetcode.cn/problems/subarray-sum-equals-k/) | `pre[j] - pre[i] = k` | 前缀和 → 次数 |
| [LC 974 和可被 K 整除的子数组](https://leetcode.cn/problems/subarray-k-divisible-sums/) | `(pre[j] - pre[i]) % k == 0` | **余数** → 次数（负数取模要修正） |
| [LC 525 连续数组](https://leetcode.cn/problems/contiguous-array/) | 0 记 −1，求 `pre[j] == pre[i]` | 前缀和 → **首次下标** |
| [LC 437 路径总和 III](https://leetcode.cn/problems/path-sum-iii/) | 树上的 `pre[down] - pre[up] = k` | 前缀和 → 次数（回溯时撤销） |
| [LC 1248 统计「优美子数组」](https://leetcode.cn/problems/count-number-of-nice-subarrays/) | 奇偶转 0/1，`pre[j] - pre[i] = k` | 前缀和 → 次数 |

**共同点**：都把「区间」压成「两个前缀量之差」，把「枚举左端点」换成「查历史」。

### 011.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**所有**子数组而不只是个数 | 输出规模本身 O(n²) | 哈希存「前缀和 → **下标列表**」，回溯时枚举列表；输出是瓶颈，不可能优于 O(答案规模) |
| 求**最长**的和为 k 的子数组 | 目标从计数变极值 | 哈希存「前缀和 → **第一次出现的下标**」（LC 325），查表时算长度取最大 |
| 数组**全是正数** | 单调性回来了 | 滑窗 O(1) 空间即可；也可以用前缀和 + 二分 |
| 数组**全非负**且要求「和 ≥ k 的最短」 | 见 019 | 变长滑窗 |
| 有负数且要求「和 ≥ k 的最短」 | 滑窗彻底失效 | 前缀和 + **单调双端队列**（LC 862），O(n) |
| 前缀和值域极大（±10¹⁸） | 不能用数组当表 | 必须 `HashMap<Long,Integer>` / `map[int64]int`，且注意 hashCode |
| **数据流**输入，边来边问 | 无法二次遍历 | 哈希方案天然适配：来一个前缀和，先查再登记 |
| 要求**在线**返回「以当前元素结尾的个数」 | 每步都要答案 | 同样适配，每轮查表值即当前答案 |

## 011.4 图解推演

### 011.4.1 前缀和的坐标系

```
nums = [ 1 ,  1 ,  1 ]        k = 2

把"前缀和"看成数轴上的刻度，子数组和 = 两个刻度之间的距离：

      0        1        2        3      ← pre 的值
      │        │        │        │
      ●────────●────────●────────●
    pre[0]   pre[1]   pre[2]   pre[3]
      ↑ 哨兵（空区间，和为 0）

区间 nums[1..2] 的和 = pre[3] - pre[1] = 3 - 1 = 2 = k   ✅
                              └────────┘
                              两个刻度的"距离"

于是"数子数组" = "数有多少对刻度，距离恰好为 k，且右刻度在左刻度右边"
```

### 011.4.2 一遍扫描的执行轨迹

```
nums = [1, 1, 1]   k = 2      cnt = {0: 1}   ans = 0   pre = 0

┌───────┬──────┬───────┬──────────────┬───────────────┬─────┬─────────────────────┐
│ 轮次  │ 元素 │  pre  │ pre-k (要找) │ cnt 命中情况  │ ans │ 本轮后 cnt          │
├───────┼──────┼───────┼──────────────┼───────────────┼─────┼─────────────────────┤
│   0   │  1   │   1   │      -1      │ 无            │  0  │ {0:1, 1:1}          │
│   1   │  1   │   2   │       0      │ 1 次（哨兵）  │  1  │ {0:1, 1:1, 2:1}     │
│   2   │  1   │   3   │       1      │ 1 次          │  2  │ {0:1, 1:1, 2:1, 3:1}│
└───────┴──────┴───────┴──────────────┴───────────────┴─────┴─────────────────────┘
                                                                       结果 = 2 ✅
```

「命中 1 次（哨兵）」这一格就是 `[0..1]` 那个子数组：右端 `pre[2] = 2`，左端 `pre[0] = 0`，距离 2 = k。

### 011.4.3 一次完整的哈希查找过程（放大看）

```
right = 2（元素编号），pre = 3，要找的是 pre - k = 1

        ┌──────────────────────────────────────┐
        │          哈希表 cnt                   │
        ├──────────────┬───────────────────────┤
        │ key = 前缀和 │ value = 出现次数      │
        ├──────────────┼───────────────────────┤
        │      0       │          1            │ ← 哨兵 pre[0]
        │      1       │          1            │ ← 这一格被命中
        │      2       │          1            │
        └──────────────┴───────────────────────┘
                       ↑
                  cnt.get(1) = 1
                       │
                       ↓
              ans += 1   →   ans = 2

  查完之后才登记 cnt[3] = 1        ← 先查后存：本轮不会查到自己
```

### 011.4.4 「先查后存」与「先存后查」的差别（`k = 0` 的反例）

```
nums = [0], k = 0       正确答案 = 1（只有子数组 [0]）

✅ 先查后存
   cnt = {0:1}
   查 cnt[pre - k] = cnt[0] = 1   → ans = 1
   登记 cnt[0] = 2
   → 1  ✅

❌ 先存后查
   cnt = {0:2}（把自己先加进去了）
   查 cnt[0] = 2                 → ans = 2     ← 多算了一个"长度 0 的空子数组"
   → 2  ❌
```

```
┌────────────────── 一句话记住 ──────────────────┐
│ 先查后存 = "先问历史，再写进历史"                │
│          → 历史里永远只有严格更早的 i            │
│ 先存后查 = "先写进历史，再问历史"                │
│          → 自己也在历史里，空窗口被算进来         │
└────────────────────────────────────────────────┘
```

## 011.5 双语言实现

### 011.5.1 Java

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int subarraySum(int[] nums, int k) {
        // key = 某个前缀和，value = 它出现过的次数
        // 不能用"前缀和 -> 下标"：同一个前缀和可能重复出现（有 0 和负数），
        // 用下标会互相覆盖，导致漏解
        Map<Integer, Integer> cnt = new HashMap<>();
        cnt.put(0, 1);                    // 哨兵 pre[0] = 0，代表"空前缀"这一次

        int pre = 0;                      // 当前前缀和 pre[j]
        int ans = 0;

        for (int x : nums) {
            pre += x;

            // 先查：表里只有严格更早的前缀和，所以 i < j，子数组非空
            Integer c = cnt.get(pre - k);
            if (c != null) ans += c;      // 用包装类型接，null 才表示"没有"；0 是合法次数

            // 后存：把本轮前缀和登记进去，供后面的 j 使用
            cnt.merge(pre, 1, Integer::sum);
        }
        return ans;
    }
}
```

`cnt.merge(pre, 1, Integer::sum)` 等价于 `cnt.put(pre, cnt.getOrDefault(pre, 0) + 1)`，但少一次查表。不用 `int[]` 而用 `HashMap` 的原因见 §011.6.2 第 5 条。

### 011.5.2 Go

```go
package main

// subarraySum 统计和恰好为 k 的连续子数组个数。
func subarraySum(nums []int, k int) int {
	// key = 前缀和，value = 出现次数
	// 字面量里直接带上哨兵 0:1，等价于 Java 的 cnt.put(0, 1)
	cnt := map[int]int{0: 1}
	pre, ans := 0, 0

	for _, x := range nums {
		pre += x
		// map 未命中返回零值 0，而"命中 0 次"与"没命中"在这里等价，
		// 所以不需要逗号-ok 语法：加 0 次和没加是一样的
		ans += cnt[pre-k]
		cnt[pre]++
	}
	return ans
}
```

### 011.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 「没有这个 key」的表示 | `get()` 返回 `null`，必须用 `Integer` 接收 | `cnt[k]` 返回零值 `0` | **Go 这里更简洁**：计数的零值 0 天然正确，不需要 `ok`；而 001 要下标，就必须用 `ok` |
| 计数的自增 | `merge(k, 1, Integer::sum)` | `cnt[k]++` | Go 一行搞定；Java 若写 `getOrDefault` 会多一次查表 |
| map 字面量 | 没有字面量，得 `new` + `put` | `map[int]int{0: 1}` | Go 的哨兵初始化更直观 |
| 装箱 | `Map<Integer,Integer>`：key/value 各一个对象 | `map[int]int` 无装箱 | n=2·10⁴ 无感；n=10⁷ 时 Go 明显更快、GC 压力更小 |
| 整数宽度 | `int` 恒 32 位 | `int` 在 64 位平台是 64 位 | 本题都安全（前缀和 ≤ 2·10⁷）；若 `nums[i]` 到 10⁹ 则 Java 必须换 `long`，Go 在 64 位机上仍安全——**这种「平台相关的安全」不可依赖**，跨平台要写 `int64` |
| 迭代写法 | `for (int x : nums)` | `for _, x := range nums` | 等价；Go 不需要下标时用 `_` 明确丢弃 |

### 011.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举左端点，内层边扩边加
func brute(nums []int, k int) int {
	c := 0
	for i := range nums {
		s := 0
		for j := i; j < len(nums); j++ {
			s += nums[j]
			if s == k {
				c++
			}
		}
	}
	return c
}

func TestSubarraySumRandom(t *testing.T) {
	// 先钉住三个手工反例，防止"随机全绿但边界全错"
	fixed := []struct {
		nums []int
		k    int
		want int
	}{
		{[]int{1, 1, 1}, 2, 2},
		{[]int{1, -1, 0}, 0, 3},   // 负数 + 0：滑窗会错、前缀和只存下标会错
		{[]int{1, 2, 3}, 3, 2},    // 漏哨兵时只剩 1 个答案
		{[]int{-1, -1, 1}, 0, 1},  // 负数前缀和：不能用数组当下标
		{[]int{0}, 0, 1},          // 空子数组陷阱
	}
	for _, f := range fixed {
		if got := subarraySum(f.nums, f.k); got != f.want {
			t.Fatalf("nums=%v k=%d got=%d want=%d", f.nums, f.k, got, f.want)
		}
	}

	r := rand.New(rand.NewSource(11))
	for iter := 0; iter < 30000; iter++ {
		n := r.Intn(12)                 // 故意只造短数组：短数组里重复前缀和更密集
		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(11) - 5    // 值域 [-5,5]，大量 0 与负数
		}
		k := r.Intn(11) - 5
		if got, want := subarraySum(nums, k), brute(nums, k); got != want {
			t.Fatalf("iter=%d nums=%v k=%d got=%d want=%d", iter, nums, k, got, want)
		}
	}
}
```

> **为什么值域要设成 `[-5, 5]`、长度只到 11**：前缀和重复得越频繁，「value 必须存次数」这个点才越容易暴露。3 万次随机里，`nums` 中 0 的密度约为 1/11，几乎每条都含重复前缀和。**随机测试不是覆盖正常情况，是高频制造边界。**

## 011.6 复杂度与常见坑

### 011.6.1 复杂度推导

- **时间 O(n)**：外层循环恰好 `n` 轮，每轮做「一次哈希查 + 一次哈希写」，均摊 O(1)。
  - 为什么是均摊：哈希冲突时单次可能退化。Java 8 之后桶内超过 8 个节点转红黑树，最坏 O(log n)；Go 的 map 用开放寻址 + 溢出桶，最坏也是一个桶拉长。
  - **什么时候退化到 O(n²)**：所有 key 落进同一个桶（哈希函数被攻击，或前缀和全是同一个值且哈希函数极差）。前缀和的取值是 `[-2·10⁷, 2·10⁷]` 的整数，Java 的 `Integer.hashCode()` 就是值本身，冲突分布均匀，实际不可构造。
- **空间 O(n)**：最坏情况下 `n+1` 个前缀和互不相同，表里存 `n+1` 项。前缀和的**不同取值个数**才是实际空间，最坏 `n+1`（全部互异），最好 1（全 0）。

### 011.6.2 八个真实踩过的坑

1. **忘记 `cnt{0: 1}`** —— 所有「从下标 0 开始」的合法子数组全部丢失。`[1,2,3], k=3` 会返回 1（只剩 `[3]`）而不是 2。
2. **先存后查** —— `k = 0` 时把「长度 0 的空子数组」算进答案；`[0], k=0` 返回 2。修法：把 `cnt[pre]++` 放到查表之后。
3. **value 存下标而不是次数** —— 有 0 或负数时前缀和会重复，`map` 里后来的覆盖前面的，答案偏小且**不报错**。这是本题最隐蔽的错误。
4. **以为可以用滑动窗口** —— 有负数时单调性崩塌，见 §011.2 末尾的 `[1,-1,1]`。滑窗错得**毫无征兆**，样例可能还全过。
5. **用数组代替哈希** —— 前缀和是负数（`[-1,-1,1]`）或者到 10⁷ 量级，数组开不下也索引不了。值域小且非负时可以考虑「前缀和 + 偏移量」的数组，但偏移量本身要 `2·10⁷` 个 `int`（80 MB），**不如哈希**。
6. **`pre - k` 溢出** —— 本题约束下 `pre ∈ [-2·10⁷, 2·10⁷]`、`k ∈ [-10⁷, 10⁷]`，最坏 `-3·10⁷`，安全。若把 `nums[i]` 放大到 `10⁹`（n=2·10⁴ 时前缀和到 2·10¹³），Java `int` 直接溢出成错误的正数，**静默错**。生产代码用 `long`。
7. **计数用 `int` 但 n 被放大** —— 本题上界 `2·10⁸` 恰好塞进 `int`；如果 n 变成 10⁵，答案是 5·10⁹，`int` 溢出成负数。写 `long` 是更安全的习惯，代价只是 LeetCode 上多一次强转。
8. **`Integer` 用 `==` 比较** —— `cnt.get(pre - k) == 0` 在值超出 `[-128,127]` 缓存范围时恒为 false。要么拆箱成 `int`，要么 `c != null` 判存在。

### 011.6.3 面试官最爱追问的四个问题

**Q1：为什么不能用滑动窗口？**
> 「滑动窗口的正确性依赖单调性：右端固定时，窗口和随左端右移单调不增，所以『一旦不满足就可以停』。本题允许负数，移出一个负数会让窗口和**变大**，单调性没了。反例 `nums=[1,-1,1], k=1`：右端扫到下标 2 时窗口和才第一次到 1，但合法答案 `[1,-1,1]` 需要左端停在 0，而左指针已经因为之前的收缩不可逆地前进了。有负数时只能用前缀和 + 哈希。」

**Q2：`cnt` 的 value 为什么必须是次数，不能是下标？**
> 「因为有 0 和负数，同一个前缀和可能出现多次。比如 `nums=[0,0,0], k=0`，前缀和序列是 `0,0,0,0`，`pre[0]` 出现了 4 次。存下标只会留下最后一次，而每一个 `i` 都对应一个不同的合法左端点。要个数就存次数，要具体下标就存**下标列表**。」

**Q3：如果要返回最长的那一段，改哪里？**
> 「哈希的 value 从『次数』改成『**第一次出现的下标**』，并且查表命中后不再累加，而是算 `j - firstIndex` 取最大值。关键点：只能存第一次出现的下标，因为同一个前缀和出现多次时，最早的那次能得到最长的区间。这就是 LC 325。反过来，如果要求最短，就存**最后一次**出现的下标，且必须边扫边更新。」

**Q4：空间能压到 O(1) 吗？**
> 「一般情况下不能——你必须记住历史前缀和的分布才能判断『有多少个 i 满足条件』。两个例外：① 数组全非负，此时前缀和单调，可以换成滑窗或双指针，空间 O(1)；② 前缀和值域很小（比如 `|nums[i]| ≤ 1`），可以用定长数组当哈希，空间 O(值域) 仍是 O(n) 级，但常数极小。」
