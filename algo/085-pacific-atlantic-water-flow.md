## 085.1 题目

**原题链接**：<https://leetcode.cn/problems/pacific-atlantic-water-flow/>

### 题意重述（把隐含条件补齐）

给你一个 `m × n` 的整数矩阵 `heights`，`heights[i][j]` 是格子 `(i, j)` 的高度。

- **太平洋**在矩阵的**上边**和**左边**；**大西洋**在**下边**和**右边**。
- 水可以从一个格子流到**上下左右相邻**的格子，条件是**目标格的高度 ≤ 当前格的高度**（水往低处流，等高也能流）。
- 请找出**所有**「水既能流到太平洋、又能流到大西洋」的格子坐标，顺序不限。

这里有三个必须自己补出来的隐含条件：

| 隐含条件 | 出处 | 读漏了会怎样 |
| --- | --- | --- |
| **等高也能流（`≥` 而不是 `>`）** | 「water can flow ... to ... with height **less than or equal to**」 | 用严格大于，平台区（全等高）会几乎没有答案 |
| **角落格子同时属于两片洋** | 上边/左边是太平洋，下边/右边是大西洋 | `(0,0)` 紧邻太平洋；`(m-1,n-1)` 紧邻大西洋；**1×1 时这一格同时紧邻两片洋** |
| **「能流到」是传递可达，不是一步** | 「flow to both oceans」 | 只检查相邻格是不是边界，会把内陆格全部漏掉 |
| **流是有方向的（高 → 低）** | 「flow from a cell to ... less than or equal」 | 把图当无向图 → 任何连通的区域都会全被算进去，答案严重偏大 |
| **返回坐标列表，顺序任意** | 「in any order」 | 不必排序，省掉一次无用的排序 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `m == heights.length` | 1 ≤ m ≤ 200 | 总格数 `N = m·n ≤ 4·10⁴` |
| `n == heights[i].length` | 1 ≤ n ≤ 200 | 同上 |
| `0 ≤ heights[i][j] ≤ 10⁵` | 高度非负、可比大小 | 可以用「高度比较」当边条件；不必对高度离散化 |
| 时间限制约 1 s | — | `O(N) = 4·10⁴` 免费；`O(N²) = 1.6·10⁹` 超时边缘 |

> 💡 **量级 → 算法**：`N ≤ 4·10⁴`。这题的正确解法是 **2 次 `O(N)` 搜索**（一片洋一次），不是 `N` 次搜索。
> **看到「每个格子都要回答一个『能不能到达某处』」时，第一反应应该是「反过来从目标出发搜一次」，而不是「对每个格子搜一次」。**

### 示例

```text
输入：heights = [
  [1,2,2,3,5],
  [3,2,3,4,4],
  [2,4,5,3,1],
  [6,7,1,4,5],
  [5,1,1,2,4]
]
输出：[[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
（顺序不限）

逐个解释这 7 个格子为什么合法：
(0,4)=5  贴右边界 → 直接进大西洋；沿 5→5? 不，沿 (0,4)=5 → (0,3)=3 → (0,2)=2 → (0,1)=2 → (0,0)=1 → 上边界/左边界 → 太平洋 ✓
(1,3)=4  贴不到边界，但它能 (1,3)=4 → (0,3)=3 → ... → 太平洋；也能 → (1,4)=4 → 右边界 → 大西洋 ✓
(2,2)=5  中间最高点：向上 5→3→2→1 到太平洋，向下 5→1→... 到 (4,x) 下边界 ✓
(3,0)=6  贴左边界 → 太平洋；沿 6→5(4,0)→... 到 (4,0) 下边界 ✓
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① heights = [[1]]                → 1×1 的格子同时贴着上边与左边（太平洋）和下边与右边（大西洋）
                                   答案必须是 [[0,0]]，不能是空

② heights = [[1,1,1]]            → 单行：每一格都贴上边（太平洋）和下边（大西洋）
                                   而且等高可以流动 → 答案必须是三格全在

③ heights = [[3,3,3],
             [3,3,3],

④ heights = [[1,2,3],
             [8,9,4],
             [7,6,5]]            → 中间是山峰：所有水都往低处流到边界，

```

②③ 是检验 `≥` 与 `>` 的分水岭：写成严格大于时，② 只剩 `[0,0]` 与 `[0,2]`，③ 只剩四个角。

## 085.2 从暴力到最优：第一个念头为什么错

### 第一个念头：对每个格子，正向模拟一次水流

最直白的写法：对每个格子 `(i, j)` 做一次 DFS/BFS，看水能不能流到上/左边界（太平洋）和下/右边界（大西洋）。

```java
// 出生版：每个格子独立搜索
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (canReachPacific(i, j) && canReachAtlantic(i, j))   // 每次 O(N)
            res.add(Arrays.asList(i, j));
```

- 时间 **O(N²)**：每次搜索都是 `O(N)`，一共 `N` 次。
- 代入 `N = 4·10⁴`：`1.6·10⁹` 次格子访问 → 落在 1~2 秒的模糊区间，**很可能 TLE**。
- 逻辑上没错，但对「同一片高地」的搜索被重复了成千上万次——一片连通的斜坡会被它上面的每个格子各走一遍。

### 卡点在哪：方向想反了

把问题翻译成一句话：

> **对每个顶点 `v`，问「在流图里，`v` 能不能到达汇点集合 `P`（太平洋）和 `A`（大西洋）」。**

这是一个**「多源到单汇」的可达性**问题，可以写成 `N` 次「单源可达」；也可以反过来，写成 **2 次「多源可达」**：

```text
正向： N 个源 × 1 个汇   → 每条路径被算 N 次
反向： 1 个汇 × 多源      → 从汇出发，一次标出所有能到达它的格子
```

关键的一步是**把边反过来**：

| 正向流图 `G` | 反向流图 `Gᵀ` |
| --- | --- |
| 边 `u → v` 存在 ⟺ `u`、`v` 四邻接且 `height(u) ≥ height(v)` | 边 `v → u` 存在 ⟺ `u`、`v` 四邻接且 `height(u) ≥ height(v)` |
| 「水从 `u` 流到 `v`」 | 「从 `v` 出发能走到所有『水能流到 `v`』的格子」 |

在 `Gᵀ` 上，「哪些格子能流到太平洋」就变成了「**从太平洋的边界格出发，在 `Gᵀ` 上能走到哪些格子**」——一次 DFS/BFS 就能标出全部。

### 灵感的来源：让「水往上爬」

反向搜索的物理直觉很好记：**假设水会往高处爬，从海洋出发向内陆倒灌**。

```
正向：水从格子往低处流          → 每个格子各流失一次
反向：水从海洋往高处"爬"        → 一次倒灌就覆盖所有能流进这片海的格子
```

具体的反向扩展条件只有一处变化：

```text
正向：从 (i,j) 能走到 (ni,nj)   ⟺  heights[ni][nj] <= heights[i][j]
反向：从 (i,j) 能走到 (ni,nj)   ⟺  heights[ni][nj] >= heights[i][j]     ← 只把 <= 换成了 >=
```

**其余代码与 082 的洪水填充完全相同。** 这就是「识别模型」的威力：换了语义，骨架不动。

### 不变量

```
不变量 I：对每片洋 O，反向搜索结束时，
         seen_O[i][j] == true ⟺ 存在一条从 (i,j) 到洋 O 的、每步高度不增的路径。
```

## 085.3 原理拆解

### 085.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐格正向搜索（暴力） | O(N²) | O(N) | 40 行 | `N ≥ 10⁴` 起就贴到超时线；本题 `1.6·10⁹` |
| **反向 DFS（两趟 + 取交集）** ✅ | **O(N)** | O(N) 栈 + 2·O(N) 标记 | **25 行** | `200×200` 全等高时递归深度 `4·10⁴` → Java 可能爆栈 |
| **反向 BFS（两趟 + 取交集）** ✅（生产首选） | **O(N)** | O(N) 队列 | 35 行 | 需要坐标队列，行数多一些 |
| 反向 BFS + **一个** `byte` 位掩码数组 | O(N) | O(N) 一个字节/格 | 35 行 | 没什么缺点，空间省一半，可读性稍差一点 |
| 按高度降序 + 并查集 | O(N log N) | O(N) | 55 行 | 多一个排序，只在需要「动态加点」时才划算 |

**为什么「两个 `boolean` 数组取交集」是最稳的写法**：

- 两片洋的搜索**完全同构**，只换起点集合与目标数组，可以抽成一个函数 `dfs(heights, i, j, seen)`。
- 交集在最后一步用一次扫描完成，`O(N)`，不会引入额外复杂度。
- 换成位掩码（`1` = 太平洋，`2` = 大西洋，`3` = 两洋）只是把两个数组压成一个，逻辑等价。

```
                    ┌────── 输入 heights ──────┐
                    │                          │
        ┌───────────▼───────────┐   ┌──────────▼────────────┐
        │ 从太平洋边界反向灌水    │   │ 从大西洋边界反向灌水    │
        │ 源：第 0 行 + 第 0 列   │   │ 源：第 m-1 行 + 第 n-1 列│
        │ 条件：邻居高度 ≥ 当前   │   │ 条件：邻居高度 ≥ 当前   │
        └───────────┬───────────┘   └──────────┬────────────┘
                    │                          │
              seenP[i][j]                 seenA[i][j]
                    └──────────┬───────────────┘
                               ▼
                  答案 = { (i,j) : seenP && seenA }
```

### 085.3.2 为什么这个做法是对的（正确性论证）

**先定义清楚两件事：**

> - 正向流图 `G`：顶点是所有格子；有向边 `u → v` ⟺ `u`、`v` 四邻接且 `heights[u] ≥ heights[v]`。
> - 「`c` 能流到太平洋」⟺ 在 `G` 中存在一条从 `c` 到某片太平洋边界格（第 0 行或第 0 列）的路径。

**引理（反向搜索标记的集合 = 能流到该洋的集合）。** 设 `S` 为该洋的边界格集合，`R` 为在 `Gᵀ` 上从 `S` 出发能到达的顶点集合，`F` 为在 `G` 上能到达 `S` 中某点的顶点集合。则 `R = F`。

- 若 `v ∈ F`，则存在 `G` 上的路径 `v = c₀ → c₁ → … → c_k ∈ S`。把每条边反向，得到 `Gᵀ` 上的路径 `c_k → … → c₁ → v`，其起点 `c_k ∈ S`。因此 `v ∈ R`。
- 若 `v ∈ R`，则存在 `Gᵀ` 上的路径 `s = c₀ → c₁ → … → c_k = v`，`s ∈ S`。把每条边反向，得到 `G` 上的路径 `v = c_k → … → c₀ = s ∈ S`，因此 `v ∈ F`。∎

> **这个引理是本章的全部内容**：「能流到汇点」与「从汇点反向可达」在有向图上是一回事，因为「把路径反向」不改变它的存在性。**注意它只对路径成立，对最短路长度之类的量不成立**（反向图的距离数值与正向相同，但意义是「离海洋多远」）。

**定理（输出正确）**：算法输出的集合恰好是 `F_pacific ∩ F_atlantic`。由定义，这正是「水既能流到太平洋又能流到大西洋」的格子集合。∎

**边界处理的正确性**（这一步最容易漏）：源集合必须**包含**四边上所有格子：

- 太平洋源 = `{(0, j)} ∪ {(i, 0)}`；
- 大西洋源 = `{(m-1, j)} ∪ {(i, n-1)}`。

若漏掉 `n == 1` 或 `m == 1` 的情形，1×1 与单行/单列的答案会错。用「两趟循环 + 同一格重复入队无害（`seen` 已标记）」的写法可以天然覆盖所有情况，不需要特判角。

**终止性**：每个格子在一趟搜索里最多被标记一次，两趟共 `2N` 次标记，有限。∎

### 085.3.3 通用解题思路（可迁移的那一层）

三要素在本题有一个重要变化：**边是有向的**。

| 要素 | 本题的答案 | 与 082–084 的差异 |
| --- | --- | --- |
| **顶点（vertex）** | 每个格子 `(i, j)` | 一致：网格题顶点永远是格子 |
| **边（edge）** | **有向**边 `u → v` ⟺ 四邻接且 `heights[u] ≥ heights[v]` | **第一次出现有向边**。082–084 的边都是无向的（互为邻居），所以「连通块」有意义；这里连通块没有意义，有意义的是「能不能流到某处」 |
| **状态（state）** | 每格两位：`bit0` = 能流入太平洋，`bit1` = 能流入大西洋 | 状态从「属于哪个分量」变成「**属于哪些汇点的反向可达集**」——本质是「多标签传播」 |

抽象成模型：

```
有向图上的反向可达模型（Reverse Reachability on Digraph）
  ① 正向边：u → v（这里是"水从 u 流到 v"）
  ② 反向边：v → u，从汇点集合出发做一次多源搜索
  ③ 需要多个汇点的性质时：跑多趟、每趟记一个标签；答案 = 标签的交集 / 并集 / 计数
```

这个模型的三种常见问法：

| 问法 | 运算 | 例子 |
| --- | --- | --- |
| 能到 `A` **且** 能到 `B` | 交集 | 本题（太平洋 ∩ 大西洋） |
| 能到 `A` **或** 能到 `B` | 并集 | 「至少能流进一片洋」 |
| 到最近的 `A` 的距离 | 多源 BFS + 层数 | [LC 542 01 矩阵](https://leetcode.cn/problems/01-matrix/) |

**状态用位掩码而不是多个布尔数组**，是个值得记住的小技巧：

```
state[i][j] = 0  → 两洋都到不了
            = 1  → 只能到太平洋
            = 2  → 只能到大西洋
            = 3  → 两洋都能到   ← 答案
用 OR 累积：state[i][j] |= 1（太平洋那趟）;  state[i][j] |= 2（大西洋那趟）
最后判 state[i][j] == 3
```

### 085.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 有**三片洋** | 标签数 3 | 位掩码扩到 3 位（`1/2/4`），跑三趟，答案判 `== 7` |
| 要求输出**一条可行路径** | 需要父指针 | 反向 BFS 时记 `parent`，最后从格子沿 `parent` 链走回海洋并反转（等价于正向路径） |
| 要求输出**离海洋的距离** | 变成最短路 | 反向 BFS 分层计数：`dist` 就是「水从这里流到该洋所需的最小步数」 |
| 允许**对角**流动 | 边定义变化 | 方向表 4 → 8，其余不动 |
| 要求**严格大于**才能流 | 边条件变化 | 把反向条件里的 `>=` 改成 `>`；`②`、`③` 两个反例的答案会从「全在」变成「很少」 |
| 网格**大到装不下** | 不能一次全图 | 按行分块，块间只通过边界行传递「可达标签」，做两趟前向/后向传播（本质是把 BFS 变成扫描线 + 位掩码） |

### 085.4.2 正向 vs 反向的搜索次数

```text

──────────────────────────────────         ─────────────────────────────────
  ○ ──→ ○ ──→ 洋                           洋 ←── ○ ←── ○ ←── ○
  ○ ──→ ○ ──→ 洋     N 次搜索               洋 ←── ○ ←── ○   2 次搜索
  ○ ──→ ○ ──→ 洋     O(N²)                  洋 ←── ○    O(N)

  N = 4·10⁴ → 1.6·10⁹ 次 ❌               N = 4·10⁴ → 8·10⁴ 次 ✅
```

## 085.5 双语言实现

### 085.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    private int m, n;
    private static final int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    public List<List<Integer>> pacificAtlantic(int[][] heights) {
        List<List<Integer>> res = new ArrayList<>();
        if (heights == null || heights.length == 0 || heights[0].length == 0) return res;

        m = heights.length;
        n = heights[0].length;

        // 两张独立的标记表：不能复用同一个，否则第二趟会被第一趟的结论污染
        boolean[][] pac = new boolean[m][n];
        boolean[][] atl = new boolean[m][n];

        // 太平洋：第 0 行 + 第 0 列；大西洋：第 m-1 行 + 第 n-1 列
        // 两趟循环同时跑，天然覆盖 m == 1 / n == 1 的情形（此时同一格既是两洋的源）
        for (int i = 0; i < m; i++) {
            dfs(heights, i, 0, pac);       // 左边界 → 太平洋
            dfs(heights, i, n - 1, atl);   // 右边界 → 大西洋
        }
        for (int j = 0; j < n; j++) {
            dfs(heights, 0, j, pac);       // 上边界 → 太平洋
            dfs(heights, m - 1, j, atl);   // 下边界 → 大西洋
        }

        // 交集：一次全图扫描，顺序天然是「按行主序」，题目说顺序不限
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (pac[i][j] && atl[i][j]) {
                    res.add(Arrays.asList(i, j));
                }
            }
        }
        return res;
    }

    // 反向 DFS：只往「高度不低于当前格」的邻居走 —— 这正是把正向的"往低处流"翻过来
    private void dfs(int[][] h, int i, int j, boolean[][] seen) {
        if (seen[i][j]) return;
        seen[i][j] = true;

        for (int[] d : DIRS) {
            int ni = i + d[0], nj = j + d[1];
            if (ni < 0 || ni >= m || nj < 0 || nj >= n) continue;   // 越界
            if (seen[ni][nj]) continue;                             // 已标记
            if (h[ni][nj] < h[i][j]) continue;   // 关键：邻居更低 → 水不可能从邻居流过来
            dfs(h, ni, nj, seen);
        }
    }
}
```

### 085.5.2 Go

```go
package main

func pacificAtlantic(heights [][]int) [][]int {
	res := [][]int{}
	if len(heights) == 0 || len(heights[0]) == 0 {
		return res
	}
	m, n := len(heights), len(heights[0])

	pac := make([][]bool, m)
	atl := make([][]bool, m)
	for i := 0; i < m; i++ {
		pac[i] = make([]bool, n)
		atl[i] = make([]bool, n)
	}

	// 与 Java 完全同构的递归 DFS。Go 里闭包无法自引用，必须先 var 声明再赋值
	var dfs func(i, j int, seen [][]bool)
	dfs = func(i, j int, seen [][]bool) {
		if seen[i][j] {
			return
		}
		seen[i][j] = true
		for _, d := range [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}} {
			ni, nj := i+d[0], j+d[1]
			if ni < 0 || ni >= m || nj < 0 || nj >= n {
				continue // 越界
			}
			if seen[ni][nj] {
				continue // 已标记
			}
			if heights[ni][nj] < heights[i][j] {
				continue // 邻居更低：水不可能从它流过来
			}
			dfs(ni, nj, seen)
		}
	}

	for i := 0; i < m; i++ {
		dfs(i, 0, pac)     // 左边界 → 太平洋
		dfs(i, n-1, atl)   // 右边界 → 大西洋
	}
	for j := 0; j < n; j++ {
		dfs(0, j, pac)     // 上边界 → 太平洋
		dfs(m-1, j, atl)   // 下边界 → 大西洋
	}

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if pac[i][j] && atl[i][j] {
				res = append(res, []int{i, j})
			}
		}
	}
	return res
}
```

### 085.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维布尔表 | `boolean[m][n]`（自动初始化为 `false`） | `[][]bool` 是**切片**，`make` 后每个元素是零值 `false`，但**外层**只有引用 | Go 必须逐行 `make`，写成 `make([][]bool, m)` 而忘了内层 `make` 会得到 `nil` 行 → 赋值 panic。这是 Go 网格题第一大坑 |
| 返回结构 | `List<List<Integer>>`，用 `Arrays.asList(i, j)` | `[][]int`，用 `append(res, []int{i, j})` | Java 的 `Arrays.asList` 返回定长列表，**不能 add** ——本题只读，安全 |
| 空结果 | `new ArrayList<>()` | `[][]int{}`（**不要**用 `nil`） | LeetCode 两者都接受；显式空切片在 JSON 序列化时是 `[]` 而不是 `null`，更安全 |
| 搜索方式 | 递归 `dfs`（最深 `4·10⁴`，**本题要小心爆栈**） | 递归 `dfs`（goroutine 栈自动扩容，深递归通常安全） | 写法同构；但在 Java 上跑 `200×200` 全等高平台会 `StackOverflowError`，生产版请把两边都换成队列 |
| 方向数组 | `int[][] DIRS`（堆上数组，for-each 有迭代开销） | `[4][2]int{{...}}` 字面量在栈上 | Go 的数组字面量可以被编译器优化成常量表，比切片更省 |

## 085.6 复杂度与常见坑

### 085.6.1 复杂度推导

- **时间 O(mn)**：每趟搜索中每个格子最多被标记一次、出队一次，每次检查 4 个邻居，所以一趟是 `O(4mn + mn)`；两趟仍是 `O(mn)`（常数 2）。最后的交集扫描 `O(mn)`。合计 `O(mn)`。
- **空间 O(mn)**：两张 `m×n` 布尔表（各 1 bit 或 1 byte）+ 队列/栈最坏 `O(mn)`。
  - 用位掩码可以压成一张（`3` 个取值），空间减半。
  - 递归栈在最坏情形（全等高平台）等于 `mn = 4·10⁴` 层。
- **与暴力的差距**：暴力是 `N` 次搜索，每次 `O(N)`；这里只有 **2** 次。**从 `N` 降到常数，是「反向」带来的全部收益。**

### 085.6.2 八个真实踩过的坑

1. **反向条件写成 `h[ni][nj] <= h[i][j]`**：这等于在正向图上搜「能流到哪」，方向又倒了。正确是 `>=`（邻居不低于当前才行）。
2. **两趟共用一张 `seen`**：第二趟一开始发现「到处都是 `true`」，答案直接变成全集。必须两张表。
3. **源集合只取两个角**：和 084 一样的老毛病。这题的源是**两条完整的边**（上边 + 左边算一片洋的两条边）。
4. **递归爆栈**：`m = n = 200` 且全等高时，反向 DFS 的深度可达 `4·10⁴`，Java 默认线程栈会 `StackOverflowError`。**本题的 `200` 就是照着递归上限设计的**，务必用 BFS 或显式栈。
5. **`m == 1` 或 `n == 1` 时漏源**：单行输入 `[[1,1,1]]` 里每个格子既贴上边（太平洋）又贴下边（大西洋），答案必须是全部格子。如果只写「上边界一个源、下边界一个源」而用 `i` 循环漏掉同一格，就会少标。
6. **把 1×1 判成空**：`[[1]]` 的答案是 `[[0,0]]`。判空逻辑写成「必须先流到左边界再流到下边界」这类多步条件就会漏掉它。
7. **返回值顺序问题**：题目说顺序不限，但如果你自己写对拍，**必须把两个集合排序后比较**，不能直接比较列表——否则会得到大量「假失败」。
8. **Go 里内层切片没 `make`**：`pac := make([][]bool, m)` 之后直接 `pac[i][j] = true` 会 panic（`nil` 切片）。必须逐行 `make([]bool, n)`。

BFS 版本的 Java 骨架（把上面第 4 条的风险直接消掉）：

```java
class SolutionBFS {
    public java.util.List<java.util.List<Integer>> pacificAtlantic(int[][] heights) {
        int m = heights.length, n = heights[0].length;
        boolean[][] pac = new boolean[m][n], atl = new boolean[m][n];
        int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

        java.util.ArrayDeque<int[]> q = new java.util.ArrayDeque<>();
        // 两片洋各自初始化源，共 2·(2m + 2n) 次入队尝试
        for (int i = 0; i < m; i++) { mark(q, pac, i, 0); mark(q, atl, i, n - 1); }
        for (int j = 0; j < n; j++) { mark(q, pac, 0, j); mark(q, atl, m - 1, j); }

        spread(heights, q, pac, DIRS, m, n);
        spread(heights, q, atl, DIRS, m, n);

        java.util.List<java.util.List<Integer>> res = new java.util.ArrayList<>();
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (pac[i][j] && atl[i][j]) res.add(java.util.Arrays.asList(i, j));
        return res;
    }

    private void mark(java.util.ArrayDeque<int[]> q, boolean[][] seen, int i, int j) {
        if (!seen[i][j]) { seen[i][j] = true; q.add(new int[]{i, j}); }
    }

    private void spread(int[][] h, java.util.ArrayDeque<int[]> q, boolean[][] seen, int[][] dirs, int m, int n) {
        while (!q.isEmpty()) {
            int[] cur = q.poll();
            for (int[] d : dirs) {
                int ni = cur[0] + d[0], nj = cur[1] + d[1];
                if (ni < 0 || ni >= m || nj < 0 || nj >= n || seen[ni][nj]) continue;
                if (h[ni][nj] < h[cur[0]][cur[1]]) continue;
                seen[ni][nj] = true;
                q.add(new int[]{ni, nj});
            }
        }
    }
}
```

### 085.6.3 面试官最爱追问的三个问题

**Q1：为什么要反向搜索？正着做错在哪？**
> 「正着做不是错，是慢。正向的问题是『每个格子都要问一次能不能到海洋』，而『能到海洋』是个可达性谓词，`N` 个格子就要 `N` 次 `O(N)` 的搜索，`O(N²)`。反向之后，问题变成『从海洋出发能到哪些格子』——一次搜索就能回答**所有**格子。有向图里『`v` 能到 `s`』和『`s` 在反向图上能到 `v`』等价，因为路径可以整体反向。所以我把 `N` 次搜索压成了 2 次。」

**Q2：怎么保证两片洋都考虑到？**
> 「跑两趟，各用一张独立的 `boolean` 表，最后取交集。不能用一张表，否则第二趟会被第一趟的标记污染。也可以用位掩码：太平洋那趟 `|= 1`，大西洋那趟 `|= 2`，最后判 `== 3`，省一半空间。**关键点是源集合要完整**：太平洋的源是第 0 行**和**第 0 列两条边上的所有格子，不是两个角。」

**Q3：如果高度改成「必须严格下降」才能流，代码怎么改？答案会有什么变化？**
> 「只改一处：反向条件从 `h[ni][nj] >= h[i][j]` 变成 `h[ni][nj] > h[i][j]`。答案会急剧变小——所有等高平台内部不再连通，只有严格递减的斜坡才会被标记。极端例子：全等高矩阵，原本是『全部格子都在答案里』，改成严格下降后答案是空。这也说明**这题对 `>=` / `>` 极其敏感，面试里必须主动确认**。」
