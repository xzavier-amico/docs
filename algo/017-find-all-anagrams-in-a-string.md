## 017.1 题目

**原题链接**：<https://leetcode.cn/problems/find-all-anagrams-in-a-string/>

### 题意重述（把隐含条件补齐）

给你两个字符串 `s` 和 `p`，找出 `s` 中**所有**是 `p` 的**字母异位词**的子串，返回这些子串的**起始索引**列表（顺序不限，按扫描顺序自然递增）。

「字母异位词（anagram）」这个词必须翻译准确，它是全题的支点：

> **两个字符串是字母异位词 ⇔ 长度相同，且每种字符出现的次数相同。**
> 注意是「每种字符的**计数**」，不是「用到的字符集合」。`"aab"` 和 `"abb"` 用到的集合都是 `{a,b}`，但它们不是异位词。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **窗口长度恒为 `len(p)`** | 异位词定义里的「长度相同」 | 你忘记长度条件 → `s = "a", p = "aa"` 会误判为异位词 |
| **要返回所有起点** | 「找到…所有」 | 你找到一个就返回 → 漏解 |
| **比较的是计数，不是集合** | 异位词定义 | `"aab"` vs `"abb"` 判成相同 |
| **子串必须连续** | 「子数组 / 子串」 | 按子序列做 → 完全另一道题 |
| **`s`、`p` 非空，且只含小写英文字母** | 约束 | 用 `int[26]` 就够；如果你假设了大写字母，数组会越界 |
| **`p` 可能比 `s` 长** | 一般性 | 不提前返回 → 返回空列表（结果对，但白跑） |
| **起点列表可以任意顺序** | 「顺序不限」 | 不必排序；按 `i` 递增扫描天然有序 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length, p.length <= 3·10⁴` | n、m 最多 3 万 | 朴素做法「每个起点取 m 长子串、排序后比较」是 `O(n · m log m)` ≈ `3·10⁴ × 3·10⁴ × 15` = 1.35·10¹⁰ 级别，必挂 |
| 「每个起点 + 逐字符计数比较」 | O(n·m) | `9·10⁸` 次比较，仍然必挂（差一个数量级） |
| 只有 26 个字母 | 小写英文 | `int[26]` 当哈希表，比较两个窗口的代价从 O(m) 降到 O(26)，**且 26 是常数** |
| 窗口长度固定为 m | 异位词定义 | **这是本题与 015/016 的分水岭**：无需任何收缩决策 |

> 💡 量级 → 算法：`n = 3·10⁴` + 「等长子串 + 词频相等」⇒ 定长滑窗。
> 关键观察：相邻两个窗口只差**两个字符**（出去一个、进来一个），所以词频可以增量维护，每步 O(1)，总计 O(n)。

### 示例

```
输入：s = "cbaebabacd", p = "abc"
输出：[0, 6]

解释：
  下标 0 开始的 "cba" 是 "abc" 的异位词 ✅
  下标 1 开始的 "bae" 不是（含 e）
  下标 2 开始的 "aeb" 不是
  下标 3 开始的 "eba" 不是
  下标 4 开始的 "bab" 不是（b 有 2 个）
  下标 5 开始的 "aba" 不是（a 有 2 个）
  下标 6 开始的 "bac" 是异位词 ✅
  下标 7 开始的 "acd" 不是

输入：s = "abab", p = "ab"
输出：[0, 1, 2]
解释：窗口长度 2，三个窗口 "ab"、"ba"、"ab" 都满足

输入：s = "a", p = "ab"
输出：[]
```

### 我自造的四个反例（写完必须打一遍）

```text
① s="a",   p="ab"        → m > n，必须提前返回空列表（而不是越界）
② s="abab", p="ab"       → 窗口长度为 2，起点 0/1/2 全命中，检验 n-m+1 个窗口
③ s="bccbcabba", p="ac"  → 检验"出窗 +1、入窗 -1"的符号方向
④ s="aaaa", p="aa"       → 全同一字符，检验 nonzero 的增减是否守恒
```

第 ③ 条是我实际踩到的坑：**我在写这一章的代码时把 `diff` 的更新方向写反了**（出窗 `-1`、入窗 `+1`），`"bccbcabba"` 的第 4 个窗口本该命中，结果漏了。随机对拍跑到第 3 轮就炸了。符号方向这种错误**不会报错、不会崩**，只会少几个答案 —— 所以必须有对拍。

## 017.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来）

```java
List<Integer> ans = new ArrayList<>();
for (int i = 0; i + m <= n; i++) {
    // 取 s[i .. i+m-1]，与 p 比较"每种字符的计数"
    int[] cs = new int[26], cp = new int[26];
    for (int k = 0; k < m; k++) { cs[s.charAt(i+k)-'a']++; cp[p.charAt(k)-'a']++; }
    if (Arrays.equals(cs, cp)) ans.add(i);
}
```

- 时间 **O(n · m)**：`n - m + 1` 个窗口，每个窗口花 O(m) 建计数 + O(26) 比较。
- `n = m = 3·10⁴` 时是 **`9·10⁸` 次字符统计**，必挂。

**先排除一个更差的方案**：对每个窗口排序再和 `p` 的排序结果比较，复杂度 `O(n · m log m)`；由于窗口之间毫无复用，比上面还慢一个 `log` 因子。排序签名只在「一次性分组」（LC 49）里才划算，因为那里没有滑动复用。

### 第二步：它为什么不够 —— 相邻窗口有 m−1 个字符是共享的

```
s = "cbaebabacd"，m = 3

窗口 [0,2] = "cba"   ┐
窗口 [1,3] = "bae"   ┘ 只差两个字符：去掉 'c'，加上 'e'
窗口 [2,4] = "aeb"     只差两个字符：去掉 'b'，加上 'b'（巧合相同）
窗口 [3,5] = "eba"     只差两个字符：去掉 'a'，加上 'a'
```

每个窗口都重建 26 个计数、重新扫 m 个字符，等于**把 m−1 个共享字符的统计工作重复做了 n 遍**。这正是所有滑窗题共同的病灶：**相邻窗口的重叠部分被反复计算**。

而本题的重叠尤其大：**窗口长度固定，所以相邻窗口重叠 `m-1` 个字符**。当 `m` 很大（比如 `m = n/2`）时，重叠率接近 100%。

### 第三步：卡点 —— 怎么把「词频相等」压成 O(1) 判断

即使增量维护了计数，每次还要比 26 个格子。虽然 26 是常数，但有个更漂亮的做法：**维护差值，并把「是否全零」压成一个标量**。

```
diff[c] = count_p(c) − count_window(c)

窗口是异位词  ⇔  对所有 c，diff[c] == 0
             ⇔  nonzero == 0        （nonzero = diff 中非零格子的个数）
```

`nonzero` 可以 O(1) 增量维护，规则是「一个格子的值**跨过 0** 时，`nonzero` 才变」：

| `diff[i]` 变化前 | 变化后 | `nonzero` 的变化 |
| --- | --- | --- |
| 0 | ≠ 0 | **+1**（从"相等"变成"不相等"） |
| ≠ 0 | 0 | **−1**（从不相等变回相等） |
| ≠ 0 | ≠ 0（同号或变号） | 0（一直不相等） |
| 0 | 0 | 不可能（除非 `d = 0`） |

把它写成一个 `bump` 函数，代码就只剩三行核心逻辑。

### 第四步：符号方向 —— 一个必须说清的细节

`diff = count_p − count_window`，那么窗口**右移一格**时：

- **出窗**字符 `d = s[i-m]`：窗口里少了一个 `d`，`count_window(d)` 减 1，所以 `diff[d]` **加 1**；
- **入窗**字符 `c = s[i]`：窗口里多了一个 `c`，`count_window(c)` 加 1，所以 `diff[c]` **减 1**。

**「出窗 +1、入窗 −1」** —— 如果你的 `diff` 定义反过来（`window − p`），那就是「出窗 −1、入窗 +1」。**两种都对，但必须和初始化一致**。我踩的坑就是初始化按 `p − window`、滑动按 `window − p`，两处打架。

## 017.3 原理拆解

### 017.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 每个窗口排序后比较 | O(n · m log m) | O(m) | 8 行 | `n = m = 3·10⁴` 时 10¹⁰ 级，必挂 |
| 每个窗口重建 26 计数再比 | O(n · (m + 26)) | O(26) | 12 行 | 同上，仍 O(n·m) |
| 定长滑窗 + 26 计数，每次比 26 格 | O(n · 26) | O(26) | 18 行 | 能过，但常数 26 白费；面试官会追问「能不能 O(1) 判」 |
| **定长滑窗 + `diff` + `nonzero`** ✅ | **O(n + m)** | **O(26)** | **25 行** | 字符集极大时 `int[26]` 不够，要换 `map`；思路不变 |
| 定长滑窗 + 双指针变长写法（窗口内计数超了就缩） | O(n) | O(26) | 30 行 | 实现更绕、更容易错；见 §017.4.4 的对比 |

**为什么 `nonzero` 值这 5 行代码**：它把「26 个整数是否全为 0」压缩成「1 个整数是否为 0」。代价是需要小心维护（跨零才变），收益是判断从 26 次比较变成 1 次。**这类「把多条件压成单值」的技巧在 016 的 `missing` 里已经出现过一次**，两者是同一个思想的两个实例：

| 场景 | 压成的标量 | 判定条件 |
| --- | --- | --- |
| 016 覆盖 `t` | `missing = Σ max(0, need[c])` | `missing == 0` |
| 017 词频完全相等 | `nonzero = #{c : diff[c] ≠ 0}` | `nonzero == 0` |
| 019 区间和 | `sum` | `sum >= target` |

### 017.3.2 为什么这个做法是对的（正确性论证）

**引理 1（异位词的判定）**：`s[i..i+m-1]` 是 `p` 的异位词 ⇔ 对每个 `c`，`count_window(c) = count_p(c)`。

*证明*：异位词的定义就是「长度相同且每种字符出现次数相同」；长度已经由窗口构造保证是 `m`，故只剩计数条件。∎

**引理 2（初始化的正确性）**：构造阶段结束后，`diff[c] = count_p(c) − count_{s[0..m-1]}(c)`。
*证明*：构造时对 `i = 0..m-1` 执行 `diff[p[i]]++` 与 `diff[s[i]]--`，逐字符累加即得。∎

**引理 3（滑动的正确性）**：若在窗口 `[i-m, i-1]` 上 `diff` 正确，则执行「`diff[s[i-m]] += 1`、`diff[s[i]] −= 1`」后，`diff` 在新窗口 `[i-m+1, i]` 上正确。
*证明*：新窗口 = 旧窗口 − `{s[i-m]}` + `{s[i]}`。对任意 `c`，`count_window` 的变化是 `−[c = s[i-m]] + [c = s[i]]`，而 `diff = count_p − count_window` 的变化恰好是 `+[c = s[i-m]] − [c = s[i]]`，与两行更新一致。∎

**引理 4（`nonzero` 的正确性）**：`bump(diff, i, d)` 返回的增量，恰好等于 `diff[i]` 变化前后「是否非零」这一布尔值的变化量（`0→≠0` 为 +1，`≠0→0` 为 −1，其余为 0）。
*证明*：`diff[i]` 只有三种状态转移（见 §017.2 的表），逐一核对。∎

**定理**：算法返回的每一个 `i`，`s[i..i+m-1]` 都是 `p` 的异位词；且所有异位词都被返回。
*证明*：由引理 2、3，每次检查时 `diff` 都是当前窗口的真实差值；由引理 4，`nonzero == 0` ⇔ 所有 `diff[c] == 0` ⇔（引理 1）当前窗口是异位词。算法遍历了全部 `n-m+1` 个窗口且逐一检查，故不重不漏。∎

### 017.3.3 通用解题思路（可迁移的那一层）

本题是 **「定长滑窗 · 维护等价类签名」** 的母题。它的可迁移形式：

```
问题：找出所有"满足某个只看多重集的谓词"的等长子串
     ↓ 观察
谓词只依赖"窗口内字符的频率向量"（长度已固定）
     ↓ 把"频率向量"变成可增量维护的量
每步：出队一个字符、入队一个字符，O(1) 更新
     ↓ 把"向量相等"压成标量
nonzero == 0
```

**为什么「长度固定」让这道题比 015/016 简单**：滑动窗口最难的部分永远是「什么时候动 left」。而这里 `left = right - m + 1` 是 `right` 的**函数**，不需要任何决策 —— **没有决策就没有正确性风险**。这是本批五道滑窗题里唯一「零决策」的两道（另一道是 018，它与本章完全同构）。

**滑窗家族对照表**（本章是第 3 行）：

| 章节 | 窗口长度 | 目标 | 维护的聚合量 | 动 left 的条件 | 收缩安全性来自 |
| --- | --- | --- | --- | --- | --- |
| [015](015-longest-substring-without-repeating-characters.md) | 变长 | 最长 | `last[c]` | 出现重复 | 左端点下界单调，可跳跃 |
| [016](016-minimum-window-substring.md) | 变长 | 最短 | `need[c]` + `missing` | 已覆盖 | 覆盖关于左端点单调 |
| **017** | **定长 = m** | **全部起点** | **`diff[26]` + `nonzero`** | **无需决策** | **长度固定 ⇒ `left` 是 `right` 的函数** |
| [018](018-permutation-in-string.md) | 定长 = m | 是否存在 | 同 017 | 同 017 | 同 017 |
| [019](019-minimum-size-subarray-sum.md) | 变长 | 最短 | `sum` | `sum >= target` | 正数保证单调 |

**与 018 的关系（必须一起读）**：017 与 018 是**同一个算法**，只是「输出契约」不同：

| | 017（本章） | 018 |
| --- | --- | --- |
| 输入 | `s`、`p` | `s2`、`s1`（注意参数顺序相反！） |
| 窗口 | `s` 上长度 `len(p)` 的窗口 | `s2` 上长度 `len(s1)` 的窗口 |
| 每命中一个窗口 | `ans.add(start)`，**继续滑** | **立即 return true**，短路 |
| 全都没命中 | 返回空列表 `[]` | 返回 `false` |
| 维护的量 | `diff[26]` + `nonzero` | **完全相同** |
| 复杂度 | O(n + m) | O(n + m)，**最好情况 O(m)**（首窗命中即返回） |

> **一句话**：018 = 017 的**短路版**。理解了 017 的「定长窗口 + 频率差」，018 只是把「收集所有答案」换成「命中即返回」。反过来说，如果你只会写 018，说明你只学会了「判断」，没学会「枚举」——面试里后者更常考。

**与「等价类签名」的联系**：`diff` 向量本质上是「窗口的多重集签名」。同一个思想在 [LC 49 字母异位词分组](https://leetcode.cn/problems/group-anagrams/) 里表现为「用排序后的字符串当 key」或「用 26 元组当 key」。**滑窗只是把「重新算签名」变成「增量更新签名」**。

### 017.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **字符集含大写 / Unicode** | `int[26]` 不够 | 换 `int[128]`（ASCII）或 `HashMap<Character,Integer>`；`nonzero` 仍可维护，但初始化要遍历 map 的 key |
| 要求返回**异位词子串本身** | 需要内容 | `s.substring(i, i+m)`；列表规模 O(n·m)，输出本身就是瓶颈 |
| 窗口长度不再是常数（要找「最长」的异位词子串） | 长度可变 | 逻辑上要求「子串是某个串的异位词」，先确定目标多重集，再退化成 016 的「计数覆盖 + 恰好」问题 |
| 改成「至多 k 处字符不同」的近似异位词 | 谓词放宽 | 维护 `bad = Σ \|diff[c]\|`，条件变成 `bad ≤ 2k`（每个不匹配字符贡献 2） |
| 改成**双指针变长**写法 | 换实现 | 窗口内每个字符计数不超过 `count_p` 就右扩，超过就左缩，窗口长恰好 `m` 时收集答案（见 §017.4.4） |
| `s` 是数据流 | 无法回看 | 定长滑窗天然适配（只需保留窗口内 26 个计数和出队字符的环形缓冲） |

## 017.4 图解推演

### 017.4.1 定长窗口的平移：一进一出

```
s = "cbaebabacd", p = "abc", m = 3

初始窗口：
   ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐
   │ c  │ b  │ a  │ e  │ b  │ a  │ b  │ a  │ c  │ d  │
   └────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
     ↑         ↑
   left=0    right=2        窗口 "cba"  → diff 全 0 → 命中，ans=[0]

右移一格（left 与 right 同时 +1）：
        ┌────┬────┬────┐
        │ b  │ a  │ e  │
        └────┴────┴────┘
        ↑              ↑
     出队 'c'        入队 'e'
     diff[c] += 1    diff[e] -= 1

   ┌──────────────────────────────────────────────────────┐
   │ 每一步只有两个字符发生变化 → 词频可以 O(1) 增量更新    │
   │ 这就是"定长滑窗"的全部内容：不需要决策，只需要平移    │
   └──────────────────────────────────────────────────────┘
```

### 017.4.2 `nonzero` 的跨零变化

```
diff 是"p 的计数 − 窗口的计数"。命中时 26 个格子全 0。

  窗口平移一步后：
  ┌───────────────────────────────────────────────────────┐
  │  c:  0 ──→ 1     nonzero += 1     （0 → 非0，跨出零） │
  │  e:  0 ──→ -1    nonzero += 1     （0 → 非0）         │
  └───────────────────────────────────────────────────────┘

  再平移一步，若刚好把刚才的差值补回来：
  ┌───────────────────────────────────────────────────────┐
  │  c:  1 ──→ 0     nonzero -= 1     （非0 → 0，跨回零） │
  │  b:  0 ──→ 2     nonzero += 1                         │
  └───────────────────────────────────────────────────────┘

      ┌────────────────────────────────────────────┐
      │ 只有"跨过 0"才改变 nonzero                  │
      │ 从 1 变 2、从 -1 变 -2 都不改变             │
      └────────────────────────────────────────────┘
```

### 017.4.3 完整状态表（`s = "cbaebabacd"`，`p = "abc"`）

初始窗口 `[0,2] = "cba"`，`diff` 全 0，`nonzero = 0`，`ans = [0]`。

| `i`（新右端） | 出队字符 | `diff[出队]` 变化 | 入队字符 | `diff[入队]` 变化 | `nonzero` | 窗口 | 命中？ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 3 | c | 0 → 1（+1） | e | 0 → −1（+1） | 2 | `"bae"` | 否 |
| 4 | b | 0 → 1（+1） | b | 1 → 0（−1） | 2 | `"aeb"` | 否 |
| 5 | a | 0 → 1（+1） | a | 1 → 0（−1） | 2 | `"eba"` | 否 |
| 6 | e | −1 → 0（−1） | b | 0 → −1（+1） | 2 | `"bab"` | 否 |
| 7 | b | −1 → 0（−1） | a | 0 → −1（+1） | 2 | `"aba"` | 否 |
| 8 | a | −1 → 0（−1） | c | 1 → 0（−1） | **0** | `"bac"` | **是** → `ans=[0,6]` |
| 9 | b | 0 → 1（+1） | d | 0 → −1（+1） | 2 | `"acd"` | 否 |

> 检验一下第 8 行：窗口 `[6,8] = "bac"`，`p = "abc"`，两个多重集相同 → `diff` 全 0 → `nonzero = 0`。此时 `nonzero` 从 2 一路减到 0，减了两次（`a` 和 `c` 各自跨回零），恰好抵消了第 6、7 行加的两下。

### 017.4.4 另一种写法：双指针变长版（以及它为什么更难）

```
思路：窗口内每个字符的计数都不超过 count_p 时，右扩；
      超过时左缩；窗口长度恰好 m 时收集答案。

   ┌────────────────────────────────────────────────────────┐
   │ 1. right++，窗口计数 cnt[s[right]]++                    │
   │ 2. while cnt[s[right]] > count_p(s[right])：            │
   │        cnt[s[left]]--; left++                          │
   │ 3. if right-left+1 == m：记录 left                      │
   └────────────────────────────────────────────────────────┘

   它是对的（窗口内永远"合法"，且长度达到 m 时必然是异位词），
   但比定长版多了一个"为什么 while 条件这样写"的论证负担，
   而收益是 0 —— 窗口长度本来就固定为 m，不需要变长逻辑。
```

> **取舍**：定长版代码长 3 行但**零决策**，正确性几乎不需要论证；变长版看起来「更通用」（能处理长度不固定的场景），但在这道题里属于**用复杂换不到任何东西**。面试里推荐定长版，但要知道变长版的存在 —— 有些面试官会问「如果窗口长度不固定呢」。

## 017.5 双语言实现

### 017.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> ans = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (n < m) return ans;                  // p 比 s 长：不可能有异位词

        // diff[c] = count_p(c) − count_window(c)
        // 初始窗口直接吃进 [0, m-1]，省掉一次单独构造
        int[] diff = new int[26];
        for (int i = 0; i < m; i++) {
            diff[p.charAt(i) - 'a']++;
            diff[s.charAt(i) - 'a']--;
        }

        int nonzero = 0;                        // diff 中非零格子的个数
        for (int v : diff) if (v != 0) nonzero++;
        if (nonzero == 0) ans.add(0);           // 别漏掉第一个窗口

        for (int i = m; i < n; i++) {
            // 出窗 s[i-m]：窗口少一个它 → count_window 减 1 → diff 加 1
            nonzero += bump(diff, s.charAt(i - m) - 'a', +1);
            // 入窗 s[i]：窗口多一个它 → count_window 加 1 → diff 减 1
            nonzero += bump(diff, s.charAt(i) - 'a', -1);
            if (nonzero == 0) ans.add(i - m + 1);   // 新窗口的起点是 i-m+1
        }
        return ans;
    }

    // 修改 diff[i] += d，并返回"非零格子数"的变化量（+1 / -1 / 0）
    private static int bump(int[] diff, int i, int d) {
        int before = diff[i];
        diff[i] += d;
        if (before == 0 && diff[i] != 0) return 1;    // 从零跨出去
        if (before != 0 && diff[i] == 0) return -1;   // 跨回零
        return 0;                                     // 一直在非零区，或 d == 0
    }
}
```

### 017.5.2 Go

```go
package main

func findAnagrams(s string, p string) []int {
	ans := []int{}
	n, m := len(s), len(p)
	if n < m {
		return ans
	}

	// diff[c] = count_p(c) − count_window(c)
	var diff [26]int
	for i := 0; i < m; i++ {
		diff[p[i]-'a']++
		diff[s[i]-'a']--
	}

	nonzero := 0
	for _, v := range diff {
		if v != 0 {
			nonzero++
		}
	}
	if nonzero == 0 {
		ans = append(ans, 0)
	}

	for i := m; i < n; i++ {
		// 注意 int(...)：Go 里 byte - byte 结果仍是 byte，
		// 直接传给 int 参数会编译报错（这是从 Java 转过来最容易卡住的一处）
		nonzero += bump(&diff, int(s[i-m]-'a'), +1)
		nonzero += bump(&diff, int(s[i]-'a'), -1)
		if nonzero == 0 {
			ans = append(ans, i-m+1)
		}
	}
	return ans
}

// bump 修改 diff[i] += d，返回"非零格子数"的增量
// 传 *[26]int 而不是 []int：数组长度在类型里，编译期就定了，无堆分配
func bump(diff *[26]int, i int, d int) int {
	before := diff[i]
	diff[i] += d
	if before == 0 && diff[i] != 0 {
		return 1
	}
	if before != 0 && diff[i] == 0 {
		return -1
	}
	return 0
}
```

### 017.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `byte` 减法 | 没有这个概念，`char - 'a'` 自动提升为 `int` | **`s[i] - 'a'` 结果是 `byte`**，传给 `int` 参数编译报错 | 必须写 `int(s[i]-'a')`。我在实测时就是这里编译失败 |
| 传数组给辅助函数 | `int[]` 天然是引用 | `[26]int` 是**值类型**，不传指针就是整份拷贝（26 个 int） | 必须写 `&diff` + `*[26]int`；写错不会出错，只是白拷贝 26 次 |
| 返回空集合 | `new ArrayList<>()` | `[]int{}`（**不是 nil**） | LeetCode 对 `nil` 和 `[]int{}` 都接受，但 `[]int{}` 更明确，且 JSON 序列化成 `[]` 而不是 `null` |
| 遍历数组求和 | `for (int v : diff)` | `for _, v := range diff` | 一致；Go 的 `range` 会拷贝元素，26 个无所谓 |
| 列表追加 | `ans.add(x)` | `ans = append(ans, x)` | Go 的 `append` 在容量不足时重新分配，均摊 O(1)；`[]int{}` 的初始 cap 是 0，第一次 append 就分配 |
| 字符串长度 | `s.length()` 是 UTF-16 码元数 | `len(s)` 是**字节数** | 只有小写字母时一致；含中文时两者不同，本题约束下无影响 |

### 017.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：每个窗口重新算 26 元组
func brute(s, p string) []int {
	out := []int{}
	m := len(p)
	if len(s) < m {
		return out
	}
	sig := func(x string) [26]int {
		var c [26]int
		for i := range x {
			c[x[i]-'a']++
		}
		return c
	}
	want := sig(p)
	for i := 0; i+m <= len(s); i++ {
		if sig(s[i:i+m]) == want {
			out = append(out, i)
		}
	}
	return out
}

func TestFindAnagramsRandom(t *testing.T) {
	fixed := []struct {
		s, p string
		w    []int
	}{
		{"cbaebabacd", "abc", []int{0, 6}},
		{"abab", "ab", []int{0, 1, 2}},
		{"a", "ab", []int{}},            // m > n
		{"aaaa", "aa", []int{0, 1, 2}},  // 全同一字符
		{"bccbcabba", "ac", []int{4}},   // 曾因符号写反漏掉的那个
		{"abc", "abc", []int{0}},
	}
	for _, f := range fixed {
		got := findAnagrams(f.s, f.p)
		if len(got) != len(f.w) {
			t.Fatalf("s=%q p=%q got=%v want=%v", f.s, f.p, got, f.w)
		}
		for i := range got {
			if got[i] != f.w[i] {
				t.Fatalf("s=%q p=%q got=%v want=%v", f.s, f.p, got, f.w)
			}
		}
	}

	r := rand.New(rand.NewSource(17))
	for iter := 0; iter < 20000; iter++ {
		ns := r.Intn(14)
		np := 1 + r.Intn(4)
		sb := make([]byte, ns)
		for i := range sb {
			sb[i] = byte('a' + r.Intn(3)) // 只用 a/b/c：异位词密集出现
		}
		pb := make([]byte, np)
		for i := range pb {
			pb[i] = byte('a' + r.Intn(3))
		}
		s, p := string(sb), string(pb)
		got, want := findAnagrams(s, p), brute(s, p)
		if len(got) != len(want) {
			t.Fatalf("iter=%d s=%q p=%q got=%v want=%v", iter, s, p, got, want)
		}
		for i := range got {
			if got[i] != want[i] {
				t.Fatalf("iter=%d s=%q p=%q got=%v want=%v", iter, s, p, got, want)
			}
		}
	}
}
```

> **为什么只用 `a/b/c`**：异位词要「频繁命中」才能压测「命中判定」这条路径；26 个字母时随机窗口几乎不可能命中，测试就退化成「永远返回空」，符号写反也测不出来。

## 017.6 复杂度与常见坑

### 017.6.1 复杂度推导

- **时间 O(n + m)**：
  - 初始化：`m` 次计数写入 + 26 次扫表。
  - 滑动：`n - m` 轮，每轮 2 次 `bump`（各含若干次比较与一次数组写）。
  - 总计 `O(m + n)`，常数极小（每轮 < 10 次操作）。
  - **注意**：`int[26]` 的 26 是**字符集大小**，与 `n` 无关，所以在复杂度里算 O(1)。
- **空间 O(26) = O(1)**：`diff` 是定长数组；输出列表的长度最多 `n - m + 1`，属于**输出本身**，不计入算法的辅助空间。

### 017.6.2 八个真实踩过的坑

1. **出窗/入窗的符号写反** —— 初始化按 `p − window`、滑动按 `window − p`，两处打架，结果**少几个答案但不报错**。我在 `"bccbcabba"` 上实测踩到。
2. **忘记检查第一个窗口** —— 循环从 `i = m` 开始，`i = 0` 那个窗口不在循环里，必须单独判断。漏了会少掉 `ans` 里的 0（示例 1 就挂）。
3. **`ans.add(i - m)` 而不是 `i - m + 1`** —— 差一位，全部答案偏左。
4. **`nonzero` 用「每次重新扫 26 格」算** —— 结果对但每轮多 26 次比较，等于放弃了本题最大的优化点。
5. **`bump` 的判零逻辑写成 `if (before * after < 0)`** —— 乘积可能溢出，且逻辑不对（`0 → 非0` 没有覆盖）。正确判据是「`before == 0` 异或 `after == 0`」。
6. **数组开 26 但输入含大写** —— `s.charAt(i) - 'a'` 得到负数，抛数组越界。题目保证小写，但通用代码应开 128 或做归一化。
7. **`n < m` 没提前返回** —— 循环 `for (i = m; i < n; i++)` 不执行，但如果初始化阶段就写了 `s.charAt(i)`（`i < m` 但 `i >= n`），会越界。提前返回最安全。
8. **Go 里 `s[i] - 'a'` 直接传参** —— 编译期报 `cannot use ... (value of type byte) as int`。必须 `int(...)`。

### 017.6.3 面试官最爱追问的三个问题

**Q1：这个解法和 018（字符串的排列）有什么区别？**
> 「同一个算法，输出契约不同。017 要遍历所有窗口、收集全部命中的起点；018 只要找到一个就 `return true`，是 017 的短路版。维护的量完全一样：长度 `len(p)` 的窗口上，`diff = count_p − count_window` 和它的非零格子数 `nonzero`。参数顺序上 018 是 `checkInclusion(s1, s2)`，`s1` 是模式串、`s2` 是长串，和 017 的 `(s, p)` 正好相反，这是最容易在面试里念错的细节。」

**Q2：为什么不用「排序后比较」？**
> 「排序签名适合『一次性分组』（LC 49），因为每个元素只算一次签名。本题有 `n - m + 1` 个窗口，而相邻窗口共享 `m - 1` 个字符，排序会把这份共享信息完全丢弃，复杂度 O(n·m log m)。滑窗利用共享，把每步降到 O(1)，总计 O(n)。**判断用哪种签名，看数据是否『滑动复用』。**」

**Q3：`nonzero` 这个技巧是必须的吗？不用它会怎样？**
> 「不是必须的。每次扫 26 格比较，总复杂度 O(26n)，26 是常数，仍然 O(n)，也能过。但 `nonzero` 有两个好处：①常数从 26 降到 2；②代码把『26 个条件』压成『1 个条件』，和 016 的 `missing` 是同一个思想 —— **把多条件判断压成可增量维护的标量**，这是滑窗题里最值得带走的一个技巧。代价是维护它需要跨零判断，写错就静默少答案，所以必须对拍。」

## 附：本章小结（可背走的三句话）

```
① 异位词 ⇔ 长度相同 + 每种字符计数相同 → 窗口长度被钉死，left = right - m + 1

```
