## 129.1 题目

**原题链接**：<https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/>

### 题意重述（把隐含条件补齐）

给你 `prices`，可以**尽量多做交易**（不限次数），但有两个额外规则：

1. **同一时间最多持有一股**（买之前必须卖掉）；
2. **卖出之后的第二天不能买入**（冷冻一天），但可以「什么都不做」。

求最大总利润。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 冷冻期**只有 1 天** | 「you cannot buy stock on the next day (i.e., cooldown one day)」 | 若理解成「卖完再也不能买」，答案会偏小；理解成「没有冷冻」，就退化成 122 |
| 冷冻只限制**买入**，不限制卖出 | 同上（下一「天」不能买） | 若把卖出也禁掉，某些多段行情会算少 |
| 可以**一直不交易** | 「find the maximum profit」 | 初值写 `-inf` 会把「不交易」这条合法方案排除 |
| 卖出当天**算第一天**，第二天才能买 | 题面措辞 | 差一天就会在 `[1,2,3,0,2]` 上答 2（正确 3） |
| 不限交易次数 | 题面「as many transactions as you like」 | 若按 1 笔或 2 笔做，答案会偏小 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= prices.length <= 5000` | 五千 | `O(n²)` 也能过（`2.5·10⁷`），`O(n)` 更轻松；指数级 DFS 在 `n = 30` 就死 |
| `0 <= prices[i] <= 1000` | 非负、值域小 | 利润 `≤ 5·10⁶`，`int` 安全 |
| 状态数固定为 3 | — | 空间 `O(1)`：三个变量就够 |
| 无取模 | — | — |

> 💡 **量级 → 算法**：`n ≤ 5000` 说明出题人并不打算卡复杂度，**这题的难度完全在「状态怎么设」**。所以本章的重点不是优化，而是把「冷冻」这件事正确地塞进状态机。

### 示例

```text
输入：prices = [1,2,3,0,2]
输出：3
解释：第 1 天买（1）、第 2 天卖（2）赚 1；第 3 天冷冻；
     第 4 天买（0）、第 5 天卖（2）赚 2；合计 3
     （如果第 2 天卖完第 3 天立刻买，就能多赚 (3−2)+(2−0)=3，共 4 —— 但这是违规的）

输入：prices = [1]
输出：0
解释：只有一天，无法完成买卖

输入：prices = [2,1,4]
输出：3
解释：1 买 4 卖，赚 3（不需要冷冻期，因为没再用到买入）
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [1]           → 只有一天：0
② [1,2]         → 最小可交易：1（卖完就结束，冷冻期不影响）
③ [1,2,3,4,5]   → 单边上涨：正确答案 4（一笔到底），不是 1+1+1+… 
                     —— 因为每卖一次都要冷冻一天，频繁交易反而更差
④ [1,2,3,0,2]   → 冷冻期生效的分水岭：3（不是 4）
⑤ [6,1,3,2,4,7] → 多段行情：正确答案 6（1 买 3 卖 + 2 买 7 卖）
```

第 ③ 条最能打醒「贪心吃所有上涨段」的直觉：在 122 题里 `[1,2,3,4,5]` 的答案是 4，靠的是「每天都买明天卖」；但本题每次卖出都要冷冻一天，所以**频繁交易反而要付代价**。

## 129.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 对每一天枚举三个动作

```text
dfs(day, holding, cooldown):
    if day == n: return 0
    best = dfs(day+1, holding, false)                  # 什么都不做（cooldown 自然过期）
    if holding:
        best = max(best, prices[day] + dfs(day+1, false, true))     # 卖出 → 明天冷冻
    else if not cooldown:
        best = max(best, -prices[day] + dfs(day+1, true, false))    # 买入
    return best
```

- 时间 **`O(3ⁿ)`**（每天至多三个分支）：`n = 5000` 时完全不可能；`n = 30` 已是 `2·10^14`。
- 空间 `O(n)` 递归栈。
- 它的价值：作为对拍基准（§129.5.4），并且它**把「状态」这件事暴露得非常清楚** —— 看函数签名 `(day, holding, cooldown)`：**要描述「现在能不能买」，光靠 `holding` 不够，还需要 `cooldown`。**

### 第二步：卡点在哪 —— 两个状态装不下「刚卖完」

127 / 128 的两状态机是：

```text
hold = 手上持股时的最大现金
free = 手上不持股时的最大现金
```

现在「不持股」分裂成两种**处境完全不同**的情形：

| 处境 | 能不能马上买 | 属于同一个 `free` 会出什么问题 |
| --- | --- | --- |
| ① 手里没股、且昨天也没卖（或早就空了） | ✅ 能买 | 与 ② 混在一起时，`free` 会把「刚卖完」的高现金带进「买入」转移 |
| ② 手里没股、但**今天刚卖** | ❌ 明天才能买 | 于是算法允许「卖了立刻买」，答案偏大 |

**反例**：`prices = [1,2,3,0,2]`。

```text
❌ 用两状态（没有冷冻）：
   第 1 天买 1、第 2 天卖 2 赚 1；第 2 天立刻再买 2、第 3 天卖 3 赚 1；
   第 3 天立刻买 3、第 4 天卖 0 亏 3（不做）；第 4 天买 0、第 5 天卖 2 赚 2
   合计 1 + 1 + 2 = 4    ❌ 正确是 3

✅ 三状态（有冷冻）：
   卖出后的第二天不能买，所以「1→2 卖完」必须空过第 3 天，只能吃 0→2 那一段
   合计 1 + 2 = 3        ✅
```

### 第三步：灵感的来源 —— 把「不持有」拆成两个状态

```text
hold  = 今天收盘【持有股票】时的最大现金
sold  = 今天【刚刚卖出】时的最大现金   ← 明天不能买！
rest  = 今天收盘【不持有且不在冷冻】时的最大现金（可以买）
```

**关键设计**：`sold` 是「今天卖出」这个**动作的结果**，不是「卖出之后的一般状态」。这样「冷冻」就自动被编码进状态图里：

- 从 `sold` 出发**没有**「买入」这条边（今天卖完不能明天买 → 明天的 `sold` 只能变成 `rest`）；
- 从 `rest` 出发**有**「买入」这条边。

### 第四步：转移（每天先算「新值」，再统一赋值）

```text
新 hold = max( hold,  rest − p )        # 继续持有；或从 rest 状态买入
新 sold = hold + p                      # 今天卖出（只能用【昨天】的 hold）
新 rest = max( rest,  sold )            # 继续 rest；或昨天刚卖，今天冷冻结束
答案   = max( sold, rest )              # 最后一天不该还持股
```

三条转移的语义一定要背下来：

| 转移 | 含义 | 为什么是这两个来源 |
| --- | --- | --- |
| `hold ← max(hold, rest − p)` | 持有 | 继续持有 / 今天买入；**买入只能从 `rest`**（不能从 `sold`，这就是冷冻） |
| `sold ← hold + p` | 今天卖出 | 只能卖昨天持有的；**没有 `max`**，因为「今天必须卖」是一个确定动作 |
| `rest ← max(rest, sold)` | 空仓可买 | 继续空仓 / **昨天刚卖，冷冻结束**（`sold` 隔一天变成 `rest`） |

### 第五步：为什么必须用「昨天」的值

`sold` 的转移用 `hold + p`，这里的 `hold` 必须是**昨天收盘**的 `hold`。如果写成「今天已经更新过的 `hold`」，就可能出现「今天买入 + 今天卖出」—— 在 128 题里这种同日交易无害（净收益 0），但**在本题里有害**：它会让 `sold` 拿到一个「今天刚买就卖」的值，等于绕过了冷冻期的计数。

所以本题的实现必须**先算好三个新值，再一起赋值**（Java 用三个临时变量，Go 用多重赋值）。这一点与 128 的「允许同日买卖」正好相反 —— **两个题看起来像，这个细节必须区别对待。**

## 129.3 原理拆解

### 129.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 三叉 DFS（无记忆化） | `O(3ⁿ)` | `O(n)` | 15 行 | `n ≥ 25` 就废，只能对拍 |
| DFS + 记忆化 `(day, state)` | `O(n)` | `O(n)` | 20 行 | 递归栈；且 `state` 要小心编码 |
| **三状态滚动（本题首选）** ✅ | **`O(n)`** | **`O(1)`** | **12 行** | 想扩展到「冷冻 k 天」时要改用队列 |
| `dp[i][0/1/2]` 二维表 | `O(n)` | `O(n)` | 15 行 | 空间浪费；但**便于打印推演**（本章 §129.4 就这么用） |
| 两状态 + 「卖出后强制插入空日」的预处理 | `O(n)` | `O(1)` | 20 行 | 思路绕，容易差一天；不如三状态直白 |
| 贪心「吃所有上涨段」 | — | — | 5 行 | **本题直接失效**（见反例 ③）：冷冻期让频繁交易变贵 |

**为什么选三状态滚动**：`O(n)` 时间、`O(1)` 空间、12 行，而且**状态图就是题目规则的直译**，讲给别人听一句「卖出后的第二天不能买，所以我把『刚卖完』单独立成一个状态」就能讲清。

### 129.3.2 为什么这个做法是对的（正确性论证）

**命题**：算法返回「在冷冻期约束下的最大总利润」。

**（1）状态语义（在第 `i` 天收盘时）**：
- `hold_i`：以「持有股票」结尾的所有合法操作序列中，现金的最大值；
- `sold_i`：以「第 `i` 天卖出」结尾的所有合法操作序列中，现金的最大值；
- `rest_i`：以「不持有且不在冷冻」结尾的所有合法操作序列中，现金的最大值。

**（2）第 `i+1` 天的动作分类完备且互斥。** 相对昨天，今天只有三种可能的动作：不操作、买入、卖出。

- **不操作**：昨天持股 → 今天仍持股（`hold` 自环）；昨天 `rest` → 今天 `rest`（`rest` 自环）；昨天 `sold` → 今天变为 `rest`（冷冻结束，这正是 `rest ← max(rest, sold)` 这一项）。
- **买入**：要求昨天不持股且不在冷冻，即昨天必须是 `rest`（`sold` 不行，因为冷冻期；`hold` 不行，因为已经有股）。买入后变 `hold`，现金 `rest − p`。
- **卖出**：要求昨天持股，即昨天是 `hold`。卖出后现金 `hold + p`，状态为 `sold`（因为冷冻从今天开始算，明天不能买）。

三种动作覆盖全部合法操作，且每个候选都对应一条合法序列 ⇒ `dp` 不会超过最优。

**（3）不漏**：任取一条合法操作序列，按天模拟其状态变化，必落在上面某条转移上。归纳即得 `dp` 恰为最优。

**（4）边界**：`hold_0 = −∞`（第 0 天不存在，不能凭空持股）、`sold_0 = −∞`（没卖过）、`rest_0 = 0`（什么都不做的现金）。答案取 `max(sold_n, rest_n)`，因为最后一天持股是非法的（题目要求把股票卖掉才实现利润）。∎

> ⚠️ **「为什么答案不取 `hold`」**：`hold` 表示手上还有股票，那部分价值没有兑现。严格来说 `hold + 最后一天价格` 也是一种「等价」结果，但既然要求「最大化利润」，把股票在最后一天卖掉总是不劣的，所以 `max(sold, rest)` 就够。**写代码时不要图省事返回 `hold`。**

### 129.3.3 通用解题思路（可迁移的那一层）

本题确立了 **「时间约束 ⇒ 新增状态」** 这条通用手段：

```text
规则的形状                         →  状态机的形状
──────────────────────────────────────────────────────────
「卖出后隔 k 天才能买」             →  卖出后经过 k 个「空日状态」
                                    （k = 1 ⇒ 三状态；k > 1 ⇒ 用长度 k 的队列/多状态）
「同一时间最多持 1 股」             →  两个互斥状态 hold / not-hold
「最多 k 笔交易」                   →  在状态外再加一维额度 c（见 128）
「每笔手续费」                      →  只改卖出项的系数（LC 714）
「同一天不能既买又卖」              →  转移时必须用「昨天」的值（本章做法）
```

**同族的其他题**：

| 题 | 需要额外编码的约束 | 状态数 |
| --- | --- | --- |
| [LC 309](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/)（本题） | 卖出后冷冻 1 天 | 3 |
| [LC 714](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/) | 每笔手续费 | 2 |
| [LC 122](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-ii/) | 无 | 2 |
| [LC 123](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/) | 至多 2 笔 | `2 × 3` |
| [LC 188](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iv/) | 至多 k 笔 | `2 × (k+1)` |
| [LC 714 + 冷冻 + k 笔（自造）](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/) | 三者叠加 | `3 × (k+1)` |

> 🔑 **一句话**：**「规则」不是限制，而是「状态」的生成器。** 每读到一条新规则，先问「它让我需要区分两种原本混在一起的情形吗？」—— 需要，就多一个状态。

### 129.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 冷冻 **k 天**（不是 1 天） | 冷冻时长可变 | 用长度 `k` 的滑动队列保存「`k` 天前卖出后的现金」，`rest` 每天从队首取；`O(n)` 时间、`O(k)` 空间 |
| 每笔**手续费** `fee`（LC 714） | 改系数 | `sold = hold + p − fee` |
| 至多**k 笔** + 冷冻 | 维度叠加 | `dp[c][3]`：`3 × (k+1)` 个状态 |
| 允许**做空** | 状态翻倍 | 增加 `short` 状态；注意做空也会触发冷冻 |
| 要求**输出交易序列** | 从值变路径 | 每格记录来源动作（buy/sell/rest），最后从 `max(sold, rest)` 回溯 |
| 价格是**流式给出**且要求随时回答当前最优 | 在线算法 | 三状态天然在线：每来一个价格更新一次，答案就是当前 `max(sold, rest)` |

**冷冻 k 天的写法（思路，Go）**：维护一个长度为 `k` 的环形缓冲 `soldHistory`，存放最近 `k` 天各自的 `sold` 值；`rest_i = max(rest_{i-1}, soldHistory[i-k])`。这样只需 `O(k)` 空间、`O(n)` 时间，`k = 1` 时退化成本章的三状态机。

## 129.4 图解推演

### 129.4.1 状态转移图（本章的核心图）

```text
                    买入：花掉 p
        ┌─────────────────────────────────────────┐
        │                                         ▼
  ┌──────────┐                              ┌──────────┐
  │   rest   │                              │   hold   │
  │ 空仓可买  │                              │  持有中   │
  └──────────┘                              └──────────┘
        ▲                                         │
        │                                         │ 卖出：得到 p
        │        ┌──────────┐                     │
        └────────┤   sold   │◄────────────────────┘
       冷冻结束   │ 今天刚卖  │      （卖出后当天进入 sold）
       （次日）   └──────────┘
                        │
                        └── ✗ 没有「sold → hold」的直达边
                              这就是冷冻期：卖完的第二天不能买
```

三个状态 + 四条边，把规则说得清清楚楚：

| 边 | 条件 | 含义 |
| --- | --- | --- |
| `rest → hold` | 空仓且不在冷冻 | 买入 |
| `hold → sold` | 持有股票 | 卖出，当天进入 `sold` |
| `sold → rest` | 经过 1 天 | 冷冻结束（**唯一出口**） |
| `hold → hold` / `rest → rest` | — | 不操作 |

### 129.4.2 逐日推演的 DP 表（`prices = [1,2,3,0,2]`）

```text
  天   p     hold     sold     rest     说明
 ─────────────────────────────────────────────────────────────
  0    -      -∞       -∞       0       初值：不能凭空持股/卖出
  1    1      -1       -∞       0       买入 1（现金 -1）
  2    2      -1        1       0       卖出：-1 + 2 = 1
  3    3      -1        2       1       又卖了一次（-1+3=2）；rest 从 sold 继承 1
  4    0       1       -1       2       rest=2 买入 0 ⇒ hold=2；sold=-1+0 无效
  5    2       1        3       2       卖出：1 + 2 = 3 ⇒ 答案 max(3, 2) = 3
 ─────────────────────────────────────────────────────────────
```

注意第 4 天：`hold` 从 `-1` 变成 `1`，来源是 `rest − p = 1 − 0 = 1` 与旧 `hold = -1` 取 max。**这一格是本题的关键**：`rest` 之所以能在第 4 天是 1（而不是 0），是因为第 3 天 `rest = max(0, sold=1) = 1` —— 也就是「第 2 天卖出、第 3 天冷冻结束」。把每一步的数值摊开写，就是下面这张严格表：

| 天 `i` | `p` | 转移前的 `hold` | 转移前的 `sold` | 转移前的 `rest` | 新 `hold = max(old, rest−p)` | 新 `sold = old hold + p` | 新 `rest = max(old rest, old sold)` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0（初值） | — | −∞ | −∞ | 0 | −∞ | −∞ | 0 |
| 1 | 1 | −∞ | −∞ | 0 | max(−∞, 0−1) = **−1** | −∞+1 = **−∞** | max(0, −∞) = **0** |
| 2 | 2 | −1 | −∞ | 0 | max(−1, 0−2) = **−1** | −1+2 = **1** | max(0, −∞) = **0** |
| 3 | 3 | −1 | 1 | 0 | max(−1, 0−3) = **−1** | −1+3 = **2** | max(0, 1) = **1** |
| 4 | 0 | −1 | 2 | 1 | max(−1, 1−0) = **1** | −1+0 = **−1** | max(1, 2) = **2** |
| 5 | 2 | 1 | −1 | 2 | max(1, 2−2) = **1** | 1+2 = **3** | max(2, −1) = **2** |

答案 `max(sold, rest) = max(3, 2) = 3` ✅

> 🔎 **看第 3 天的 `rest`**：`max(0, sold=1) = 1`，这就是「第 2 天卖出 → 第 3 天冷冻结束」的体现。**如果 `rest` 少了 `sold` 这一项，那么「卖完再买」这条唯一的合法路径就断了，答案会偏小。** 反之，若 `hold` 的转移写成 `max(hold, sold − p)`，冷冻期就被绕过，答案会偏大。

### 129.4.3 两状态（无冷冻）的错误轨迹（对比图）

```text
❌ 两状态写法：
   hold = max(hold, free - p)      ← free 里混着「刚卖完」
   free = max(free, hold + p)
   在 [1,2,3,0,2] 上：
     第 2 天：hold=-1, free=1
     第 3 天：hold = max(-1, free - 3 = -2) = -1； free = max(1, -1+3=2) = 2
     第 4 天：hold = max(-1, free - 0 = 2) = 2；  free = max(2, -1+0) = 2
     第 5 天：hold = max(2, 2-2=0) = 2；          free = max(2, 2+2=4) = 4
   答案 4  ❌  （多赚了「第 2 天卖完、第 3 天立刻买」那一段）

✅ 三状态写法：答案 3
```

```text
   两状态：  hold ⇄ free         ← free 是一团「糊在一起」的状态
   三状态：  hold → sold → rest  ← 把「刚卖完」单独拎出来，时间约束变成一条边
              ↑__________│
            买入只能从 rest 出发
```

## 129.5 双语言实现

### 129.5.1 Java

```java
class Solution {
    public int maxProfit(int[] prices) {
        // 用 MIN_VALUE/2 而非 MIN_VALUE：转移里有 NEG + p，MIN_VALUE + p 会溢出回正
        final int NEG = Integer.MIN_VALUE / 2;

        int hold = NEG; // 持有：现金为负（买股票花掉的钱）
        int sold = NEG; // 今天刚卖出：明天不能买
        int rest = 0;   // 空仓且不在冷冻、可以买

        for (int p : prices) {
            // 三个新值都必须用【昨天】的三个旧值算，
            // 否则会出现「今天买入后立刻卖出」——那会绕过冷冻期的计数（本题与 128 的关键差别）
            int newHold = Math.max(hold, rest - p); // 继续持有；或从 rest 买入（不能从 sold 买！）
            int newSold = hold + p;                 // 只能卖昨天持有的；今天必须卖，所以没有 max
            int newRest = Math.max(rest, sold);     // 继续空仓；或昨天刚卖，今天冷冻结束

            hold = newHold;
            sold = newSold;
            rest = newRest;
        }
        // 最后一天还持股不算「实现利润」，所以只看 sold / rest
        return Math.max(sold, rest);
    }
}
```

### 129.5.2 Go

```go
package main

func maxProfit(prices []int) int {
	const neg = -1 << 60 // 足够小且不会在 +p 时溢出

	hold, sold, rest := neg, neg, 0

	for _, p := range prices {
		// Go 的多重赋值天然保证「右边全用旧值」—— 正好是本题需要的语义
		// 若拆成三条独立赋值，必须借临时变量，否则 newRest 会读到已更新的 sold
		newHold := hold
		if v := rest - p; v > newHold {
			newHold = v
		}
		newSold := hold + p // 用旧的 hold
		newRest := rest
		if sold > newRest {
			newRest = sold // 昨天刚卖 → 今天冷冻结束
		}
		hold, sold, rest = newHold, newSold, newRest
	}
	if sold > rest {
		return sold
	}
	return rest
}
```

### 129.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 同时更新三个变量 | **必须**借三个临时变量，或严格按「先算全部新值、再赋值」的顺序写 | 可直接 `hold, sold, rest = h2, s2, r2` 多重赋值 | 本题是「滚动赋值顺序」最敏感的一题：写错顺序会静默给出偏大的答案 |
| `max` | `Math.max(a, b)` | 手写 `if` | 本题每轮三次比较，Go 版多 9 行；可封装 `maxInt` |
| 负无穷 | `Integer.MIN_VALUE / 2` | `-1 << 60` | 都不许用真正的最小值（见 128 的解释） |
| 返回值 | `Math.max(sold, rest)` | 手写比较 | 一致 |
| 空数组 | `for` 不执行 → `max(NEG, 0) = 0` | 同 | 本题保证 `n ≥ 1`；空数组也会得到 0，安全 |

### 129.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：逐日枚举「不动 / 买 / 卖」，用 (holding, cooldown) 两个布尔描述局面
// 这是对题目规则的直译，与三状态 DP 的建模完全不同
func cooldownBrute(prices []int) int {
	var dfs func(day int, holding bool, cooldown bool) int
	dfs = func(day int, holding bool, cooldown bool) int {
		if day == len(prices) {
			return 0
		}
		// 选择 1：什么都不做（冷冻标记自然过期）
		best := dfs(day+1, holding, false)
		if holding {
			// 选择 2：卖出 → 明天进入冷冻
			if v := prices[day] + dfs(day+1, false, true); v > best {
				best = v
			}
		} else if !cooldown {
			// 选择 3：买入（只有「不持有且不在冷冻」时才能买）
			if v := -prices[day] + dfs(day+1, true, false); v > best {
				best = v
			}
		}
		return best
	}
	return dfs(0, false, false)
}

func TestMaxProfitCooldown(t *testing.T) {
	edges := [][]int{
		{1},                  // 一天 → 0
		{1, 2},               // 最小可交易 → 1
		{1, 2, 3, 4, 5},      // 单边上涨 → 4（频繁交易更差）
		{1, 2, 3, 0, 2},      // 题面样例 → 3（冷冻生效）
		{6, 1, 3, 2, 4, 7},   // 多段 → 6
		{2, 1},               // 下跌 → 0
		{0, 0, 0},            // 全等 → 0
		{5, 4, 3, 2, 1},      // 单调跌 → 0
	}
	for _, a := range edges {
		if got, want := maxProfit(a), cooldownBrute(a); got != want {
			t.Fatalf("edge %v got=%d want=%d", a, got, want)
		}
	}

	r := rand.New(rand.NewSource(309309))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(11) // 1..11，保证 3^n 可跑
		a := make([]int, n)
		for i := range a {
			a[i] = r.Intn(8) // 值域 0..7：等值多，能压制「同日买卖」与「冷冻差一天」的错误
		}
		if got, want := maxProfit(a), cooldownBrute(a); got != want {
			t.Fatalf("iter=%d a=%v got=%d want=%d", iter, a, got, want)
		}
	}
}
```

> 📌 **对拍有效性**：`cooldownBrute` 的 `cooldown` 是「明天能不能买」的布尔，语义与题目原文一字不差；而 DP 用「`sold` 状态 + `rest` 继承」来编码同一件事。**两个建模越不相似，对拍越有说服力。**

## 129.6 复杂度与常见坑

### 129.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(n)`**：一趟循环，每轮三次 max / 两次加法 / 一次比较。`n = 5000` 时约 `3·10^4` 次操作 —— 纳秒级。
- **空间 `O(1)`**：三个整数（`hold` / `sold` / `rest`）。**为什么能 O(1)**：转移只依赖**前一天的三个状态**，回看宽度是 1 天 ⇒ 不需要历史数组。
- **下界 `Ω(n)`**：必须读完价格序列（任意一天的信息都可能改变最优解）。
- **暴力的定量代价**：`O(3ⁿ)`；`n = 20` 时 `3.4·10^9`，已无法在 1 秒内完成。这是「状态机」最直接的收益。

### 129.6.2 七个真实踩过的坑

1. **`hold` 的买入来源写成 `sold − p`** —— 冷冻期被绕过，`[1,2,3,0,2]` 答 4（正确 3）。
2. **`rest` 少了 `max(rest, sold)` 里的 `sold`** —— 「卖完再买」这条唯一合法路径断了，多段行情的答案偏小。
3. **三个变量没有同时更新** —— 例如先写 `rest = max(rest, sold)` 再写 `hold = max(hold, rest − p)`，此时 `hold` 用的是**今天刚更新**的 `rest`，等价于「今天冷冻结束 + 今天买入」，多算一天。
4. **`sold` 写成 `max(sold, hold + p)`** —— 加 `max` 不致命（`sold` 只影响下一天的 `rest`），但会让人误以为 `sold` 是「累计」状态；语义上 `sold` 只表示「今天卖出」，写成 `max` 后可能混入旧值，导致 `rest` 早一天解冻。
5. **答案返回 `hold`** —— 最后一天还持股，利润没兑现。必须 `max(sold, rest)`。
6. **`NEG` 用 `Integer.MIN_VALUE`** —— `NEG + p` 溢出成正数，答案爆炸。
7. **以为「贪心吃所有上涨段」仍然适用** —— `[1,2,3,4,5]` 会答 4（恰好对），但 `[1,2,3,0,2]` 会答 4（正确 3）。**这类「在部分输入上碰巧正确」的错误最危险。**

### 129.6.3 面试官最爱追问的三个问题

**Q1：为什么两个状态不够，非要三个？**

> 「因为『不持有』实际上包含两种处境：**刚卖完（明天不能买）** 和 **空仓且可买**。它们的『能做的动作』完全不同，而两状态把两者糊成一个 `free`，于是 `hold = max(hold, free − p)` 就允许了『卖了立刻买』。反例 `[1,2,3,0,2]`：两状态答 4，正确 3。把『刚卖完』拆成独立状态 `sold`，冷冻就变成一条『`sold` 只能流向 `rest`，不能直接流向 `hold`』的图结构。」

**Q2：如果冷冻期是 k 天呢？**

> 「把 `sold` 的『延迟 1 天』换成『延迟 k 天』：维护一个长度为 k 的环形队列，存最近 k 天各自的 `sold` 值，每天 `rest_i = max(rest_{i-1}, 队列头部那个 k 天前的 sold)`。时间 `O(n)`、空间 `O(k)`。也可以把状态扩成 `hold / sold_1 / sold_2 / … / sold_k`，但那是 `O(nk)` 空间，不如队列。」

**Q3：为什么三状态的更新必须用「昨天的值」？**

> 「因为『买入』和『卖出』是两件事，如果 `sold` 用今天更新过的 `hold`，就可能出现『今天买入 + 今天卖出』，等价于零收益地多算一个交易日，而这一天本该被冷冻期吃掉。所以必须先把三个新值都算完再统一赋值。注意这与 128 题正相反 —— 那里『同一天卖出上一笔再买入下一笔』是无害的（它只传递额度），而这里是有害的（它绕过冷冻）。**同一个写法在不同题目里对错相反，这就是为什么状态机必须逐题推导，不能套模板。**」
