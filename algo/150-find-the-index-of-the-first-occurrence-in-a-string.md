## 150.1 题目

**原题链接**：<https://leetcode.cn/problems/find-the-index-of-the-first-occurrence-in-a-string/>

### 题意重述（把隐含条件补齐）

给你两个字符串 `haystack`（主串，俗称「干草堆」）和 `needle`（模式串，俗称「针」）。请你在 `haystack` 中找出 `needle` **第一次出现**的下标，如果不存在则返回 `-1`。

六条必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 返回的是**下标**，不是子串 | 「返回 `needle` 在 `haystack` 中出现的第一个位置」 | 返回 `"sad"` 而不是 `0` 会直接判错 |
| 找不到返回 **`-1`**，不是 `0` 也不是 `len` | 「如果不存在，则返回 `-1`」 | 返回 0 会和「在下标 0 处找到」混淆 |
| 是**第一次**出现 | 「第一个匹配项」 | 找到就立刻返回；不能等着看后面有没有更好的 |
| 模式串可能**比主串长** | 约束里两者各自独立 | 不先判断长度就会越界（`needle[j]` 访问不到） |
| 空模式串的处理（历史版本） | 「`0 <= needle.length`」（旧版） | 按约定返回 `0`；新版约束 `needle.length >= 1`，但工程代码要防 |
| 题目不要求 `O(n)`，但**面试会问** | 约束 `1 <= len <= 10⁴` | `O(nm)` 在 `10⁴ × 10⁴ = 10⁸` 最坏情况下勉强能过，但那是「靠数据弱」，不是「算法好」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= haystack.length, needle.length <= 10⁴` | 各最多 1 万 | 最坏 `n·m = 10⁸` 次字符比较。本机实测（2 核容器 / JDK 17 / Go 1.19）：最坏输入下暴力 Java ≈ 0.35 s、Go ≈ 0.09 s —— **能过，但已经贴线** |
| 全部由小写英文字母组成 | 字母表只有 26 个 | 重复字符极多，**最坏输入很容易构造**（`"aaaa…a"` 配 `"aaab"`），暴力必然退化成 `O(nm)` |
| 只要第一个出现位置 | 不需要所有位置 | 找到就能 `return`，不需要收集；但 KMP 稍改一行就能收集全部 |
| 常数空间不是硬要求 | 题面未限制 | KMP 的 `O(m)` 空间可以接受；真正的约束是**时间不能有 `nm` 项** |

> 💡 **量级 → 算法** 的收官一条：
> **看到「子串/模式匹配」，先想「有没有一种办法，让失配时主串指针不回退」？**
> 能让主串不回退的技术只有几种：**KMP（利用模式串自身的重复结构）**、**Z 函数（前缀函数）**、**Rabin-Karp（哈希）**、**Boyer-Moore（从右往左 + 坏字符跳跃）**。它们的分水岭都是「用模式串的什么信息换掉回退」。

### 示例

```text
输入：haystack = "sadbutsad", needle = "sad"     输出：0
      "sad" 在下标 0 与 6 各出现一次，取第一个

输入：haystack = "leetcode", needle = "leeto"    输出：-1
      "leeto" 不是 "leetcode" 的子串

输入：haystack = "abababaca", needle = "ababaca"  输出：2
      本章全程用这个例子演示 KMP 的回退
```

### 我自造的六个反例（写完解法必须拿它们打一遍）

```text
① haystack = "", needle = "a"        → -1    空干草堆：n = 0 < m，必须先判长度
② haystack = "a", needle = "aa"      → -1    模式串比文本长，同上
③ haystack = "", needle = ""         → 0     都为空：按约定匹配在 0 处成功
④ haystack = "a", needle = ""        → 0     空模式串：约定返回 0
⑤ haystack = "aaa", needle = "aa"    → 0     重叠匹配：第一次就成功
⑥ haystack = "abababab", needle = "abab"  → 0
                                   本章回退的关键用例：若在找到后误把 j 清零，
                                   就再也匹配不到起点 2（结果的正确性不受影响，
                                   但「找出所有位置」的变体会漏）
```

第 ⑥ 条要留着：本书最后一章的常见变体是「找出**所有**出现位置」，那时候「找到之后 `j` 该退回到哪」就是核心问题——正确做法是 `j = next[j-1]`（而不是 `j = 0`），否则 `"abababab"` 里 `"abab"` 的第二次出现（下标 4）会被漏掉。

## 150.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的做法：枚举每一个起点 `i`，逐字符检查 `needle[0..m-1]` 是否等于 `haystack[i..i+m-1]`。

```java
for (int i = 0; i + needle.length() <= haystack.length(); i++) {
    int j = 0;
    while (j < needle.length() && haystack.charAt(i + j) == needle.charAt(j)) j++;
    if (j == needle.length()) return i;      // 整段匹配
}
return -1;
```

- 时间 **O(n·m)**，空间 **O(1)**。
- `n = m = 10⁴` 且输入是 `"aaaa…a"` 配 `"aaa…ab"` 时，每次尝试都要比到 `m−1` 个字符才失败 → **`10⁸` 次比较**。本机实测 Java ≈ 0.35 s、Go ≈ 0.09 s，**能过**（本题数据弱）。
- 它为什么不够？两个理由，都必须在面试里说出来：
  1. **它把已经确认过的信息全扔了**。若 `haystack[i..i+j-1] == needle[0..j-1]` 已经匹配了 9999 个字符、第 10000 个失配，暴力会让起点 `i+1` 重新从 `j = 0` 开始比 —— **刚验证过的 9999 个字符全部作废**。
  2. **最坏输入极易构造**：全同字符 + 末尾不同，就能把任何「朴素实现」钉在 `O(nm)`。

### 第二步：卡点在哪

把问题翻译成一句话：

> **失配时，我已经知道了「主串里 `haystack[i..i+j-1]` 这一段恰好等于 `needle[0..j-1]`」。这个信息能不能让我跳过一些起点？**

这是全部问题的核心。换句话说：

```
失配发生在 needle[j] 处，说明：
     haystack[i .. i+j-1]  ==  needle[0 .. j-1]        （前 j 个字符已匹配）

问题：起点能不能从 i 跳到更靠右的 i' ，而不必从 i+1 逐个试？

能 —— 只要 needle 的一个「后缀」等于它的一个「前缀」：
     如果 needle[0 .. k-1] == needle[j-k .. j-1]
     那么把起点挪到 i' = i + (j - k) 之后，
     主串里 [i'..i+j-1] 这 k 个字符已经天然等于 needle[0..k-1]，
     可以直接从 needle[k] 继续比。
```

也就是说：**能不能跳过，取决于「已匹配的那段 `needle[0..j-1]` 有多长的『前缀同时是后缀』」。** 而这个长度**只与模式串自己有关**，与主串无关——所以可以**预处理**成一张表。

### 第三步：灵感的来源 —— `next` 数组（失败函数）

定义（本章唯一的定义，务必背下来）：

```
next[i] = needle[0..i] 这个前缀的「最长『真前缀 = 真后缀』的长度」
         其中「真」的意思是：长度严格小于 i+1（不能是自己整段）
         特别地 next[0] = 0
```

举例，`needle = "ababaca"`：

| `i` | 前缀 `needle[0..i]` | 最长「真前缀 = 真后缀」 | `next[i]` |
| --- | --- | --- | --- |
| 0 | `a` | 无（真前缀只能是空串） | **0** |
| 1 | `ab` | 无 | **0** |
| 2 | `aba` | `a` | **1** |
| 3 | `abab` | `ab` | **2** |
| 4 | `ababa` | `aba` | **3** |
| 5 | `ababac` | 无（`c` 开头对不上） | **0** |
| 6 | `ababaca` | `a` | **1** |

于是 `next = [0, 0, 1, 2, 3, 0, 1]`。

**这张表怎么用**：失配发生在 `needle[j]` 时，说明已匹配长度是 `j`（即 `needle[0..j-1]` 已匹配）。我们要找「这段的最长前缀=后缀」，它的长度正是 **`next[j-1]`**（注意下标是 `j-1`，因为 `next` 是按「前缀结束下标」定义的）。于是：

```
j = next[j - 1]        ← 一次回退，可能还要再退几次（用 while）
```

这就是那句著名的 **`j = next[j-1]` 回退**。它的三句话解释：

1. **主串指针 `i` 不动**（不回退）——这是 KMP 能 `O(n+m)` 的根本。
2. **`j` 变短**（因为 `next[j-1] < j`，真前缀必须比整段短）——保证收敛、不会死循环。
3. **回退后的对齐是合法的**：`needle[0..next[j-1]-1]` 与「已匹配段的后缀」相同，所以这 `next[j-1]` 个字符不需要重新比。

### 第四步：`next` 数组自己怎么算？（一个「模式串匹配自己」的过程）

计算 `next` 用的是**同一套回退逻辑**，只是把「主串」换成了模式串自己：

```java
int k = 0;                                  // k = 当前「前缀=后缀」的长度
for (int i = 1; i < m; i++) {               // i 是从 1 开始的「后缀末尾」
    while (k > 0 && p.charAt(i) != p.charAt(k)) k = next[k - 1];  // 失配就退
    if (p.charAt(i) == p.charAt(k)) k++;    // 匹配就延长一位
    next[i] = k;
}
```

**这就是本章真正的「一行核心」**：`k = next[k-1]` 与搜索阶段的 `j = next[j-1]` 是同一个动作，只是它在「模式串 vs 模式串」上跑。

## 150.3 原理拆解

### 150.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力（枚举起点逐字符比） | **O(n·m)** | O(1) | 8 行 | 重复字符多的输入（`aaa…a` vs `aaa…ab`）直接退化成 `10⁸` 次比较 |
| **KMP（`next` 数组）** ✅ | **O(n + m)** | **O(m)** | 25 行 | 实现细节多（`next` 的下标差一）；多模式匹配要换 AC 自动机 |
| Z 函数（前缀数组） | O(n + m) | O(n + m) | 20 行 | 需要拼接 `pattern + 分隔符 + text`，额外空间是 `O(n+m)` 而不是 `O(m)` |
| Rabin-Karp（滚动哈希） | 期望 O(n + m) | O(1) | 18 行 | **有哈希碰撞** → 需双哈希或碰撞后逐字符校验；最坏仍可能退化 |
| Boyer-Moore（坏字符 + 好后缀） | 平均**亚线性** | O(字母表 + m) | 60 行 | 实现复杂；最坏 `O(nm)`（需 BM 的完整版才降到 `O(n+m)`） |
| 内建 `indexOf` / `strings.Index` | 各语言实现不同（多为「暴力优化 + 特殊路径」） | — | 1 行 | 面试要求手写；且不同语言实现差异大 |

### 150.3.2 为什么这个做法是对的（正确性论证）

**引理 1（`next` 的定义与下标）**：`next[i]` 是满足「`needle[0..k-1] == needle[i-k+1..i]` 且 `k < i+1`」的最大 `k`（`k ≥ 0`）。

- 当 `i = 0`：`k < 1` 只能是 0，所以 `next[0] = 0` ✓。
- 用这个定义，搜索时「已匹配段」是 `needle[0..j-1]`（长度 `j`），它的最长「真前缀=后缀」长度就是 `next[j-1]` ✓。

**引理 2（回退后不变量仍成立）**：设某轮开始时有

```
haystack[i-j .. i-1] == needle[0 .. j-1]        （已匹配 j 个字符）
```

若 `haystack[i] != needle[j]`，令 `j' = next[j-1]`，则

```
haystack[i-j' .. i-1] == needle[0 .. j'-1]      （新对齐仍然合法）
```

**证明**：由 `next` 的定义，`needle[0..j'-1] == needle[j-j' .. j-1]`（前缀等于后缀）。而已匹配条件给的是 `haystack[i-j..i-1] == needle[0..j-1]`，把它的**后 `j'` 个字符**单独取出来：

```
haystack[i-j' .. i-1] == needle[j-j' .. j-1] == needle[0 .. j'-1]
```

三步拼接，结论成立 ✓。这正是「回退之后那 `j'` 个字符不用重新比」的严格理由。∎

**定理（搜索的循环不变量）**：主循环每次迭代开始时，

```
① haystack[i-j .. i-1] == needle[0 .. j-1]
② j 是「满足 ① 的最大可能值」中，与当前 i 相容的那个（即不会漏掉更早的完整匹配）
```

- **初始化**：`i = 0, j = 0`，① 是空条件 ✓。
- **保持**：三种情况。
  - `haystack[i] == needle[j]`：`j++`，① 从长度 `j` 延长到 `j+1` ✓。
  - `haystack[i] != needle[j]` 且 `j > 0`：按引理 2 回退，① 仍成立；循环 `while` 直到 `j == 0` 或字符相等，保证退出时要么 `j = 0`（空前缀，①恒成立），要么可以继续匹配 ✓。
  - `j == 0` 且不等：**不回退**（已经退无可退），`i` 前进 ✓。
- **终止**：`j == m` 时，① 说明 `haystack[i-m+1 .. i] == needle[0..m-1]`，即在下标 `i-m+1` 处找到一个完整匹配；若循环跑到 `i == n` 都没出现，则任何起点都不可能匹配（因为 ① 保证了「已匹配的最长长度」），返回 `-1` ✓。∎

**定理（复杂度 O(n+m)）**：

- 搜索阶段：`i` 从 0 增到 `n`，**只增不减**，共 `n` 次递增。`j` 每次成功匹配 `+1`，所以 `j` 的**总增加量 ≤ n**。每次 `j = next[j-1]` 会让 `j` **严格减少**（因为 `next[j-1] < j`），而 `j ≥ 0`，所以 `j` 的**总减少量 ≤ 总增加量 ≤ n`。因此 `while` 的总执行次数 ≤ `n`。合计 `O(n)`。
- 构造 `next`：同一套论证，`k` 的总增加量 ≤ `m`，总减少量 ≤ `m`，共 `O(m)`。
- 总时间 `O(n + m)`，空间 `O(m)`（`next` 表）。∎

> **这个「势能分析」是 KMP 复杂度证明的灵魂**：不要说「`while` 里可能退很多次所以是 `O(nm)`」——**摊还**看，总退步次数不超过总进步次数。

### 150.3.3 通用解题思路（可迁移的那一层）

**模型：用「字符串自身的重叠结构」消灭回退**

```
朴素匹配失败时，主串指针要回退 → 已经验证的信息被浪费
        ↓ 观察：失配瞬间，已匹配的那段是「模式串的一个前缀」
        ↓ 于是只需知道「这个前缀的最长『真前缀=真后缀』长度」
就能把模式串右移到一个「新对齐仍合法」的位置，主串指针不动
        ↓ 这张表只依赖模式串 → 预处理一次，O(m)
        ↓ 搜索时每个字符只进出 O(1) 次 → O(n)
```

`next` 数组（失败函数 / 前缀函数）是字符串算法里**复用率最高**的一个结构。它的定义只有一句话，但能推出半个字符串工具箱：

| 用途 | 怎么用 `next` |
| --- | --- |
| 单模式匹配（LC 28） | 失配时 `j = next[j-1]` |
| **最短循环节 / 周期** | `p = m - next[m-1]`；若 `m % p == 0` 则整串由周期 `p` 重复构成（LC 459） |
| **最长「前缀=后缀」** | 直接是 `next[m-1]`（LC 1392 最长快乐前缀） |
| **所有「前缀=后缀」长度** | 沿 `k = next[k-1]` 一路跳下去（每次跳都得到一个更短的前后缀相等长度） |
| 求所有出现位置 | 匹配成功后 `j = next[j-1]` 继续（而不是清零） |
| 构造最短回文（LC 214） | 对 `s + '#' + reverse(s)` 求 `next`，用最长前后缀补到前面 |

**与 Z 函数的一句话对比**（面试常问「你还知道别的方法吗」）：

> **Z 函数**：`Z[i]` = 「`s` 与 `s[i:]` 的最长公共前缀长度」。把 `pattern + 分隔符 + text` 拼成一个串求 `Z`，凡是 `Z[i] == m` 的位置就是一个匹配。复杂度同为 `O(n+m)`，**思路更直白（不用想回退）、实现常数更小**，代价是要多花 `O(n+m)` 空间、还得挑一个字母表里不存在的分隔符。**KMP 的 `next` 是「前缀=后缀」，Z 是「自己与后缀的公共前缀」——两者是同一件事的两种切法。**

### 150.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 找**所有**出现位置 | 不能找到就返回 | 匹配成功后 `j = next[j-1]`（**不是 0**），继续扫，保证重叠匹配不漏 |
| **多模式**匹配（一堆针扎一个堆） | 单模式不够 | **AC 自动机** = Trie + 失配指针（`next` 的多叉推广），`O(S + n + 匹配数)` |
| 允许**最多 k 处不匹配** | 精确匹配失效 | 把「字符不等」换成「计数」，纵向扫描或 DP（`dp[i][j] = 最小不匹配数`） |
| **流式**输入（主串边来边匹配） | 不能回头 | KMP 天然流式：只要 `j` 与 `next` 表，来一个字符推进一次，内存 `O(m)` |
| 内存极度受限 | 不能存 `next` 表 | 用 `O(1)` 空间的暴力 + 首字符过滤；或 Boyer-Moore-Horspool 的坏字符表（`O(字母表)`） |
| 串里有**通配符 / 正则** | 语义升级 | 通配符用分段 KMP；正则需要 NFA/DFA（正则引擎），KMP 只覆盖「固定模式串」 |

## 150.4 图解推演

### 150.4.1 `next` 数组的形成（`needle = "ababaca"`）

```
下标 i :    0    1    2    3    4    5    6
字符 p :    a    b    a    b    a    c    a
next[i]:    0    0    1    2    3    0    1
                 ▲    ▲    ▲    ▲    ▲    ▲
                 │    │    │    │    │    └── "ababaca" 的最长真前后缀 = "a"    → 1
                 │    │    │    │    └─────── "ababac"  没有              → 0
                 │    │    │    └──────────── "ababa"  前后缀 "aba"       → 3
                 │    │    └───────────────── "abab"   前后缀 "ab"         → 2
                 │    └────────────────────── "aba"    前后缀 "a"          → 1
                 └─────────────────────────── "ab"     没有               → 0

     ┌───────────────────────────────────────────────────────────────┐
     │ 记住这张表的读法：next[i] 说的是「p[0..i] 这个前缀」的重叠度， │
     │ 而不是「p[i] 这个字符」的属性。所以搜索时用它要写 next[j-1]。 │
     └───────────────────────────────────────────────────────────────┘
```

### 150.4.2 搜索时的回退（`haystack = "abababaca"`，`needle = "ababaca"`）

```
  初始： i=0, j=0
  ──────────────────────────────────────────────────────────────
  主串   a  b  a  b  a  b  a  c  a
  模式   a  b  a  b  a  c  a
         ↑
         逐字符匹配，j: 1 → 2 → 3 → 4 → 5
  ──────────────────────────────────────────────────────────────
  i=5 时失配：

  主串   a  b  a  b  a  b  a  c  a
  模式   a  b  a  b  a  c  a
                        ↑
                     j=5，主串是 'b'，模式是 'c' → 不等

  已匹配长度 j=5，即已确认：haystack[0..4] == needle[0..4] == "ababa"

  回退：j = next[j-1] = next[4] = 3
        含义：「ababa」的最长真前后缀是 "aba"，长度 3
        于是 needle[0..2] ("aba") 自动等于 haystack[2..4] ("aba")，
        这 3 个字符不用重比 → 模式串右移 2 格，直接从 needle[3] 比

  主串   a  b  a  b  a  b  a  c  a
             a  b  a  b  a  c  a        ← 右移 2 格后的对齐
                        ↑
                     j 已变成 3，i 仍然是 5（主串指针没回退！）

  needle[3]='b' 与 haystack[5]='b' 相等 → j=4
  ──────────────────────────────────────────────────────────────
  继续：i=6 'a' vs needle[4]='a' → j=5
        i=7 'c' vs needle[5]='c' → j=6
        i=8 'a' vs needle[6]='a' → j=7 == m → 找到！
        起点 = i - m + 1 = 8 - 7 + 1 = 2   ✓
```

把回退的那一步单独画成图：

```
   j=5 失配
      │
      ├── needle[0..4] = "ababa"      已匹配段
      │        ↑
      │        └─ 它的最长真后缀 = "aba"（长度 3），同时也是真前缀
      │
      ▼
   j = next[4] = 3                     ┌─ 这一步就是 j = next[j-1]
      │                               │
      ▼                               │
   needle[0..2] = "aba" 已经和主串尾部对齐 ──┘
      │
      └── 主串指针 i 停在原地不动（这是 O(n) 的来源）
```

### 150.4.3 逐步状态表（`haystack = "abababaca"`，`needle = "ababaca"`）

| `i` | `haystack[i]` | 进入时 `j` | 比较 `needle[j]` | 是否回退 | 退出时 `j` | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `a` | 0 | `a` | 否 | 1 | 匹配 |
| 1 | `b` | 1 | `b` | 否 | 2 | 匹配 |
| 2 | `a` | 2 | `a` | 否 | 3 | 匹配 |
| 3 | `b` | 3 | `b` | 否 | 4 | 匹配 |
| 4 | `a` | 4 | `a` | 否 | 5 | 匹配 |
| 5 | `b` | 5 | `c` | **是**：`j=next[4]=3` | 4 | 退到 `"aba"` 后 `b==b`，继续 |
| 6 | `a` | 4 | `a` | 否 | 5 | 匹配 |
| 7 | `c` | 5 | `c` | 否 | 6 | 匹配 |
| 8 | `a` | 6 | `a` | 否 | **7 = m** | 找到，返回 `8-7+1 = 2` |

### 150.4.4 `next` 数组的构造过程（同样是逐步的表）

| `i` | `p[i]` | 进入时 `k` | `p[k]` | 动作 | `next[i]` |
| --- | --- | --- | --- | --- | --- |
| 0 | `a` | — | — | 初始 | **0** |
| 1 | `b` | 0 | `a` | `b != a`，`k` 已是 0 → 不动 | **0** |
| 2 | `a` | 0 | `a` | 相等 → `k=1` | **1** |
| 3 | `b` | 1 | `b` | 相等 → `k=2` | **2** |
| 4 | `a` | 2 | `a` | 相等 → `k=3` | **3** |
| 5 | `c` | 3 | `b` | 不等 → `k=next[2]=1`；`c != p[1]='b'` → `k=next[0]=0`；`c != p[0]='a'` → 停在 0 | **0** |
| 6 | `a` | 0 | `a` | 相等 → `k=1` | **1** |

> **第 5 行展示了 `while` 的必要性**：`k` 可能连续回退两次。写成 `if` 而不是 `while` 就会在这类「级联失配」上算错 `next`。

## 150.5 双语言实现

### 150.5.1 Java

```java
class Solution {
    public int strStr(String haystack, String needle) {
        int n = haystack.length(), m = needle.length();

        // 空模式串：按约定在任何位置都算匹配，返回 0（旧版约束允许空串）
        if (m == 0) {
            return 0;
        }
        // 模式串比主串长：不可能有匹配，先挡掉，避免下面 needle.charAt(j) 越界
        if (n < m) {
            return -1;
        }

        int[] next = buildNext(needle);

        int j = 0;                       // j = 已匹配的模式串长度（= 下一个要比的 needle 下标）
        for (int i = 0; i < n; i++) {    // i 只增不减：这是 O(n) 的全部来源
            // 失配就沿 next 回退，直到 j 退到 0 或字符对上。
            // 必须用 while：一次失配可能需要连续回退（见 §150.4.4 第 5 行）
            while (j > 0 && haystack.charAt(i) != needle.charAt(j)) {
                j = next[j - 1];         // 下标是 j-1：next 是按「前缀结束下标」定义的
            }
            if (haystack.charAt(i) == needle.charAt(j)) {
                j++;                     // 这一位也对上了，已匹配长度 +1
            }
            if (j == m) {
                return i - m + 1;        // 完整匹配的起点
            }
        }
        return -1;
    }

    // 构造失败函数：next[i] = needle[0..i] 的最长「真前缀 = 真后缀」长度
    private int[] buildNext(String p) {
        int m = p.length();
        int[] next = new int[m];
        int k = 0;                        // k = 当前已知的最长前后缀长度
        for (int i = 1; i < m; i++) {     // 从 1 开始：next[0] 恒为 0
            while (k > 0 && p.charAt(i) != p.charAt(k)) {
                k = next[k - 1];          // 与搜索阶段的 j = next[j-1] 是同一个动作
            }
            if (p.charAt(i) == p.charAt(k)) {
                k++;                      // 前后缀可以再延长一位
            }
            next[i] = k;
        }
        return next;
    }
}
```

### 150.5.2 Go

```go
package main

func strStr(haystack string, needle string) int {
	n, m := len(haystack), len(needle)

	if m == 0 {
		return 0 // 空模式串约定匹配在 0 处
	}
	if n < m {
		return -1 // 针比干草堆还长，直接不可能
	}

	next := buildNext(needle)

	j := 0
	for i := 0; i < n; i++ {
		// Go 里 s[i] 是 byte：小写英文字母串按字节比较完全正确；
		// 若含中文等多字节字符，必须转成 []rune 再用同样的算法
		for j > 0 && haystack[i] != needle[j] {
			j = next[j-1]
		}
		if haystack[i] == needle[j] {
			j++
		}
		if j == m {
			return i - m + 1
		}
	}
	return -1
}

// buildNext 返回失败函数：next[i] = p[0..i] 的最长「真前缀 = 真后缀」长度
func buildNext(p string) []int {
	m := len(p)
	next := make([]int, m) // next[0] 默认为 0，与定义一致
	k := 0
	for i := 1; i < m; i++ {
		for k > 0 && p[i] != p[k] {
			k = next[k-1]
		}
		if p[i] == p[k] {
			k++
		}
		next[i] = k
	}
	return next
}
```

### 150.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 字符单位 | `charAt` 返回 `char`（UTF-16 码元） | `s[i]` 返回 **`byte`** | 小写英文串两者完全等价（本题约束）；含中文时 `s[i]` 会切碎多字节字符，必须 `[]rune(s)` |
| 内建查找 | `String.indexOf` / `contains` | `strings.Index` | 都可用一行过题；面试要求手写时禁用。两语言的内建实现都不是纯 KMP（Go 的 `bytealg` 按长度切换几种不同做法） |
| 长度 | `length()` 方法 | `len()` 内建 | Go 的 `len(s)` 是**字节数**，Java 的 `length()` 是 **UTF-16 码元数**——含非 ASCII 时两者不同 |
| 数组 | `int[] next = new int[m]` | `make([]int, m)` | 零值都是 0，正好符合 `next[0] = 0`，省一次显式赋值 |
| 越界 | 抛异常 | panic | 两者都必须靠 `n < m` 提前挡；`needle[j]` 在 `j == m` 时会出界，靠「到了 `m` 立刻返回」避免 |
| 切片开销 | `substring` 复制 | `s[a:b]` 共享底层数组 | 本题不切片，无影响；但若写「返回匹配到的子串」的变体，Go 会持有整个原串 |

func bruteIndex(haystack, needle string) int {
	n, m := len(haystack), len(needle)
	if m == 0 {
		return 0
	}
	for i := 0; i+m <= n; i++ {
		j := 0
		for j < m && haystack[i+j] == needle[j] {
			j++
		}
		if j == m {
			return i
		}
	}
	return -1
}

	for i := 0; i < len(p); i++ {
		want := 0
		// 从大到小找第一个满足「前缀 == 后缀」的 k，那就是最长长度
		for k := i; k >= 1; k-- {
			if p[:k] == p[i-k+1:i+1] {

			}

func allMatches(haystack, needle string) []int {

## 150.6 复杂度与常见坑

### 150.6.1 复杂度推导（写结论不算本事，要能推）

- **预处理 O(m)**：构造 `next` 的循环里，`k` 每次 `++` 使 `k` 增 1，每次 `k = next[k-1]` 使 `k` 严格减（至少减 1）。`k` 总增加量 ≤ `m`，下界为 0，所以总减少量也 ≤ `m`，`while` 的总执行次数 ≤ `m`。合计 `O(m)`。
- **搜索 O(n)**：同上，`j` 总增加量 ≤ `n`（每次 `i` 前进最多让 `j` 增 1），总减少量 ≤ `n`。所以 `while` 总次数 ≤ `n`。
- **总计 O(n + m)**，**空间 O(m)**。
- **对比暴力 O(n·m)**：最坏输入 `"a"×10⁴` 配 `"a"×9999 + "b"`。暴力要做 `10⁴ × 10⁴ = 10⁸` 次字符比较；KMP 只需约 `2×10⁴` 次。**差距 5000 倍**——这就是「算法复杂度」在真实数据上的意义。
- **均摊的严格说法**：单次 `while` 可能退很多步（最坏 `O(m)`），但**摊还**到整个扫描是常数。面试里说「`j` 的每一次回退都对应着之前的一次成功匹配，所以总回退次数不超过总匹配次数」，这就是势能分析的白话版。

### 150.6.2 七个真实踩过的坑

1. **`j = next[j-1]` 写成 `j = next[j]`** —— 差一位，`next` 是按「前缀结束下标」定义的，回退时要用「已匹配长度 `j` 对应的前缀的结束下标」即 `j-1`。写错的症状是回退不到位（漏匹配）或回退过头。
2. **回退用 `if` 而不是 `while`** —— 一次失配可能需要连续回退（`"aabaaac"` 这类模式串），`if` 会让 `j` 退一次就不动了，导致误判。
3. **`while` 条件漏了 `j > 0`** —— `j = 0` 时 `needle[j]` 是合法的（下标 0），但 `next[j-1] = next[-1]` 会越界；更重要的是退到 0 就必须停（已经退无可退）。
4. **主串指针也跟着回退** —— 有人把「回退」理解成 `i = i - j + 1; j = 0;`，那就退化成暴力了；KMP 的**全部价值**在于 `i` 单调前进。
5. **没判「模式串比主串长」** —— `needle[j]` 在 `j` 到 `m` 前就 index 越界，或返回错误的 0。
6. **`next[i]` 里存的是「下标」而不是「长度」** —— 两种约定都存在（有些教材令 `next[0] = -1`、`next[i]` 表示「失配后跳到哪个下标」）。**混用两套约定**是 KMP 最常见的灾难；本书统一采用「长度约定（`next[0] = 0`）」，并在注释里写明。
7. **找到后 `j` 清零导致漏掉重叠匹配**（变体题） —— `"abababab"` 里 `"abab"` 的三次出现只找到一次。正确做法：`j = next[j-1]`。

### 150.6.3 面试官最爱追问的三个问题

**Q1：`next` 数组到底在表达什么？为什么它能保证主串不回退？**

> 「`next[i]` 是 `needle[0..i]` 的**最长『真前缀 = 真后缀』长度**——也就是这段字符串自己有多少『自我重叠』。它的用处是：失配发生时，已匹配的那 `j` 个字符恰好是 `needle[0..j-1]`，而 `next[j-1]` 告诉我们这段里『多长的后缀同时也是前缀』。把那 `next[j-1]` 个字符直接认成已匹配，就能把模式串右移到一个**仍然合法**的新对齐位置，主串指针一步都不用退。因为 `next[j-1] < j` 恒成立，`j` 每次都严格变小，所以回退必然终止。」

**Q2：为什么复杂度是 O(n+m) 而不是 O(n·m)？**

> 「做势能分析。`j` 只在字符匹配时加 1，一共最多加 `n` 次；每次回退 `j = next[j-1]` 都让 `j` 严格减小，而 `j` 不会小于 0，所以总回退次数不会超过总增加次数，也就 ≤ `n`。于是整个搜索过程是 `O(n)`，构造 `next` 按同一套论证也是 `O(m)`。**单次失配可能退很多步，但摊还到全局是常数**——这就是为什么不能只看最内层那个 `while`。」

**Q3：除了 KMP，还有什么方法？Z 函数和哈希各有什么取舍？**

> 「三条常见的替代路线：① **Z 函数**：`Z[i]` 是 `s` 与 `s[i:]` 的最长公共前缀长度，把 `pattern + 分隔符 + text` 拼起来求一遍，`Z[i] == m` 的位置就是匹配。复杂度同为 `O(n+m)`，思路比 KMP 直白（不用想回退），常数通常更小，代价是要 `O(n+m)` 空间和一个不在字母表里的分隔符。② **Rabin-Karp 滚动哈希**：期望 `O(n+m)`、空间 `O(1)`，但存在哈希碰撞，工程上要么双哈希要么碰撞后逐字符复核。③ **Boyer-Moore**：从右往左比、靠坏字符/好后缀跳跃，平均**亚线性**，是很多语言 `indexOf` 的实际实现思路之一，但完整版实现复杂。面试答『KMP 用来讲清原理、Z 函数用来快速实现、哈希用来处理多模式或流式』就够了。」

## 附：本章小结（可背走的三句话）

```
① next[i] = needle[0..i] 的最长「真前缀 = 真后缀」长度；next[0] = 0
② 失配时 j = next[j-1]（下标是 j-1），主串指针 i 一步不退 → 摊还 O(n+m)
③ 找到匹配后继续找重叠解要 j = next[j-1]；Z 函数是同一种「自我重叠」的另一种切法
```
