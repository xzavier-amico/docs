## 126.1 题目

**原题链接**：<https://leetcode.cn/problems/regular-expression-matching/>

### 题意重述（把隐含条件补齐）

给你一个字符串 `s` 和一个**模式** `p`，实现支持 `.` 与 `*` 的正则匹配，要求**整串匹配**（不是找子串）：

- `'.'` 匹配**任意单个字符**；
- `'*'` 匹配**零个或多个**它前面的那个字符。

必须读到下面六条，否则代码一定会错：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| `*` 修饰的是**前一个字符**，不是「任意串」 | 「matches zero or more of the **preceding** element」 | 若理解成通配（`*` 单独匹配任意长度），`s="ab"`, `p="a*b"` 会被误判成「`*` 吃掉 `b` 后 `b` 无字符可匹配」 |
| `*` 可以匹配**零次** | 「zero or more」 | 漏掉零次分支，`s="aab"`, `p="c*a*b"` 会答 false（正确 true） |
| 必须**整串**匹配 | 「The matching should cover the **entire** input string」 | 若按「找子串」做，`s="xa"`, `p="a"` 会答 true（正确 false） |
| 模式**保证合法**（不会出现开头 `*`、连续两个 `*`） | 「It is guaranteed… `*` is preceded by a valid character」 | 但**对拍时仍可能造出 `*` 开头的串**，代码要么防御、要么在对拍里排除 |
| `s` **可以为空** | 约束 `0 <= s.length` | 空 `s` 必须能匹配 `"a*b*c*"` 这类模式 |
| `.` 只匹配**一个**字符，`.*` 才是任意串 | 「`.` matches any single character」 | 把 `.` 当「任意长度」会让 `s="ab"`, `p=".b"` 判错 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= s.length <= 20` | 只有 20 | 指数级回溯**在本题能过**（`2²⁰ ≈ 10⁶`），这正是为什么很多人写回溯也 Accepted |
| `1 <= p.length <= 20` | 只有 20 | 同上；但真正的面试会把约束改成 `10³`，那时只有 `O(mn)` 能活 |
| `s` 只含小写字母，`p` 含小写字母与 `.` `*` | 字符集小 | `match(c, pc)` 是 O(1) 判断 |
| **20 × 20** | 极小 | `O(mn) = 400` 格 —— 本题的难度**完全来自转移的思考，不来自规模** |

> 💡 **量级 → 算法**：`n ≤ 20` 是「指数解也能过」的典型尺寸，所以本题的 LeetCode 通过率里混着大量「回溯 + 剪枝」的解。但**本章要写的是能顶到 `10³` 的 `O(mn)` 解** —— 因为面试官问的一定是「如果 `s` 有 10 万个字符呢」。**别把题目的规模当成算法的许可证。**

### 示例

```text
输入：s = "aa", p = "a"
输出：false
解释：整串匹配要求 p 覆盖 "aa"，但 "a" 只覆盖一个字符

输入：s = "aa", p = "a*"
输出：true
解释：'*' 让 'a' 重复两次

输入：s = "ab", p = ".*"
输出：true
解释："." 任意字符 + "*" 任意次 = 任意串

输入：s = "aab", p = "c*a*b"
输出：true
解释："c*" 匹配零个 c，"a*" 匹配两个 a，然后 "b" 匹配 "b"   ← 零次分支的分水岭
```

### 我自造的六个反例（写完解法必须拿它们打一遍）

```text
① ("", "a*")        → '*' 匹配零次 ⇒ true。空串匹配非空模式，是最常错的初值
② ("", "a*b*c*")    → 连续三个「可零次」的量词 ⇒ true，检验 dp[0][*] 的链式初始化
③ ("", ".*")        → true（'.' 本身也需要字符，但 '*' 可以吃掉零个）
④ ("a", "ab*")      → true（"b*" 吃掉零个 b）
⑤ ("ab", ".*c")     → false（".*" 再强也必须留一个 c，而 s 里没有 c）
⑥ ("aaa", "a*a")    → true（"a*" 吃两个 a，最后一个 a 由模式末尾的 a 匹配）
```

第 ② 条最关键：`p = "a*b*c*"` 对空串成立，这要求 `dp[0][2]`、`dp[0][4]`、`dp[0][6]` 全部为 true。**初值初始化是一条「沿模式前进 2 格」的链**，写成「只看 `dp[0][j-2]` 而不检查 `p[j-1]=='*'`」就会把 `"a*b"` 也判成能匹配空串（错误）。

## 126.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 按定义递归回溯

最直白的写法是把「匹配」直接翻译成递归：看 `s[i]` 与 `p[j]`，遇到 `*` 时**枚举它吃几个字符**。

```text
match(i, j):                          # s[i..] 与 p[j..] 能否整串匹配
    if j == len(p):  return i == len(s)          # 模式用完，s 也必须用完
    first = (i < len(s)) 且 (p[j] == '.' 或 p[j] == s[i])
    if j+1 < len(p) 且 p[j+1] == '*':
        # 分支 A：'*' 吃 0 个 —— 直接跳过「x*」这两个字符
        if match(i, j+2): return true
        # 分支 B：'*' 吃 1 个 —— 消耗 s[i]，仍停在 j（还能继续吃）
        if first 且 match(i+1, j): return true
        return false
    # 没有 '*'：必须匹配当前字符，双双前进
    return first 且 match(i+1, j+1)
```

- 时间：最坏 **`O(2^{m+n})`**（每个 `*` 处二分支）。`s="aaaaaaaaaaaaaaaaaaaa"`, `p="a*a*a*a*a*a*a*a*a*a*b"` 这种输入是经典的**灾难性回溯（catastrophic backtracking）**：指数级。
- 空间：`O(m+n)` 递归栈。
- `m,n ≤ 20` 时它能过（剪枝后更快），**但把规模改到 100 就必死**；真实世界里正则引擎被这种输入打挂（ReDoS）是有 CVE 的。

### 第二步：卡点在哪 —— 同一对 `(i, j)` 被反复求值

看 `s = "aaaa"`, `p = "a*a*a*"` 的调用树（只画前两层）：

```text
                        match(0,0)
                 ┌──────────┴──────────┐
        零次→match(0,2)           一次→match(1,0)
        ┌────┴────┐               ┌────┴────┐
   m(0,4)     m(1,2)         m(1,2)      m(2,0)
                              ▲
                              └── 与左边同名同参！整棵子树被重算
```

`match(1,2)` 在上面的树里出现了 **2 次**，深度更大时会出现更多次。这就是**重叠子问题**的定义 —— 与 108 章的爬楼梯、120 章的解码方法一模一样。

而 `match(i,j)` 的输入只有两个整数，取值范围 `(m+1)(n+1)`。**状态数是 400 量级，调用数是 2²⁰ 量级。中间的全部浪费都来自重复。**

### 第三步：把递归改写成表 —— 二维布尔 DP

```text
dp[i][j] = 布尔值：s 的前 i 个字符 能否被 p 的前 j 个字符【整串】匹配
```

- `dp[0][0] = true`：空串被空模式匹配。
- `dp[i][0] = false`（`i ≥ 1`）：非空 `s` 不能被空模式匹配。
- 答案 `dp[m][n]`。

### 第四步（本章的核心）：把 `*` 的分支**逐步拆开**

`*` 是全题唯一的麻烦。它同时意味着「可以一次都不用」和「可以用很多次」。把这两件事写成两条边：

```text
设模式形如  ... x *   （x 可以是普通字符，也可以是 '.'），当前考察 p[j-1] == '*'

【零次分支】x* 整体被丢弃 —— 相当于从状态 j 沿 ε 边跳到 j-2
        dp[i][j]  |=  dp[i][j-2]
        ↑ 注意是【同一行】左边两格：s 没有被消耗（i 不变），模式跳过 2 个字符

【多次分支】x* 先吃掉 s 的一个字符，然后【仍然停在 j】
        前提：s[i-1] 能被 x 匹配（x == '.' 或 x == s[i-1]）
        dp[i][j]  |=  dp[i-1][j]
        ↑ 注意是【上一行】同一列：s 消耗了 1 个字符，模式【一位都没前进】
          —— 这正是「*」的自环：吃一个，还能再吃
```

用状态机画出来就是这样（`j` 表示「模式已处理到第 j 个字符」的状态）：

```text
        ε（零次）                   吃一个字符
   j-2 ──────────────→ j ──────────────→ j
                        ↑___________________│
                           自环（多次）：每吃一个 s 字符就回到同一个状态
```

**为什么「多次分支」引用的是 `dp[i-1][j]` 而不是 `dp[i-1][j-2]`？** 这是最关键的一问：
- 如果写成 `dp[i-1][j-2]`，那意味着「`x*` 只吃一个」，无法表达「吃两个、三个」。
- 写成 `dp[i-1][j]`，含义是「吃完这一个之后，`x*` 依然有效、依然可以选择再吃或停止」。于是**通过多次应用同一条转移，自然得到「吃 k 个」的全部情形** —— 这就是 DP 用「一次一步」表达「任意多个」的标准手法。

> 🔑 **一句话**：**「任意多个」不是靠循环枚举出来的，而是靠「自环 + 零次出口」两条转移递归出来的。** 这条经验可以直接迁移到 44 通配符匹配、正则引擎实现、以及一切「可重复」的 DP。

### 第五步：初值里也藏着 `*` 的零次分支

空 `s` 与 `p` 的匹配，只能靠 `*` 的零次分支：

```text
dp[0][0] = true
dp[0][j] = dp[0][j-2]  若 p[j-1] == '*'    （把「x*」整体丢弃）
dp[0][j] = false       其他情况（含 p[j-1] 是普通字符 / '.' 的情形）
```

举例 `p = "a*b*c*"`：

```text
dp[0][0]=T
j=1: p[0]='a' 非 '*' → F
j=2: p[1]='*' 且 dp[0][0]=T → T
j=3: p[2]='b' 非 '*' → F
j=4: p[3]='*' 且 dp[0][2]=T → T
j=5: p[4]='c' 非 '*' → F
j=6: p[5]='*' 且 dp[0][4]=T → T
```

而对 `p = "a*b"`：`dp[0][2]=T` 但 `dp[0][3]=F`（末尾的 `b` 需要一个字符），所以空串不能匹配 `"a*b"`。✅

## 126.3 原理拆解

### 126.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 回溯（无记忆化） | `O(2^{m+n})` 最坏 | `O(m+n)` 栈 | 18 行 | 遇到 `a*a*a*…b` 这类模式指数爆炸（ReDoS） |
| 回溯 + `(i,j)` 记忆化 | `O(mn)` | `O(mn)` | 25 行 | 递归栈深 `m+n`；`10⁵` 时栈爆 |
| **二维布尔递推** ✅ | **`O(mn)`** | **`O(mn)`** | **22 行** | `10⁴ × 10⁴` 内存 100 MB（存 `bool` 只占 1 字节，比 `int` 省 4 倍） |
| 一维滚动（两行 / 一行） | `O(mn)` | `O(n)` | 25 行 | 需要小心 `dp[i][j-2]` 与 `dp[i-1][j]` 的覆盖顺序 |
| 编译成 NFA + 子集模拟 | `O(mn)` | `O(n)` | 60 行 | 代码量最大；但**支持回溯引用、流式匹配**时是唯一正路 |
| 转为 DFA（Thompson 构造） | `O(1)` 每次查询 | 指数 | 100+ 行 | 状态数可指数爆炸；编译成本高 |

**为什么选二维递推**：`m,n ≤ 20` 时 `400` 格；即使放大到 `10³ × 10³` 也只有 `10⁶` 格。它把「`*` 的语义」压缩成两条转移，代码短到能在白板上写完 —— **这是面试最想要的形态**。

### 126.3.2 为什么这个做法是对的（正确性论证）

**命题**：`dp[m][n]` 为 true 当且仅当 `s` 整个被 `p` 匹配。

**（1）转移的分类完备且互斥。** 固定 `(i,j)`（`i ≥ 1, j ≥ 1`），考虑任何一条「`s[0..i-1]` 被 `p[0..j-1]` 整串匹配」的对齐方案。看模式 `p` 的**最后一个元素**是什么：

- **情形 ①：`p[j-1]` 是普通字符或 `.`**（不是 `*`）。那它必须恰好吞掉 `s` 的最后一个字符 `s[i-1]`（正则模式从左到右消费，最后一个模式元素对应最后一个被消费的字符）。前提是 `s[i-1]` 与 `p[j-1]` 相容。剩余部分是 `s[0..i-2]` 被 `p[0..j-2]` 匹配。⇒ `dp[i][j] = match(s[i-1], p[j-1]) && dp[i-1][j-1]`。

- **情形 ②：`p[j-1] == '*'`**，此时模式末尾是「`x*`」，其中 `x = p[j-2]`。`x*` 在匹配中消费了 `k ≥ 0` 个字符（一定是从 `s` 的末尾连续往前数的 `k` 个：`s[i-k..i-1]`）。
  - **子情形 ②-a：`k = 0`**。整个「`x*`」被丢弃，`s[0..i-1]` 必须被 `p[0..j-3]` 匹配（即下标 `j-2` 前缀）。⇒ 候选 `dp[i][j-2]`。
  - **子情形 ②-b：`k ≥ 1`**。先看最后一个被消费的字符 `s[i-1]`，它必须被 `x` 匹配。把它摘掉之后，模式仍然是「`... x*`」，`s` 少了最后一个字符，于是剩下的是 `dp[i-1][j]` 这个子问题。⇒ 候选 `dp[i-1][j]`。
  
  两种子情形按 `k = 0` 与 `k ≥ 1` 划分，**互斥且完备**（`k` 是非负整数，要么 0 要么 ≥1）。所以 `dp[i][j] = dp[i][j-2] || dp[i-1][j]`。

- `p` 的最后一个元素不可能是别的（只有「普通字符 / `.` / `*`」三种），所以两种情形覆盖全部。

**（2）归纳**。以 `i+j` 递增的顺序归纳：所有 `dp[i'][j']`（`i'+j' < i+j`）已正确。情形 ① 用的是 `dp[i-1][j-1]`（和少 2）；情形 ② 用的是 `dp[i][j-2]`（和少 2）与 `dp[i-1][j]`（和少 1）。都在归纳假设覆盖范围内。

**（3）初值**。`dp[0][0] = true`（空对接空模式）。`dp[0][j]`：`s` 为空，只能靠「`x*` 吃零个」逐步跳跃 ⇒ `dp[0][j] = dp[0][j-2]` 当 `p[j-1]=='*'`，否则 false。这与情形 ② 的 ②-a 分支在 `i = 0` 时的行为完全一致。`dp[i][0] = false`（`i ≥ 1`）：非空串无法被空模式匹配。∎

> ⚠️ **一个必须说清的点**：为什么「`k ≥ 1` 时模式一位都不前进」还能收敛？因为**每次应用这条转移，`i` 都减 1**。`i` 有下界 0，所以「吃 k 个」最多迭代 `i` 次就停 —— 自环不会产生无限递归。**这正是 DP 与「死循环」的区别：状态 `(i,j)` 上必须有某个量严格单调递减。**

### 126.3.3 通用解题思路（可迁移的那一层）

本题属于 **「模式匹配 = 自动机可达性」** 模型。把它抽象出来有三层：

```text
第 1 层（语言层）：正则表达式描述一个字符集；匹配 = 判断 s 是否属于该语言
第 2 层（自动机层）：把模式编译成 NFA —— 每个模式位置是一个状态
                     · 普通字符 c：j --c--> j+1
                     · '.'      ：j --任意--> j+1
                     · 'x*'     ：j --ε--> j+2 （零次）；j+1 --x--> j+1（自环，多次）
第 3 层（DP 层）：dp[i][j] = 「s 的前 i 个字符」能否把 NFA 带到状态 j
                 = 在 (i, j) 这张二维表上做「可达性传播」
```

一旦用 NFA 的眼光看，转移式就**不需要背**了：`dp` 表的每一格就是自动机的一个「格局」，转移来自 NFA 的边。

**与 44 通配符匹配的对比**（这是最常被追问的一组）：

| 维度 | LC 10 正则匹配（本题） | LC 44 通配符匹配 |
| --- | --- | --- |
| `*` 的含义 | 修饰**前一个**字符，表示「前一个字符重复 0+ 次」 | **独立**字符，匹配**任意长度**的串（含空） |
| `?` | 无（`.` 承担「单字符」） | `?` 匹配任意单个字符 |
| 转移里的「多次」分支 | `dp[i][j] = dp[i][j-2] (零次) 或 dp[i-1][j] (多次，字符须相容)` | `dp[i][j] = dp[i-1][j] (吃一个) 或 dp[i][j-1] (空匹配)` |
| 「零次」怎么表达 | 跳过 2 个模式字符（`j-2`） | 跳过 1 个模式字符（`j-1`） |
| 空串初值 | `p` 形如 `a*b*c*` 时可为 true | `p` 形如 `*` 或 `***` 时可为 true |

> 🔑 **牢记这个差异**：本题的 `*` **必须和前一个字符绑定**，所以永远跳 `j-2`；44 题的 `*` 是独立符号，永远跳 `j-1`。**面试里把这两题的 `*` 混为一谈是最常见的失分点。**

### 126.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 支持 `'+'`（1 次或多次）与 `'?'`（0 或 1 次） | 量词变多 | `+`：`dp[i][j] = dp[i-1][j-1] 或 dp[i-1][j]`（至少一次）；`?`：`dp[i][j] = dp[i][j-2] 或 dp[i-1][j-1]` |
| 支持字符类 `[a-c]` | 单字符判定变复杂 | 只改 `match(c, p[j-1])` 这一个函数，**转移结构完全不变** |
| 要**找出所有匹配位置**（`findAll`） | 从整串匹配变子串搜索 | 在外层对每个起点跑一次；或用 NFA 模拟并在每步检查「是否到达终态」 |
| **流式输入**（字符一个一个来） | 不能预知 `m` | 只保留一行 `dp`，边读边推进 —— NFA 模拟天然支持 |
| 要求**回溯引用** `\1` | 正则语言之外 | DP 失效（不再是正则语言），必须用带回溯的引擎（性能无保证） |
| 输入规模 `10⁵` 且模式固定 | 每次查询都要 `O(mn)` | 把模式编译成 DFA（Thompson + 子集构造），每次查询 `O(m)`；编译成本一次性 |

**一维滚动的关键（Go 版，展示覆盖顺序）**：

```go
package main

func isMatchRolling(s string, p string) bool {
	m, n := len(s), len(p)
	// 需要「当前行」与「上一行」两行，因为转移同时用到 dp[i][j-2]（本行）与 dp[i-1][j]（上一行）
	prev := make([]bool, n+1)
	cur := make([]bool, n+1)

	// 第 0 行：空 s 与 p 的前缀匹配（见 §126.2 第五步）
	prev[0] = true
	for j := 2; j <= n; j++ {
		if p[j-1] == '*' && prev[j-2] {
			prev[j] = true
		}
	}

	for i := 1; i <= m; i++ {
		cur[0] = false // 非空 s 不能匹配空模式
		for j := 1; j <= n; j++ {
			if p[j-1] == '*' {
				// 零次：本行 j-2；多次：上一行 j
				zero := j >= 2 && cur[j-2]
				one := j >= 2 && (p[j-2] == '.' || p[j-2] == s[i-1]) && prev[j]
				cur[j] = zero || one
			} else {
				cur[j] = (p[j-1] == '.' || p[j-1] == s[i-1]) && prev[j-1]
			}
		}
		prev, cur = cur, prev // 交换两行，cur 变成「可覆盖的垃圾区」
	}
	return prev[n]
}
```

### 126.4.3 `*` 两支的逐步拆解（本章最重要的一张推演表）

以 `s = "aab"`, `p = "c*a*b"` 的 `dp[3][5]` 为例，把「多次」这条自环走到底：

```text
目标：s[0..2] = "aab" 能否被 p[0..4] = "c*a*b" 匹配？

step 1  p 的末尾是 'b'（普通字符）→ 看左上：dp[2][4] 且 s[2]=='b'
        dp[2][4]：s[0..1]="aa" 能否被 "c*a*" 匹配？
          step 2  p 末尾是 '*'，x = p[3] = 'a'
                  多次分支：dp[1][4] 且 s[1]=='a'
                  dp[1][4]：s[0..0]="a" 能否被 "c*a*" 匹配？
                    step 3  多次分支：dp[0][4] 且 s[0]=='a'
                            dp[0][4]：空串能否被 "c*a*" 匹配？
                              step 4  多次分支：s 已空，走不通
                                       零次分支：dp[0][2] —— 空串能否被 "c*" 匹配？
                                         step 5  'c*' 零次：dp[0][0] = T  ⇒ dp[0][2]=T
                                       ⇒ dp[0][4] = T      （"c*a*" 全吃零次）
                            ⇒ dp[1][4] = T                （a* 吃 1 个 a）
                  ⇒ dp[2][4] = T                          （a* 吃 2 个 a，自环走两次）
        ⇒ dp[3][5] = T 且 'b'=='b' ⇒ 【true】              🎉

结论："c*" 吃 0 个、"a*" 吃 2 个、"b" 吃 1 个 —— 每一步都在表里留下痕迹
```

> 🔎 **看图的方式**：`dp[i][4]` 这一列（对应 `"a*"`）从 `(0,4)` 到 `(2,4)` 一路 T 下去，就是**自环连续走了 3 次**（吃 0、1、2 个 a）。**同一列连续为 T，是「多次分支」在视觉上的签名。**

### 126.4.4 三个反例的轨迹

```text
❌ ① ("", "a*")  —— 若 dp[0][j] 初始化漏掉
   正确：dp[0][2] = dp[0][0] = T  →  true
   错误：dp[0][*] 全 F           →  false   （漏掉「零次」的初值）

❌ ② ("a", "ab*")  —— 若 'b*' 的零次分支没写
   正确：dp[1][3] 可由 dp[1][1](=T) 得到 → true
   错误：只剩多次分支，'b' 与 'a' 不相容 → false

❌ ③ ("aaa", "a*a")  —— 若多次分支错写成 dp[i-1][j-2]
   正确：
     dp[1][2]=T, dp[2][2]=T, dp[3][2]=T   （a* 吃 0/1/2/3 个）
     dp[3][3] = dp[2][2] 且 'a'=='a' = T  → true
   错误（多次分支用 j-2）：
     dp[2][2] = dp[1][0] 且相容 = F       （只允许吃一个，链断了）
     dp[3][2] = F  →  dp[3][3] = F        → false
```

第 ③ 条精确指出「自环」的价值：**`dp[i-1][j-2]` 只能吃一个，`dp[i-1][j]` 能吃任意个。**

## 126.5 双语言实现

### 126.5.1 Java

```java
class Solution {
    public boolean isMatch(String s, String p) {
        int m = s.length(), n = p.length();

        // dp[i][j] = s 的前 i 个字符能否被 p 的前 j 个字符整串匹配
        // 布尔表比 int 表省 4 倍内存；本题规模小，但这个习惯在 10^3 量级有用
        boolean[][] dp = new boolean[m + 1][n + 1];
        dp[0][0] = true;

        // 空 s 只能靠「x* 吃零次」一步步跳过：这是零次分支在初值上的体现
        // 注意必须判 p[j-2] == '*'（写成 p[j-1] 会把 "a*b" 也判成能匹配空串）
        for (int j = 2; j <= n; j++) {
            if (p.charAt(j - 1) == '*' && dp[0][j - 2]) {
                dp[0][j] = true;
            }
        }
        // dp[i][0] (i >= 1) 保持 false：非空串无法被空模式匹配

        for (int i = 1; i <= m; i++) {
            char sc = s.charAt(i - 1);
            for (int j = 1; j <= n; j++) {
                char pc = p.charAt(j - 1);

                if (pc == '*') {
                    // 到目前为止模式是 "... x *"，x = p[j-2]
                    char x = p.charAt(j - 2);

                    // 分支一（零次）：x* 整个丢掉，s 不消耗 ⇒ 看【本行】j-2
                    boolean zero = dp[i][j - 2];

                    // 分支二（多次）：先吃掉 s[i-1]（须与 x 相容），模式留在 j
                    // ⇒ 看【上一行】同一列。这样通过多次转移即可表达「吃 k 个」
                    boolean more = (x == '.' || x == sc) && dp[i - 1][j];

                    dp[i][j] = zero || more;
                } else {
                    // 普通字符或 '.'：必须吃一个 s 字符，双双前进 ⇒ 看【左上】
                    boolean ok = (pc == '.' || pc == sc);
                    dp[i][j] = ok && dp[i - 1][j - 1];
                }
            }
        }
        return dp[m][n];
    }
}
```

### 126.5.2 Go

```go
package main

func isMatch(s string, p string) bool {
	m, n := len(s), len(p)

	// 与 Java 版逐行同构。Go 的 bool 二维切片同样逐行 make
	dp := make([][]bool, m+1)
	for i := range dp {
		dp[i] = make([]bool, n+1) // 零值 false：省掉 dp[i][0] = false 的显式赋值
	}
	dp[0][0] = true

	// 空 s 的初始化：只认「x* 吃零次」
	for j := 2; j <= n; j++ {
		if p[j-1] == '*' && dp[0][j-2] {
			dp[0][j] = true
		}
	}

	for i := 1; i <= m; i++ {
		sc := s[i-1]
		for j := 1; j <= n; j++ {
			pc := p[j-1]
			if pc == '*' {
				x := p[j-2]
				zero := dp[i][j-2] // 零次：本行左两格
				more := (x == '.' || x == sc) && dp[i-1][j] // 多次：上一行同列（自环）
				dp[i][j] = zero || more
			} else {
				ok := pc == '.' || pc == sc
				dp[i][j] = ok && dp[i-1][j-1]
			}
		}
	}
	return dp[m][n]
}
```

### 126.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 布尔二维表 | `new boolean[m+1][n+1]`，默认 `false` | `make([][]bool, m+1)` + 逐行 `make`，默认 `false` | 都要记得 `dp[0][0] = true`，其余零值正好是「不可达」 |
| 逻辑运算短路 | `&&` / `\|\|` 短路 | `&&` / `\|\|` 同样短路 | 都依赖短路避免「先算右边再判左边」；但**不要把下标越界的表达式放在右侧**（如 `p[j-2]` 在 `j=1` 时） |
| 越界风险点 | `p.charAt(j-2)` 在 `j == 1` 时抛异常 | `p[j-2]` 在 `j == 1` 时 panic / 得到错误字节（负数下标直接 panic） | 本题保证模式合法（`*` 不会出现在开头），所以 `pc == '*'` 时必有 `j ≥ 2`；但**对拍造数据时要排除非法模式**，或在代码里加 `j >= 2` 防御 |

| 空串 | `"".length() == 0` | `len("") == 0`；`nil` 字符串同理 | 两边都靠 `dp[0][*]` 处理，不需要特判 `m == 0` |

### 126.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：把模式拆成 token 列表，然后【显式枚举每个 * 的重复次数】
// 这是与 DP 完全不同的结构：DP 用「自环」隐式表达 k 次，暴力用循环显式枚举 k
func matchBrute(s, p string) bool {
	type tok struct {
		ch   byte // 普通字符或 '.'
		star bool // 后面是否跟着 '*'
	}
	var toks []tok
	for j := 0; j < len(p); j++ {
		if p[j] == '*' {
			toks[len(toks)-1].star = true // 与前一 token 绑定
		} else {
			toks = append(toks, tok{ch: p[j]})
		}
	}

	eq := func(a byte, t tok) bool { return t.ch == '.' || t.ch == a }

	var dfs func(ti int, si int) bool
	dfs = func(ti int, si int) bool {
		if ti == len(toks) {
			return si == len(s) // 模式用完，s 也必须用完
		}
		t := toks[ti]
		if !t.star {
			if si < len(s) && eq(s[si], t) {
				return dfs(ti+1, si+1)
			}
			return false
		}
		// 枚举这个 token 吃多少个字符：0 个、1 个、2 个 …… 直到不匹配
		k := 0
		for {
			if dfs(ti+1, si+k) {
				return true
			}
			if si+k >= len(s) || !eq(s[si+k], t) {
				break // 再多吃一个就吃不下了
			}
			k++
		}
		return false
	}
	return dfs(0, 0)
}

func TestIsMatch(t *testing.T) {
	// LeetCode 官方样例 + 自造边界（含空串、* 连续、a* 收尾）
	type tc struct {
		s, p string
		want bool
	}
	cases := []tc{
		{"aa", "a", false},
		{"aa", "a*", true},
		{"ab", ".*", true},
		{"aab", "c*a*b", true},
		{"mississippi", "mis*is*p*.", false},
		{"", "a*", true},
		{"", "a*b*c*", true},
		{"", ".*", true},
		{"", "a", false},
		{"a", "ab*", true},
		{"ab", ".*c", false},
		{"aaa", "a*a", true},
		{"aaa", "ab*a*c*a", true},
		{"abcd", "d*", false},
		{"bbbba", ".*a*a", true},
	}
	for _, c := range cases {
		if got := isMatch(c.s, c.p); got != c.want {
			t.Fatalf("s=%q p=%q got=%v want=%v", c.s, c.p, got, c.want)
		}
		if got := matchBrute(c.s, c.p); got != c.want {
			t.Fatalf("brute s=%q p=%q got=%v want=%v", c.s, c.p, got, c.want)
		}
	}

	r := rand.New(rand.NewSource(101010))
	for iter := 0; iter < 20000; iter++ {
		// 随机生成 s
		ls := r.Intn(7) // 0..6
		sb := make([]byte, ls)
		for i := range sb {
			sb[i] = byte('a' + r.Intn(2)) // 只用 {a,b}：让 '.' 与 '*' 的效果明显
		}
		// 随机生成【合法】模式：每个 token 是 (a|b|.) 可选地跟一个 '*'
		var pb []byte
		for k := 0; k < 1+r.Intn(5); k++ {
			pb = append(pb, []byte{'a', 'b', '.'}[r.Intn(3)])
			if r.Intn(2) == 0 {
				pb = append(pb, '*') // 允许连续出现 a*b*，覆盖「连续量词」边界
			}
		}
		s, p := string(sb), string(pb)
		want := matchBrute(s, p)
		if got := isMatch(s, p); got != want {
			t.Fatalf("iter=%d s=%q p=%q got=%v want=%v", iter, s, p, got, want)
		}
	}
}
```

> 📌 **随机生成的两个要点**：
> ① **模式必须由 token 生成，不能逐字符随机** —— 否则会出现 `*` 在开头、连续 `**` 这类**非法模式**，而 LeetCode 保证不出现，测它们只会引入噪声。我用「先出字符、再决定要不要加 `*`」的生成器，天然保证合法性，同时能造出 `a*b*c*` 这种连续量词。
> ② **`*` 出现的概率设成 1/2**：量词是本题唯一的难点，出现率太低就测不到。

## 126.6 复杂度与常见坑

### 126.6.1 复杂度推导（写结论不算本事，要能推）

- **DP 时间 `O(mn)`**：`(m+1)(n+1)` 个格子，每格常数次比较与逻辑运算。`m = n = 20` 时 `441` 格；放大到 `10³` 也只有 `10⁶` 格。
- **DP 空间 `O(mn)`**：`boolean` 表 `1000×1000` 约 1 MB（Java 的 `boolean` 在数组中占 1 字节）。滚动两行可降到 `O(n)`。
- **回溯的时间上界 `O(2^{m+n})`**：每个 `*` 处两个分支（零次 / 一次），深度 `m+n`。构造最坏输入的标准配方是 `s = "a"*k`, `p = "a*"*(k) + "b"`：每个 `a*` 都要做一次「吃/不吃」的选择，组合数指数级。**这就是 ReDoS（正则拒绝服务）的经典形态**，Java / Python / JS 的引擎历史上都因此打过补丁（加上回溯步数上限）。
- **为什么 DP 不会指数**：回溯的问题是**同一 `(i,j)` 被多次求值**；DP 把它变成「每个 `(i,j)` 只算一次」。**这也是「记忆化」这个名字的字面意思。**
- **NFA 模拟（非 DP）也是 `O(mn)`**：每读一个 `s` 字符，对 `n` 个状态做一次 ε-闭包传播。与 DP 等价，只是内存 `O(n)`，且天然支持流式输入。

### 126.6.2 八个真实踩过的坑

1. **`dp[0][j]` 的初始化漏掉「链式」** —— 只写 `dp[0][1]` 或只写 `dp[0][2]`，`"a*b*c*"` 匹配空串会错。必须 `for j = 2..n` 递推，且判的是 `p[j-1]=='*'` 与 `p[j-2]`（`x`）。
2. **多次分支写成 `dp[i-1][j-2]`** —— 只能吃一个，`"aaa"` vs `"a*a"` 会错。**必须是 `dp[i-1][j]`（自环）。**
3. **`*` 的零次分支写成 `dp[i][j-1]`** —— `j-1` 停在 `*` 自己身上，`x*` 里的 `x` 没被丢弃，逻辑不闭合。**必须是 `j-2`。**
4. **把 `.` 当「任意长度」** —— `"ab"` vs `".b"` 会被判成 true。`.` 只吃一个字符，`.*` 才是任意串。
5. **忘记「整串匹配」** —— 若把 `dp[0][j]` 里任意一列置 true 当「可以从这里开始」，`"xa"` vs `"a"` 会错。本 DP 的初值只允许「模式自己吃零次」，不允许「`s` 跳过前缀」。
6. **模式不合法时越界** —— `p = "*a"` 或 `p = "a**"`：`p[j-2]` 在下标 `-1`，Java 抛异常、Go panic。LeetCode 保证不出现，但**自己造对拍数据时必须过滤**（本章的生成器就是为此设计的）。
7. **在 `j == 1` 时访问 `p[j-2]`** —— 只有当 `p[0] == '*'` 才会发生（非法模式）。加一句 `j >= 2` 防御更稳。
8. **递归记忆化里把 `false` 当成「未计算」** —— `memo` 必须用三态（未访问 / true / false），用 `boolean[]` 默认 `false` 会把「算过且为 false」误当成「没算过」，退化成指数。**用 `int[]`：0 未算、1 true、-1 false。**

### 126.6.3 面试官最爱追问的三个问题

**Q1：`*` 的「多次」为什么用 `dp[i-1][j]` 而不是 `dp[i-1][j-1]`？**

> 「因为 `x*` 吃一个字符之后，**模式本身没有前进** —— `x*` 依然可以继续吃。`dp[i-1][j]` 正好表达『`s` 少一个字符、模式还在同一个位置』，这就是自环。通过反复应用这条转移，可以覆盖吃 2 个、3 个…… 的所有情形。如果用 `dp[i-1][j-2]`，那就只允许吃一个，`"aaa"` vs `"a*a"` 立刻错。」

**Q2：这题和 LC 44 通配符匹配有什么区别？**

> 「核心区别是 `*` 的绑定对象。本题的 `*` 修饰**前一个字符**，所以『零次』是跳过 **2** 个模式字符（`j-2`），且要吃字符时必须与 `x = p[j-2]` 相容。LC 44 的 `*` 是**独立符号**，表示任意长度串，所以『零次』只跳过 **1** 个模式字符（`j-1`），且不需要判相容。把这两题的 `j-2` / `j-1` 混用是最常见的失分点。」

**Q3：如果 `s` 有 10 万个字符、模式固定，怎么做？**

> 「两条路。① 只保留两行 `dp`（或一行 + 上一行同列的暂存），边读边推进，空间 `O(n)`、时间 `O(mn)`，`10⁵ × 20 = 2·10⁶` 次操作完全可行。② 把模式编译成 NFA 并做 ε-闭包模拟：每个字符只花 `O(n)`，且天然支持**流式**输入（不需要知道 `m`）。若模式要复用几十万次，就再往前一步做子集构造转 DFA，每次查询 `O(m)`，代价是编译期状态数可能指数增长。」

## 附：本章小结（可背走的三句话）

```text
① `*` 拆两支：零次 ⇒ dp[i][j-2]（本行左两格）；多次 ⇒ 相容且 dp[i-1][j]（上一行同列，自环）
② 自环是「任意多个」的唯一正确表达方式；写成 dp[i-1][j-2] 就只能吃一个
③ 初值是零次分支的延伸：dp[0][j] = dp[0][j-2]（p[j-1]=='*'），且必须判 p[j-1] 而不是 p[j-2]
```
