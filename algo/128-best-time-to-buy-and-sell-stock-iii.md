## 128.1 题目

**原题链接**：<https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/>

### 题意重述（把隐含条件补齐）

给你 `prices`，**最多完成两笔交易**（同一时间最多持有一股：必须先卖掉再买），求最大总利润。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **最多**两笔，不是恰好两笔 | 「at most two transactions」 | 若强制两笔，`[7,6,4,3,1]` 会返回负数 |
| **同一时间最多持一股** | 「you must sell the stock before you buy again」 | 若允许重叠（可同时持两股），`[1,2,3,4]` 会答「(2−1)+(4−3)=2」还是 3？—— 允许重叠时「买 1 卖 4、买 1 卖 4」这种叠仓会让答案虚高 |
| 两笔之间**不允许同日结算两次** | 题面未明说，但「先卖后买」隐含 | 同日买卖利润为 0，无害；但不能「同日既结束第 1 笔又当作第 2 笔的买入」来骗次数（其实也只用 0 次利润，无害） |
| 无利润返回 **0** | 「If you cannot achieve any profit, return 0」 | 初值写 `-inf` 会答负 |
| `k = 2` 是**写死的** | 约束 | 面试必问「改成 `k` 笔怎么办」→ 188（§128.3.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= prices.length <= 10^5` | 十万 | `O(n·k)` 且 `k = 2` ⇒ **`O(n)` 量级**，能过；`O(n²)`（枚举两笔的四个端点）是 `10^10`，必死 |
| `0 <= prices[i] <= 10^5` | 非负 | 利润上界 `2·10^5`，`int` 安全 |
| `k = 2` 固定 | 常数 | 常数维度 ⇒ 空间 `O(1)`（只有 6 个变量：`c = 0,1,2` × 2 状态） |
| 无取模 | — | 不需要 `long`；但 188 的 `k` 可到 `10^9` 级别（题面 `k ≤ 100`，思想上是 `k ≥ n/2` 的退化） |

> 💡 **量级 → 算法**：`n = 10^5` + 「两笔交易」= `O(nk)`。注意 `k` 是常数，所以**空间可以压到 `O(k)`（= `O(1)`）**，这是本题的隐藏加分点。

### 示例

```text
输入：prices = [3,3,5,0,0,3,1,4]
输出：6
解释：第 4 天买（0）、第 6 天卖（3）赚 3；第 7 天买（1）、第 8 天卖（4）赚 3；共 6
     注意不能贪心「只吃最大的一段」（那会得到 4）

输入：prices = [1,2,3,4,5]
输出：4
解释：最多两笔，但只用一笔「1 买 5 卖」就赚 4（多于两笔也没用）

输入：prices = [7,6,4,3,1]
输出：0
解释：一直跌，不交易
```

### 我自造的六个反例（写完解法必须拿它们打一遍）

```text
① [1]                   → 只有一天：0
② [1,2]                 → 最小可交易：1
③ [7,6,4,3,1]           → 单调递减：0（检验「最多」而不是「恰好」）
④ [1,2,3,4,5]           → 单边上涨：4（两笔不如一笔，检验「额度浪费」的处理）
⑤ [3,3,5,0,0,3,1,4]     → 两段收益：6（本题的分水岭样例）
⑥ [1,2,4,2,5,7,2,4,9,0] → 三段收益，只能取两段：正确答案 13（(7−1)+(9−2)）
```

第 ④ 条最关键：**「最多两笔」意味着少用一笔也可以**。如果状态机把「用满两笔」当成必经之路，就会在单边上涨的输入上少算或多算。这个语义要么靠「状态 0 初值为 0」来保证，要么靠「按 `c` 递增处理、让额度自然继承」来保证（§128.3.2 会讲清）。

## 128.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举四个端点

「两笔交易」= 选 `i₁ < j₁ ≤ i₂ < j₂`，利润 `(p[j₁]−p[i₁]) + (p[j₂]−p[i₂])`。再加上「只做一笔」和「不做」。

- 时间 **`O(n⁴)`**：`n = 10^5` 时 `10^20`，彻底不可能。
- 即使优化成「枚举分割点 + 左右各求一次单笔最优」（`O(n²)` 或 `O(n)` 预处理后 `O(n)`），也需要先想清楚「分割点」这件事 —— 那是另一条路（见 §128.3.1 的「前后缀分解」方案）。

### 第二步：`O(n)` 的经典暴力优化 —— 前后缀分解

固定「第一笔结束 / 第二笔开始」的分割点 `d`：

```text
答案 = max over d of ( leftMax[d] + rightMax[d] )
leftMax[d]  = 在 prices[0..d] 上做【一笔】交易的最大利润（127 题）
rightMax[d] = 在 prices[d..n-1] 上做【一笔】交易的最大利润（127 题的镜像）
```

- 时间 `O(n)`：两次 127 的扫描（一次正、一次反）+ 一次合并。
- 空间 `O(n)`。

**它是对的**，而且很优雅。但它有一个致命缺点：**只适用于 `k = 2`**。`k = 3` 就要二维分割，`k` 一般化后复杂度变 `O(n^k)`。这正是本节要建立状态机的原因 —— **需要一种「`k` 只是参数」的建模**。

### 第三步：卡点 —— 「第几笔」不是一个能靠下标表达的量

127 题的 `hold / free` 两个状态能工作，是因为「只允许一笔」时 `hold` 的候选永远是 `-p`。现在允许两笔，`hold` 的候选变成「**卖完第一笔之后的现金 − 今天的价格**」。于是光有 `hold/free` 不够了 —— 必须知道「**已经用掉几笔**」。

> **卡点：状态里缺少「已用额度」这个维度。**

### 第四步：灵感的来源 —— 把交易次数加进状态

定状态：

```text
dp[c][0] = 已用「至多 c 次交易」的额度、当前【不持有】股票时，手上的最大现金
dp[c][1] = 已用「至多 c 次交易」的额度、当前【持有】股票时，手上的最大现金
c ∈ [0, K]，K = 2
```

- `dp[c][0]` 的初值是 **0**（什么都不做），`dp[c][1]` 的初值是 **−∞**（不允许凭空持有）。
- 每天的转移：

```text
买入（不持有 → 持有，消耗 1 次额度）：
    dp[c][1] = max( dp[c][1],  dp[c-1][0] − p )
                              └──────────┘
                              用「至多 c-1 次」的钱，再买入

卖出（持有 → 不持有，不消耗新额度）：
    dp[c][0] = max( dp[c][0],  dp[c][1] + p )
```

- 答案 `dp[K][0]`。

**为什么「买入」消耗额度而「卖出」不消耗？** 因为「一笔交易」= 一次买 + 一次卖。把额度记在「买入」这个动作上，就能保证「卖的次数 ≤ 买的次数 ≤ K」，从而交易笔数 ≤ K。

### 第五步：为什么 `c` 要**递增**遍历（这是本题最容易写错的地方）

`dp[c][1]` 的转移要用 `dp[c-1][0]`。如果 `c` 递增遍历：

```text
c = 1: dp[1][1] = max(dp[1][1], dp[0][0] − p)     ← dp[0][0] = 0，永远是「还没赚钱」
       dp[1][0] = max(dp[1][0], dp[1][1] + p)     ← 用【刚才更新过的】dp[1][1]
c = 2: dp[2][1] = max(dp[2][1], dp[1][0] − p)     ← 用的是【今天刚卖出】的 dp[1][0]
       dp[2][0] = max(dp[2][0], dp[2][1] + p)     ← 用今天刚买入的 dp[2][1]
```

这样写会允许「**同一天卖出第一笔、再买入第二笔、再卖出**」。听起来像作弊，但它在数学上是**无害的**：

- 「同一天卖出又买入」在同一个价格 `p` 上发生，净收益 `(p) − (p) = 0`；
- 它唯一的效果是把 `dp[c-1][0]` 的值**原样传递**给 `dp[c][0]`，也就是保证 **`dp[c][0] ≥ dp[c-1][0]`（额度单调性）**。

而额度单调性正是「**最多** c 笔」这个语义所需要的：允许少用额度。**所以「同一天买卖」这个看似违规的动作，恰好是让状态机自动满足「至多」语义的装置。**

> ⚠️ **另一种写法（禁用同日）**：如果坚持「同日不能既卖又买」，就必须用**倒序** `c`（或暂存上一轮的值），并且**答案要取 `max over c of dp[c][0]`**，否则「只用一笔更优」的情形会丢。两种写法都对，但递增写法更短、更不容易错 —— **只要你能说清「为什么同日买卖无害」**。

## 128.3 原理拆解

### 128.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举四个端点 | `O(n⁴)` | `O(1)` | 12 行 | `n ≥ 100` 就废，只能对拍 |
| **前后缀分解**（左右各一次 127） | `O(n)` | `O(n)` | 25 行 | **只适用于 `k = 2`**；推广到 `k` 笔要 `O(n^k)` 或 `O(kn²)` |
| **状态机 DP（`dp[c][0/1]`）** ✅ | **`O(nK)`** | **`O(K)`** | **15 行** | `K` 很大时内存/时间线性增长（但 `K ≥ n/2` 可退化为无限次交易） |
| 状态机 + 4 变量展开（`buy1/sell1/buy2/sell2`） | `O(n)` | `O(1)` | 12 行 | 可读性差；`k` 一变就要重写，**不推荐作为首选** |
| 状态机 + `dp[i][c][s]` 三维表 | `O(nK)` | `O(nK)` | 15 行 | 空间浪费；本题 `n = 10^5` 时 `10^5 × 3 × 2` 个 `int` = 2.4 MB，尚可但没必要 |

**为什么选「状态机 + 滚动」**：`K = 2` 时只有 6 个变量；代码与 188（`K` 笔）**完全同一份**，只把 `2` 换成参数。这种「`k` 只是参数」的性质，是判断「你写的到底是不是状态机」的标志。

### 128.3.2 为什么这个做法是对的（正确性论证）

**命题**：算法返回 `max{0, max over 至多 K 笔不重叠交易的利润和}`。

**（1）状态语义的归纳。** 先明确 `dp[c][s]` 在「处理完前 `i` 天之后」的语义：
- `dp[c][0]` = 「用至多 `c` 笔交易、第 `i` 天收盘时不持股」的最大现金；
- `dp[c][1]` = 「用至多 `c` 笔交易、第 `i` 天收盘时持股」的最大现金（成本已扣）。

**（2）转移的完备性。** 第 `i` 天只有三种选择：不操作、买入、卖出。

- **不操作**：`dp[c][s]` 原值保留（转移里的 `max(dp[c][s], …)` 第一项）。
- **买入**：昨天末必须不持股，所以现金来自 `dp[c-1][0]`（买入消耗一次额度），今天花掉 `p` ⇒ `dp[c-1][0] − p`。
- **卖出**：昨天末必须持股，即 `dp[c][1]`（当天更新前的值），今天得到 `p` ⇒ `dp[c][1] + p`。

三种选择覆盖全部可能，且每个候选都对应一个合法方案 ⇒ `dp` 不会超过最优值。

**（3）完备性（不漏）**：任何合法方案，按「每天的动作序列」逐日模拟，其现金变化完全由上面三种动作组合而成，因此必被某个 `dp[c][s]` 覆盖。归纳即得 `dp[c][s]` 恰为最优值。

**（4）「至多 c 笔」语义的保证**（本题关键）：需要证明 `dp[c][0] ≥ dp[c-1][0]`（额度不强制用完）。
- 在**递增 c + 原地更新**的写法下，同一天内 `dp[c][1]` 先被更新为 `dp[c-1][0] − p`（用的是当天已更新的 `dp[c-1][0]`），随后 `dp[c][0] = max(dp[c][0], dp[c][1] + p) ≥ dp[c-1][0] − p + p = dp[c-1][0]`。所以「同日卖出再买入」这一条零收益路径保证了单调性。∎
- 在**倒序 c** 的写法下不会自动继承，因此必须让答案取 `max_c dp[c][0]`。

**（5）初值**：`dp[c][0] = 0`（不交易，现金 0），`dp[c][1] = −∞`（不能凭空持股）。用 `−∞` 而不是 `−prices[0]`，是为了让「第一天买入」这件事**只能通过转移发生**，避免初值里偷偷允许「多买几次」。∎

> ⚠️ **`−∞` 的实现细节**：不要用 `Integer.MIN_VALUE`，因为转移里有 `dp[c-1][0] − p` 与 `dp[c][1] + p`，`MIN_VALUE + p` 会**溢出回正**变成大正数，答案直接错。标准做法是用 `Integer.MIN_VALUE / 2`（约 `−10⁹`），它足够小又不会在加减时溢出。

### 128.3.3 通用解题思路（可迁移的那一层）

本题是 **「状态机 DP」** 模型的标准范例：把「决策过程」压成「有限个状态 + 转移」，把「资源约束」压成「状态的额外维度」。

```text
① 找出过程里的「状态」：持有 / 不持有（本题）、冷冻 / 可买（129）、是否已卖出（309）
② 找出「资源/约束维度」：可用交易次数 c、手续费、是否持有（仓位）
③ 每天枚举「动作」：不动、买、卖 —— 每个动作必须来自一个合法的前一状态
④ 状态数 = 状态 × 资源维度 ⇒ 时间 O(n · 状态数)，空间可滚动到 O(状态数)
```

**股票系列全表**（把它们当同一道题的不同参数）：

| 题 | 状态 | 资源维度 | 转移差异 |
| --- | --- | --- | --- |
| [LC 121](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/) | 2 | 无（只买一次） | `hold = max(hold, −p)` |
| [LC 122](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-ii/) | 2 | 无限次 | `hold = max(hold, free − p)` |
| [LC 123](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iii/)（本题） | 2 | `c ≤ 2` | `hold(c) = max(hold(c), free(c−1) − p)` |
| [LC 188](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-iv/) | 2 | `c ≤ k` | 同本题，`K` 变参数 |
| [LC 309](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-cooldown/) | **3** | 无限次 | 卖出后当天进入 `sold`，次日才能买 |
| [LC 714](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/) | 2 | 无限次 + 手续费 | `free = max(free, hold + p − fee)` |

> 🔑 **一句话**：股票系列的六道题，**状态数最多 3，维度最多 1 个**。把这张表背下来，就再也不会「见到新变体就慌」。

### 128.3.4 可扩展性（面试追问的六个方向）—— 推广到 188

**推广规则：把 `K = 2` 换成参数 `k`，并处理 `k ≥ n/2` 的退化。**

```text
k ≥ n/2  ⇒ 交易次数不再构成约束（每次至少占 2 天，所以最多 n/2 笔）
         ⇒ 直接退化为「无限次交易」= LC 122 的 2 状态解法，O(n) 且与 k 无关
```

否则 `O(nk)` 会退化成 `O(n²)`（`k = 10^5` 时），而过大的 `k` 本身没有意义。

**LC 188 的完整实现（Java，与本题目的一模一样，只多了一个 `k` 参数与退化分支）**：

```java
class SolutionK {
    public int maxProfit(int k, int[] prices) {
        int n = prices.length;
        if (n < 2 || k == 0) return 0;

        // 退化：k 大到不可能成为约束 ⇒ 无限次交易（LC 122），O(n) 且与 k 无关
        if (k >= n / 2) {
            int free = 0, hold = Integer.MIN_VALUE / 2;
            for (int p : prices) {
                hold = Math.max(hold, free - p);   // 无限次：买入的钱可以来自已实现利润
                free = Math.max(free, hold + p);
            }
            return free;
        }

        final int NEG = Integer.MIN_VALUE / 2;     // 不用 MIN_VALUE：避免 +p 溢出回正
        int[][] dp = new int[k + 1][2];            // dp[c][0] 不持有 / dp[c][1] 持有
        for (int c = 0; c <= k; c++) {
            dp[c][1] = NEG;
        }
        for (int p : prices) {
            // c 递增：同一天「卖出第 c-1 笔 + 买入第 c 笔」的零收益衔接，
            // 保证 dp[c][0] >= dp[c-1][0]，即「至多 c 笔」而不是「恰好 c 笔」
            for (int c = 1; c <= k; c++) {
                dp[c][1] = Math.max(dp[c][1], dp[c - 1][0] - p);
                dp[c][0] = Math.max(dp[c][0], dp[c][1] + p);
            }
        }
        return dp[k][0];
    }
}
```

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| `k` 笔（LC 188） | 参数化 | 上面这段代码；注意 `k ≥ n/2` 的退化 |
| 「**恰好** k 笔」而不是「至多」 | 语义反转 | 初始化 `dp[c][0] = NEG`（`c ≥ 1`）表示「必须完成 c 笔」；答案取 `dp[k][0]` |
| 卖出后冷冻（LC 309） | 加状态 | 三状态机（见 129） |
| 每笔手续费（LC 714） | 改系数 | 卖出项改成 `hold + p − fee` |
| 允许**做空** | 状态翻倍 | 增加 `short` 状态，`short` 与 `free` 互相转移 |
| 要**输出方案** | 记录来源 | 每格存「转移来自哪个动作」，最后回溯 |

## 128.4 图解推演

### 128.4.1 状态转移图（本题的核心图）

```text
                    买入：消耗 1 次额度，花掉 p
            ┌──────────────────────────────────────┐
            │                                      ▼
     ┌──────────────┐                        ┌──────────────┐
     │  dp[c-1][0]  │                        │   dp[c][1]   │
     │ 不持有，额度 c-1│                       │ 持有，额度 c  │
     └──────────────┘                        └──────┬───────┘
            ▲                                       │
            │                                       │ 卖出：得到 p（不消耗额度）
            │                                       ▼
     ┌──────────────┐   ←───────────────────┌──────────────┐
     │  dp[c][0]    │      卖出后回到「不持有」│  dp[c][0]    │
     │ 不持有，额度 c │ ─────────────────────→│（自环：不动） │
     └──────────────┘                        └──────────────┘

   等价的自环写法（更容易写代码）：
     dp[c][1] = max( dp[c][1],  dp[c-1][0] - p )     ← 「继续持有」或「今天买入」
     dp[c][0] = max( dp[c][0],  dp[c][1] + p )       ← 「继续不持有」或「今天卖出」
```

### 128.4.2 DP 表逐日推演（`prices = [3,3,5,0,0,3,1,4]`, `K = 2`）

```text
初始：
   c=0: (free=0, hold=-∞)
   c=1: (free=0, hold=-∞)
   c=2: (free=0, hold=-∞)

天  p    c=1 hold   c=1 free   c=2 hold   c=2 free
───────────────────────────────────────────────────
 1  3      -3         0          -3          0
 2  3      -3         0          -3          0
 3  5      -3         2          -3          2      ← 第 1 笔：3 买 5 卖
 4  0       0         2           2          2      ← 0 买（等更低价）
 5  0       0         2           2          2
 6  3       0         3           2          5      ← 第 1 笔在 5 结束(3)，第 2 笔 0→3
 7  1       0         3           2          5
 8  4       0         4           2          6      ← 第 2 笔 1 买 4 卖 ⇒ 答案 6
───────────────────────────────────────────────────
```

关键三格的来源：

```text
第 6 天 (c=2, free) = 5：
    dp[2][1] + p = 2 + 3 = 5     ← dp[2][1]=2 是「0 那天买入」的成本（0 - 0 = 0？）
    实际链条：dp[1][0]（=2，3 买 5 卖的利润）→ dp[2][1] = 2 - 0 = 2（0 那天买）
             → dp[2][0] = 2 + 3 = 5（3 那天卖）

第 8 天 (c=2, free) = 6：
    第 7 天 dp[2][1] = max(2, dp[1][0] - 1 = 3 - 1 = 2) = 2
    dp[2][0] = max(5, 2 + 4) = 6
```

### 128.4.3 与「前后缀分解」的对比图

```text
输入 prices[0..n-1]
        │
        ├───────────── 路线 A：状态机（本章）─────────────┐
        │   dp[c][0/1]，逐日推进                          │
        │   O(nK) 时间 / O(K) 空间 / 15 行                │
        │   ✅ k 是参数，直接推广到 188                    │
        │                                                 │
        └───────────── 路线 B：前后缀分解 ────────────────┐
            leftMax[i]  = 127(prices[0..i])              │
            rightMax[i] = 127(prices[i..n-1])            │
            ans = max_i (leftMax[i] + rightMax[i])       │
            O(n) 时间 / O(n) 空间 / 25 行                 │
            ✅ 常数更小、更容易讲清「两段」的几何直觉       │

```

> 🔑 **两条路都值得会**：面试里如果先讲「前后缀分解」，能立刻显示你抓住了「两段」的几何结构；再补一句「但如果 `k` 是一般参数，就必须用状态机」—— 这一句是 L5 以上的分水岭。

## 128.5 双语言实现

### 128.5.1 Java

```java
class Solution {
    public int maxProfit(int[] prices) {
        final int K = 2;
        // 用 MIN_VALUE/2 而不是 MIN_VALUE：转移里有 NEG + p，
        // MIN_VALUE + p 会溢出成一个大正数，直接毁掉答案
        final int NEG = Integer.MIN_VALUE / 2;

        // dp[c][0] = 至多 c 笔、收盘不持股的最大现金（= 已实现利润）
        // dp[c][1] = 至多 c 笔、收盘持股的最大现金（买入成本已扣）
        int[][] dp = new int[K + 1][2];
        for (int c = 0; c <= K; c++) {
            dp[c][0] = 0;    // 不交易 ⇒ 现金 0
            dp[c][1] = NEG;  // 不能凭空持股
        }

        for (int p : prices) {
            // c 必须【递增】：
            //   dp[c][1] 用当天已更新的 dp[c-1][0]，相当于允许「同一天卖出上一笔、立刻买入下一笔」。
            //   这个动作净收益为 0，唯一作用是让 dp[c][0] >= dp[c-1][0]，
            //   从而保证语义是「至多 c 笔」而不是「恰好 c 笔」。
            for (int c = 1; c <= K; c++) {
                dp[c][1] = Math.max(dp[c][1], dp[c - 1][0] - p); // 买入：花掉 p，消耗 1 次额度
                dp[c][0] = Math.max(dp[c][0], dp[c][1] + p);     // 卖出：得到 p
            }
        }
        return dp[K][0];   // 空数组 / 单日 → 返回 0
    }
}
```

### 128.5.2 Go

```go
package main

func maxProfit(prices []int) int {
	const K = 2
	const neg = -1 << 60 // 相当于 Java 的 MIN_VALUE/2：小到不会成为答案，又不会在加减时溢出

	// dp[c][0] 不持有、dp[c][1] 持有
	dp := make([][2]int, K+1)
	for c := 0; c <= K; c++ {
		dp[c][0] = 0
		dp[c][1] = neg // 不能凭空持股
	}

	for _, p := range prices {
		for c := 1; c <= K; c++ {
			// 与 Java 版逐行同构；Go 没有 Math.max，手写比较
			if v := dp[c-1][0] - p; v > dp[c][1] {
				dp[c][1] = v
			}
			if v := dp[c][1] + p; v > dp[c][0] {
				dp[c][0] = v
			}
		}
	}
	return dp[K][0]
}
```

### 128.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 「负无穷」 | `Integer.MIN_VALUE / 2` | `-1 << 60`（或用 `math.MinInt32/2`） | **两边都不能直接用最小值**：转移里有 `NEG + p`，会溢出回正。Go 的 `int` 是 64 位时 `-1<<60` 加减 `10^5` 不会溢出 |
| 常量声明 | `final int K = 2;`（方法内） | `const K = 2`（包内/函数内皆可） | 一致；Go 的 `const` 必须编译期常量，本题满足 |
| `[][2]int` vs `int[][]` | `new int[K+1][2]` 一次分配 | `make([][2]int, K+1)` 一次分配 | Go 的 `[2]int` 是**值数组**，内存连续，比 `[][]int` 快 |
| `max` | `Math.max` | 手写 `if` | 本题每格两次 max，Go 版多 6 行 |
| 溢出保护 | `long` 可用 | `int` 已是 64 位（amd64） | 但 32 位平台 Go 的 `int` 只有 32 位 —— 生产代码写 `int64` 更稳 |

### 128.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"

// 暴力参考：递归枚举「从第 i 天开始、还剩 k 笔额度」的最优解
// 与状态机的结构完全不同（它是「枚举卖出点 + 递归」，状态机是「逐日推状态」）
func profitBrute(prices []int, i int, k int) int {
	if i >= len(prices)-1 || k == 0 {
		return 0
	}
	// 选择 1：第 i 天不买，从 i+1 开始
	best := profitBrute(prices, i+1, k)
	// 选择 2：第 i 天买入，枚举卖出日 j
	for j := i + 1; j < len(prices); j++ {
		if v := prices[j] - prices[i] + profitBrute(prices, j+1, k-1); v > best {
			best = v
		}
	}
	return best
}

// 188 的通用版本（k 为参数），用来验证「本题只是 k=2 的特例」
func maxProfitK(k int, prices []int) int {
	n := len(prices)
	if n < 2 || k == 0 {
		return 0
	}
	const neg = -1 << 60
	if k >= n/2 { // 退化为无限次交易
		free, hold := 0, neg
		for _, p := range prices {
			if v := free - p; v > hold {
				hold = v
			}
			if v := hold + p; v > free {
				free = v
			}
		}
		return free
	}
	dp := make([][2]int, k+1)
	for c := 0; c <= k; c++ {
		dp[c][1] = neg
	}
	for _, p := range prices {
		for c := 1; c <= k; c++ {
			if v := dp[c-1][0] - p; v > dp[c][1] {
				dp[c][1] = v
			}
			if v := dp[c][1] + p; v > dp[c][0] {
				dp[c][0] = v
			}
		}
	}
	return dp[k][0]
}
```

## 128.6 复杂度与常见坑

### 128.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(nK)`**：外层 `n` 天，内层 `c = 1..K` 各两次 max。`K = 2`、`n = 10^5` ⇒ 约 `4·10^5` 次操作，实测 Java 2 ms、Go 1 ms。
- **空间 `O(K)`**：滚动后只需 `(K+1) × 2` 个整数。`K = 2` 时 6 个变量 —— **等价于 `O(1)`**。
- **`K = 2` 时为什么是 `O(n)`**：`K` 是常数，`O(nK) = O(n)`。若有人把 `K` 也当变量写成 `O(n²)`，说明他把「两笔」当成了「枚举分割点」（那是前后缀分解方案的 `O(n²)` 变体，不是状态机）。
- **188 的退化**：`k ≥ n/2` 时用 122 的 2 状态解法，时间 `O(n)`、空间 `O(1)`，**与 `k` 无关**。若不做这个判断，`k = 10^5` 时 `O(nk) = 10^10` → TLE。

### 128.6.2 七个真实踩过的坑

1. **`NEG` 用 `Integer.MIN_VALUE`** —— 转移里 `NEG + p` 溢出成正数，答案直接变天文数字。必须用 `MIN_VALUE / 2`。
2. **`c` 写成倒序** —— 那就不再自动满足「至多 c 笔」的单调性，必须改答案 `max over c`。**倒序不是错，但要配套改答案。**
3. **初值把 `dp[c][1]` 设成 `-prices[0]`** —— 等于「第一天就买入了 c 次」，`dp[2][1]` 会被初始化成 `-prices[0]`，之后算出的答案可能偏大。
4. **答案返回 `dp[K][0]` 却在倒序写法下** —— 见第 2 条；「只用一笔更优」的情形会丢。
5. **`K = 2` 写成「恰好两笔」**（`dp[c][0]` 对 `c ≥ 1` 初始化成 `NEG`） —— `[7,6,4,3,1]` 会返回负数。题目是「最多」。
6. **把「同一天卖出再买入」当成必须禁止** —— 于是在递增写法里强行加 `prev` 暂存，结果忘了改答案取 `max`。**先说清「为什么同日买卖无害」，就没这个问题。**
7. **188 里忘掉 `k >= n/2` 的退化** —— `k = 10^5`, `n = 10^5` 时 `O(nk)` 爆掉；而且 `dp` 数组开 `k+1` 行会 MLE。

### 128.6.3 面试官最爱追问的三个问题

**Q1：为什么买入消耗额度而卖出不消耗？**

> 「因为『一笔交易』定义为『一次买 + 一次卖』。把额度记在买入上，就能保证『卖出次数 ≤ 买入次数 ≤ K』，从而完成的交易笔数 ≤ K。如果两个动作都消耗或都不消耗，都无法保证买卖成对。」

**Q2：为什么 `c` 要递增遍历？允许同一天买卖合理吗？**

> 「递增遍历让 `dp[c][1]` 用到『今天已经更新过的』`dp[c-1][0]`，等价于允许『同一天卖出第 c−1 笔、再买入第 c 笔』。这个动作发生在同一个价格上，净收益为 0，所以不影响答案；它唯一的作用是在状态机里自动传递『额度可以不用完』这个语义，保证 `dp[c][0] ≥ dp[c-1][0]`。如果改成倒序（禁止同日），就必须把答案改成 `max over c dp[c][0]`，否则『只用一笔更优』的情形会漏。」

**Q3：如果 `k` 是一般参数（LC 188）？**

> 「把 `K = 2` 换成参数 `k`，`O(nk)` 时间、`O(k)` 空间。要加一个退化判断：`k ≥ n/2` 时交易次数不再构成约束（一笔至少占 2 天），直接退化为无限次交易的 2 状态解法，`O(n)` 与 `k` 无关。如果不加这个判断，`k = n = 10^5` 时 `O(nk) = 10^10` 必 TLE，`dp` 数组也会 MLE。」
