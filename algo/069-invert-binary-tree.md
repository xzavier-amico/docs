## 069.1 题目

**原题链接**：<https://leetcode.cn/problems/invert-binary-tree/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root`，把这棵树**翻转**：对**每一个**节点，把它的左子树和右子树整体互换。返回翻转后的**根节点**。

「整体互换」是关键词 —— 不是「把两个孩子的值换一下」，而是**连孩子下面的整棵子树一起搬过去**，并且子树内部也要各自翻转。

一句话就说完的题，藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 交换的是**子树**，不只是值 | 「左右子树互换」 | 只交换 `left.val` 与 `right.val` → 第三层全错 |
| **每个节点**都要交换 | 「翻转这棵树」 | 只交换根的两个孩子 → 只有前两层对 |
| 返回值是**根节点** | 「返回其根节点」 | 写成 `void` 原地改完不返回 → 提交直接编译/判错 |
| 空树返回 `null` | 样例 `root = []` | 没判空就取 `root.left` → `NullPointerException` |
| 允许**原地修改** | 「返回其根节点」（没有要求新树） | 非要新建一棵镜像树 → 空间从 O(h) 涨到 O(n) |

> 📌 **本章与 068 的关系**：068 的答案是「子节点交上来的」（后序返回值），本章的答案**不需要子节点交任何东西** —— 进入节点就交换，交换完再分别处理两棵子树。
> 这正是 068 §068.3.3 那张对照表的**范式一**：**前序 + 无返回值**（答案直接在树上生效）。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `[0, 100]` | 最多 100 个 | 任何 O(n) 都过；**本题不考时间，考「有没有把每个节点都翻到」** |
| `-100 <= Node.val <= 100` | 值不参与运算 | 本题是纯结构操作，不需要看值（连比较都不用） |
| 树不保证平衡 | 可能是全左链 | 递归深度最坏 100，安全；但同一段代码搬到 `10⁵` 链上会爆栈 |
| 返回 `TreeNode` | 返回引用 | 必须 `return root`，且**空树要 `return null`** |

> 💡 **量级 → 算法**：`n ≤ 100`，复杂度完全不是考点。
> 本题真正的考点是**「交换这件事在递归里的位置」**：放在递归前（前序）还是递归后（后序）都能对，但放在**两次递归中间**（中序）会翻错一半。
> 这是本章唯一值得记一辈子的坑，§069.4.3 会用图把它画出来。

### 示例

```
示例 1
输入：root = [4, 2, 7, 1, 3, 6, 9]
输出：      [4, 7, 2, 9, 6, 3, 1]

翻转前：                     翻转后：
        4                            4
     ┌──┴──┐                      ┌──┴──┐
     2     7          →          7     2
    ┌┴┐   ┌┴┐                   ┌┴┐   ┌┴┐
    1 3   6 9                   9 6   3 1

示例 2
输入：root = [2, 1, 3]
输出：      [2, 3, 1]

        2            2
       ┌┴┐    →    ┌┴┐
       1 3          3 1

示例 3
输入：root = []
输出：[]
```

### 我自造的三个反例（写完必须拿它们打一遍）

```text
① 空树 []                        → 暴露「没判空」的 NPE，以及「返回 null 还是返回空树」的混淆
② 单结点 [1]                     → 翻转后必须还是 [1]（交换 null 与 null）；返回 null 就全错
③ 全左链 4←2←1（只有 left）       → 翻转后必须变成「全右链」4→2→1：
                                  层序 [4,2,null,1] → [4,null,2,null,1]
                                  这一条专治「只交换值」「只翻一层」
```

第 ③ 条最有诊断价值：全左链翻转后**形状必须变成全右链**。如果你的输出仍然是 `[4,2,null,1]`，说明你只换了值没换结构；如果输出是 `[4,2,1]`，说明你把「左链」当成了「同一层的兄弟」。

## 069.2 从暴力到最优：第一个念头为什么错

### 第一个念头：只交换根的两个孩子

```java
TreeNode t = root.left;
root.left = root.right;
root.right = t;
return root;
```

- 时间 **O(1)**，空间 **O(1)** —— 但只翻了**第一层**。
- 示例 1 上得到的是 `[4, 7, 2, 1, 3, 6, 9]`，而正确答案是 `[4, 7, 2, 9, 6, 3, 1]`。**前两层完全一致，第三层全错** —— 这种「看起来对了一半」的输出现象，正是本章最需要警惕的形态。

```
只交换根：                     正确翻转：
        4                            4
     ┌──┴──┐                      ┌──┴──┐
     7     2          ≠          7     2
    ┌┴┐   ┌┴┐                   ┌┴┐   ┌┴┐
    1 3   6 9                   9 6   3 1
    ↑ 子树内部没翻                  ↑ 每一层都翻了
```

### 第二个念头：按层把值反转

既然示例 1 的输入 `[[4],[2,7],[1,3,6,9]]` 看上去「每层反转一下」就得到输出 `[[4],[7,2],[9,6,3,1]]`，一个很自然的念头是：**层序遍历取值 → 每层 `reverse` → 重建树**。

```java
List<List<Integer>> levels = levelOrder(root);   // 066
for (List<Integer> lv : levels) Collections.reverse(lv);
return buildFromLevels(levels);                  // 用「完全二叉树」的方式重建
```

- 时间 **O(n)**，空间 **O(n)**（要存整棵树的层序，还要重建）。
- **它在完全二叉树上完全正确**，在**不平衡树**上立刻错。反例 `root = [4,2,7,1]`（`1` 是 `2` 的**左孩子**）：

```
原树：            正确翻转：            「按层反转」给出：
      4                4                      4
    ┌─┴─┐            ┌─┴─┐                  ┌─┴─┐
    2   7            7   2                  7   2
   ┌┘                    └┐                   ┌┘
   1                      1                   1
  层序 [4,2,7,1]      [4,7,2,null,null,       按层反转 → [[4],[7,2],[1]]
                       null,1]                 重建 → 1 变成了 7 的左孩子 ❌
```

**根因**：层序数组丢掉了「每个节点挂在谁的哪个位置」的信息，`1` 在数组里只是「第 2 层的第一个元素」，反转后被当成「第 2 层从右往左的第一个」，于是挂到了错误的父节点上。**层序反转只在「完全二叉树」这种「层内位置与父节点一一对应」的形态下等价于翻转。**

### 第三个念头：递归 —— 但交换放在两次递归中间

```java
invert(root.left);                    // 先翻左子树
TreeNode t = root.left; root.left = root.right; root.right = t;   // 再交换（❌ 位置错了）
invert(root.right);                   // 再翻「右子树」—— 此时它已经是原来那棵左子树了！
```

这段代码长得和正确写法几乎一样，只差一行位置，而结果是**左子树被翻转了两次、右子树被翻转了零次**。

- 时间仍是 O(n)，空间仍是 O(h)，**完全不报错、绝不越界**，只是答案错。
- 它是本章的**头号陷阱**，§069.4.3 会逐步推演它是怎么翻错的。
- 修法：交换要么放在**两次递归之前**（前序），要么放在**两次递归之后**（后序），**不要放在中间**。

### 卡点在哪

> **卡点不在「怎么交换」，而在「交换与递归的先后顺序」。**

交换是**对指针的操作**，递归是**对子树的遍历**。两者都能正确完成各自的任务，但一旦顺序错位，递归就会跑到「已经被交换走的子树」上去，于是同一支被处理两次、另一支被跳过。

| 交换位置 | 遍历类型 | 是否正确 | 原因 |
| --- | --- | --- | --- |
| 两次递归**之前** | 前序（065 术语） | ✅ | 先摆好左右，再分别深入；两支各走一次 |
| 两次递归**之后** | 后序 | ✅ | 先分别翻好子树，最后把两棵已翻好的子树挂到对侧 |
| 两次递归**之间** | 中序 | ❌ | 交换后 `root.left` 已是原右子树，第二行递归会重复处理原左子树 |
| 一次递归也不做 | — | ❌ | 只翻了根这一层 |

### 灵感的来源 —— 「一条与子树互不干扰的局部操作」

关键观察只有一句：

> **交换 `v` 的左右两个孩子，与「左子树内部怎么翻」「右子树内部怎么翻」是两件完全独立的事。**

用一句更技术的话说：翻转对「节点自身」和「子树」是**可交换**的两个动作 ——

```
inv(v) = v' 其中 v'.left = inv(v.right), v'.right = inv(v.left)
```

也就是：**先把两支子树各自翻好（递归），再整体换位（交换）**；或者**先换位，再各自翻好**。两种顺序都满足上式，因为「换位」和「各自翻」作用在不同的指针上（前者动 `v` 的两条出边，后者动子树内部的边）。

一旦你意识到「局部操作 + 子问题」可以任意排序（只要不交错），前序/后序都能一眼写出来，而中序为什么不行也就清楚了：中序会让「换位」插在两次子问题调用**中间**，此时第二次调用拿到的已经不是原来那棵树了。

## 069.3 原理拆解

### 069.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| **前序递归（先交换再递归）** ✅ 首选 | O(n) | O(h) 系统栈 | 6 行 | 深链树 `h ≈ n` 时 Java 爆栈 |
| 后序递归（先递归再交换） | O(n) | O(h) 系统栈 | 6 行 | 与上一行完全等价，只是写作习惯不同 |
| 中序递归（交换夹在中间） | O(n) | O(h) | 6 行 | **答案错**，只翻半边（本章头号坑） |
| BFS 队列迭代（每弹一个节点就交换它的孩子） | O(n) | O(w) 队列 | 12 行 | 宽树内存大；链状树反而 O(1) |
| DFS 显式栈迭代（前序，065 的栈模板） | O(n) | O(h) 堆栈 | 14 行 | 代码比递归长，只在「不许递归」时用 |
| 递归**新建**一棵镜像树（不改原树） | O(n) | **O(n)** | 8 行 | 输入树被多处共享、不允许修改时**必须**这样；但本题允许原地改，纯浪费 |
| 层序反转后重建 | O(n) | O(n) | 30 行 | **不平衡树上答案就错**（见 §069.2 第二个念头） |
| 只交换根的两个孩子 | O(1) | O(1) | 4 行 | 只有前两层对 |

**为什么前序递归是首选**：

- 它把「本节点要做什么」放在最前面，读代码时第一眼就看到「交换」，与题目语义（翻转 = 交换）**完全对齐**；
- 与 068 的**范式一**（前序、无需子树结果）严格同构：进入节点干活、把任务交给孩子、没有返回值要合并。

**为什么原地改就够了**：题目只要求「返回翻转后的根」，没有要求保留原树。原地交换只动指针，空间 O(h)（只有递归栈），而新建镜像树要额外 O(n) 个节点。**能原地就别新建，除非输入树还被别处引用。**

### 069.3.2 为什么这个做法是对的（正确性论证）

**定义（翻转的形式化）**：对任意树 `T`，其翻转 `inv(T)` 递归定义为

```
inv(∅) = ∅
inv(v) = 节点 v'，其中 v'.val = v.val, v'.left = inv(v.right), v'.right = inv(v.left)
```

**命题**：前序递归算法返回的树 `A(root)` 满足 `A(root) = inv(root)`。

**证明（结构归纳）**：

1. **基例**：`root == null`。算法返回 `null = inv(∅)`。成立。
2. **归纳假设**：对 `root.left`、`root.right` 两棵更小的子树，算法返回的恰是它们的翻转。
3. **归纳步**：前序算法执行顺序是
   1. 交换 `root.left` 与 `root.right`（此时 `root.left` 指向原右子树，`root.right` 指向原左子树）；
   2. 递归处理 `root.left`（原右子树）→ 由归纳假设，返回 `inv(原右子树)`；
   3. 递归处理 `root.right`（原左子树）→ 返回 `inv(原左子树)`。
   
   最终 `root.left = inv(原右子树)`、`root.right = inv(原左子树)`、`root.val` 不变 —— 与 §069.3.2 开头的递归定义**逐字吻合**。∎

**后序版本的对偶论证**：先递归得到 `inv(左)`、`inv(右)`，再把它们互换挂到对侧，结果同样是 `v'.left = inv(原右)`、`v'.right = inv(原左)`。∎

**为什么中序版本会错**（用同一套语言严格指出）：中序版本执行的是

1. 递归 `root.left` → 返回 `inv(原左)`，挂在 `root.left` 上；
2. 交换：`root.left` 变成原右子树（**还没翻**），`root.right` 变成 `inv(原左)`；
3. 递归 `root.right` → 返回 `inv(inv(原左)) = 原左`（翻转两次等于原样）。

结果 `root.left = 原右子树`（一次都没翻）、`root.right = 原左子树`（翻了两次，回到原样）。∎

> **这个论证解释了一个反直觉的现象**：中序版本**不是随机错，而是有规律地错** —— 左右两支各自被处理了「错误次数」。这就是为什么它在小树上「看起来差一点」，在大树上「错得离谱」，而任何时候都不报错。

### 069.3.3 通用解题思路（可迁移的那一层）

#### ① 本章在「树递归语言」里的位置

068 立了两个范式，本章是**范式一的第一个完整实例**：

| 对照项（引自 068 §068.3.3） | 本章的具体形态 |
| --- | --- |
| 信息流向 | 不需要流（本节点就能决定一切） |
| 递归位置 | **前序**：进入节点先交换，再分别深入 |
| 需要的外部状态 | 不需要 —— 交换直接作用在树上，「答案」就是树本身 |
| 空节点返回什么 | `null`（空树的翻转还是空树） |
| 能否提前终止 | 不能（每个节点都必须翻，无处可省） |
| 返回值 | 返回 `root` 本身，供父节点重新挂接（**这也是返回值，只是含义是「挂接点」而不是「聚合值」**） |

> 🧭 **本章新增的一句语言**：**返回值不一定是「聚合出答案」，它也可以是「告诉父节点该把我的哪个指针接回去」**。
> 这句话在 078（从前序与中序构造二叉树）里会变成「返回构造出的子树根」，在 079（序列化/反序列化）里会变成「返回解析到的子树根」。

#### ② 三种遍历顺序能不能翻，一张判定表

| 遍历 | 写法骨架 | 正确性 | 一句话解释 |
| --- | --- | --- | --- |
| 前序 | `swap(v); f(v.left); f(v.right);` | ✅ | 先换位，再分别处理（注意 `v.left` 此刻已是原右子树） |
| 后序 | `f(v.left); f(v.right); swap(v);` | ✅ | 先各自翻好，最后换位 |
| 中序 | `f(v.left); swap(v); f(v.right);` | ❌ | `v.right` 此时已是原左子树（已翻过一次），会被翻第二遍 |
| 层序 | 队列逐个弹出 → `swap(v)` | ✅ | 每个节点恰好弹一次、换一次，顺序无关 |

**「为什么层序也行」的通用结论**：**只要「每个节点恰好被处理一次」且「处理动作是局部的、与其它节点的处理顺序无关」，那么任何遍历顺序都可以。** 这解释了为什么 068（要子树结果）只能用后序，而 069（局部动作）三种顺序（除中序写错）都行：

| 问题 | 动作依赖子树结果吗 | 可用的遍历 |
| --- | --- | --- |
| 068 最大深度 | 依赖（要 `max` 两个孩子的高度） | **只能后序** |
| 069 翻转 | 不依赖 | 前序 / 后序 / 层序都行（中序会因交换时机错位而失败） |
| 072 路径总和 II | 不依赖，但需要「撤销」 | 前序 + 回溯 |

#### ③ 迭代骨架（把递归栈换成显式栈，沿用 065 的术语）

```text
# 前序显式栈版
stack = [root]
while stack 非空:
    v = stack.pop()
    swap(v.left, v.right)          # 进栈即处理（前序语义）
    if v.left  != null: stack.push(v.left)
    if v.right != null: stack.push(v.right)

# 层序版：把 stack 换成队列，语义完全相同
```

注意这里**必须让 `swap` 发生在取孩子之前**：如果先取 `p = v.left; q = v.right` 再交换再入栈，写反了就会把同一支压栈两次。**这是迭代版唯一的坑。**

### 069.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 判两棵树是否互为镜像 | 不翻转，只比较 | 070 对称二叉树：改成「双指针镜像递归」，比较 `a.left` 与 `b.right` |
| 判**能否通过翻转**变成同一棵树（LC 951） | 允许选择性地翻 | 递归时两个分支都要试（不翻 / 翻），返回 `boolean` |
| 只翻**奇数层**（LC 2415） | 按深度决定翻不翻 | 传参范式（068 范式一）：带 `depth`，奇数层才 `swap` |
| 树是 **N 叉** | 孩子列表 | `reverse(children)` 后逐个递归 |
| 原树**不许改** | 必须新树 | 递归新建：`new TreeNode(v.val, inv(v.right), inv(v.left))`，空间 O(n) |
| 树被**多线程**共享 | 原地改有数据竞争 | 只读场景用「新建镜像树」或加锁；或者干脆在序列化层做镜射 |

### 069.4.3 中序版本的「翻错一半」（本章最该看懂的图）

同一棵树，交换放在两次递归**中间**：

```
调用 invert_mid(4)：
  ① invert_mid(4.left = 2)                     ← 先翻左子树
       ① invert_mid(2.left = 1) → 叶子
       ② swap(2) → 2 的孩子变成 (3, 1)
       ③ invert_mid(2.right) —— 注意！此时 2.right 已经是【原来的 1】
          于是 1 被第二次处理（1 是叶子，看不出问题）
       返回：2 的子树 = (3, 1)

  ② swap(4) → 4 的孩子变成 (原 7, 原 2)

  ③ invert_mid(4.right) —— 此时 4.right 是【原来的 2】（而且刚被翻过一遍！）
       ① invert_mid(原2.left = 3) → 叶子
       ② swap(原2) → 它的孩子又换回 (1, 3)      ← 翻第二次 = 复原
       ③ invert_mid(原2.right = 1)
       返回：原 2 的子树 = (1, 3)  ← 等于没翻

最终结果：
        4
     ┌──┴──┐
     7     2         ← 4 换位了（对）
    ┌┴┐   ┌┴┐
    6 9   1 3       ← 7 那支一次没翻（错），2 那支翻两次=没翻（错）

正确结果应为 9 6 / 3 1 —— 中序版本给出了「完全没翻的子树」：
        4
     ┌──┴──┐
     7     2
    ┌┴┐   ┌┴┐
    6 9   1 3
   ↑ 这正是「只交换了根」的那个错误答案！
```

> 结论极其干净：**中序版本的净效果 = 只交换了根**。因为每一支子树都被「翻一次（正确）+ 翻一次（多余）」抵掉了。**这就是「不报错但答案错」的完整机理。**

### 069.4.4 两条路线的对比

```
                  ┌────────── 输入 root ──────────┐
                  │                               │
     ┌────────────▼─────────────┐  ┌──────────────▼─────────────┐
     │ 递归（前序 / 后序）       │  │ 迭代（层序 队列 / 前序 栈） │
     │ O(n) / O(h)              │  │ O(n) / O(w) 或 O(h)        │
     └────────────┬─────────────┘  └──────────────┬─────────────┘
                  │                               │
        swap 在两次递归之前或之后            每个节点弹出时 swap
        中序（夹在中间）会翻错一半             顺序无关，只要求「弹一次换一次」
                  │                               │
        【本题首选，代码最短】           【不许递归时的替代，或想避免栈深】 
```

## 069.5 双语言实现

### 069.5.1 Java

**主解（前序递归：先交换，再分别深入）**：

```java
// LeetCode 判题环境已内置 TreeNode，粘贴到网页时不要重复定义：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode(int val) { this.val = val; }
// }

class Solution {
    public TreeNode invertTree(TreeNode root) {
        // 空树的翻转还是空树；这行同时承担"边界处理"和"返回 null"两件事
        if (root == null) {
            return null;
        }

        // ① 先交换自己的两个孩子（连整棵子树一起换位）
        // 注意必须用临时变量：写成 root.left = root.right; root.right = root.left; 会把两边都变成原右子树
        TreeNode t = root.left;
        root.left = root.right;
        root.right = t;

        // ② 再分别深入两棵子树。此刻 root.left 已经是「原右子树」，
        //    但无所谓 —— 我们要翻的正是"当前挂在左边的那棵树"，谁在上面都一样
        invertTree(root.left);
        invertTree(root.right);

        // ③ 返回自己，供父节点重新挂接（父节点需要知道"我的孩子在哪"）
        return root;
    }
}
```

**备解（BFS 队列迭代：每个节点弹出时交换）**：

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) {
            return null;
        }
        Deque<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        while (!q.isEmpty()) {
            TreeNode cur = q.poll();
            // 弹出即交换：这里不需要 size 快照，因为「第几层」与本题无关
            TreeNode t = cur.left;
            cur.left = cur.right;
            cur.right = t;
            // ★ 必须在交换之后再看孩子：交换前先把 left/right 存进局部变量再入队的话，
            //   一旦两行顺序写反，就会把同一支压栈两次
            if (cur.left != null) {
                q.offer(cur.left);
            }
            if (cur.right != null) {
                q.offer(cur.right);
            }
        }
        return root;
    }
}
```

### 069.5.2 Go

**主解（前序递归）**：

```go
package main

// LeetCode 判题环境已内置该定义，本地编译时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func invertTree(root *TreeNode) *TreeNode {
	if root == nil {
		return nil
	}
	// Go 支持多重赋值，不需要临时变量：
	// 右边先整体求值（拿到两个旧指针），再赋给左边，语义等价于"同时交换"
	root.Left, root.Right = root.Right, root.Left

	invertTree(root.Left)  // 此时 root.Left 是原右子树
	invertTree(root.Right) // 此时 root.Right 是原左子树
	return root
}
```

**备解（BFS 队列迭代）**：

```go
package main

func invertTreeBFS(root *TreeNode) *TreeNode {
	if root == nil {
		return nil
	}
	q := make([]*TreeNode, 1, 64)
	q[0] = root
	head := 0
	for head < len(q) {
		cur := q[head]
		head++
		cur.Left, cur.Right = cur.Right, cur.Left // 弹出即交换
		if cur.Left != nil {
			q = append(q, cur.Left)
		}
		if cur.Right != nil {
			q = append(q, cur.Right)
		}
	}
	return root
}
```

**本地跑一遍（含四类边界）**：

```go
package main

import "fmt"

// 按 LeetCode 层序数组建树：nil 表示空位
func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}

// 按层序把树打印成数组（nil 用 "<nil>" 表示），方便肉眼对照。
// 最后统一砍掉尾部的 nil —— 它们只是"更深层全空"的产物，留着会淹没真正的形状信息
func dump(root *TreeNode) []interface{} {
	out := []interface{}{}
	if root == nil {
		return out
	}
	q := []*TreeNode{root}
	for len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if cur == nil {
			out = append(out, nil)
			continue
		}
		out = append(out, cur.Val)
		q = append(q, cur.Left, cur.Right)
	}
	for len(out) > 0 && out[len(out)-1] == nil {
		out = out[:len(out)-1]
	}
	return out
}

func main() {
	cases := [][]interface{}{
		{},                         // 空树
		{1},                        // 单结点
		{4, 2, 7, 1, 3, 6, 9},      // 官方样例
		{2, 1, 3},                  // 小样例
		{4, 2, nil, 1},             // 全左链：翻转后必须变成全右链
	}
	for _, c := range cases {
		root := build(c)
		fmt.Printf("%v → %v\n", c, dump(invertTree(root)))
	}
}
```

[4 2 7 1 3 6 9] → [4 7 2 9 6 3 1]

### 069.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 交换写法 | 必须用临时变量 `TreeNode t` | 多重赋值 `a, b = b, a`，编译器保证右边先求值 | Go 少一个变量，且不会写错顺序；Java 写成 `left = right; right = left` 是经典 bug |
| 空值 | `null` | `nil` | 语义一致，都要在开头判 |
| 递归返回类型 | `TreeNode invertTree(...)` | `*TreeNode` | 两者都返回引用/指针，父节点靠它重新挂接 |
| 迭代容器 | `ArrayDeque<TreeNode>` | `[]*TreeNode` + `head` 下标 | Go 用 `q = q[1:]` 会拖住底层数组，`head` 法更稳 |
| 打印/调试 | `Arrays.toString` 只能打扁平数组 | 自己写 `dump` 输出 `[]interface{}` | 树形状的调试两边都得自己写辅助函数 |
| 修改可见性 | 引用类型，改指针即改原树 | `*TreeNode`，同样改到原树 | 对拍时**必须每次重建树**，否则第二次测的是被改过的树 |

### 069.5.4 对拍测试（暴力：按定义递归新建镜像树 + 幂等性双检）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：严格按定义"新建"一棵镜像树（不动原树），
// 这与 invertTree 的原地交换是完全不同的实现路径，适合当裁判
func mirrorCopy(root *TreeNode) *TreeNode {
	if root == nil {
		return nil
	}
	return &TreeNode{
		Val:   root.Val,
		Left:  mirrorCopy(root.Right), // 左 = 原右的镜像
		Right: mirrorCopy(root.Left),  // 右 = 原左的镜像
	}
}

func copyTree(root *TreeNode) *TreeNode {
	if root == nil {
		return nil
	}
	return &TreeNode{Val: root.Val, Left: copyTree(root.Left), Right: copyTree(root.Right)}
}

// 结构 + 值完全相等
func sameTree(a, b *TreeNode) bool {
	if a == nil || b == nil {
		return a == b
	}
	return a.Val == b.Val && sameTree(a.Left, b.Left) && sameTree(a.Right, b.Right)
}

func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(201) - 100}
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(201) - 100}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

func TestInvertTreeRandom(t *testing.T) {
	r := rand.New(rand.NewSource(226))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(40)
		base := randTree(r, n)

		// ① 与「新建镜像树」比对
		t1 := copyTree(base)
		want := mirrorCopy(base)
		got := invertTree(t1)
		if !sameTree(got, want) {
			t.Fatalf("iter=%d n=%d 翻转结果与镜像定义不符", iter, n)
		}

		// ② 幂等性：翻两次必须回到原树（能抓出"只翻一半""翻两次"这类型错）
		inv := invertTree(copyTree(base))
		if !sameTree(invertTree(inv), base) {
			t.Fatalf("iter=%d n=%d 翻两次没回到原树", iter, n)
		}

		// ③ BFS 版与递归版必须一致
		if !sameTree(invertTreeBFS(copyTree(base)), want) {
			t.Fatalf("iter=%d n=%d BFS 版不一致", iter, n)
		}
	}
}

// 边界专测：空树、单结点、全左链（必须变成全右链）
func TestInvertTreeEdge(t *testing.T) {
	if invertTree(nil) != nil {
		t.Fatal("空树翻转后应为 nil")
	}
	if got := invertTree(&TreeNode{Val: 5}); got == nil || got.Val != 5 || got.Left != nil || got.Right != nil {
		t.Fatal("单结点翻转后应保持不变")
	}
	// 全左链 1←2←3←4 翻转后必须是全右链
	root := &TreeNode{Val: 1, Left: &TreeNode{Val: 2, Left: &TreeNode{Val: 3, Left: &TreeNode{Val: 4}}}}
	got := invertTree(root)
	cur := got
	for want := 1; want <= 4; want++ {
		if cur == nil || cur.Val != want || cur.Left != nil {
			t.Fatalf("第 %d 个节点应为 %d 且无左孩子", want, want)
		}
		cur = cur.Right
	}
	if cur != nil {
		t.Fatal("翻转后右链应该正好 4 个节点")
	}
}
```

> **为什么要加「幂等性」这条断言**：本章最典型的 bug（中序版）会产出「只交换了根」的答案 —— 它既不越界也不报错。而「翻两次回原树」这条性质，**只有每一支都被正确翻过一次才成立**；任何「翻两次」或「一次没翻」的分支都会破坏它。**判据的性质要贴着 bug 的形态设计。**

## 069.6 复杂度与常见坑

### 069.6.1 复杂度推导

- **时间 O(n)**：每个节点被访问一次，函数体内只做常数次（两次指针交换 + 两次判空）。指针交换是 O(1)，没有值的复制，也没有子树重建。
- **空间 O(h)**：递归栈深等于树高。完全二叉树 `h = ⌊log₂n⌋ + 1`；链状树 `h = n`。本题 `n ≤ 100`，最坏 100 层，绝对安全。
- **迭代 BFS 版空间 O(w)**：队列最多同时装最宽一层。链状树 `w = 1`（O(1)），完全树 `w ≈ n/2`。
- **注意**：本题**没有**额外的节点分配 —— 交换的是指针，不是值。所以不存在「O(n) 额外对象」的问题；如果改成新建镜像树，才会有 O(n) 新节点。

| 方案 | 时间 | 空间 | 全左链 `n = 100` | 满二叉树 `n = 100` |
| --- | --- | --- | --- | --- |
| 前序递归 | O(n) | O(n) 栈（深 100） | 安全 | O(log n) 栈 |
| 后序递归 | O(n) | 同上 | 安全 | 同上 |
| BFS 迭代 | O(n) | O(1) 队列 | **最省空间** | O(n/2) 队列 |
| 新建镜像树 | O(n) | **O(n) 新节点** | 多 100 个对象 | 多 100 个对象 |

### 069.6.2 七个真实踩过的坑

1. **交换夹在两次递归中间（中序）** —— 本章头号坑，结果恰好等于「只交换根」。修法：交换放在两次递归**之前**或**之后**。
2. **Java 里不用临时变量** —— `root.left = root.right; root.right = root.left;` 让两边都变成原右子树，整棵右子树被复制、左子树丢失。Go 的多重赋值没有这个问题。
3. **只交换值不交换子树** —— `int t = root.left.val; ...` 两层以下全错。题目要的是结构翻转。
4. **忘记返回 `root`（写成 `void`）** —— LeetCode 判题签名要求返回 `TreeNode`；`void` 直接编译不过，或者在末尾 `return null` 返回了空树。
5. **空树没判空** —— `root.left` 直接 NPE。开头一行 `if (root == null) return null;` 同时解决判空与返回值。
6. **用「层序按层反转」代替结构翻转** —— 完全二叉树上侥幸正确，不平衡树上必错（§069.2 第二个念头给了反例图）。
7. **迭代版把「取孩子」写在 `swap` 之前还存了局部变量** —— 例如 `l, rr := cur.Left, cur.Right; cur.Left, cur.Right = rr, l; push(l); push(rr)` 还算正确（压的是交换前的两支，各一次），但若写成 `push(cur.Left)` 之后又 `swap`，就会漏压或重压一支。**统一规则：先 `swap`，再按新的 `Left/Right` 入队。**

### 069.6.3 面试官最爱追问的三个问题

**Q1：前序和后序都对，为什么中序不行？**

> 「因为中序把『交换』插在了两次递归**中间**。交换之后 `root.left` 指向的已经是原右子树，于是第二次递归处理的不是原左子树，而是**刚翻过一次的原左子树**（它被换到了 `root.right`）。结果是：一支被翻两次（等于复原）、一支一次没翻。净效果恰好等于『只交换了根』—— 不报错但答案错，所以它比崩溃更危险。」

**Q2：能不能不改原树？**

> 「能，用『新建镜像树』的写法：`new TreeNode(v.val, inv(v.right), inv(v.left))`。代价是 O(n) 个新节点。什么时候必须这么做？**① 输入树还被别处引用**（改了会影响调用方）；**② 树是共享只读数据**（多线程同时读会看到中间状态）；**③ 需要保留原树用于对比**。本题没有这些约束，原地改是最省的。」

**Q3：如果要求「只翻某一层」怎么办？**

> 「换成 068 的**范式一**：加一个 `depth` 参数，只在目标层执行 `swap`，其余层只递归。这就是 LC 2415（翻转二叉树的奇数层）。**关键认识是：『翻不翻』是一个可以按节点决定的局部决策，而『递归到哪』与它无关。**」

**Q4（常见追问）：迭代怎么写才不会写错顺序？**

> 「记住一句：**先交换、再按新的孩子指针入队**。因为交换后 `cur.left` 就是待处理的『原右子树』，它和交换前的 `cur.right` 是同一棵 —— 反正每棵子树都要处理，只要保证**每棵子树恰好入队一次**就行。如果交换前先把两个旧指针存进局部变量再入队，也正确；唯一会错的是『交换后还用旧变量入队两次』。」

## 附：本章小结（可背走的三句话）

```
① 翻转 = 每个节点交换自己的两个孩子；改的是指针（子树整体搬家），不是值
② 交换放在两次递归之前（前序）或之后（后序）都对，夹在中间（中序）会翻错一半
③ 返回值是"让父节点接回去的挂接点"，不一定是聚合值 —— 这是 068 双范式在本章的另一副面孔
```
