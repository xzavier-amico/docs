## 124.1 题目

**原题链接**：<https://leetcode.cn/problems/edit-distance/>

### 题意重述（把隐含条件补齐）

给两个单词 `word1`、`word2`，你可以对 `word1` 做三种操作：**插入**一个字符、**删除**一个字符、**替换**一个字符。每种操作算 **1 步**。求把 `word1` 变成 `word2` 的**最少步数**。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 三种操作**代价都是 1** | 「You have the following three operations… each costs 1」 | 若替换代价算 2（认为 = 删 + 插），`"ab"→"ba"` 会答 2 而不是 2…但 `"abc"→"abd"` 会答 2 而不是 1 |
| 可以**插在任意位置**，不限于末尾 | 「Insert a character」 | 只允许末尾插入会把 `"abc"→"aebc"` 算成 3（正确 1） |
| 目标是最**少**步数 | 「minimum number of operations」 | 忘记取 min 会走到更长的路径 |
| 两串都**允许空** | 约束 `0 <= word1.length` | 空串时答案 = 另一串的长度，初值写错会答 0 |
| 只问**步数** | 「return the minimum number of operations」 | 要输出操作序列需回溯（§124.3.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= word1.length, word2.length <= 500` | 各 500 | `O(mn) = 2.5·10⁵` 格，实测 Java 4 ms、Go 6 ms，**非常宽裕** |
| 只含小写英文字母 | 字符集 26 | 字符比较是 `O(1)`；不需要哈希 |
| 无取模 | — | 答案 `≤ max(m,n) ≤ 500`，`int` 绝对安全 |
| **两串都可能为空** | 约束下限是 0（不是 1） | **必须处理空串**，这是本题唯一需要我们主动写的边界 |

> 💡 **量级 → 算法**：`500 × 500` 是双串 DP 的标准舒适区。真正的考点不是复杂度，而是**转移的三种分类为什么恰好是三种**。

### 示例

```text
输入：word1 = "horse", word2 = "ros"
输出：3
解释：horse → rorse（把 h 换成 r）→ rose（删掉第 2 个 r）→ ros（删掉 e）

输入：word1 = "intention", word2 = "execution"
输出：5

输入：word1 = "", word2 = "abc"
输出：3
解释：只能插入 3 次
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① ("", "")            → 两串皆空：答案 0，dp[0][0] = 0
② ("", "abc")         → 单边为空：答案 3（插入三次），dp[0][j] = j
③ ("a", "a")          → 完全相同：答案 0（对角线一路走到底，不能有 +1）
④ ("abc", "yabd")     → 长度接近但错位：正确答案 2（插 y、改 c→d）；若把「替换」当两步会答 3
```

第 ④ 条专门打「替换 = 2 步」这个错误认知。**替换的成本是 1，所以它永远优于「删 + 插」的 2**；这个不对称性正是很多加权的编辑距离变体（比如某些拼写纠错场景把相邻字符交换算 1 步）要额外加转移项的原因。

## 124.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 在「字符串图」上 BFS

最直白的建模：把每个可能的字符串当顶点，一次操作当一条边，从 `word1` 出发 BFS 找 `word2`。

- 顶点数：所有长度 `≤ max(m,n)` 的字符串，是 `26^L` 量级 —— **无穷大**（长度也可以无限增长，但最优解不会超过 `m+n` 步）。
- 时间 `O(26^L)`，`m=n=10` 时已经天文数字。
- 空间同样爆炸。

它唯一的价值：**在小字母表 + 极短串上可作为对拍基准**（§124.5.4 我确实写了一个 `alphabet{a,b}`、长度 `≤3` 的 BFS 版本），因为它对「编辑距离」的定义零假设。

### 第二步：为什么暴力里全是重复

BFS 会把 `"hor"→"hose"→"horse"` 这类来回路径全部展开。而真正有用的信息只有一句：

> **`word1` 的前 `i` 个字符变成 `word2` 的前 `j` 个字符要几步。**

所有具体字符串的内容都不重要，只有「两边各处理到哪儿」重要。状态数从 `26^L` 掉到 `(m+1)(n+1)`，这才是能算的东西。

### 第三步：卡点 —— 「操作」是作用在「对齐」上的

这是本题最容易讲不清的一步。先看一个反直觉的事实：

```text
"abc" → "adc"   ：1 步（把 b 换成 d）
但插入/删除的做法是："abc" → "abdc" → "adc"？那是 2 步
```

也就是说：**具体在某一位做哪种操作，取决于两边怎么「对齐」**。把两串上下写、中间允许塞「空位」，就得到一张对齐表：

```text
  h  o  r  s  e
  -  r  o  s  -
  ↑  ↑  ↑  ↑  ↑
 删  改 改 保  删        → 4 步？不优
```

最优对齐是：

```text
  h  o  r  s  e
  ↓  ↓  ↓  ↓  ↓
  r  o  s  ?  ?
把 h 替成 r  →  r  o  r  s  e
删掉第二个 r →  r  o  s  e
删掉 e       →  r  o  s       共 3 步
```

**编辑距离 = 一种对齐方案下「需要付代价的列」的数量。** 于是问题变成：**选一种最优对齐**。而「选对齐」的最佳工具就是 DP —— 逐列决定「这一列怎么处理」。

### 第四步：灵感的来源 —— 三种操作 = 三种「列类型」

把 `word1[0..i-1] → word2[0..j-1]` 的最后一次操作分类，只有三种可能：

```text
① 删除 word1[i-1]        → 问题变成 word1[0..i-2] → word2[0..j-1]   ⇒ dp[i-1][j] + 1
② 插入 word2[j-1]        → 问题变成 word1[0..i-1] → word2[0..j-2]   ⇒ dp[i][j-1] + 1
③ 替换 / 保留 word1[i-1] → 问题变成 word1[0..i-2] → word2[0..j-2]   ⇒ dp[i-1][j-1] + (相等?0:1)
```

**关键在第 ③ 条**：替换与保留是同一个位置上的两种情形，所以它们共用「左上」这条对角线，只是代价不同（`0` 或 `1`）。这就是本书反复说的那句话：

> **替换 = 对角线 + 1。**

而删除和插入分别对应「上」和「左」，各自 `+1`。三种操作恰好铺满 3×3 邻域的三个方向 —— **这就是为什么转移式里只有这三项**。

## 124.3 原理拆解

### 124.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 字符串图 BFS | `O(26^L)` | 指数 | 30 行 | 直接爆，只能做超小规模对拍 |
| 无记忆化递归（把三种操作直译） | `O(3^{m+n})` | `O(m+n)` 栈 | 12 行 | `m+n = 20` 就已几十亿次调用 |
| 记忆化搜索 | `O(mn)` | `O(mn)` + 栈 | 20 行 | 栈深度 `m+n`，`500` 时安全；但常数大 |
| **二维递推** ✅ | **`O(mn)`** | **`O(mn)`** | **15 行** | `10⁴ × 10⁴` 时内存 400 MB；且无「按需计算」能力 |
| 滚动数组 | `O(mn)` | `O(min(m,n))` | 18 行 | 无法回溯操作序列 |
| Ukkonen 带宽优化（只关心距离 `≤ k`） | `O(k·min(m,n))` | `O(k)` | 40 行 | 只有当 `k` 远小于 `m` 时才有意义（如模糊搜索的容错查询） |
| **Hyyrö 位并行** | `O(mn/w)` | `O(n)` | 50+ 行 | 只能求距离，无法回溯；可读性极差 |

**为什么选二维递推**：`2.5·10⁵` 个格子，每格三次比较、一次加法。它是「对齐」模型最直白的翻译，也是唯一能自然回溯出操作序列的版本。

### 124.3.2 为什么这个做法是对的（正确性论证）

**命题**：`dp[m][n]` 等于把 `word1` 变成 `word2` 的最小操作数。

**（1）三种操作分类完备且互斥。** 考虑把 `word1[0..i-1]` 变成 `word2[0..j-1]` 的任意一个最优操作序列。看它**最后一步**：这一步要么删除了 `word1` 的某个字符、要么插入了 `word2` 的某个字符、要么替换了某个字符（或者什么都不用做，因为那一位本来就相等）。关键在于：**总存在一个最优解，它的最后一步作用于「当前的最后一个字符」**。

理由（交换论证）：若最后一步删除的是 `word1` 中不是末尾的某个字符，我们可以把它推迟到最后再做 —— 因为它不影响前面字符的匹配关系。同理，插入 `word2[j-1]` 也可以在最后插入（只要保证插入位置在末尾），替换 `word1[i-1] → word2[j-1]` 同理。于是三类操作可以按「最后一步」分类，且：
- 删除 `word1[i-1]` 后，剩下的任务是 `word1[0..i-2] → word2[0..j-1]`，代价 `dp[i-1][j] + 1`；
- 插入 `word2[j-1]` 后，剩下的任务是 `word1[0..i-1] → word2[0..j-2]`，代价 `dp[i][j-1] + 1`；
- `word1[i-1]` 与 `word2[j-1]` 配对：若相等则免费（`dp[i-1][j-1]`），否则替换（`dp[i-1][j-1] + 1`）。

三类互斥（一次操作只可能是其中一种），完备（没有第四种操作）。所以取三者最小值不重不漏。

**（2）三个来源各自「不会更差」。** 上面给出的是「上界」：任何解都能归到这三种形态之一，所以 `dp[i][j] ≥ min{三项}`。反过来，三项每一种都对应一个合法操作序列（先做那个「最后一步」，再用最优子方案处理剩下的），所以 `dp[i][j] ≤ min{三项}`。两边夹逼得等号。

**（3）归纳与边界。** `dp[0][0] = 0`（空串变空串，0 步）；`dp[i][0] = i`（删 `i` 次）；`dp[0][j] = j`（插 `j` 次）。这三条不是「凑初值」，而是**空问题的最优答案**，与转移式在 `i = 0` 或 `j = 0` 时自然衔接。∎

> ⚠️ **一个常被问到的疑点**：为什么不考虑「删除 `word2` 的字符」或「插入到 `word1` 中间」？因为**操作只作用在 `word1` 上**：把 `word1` 变 `word2`，删除只能删 `word1` 的字符，插入只能插入 `word2` 需要的字符。而在「对齐」视角下，这两种操作恰好是「`word1` 这一列空着」和「`word2` 这一列空着」。**视角一换，就发现不需要第四种操作。**

### 124.3.3 通用解题思路（可迁移的那一层）

编辑距离是 **「序列比对（sequence alignment）」** 模型的最小实例。整个家族都共享同一张表，只是操作集合与代价不同：

| 模型 | 允许的操作 | 与本题的关系 |
| --- | --- | --- |
| **编辑距离（Levenshtein）** | 插入、删除、替换，均代价 1 | 本题 |
| **LCS** | 只有「免费保留相等字符」，其余视为删除 | `d = m + n − 2·LCS`（LC 583 用的正是这条） |
| **Hamming 距离** | 只允许替换，且要求等长 | `dp` 退化成逐位比较 |
| **加权编辑距离（Needleman–Wunsch）** | 插入/删除代价 `gap`，替换代价 `sub(a,b)` | 生物信息学的序列比对；转移形状完全不变，只换系数 |
| **最长公共子串** | 只允许「连续匹配」 | `dp[i][j] = 0` 打断继承（LC 718） |
| **最小代价路径** | 网格上向右/向下/斜向走，代价不同 | 112 / 113 的网格 DP，与本题同构 |

**通用套路（三段式）**：

```text
① 定义「对齐」：把两个串上下排，允许插入空位，让每列是（字符, 字符）或（字符, 空）或（空, 字符）
② 给每列定代价：匹配 0、替换 1、单边空位 1（不同题改这里的数）
③ 求总代价最小的对齐 = 二维 DP，三方向转移
```

> 🔑 **一句话**：只要你能把问题写成「两个序列的逐位对齐 + 每列有代价」，你就已经写完了 80% 的转移式。

### 124.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只允许**删除**操作（LC 583） | 操作集缩小 | 答案 = `m + n − 2·LCS`；也可以把转移里的 `+1` 项砍到只剩两个方向 |
| 允许**相邻交换**算 1 步（Damerau 距离） | 多一种操作 | 转移加一项 `dp[i-2][j-2] + 1`（当 `word1[i-1]==word2[j-2]` 且 `word1[i-2]==word2[j-1]`） |
| 操作**带不同权重** | 系数变化 | `dp[i][j] = min(dp[i-1][j] + del, dp[i][j-1] + ins, dp[i-1][j-1] + sub)` |
| 只关心距离 `≤ k`（模糊搜索） | 需要剪枝 | **Ukkonen 带宽**：只算 `|i-j| ≤ k` 的格子，`O(k·min(m,n))`；超出带宽的格子直接置 `+inf` |
| 要**输出操作序列** | 从值变路径 | 保留全表，从 `(m,n)` 回溯，按来源决定是 delete/insert/replace；再反转 |
| 要与**一个词典里所有词**比距离 | 多次查询 | 把词典建 Trie，在 Trie 上做 DP（每层一次行推进）；或用 BK 树做索引 |

**带权重的转移写法（Java，展示「系数可换」这一点）**：

```java
class SolutionWeighted {
    // 三种操作的代价由调用方决定，转移结构完全不变
    public int minDistance(String a, String b, int ins, int del, int sub) {
        int m = a.length(), n = b.length();
        int[][] dp = new int[m + 1][n + 1];
        for (int i = 1; i <= m; i++) dp[i][0] = i * del;   // 只能全删
        for (int j = 1; j <= n; j++) dp[0][j] = j * ins;   // 只能全插
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (a.charAt(i - 1) == b.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1];           // 相等免费，不需要考虑 ins/del
                } else {
                    dp[i][j] = Math.min(
                        dp[i - 1][j] + del,                 // 删 a[i-1]
                        Math.min(dp[i][j - 1] + ins,        // 插 b[j-1]
                                 dp[i - 1][j - 1] + sub));  // 替换
                }
            }
        }
        return dp[m][n];
    }
}
```

## 124.4 图解推演

### 124.4.1 3×3 转移示意（本章的重点图）

```text
                 word2 的前 j-1 个      word2 的前 j 个
              ┌──────────────────────┬──────────────────────┐
 word1 前 i-1 │   dp[i-1][j-1]       │   dp[i-1][j]         │
 个字符       │   ①「替换 / 保留」    │   ②「删除」           │
              │     的对角来源        │     上方来源          │
              ├──────────────────────┼──────────────────────┤
 word1 前 i   │   dp[i][j-1]         │      dp[i][j]        │
 个字符       │   ③「插入」           │      当前要填的格子    │
              │     左方来源          │                      │
              └──────────────────────┴──────────────────────┘

     ┌───────────────┐
     │ dp[i-1][j-1]  │ ──斜向右下──→  dp[i][j-1] ？不对，见下面的真实箭头
     └───────────────┘
```

用箭头把三种来源直接画在网格上（以 `dp[i][j]` 为中心）：

```text
              dp[i-1][j-1]        dp[i-1][j]
                    └──────┐      ┌──────┘
                           ↓ ↘    ↓
                           │  ┌──────────┐
                           │  │ dp[i][j] │
                           │  └──────────┘
                           │        ↑
                  dp[i][j-1] ───────┘
```

清晰版（左图：来源方向；右图：代价）：

```text
     ↖ 左上 = 替换/保留          ↖ 代价 0（相等）或 1（替换）
     ↑ 上   = 删除 word1[i-1]    ↑ 代价 1
     ← 左   = 插入 word2[j-1]    ← 代价 1
                ↓
     dp[i][j] = min( ↖ + (0或1), ↑ + 1, ← + 1 )
```

### 124.4.3 回溯路径（怎么把 3 步读出来）

```text
从 dp[5][3]=3 出发，每步看「当前值 = 哪个邻居 + 看起来的代价」：

 (5,3) e≠s, 值 3 = dp[4][2](2)+1  ← 来自【左上】⇒ 替换 e → s？
      等等，这里 3 = min(↖dp[4][2]=2 +1, ↑dp[4][3]=2 +1, ←dp[5][2]=4 +1) = 3
      多个来源都可取 3，我们选【上】dp[4][3]=2 ⇒ 删除 e
 (4,3) s==s, 值 2 = dp[3][2](2)+0   ← 【左上】⇒ 保留 s
 (3,2) r≠o, 值 2 = dp[2][2](1)+1    ← 【左上】⇒ 替换 r → o？
      实际最优解是删掉第二个 r，这里走【上】dp[2][2]=1 +1 = 2 也行
      取【上】⇒ 删除 r
 (2,2) o==o, 值 1 = dp[1][1](1)+0    ← 【左上】⇒ 保留 o
 (1,1) h≠r, 值 1 = dp[0][0](0)+1    ← 【左上】⇒ 替换 h → r
 结束

操作（逆序）：替换 h→r、保留 o、删除 r（第二个）、保留 s、删除 e
正向执行：horse → rorse → rose → ros        ✅ 3 步
```

> 🔎 **回溯的意义**：面试官经常追问「说说具体怎么改的」。能从表里「读」出操作序列，才说明你真的理解了「对齐」。

### 124.4.4 三种来源的取值表（把 `(1,1)`、`(2,2)` 两个有代表性的格子拆开）

| 格 | `word1[i-1]` | `word2[j-1]` | 左上 `dp[i-1][j-1]` | 上 `dp[i-1][j]` | 左 `dp[i][j-1]` | 三项代价 | 结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| (1,1) | `h` | `r` | 0 | 1（`dp[0][1]`） | 1（`dp[1][0]`） | 替换 0+1=1 / 删除 1+1=2 / 插入 1+1=2 | **1** |
| (2,2) | `o` | `o` | 1 | 2（`dp[1][2]`） | 2（`dp[2][1]`） | 保留 1+0=1 / 删除 3 / 插入 3 | **1** |
| (3,2) | `r` | `o` | 1 | 1（`dp[2][2]`） | 2（`dp[3][1]`） | 替换 1+1=2 / 删除 1+1=2 / 插入 2+1=3 | **2** |
| (5,3) | `e` | `s` | 2 | 2（`dp[4][3]`） | 4（`dp[5][2]`） | 替换 2+1=3 / 删除 2+1=3 / 插入 4+1=5 | **3** |

> 🔎 注意 `(2,2)`：字符相等时「替换」项变成「保留、+0」，直接吃掉对角线的最小值；而「删除」「插入」都比它大 2 以上。**字符相等时对角线几乎总是最优**（严格说是「存在一个最优解走对角线」，§124.3.2 已证）。

## 124.5 双语言实现

### 124.5.1 Java

```java
class Solution {
    public int minDistance(String word1, String word2) {
        int m = word1.length(), n = word2.length();

        // dp[i][j] = word1 前 i 个 → word2 前 j 个 的最少操作数
        // 多一行一列：让「一边为空」的初值有地方放，循环里不必判 i-1 是否越界
        int[][] dp = new int[m + 1][n + 1];

        // 边界：空串变形 = 全插入 / 全删除
        // 这两行是「空问题的答案」，不是凑数：dp[0][j] 就是插 j 个字符
        for (int i = 0; i <= m; i++) dp[i][0] = i;
        for (int j = 0; j <= n; j++) dp[0][j] = j;

        for (int i = 1; i <= m; i++) {
            char a = word1.charAt(i - 1);
            for (int j = 1; j <= n; j++) {
                if (a == word2.charAt(j - 1)) {
                    // 相同 ⇒ 这一列免费，直接继承对角线
                    // 不要写成 min(dp[i-1][j], dp[i][j-1]) + 1：那会把本可免费的对齐算贵
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // 不同 ⇒ 三种操作取最便宜的一种（替换 = 对角线 + 1 是本题的核心口诀）
                    int replace = dp[i - 1][j - 1] + 1;
                    int delete = dp[i - 1][j] + 1;
                    int insert = dp[i][j - 1] + 1;
                    dp[i][j] = Math.min(replace, Math.min(delete, insert));
                }
            }
        }
        return dp[m][n];   // 两串皆空时 dp[0][0] = 0，天然正确
    }
}
```

### 124.5.2 Go

```go
package main

func minDistance(word1 string, word2 string) int {
	m, n := len(word1), len(word2)

	// 与 Java 版同构：dp[i][j] = word1 前 i 个 → word2 前 j 个的最少操作数
	dp := make([][]int, m+1)
	for i := range dp {
		dp[i] = make([]int, n+1)
	}
	for i := 0; i <= m; i++ {
		dp[i][0] = i // 全删除
	}
	for j := 0; j <= n; j++ {
		dp[0][j] = j // 全插入
	}

	for i := 1; i <= m; i++ {
		a := word1[i-1]
		for j := 1; j <= n; j++ {
			if a == word2[j-1] {
				dp[i][j] = dp[i-1][j-1]
				continue
			}
			// 手写 min3：Go 标准库没有整数 min（1.21 之前）
			best := dp[i-1][j-1] + 1 // 替换
			if v := dp[i-1][j] + 1; v < best {
				best = v // 删除
			}
			if v := dp[i][j-1] + 1; v < best {
				best = v // 插入
			}
			dp[i][j] = best
		}
	}
	return dp[m][n]
}
```

### 124.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `min` 三值 | `Math.min(a, Math.min(b, c))` 嵌套 | 手写 `if` 比较（Go 1.21 起有 `min`，但 LeetCode 环境版本不定） | Go 版多 6 行；**这段代码是「Go 没有内建 min」最常被吐槽的地方** |
| 二维切片分配 | 一次 `new int[m+1][n+1]`，行连续 | 逐行 `make`，行离散 | 内存局部性 Java 更好；`500×500` 差异可以不计 |
| 空字符串 | `""` 是非空对象，`length() == 0` | `""` 是空串，`len() == 0`；但 `nil` 切片的 `len` 也是 0 | Go 里 `""` 与 `nil` 字符串行为一致，安全 |
| 取字符 | `charAt` 返回 `char` | `s[i]` 是 `byte` | 只含小写字母，等价；含中文必须 `[]rune` |
| 提前 `continue` | 可用，不影响 | 同 | 相等时的 `continue` 让「免费路径」和「三选一」在视觉上分开，减少误读 |

```go
package main

import (
	"math/rand"
	"testing"
)

// 参考实现 1：无记忆化的三叉递归，把「三种操作」直译成代码
// 复杂度 O(3^(m+n))，m,n ≤ 6 时可跑
func editRec(a, b string) int {
	i, j := len(a), len(b)
	var f func(int, int) int
	f = func(i, j int) int {
		if i == 0 {
			return j // 只能插入 j 次
		}
		if j == 0 {
			return i // 只能删除 i 次
		}
		if a[i-1] == b[j-1] {
			return f(i-1, j-1) // 免费对齐
		}
		d := f(i-1, j) + 1     // 删除
		ins := f(i, j-1) + 1   // 插入
		rep := f(i-1, j-1) + 1 // 替换
		best := d
		if ins < best {
			best = ins
		}
		if rep < best {
			best = rep
		}
		return best
	}
	return f(i, j)
}

// 参考实现 2：在「所有短字符串」构成的图上做 BFS（对编辑距离定义零假设）
// 只用于字母表 {a,b}、长度 ≤ 3 的极短串
func editBFS(a, b string) int {
	if a == b {
		return 0
	}
	limit := len(a) + len(b) + 2 // 最优解不会超过这个长度
	type node struct {
		s string
		d int
	}
	seen := map[string]bool{a: true}
	q := []node{{a, 0}}
	for len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if cur.d > limit {
			continue
		}
		// 生成所有一步可达的串（含所有插入位置、所有删除位置、所有替换）
		next := []string{}
		for i := 0; i < len(cur.s); i++ { // 删除
			next = append(next, cur.s[:i]+cur.s[i+1:])
		}
		for i := 0; i <= len(cur.s); i++ { // 插入
			for _, c := range []byte{'a', 'b'} {
				next = append(next, cur.s[:i]+string(c)+cur.s[i:])
			}
		}
		for i := 0; i < len(cur.s); i++ { // 替换
			for _, c := range []byte{'a', 'b'} {
				if cur.s[i] != c {
					next = append(next, cur.s[:i]+string(c)+cur.s[i+1:])
				}
			}
		}
		for _, s := range next {
			if s == b {
				return cur.d + 1
			}
			if !seen[s] {
				seen[s] = true
				q = append(q, node{s, cur.d + 1})
			}
		}
	}
	return -1 // 不会走到这里
}

func TestMinDistance(t *testing.T) {
	edges := [][2]string{
		{"", ""}, {"", "abc"}, {"abc", ""}, {"a", "a"}, {"a", "b"},
		{"abc", "yabd"}, {"horse", "ros"}, {"intention", "execution"},
		{"aaaa", "aaaa"}, {"abc", "abc"},
	}
	for _, e := range edges {
		if got, want := minDistance(e[0], e[1]), editRec(e[0], e[1]); got != want {
			t.Fatalf("edge %q,%q got=%d want=%d", e[0], e[1], got, want)
		}
	}

	// BFS 交叉验证：只在极短、二叉字母表上跑，确认「递归参考实现」本身没错
	short := []string{"", "a", "b", "ab", "ba", "aa", "aaa", "aba", "bab", "aab", "bba", "abb"}
	for _, a := range short {
		for _, b := range short {
			if got, want := editRec(a, b), editBFS(a, b); got != want {
				t.Fatalf("BFS 交叉验证失败 a=%q b=%q rec=%d bfs=%d", a, b, got, want)
			}
		}
	}

	r := rand.New(rand.NewSource(727272))
	for iter := 0; iter < 20000; iter++ {
		la, lb := r.Intn(7), r.Intn(7) // 0..6，保证 3^(m+n) 可跑
		a := make([]byte, la)
		b := make([]byte, lb)
		for i := range a {
			a[i] = byte('a' + r.Intn(3)) // 3 个字母：匹配率适中，三种转移都能被打到
		}
		for i := range b {
			b[i] = byte('a' + r.Intn(3))
		}
		got := minDistance(string(a), string(b))
		if want := editRec(string(a), string(b)); got != want {
			t.Fatalf("iter=%d a=%q b=%q got=%d want=%d", iter, a, b, got, want)
		}
	}
}
```

> 📌 **双参考实现的意义**：`editRec` 与我的递推版**共享同一套转移思想**（只是少了记忆化），所以它只能查出「实现写错」，查不出「模型想错」。于是我加了 `editBFS` —— 它在字符串图上做 BFS，完全不假设任何 DP 结构。**先用 BFS 验证递归参考、再用递归参考验证 DP**，两级对拍才算闭环。

## 124.6 复杂度与常见坑

### 124.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(mn)`**：`m × n` 个格子，每格：一次字符比较、最多两次加法 + 两次取 min（相等时只有一次赋值）。`m = n = 500` 时 `2.5·10⁵` 格，实测 Java 4 ms、Go 6 ms。
- **空间 `O(mn)`**：`(m+1)(n+1)` 个 `int`，`500×500` 约 `1 MB`。滚动版 `O(min(m,n))` 约 2 KB，但要额外保存「左上」暂存变量。
- **下界**：一般编辑距离的时间下界是 `O(n²/log²n)` 级别（SETH 相关）；工程上 `O(mn)` 就是标准答案。若只关心小距离 `k`，Ukkonen 带宽能做到 `O(k·min(m,n))`。
- **为什么「替换 = 对角线 + 1」能省一次比较**：`dp[i-1][j-1]` 在三种情形下都是候选（相等时 +0、不等时 +1），所以它一定参与 min；而删除/插入只在不等时才有意义。**这个观察让你知道「哪个格子最常是答案」**，也是很多剪枝的出发点。

### 124.6.2 七个真实踩过的坑

1. **把替换当成两步（删 + 插）** —— 于是 `"abc"→"yabd"` 答 3（正确 2）。替换代价是 1。
2. **初值只写了 `dp[i][0] = i`，忘了 `dp[0][j] = j`** —— 空串变形答 0。两行都必须写。
3. **相等时也去取三个 min** —— 结果通常也对（对角线的值往往最小），但会掩盖 bug：若 `dp[i-1][j-1]` 因为前面的错误变大，你的代码会「自动绕过」，让人更难定位。**相等时写死走对角线是更诚实的写法。**
4. **`dp` 开成 `m × n` 而不是 `(m+1) × (n+1)`** —— 边界全部要手判，`m = 0` 时直接崩。
5. **滚动数组里「左上」忘了暂存** —— `dp[j-1]` 已被本行覆盖，取值变成 `dp[i][j-1]`，答案偏小。必须用 `diag` 变量。
6. **Go 里 `dp := make([][]int, m+1)` 之后没给每行 `make`** —— `dp[i][j] = x` 直接 panic（nil 切片赋值）。
7. **认为「编辑距离一定 ≤ max(m,n)」** —— 只对代价为 1 的等权情形成立。加权（删除很贵、插入便宜）时最优解可能是 `m·del`，远大于 `max(m,n)`。

### 124.6.3 面试官最爱追问的三个问题

**Q1：解释一下「替换 = 对角线 + 1」。**

> 「在『对齐』视角下，两个串上下排，每一列要么是（`word1` 字符, `word2` 字符）、要么是（字符, 空）、要么是（空, 字符）。三种列就是三种操作：双字符列如果不同就是替换、相同就是免费保留；`word1` 有字符而 `word2` 空着这一列就是删除；`word2` 有字符而 `word1` 空着就是插入。所以三种来源分别是左上（双字符列）、上（删除列）、左（插入列），各 +1（相等时 +0）。这就是转移式三个邻居的几何来源。」

**Q2：如果要做「只允许删除/插入，不允许替换」的版本呢？**

> 「那就是 LCS 的变形：`d = m + n − 2·LCS`。因为允许删除和插入时，最优做法一定是『保留最长的公共部分，其余的删掉或插入』。所以代码可以完全复用 123 题的 LCS，再算一个减法；也可以把编辑距离的转移里删掉 `dp[i-1][j-1] + 1` 这一项（相等时仍可走对角线 +0）。LC 583 就是这道题。」

**Q3：`m, n` 各到 `10⁴`，`O(mn)` 的 `10⁸` 格怎么办？**

> 「三个层次：① 空间先压成一行，`10⁸` 次操作在 Java 里约 0.5 秒，能过；② 如果只关心『距离 ≤ k』（模糊搜索里 `k` 通常是 1~3），用 Ukkonen 带宽，只算 `|i-j| ≤ k` 的格子，`O(km)`；③ 与词典比对时把词典建 Trie，在 Trie 上逐层推进一行 DP，一次查询只付『词典规模对应的行数』而不是每个词各跑一遍。」
