## 071.1 题目

**原题链接**：<https://leetcode.cn/problems/diameter-of-binary-tree/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root`，返回这棵树的**直径**：树中任意两个节点之间**最长路径的长度**。

而 LeetCode 543 的官方注释写得很清楚：**这条路径的长度用「边数」计量**。这句注释是本题第一个陷阱，务必读出来。

一句话就说完的题，藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 长度是**边数**，不是节点数 | 官方注释「路径长度是以它们之间边的数目表示」 | 全按节点数算 → 每个答案都大 1（单结点树返回 `1`，应为 `0`） |
| 路径**不一定经过根** | 「这条路径可能经过也可能不经过根节点」 | 只算「左高 + 右高」→ 直径在子树内部时答案偏小 |
| 可以只走**一个节点** | 两个端点可以重合 | 单结点树返回 `0` 才是对的 |
| 端点可以是**任意两个节点**（不必是叶子） | 「任意两个节点」 | 硬凑成「两个叶子之间」→ 在某些树上漏掉更长的路径 |
| 只求**长度**，不用给出路径 | 「返回……长度」 | 花力气记录路径 → 白做（要给出路径是追问，见 §071.6.3） |

> 📌 **本章在全书里的位置**：068 已经立了「后序返回值」，本章第一次让返回值**背叛**题目：
> **函数返回的是「单边高度」，而题目要的是「左高 + 右高」的最大值。** 两者不是同一个东西。
> 这道分水岭一旦越过，074（最大路径和）、080（打家劫舍 III）、687（最长同值路径）、124 全部一看就懂；越不过去，就会在每道题里反复写 `return 1 + left + right` 这种把答案当高度交上去的错。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `[1, 10⁴]` | 最多 1 万（**注意不含空树**） | O(n) 与 O(n²) 都能过，但 O(n²) = 10⁸ 次，接近 TLE；本题明确想考 O(n) |
| `-100 <= Node.val <= 100` | 值不参与运算 | 纯结构问题 |
| 树不保证平衡 | 可能是全左链 | 全左链的直径 = `n-1`（一条链本身），是很好的自测用例 |
| 返回 `int` | 单个整数 | 不需要容器 |

> 💡 **量级 → 算法**：`n ≤ 10⁴` 时 O(n²) 是 **10⁸ 级别**，Java 约 200~400 ms、Go 约 100 ms，属于「能过但很难看」。
> 本题真正的门槛是**复杂度从 O(n·h) 降到 O(n)** 的那一步：它靠的不是更快的遍历，而是**「在一次后序遍历里同时算高度和直径」**。
> 而要做到这一点，你必须先接受一件事：**函数的返回值不是答案。**

### 示例

```
示例 1
输入：root = [1, 2, 3, 4, 5]
输出：3
解释：最长路径是 4 → 2 → 1 → 3 或 5 → 2 → 1 → 3，都含 3 条边。

            1
         ┌──┴──┐
         2     3
       ┌─┴┐
       4   5

   路径 4→2→1→3：边数 = 3
   路径 4→2→5：  边数 = 2
   所以直径 = 3

示例 2
输入：root = [1, 2]
输出：1
解释：唯一的路径是 1 → 2，1 条边。

示例 3
输入：root = [1]
输出：0
解释：只有一个节点，没有边。
```

### 我自造的三个反例（写完必须拿它们打一遍）

```text
① [1]                      → 必须返回 0（不是 1）。暴露「按节点数算」的错
② [1,2]                    → 必须返回 1。暴露「空树/单边」边界
③ 直径不在根上的树（层序 [1,2,null,3,4,5,null,null,6]）：
        1
        │
        2
       ┌┴┐
       3 4
      ┌┘ └┐
      5   6
   过根的最长路径是 5→3→2→1 = 3 条边
   但直径是 5→3→2→4→6 = 4 条边，其"最高点"是 2，完全不经过根！
   → 暴露「只算 root.left 高 + root.right 高」的错
```

第 ③ 条是本章最关键的用例。它的输出 `4` 比「过根的最大值 `3`」更大，**一条断言就能把错误思路钉死**。

## 071.2 从暴力到最优：第一个念头为什么错

### 第一个念头：直径 = 左子树深度 + 右子树深度

```java
public int diameterOfBinaryTree(TreeNode root) {
    return depth(root.left) + depth(root.right);     // ❌ 只考虑"过根"的路径
}
```

- 时间 **O(n)**（`depth` 各走一遍，共 O(n)），空间 O(h)。
- 反例 §071.1 ③：过根的最长路径只有 `3` 条边，而真正的直径是 `4`（藏在左子树内部）。**`root` 只是「最高点」的一个候选，不是唯一候选。**

```
为什么想法会错：把「最高点」误当成了根
        1                    ← 以 1 为最高点：左臂 3 + 右臂 0 = 3
        │
        2                    ← 以 2 为最高点：左臂 2 + 右臂 2 = 4   ★ 真正的答案在这里
       ┌┴┐
       3 4
      ┌┘ └┐
      5   6
```

### 第二个念头：对每个节点都算一次「左高 + 右高」（O(n·h)）

把第一个念头补全：既然最高点可能是任意节点，那就**枚举每个节点**当最高点：

```java
public int diameterOfBinaryTree(TreeNode root) {
    if (root == null) return 0;
    int throughRoot = depth(root.left) + depth(root.right);          // 以 root 为最高点
    int inner = Math.max(diameterOfBinaryTree(root.left),            // 最高点在左子树里
                         diameterOfBinaryTree(root.right));          // 最高点在右子树里
    return Math.max(throughRoot, inner);
}
```

- 时间 **O(n·h)**：每个节点都调用了两次 `depth`，而 `depth` 本身是 O(子树大小)。对链状树 `h = n`，总代价 **O(n²) = 10⁸**（`n = 10⁴`）。
- **它是对的**，而且思路清楚：把「最高点是哪个节点」显式枚举出来。这是很好的第一版。
- 问题在于**重复计算**：`depth(v)` 在 `v` 的每个祖先处都被重新算了一遍 —— 同一个子树的高度被算了 `h` 次。

```
重复劳动可视化（n = 10⁴ 全左链）：
  最底层节点的 depth 被算了 ~10⁴ 次
  次底层 ~10⁴-1 次
  ...
  总计 ≈ n²/2 = 5·10⁷ 次 —— 每次只为了拿一个数
```

### 第三个念头：让函数直接返回「直径」（看起来最省事，其实最麻烦）

```java
public int diameter(TreeNode node) {
    if (node == null) return 0;
    int l = diameter(node.left);
    int r = diameter(node.right);
    return Math.max(Math.max(l, r), depth(node.left) + depth(node.right));  // ❌ 还是绕回去了
}
```

- 你很快会发现：要算 `depth(node.left) + depth(node.right)`，还是得再求一次高度 —— 于是又回到 O(n·h)。
- **根本原因**：一个节点的子树里有两类信息要往上带：
  1. **高度**（父节点需要它，用来算「穿过父节点的路径」）；
  2. **直径**（父节点不需要它算自己的高度，但**答案要取全局最大**）。
  
  **一个 `int` 返回值装不下两个量。** 这就是本章真正的卡点。

### 卡点在哪

> **卡点：返回值只有一个槽位，而节点想往上汇报两件事。**

| 想汇报的量 | 父节点要不要 | 能不能向上叠加 | 结论 |
| --- | --- | --- | --- |
| 子树**高度** | **要**（父节点的「左高」「右高」就是它） | 能：`1 + max(lh, rh)` | **必须放进返回值** |
| 以本节点为最高点的**路径长度** `lh + rh` | **不要** | 不能：这条路径在父节点处就断了（父节点无法把两条臂同时接上） | **只能记到全局答案里** |

一句话：**能继续往上用的，交给返回值；到本节点就结束的，交给全局变量。**

### 灵感的来源 —— 「以 v 为最高点的最长路径」

任何一条树上的路径 `u ⇝ w`，都有一个**最高点** `t`（即 `u` 与 `w` 的最近公共祖先）。在 `t` 处，这条路径被拆成两段：一段沿 `t` 的左侧往下，一段沿右侧往下。于是：

```
以 t 为最高点的最长路径长度 = t 的左子树高度 + t 的右子树高度
（高度用"边数"计：空子树高 0，这样"左高 + 右高"天然就是边数）
```

而全树的直径就是：

```
直径 = max over 所有节点 t ( 左高(t) + 右高(t) )
```

有了这个式子，只差最后一步：**怎么在一次遍历里同时拿到所有 `t` 的左右高度？** 答案就是后序遍历 —— 因为后序回来时，左右子树的高度**刚刚算好、正在手里**：

```
后序在 t 处的时刻：
    ├─ 递归左子树 → 交回 lh      ← 现成的
    ├─ 递归右子树 → 交回 rh      ← 现成的
    ├─ ① ans = max(ans, lh + rh)          ← 立即把"能当答案的部分"记下来
    └─ ② return 1 + max(lh, rh)           ← 只把"能往上用的部分"交上去
```

> 这两行的分工，就是本章全部。**① 记答案（不往上交），② 交高度（不当答案）。**

## 071.3 原理拆解

### 071.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| **后序 + 全局 `ans`** ✅ 首选 | O(n) | O(h) 栈 | 12 行 | 全局状态（多线程要小心）；深链树爆栈 |
| 后序 + 返回 `int[]{height, diameter}` | O(n) | O(h) + 每层一个小数组 | 15 行 | 每层都要分配一个数组，常数更大；但**无全局状态、可重入** |
| 后序 + 返回结构体 `(h, d)`（Go） | O(n) | O(h) | 15 行 | 同上，Go 里值传递结构体常数更小 |
| 枚举每个节点的 `depth(l)+depth(r)` | O(n·h) | O(h) | 15 行 | 链状树 O(n²) = 10⁸，`n = 10⁴` 已到边缘 |
| 只算过根的路径 | O(n) | O(h) | 3 行 | **答案错**（直径可能在子树内部） |
| 两遍扫描：先算高度存起来，再枚举 | O(n) | O(n) 或 O(n log n) | 25 行 | 要额外的「节点 → 高度」映射，空间和管理都变复杂 |
| 用 `BFS` 求所有点对距离 | O(n²) | O(n) | 30 行 | 纯暴力，只适合作对拍裁判 |

**为什么「后序 + 全局 `ans`」是首选**：

- 一次遍历拿到全部信息，时间 O(n)；
- 代码只要两行额外内容（`ans = max(ans, lh+rh)` 与 `return 1+max(lh,rh)`），读者一眼就能看出「答案」和「返回值」的分工；
- 与 068 的骨架完全兼容 —— **把 068 的 `return 1 + max(lh, rh)` 一字不改地复用，只多插一行记答案。**

**什么时候改用「返回一对值」**：如果这个函数处于多线程环境、或者要在一个程序里对多棵树并发调用，全局变量就不安全。此时返回 `(height, diameter)` 是**无状态**版本，代价是每层一次小分配。

### 071.3.2 为什么这个做法是对的（正确性论证）

先证两个引理。

**引理 1（路径的最高点分解）**：任取树中两个节点 `u`、`w`，令 `t = LCA(u, w)`。则路径 `u ⇝ w` 的边数 = `d(u, t) + d(w, t)`，其中 `d` 表示「沿树边的距离」，且其中一段落在 `t` 的左侧（或为空）、另一段落在右侧（或为空）。

**证明**：`LCA` 的定义保证 `u`、`w` 分别在 `t` 的两棵**不同**子树中（或其中之一就是 `t` 本身）。树上两点间路径唯一，必然先各自上行到 `t` 再下行，故边数相加。∎

**引理 2**：对任意节点 `t`，令 `lh(t)`、`rh(t)` 为其左右子树的**高度（边数，空树为 0）**，则「以 `t` 为最高点的最长路径长度」恰为 `lh(t) + rh(t)`。

**证明**：以 `t` 为最高点的路径由两段组成 —— 一段从 `t` 沿左侧往下走到底（最长即 `lh(t)`），另一段沿右侧往下走到底（最长即 `rh(t)`）；每一段都是「`t` 到某个后代」的最长路径（由引理 1 的分解式）。两段可以各自独立地取到最长（互不干扰，因为一个在左子树、一个在右子树），故最大值为二者之和。∎

**定理（主命题）**：设 `ans` 为算法所有 `ans = max(ans, lh + rh)` 更新的最终值，则 `ans` 等于全树直径。

**证明**：

1. **上界**：任取一条路径 `P`，设其最高点为 `t`。由引理 1、2，`|P| ≤ lh(t) + rh(t) ≤ ans`（`ans` 取过所有节点的这个值）。所以直径为 `max |P| ≤ ans`。
2. **可达**：取达到 `ans` 的那个节点 `t*`（`ans = lh(t*) + rh(t*)`）。把「`t*` 左子树里最深的那条路径」与「右子树里最深的那条」接起来，得到一条真实的、长度为 `lh(t*) + rh(t*)` 的路径（它的最高点是 `t*`）。所以 `ans ≤ 直径`。
3. 两个方向合并：`ans = 直径`。∎

**引理 3（返回值正确）**：函数返回值 `h(v)` 恰好等于 `v` 子树的**高度（边数）**。

**证明（结构归纳）**：`h(null) = 0`，即空子树高度 0 ✅。对非空 `v`，`h(v) = 1 + max(h(l), h(r))`，由归纳假设 `h(l)`、`h(r)` 是左右子树高度，故 `h(v)` 是「从 `v` 出发最深的边数」，即高度。∎

> **注意 `h(null) = 0` 的妙处**：本题用**边数**计量，于是「单结点子树的高度 = 0」，「叶子处 `lh + rh = 0 + 0 = 0`」—— 与「单结点树直径为 0」完全一致。**如果改用节点数（`h(∅) = 0`、`h(叶) = 1`），那么 `lh + rh` 会变成「节点数 − 1」的错位答案，必须再减 1 或改定义。**
> 这就是 068 §068.3.2 那句「空单位元要由定义反推」的第二个实例。

### 071.3.3 通用解题思路（本章核心：返回值 ≠ 答案）

#### ① 「可上传量」与「局部答案」——本书树递归语言的第三条

068 立了两个范式，070 立了双指针，本章立**第三个概念：一个节点上有两类信息，必须分开走**。

| 类型 | 定义 | 归宿 | 本章实例 | 其它题的实例 |
| --- | --- | --- | --- | --- |
| **可上传量**（uploadable） | 父节点还能继续用的信息，能沿路径叠加 | 函数**返回值** | 单边高度 `h(v)` | 074 的「单边最大贡献」、070 的 `boolean` |
| **局部答案**（local answer） | 到本节点就结算完毕、父节点用不上 | **全局变量 / 引用参数** | `lh + rh` | 074 的「整体最大路径和」、687 的「最长同值路径」 |

判断一个量属于哪一类，只需问一句：

> **「父节点拿到这个数以后，还能拿它继续算出更大的答案吗？」**
> 能 ⟹ 可上传量，进返回值。不能（或含义会变） ⟹ 局部答案，进全局。

**「父节点拿到 `lh + rh` 能继续用吗？」** 不能。因为一条路径在 `v` 处已经「用了两条臂」，父节点无法把它再往上接第三段 —— 父节点能接的只有「从 `v` 一路向上的那一条臂」。

#### ② 068 与 071 的正面比较（把差别钉死）

| 维度 | 068 最大深度 | 071 直径 |
| --- | --- | --- |
| 返回值 | `h(v)` = 子树高度 | `h(v)` = 子树高度（**一样**） |
| 题目答案 | 就是 `h(root)` | **不是**返回值，是 `max(lh + rh)` |
| 答案在哪产生 | 根节点（递归终点） | **每个节点都可能**产生 |
| 需要额外状态 | 不需要 | **需要**（全局 `ans` 或返回对） |
| 少写会怎样 | 无 | 只写 `return 1 + max(...)` → 得到的是「树高」而不是「直径」 |
| 多写会怎样 | 无 | 把 `return` 写成 `1 + lh + rh` → **答案被污染**（见 §071.6.2 坑 1） |

#### ③ 三种「装下两个量」的写法（一次写清，074/080 直接照搬）

| 写法 | 骨架 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **全局变量 + 返回值只管高度** ✅ | `ans = max(ans, lh+rh); return 1+max(lh,rh);` | 代码最短，常数最小 | 有状态；多线程不安全；Java 里要用字段或 `int[]` |
| **返回 `int[]{h, d}`** | `return new int[]{1+max(lh,rh), max(dl, dr, lh+rh)};` | 无状态、可重入 | 每层一次小数组分配 |
| **返回结构体（Go）** | `type Info struct{ h, d int }` | 无状态，值传递，常数低 | 代码稍长 |

> 🧭 **一句话记忆**：
> **「答案在节点处结算，高度沿路径上传。」**
> 这句话在 074（最大路径和）里变成「答案取 `v.val + max(0,lh) + max(0,rh)`，上传 `v.val + max(0, max(lh,rh))`」；在 687 里变成「答案取同值链相加，上传同值的最长单边」；在 080 里变成「答案取两套方案的最大，上传两套方案」。**骨架一个都不变。**

#### ④ 为什么必须后序（不能用前序）

前序（进入节点时）拿到的是「父节点传下来的上下文」，而 `lh`、`rh` 需要**子树算完**才能知道。所以「记答案」这一步只能放在两次递归之后 —— 这也解释了为什么本章**没有**传参版本：`lh + rh` 这个量本质上是「子树上行的结果」，不是「父节点下行的上下文」。

### 071.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要输出**这条路径本身** | 不只长度 | 在更新 `ans` 时记下「取得最大值的节点 + 最深的两条分支」，最后向上回溯拼路径 |
| 边上有**权**（可正可负） | 高度换成「最大下行和」 | 上传量改为 `w(v, child) + best(child)`，负数截断；这就是 124 的思想 |
| 求**最长同值路径**（687） | 路径上值必须相同 | 上传量加一个「同值条件」：只有 `child.val == v.val` 时才累加 |
| 树是 **N 叉** | 孩子不定 | 每个节点维护**最大的两个**孩子高度（`top1`、`top2`），`ans = max(ans, top1 + top2)` |
| **每个节点**都要求一次直径（多次查询） | 不能只给全局最大 | 沿树做「换根 DP」/rerooting：用一次 DFS 预计算，再 O(1) 回答每个节点 |
| 树极深，不许递归 | 爆栈 | 显式栈后序（065 §3.3 ②）在弹出时拿到两个孩子的高度；或 BFS 反拓扑序（按层记录，从底层往上算） |

## 071.4 图解推演

### 071.4.1 用示例 1 走一遍

```
                1
             ┌──┴──┐
             2     3
           ┌─┴┐
           4   5

后序顺序：4 → 5 → 2 → 3 → 1

节点 4（叶）：lh=0, rh=0 → ans = max(0, 0+0) = 0 ; return 1+max(0,0) = 1
节点 5（叶）：lh=0, rh=0 → ans = max(0, 0+0) = 0 ; return 1
节点 2     ：lh=1(来自4), rh=1(来自5) → ans = max(0, 1+1) = 2 ; return 1+1 = 2
节点 3（叶）：lh=0, rh=0 → ans = max(2, 0) = 2 ; return 1
节点 1     ：lh=2(来自2), rh=1(来自3) → ans = max(2, 2+1) = 3 ; return 1+max(2,1) = 3

最终 ans = 3 ✅ ；而函数返回值是 3（树的"高度"= 3 条边）—— 恰好相等，纯属巧合
```

> ⚠️ 最后那句「巧合」很重要：示例 1 里返回值与答案同为 3，**这会误导你以为返回值就是答案**。§071.4.2 会给出一张对照表，列出「两者相等」和「两者不等」的各种树形 —— **只有两者不同时，才能看出你有没有分清它们。**

### 071.4.2 反例 ③ 的完整轨迹（直径藏在子树内部）

```
        1
        │
        2
       ┌┴┐
       3 4
      ┌┘ └┐
      5   6

后序顺序：5 → 3 → 6 → 4 → 2 → 1

节点 5：lh=0, rh=0 → ans = max(0, 0) = 0 ;  return 1
节点 3：lh=1(来自5), rh=0 → ans = max(0, 1) = 1 ;  return 1+max(1,0) = 2
节点 6：lh=0, rh=0 → ans = max(1, 0) = 1 ;  return 1
节点 4：lh=0, rh=1(来自6) → ans = max(1, 1) = 1 ;  return 1+max(0,1) = 2
节点 2：lh=2(来自3), rh=2(来自4) → ans = max(1, 4) = 4 ★ ;  return 1+2 = 3
节点 1：lh=3(来自2), rh=0 → ans = max(4, 3) = 4 ;  return 1+3 = 4

最终 ans = 4（答案：路径 5→3→2→4→6 的 4 条边）
而节点 1 返回的 4 是"节点数口径"的高度（等价于 3 条边）—— 数值碰巧相同，含义完全不同
```

**返回值与答案到底什么时候相等？** 下面四种树形一次说清（`返回值`用的是「节点数口径」，`答案`用的是「边数口径」）：

| 树形 | 返回值 `h(root)` | 答案（直径） | 相等？ | 说明 |
| --- | --- | --- | --- | --- |
| 空树 `[]` | `0` | `0` | ✅ | 两者都是 0，没有路径 |
| 单结点 `[1]` | `1` | `0` | ❌ | 返回值数了根自己，直径要求「两点之间的边」 |
| 左链 4 个节点 | `4` | `3` | ❌ | 链上直径就是全长减一 |
| 满二叉树 7 个节点 | `3` | `4` | ❌ | 直径走两条臂（叶到叶），返回值只走一条 |
| 反例 ③ `[1,2,null,3,4,5,null,null,6]` | `4` | `4` | ✅（巧合） | 两种口径恰好同值 |

> 🧭 **这张表的结论**：`h(root)` 和直径**没有任何必然关系** —— 有时相等、有时不等，纯属口径巧合。
> 所以「把 `return` 当成答案」不是「近似正确」，而是**逻辑上无关**：它只是偶尔撞对了。
> 想一次看穿，只需记住本章那两行分工：`ans` 收「两臂之和」，`return` 交「单臂长度」。

### 071.4.3 逐步状态表（行 = 节点，列 = 变量）

（数据取自 §071.4.2 的反例 ③：`1 → 2`，`2` 的左 `3`、右 `4`，`3` 的左 `5`，`4` 的右 `6`）

| 节点（后序） | `lh` | `rh` | `lh + rh` | 更新后 `ans` | 返回值 |
| --- | --- | --- | --- | --- | --- |
| `5` | 0 | 0 | 0 | 0 | 1 |
| `3` | 1 | 0 | **1** | **1** | 2 |
| `6` | 0 | 0 | 0 | 1 | 1 |
| `4` | 0 | 1 | **1** | 1 | 2 |
| `2` | 2 | 2 | **4** | **4** ★ | 3 |
| `1` | 3 | 0 | 3 | 4 | 4 |

### 071.4.4 「可上传量」与「局部答案」的分流图

```
                        ┌──────── 后序回到节点 v ────────┐
                        │                               │
        ┌───────────────▼──────────────┐   ┌────────────▼─────────────┐
        │ 局部答案：lh + rh            │   │ 可上传量：1 + max(lh,rh) │
        │ 父节点用不上（路径已闭合）   │   │ 父节点需要它算自己的臂长 │
        └───────────────┬──────────────┘   └────────────┬─────────────┘
                        │                               │
              ans = max(ans, lh+rh)                 return 给父节点
                        │                               │
                 【全局变量 ans】                  【函数返回值】
                        │                               │
                最终答案从这里取                    往上继续累加
```

### 071.4.5 两条路线对比（O(n·h) vs O(n)）

```
              ┌──────── 枚举每个节点当"最高点" ────────┐
              │ 对每个 v 求 depth(v.left)+depth(v.right) │
              └───────────────────┬────────────────────┘
                                  │ 每个 depth 是 O(子树)
                                  ▼
                       总代价 O(n·h)，链状树 O(n²) = 10⁸
                                  │
              ┌───────────────────┴────────────────────┐
              │ 观察：后序回来时 lh、rh 已经在手里      │
              │ 于是"每个节点都算一次"几乎免费          │
              └───────────────────┬────────────────────┘
                                  ▼
                   一次后序 O(n)：ans 记答案，return 交高度
```

## 071.5 双语言实现

### 071.5.1 Java

**主解（后序 + 字段 `ans`）**：

```java
// LeetCode 判题环境已内置 TreeNode，粘贴到网页时不要重复定义：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode(int val) { this.val = val; }
// }

class Solution {
    // 全局答案：因为"以 v 为最高点的路径长度"父节点用不上，必须就地结算
    private int ans = 0;

    public int diameterOfBinaryTree(TreeNode root) {
        height(root);
        return ans;                 // 返回值是高度，答案在这里取
    }

    // 返回：以 node 为根的子树高度（边数）。空子树高度 0 —— 与"直径用边数"对齐
    private int height(TreeNode node) {
        if (node == null) {
            return 0;
        }
        int lh = height(node.left);      // 左子树高度
        int rh = height(node.right);     // 右子树高度

        // ★ 局部答案：以当前节点为最高点的最长路径 = 左臂 + 右臂
        //   注意这里【不能】return 它 —— 它是一条已经闭合的路径，父节点接不上第三段
        ans = Math.max(ans, lh + rh);

        // ★ 可上传量：只把"一条臂"交上去，父节点才能继续往上接
        return 1 + Math.max(lh, rh);
    }
}
```

**备解（无状态：返回 `int[]{height, diameter}`）**：

```java
class Solution {
    public int diameterOfBinaryTree(TreeNode root) {
        return info(root)[1];          // [0] = 高度，[1] = 直径
    }

    private int[] info(TreeNode node) {
        if (node == null) {
            return new int[]{0, 0};    // 空子树：高度 0，直径 0
        }
        int[] l = info(node.left);
        int[] r = info(node.right);
        int h = 1 + Math.max(l[0], r[0]);                        // 可上传量
        int d = Math.max(Math.max(l[1], r[1]), l[0] + r[0]);      // 局部答案与子树答案取最大
        return new int[]{h, d};
    }
}
```

### 071.5.2 Go

**主解（后序 + 闭包外的 `ans`）**：

```go
package main

// LeetCode 判题环境已内置该定义，本地编译时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func diameterOfBinaryTree(root *TreeNode) int {
	ans := 0 // 用闭包捕获：等价于 Java 的字段，但没有"实例复用要重置"的隐患
	var height func(node *TreeNode) int
	height = func(node *TreeNode) int {
		if node == nil {
			return 0 // 空子树高度 0（边数语义）
		}
		lh := height(node.Left)
		rh := height(node.Right)

		if lh+rh > ans {
			ans = lh + rh // ★ 局部答案：就地结算
		}
		if lh > rh {
			return lh + 1 // ★ 可上传量：只交一条臂
		}
		return rh + 1
	}
	height(root)
	return ans
}
```

**备解（无状态：返回结构体）**：

```go
package main

type info struct {
	h int // 高度（边数）
	d int // 以该子树为范围的最大直径
}

func diameterOfBinaryTreePure(root *TreeNode) int {
	var dfs func(node *TreeNode) info
	dfs = func(node *TreeNode) info {
		if node == nil {
			return info{0, 0}
		}
		l := dfs(node.Left)
		r := dfs(node.Right)
		h := 1 + maxInt(l.h, r.h)                  // 可上传量
		d := maxInt(maxInt(l.d, r.d), l.h+r.h)     // 局部答案 vs 子树答案
		return info{h, d}
	}
	return dfs(root).d
}

func maxInt(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```

```go
package main

import "fmt"

// 按 LeetCode 层序数组建树：nil 表示空位
func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}
```

### 071.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 全局答案的载体 | `private int ans` 字段；或用 `int[] ans = {0}` 传引用 | 闭包捕获的局部变量 | Java 字段在**同一实例多次调用**时会累加（LeetCode 每题新实例所以安全）；Go 闭包每次调用都是新变量，更安全 |
| 若想强制无状态 | `int[]` 参数两边都传同一个数组 | 指针参数 `*int` 或干脆返回结构体 | Go 更推荐返回结构体（值传递零分配） |
| 「两个量」的表达 | `int[]{h, d}` 数组 | `type info struct{ h, d int }` | Go 的结构体可读性更好；Java 数组要记住 `[0]`/`[1]` 的含义 |
| `max` 函数 | `Math.max(int,int)` 直接可用 | 1.20 之前要自己写 `maxInt` | Go 里自建 `maxInt` 是常态，注意别与将来同名内建冲突 |
| 空树 | `null` | `nil` | 两边都必须在开头返回「高度 0 / 直径 0」 |
| 递归深度 | `n ≤ 10⁴` 的链状树正好在 Java 默认栈边缘 | goroutine 栈可增长 | 本题能过，但把「后序 + 全局」搬到 10⁵ 链上时 Java 会爆栈 |

### 071.5.4 对拍测试（暴力 O(n²) 枚举所有点对，真跑 20000 次 + 边界专测）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：以每个节点为源点 BFS，求出"到所有节点的最大距离"，再取全局最大。
// 这条路径与"后序 + 左高右高"没有任何共享逻辑，是干净的裁判。
//
// ⚠️ 写这个暴力时踩了一个必须记住的坑：TreeNode 只有"父亲指向孩子"的单向指针，
//    直接对孩子做 BFS 根本回不到父亲（从叶子出发只能走到它自己）。
//    所以第一步必须先把树写成【无向】邻接表，把 parent ↔ child 两条边都补上。
func bruteDiameter(root *TreeNode) int {
	if root == nil {
		return 0
	}
	adj := map[*TreeNode][]*TreeNode{}
	nodes := []*TreeNode{}
	var link func(n *TreeNode)
	link = func(n *TreeNode) {
		if n == nil {
			return
		}
		nodes = append(nodes, n)
		if _, ok := adj[n]; !ok {
			adj[n] = nil // 保证叶子也有键，避免下面 range 出现 nil
		}
		for _, c := range []*TreeNode{n.Left, n.Right} {
			if c == nil {
				continue
			}
			adj[n] = append(adj[n], c)
			adj[c] = append(adj[c], n) // ★ 反向边：暴力能跑通的关键
		}
		link(n.Left)
		link(n.Right)
	}
	link(root)

	best := 0
	for _, s := range nodes { // 以每个节点为源点做 BFS 求距离
		dist := map[*TreeNode]int{s: 0}
		queue := []*TreeNode{s}
		for head := 0; head < len(queue); head++ {
			cur := queue[head]
			d := dist[cur]
			if d > best {
				best = d
			}
			for _, nx := range adj[cur] {
				if _, seen := dist[nx]; !seen {
					dist[nx] = d + 1
					queue = append(queue, nx)
				}
			}
		}
	}
	return best
}

func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(201) - 100}
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(201) - 100}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

// 随机对拍：全局版 + 纯函数版 vs 暴力，20000 次
func TestDiameterRandom(t *testing.T) {
	r := rand.New(rand.NewSource(543))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(45)
		root := randTree(r, n)
		want := bruteDiameter(root)
		if got := diameterOfBinaryTree(root); got != want {
			t.Fatalf("iter=%d 全局版 got=%d want=%d", iter, got, want)
		}
		if got := diameterOfBinaryTreePure(root); got != want {
			t.Fatalf("iter=%d 纯函数版 got=%d want=%d", iter, got, want)
		}
	}
}

// 边界专测：空树、单结点、全左链、全右链、"直径不在根上"的反例
func TestDiameterEdge(t *testing.T) {
	if got := diameterOfBinaryTree(nil); got != 0 {
		t.Fatalf("空树应为 0，got=%d", got)
	}
	if got := diameterOfBinaryTree(&TreeNode{Val: 1}); got != 0 {
		t.Fatalf("单结点应为 0，got=%d", got)
	}
	for n := 1; n <= 200; n++ {
		var l, rr *TreeNode
		for i := n; i >= 1; i-- {
			l = &TreeNode{Val: i, Left: l}
			rr = &TreeNode{Val: i, Right: rr}
		}
		if got := diameterOfBinaryTree(l); got != n-1 {
			t.Fatalf("全左链 n=%d 应为 %d，got=%d", n, n-1, got)
		}
		if got := diameterOfBinaryTree(rr); got != n-1 {
			t.Fatalf("全右链 n=%d 应为 %d，got=%d", n, n-1, got)
		}
	}
	// 反例：直径完全在一棵子树的内部，不经过根
	//        1
	//        │
	//        2
	//       ┌┴┐
	//       3 4
	//      ┌┘ └┐
	//      5   6      最长路径 5→3→2→4→6 = 4 条边，过根的最长只有 3 条
	root := &TreeNode{Val: 1,
		Left: &TreeNode{Val: 2,
			Left:  &TreeNode{Val: 3, Left: &TreeNode{Val: 5}},
			Right: &TreeNode{Val: 4, Right: &TreeNode{Val: 6}}}}
	if got := diameterOfBinaryTree(root); got != 4 {
		t.Fatalf("直径不在根上的反例应为 4，got=%d", got)
	}
	if got := diameterOfBinaryTreePure(root); got != 4 {
		t.Fatalf("纯函数版反例应为 4，got=%d", got)
	}
	// 高度与直径必须不同：这棵树的"边数高度"是 3，直径也是 3；用全左链验证两者会分离
	chain := &TreeNode{Val: 1, Left: &TreeNode{Val: 2, Left: &TreeNode{Val: 3, Left: &TreeNode{Val: 4}}}}
	if got := diameterOfBinaryTree(chain); got != 3 {
		t.Fatalf("4 节点全左链直径应为 3，got=%d", got)
	}
}
```

> **为什么暴力要用「每个源点做 BFS」**：它直接对着**定义**算（任意两点最长路径），完全不涉及「最高点」「左高右高」这些推理结论。用它当裁判，才能验证 §071.3.2 那套引理真的没错 —— 这叫「用定义验定理」。
>
> 同时它也提醒了一件事：**树在答案层面是「无向」的（任意两点都有唯一路径），但在代码层面是「有向」的（只有孩子指针）**。所以「求任意两点距离」的暴力必须先补反向边；而「以 v 为最高点」这种从父往子看的视角，恰好只需要向下指针 —— 这也解释了为什么 O(n) 解法不需要额外建图。

## 071.6 复杂度与常见坑

### 071.6.1 复杂度推导

- **时间 O(n)**：`height` 对每个节点恰好调用一次；函数体内是 O(1)（两次取 `max` 加一次 `ans` 更新）。**注意不能用「每个节点都调用两次 `depth`」的写法，那才是 O(n·h)。**
- **空间 O(h)**：递归栈深 = 树高。链状树 `h = n = 10⁴`，正好在 Java 默认栈的边缘（约 1 万层）。
- **暴力对照**：`O(n²)` 时间。`n = 10⁴` 时是 `10⁸` 级别访问，Java 约 200~400 ms，接近 TLE 线；若约束放大到 `10⁵`，直接超时 100 倍。

| 方案 | 时间 | 空间 | `n = 10⁴` 链状树 |
| --- | --- | --- | --- |
| 后序 + 全局 `ans` | O(n) | O(h) | 1 万次调用，栈深 1 万（边缘） |
| 后序 + 返回对 | O(n) | O(h) + O(h) 小数组 | 同上，多 1 万次小分配 |
| 枚举最高点 + `depth` | O(n·h) | O(h) | **5·10⁷ ~ 10⁸ 次**，慢 4 个数量级 |
| 每点 BFS 求距离 | O(n²) | O(n) | 10⁸ 次 + map 开销，只作对拍用 |

### 071.6.2 七个真实踩过的坑

1. **把 `lh + rh` 当返回值交上去** —— `return 1 + lh + rh;` 会让父节点把「闭合路径」当「单臂长度」继续累加，答案被放大且**全局 `ans` 也救不回来**。**这是本章唯一必须默念的规则：`ans` 记 `lh + rh`，`return` 交 `1 + max(lh, rh)`。**
2. **只算过根的路径** —— `return depth(root.left) + depth(root.right);`，直径在子树内部时答案偏小（反例见 §071.1 ③）。
3. **按节点数计量** —— 空子树高度取 1、或最后给答案加 1，导致单结点树返回 1。题目用**边数**，`h(∅) = 0`。
4. **Java 全局 `ans` 忘记初始化/忘记重置** —— 类型是 `int` 时默认 0 恰好正确；但如果答案可能是负数（比如 124 最大路径和），`ans` 必须初始化成 `Integer.MIN_VALUE`，不能是 0。
5. **全局 `ans` 在多线程下共享** —— 字段被两个线程同时 `Math.max`，结果互相污染。修法：用「返回对」的无状态写法，或每次调用新建 Solution 实例。
6. **`n = 1` 时把 `-1` 当"没有路径"** —— 有人把 `ans` 初始化为 `-1` 表示「还没找到路径」，然后忘记单结点的情况，返回 `-1`。正确初始化是 `0`（单结点直径就是 0）。
7. **在 `ans` 更新时把 `lh + rh` 写成 `lh + rh + 1`** —— 这是把「边数」和「节点数」混着算的产物，全树答案整体大 1。

### 071.6.3 面试官最爱追问的三个问题

**Q1：为什么返回值不能是直径？**

> 「因为一个节点要往上汇报**两件不同的事**：父节点需要『单边高度』来算它自己的臂长；而『以本节点为最高点的路径长度』在父节点处已经**接不上第三段**了 —— 一条路径只有两条臂。所以直径只能在节点处**结算**、存到全局最大里；返回值必须专供『能继续累加的那个量』。**一句话：能继续往上用的进返回值，到这就结束的进全局。**」

**Q2：如果要求输出这条最长路径，怎么改？**

> 「在更新 `ans` 时，除了记下 `lh + rh`，还要记下**取到最大值的那个节点**以及**左臂最深走的是哪个孩子、右臂最深走的是哪个孩子**。最后从那个节点出发，沿两条记录下来的分支往下走到底，就得到路径。代价是返回值要带上『最深孩子的引用』，或者事后从记录的节点再做一次 DFS 挑最深的分支 —— 两种都还是 O(n)。」

**Q3：如果边有权（甚至可以为负）？**

> 「这时『高度』不再是『边数』，而是『从节点往下的最大路径和』，空子树的贡献取 `max(0, ...)`（可以放弃这一支）。『以 `v` 为最高点』的答案变成 `v.val + best(左) + best(右)`，上传量变成 `v.val + max(best(左), best(右))`。这正是 LC 124 二叉树中的最大路径和 —— **骨架和本章一字不差，只是把『1 +』换成了『v.val +』、把负数截断成 0。**」

**Q4（常见追问）：O(n) 时间还能再快吗？能不能不用两次遍历就拿到路径？**

> 「时间上 O(n) 已是最优 —— 直径可能藏在任意子树，至少得看每个节点一眼。想『少一次遍历』只能靠结构性质（比如把这棵树当成无向图，从任意点 BFS 找最远点，再从最远点 BFS 一次得到直径 —— 那是**两遍 BFS 的树直径标准做法**，在本题的『节点对』定义下同样成立，且不用递归，天然防爆栈）。**面试里第二种答案往往是加分项，因为它换了一个视角：把树当图。**」

