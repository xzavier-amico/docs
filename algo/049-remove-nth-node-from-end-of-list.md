## 049.1 题目

**原题链接**：<https://leetcode.cn/problems/remove-nth-node-from-end-of-list/>

### 题意重述（把隐含条件补齐）

给你一个链表的头结点 `head` 和一个整数 `n`，请你**删除链表的倒数第 `n` 个结点**，并返回删除后的头结点。

五个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **`1 <= n <= 结点数`** | 约束 | 保证待删结点一定存在；但**`n` 可能等于结点总数**，此时删的是头结点 |
| **返回头结点** | 「返回链表的头结点」 | 删头时返回值必须变，所以不能用 `return head` 了事 |
| **只删一个结点** | 「倒数第 n 个结点」 | 不是「最后 n 个」 |
| **要求一趟扫描** | 进阶追问（题目 note 提示可以做到） | 两趟写法（先求长度）也对，但会被追问「能不能一趟」 |
| 链表可能只有 1 个结点 | `1 <= 结点数` | 删完后返回 `null`，所有 `dummy.next` 必须能正确表达「空」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= 结点数 <= 30` | 极小 | **规模完全不是考点**，O(n²) 都能过 |
| `1 <= n <= 结点数` | 合法 | 不需要处理越界；但要处理 `n == 结点数`（删头） |
| 进阶要求一趟 | note | 双指针定距，O(n) 一趟 |
| 空间期望 O(1) | 面试默认 | 双指针满足；栈 / 递归是 O(n) |

> 💡 **量级 → 算法**：`30` 个结点小到可以随便暴力。所以这题的真正考点是**「怎么在不知道长度的前提下做反向定位」**。这是一个**结构化**问题，不是**性能**问题 —— 记住这个区别，很多中等题的定位就清楚了。

### 示例

```text
输入：head = [1,2,3,4,5], n = 2
输出：      [1,2,3,5]
解释：倒数第 2 个是 4，删掉它

输入：head = [1], n = 1
输出：      []

输入：head = [1,2], n = 1
输出：      [1]
```

### 我自造的七个反例（写完必须逐个跑）

```text
① [1], n=1              → 删唯一结点，结果必须是空
② [1,2], n=2            → 删头结点：返回的 head 变成了 2
③ [1,2], n=1            → 删尾结点：前驱的 next 要指向 null
④ [1,2,3], n=3          → n 等于长度：等价于删头
⑤ [1,2,3,4,5], n=1      → 删最后一个：最容易把「前驱.next = null」写错
⑥ [5,5,5], n=2          → 全相等值：不能靠值定位
⑦ [1,2,3], n=4          → 非法输入（本题保证不会有），但实现若用 n+1 步会 NPE，要知道这是「前提之外的输入」
```

第 ② 和 ④ 是同一个坑的两副面孔：**删头结点时「前驱」不存在**。这正是本章要反复用到哑结点的原因 —— 和 045 / 046 一模一样的问题，一模一样的解药。

## 049.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（两趟：先求长度，再正着删）

```text
L = 0
for p in list: L++
target = L - n          // 待删结点的前一个结点的下标（0-based）
if target < 0: return head.next      // 删的是头，单独处理
p = head
for i in 0 .. target-1: p = p.next
p.next = p.next.next
return head
```

- 时间 O(n)，空间 O(1)。
- **它是对的**，能 AC，而且思路清晰。
- 那为什么还要优化？两个理由：

1. **两趟遍历**。第一趟完全是为了「数数」。在数据流、大文件、不可重复读的场景里，你只有一次机会。
2. **面试会追问**。题目 note 明确写着「你能尝试使用一趟扫描实现吗？」—— 这不是可选项，是出题人的暗示。

> **注意一个思维陷阱**：不要因为「这题有两趟解法」就说两趟是错的。**两趟解法的复杂度同样是 O(n)**，它只是多了一次常数倍的遍历。真正的差别是「是否需要提前知道长度」这个**信息依赖**。面试时要讲的是这个，而不是「两趟更慢所以不好」。

### 第二步：卡点在哪

把问题翻译成一句话：

> **我需要在「还没走到链表末尾」的时候，就知道「当前结点是不是倒数第 n 个」。**

而「倒数第 n 个」这个信息，**只有走到末尾才能确认**。除非……你能让某个人**替你先走到末尾**。

这就是全部卡点：**单链表不可回退，所以「反向位置」无法在正向遍历中被直接观测。**

### 第三步：灵感的来源 —— 用「固定间距」把反向位置变成正向位置

假设有两个人 A、B 在同一条链上走，**A 始终领先 B 正好 4 个结点**（间距 4）。当 A 走到末尾的 `null` 时，B 在哪？

```
链：  d → 1 → 2 → 3 → 4 → 5 → ∅
                 ↑           ↑
                 B           A         A 领先 B 恰好 4 个位置

A 到了 ∅（末尾之后），B 停在 3
而 3 是「倒数第 4 个」的前一个 → 也就是「倒数第 5 个」
```

**换句话说：谁领先谁 n+1 个位置，领先者走到尽头时，落后者正好停在「倒数第 n 个」的前一个。** 而「前一个」正是删除操作唯一需要的位置（因为删除要改前驱的 `next`）。

于是「倒数第 n 个」这个反向问题，被一次「保持间距的正向行走」解决了。**这就是用「距离」替代「长度」** —— 你不需要知道 L 是多少，你只需要知道「谁比谁多走了几步」。

### 第四步：把「n+1」和「n」两种间距都算清楚（这是本章最重要的一段）

这是本题唯一容易搞混的地方，所以两种写法都推一遍。**用「位置编号」来算最不容易错**：设哑结点在位置 0，真实第 i 个结点在位置 i（1 ≤ i ≤ L）。

#### 写法一：哑结点 + `fast` 先走 `n+1` 步（本章采用）

```text
fast、slow 都从 dummy（位置 0）出发
fast 先走 n+1 步 → 位置 n+1
然后同步走，直到 fast == null
```

- 待删结点是「倒数第 n 个」，位置 = `L - n + 1`。
- 它的前驱位置 = `L - n`。
- `fast` 从位置 `n+1` 走到 `null`（即位置 `L+1`），共走 `L+1-(n+1) = L-n` 步。
- 同步走时 `slow` 也走 `L-n` 步，从位置 0 到位置 **`L-n`** —— **正是待删结点的前驱**。✅

#### 写法二：无哑结点 + `fast` 先走 `n` 步

```text
fast、slow 都从 head（位置 1）出发
fast 先走 n 步 → 位置 1+n
然后同步走，直到 fast.next == null（fast 停在最后一个结点，位置 L）
```

- `fast` 走 `L - (1+n)` 步到位置 L，`slow` 到位置 `1 + L - 1 - n = L - n` —— **也是前驱**。✅

#### 两种写法的差别（一张表说清）

| | 写法一（dummy + n+1 步） | 写法二（无 dummy + n 步） |
| --- | --- | --- |
| 起点 | `dummy`（位置 0） | `head`（位置 1） |
| fast 先走 | `n+1` 步 | `n` 步 |
| 循环条件 | `fast != null` | `fast.next != null` |
| `slow` 的落点 | 位置 `L-n` = 前驱 | 位置 `L-n` = 前驱 |
| **`n == L`（删头）时** | 正常工作：`slow = dummy`，`dummy.next = dummy.next.next` ✅ | **崩**：`fast` 起步就走 `L` 步变成 `null`，再取 `fast.next` 直接 NPE ❌ |
| 是否要特判 | 不用 | 必须特判 `n == L` |

> **结论**：写法二的「n 步」看起来更「对称」，但它把 `n == L` 这个边界留给了你。写法一多走一步、多一个哑结点，换来「所有 n 都走同一条路径」。**这就是哑结点的价值：用 1 个假结点换掉 1 个 if。**

**为什么间距是 `n+1` 而不是 `n`？** 因为你要落到的位置是「待删结点的**前一个**」，而删除操作必须站在前驱上。如果间距取 `n`，`slow` 会落在待删结点**自己**身上 —— 此时你无法删除它（单链表删不掉自己，必须靠前驱改 `next`）。

### 另一条路：栈 / 递归

- **栈**：全部压栈，弹出 n 个，此时栈顶就是待删结点的前驱。时间 O(n)，空间 O(n)。
- **递归**：递归到底后回溯，用一个计数器数到 n，回溯到第 n+1 层时改 `next`。时间 O(n)，空间 O(n) 栈。

两条都正确，但都不满足「一趟 + O(1) 空间」。**它们唯一的价值是「证明你还有别的视角」**，面试时一句话带过即可。

## 049.3 原理拆解

### 049.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 趟数 | 要不要特判 `n == L` | 什么时候会输 |
| --- | --- | --- | --- | --- | --- |
| 两趟（先求长度） | O(n) | O(1) | 2 | 要 | 只允许一趟 / 流式输入 |
| **双指针（dummy + n+1 步）** ✅ | **O(n)** | **O(1)** | **1** | **不要** | 几乎不会输 |
| 双指针（n 步 + `fast.next`） | O(n) | O(1) | 1 | 要 | 忘了特判 `n == L` 就崩 |
| 栈 | O(n) | O(n) | 1 | 不要 | 空间要求 O(1) |
| 递归 | O(n) | O(n) 栈 | 1 | 不要 | 长链栈溢出；且 `n` 要靠返回值传递，绕 |

**为什么「dummy + n+1」是最优**：一趟、O(1)、零特判。三个指标全满。

### 049.3.2 为什么这个做法是对的（正确性论证）

**循环不变量**（同步走的每一轮开始前）：

> `fast` 与 `slow` 之间的**位置差恒为 `n+1`**（`fast` 的位置 − `slow` 的位置 = `n+1`），且两者都还没越过 `null`。

**初始化**：`fast` 走了 `n+1` 步，`slow` 走 0 步，位置差 = `n+1`。成立。

**保持**：同步走时两者都 +1，差不变。成立。

**终止与落点**：设链表共 L 个结点，哑结点占位置 0，故 `null` 在位置 `L+1`。`fast` 从位置 `n+1` 出发，走到 `null` 共需 `(L+1) - (n+1) = L - n` 步。因为 `1 ≤ n ≤ L`，所以 `L - n ≥ 0`，步数合法。

`slow` 同步走 `L-n` 步后位于位置 `L-n`。而待删结点（倒数第 n 个）位于位置 `L-n+1`，其前驱位于位置 `L-n`。**所以 `slow` 正好停在待删结点的前驱上。** ∎

**删除的正确性**：`slow.next = slow.next.next` 把 `slow` 的后继从待删结点改成它的后继，于是待删结点从链上脱落。因为 `1 ≤ n ≤ L`，待删结点一定存在，所以 `slow.next` 非空，不会 NPE。∎

**边界 `n == L`**：此时 `L - n = 0`，`slow` 走了 0 步，仍在 `dummy` 上；`slow.next` 是原 `head`，`slow.next.next` 是第二个结点。执行删除后 `dummy.next` 变成第二个结点，返回 `dummy.next` 正确。∎

**边界 `n == 1`**：`L-n = L-1`，`slow` 停在位置 `L-1`（倒数第二个），删掉最后一个，其 `next` 变成 `null`。∎

> **这个论证的关键是「位置编号法」**：把 dummy 编成 0，`null` 编成 `L+1`，然后所有距离都变成简单减法。**用坐标算指针题，比用「感觉」算可靠 10 倍** —— 这也是我在 046 里算「走 k 步落在第 k 个」时用的同一套方法。

### 049.3.3 通用解题思路（可迁移的那一层）

**链表章的统一语言：哑结点 + 指针三件套（prev/cur/next）+ 先存后断。** 049 展示的是「两个指针互相约束」的第二种形态 —— **快慢指针的三种用法**：

| 用法 | 约束关系 | 典型题 |
| --- | --- | --- |
| **定距**（本章） | 两指针**距离固定**，一个探到尽头，另一个落在目标前驱 | 19 删除倒数第 n 个；61 旋转链表（找断点） |
| **判圈**（050） | 一个走 1 步、一个走 2 步，相遇说明有环 | 141 / 142 环形链表 |
| **找中点**（051） | 一个走 1 步、一个走 2 步，快的到头时慢的在中点 | 876 链表的中间结点；143 重排；148 排序 |

**共同点**：都是「**让两个指针满足某个几何关系，然后借这个关系把需要的信息『算』出来**」。
- 定距：用「距离」换「长度」—— 不需要知道 L。
- 判圈：用「速度差」换「是否存在环」—— 不需要额外空间标记。
- 找中点：用「速度比 2:1」换「中点在哪儿」—— 不需要先求长度。

> **一句话**：**快慢指针不是「两个指针一起走」，而是「用两个指针的几何关系，替代一次额外的遍历或一块额外的空间」。**

属于同一模型的题：

| 题 | 几何关系 | 解决什么 |
| --- | --- | --- |
| [LC 19](https://leetcode.cn/problems/remove-nth-node-from-end-of-list/) | 距离 n+1 | 反向定位 |
| [LC 876 链表的中间结点](https://leetcode.cn/problems/middle-of-the-linked-list/) | 速度 2:1 | 中点 |
| [LC 142 环形链表 II](https://leetcode.cn/problems/linked-list-cycle-ii/) | 速度 2:1 + 相遇后同步 | 环入口（050） |
| [LC 143 重排链表](https://leetcode.cn/problems/reorder-list/) | 速度 2:1 | 切分前后半（051） |
| [LC 61 旋转链表](https://leetcode.cn/problems/rotate-list/) | 距离 k mod L | 找新头 / 新尾 |
| [LC 2095 删除链表的中间结点](https://leetcode.cn/problems/delete-the-middle-node-of-a-linked-list/) | 速度 2:1 + 前驱 | 中点 + 删除（本题 + 876 的组合） |

### 049.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 删除**倒数第 n 到 m 个**（一段） | 两个边界 | 再找一个间距 `m+1` 的指针，三个指针一起走 |
| **正向**第 n 个 | 更简单 | 走 n−1 步即可；仍建议用 dummy 统一「删头」 |
| 改成**交换**倒数第 n 个与正数第 m 个 | 需要两个定位 | 先各定位一次（或同时定位），再交换值 / 改链 |
| 只**读**不删（返回倒数第 n 个的值） | 不需要前驱 | 间距取 `n` 就行，`slow` 落在目标本身 |
| **双向链表** | 有 `prev` | 直接从尾结点走 n−1 步，O(n) 但不需要双指针 |
| **流式**输入（长度未知且不缓存） | 无法回头 | 双指针天然适配：维持一个长度 n+1 的窗口，走到头时窗口尾就是答案 |

## 049.4 图解推演

### 049.4.1 完整轨迹（`[1,2,3,4,5]`，`n = 2`）

```text
初始：fast = slow = dummy
  dummy
    ↓
   [∅] → [1] → [2] → [3] → [4] → [5] → ∅
    ↑
  fast, slow

① fast 先走 n+1 = 3 步（位置 0 → 1 → 2 → 3）
  dummy
    ↓
   [∅] → [1] → [2] → [3] → [4] → [5] → ∅
    ↑                   ↑
   slow                fast         间距 = 3

② 同步走，直到 fast == ∅
  第 1 步：
   [∅] → [1] → [2] → [3] → [4] → [5] → ∅
           ↑                   ↑
          slow                fast
  第 2 步：
   [∅] → [1] → [2] → [3] → [4] → [5] → ∅
                 ↑                   ↑
                slow                fast
  第 3 步（fast 到 ∅）：
   [∅] → [1] → [2] → [3] → [4] → [5] → ∅
                       ↑                   ↑
                      slow              fast=∅

③ 删除 slow.next（= 4）
  slow.next = slow.next.next

   [∅] → [1] → [2] → [3] ─────────→ [5] → ∅
                       ↑
                      slow

④ return dummy.next = 1
   结果：1 → 2 → 3 → 5 ✅
```

### 049.4.2 位置表推演（这张表就是正确性证明的算术版）

| 时刻 | `fast` 位置 | `slow` 位置 | 位置差 | 说明 |
| --- | --- | --- | --- | --- |
| 初始 | 0 | 0 | 0 | 都在 dummy |
| fast 走完 3 步 | 3 | 0 | 3 = n+1 | 保持间距 |
| 同步第 1 步 | 4 | 1 | 3 | |
| 同步第 2 步 | 5 | 2 | 3 | |
| 同步第 3 步 | 6 = `null`（即 L+1） | 3 | 3 | 停下 |
| 删除 | — | 3 = `L-n` = 前驱 | — | `slow.next` 是待删结点（位置 4 = `L-n+1`） |

### 049.4.3 两种间距约定对比（`n == L` 时的分水岭）

```text
输入 [1,2], n = 2（删头）

写法一（dummy + n+1 步）：
  ① fast 从 dummy 走 3 步 → 位置 3 = null
  ② slow 还在 dummy（位置 0）
  ③ while fast != null → 一步都不走
  ④ slow.next = slow.next.next → dummy.next = 2     ✅ 正确

写法二（无 dummy + n 步）：
  ① fast 从 head 走 2 步 → null
  ② while fast.next != null → 取 null.next → 💥 NPE

┌──────────────────── 差别在哪 ────────────────────┐
│ dummy 给「前驱不存在」这种情况提供了一个真实存在的落脚点  │
│ 没有 dummy 时，"前驱" 是 null，所有 .next 都要特判       │
└─────────────────────────────────────────────────┘
```

### 049.4.4 一条链上的三条路线

```text
        ┌────────── 倒数第 n 个在哪儿？──────────┐
        │                                        │
   ┌────▼─────┐        ┌──────────┐        ┌─────▼─────┐
   │ 两趟：求 L │        │ 双指针定距 │        │ 栈 / 递归  │
   │ 再走 L-n  │        │ 间距 n+1  │        │ 弹 n 个    │
   └────┬─────┘        └────┬─────┘        └─────┬─────┘
        │                   │                    │
   O(n)/O(1)          O(n)/O(1) 一趟        O(n)/O(n)
   需要知道 L          不需要 L              不需要 L
   要特判删头          哑结点免特判           要特判删头
        │                   │                    │
    ✅ 能过，面试降级    ✅ 推荐              ❌ 空间不达标
```

## 049.5 双语言实现

### 049.5.1 Java

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}

class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode fast = dummy;
        ListNode slow = dummy;

        // 关键：先走 n+1 步而不是 n 步
        // 理由：删除需要站在「前驱」上，而间距 n+1 才能让 slow 落在前驱
        for (int i = 0; i <= n; i++) {
            fast = fast.next;
        }
        // 同步走，fast 到 null 时 slow 正好停在待删结点的前驱
        while (fast != null) {
            fast = fast.next;
            slow = slow.next;
        }
        slow.next = slow.next.next; // 跳过待删结点
        return dummy.next;          // n == L 时 head 已被删，必须从 dummy 取
    }
}
```

**四处「为什么」**：

1. `for (int i = 0; i <= n; i++)` 是 `n+1` 次而不是 `n` 次：间距必须比 `n` 大 1，才能让 `slow` 落到**前驱**而不是目标本身。
2. `while (fast != null)` 而不是 `while (fast.next != null)`：终点定在 `null`，配合 dummy 让 `n == L` 也能走通（见 049.4.3）。
3. `slow.next = slow.next.next`：单链表删除只能改前驱的 `next`，这就是为什么非要站在前驱上。
4. `return dummy.next` 而不是 `return head`：`n == L` 时 `head` 已被删，返回它就是返回一个已经脱离链表的结点。

### 049.5.2 Go

```go
package main

type ListNode struct {
	Val  int
	Next *ListNode
}

// 双指针定距：快指针先走 n+1 步，再与慢指针同步走
func removeNthFromEnd(head *ListNode, n int) *ListNode {
	dummy := &ListNode{Next: head}
	fast, slow := dummy, dummy
	for i := 0; i <= n; i++ { // n+1 步，不是 n 步
		fast = fast.Next
	}
	for fast != nil {
		fast = fast.Next
		slow = slow.Next
	}
	slow.Next = slow.Next.Next // slow 停在待删结点的前驱
	return dummy.Next
}
```

### 049.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 多指针初始化 | `ListNode fast = dummy; ListNode slow = dummy;` 两行 | `fast, slow := dummy, dummy` 一行 | Go 更紧凑；注意 `:=` 声明后两个变量都是 `*ListNode` |
| 越界风险 | `fast.next` 在 `fast == null` 时 NPE | 在 `fast == nil` 时 panic | **两边都会崩**，所以 `for` 次数必须严格 `n+1`，且题目保证 `n ≤ 结点数` |
| `dummy` 构造 | `new ListNode(0)` + 手动赋 `next` | `&ListNode{Next: head}` | Go 可一行构造，且不关心 `Val` |
| 返回值 | `dummy.next` | `dummy.Next` | 一致 |
| 字段名 | 小写 `.val` / `.next` | 大写 `.Val` / `.Next` | LeetCode 的 Go 模板就是大写 |
| 空链表 | `n ≥ 1` 保证非空，不会走到 | 同理 | 无需额外判空 |

### 049.5.4 对拍测试（Go，2 万次随机 + 五个边界）

```go
package main

import (
	"math/rand"
	"testing"
)

func build(a []int) *ListNode {
	dummy := &ListNode{}
	t := dummy
	for _, v := range a {
		t.Next = &ListNode{Val: v}
		t = t.Next
	}
	return dummy.Next
}

func dump(h *ListNode) []int {
	out := []int{}
	for p := h; p != nil; p = p.Next {
		out = append(out, p.Val)
		if len(out) > 100000 {
			panic("疑似成环")
		}
	}
	return out
}

func TestRemoveNthFromEndRandom(t *testing.T) {
	r := rand.New(rand.NewSource(49))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(10) // 链长 1..10
		a := make([]int, n)
		for i := range a {
			a[i] = r.Intn(4) // 大量重复值
		}
		k := 1 + r.Intn(n) // 1 <= k <= n，严格合法（题目保证）
		del := n - k       // 待删结点下标（0-based）

		// 参考实现：切片删除，最朴素
		want := append(append([]int{}, a[:del]...), a[del+1:]...)

		got := dump(removeNthFromEnd(build(a), k))
		if len(got) != len(want) {
			t.Fatalf("iter=%d a=%v k=%d got=%v want=%v", iter, a, k, got, want)
		}
		for i := range got {
			if got[i] != want[i] {
				t.Fatalf("iter=%d a=%v k=%d got=%v want=%v", iter, a, k, got, want)
			}
		}
	}
	// 五个边界
	cases := []struct {
		a    []int
		k    int
		want []int
	}{
		{[]int{1}, 1, nil},          // ① 删唯一结点 → 空链
		{[]int{1, 2}, 2, []int{2}},  // ② 删头结点
		{[]int{1, 2}, 1, []int{1}},  // ③ 删尾结点
		{[]int{1, 2, 3}, 3, []int{2, 3}}, // ④ n == 长度
		{[]int{5, 5, 5}, 2, []int{5, 5}}, // ⑤ 全相等值
	}
	for i, c := range cases {
		got := dump(removeNthFromEnd(build(c.a), c.k))
		if len(got) != len(c.want) {
			t.Fatalf("边界 %d: a=%v k=%d got=%v want=%v", i+1, c.a, c.k, got, c.want)
		}
		for j := range got {
			if got[j] != c.want[j] {
				t.Fatalf("边界 %d: a=%v k=%d got=%v want=%v", i+1, c.a, c.k, got, c.want)
			}
		}
	}
	// 特别验证：删除头结点后返回的链必须与原 head 脱钩（不是返回被删的结点）
	h := build([]int{1, 2, 3})
	got := removeNthFromEnd(h, 3)
	if got == h {
		t.Fatal("删头结点后返回的仍然是原 head，说明取错了返回值")
	}
	if got.Val != 2 {
		t.Fatalf("删头后新头应为 2，实际 %d", got.Val)
	}
}
```

> **最后一个断言值得单独说**：`got == h` 这条检查能抓出「`return head`」这种错误 —— 那种实现下返回值指针与输入 `head` 完全相同，虽然打印出来的链可能「看起来对」（因为 `head` 还连着后面），但语义上它已经是待删结点。**指针题的测试除了比对序列，还要比对「指针身份」。**

## 049.6 复杂度与常见坑

### 049.6.1 复杂度推导

- **时间 O(L)**：`fast` 先走 `n+1` 步，再与 `slow` 同步走 `L-n` 步，合计 `(n+1) + (L-n) = L+1` 步。**恰好是「每条边访问两次」的反面：总共只走了 L+1 步，即一趟。**
- **空间 O(1)**：`dummy`、`fast`、`slow` 三个指针（`dummy` 是唯一新分配结点）。
- **对比两趟版**：两趟版走 `L`（数数）+ `L-n`（定位）≈ `2L - n` 步。一趟版是 `L+1` 步。**常数差约 2 倍，复杂度同阶。** 所以「一趟」的收益主要是**信息依赖**（不需要预先知道 L），而不是纯粹的常数。
- **下界**：任何算法都必须至少走到链表末尾（否则不知道倒数第 n 个是谁），所以 Ω(L) 是紧的 —— 本题达到最优。

### 049.6.2 八个真实踩过的坑

1. **`fast` 只走 `n` 步** —— `slow` 落在待删结点**自己**身上，无法删除（单链表必须靠前驱）。表现为「结果没删对，删掉的是后一个」或者崩溃。
2. **`for` 写成 `i < n`** —— 同 ①，间距少 1。
3. **不用 dummy，且没特判 `n == 结点数`** —— 删头时 `fast` 起步就越界，NPE / panic。
4. **`while (fast.next != null)` 配 dummy** —— `fast` 停在最后一个结点，少走一步，`slow` 落在目标本身。**间距与终止条件必须配对使用**（要么 dummy+n+1+null，要么 无dummy+n+next）。
5. **`return head`** —— 删头时返回的是已脱离链表的结点，输出错误（而且是那种「`[1,2], n=2` 输出 `[1,2]`」的迷惑性错误）。
6. **`slow.next = slow.next.next` 之前没判 `slow.next != null`** —— 本题约束保证不会，但如果把「`n` 可能大于长度」当成非法输入之外的情况处理，就会 NPE。
7. **删除后忘了「断开」待删结点的 `next`** —— 严格说不影响判题（LeetCode 只看返回的链），但在有内存泄漏检查或后续复用的场景里，那个被删结点还指着链里的结点，可能造成引用泄漏。讲究的做法是 `del.next = null`。
8. **把 `n` 当成「正数第 n 个」** —— 完全不同的题，输出会像是「删了对称位置的结点」。

### 049.6.3 面试官最爱追问的三个问题

**Q1：为什么 `fast` 要先走 `n+1` 步，而不是 `n` 步？**
> 「因为删除必须站在待删结点的**前驱**上（单链表只能改前驱的 `next`）。设 dummy 在位置 0、`null` 在位置 L+1，待删结点在位置 L−n+1，它的前驱在 L−n。`fast` 从位置 n+1 走到位置 L+1 要走 L−n 步，`slow` 同步走 L−n 步，正好从 0 到 L−n —— 就是前驱。如果间距取 n，`slow` 会落在 L−n+1，也就是待删结点本身，那时你就没法删它了。」

**Q2：不用哑结点行不行？**
> 「行，但必须换一套间距约定并补特判：`fast` 先走 n 步、循环条件用 `fast.next != null`，此时 `slow` 也落在前驱；但 `n == 结点数` 时 `fast` 起步就是 `null`，`fast.next` 直接崩，所以必须单独处理『删头』。用哑结点则所有 n 走同一条路径，代码里一个 if 都没有。我选哑结点，是拿 1 个假结点换掉 1 个边界分支。」

**Q3：如果链表非常长、只允许读一次（流式），你还能做吗？**
> 「能，而且这正是双指针的强项。维护一个长度为 n+1 的『窗口』：读入时先填满 n+1 个结点，之后每来一个新结点，窗口整体前移一格（`fast` 指最新，`slow` 指窗口最旧）。等输入结束时，`slow` 就是待删结点的前驱。整个过程不需要知道总长度，也不需要回头，空间是 O(1)。两趟写法和栈写法在这个场景下都做不到 —— 这才是『一趟』真正的价值。」
