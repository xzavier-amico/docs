## 030.1 题目

**原题链接**：<https://leetcode.cn/problems/insert-interval/>

### 题意重述（把隐含条件补齐）

给你一个**无重叠**的区间列表 `intervals`，其中 `intervals[i] = [startᵢ, endᵢ]` **按 `startᵢ` 升序排列**；再给你一个新区间 `newInterval = [start, end]`。把 `newInterval` 插入列表，若因此产生重叠就合并，最后返回仍然**有序且无重叠**的结果。

六个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **输入已按左端点升序** | 「按 `startᵢ` 升序排列」 | 直接复用 029 的「先排序」是**浪费**：`n=10⁵` 时实测慢 3.6 倍 |
| **输入本身无重叠** | 「无重叠的区间列表」 | 如果输入有重叠，三阶段扫描仍然对，但「互不重叠」这条推论就不能用了 |
| **可能有多个区间与新区间重叠** | 示例 2 合并了 3 个 | 只处理「一个重叠」会漏 |
| **端点相接（`end == start`）也算重叠** | 示例 1 的 `[4,8]` 与 `[3,5]`、`[6,7]` | 判定写成 `<` 会输出两个相邻区间 |
| **`intervals` 可能为空** | 约束 `0 <= intervals.length` | 忘了判空 → 访问 `intervals[0]` 越界 |
| **`newInterval` 可能覆盖全部区间** | 无特殊限制 | 输出应该是单个区间 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= intervals.length <= 10⁴` | n 最多 1 万 | 「塞进去重排再合并」是 `O(n log n)`，1 万规模实测 1.2 ms，**能过** |
| `0 <= startᵢ <= endᵢ <= 10⁵` | 值域 10⁵ | 差分数组可用，但**输出的是一组区间而不是长度**，差分帮不上忙 |
| **输入已排好序** | 题目明说 | 这是本题唯一的「额外信息」。用上它 → `O(n)`；不用它 → 凭什么考这题？ |
| 只插入**一个**区间 | 题干 | 所以「插入点」只有一个，切成三段就够；如果插入 m 次，结构就完全变了（见 §030.3.4） |

> 💡 **量级 → 算法**：`n = 10⁴` 时「先排序」能过，所以很多人就这么交了。但面试官把 `n` 改成 `10⁶`（实测：三阶段 43.9 ms vs 重排 142.5 ms，且差距会随 `log n` 继续拉大）时，这个选择就变成生死线。
> **看到「输入已有序」，第一反应必须是：能不能省掉排序？**

### 示例

```text
输入：intervals = [[1,3],[6,9]], newInterval = [2,5]
输出：[[1,5],[6,9]]
解释：[2,5] 与 [1,3] 重叠 → [1,5]；[1,5] 与 [6,9] 不重叠（5 < 6）

输入：intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
输出：[[1,2],[3,10],[12,16]]
解释：[4,8] 一口气吞掉 [3,5]、[6,7]、[8,10] → [3,10]

输入：intervals = [], newInterval = [5,7]
输出：[[5,7]]
```

### 我自造的五个反例

```text
① [[1,5]], [2,3]                  → 打「新区间被原区间完全包含」：答案 [[1,5]]，一个都不能少
② [[1,2],[3,5]], [2,3]            → 打「端点相接」：答案 [[1,5]]，两个都吞
③ [[3,5]], [1,10]                 → 打「新区间吞掉全部」：答案 [[1,10]]
④ [[1,2]], [5,6]                  → 打「插到最后」：答案 [[1,2],[5,6]]
⑤ [], [1,2]                       → 打「空列表」
```

① 和 ② 是这题的两个判定点：**① 管「右端点用 max」**（不能把 `[1,5]` 缩成 `[1,3]`），**② 管「左端点用 `<=`」**（不能让 `[1,2]` 和 `[3,5]` 之间裂开）。

## 030.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（把新区间塞进去，然后重做一遍 029）

最省脑子的写法：`intervals` 里追加 `newInterval`，排序，再跑 029 的合并扫描。

```text
all = intervals + [newInterval]
sort all by 左端点
res = []
for cur in all:
    if res 非空 且 cur[0] <= res[-1][1]:  res[-1][1] = max(res[-1][1], cur[1])
    else:                                  res.append(cur)
return res
```

- 时间 **O(n log n)**（排序主导），空间 **O(n)**（要复制一份）。
- 正确，代码也短，`n = 10⁴` 实测 1.18 ms——**在本题的限制下完全能过**。

**它错在哪？** 错在「**扔掉了一个已经付费买到的信息**」。输入本来就是有序的，而排序正是这题最贵的一步。实测差距：

| n | 三阶段扫描（O(n)） | 塞入 + 重排 + 合并（O(n log n)） | 差距 |
| --- | --- | --- | --- |
| 10⁴ | **0.375 ms** | 1.184 ms | 3.2× |
| 10⁵ | **5.056 ms** | 18.076 ms | 3.6× |
| 10⁶ | **43.906 ms** | 142.455 ms | 3.2× |

（Go 1.19.8 / 2 核容器 / 5 次取最快 / 输入是 10⁶ 个几乎连续的短区间）

### 第二步：卡点在哪 —— 插入点只有一个

把问题翻译成一句话：

> **在有序列表里找到 `newInterval` 的「落点」，然后把落点附近所有与它重叠的区间缝成一个。**

因为**只插入一个区间**，所以：

- 与 `newInterval` 重叠的那些区间，在有序列表里必然**连成一段**（和 029 的引理一样：排序后「可合并的区间」构成连续段）；
- 这段之前的所有区间，右端点都严格小于 `newInterval` 的左端点 → **原样保留**；
- 这段之后的所有区间，左端点都严格大于合并后的右端点 → **原样保留**。

于是整个数组被切成三段，每段只做一件事。这就是三阶段。

### 第三步：灵感的来源 —— 用「三段」代替「排序」

```text
        ┌──────────────┬───────────────────┬──────────────┐
        │ 段 ①：完全在左 │ 段 ②：与新区间相交 │ 段 ③：完全在右 │
        │ iv[i][1] < lo │ iv[i][0] <= hi     │ iv[i][0] > hi │
        └──────────────┴───────────────────┴──────────────┘
             原样搬运         吞并成一个         原样搬运
```

三个判据的关键细节：

- 段 ① 用 **`iv[i][1] < lo`**（比右端点），不是 `iv[i][0] < lo`。因为一个区间可能「左端点在 `lo` 之前，但右端点越过了 `lo`」，那它就和新区间重叠，属于段 ②。
- 段 ② 用 **`iv[i][0] <= hi`**（`<=` 不是 `<`）。因为端点相接也算重叠。
- 段 ② 的 `hi` 在循环里会变大，所以**必须用局部变量** `lo / hi`，并且每次用最新的 `hi` 判断 —— 这正是「一口气吞三个」能成立的原因。

### 另一条路：二分定位 + 数组插入

既然输入有序，可以用二分找「第一个右端点 ≥ `lo` 的区间」和「最后一个左端点 ≤ `hi` 的区间」，把中间那段替换成合并结果。

- 定位是 `O(log n)`，但**替换中间那段需要移动数组元素，仍是 `O(n)`**（Java/Go 的数组插入都是 `System.arraycopy` / `copy`）。
- 所以总复杂度还是 `O(n)`，**常数更大、代码更长、边界更容易错**。

> ⚠️ 这是「二分不一定更快」的典型场景：**当你必须移动 `O(n)` 个元素时，把 `O(n)` 的定位换成 `O(log n)` 一分钱都省不下来。** 只有当数据在**链表 / 平衡树**上（插入不用搬移）时，二分定位才有意义。

## 030.3 原理拆解

### 030.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 塞入 + 重排 + 合并（029 复用） | O(n log n) | O(n) | 15 行 | 输入有序时白花 `log n` 倍；`n=10⁶` 实测慢 3.2 倍 |
| **三阶段线性扫描** ✅ | **O(n)** | O(n) 结果 | **18 行** | 输入无序时直接错（但本题保证有序） |
| 二分定位 + 三段拼接 | O(log n) + O(n) 搬移 = O(n) | O(n) | 30 行 | 常数更大；边界（端点相接、完全包含）更易写错 |
| 逐个区间「比较后决定放哪」 | O(n) | O(n) | 12 行 | 判定条件要在一个循环里分三种情况，反而更绕 |
| 平衡树（有序区间集） | O(log n + k) | O(n) | 80 行 | 静态输入下过度设计；插入 m 次时才是正解 |

**三阶段 vs 逐区间判定**：两者都是 `O(n)`，但结构差异很关键。

```text
逐区间（一个循环里塞三个分支）：
  for each iv:
      if iv 在左:  搬到 res
      elif iv 相交: 扩展 lo/hi，先不输出
      else:        输出合并结果，再搬 iv        ← 状态机藏在循环里，容易漏「只输出一次」

三阶段（三个 while 顺序执行）：
  while 段①: 搬
  while 段②: 吞
  输出合并结果（只写一次，位置明确）
  while 段③: 搬
```

**三个独立循环 = 三段独立的不变量**，每段都能单独验证。这就是「结构化代码」在算法题里的价值：它把「边界条件」从「藏在 if 里」变成「写在 while 的条件里」。

### 030.3.2 为什么这个做法是对的（正确性论证）

设 `newInterval = [lo, hi]`（`lo / hi` 是会被就地扩展的局部变量）。

**引理 1（段 ① 判定正确）**：段 ① 结束时，对所有已搬走的区间 `iv`，有 `iv[1] < lo₀`（`lo₀` 是初始的左端点）。
因为循环条件就是 `iv[i][1] < lo`，且 `lo` 在段 ① 里从未被修改（只有段 ② 会改）。这些区间的右端点严格小于新区间左端点 → 不重叠 → 原样保留是对的。∎

**引理 2（段 ② 一次到底）**：段 ② 的循环条件 `iv[i][0] <= hi` 中的 `hi` 是**实时扩展后**的值。设某轮吞并后 `hi` 变成了 `hi'`。
因为输入按左端点升序，后续所有区间的左端点 `≥ iv[i][0]`；只要它们 `≤ hi'` 就继续被吞。所以段 ② 恰好吞掉「与 `[lo, hi]` 的传递闭包相交」的全部区间。∎

**引理 3（段 ③ 不会再有重叠）**：段 ② 退出时，`iv[i][0] > hi`。因为输入按左端点升序，后面所有区间的左端点都 `> hi`，与合并后的 `[lo, hi]` 不重叠。原样搬运是对的。∎

**定理**：输出 = 输入的并集，且有序、无重叠、无冗余。
- 覆盖性：每个输入区间要么被原样搬走（段 ①、③），要么被并入 `[lo, hi]`（段 ②），`newInterval` 也被并入。所以并集不变。
- 有序无重叠：段 ① 内有序（输入有序）且最后一个个右端点 `< lo₀ ≤ lo`；`[lo, hi]` 与段 ① 不重叠且 `lo ≥ lo₀`；段 ③ 左端点 `> hi`。三段拼起来有序无重叠。∎

> 这个证明的形状值得记住：**三条引理分别对应三个 while 循环**。写代码时把循环和引理一一对上，边界就不会漏。

### 030.3.3 通用解题思路（可迁移的那一层）

本题是 **「有序输入 + 单点插入 = 三段切分」** 这个模型的母题：

```
原始问题：在有序序列里插入一个元素，并维护某种「不重叠 / 有序」性质
          ↓ 找出「新元素影响的范围」
三段化：  受影响范围在有序序列里必然是一段连续区间
          ↓ 三个循环：搬左边 / 处理中段 / 搬右边
结果：    O(n)，比「重新排序」少一个 log
```

同一模型下的题：

| 题 | 「中段」是什么 | 处理方式 |
| --- | --- | --- |
| [LC 57 插入区间](https://leetcode.cn/problems/insert-interval/) | 与新区间重叠的连续段 | 吞并成 `[min lo, max hi]` |
| [LC 88 合并两个有序数组](https://leetcode.cn/problems/merge-sorted-array/) | 整个数组 | 逆向双指针（避免覆盖） |
| [LC 21 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/) | 整个链表 | 哑结点 + 双指针 |
| [LC 986 区间列表的交集](https://leetcode.cn/problems/interval-list-intersections/) | 逐对求交集 | 双指针（谁先结束谁前进） |
| [LC 34 在排序数组中查找元素的第一个和最后一个位置](https://leetcode.cn/problems/find-first-and-last-position-of-element-in-sorted-array/) | 等于 target 的连续段 | 两次二分定左右边界 |
| [LC 1089 复写零](https://leetcode.cn/problems/duplicate-zeros/) | 被复写影响到的尾段 | 逆向填充 |

**共同点**：**「有序」这个前提一旦存在，就要问「哪些元素会受影响」；受影响的一定是连续一段，于是「三段式」就能把 `O(n log n)` 压到 `O(n)`。**

### 030.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要插入 **m 个**区间 | 每次 `O(n)` → 总 `O(mn)` | 维护有序区间集：`TreeMap<start, end>`，每次插入 `O(log n + k)`（`k` = 被吞并的个数，均摊 `O(log n)`） |
| 区间**流式到达**（边来边查） | 不能回看 | 同上的平衡树；或先攒一批再批量合并（批处理降低常数） |
| 要求**严格** `O(log n)` 查询「某点是否被覆盖」 | 需要结构支持 | 区间树 / 动态线段树，节点存 `max(end)` |
| 端点是大整数或时间戳 | `int` 不够 | Java 用 `long` / `BigInteger`，Go 用 `int64`；注意 `[start, end)` 半开区间的语义差别 |
| 输入**可能重叠** | 三阶段的引理 1/3 失效 | 先按 029 排序合并一遍，再走三阶段；或直接用 029 |
| 二维（矩形插入 + 合并） | 一维区间变二维矩形 | 扫描线 + 线段树；或按一个维度排序后做区间树套区间树 |

## 030.4 图解推演

### 030.4.1 三阶段扫描的完整轨迹

输入 `[[1,2],[3,5],[6,7],[8,10],[12,16]]`，`newInterval = [4,8]`：

```text
下标:      0      1      2      3       4
区间:   [1,2]  [3,5]  [6,7]  [8,10]  [12,16]      newInterval = [4,8]
                └──────┬──────┘
                   被 [4,8] 吞掉的三段

阶段 ①：iv[i][1] < 4 ?
  i=0: 2 < 4  ✅ → res = {[1,2]}
  i=1: 5 < 4  ❌ → 停，进入阶段 ②

阶段 ②：iv[i][0] <= hi ?（hi 实时扩展）
  i=1: 3 <= 8 ✅ → lo=min(4,3)=3, hi=max(8,5)=8
  i=2: 6 <= 8 ✅ → lo=3,          hi=max(8,7)=8
  i=3: 8 <= 8 ✅ → lo=3,          hi=max(8,10)=10   ← 注意 8<=8 成立，端点相接必须吞
  i=4: 12 <= 10 ❌ → 停
  输出一个区间 [3,10] → res = {[1,2],[3,10]}

阶段 ③：剩下原样搬
  i=4: res = {[1,2],[3,10],[12,16]}
```

状态表：

| 阶段 | i | 当前区间 | 判定 | `lo` | `hi` | 本步后 res |
| --- | --- | --- | --- | --- | --- | --- |
| ① | 0 | `[1,2]` | `2 < 4` ✅ | 4 | 8 | `{[1,2]}` |
| ① | 1 | `[3,5]` | `5 < 4` ❌ | 4 | 8 | `{[1,2]}` |
| ② | 1 | `[3,5]` | `3 ≤ 8` ✅ | **3** | 8 | `{[1,2]}` |
| ② | 2 | `[6,7]` | `6 ≤ 8` ✅ | 3 | 8 | `{[1,2]}` |
| ② | 3 | `[8,10]` | `8 ≤ 8` ✅ | 3 | **10** | `{[1,2]}` |
| ② | 4 | `[12,16]` | `12 ≤ 10` ❌ | 3 | 10 | 输出 `[3,10]` → `{[1,2],[3,10]}` |
| ③ | 4 | `[12,16]` | — | — | — | `{[1,2],[3,10],[12,16]}` |

### 030.4.2 两个最容易写错的判定（对比图）

```text
① 段 ① 用错字段：iv[i][0] < lo  ✗
   intervals=[[1,10]]  newInterval=[5,6]
   iv[0][0]=1 < 5 ✅ → 把 [1,10] 当「完全在左边」搬走
   结果：{[1,10],[5,6]}   ✗ 明明 [5,6] 被 [1,10] 包含，应该合成一个 [1,10]
   正确判据：iv[i][1] < lo，即 10 < 5 ❌ → 进入段 ② → 输出 [1,10] ✓

② 段 ② 用严格小于：iv[i][0] < hi  ✗
   intervals=[[1,2],[3,5]]  newInterval=[2,3]
   i=0: 1 < 2 ✅ → 吞 → lo=1, hi=33?  实际 hi=max(3,2)=3
   i=1: iv[1][0]=3 < hi=3 ❌ → 停下
   结果：{[1,3],[3,5]}   ✗ 两个区间端点相接，还能合并
   正确判据：iv[i][0] <= hi，3 <= 3 ✅ → 继续吞 → [1,5] ✓
```

### 030.4.3 三阶段 vs 重排的两条路线

```text
                  ┌───────── intervals（已有序）+ newInterval ─────────┐
                  │                                                   │
      ┌───────────▼────────────┐                    ┌─────────────────▼─────────────────┐
      │ 路线 A：塞进去重排      │                    │ 路线 B：三段切分                   │
      │ O(n log n) + 合并扫描   │                    │ O(n)  / 三个 while                 │
      └───────────┬────────────┘                    └─────────────────┬─────────────────┘
                  │                                                   │
      用掉了「有序」这个信息吗？没有                       每段一个不变量，边界写在 while 里
                  │                                                   │
          n=10⁶ 需 142 ms                                 n=10⁶ 需 43.9 ms
                  │                                                   │
            【输入无序时才选它】                              【本章选择】
```

## 030.5 双语言实现

### 030.5.1 Java

```java
import java.util.*;

class Solution {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        List<int[]> res = new ArrayList<>(intervals.length + 1);
        int i = 0, n = intervals.length;
        // lo / hi 是局部变量：段 ② 会就地扩展它们，不能直接用 newInterval[0] / [1] 判断
        int lo = newInterval[0], hi = newInterval[1];

        // 阶段一：整个区间都在新区间左边（比右端点！不是左端点）
        while (i < n && intervals[i][1] < lo) {
            res.add(intervals[i]);
            i++;
        }

        // 阶段二：与新区间有交集（<= 而不是 <，端点相接也要吞）
        while (i < n && intervals[i][0] <= hi) {
            lo = Math.min(lo, intervals[i][0]);
            hi = Math.max(hi, intervals[i][1]);   // 用 max：允许新区间被某个区间撑大
            i++;
        }
        res.add(new int[]{lo, hi});               // 合并结果只写这一次，位置明确

        // 阶段三：剩下的都在右边，原样搬
        while (i < n) {
            res.add(intervals[i]);
            i++;
        }

        return res.toArray(new int[res.size()][]);
    }
}
```

### 030.5.2 Go

```go
package main

import "fmt"

// LeetCode 只提交 insertInterval；main 是本地的自检入口
func insertInterval(intervals [][]int, newInterval []int) [][]int {
	// 预分配 n+1 的容量：最坏情况是新增一个区间，一次分配到位避免扩容
	res := make([][]int, 0, len(intervals)+1)
	i, n := 0, len(intervals)
	lo, hi := newInterval[0], newInterval[1] // 局部变量：段 ② 会就地扩展

	// 阶段一：整个区间都在新区间左边（比右端点！不是左端点）
	for i < n && intervals[i][1] < lo {
		res = append(res, intervals[i])
		i++
	}

	// 阶段二：与新区间有交集（<= 而不是 <，端点相接也要吞）
	for i < n && intervals[i][0] <= hi {
		if intervals[i][0] < lo {
			lo = intervals[i][0]
		}
		if intervals[i][1] > hi {
			hi = intervals[i][1]
		}
		i++
	}
	res = append(res, []int{lo, hi}) // 合并结果只写这一次

	// 阶段三：剩下的都在右边，原样搬（append(res, intervals[i:]...) 也行，
	// 但那样会共享底层数组，见 030.6.2 的坑 6）
	for i < n {
		res = append(res, intervals[i])
		i++
	}
	return res
}

func main() {
	cases := []struct {
		in   [][]int
		nw   []int
		want [][]int
	}{
		{[][]int{{1, 3}, {6, 9}}, []int{2, 5}, [][]int{{1, 5}, {6, 9}}},
		{[][]int{{1, 2}, {3, 5}, {6, 7}, {8, 10}, {12, 16}}, []int{4, 8}, [][]int{{1, 2}, {3, 10}, {12, 16}}},
		{[][]int{}, []int{5, 7}, [][]int{{5, 7}}},
		{[][]int{{1, 5}}, []int{2, 3}, [][]int{{1, 5}}},        // 被完全包含
		{[][]int{{1, 2}, {3, 5}}, []int{2, 3}, [][]int{{1, 5}}}, // 端点相接
		{[][]int{{3, 5}}, []int{1, 10}, [][]int{{1, 10}}},      // 吞掉全部
		{[][]int{{1, 2}}, []int{5, 6}, [][]int{{1, 2}, {5, 6}}}, // 插到最后
	}
	for i, c := range cases {
		got := insertInterval(c.in, c.nw)
		if fmt.Sprint(got) != fmt.Sprint(c.want) {
			panic(fmt.Sprintf("case %d: got %v want %v", i, got, c.want))
		}
	}
	fmt.Println("insertInterval: 7 个用例全部通过")
}
```

### 030.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 结果容器 | `ArrayList<int[]>`，最后 `toArray(new int[0][])` | `make([][]int, 0, n+1)` + `append` | Go 可以预留容量，避免扩容时重新分配；Java 的 `ArrayList` 也会扩容（默认 1.5 倍），所以 `new ArrayList<>(n+1)` 值得写 |
| 追加「剩余整段」 | 只能 `while` 逐个 `add`（`addAll` 需要先切子列表） | `append(res, intervals[i:]...)` 一行搞定 | Go 更简洁，但**共享底层数组**：`res` 里那部分元素和入参是同一个 `[][]int` 的元素（`[]int` 头被复制，`int` 数据没被复制）——本题只读不改，所以安全 |
| 局部变量遮蔽 | `int lo = newInterval[0]` | `lo, hi := newInterval[0], newInterval[1]` | 两边都必须用局部变量；直接写 `newInterval[1] = max(...)` 会污染入参（LeetCode 不管，但业务代码会出事故） |
| 判空的必要性 | `intervals.length == 0` 时三个 while 全不进，直接 `res.add([lo,hi])` | 走的是同一套循环，行为一致 | **三阶段结构天然正确**，反而不需要显式的判空分支（这是它比「逐区间判定」更好的地方） |
| 返回空 | 本题不会返回空（至少含 `[lo,hi]`） | 同 | `n = 0` 时返回 `[[lo,hi]]`，是题目要求的 |

## 030.6 复杂度与常见坑

### 030.6.1 复杂度推导

- **时间 `O(n)`**：三个 `while` 的下标 `i` 单调递增、永不回退，总迭代次数恰好 `n` 次，每次 `O(1)` → `O(n)`。这就是「三段式」比「重排」少一个 `log n` 的来源。
- **空间 `O(n)`**：结果是 `n+1` 个区间的列表（最坏全不相交）。**额外**辅助空间是 `O(1)`（除输出本身）。
- **能否做到 `O(1)` 额外空间？** 若允许原地修改 `intervals`：先把 `newInterval` 合并进 `intervals` 的一段，再把尾部元素左移/右移。段 ② 吞掉 `k` 个区间时，结果是 `1` 个区间，需要把后面的元素**左移 `k-1` 位**，仍是 `O(n)` 时间、`O(1)` 空间。面试里说出来是加分项。

### 030.6.2 七个真实踩过的坑

1. **段 ① 判 `intervals[i][0] < lo`**。`[[1,10]]` 插 `[5,6]` 时会把 `[1,10]` 当「在左边」搬走，输出两个重叠区间（§030.4.2 有图）。正确判据是比**右端点**。
2. **段 ② 用 `<` 而不是 `<=`**。`[[1,2],[3,5]]` 插 `[2,3]` 会裂成 `[[1,3],[3,5]]`。端点相接必须合并。
3. **忘了 `res.add(new int[]{lo, hi})`**。段 ② 里只更新 `lo/hi` 不输出，退出后才写一次；漏写这一行直接少一个区间。
4. **用 `newInterval[1]` 当 `hi` 判断**。段 ② 中 `hi` 会被撑大，如果判断里用 `newInterval[1]`（原值），`[[1,2],[3,5],[6,7]]` 插 `[4,5]` 就只能吞掉两个，漏掉 `[6,7]`。
5. **`hi` 没取 `max`**。`[[1,10]]` 插 `[5,6]` 时若写 `hi = intervals[i][1]`（直接赋值），`hi` 会从 6 变成 10 还是对的；但 `[[1,10],[11,12]]` 插 `[5,6]` 时若写成 `hi = 6` 不更新，`[11,12]` 就会被错误吞掉。
6. **Go 里 `append(res, intervals[i:]...)` 之后再改 `res`**。这个写法本身没问题，但如果你随后修改了 `res` 中那些元素（比如再合并一次），会**改到入参的底层数组**。本题只读，安全；作为库函数暴露出去时，要么深拷贝，要么在文档里写清「会共享」。
7. **以为「输入已有序」可以直接二分找到唯一重叠区间**。与 `newInterval` 重叠的区间可能有好几个（示例 2 有三个），二分只能定位起点，吞并仍要线性走。

### 030.6.3 面试官最爱追问的三个问题

**Q1：为什么不用二分？输入明明是有序的。**
> 「因为最终的输出必须是一次**数组重建**：即使我用二分在 `O(log n)` 内找到左右边界，把中间一段替换成一个区间仍然需要 `O(n)` 的搬移（Java 的 `System.arraycopy`、Go 的 `copy`）。所以总代价还是 `O(n)`，二分只省下一个常数，却引入了左右边界的两套判断（第一个 `end ≥ lo`、最后一个 `start ≤ hi`），边界错误概率明显上升。**只有数据结构换成链表或平衡树、插入不需要搬移时，二分才真正有价值。**」

**Q2：如果输入本身就可能有重叠，你的算法还对不对？**
> 「不对。三阶段的两个引理都依赖「输入无重叠且有序」：段 ① 的区间右端点都 `< lo`，段 ③ 的区间左端点都 `> hi`，中间不会再有重叠。如果输入有重叠，段 ① 里就可能藏着重叠对，段 ③ 里也可能。正确做法是先按 029 排序合并一遍再插入，复杂度回到 `O(n log n)`；或者先验证输入无重叠（线性扫一遍），验证失败再走 029。」

**Q3：如果要在 10 分钟内支持 10 万次插入，每次都返回合并结果，怎么设计？**
> 「用一个以 `start` 为键的有序映射（Java `TreeMap<Long, Long>`、Go 手写跳表或红黑树）存互不重叠的区间，并提供两个操作：`floorEntry(lo)` 找「左端点 ≤ lo 的最后一个区间」判断是否要向左合并，然后 `ceilingEntry(hi)` 向右逐个吞并并删除。每次插入 `O(log n + k)`，`k` 是被吞并删除的区间数；因为每个区间一生只会被创建一次、被删除一次，`k` 的均摊值是 `O(1)`，所以均摊 `O(log n)`。」
