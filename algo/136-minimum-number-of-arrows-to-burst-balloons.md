## 136.1 题目

**原题链接**：<https://leetcode.cn/problems/minimum-number-of-arrows-to-burst-balloons/>

### 题意重述（把隐含条件补齐）

二维平面上有一些球形气球，每个气球用一个**闭区间** `points[i] = [xstart, xend]` 表示它在 x 轴上的水平跨度。你可以从 x 轴上的**任意位置** `x` 垂直向上射出一支箭：

- 一支箭能打爆**所有**满足 `xstart ≤ x ≤ xend` 的气球（注意是**闭区间**，箭正好落在端点上也算打中）；
- 箭可以射到任意远的高度；
- 求把所有气球都打爆所需的**最少箭数**。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **闭区间** | 「`xstart ≤ x ≤ xend`」 | 当成开区间 → `[[1,2],[2,3]]` 会答成 2（正确 1：箭射在 2 上） |
| **箭在 x 轴上任意位置** | 「从 x 轴的不同点垂直向上射」 | 误以为只能射在端点 → 缩小了解空间（但最优解总能在端点取到，见 §136.3.2） |
| **一支箭打中多球** | 「一个气球被射中即消失」 | 误以为每球一支 → 退化成答案 `n` |
| **箭可以无限高** | 「箭可以完全垂直地向上射」 | 若高度有限，就变成二维问题 |
| **端点可达 `±2^31`** | 约束 `-2^31 ≤ xstart < xend ≤ 2^31-1` | 用减法比较大小 → **整数溢出**，排序直接错乱（§136.6.2 坑 2） |
| **气球个数可为 1** | `1 <= points.length` | 不特判空数组会 `points[0]` 越界 |

> **本章第一个必读细节**：135 的「不重叠」把端点相接算作**不重叠**（`[1,2]` 与 `[2,3]` 可以同时保留），而 136 的闭区间意味着两支箭语义下「箭落在 2 上能同时打中 `[1,2]` 和 `[2,3]`」。**同一个贪心，判据符号差一个** —— §136.3.3 会把这件事对照清楚。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= points.length <= 10^5` | 最多 10 万 | O(n²) 的「每支箭扫一遍剩余气球」是 `10^10`，必超时；O(n log n) 才是目标 |
| `points[i].length == 2` | 每个气球两个数 | 无退化输入 |
| `-2^31 <= xstart < xend <= 2^31 - 1` | **正好卡在 `int32` 边界** | `a - b` 会溢出（`-2^31 - (2^31-1)` 远超 `int` 范围）→ **排序比较器必须用 `Integer.compare`**；这是本题最硬的工程细节 |
| `xstart < xend` 严格 | 区间非空 | 不存在「零长区间」这种退化情形 |

> 💡 **量级反推**：`n = 10^5` ⟹ O(n log n)。而端点值域高达 `2^32` 说明**不能用值域桶**，只能排序。至于「排序之后怎么做」，就交给本章的贪心。

### 示例

```
输入：points = [[10,16],[2,8],[1,6],[7,12]]
输出：2
解释：在 x = 6 射一箭打爆 [1,6] 和 [2,8]；在 x = 12 射一箭打爆 [7,12] 和 [10,16]

输入：points = [[1,2],[3,4],[5,6],[7,8]]
输出：4
解释：四个区间互不相交，一支箭最多打一个

输入：points = [[1,2],[2,3],[3,4],[4,5]]
输出：2
解释：x = 2 打爆前两个（闭区间：2 同时属于 [1,2] 和 [2,3]），x = 4 打爆后两个
```

### 我自造的四个反例

```text
① [[1,2]]                                  → 答案 1（单个气球，也要一支箭）
② [[1,2],[2,3]]                            → 答案 1（闭区间，箭射在 2 上同时打中）
                                              若写成「箭头不能落在端点」会答 2
③ [[1,10],[2,3],[4,5],[6,7]]               → 答案 3（不是 1！）
                                              [2,3]、[4,5]、[6,7] 两两不相交，各需一支箭；
                                              [1,10] 跨度最长，反而被任意一支箭顺带打中。
                                              这组用来抓「长得最长/最短的区间优先」这类直觉
④ [[-2147483648,-2147483647],[2147483646,2147483647]]
                                           → 答案 2，且排序比较器若写成 a[1]-b[1] 会溢出成负数 → 顺序错乱
```

第 ④ 条是本题的真·杀手：它不改变算法逻辑，却能让你在一个「看起来完全正确」的排序上拿到错误答案。**Java 里必须 `Integer.compare`，Go 里 `a < b` 天然安全。**

## 136.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举箭放哪儿

最直白的想法：答案一定可以取在「某个气球的端点」上（因为把箭从区间内部往端点挪，只会打中更多或同样多的气球）。于是候选位置只有 `2n` 个。

```text
cands = 所有 xstart 和 xend（去重）
for k = 1 .. n:                       # 从小到大试箭数
    for 每个大小为 k 的子集 S ⊂ cands:
        if S 覆盖全部气球: return k
return n
```

- 时间 **O(n · C(2n, k) · n)**，即指数级；空间 O(n)。
- `n = 20` 就已经不可行，`n = 10^5` 完全无从谈起。
- 这是一个**集合覆盖（set cover）**的特例，而一般集合覆盖是 NP-hard —— 本题之所以有 O(n log n) 解，**完全依赖「区间」这个结构**。

稍微像样一点的暴力是 DP / 搜索：`f(i) = 打完前 i 个气球所需的最少箭数`，但「前 i 个」这种划分对区间问题不自然，转移会变得很难写。

### 第二步：卡点在哪

把问题重新描述成一句话：

> **选出最少的点，使得每个区间都至少包含一个点。**

这叫「**区间选点**」（stabbing intervals）。它的难点在于：**一个点的「收益」取决于它落在多少个区间里**，而这个收益是全局的、互相纠缠的。于是第一个念头往往是错的：

- ❌「找被最多区间覆盖的点，射一箭，删掉这些区间，重复」—— 这是**贪心集合覆盖**，在区间上恰好也是错的（虽然直觉很强）。反例：`[[1,3],[2,4],[3,5],[4,6]]`，被覆盖最多的点是 3 或 4（各覆盖 3 个区间）？射 3 打中 `[1,3],[2,4],[3,5]`，剩 `[4,6]` 需再一箭 → 2 支；而最优是 2 支（射 3 和 5？也是 2）。换一组：`[[1,2],[1,4],[2,3],[4,5]]`？覆盖最多的是 2（`[1,2],[1,4],[2,3]`），射 2 → 剩 `[4,5]` → 2 支；最优也是 2。要真正打穿「覆盖最多优先」需要精心构造，见 §136.6.2 坑 5。
- ❌「每个气球都射一箭」—— 退化成 `n`。

### 第三步：灵感的来源 —— 「最早结束的那个，必须现在解决」

换个视角：**看最早结束的气球**。

```
设「结束最早」的气球是 B = [s, e]（e 是所有右端点里最小的）。
任何合法方案都必须用某支箭打中 B，而那支箭的位置 x 必须满足 s ≤ x ≤ e。
⟹ 若把箭放在 x = e，它打中的气球集合 ⊇ 任何放在别的 x' ∈ [s,e] 处的箭所打中的集合
   （因为对任何被 x' 打中的气球 C = [cs, ce]：cs ≤ x' ≤ e ≤ ce，于是 cs ≤ e ≤ ce，x = e 也打中它）
```

这一步就锁定了「箭放右端点」，而且**不需要任何未来信息**：最早结束的气球必须现在解决，而放在 `e` 是最优的那种解决方式。放完之后，被打中的气球全部删掉（它们已经被处理完了），对剩下的气球重复同样的事。

于是算法是：

```
按右端点升序排序
arrows = 1, arrowPos = end(第一个区间)
for 其余每个区间 [s, e]:
    if s > arrowPos:            # 这个区间打不到，需要新箭
        arrows++, arrowPos = e  # 新箭放在它的右端点
    # 否则它已被 arrowPos 打中（s <= arrowPos <= e）
```

### 它与 135 的关系（本章必须讲清的一件事）

把两章的算法并排放：

```
135（无重叠区间，数「删」）              136（引爆气球，数「留」）
按右端点升序                            按右端点升序
keep = 1, lastEnd = end₁                arrows = 1, pos = end₁
for 每个区间 [s, e]:                    for 每个区间 [s, e]:
    if s >= lastEnd:   # 能接上           if s > pos:      # 接不上
        keep++, lastEnd = e                  arrows++, pos = e
return n - keep                          return arrows
```

**这两段代码是同一个算法**，只有两点不同：

1. **计数方向相反**：135 数的是「能留下多少个不相交的区间」，最后用 `n - keep` 得到「删几个」；136 数的是「必须开几支箭」，直接就是答案。
2. **判据符号差一个**：`>=` vs `>`。这不是随便写的 —— 它精确反映了两题的端点语义（135 是左闭右开，相接不算重叠；136 是闭区间，箭可以落在端点上）。

真正的数学桥梁是：**136 的答案 = 135 的 `keep` = 最大两两不相交区间个数。** §136.3.2 用下界把它证死。

## 136.3 原理拆解

### 136.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举箭位置子集（集合覆盖暴力） | 指数级 | O(n) | 15 行 | `n ≥ 20` 就跑不完；只能当对拍判据 |
| 「覆盖最多点优先」贪心 | O(n²) ~ O(n log n) | O(n) | 25 行 | **区间上也可能不是最优**（坑 5 给反例），且难以证明 |
| DP（区间 DP / 状压） | O(n²) 或更高 | O(n²) | 30 行 | `n = 10^5` 必死；纯属把简单问题写复杂 |
| **按右端点排序 + 线性贪心** ✅ | **O(n log n)** | **O(1)** | **9 行** | 若气球变成二维矩形 → 失效（那是二维刺穿问题，NP-hard） |
| 与 135 共用同一段代码（改判据符号 + 改计数） | O(n log n) | O(1) | 9 行 | 见 §136.3.3 的同构表 |

**为什么不用「覆盖最多点优先」**：它的每一步都要重新统计覆盖数（O(n log n) 或 O(n²)），而且贪心选择本身在区间选点问题上并不保证最优 —— 直觉上「选覆盖最多的点」很迷人，但它没有考虑「剩下的区间是否还能被同一支箭顺带解决」。**下界法会告诉你为什么「按右端点」天然达到下界，而「覆盖最多」没有下界保护。**

### 136.3.2 为什么这个做法是对的（正确性论证 · 下界 / 不变量）

**记号**：区间 `C_i = [s_i, e_i]`。排序后满足 `e_1 ≤ e_2 ≤ … ≤ e_n`。
贪心产生的箭位置记为 `p_1 < p_2 < … < p_k`（`p_j` 单调递增，因为每次新箭的 `pos` 是当前区间的右端点，而右端点沿排序不减）。
每个 `p_j` 由一个「触发区间」`C_{i_j}` 产生，满足 `p_j = e_{i_j}`。约定 `i_1 = 1`（第一支箭由排序后第一个区间触发）。

**引理 1（贪心的每支箭都合法地打中它的触发区间）**
`p_j = e_{i_j}`，而 `s_{i_j} ≤ e_{i_j}` 由约束 `xstart < xend`，所以 `p_j ∈ [s_{i_j}, e_{i_j}]`，触发区间自己一定被打中。∎

**引理 2（贪心是可行的：所有气球都被打中）**
对任意区间 `C_i`，考察贪心扫描到它时的 `pos`（此时 `pos = p_j`，`j` 是当前箭号）：

- 若 `s_i > p_j`：它触发新箭，由引理 1 被打中；
- 若 `s_i ≤ p_j`：排序保证 `e_i ≥ p_j`（因为 `p_j` 是某个 `e_{i'}` 且 `i' < i` 时不晚于 `e_i`；`i' = i` 时就是它自己），于是 `s_i ≤ p_j ≤ e_i`，即 `p_j ∈ C_i`，也被打中。

两种情形覆盖全部，所以 `k` 支箭足够。∎

**引理 3（下界：任何方案都至少需要 `k` 支箭）**
贪心的触发区间 `C_{i_1}, C_{i_2}, …, C_{i_k}` **两两不相交**。证明：取 `a < b`，

```
e_{i_a} = p_a ≤ p_{b-1} < s_{i_b}
```

第一步用 `p` 单调不减，第二步用「`C_{i_b}` 触发了新箭」这一事实（触发条件正是 `s_{i_b} > p_{b-1}`）。于是 `e_{i_a} < s_{i_b}`，两个闭区间 `C_{i_a}` 与 `C_{i_b}` 完全分离，不相交（注意这里是**严格**小于，连端点都不接触）。

现在考虑任一合法方案（一组箭位置 `X`）。每支箭是一个点，而**一个点不可能同时落在两个不相交的区间里**。所以 `X` 中每一支箭最多打死这 `k` 个两两不相交的触发区间中的**一个** ⟹ `|X| ≥ k`。∎

> 这就是「弱对偶」：**任何一组两两不相交的区间，其个数都是「覆盖所需点数」的下界。** 而且这个下界对**任何**区间族都成立，与具体算法无关 —— 所以它是一把非常硬的尺子。

**定理（贪心最优）**
由引理 2，`OPT ≤ k`；由引理 3，`OPT ≥ k`。故 `OPT = k`，贪心输出即最优。∎

**推论（与 135 的桥）**
`k` 是贪心构造出的**最大**两两不相交区间族的大小（引理 3 给出下界、贪心自身产生 `k` 个，且任何不相交族的大小都 ≤ 最大独立集 ≤ `k`），因此

```
136 的答案 = 最大两两不相交区间个数 = 135 的 keep
135 的答案 = n − 136 的答案
```

**这就是两章之间的恒等式。** 两题在数学上是同一个参数的两个名字：**区间图的「最大独立集」= 「最小团覆盖」（对区间图，团 = 有公共点的区间集合 = 一支箭能覆盖的集合）**。这个等式对区间图恒成立（区间图是完美图），135 与 136 分别是它的两边。∎

> **为什么这个论证比「交换论证」更适合本章**：
> 交换论证（135 的写法）说明「贪心解不劣于最优解」，属于「改造最优解」；
> 下界论证说明「贪心解等于一个不可突破的下界」，属于「**直接夹逼**」。
> 后者更短，而且它顺带揭示了「为什么两题答案相同」—— 因为它根本不关心贪心的细节，只关心「不相交族的个数」。

### 136.3.3 通用解题思路（可迁移的那一层）

本题是 **「区间选点 = 按右端点贪心，用不相交族做下界」** 模型：

```
原始问题：用最少的点刺穿所有区间（区间刺穿 / stabbing）
         ↓ 观察 1：最早结束的区间必须被「现在」刺穿
         ↓ 观察 2：刺在它的右端点，收益最大（包含关系）
贪心：    按右端点升序 + 线性扫描
证明：    下界 = 互不相交的区间个数；贪心恰好达到下界
```

**与 135 的同构对照表（本章必读）**：

| 维度 | 135 无重叠区间 | 136 引爆气球 |
| --- | --- | --- |
| 输入 | `[start, end)` 区间 | `[xstart, xend]` 闭区间 |
| 问法 | 最少**移除**几个，使剩下互不重叠 | 最少用几个**点**，使每个区间都被命中 |
| 数学本质 | 区间图的**最大独立集** | 区间图的**最小团覆盖**（= 刺穿数） |
| 贪心动作 | 能接上就**保留**（`keep++`） | 接不上就**开新箭**（`arrows++`） |
| 判据符号 | `start >= lastEnd`（相接非重叠） | `start > lastArrow`（箭头要落在内部） |
| 计数方向 | 数**删**：`n - keep` | 数**留**：`arrows`（就是我们构造出的那个族的大小） |
| 两者关系 | `n - 136 答案` | `= 135 的 keep` |
| 证明工具 | 交换论证 | 下界 / 不变量 |

**一句话记忆**：**同一段代码，135 数「删」（`n - keep`），136 数「留」（`arrows`）；判据的 `>=` 与 `>` 之差正好对应开/闭区间的语义之差。**

### 136.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求输出**每支箭的位置** | 要方案 | 贪心时把 `pos` 收集起来即可，O(k) 空间 |
| 箭有**射程限制**（每支箭只能覆盖长度 ≤ L 的跨度） | 问题变难 | 不再是纯区间刺穿，要用 DP 或二分答案 |
| 气球是**二维矩形**，箭是竖直线 | 二维刺穿 | **NP-hard**（本质是集合覆盖），只能近似或约束规模小 |
| 每个气球需要**多支箭**（需求 `d_i`） | 加权版本 | 变成「带需求的区间刺穿」，通常用贪心 + 优先队列或流 |
| 箭必须射在**整数坐标**且端点可达 `2^31` | 溢出与离散化 | 比较器用 `Integer.compare`、位置用 `long`；离散化候选点 = 全部端点 |
| 输入是**流式**（气球逐个到来，随时要能回答当前最少箭数） | 无法回头重排 | 维护一个「有序的箭位置序列」，插入 O(log n)（进阶） |

**进阶延伸（自己写代码验证）**：

- **LC 435 无重叠区间**：把本章代码改成 `n - keep` 就是上一章的答案 —— 亲眼看这两题的代码如何互相翻译。
- **LC 1288 删除被覆盖区间**：同样是「按端点排序 + 维护一个边界」，但排序键与判据都不一样，很适合练习「排序键与判据的配对」。
- **LC 253 会议室 II**：把「选点」换成了「同时占用的最大个数」，是同一张区间图的色数。

## 136.5 双语言实现

### 136.5.1 Java

```java
import java.util.Arrays;

class Solution {
    public int findMinArrowShots(int[][] points) {
        int n = points.length;
        if (n == 0) {
            return 0;   // 约束保证 n >= 1，这行只作为通用函数的兜底
        }

        // 按右端点升序。必须用 Integer.compare：
        // 端点可达 ±2^31，写成 (a,b) -> a[1] - b[1] 会溢出成错序。
        Arrays.sort(points, (a, b) -> Integer.compare(a[1], b[1]));

        int arrows = 1;                          // 第一支箭由「最早结束」的气球逼出来
        long arrowPos = points[0][1];            // 用 long 存箭位置：闭区间端点可能是 2^31-1

        for (int i = 1; i < n; i++) {
            // 严格大于：箭必须真的落在 [start, end] 内部（含端点）才打得到。
            // 写成 >= 就会把「箭恰好在 start 上」的情况误判成打不到。
            if ((long) points[i][0] > arrowPos) {
                arrows++;
                arrowPos = points[i][1];         // 新箭放在当前气球的右端点（最早结束处）
            }
            // 否则 start <= arrowPos <= end（end 由排序保证 >= arrowPos），已被当前箭打中
        }
        return arrows;
    }
}
```

### 136.5.2 Go

```go
package main

import "sort"

func findMinArrowShots(points [][]int) int {
	n := len(points)
	if n == 0 {
		return 0
	}

	// 与 Java 同构：按右端点升序。
	// Go 直接写 a[1] < b[1]，不存在「相减溢出」的问题（Go 的比较不产生运算）。
	sort.Slice(points, func(i, j int) bool {
		return points[i][1] < points[j][1]
	})

	arrows := 1
	arrowPos := points[0][1]

	for i := 1; i < n; i++ {
		if points[i][0] > arrowPos { // 严格大于：闭区间，箭落在端点上也算命中
			arrows++
			arrowPos = points[i][1]
		}
	}
	return arrows
}
```

### 136.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 排序比较器 | `Integer.compare(a[1], b[1])` | `points[i][1] < points[j][1]` | **Java 若写减法会溢出**（端点 `±2^31`）；Go 天然安全 |
| 存箭位置的类型 | 建议 `long` | `int` 在 64 位平台是 64 位 | 本题端点最大 `2^31-1`，`int` 装得下；但 Java 若做任何加法（例如 `pos + 1`）就会溢出，所以用 `long` 更省心 |
| 二元比较 | `(long) points[i][0] > arrowPos` | `points[i][0] > arrowPos` | 只要不写减法，两语言都安全 |
| 二维数组 | `int[][]`，`points[i].length == 2` | `[][]int`，行切片长度不保证 | Go 里若担心畸形输入，要显式判 `len(row) >= 2` |
| 返回类型 | `int` | `int` | 一致；箭头数最多 `n ≤ 10^5`，不会溢出 |

### 136.5.4 对拍测试（小 `n` 枚举箭位置子集）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：候选箭位置 = 所有端点；从小到大枚举子集，找出能覆盖全部气球的最小箭数。
// 完全独立于贪心（不排序、不看右端点），是最可信的判据。
func bruteArrows(points [][]int) int {
	n := len(points)
	// 收集候选点（去重）
	cands := make([]int, 0, 2*n)
	for _, p := range points {
		cands = append(cands, p[0], p[1])
	}
	// 冒泡去重（n 很小，够用）
	uniq := cands[:0]
	for _, v := range cands {
		dup := false
		for _, u := range uniq {
			if u == v {
				dup = true
				break
			}
		}
		if !dup {
			uniq = append(uniq, v)
		}
	}
	m := len(uniq)
	best := n
	// 枚举候选点子集，取「覆盖全部气球」的最小大小
	for mask := 1; mask < (1 << m); mask++ {
		k := 0
		for b := 0; b < m; b++ {
			if mask&(1<<b) != 0 {
				k++
			}
		}
		if k >= best {
			continue // 剪枝：不可能更好
		}
		ok := true
		for _, p := range points {
			hit := false
			for b := 0; b < m; b++ {
				if mask&(1<<b) != 0 && uniq[b] >= p[0] && uniq[b] <= p[1] {
					hit = true
					break
				}
			}
			if !hit {
				ok = false
				break
			}
		}
		if ok {
			best = k
		}
	}
	return best
}

			s := r.Intn(10) - 3 // 值域 [-3, 6]，故意制造大量端点相接

		}
		cp := make([][]int, n)

			cp[i] = []int{points[i][0], points[i][1]}
		}
		got, want := findMinArrowShots(cp), bruteArrows(points)
```

## 136.6 复杂度与常见坑

### 136.6.1 复杂度推导

- **时间 O(n log n)**：排序主导（Java 对象数组 TimSort / Go pdqsort）。扫描是严格一遍 O(n)，每轮只做一次比较和一个赋值。
- **空间 O(log n) ~ O(n)**：排序的栈/临时空间。贪心本身只有 `arrows / arrowPos / i`，**O(1)**。
- **对照**：集合覆盖暴力是指数级；「覆盖最多点优先」的朴素实现是 O(n²) 甚至 O(n² log n)。

### 136.6.2 七个真实踩过的坑

1. **贪心没有证明 = 猜** —— 本章最危险的一点是「代码太短」。9 行代码让人以为「这题就这么写」，但被问「为什么答案等于最大不相交区间数」时卡住。**这条等式才是本题的全部内容**；答不出，就说明你只是在背模板，遇到「箭有射程」或「二维矩形」的变体会立刻失手。
2. **Java 排序比较器写成 `(a,b) -> a[1] - b[1]`** —— 端点可达 `±2^31`，相减溢出成错序（`-2^31 - (2^31-1)` 的结果在 `int` 里是正数，排序直接把最小和最大对调）。**必须 `Integer.compare`。** 这个 bug 在本地小数据上永远不会暴露。
3. **判据写成 `start >= arrowPos`** —— 闭区间语义下，箭落在 `start` 上**能**打中。写成 `>=` 会把 `[[1,2],[2,3]]` 判成需要 2 支箭（正确 1）。
4. **和 135 的 `>=` 混淆** —— 135 是「贴合边界」，为 `>=`；136 是「箭必须落在内部，含端点」，为 `>`。**两题代码一样，判据不同，随手抄一定错。**
5. **用「覆盖最多点优先」的贪心** —— 直觉很强但缺少下界保护。构造反例：`[[1,2],[2,5],[3,4],[4,6]]`，点 2 覆盖 `[1,2],[2,5]`（2 个），点 4 覆盖 `[2,5],[3,4],[4,6]`（3 个）→ 若先选 4，剩 `[1,2]` 一箭 → 共 2；最优也是 2。要真正打穿它需要更精巧的构造，但**关键问题不是「有没有反例」，而是「你凭什么保证它没反例」** —— 没有下界/上界的保护，就是猜。
6. **忘记 `n == 0` 的兜底** —— 约束是 `n >= 1`，所以 `points[0]` 安全；但把这段代码搬进通用库时，空输入会直接崩。写 `if (n == 0) return 0;` 零成本。
7. **把箭位置存成 `int` 后做 `pos + 1` 之类的运算** —— 端点可能正好是 `2^31-1`，加一就溢出成负数，后续比较全部错乱。本题不需要任何偏移运算；需要时请用 `long`。

### 136.6.3 面试官最爱追问的三个问题

**Q1：为什么答案等于「最大两两不相交区间数」？**

> 「两个方向夹。**上界**：贪心产生的触发区间两两不相交（因为 `e(前) = p ≤ p_before < s(后)`），任何方案里每支箭只能落在一个触发区间中，所以至少需要这么多个点；**下界那侧**是：贪心用同样多的箭就把所有气球打完了，所以它就是最优值。于是『最少点数』等于『最大不相交族大小』—— 这正是区间图的对偶恒等式（最大独立集 = 最小团覆盖），135 是左边，136 是右边。」

**Q2：为什么箭放在右端点？放在左端点行不行？**

> 「不行。以最早结束的气球 `C = [s, e]` 为例，箭必须落在 `[s, e]` 内。对任何落在 `x' ∈ [s, e]` 的箭，以及任何被它打中的气球 `D = [ds, de]`，都有 `ds ≤ x' ≤ e`（因为 `x' ≤ e`），而 `de ≥ e`（因为 `e` 是所有右端点的最小值），所以 `ds ≤ e ≤ de`，即 `e` 也打中 `D`。也就是说**把箭从 `x'` 挪到 `e`，打中的集合只增不减**。既然放在 `e` 从不吃亏，那就放 `e`。」

**Q3：如果气球变成二维矩形，箭是一条竖直直线，还能贪心吗？**

> 「不能。二维刺穿等价于一般集合覆盖的一个特例，是 NP-hard 的（一维之所以可解，全靠『区间族有单调结构 + 端点全序』）。工程上只能上近似（比如按某种规则选竖线）或者对规模小的实例做搜索。这个对比也解释了为什么『排序 + 一次扫描』在一维能封顶，到了二维就彻底失效。」

- 任何「按右端点排序 + 一次扫描」的贪心，判据的 `>` 与 `>=` 都必须能对应到题面的**开/闭区间语义**，否则抄错必错。

</details>
