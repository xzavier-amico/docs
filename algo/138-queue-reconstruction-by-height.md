## 138.1 题目

**原题链接**：<https://leetcode.cn/problems/queue-reconstruction-by-height/>

### 题意重述（把隐含条件补齐）

有一群人站成一队，每个人用 `people[i] = [h_i, k_i]` 描述：`h_i` 是他的身高，`k_i` 是**排在他前面、且身高不低于他的人的数量**。这组数据在打乱之前来自一个真实队列，也就是**至少存在一种排列满足所有约束**。请你重建这个队列（返回任意一个合法排列；本题输入保证解唯一）。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **`k` 数的是「前面」的人** | 「排在这个人前面」 | 数成后面的 → 全错 |
| **`k` 数的是「不低于」自己身高** | 「身高大于或等于 `h_i` 的人」 | 用严格大于 → 同身高的人互相漏计 |
| **`k` 不含自己** | 「排在他前面」 | 把 `k+1` 当插入下标 → 整体偏移一位 |
| **输入保证可构造** | 「题目数据保证…」 | 省掉「无解」分支；但验证函数仍要能识别非法 |
| **解唯一** | 输入保证 | 可以对拍「逐项相等」；若无此保证就只能验合法性 |
| **`n` 可以等于 1** | `1 <= n` | 答案就是原样；不特判也要能跑通 |
| **身高可重复** | `0 <= h <= 10^5` | 同身高的人之间**互相计数**，这是本题最烧脑的地方 |

> 最后一条是本题的题眼。若所有人身高都不同，题目会简单很多（每个人的 `k` 直接就是最终下标）。**正因为有同身高的人**，「按身高降序、同高按 `k` 升序」这个 tie-break 才变得必须。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= people.length <= 2000` | 最多 2000 人 | **O(n²) = 4·10⁶ 次移动**，完全可行 —— 这是本题「允许用 `ArrayList` 插入」的关键前提 |
| `0 <= h_i <= 10^5` | 身高值域大 | 不能用「身高当数组下标」的桶排；只能排序 |
| `0 <= k_i < n` | `k` 合法 | 插入位置 `k` 一定落在 `[0, size]` 内，不会越界 |
| 解唯一 | 输入保证 | 对拍可以「逐项相等」，不必只验合法性 |

> 💡 **量级反推**：`n ≤ 2000` 这个上限**故意**定得很小，因为它允许 O(n²) 的「逐个插入」实现（每次插入要搬移 `O(n)` 个元素）。如果 `n` 到 `10^5`，就必须换成「从低到高 + 树状数组找第 `k` 个空位」的 O(n log n) 写法（§138.3.1、§138.3.4）。**看到 2000，就知道出题人允许你 O(n²)。**

### 示例

```
输入：people = [[7,0],[4,4],[7,1],[5,0],[5,2],[6,1]]
输出：[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]

校验（逐人数前面身高不低于自己的人）：
  位置0 [5,0]：前面没人 → 0 ✓
  位置1 [7,0]：前面 [5] 都低于 7 → 0 ✓
  位置2 [5,2]：前面 ≥5 的有 [5,0]、[7,0] → 2 ✓
  位置3 [6,1]：前面 ≥6 的有 [7,0] → 1 ✓
  位置4 [4,4]：前面 [5,0],[7,0],[5,2],[6,1] 全 ≥4 → 4 ✓
  位置5 [7,1]：前面 ≥7 的有 [7,0] → 1 ✓

输入：people = [[6,0],[5,0],[4,0],[3,2],[2,2],[1,4]]
输出：[[4,0],[5,0],[2,2],[3,2],[1,4],[6,0]]
```

### 我自造的四个反例

```text
① [[7,0]]                                  → 答案 [[7,0]]（单人）
② [[5,0],[5,0],[5,0]]                      → 这组输入无解（三个人都要求前面 0 个 ≥5 的人，
                                              但彼此都算「不低于」）→ 不会出现在测试里；
                                              用来校验「验证函数」能不能识别非法
③ [[5,2],[5,0],[5,1]]                      → 同身高三人的 k 各不相同，答案 [[5,0],[5,1],[5,2]]
                                              这组能打穿「同高不按 k 升序」的写法
④ [[9,0],[7,0],[1,9],[9,1],[7,1],[1,9]]    → 非法输入（k 重复），同 ②
```

第 ③ 条是关键：**同身高的人，`k` 必须严格递增**（否则第 2 个人必然看到第 1 个同高者）。这个观察在 §138.3.2 的归纳证明里会变成一条正式引理。

## 138.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有排列

```text
for 每个排列 P of people:
    if 对每个位置 i，前面的元素里 h >= h_i 的个数 == k_i: return P
```

- 时间 **O(n!·n)**，`n = 11` 时 `4·10⁷`，`n = 15` 时 `1.3·10^12` —— **毫无希望**。
- 加上剪枝（按 `k` 从 0 递增地填位置）能减少常数，但复杂度仍是指数级。

另一条看似聪明的暴力：**按 `k` 从小到大填位置**。第 `k = 0` 的人必须排在最前面（前面没有任何身高不低于他的人）—— 可是「最前面」可能有多个候选（身高互不影响的人可以互换），于是仍然要搜索。

### 第二步：卡点在哪

卡点是一个「**相互冲突**」：

```
矮个子在意的情况   ⟸ 取决于高个子站在哪儿（高个子站他前面就会计入）
高个子在意的情况   ⟸ 完全不受矮个子影响（矮个子站他前面不算「不低于」）
```

这个不对称就是全部机会。**如果能先把高个子全部安顿好，矮个子再一个个插进去，那么矮个子的插入对高个子完全「透明」** —— 高个子的 `k` 值不会因为前面多了个矮子而变化。

反过来做行不行？先安顿矮个子，再往队列里放高个子 —— 高个子插进去会**顶到矮个子前面**，矮个子的 `k` 值会被改变（如果高个子站他前面，他的计数要 +1）。所以「先矮后高」必须同时维护「空位」的语义，那就难多了（§138.3.1 会给出那种写法，它需要树状数组）。

### 第三步：灵感的来源 —— 「高者先行，按 k 插入」

于是算法是：

```
1) 按身高降序排序；身高相同时按 k 升序
2) 依次取出每个人，把他插入到当前队列的下标 k 处
```

为什么敢直接插到下标 `k`？

- 已经被放进队列的人，身高**都不低于**当前这个人（降序排序保证）⟹ 他们全部计入「不低于自己」的计数；
- 而插到下标 `k`，前面刚好有 `k` 个人 ⟹ 这 `k` 个人全是「不低于自己」的 ⟹ 计数恰为 `k` ✓；
- 队列里还没放进来的人，身高**都不高于**当前这个人 ⟹ 他们将来只会插到「更靠前的位置」（因为他们的 `k` 更小或相当），即使站到当前人前面，也不会被计入 …… **等等，真的不会吗？**

```
不变量（本章核心）：插入第 m+1 个人时，队列里已有的 m 个人身高全都 ≥ 他的身高。
                   ⟹ 他前面恰好 k 个人 ⟹ 恰有 k 个「不低于自己」的人
                   ⟹ 而他插入后把某些人往后挤，但他是「最矮的」，
                      所以对那些人来说「前面多了一个人」这件事**不计入**他们的 k
```

最后一个 `⟹` 里藏着一个同身高的陷阱 —— §138.3.2 用「等高者按 `k` 升序、位置恰为 `k`」这条引理把它堵死。

## 138.3 原理拆解

### 138.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举全排列 | O(n!·n) | O(n) | 10 行 | `n ≥ 12` 就跑不动；只能当对拍判据 |
| **高者先行 + `ArrayList` 按 `k` 插入** ✅ | **O(n²)** | O(n) | **6 行** | `n ≥ 10^5` 时超时（每次插入搬 `O(n)` 个元素） |
| 高者先行 + 手写链表（`LinkedList` / 双向链表） | O(n²) | O(n) | 30 行 | **反而更慢**：链表「找第 k 个位置」要 O(n) 走一趟，且常数大、缓存不友好 |
| 矮者先行 + 树状数组/线段树「找第 k+1 个空位」 | O(n log n) | O(n) | 40 行 | 代码长、同身高的 tie-break 更容易写错；只在 `n` 很大时才划算 |
| 平衡树（`order statistic tree`） | O(n log n) | O(n) | 50 行 | Java/Go 标准库都没有现成实现，要手写 |

**为什么 O(n²) 的 `ArrayList` 插入是本题正解**：`n ≤ 2000`，`4·10⁶` 次元素搬移在现代 CPU 上是毫秒级；而 `ArrayList` 的连续内存让搬移非常缓存友好，实测比链表的 O(n²) 快一个数量级。**别被「链表插入 O(1)」这句话骗了 —— 它省掉的是插入，但没省掉「找第 k 个位置」。**

### 138.3.2 为什么这个做法是对的（正确性论证 · 归纳法）

**算法**

```text
按 (h 降序, k 升序) 排序
q = 空列表
for 每个人 p in 排序后的顺序:
    q.insert(p.k, p)          # 插到下标 p.k 处
return q
```

**记号的建立**：记排序后的顺序为 `p_1, p_2, …, p_n`，满足

```
(排序性质 S)  h(p_1) ≥ h(p_2) ≥ … ≥ h(p_n)；若 h(p_a) = h(p_b) 且 a < b，则 k(p_a) < k(p_b)
```

记 `Q_m` 为插入完前 `m` 个人后的队列。对 `Q_m` 中任一元素 `q`，定义

```
cnt(q, Q_m) = Q_m 中排在 q 前面、且身高 ≥ h(q) 的人数
```

目标是证明：`Q_n` 里每个 `q` 都满足 `cnt(q, Q_n) = k(q)`。

**引理 1（等高者的位置恰好等于自己的 `k`）**
在 `Q_m` 中，如果 `q` 的身高等于 `H = min{ h(p_1), …, h(p_m) }`（也就是当前队列里的最小身高），那么 `q` 在 `Q_m` 中的**下标恰好是** `k(q)`。

*证明*：`Q_m` 里所有元素身高都 `≥ H`（排序性质 S），而 `h(q) = H`，所以「`q` 前面的所有人」都满足身高 `≥ h(q)`，于是

```
cnt(q, Q_m) = q 前面的总人数 = q 的下标
```

只要归纳假设「此前每个人的 `cnt` 都等于自己的 `k`」（见引理 3 的归纳），就有 `q 的下标 = cnt(q, Q_m) = k(q)`。∎

**引理 2（插入点不越过任何等高者 —— 同身高陷阱的堵点）**
设当前要插入 `p_{m+1}`，身高 `h`。则 `Q_m` 中所有身高恰好为 `h` 的元素，其下标都 `< k(p_{m+1})`。

*证明*：设 `q ∈ Q_m` 且 `h(q) = h`。因为排序性质 S 保证 `h` 是 `Q_m ∪ {p_{m+1}}` 中的最小身高，所以 `h(q) = min{…}`，由引理 1，`q 的下标 = k(q)`。又因为 `q` 与 `p_{m+1}` 同高且 `q` 更早被插入（`q` 在排序中位于 `p_{m+1}` 之前），由排序性质 S 的 tie-break 得 `k(q) < k(p_{m+1})`。故 `q 的下标 = k(q) < k(p_{m+1})`。∎

> 引理 2 是本章**唯一真正难的地方**。如果同身高的人不按 `k` 升序处理（例如按 `k` 降序），就会有人被插到等高者的前面，把对方的 `cnt` 顶成 `k+1` —— 而那正是最常见的 WA。

**引理 3（不变量：每次插入后所有人的 `cnt` 都正确）**
对每个 `m = 0, 1, …, n`：`Q_m` 中每个元素 `q` 都满足 `cnt(q, Q_m) = k(q)`。

*证明（对 m 归纳）*：

- **基础 `m = 0`**：队列为空，命题空洞成立。
- **归纳步**：设 `Q_m` 满足不变量。把 `p = p_{m+1}`（身高 `h`，`k = k(p)`）插入到下标 `k`，得到 `Q_{m+1}`。分两类元素检查：

  1. **新人 `p` 自己**：插在下标 `k` 处，前面恰有 `k` 个元素；由排序性质 S，这 `k` 个元素的身高都 `≥ h`，所以 `cnt(p, Q_{m+1}) = k = k(p)` ✓。
  2. **老人 `q ∈ Q_m`**：
     - 若 `q` 原下标 `< k`：`q` 的下标不变，且 `p` 排在 `q` **后面**，不进入 `q` 的前缀 ⟹ `cnt` 不变 ✓。
     - 若 `q` 原下标 `≥ k`：`q` 的下标后移一位，同时 `p` 排到了 `q` **前面**。此时需要判断 `p` 是否计入 `q` 的「不低于」计数 —— 只有当 `h(p) ≥ h(q)` 时才计入。
       若 `h(p) = h(q)`：由引理 2，`q` 的原下标应 `< k`，与「原下标 `≥ k`」矛盾。所以 `h(p) < h(q)`，即 `p` 比 `q` 矮，**不计入** `q` 的计数。于是 `q` 前面的「不低于自己」的人数不变 ✓。

  两类都成立，归纳完成。∎

**定理（算法输出合法）**
取 `m = n`，由引理 3，`Q_n` 中每个人都满足 `cnt = k` —— 这正好是题目要求的合法队列。∎

**唯一性的简短说明**
由引理 1 的机制可以反过来读：在任何合法队列里，身高最大的人必然占据「`k` 递增」的前若干位置，其中最矮一层的位置被 `k` 强制；剥掉这一层后，剩下的问题同构。所以合法队列被逐步决定，**不会有两个不同的合法答案**。这也解释了为什么题目敢说「解唯一」，以及为什么对拍可以写「逐项相等」。

> **这个论证的骨架**：把「插入位置 `k` 前面恰好有 `k` 个不低于自己的人」拆成两条 ——
> ① **新人自己的计数**（靠「已排的人都不矮于他」+「插在下标 `k`」）；
> ② **老人的计数不被破坏**（靠「新人不高于老人 ⟹ 不计入」+ 引理 2 堵掉同身高）。
> 第 ② 条的关键是：**计数只统计「不低于自己」的人，于是「更矮的人插到我前面」是无害的** —— 这不是巧合，而是这道题被设计成可贪心的原因。

### 138.3.3 通用解题思路（可迁移的那一层）

本题是 **「让一部分元素对另一部分透明 → 逐层剥离」** 模型：

```
原始问题：n 个人互相约束（矮的人在乎高的人，高的人不在乎矮的人）
         ↓ 观察：约束是**单向**的（不对称）
建模：    把元素按「影响力」排序（身高降序），高影响力者先定位置
         ↓ 后插入者只影响「比它更弱」的元素，而它们已经排完
贪心：    插入到第 k 位（k 就是它在前缀里应有的名次）
收益：    一个互相纠缠的约束系统 → 一个「逐个定位」的构造
```

**同族题目**：

| 题 | 「透明」的方向 | 处理方式 |
| --- | --- | --- |
| [LC 406 根据身高重建队列](https://leetcode.cn/problems/queue-reconstruction-by-height/) | 高个看不矮个 | 高者先行 + 按 `k` 插入 |
| [LC 135 分发糖果](https://leetcode.cn/problems/candy/) | 左边看不右边 | 左右各扫一遍，取 `max` |
| [LC 312 戳气球](https://leetcode.cn/problems/burst-balloons/) | —— | 反过来想「最后一个被戳的」 |
| [LC 105 从前序与中序构造二叉树](https://leetcode.cn/problems/construct-binary-tree-from-preorder-and-inorder-traversal/) | 根看左右子树 | 先定根，再递归（也是「强约束先行」） |
| [LC 950 按递增顺序显示卡牌](https://leetcode.cn/problems/reveal-cards-in-increasing-order/) | —— | 逆序模拟，把操作反过来做 |

**共同点**：只要约束是**有向的**（A 影响 B，B 不影响 A），就可以按影响力排序，逐个把元素放进「它该在的位置」，把 O(n!) 的搜索降成 O(n²) 或 O(n log n) 的构造。

### 138.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| `k` 改成「前面身高**严格大于**自己的人数」 | 同身高不再互相计数 | 排序改成「身高降序、同高按 `k` **降序**」会更自然；插入位置仍为 `k`，但引理 2 的论证要重写 |
| `n` 放大到 `10^5` | O(n²) 插入超时 | 矮者先行 + 树状数组「找第 `k+1` 个空位」，O(n log n)；同高需按 `k` **降序**处理（等价于把「不低于」换成「严格大于」的补集） |
| 输入**不保证有解**，要求返回 `[]` | 输入校验 | 构造时若 `k > 当前队列长度` 就说明无解；另外要检查全体 `k` 的分布是否可满足 |
| 要求输出**所有**合法队列 | 计数问题 | 先证明解唯一（本章定理后的小节），答案为 1 或 0 |
| 数据是**流式**（人一个一个来） | 无法全局排序 | 只能增量维护「按身高分层的结构 + 各层内的 `k` 有序表」，用平衡树 O(log n) 每次 |
| 每个人还有别的属性（如体重），`k` 描述更复杂 | 多维约束 | 通常退化成 NP-hard 或需要 DP，不再是贪心题 |

- **LC 950 按递增顺序显示卡牌**：把「操作」反过来做，是「逆向构造」的经典。

## 138.4 图解推演

### 138.4.1 插入全过程

```text
people = [[7,0],[4,4],[7,1],[5,0],[5,2],[6,1]]
排序（h 降序，同高按 k 升序）：
    [[7,0], [7,1], [6,1], [5,0], [5,2], [4,4]]

┌─ 步骤 ─┬─ 当前人 ─┬─ 插入位置 ─┬────────── 队列（左 → 右 = 前 → 后）──────────┐
│   1    │  (7,0)   │   下标 0   │ [(7,0)]                                        │
│   2    │  (7,1)   │   下标 1   │ [(7,0), (7,1)]                                 │
│   3    │  (6,1)   │   下标 1   │ [(7,0), (6,1), (7,1)]                          │
│   4    │  (5,0)   │   下标 0   │ [(5,0), (7,0), (6,1), (7,1)]                   │
│   5    │  (5,2)   │   下标 2   │ [(5,0), (7,0), (5,2), (6,1), (7,1)]            │
│   6    │  (4,4)   │   下标 4   │ [(5,0), (7,0), (5,2), (6,1), (4,4), (7,1)]     │
└────────┴──────────┴────────────┴────────────────────────────────────────────────┘

每一步的「透明性」：
  插入 (6,1) 时，队列里只有 7 和 7（都 ≥ 6）→ 插到下标 1，前面 1 个全是「不低于」→ 计数 = 1 ✓
  插入 (5,0) 时，队列里 7、7、6 都 > 5 → 插到下标 0，前面 0 个 → 计数 = 0 ✓
  插入 (4,4) 时，队列里 5 个都比 4 高 → 插到下标 4，前面 4 个全计入 → 计数 = 4 ✓
```

### 138.4.2 第 5 步的插入细节（看懂「挤动」为什么不破坏别人）

```text
插入前： [(5,0), (7,0), (6,1), (7,1)]
                 ▲              ▲
                 └── 下标 2 ────┤  把 (5,2) 插到下标 2
                                ↓
插入后： [(5,0), (7,0), (5,2), (6,1), (7,1)]
                              ▲     ▲
                              │     └─ (6,1) 从下标 2 被挤到 3；前面多了 (5,2)，
                              │        但 5 < 6，不满足「不低于」，所以它的计数仍为 1 ✓
                              └─ (7,1) 从下标 3 被挤到 4；5 < 7 同样不计入，计数仍为 1 ✓
```

### 138.4.3 同身高的陷阱（如果不按 `k` 升序会怎样）

```text
输入：[[5,1], [5,0]]

✅ 正确顺序（同高按 k 升序）： (5,0) → (5,1)
   插 (5,0) 到下标 0： [(5,0)]
   插 (5,1) 到下标 1： [(5,0), (5,1)]
   (5,1) 前面有 1 个 ≥5 的人 → 计数 1 ✓

❌ 错误顺序（同高按 k 降序）： (5,1) → (5,0)
   插 (5,1) 到下标 1 …… 队列只有 1 个元素，下标 1 即末尾 → [(5,1)]
   插 (5,0) 到下标 0： [(5,0), (5,1)]
   这时 (5,1) 前面有 1 个 ≥5 的人 → 计数 1 ✓ …… 看似也对？
   但如果队列里还有别人呢：[[5,2],[5,0],[5,1]]
   ❌ 降序：(5,2) → (5,1) → (5,0)
      插 (5,2) 到下标 2 → [(5,2)]（追加到末尾）
      插 (5,1) 到下标 1 → [(5,2), (5,1)]
      插 (5,0) 到下标 0 → [(5,0), (5,2), (5,1)]
      校验 (5,1)：它前面有 (5,0)、(5,2) 两个 ≥5 的人 → 计数 2 ≠ 1 ✗
   ✅ 升序：(5,0) → (5,1) → (5,2) → [(5,0), (5,1), (5,2)] ✓
```

> 记住引理 2 的一句话版本：**等高的人必须「按 k 从小到大地坐进自己的位置」，否则后插的同高者会顶掉前者的计数。**

## 138.5 双语言实现

### 138.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public int[][] reconstructQueue(int[][] people) {
        // 身高降序；身高相同时 k 升序。
        // 这个 tie-break 不是审美问题：同高者必须让「k 小的先坐进去」，
        // 否则后插入的同高者会顶到前面，把对方的 k 撑大（见 §138.4.3 的反例）。
        // 用 Integer.compare 而不是相减，避免极端值溢出（本题 h <= 1e5 不会溢出，
        // 但这是必须养成的习惯）。
        Arrays.sort(people, (a, b) -> {
            if (a[0] != b[0]) {
                return Integer.compare(b[0], a[0]);   // 身高降序
            }
            return Integer.compare(a[1], b[1]);       // k 升序
        });

        // ArrayList 的 add(index, e) 是 O(n) 的元素搬移：本题 n <= 2000，
        // 总代价 4·10^6 次搬移，连续内存 + System.arraycopy，毫秒级完成。
        List<int[]> q = new ArrayList<>(people.length);
        for (int[] p : people) {
            q.add(p[1], p);   // p[1] 就是 k：插到下标 k，前面正好 k 个人
        }

        return q.toArray(new int[q.size()][]);
    }
}
```

### 138.5.2 Go

```go
package main

import "sort"

func reconstructQueue(people [][]int) [][]int {
	// 与 Java 同构：身高降序，同高按 k 升序。
	sort.Slice(people, func(i, j int) bool {
		if people[i][0] != people[j][0] {
			return people[i][0] > people[j][0]
		}
		return people[i][1] < people[j][1]
	})

	q := make([][]int, 0, len(people))
	for _, p := range people {
		k := p[1]
		// Go 的切片没有 insert 方法，手写三步：
		//   ① append 一格把长度撑开（q[k] 之后整体后移一位的空间就出来了）
		//   ② copy 从 k 开始整体后移（copy 内部按 memmove 处理重叠，安全）
		//   ③ 把 p 放到下标 k
		q = append(q, nil)
		copy(q[k+1:], q[k:])
		q[k] = p
	}
	return q
}
```

> **Go 的 `copy(q[k+1:], q[k:])` 为什么安全**：`copy` 在源与目标重叠时按 `memmove` 语义处理（等价于先拷到临时区），不会出现「自己覆盖自己」的错位。若用 `for` 循环从前往后搬，就会把元素冲掉 —— 必须**从后往前**搬。这是 Go 手写插入最常见的坑。

### 138.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 插入 API | `List.add(index, e)`（内置，O(n)） | 无内置，手写 `append` + `copy` | Go 代码多 3 行，且必须注意重叠拷贝方向 |
| 元素类型 | `int[]`（引用） | `[]int`（切片头 3 字） | 两者都只搬指针/切片头，不是搬 8 字节的 `int` —— 所以 O(n) 的「搬移」其实很快 |
| 排序比较器 | `Integer.compare` | 直接 `<` / `>` | Java 必须防溢出，Go 天然安全 |
| 返回类型 | `int[][]` | `[][]int` | 一致；`q.toArray` 要给出「元素类型 + 长度」 |
| 切片预分配 | `new ArrayList<>(n)` | `make([][]int, 0, n)` | 两者都能省掉扩容；Go 的扩容会**复制整个切片头数组**，预分配收益更明显 |

### 138.5.4 对拍测试（合法性验证 + 小 n 全排列）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// ---------- 工具：生成「保证有解」的输入 ----------

// 先随机造一个队列，再从队列推出每个人的 (h, k)，最后打乱。
// 这样得到的输入必然可构造（因为队列本身就满足约束）。
func genValid(r *rand.Rand, n int) [][]int {
	people := make([][]int, n)
	for i := 0; i < n; i++ {
		people[i] = []int{r.Intn(5) + 1, 0} // 身高值域故意压小 → 大量同高
	}
	// 按身高降序、k 升序（此时 k 全 0，排序只需看身高）排好，再用「插到 k」构造一个合法队列
	sort.Slice(people, func(i, j int) bool { return people[i][0] > people[j][0] })
	q := make([][]int, 0, n)
	for _, p := range people {
		// 这一步只是为了造一个「看起来随机」的合法队列：把 p 随机插到某个位置
		pos := r.Intn(len(q) + 1)
		q = append(q, nil)
		copy(q[pos+1:], q[pos:])
		q[pos] = []int{p[0], 0}
	}
	// 从队列反推出真实的 k：q[i] 前面身高 >= q[i].h 的人数
	res := make([][]int, n)
	for i := 0; i < n; i++ {
		cnt := 0
		for j := 0; j < i; j++ {
			if q[j][0] >= q[i][0] {
				cnt++
			}
		}
		res[i] = []int{q[i][0], cnt}
	}
	// 打乱顺序
	r.Shuffle(n, func(i, j int) { res[i], res[j] = res[j], res[i] })
	return res
}

// ---------- 工具：合法性校验 ----------

func validate(people, q [][]int) bool {
	if len(people) != len(q) {
		return false
	}
	// ① 多重集合必须一致
	a := make([][2]int, len(people))
	b := make([][2]int, len(q))
	for i := range people {
		a[i] = [2]int{people[i][0], people[i][1]}
		b[i] = [2]int{q[i][0], q[i][1]}
	}
	sort.Slice(a, func(i, j int) bool {
		if a[i][0] != a[j][0] {
			return a[i][0] < a[j][0]
		}
		return a[i][1] < a[j][1]
	})
	sort.Slice(b, func(i, j int) bool {
		if b[i][0] != b[j][0] {
			return b[i][0] < b[j][0]
		}
		return b[i][1] < b[j][1]
	})
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	// ② 每个人的「前面身高不低于自己的人数」必须等于自己的 k
	for i := 0; i < len(q); i++ {
		cnt := 0
		for j := 0; j < i; j++ {
			if q[j][0] >= q[i][0] {
				cnt++
			}
		}
		if cnt != q[i][1] {
			return false
		}
	}
	return true
}

// ---------- 对拍 1：验证重建结果合法性（主体判据）----------

func TestReconstructRandomValid(t *testing.T) {

		}
		got := reconstructQueue(cp)

			t.Fatalf("iter=%d in=%v got=%v 不是合法重建", iter, in, got)
		}

// ---------- 对拍 2：n 很小时与全排列暴力逐项比较 ----------

// 暴力：枚举所有排列，返回唯一合法解（本题输入保证唯一）
func bruteReconstruct(people [][]int) [][]int {
	n := len(people)
	idx := make([]int, n)
	for i := range idx {
		idx[i] = i
	}
	var res [][]int
	var perm func(k int)
	perm = func(k int) {
		if res != nil {
			return
		}
		if k == n {
			cur := make([][]int, n)
			for i, id := range idx {
				cur[i] = []int{people[id][0], people[id][1]}
			}
			if validate(people, cur) {
				res = cur
			}
			return
		}
		for i := k; i < n; i++ {
			idx[k], idx[i] = idx[i], idx[k]
			perm(k + 1)
			idx[k], idx[i] = idx[i], idx[k]
		}
	}
	perm(0)
	return res
}

func TestReconstructAgainstBrute(t *testing.T) {
	r := rand.New(rand.NewSource(4242))
	for iter := 0; iter < 3000; iter++ {
		n := 1 + r.Intn(7) // n <= 7 → 5040 个排列，可枚举
		in := genValid(r, n)
		cp := make([][]int, n)
		for i := range in {
			cp[i] = []int{in[i][0], in[i][1]}
		}
		got := reconstructQueue(cp)
		want := bruteReconstruct(in)
		if want == nil {
			t.Fatalf("iter=%d in=%v 生成器给出了无解输入", iter, in)
		}
		if len(got) != len(want) {
			t.Fatalf("长度不一致 got=%v want=%v", got, want)
		}
		for i := range got {
			if got[i][0] != want[i][0] || got[i][1] != want[i][1] {
				t.Fatalf("iter=%d in=%v got=%v want=%v", iter, in, got, want)
			}
		}
	}
}

func TestReconstructEdge(t *testing.T) {

		people [][]int

	}{
		{[][]int{{7, 0}}, [][]int{{7, 0}}},
		{[][]int{{5, 2}, {5, 0}, {5, 1}}, [][]int{{5, 0}, {5, 1}, {5, 2}}},

	for _, c := range cases {
```

> 注意对拍用的**输入生成器**：先造一个队列，再从队列反推 `(h, k)`，最后打乱 —— 这样得到的输入**必然有解**（因为队列自己就是证据）。直接随机生成 `(h, k)` 会得到大量无解输入，算法行为就变得未定义，对拍也就失去意义。**「生成合法输入」本身就是对拍工作的一半。**

## 138.6 复杂度与常见坑

### 138.6.1 复杂度推导

- **时间 O(n²)**：排序 `O(n log n)`；随后 `n` 次插入，第 `m` 次插入要搬移最多 `m` 个元素 ⟹ `Σ m = n(n+1)/2 = O(n²)`。`n = 2000` 时约 `2·10^6` 次元素搬移（搬的是引用，不是结构体），毫秒级。
- **空间 O(n)**：队列本身 + 排序栈空间。
- **如果 `n = 10^5`**：`O(n²) = 10^10` 不可行，此时改用「矮者先行 + 树状数组找第 `k+1` 个空位」，`O(n log n)`（§138.3.4）。

### 138.6.2 七个真实踩过的坑

1. **贪心没有证明 = 猜** —— 这题的代码只有 6 行，但**核心是引理 2**：为什么新插入的同高者不会破坏前人的计数？很多人答「因为它插在后面」（错，它插在下标 `k` 处，可能在前人前面）。正确回答是「同高者按 `k` 升序处理 ⟹ 所有同高者的下标都 `< k` ⟹ 它们恰好都在插入点左边」。答不出这条，一旦把 `k` 的升序改成降序就立刻 WA，而你还不知道为什么。
2. **排序键写成「身高升序」** —— 变成「矮者先行」，此时插入位置不能直接用 `k`（要理解成「第 `k` 个空位」）。直接套 `add(k, p)` 会得到一堆错答案。
3. **同身高按 `k` 降序** —— 见 §138.4.3 的三元素反例 `[[5,2],[5,0],[5,1]]`。
4. **`k` 用了 `k+1`** —— 「插到下标 `k`」表示前面有 `k` 个人；写成 `k+1` 会让前面有 `k+1` 个人，全表偏移一位（`[[7,0]]` 这种单元素用例还会直接越界崩溃）。
5. **以为 `LinkedList` 会更快** —— 链表插入本身是 O(1)，但「走到第 `k` 个结点」要 O(n)，而且指针追逐导致缓存命中率极低。实测 `n = 2000` 时 `ArrayList` 快 5~10 倍。**复杂度相同不代表实际速度相同。**
6. **Go 里手写插入时从前往后搬** —— `for i := len(q)-1; i > k; i-- { q[i] = q[i-1] }` 是对的；写成从 `k` 开始往后赋值会把元素冲掉。用 `copy(q[k+1:], q[k:])` 最稳（重叠安全）。
7. **对拍直接随机生成 `(h, k)`** —— 大量无解输入会让「正确算法」也返回非法结果（因为题目只保证有解时唯一）。必须先造队列再反推。

### 138.6.3 面试官最爱追问的三个问题

**Q1：为什么按身高降序插入，插入后不需要再调整？**

> 「因为计数定义是单向的：`k` 只统计**不低于自己**的人。降序插入保证「已在队列里的人都 ≥ 当前人」，于是当前人插到下标 `k` 时，前面那 `k` 个人全都计入 ⟹ 他的 `k` 天然被满足。而他对别人来说是最矮的，插到别人前面时别人**不会**把他计入（除了同身高，而那种情况被 tie-break 排掉了）。所以一次插入就永远正确，不需要回改。」

**Q2：如果 `k` 改成「前面身高严格大于自己的人数」，要怎么改？**

> 「排序改成「身高降序、同高按 `k` 降序」，插入位置仍是 `k`。直觉：现在同身高的人**互相看不见**，所以同高的人之间谁先谁后无所谓，但为了不互相干扰，让 `k` 大的先坐（它需要更多空位在前面）。也可以把「不低于」降序、看成「严格大于」升序的镜像来处理。关键结论不变：**`k` 的语义决定 tie-break 的方向**，两者必须配对。」

**Q3：`n = 10^5` 时怎么办？**

> 「换成「矮者先行 + 找第 `k+1` 个空位」：先把人按身高**升序**排（同高按 `k` 降序），准备一个长度 `n` 的空位数组，用树状数组维护「前缀还有几个空位」。对每个人，二分 + 树状数组求出第 `k+1` 个空位的下标，放进去。总复杂度 `O(n log n)`。代码量大约翻三倍，但 `n = 10^5` 时是唯一可行解。」
