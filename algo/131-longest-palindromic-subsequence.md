## 131.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-palindromic-subsequence/>

### 题意重述（把隐含条件补齐）

给你一个字符串 `s`，找出**最长的回文子序列**的**长度**。子序列可以**不连续**，但要**保持相对顺序**。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **子序列**（可不连续） | 「subsequence」 | 若按「子串」做（LC 5），`"bbbab"` 会答 3（`"bbb"` 或 `"bab"`），正确是 4（`"bbbb"`） |
| 保序 | 子序列定义 | 若允许重排，答案就变成「字符计数里奇数个数的处理」即 `n − (奇数频次字符数 − 1)` |
| 只问**长度** | 「return the length」 | 输出串需额外回溯（§131.3.4） |
| 回文允许长度 1 | 定义 | `"abc"` 答 1，不是 0 |
| `s` 可以只有 1 个字符 | 约束 `1 <= s.length` | 初值必须 `dp[i][i] = 1` |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length <= 1000` | 一千 | 区间 DP 是 `O(n²) = 10⁶` 格，**舒适**；`O(2ⁿ)` 完全不可能 |
| 只含小写英文字母 | 字符集 26 | 比较 `O(1)` |
| 无取模 | — | 答案 `≤ 1000`，`int` 安全 |
| 空间可以压 | — | 区间 DP 能压到 `O(n)`（§131.3.4），本题不强制但值得会说 |

> 💡 **量级 → 算法**：`n = 1000` + 「回文 + 不连续」= 区间 DP。**看到「子序列 + 两端配对」的题，状态几乎一定是「区间 `[i, j]`」。**

### 示例

```text
输入：s = "bbbab"
输出：4
解释：最长回文子序列是 "bbbb"

输入：s = "cbbd"
输出：2
解释："bb"

输入：s = "a"
输出：1
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① "a"       → 单字符：1（初值 dp[i][i]=1）
② "ab"      → 无长度 2 的回文：1
③ "aaaa"    → 全相同：4（整串就是回文子序列）
④ "bbbab"   → 分水岭：4（注意不是子串的 3）
⑤ "abcabcabc" → 多段重复：正确答案 5（"abcba" 或 "acbca" 一类），
                 检验「两端相等就 +2」这个转移是否被正确使用
```

第 ④ 条是全章的分水岭：**`"bbb"` 是回文子串（长度 3），而 `"bbbb"` 才是最长回文子序列（长度 4）** —— 取了下标 `0,1,2,4` 的四个 `b`。**任何基于「中心扩展」的直觉在这里都会低估答案。**

## 131.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有子序列

```text
best = 0
for mask in [0, 2^n):
    sub = 按 mask 取出字符
    if sub 是回文: best = max(best, len(sub))
```

- 时间 `O(2ⁿ·n)`，`n = 1000` 时不可能。
- 空间 `O(n)`。
- 它的价值：作为对拍基准（§131.5.4），以及「答案的定义」。

### 第二步：为什么「中心扩展」在这里直接失效

130 题的中心扩展依赖一个前提：**回文是连续的一段**，所以「从一个中心向外扩」得到的每一段都是合法的子串。

现在允许跳着选，于是：

```text
s = "bbbab"，答案是 "bbbb"（下标 0,1,2,4）
它的「中心」在哪？不在任何相邻位置之间 —— 它是【两头往中间夹】选出来的。
```

```text
   中心扩展：从一个中心向【外】推，要求连续
   本题：    从两端向【内】夹，允许跳过中间任何字符
```

> 🔑 **卡点的本质**：连续子问题可以用「一个中心 + 半径」描述；不连续的子问题必须用「**一段区间 `[i, j]` + 在这段里选**」描述。**区间才是这类题的正确状态。**

### 第三步：建模 —— 状态是「区间」

```text
dp[i][j] = s[i..j] 这个区间内，最长回文子序列的长度
```

- `i == j`：`dp[i][i] = 1`（单字符是回文）。
- 空区间（`i > j`）：长度 0（代码里靠 `len == 2` 的短路避免访问）。
- 答案 `dp[0][n-1]`。

### 第四步：转移 —— 看区间两端

```text
情况 1：s[i] == s[j]
        最优解一定可以取「两端都用上」 ⇒ dp[i][j] = dp[i+1][j-1] + 2
情况 2：s[i] != s[j]
        两端不可能同时成为回文的两端（它们不相等）
        ⇒ 至少舍弃一端：dp[i][j] = max(dp[i+1][j], dp[i][j-1])
```

这两个分支与 123（最长公共子序列）的转移**形状完全一样**，区别只在「相等时是 `dp[i+1][j-1] + 2` 而不是 `+1`」——因为这里两端一次吃了**两个**字符。

### 第五步（本章的核心）：为什么遍历必须按「长度递增」

`dp[i][j]` 依赖三个更小的状态：

```text
        j-1    j
  i+1    ↖    dp[i+1][j]     ← 上（更大下标的行）
   i     dp[i][j-1] ├ dp[i][j]
                    └ dp[i+1][j-1]  ← 左下
```

- `dp[i][j-1]`：同一行、左边一格 —— 「`i` 递增」时它是本行已算的 ✅
- `dp[i+1][j]`：**下一行**、同一列 —— 「`i` 递增」时它**还没算** ❌
- `dp[i+1][j-1]`：**下一行**、左边 —— 同样还没算 ❌

所以「`i` 从 0 到 `n-1`、`j` 从 `i` 到 `n-1`」这种「顺着扫」的顺序是**错的**。正确做法有三种等价写法：

```text
写法 ①（最常用）：按【区间长度】递增遍历
    for len = 1..n:
        for i = 0..n-len:
            j = i + len - 1

写法 ②：i 从 n-1 递减，j 从 i+1 递增
    for i = n-1 downto 0:
        for j = i+1 to n-1:

写法 ③：i 从 0 递增，j 从 n-1 递减（按对角线填）
```

三种写法都能保证「用到 `dp[i+1][*]` 时它已经算好」。**本章用写法 ①，因为它最直观地把「先算小区间、再算大区间」写在代码里**；§131.3.4 的 `O(n)` 空间压缩版用写法 ②。

> ⚠️ **这个坑的杀伤力**：写错了不会报错，只会**答案偏小**（因为读到的是初值 0）。而随机对拍**一定能抓到** —— 这是本章对拍的价值所在。

## 131.3 原理拆解

### 131.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举全部子序列 | `O(2ⁿ·n)` | `O(n)` | 15 行 | `n ≥ 25` 就废；只能对拍 |
| 递归 + 记忆化 `f(i,j)` | `O(n²)` | `O(n²)`+栈 | 20 行 | 栈深 `n = 1000` 时接近 1000 层，可行但不如递推稳 |
| **区间 DP（二维）** ✅ | **`O(n²)`** | **`O(n²)`** | **15 行** | `n = 10⁴` 时 `10⁸` 个 `int` = 400 MB（要压缩） |
| **区间 DP（一维压缩）** ✅ | `O(n²)` | **`O(n)`** | 18 行 | 无法回溯方案；下标映射需要小心 |
| **转成 `LCS(s, reverse(s))`** | `O(n²)` | `O(n²)` 或 `O(n)` | 20 行 | 只求长度时成立；**要输出具体串时不能直接用**（会得到反向 LCS 的映射，需要额外处理） |
| 记忆化 + 剪枝（只考虑首尾相同字符） | 平均更快 | `O(n²)` | 25 行 | 最坏仍是 `O(n²)`；实现复杂 |

**为什么选区间 DP**：`O(n²)` 时间、`O(n²)` 空间、15 行，转移的几何形状（左下角）一看就懂。**而「转 LCS」这条路极其漂亮**（`LPS(s) = LCS(s, reverse(s))`），值得作为第二个解法讲出来 —— 它能把这道题完全归约到 123 题。

**关于 `LCS(s, reverse(s))` 的严格说法**：设 `r = reverse(s)`。任何 `s` 的回文子序列 `P`，在 `r` 中同样作为子序列出现（因为 `P` 与其反向相同，而 `r` 中的子序列恰好是 `s` 中子序列的反向），所以 `LCS ≥ LPS`；反过来，任一公共子序列不一定是回文（例如 `s="abc", r="cba"`，LCS 可以取 `"a"`、`"b"`、`"c"`，都恰好是回文，但一般情形下公共子序列未必回文 —— 这条路的正确性需要更细的论证）。**因此工程上常用的是「LPS 长度 = LCS 长度」这个等式（有严格证明，但证明不平凡），面试里如果提它，最好补一句「等式成立但映射不直接给出回文串」。**

### 131.3.2 为什么这个做法是对的（正确性论证）

**命题**：`dp[i][j]` 等于 `s[i..j]` 内最长回文子序列的长度。

**（1）情形 1：`s[i] == s[j]` ⇒ `dp[i][j] = dp[i+1][j-1] + 2`。**

- **(≥)**：取 `s[i+1..j-1]` 内的一条最长回文子序列 `P`（长度 `L`），把 `s[i]` 与 `s[j]` 分别贴在两端，得到长度 `L+2` 的回文子序列（因为 `s[i] == s[j]`，对称性保持）。所以 `dp[i][j] ≥ L + 2`。
- **(≤)**：设 `Q` 是 `s[i..j]` 内的一条最长回文子序列。若 `Q` 同时用到了 `s[i]` 与 `s[j]`，则去掉两端得 `s[i+1..j-1]` 内的回文子序列，长度 `|Q| − 2 ≤ dp[i+1][j-1]`。若 `Q` 没有同时用到两端，则 `Q` 是以下三者之一：只含 `s[i+1..j]`、只含 `s[i..j-1]`、或含 `s[i]` 但不含 `s[j]`（此时 `Q` 也含于 `s[i..j-1]`）。**但我们可以做交换**：把 `Q` 的两端换成 `s[i]` 与 `s[j]`（它们相等且位于区间两端，替换不破坏回文性，也不缩短长度），于是存在一个「同时用到两端」的最优解，回到上一段。∎
- 因此 `dp[i][j] = dp[i+1][j-1] + 2`。

**（2）情形 2：`s[i] != s[j]` ⇒ `dp[i][j] = max(dp[i+1][j], dp[i][j-1])`。**

- **(≤)**：任一最优解 `Q` 不可能同时以 `s[i]` 和 `s[j]` 为两端（它们不相等）。于是 `Q` 必然「不用 `s[i]`」或「不用 `s[j]`」：前者 `Q ⊆ s[i+1..j]`，后者 `Q ⊆ s[i..j-1]`。所以 `|Q| ≤ max(dp[i+1][j], dp[i][j-1])`。
- **(≥)**：`s[i+1..j]` 与 `s[i..j-1]` 内的任何回文子序列都是 `s[i..j]` 内的回文子序列，所以 `max(...) ≤ dp[i][j]`。∎

**（3）归纳与边界**：`dp[i][i] = 1`（单字符）；长度为 2 时 `dp[i][i+1] = s[i]==s[i+1] ? 2 : 1`（公式里 `dp[i+1][j-1]` 落在空区间，取 0）。按区间长度递增归纳，全部正确。∎

> ⚠️ **注意情形 1 的「交换论证」为什么必需**：不能说「既然两端相等，最优解当然用它们」—— 必须证明**存在**一个最优解用到它们（否则 (≤) 方向只能得到 `≥`，无法夹逼）。这一步与 123 题 LCS 的引理 1 完全同构。**面试里被追问「为什么相等就一定用两端」时，答案是这个交换。**

### 131.3.3 通用解题思路（可迁移的那一层）

本题是 **「区间 DP」** 模型的第二个例子（第一个是 130 的布尔版）。区间 DP 有固定的四步：

```text
① 状态：dp[i][j] = 区间 s[i..j] 上的某个最优值
② 转移：永远从「区间两端」出发分类
     两端相等 → 用上两端 + 解决内部 dp[i+1][j-1]
     两端不等 → 舍弃一端：max/min( dp[i+1][j], dp[i][j-1] )
③ 初始化：长度 1（单点）与长度 2（或空区间）的答案
④ 遍历：按区间【长度】递增（因为依赖内部更短的区间）
```

| 题 | `dp[i][j]` 的含义 | 相等时 | 不等时 |
| --- | --- | --- | --- |
| [LC 516 LPS](https://leetcode.cn/problems/longest-palindromic-subsequence/)（本题） | 最长回文子序列长度 | `dp[i+1][j-1] + 2` | `max(上, 左)` |
| [LC 5 最长回文子串](https://leetcode.cn/problems/longest-palindromic-substring/) | 是否回文（布尔） | `len<=2 或 dp[i+1][j-1]` | `false` |
| [LC 647 回文子串计数](https://leetcode.cn/problems/palindromic-substrings/) | 是否回文 + 累加 | 同上 | `false` |
| [LC 312 戳气球](https://leetcode.cn/problems/burst-balloons/) | 戳破 `(i,j)` 之间所有气球的最大收益 | 枚举「最后一个被戳的 `k`」 | —（没有「相等」这个分支） |
| [LC 1039 多边形三角剖分的最低得分](https://leetcode.cn/problems/minimum-score-triangulation-of-polygon/) | 剖分 `(i,j)` 的最低分 | 枚举中间顶点 `k` | — |
| [LC 1547 切棍子的最小成本](https://leetcode.cn/problems/minimum-cost-to-cut-a-stick/) | 切完 `(i,j)` 段的最小成本 | 枚举切点 `k` | — |

> 🔑 **两类区间 DP**：①「两端配对型」（回文系列）—— 看两端；②「枚举分割点型」（戳气球、三角剖分）—— 枚举中间的 `k`。**前者是 `O(n²)`，后者是 `O(n³)`。** 识别方法是问一句「这个区间的最优解，是由『两端』决定的还是由『最后一个动作发生在哪』决定的？」

### 131.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要**输出**最长回文子序列 | 从长度变方案 | 保留全表，从 `(0, n-1)` 回溯：相等则两端各取一个并向内收，否则向较大的邻居走 |
| 空间压到 `O(n)` | 二维太大 | 用写法 ②（`i` 倒序）+ 一维数组 + 一个 `prevDiag` 暂存（见下） |
| 求**最少插入次数**使串变回文（LC 1312） | 从「长度」变「补几个」 | 答案 = `n − LPS`（因为保留最长回文子序列，其余字符各补一个镜像） |
| 求**最少删除次数**使串变回文 | 同上 | 也是 `n − LPS`（删掉不在回文子序列里的字符） |
| 允许**重排**字符构造最长回文 | 简化为计数 | `奇数频次的字符个数` 决定损失：答案 = `n − max(0, 奇数个数 − 1)`，`O(n)` |
| 统计**不同**回文子序列个数（LC 730） | 计数 + 去重 | 区间 DP 加「上次出现位置」去重，难度跳一档 |

**`O(n)` 空间压缩（Java，写法 ②：`i` 倒序 + `prevDiag` 暂存）**：

```java
class Solution1D {
    public int longestPalindromeSubseq(String s) {
        int n = s.length();
        if (n == 0) return 0;
        int[] dp = new int[n];          // dp[j] 在 i 固定时表示 dp[i][j]
        java.util.Arrays.fill(dp, 1);
        for (int i = n - 1; i >= 0; i--) {
            dp[i] = 1;
            int prevDiag = 0;           // 代表 dp[i+1][i] = 空区间 = 0
            for (int j = i + 1; j < n; j++) {
                int old = dp[j];        // 覆盖前先取走 dp[i+1][j]
                if (s.charAt(i) == s.charAt(j)) {
                    dp[j] = prevDiag + 2;               // dp[i+1][j-1] + 2
                } else {
                    dp[j] = Math.max(dp[j], dp[j - 1]); // max(dp[i+1][j], dp[i][j-1])
                }
                prevDiag = old;         // 下一列的「左上」就是这一列的「上」
            }
        }
        return dp[n - 1];
    }
}
```

| (2,4) | 3 | `b` == `b` | `dp[3][3] + 2` = 1+2 | **3** |
| (0,3) | 4 | `b` != `a` | `max(dp[1][3]=2, dp[0][2]=3)` | 3 |
| (1,4) | 4 | `b` == `b` | `dp[2][3] + 2` = 1+2 | **3** |
| (0,4) | 5 | `b` == `b` | `dp[1][3] + 2` = 2+2 | **4** |

### 131.4.2 依赖箭头 + 填表方向（本章最重要的一张图）

```text
      dp[i][j] 的三个依赖：

            dp[i+1][j-1]   dp[i+1][j]
                  ↖          ↑
                    ╲       │
                     ╲  ┌───────┐
        dp[i][j-1] ────→│ dp[i][j] │
                        └───────┘

  ⇒ 「上」「左上」都在【下一行】⇒ 必须先算更短的区间（更大的 i）
  ⇒ 正确顺序：【按 len 递增】（或 i 倒序）

填表顺序图（数字 = 计算次序）：
        j=0  1  2  3  4
   i=0   1  2  4  7 11
   i=1   .  1  3  6 10
   i=2   .  .  1  5  9
   i=3   .  .  .  1  8
   i=4   .  .  .  .  1

   ├─ len=1：①
   ├─ len=2：②③
   ├─ len=3：④⑤⑥
   ├─ len=4：⑦⑧⑨⑩
   └─ len=5：⑪  ← 右下角那个「斜向」推进的次序，就是「按长度递增」的几何含义

❌ 错误顺序（i 递增 + j 递增 = 按行扫）：
   i=0: 算 dp[0][1] 时要用 dp[1][0]（还没算 → 读到 0）
   i=0: 算 dp[0][2] 时要用 dp[1][1]（还没算 → 读到 0）
   … 整张表从上往下大面积读到 0，答案偏小
```

### 131.4.3 与「最长回文子串」（130）的对照

```text
                 s = "bbbab"
   ┌─────────────────────────────────────────────┐
   │ 130 子串（连续）      → "bbb" 长度 3          │
   │   靠「中心扩展」或 Manacher，O(n)/O(n²)      │
   ├─────────────────────────────────────────────┤
   │ 131 子序列（可跳过）  → "bbbb" 长度 4         │
   │   只能「区间 DP」，O(n²)/O(n²)               │
   └─────────────────────────────────────────────┘

   "bbbab" 里答案 4 的来源：下标 0,1,2,4 的四个 b
       b  b  b  a  b
       ↑  ↑  ↑     ↑
       └──┴──┴─────┘   跳过中间的 'a' ⇒ 这正是不连续带来的额外自由度，
                        也是中心扩展/Manacher 全部失效的原因
```

### 131.4.4 回溯出一条最长回文子序列

```text
从 (0,4) 出发：s[0]='b' == s[4]='b' ⇒ 取两端，跳到 (1,3)
 (1,3)：s[1]='b' != s[3]='a' ⇒ 比较 dp[2][3]=1 与 dp[1][2]=2，取较大的 dp[1][2] ⇒ 跳到 (1,2)
 (1,2)：s[1]='b' == s[2]='b' ⇒ 取两端，跳到 (2,1)（空区间，停）
 (1,2) 时两端都取 ⇒ 中间没有剩余

收集顺序：（左端）b、b … b、b（右端）  ⇒  "bbbb"，长度 4 ✅
```

## 131.5 双语言实现

### 131.5.1 Java

```java
class Solution {
    public int longestPalindromeSubseq(String s) {
        int n = s.length();
        if (n == 0) {
            return 0;                  // 防御性：题面 n >= 1
        }

        // dp[i][j] = s[i..j] 内最长回文子序列的长度
        // 只填 i <= j 的上三角；下三角保持 0（代表空区间）
        int[][] dp = new int[n][n];

        // len = 1：单字符是长度 1 的回文
        for (int i = 0; i < n; i++) {
            dp[i][i] = 1;
        }

        // 必须【按区间长度递增】：dp[i][j] 依赖 dp[i+1][j-1]（左下），
        // 那个格子在「i 递增 + j 递增」的顺序下还没算，会读到 0
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                if (s.charAt(i) == s.charAt(j)) {
                    // 两端相等 ⇒ 一定存在最优解用上两端（交换论证见正文）
                    // len == 2 时 dp[i+1][i] 是空区间 = 0，公式自然给出 2，不需要特判
                    dp[i][j] = dp[i + 1][j - 1] + 2;
                } else {
                    // 两端不等 ⇒ 至少舍弃一端，两种舍法取较优
                    dp[i][j] = Math.max(dp[i + 1][j], dp[i][j - 1]);
                }
            }
        }
        return dp[0][n - 1];
    }
}
```

### 131.5.2 Go

```go
package main

func longestPalindromeSubseq(s string) int {
	n := len(s)
	if n == 0 {
		return 0
	}

	// 与 Java 版同构：dp[i][j] = s[i..j] 内 LPS 长度
	// Go 的二维切片必须逐行 make；本题 n <= 1000，内存约 8 MB
	dp := make([][]int, n)
	for i := range dp {
		dp[i] = make([]int, n)
		dp[i][i] = 1 // len = 1 的初值顺手放在这里，省一次循环
	}

	for length := 2; length <= n; length++ { // 关键：按长度递增
		for i := 0; i+length-1 < n; i++ {
			j := i + length - 1
			if s[i] == s[j] {
				// 长度 2 时 i+1 > j-1，dp[i+1][j-1] 会越界！
				// 所以要判 length == 2（或用上三角之外的 0 兜底，但那会 panic）
				if length == 2 {
					dp[i][j] = 2
				} else {
					dp[i][j] = dp[i+1][j-1] + 2
				}
			} else {
				if dp[i+1][j] > dp[i][j-1] {
					dp[i][j] = dp[i+1][j]
				} else {
					dp[i][j] = dp[i][j-1]
				}
			}
		}
	}
	return dp[0][n-1]
}
```

### 131.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 越界行为 | `dp[i+1][j-1]` 在 `len == 2` 时是 `dp[i+1][i]`，**下标合法、值为 0**（同一行数组内的位置） | 同样是 `dp[i+1][i]`，但两个下标都在 `[0,n)` 内，**也合法**；只有 `i+1 == n` 时才 panic | 关键差别不在越界而在**语义**：`dp[i+1][i]` 是「下三角」的无效区间，必须保证它是 0（Java 默认 0，Go 也是 0）。**若换成 `int[2][n]` 的滚动写法，就必须显式处理 `len == 2`。** |
| 二维分配 | `new int[n][n]` 一次分配、内存连续 | 逐行 `make`，内存离散 | `n = 1000` 时 Go 版缓存局部性差一点（实测慢 10%~20%） |
| `max` | `Math.max` | 手写 `if` | 都只有两个候选，手写可接受 |
| 取字符 | `charAt` → `char` | `s[i]` → `byte` | 小写字母等价；中文必须 `[]rune`，且 `dp` 要按 rune 长度建 |
| 一维压缩 | 用 `prevDiag` 暂存 | 同，且可用多重赋值 | Go 的多重赋值让「取旧值」更安全（见 §131.3.4 思路） |

### 131.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举 s 的每个子序列（位掩码），如果是回文就更新答案
// 它把「子序列」的定义用到极致，与区间 DP 的结构毫无关系
func lpsBrute(s string) int {
	n := len(s)
	best := 0
	for mask := 0; mask < 1<<n; mask++ {
		sub := make([]byte, 0, n)
		for i := 0; i < n; i++ {
			if mask&(1<<i) != 0 {
				sub = append(sub, s[i])
			}
		}
		if len(sub) <= best {
			continue // 长度不够，省掉回文判定
		}
		ok := true
		for a, b := 0, len(sub)-1; a < b; a, b = a+1, b-1 {
			if sub[a] != sub[b] {
				ok = false
				break
			}
		}
		if ok {
			best = len(sub)
		}
	}
	return best
}

// 参考实现 2：记忆化递归 f(i,j)，与递推版的遍历序完全无关
// 它可以直接验证「按长度递增」这个顺序是否被我写对了
func lpsMemo(s string) int {
	n := len(s)
	memo := make([][]int, n)
	for i := range memo {
		memo[i] = make([]int, n)
		for j := range memo[i] {
			memo[i][j] = -1
		}
	}
	var f func(i, j int) int
	f = func(i, j int) int {
		if i > j {
			return 0
		}
		if i == j {
			return 1
		}
		if memo[i][j] != -1 {
			return memo[i][j]
		}
		var r int
		if s[i] == s[j] {
			r = f(i+1, j-1) + 2
		} else {
			a, b := f(i+1, j), f(i, j-1)
			if a > b {
				r = a
			} else {
				r = b
			}
		}
		memo[i][j] = r
		return r
	}
	return f(0, n-1)
}

func TestLongestPalindromeSubseq(t *testing.T) {
	edges := []string{"a", "ab", "aa", "aaaa", "bbbab", "cbbd", "abcabcabc",
		"aabaa", "abacdfgdcaba", "aba", ""}
	for _, s := range edges {
		want := lpsBrute(s)
		if got := longestPalindromeSubseq(s); got != want {
			t.Fatalf("edge %q got=%d want=%d", s, got, want)
		}
		if got := lpsMemo(s); got != want {
			t.Fatalf("memo edge %q got=%d want=%d", s, got, want)
		}
	}

	r := rand.New(rand.NewSource(516516))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(15) // 0..14，保证 2^n 可枚举
		b := make([]byte, n)
		for i := range b {
			// 只用 2 个字母：回文密度高，「两端相等」这条分支才会被高频打到
			b[i] = byte('a' + r.Intn(2))
		}
		s := string(b)
		want := lpsBrute(s)
		if got := longestPalindromeSubseq(s); got != want {
			t.Fatalf("iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
		if got := lpsMemo(s); got != want {
			t.Fatalf("memo iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
	}
}
```

> 📌 **三层对拍的价值**：`lpsBrute`（指数枚举）验证**语义**，`lpsMemo`（递归）验证**转移式**，递推版验证**遍历序**。三者同时通过，才能说明「按长度递增」这个顺序真的没问题 —— **只靠前两层是查不出遍历序错误的**（因为递归版没有遍历序这回事）。

## 131.6 复杂度与常见坑

### 131.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(n²)`**：只填上三角，共 `n(n+1)/2` 个区间，每格 `O(1)`（一次字符比较 + 至多一次加法或一次 max）。`n = 1000` 时约 `5·10⁵` 格，实测 Java 15 ms、Go 18 ms。
- **空间 `O(n²)`**：`n²` 个 `int`，`n = 1000` 时 4 MB。一维压缩后 `O(n)`（4 KB）。
- **为什么不能更快**：区间 DP 的下界是 `Ω(n²)`（要判断所有区间对），除非用特殊的字符串算法；LPS 有 `O(n²/log n)` 的位并行改进，但工程上无必要。
- **压缩后的常数**：一维版仍是 `n²/2` 次内层迭代，**时间不变**，只是空间从 `O(n²)` 变 `O(n)`。**再次强调：空间压缩从不改变时间复杂度。**

### 131.6.2 七个真实踩过的坑

1. **遍历序写成「`i` 递增 + `j` 递增」** —— 依赖的左下角还没算，答案偏小。**必须按长度递增，或 `i` 倒序。**
2. **`len == 2` 时去访问 `dp[i+1][i-1]`** —— 那是真正的越界（`j-1 < i`）。用 `dp[i+1][j-1]`（等于 `dp[i+1][i]`，还在数组内且为 0）或显式判 `len == 2`。
3. **`dp[i][i]` 忘了初始化成 1** —— 全表为 0，答案 0（`"a"` 会答 0）。
4. **把「子序列」当「子串」做** —— 用 130 的中心扩展，`"bbbab"` 答 3。
5. **把转移写成 `dp[i+1][j-1] + 1`** —— 那是 LCS 的 `+1`（一次吃一个字符）；LPS 一次吃**两个**字符，必须 `+2`。
6. **`s[i] == s[j]` 时也去取 `max(上, 左)`** —— 结果一般仍然对（因为 `dp[i+1][j-1]+2` 往往 ≥ 两者），但在某些输入上会偏小，而且会掩盖真 bug。
7. **一维压缩时忘了 `prevDiag`** —— `dp[j-1]` 已被本行覆盖，`dp[i+1][j-1]` 读成了 `dp[i][j-1]`，答案偏大。

### 131.6.3 面试官最爱追问的三个问题

**Q1：为什么必须按区间长度递增遍历？**

> 「因为 `dp[i][j]` 依赖 `dp[i+1][j-1]`、`dp[i+1][j]`、`dp[i][j-1]`，其中前两个都在**下一行**。如果按 `i` 从小到大、`j` 从小到大扫，读它们时还没算。按长度递增时，长度 `len` 的区间只依赖长度 `len-3` 和 `len-1` 的区间，全都已算好。等价写法是 `i` 从 `n-1` 递减、`j` 从 `i+1` 递增。」

**Q2：`s[i] == s[j]` 时为什么可以直接 `+2`，不需要和 `max` 比较？**

> 「因为存在一个最优解用上了这两个字符。交换论证：取任一条最长回文子序列，把它的两端换成 `s[i]` 与 `s[j]`（它们相等且位于区间两端），仍然是合法的回文子序列，长度不变。所以 `dp[i][j] = dp[i+1][j-1] + 2` 既是下界（构造）也是上界（任何最优解去掉两端后落在内部）。」

**Q3：这题和 LC 5 最长回文子串、LC 1312 最少插入次数有什么关系？**

> 「LC 5 要求连续，所以 `dp` 是布尔型（`s[i]==s[j] && dp[i+1][j-1]`），并且可以用中心扩展或 Manacher 做到 `O(n)`/`O(n²)` 且空间 `O(1)`。LC 516 允许跳过，布尔型不够（要数长度），只能 `int` 型区间 DP。LC 1312 最少插入次数使串变回文，答案就是 `n − LPS`：保留最长回文子序列，其余字符各自补一个镜像。同理 LC 583 的『最少删除使两串相等』是 `m+n−2·LCS`，都是同一套『保留最优子结构、剩下的补/删』的思路。」
