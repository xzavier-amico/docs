## 041.1 题目

**原题链接**：<https://leetcode.cn/problems/majority-element/>

### 题意重述（把隐含条件补齐）

给你一个长度为 `n` 的数组 `nums`，返回其中的**多数元素**。多数元素的定义是：**出现次数严格大于 `⌊n/2⌋`** 的元素。题目保证多数元素一定存在，你可以假设数组非空。

这句话背后有五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 出现次数 **> ⌊n/2⌋**，不是 `≥` | 「出现次数大于 `⌊ n/2 ⌋`」 | `[1,2]` 里没有多数元素。若按 `≥` 判，`[1,2]` 会误判 1 或 2 为答案 |
| **一定存在**多数元素 | 「你可以假设数组总是存在多数元素」 | 这一条**允许你省掉最后一次校验**；一旦题目没这句话（比如 042），不校验就错 |
| 答案可以是**任意整数** | `-10^9 <= nums[i] <= 10^9` | 不能拿值当下标做计数数组（值域 20 亿） |
| `n` 最多 `5·10^4` | 约束表 | `O(n²)` 是 `2.5·10^9`，必超时；`O(n log n)` 排序能过 |
| 「进阶」要求 **`O(1)` 空间** | 「尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法」 | 哈希计数 `O(n)` 空间不达标；这才逼出了摩尔投票 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 5·10^4` | n 最多五万 | `O(n)` 与 `O(n log n)` 都轻松过；`O(n²) = 2.5·10^9` 不行 |
| `-10^9 <= nums[i] <= 10^9` | 值域 20 亿 | 计数数组不可行；哈希或排序 |
| 多数元素一定存在 | 保证 | 只需「找到」，不需「验证」；省一次 `O(n)` 扫描 |
| 进阶要求 `O(1)` 空间 | 官方提示 | 摩尔投票；或「排序取中位数」（空间取决于能否原地排序） |

> 💡 **量级 → 算法**：`n = 5·10^4` 说明这题**不是靠时间卡人**，而是靠「`O(1)` 空间」这一句卡人。
> 换句话说：凡是能用 `O(n)` 空间做的题，面试官加一句「空间压到 O(1)」，考的就是你对**结构**的理解深度。

### 示例

```
输入：nums = [3,2,3]
输出：3

输入：nums = [2,2,1,1,1,2,2]
输出：2
解释：2 出现 4 次，4 > 7/2 = 3.5 ✓

输入：nums = [1]
输出：1
解释：n = 1，1 出现 1 次 > 0 ✓
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① [1]                    → 1。n = 1 时任何元素都是多数元素（1 > 0）
② [1,1]                  → 1。n = 2 时阈值是 1，出现 2 次才叫多数
③ [1,2,2]                → 2。投票过程中 cand 会先变成 1 再变成 2，考验"count 归零后覆盖"
④ [2,2,1,1,1,2,2]        → 2。count 中途归零两次，最终仍应得 2
⑤ [1,2,3,1,1]            → 1。前三个互不相同，count 会反复归零
⑥ [1,1,1,2,2,3]          → 1。多数派出现的次数刚好过半（3 > 3 为假？）
                            注意：3 > 6/2 = 3 为假，所以这不是合法输入 —— 说明"严格大于"的重要性
```

第 ⑥ 条是本题最值得记住的边界：**`count == n/2` 不算多数派**。`[1,1,1,2,2,3]` 里 1 出现 3 次、`n/2 = 3`，不满足「严格大于」，所以这样的输入不合法（题目保证有解）。但如果你自己造测试数据时按 `≥` 生成，就会造出无解的输入，然后误以为算法错了。

## 041.2 从暴力到最优：第一个念头为什么错

### 第一步：四个「第一念头」

```java
// 念头 A：哈希计数，最后挑最大
Map<Integer, Integer> cnt = new HashMap<>();
for (int x : nums) cnt.merge(x, 1, Integer::sum);
for (Map.Entry<Integer, Integer> e : cnt.entrySet())
    if (e.getValue() > nums.length / 2) return e.getKey();
// 时间 O(n)，空间 O(n)

// 念头 B：排序后取中位数
Arrays.sort(nums);
return nums[nums.length / 2];
// 时间 O(n log n)，空间 O(1)~O(log n)

// 念头 C：双重循环，对每个值再数一遍
for (int x : nums) { int c = 0; for (int y : nums) if (y == x) c++; if (c > n/2) return x; }
// 时间 O(n²)，必超时

// 念头 D：分治 —— 左半的多数派或右半的多数派，必有一个是整体多数派
// 时间 O(n log n)，递归栈 O(log n)
```

| 念头 | 时间 | 额外空间 | 问题 |
| --- | --- | --- | --- |
| A 哈希 | `O(n)` | `O(n)` | 空间不满足「进阶」要求 |
| B 排序 | `O(n log n)` | `O(1)`（原地）~ `O(log n)` | 时间不最优；且改动了输入 |
| C 双循环 | `O(n²)` | `O(1)` | 超时 |
| D 分治 | `O(n log n)` | `O(log n)` | 空间不是常数；代码 20 行 |

### 第二步：卡点在哪 —— 「计数」这件事看起来必须有张表

```
     ┌──────────────────────────────────────────────────────────┐
     │ 任务：找出出现次数 > n/2 的值                             │
     │ 直觉：得给每个不同的值记一个计数 → 需要 O(不同值个数) 空间 │
     │ 约束：O(1) 空间                                          │
     │                                                         │
     │ 于是必须放弃"给每个值计数"，改为"只维护极少数几个变量"    │
     └──────────────────────────────────────────────────────────┘
```

**关键的问题转化**：不要问「每个值出现几次」，改问「**有没有一个值，能把所有其它值『抵掉』之后还剩**」。

### 第三步：灵感的来源 —— 两两抵消

想象把数组里的元素两两配对，**只要两个数不同就互相抵消（都扔掉）**。反复抵消到不能再抵消为止。

```
nums = [2,2,1,1,1,2,2]

  2  2  1  1  1  2  2
  └──┘        │  │  │
   同值，保留  │  │  │
         └────┘  │  │     2 与 1 抵消
               └─┘  │     1 与 2 抵消
                    │
                  剩 2      ← 抵消不下去了，剩下的就是多数派
```

为什么剩下的必然是多数派？因为：

```
多数派出现 c 次，c > n/2
其它所有元素加起来最多 n - c 个，而 n - c < n/2 < c
      ↓
每次抵消最多消掉 1 个多数派（配对的另一个必须与它不同）
      ↓
用 n - c 个"其它元素"最多能消掉 n - c 个多数派
      ↓
c - (n - c) = 2c - n > 0   →   必定还有多数派元素剩下
```

**这就是摩尔投票的全部直觉**：多数派的数量比所有对手加起来还多，所以「一对一互换」它永远不会被换光。

### 第四步：把「抵消」写成 O(1) 空间

真实实现不能真的去配对（那要记录配对关系）。但注意一件事：**抵消过程中剩下的元素永远全都是同一个值**（因为你只在「不同」时才抵消，一旦抵消完，栈里剩下的要么空、要么全等）。

所以只需要两个变量：

```
candidate = 当前"栈里"的值
count     = 栈里该值的个数
```

扫描每个 `x`：

```
if count == 0:  candidate = x; count = 1     # 栈空，x 进栈
elif x == candidate:  count += 1             # 同值，进栈
else:  count -= 1                            # 异值，与栈顶抵消
```

```
用"栈"理解（栈里永远只有一种值，所以只需要 candidate + count 两个变量）：

  读 2 → [2]            candidate=2, count=1
  读 2 → [2,2]          candidate=2, count=2
  读 1 → [2]            candidate=2, count=1   （2 与 1 抵消一对）
  读 1 → []             candidate=2, count=0   （再抵消一对）
  读 1 → [1]            candidate=1, count=1   （栈空，1 进栈）
  读 2 → []             candidate=1, count=0   （1 与 2 抵消）
  读 2 → [2]            candidate=2, count=1   ← 最终候选者 = 2 ✓
```

> **注意一个反直觉的点**：`count` 最终是 1，不是 4。`count` **不是**多数派的出现次数，它只是「抵消后栈的大小」。
> 想知道真实次数，必须再扫一遍数一次 —— 本题因为「保证存在」可以省，但生产代码不该省。

## 041.3 原理拆解

### 041.3.1 数据结构与算法选型

| 方案 | 时间 | 额外空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 双重循环数每个值 | `O(n²)` | `O(1)` | 6 行 | n ≥ 10⁴ 就超时 |
| 哈希计数 | `O(n)` | `O(n)` | 8 行 | 空间不达标；值域极大时内存吃紧 |
| 排序取中位数 | `O(n log n)` | `O(1)`~`O(log n)` | 3 行 | 时间不最优；改输入；**「中位数」这个技巧只在「> n/2」时成立** |
| 分治 | `O(n log n)` | `O(log n)` | 20 行 | 递归栈；常数大；但**最容易推广到「区间众数」查询** |
| **摩尔投票** ✅ | **`O(n)`** | **`O(1)`** | **8 行** | 只在「存在多数派」时直接可用；否则必须二次校验 |
| 随机抽样 + 校验 | 期望 `O(n)` | `O(1)` | 10 行 | 随机性；最坏 `O(∞)`；但在「多数派占比高」时期望 2 次就中 |
| 按位统计 | `O(32n)` | `O(1)` | 12 行 | 常数 32；需要「多数派的每个 bit 也是多数」这个前提（成立） |

**为什么「排序取中位数」是对的？**

排序后，多数派的所有副本在数组里是**连续的一段** `[k, k+c-1]`（`c > n/2`）。要证明下标 `⌊n/2⌋` 落在这段里：

- `k ≤ ⌊n/2⌋`：若 `k > ⌊n/2⌋`，则 `k + c - 1 ≤ n - 1` 给出 `c ≤ n - k < n/2`，与 `c > n/2` 矛盾。
- `k + c - 1 ≥ ⌊n/2⌋`：`n` 为偶数时 `c ≥ n/2 + 1`，故 `k + c - 1 ≥ c - 1 ≥ n/2`；`n` 为奇数时 `c ≥ (n+1)/2`，故 `k + c - 1 ≥ (n-1)/2 = ⌊n/2⌋`。

所以 `nums[⌊n/2⌋]` 一定落在那段连续区间内，即多数派。∎

> **这个证明值得读两遍**：它说明「中位数 = 多数派」不是巧合，而是「多数派超过一半」的**直接推论**。
> 但它也暴露了局限：一旦阈值从 `n/2` 变成 `n/3`，中位数就不一定是「出现最多的那个」了。**摩尔投票可以推广（见 042），取中位数不能。**

### 041.3.2 为什么这个做法是对的（正确性论证）

设多数派为 `m`，出现 `c` 次，`c > ⌊n/2⌋`。

**不变量（抵消模型）**：处理完前 `i` 个元素后，若当前 `count = t > 0`，则可以把这 `i` 个元素分成：

- `(i - t)/2` 对「值互不相同」的元素（已抵消），
- 以及 `t` 个值全部等于 `candidate` 的元素（栈里的残留）。

*归纳证明*：

- `i = 0`：`t = 0`，两边都是空集，成立。
- 读入 `x`：
  - `t = 0`：设 `candidate = x, t = 1`。前 `i` 个元素已被完全配成 `i/2` 对（由归纳假设，`t=0` 时 `i` 为偶数），加上新的 `x` 作为 1 个残留 → 成立。
  - `x == candidate`：`t+1`，残留集合加上 `x`（也是 `candidate`）→ 成立。
  - `x != candidate`：把 `x` 与一个残留的 `candidate` 配成一对（两者不同）→ 对数 +1，残留 −1，`t-1` → 成立。∎

**定理**：扫描结束后，若 `t > 0`，则 `candidate` 就是多数派 `m`。

*证明*：由不变量，全部 `n` 个元素被分成 `(n - t)/2` 对互不相同的元素，加上 `t` 个 `candidate`。

1. **每一对里最多有 1 个 `m`**（因为对里两个值不同）。所以 `m` 的总数 `c ≤ (n - t)/2 + [t 个残留里等于 m 的个数]`。
2. 若 `candidate ≠ m`，则残留里没有 `m`，于是 `c ≤ (n - t)/2 ≤ n/2`，与 `c > ⌊n/2⌋` 矛盾。**故 `candidate = m`。**
3. 顺带得到 `t > 0`：把 `candidate = m` 代回第 1 条，`c ≤ (n - t)/2 + t = (n + t)/2`，即 `t ≥ 2c - n > 0`。∎

> **这个证明同时回答了两个问题**：
> ①「为什么候选者**一定存在**」—— 因为 `t ≥ 2c - n > 0`，`count` 不可能归零收场；
> ②「为什么候选者**一定是多数派**」—— 如果候选者不是多数派，多数派的总数就被 `n/2` 卡住了，矛盾。
>
> 面试里能把这两句说清楚，比背下三行代码有价值得多。

**推论（为什么本题可以不校验）**：题目保证多数派存在，而定理说「若多数派存在，则候选者就是它」。所以候选者必然正确，不需要第二遍扫描。

**反推论（为什么 042 必须校验）**：若「多数派」不保证存在（例如求「出现 > n/3 的所有元素」），候选者可能是个**恰好活到最后的普通元素**。此时必须先假设、后验证。

### 041.3.3 通用解题思路（可迁移的那一层）

本题是 **「用抵消 / 配对消除候选者，把 O(不同值) 的空间压成 O(1)」** 这个模型的母题：

```
原始问题：找出出现次数超过 n/k 的元素
         ↓ 关键观察：这类元素最多只有 k-1 个（否则总和 > n）
         ↓ 更进一步：它的数量超过"所有对手之和"
建模：   把"计数"换成"抵消"——不同值两两配对消掉
         ↓ 抵消到最后，剩下的残留必然是那个"数量超过对手之和"的值
         ↓ 每个候选只需 1 个计数器 → 空间 O(k)
代价：   只给出"候选"，不给出"次数"；不保证存在时必须二次校验
```

**这套技巧的三条可迁移经验**：

| 经验 | 说法 | 其他场景 |
| --- | --- | --- |
| **阈值决定候选个数** | 「出现 > n/k」最多有 `k-1` 个候选 | 042（`k=3`，2 个候选）、求「出现 > n/4」用 3 个候选 |
| **抵消代替计数** | 不同就互相消耗，相同就累加 | 括号匹配的抵消、LC 921 使括号有效的最少添加、字符串消除相邻相同字符 |
| **必须能二次校验** | 候选 ≠ 答案，除非题目保证 | 042、流式场景的「重元素」查询（Misra-Gries 算法） |

归属同一模型的题：

| 题 | 阈值 | 候选数 | 关键差异 |
| --- | --- | --- | --- |
| [LC 169 多数元素](https://leetcode.cn/problems/majority-element/) | `> n/2` | 1 | 保证存在，无需校验 |
| [LC 229 多数元素 II](https://leetcode.cn/problems/majority-element-ii/) | `> n/3` | 2 | **不保证存在 → 必须校验**（见 `042`） |
| [LC 961 在长度 2N 的数组中找出重复 N 次的元素](https://leetcode.cn/problems/n-repeated-element-in-size-2n-array/) | `= n` | — | 随机抽样即可，期望 `O(1)` 次 |
| [LC 1157 子数组中占绝大多数的元素](https://leetcode.cn/problems/online-majority-element-in-subarray/) | 区间内 `> 50%` | — | 线段树 + 摩尔投票合并（把 `(cand, count)` 当可合并的信息） |
| [LC 1287 有序数组中出现次数超过 25% 的元素](https://leetcode.cn/problems/element-appearing-more-than-25-in-sorted-array/) | `> n/4` | — | 数组有序 → 只需检查 `nums[i] == nums[i + n/4]` |
| [LC 2780 合法分割的最小下标](https://leetcode.cn/problems/minimum-index-of-a-valid-split/) | 两侧都是多数派 | 1 | 先求全局多数派，再从左往右扫 |
| [LC 921 使括号有效的最少添加](https://leetcode.cn/problems/minimum-add-to-make-parentheses-valid/) | — | — | 抵消思想：「未匹配的右括号」与「未匹配的左括号」互相抵消 |

### 041.3.4 可扩展性（面试追问的方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 求出现 **`> n/3`** 的**所有**元素 | 候选数变 2 | 两个候选 + 两个计数器，规则变成「先比候选、再清零位」；**结尾必须校验**（见 `042`） |
| 求出现 `> n/k` 的所有元素 | 候选数 `k-1` | Misra-Gries：`k-1` 个槽位，满了就全体 −1；时间 `O(nk)`、空间 `O(k)`；同样要校验 |
| 要求**同时返回出现次数** | 多一个输出 | 投票完再扫一遍数 `candidate` 的次数，`O(n)` / `O(1)` |
| **数据流**输入（不能回看） | 只能一遍 | 摩尔投票天然是流式算法：`O(1)` 空间、单遍；但它只能给候选，流式场景下无法二次校验，只能用「重元素」的近似算法（Misra-Gries / Space-Saving） |
| **不保证**多数派存在 | 候选可能错 | 必须在结尾加一次 `O(n)` 计数校验；返回 `-1` 或报错 |
| 改成**区间查询**（多次询问某区间内的多数派） | 需要可合并结构 | 把 `(candidate, count)` 定义成可合并的半群，用线段树维护；`O(log n)` 每次查询 |
| **多线程 / 分布式**归并 | 各分片各投票 | 合并两个 `(cand, count)`：同 `cand` 则相加，不同则大减小、`cand` 取大的那个 —— 这是「抵消」的结合律体现 |

## 041.4 图解推演

### 041.4.1 投票轨迹（`[2,2,1,1,1,2,2]`）

| 轮次 | 读入 `x` | 进这一轮前 `count` | 分支 | `candidate` | `count` | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 2 | 0 | 栈空 → 进栈 | 2 | 1 | `candidate = 2` |
| 1 | 2 | 1 | 同值 → 累加 | 2 | 2 | 栈里有 2 个 2 |
| 2 | 1 | 2 | 异值 → 抵消 | 2 | 1 | 消掉一个 2 和一个 1 |
| 3 | 1 | 1 | 异值 → 抵消 | 2 | 0 | 栈空，但 `candidate` 仍是 2（下一轮会被覆盖） |
| 4 | 1 | 0 | 栈空 → 进栈 | 1 | 1 | `candidate` 换成 1 |
| 5 | 2 | 1 | 异值 → 抵消 | 1 | 0 | 又空 |
| 6 | 2 | 0 | 栈空 → 进栈 | 2 | 1 | `candidate` 回到 2 |
| 结束 | — | — | — | **2** | 1 | 返回 2 ✅（2 实际出现 4 次，`count` 只是残留数） |

### 041.4.2 抵消的对账（为什么多数派消不完）

```
多数派 m = 2，c = 4；其它元素总数 = 3

  2  2  1  1  1  2  2
  │  │  │  │  │  │  │
  └──┼──┘  │  │  └──┘
     │     │  │
     └─────┴──┘
       每次抵消都消耗 1 个"非 2" + 1 个"2"

  最多能抵消 min(c, n-c) = min(4, 3) = 3 对
  → 3 个非多数派全被消耗光，多数派还剩 4 - 3 = 1 个
  → 剩下的一定是多数派
```

```
一般情形的不等式：

   c        > n/2          （多数派的定义）
   c - (n-c) = 2c - n  > 0  （抵消后剩余 ≥ 2c-n 个多数派）
   
   ┌───────────────────────────────────────────────┐
   │ 2c - n 就是"消不掉的那部分"，它恒 > 0          │
   │ 所以 count 永远不会"把多数派清零后还继续"      │
   └───────────────────────────────────────────────┘
```

### 041.4.3 三种解法的路线对比

```
                ┌─────────── 输入：长度 n，多数派占比 > 1/2 ───────────┐
                │                                                      │
   ┌────────────▼─────────────┐   ┌──────────────▼──────────┐   ┌──────▼──────────────┐
   │ 哈希计数 O(n)/O(n)       │   │ 排序取中位 O(n log n)/O(1)│   │ 摩尔投票 O(n)/O(1)  │
   └────────────┬─────────────┘   └──────────────┬──────────┘   └──────┬──────────────┘
                │                                 │                     │
   给每个值记一个数                    排序后多数派是连续一段          两两抵消，剩者为王
                │                                 │                     │
   ✅ 最简单、可复用                   ✅ 三行、常数小                 ✅ 一遍、O(1)、可流式
```

## 041.5 双语言实现

### 041.5.1 Java

```java
class Solution {
    public int majorityElement(int[] nums) {
        // candidate = 当前"栈里"的那个值；count = 栈里它的个数
        // 不变量：count == 0 时，已处理的前缀可以被完整地两两抵消；
        //         count > 0 时，前缀 = (i-count)/2 对"互不相同"的元素 + count 个 candidate
        int candidate = nums[0];
        int count = 0;

        for (int x : nums) {
            if (count == 0) {
                candidate = x;   // 栈空：谁进来谁就是候选者
                count = 1;
            } else if (x == candidate) {
                count++;         // 同值：进栈
            } else {
                count--;         // 异值：与栈顶抵消一对
            }
        }

        // 题目保证多数元素存在，由"抵消不变量"可证 candidate 必为多数元素，
        // 所以这里不需要再扫一遍数次数。
        // 生产代码里若不确定"保证存在"，一定要补：int c = 0; for (int x : nums) if (x == candidate) c++; 
        // 然后校验 c > nums.length / 2。
        return candidate;
    }
}
```

### 041.5.2 Go

```go
package main

func majorityElement(nums []int) int {
	// 与 Java 完全相同的三个分支
	candidate := nums[0]
	count := 0

	for _, x := range nums {
		switch {
		case count == 0:
			candidate = x
			count = 1
		case x == candidate:
			count++
		default:
			count--
		}
	}
	return candidate
}
```

### 041.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 分支写法 | `if / else if / else` | `switch { case ... }`（无表达式 switch） | Go 的 `switch` 从上往下命中第一个真分支，语义与 `if-else` 链一致，可读性更好 |
| `candidate` 初值 | `nums[0]` | `nums[0]` | 两语言都要求非空数组；`count = 0` 保证第一轮会被覆盖，所以初值其实无关紧要，但**写 `nums[0]` 能避免「0 是合法值」的混淆** |
| 空数组 | 会抛 `ArrayIndexOutOfBounds` | 会 `panic` | 题目保证 `n ≥ 1`；若要健壮，两语言都得先判空 |
| 遍历方式 | 增强 `for` | `for _, x := range nums` | Go 的 `range` 对切片复制值，性能一致 |
| 空间 | 两个局部变量 | 两个局部变量 | 都是 `O(1)`；编译器可能把两者都放进寄存器 |

### 041.5.4 对拍测试（裁判：排序取中位数）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 裁判：排序后取中位数。
// 选择它的理由：实现只有 3 行、与摩尔投票的思路完全不同（一个靠"位置"、一个靠"抵消"），
// 错误不会同源 —— 这正是对拍裁判该有的独立性。
func bruteMedian(nums []int) int {
	a := append([]int(nil), nums...)
	sort.Ints(a)
	return a[len(a)/2]
}

// 校验候选者是否真是多数派（用于反向测试：证明"不校验会错"）
func countOf(nums []int, v int) int {
	c := 0
	for _, x := range nums {
		if x == v {
			c++
		}
	}
	return c
}

func TestMajorityElementRandom(t *testing.T) {
	r := rand.New(rand.NewSource(169))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(20)
		// 先造一个"保证有多数派"的数组：多数派占 n/2+1 个位置，其余随机填
		majority := r.Intn(7) - 3 // 值域 -3..3，故意包含 0 和负数
		cnt := n/2 + 1
		nums := make([]int, 0, n)
		for i := 0; i < cnt; i++ {
			nums = append(nums, majority)
		}
		for len(nums) < n {
			// 其余位置从"非多数派"里随机取，且保证最终多数派仍然过半
			v := r.Intn(7) - 3
			if v == majority {
				continue
			}
			nums = append(nums, v)
		}
		r.Shuffle(len(nums), func(i, j int) { nums[i], nums[j] = nums[j], nums[i] })

		got := majorityElement(nums)
		want := bruteMedian(nums)
		if got != want {
			t.Fatalf("iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
	}
}

func TestMajorityElementEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{[]int{1}, 1},
		{[]int{1, 1}, 1},
		{[]int{1, 2, 2}, 2},
		{[]int{3, 2, 3}, 3},
		{[]int{2, 2, 1, 1, 1, 2, 2}, 2},
		{[]int{1, 2, 3, 1, 1}, 1},
		{[]int{-1, -1, 2}, -1},
		{[]int{0, 0, 1}, 0},
	}
	for _, c := range cases {
		got := majorityElement(c.nums)
		if got != c.want {
			t.Fatalf("nums=%v got=%d want=%d", c.nums, got, c.want)
		}
	}
}

// 反向测试：故意喂"没有多数派"的输入，验证"不校验就会返回垃圾"。
// 这条测试的意义不是让解法通过，而是把"校验的必要性"钉成可执行的事实。
func TestMajorityElementNeedsVerify(t *testing.T) {
	nums := []int{1, 2, 3, 4} // 没有多数派：每个值各出现 1 次，1 > 2 不成立
	cand := majorityElement(nums)
	if countOf(nums, cand)*2 > len(nums) {
		t.Fatalf("在无多数派的输入上居然得到了合法多数派，说明测试数据不对：%v cand=%d", nums, cand)
	}
	// 正确做法：cand 只是"候选"，必须 countOf(nums, cand) > n/2 才能当真
}
```

实测：2 万组随机（多数派位置随机打乱、值域含 0 与负数）+ 8 个边界用例全部通过；第三个测试确认「无多数派时投票会给出错误候选」，从而把「必须校验」这件事变成可执行的事实。

> **为什么裁判用「排序取中位数」而不是哈希**：哈希和投票都是「线性扫描 + 计数」，而中位数裁判用的是**排序后的位置**，论证依据（§041.3.1 的区间包含证明）与抵消完全不同。**裁判与被测实现越不相关，对拍越可信。**

## 041.6 复杂度与常见坑

### 041.6.1 复杂度推导

- **时间 `O(n)`**：一次遍历，每轮做常数次比较与加减。没有均摊、没有嵌套，最坏就是 `n` 轮。
- **额外空间 `O(1)`**：`candidate`、`count` 两个局部变量。
- 对比：哈希解 `O(n)` 空间（`n = 5·10^4` 时 Java 约 2~3 MB），排序解 `O(n log n)` 时间 + `O(log n)` 栈。

### 041.6.2 七个真实踩过的坑

1. **`count == 0` 时忘记更新 `candidate`** —— 只把 `count` 置 1，候选者还是旧值，结果随输入顺序漂移。`[1,2,2]` 会返回 1。
2. **以为返回值是「出现次数」** —— `count` 是抵消后的残留量，不是频次。想知道频次必须二次扫描。
3. **在「不保证存在」的题里直接返回候选者** —— 这是 042 的经典错误：`[1,1,2,2,3,3]` 求 `> n/3` 时会返回某个候选（比如 3），但它并不是答案。
4. **阈值写成 `≥ n/2`** —— `[1,1,2,2]` 里 1 出现 2 次，`2 ≥ 2` 为真，但题目要求**严格大于**，这样的输入不合法。写校验时必须是 `c * 2 > n`。
5. **用「排序取中位数」却复制了数组** —— `int[] copy = nums.clone(); Arrays.sort(copy);` 看似保护输入，但空间从 `O(1)` 变成 `O(n)`，不再满足「进阶」要求。
6. **把投票用于「求出现最多的元素」** —— 摩尔投票求的是「**超过一半**的元素」，不是「出现次数最多的元素」。`[1,1,2,2,3]` 里没有超过一半的元素，投票返回的 3 毫无意义。
7. **`count` 用 `int` 但在超大流上累加** —— 本题不必担心；但若把投票用于「长度 10⁹ 的流」，`count` 可能接近 10⁹，Java 的 `int` 上限 2.1·10⁹ 刚好够，再大就要 `long`。

### 041.6.3 面试官最爱追问的三个问题

**Q1：为什么抵消到最后，剩下的那个一定是多数派？**

> 「因为多数派的个数超过所有其它元素之和。设多数派出现 `c` 次，`c > n/2`，其它元素总共 `n-c` 个且 `n-c < c`。每次抵消最多消掉 1 个多数派（配对的另一个值必须不同），所以 `n-c` 个对手最多消掉 `n-c` 个多数派，之后还剩 `c-(n-c) = 2c-n > 0` 个。形式化地，扫描结束时有 `(n-t)/2` 对互不相同的元素和 `t` 个等于 `candidate` 的残留。如果 `candidate` 不是多数派，多数派的总数就 ≤ `(n-t)/2 ≤ n/2`，与 `c > n/2` 矛盾。」

**Q2：如果数组里没有多数元素，你的算法会返回什么？**

> 「会返回一个『活到最后的普通元素』，它可能只出现一次。比如 `[1,2,3,4]` 最终 `candidate = 4`，`count = 1`。所以『保证存在』这个前提是省掉校验的许可证；一旦没有这个保证（比如 229 求 `> n/3`），就必须再扫一遍统计候选者的真实次数并校验。我在测试里专门写了一条『无多数派』的用例，把这件事钉成可执行的事实。」

**Q3：能不能推广到「出现次数 > n/3 的所有元素」？**

> 「能，这就是 042。核心是两条：① 阈值 `n/k` 决定候选个数最多 `k-1` 个（否则它们的总次数会超过 n）；② 抵消规则从『1 个候选 + 1 个计数器』变成『`k-1` 个候选 + `k-1` 个计数器』：新元素先看是否等于某个候选（对应计数器 +1），否则看有没有计数为 0 的槽位（占位），再否则把所有计数器 −1（相当于一次消掉 `k` 个互不相同的元素）。最后必须逐个校验。空间 `O(k)`，时间 `O(nk)`。」
