## 090.1 题目

**原题链接**：<https://leetcode.cn/problems/redundant-connection/>

### 题意重述（把隐含条件补齐）

树可以看成是一个**连通**且**无环**的**无向**图。现在给你一棵有 `n` 个节点的树，再给它加上**一条额外的边**，得到一个「`n` 个节点、`n` 条边」的图。请找出那条可以被删掉的边：删掉它之后，剩下的图恰好是一棵有 `n` 个节点的树。如果有多条边都满足，返回**输入中最后出现**的那一条（也就是 `edges` 里下标最大的那条）。

题干只有四行，但它藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **图本身就是「树 + 1 条边」** | 「给你一棵树，加一条边」 | 所以图里**恰好只有一个环**，不用考虑「多个环怎么办」 |
| **边是无向的** | 「无向图」 | `(1,2)` 与 `(2,1)` 等价；并查集 `union(a,b)` 天然对称，别写成有向边 |
| **必须删掉一条边后仍是树** | 「剩下的图是一棵树」 | 删掉非环上的边会让图变成森林，不连通 |
| **多解时返回输入中最后出现的那条** | 「如果有多个答案，返回最后出现的」 | 这是本题的唯一「坑面」：不能返回「任意一条环上的边」 |
| **原题保证没有重复边、没有自环** | 约束「`1 <= ai < bi <= n`」 | 严格不等号直接排除了自环与重边。但本章的对拍测试会**故意**造自环与重边——那是「约束放松后你的代码还活不活」的健壮性检查 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n == edges.length` | 等于边数，即点数 | 树的边数是 `n-1`，这里恰好 `n`，**多的那一条**就是冗余边 |
| `3 <= n <= 1000` | 最多 1 千个点 | `O(n²)` = `10⁶` 次操作，本机能过；`O(n·α(n))` 是「顺手就拿下」的写法 |
| `1 <= ai < bi <= n` | 严格小于 | 无自环、无重边；节点编号从 **1** 开始（数组要开 `n+1`） |
| 图连通 | 「是一棵树加一条边」 | 不用考虑孤立点，也不用判 `-1` |

> 💡 **量级 → 算法**：`n ≤ 10³` 时 `O(n²)` 也能过，这意味着本题**不靠时间复杂度区分人**，它靠的是「你有没有识别出这是**增量连通性**问题」。同一套模型换成 `n ≤ 10⁵`（例如 [LC 1319 连通网络的操作次数](https://leetcode.cn/problems/number-of-operations-to-make-network-connected/)）时，`O(n²)` 立刻死，而并查集依旧 `O(n·α(n))`。

### 示例

```
输入：edges = [[1,2], [1,3], [2,3]]
输出：[2,3]
解释：加入前两条边后 1-2、1-3 已经连通，第 3 条边 2-3 的两端
      本来就有路（2→1→3），所以它闭合了唯一那个环。

输入：edges = [[1,2], [2,3], [3,4], [1,4], [1,5]]
输出：[1,4]
解释：环是 1-2-3-4-1，环上的 4 条边都能删（删任意一条仍是树），
      其中输入顺序最靠后的是第 4 条 [1,4]。

输入：edges = [[1,2], [2,3], [1,5], [3,4], [1,3]]
输出：[1,3]    ← 注意：环是 1-2-3-1，但答案是最后出现的 [1,3]
```

### 我自造的四个边界（写完代码必须拿它们打一遍）

```text
① [[1,2],[1,3],[2,3]]            最小三元环：答案只能是最一条 [2,3]
② [[1,2],[1,2]]                 重边（约束放松版）：第二条就是答案
③ [[1,1]]                       自环（约束放松版）：单点图，答案 [1,1]
④ [[1,2],[2,3],[3,1],[3,4]]     先闭环再来尾巴：答案 [3,1]，不能是 [3,4]
```

第 ④ 条最能筛掉错误写法：有人在遍历时「记录每个点第一次出现的下标」然后取最大，这种写法会在「闭环后又长出尾巴」时错选成 `[3,4]`。

## 090.2 从暴力到最优：第一个念头为什么错

### 第一个念头 A：「枚举删哪条边，再判剩下的是不是树」

这是最符合直觉的写法，而且要写对并不难：

```
for i in 0..n-1:
    把除 edges[i] 之外的 n-1 条边建成图
    从 1 号点 BFS，看能不能访问到全部 n 个点
    能 → edges[i] 就是答案（若是多解，从后往前扫就得到「最后出现的」）
```

复杂度 **O(n²)**：`n` 条边各做一次 `O(n + m)` 的 BFS。`n = 1000` 时是 `1000 × 2000 = 2·10⁶` 次操作，本机不到 3 ms，**能过**。

那为什么它不是「正确的那把锤子」？两个理由：

1. **它把「增量」当成了「重来」**。图是一条边一条边长出来的，而试删法每次都要从零重建邻接表、从零跑 BFS，前面算过的连通信息全部扔掉。当 `n` 涨到 `10⁵`（[LC 1319](https://leetcode.cn/problems/number-of-operations-to-make-network-connected/) 就是这个规模）时，操作次数是 `10⁵ × (10⁵ + 10⁵) = 2·10¹⁰`，**秒级变成分钟级**，直接 TLE。
2. **它回答错了问题**。题目问的是「哪条边多余」，试删法回答的是「删掉谁还连通」。这两件事在本题答案相同，但在「有多条冗余边」的放松版本（[LC 685 冗余连接 II](https://leetcode.cn/problems/redundant-connection-ii/)）里就分道扬镳了。

### 第一个念头 B：「树有 n-1 条边，多的那条就是答案」

错得很具体：`edges = [[1,2],[2,3],[1,3]]` 里三条边都在环上，删哪一条都能得到一棵树。题目用「返回最后出现的那条」强行把答案定成 `[1,3]`。**所以「哪条边多余」不是一个集合性质，而是一个顺序性质**：必须按输入顺序扫。

### 卡点在哪

真正的卡点只有一句话：

> **处理第 `i` 条边 `(u, v)` 的那一刻，我需要知道「`u` 和 `v` 在前面 `i-1` 条边里是不是已经连通」。**

暴力 A 每次回答这个问题要 `O(n + m)`。但这个查询是**增量**的：图只加边、不删边，而且我只需要「连通/不连通」这一个比特，不需要路径长什么样。

### 灵感的来源 —— 把「判环」换成「判连通」

先证一个小等价关系（§090.3.2 会给严格证明）：

```
在「前 i-1 条边」构成的图 G 里，u 与 v 已连通
        ⇕  等价
加入第 i 条边 (u,v) 之后，整个图出现了环
```

- **⇒** 已知 `G` 里有一条 `u → … → v` 的路 `P`，那么 `P` 加上新边 `(u,v)` 就闭成一个环；
- **⇐** 若加入 `(u,v)` 后出现环，这个环去掉 `(u,v)` 就是一串只用旧边组成的 `u → … → v` 的路。

于是「判环」这个听起来要遍历全图的任务，变成了「查两个点是否同属一个连通块」——这正是**并查集**（Union-Find / DSU）唯一擅长的事。

```
并查集的两个操作：
  find(x)       → x 所在连通块的代表元（根）
  union(a, b)   → 把 a、b 所在的两个块合并；若本来就是同一个块，返回 false
```

主循环只有三行，而且**每加一条边只做一次 union，失败的那一次就是答案**：

```
for e in edges:
    if not union(e.u, e.v):      # 两端已连通 → 这条边闭环 → 它就是答案
        return e
```

## 090.3 原理拆解

### 090.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐边试删 + BFS 判连通 | O(n²) | O(n) | 25 行 | `n ≥ 10⁵`；边是「在线」来的（流式加边） |
| 整图 DFS 找环，取环上最靠后的边 | O(n) | O(n) | 40 行 | 环的唯一性靠题目保证；有多个环时要重复跑，且要额外对付自环/重边分支 |
| 拓扑剥叶（反复删度数为 1 的点） | O(n) | O(n) | 30 行 | 只能得到「环上的边集」；重边会让度数算不准；还要回到输入里取最后一条 |
| **并查集（路径压缩 + 按秩合并）** ✅ | **O(n·α(n)) ≈ O(n)** | O(n) | 25 行 | 需要「删边」时它做不到（要么离线倒序，要么支持回滚） |
| Kruskal 式的「按边权排序再加边」 | O(n log n) | O(n) | 20 行 | 本题根本没有边权，排序白付一次 `log` |

**为什么是并查集而不是别的**：题目只问「连通性」，且只加不删、只问不查路径。并查集把「连通性」这一比特信息压到极致——它甚至不知道图长什么样，只知道「谁和谁一伙」。当你发现「我只需要等价类关系，不需要具体路径」时，并查集就是那个最小的结构。

**并查集的两种优化各值多少钱**（这张表要能背）：

| 写法 | `find` 最坏 | `n` 次操作总计 | 什么时候会被打回原形 |
| --- | --- | --- | --- |
| 朴素：`parent[x]` 直接挂 | O(n) | O(n²) | 输入是 `1-2, 2-3, 3-4, …` 这样的链，树退化成链表 |
| 只有路径压缩 | 均摊 O(log n) | O(n log n) | 单次仍可能走 `log n` 层；理论上还有更紧的界要配合秩 |
| 只有按秩合并 | O(log n) | O(n log n) | 树高恒为 `log n`，但每次 `find` 都要走到底 |
| **两者都有** ✅ | **O(α(n))** | **O(n·α(n))** | `α(n)` 是反阿克曼函数，`n < 10⁶⁰⁰` 时 `α(n) ≤ 4`；等于常数 |

### 090.3.2 为什么这个做法是对的（正确性论证）

**引理**：设 `G_{i-1}` 是前 `i-1` 条边构成的图。则「`u_i` 与 `v_i` 在 `G_{i-1}` 中连通」⇔「把 `e_i = (u_i, v_i)` 加进去后图中出现环」。

- **⇒**：连通意味着存在一条只由 `G_{i-1}` 的边组成的路 `u_i = x_0, x_1, …, x_k = v_i`。把它与新边 `e_i` 接起来，得到一条闭合回路；又因为 `G_{i-1}` 里前 `i-1` 条边是森林（下面引理二会证），这条路是简单路，回路就是真环。
- **⇐**：若加入 `e_i` 后出现环 `C`，则 `C` 中一定包含 `e_i`（因为 `G_{i-1}` 无环）。把 `e_i` 从 `C` 里去掉，剩下是一条 `u_i → … → v_i` 的路，全部由旧边组成。∎

**引理二（第一次闭环之前，图始终是森林）**：对「处理的边数」做归纳。只要每一次 `union` 都成功，就说明它把两个**不同**的连通块合并成一个，于是连通块总数严格递减、图里不可能出现环（环要求某条边的两端早已在同一块内）。因此在「第一次 `union` 失败」之前，前若干条边构成的图一定是森林。这条引理保证了引理一里说的「闭合回路」确实是简单回路。∎

**命题（答案正确且唯一）**：算法返回的 `e_j`（第一个 `union` 返回 `false` 的边）就是题目要求的唯一答案。

1. **一定存在**：`n` 个点、`n` 条边，若全程无环则是森林，而森林最多 `n-1` 条边，矛盾。所以循环一定会命中某条边，不会「扫完还没返回」。
2. **命中的边唯一**：若 `e_i` 与 `e_j`（`i < j`）都满足「删掉它之后仍是树」。取 `e_j`：删掉它之后图 `T = G_n \ {e_j}` 是一棵树。而 `G_{j-1}` 是 `T` 的子图（`G_{j-1}` 不含 `e_j`）。在树 `T` 中，`u_j` 到 `v_j` 的唯一路径就是边 `e_j` 本身，所以 `u_j, v_j` 在 `T` 里**不**连通，自然在子图 `G_{j-1}` 里也不连通——与「`e_j` 被命中」矛盾。∎
3. **「唯一」与「返回最后出现的」等价**：既然命中边唯一，题目里那句「多条时返回最后出现的」在实践中退化成了「只有一条」，我们直接返回它即可。这也解释了为什么没人需要「记住所有候选再取最后一个」。

> **这个论证的价值**：它同时说明了三件事——为什么可以「边扫边 union 边返回」、为什么不需要记录任何历史、以及为什么题目里「多条时返回最后出现的」那句话在本题中其实不会被用到（**但你必须能证明它不会被用到**，否则面试官一定会追问）。

用 find 回答「是否同类」，用 union 宣布「两类合并」
      ↓
代价：O(α(n)) 每次；收益：把一个 O(n) 的连通性查询压成常数

### 090.3.4 可扩展性（面试追问的五个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 图里有**多个环**，要找出**所有**冗余边 | 边的总数不再只是 `n` | 仍是一遍并查集：每次 `union` 失败就把这条边收进答案集，复杂度不变 |
| 变成**有向图** | 「连通」变成「入度」+「环」 | 先看有没有入度为 2 的点，分情况删一条再判环 → 见 685 |
| 要求支持**删边** | 并查集不支持拆 | 要么离线倒序（删变加），要么用「可回滚并查集」（不压缩路径，记录每步改动） |
| 边是**流式**到达（在线） | 一次性输入的前提没了 | 并查集天生在线：来一条 `union` 一条，这是它比 DFS 更强的地方 |
| 边带**权**，问「什么时候图连通」 | 变成最小生成树问题 | 按权排序后加边，记录最后一条被收下的边 → 094 的 Kruskal |

## 090.4 图解推演

### 090.4.1 主循环的逐步推演

以 `edges = [[1,2], [1,3], [2,3]]` 为例。`parent` 数组初始是 `[0,1,2,3]`（`parent[i] = i`，下标 0 不用），`rank` 全 0。

```
初始：parent = [_,1,2,3]    三个簇 {1} {2} {3}
rank   = [_,0,0,0]

第 1 条 [1,2]  find(1)=1 find(2)=2  不同 → union
      parent = [_,1,1,3]    簇 {1,2} {3}
      rank   = [_,1,0,0]    ← 等高合并，新根 1 的秩 +1

第 2 条 [1,3]  find(1)=1 find(3)=3  不同 → union
      parent = [_,1,1,1]    簇 {1,2,3}
      rank   = [_,1,0,0]

第 3 条 [2,3]  find(2)=1 find(3)=1  相同 → ❌ 闭环 → 返回 [2,3]
```

用一张表看清「每一次 union 到底改了什么」：

| 步骤 | 边 | `find(u)` | `find(v)` | 同簇？ | 动作 | 之后 `parent` | 之后 `rank` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `[1,2]` | 1 | 2 | 否 | `parent[2]=1`，秩相等 → `rank[1]++` | `[_,1,1,3]` | `[_,1,0,0]` |
| 2 | `[1,3]` | 1 | 3 | 否 | `parent[3]=1`，秩 1 > 0 不变 | `[_,1,1,1]` | `[_,1,0,0]` |
| 3 | `[2,3]` | 1 | 1 | **是** | 立即返回 `[2,3]` | 不变 | 不变 |

### 090.4.2 路径压缩那一步到底做了什么

`find` 的隔代压缩可以画成这样（`→` 表示 `parent` 指针）：

```
压缩前（一条长链）：            find(6) 的过程中：
1 → 2 → 3 → 4 → 5 → 6
                               6 → 4 → 3   （6 的父从 5 改成 4，父的父）
最终：                          → 3 → 2
1 → 2 → 3 → 4 → 6              （4 的父从 3 改成 2）
    ↑     ↖___
    └─────────┘  下一次 find(6) 只走 2 步
```

隔代压缩（`parent[x] = parent[parent[x]]`）比「两趟完全压缩」少一趟扫描，均摊效果一样，而且**不需要递归**——这在 Go 里尤其重要，因为深度递归压栈在 `n = 10⁵` 的链上并不便宜。

### 090.4.3 两条路线的对比图

```
              ┌──────────── edges: n 条边 ────────────┐
              │                                       │
     ┌────────▼─────────┐                  ┌──────────▼──────────┐
     │ 路线 A：试删 + BFS│                  │ 路线 B：并查集       │
     │ O(n²) / 每轮重建  │                  │ O(n·α(n)) / 只加不删 │
     └────────┬─────────┘                  └──────────┬──────────┘
              │                                       │
      删一条 → BFS 判连通                       union 失败即答案
              │                                       │
     ✅ n≤10³ 能过，但不可增量               ✅ 天生支持在线加边
     ❌ n=10⁵ 时 2·10¹⁰ 次操作 → TLE          ❌ 不支持删边
              │                                       │

```

## 090.5 双语言实现

### 090.5.1 Java

```java
class Solution {
    private int[] parent;
    private int[] rank;

    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;              // 节点编号 1..n，点数 == 边数
        parent = new int[n + 1];
        rank = new int[n + 1];
        for (int i = 0; i <= n; i++) {
            parent[i] = i;                 // 自成一簇：每个点自己是根
        }
        for (int[] e : edges) {
            if (!union(e[0], e[1])) {
                return new int[]{e[0], e[1]};  // 两端已同簇 → 这条边闭环 → 它就是答案
            }
        }
        return new int[0];                 // 题目保证有解，这行只为满足编译器
    }

    private int find(int x) {
        // 隔代压缩：每走一步顺手把 x 挂到爷爷上。均摊 O(α(n))，且不需要递归
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) {
            return false;                  // 已连通：合并失败，这正是我们要的信号
        }
        if (rank[ra] < rank[rb]) {         // 让 ra 始终是更高的树
            int t = ra; ra = rb; rb = t;   // 高树接矮树，树高不会增长
        }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) {
            rank[ra]++;                    // 只有等高合并才可能长高一层
        }
        return true;
    }
}
```

### 090.5.2 Go

```go
package main

// DSU：用两个定长切片存 parent 与 rank，不需要任何指针
type DSU struct {
	parent []int
	rank   []int
}

func newDSU(n int) *DSU {
	d := &DSU{parent: make([]int, n+1), rank: make([]int, n+1)}
	for i := 0; i <= n; i++ {
		d.parent[i] = i
	}
	return d
}

// find：路径压缩（隔代压缩，迭代版；Go 里递归会被深度限制坑到）
func (d *DSU) find(x int) int {
	for d.parent[x] != x {
		d.parent[x] = d.parent[d.parent[x]]
		x = d.parent[x]
	}
	return x
}

// union：按秩合并；返回 false 表示两端本来就在同一棵树上
func (d *DSU) union(a, b int) bool {
	ra, rb := d.find(a), d.find(b)
	if ra == rb {
		return false
	}
	if d.rank[ra] < d.rank[rb] {
		ra, rb = rb, ra
	}
	d.parent[rb] = ra
	if d.rank[ra] == d.rank[rb] {
		d.rank[ra]++
	}
	return true
}

func findRedundantConnection(edges [][]int) []int {
	d := newDSU(len(edges))
	for _, e := range edges {
		if !d.union(e[0], e[1]) {
			return []int{e[0], e[1]}
		}
	}
	return nil
}
```

### 090.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 状态放哪 | 类的成员变量 `parent` / `rank` | 结构体字段 + 值接收者 / 指针接收者 | Go 的 `func (d *DSU) find` 必须用**指针**接收者，否则改的是副本，压缩白做 |
| 数组初始化 | `new int[n+1]` 自动全 0，再手动填 `i` | `make([]int, n+1)` 同样全 0，再 `for` 填 | 两者都要显式 `parent[i] = i`，别指望「0 就是根」 |
| `dead loop` 风险 | `while (parent[x] != x)` | 同 | 若把 `parent[i] = i` 那步写漏（全 0），`find` 会在 `parent[0]=0` 上原地打转，肉眼很难看出来 |
| 返回值 | `int[]` / `new int[0]` | `[]int` / `nil` | 两者都被 LeetCode 接受；Go 返回 `nil` 语义更诚实 |
| 堆（本章不涉及，但要知道） | `PriorityQueue` 是内置类，传 `Comparator` 即可 | **Go 标准库没有优先队列**，要用 `container/heap` 手写 `Len/Less/Swap/Push/Pop` 五个方法 | 从 091 起每一章都要写这五个方法，并且 `Push/Pop` 的参数是 `interface{}`，要自己做类型断言 |
| 组合 | 内部类 / 静态嵌套类 | 匿名结构体或独立类型 | Go 没有内部类，`DSU` 只能做成包级类型（同包内不重名） |

### 090.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 参考实现：逐条加边，然后重判两端是否已连通（每步跑一次 O(n+m) 的 DFS）
func bruteRedundant(edges [][]int) []int {
	n := len(edges)
	for i := 0; i < len(edges); i++ {
		adj := make([][]int, n+1)
		for j := 0; j < i; j++ { // 只用前 i 条边（下标 0..i-1）
			u, v := edges[j][0], edges[j][1]
			adj[u] = append(adj[u], v)
			adj[v] = append(adj[v], u)
		}
		seen := make([]bool, n+1)
		seen[edges[i][0]] = true
		stack := []int{edges[i][0]}
		for len(stack) > 0 {
			x := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			for _, y := range adj[x] {
				if !seen[y] {
					seen[y] = true
					stack = append(stack, y)
				}
			}
		}
		if seen[edges[i][1]] { // 两端已连通 → 这条就是冗余边
			return []int{edges[i][0], edges[i][1]}
		}
	}
	return nil
}

func TestFindRedundantConnection(t *testing.T) {
	r := rand.New(rand.NewSource(20240684))
	for iter := 0; iter < 20000; iter++ {
		n := 2 + r.Intn(8)
		edges := make([][]int, 0, n)
		for v := 2; v <= n; v++ {              // 先长一棵随机树：每个点挂到随机父亲上
			edges = append(edges, []int{1 + r.Intn(v-1), v})
		}
		edges = append(edges, []int{1 + r.Intn(n), 1 + r.Intn(n)}) // 再加一条（可能是重边/自环）
		r.Shuffle(len(edges), func(i, j int) { edges[i], edges[j] = edges[j], edges[i] })

		got, want := findRedundantConnection(edges), bruteRedundant(edges)
		if len(got) != 2 || got[0] != want[0] || got[1] != want[1] {
			t.Fatalf("iter=%d edges=%v got=%v want=%v", iter, edges, got, want)
		}
	}
}
```

> ⚠️ **随机数据必须打乱顺序**：如果按「先树后多余边」的天然顺序喂进去，多余边永远在最后，`Shuffle` 一旦省掉，就再也测不出「返回最后出现的那条」这类顺序性质的 bug。
> 另外注意参考实现本身是 `O(n²)`，所以随机规模只能开到 `n ≤ 9`——**对拍的目标不是压测性能，而是逼出逻辑分歧**。

## 090.6 复杂度与常见坑

### 090.6.1 复杂度推导

- **时间 `O(n·α(n))`**：主循环执行 `n` 次，每次做两次 `find` 加一次可能合并。
  - 单次 `find` 的均摊代价是 `O(α(n))`：路径压缩把「走过一次的长链」永久压平，按秩合并保证树高从未超过 `log n`，两者共同作用把均摊压到反阿克曼函数。
  - `α(n)` 增长慢到离谱：`α(10⁶) = 3`，`α(10⁶⁰⁰) = 4`。所以工程上直接把它当 `O(1)`，但因为它是**均摊**，严谨写法要保留 `α`。
- **空间 `O(n)`**：`parent` 与 `rank` 各 `n+1` 个 `int`，没有任何指针、链表或递归栈。

### 090.6.2 七个真实踩过的坑

1. **数组少开一格**：节点编号是 `1..n`，`new int[n]` 会让 `parent[n]` 越界。必须 `n+1`。
2. **`parent` 全 0 没有初始化**：`find` 遇到 `parent[0] = 0` 会「自根」，把 1 号点也拉进 0 号簇，于是所有点看起来都连通，第一条边就被判成答案。
3. **`union` 用递归 `find` 且没压缩**：`n = 1000` 的链上递归深度 1000，Java 默认栈能扛，但把规模换成 `10⁶` 就 `StackOverflowError`；Go 的 goroutine 栈会自动增长，可代价是内存。
4. **只写按秩合并，忘了路径压缩**（或反过来）：都能过本题，但复杂度从 `O(α(n))` 退化到 `O(log n)`。面试里被问「你的并查集为什么是近似 O(1)」会答不上来。
5. **把「返回最后一条」理解成「返回最后一条在环上的边」**：错。是「输入顺序上最后一条使图闭环的边」，而这条恰好唯一（§090.3.2 命题第 2 点）。
6. **忘记处理自环**（约束放松后）：`edges = [[1,1]]` 时 `find(1) == find(1)` 直接返回 `false`，答案就是 `[1,1]` —— 这恰好是对的，但如果你在 `union` 里写 `if (a == b) return true;` 就会漏答案。
7. **在 Go 里用值接收者**：`func (d DSU) find(...)` 会复制整个结构体切片头，压缩写回的是副本的底层数组……因为切片共享底层数组，压缩**碰巧**生效了；`rank` 也是切片，所以同样侥幸没出错。但如果哪天改成 `parent [1005]int` 定长数组，压缩就彻底失效。**统一用指针接收者**。

### 090.6.3 面试官最爱追问的三个问题

**Q1：为什么路径压缩 + 按秩合并就是近似 O(1)？**
> 「路径压缩让每个节点在被访问一次之后离根变近，按秩合并保证树的形态不会长成链，树高上界是 `log n`。两者叠加后的均摊复杂度是 `O(α(n))`，`α` 是反阿克曼函数，在任何能写进内存的 `n` 上都不超过 4。严格证明要用电位能法：把「压缩省下的深度」记成势能，均摊到每次操作上就是常数。」

**Q2：并查集能不能删边？**
> 「不能直接删。两条路：① **离线倒序**——把「删边」变成「加边」，从最终状态倒着做；② **可回滚并查集**——放弃路径压缩、只用按秩合并，把每次 `parent` 的改动压进栈里，删除时按栈回滚，单次 `O(log n)`。这也是为什么可回滚并查集常出现在「线段树分治 + 判连通」的题里。」

**Q3：这题如果图里有多条环，返回什么？**
> 「原题保证只有一条。若放松成多个环，题意就得改成『返回所有冗余边』，做法仍是一遍扫：每次 `union` 返回 `false` 就把这条边收进答案。此时答案不再是单条边，而是生成森林的『多余边集』，规模等于 `m - (n - 连通块数)`。」
