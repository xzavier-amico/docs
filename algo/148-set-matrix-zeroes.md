## 148.1 题目

**原题链接**：<https://leetcode.cn/problems/set-matrix-zeroes/>

### 题意重述（把隐含条件补齐）

给你一个 `m × n` 的矩阵，如果某个元素是 `0`，就把**它所在的整行和整列**都置为 `0`。要求在**原地**完成（直接修改输入矩阵），进阶要求是 `O(1)` 额外空间。

五条必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 「整行整列清零」针对的是**原始的 0** | 示例 2 | 边扫边清零会把「被清出来的 0」当成新的源头，一路蔓延把整个矩阵清成 0 |
| 必须**原地** | 「你必须原地操作」 | 复制一份矩阵虽然简单正确，但空间 `O(mn)`，答不到进阶 |
| 进阶要 **`O(1)` 额外空间** | 「进阶：一个直观的解决方案是使用 `O(mn)` 的额外空间，但这并不是最好的解决方案」 | 用两个集合存「要清的行/列」是 `O(m+n)`，不算 `O(1)` |
| `m` 与 `n` 可以不等 | 「`m x n` 矩阵」 | 行列混用会越界；`1 × n` 与 `m × 1` 是最容易被写错的形状 |
| `1 <= m, n` | 约束 | 不会出现真正的空矩阵，但工程代码仍应防一下 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= m, n <= 200` | 最多 40 000 个格子 | 时间 `O(mn)` 轻松；**这题的时间从来不是问题，空间才是** |
| `-2³¹ <= matrix[i][j] <= 2³¹-1` | 值域是全 `int` | **不能拿某个「特殊值」当标记**（比如 `-1`：它本身可能就是合法数据）。这直接否掉了「用哨兵值标记」的想法 |
| 进阶 `O(1)` 空间 | 题面明写 | 只剩一条路：**复用矩阵自身的首行首列** |
| `0` 是判定的唯一依据 | 题意 | 「原始的 0」与「被清出来的 0」必须区分，否则传播会失控 |

> 💡 **量级 → 算法** 在这里换成**空间 → 算法**：
> **当题目要求 `O(1)` 额外空间、而输入本身有 `k` 个「空位」可以借用时，优先想「把输入当标记表」。**
> 代价是：**你借用的那些格子，原本的信息必须先单独存起来**——这就是本章「首行首列要单独记录」的来源。

### 示例

```text
输入：matrix = [[1,1,1],
                [1,0,1],
                [1,1,1]]
输出：          [[1,0,1],
                [0,0,0],
                [1,0,1]]

输入：matrix = [[0,1,2,0],
                [3,4,5,2],
                [1,3,1,5]]
输出：          [[0,0,0,0],
                [0,4,5,0],
                [0,3,1,0]]
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① matrix = [[1,0,3]]               → [[0,0,0]]（单行）
                                     暴露：首行本身就含 0 时，若只用 matrix[0][j] 当列标记，
                                     会把「第 0 行要清零」的信息和「第 j 列要清零」混在一起
② matrix = [[1],
            [0],
            [3]]                    → [[0],[0],[0]]（单列）
                                     与 ① 完全对称，暴露首列被借用时的同一类问题
③ matrix = [[0]]                    → [[0]]
                                     唯一的格子本身就是 0：firstRowZero 与 firstColZero 都为 true
④ matrix = [[1,1],[1,1]]            → 不变
                                     暴露：没有任何 0 时，标记阶段不能「凭空」写出 0
⑤ matrix = [[2,0,2],[2,2,2]]（2 行 3 列）
                                     → [[0,0,0],[2,0,2]]
                                     暴露：把 m 与 n 弄反（用 2 当列数会漏掉第 3 列）
```

第 ① 条是本章的**灵魂反例**：`[[1,0,3]]` 只有一行，`matrix[0][0] = 1`、`matrix[0][1] = 0`。若你打算用「第 0 行存列标记」，那 `matrix[0][1] = 0` 到底是「第 1 列要清零」还是「第 0 行原本就该清零」？**这一格被两种含义争用了**——所以必须用 `firstRowZero` 把「第 0 行是否需要清零」单独记下来。

## 148.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```java
// 方案 A：复制一份矩阵，扫描原矩阵，往副本里写 0
int[][] copy = deepCopy(matrix);
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (copy[i][j] == 0) {          // 注意：判的是副本（原始值），不是被改过的 matrix
            for (int k = 0; k < n; k++) matrix[i][k] = 0;
            for (int k = 0; k < m; k++) matrix[k][j] = 0;
        }

// 方案 B：两个集合记下要清的行号与列号
Set<Integer> rows = new HashSet<>(), cols = new HashSet<>();
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (matrix[i][j] == 0) { rows.add(i); cols.add(j); }
for (int i : rows) for (int j = 0; j < n; j++) matrix[i][j] = 0;
for (int j : cols) for (int i = 0; i < m; i++) matrix[i][j] = 0;
```

- 方案 A：时间 **O(mn(m+n))**（每次发现 0 都要清一整行一整列），空间 **O(mn)**。
- 方案 B：时间 **O(mn)**，空间 **O(m+n)**。
- 两者**都正确**（B 是标准的两阶段做法，先收集再统一清除）。它们的问题只在空间：
  - A 的 `O(mn)` 是题面直接点名的「直观但不最好」的解法；
  - B 的 `O(m+n)` 已经很好，但**进阶要求 `O(1)`**。

### 第二步：边扫边清零为什么一定错（这是最直觉的错法）

最省事的想法是「见到 0 就立刻把行列清掉」：

```java
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (matrix[i][j] == 0) {
            for (int k = 0; k < n; k++) matrix[i][k] = 0;   // ✗
            for (int k = 0; k < m; k++) matrix[k][j] = 0;   // ✗
        }
```

问题在于**扫描过程中新写出的 0 会被后续循环当成「原始的 0」**：

```
输入  [[1,1,1],
       [1,0,1],
       [1,1,1]]

扫到 (1,1) 是 0 → 把第 1 行、第 1 列清零：
      [[1,0,1],
       [0,0,0],
       [1,0,1]]
继续扫到 (2,1) —— 它现在也是 0 了！→ 把第 2 行清零：
      [[1,0,1],
       [0,0,0],
       [0,0,0]]     ✗ 第 2 行本不该被清零
```

**这就是「污染」**：`0` 会沿行与列蔓延，最终把整张矩阵吃成 0。所以必须**分两个阶段**：先收集完「哪些行、哪些列要清」，再统一清。

### 第三步：卡点在哪 —— 标记位放哪儿

两阶段做法需要一个地方存「第 i 行要清、第 j 列要清」。`O(mn)` 的副本、`O(m+n)` 的集合都能存，但进阶要 `O(1)`。

于是卡点非常具体：

> **矩阵里有没有 `m + n` 个「空位」可以借来当标记？**

有——**首行有 `n` 个格子，首列有 `m` 个格子，一共 `m + n` 个**，而且它们的行列含义天然对应：

- `matrix[i][0] == 0` ⟹ 第 `i` 行要清零；
- `matrix[0][j] == 0` ⟹ 第 `j` 列要清零。

### 第四步：灵感的关键 —— 被借用的格子自己的信息要单独存

借用是有代价的：`matrix[0][0]` 这一格**同时被两种含义争用**（既代表「第 0 行」又代表「第 0 列」），而且首行、首列**原本就可能是 0**，那个信息在借用过程中会被覆盖。

解决办法只有两个字：**单独记**。

```
firstRowZero = 第 0 行原本是否有 0      ← 单独存
firstColZero = 第 0 列原本是否有 0      ← 单独存
```

于是完整流程分成四阶段：

| 阶段 | 做什么 | 为什么这个顺序 |
| --- | --- | --- |
| **0** | 扫首行、首列，记录 `firstRowZero` / `firstColZero` | 必须在任何写操作之前，否则原值已被改掉 |
| **1** | 扫**内部** `i ≥ 1, j ≥ 1`，遇 0 就写 `matrix[i][0] = 0` 与 `matrix[0][j] = 0` | 只写 0，不写非 0 → 「是否为零」的信息单调累积，不会误判 |
| **2** | 扫**内部** `i ≥ 1, j ≥ 1`，若 `matrix[i][0] == 0` 或 `matrix[0][j] == 0` 就置 0 | 此时标记已完整；只动内部，不破坏标记 |
| **3** | 若 `firstRowZero` 则清第 0 行；若 `firstColZero` 则清第 0 列 | 最后处理，因为首行首列在前面一直充当标记板 |

**这个四阶段顺序就是本章的全部内容。**

## 148.3 原理拆解

### 148.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（额外） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 边扫边清零 | O(mn(m+n)) | O(1) | 8 行 | **逻辑错**（新 0 会被当原始 0），无论怎么调都不对 |
| 复制矩阵 + 双阶段 | O(mn(m+n))~O(mn) | **O(mn)** | 10 行 | 题面点名的「直观但不最好」；大矩阵内存吃紧 |
| 行/列集合（`HashSet`） | O(mn) | **O(m+n)** | 10 行 | 进阶要求 `O(1)`；装箱开销 |
| 布尔数组当标记 | O(mn) | **O(m+n)** | 12 行 | 同上，但常数更小（位图可以做到 `O((m+n)/64)`） |
| **首行首列当标记 + 两个布尔** ✅ | **O(mn)** | **O(1)** | **20 行** | 阶段顺序与「首行首列单独记录」必须写对，否则 ① 类反例崩 |
| 用「特殊值」当哨兵（如 `−10¹⁰`） | O(mn) | O(1) | 10 行 | **值域是全 `int`，任何哨兵都可能是合法数据** → 不可靠 |

### 148.3.2 为什么这个做法是对的（正确性论证）

先证明「标记的准确性」，再证明「两阶段的清除是对的」。

**引理 1（首行首列的原始信息被完整保存）**：阶段 0 在**任何写操作之前**执行，因此 `firstRowZero` / `firstColZero` 精确等于「第 0 行 / 第 0 列原本是否含 0」；之后这两个布尔量不再被修改，信息不会丢失。∎

**引理 2（标记等价性）**：阶段 1 结束后，对任意 `i ≥ 1`：

```
matrix[i][0] == 0  ⟺  原矩阵第 i 行含 0
```

**证明**（两个方向）：

- 「⟸」：若原矩阵第 `i` 行含 0，取一个 `j` 使原 `matrix[i][j] == 0`。
  - 若 `j ≥ 1`：阶段 1 扫到 `(i, j)` 时会写 `matrix[i][0] = 0` ✓。
  - 若 `j == 0`：那么 `matrix[i][0]` 本来就是 0 ✓。
- 「⟹」：若阶段 1 结束时 `matrix[i][0] == 0`，考虑它为何是 0：要么**原本就是 0**（那么原第 `i` 行确实含 0，就是 `(i,0)` 这一格），要么**被阶段 1 写成 0**（那么存在 `j` 使原 `matrix[i][j] == 0`）。两种可能都推出「原第 `i` 行含 0」 ✓。∎

> 这个引理的精髓在于：**阶段 1 只写 0、不写非 0**。所以「某格是否为 0」这个信息只会「从否变是」，绝不会被擦掉；于是即便某些格子在借用前就是 0，也不会让标记失真——那种情况恰好对应「这一行/列本来就要清零」，语义一致。

**对称地**，阶段 1 结束后对任意 `j ≥ 1`：`matrix[0][j] == 0 ⟺ 原矩阵第 j 列含 0`（同样论证，「原本为 0」与「被写成 0」两种情形都成立）。∎

**命题（最终结果正确）**：处理完毕后

```
matrix[i][j] == 0  ⟺  原矩阵第 i 行含 0 或第 j 列含 0 （对 i ≥ 1, j ≥ 1）
```

- 阶段 2 对内部格子做的正是这个判断：`matrix[i][0] == 0` 由引理 2 等价于「第 `i` 行含 0」，`matrix[0][j] == 0` 等价于「第 `j` 列含 0」。所以内部格子被正确清零 ✓。
- 阶段 3 用 `firstRowZero` / `firstColZero` 处理首行首列：若第 0 行原本含 0，则整个第 0 行清零（这正是题意要求——`(0,j)` 是原始 0 时要清第 0 行与第 `j` 列，第 0 行当然全清）；若不含，则第 0 行不做整体清零（它内部的个别格子可能因所在列含 0 而已被阶段 1 正确写成 0）。第 0 列按同一套逻辑处理 ✓。

把三段合起来，每个格子的最终值都符合题意，且没有任何格子被「不该清却清了」或「该清没清」。∎

**为什么两个布尔量就够（而不需要更多）**：首行有 `n` 列、首列有 `m` 行，看起来要记 `m + n` 个原始值。但其实我们**只关心「第 0 行原本有没有 0」这一个布尔问题**——因为阶段 3 的处理是「整行清 0 / 整行不动」这种粗粒度动作，不需要知道 0 具体在哪一格。对称地，第 0 列也只需要一个布尔。这是本题最漂亮的一处「把信息压缩到刚好够用」。

### 148.3.3 通用解题思路（可迁移的那一层）

**模型：把输入自身当标记表（原地哈希的思想）**

```
需要 k 个标记位，但要求 O(1) 额外空间
        ↓ 输入里有没有 k 个「可以借」的位置？
有 → 借用，并把被借用位置的原值单独保存
        ↓ 关键三问
① 借哪些位置？（必须是「用完还能恢复语义」的位置）
② 借的时候会不会破坏还需要的信息？（→ 阶段顺序：先读、后写）
③ 被借走的信息怎么存？（→ 少量标量 / 布尔 / 符号位）
```

同一个模型在不同题里的样子：

| 题 | 借用了什么 | 单独记住了什么 |
| --- | --- | --- |
| [LC 73 矩阵置零](https://leetcode.cn/problems/set-matrix-zeroes/) | 首行 + 首列共 `m + n` 格 | 两个布尔（首行/首列原本是否含 0） |
| [LC 41 缺失的第一个正数](https://leetcode.cn/problems/first-missing-positive/) | 数组下标本身（值当索引） | 用交换归位，不需要额外记 |
| [LC 448 找到所有消失的数字](https://leetcode.cn/problems/find-all-numbers-disappeared-in-an-array/) | 每个元素的**符号位** | 无需额外记（符号只表达「见过」） |
| [LC 442 数组中重复的数据](https://leetcode.cn/problems/find-all-duplicates-in-an-array/) | 同上，符号位 | 「发现已标记」即为重复 |
| [LC 289 生命游戏](https://leetcode.cn/problems/game-of-life/) | 每个格子的**高位**（`int` 的第二个 bit） | 用两位编码同时存旧状态与新状态 |
| [LC 189 轮转数组](https://leetcode.cn/problems/rotate-array/) | 不需要借用（自逆置换） | — |
| [LC 645 错误的集合](https://leetcode.cn/problems/set-mismatch/) | 符号位标记 | 找到那个被二次访问的位置 |

### 148.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 不要求 `O(1)` 空间 | 约束放宽 | 用两个 `boolean[m]` / `boolean[n]` 数组最清晰（`O(m+n)`），代码短一半；面试先说这个再优化 |
| 要求把行/列**置成 1** 而不是 0 | 语义变化 | 把「标记为 0」改成「标记为一个不会被误判的状态」——最稳妥的是另开布尔数组（因为 `1` 也可能是原始数据） |
| 只清**行**不清列（或反过来） | 少一半标记 | 只需要 `m` 个标记位 —— 直接用首列（`matrix[i][0]`），连 `firstColZero` 都不用记（首列本身要不要清，靠另一个布尔即可） |
| 矩阵**逐行流式**输入（内存只放得下一行） | 不能回头读 | 维护「首行标记 + 待清列集合」；每来一行先按标记清该行，再记录新出现的 0 所在列（空间 `O(n)`） |
| 矩阵元素是**浮点数** | 不能用 `== 0` 精确判定 | 用 `Math.abs(x) < eps` 判「近似 0」；标记位本身仍可用 `boolean` 或哨兵 `0.0` |
| 要求返回**被清零的行列列表** | 需要额外输出 | 阶段 1 时顺手把 `i`、`j` 记到输出列表里，不影响 `O(1)` 额外空间（输出不算空间） |

## 148.4 图解推演

### 148.4.1 四个阶段的完整轨迹（`3 × 4` 例子）

原始矩阵（用 `0` 表示原始零）：

```
        j=0   j=1   j=2   j=3
       ┌─────┬─────┬─────┬─────┐
 i=0   │  0  │  1  │  2  │  0  │   ← 首行原本含 0
       ├─────┼─────┼─────┼─────┤
 i=1   │  3  │  4  │  5  │  2  │
       ├─────┼─────┼─────┼─────┤
 i=2   │  1  │  3  │  1  │  5  │
       └─────┴─────┴─────┴─────┘
          ↑                       ↑
       首列首格也是 0        第 3 列首格是 0
```

**阶段 0：记录首行首列**

```
firstRowZero = true      （matrix[0][0]=0 或 matrix[0][3]=0）
firstColZero = true      （matrix[0][0]=0 或 matrix[2][0]? 不 —— 看 matrix[0][0]=0）
```

**阶段 1：只扫内部（`i ≥ 1, j ≥ 1`）**

```
        j=0   j=1   j=2   j=3
       ┌─────┬─────┬─────┬─────┐
 i=0   │  0  │  1  │  2  │  0  │   ← 首行：只作「列标记」用
       ├─────┼─────┼─────┼─────┤
 i=1   │  3  │  4  │  5  │  2  │   内部没有 0 → 不改任何标记
       ├─────┼─────┼─────┼─────┤
 i=2   │  1  │  3  │  1  │  5  │
       └─────┴─────┴─────┴─────┘
         ↑ 首列：只作「行标记」用
```

换个例子更能看出标记的作用——原始矩阵：

```
       ┌─────┬─────┬─────┬─────┐
 i=0   │  1  │  1  │  1  │  1  │
       ├─────┼─────┼─────┼─────┤
 i=1   │  1  │  1  │  0  │  1  │   ← 内部的 0 在 (1,2)
       ├─────┼─────┼─────┼─────┤
 i=2   │  0  │  1  │  1  │  1  │   ← 内部的 0 在 (2,0)？ 不是内部，是首列！
       └─────┴─────┴─────┴─────┘
```

阶段 1 处理 `(1,2)`：

```
matrix[1][0] = 0    （第 1 行要清）
matrix[0][2] = 0    （第 2 列要清）

       ┌─────┬─────┬─────┬─────┐
 i=0   │  1  │  1  │  0  │  1  │   ← 这一格变成「第 2 列的标记」
       ├─────┼─────┼─────┼─────┤
 i=1   │  0  │  1  │  0  │  1  │   ← 这一格变成「第 1 行的标记」
       ├─────┼─────┼─────┼─────┤
 i=2   │  0  │  1  │  1  │  1  │   ← (2,0) 原本就是 0，同时是第 2 行的标记
       └─────┴─────┴─────┴─────┘
```

**阶段 2：用标记清零内部**

```
       ┌─────┬─────┬─────┬─────┐
 i=0   │  1  │  1  │  0  │  1  │   ← 首行暂时不动（它还是标记板）
       ├─────┼─────┼─────┼─────┤
 i=1   │  0  │  0  │  0  │  0  │   ← matrix[1][0]=0 → 整行清
       ├─────┼─────┼─────┼─────┤
 i=2   │  0  │  1  │  0  │  1  │   ← matrix[2][0]=0 → 整行清；同时 matrix[0][2]=0 → 第 2 列清
       └─────┴─────┴─────┴─────┘
```

**阶段 3：处理首行首列**

```
此例 firstRowZero = false，firstColZero = true

  if (firstColZero)  → 第 0 列整列清 0（(0,0) 与 (1,0)、(2,0) 都已经是 0）
  if (firstRowZero)  → 为 false，什么都不做

最终：
       ┌─────┬─────┬─────┬─────┐
 i=0   │  0  │  1  │  0  │  1  │   ← 第 0 行「没被整行清」，但 (0,0) 因第 0 列、(0,2) 因第 2 列而为 0
       ├─────┼─────┼─────┼─────┤
 i=1   │  0  │  0  │  0  │  0  │   ← 第 1 行整行清
       ├─────┼─────┼─────┼─────┤
 i=2   │  0  │  0  │  0  │  0  │   ← 第 2 行整行清
       └─────┴─────┴─────┴─────┘
```

这里有个乍看很别扭的地方，值得单独说清楚：`firstRowZero == false`，第 0 行「不该被整行清」，可阶段 1 还是把 `matrix[0][2]` 写成了 `0`（因为第 2 列里有 0）。阶段 3 什么都不做，那个 `0` 就留在了结果里。

**这是对的。** 因为第 2 列里原本有 0，所以整列（含 `(0,2)` 这一格）都该变 0 —— 阶段 1 写下的那个标记 `0`，**恰好就是最终答案**。

> 这就是「借用标记」能成立的最深层原因：
> **标记写下的 `0`，在语义上与「这一列要被清零」的结果完全一致，所以永远不需要「恢复原值」。**
> 而 `firstRowZero` / `firstColZero` 负责的是另一件事——**「整个首行 / 首列是否清零」这种粗粒度判断**，标记位本身表达不了它（一格标记只说「某一列要清」，说不出「第 0 行整体要清」）。

### 148.4.2 单行反例的剖析（`[[1,0,3]]`）

```
初始： [ 1 | 0 | 3 ]        firstRowZero = true（首行含 0）, firstColZero = false（首格是 1）

阶段 1：没有内部格子（m = 1），什么也不写
阶段 2：没有内部格子，什么也不写
阶段 3：firstRowZero == true → 整行清零

最终： [ 0 | 0 | 0 ]   ✓ 正确（第 1 列含 0 → 整列清；第 0 行含 0 → 整行清）
```

若没有 `firstRowZero` 这个布尔量，你只能从 `matrix[0][*]` 里读「第 0 行有没有 0」，可那时它已经被当作列标记写乱了——**信息丢失，无法恢复**。这就是「首行首列自身是否为零要单独记录」的全部理由。

```
   ┌──────────────────────────────────────────────────────────┐
   │ 借用首行首列的两个必要条件：                                │
   │ ① 阶段 0 先记录「首行/首列原本是否有 0」（两个布尔）        │
   │ ② 阶段 1 只写 0、不写非 0 → 标记信息单调，不会被擦掉        │
   │ 于是「借来的标记」与「最终答案」天然一致，无需恢复原值      │
   └──────────────────────────────────────────────────────────┘
```

### 148.4.3 逐步状态表（题面示例 2，`3 × 4`）

| 阶段 | `firstRowZero` | `firstColZero` | 扫到的关键格子 | 动作 | 矩阵当前首行 / 首列 |
| --- | --- | --- | --- | --- | --- |
| 0 | true | true | `matrix[0][0] = 0` | 记录两个 true | 未改动 |
| 1 | true | true | `(1,3) = 2` 非 0 | 无 | 未改动 |
| 1 | true | true | 内部无 0 | 无 | 未改动 |
| 2 | true | true | 内部全非 0 标记 | 无需清 | 未改动 |
| 3 | true | true | — | 第 0 行清 0、第 0 列清 0 | `[[0,0,0,0],[0,4,5,2],[0,3,1,5]]` |

> 注意题面示例 2 的输入是 `[[0,1,2,0],[3,4,5,2],[1,3,1,5]]`：原始零全部落在首行首列，所以内部阶段什么都不做，全靠阶段 3 的两个布尔完成——**这个例子正好把「首行首列单独记录」的价值演示到极致**。

## 148.5 双语言实现

### 148.5.1 Java

```java
class Solution {
    public void setZeroes(int[][] matrix) {
        if (matrix == null || matrix.length == 0 || matrix[0].length == 0) {
            return; // 工程代码的防御：题面保证 m, n ≥ 1，但空输入不应崩
        }
        int m = matrix.length, n = matrix[0].length;

        // 阶段 0：在改动任何格子之前，先把「首行 / 首列原本是否含 0」记下来。
        // 这两个布尔量是本题的灵魂：首行首列稍后会被当成标记板，原值再也读不回来。
        boolean firstRowZero = false, firstColZero = false;
        for (int j = 0; j < n; j++) {
            if (matrix[0][j] == 0) { firstRowZero = true; break; }
        }
        for (int i = 0; i < m; i++) {
            if (matrix[i][0] == 0) { firstColZero = true; break; }
        }

        // 阶段 1：只扫内部（i ≥ 1, j ≥ 1），把「行/列要清零」写进首列/首行。
        // 注意只写 0、不写非 0：这样标记只会「从否变是」，不会覆盖掉真实信息。
        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                if (matrix[i][j] == 0) {
                    matrix[i][0] = 0;   // 第 i 行要清
                    matrix[0][j] = 0;   // 第 j 列要清
                }
            }
        }

        // 阶段 2：用标记清零内部。此刻首行首列还是标记板，所以只动内部格子。
        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                if (matrix[i][0] == 0 || matrix[0][j] == 0) {
                    matrix[i][j] = 0;
                }
            }
        }

        // 阶段 3：最后处理首行首列本身。
        // 这里只判断两个布尔量，不去读 matrix[0][j] / matrix[i][0] ——
        // 因为它们已经被阶段 1 改过了，读出来的是标记而不是原始信息。
        if (firstRowZero) {
            for (int j = 0; j < n; j++) {
                matrix[0][j] = 0;
            }
        }
        if (firstColZero) {
            for (int i = 0; i < m; i++) {
                matrix[i][0] = 0;
            }
        }
    }
}
```

### 148.5.2 Go

```go
package main

func setZeroes(matrix [][]int) {
	if len(matrix) == 0 || len(matrix[0]) == 0 {
		return
	}
	m, n := len(matrix), len(matrix[0])

	// 阶段 0：先记录首行 / 首列的原始状态（两个布尔量）
	firstRowZero, firstColZero := false, false
	for j := 0; j < n; j++ {
		if matrix[0][j] == 0 {
			firstRowZero = true
			break
		}
	}
	for i := 0; i < m; i++ {
		if matrix[i][0] == 0 {
			firstColZero = true
			break
		}
	}

	// 阶段 1：只在内部找 0，把标记写到首列与首行（只写 0）
	for i := 1; i < m; i++ {
		for j := 1; j < n; j++ {
			if matrix[i][j] == 0 {
				matrix[i][0] = 0
				matrix[0][j] = 0
			}
		}
	}

	// 阶段 2：按标记清内部
	for i := 1; i < m; i++ {
		for j := 1; j < n; j++ {
			if matrix[i][0] == 0 || matrix[0][j] == 0 {
				matrix[i][j] = 0
			}
		}
	}

	// 阶段 3：按两个布尔清首行 / 首列
	if firstRowZero {
		for j := 0; j < n; j++ {
			matrix[0][j] = 0
		}
	}
	if firstColZero {
		for i := 0; i < m; i++ {
			matrix[i][0] = 0
		}
	}
}
```

### 148.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维容器 | `int[][]`（行是数组引用） | `[][]int`（行是切片，各自独立底层数组） | 原地写入都生效；但 Go 里 `for _, row := range matrix` 得到的 `row` 是副本头，改 `row[j]` 有效、`row = newRow` 无效 |
| 空输入 | `matrix == null \|\| matrix.length == 0` | `len(matrix) == 0` | 两者都必须先判，再取 `matrix[0]` |
| 布尔 | `boolean` | `bool` | 一致；Go 可以一行 `firstRowZero, firstColZero := false, false` |
| 提前 break | `break` 跳出内层 | `break` 同 | 记住只跳出一层，需要时用带标签的 `break` |
| 行列数 | `matrix.length` / `matrix[0].length` | `len(matrix)` / `len(matrix[0])` | 非方阵时混用会越界，`1 × n` 反例专治这个 |

```go
package main

import (
	"math/rand"
	"testing"

// 参考实现：两阶段 + 行/列集合。它与「首行首列当标记」的机制完全不同，
// 所以两边的 bug 不会同向。
func bruteSetZeroes(matrix [][]int) {
	if len(matrix) == 0 || len(matrix[0]) == 0 {
		return
	}
	m, n := len(matrix), len(matrix[0])
	rows := make([]bool, m)
	cols := make([]bool, n)
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if matrix[i][j] == 0 {
				rows[i] = true
				cols[j] = true
			}
		}
	}
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if rows[i] || cols[j] {
				matrix[i][j] = 0
			}
		}
	}
}

func clone2D(a [][]int) [][]int {
	b := make([][]int, len(a))
	for i := range a {
		b[i] = append([]int(nil), a[i]...)
	}
	return b
}

func equal2D(a, b [][]int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if len(a[i]) != len(b[i]) {
			return false
		}
		for j := range a[i] {
			if a[i][j] != b[i][j] {
				return false
			}
		}
	}
	return true
}

	r := rand.New(rand.NewSource(20260221))

		a := make([][]int, m)

			a[i] = make([]int, n)
			for j := 0; j < n; j++ {
				// 值刻意限制在 {0,1,2}：0 的比例高，才能高频造出
				// 「首行首列本身含 0」「内部含 0」「整行整列都要清」这些关键形态
				a[i][j] = r.Intn(3)
```

## 148.6 复杂度与常见坑

### 148.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(mn)**：阶段 0 两次单行/单列扫描，共 `O(m + n)`；阶段 1 与阶段 2 各扫内部 `(m−1)(n−1)` 格；阶段 3 最多 `O(m + n)`。总计 `O(mn + m + n) = O(mn)`。注意到**每个格子只被访问常数次**（最多 3 次：标记、判标记、可能被清零），这是最优的——至少要看一遍全部元素才能知道哪里有 0。
- **空间 O(1)**：只有 `firstRowZero`、`firstColZero` 两个布尔量 + 若干下标变量。**连一个额外数组都没有**。
- **对比 `O(m+n)` 的行列集合**：`m = n = 200` 时两个 `bool` 数组共 400 字节，几乎无感；但面试官问的就是「能不能做到 `O(1)`」，而 `O(1)` 的写法同时也更快（无额外内存分配、缓存更友好）。
- **信息论下界**：要区分「首行是否整体清零」这件事，至少需要 1 bit；要区分首列，又需要 1 bit。所以**两个布尔量不是巧合，而是下界**。这解释了为什么「一个布尔量」的写法必然错。

### 148.6.2 七个真实踩过的坑

1. **边扫边清零** —— 新写出的 0 被当成原始 0，整张矩阵被吃成 0。必须分成「标记」与「清除」两阶段。
2. **忘了 `firstRowZero` / `firstColZero`** —— 只用 `matrix[0][j]` / `matrix[i][0]` 当标记，却不记「首行/首列自身是否含 0」。`[[1,0,3]]` 一测就崩（首行该清零却不清）。
3. **阶段顺序颠倒** —— 先扫内部再记录首行首列，此时标记已经写进去了，`firstRowZero` 读到的是被污染的值。
4. **阶段 2 把首行首列也清了** —— 用 `i`、`j` 从 0 开始扫内部区域，会把标记板本身清掉，导致后面所有判断都读到 0（结果是整张矩阵全 0）。
5. **想用哨兵值（如 `−1`）当标记** —— 值域是全 `int`，`−1` 完全可能是合法数据，会误判。换成 `INT_MAX`、`0x7FFFFFFF` 或任何别的哨兵值，同样都可能是数据本身。
6. **`m` / `n` 混用** —— `matrix.length` 是行数、`matrix[0].length` 是列数；`2 × 3` 矩阵里用 2 当列数会漏掉一整列。
7. **`1 × 1` 与 `1 × n` 的循环边界** —— 内部循环用 `i < m && j < n` 起于 1，`m == 1` 时一次都不执行，这是**正确**的；但如果写成 `i <= m` 就越界。

### 148.6.3 面试官最爱追问的三个问题

**Q1：为什么必须单独记录首行和首列是否为零？**

> 「因为首行首列被借来当标记板了：`matrix[i][0]` 表示『第 `i` 行要清』、`matrix[0][j]` 表示『第 `j` 列要清』。可首行首列**自己**也属于矩阵，它们是否整体清零是另外一件事，标记位表达不了。而且一旦阶段 1 往首行写了 0，原来的值就没了——所以必须在改动任何格子之前，用两个布尔量把它记下来。从信息论上看，这件事本来就需要 2 bit，少一个都不行。」

**Q2：为什么「标记写进去的 0」不需要恢复？**

> 「因为它正好就是正确答案。如果 `matrix[0][j]` 被写成 0，说明第 `j` 列里原来有 0，那么按题意 `(0, j)` 这一格本来就该变成 0。所以『标记』与『结果』在这里是同一件事。真正需要额外信息的是『整行/整列是否清零』这种粗粒度判断，那才需要两个布尔量。」

**Q3：如果只允许你清行、不清列呢？空间还能更省吗？**

> 「能。只需要 `m` 个标记位，用首列 `matrix[i][0]` 就够了，而且连『首列是否要清』都不用管（因为不清列）。只剩一个布尔量：`firstRowZero`——它回答『第 0 行要不要清』。这就是为什么『问题约束越窄，可复用的空间就越多』，也是原地题的通用思路：先数清楚需要多少 bit 的状态，再从输入里找地方放。」
