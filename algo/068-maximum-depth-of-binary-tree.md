## 068.1 题目

**原题链接**：<https://leetcode.cn/problems/maximum-depth-of-binary-tree/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root`，返回它的**最大深度**：从根节点到**最远叶子节点**的路径上，**节点的个数**。

一句话就说完的题，藏了五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 深度数的是**节点个数**，不是边数 | 「根节点到叶子节点的**最长路径上的节点数**」 | 把边数当深度：单结点树返回 `0`，应为 `1` |
| **空树深度为 0** | 样例 `root = [] → 0` | 空树返回 `1` → 判错；这是本题第一失分点 |
| 终点是**叶子**（左右孩子都空） | 「最远**叶子**节点」 | 把「最后一个非空节点」当叶子 → 在单孩子链上算多一层/少一层 |
| 只算**最长**那一条 | 「最大深度」 | 求成最小深度，是 LC 111 的题（它有个更阴的坑，见 §068.7） |
| 节点值**与答案无关** | 值域 `-100..100` | 想用值做标记、做累加 → 白费力气 |

> 📌 **本章在全书里的位置**：这是第 8 部分**唯一指定要讲「双范式」**的一章。
> 从本章起，本书写任何树递归都会先问一句：**这道题该「自顶向下传参」还是「自底向上返回值」？**
> 后面 069（前序交换）、070（镜像双指针）、071（直径，返回值≠答案）、072（回溯带参）、073（前缀和带参）、074（树形 DP 返回值）、080（选/不选两返回值）全部是这条语言的应用。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `[0, 10⁴]` | 最多 1 万 | 递归深度最坏 `10⁴`，Java 默认栈（约 512 KB~1 MB、1 万层上下）**刚好在边缘**；Go 的 goroutine 栈可自动增长，安全 |
| `-100 <= Node.val <= 100` | 与答案无关 | 本题是纯结构问题，不需要看值 |
| 树不保证平衡 | 可能是全左链 | 链状树 `h = n = 10⁴`，这是**栈深上界**的真实来源 |
| 返回 `int` | 单个整数 | 不需要收集路径，也不需要额外容器 |

> 💡 **量级 → 算法**：`n ≤ 10⁴` 时 O(n) 与 O(n·h) 都能过。
> 本题的考点不是复杂度，而是**递归的两种信息流向**：数据是「从上面下来」还是「从下面上去」。
> **把这件事想清楚，后面 13 章（069–081）都能对号入座；想不清楚，就会每道题都重新试一遍。**

### 示例

```
示例 1
输入：root = [3, 9, 20, null, null, 15, 7]
输出：3

                   3            ← 深度 1
                ┌──┴──┐
                9     20        ← 深度 2
                     ┌┴┐
                    15  7       ← 深度 3（叶子）
   最长路径：3 → 20 → 15（3 个节点），所以最大深度 = 3

示例 2
输入：root = [1, null, 2]
输出：2

        1
         \
          2        ← 最长路径 1 → 2，2 个节点

示例 3
输入：root = []
输出：0
```

### 我自造的三个反例（写完必须拿它们打一遍）

```text
① 空树 []                       → 暴露「return 1 写死」和「全局 max 初值 0 却忘了判空」
② 全左链 1←2←3←4（只有 left）    → 暴露「只递归右子树」或「只递归左子树」的单边错误
③ 全右链 1→2→3（只有 right）     → 暴露「转过一次弯就停了」的写法（见下方 068.2 的第三个念头）
```

第 ③ 条最值得记：它对应一个极常见的误读 —— 把「深度」当成「最左链的长度」。这类写法在**全左链**上完美通过，在**全右链**上却只剩 1（见 §068.2 第三个念头）。所以自测的树形必须成对准备：全左链和全右链各一棵。

## 068.2 从暴力到最优：第一个念头为什么错

### 第一个念头：把所有「根到叶子」的路径都列出来，取最长

```java
void collect(TreeNode node, List<Integer> path, List<List<Integer>> all) {
    if (node == null) return;
    path.add(node.val);
    if (node.left == null && node.right == null) all.add(new ArrayList<>(path)); // 叶子：整条路径存下来
    else { collect(node.left, path, all); collect(node.right, path, all); }
    path.remove(path.size() - 1);
}
// 答案 = all 里最长的那个路径长度
```

- 时间 **O(n·h)**（每条路径长度最多 `h`，且每条路径都要 `copy` 一份），空间 **O(n·h)** —— 一棵满二叉树有 `n/2` 条叶子路径，每条约长 `log n`，总存储 `O(n log n)`；链状树只有 1 条路径但长度 `n`。
- 它**是对的**，LeetCode 上也能过（`n ≤ 10⁴`）。
- 但它在做**无用功**：题目只要一个数，你却把**所有路径都物化**了。`n = 10⁴` 时内存里塞着几十万个 `Integer`，而正确答案的规模只是一个 `int`。

### 第二个念头：自顶向下传参，到叶子时更新全局最大值

```java
int best = 0;
void dfs(TreeNode node, int depth) {          // depth 从 1 开始（根算第 1 层）
    if (node == null) return;
    best = Math.max(best, depth);             // 每到一个节点都可以更新（不一定是叶子）
    dfs(node.left,  depth + 1);
    dfs(node.right, depth + 1);
}
```

- 时间 **O(n)**，空间 **O(h)**。**这是完全正确的解法**，而且思路自然：既然深度是「根到当前节点的层数」，那就在走的过程里把层数带下去。
- 它的代价只有两处：
  1. 需要一个**外部变量** `best`（字段或引用参数）—— 它打破了「函数只靠参数和返回值通信」的纯粹性，多线程/多次调用都要小心重置；
  2. `depth` 这个参数，本来就是「调用方已经知道的信息」，**写起来比「返回值」多一层簿记**。
- 这个念头**不该被否定**，它是本章 §068.3.3 要正式立住的**范式一**。只是本题还有更短的写法。

### 第三个念头：只沿一条边走（把「最深」误读成「最左链」）

```java
int depth = 0;
TreeNode cur = root;
while (cur != null) {      // ❌ 只走 left
    depth++;
    cur = cur.left;
}
return depth;
```

- 时间 **O(h)**、空间 **O(1)**，复杂度漂亮得让人想立刻交卷 —— 但它在**全右链** `[1,null,2,null,3]` 上返回 `1`，正确答案是 `3`。
- 它的错误非常隐蔽：只要每层的最深节点都恰好在左侧，它就对。而这正是「随机构造、随手自测」最容易造出来的树形。

同样危险的变体是**只递归一边**：

```java
return root == null ? 0 : 1 + maxDepth(root.left);   // ❌ 右子树被彻底无视
```

- 这个版本连 `n = 1` 的样例都能过（单结点时左右都空）；但只要根的右子树更深就立刻错。
- **共同教训**：本题的「max」是**不可省掉的比较**，删掉任何一半都等于把「最大值」换成了「某个方向的值」。**104 的递推式必须同时看两个孩子。**

### 卡点在哪

把三个念头并排看，卡点很清楚：

> **父节点能不能自己算出深度？** 不能 —— 它只知道自己有两个孩子，不知道「每个孩子下面还有多深」。
> 这个信息只能**由子节点算完再交上来**。

也就是说，本题的答案本质上是「**子树的函数**」：

```
h(空) = 0
h(v)  = 1 + max( h(v.left), h(v.right) )
```

这里有个细节必须点明：**`h` 是一个「返回值」，不是一个「参数」**。`depth` 是往下传的（范式一），`h` 是往上传的（范式二）。同一道题两种写法，差别全在这个方向上。

### 灵感的来源 —— 「先算两棵子树，再合并」

后序遍历（065 术语）的执行顺序天然是「左子树算完 → 右子树算完 → 处理自己」。而「处理自己」这一步需要的信息，恰好就是两棵子树刚刚算完的高度：

```
后序时间线：
  进入 v
    ├─ 递归左子树 → 拿到 h(left)       ← 左边交上来了
    ├─ 递归右子树 → 拿到 h(right)      ← 右边交上来了
    └─ 计算 h(v) = 1 + max(...)        ← 此刻才可能算出来
```

> 一句话：**「什么时候能算」决定「用哪种遍历」**。
> 需要子树结果才能算自己 ⟹ 后序（自底向上返回值）。
> 算自己不需要子树结果、而是子树需要自己提供信息 ⟹ 前序（自顶向下传参）。
> 这条判据是本书 069–081 全部递归题的第一道分岔口。

## 068.3 原理拆解

### 068.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| **后序递归（自底向上返回值）** ✅ 首选 | O(n) | O(h) 系统栈 | 5 行 | 链状树 `h = 10⁵` 时 Java 爆栈 |
| **自顶向下传参 + 全局 max** ✅ 并列范式 | O(n) | O(h) 系统栈 | 8 行 | 需要外部状态；多线程/重复调用要重置 |
| BFS 层计数（数层数） | O(n) | O(w) 队列 | 10 行 | 宽树内存大；但**链状树只有 O(1) 空间**，正好补递归的短板 |
| 显式栈后序（065 的迭代写法） | O(n) | O(h) 堆栈 | 25 行 | 代码长；只在「不许递归」的硬性要求下才值得 |
| Morris 式 O(1) 求高度 | O(n) | O(1) | 40+ 行 | 常数大、会改树，实战几乎不用，只用于秀「O(1) 空间」 |
| 物化所有根到叶路径取最长 | O(n·h) | O(n·h) | 20 行 | 只要一个数却存了全部路径，纯浪费 |

**为什么后序递归是首选**：

- 它与问题的数学定义（`h(v) = 1 + max(h(l), h(r))`）**一字不差**，读代码的人不需要在脑子里再翻译一遍；
- 不需要任何外部状态，**天然可重入**（同一个函数对象可以并发调用）；
- 空间与 BFS 同阶（都是 O(h) 对 O(w)），但常数更小（无队列分配）。

**什么时候改用 BFS**：树极深（链状）时递归有爆栈风险，而链状树的 `w = 1`，BFS 只用 O(1) 额外空间 —— **深树用 BFS、宽树用递归**，这条经验在 §068.6.1 有量化对比。

### 068.3.2 为什么这个做法是对的（正确性论证）

**定义**：一棵树（或空树）的**深度** `d(T)` = 「根到最远叶子的路径上的节点数」；空树的 `d(∅) = 0`。

**命题**：对任意节点 `v`，算法返回的 `h(v)` 满足 `h(v) = d(子树 v)`。

**证明（对树高做结构归纳）**：

1. **基例**：`v == null`。此时子树是空树，`d(∅) = 0`，而算法返回 `0`。成立。
2. **归纳假设**：对 `v` 的左右孩子 `l`、`r`（若存在），`h(l) = d(l)`、`h(r) = d(r)` 成立。
3. **归纳步**：`v` 的子树里，任何一条「根到叶」的路径必然是 `v` 自己，接上「`l` 的某条根到叶路径」或「`r` 的某条根到叶路径」。因此
   - 若 `v` 是叶子（`l = r = ∅`）：唯一的路径是 `[v]`，`d = 1`。算法给 `1 + max(0, 0) = 1`。成立。
   - 否则：`d(子树 v) = 1 + max(d(l), d(r))`（路径第一步要么往左要么往右，取更长的那支），由归纳假设即 `1 + max(h(l), h(r))`，正是算法算出的值。成立。
4. 由结构归纳，对所有节点成立，故对根节点成立。∎

**再证「空树的返回值必须是 0，不能是 1」**：由基例可见，`h(∅) = 0` 是让递推式在「叶子」处算出 `1` 的**唯一**选择：`1 + max(h(∅), h(∅)) = 1` 才是叶子的正确深度。如果令 `h(∅) = 1`，叶子就会算出 `2`，全树整体偏大 1。∎

> **这一小段是本章最值钱的地方**：它解释了 065 §3.3「问 2：`null` 该返回什么空单位元」为什么是正确性的一半。
> 同一个位置，068 要返回 `0`（高度），074（最大路径和）要返回 `0`（贡献可以为零），071（直径）的**全局答案**初值要 `0` 但**返回值**是单边高度 `0`，070（对称）要判 `null == null` 为真 —— **每道题的空单位元都不同，必须每题单独推一遍。**

### 068.3.3 通用解题思路（本章核心：双范式对照）

#### ① 两个范式的正面对照（全书最重要的一张表，后续 069–081 反复回查）

| 维度 | **范式一：自顶向下传参**（带 `depth` / `path` / `prefix`） | **范式二：自底向上返回值**（`return h(v)`） |
| --- | --- | --- |
| 信息流向 | 父 → 子（把「我已知的上下文」传下去） | 子 → 父（把「子树算出的结果」交上来） |
| 递归位置 | **前序**：进入节点先干活，再递归孩子 | **后序**：先递归孩子，拿到结果再干活 |
| 需要的外部状态 | 需要（全局 `best` / 引用参数 / 容器），因为答案在「路上」产生 | 不需要，答案就是根节点的返回值 |
| 空节点要返回什么 | **不需要**（`null` 直接 `return`，因为参数已携带全部信息） | **必须给出空单位元**，且必须由递推式反推（068 是 `0`） |
| 答案存放在哪 | 全局变量 or 容器（如 072 的 `path` 快照） | 函数返回值（如 068 的 `h(root)`） |
| 能否提前终止 | ✅ 容易（找到答案即 `return`） | ❌ 难（要算完两棵子树才能返回） |
| 典型风险 | 全局变量忘记重置；多线程不安全；`path` 忘了「撤销选择」 | 空单位元选错（最常见）；返回值和答案不是同一个东西（071 的坑） |
| 本书代表题 | 069（前序交换）、072（回溯 + 撤销）、073（路径前缀和）、067 的 DFS 版 | **068（本章）**、070、071、074、080 |
| 一句话记忆 | 「**答案在路径上，边走边记**」 | 「**答案在子树上，算完再交**」 |

#### ② 同一道题的两种写法（本章要求：必须都写出来）

**范式二（自底向上返回值）**：

```text
h(node):
    if node == null: return 0                     # 空单位元 0
    lh = h(node.left)                             # 先算左
    rh = h(node.right)                            # 再算右
    return 1 + max(lh, rh)                        # 最后合并自己
```

**范式一（自顶向下传参 + 全局 max）**：

```text
best = 0                                          # 外部状态，每次调用前必须重置
dfs(node, depth):                                 # depth 从 1 开始
    if node == null: return
    best = max(best, depth)                       # 到点即更新（不必等叶子）
    dfs(node.left,  depth + 1)
    dfs(node.right, depth + 1)
答案 = best
```

**把两者放在同一棵树上看差别**（同一棵 `[3,9,20,null,null,15,7]`）：

```
范式一（传参）：depth 从上往下流
           3  (depth=1)  best←1
        ┌──┴──┐
   9(2)      20(2)      best←2
   └交回      ┌┴┐
         15(3) 7(3)     best←3
     ↑ 每个节点只做两件事：更新 best、把 depth+1 传下去

范式二（返回值）：h 从下往上流
           3  h=3
        ┌──┴──┐
   9 h=1     20 h=2
             ┌┴┐
        15 h=1  7 h=1
     ↑ 每个节点只做一件事：等两个孩子交回高度，取 max 加 1
```

#### ③ 三问 × 双范式：本书的「树递归语言」正式定义（074–081 全靠它）

065 给了递归三问，本章把它和两个范式接起来，形成完整语言：

| 三问 | 范式一（前序 + 传参） | 范式二（后序 + 返回值） |
| --- | --- | --- |
| **问 1 做什么** | 「记录/判断/交换」放在**进入节点时**；孩子拿到的是「更新后的上下文」 | 「合并」放在**两棵子树都回来之后**；孩子之间互不通信，只和父通信 |
| **问 2 何时停** | `node == null` 直接 `return`（**不返回任何值**） | `node == null` 返回**空单位元**，这个值必须能代回递推式 |
| **问 3 返回什么** | 不需要返回值（答案在全局状态里）；如果非要返回，通常返回 `boolean`（如 072 的「找到就停」） | 返回「**父节点需要的那份信息**」—— 注意它**常常不是题目要的答案**（071 直径 / 074 最大路径和） |

> 🧭 **本章要背走的判据**（后续每章第一句话都该是它）：
> **「算自己需要子树的结果吗？」需要 ⟹ 后序返回值；不需要、而是子树需要我提供上下文 ⟹ 前序传参。**

#### ④ 双语言骨架（两种范式并排，可直接套到 069–081）

```text
# 范式二：返回值（后序）
int h(node) { if (node == null) return UNIT; a = h(node.left); b = h(node.right); return COMBINE(a, b, node); }

# 范式一：传参（前序）
void dfs(node, ctx) { if (node == null) return; UPDATE(ctx, node); dfs(node.left, NEXT(ctx)); dfs(node.right, NEXT(ctx)); }
```

### 068.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成**最小深度**（LC 111） | `max` → `min` | **必须**加单边特判：只有一个孩子时不能取到 `0` —— 空孩子不是叶子，不构成路径终点（详见 §068.7） |
| 树的深度定义改成**边数** | 答案整体减 1 | 只需把 `h(∅)` 改成 `-1`；这是「空单位元跟着定义走」的直接体现 |
| 树是 **N 叉**（LC 559） | 孩子个数不定 | `best = 0; for c in children: best = max(best, h(c)); return 1 + best;` —— 语义完全一致 |
| 只问**某一条路径**（如根到某个值） | 不需要最大 | 换成范式一（传 `path`），找到就停 → 072 |
| 树**极深**（`h = 10⁶` 链状） | 递归爆栈 | BFS 数层（链状树 `w = 1`，空间 O(1)）；或显式栈后序（065 §3.3 ②） |
| 要**每一层的深度分布** | 不只要最大值 | 层序遍历（066）逐层计数；或 DFS 传参 + 按 `depth` 建桶 |
| 要在**动态插入**的树上反复查深度 | 每次 O(n) 太慢 | 每个节点缓存子树高度，插入/删除时回溯更新祖先（O(h) 每次）→ 平衡树 / 线段树的思路 |

## 068.5 双语言实现

### 068.5.1 Java

**主解（范式二：后序返回值）**：

```java
// LeetCode 判题环境已内置 TreeNode，粘贴到网页时不要重复定义：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode(int val) { this.val = val; }
// }

class Solution {
    public int maxDepth(TreeNode root) {
        // 空树的深度定义为 0 —— 这个 0 不是"随便写的默认值"，
        // 而是让叶子的 1 + max(0,0) = 1 成立的唯一选择（见 §068.3.2）
        if (root == null) {
            return 0;
        }
        int lh = maxDepth(root.left);    // 左子树交回高度
        int rh = maxDepth(root.right);   // 右子树交回高度
        return 1 + Math.max(lh, rh);     // 自己算一格，取更深的那个分支
    }
}
```

**备解（范式一：自顶向下传参 + 全局最大）**：

```java
class Solution {
    public int maxDepth(TreeNode root) {
        dfs(root, 1);            // 根算第 1 层
        return best;
    }

    // 写成字段而不是局部变量：因为递归调用之间要共享它。
    // 坑：多个测试用例共用同一个 Solution 实例时必须重置（LeetCode 每题新实例，安全）
    private int best = 0;

    private void dfs(TreeNode node, int depth) {
        if (node == null) {
            return;              // 传参范式不需要"空单位元"，参数已带够信息
        }
        best = Math.max(best, depth);   // 每到一个节点就更新：不必等到叶子，
                                        // 因为"更深"必然发生在更早被访问的节点上，
                                        // 用 max 累积即可覆盖到所有节点
        dfs(node.left,  depth + 1);     // ctx 往后传
        dfs(node.right, depth + 1);
    }
}
```

### 068.5.2 Go

**主解（范式二）**：

```go
package main

// LeetCode 判题环境已内置该定义，本地编译时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func maxDepth(root *TreeNode) int {
	if root == nil {
		return 0 // 空单位元；写成 1 会让所有叶子多算一层
	}
	lh := maxDepth(root.Left)
	rh := maxDepth(root.Right)
	if lh > rh { // Go 1.20 之前 math.Max 只支持 float64，这里手写比较更直接
		return lh + 1
	}
	return rh + 1
}
```

**备解（范式一）**：

```go
package main

func maxDepthParam(root *TreeNode) int {
	best := 0 // 外部状态：闭包捕获变量本身，所以递归里改它能被外面看到
	var dfs func(node *TreeNode, depth int)
	dfs = func(node *TreeNode, depth int) {
		if node == nil {
			return
		}
		if depth > best {
			best = depth
		}
		dfs(node.Left, depth+1)
		dfs(node.Right, depth+1)
	}
	dfs(root, 1)
	return best
}
```

**备解（BFS 数层数，防爆栈）**：

```go
package main

func maxDepthBFS(root *TreeNode) int {
	if root == nil {
		return 0
	}
	q := make([]*TreeNode, 1, 1024)
	q[0] = root
	head := 0
	depth := 0
	for head < len(q) {
		size := len(q) - head // 066 的 size 快照
		depth++               // 每处理完一整层，深度 +1
		for i := 0; i < size; i++ {
			cur := q[head]
			head++
			if cur.Left != nil {
				q = append(q, cur.Left)
			}
			if cur.Right != nil {
				q = append(q, cur.Right)
			}
		}
	}
	return depth
}
```

		if i < len(a) && a[i] != nil {

		}

	}

}

### 068.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 外部状态的位置 | `private int best` 字段 | 闭包捕获的局部变量 `best` | Java 字段在多实例复用时要重置；Go 闭包每次调用天然新建，**更安全** |
| 递归内部函数 | 私有方法 `dfs(...)` | 必须先 `var dfs func(...)` 声明再赋值 | 漏掉声明 → `undefined: dfs` 编译错；这是 Go 写树递归最常见的第一个报错 |
| `max` 函数 | `Math.max(int,int)` | 1.20 之前**没有**泛型 `max` | 手写 `if a > b`；若用 `math.Max` 要转 `float64`，大数会丢精度 |
| 空值 | `null` | `nil` | 判空写法不同，语义一致：都必须**在函数最开头**判 |
| 栈深 | 默认 512 KB~1 MB，约 1 万层 → `n = 10⁴` 链状树**在边缘** | goroutine 栈按需增长（可到 1 GB） | 同一段递归，Java 在 `n = 10⁵` 链上会 `StackOverflowError`，Go 不会（但也不该依赖这个） |
| 返回值 | `int` 32 位 | `int` 在 64 位平台是 64 位 | 深度最大 `10⁴`，两者都远未溢出 |

### 068.5.4 对拍测试（暴力枚举所有根到叶路径，真跑 20000 次）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：真的把所有"根到叶子"的路径都走一遍，取最长的节点数。
// 它和 maxDepth 的递推式没有任何共享逻辑，只依赖"深度 = 某条根到叶路径的长度"这个定义
func bruteMaxDepth(root *TreeNode) int {
	best := 0
	var walk func(n *TreeNode, pathLen int)
	walk = func(n *TreeNode, pathLen int) {
		if n == nil {
			return
		}
		pathLen++ // 当前节点进入路径
		if n.Left == nil && n.Right == nil {
			if pathLen > best { // 只统计到叶子的路径
				best = pathLen
			}
			return
		}
		walk(n.Left, pathLen)
		walk(n.Right, pathLen)
	}
	walk(root, 0)
	return best
}

// 造随机树：每个新节点挂到一个随机空槽，能覆盖链状 / 完全 / 稀疏各种形状
func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(201) - 100}
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(201) - 100}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

// 随机对拍：三种实现（返回值 / 传参 / BFS）vs 暴力，20000 次
func TestMaxDepthRandom(t *testing.T) {
	r := rand.New(rand.NewSource(104))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(60) // 含 n = 0 的空树
		root := randTree(r, n)
		want := bruteMaxDepth(root)
		if got := maxDepth(root); got != want {
			t.Fatalf("iter=%d 返回值版 got=%d want=%d", iter, got, want)
		}
		if got := maxDepthParam(root); got != want {
			t.Fatalf("iter=%d 传参版 got=%d want=%d", iter, got, want)
		}
		if got := maxDepthBFS(root); got != want {
			t.Fatalf("iter=%d BFS 版 got=%d want=%d", iter, got, want)
		}
	}
}

// 边界专测：空树、单结点、全左链 1..300、全右链 1..300
func TestMaxDepthEdge(t *testing.T) {
	if got := maxDepth(nil); got != 0 {
		t.Fatalf("空树应为 0，got=%d", got)
	}
	if got := maxDepth(&TreeNode{Val: 7}); got != 1 {
		t.Fatalf("单结点应为 1，got=%d", got)
	}
	for n := 1; n <= 300; n++ {
		var l, r *TreeNode
		for i := n; i >= 1; i-- {
			l = &TreeNode{Val: i, Left: l}
			r = &TreeNode{Val: i, Right: r}
		}
		if got := maxDepth(l); got != n {
			t.Fatalf("全左链 n=%d 应为 %d，got=%d", n, n, got)
		}
		if got := maxDepth(r); got != n {
			t.Fatalf("全右链 n=%d 应为 %d，got=%d", n, n, got)
		}
		if got := maxDepthBFS(l); got != n {
			t.Fatalf("全左链 BFS n=%d 应为 %d，got=%d", n, n, got)
		}
	}
}
```

> **为什么暴力要「只统计到叶子的路径」**：如果暴力写成「每到一个节点就更新 `best = max(best, pathLen)`」，那它和传参版就是同一个逻辑，等于**没有独立裁判**。用「只在叶子处收账」的写法，才真正验证了「深度 = 根到叶路径的节点数」这个定义。

## 068.6 复杂度与常见坑

### 068.6.1 复杂度推导

- **后序递归：时间 O(n)** —— 每个节点进入一次，函数体内只有 O(1) 工作（两次 `max` 比较）。没有重复访问。
- **后序递归：空间 O(h)** —— 递归栈深度等于树高。完全二叉树 `h = ⌊log₂n⌋ + 1`，链状树 `h = n`。所以**最坏 O(n)**，`n = 10⁴` 的链状树约 1 万层，正好在 Java 默认栈的边缘。
- **传参范式：时间 O(n)，空间 O(h)** —— 与后序完全相同，多的只是每次调用多一个 `int` 参数的压栈代价（常数级）。
- **BFS：时间 O(n)，空间 O(w)** —— `w` 是最宽一层。链状树 `w = 1`，**空间 O(1)**；完全二叉树 `w ≈ n/2`，空间 O(n)。

| 方案 | 时间 | 空间 | `n = 10⁴` 链状树 | `n = 10⁴` 完全树 |
| --- | --- | --- | --- | --- |
| 后序返回值 | O(n) | O(h) | 栈深 1 万，**Java 边缘** | 栈深 14，安全 |
| 传参 + 全局 | O(n) | O(h) | 同上 | 同上 |
| BFS 数层 | O(n) | O(w) | **O(1)，最安全** | O(n/2) 队列 |
| 物化所有路径 | O(n·h) | O(n·h) | O(n)（只有 1 条路径） | O(n log n) |

> **这张表的结论**：递归与 BFS 是**互补**的 —— 深树（`h` 大）用 BFS，宽树（`w` 大）用递归。面试里能说出「按树形选写法」比背复杂度更有价值。

### 068.6.2 七个真实踩过的坑

1. **空树返回 `1`** —— 最高频。`h(∅)` 必须是 `0`，否则所有叶子都多算一层、根答案整体偏大 1。
2. **把深度当成边数** —— 单结点树返回 `0`。题目要的是**节点数**；若定义改成边数，只需把 `h(∅)` 改成 `-1`。
3. **只递归一边**（`return 1 + maxDepth(root.left)`）—— 全右链上返回 `1`。这个 bug 在满二叉树上**完全测不出来**（两边一样深），必须用单链树测。
4. **把「最大深度」写成「最左链长度」** —— `while (cur != null) cur = cur.left` 在左偏树上完全正确、在右偏树上错得离谱。**104 的递推式必须同时看两个孩子**；而 111（最小深度）反而**必须**对单孩子节点特判（见 §068.7）。两道题长得一样、要求相反，别把特判搬错题。
5. **传参版忘了重置全局 `best`** —— 同一个对象连续调用两次，第二次的结果会被第一次污染。LeetCode 每题新实例所以侥幸通过，工程里是真实 bug。**修法：把 `best` 变成闭包/局部变量，或者在入口显式置 0。**
6. **BFS 版把 `size` 快照写成动态 `len`** —— 066 讲过的坑在这里复现：`depth` 会数错层数。必须 `size := len(q) - head` 先存下来。
7. **Go 里把 `math.Max` 用在 `int` 上** —— 1.20 之前 `math.Max` 只接受 `float64`，写 `math.Max(float64(a), float64(b))` 再转回 `int` 会引入转换噪音，超大值还会丢精度（`int` 超过 2⁵³ 时）。**手写 `if a > b` 最稳。**

### 068.6.3 面试官最爱追问的三个问题

**Q1：递归和迭代，你怎么选？**

> 「看两个量：树高 `h` 和层宽 `w`。递归空间是 O(h)，BFS 是 O(w)。**深树（链状）用 BFS，宽树（完全/满）用递归**：`n = 10⁴` 的链状树递归要 1 万层栈，Java 默认栈就在边缘；而链状树的 `w = 1`，BFS 只用 O(1)。反过来满二叉树 `h` 只有 14，递归毫无压力，BFS 队列却要装 `n/2` 个节点。」

**Q2：为什么 `null` 返回 `0` 是对的？换个题还一样吗？**

> 「`0` 不是随便挑的默认值，是从递推式反推出来的：叶子必须满足 `1 + max(h(∅), h(∅)) = 1`，所以 `h(∅) = 0`。**换题就完全不同**：071 直径的空孩子要返回 `0`（单边高度），但全局答案是 `left + right` 的最大值、初始 `0`；074 最大路径和的空孩子返回 `0`（因为可以「不走」这个分支，贡献为 0）；070 对称判的是 `null == null` 为真。**每道题的空单位元都要用递推式反推一遍，不能抄。**」

**Q3：不用递归、也不用队列，能求深度吗？**

> 「可以但很别扭：065 的显式栈后序（`prev` 指针版）能拿到后序序列，再在栈里额外维护每个节点的「已完成子树高度」；或者 Morris 变体 —— 用线索遍历，同时用「回溯到祖先时深度减一」的技巧记录最大深度。两者都能做到 O(1) 额外空间，代价是代码量涨 5 倍、还要改树（Morris）。**真实取舍是：除非题目硬性要求 O(1) 空间，否则递归/队列就是最优工程解。**」

**Q4（常见追问）：如果树有 10⁶ 个节点成一条链，你会怎么改？**

> 「改 BFS：链状树每层一个节点，队列长度恒为 1，空间 O(1)，完全不会爆栈。或者写显式栈的后序迭代（O(h) 但栈在堆上）。**绝对不能直接递归** —— Java 会 `StackOverflowError`，Go 虽然栈能长，但每次增长都要搬移，性能更差。」

## 附：本章小结（可背走的三句话）

```
① 父节点算不出深度，只能等子节点把 h 交上来 → h(v) = 1 + max(h(l), h(r))、h(∅) = 0
② 两个范式：自顶向下传参（前序、要外部状态、能提前终止）vs 自底向上返回值（后序、无外部状态、空单位元要推）
③ 判据只有一句：「算自己需要子树结果吗？」需要 ⟹ 后序返回值；否则 ⟹ 前序传参
```
