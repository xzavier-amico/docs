## 100.1 题目

**原题链接**：<https://leetcode.cn/problems/combination-sum-ii/>

### 题意重述（把隐含条件补齐）

给你一个**可能含重复元素**的整数数组 `candidates` 和一个目标整数 `target`，找出所有**和为目标数**的组合，要求：

- `candidates` 中的**每个数字在每个组合中只能使用一次**（同一个下标不能用两次）；
- 解集里不能包含重复的组合；
- 组合内部顺序无关，解集顺序任意。

与 [`099`](099-combination-sum.md) 相比，输入和输出两条约束**同时变严**：输入从「互不相同」变成「可能重复」，语义从「可无限复用」变成「每个下标只能用一次」。这正好把 099 的 `dfs(i)` 和 097 的同层去重**同时**拉进同一段代码。

五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **每个数字只能用一次** | 「candidates 中的每个数字在每个组合中只能使用一次」 | 写成 `dfs(i)` 会复用同一元素，`[1,1,6]` 在 `[1,1,1,6]` 上被反复产出 |
| **元素可能重复** | 「candidates 可能包含重复元素」 | 不去重会输出多份 `[1,7]`（来自不同的 `1`） |
| **去重按「值组合」判** | 「解集不能包含重复的组合」 | 只按「下标集合不同」判重 → 重复项全留着 |
| **每个数字的后代不能跨层复用** | 同第 1 条 | 这里要特别区分：`[1,1,6]` 用两个**不同下标**的 `1` 是**合法**的（只要数组里有两个 `1`） |
| **顺序任意** | 「你可以按任意顺序返回答案」 | 对拍要规范化后再比（§100.5.4） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `3 <= candidates.length <= 100` | n 最大 100 | `2^100` 全子集不可能；但**深度**被 `target` 卡死：每个数 `≥ 1`，所以深度 `≤ target ≤ 30`——树是「窄而浅」的 |
| `1 <= candidates[i] <= 50` | 值域 50 | 值域小 → 「值 → 出现次数」分组是可行路线（§100.3.4） |
| `1 <= target <= 30` | 目标很小 | 这是全章最重要的数字：**深度上界 30**，所以 `O(2^n)` 的理论上界永远不会真正到达；剪枝 + 同层去重能把树砍到与答案同阶 |
| 答案个数 < 100 | 出题人显式保证 | 说明搜索树被剪得很干净；也说明「先枚举再 set 去重」虽然能过，但错得离谱（浪费几个数量级） |

> 💡 **量级反推**：`n = 100` 与 `target = 30` 这两个数字放在一起，等于告诉你：**这题的时间不由 `n` 决定，而由 `target` 和「同值元素的重数」共同决定**。如果只盯着 `n = 100` 想「指数爆炸」，你会得出「这题不可做」的错误结论；看清 `Σ c_i ≤ target ≤ 30`，才知道树有多小。

### 示例

```text
输入：candidates = [10,1,2,7,6,1,5], target = 8
输出：[[1,1,6],[1,2,5],[1,7],[2,6]]
解释：输入里有两个 1（下标 1 与下标 5）。
      [1,1,6] 用了两个不同下标的 1 —— 合法；
      但 [1,7] 只能出现一次，不能因为「用下标 1 的 1」和「用下标 5 的 1」就输出两份。

输入：candidates = [2,5,2,1,2], target = 5
输出：[[1,2,2],[5]]

输入：candidates = [1,1,1,1], target = 2（自造）
输出：[[1,1]]                  ← 只有一个解！重数相同就算同一个组合
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [1,1,1,1], target=2      → 答案只有 [[1,1]]；不去重会输出 6 份（C(4,2)）
② [1,1], target=2          → 最小重复输入：[[1,1]]，检验「不同下标的 1 可以各用一次」
③ [2,2], target=4          → 检验「同一值只能用一次下标」与「两个 2 可以同时用」的区别
④ [5], target=3            → 目标不可达 → 空
⑤ [3,1,2,1], target=4      → 乱序 + 重复：不排序时去重行失效
```

第 ②③ 条是本章的题眼：**「每个数字只能用一次」说的是「每个下标一次」，不是「每个不同的值一次」**。所以 `[2,2]` 里两个 `2`（不同下标）可以一起用，得到 `[2,2]`；但不允许同一个 `2` 被用两次。

## 100.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 —— 「099 的代码 + set 去重」

```text
sort(candidates)
dfs(start, sum):
    if sum == target: seen.add(copy(path)); return
    for i in start..n-1:
        path.add(c[i]); dfs(i, sum + c[i]); path.removeLast()     // 注意：传的是 i
```

两个问题：

1. **`dfs(i)` 本身已经错了**：099 的 `dfs(i)` 表达「同一个下标可以反复用」。在 100 里 `[1,1,1,1], target=2` 会生成 `[1,1]`（同一个下标用两次）、`[1,1,1]`（和已超被剪）、以及大量非法组合。**语义错了，去重只能掩盖一部分症状。**
2. **即使把 `dfs(i)` 改成 `dfs(i+1)`，仍然会重复**：`[10,1,2,7,6,1,5]` 里两个 `1` 下标不同，`[1,7]` 会被生成两份（用第一个 1 / 用第二个 1），set 能兜住，但**你枚举了两遍**。

这就是「先污染后治理」的代价：`n` 里重复值越多，浪费越大。`[1,1,1,1]` 这种极端输入上，真正的答案只有 1 个，而模板要走 `C(4,2)+C(4,3)+C(4,4)=11` 条路径。

### 第二步：卡点在哪 —— 两条约束长得像，其实彼此独立

把题目要求拆开，会发现它其实是两句完全不同的话：

| 约束 | 直觉描述 | 它在树上的位置 |
| --- | --- | --- |
| **C1：每个下标最多用一次** | 「一个元素不能拿两次」 | 影响**纵深**：递归参数 `i` → `i+1` |
| **C2：值组合不能重复** | 「两个不同的 1 换来的是同一个组合」 | 影响**横向**：同一层里等值的兄弟只走第一个 |

这两条约束**互相独立**：

- 只做 C1（`i+1`，不去重）→ 结果是「下标组合」的全部子集，会有重复的**值组合**；
- 只做 C2（同层去重，但 `dfs(i)` 复用）→ `[1,1,1]` 在只有一个 `1` 的数组上也会被生成，超出「下标」的物理限制；
- 两个都做 → 才是 100 的正解。

**卡点因此是：「一个 `for` 循环里要放两个判断，而且它们服务于完全不同的目的」。** 大多数人只写了 C1（因为 098/099 刚讲过 `i+1`），然后在样例上看到重复却想不通为什么。

### 第三步：灵感的来源 —— 排序把「等价」变成「相邻」

C2 的正确实现依赖一个物理事实：**相同值的元素在排序后是连续的一段**。于是「同一层里值相同的兄弟」就变成了「`for` 循环里紧挨着的两次迭代」，判重只需比较 `c[i]` 与 `c[i-1]`：

```text
排序后： c = [1, 1, 2, 5, 6, 7, 10]
              ↑  ↑
           第 1 个与第 2 个 1：同层时只走第一个 → 子树完全同构，剪掉第二个
```

而「跨层用第二个 1」是被允许的：选了第 1 个 `1` 之后，下一层的 `start` 正好指向第 2 个 `1`，此时 `i == start`，`i > start` 为假，不被剪 —— 于是 `[1,1,6]` 可以生成。

**这正是 097 那张「同层跳 / 跨层不跳」图在组合题里的复刻**，只是收集条件从「每个结点」换成了「`sum == target`」，并且多了一个 `break` 剪枝。

### 第四步：把三条代码写对（缺一不可）

```text
sort(candidates)                                   // 前提：让相同值相邻
dfs(start, sum):
    if sum == target: ans.add(copy(path)); return  // ① 收集
    for i in start..n-1:
        if i > start && c[i] == c[i-1]: continue   // ② C2：同层去重
        if sum + c[i] > target: break              // ③ 可行性剪枝（依赖升序）
        path.add(c[i]); dfs(i + 1, sum + c[i]); path.removeLast()   // C1：i+1
```

**三条判断的先后顺序也有讲究**：`continue`（去重）放在 `break`（超限）之前还是之后，结果一样，但**语义上先去重更清晰**——去重是「这一支与上一支等价」，与和值无关；而 `break` 是「这一支及其后所有支都不可行」。若把 `break` 放前面，遇到超限时直接终止，去重判断就没机会执行（结果仍正确，只是顺序上要能说清理由）。

## 100.3 原理拆解

### 100.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 099 模板（`dfs(i)`）+ set 去重 | 指数且在重复值上暴增 | `O(答案数)` 的 set | 15 行 | **语义错误**：允许复用下标，`[1,1]` 在单 `1` 数组上也能生成；只能靠 set 兜底 |
| `dfs(i+1)` + set 去重 | `O(2^n · ...)` | 同上 | 14 行 | 枚举量是「下标组合数」而非「值组合数」，重复值多时差数量级；不满足「不许额外空间」的追问 |
| 先按值分组，再枚举每组的取用个数 | `O(∏(cnt_v+1))` | `O(答案数)` | 25 行 | 需要先建频次表；输出顺序不是字典序；代码更长 |
| **排序 + `dfs(i+1)` + 同层去重 + 和值 `break`** ✅ | `O(S)`（S = 树结点数，与答案同阶） | `O(target)` 栈 | **14 行** | 入参不允许修改时要先拷贝；值域极大时排序成本上升（本题值域 50，无影响） |

**为什么选最后一行**：它是 099 与 097 两个模板的**交集**，各贡献一条约束，没有一行是多余的。而且它天然按字典序输出（排序 + 按值升序展开），调试时肉眼可读。

### 100.3.2 为什么这个做法是对的（正确性论证）

**引理 1（规范形唯一）**：把数组排序后，每种值 `v` 的出现构成连续区间，记其重数为 `cnt_v`。任何合法组合唯一对应一个向量 `(k_v)`，其中 `0 ≤ k_v ≤ cnt_v` 且 `Σ k_v · v = target`。

> 证明：组合是值多重集，`k_v` 就是值 `v` 在该组合里的重数；值 + 重数唯一确定多重集。∎

**引理 2（算法只产生规范路径）**：算法产生的每条路径，对每个值 `v` 取的是「该值的**前** `k_v` 个出现下标」。

> 证明（对值组归纳，与 097 §3.2 同构）：
> ① 设值 `v` 的首次出现位置为 `L_v`（连续区间的左端）。在某层的候选区间 `[start, n-1]` 中，若 `L_v ≥ start`，则本层第一个值为 `v` 的候选是 `c[L_v]`：因为 `for` 把所有 `i > start` 且与前驱同值的候选都 `continue` 了，所以本层只有「第一个 `v`」能进入分支。
> ② 进入后递归 `start' = L_v + 1`，值 `v` 的第二个出现 `L_v + 1` 满足 `i == start'`，不被剪 → 可以继续选。第三个同理。
> ③ 归纳得：每个值被选的下标必是它的前 `k_v` 个出现。∎

**引理 3（不重）**：两条不同的路径产生不同的组合。由引理 2，路径 ↔ 向量 `(k_v)` 是单射；由引理 1，向量 ↔ 组合是双射。∎

**引理 4（不漏）**：任意合法 `(k_v)` 都有路径生成。

> 按键值递增依次决策：对每个 `v`，连续走 `k_v` 次「选 `L_v + j`」（引理 2 的 ② 保证这些边都未被剪）；每走一步 `sum` 增加 `v ≥ 1`，且 `Σ k_v·v = target`，因此过程中的 `sum` 始终 `≤ target`，不会被 `break` 打断；最后 `sum == target` 时收集。∎

**引理 5（剪枝安全）**：`candidates` 升序时，若 `sum + c[i] > target`，则本层所有 `i' ≥ i` 的分支都不可能产出解（证明同 099 的引理 3：候选全为正，`sum` 单调增）。

**定理**：输出 = 全部合法组合，每个恰好一次。∎

> **这个论证最值得记的一点**：剪枝（引理 5）与去重（引理 2）的证明**用的不是同一套工具**——「剪枝安全」只要「被砍的分支里没有解」，而「去重正确」要「保留下来的路径恰好覆盖全部规范形」。**混在一起想，就会写出「既漏解又重复」的代码。**

### 100.3.3 通用解题思路（可迁移的那一层）：两条独立约束

本章要装进工具箱的是一张「约束 → 代码」的映射表：

```text
┌────────────── 约束 → 代码：两张互不干扰的开关 ──────────────┐
│                                                            │
│   C1 「每个下标只能用一次」                                   │
│       → 递归参数 i + 1                                      │
│       → 少写 = 允许复用（099）；写成 start = 允许换序（重复解）│
│                                                            │
│   C2 「值组合不能重复」                                      │
│       → 排序 + if (i > start && c[i] == c[i-1]) continue     │
│       → 少写 = 同值元素产生等价路径（重复解）                  │
│       → 多加（无条件跳过同值）= 连 [1,1] 也剪掉（漏解）        │
│                                                            │
│   C3 「和不能超过 target」                                   │
│       → 排序 + if (sum + c[i] > target) break                │
│       → 少写 = 白跑（慢），写成 continue = 慢但不影响正确性   │
│                                                            │
│   三者的判定互相独立：C1 管纵深，C2 管横向，C3 管边界          │
└────────────────────────────────────────────────────────────┘
```

**四个同类题的最小差异表（背下来这一张，本部分就通了）**：

| 题 | C1 下标复用 | C2 同层去重 | C3 和值剪枝 | 关键代码差异 |
| --- | --- | --- | --- | --- |
| [LC 78 子集](https://leetcode.cn/problems/subsets/) | 否（`i+1`） | 不需要（值不重复） | 无目标和 | 收集在每个结点 |
| [LC 90 子集 II](https://leetcode.cn/problems/subsets-ii/) | 否（`i+1`） | **必须** | 无目标和 | 097 的写法 |
| [LC 39 组合总和](https://leetcode.cn/problems/combination-sum/) | **是**（`i`） | 不需要（值不重复） | `sum > target → break` | 099 的写法 |
| [LC 40 组合总和 II](https://leetcode.cn/problems/combination-sum-ii/) | 否（`i+1`） | **必须** | `sum > target → break` | **本章**：三者齐全 |

统一骨架（本章版）：

```text
sort(c)
void dfs(int start, int sum, path) {
    if (sum == target) { ans.add(copy(path)); return; }
    for (int i = start; i < n; i++) {
        if (i > start && c[i] == c[i-1]) continue;   // C2 同层去重
        if (sum + c[i] > target) break;              // C3 可行性剪枝
        path.add(c[i]);                              // ③(a)
        dfs(i + 1, sum + c[i], path);                // C1 下标不复用
        path.removeLast();                           // ③(b)
    }
}
```

属于「两条约束叠加」这个模型的题：

| 题 | C1 | C2 | 备注 |
| --- | --- | --- | --- |
| [LC 47 全排列 II](https://leetcode.cn/problems/permutations-ii/) | 用 `used` 表达 | 用 `!used[i-1]` 表达 | 序列而非组合，所以 C1 的写法换了 |
| [LC 491 非递减子序列](https://leetcode.cn/problems/non-decreasing-subsequences/) | 子序列天然不复用 | 每层用 `set` 记录已用值 | **不能排序**，所以 C2 换成逐层 set |
| [LC 15 三数之和](https://leetcode.cn/problems/3sum/) | 双指针跳过 | 外层 `i > 0 && nums[i]==nums[i-1]` | C2 在外层循环，C1 由双指针保证 |
| [LC 216 组合总和 III](https://leetcode.cn/problems/combination-sum-iii/) | `i+1` | 不需要（1..9 互不相同） | 另有「个数」剪枝 |

### 100.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 元素**可重复使用** | C1 变「是」 | 递归传 `i`；但此时 C2 不能再用 `i>start` 判（同一值要能反复用）→ 变成 099 的题型 |
| 只要**方案数** | 输出退化 | 「多重子集和计数」DP：对每个值组做一次「0/1 背包 + 组内多重选择」`dp[s] += dp[s-k·v]`，`O(n·target)` |
| `candidates` **不允许修改** | 排序破坏入参 | 先 `copy` 再排序（`O(n)` 空间）；或建「值 → 频次」表后按值枚举 |
| 值域**极大**（`10^9`） | 排序仍可，频次桶不行 | 排序 + 同层去重照样成立；放弃「按值分组」路线 |
| 要求输出**字典序** | 有序性 | 排序 + 按值升序展开天然字典序；解法无需改动 |
| 每个数字可以用**有限次 k** | 介于 099 与 100 之间 | 递归传 `i`，并在状态里记「当前值已用次数」，达到 `k` 才推进到 `i+1` |

## 100.4 图解推演

### 100.4.1 `candidates = [1,1,2,5,6,7,10], target = 8` 的决策树（排序后）

```text
                             dfs(start=0, sum=0, [])
     ┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
   i=0(1)     i=1(1)     i=2(2)     i=3(5)     i=4(6)     i=5(7)     i=6(10)
   sum=1     ⊘剪枝(i>0     sum=2      sum=5      sum=6      sum=7     ⊘ 8+10>8
             且同值)                                        │          break
      │                    │          │          │        sum=8 ✅ [7]… 等等
      │                    │          │          │
  ┌───┼───┬───┐        ┌───┼───┐      │          │
 i=1 i=2 i=3 i=4      i=2 i=3 i=4    …          …
 (1) (2) (5) (6)
sum=2 sum=3 sum=6 sum=7
  │     │     │     │
  │     │     │   +1? 无 → 但 sum=7 需要 1，已无候选 → 无解
  │     │   sum=6+? : i=4(6) → 12 > 8 break …
  │   sum=3 …
  ▼
sum=2, path=[1,1]
  │
 i=2(2): sum=4
  │
 i=2(2)?? 不行：C1 要求 i+1 → 下一层从 3 开始
 ...
 最终命中三条：
   [1,1,6]  ← 两个不同下标的 1 + 6 = 8
   [1,2,5]  ← 第二个 1 在跨层时可用（i==start 不剪）
   [1,7]    ← 只保留「用第一个 1」这一份
   [2,6]
```

**读图要点**：根结点的 `i=1`（第二个 `1`）被 C2 剪掉，所以 `[1,…]` 开头的所有组合只从 `i=0` 出发一次；而 `i=0` 之后的**下一层**里，`i=1` 是 `start`（等于 1），`i > start` 为假，于是「第二个 1」在深层仍然可用 —— `[1,1,6]` 正是这么来的。

### 100.4.2 逐行执行轨迹（`candidates=[1,1,2], target=3`）

| 步 | 调用 | `path` / `sum` | 判定 | 结果 |
| --- | --- | --- | --- | --- |
| 1 | `dfs(0,0)` | `[]` / 0 | `i=0`(1)：不剪 | 进入 |
| 2 | `dfs(1,1)` | `[1]` / 1 | `i=1`(1)：`i==start` 不剪 → 进入；`i=2`(2)：3 ≤ 3 → 进入 | 两条边 |
| 3 | `dfs(2,2)` | `[1,1]` / 2 | `i=2`(2)：`2+2=4 > 3` → `break` | 无解分支 |
| 4 | `dfs(3,3)` | `[1,2]` / 3 | `sum == target` → 收集 `[1,2]` | ✅ |
| 5 | 回 `dfs(1,1)` 后 `i=2` | `[1,2]`→撤销 | 已收集过，撤销回 `[1]` | — |
| 6 | 回 `dfs(0,0)` 的 `i=1` | `[1]`(第二个 1) | `i>start && c[1]==c[0]` → **`continue` 剪掉** | ⊘ |
| 7 | `dfs(0,0)` 的 `i=2` | `[2]` / 2 | 下一层从 3 开始（无候选） | 无解 |

**注意第 6 步**：根层的第二个 `1` 被剪，避免 `[1,2]` 被生成两次（一次用下标 0 的 1、一次用下标 1 的 1）。**注意第 3 步**：`break` 在 `i=2` 触发，若数组后面还有更大的值，它们也一并放弃——因为已升序，全都超。

### 100.4.3 三条判断的「谁管哪一维」

| 判断 | 影响树的哪个方向 | 去掉它会怎样 | 相关题 |
| --- | --- | --- | --- |
| `dfs(i+1)` | **纵深**（下一层从哪开始） | 变成「元素可复用」，`[1,1,1]` 在单 `1` 数组上也出现 | 099 |
| `i > start && c[i]==c[i-1] → continue` | **横向**（同一层的兄弟） | 同一值产生多份等价路径 → 重复解 | 097 / 102 / 491 |
| `sum + c[i] > target → break` | **边界**（本层剩余候选全废） | 结果不变，但要多搜索大量超限分支 | 099 / 100 |

## 100.5 双语言实现

### 100.5.1 Java

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        // 排序有两个作用：① 让相同值相邻（同层去重的前提）② 让 break 剪枝成立
        Arrays.sort(candidates);

        List<List<Integer>> res = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        dfs(candidates, 0, 0, target, path, res);
        return res;
    }

    private void dfs(int[] c, int start, int sum, int target, List<Integer> path, List<List<Integer>> res) {
        if (sum == target) {
            res.add(new ArrayList<>(path));
            return;                       // 已命中，再加正数必超
        }

        for (int i = start; i < c.length; i++) {
            // C2 同层去重：i > start 说明不是本层第一个候选；
            // 与前一个值相同 → 它和刚走完的兄弟等价，子树同构 → 整枝跳过
            if (i > start && c[i] == c[i - 1]) {
                continue;
            }
            // C3 可行性剪枝：升序 → 当前候选已超，后面的更大，全部不可行
            if (sum + c[i] > target) {
                break;
            }
            path.add(c[i]);                                  // ③(a) 选择
            dfs(c, i + 1, sum + c[i], target, path, res);    // C1：i+1 → 每个下标只用一次
            path.remove(path.size() - 1);                    // ③(b) 撤销
        }
    }
}
```

### 100.5.2 Go

```go
package main

import "sort"

func combinationSum2(candidates []int, target int) [][]int {
	sort.Ints(candidates) // 同层去重 + break 剪枝的共同前提

	res := make([][]int, 0)
	path := make([]int, 0)

	var dfs func(start, sum int)
	dfs = func(start, sum int) {
		if sum == target {
			// 深拷贝：path 之后还会被其它分支改写
			res = append(res, append([]int(nil), path...))
			return
		}
		for i := start; i < len(candidates); i++ {
			if i > start && candidates[i] == candidates[i-1] {
				continue // C2 同层去重：等价兄弟只走第一个
			}
			if sum+candidates[i] > target {
				break // C3 升序 → 本层后面全部不可行
			}
			path = append(path, candidates[i])                // ③(a) 选择
			dfs(i+1, sum+candidates[i])                       // C1：i+1 → 下标不复用
			path = path[:len(path)-1]                         // ③(b) 撤销
		}
	}
	dfs(0, 0)
	return res
}
```

### 100.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 排序 | `Arrays.sort(candidates)` | `sort.Ints(candidates)` | 都原地改入参；若入参不可改要先拷贝 |
| 结果里的 `path` | `new ArrayList<>(path)` | `append([]int(nil), path...)` | **都必须深拷贝**（§100.5.4 有实测） |
| 撤销 | `path.remove(path.size()-1)` | `path = path[:len(path)-1]` | Java 的重载陷阱：`remove(c[i])` 删的是**值** |
| `continue` / `break` 混用 | 语义同 Go | 语义同 Java | 两处都容易写反：去重只能 `continue`（后面还有别的值），超限才能 `break` |
| 空结果 | `new ArrayList<>()`（空 list） | `[][]int{}` 或 `nil` | Go 返回 `nil` 时 `len` 也是 0，安全；但打印成 `[]` 更直观 |

#### ⚠️ Go 切片别名：本章的实测反例

本章的路径长度通常很短（`target ≤ 30`），所以更容易出现「看起来对、其实错」的情况。我实测 `candidates=[1,1,2,5,6,7,10], target=8`：

```text
不加拷贝（错误）  res = append(res, path)
  [[7 6 5] [7 6 5] [7 6] [7 6]]
  ↑ 期望是 [[1 1 6] [1 2 5] [1 7] [2 6]]：
    内容被"最后一次写入"覆盖成了脏数据，连长度也从 3/3/2/2 那种混合状态读出来

加拷贝（正确）  res = append(res, append([]int(nil), path...))
  [[1 1 6] [1 2 5] [1 7] [2 6]]        ✓

c=[2,5,2,1,2], target=5
  不加拷贝：[[5 2 2] [5]]     ← 第一项本该是 [1 2 2]
  加拷贝  ：[[1 2 2] [5]]     ✓

c=[1,1,1,1], target=2   （只有 1 个解时看不出问题）

  加拷贝  ：[[1 1]]
```

第三组是本章最阴的一行：**只有一个解的时候，切片别名一定不会暴露**。用「最小能过的样例」手测，永远是绿灯。

```go
// 写法 1（推荐）：显式深拷贝
```

### 100.5.4 对拍测试（写完必须跑）

参考实现用**「按值分组 + 枚举每组取几个」**，与「排序 + 同层去重」的回溯思路不同。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 参考实现：把相同值归为一组，组内枚举「取 0..cnt 个」，用剩余 target 剪枝
func bruteCombSum2(c []int, target int) [][]int {
	vals := append([]int(nil), c...)
	sort.Ints(vals)
	// 分组
	type group struct{ v, cnt int }
	groups := []group{}
	for i := 0; i < len(vals); {
		j := i
		for j < len(vals) && vals[j] == vals[i] {
			j++
		}
		groups = append(groups, group{vals[i], j - i})
		i = j
	}
	out := [][]int{}
	cur := []int{}
	var rec func(g, rest int)
	rec = func(g, rest int) {
		if rest == 0 {
			out = append(out, append([]int(nil), cur...))
			return
		}
		if g == len(groups) {
			return
		}
		maxTake := groups[g].cnt
		if groups[g].v > 0 && rest/groups[g].v < maxTake {
			maxTake = rest / groups[g].v
		}
		for take := 0; take <= maxTake; take++ {
			for k := 0; k < take; k++ {
				cur = append(cur, groups[g].v)
			}
			rec(g+1, rest-take*groups[g].v)
			for k := 0; k < take; k++ {
				cur = cur[:len(cur)-1]
			}
		}
	}
	rec(0, target)
	return out
}

func normCS2(res [][]int) [][]int {
	out := make([][]int, len(res))
	for i, r := range res {
		c := append([]int(nil), r...)
		sort.Ints(c)
		out[i] = c
	}
	sort.Slice(out, func(a, b int) bool {
		if len(out[a]) != len(out[b]) {
			return len(out[a]) < len(out[b])
		}
		for k := range out[a] {
			if out[a][k] != out[b][k] {
				return out[a][k] < out[b][k]
			}
		}
		return false
	})
	return out
}

func TestCombinationSum2Random(t *testing.T) {
	r := rand.New(rand.NewSource(2026100))
	for iter := 0; iter < 4000; iter++ {

		target := 1 + r.Intn(25)

				t.Fatalf("iter=%d c=%v t=%d 第%d项 %v vs %v", iter, c, target, i, got[i], want[i])
```

## 100.6 复杂度与常见坑

### 100.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(S · L)`**，其中 `S` = 搜索树结点数，`L` = 路径长度 `≤ target/min(c) ≤ 30`。

1. **深度上界**：每个候选 `≥ 1`，每选一个 `sum` 至少 `+1`，且 `sum ≤ target`，所以深度 `≤ target ≤ 30`。
2. **每层分支数**：剪掉同值兄弟后，每层最多「不同值的个数」≤ `min(n, 50)` 条边。
3. **结点数**：因此 `S ≤ Σ_{d≤30} 50^d`，这个形式上界极大，但实际被两条剪枝压到「与答案数量同阶」——题目保证答案 `< 100` 个。
4. **每结点工作量**：拷贝路径 `O(L)`。

所以时间 `O(S·L)`，**实践中由「答案数量 × 路径长度」主导**。而不去重时 `S` 会乘上「重复值的排列数」（`[1,1,1,1]` 上是 `C(4,2)+C(4,3)+C(4,4)=11` vs 1），这就是同层去重的价值。

**空间 `O(L) = O(target)`（不含输出）**：递归深度 ≤ 30，`path` 长度 ≤ 30。

### 100.6.2 七个真实踩过的坑

1. **沿用 099 的 `dfs(i)`** —— 允许复用下标，`[1,1]` 在只有一个 `1` 的数组上也会被生成。必须改成 `i+1`。
2. **忘了同层去重** —— 输出重复组合（`[1,7]` 两份）。这一行是 097 的原样搬运，不需要改动。
3. **把 `continue` 写成不带 `i > start` 的 `continue`** —— 跨层也被剪，`[1,1,6]` 消失（`[1,1]`、`[2,2]` 这类解全丢）。单测 `[2,2], target=4` 立刻暴露。
4. **`break` 与 `continue` 用反** —— 去重的位置写 `break` 会砍掉本层后面**不同值**的候选（数组有序，`break` 意味着「全都不要」），漏解。
5. **忘了排序** —— 同层去重依赖「相同值相邻」，`[3,1,2,1]` 上 `c[i]==c[i-1]` 判不出来；`break` 也不再安全。
6. **误以为「两个 2 不能同时用」** —— 约束是「每个**下标**用一次」，所以 `[2,2]` 上取 `[2,2]` 是合法的。把它当成「每个值只能用一次」会漏掉大量解。
7. **Go 里 `res = append(res, path)`** —— 切片别名，结果被后续分支改写（§100.5.3 实测）。

### 100.6.3 面试官最爱追问的三个问题

**Q1：为什么不能只用 set 去重？**
> 「三个理由：① 语义层面，`dfs(i)` 会让「同一个下标用两次」合法化，set 兜不住这类结构性错误（它只能删重复，不能阻止非法生成）；② 效率层面，set 把复杂度乘上「重复值的排列数」，`[1,1,1,1]` 上白白多跑 10 倍；③ 空间层面，set 需要与答案同阶的额外空间，而做题的规范答案是 `O(target)` 栈。**结构层的约束永远优于结果层的补丁。**」

**Q2：`i > start` 去掉会怎样？**
> 「会漏解。去掉后 `c[i] == c[i-1]` 在任何层都生效，于是「同一个值的第二个出现」永远用不上，`[1,1,6]`、`[2,2]` 这类「重数 ≥ 2」的解全部消失。`i > start` 的作用就是把规则限定在**同层**：跨层时 `i == start`，说明这是该值在本层的第一个候选，必须允许。」

**Q3：`break` 能不能换成 `continue`？**
> 「结果一样，只是慢。`break` 依赖「数组升序 + 候选全为正」：当前候选已超，后面只会更大，全都不可能。若换成 `continue`，程序仍正确，但要把本层剩余候选逐个判一遍（099 §4.3 有实测：`[2,3,6,7], t=7` 从 16 次迭代变成 27 次）。**若数组没有排序，`break` 就变成错的**——这是它们唯一的实质性区别。」
