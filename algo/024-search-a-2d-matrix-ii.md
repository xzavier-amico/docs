## 024.1 题目

**原题链接**：<https://leetcode.cn/problems/search-a-2d-matrix-ii/>

### 题意重述（把隐含条件补齐）

给你一个 `m × n` 的整数矩阵 `matrix`，它满足：

- 每一行从左到右**升序**；
- 每一列从上到下**升序**。

给定 `target`，判断它是否出现在矩阵中，返回 `true` / `false`。

五条必须读出来的隐含条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **行**内升序 | 「每行的元素从左到右升序排列」 | 这条只保证「一行之内」可比，**不保证行与行之间的顺序** |
| **列**内升序 | 「每列的元素从上到下升序排列」 | 同上，只保证「一列之内」 |
| **没有**「下一行首 > 上一行尾」 | 题目只给了上面两条 | 所以**不能把矩阵摊平成一维再二分** —— 那是 LC 74，比本题多一个条件 |
| 元素可能**重复** | 题目没有保证互不相同 | 所以判据里只能用 `==` / `>` / `<`，不能假设严格 |
| 值域含负数 | `-10^9 <= matrix[i][j] <= 10^9` | 不能拿 0 当哨兵，也不能用值当下标 |
| 返回 `bool` | 「判断…是否存在」 | 返回下标 / 计数 → 错 |

> **最关键的是第三条**：很多人一看到「二维有序」就条件反射想摊平。**在本题摊平后的一维数组是 `[1,4,7,11,15,2,5,8,12,19,...]` 这种「先增后掉再增」的形状，不是有序的，二分直接失效。** LC 74 之所以能摊平，是因为它额外要求「每行第一个整数大于上一行最后一个整数」。**读题时少看一句约束，思路就全错。**

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `m == matrix.length`，`n == matrix[i].length` | — | 行列长度要分开取，**不能假设方阵** |
| `1 <= n, m <= 300` | 最多 9 万个元素 | 暴力 `O(mn) = 9·10⁴` 次比较，实测 Java ≈ 0.4 ms —— **能过**。所以这题和 022/023 一样：**考的是你能不能说清更优解的来源** |
| `-10^9 <= matrix[i][j] <= 10^9` | 值域大 | 前缀和 / 计数数组都用不了；比较运算本身安全 |
| 行、列各自升序 | 两条独立的单调链 | **两条单调链交叉，产生一个「阶梯」结构** —— 这就是本章的抓手 |
| 没有更强的全局有序 | 不能摊平 | 排除 O(log(mn)) 的路线（除非用更复杂的算法，见 024.3.4） |

> 💡 **量级 → 算法**：`m = n = 300` 时
> - 暴力：`m·n = 9·10⁴`
> - 每行二分：`m·log₂ n = 300 × 9 = 2.7·10³`
> - **阶梯搜索：`m + n = 600`**
>
> 阶梯搜索比「每行二分」还快一个量级，而且**代码只有 8 行**。这就是为什么它是本题的标准答案。

### 示例

```
输入：matrix = [[1,   4,  7, 11, 15],
                [2,   5,  8, 12, 19],
                [3,   6,  9, 16, 22],
                [10, 13, 14, 17, 24],
                [18, 21, 23, 26, 30]],  target = 5
输出：true

输入：matrix = 同上,  target = 20
输出：false
解释：20 不在矩阵中。注意它不是「比所有元素都大」或「都小」，而是夹在中间 —— 这才是难的地方。

输入：matrix = [[-5]],  target = -5
输出：true          ← 1×1 矩阵，i 和 j 同时到达边界

输入：matrix = [[1,4],[2,5]],  target = 2
输出：true          ← 2×2，右上角是 4，左移一次就命中
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① 1×1 命中 / 不命中          → while 条件 (i < m && j >= 0) 的边界
② 1×n 单行                   → 阶梯退化成单行右到左扫描
③ m×1 单列                   → 阶梯退化成单列上到下扫描
④ target 比右上角大但比左下角小（示例 2 的 20）
                              → 检验「一步只排除一行/列」会不会漏
⑤ target 在左下角            → 需要走完整个阶梯（m+n 步），最容易越界
⑥ target 比所有元素都小 / 都大 → 会不会在 j<0 之前就越界访问
```

⑥ 特别值得说：`target = -100`，右上角 `matrix[0][n-1] = 15 > -100`，代码会一路 `j--` 到 `j = -1`，然后 `while` 条件 `j >= 0` 为假，退出返回 `false`。**如果 `while` 写成 `j > 0`，`j = 0` 时就会提前退出，漏掉第一列。** 这是本题最常见的边界 bug。

## 024.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（逐格扫描）

```java
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        if (matrix[i][j] == target) return true;
return false;
```

- 时间 **O(mn)**，空间 **O(1)**，绝对正确。
- `m = n = 300` 时 **9·10⁴ 次比较**，Java ≈ 0.4 ms —— **能过**。
- 问题不在「能不能过」，而在「它把两条有序信息全部浪费了」。**9 万个格子，其中 99% 的比较是毫无信息量的。**

### 第二步：第一个「像样」的念头 —— 每行二分

既然每行升序，那就对每一行做一次 020 的模板 A / B：

```java
for (int i = 0; i < m; i++)
    if (binarySearch(matrix[i], target)) return true;
return false;
```

- 时间 **O(m log n)**，空间 **O(1)**。
- `m = n = 300` → `300 × 9 = 2.7·10³` 次比较，比暴力快 33 倍。

**它错在哪？** 它**完全没有用「列也升序」这条信息**。而题目给了两条信息，你只用了一条 —— 这不是「错」，是「亏」。

更具体地说：如果第 `i` 行的二分告诉我「`target` 不在这一行，且它应该在位置 `p` 插入」，那么下一行我**不必从 `[0, n)` 开始二分** —— 因为列升序意味着「第 `i+1` 行的第 `p` 个元素 ≥ 第 `i` 行的第 `p` 个元素」，所以 `target` 的插入点只会**往右移或不动**。利用这一点可以把每行的二分区间收窄，总复杂度降到 `O(m + n log n)` 甚至 `O(m + n)`。

**这个「插入点单调」的观察，就是阶梯搜索的另一条推导路径。** 下面走更直接的那条。

### 第三步：卡点 —— 全局不单调，二分的前提没了

想直接二分，就必须有一个「一次比较能排除一半候选」的判据。在本题：

| 拿 `matrix[mid_i][mid_j]` 和 `target` 比 | 能推出什么 |
| --- | --- |
| `==` | 找到了 |
| `<` | 只能推出「它的左上区域全都 `< target`」→ 排除的是**一个矩形**，但右下区域仍可能含 target，且不是「一半」 |
| `>` | 只能推出「它的右下区域全都 `> target`」→ 同理 |

问题在于：**排除的区域是矩形，而剩下的是「L 形」**。二分要求「排除后剩下的还是一段连续区间」，L 形不满足。**所以对中心点二分行不通。**

### 第四步：灵感 —— 去「角」上找，因为角落里只有两个方向

换个角度：如果我从**右上角** `matrix[0][n-1]` 出发，这个位置有什么特殊？

- 它是**第 0 行的最大值**（行升序）；
- 它是**第 n-1 列的最小值**（列升序）。

这两句话合起来，产生了一个极其锋利的性质：

```
设 v = matrix[i][j]（当前在剩余矩形的右上角）

v > target  ⇒  matrix[i][j] 是第 j 列（从第 i 行往下）的最小值
            ⇒  整列 matrix[i..m-1][j] 全都 ≥ v > target
            ⇒  这一列可以整列扔掉  →  j--

v < target  ⇒  matrix[i][j] 是第 i 行（到第 j 列为止）的最大值
            ⇒  整行 matrix[i][0..j] 全都 ≤ v < target
            ⇒  这一行可以整行扔掉  →  i++
```

**一次比较，排除一整行或一整列。** 每步要么 `i` 加一，要么 `j` 减一，所以最多 `m + n` 步走完。

**为什么左上角不行**：`matrix[0][0]` 是第 0 行的最小值、第 0 列的最小值。`v < target` 时你只知道「它在行首和列首都很小」，往右往下的邻居都可能更大 —— **没有任何方向可以排除**。`v > target` 时倒是能排除整个矩阵，但那时候你已经可以直接返回 `false` 了。**左上角是一个「两边都最小」的点，信息量为零。**

**为什么左下角也行**：`matrix[m-1][0]` 是第 `m-1` 行的最小值、第 0 列的最大值 —— 同样是「一个最大一个最小」的角。对称地，`v > target` 时排除行（`i--`），`v < target` 时排除列（`j++`）。**两个角（右上、左下）都能用，左上和右下不行。**

### 第五步：为什么这不算「二分」

必须说清：**阶梯搜索的复杂度是 `O(m + n)`，不是 `O(log)`。** 它属于本部分的「单调结构」家族，但不是二分。

| 维度 | 二分 | 阶梯搜索 |
| --- | --- | --- |
| 每步排除 | 一半候选 | 一行或一列 |
| 前提 | 一维有序（或谓词单调） | 两条正交的单调链 |
| 步数 | `log n` | `m + n` |
| 信息利用 | 1 个维度上的「位置」 | 2 个维度上的「极值」 |

**什么时候阶梯搜索最优？** 方阵或长宽同量级时，最坏至少要检查线性数量的元素（见 §024.3.2）。但极窄的矩阵另当别论：`1×n` 直接用二分，只需 `O(log n)`。

## 024.3 原理拆解

### 024.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力逐格 | O(mn) | O(1) | 5 行 | `m = n = 300` 时 9·10⁴ 次比较；规模放大到 3000 就是 9·10⁶ |
| 每行二分 | O(m log n) | O(1) | 20 行 | 只用了「行有序」，列信息浪费；`m ≫ n` 时退化成 `O(m)` |
| 每列二分 | O(n log m) | O(1) | 20 行 | 对称地浪费行信息；`n ≫ m` 时更差 |
| **阶梯搜索（右上 → 左下）** ✅ | **O(m + n)** | **O(1)** | **8 行** | 只适用于「行列各自有序」这种特殊结构；一般矩阵没有阶梯 |
| 阶梯搜索（左下 → 右上） | O(m + n) | O(1) | 8 行 | 完全对称的另一种写法，选一个记住即可 |
| 值域二分 + 行内计数 | O(m log n · log V) | O(1) | 30 行 | `V = 2·10⁹` 时 `log V ≈ 31`，总代价 `m·log n·31`，**比阶梯慢** |
| 四叉分治（排除 ≤ target 的左上和 ≥ target 的右下） | O((mn)^0.5) 量级 | O(1) | 40 行 | 递归栈 + 常数极大，实际比阶梯慢；但能处理「没有阶梯」的弱结构 |

**「每行二分」和「阶梯」的取舍**：

| 维度 | 每行二分 | 阶梯搜索 |
| --- | --- | --- |
| 复杂度 | `O(m log n)` | `O(m + n)` |
| `m=n=300` 的步数 | 2700 | 600 |
| 代码行数 | 20（要写二分子函数） | 8 |
| 正确性难度 | 低（复用 020 模板） | 中（要证「整列/整行可扔」） |
| 可迁移性 | **高**（任何「行有序」都能用） | 低（必须是行列双有序） |

**面试建议**：先说「每行二分，O(m log n)」作为保底，再说「其实有 O(m+n) 的阶梯法」，最后写阶梯。**这个递进展示了「从会做到做优」的过程，比直接背阶梯法有说服力得多。**

### 024.3.2 为什么这个做法是对的（正确性论证）

#### (a) 剩余区域的不变量

**不变量 I（剩余区域是矩形）**：每轮循环开始时，尚未被排除的格子恰好是矩形 `R = {(r, c) : i ≤ r < m, 0 ≤ c ≤ j}`，且若 `target` 存在，它的位置必在 `R` 内。

**初始**：`i = 0, j = n-1`，`R` 是整个矩阵。✔

**保持**：设当前 `v = matrix[i][j]`。

- **`v > target`**：由列升序，`matrix[r][j] ≥ matrix[i][j] = v > target` 对所有 `r ≥ i` 成立。故 `R` 中第 `j` 列的**全部**元素都 `> target`，可以整列排除。代码令 `j--`，新区域 `{(r,c) : i ≤ r < m, 0 ≤ c ≤ j-1}`，正是 `R` 去掉第 `j` 列。✔
- **`v < target`**：由行升序，`matrix[i][c] ≤ matrix[i][j] = v < target` 对所有 `c ≤ j` 成立。故 `R` 中第 `i` 行的**全部**元素都 `< target`，可以整行排除。代码令 `i++`，新区域 `{(r,c) : i+1 ≤ r < m, 0 ≤ c ≤ j}`，正是 `R` 去掉第 `i` 行。✔

两种情形都只删掉「确定不含 target」的格子，不变量保持。✔

> **注意「整行/整列」这两个字**：删的是 `R` 里这一行/列**剩下的部分**，不是整个矩阵的这一行/列。因为之前已经删掉的列（`c > j`）和行（`r < i`）本来就不在 `R` 里了。**这就是为什么区域始终保持矩形、而边缘呈阶梯状。**

**终止**：循环条件 `i < m && j >= 0`。退出时 `i == m`（所有行都排除完）或 `j < 0`（所有列都排除完），`R` 为空。由不变量，`target` 不存在，返回 `false`。✔

**若中途 `v == target`**：直接返回 `true`，正确。✔

#### (b) 为什么不会死循环（以及为什么甚至不需要通用论证）

这个算法**不是二分**，所以 020 里那套「区间长度严格递减」的论证用不上。但它有一个更强、更简单的势函数：

```
势函数 Φ = (m - i) + (j + 1)      // 剩余区域包含的「行数 + 列数上界」
```

每一轮：

- `j--` 让 `Φ` 减 1；
- `i++` 让 `Φ` 减 1；
- 命中则直接返回。

**每轮 `Φ` 严格减少 1，初始 `Φ = m + n`，而 `Φ ≥ 0`。所以最多 `m + n` 轮必然退出。** 不存在「原地踏步」的可能，因为**两个分支都是对 `i` 或 `j` 的单向移动**，没有任何回溯。∎

> 💡 **这个论证比二分的更简单，因为它根本不依赖「减半」**。阶梯搜索是「每次挪一步的单调扫描」，`i` 单调不减、`j` 单调不增，两条单调性一交叉就是有限的 `(m+1)(n+1)` 个状态，当然收敛。
> **反过来说，任何时候你看到「两个指针各只往一个方向动」，就知道它必然终止** —— 这和 001 的双指针、019 的滑窗是同一类终止性论证。

#### (c) 下界：为什么阶梯搜索在方阵上最优

**命题**：在 `k×k` 方阵上，最坏至少要检查 `k` 个元素，即 `Ω(k)`。

**证明**：令 `target=0`。在零基下标的方阵中，令 `r+c<k−1` 的元素为负，`r+c>k−1` 为正；反对角线 `r+c=k−1` 上的 `k` 个格子均为 `−1`。例如其余格子取 `2(r+c−(k−1))`，每行每列仍严格递增。反对角线任意一格单独改成 `0` 也不破坏单调性。在无目标的输入上，只要有一格没检查，就无法排除该格是 `0` 的另一种输入。因此最坏必须检查这 `k` 格。∎

方阵上的 `O(2k)` 与 `Ω(k)` 是同一量级。这个证明不能推出任意矩形的 `Ω(m+n)`：特别窄时，可以沿长维逐行或逐列二分。

### 024.3.3 通用解题思路（可迁移的那一层）

本章提炼出二分的**第五条方法论**：**「找极值点，而不是找中点」**。

```
问题：二维（或多维）网格上找目标，每个维度都单调，但整体不单调
   ↓ 对「中心点」二分 → 排除的是矩形，剩 L 形，不可二分 ❌
换问法：哪个位置的元素，能让"一步排除"覆盖最大范围？
   ↓ 极值点：一行之最大 + 一列之最小
比如右上角：v 是本行最大、本列最小
   ↓ v > target ⇒ 整列都比它大 ⇒ 扔列
     v < target ⇒ 整行都比它小 ⇒ 扔行
结论：沿阶梯走，O(m+n)，在方阵上达到同量级下界
```

**「起点选择」决策表**（这是本章最值钱的一张表）：

| 起点 | 在行里的地位 | 在列里的地位 | `v < target` 能干什么 | `v > target` 能干什么 | 可用？ |
| --- | --- | --- | --- | --- | --- |
| **右上角** `(0, n-1)` | 最大 | 最小 | 扔整行（`i++`） | 扔整列（`j--`） | ✅ |
| **左下角** `(m-1, 0)` | 最小 | 最大 | 扔整列（`j++`） | 扔整行（`i--`） | ✅ |
| 左上角 `(0, 0)` | 最小 | 最小 | **什么都扔不掉** | 全扔（等于直接 false） | ❌ |
| 右下角 `(m-1, n-1)` | 最大 | 最大 | 全扔（等于直接 false） | **什么都扔不掉** | ❌ |

**判据**：起点必须**一个维度取极值大、另一个维度取极值小**（「鞍点」）。两个维度同向的角（左上、右下）信息量为零。

**同族题目**：

| 题 | 结构 | 用什么 |
| --- | --- | --- |
| [LC 240](https://leetcode.cn/problems/search-a-2d-matrix-ii/) | 行、列各自升序 | 右上角阶梯，O(m+n) |
| [LC 74 搜索二维矩阵](https://leetcode.cn/problems/search-a-2d-matrix/) | 行升序 **且** 下一行首 > 上一行尾 | **摊平成 0-1 一维，直接二分** O(log(mn)) |

### 024.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 矩阵**只保证行有序** | 列信息没了 | 只能每行二分 `O(m log n)`，或对每行做双指针（若 target 固定且行有序，`O(m log n)` 已最优） |
| 矩阵是**方阵且完全有序**（LC 74） | 摊平后一维有序 | 直接 `O(log(mn))` 二分，比阶梯快得多 |
| 要返回**所有**出现位置 | 元素可重复 | 阶梯法会漏（它找到一个就返回）。正确做法：逐行二分找区间（021 的两次二分），`O(m log n + k)` |
| 要统计 **≤ target 的元素个数** | 不需要定位 | 逐行二分（`upperBound`），`O(m log n)`；这就是 LC 378 的 `check` 函数 |
| 矩阵**非常大**，无法全部装入内存 | 只能按块读 | 阶梯法很友好（只读 `m + n` 个格子），比逐格扫描的 IO 少几个量级 |
| 维度升到 **3 维** | 三个方向都单调 | 阶梯法**不能直接推广**（3 维的「角」有 8 个，但没有任何一个能一步排除一个面）。需要用更复杂的算法，复杂度也要重新分析 |

- **LC 1351 统计有序矩阵中的负数**：矩阵行列都**降序**，从左下角出发 —— 与本章镜像。做完再回头看「起点选鞍点」这张表，会有一眼看穿的感觉。

## 024.5 双语言实现

### 024.5.1 Java

```java
class Solution {
    public boolean searchMatrix(int[][] matrix, int target) {
        // LeetCode 约束 m, n ≥ 1，但通用工具函数要防一手
        if (matrix == null || matrix.length == 0 || matrix[0].length == 0) {
            return false;
        }

        int m = matrix.length, n = matrix[0].length;
        int i = 0, j = n - 1;         // 从右上角出发：本行最大 + 本列最小（鞍点）

        // i 只增、j 只减 ⇒ 势函数 (m-i)+(j+1) 每轮减 1 ⇒ 最多 m+n 轮必然退出
        // 注意 j >= 0 而不是 j > 0：j == 0 时第一列还没检查完，不能提前退
        while (i < m && j >= 0) {
            int v = matrix[i][j];
            if (v == target) {
                return true;
            }
            if (v > target) {
                // 列升序 ⇒ matrix[i..m-1][j] 全都 ≥ v > target ⇒ 整列排除
                // 只动 j，不动 i：这样"已排除的列"始终是后缀，剩余区域仍是矩形
                j--;
            } else {
                // 行升序 ⇒ matrix[i][0..j] 全都 ≤ v < target ⇒ 整行排除
                i++;
            }
        }
        return false;                 // 剩余区域为空 ⇒ 不存在
    }
}
```

### 024.5.2 Go

```go
package main

func searchMatrix(matrix [][]int, target int) bool {
	if len(matrix) == 0 || len(matrix[0]) == 0 {
		return false
	}

	m, n := len(matrix), len(matrix[0])
	i, j := 0, n-1 // 右上角

	for i < m && j >= 0 {
		switch v := matrix[i][j]; {
		case v == target:
			return true
		case v > target:
			j-- // 整列排除
		default:
			i++ // 整行排除
		}
	}
	return false
}

func main() {
	// 只为了让 `go run .` 可执行；LeetCode 上不需要 main
	mat := [][]int{
		{1, 4, 7, 11, 15},
		{2, 5, 8, 12, 19},
		{3, 6, 9, 16, 22},
		{10, 13, 14, 17, 24},
		{18, 21, 23, 26, 30},
	}
	println(searchMatrix(mat, 5))  // true
	println(searchMatrix(mat, 20)) // false
	println(searchMatrix([][]int{{-5}}, -5)) // true
}
```

### 024.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维数组形状 | `int[][]` 是**数组的数组**，每行长度可以不同 | `[][]int` 同理，`len(matrix[0])` 只是第 0 行的长度 | **两者都必须假设「矩阵是矩形」**；题目保证，但通用函数要自己校验 |
| 空值 | `null` 检查 | `nil` 检查（`len(nil) == 0` 已足够，不需要显式判 nil） | Go 的 `len(nil slice)` 返回 0，所以 `len(matrix) == 0` 一次就够；Java 的 `null` 必须单独判，否则 `matrix.length` 直接 NPE |
| 取行列数 | `matrix.length` / `matrix[0].length` | `len(matrix)` / `len(matrix[0])` | 名字不同，语义一致 |
| 多路分支 | `if / else if / else` | `switch v := matrix[i][j]; { case ... }` | Go 的 `switch` 带初始化语句，**顺手把 `v` 绑到当前格子的值**，比 Java 先声明再比较更紧凑；但要小心 `switch` 无 `fallthrough` |
| 越界 | `ArrayIndexOutOfBoundsException` | `panic: runtime error: index out of range` | 两者都会崩。**本题 `i < m && j >= 0` 的双条件必须都在**，少一个就崩 |
| 逻辑右移 `j--` 的类型 | `int` 可为负，`j >= 0` 是有效判断 | 同形 | Go 里如果 `j` 用 `uint`，`j--` 到 0 再减会**回绕成巨大正数**，死循环。**索引一律用有符号 `int`** |

```go
package main

import (
	"math/rand"
	"testing"

// 参考实现：暴力逐格，O(mn)
func bruteSearchMatrix(matrix [][]int, target int) bool {
	for _, row := range matrix {
		for _, v := range row {
			if v == target {
				return true
			}
		}
	}
	return false
}

// 造一个行列都非降的矩阵：
// 用「行增量 + 列增量」的二维前缀构造，M[i][j] = 行前缀和 + 列前缀和
// 这样任意相邻行、相邻列都满足单调（增量非负），且能制造大量重复值
func makeMonotoneMatrix(r *rand.Rand, m, n int) [][]int {
	rowAdd := make([]int, m)
	colAdd := make([]int, n)
	for i := 1; i < m; i++ {
		rowAdd[i] = rowAdd[i-1] + r.Intn(3) // 每步增 0~2，允许相等
	}
	for j := 1; j < n; j++ {
		colAdd[j] = colAdd[j-1] + r.Intn(3)
	}
	mat := make([][]int, m)
	for i := 0; i < m; i++ {
		mat[i] = make([]int, n)
		for j := 0; j < n; j++ {
			mat[i][j] = rowAdd[i] + colAdd[j] - 20 // 平移，制造负数
		}
	}
	return mat
}

		}
```

> ⚠️ **造数据为什么要用「行增量 + 列增量」**：如果直接随机填值然后 `sort` 行再 `sort` 列，会破坏另一维的单调性（排序行会打乱列）。用「`M[i][j] = rowPrefix[i] + colPrefix[j]`、增量非负」的构造，**两个维度的单调性由构造本身保证**，不需要事后修正。**这是造「双调矩阵」测试数据的标准手法，值得记住。**

## 024.6 复杂度与常见坑

### 024.6.1 复杂度推导

**时间 O(m + n)**：

- `i` 从 0 增到 `m`，`j` 从 `n-1` 减到 `-1`，两者都**单向**移动。
- 每轮循环要么 `i++`，要么 `j--`（或直接返回），所以总轮数 = `i` 的总增量 + `j` 的总减量 `≤ m + n`。
- 每轮做 **1 次数组访问 + 至多 2 次比较**。
- `m = n = 300` → 至多 600 轮。**对比暴力 9·10⁴ 轮，快 150 倍。**

**空间 O(1)**：只有 `i / j / m / n / v` 五个变量。**没有递归、没有额外数组。**

**为什么方阵不能对数搜索**：见 §024.3.2(c) 的 `Ω(k)` 下界；特别窄的矩阵不受这个方阵下界约束。

### 024.6.2 八个真实踩过的坑

1. **`while (j > 0)` 而不是 `j >= 0`** —— `j == 0` 时第 0 列还没检查完就退出了，会漏掉第一列的所有元素。`matrix = [[1,4],[2,5]], target=2` 走一遍：`(0,1)=4 > 2 → j=0`，此时 `j > 0` 为假，退出返回 `false`，**但 2 就在 `(1,0)`**。**这是本题第一号 bug，必须 `j >= 0`。**
2. **行列索引写反** —— `matrix[i][j]` 里 `i` 是行、`j` 是列。初始化写成 `int i = n-1, j = 0`（左下角的坐标写成了右上角的形状），然后 `while (i >= 0 && j < n)`。**两种写法都对，但混用就全错。** 建议在变量名上标注：`row` / `col`，或者写注释。
3. **从左上角出发** —— 前面详细讲过：`matrix[0][0]` 在行和列上都是最小，两个方向都可能更大，**没有任何一步能排除**。代码会变成「往右试一下，不对再往下试」的指数级搜索。
4. **从右下角出发** —— 对称地失败：`matrix[m-1][n-1]` 在行和列上都是最大，两个方向都可能更小。
5. **只 `j--` 不 `i++`（或反之）** —— 比如 `v < target` 时也写 `j--`，那就变成单行/单列的线性扫描，可能永远走不到目标。**两个分支的方向必须相反。**
6. **空矩阵不判** —— `matrix = []` 时 `matrix[0]` 直接崩。`matrix = [[]]` 时 `matrix[0].length == 0`，`j = -1`，`while` 不进，返回 `false`（碰巧对）。**Java 要先判 `null` 再判 `length == 0`。**
7. **以为这题能摊平后二分** —— 摊平需要「下一行首 > 上一行尾」，本题没有。`[[1,4],[2,5]]` 摊平是 `[1,4,2,5]`，**不是有序的**。这是 LC 74 和 LC 240 的本质区别。
8. **Go 里用 `uint` 当列索引** —— `j--` 到 0 之后再减会回绕成 `2⁶⁴-1`，`j >= 0` 恒真，**死循环且越界 panic 在很远的地方才发生**，极难调试。**索引一律用 `int`。**

### 024.6.3 面试官最爱追问的三个问题

**Q1：为什么从右上角出发？左上角不行吗？**
> 「右上角的元素同时是『本行最大』和『本列最小』，是一个鞍点。所以拿它跟 target 比，方向是唯一的：它比 target 大，由列升序可知整列都比它大，直接扔一列；它比 target 小，由行升序可知整行都比它小，直接扔一行。而左上角是『本行最小 + 本列最小』，比 target 小时右边和下边都可能更大，**没有方向可以排除**，一步也走不动。判据是：起点必须一个维度取极大、另一个维度取极小。」

**Q2：这个算法是二分吗？复杂度为什么是 O(m+n) 而不是 O(log)？**
> 「不是二分，是阶梯扫描；每次排除一行或一列，得到 `O(m+n)` 上界。`k×k` 方阵的反对角线可放 `k` 个互不决定的候选，最坏要检查 `k` 格。矩形不能直接套这个下界，`1×n` 就能二分。」

**Q3：如果我只用「每行二分」，复杂度是多少？什么时候它更好？**
> 「`O(m log n)`。当 `m` 远小于 `n` 时，两者差不多（`m log n` vs `m + n`，比如 `m=10, n=10^6`：`10·20 = 200` vs `10^6`，**每行二分反而快得多**）。阶梯法的优势在 `m` 和 `n` 同量级时，比如 `300×300`：600 vs 2700。所以严格来说：**`m ≪ n` 用每行二分，`m ≈ n` 用阶梯。** 另外，`O(m log n)` 只依赖「行有序」，适用面更广。」

## 附：本章小结（可背走的三句话）

```
① 左上/右下是"双极值"，信息量为零；右上/左下是"鞍点"，一步能扔一行或一列
② 剩余区域永远是矩形（行前缀 + 列后缀被删）⇒ 阶梯路径，i 只增 j 只减 ⇒ 最多 m+n 步
③ 阶梯法 O(m+n)，在方阵上渐近最优；只保证行有序或行数远少于列数时，可考虑逐行二分
```
