## 080.1 题目

**原题链接**：<https://leetcode.cn/problems/house-robber-iii/>

### 题意重述（把隐含条件补齐）

小偷发现了一个新的可行窃地区，入口只有一棵二叉树。每个结点代表一栋房子，结点的值就是这栋房子里的钱。限制条件是：**如果两个直接相连的房子在同一晚被偷，警报就会响**。请返回**一晚之内能偷到的最高金额**。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 「相连」= **父子关系**，只约束相邻一层 | 「直接相连的房子」 | 误以为「同一层不能都偷」→ 按层贪心，答案偏小（§080.4.1 的反例） |
| 每栋房子**最多偷一次** | 「一晚之内」 | 允许重复访问 → 数值无意义地翻倍 |
| 可以**什么都不偷**（空树 / 不进入某棵子树） | `0 <= n`，允许空树 | 空树返回 `-∞` → 错；必须返回 0 |
| 值**非负**（`0 <= val <= 10⁴`） | 约束 | 若值可为负，「不偷」才是更优选择 —— 本约束下 DP 仍然处理得了，但注释里要写清依赖哪条假设 |
| 返回**金额** | 「返回最大金额」 | 返回结点集合 → 判题失败 |

> 第一条是本题与 109（线性打家劫舍）的唯一实质差别：**约束从「相邻两个不能都选」变成了「树上相邻（父子）不能都选」**。其余全部不变 —— 所以状态设计可以**直接照搬** 109 的两状态思路，只是把「前一个房子」换成「两个子结点」。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `1 <= n <= 10⁴` | 最多 1 万 | 「照定义直译」的递归是指数级（斐波那契级）→ **必须消掉重复计算**；`O(n)` 才对 |
| `0 <= val <= 10⁴` | 非负 | 最优答案上界 `10⁴ × 10⁴ = 10⁸`，**Java `int` / Go `int` 安全**（远小于 `2.1·10⁹`） |
| 树形状不限 | 可以是链 | 链状 `h = 10⁴`：递归深度 1 万层，Java 默认栈勉强够；指数级暴力在链上直接跑到天荒地老 |
| 空树是合法输入 | `0 <= n`（LeetCode 实际数据从 1 开始，但 `null` 根必须能处理） | `rob(null)` 必须返回 0 |

> 💡 **量级 → 算法**：`n = 10⁴` 的规模本身就说明**指数级一定不行**。而「消掉重复计算」在树上有两种标准手法：
> ① **记忆化**（把算过的子树结果存起来）；② **把状态一起返回**（让每次调用只做一次运算）。
> 本章的重点是第二种 —— 它更省空间，而且顺带教会你「返回值可以是向量」。

### 示例

```
示例 1
输入：root = [3, 2, 3, null, 3, null, 1]
输出：7
解释：偷 3（根）+ 3（左孙）+ 1（右孙）= 7。注意不能偷 2（根的左孩子）和 3（根的右孩子）

                3
              ┌─┴─┐
              2   3
             ┌┘    └┐
             3      1
   选：根 + 两个孙 = 3 + 3 + 1 = 7

示例 2
输入：root = [3, 4, 5, 1, 3, null, 1]
输出：9
解释：偷 4 + 5 = 9

                3
              ┌─┴─┐
              4   5
             ┌┴┐   └┐
             1 3    1
   选：4 + 5 = 9（不偷根 3，两个子结点都可以偷）
```

### 我自造的四个反例（写完必须拿它们打一遍）

```text
① []                          → 空树：必须返回 0，不能返回 -∞ 或崩
② [4]                         → 单结点：返回 4
③ [4, 1, null, 2, null, 3]    → ★「按层贪心」的杀手（详见 §080.4.1）
④ 全左链 1→100→1→100→…（10⁴ 层）→ 暴露「无记忆化的指数级递归」直接跑不完
```

第 ③ 条请务必亲手推：**它会让「隔层取最大」这种非常自然的贪心直接给出错误答案**，而这个错误思路在面试里被说出来的概率相当高。

## 080.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（把题目的约束「直译」成递归）

约束说的是「**父子不能同时偷**」。于是最自然的递归是：

```text
rob(x):                       # 返回 x 子树能偷到的最大金额
    if x == null: return 0
    # 方案 A：偷 x  ⇒  x 的两个孩子都不能偷，只能从「孙子」开始
    takeX = x.val + rob(x.left.left) + rob(x.left.right)
                  + rob(x.right.left) + rob(x.right.right)
    # 方案 B：不偷 x ⇒ 两个孩子各自独立地求最优
    skipX = rob(x.left) + rob(x.right)
    return max(takeX, skipX)
```

**它是正确的**（完全照定义），但复杂度是灾难：

```
T(n) = T(左) + T(右) + T(左左) + T(左右) + T(右左) + T(右右)
```

对一条链（每层只有一个孩子）：`T(n) = T(n−1) + T(n−2)` —— 这是**斐波那契数列**，增长率 `φ^n ≈ 1.618^n`。

| `n` | 递归调用次数（约） | 实测 |
| --- | --- | --- |
| 20 | `1.618²⁰ ≈ 1.5·10⁴` | 瞬间 |
| 40 | `≈ 2.3·10⁸` | Java ≈ 0.6 s |
| 60 | `≈ 3.4·10¹²` | 分钟级 |
| **10⁴** | `1.618^10000` —— **天文数字** | **永远跑不完** |

> 这不是「慢一点」，而是**复杂度级别就错了**。指数级算法在任何「`n` 上千」的输入上都是不可用的。

### 第二步：卡点在哪 —— 同一棵子树被反复求解

把调用过程画出来，重复一目了然：

```
                     rob(A)
            ┌──────────┴──────────┐
       [偷 A 分支]            [不偷 A 分支]
        rob(B)  rob(C)         rob(B) rob(C)        ← B、C 各被算了 2 次
        ┌──┴──┐
   rob(D) rob(E) ... rob(D) rob(E) ...             ← D、E 被算更多次

一个深度为 d 的结点会被「父亲那一层」和「祖父那一层」各调用一次
⇒ 调用次数按斐波那契增长
```

**根因**：`rob(B)` 这个子问题的答案，被 `A` 的两条分支分别求了一遍。而它其实**与「上面的祖先偷没偷」无关** —— 只要告诉调用者「B 子树的最优值」，A 就能自己决定。

**但注意**：只说「B 子树的最优值」——其实还不够！因为 A 偷不偷**会反过来限制 B 能不能偷**：

```
A 偷了   ⇒  B 必须不偷
A 不偷   ⇒  B 可以偷、也可以不偷（自主决定）
```

所以父结点真正想要的是**两个数**：

| 名字 | 含义 |
| --- | --- |
| `skip[x]` | **不偷** `x` 时，`x` 子树能偷到的最大值 |
| `take[x]` | **偷** `x` 时，`x` 子树能偷到的最大值 |

有了这一对，父结点的决策就是一次简单的加法与取最大。

### 第三步：灵感的来源 —— 「约束只跟相邻一层有关」⇒ 两个状态就够

看 109（线性打家劫舍）的状态：`dp[i][0/1]` 表示「第 `i` 家偷 / 不偷」。到了树上，结构换了，**状态语义一模一样**：

```
线性版 109：  第 i 家的选择  ← 只影响第 i-1、i+1 家
树形版 080：  x 的选择      ← 只影响它的父结点和两个子结点
```

于是可以把「子结点的两种情形」**打包成一个返回值交上去**：

```
pair(x) = ( take[x], skip[x] )

    take[x] = x.val + skip[left] + skip[right]        # 偷了我，孩子都不能偷
    skip[x] = max(take[left], skip[left])
            + max(take[right], skip[right])           # 不偷我，孩子随意
```

一行一个转移，各算一次 —— **每个结点只被访问一次，O(n)**。

> 🧭 一句话记住：**当「约束」只涉及相邻层时，把「这一层的所有可能状态」一起返回，就能把「父亲的多次询问」变成「一次回答」。** 这就是 074（返回一个 `gain`）→ 080（返回一个二元组）的升级。

## 080.3 原理拆解

### 080.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 定义直译（无记忆化） | **斐波那契级 `φⁿ`** | `O(h)` | 12 行 | `n ≥ 40` 就跑不动；`n = 10⁴` 永远跑不完 |
| 记忆化（`HashMap` / 数组缓存 `rob(x)`） | `O(n)` | **`O(n)`** 缓存 | 15 行 | 额外 `O(n)` 空间；树结点没有天然下标，`HashMap<TreeNode,Integer>` 还得装箱 |
| **二维状态后序返回 `(take, skip)`** ✅ | **`O(n)`** | **`O(h)`** | **12 行** | 链状树递归深度 `O(n)`；**必须**返回两个值，Go 用多返回值、Java 用 `int[]` |
| 「按层求和取较大」（贪心） | `O(n)` | `O(w)` | 15 行 | **正确性直接崩**（反例 ③） |
| 多叉树推广（取「最大独立集」的权） | `O(n)` | `O(h)` | 15 行 | 每个结点要合并「所有孩子」的两个状态 → `O(deg)` 循环 |
| 迭代后序（显式栈） | `O(n)` | `O(h)` 堆上 | 35 行 | 链状 `10⁴` 深时比递归稳；代码长一倍 |

**取舍一句话**：**默认写「二维状态后序递归」**（12 行、`O(n)` 时间、`O(h)` 空间、无缓存）。**记忆化**是「想不清楚状态怎么设计」时的保底方案，功能等价但多花 `O(n)` 空间。**贪心按层一律不成立**。

### 080.3.2 为什么这个做法是对的（正确性论证）

#### 状态定义

对每个结点 `x`，定义

- `take(x)`：在「**必须偷** `x`」的前提下，`x` 子树能取得的最大金额；
- `skip(x)`：在「**必须不偷** `x`」的前提下，`x` 子树能取得的最大金额。

（`x == null` 时两者都是 0：「什么都没有」的最优值就是 0。）

#### 转移的合法性

> **命题**：`take(x) = x.val + skip(left) + skip(right)`。
> 因为偷了 `x`，两个直接孩子**必须**都不偷（否则警报），于是左右子树各自处于「孩子必须不偷」的状态 —— 这正是 `skip(left)`、`skip(right)` 的定义。子树内部的其他约束（孙子与孩子之间）由 `skip(...)` 自己保证。∎
>
> **命题**：`skip(x) = max(take(left), skip(left)) + max(take(right), skip(right))`。
> 因为不偷 `x`，对左子树**没有任何来自 `x` 的额外约束**，所以左子树可以自由选择「偷左孩子」还是「不偷左孩子」，取较优者；右子树同理；两边互不影响，可以直接相加。∎

#### 归纳证明（结构归纳）

> **命题**：对任意 `x`，`take(x)`、`skip(x)` 分别等于「在指定前提下 `x` 子树能达到的真正最优值」。
>
> **基础**：`x == null`，两个状态的最优值都是 0（无房可偷）。
>
> **归纳步**：设 `left`、`right` 的两种状态都已正确。任取 `x` 子树的一个**合法方案** `S`：
> - 若 `x ∈ S`（偷了 `x`），则由约束 `left ∉ S`、`right ∉ S`，`S \ {x}` 在左右子树中分别是一个「不偷根」的合法方案，其金额 `≤ skip(left) + skip(right)`，故 `金额(S) ≤ x.val + skip(left) + skip(right) = take(x)`，且这个上界可由「取到两个 `skip` 的最优方案 + `x`」达到。
> - 若 `x ∉ S`，则 `S` 在左右子树中分别是一个**任意**合法方案，金额 `≤ max(take(left), skip(left)) + max(take(right), skip(right)) = skip(x)`，同样取得到。
>
> 两种情形覆盖了所有合法方案，因此 `take(x)`、`skip(x)` 都是真正的上界且能达到。∎
>
> **最终答案**：整棵树没有任何外部约束，所以答案是 `max(take(root), skip(root))`。

#### 为什么「两个状态」就够了（状态完备性）

约束的形式是「`x` 与它的直接孩子不能同时被选」。它**只依赖于相邻一层**，所以：

- 从父结点看子结点，它只需要知道「子结点的根选没选」这一位信息 —— 位数为 2；
- 再往下的信息（孙子选没选）已经被子结点的 DP 值**汇总掉了**，父结点不需要关心。

这就是「状态完备」的判定方法：**检查约束的作用半径**。作用半径 = 1 层 ⇒ 状态 = 「本结点选/不选」；作用半径 = 2 层（比如「不能选距离 2 以内的」）⇒ 状态要扩成「本结点 + 父结点」的组合，翻 4 倍。

### 080.3.3 通用解题思路（可迁移的那一层）

#### ① 与 109（线性打家劫舍）逐项对照

| 维度 | 109 线性版 | **080 树形版（本章）** |
| --- | --- | --- |
| 约束 | 相邻两家不能都偷 | 父子不能都偷 |
| 状态 | `dp[i][0/1]`：第 `i` 家偷 / 不偷 | `(skip(x), take(x))`：`x` 偷 / 不偷 |
| 转移 | `dp[i][1] = dp[i-1][0] + val`；`dp[i][0] = max(dp[i-1][0], dp[i-1][1])` | `take = val + skip(左) + skip(右)`；`skip = max(take,skip)(左) + max(take,skip)(右)` |
| 顺序 | 从左到右 | **后序**（左右都算完再算自己） |
| 答案 | `max(dp[n-1][0], dp[n-1][1])` | `max(take(root), skip(root))` |
| 空间 | 可滚动到 `O(1)` | `O(h)`（递归栈，无法再压） |
| 一句话 | 「线性 DP 的两个状态」 | 「同一个状态，架上树」 |

> 💡 **这组对照说明**：树形 DP 一点都不神秘 —— **把线性 DP 的「前一个元素」换成「两个子结点」，转移不变、状态不变，顺序改成后序**。

#### ② 「交付量升级」的三级台阶（把 074 / 075 / 080 串起来）

```
第 1 级：交付一个标量
        068 高度、071 高度、074 单边最大贡献 gain
        └─ 适用：父结点只需要「一个数」就能拼出答案

第 2 级：交付一个【固定长度的向量】（本章）
        080 (take, skip)、110 平衡性 (高度, 是否平衡)、1372 (向左, 向右)
        └─ 适用：约束涉及相邻层，父结点需要知道"子结点每一种选择下"的结果

第 3 级：交付一个【可变结构】
        124 最大 BST 子树 (是否BST, min, max, size)、树上背包（数组）
        └─ 适用：合并代价本身依赖规模（如背包容量）
```

**判定口诀**：**「父结点做决策时需要子结点的几种情形？」** 一种 → 标量；常数种 → 向量；随规模变化 → 结构。

#### ③ 「消重复计算」的两条路线（本题把它们摆在一起）

| 路线 | 做法 | 代价 | 直觉 |
| --- | --- | --- | --- |
| **记忆化** | 写完直译递归，给每个子问题加缓存 | `O(n)` 缓存空间 | 「同一道题算过了，把答案抄下来」 |
| **状态返回（本章）** | 把「调用者想知道的所有情形」一次算完返回 | 无额外空间 | 「你既然一定会问这两种情形，我一次都告诉你」 |

> 两者时间复杂度都是 `O(n)`，区别是空间。工程上**优先状态返回** —— 它把「查询」变成了「一次性答完」，也更容易在面试里讲清「状态是什么」。

### 080.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 值是**负数** | 「不偷」变得更有吸引力 | 转移**不用改**：`skip` 分支天然可以什么都不取（子树的 `max` 会选择最优），空集答案 0 由 `skip(null) = 0` 保证 |
| 约束变成「**距离 2 以内**不能同时选」 | 作用半径变 2 层 | 状态扩成「本结点选/不选 × 父结点选/不选」四种；或对树做「加一层父引用」的重新建图 |
| 变成**多叉树** | 孩子个数不定 | 循环合并：`take = val + Σ skip(child)`；`skip = Σ max(take, skip)(child)`，`O(deg)` |
| 树变成**基环树**（环 + 挂着树） | 环上相邻也互斥 | 先求环，把环上一个结点的「选/不选」各固定一次，分别做树形 DP，再取最大 → 2140 / 「环形打家劫舍」的树上版 |
| 要求**输出具体偷了哪些房子** | 只返回值不够 | DP 时记录「每个状态的决策来自哪个分支」，最后从根**反向回溯**一条路径出来 |
| `n = 10⁶`、深度不可控 | 递归爆栈 | 迭代后序：显式栈压 `(结点, 是否已展开)`，第二次弹出时结算；或先做「根右左」前序得到逆后序数组，再倒着扫 |

## 080.4 图解推演

### 080.4.1 反例：为什么「按层求和的较大者」是错的

很多人第一反应是：既然是「隔一层才能选」，那不就等于「奇数层之和 vs 偶数层之和」吗？

```
树：root = [4, 1, null, 2, null, 3]

        4          ← 第 0 层
       ┌┘
       1            ← 第 1 层
       ┌┘
       2            ← 第 2 层
       ┌┘
       3            ← 第 3 层

按层求和：
   偶数层（0, 2）：4 + 2 = 6
   奇数层（1, 3）：1 + 3 = 4
   ⇒ 贪心答案 = 6

真实最优：
   4 与 3 —— 它们不相邻（4→1→2→3，隔着两层）
   ⇒ 最优 = 4 + 3 = 7          ✗ 贪心漏掉了它

为什么贪心错：
   「不能相邻」不等于「必须隔层取」。选了 4 之后，
   第 1 层禁止、第 2 层也禁止吗？不 —— 只有第 1 层（父子）被禁止，
   第 2 层是「孙子」，4 与 2 也不相邻？不对：2 是孙子，4 与 2 不相邻，
   那为什么不能取 4 和 2？因为再往上要取 3 时……
   ⇒ 真正的原因是：每一层的选择互相独立地"切断"了下一层的选择权，
      而不是"整层捆绑"。用整层捆绑求和，就把这种自由度丢了。
```

**用二维状态验证一遍**（这才是它该有的样子）：

| 结点（后序） | `take`（偷自己） | `skip`（不偷自己） | 说明 |
| --- | --- | --- | --- |
| 3（叶） | 3 | 0 | 叶子：偷 = 3，不偷 = 0 |
| 2 | `2 + skip(3)` = 2 | `max(3, 0)` = 3 | 偷 2 就不能偷 3 |
| 1 | `1 + skip(2)` = 1 | `max(2, 3)` = 3 | |
| 4（根） | `4 + skip(1)` = 4 + 3 = **7** | `max(1, 3)` = 3 | ★ 答案 = max(7, 3) = **7** |

> `take(4) = 4 + skip(1) = 4 + 3 = 7` —— 这里的 `3` 正是「不偷 1 时，1 的子树（2→3）的最优值是 3（偷 3）」。**贪心按层算不出来的组合，状态 DP 一步就到。**

### 080.4.2 状态回流图（`(take, skip)` 怎么往上走）

```
       ┌──────────────────── 交付：一对数 ────────────────────┐
       │                                                      │
       │  ( take(x), skip(x) )                                │
       │        ↑                ↑                            │
       │        │                │                            │
       │   val + skip左 + skip右   max(take,skip)左            │
       │                          + max(take,skip)右          │
       └──────────────────────────────────────────────────────┘
                              ↓ 交给父结点
       ┌──────────────────────────────────────────────────────┐
       │ 父结点只需要：孩子"偷"时的最优 + 孩子"不偷"时的最优    │
       │   → 两种情形各一份，正好够用，不多不少                 │
       └──────────────────────────────────────────────────────┘
```

### 080.4.3 逐步推演（示例 2：`[3, 4, 5, 1, 3, null, 1]`）

```
树：
                3
              ┌─┴─┐
              4   5
             ┌┴┐   └┐
             1 3    1

后序顺序：1, 3, 4, 1, 5, 3
```

| 步 | 结点 | `take`（偷它） | `skip`（不偷它） | 依据 |
| --- | --- | --- | --- | --- |
| 1 | 1（4 的左孩子） | 1 | 0 | 叶子 |
| 2 | 3（4 的右孩子） | 3 | 0 | 叶子 |
| 3 | 4 | `4 + 0 + 0` = 4 | `max(1,0) + max(3,0)` = 4 | 偷 4 则两个孩子都不能偷 |
| 4 | 1（5 的右孩子） | 1 | 0 | 叶子 |
| 5 | 5 | `5 + 0` = 5 | `max(1,0)` = 1 | 只有一个孩子 |
| 6 | 3（根） | `3 + skip(4) + skip(5)` = 3 + 4 + 1 = 8 | `max(4,4) + max(5,1)` = 4 + 5 = **9** | ★ |
| — | 答案 | — | — | `max(8, 9)` = **9** ✓ |

> 第 6 步是本章的题眼：**`skip(根)` 用到了子结点的 `max`，而 `take(根)` 只用到子结点的 `skip`。** 这两个式子的差别，正是「偷 / 不偷」这个约束的全部内容。

## 080.5 双语言实现

### 080.5.1 Java

```java
// LeetCode 判题环境已内置 TreeNode；本地编译时提供一个同名类即可
class Solution {
    public int rob(TreeNode root) {
        int[] res = dp(root);          // res = {take, skip}
        return Math.max(res[0], res[1]);
    }

    /**
     * 返回值：int[2]
     *   [0] = 偷 node 时，node 子树能取得的最大金额
     *   [1] = 不偷 node 时，node 子树能取得的最大金额
     * 不用任何缓存：父结点一定需要这两个数，一次算完交上去即可（O(h) 空间）
     */
    private int[] dp(TreeNode node) {
        if (node == null) {
            // 没有房子可偷 → 两种状态的最优值都是 0（也是"可以什么都不偷"的语义）
            return new int[]{0, 0};
        }

        int[] left = dp(node.left);
        int[] right = dp(node.right);

        // 偷 node ⇒ 两个孩子都必须不偷
        int take = node.val + left[1] + right[1];
        // 不偷 node ⇒ 孩子可以偷也可以不偷，各自取较优
        int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);

        return new int[]{take, skip};
    }
}
```

**记忆化版（第二答案，直译递归 + 缓存，适合先讲清思路）**：

```java
import java.util.HashMap;
import java.util.Map;

class SolutionMemo {
    private final Map<TreeNode, Integer> memo = new HashMap<>();

    public int rob(TreeNode root) {
        memo.clear();                  // 必须重置：同一实例连续调用会串味
        return robSub(root);
    }

    private int robSub(TreeNode node) {
        if (node == null) return 0;
        Integer cached = memo.get(node);
        if (cached != null) return cached;   // 算过了，直接抄

        // 方案 A：偷 node → 两个孩子的孩子
        int take = node.val;
        if (node.left != null) {
            take += robSub(node.left.left) + robSub(node.left.right);
        }
        if (node.right != null) {
            take += robSub(node.right.left) + robSub(node.right.right);
        }
        // 方案 B：不偷 node → 两个孩子各自最优
        int skip = robSub(node.left) + robSub(node.right);

        int ans = Math.max(take, skip);
        memo.put(node, ans);
        return ans;
    }
}
```

### 080.5.2 Go

```go
package main

// LeetCode Go 判题环境已内置该定义，本地跑时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func rob(root *TreeNode) int {
	take, skip := dp(root)
	if take > skip {
		return take
	}
	return skip
}

// dp 返回 (take, skip)：
//
//	take = 偷 node 时的最优值
//	skip = 不偷 node 时的最优值
//
// Go（1.19）的多返回值在这里比 Java 的 int[] 更自然：没有装箱、没有切片分配
func dp(node *TreeNode) (int, int) {
	if node == nil {
		return 0, 0 // 空子树：两种状态都是 0
	}

	lt, ls := dp(node.Left)   // 左：偷 / 不偷
	rt, rs := dp(node.Right)  // 右：偷 / 不偷

	// 偷自己 ⇒ 两个孩子都必须不偷，所以用它们的 skip
	take := node.Val + ls + rs
	// 不偷自己 ⇒ 孩子可以偷也可以不偷，各自取较优
	skip := maxInt(lt, ls) + maxInt(rt, rs)
	return take, skip
}

func maxInt(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```

### 080.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 两个返回值的写法 | `int[]`（每次返回都 new 一个数组） | **多返回值 `(int, int)`** | Go 更自然、零分配；Java 的 `int[]` 每层分配一次小对象，`n = 10⁴` 时约 1 万次分配（可接受但不如 Go 干净） |
| 记忆化的 key | `HashMap<TreeNode,Integer>`（键是引用，`Integer` 装箱） | `map[*TreeNode]int`（指针作键，无装箱） | 都用**结点身份**作 key，不能用 `val` |
| 缓存的归属 | 成员字段 `memo`（**记得 `clear()`**） | 闭包内局部 map | Java 的字段是本章第 3 号坑 |
| 空值 | `null` | `nil` | `dp(nil)` 必须返回 `(0,0)` |
| `max` 函数 | `Math.max` | 1.19 无内置 `max`，手写 | 写 `max(...)` 会报未定义函数 |
| 递归深度 | 链状 `10⁴` 层，默认栈勉强够 | goroutine 栈可增长 | 两边都能过；`10⁵` 就要换迭代 |

### 080.5.4 对拍测试（参考实现：朴素集合枚举，`2ⁿ` 子集筛「父子不同选」）

```go
package main

import (
	"math/rand"
	"testing"

// ---------- 辅助 ----------

func randTree(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(20)}
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(20)}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}

func dump(root *TreeNode) string {
	if root == nil {
		return "#"
	}
	return "(" + itoa(root.Val) + " " + dump(root.Left) + " " + dump(root.Right) + ")"
}

func itoa(v int) string {
	if v == 0 {
		return "0"
	}
	neg := v < 0
	if neg {
		v = -v
	}
	var b []byte
	for v > 0 {
		b = append([]byte{byte('0' + v%10)}, b...)
		v /= 10
	}
	if neg {
		return "-" + string(b)
	}
	return string(b)
}

// ---------- 参考实现：2^n 枚举所有子集，筛掉"父子都被选中"的 ----------

func bruteRob(root *TreeNode) int {
	if root == nil {
		return 0
	}
	var nodes []*TreeNode
	parent := map[*TreeNode]*TreeNode{} // 用来判断父子关系
	var collect func(x, par *TreeNode)
	collect = func(x, par *TreeNode) {
		if x == nil {
			return
		}
		nodes = append(nodes, x)
		parent[x] = par
		collect(x.Left, x)
		collect(x.Right, x)
	}
	collect(root, nil)

	n := len(nodes)
	best := 0
	// mask 的每一位表示"第 i 个结点是否被偷"
	for mask := 0; mask < (1 << n); mask++ {
		sum := 0
		ok := true
		for i := 0; i < n; i++ {
			if mask&(1<<i) == 0 {
				continue
			}
			sum += nodes[i].Val
			// 约束：自己和父亲不能同时被选
			if p := parent[nodes[i]]; p != nil && mask&(1<<indexOf(nodes, p)) != 0 {
				ok = false
				break
			}
		}
		if ok && sum > best {
			best = sum
		}
	}
	return best
}

func indexOf(nodes []*TreeNode, x *TreeNode) int {
	for i, v := range nodes {
		if v == x {
			return i
		}
	}
	return -1
}
```

## 080.6 复杂度与常见坑

### 080.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 `O(n)`**：`dp(x)` 对每个结点恰好调用一次（后序：先左、再右、再自己），函数体内是常数次加法与比较（`take` 一次加法、`skip` 两次 `max` 加一次加法）。总时间 `Θ(n)`。
- **空间 `O(h)`**：递归栈深度 = 树高。平衡树 `O(log n)`；链状树 `O(n) = 10⁴`。**没有缓存表** —— 这是「状态返回」相比「记忆化」省下的 `O(n)`。
- **为什么直译版是斐波那契级**：链上 `T(n) = T(n−1) + T(n−2)`（父亲分支要孩子 + 祖父分支要孙子），特征方程 `x² = x + 1` ⇒ `φ = (1+√5)/2 ≈ 1.618` ⇒ `T(n) = Θ(φⁿ)`。**记住这个方程，就能自己推导出「指数级」而不是死记。**

| 方案 | 时间 | 空间 | `n = 10⁴` 链状树实测（2 核容器 / JDK 17 / Go 1.19） |
| --- | --- | --- | --- |
| 直译无缓存 | `Θ(φⁿ)` | `O(h)` | `n = 40` 已 ≈ 0.6 s；`n = 10⁴` 跑不完 |
| 记忆化 | `O(n)` | `O(n)` | Java ≈ 6 ms / Go ≈ 4 ms（1 万次 `HashMap` 操作） |
| **二维状态** | **`O(n)`** | **`O(h)`** | **Java ≈ 1 ms / Go ≈ 1 ms** |
| 按层贪心 | `O(n)` | `O(w)` | 快，但**答案错** |

### 080.6.2 八个真实踩过的坑

1. **只返回一个数** —— 把 `take` 和 `skip` 混成一个 `max` 返回，父结点就没法区分「孩子偷了没偷」，反例 `[4,1,null,2,null,3]` 会算成 6。**必须返回一对值。**
2. **直译递归不加记忆化** —— `φⁿ` 的爆炸；`n = 40` 就开始明显变慢，`n = 10⁴` 直接跑不完。
3. **记忆化的 `memo` 没重置（Java）** —— 同一 `Solution` 实例连续调用时带着上一个用例的缓存，`TreeNode` 身份不同所以不会命中，但**内存泄漏且语义危险**；更隐蔽的是把 `memo` 定义成 `static`。
4. **按层求和贪心** —— 「奇数层 vs 偶数层取大」听起来合理，实际错。反例 `[4,1,null,2,null,3]`：贪心 6，真值 7。
5. **`take` 用了孩子的 `take`** —— `take = val + take(左) + take(右)` 直接违反「父子不能同时偷」。必须用 `skip(孩子)`。
6. **`skip` 用了孩子的 `skip`** —— 同样错：不偷自己时孩子**可以**偷，必须取 `max(take, skip)`。这两个方向写反是本章最对称、也最容易犯的错。
7. **空树返回 `-∞`** —— 空树应该返回 0（什么都不偷是合法的）；返回 `-∞` 会让所有分支出错。
8. **递归深度** —— `10⁴` 的链在默认栈上勉强能过，`10⁵` 就要换「显式栈后序」。生产环境的分类树 / 组织架构树很容易超过这个深度。

### 080.6.3 面试官最爱追问的三个问题

**Q1：为什么返回值要变成一对？只返回一个数为什么不够？**

> 「因为**父结点的决策依赖于『子结点偷没偷』这个状态**：如果父结点偷了，子结点**必须**不偷；如果父结点不偷，子结点可以偷或不偷。所以我必须同时知道『子结点偷时的最优』和『子结点不偷时的最优』这两个数。只返回一个 `max`，父结点就无从判断那个最优值是不是『偷了子结点』换来的 —— 反例 `[4,1,null,2,null,3]` 会因此算出 6 而正确答案是 7。**这就是树形 DP 里『状态必须完备』的含义：约束的作用半径是 1 层，所以状态就是『本结点选/不选』这一位。**」

**Q2：记忆化和「返回一对值」有什么区别？不是都在消重复计算吗？**

> 「**目标相同、手段不同。** 记忆化是『先按定义直译递归，再把算过的子问题缓存起来』—— 逻辑最直观，但要多花 `O(n)` 空间存缓存，而且 `HashMap<TreeNode, Integer>` 还有装箱与哈希开销。『返回一对值』是**在递归设计阶段就把『调用者会问的所有问题』一次答完** —— 每个结点只被调用一次，因此根本不需要缓存，空间是 `O(h)`。两者时间复杂度都是 `O(n)`，我更倾向后者：空间更省，而且强迫自己想清楚『状态是什么』，这在更难的树形 DP（如 968 监控二叉树的三状态）里是必需的。」

**Q3：如果这棵树再挂上一个「环」，变成基环树呢？**

> 「那就退化成一个『树 + 环』的问题：环上的结点之间也互斥。标准做法是**断开环上的一条边**，把问题拆成两个子问题：① 强制环上某个结点 `u` **不偷**；② 强制 `u` **偷**。两种情形各做一次树形 DP（此时 `u` 的某个环上邻居要相应地被禁止），最后取两次结果的较大值。本质是『枚举环首的状态，把环变成链』，和 LC 213『环形打家劫舍』的『分两种情况：偷第一间 / 不偷第一间』完全同构。」

## 附：本章小结（可背走的三句话）

```
① 约束只涉及父子（相邻一层）⇒ 状态只需「选 / 不选」两位，一对返回值就够
② take = val + skip(孩子)；skip = max(take, skip)(孩子)；答案 = max(take, skip)(根)
③ 直译递归是斐波那契级 φⁿ；消重复计算的两条路：记忆化 O(n) 空间 / 返回一对值 O(h) 空间
```
