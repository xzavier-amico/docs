## 121.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-increasing-subsequence/>

### 题意重述（把隐含条件补齐）

给你一个整数数组 `nums`，找出**最长严格递增子序列**的长度。「子序列」不是「子数组」——这一点决定了整道题的做法。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **子序列**可以不连续 | 「子序列」三个字 | 若按「子数组」做（滑动窗口），`[10,9,2,5,3,7,101,18]` 会答 2，正确是 4 |
| 必须**保持原有相对顺序** | 「子序列」的定义 | 若允许任意重排，答案就退化成「去重后计数」，`[3,1,2]` 会答 3，正确是 2 |
| **严格**递增，`nums[j] < nums[i]` | 「递增」在 LC 300 指严格 | 写成 `<=` 时 `[7,7,7]` 答 3，正确是 1 |
| 只问**长度**，不问序列本身 | 「返回长度」 | 输出方案要额外记录前驱，代码复杂一档（§121.3.4 讲怎么加回去） |
| `nums` 可能含负数 | 约束 `-10^4 <= nums[i]` | 拿 `0` 或 `-1` 当哨兵会失效，见 §121.6 第 2 条 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 2500` | n 最多 2500 | **`O(n²) = 6.25·10⁶` 次比较，能过**（本机实测 Java ≈ 30 ms、Go ≈ 18 ms）；`O(2ⁿ)` 在 `n = 60` 就已经 `10¹⁸`，永远出不来答案 |
| `-10^4 <= nums[i] <= 10^4` | 值域很小 | 值域 `2·10⁴` 小到可以当数组下标 → 「树状数组 / 权值线段树优化」这条路走得通（§121.3.4） |
| 只问长度 | 不问方案 | 可以「边扫边丢信息」：`tails` 只留最小结尾，不需要存整条子序列 |
| 无取模 | — | 答案是 `≤ n` 的整数，`int` 绝对安全 |

> 💡 **量级 → 算法**：看到 `n ≤ 2500` 要能立刻说出「`O(n²)` 是官方给你的舒适区」，同时补一句「如果 `n` 变成 `10⁵`，就必须 `O(n log n)`」。**这道题的全部价值就在这个括号里**：它同时是 `O(n²)` DP 的教学题和 `O(n log n)` 的面试题。

### 示例

```text
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]（或 [2,3,7,18]），长度 4

输入：nums = [0,1,0,3,2,3]
输出：4
解释：[0,1,2,3]

输入：nums = [7,7,7,7,7,7,7]
输出：1
解释：严格递增，重复元素不能接在一起
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① []                 → 空数组答案 0，二分版里若写 tails[0] 直接 panic
② [7,7,7]            → 逼出「严格」与「非严格」的分界：lower_bound 与 upper_bound 只差一行
③ [4,3,2,1]          → 完全逆序，答案 1；dp 版若把 best 初始化为 0 会答 0
④ [1,3,6,7,9,4,10,5,6] → tails 会在中途被「覆盖」成非答案序列，暴露「tails 不是答案序列」这个误解
```

第 ④ 条最值得记：`tails` 最终可能是 `[1,3,4,5,6]`，而真实 LIS 是 `[1,3,6,7,9,10]`。**`tails` 的长度是对的，内容几乎总是错的** —— 这一点在 §121.3.2 会用不变量说清楚。

## 121.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有子序列

「最长子序列」最直白的翻译是：把所有子序列都列出来，逐个判递增，取最长。

```text
for mask in [0, 2^n):          # 位掩码表示「选哪些位置」
    if 选出的序列严格递增:
        ans = max(ans, popcount(mask))
```

- 时间 **O(2ⁿ·n)**，`n = 2500` 时是 `2²⁵⁰⁰`，宇宙寿命都算不完。
- 空间 **O(n)**（存当前序列）。
- 它唯一的价值：**它是「正确性定义」**，所以我把它写成对拍用的参考实现（§121.5.4）。

### 第二步：卡点在哪 —— 指数爆炸来自「每个元素选/不选」，但答案不需要知道选了什么

枚举子序列时，一个元素有「选」和「不选」两条路，于是树有 `2ⁿ` 个叶子。可题目只要**长度**，不要方案。那就问一句：

> **如果我只看「以 `nums[i]` 结尾的最长递增子序列长度」，够不够推出全部答案？**

够。因为任何一条递增子序列都有唯一一个**最后一个元素**，按最后元素分类，就把「全体子序列」切成了 `n` 个互斥的类。这就是 §108 里说的「按最后一步分类」的第二次应用。

### 第三步：`O(n²)` DP —— 把「最后一步」换成「上一个元素」

```text
dp[i] = 以 nums[i] 结尾的最长严格递增子序列的长度
dp[i] = 1 + max{ dp[j] : j < i 且 nums[j] < nums[i] }      （没有可接的就取 1）
答案  = max dp[i]
```

- 时间 `O(n²)`，空间 `O(n)`。
- `n = 2500`：`2500²/2 ≈ 3.1·10⁶` 次「比较 + 取 max」，实测 Java 30 ms、Go 18 ms，**能过**。
- 但把它想成一条曲线：`n` 翻 40 倍到 `10⁵`，操作数变 `10¹⁰/2 = 5·10⁹`，按每秒 10⁸ 次比较要 **50 秒** → **TLE**。`n = 10⁵` 是这类题的常见加强版尺寸。

所以「`O(n²)` 能过」只是本题的运气，不是它的上限。

### 第四步：卡点的真正位置 —— 我们记住了太多无用的信息

`dp[i]` 记的是「以 `i` 结尾的最长长度」。想从 `dp[i]` 推到后面时，你需要比较的是 `nums[i]` 的值。于是每个 `i` 都成了一个独立的「候选接续点」，转移时要把它们全扫一遍 —— `O(n)` 的扫描就是这么来的。

关键观察：

> **长度相同的那些候选结尾里，只有「最小的那个结尾」值得留。**
>
> 若 `len(A) == len(B)` 且 `last(A) < last(B)`，那么任何能接在 `B` 后面的元素，**一定能接在 `A` 后面**（因为要求是 `x > last`）。所以 `B` 永远不会比 `A` 更好，`B` 可以直接扔掉。

这句话把「`n` 个候选」压成了「每个长度只有一个候选」——总候选数从 `n` 变成「答案长度」个，而答案长度 `≤ n`。这就是 `tails` 数组的由来。

### 第五步：灵感的来源 —— `tails[k]` 的语义

定义（这是全章最重要的一行）：

```text
tails[k] = 所有「长度为 k+1 的递增子序列」中，结尾元素的【最小值】
```

于是：

1. `tails` 天然**严格递增**（长度更长 ⇒ 结尾不可能更小，§121.3.2 给证明）；
2. 新元素 `x` 到来时，只需在 `tails` 里找**第一个 `>= x` 的位置**替换掉它：

```text
x = 6, tails = [1, 3, 7, 9]
              ↑ 第一个 >= 6 的是 7（下标 2）
替换后 tails = [1, 3, 6, 9]
含义：长度为 3 的子序列，结尾从 7 降到了 6 —— 更「便宜」了，后面更容易接得上
```

3. 若 `x` 比 `tails` 里所有元素都大，就**追加**到末尾 —— 这等价于「答案长度 +1」。

`tails` 只在尾部增长，且尾部增长恰好等于「LIS 长度」。这就是 `O(n log n)` 的全部秘密：**二分找替换位置 + 只在尾部 append**。

## 121.3 原理拆解

### 121.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举子序列 | `O(2ⁿ·n)` | `O(n)` | 15 行 | `n ≥ 30` 就不可用，只能当对拍基准 |
| 记忆化搜索（`f(i) = 从 i 开始的最长长度`） | `O(n²)` | `O(n)` 栈 | 15 行 | 递归栈深度 `n = 10⁵` 时爆栈；常数比递推大 |
| **`O(n²)` 递推（`dp[i]` 以 `i` 结尾）** ✅ | `O(n²)` | `O(n)` | 8 行 | `n ≥ 10⁴` 开始明显卡，`n = 10⁵` 必 TLE |
| **贪心 + 二分（`tails`）** ✅✅ | **`O(n log n)`** | **`O(n)`** | **12 行** | **要输出具体序列时要额外维护前驱与「版本链」**（§121.3.4）；要统计方案数时完全失效 |
| 树状数组 / 权值线段树（按值域维护前缀 max） | `O(n log V)` | `O(V)` | 30 行 | 值域大（`10^9`）要先离散化；代码量翻倍 |
| 排序后转「二维偏序」 | `O(n log n)` | `O(n)` | 同二分版 | 只适用于两维都严格比较的变体（122 就是这么干的） |

**为什么两个都值得会**：`O(n²)` 版是**状态定义的标准示范**（「以 `i` 结尾」这个限定词的所有权重大概占本题一半分数）；`O(n log n)` 版是**「用一个更强的不变量替掉整张表」的示范**。面试里先说 `O(n²)` 的转移，再被追问「能更快吗」，然后给出 `tails` —— 这个顺序是标准答案。

### 121.3.2 为什么这个做法是对的（正确性论证）

**命题 A（`O(n²)` DP）**：设 `dp[i]` 为以 `nums[i]` 结尾的最长严格递增子序列长度，则 `dp[i] = 1 + max{dp[j] : j < i, nums[j] < nums[i]}`（空集时取 1），`max dp[i]` 就是答案。

**证明**：
1. **完备**：任取一条以 `i` 结尾的递增子序列 `nums[i₁] < … < nums[i_{k-1}] < nums[i]`（`i_{k-1} < i`）。去掉 `nums[i]` 后，它是一条以 `i_{k-1}` 结尾、长度为 `k-1` 的递增子序列，所以 `dp[i_{k-1}] ≥ k-1`，于是 `dp[i] ≥ k`。
2. **可达**：若 `dp[j] = m` 且 `nums[j] < nums[i]`，把那条长度 `m` 的序列接上 `nums[i]`，得到长度 `m+1` 的合法序列，所以 `dp[i] ≥ m+1`。
3. 两边夹逼 ⇒ `dp[i]` 恰为最长长度。对 `i` 归纳（`i` 递增时 `dp[j] (j < i)` 已算好）。∎

**命题 B（`tails` 版）**：维护 `tails` 后，`len(tails)` 恒等于「当前已处理前缀的 LIS 长度」。

证明需要三条不变量，缺一不可：

- **不变量 1（语义）**：处理完前 `i` 个元素后，对每个 `0 ≤ k < len(tails)`，`tails[k]` 是「在 `nums[0..i-1]` 中、长度为 `k+1` 的递增子序列的最小可能结尾」。
- **不变量 2（严格递增）**：`tails[0] < tails[1] < … < tails[len-1]`。
- **不变量 3（长度正确）**：`len(tails)` = 前缀 `nums[0..i-1]` 的 LIS 长度。

**不变量 2 的证明**（反证）：若存在 `k` 使 `tails[k] ≥ tails[k+1]`。设 `tails[k+1] = x`，即存在长度 `k+2`、结尾为 `x` 的递增子序列，它删掉最后一个元素后给出长度 `k+1`、结尾 `< x ≤ tails[k]` 的子序列 —— 这与「`tails[k]` 是长度 `k+1` 的最小结尾」矛盾。∎

**不变量 2 的用途**：它保证 `tails` 有序，二分才合法。**这就是「为什么要证明它有序」**——不是审美，是算法的前提。

**转移的正确性**：设 `x = nums[i]`，用 `p = lower_bound(tails, x)`（第一个 `≥ x` 的下标）。

- **若 `p == len`**：`x` 比所有 `tails` 都大，于是存在长度 `len+1` 的递增子序列（长度 `len` 的那条接上 `x`），且不可能有更长的（否则 `tails` 里会有长度 `len+1` 的项）。append 后不变量 1/2/3 全部保持。
- **若 `p < len`**：`x` 落在 `[tails[p-1], tails[p]]` 区间（`p = 0` 时无下界）。原来是「长度 `p+1` 的最小结尾 = `tails[p]`」，现在 `x ≤ tails[p]` 且 `x > tails[p-1]`，说明存在长度 `p+1`、结尾为 `x` 的序列（长度 `p` 的那条接上 `x`），于是把 `tails[p]` 更新为 `x` 仍满足「最小」语义；同时 `x > tails[p-1]` 保证严格递增不被破坏。其余位置不受影响。∎

> ⚠️ **注意这个论证里最容易被跳过的一句**：替换时依赖 `x > tails[p-1]`。这正是用 `lower_bound`（第一个 `≥ x`）而不是「随便找一个比 `x` 大的」的原因 —— **位置必须唯一确定**，否则不变量 2 会被打破。

### 121.3.3 通用解题思路（可迁移的那一层）

把这道题抽象成两个可迁移的模型：

**模型一：序列 DP 的「限定结尾」技巧**。凡是「子序列」类问题（不连续、保序），状态定义几乎都要加「以 `i` 结尾 / 以 `i` 开头」这个限定词，因为只有这样「最后一步」才有唯一的前驱集合：

| 题 | 状态定义 | 为什么必须限定结尾 |
| --- | --- | --- |
| [LC 300 最长递增子序列](https://leetcode.cn/problems/longest-increasing-subsequence/)（本题） | 以 `i` 结尾的 LIS 长度 | 否则无法判断能否接上 `nums[i]` |
| [LC 53 最大子数组和](https://leetcode.cn/problems/maximum-subarray/) | 以 `i` 结尾的最大和 | 否则「接不接」无法表达 |
| [LC 110 相关：最长摆动子序列 LC 376](https://leetcode.cn/problems/wiggle-subsequence/) | 以 `i` 结尾且最后一步上升/下降 | 转移方向要与「上一步方向」配对 → 状态机 |
| [LC 152 乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/) | 以 `i` 结尾的最大 / 最小积 | 负数会把 max 变 min → 双状态 |

**模型二：「维护一个更强的单调不变量，把扫描变成二分」**。这是 `O(n²) → O(n log n)` 的通用套路：

```text
原始：对每个 i 扫一遍 j  ← O(n) 的「查询前缀里的最优」
      ↓ 问：前缀里我们真正需要的信息是什么？
更强不变量：每条长度只保留一个「最便宜」的代表元（tails）
      ↓ 代表元按长度天然单调 ⇒ 有序
查询变成：在有序数组上 lower_bound  ← O(log n)
```

同一套路在别处的化身：
- **LIS 的耐心排序**（patience sorting）：把 `x` 放到「第一堆顶部 `≥ x` 的牌堆」上，堆数 = LIS 长度。`tails[k]` 就是第 `k` 堆的顶部。
- **俄式信封（122）**：二维偏序 → 排序后一维化 → 本题。
- **最长数对链（LC 646）**：按右端点排序后贪心。
- **区间调度（LC 435 / 452）**：贪心本身就能给出「按结束时间的最强代表元」。

> 🔑 **一句话**：`O(n log n)` 不是「把 `O(n²)` 写快一点」，而是**换了一个信息量更大的状态**。旧状态记「答案」，新状态记「让答案将来更容易变长的最小代价」。

### 121.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成**非严格**递增（`nums[j] <= nums[i]`） | 「可以相等」 | 二分换成 `upper_bound`（第一个 `> x`），其余一行不改。`[7,7,7]` 会从 1 变 3 |
| 要**输出某一条** LIS | 从长度变方案 | 加 `pre[i] = 前驱下标`，`dp[i]` 更新时一并记录；最后从 `argmax dp` 回溯 |
| 要**字典序最小**的 LIS | 贪心不够 | 从后往前做「后缀 LIS 长度」`suf[i]`，再正着扫描贪心取第一个满足 `suf[i] == need` 且 `nums[i] > last` 的元素 |
| 统计 LIS 的**条数** | 计数 | `cnt[i] = Σ cnt[j]`（所有最优前驱），`tails` 版失效，退回 `O(n²)` 或树状数组 |
| `n = 10⁵` 且值域 `10⁹` | 二分换结构 | 值域大时用「树状数组维护前缀 max」+ 离散化，`O(n log n)`；与 `tails` 同阶但能顺带求方案数 |
| **二维**版本的递增（如 354 信封） | 两维都要严格 | 排序消掉一维 + 本题（但排序方向有陷阱，见 [`122-russian-doll-envelopes.md`](122-russian-doll-envelopes.md)） |

**输出一条 LIS 的完整写法**（Java，`O(n²)` 版，最直观）：

```java
class SolutionWithPath {
    public int[] lisPath(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n];
        int[] pre = new int[n];
        int best = 0;                       // 最优结尾下标
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            pre[i] = -1;                    // -1 表示「没有前驱」= 序列起点
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) {
                    dp[i] = dp[j] + 1;
                    pre[i] = j;             // 只有「更优」时才改前驱，保证前驱链与 dp 一致
                }
            }
            if (dp[i] > dp[best]) best = i;
        }
        // 回溯得到逆序序列，再反转
        int[] path = new int[dp[best]];
        for (int k = dp[best] - 1, cur = best; cur != -1; cur = pre[cur]) path[k--] = nums[cur];
        return path;
    }
}
```

## 121.4 图解推演

### 121.4.1 `O(n²)` DP 表：`nums = [10,9,2,5,3,7,101,18]`

```text
下标 i :    0     1     2     3     4     5      6      7
nums[i]:   10     9     2     5     3     7    101     18
dp[i]  :    1     1     1     2     2     3      4      4
                                             ▲      ▲      ▲
                                             │      │      └─ dp[7]=1+max{dp[3]=2,dp[4]=2,dp[5]=3} = 4
                                             │      └──────── dp[6]=1+max{...,dp[5]=3} = 4
                                             └─────────────── dp[5]=1+max{dp[2]=1,dp[3]=2,dp[4]=2} = 3

转移依赖示意（只看「左边且更小」的格子）：
      10   9   2   5   3   7  101  18
     ┌───┬───┬───┬───┬───┬───┬───┬───┐
dp = │ 1 │ 1 │ 1 │ 2 │ 2 │ 3 │ 4 │ 4 │
     └─┬─┴─┬─┴───┴─┬─┴───┴─┬─┴───┴─┬─┘
       │   │       │       │       │
       └───┴───────┴───────┴───────┴──→ 每次只往左看，因此 i 递增即可安全填表
答案 = max dp = 4       （最优序列之一：[2,3,7,18]）
```

关键点：**`dp[i]` 只依赖左边的格子**，所以「`i` 从左到右」就是正确遍历序（DP 四步法的第 ④ 步）。若有人写成从右往左，读到的全是初值 1，答案会恒为 1 —— 这类错误在自测中表现为「长数组答 1」。

### 121.4.2 `O(n log n)` 的 `tails` 轨迹（耐心排序视角）

```text
输入：[10, 9, 2, 5, 3, 7, 101, 18]

  x     lower_bound(tails, x)        操作          tails
 ────────────────────────────────────────────────────────────────
 10     0（空）                       append        [10]
  9     0（第一个 >=9 是 10）          replace       [ 9]
  2     0（第一个 >=2 是 9）           replace       [ 2]
  5     1（len=1，没有 >=5）           append        [ 2, 5]
  3     1（第一个 >=3 是 5）           replace       [ 2, 3]
  7     2（len=2，没有 >=7）           append        [ 2, 3, 7]
101     3（len=3，没有 >=101）         append        [ 2, 3, 7, 101]
 18     3（第一个 >=18 是 101）        replace       [ 2, 3, 7,  18]
 ────────────────────────────────────────────────────────────────
答案 = len(tails) = 4
```

逐步对照表（把「谁被换掉」记下来，便于自测）：

| 步骤 | `x` | 二分位置 `p` | 命中方式 | 操作后 `tails` | `len` |
| --- | --- | --- | --- | --- | --- |
| 1 | 10 | 0 | append | `[10]` | 1 |
| 2 | 9 | 0 | replace | `[9]` | 1 |
| 3 | 2 | 0 | replace | `[2]` | 1 |
| 4 | 5 | 1 | append | `[2,5]` | 2 |
| 5 | 3 | 1 | replace | `[2,3]` | 2 |
| 6 | 7 | 2 | append | `[2,3,7]` | 3 |
| 7 | 101 | 3 | append | `[2,3,7,101]` | 4 |
| 8 | 18 | 3 | replace | `[2,3,7,18]` | 4 |

> 🔎 **看第 2 步与第 8 步**：`tails` 的内容从 `[10]` 变成 `[9]`，意味着「长度为 1 的子序列，结尾从 10 降到 9」。它**不代表** LIS 真的以 9 结尾（后面 101 才是答案的一部分），只代表「未来接续的门槛降低了」。第 8 步同理：`101` 被 `18` 顶掉，让「长度 4」的门槛从 101 降到 18。**`tails` 是一张「柜台价目表」，不是一张「已成交订单」。**

### 121.4.3 两条路线的对比图

```text
                    ┌──────── 输入 nums[0..n-1] ────────┐
                    │                                  │
        ┌───────────▼────────────┐        ┌────────────▼─────────────┐
        │ 路线 A：dp[i] 以 i 结尾 │        │ 路线 B：tails 按长度记最小结尾│
        │ O(n²) 时间 / O(n) 空间  │        │ O(n log n) / O(n)         │
        └───────────┬────────────┘        └────────────┬─────────────┘
                    │                                  │
       对每个 i 扫一遍左边全部 j                每个 x 只做一次二分
       信息完整：能顺带求方案数/路径            信息压缩：只剩长度，方案数失效
                    │                                  │
             【n ≤ 2500 够用】                  【n = 10⁵ 唯一选择】
                    │                                  │
                    └────────── 二者答案必然相等 ───────┘
                    （所以可以用一个对拍另一个，见 §121.5.4）
```

## 121.5 双语言实现

### 121.5.1 Java

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        // tails[k] 的语义：所有长度为 k+1 的递增子序列里，最小的结尾元素
        // 不变量：tails[0] < tails[1] < ... < tails[len-1]（严格递增，所以能二分）
        int[] tails = new int[nums.length];
        int len = 0;                       // 当前 tails 的有效长度 = 目前 LIS 长度

        for (int x : nums) {
            // 手写 lower_bound：在 tails[0..len-1] 找第一个 >= x 的位置
            // 为什么是「>=」而不是「>」：严格递增要求相等的值不能接在后面，必须替换
            int lo = 0, hi = len;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1; // 无符号右移：lo+hi 溢出时也不会变负数
                if (tails[mid] < x) {
                    lo = mid + 1;          // 位置和它左边都 < x，答案在右半区
                } else {
                    hi = mid;              // mid 本身可能是答案，保留在区间内
                }
            }

            tails[lo] = x;                 // 覆盖（lo < len）或写入新槽位（lo == len）
            if (lo == len) {
                len++;                     // 只有「扩展到尾部」才让答案 +1
            }
        }
        return len;                        // 空数组时 len = 0，天然正确
    }
}
```

### 121.5.2 Go

```go
package main

import "sort"

func lengthOfLIS(nums []int) int {
	// tails 的语义与 Java 版完全一致：tails[k] = 长度 k+1 的递增子序列的最小结尾
	// 用切片而不是定长数组：append 只在「扩展尾部」时发生，最多 n 次
	tails := make([]int, 0, len(nums))

	for _, x := range nums {
		// sort.SearchInts 返回第一个 >= x 的下标 = lower_bound，正是严格递增所需
		// 若题目改成「非递减」，这里要换成 sort.Search(len(tails), func(i int) bool { return tails[i] > x })
		p := sort.SearchInts(tails, x)
		if p == len(tails) {
			tails = append(tails, x) // 比所有元素都大 → 答案长度 +1
		} else {
			tails[p] = x // 同一长度换一个更小的结尾
		}
	}
	return len(tails) // 空切片返回 0
}
```

### 121.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二分从哪来 | 必须手写 `lower_bound`（`Arrays.binarySearch` 在找不到时返回 `-(insertion)-1`，语义绕） | 标准库 `sort.SearchInts` 直接给出 `lower_bound` | Go 代码更短；但**面试常要求手写**，所以 Java 版故意展开写 |
| 容器 | `int[] tails = new int[n]` 定长，用 `len` 记有效区 | `make([]int, 0, n)` + `append` | Go 的 `append` 可能扩容并复制，这里给了 cap 所以最多复制 O(log n) 次；Java 定长数组零额外开销 |
| 有效长度 | 单独一个 `int len` 变量 | `len(tails)` 自带 | Go 少一个状态变量，**少一个可以写错的地方** |
| 越界 | `tails[n-1]` 越界抛 `ArrayIndexOutOfBoundsException` | 越界 panic，栈信息更短 | 都必须在 `lo < hi` 的 `hi = len` 上用「半开区间」写法，避免 `len-1` |
| 溢出 | `(lo+hi)>>>1` 处理 | `lo + (hi-lo)/2` 处理 | Go 的 `int` 在 64 位平台更宽，但**可移植代码应两种都按 32 位写** |
| 比较语义 | `-` 可能溢出（`Integer.MIN_VALUE - 1`），所以用 `<` | 同 | 本题 `nums[i]` 到 `10⁴`，无风险；但排序比较器里写 `a - b` 是常见溢出坑 |

### 121.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：经典的 O(n^2) 定义式 DP，与 tails 版实现路径完全不同
func lisBrute(nums []int) int {
	n := len(nums)
	best := 0
	dp := make([]int, n)
	for i := 0; i < n; i++ {
		dp[i] = 1
		for j := 0; j < i; j++ {
			if nums[j] < nums[i] && dp[j]+1 > dp[i] {
				dp[i] = dp[j] + 1
			}
		}
		if dp[i] > best {
			best = dp[i]
		}
	}
	return best
}

func TestLengthOfLISRandom(t *testing.T) {
	// 边界必须单独立测：随机几乎抽不到「空数组」「全相同」「完全逆序」这些点
	edges := [][]int{
		{},                    // 空数组 → 0
		{1},                   // 单元素 → 1
		{7, 7, 7, 7},          // 全相同 → 1（严格递增的关键反例）
		{4, 3, 2, 1},          // 完全逆序 → 1
		{1, 2, 3, 4, 5},       // 已递增 → 5
		{-5, -3, -1, -7},      // 负数
		{1, 3, 6, 7, 9, 4, 10, 5, 6}, // tails 被反复覆盖的经典样例
	}
	for _, a := range edges {
		if got, want := lengthOfLIS(a), lisBrute(a); got != want {
			t.Fatalf("edge %v got=%d want=%d", a, got, want)
		}
	}

	r := rand.New(rand.NewSource(121300))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(30)
		a := make([]int, n)
		for i := range a {
			// 值域刻意压到 [-5, 5]：重复值与相邻值密集，才能逼出 lower/upper bound 的差异
			a[i] = r.Intn(11) - 5
		}
		if got, want := lengthOfLIS(a), lisBrute(a); got != want {
			t.Fatalf("iter=%d a=%v got=%d want=%d", iter, a, got, want)
		}
	}
}
```

> 📌 **为什么要加权制造重复值**：`lower_bound` 与 `upper_bound` 只有在**数组里有等值元素**时才产生分歧。均匀随机大值域的数组里等值概率极低，写完就通过的代码可能是错的。把值域压到 11 个取值，2 万次里几乎每轮都含重复。

## 121.6 复杂度与常见坑

### 121.6.1 复杂度推导（写结论不算本事，要能推）

- **`O(n²)` 版**：外层 `n` 次，内层对每个 `i` 扫 `0..i-1` 共 `i` 次 → 总比较次数 `Σ i = n(n-1)/2`。`n = 2500` 时约 **3.1·10⁶** 次，实测 Java 30 ms / Go 18 ms。
- **`O(n log n)` 版**：外层 `n` 次；内层二分区间长度从 1 长到 `L`（`L` 是最终答案），每次 `⌈log₂(L+1)⌉` 次比较。总计 `Σ log(len_i) ≤ n log n`。`n = 2.5·10⁵` 时约 4.5·10⁶ 次比较。
- **空间**：`tails` 最坏 `n` 个（整个数组递增时），最好 `O(L)`。`O(n²)` 版是 `O(n)`。**两版都不能压到 `O(1)`**：`tails` 的每个槽位都在被后续元素读取。
- **为什么不可能更快**：这是「最长链」问题，一般情况下的下界是 `Ω(n log n)`（可归约到元素唯一性判定）；只有在值域很小（本题 `2·10⁴`）时，用「桶 + 并查集/树状数组」能做到 `O(n log log V)` 之类的改进，实践中不必要。

### 121.6.2 七个真实踩过的坑

1. **`tails` 当成答案序列打印** —— `tails` 长度对、内容错（§121.4.2 第 2 步）。要输出序列必须加前驱数组（§121.3.4）。
2. **哨兵用 `0` 或 `-1`** —— `nums = [-5,-3,-1]` 时答案 3，但若把 `best` 初始化为 0 并只在与正数比较，会答 0。**最值题的初值要用「真正的下界」**（长度类用 0 安全，金额类必须用 `Integer.MIN_VALUE`）。
3. **`<=` 与 `<` 混用** —— 用 `upper_bound` 实现「严格递增」会让 `[7,7,7]` 答 3（正确 1）。判定口诀：**严格递增用 `lower_bound`（第一个 `≥ x`），非递减用 `upper_bound`（第一个 `> x`）**。
4. **二分写成「找最后一个 `< x`」再 +1 却把边界写错** —— `lo = 0, hi = len` 的半开区间里，`hi` 初值必须是 `len` 而不是 `len-1`，否则「全部更小 ⇒ 追加」这条分支永远走不到，答案少 1。
5. **`(lo + hi) / 2` 在最坏情况下溢出** —— `lo + hi` 可超过 `2³¹-1`（本题不会，但这是二分模板的肌肉记忆）。用 `lo + (hi-lo)/2` 或 `(lo+hi)>>>1`。
6. **`O(n²)` 版把 `dp` 初始化为 0** —— `[4,3,2,1]` 会答 0。`dp[i]` 至少是 1（单个元素自身构成序列）。
7. **`n = 0` 时 `new int[0]` 上访问 `tails[0]`** —— Java 抛异常、Go panic。本题约束 `n ≥ 1`，但把这段代码复用到 LC 354（信封可能为空）时必须先判空。

### 121.6.3 面试官最爱追问的三个问题

**Q1：`O(n²)` 已经能过，为什么还要写 `O(n log n)`？**

> 「因为 `2500` 是出题人给的舒适区，真实业务里序列长度是 `10⁵`~`10⁶` 量级。而且 `tails` 这个结构本身是可迁移的：它就是耐心排序，`tails` 数组的严格递增性也解释了为什么『区间调度』『最长数对链』这类题只需要一个贪心代表元。面试里我会先写 `dp[i]` 定义的那版讲清转移，再说『把状态换成 `tails[k] = 长度 k+1 的最小结尾` 就能二分』——先说清定义再加优化，比直接背 `lower_bound` 更能证明理解。」

**Q2：`tails` 数组里的元素是不是某条 LIS？**

> 「不是。`tails[k]` 只保证『存在一条长度 `k+1`、结尾为这个值的递增子序列』，不保证这些值能拼成一条完整序列 —— 后面的替换会改写前面的历史（`[10] → [9]` 那一步就是）。所以它只能回答『长度』，要回答『序列』必须额外维护 `pre` 前驱数组，并且只能回到 `O(n²)` 或树状数组版。」

**Q3：如果要统计 LIS 的条数（LC 673）怎么办？**

> 「`tails` 版失效，因为压缩掉的信息恰好是『有哪些前驱能接上』。做法是 `O(n²)`：`dp[i]` 记长度、`cnt[i]` 记方案数；当 `dp[j]+1 > dp[i]` 时重置 `cnt[i] = cnt[j]`，当 `dp[j]+1 == dp[i]` 时累加 `cnt[i] += cnt[j]`；最后对所有 `dp[i] == L` 的位置累加。若 `n` 是 `10⁵`，用树状数组维护 `(长度, 方案数)` 的二元组最大值，比较时先比长度再比方案数。」
