## 141.1 题目

**原题链接**：<https://leetcode.cn/problems/number-of-1-bits/>

### 题意重述（把隐含条件补齐）

给你一个整数 `n`，把它看成 **32 位**的**无符号**二进制串，返回其中**数字 `1` 的个数**（这个量有个正式名字：**汉明重量**，英文 popcount / Hamming weight）。

看似一句话结束，但它藏了四个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 位宽**固定 32 位** | 「输入必须是长度为 32 的二进制串」 | 用「一直右移直到 0」的写法，在 Java 里碰上负数会**死循环**（算术右移的高位永远补 1） |
| `n` 是**无符号**的 | 「无符号整数」 | `n > 0` 不能当循环条件：Java 的 `int` 是有符号的，`0x80000000` 会被读成 `-2147483648` |
| 只问**个数**，不问位置 | 「返回其二进制表达式中数字位数为 `1` 的个数」 | 想要位置就会顺手写成「逐位 `& 1`」，多绕一步 |
| 进阶：会被**多次调用** | 「如果多次调用这个函数，你将如何优化」 | 只看单次 O(32) 会说「已经最优」，答不到进阶那层 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n` 是 32 位无符号整数 | 值域 `0 ~ 2³²−1` | 位宽是个**常数 32**，所以任何「按位扫一遍」的解法都是 O(1)。本题的复杂度比较不在量级，而在**常数因子**：32 次 vs `popcount` 次 |
| 无符号 | `0xFFFFFFFF` = `4294967295` | 最高位为 1 时，Java 的 `int` 拿到的是**负数**；Go 里如果写 `int`，64 位平台上又是 8 字节。位宽与符号必须主动定下来 |
| 进阶要求「多次调用」 | 题面明写 | 这把「每次重扫 32 位」推到了台面上：如果调用 `10⁷` 次，32 次/次就是 `3.2·10⁸` 次位运算 |

> 💡 **量级 → 算法** 在这里要换一种读法：`n` 的大小不重要（它只占 32 位，是常数），**重要的是「1 的个数」这个量**。
> 记住这条条件反射：**看到「统计二进制里 1 的个数 / 判断是不是 2 的幂 / 数末尾多少个 0」，先想 `n & (n-1)` 和 `n & (-n)` 这对工具。**

### 示例

```text
输入：n = 11              二进制 0000 0000 0000 0000 0000 0000 0000 1011
输出：3                   因为有 3 个 1

输入：n = 128             二进制 ...1000 0000
输出：1

输入：n = 4294967293      二进制 0xFFFFFFFD = ...1111 1101
输出：31                  只有最低位是 0
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① n = 0                    → 答案 0。暴露「先执行再判断」的 do-while 写法（会多算一次）
② n = 0x80000000           → 答案 1。Java 里这个 int 是 -2147483648，
                             暴露 `while (n > 0)` 直接不进循环 → 返回 0
③ n = 0xFFFFFFFF           → 答案 32。暴露 `n >>= 1` 的算术右移死循环
                             （负数右移高位补 1，n 永远不等于 0）
④ n = 0x00000001           → 答案 1。暴露「把 `n & (n-1)` 写成 `n & (-n)`」：
                             `1 & -1 = 1` 不变，循环原地转死
```

第 ③ 条是 Java 独有的坑：`>>` 是**算术右移**（符号位跟着走），`>>>` 才是**逻辑右移**（高位补 0）。而 `n & (n-1)` 这条路线**根本不右移**，所以天然免疫这个坑——这也是它的价值之一。

## 141.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的一版：把 32 位一个一个看过去。

```java
// 逐位检查：第 i 位是不是 1
int cnt = 0;
for (int i = 0; i < 32; i++)
    if (((n >>> i) & 1) == 1) cnt++;
return cnt;
```

- 时间 **O(32)**，其实已经是常数；空间 **O(1)**。
- 32 次循环，每次「右移 + 与 + 比较」，本机实测（2 核容器 / JDK 17 / Go 1.19）单次调用约 **20 ns**。**它是能过题的**。
- 那它错在哪？错在**它做了与答案无关的功**：`n = 1` 时答案一眼就能看出是 1，它却要老老实实看 32 位。如果进阶要求「调用 `10⁷` 次」，累计 `3.2·10⁸` 次位运算 ≈ 0.4 s，而真正需要处理的 `1` 通常只有几个到几十个。

### 第二步：卡点在哪

把问题翻译成一句话：

> **我要的是「有多少个 1」，不是「哪些位置是 1」。**

于是卡点变成一个很具体的问题：

> **能不能设计一种操作，让它「每执行一次，就恰好弄掉一个 1」，这样循环次数天然等于答案？**

如果存在这样的操作，循环体执行 `popcount(n)` 次就结束，**循环次数本身就是答案**——不需要额外的判断，不需要扫过那些 0 位。

### 第三步：灵感的来源 —— `n - 1` 会「借位到最低位的 1」

观察一个数的减一过程。把 `n` 的最低位的 `1` 记作位置 `p`（它右边全是 `0`）：

```
n         = ...  1  0  0  0     ← 第 p 位是 1，右边 3 个 0
n - 1     = ...  0  1  1  1     ← 向 p 借 1：p 变 0，右边全变 1
n & (n-1) = ...  0  0  0  0     ← 与之后：p 位变 0，右边本来就是 0，保持 0
                   ↑
              只动了「p 及它右边」，p 左边一位没动
```

于是得到本章的主角恒等式：

```
n & (n - 1)  =  把 n 的最低位 1 抹成 0，其余位不变
```

这是一个**单调下降**的操作：每次至少清掉一个 1，且不会凭空造出新的 1。所以反复执行必然在**有限步**内把 `n` 变成 `0`，而**步数恰好等于 1 的个数**。

```java
int cnt = 0;
while (n != 0) { n &= n - 1; cnt++; }
return cnt;
```

**四行。这就是最优解。**

### 为什么「除以 2」或「异或」不行（这一步必须想清楚，否则换皮就废）

- **`n / 2`（或右移）**：它消掉的是**最低位**，不管这一位是 0 还是 1。所以循环一步只前进一个二进制位，最坏 32 步，且要用 `cnt += n & 1` 补一次判断——它退化成「逐位扫描」。
- **异或**：`n ^ n = 0` 是把**整个数**抹掉，它没有「只抹一个 1」的粒度。140 章的异或是「整段折叠」，本章需要的是「单位点操作」，两者粒度不同。
- **取最低位 1（`lowbit`）**：`n & (-n)` 得到的是**最低位那个 1 的值**（如 `10110 → 10`），它是**取**不是**消**。`140` 章的 LC 260 用它分组，本章要用它的**对偶**。这一对工具必须分清：

| 写法 | 效果 | 典型用途 |
| --- | --- | --- |
| `n & (n - 1)` | **消**掉最低位的 1 | 数 1 的个数（191）、判 2 的幂（231）、判 4 的幂（342） |
| `n & (-n)` | **取**出最低位的 1（低位不变，其余清零） | 树状数组 BIT、LC 260 分组、`lowbit` 分解 |

## 141.3 原理拆解

### 141.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐位 `(n >>> i) & 1` | O(32) | O(1) | 3 行 | 高频调用且 `1` 稀疏时做无用功；Java 写成 `>>` 会死循环 |
| **`n & (n-1)` 消位** ✅ | **O(popcount)** ≤ O(32) | **O(1)** | **4 行** | 需要并行化（超长位串/SIMD）时要换 SWAR |
| 8 位查表（256 项） | O(4) 次查表 | O(256) | 8 行 | 内存紧；表初始化有一次性成本 |
| SWAR 位并行（`0x55555555` 那套掩码） | O(1) 约 12 条指令，**固定** | O(1) | 10 行 | 可读性差，除非极端性能敏感（编译器内建就是这么做的） |
| `Integer.bitCount` / `bits.OnesCount32` | 内建，通常编译成单条 `popcnt` 指令 | O(1) | 1 行 | 面试里被追问「自己实现」时会露怯 |

**为什么「`n & (n-1)` 是这题的答案」**：本题的三条信息（只要个数、32 位固定、可能高频调用）恰好让「每次消一个 1」成为最贴合的做法——**循环次数 = 答案**，既不扫过 0 位，也不需要额外状态。

### 141.3.2 为什么这个做法是对的（正确性论证）

**命题 1（消位恒等式）**：对任意整数 `n > 0`，`n & (n - 1)` 等于「把 `n` 的最低位的 `1` 改成 `0`，其余位不变」。

**证明**：设 `n` 最低位的 `1` 在第 `p` 位（从 0 开始计数），即 `n = H·2^{p+1} + 2^p`，其中 `H` 是 `p` 左边那一段二进制（可以为 0），且 `p` 位右边全是 `0`。

1. `n - 1` 的借位只发生在 `p` 及其右边：`2^p - 1 = Σ_{i<p} 2^i`，那些位本来是 `0`，减一后变成全 `1`；`p` 位从 `1` 变 `0`；`H` 那一段**没有借位传上去**，保持原样。
   于是 `n - 1 = H·2^{p+1} + 0·2^p + (2^p - 1)`。
2. 按位与：高位 `H` 与 `H` 与得 `H`；第 `p` 位 `1 & 0 = 0`；`p` 右边的位 `0 & 1 = 0`。
3. 合起来 `n & (n-1) = H·2^{p+1}`，正是「只把第 `p` 位的 1 抹掉」。∎

**命题 2（算法返回的就是 1 的个数）**：

```
不变量：每次循环开始前，popcount(n) = 原输入的 1 的个数 − cnt
```

- 初始化：`cnt = 0`，等式成立。
- 保持：循环体执行 `n &= n - 1`，由命题 1，`popcount` 恰好减 1；`cnt++` 使右边也减 1，等式保持。
- 终止：循环在 `n == 0` 时退出，此时 `popcount(n) = 0`，代入不变量得 `cnt = 原输入的 1 的个数`。∎

**终止性**：每次循环 `popcount` 严格减 1 且下界为 0，故最多 `popcount` 次后结束，不可能死循环（前提是 `n` 用**位运算**判零，而不是用 `n > 0`）。

### 141.3.3 通用解题思路（可迁移的那一层）

本章要讲的核心工具就是 `n & (n-1)` 的**三个等价说法**，面试时能说出哪一个决定你是否真的懂：

| 说法 | 表述 | 立刻能解决的问题 |
| --- | --- | --- |
| 位操作版 | 把最低位的 `1` 清零 | 统计 1 的个数 |
| 判定版 | `n & (n-1) == 0` ⟺ `n` 是 **2 的幂**（或 `n == 0`） | LC 231 2 的幂、LC 342 4 的幂 |
| 计数版 | `n` 能执行几次「消位」就是它有几个 1 | LC 762 二进制表示中质数个计算置位 |

**判定版为什么成立**（顺手证一下，因为它是最常被追问的一句）：`n` 是 2 的幂 ⟺ 它的二进制恰好只有**一个** `1` ⟺ 消掉这个 1 之后是 0。反过来，若 `n & (n-1) == 0` 且 `n > 0`，说明消掉最低位的 1 之后没有别的 1 了，也就是只有一个 1。∎

**迁移模型：位级问题的两种粒度**

```
整段粒度：对整个数做一次运算      → 异或折叠（140 章，一次性处理全部位）
单位粒度：每次只处理一个 1        → n & (n-1)（本章）
区间粒度：按掩码分段并行处理      → SWAR / bitset（扩展方向）
```

遇到位运算题，先问自己一句：**「我这题该用哪种粒度？」** 191 要个数，用单位粒度最省。

属于同一个「单位粒度」模型的题：

| 题 | 用 `n & (n-1)` 做什么 |
| --- | --- |
| [LC 191](https://leetcode.cn/problems/number-of-1-bits/) | 数 1 的个数（每消一次计数加一） |
| [LC 231](https://leetcode.cn/problems/power-of-two/) | 判 `n & (n-1) == 0 && n > 0` |
| [LC 342](https://leetcode.cn/problems/power-of-four/) | 4 的幂 = 2 的幂 且 唯一的 1 在**偶数位**（与 `0x55555555` 与一下） |
| [LC 461](https://leetcode.cn/problems/hamming-distance/) | 先 `a ^ b` 把「不同的位」标出来，再数 1 |
| [LC 762](https://leetcode.cn/problems/prime-number-of-set-bits-in-binary-representation/) | 数 1 的个数 → 判质数 |
| [LC 338](https://leetcode.cn/problems/counting-bits/) | 从「单个数」升级成「0 ~ n 全体」→ 下一章 |

### 141.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 变成 **64 位** | 位宽从 32 到 64 | 恒等式与位宽无关，改 `long` / `uint64` 即可；注意 Java 里 `1L << 63` 才不会溢出 |
| 「**多次调用**怎么优化」 | 高频、输入重复 | ① 8 位查表（256 项 `byte`，O(4) 次查表）② 缓存结果（输入重复多时哈希表）③ 直接用 `popcnt` 内建 |
| 要**并行**处理 512 位 / SIMD | 一条指令算多段 | SWAR：分半加、用 `0x33333333`、`0x0F0F0F0F`、`0x01010101` 三段掩码把「数 1」变成「加字节」，最终 `(x * 0x01010101) >>> 24` |
| 输入是**大整数**（任意长度） | 超出机器字 | 按字节切成块，对每块用查表 + 累加；或转成 `[]uint64` 逐段 SWAR |
| 要返回**位置列表**而不是个数 | 需要具体下标 | 改用 `lowbit`：`low = n & (-n)` 取一个位置，`n ^= low` 消掉它，循环下去；这与本章互为对偶 |
| 位串是**动态变化的**（边改边查） | 需要增量维护 | 维护一个计数器：置位时 +1、清位时 −1（用 `n ^ x` 前后的 popcount 差），避免每次重扫 |

## 141.4 图解推演

### 141.4.1 三步消位的完整轨迹（n = 11）

```
n = 11 = 1 0 1 1

第 1 轮
  n          = 1 0 1 1
  n - 1      = 1 0 1 0     ← 最低位 1（第 0 位）被借走
  n & (n-1)  = 1 0 1 0     ← 第 0 位清零，cnt = 1

第 2 轮
  n          = 1 0 1 0
  n - 1      = 1 0 0 1     ← 最低位 1（第 1 位）被借走，右边翻成全 1
  n & (n-1)  = 1 0 0 0     ← cnt = 2

第 3 轮
  n          = 1 0 0 0
  n - 1      = 0 1 1 1     ← 最低位 1（第 3 位）被借走，右边三位全翻 1
  n & (n-1)  = 0 0 0 0     ← cnt = 3，n 归零，循环结束
```

```
     ┌──────────────────────────────────────────────┐
     │  每次 n &= n-1 ：                           │
     │    最低位的 1  ──► 变 0                      │
     │    它右边的 0  ──► 先被借成 1，再被 & 清掉    │
     │    左边的位    ──► 一位都没动                 │
     └──────────────────────────────────────────────┘
```

### 141.4.2 逐步状态表（列 = 变量）

| 轮次 | `n`（十进制） | `n`（二进制） | `n - 1` | `n & (n-1)` | `cnt` |
| --- | --- | --- | --- | --- | --- |
| 0（初始） | 11 | `1011` | — | — | 0 |
| 1 | 10 | `1010` | `1010` | `1010` | 1 |
| 2 | 8 | `1000` | `1001` | `1000` | 2 |
| 3 | 0 | `0000` | `0111` | `0000` | 3 |

> 注意第 2 行：`n = 10` 时 `n - 1 = 9 = 1001`，最低位 1 在第 1 位，右边那一位（第 0 位）本来是 0，被借成 1，`&` 之后又清回 0 —— 这就是「它右边的 0 只是路过」的含义。

### 141.4.3 两种粒度的对比图

```
输入 n = 0x80000001 = 1000 ... 0001（只有 2 个 1，共 32 位）

逐位扫描（32 步）：
  位号 0  ──1──► cnt=1
  位号 1  ──0──► （白跑）
  位号 2  ──0──► （白跑）
   ...   ──0──► （白跑 29 次）
  位号 31 ──1──► cnt=2
  合计：32 次位运算

n & (n-1)（2 步）：
  第 1 步  ...0001 ──► ...0000    cnt=1
  第 2 步  1000... ──► 0000...    cnt=2
  合计：2 次位运算
```

> **这张图就是「循环次数 = 答案」的可视化**：稀疏输入下差距可以到 16 倍。

## 141.5 双语言实现

### 141.5.1 Java

```java
class Solution {
    public int hammingWeight(int n) {
        int cnt = 0;
        // 必须用 n != 0 而不是 n > 0：LeetCode 的 Java 签名是 int（有符号），
        // 当输入最高位为 1（如 0x80000000）时会变成负数，用 > 0 会直接不进循环。
        while (n != 0) {
            // 关键一步：把最低位的 1 抹成 0，其余位一位不动（见 §141.3.2 命题 1）。
            // 循环次数恰好等于 1 的个数，不会扫过任何 0 位。
            n &= n - 1;
            cnt++;
        }
        return cnt;
    }
}
```

### 141.5.2 Go

```go
package main

func hammingWeight(num uint32) int {
	cnt := 0
	// 参数用 uint32 而不是 int：位宽与题目要求的 32 位严格对齐。
	// Go 的 int 在 64 位平台是 64 位，若用 int，位宽会随平台变化，
	// 这类「位宽就是语义」的题必须用定宽类型。
	for num != 0 {
		num &= num - 1
		cnt++
	}
	return cnt
}
```

> 位运算与符号无关：`num - 1` 在 `num = 0` 时会下溢成大正数（`uint32` 无符号回绕），但循环条件 `num != 0` 已经把它挡在外面，所以不会执行到那一步。

### 141.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `int` 宽度 | 恒 **32 位**，有符号 | 64 位平台上是 **64 位**，有符号 | 本题语义要求 32 位，所以 Go 端用 `uint32` 把位宽钉死 |
| 无符号整数 | 没有独立类型，只有 `>>>` 与 `Integer.compareUnsigned` | 有 `uint32` / `uint64` | 「按位看」的题（191、190）Go 写起来更自然；Java 要靠 `>>>` 与 `& 0xFFFFFFFFL` 补齐 |
| 右移语义 | `>>` 算术（补符号位）、`>>>` 逻辑（补 0） | 只有 `>>`，语义由**类型**决定（无符号类型就是补 0） | Java 用 `>>` 处理负数会死循环；本题不右移，天然安全 |
| 最高位 1 的字面量 | `1 << 31` 是负数，要写 `1L << 31` | `uint32(1) << 31` 正常 | 自造测试用例时容易踩 |
| 内建 popcount | `Integer.bitCount(n)` | `math/bits.OnesCount32(num)` | 面试时说出内建名是加分项，但要求手写时必须能写出 `n & (n-1)` |

### 141.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/bits"
	"math/rand"
	"testing"
)

// 参考实现：老老实实数 32 位，肉眼可验证，不含任何技巧
func brutePopcount(n uint32) int {
	cnt := 0
	for i := 0; i < 32; i++ {
		if (n>>uint(i))&1 == 1 {
			cnt++
		}
	}
	return cnt
}

func TestHammingWeightRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20260214))
	for iter := 0; iter < 20000; iter++ {
		// 三类输入混合：随机全 32 位 / 低位稀疏 / 高位单点，逼出位宽与符号问题
		var n uint32
		switch iter % 3 {
		case 0:
			n = r.Uint32()
		case 1:
			n = uint32(r.Intn(1 << 10)) // 低位稀疏
		default:
			n = 1 << uint(r.Intn(32)) // 单个 1 的高位
		}
		want := brutePopcount(n)
		if got := hammingWeight(n); got != want {
			t.Fatalf("iter=%d n=%#x got=%d want=%d", iter, n, got, want)
		}
		// 与标准库再交叉验证一次，防止「参考实现和被测实现同错」
		if got := hammingWeight(n); got != bits.OnesCount32(n) {
			t.Fatalf("iter=%d n=%#x got=%d OnesCount32=%d", iter, n, got, bits.OnesCount32(n))
		}
	}
}

func TestHammingWeightEdge(t *testing.T) {
	cases := []struct {
		n    uint32
		want int
	}{
		{0, 0},          // 全 0：一次循环都不进
		{1, 1},          // 最低位 1
		{0x80000000, 1}, // 最高位 1：Java 侧对应的 int 是负数
		{0xFFFFFFFF, 32}, // 全 1：循环 32 次
		{0xFFFFFFFD, 31},
		{0xAAAAAAAA, 16},
	}
	for _, c := range cases {
		if got := hammingWeight(c.n); got != c.want {
			t.Fatalf("n=%#x got=%d want=%d", c.n, got, c.want)
		}
	}
}
```

> **为什么要和 `bits.OnesCount32` 再比一次**：参考实现用的是「逐位扫描」，被测实现用的是「消位」，两者的 bug 方向不同，但都可能与「真实答案」一起错（比如都漏了最高位）。加一个**互不相关的第三方**（标准库）能让对拍更可信。

## 141.6 复杂度与常见坑

### 141.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(1)**，更精确是 **O(popcount(n)) ≤ O(32)**：由 §141.3.2 的不变量，每次循环 `popcount` 严格减 1，所以循环次数 = `popcount(n)`。每次循环是「一次减一 + 一次与 + 一次自增」，都是固定代价的机器指令。
- **空间 O(1)**：只有 `cnt` 与 `n` 两个机器字，与输入无关。
- **和逐位扫描的差别在常数上**：`n = 0x80000001` 时，消位法 2 步、扫描法 32 步，差 **16 倍**；`n = 0xFFFFFFFF` 时两者都是 32 步，此时消位法**没有优势**。这就是为什么面试官会问「最坏情况呢」——**要主动说出「最坏 O(32)，最好 O(1)」**。
- **对比**：8 位查表是 O(4) 次查表（4 次循环，常数更小但常数更大空间），SWAR 是**固定约 12 条指令**（与输入完全无关，最坏情况下更快）。

### 141.6.2 七个真实踩过的坑

1. **`while (n > 0)` 处理负数** —— `0x80000000` 在 Java 里是 `-2147483648`，`> 0` 为 false，直接返回 0（正确答案是 1）。必须写 `n != 0`。
2. **`n >>= 1` 死循环** —— 算术右移补符号位，负数永远移不到 0。要么用 `>>>=`，要么根本别右移。
3. **`n & (n-1)` 写成 `n & (-n)`** —— 后者是 `lowbit`，**取**最低位 1 而**不清**它，`n = 1` 时 `1 & -1 = 1`，循环原地打转。
4. **运算符优先级** —— Java / Go 里 `==` 的优先级**高于** `&`，`if (n & n-1 == 0)` 会被解析成 `n & (n-1 == 0)`，编译报错（Java 中 `int & boolean` 不合法）或语义错。永远写 `(n & (n-1)) == 0`。
5. **Go 用 `int` 而不是 `uint32`** —— 位宽变成 64 位，`num - 1` 在 `num = 0` 时回绕成 `-1`（有符号），若循环条件写错就会无限循环。定宽类型是这类题的硬要求。
6. **把 `n` 当有符号数做 `Math.abs`** —— `Math.abs(Integer.MIN_VALUE) == Integer.MIN_VALUE`（补码不对称），任何「先取绝对值」的思路都会在 `0x80000000` 上失效。
7. **用 `n & (n-1)` 判断 2 的幂却忘了排除 0** —— `0 & (-1) == 0`，于是 `n = 0` 被误判成 2 的幂。判定必须写 `n > 0 && (n & (n-1)) == 0`。

### 141.6.3 面试官最爱追问的三个问题

**Q1：为什么 `n & (n-1)` 恰好能消掉最低位的 1？**

> 「减一的时候，借位只会发生在**最低位的 1 及其右边**：那一位由 1 变 0，右边的 0 全被借成 1。再做按位与，右边那些位是 `0 & 1 = 0`（原来是 0 保持不变），那一位是 `1 & 0 = 0`，而更高位两边完全相同、与得原值。合起来就是『只把最低位的 1 清零』。这个操作每次至少清掉一个 1，所以循环次数就等于 1 的个数。」

**Q2：如果要求 O(1) 且与输入完全无关，怎么做？**

> 「用 SWAR（`divide and conquer` 式的位并行）：先两两一组把 1 数成 2 位，再四四一组数成 4 位，再 8 位，三步掩码 `0x33333333`、`0x0F0F0F0F`、`0x01010101` 把 32 个计数器塞进 4 个字节，最后一次乘法 + 右移把字节求和。固定约 12 条指令，没有任何数据依赖的分支。现代 CPU 直接给了 `popcnt` 指令，Java 的 `Integer.bitCount` 与 Go 的 `bits.OnesCount32` 一般就编译成它。」

**Q3：如果输入是负数（Java 的 `int`），你的解法还成立吗？**

> 「成立，因为 `n & (n-1)` 完全不关心符号位——它只做位运算，补码下每一位都是良定义的。唯一要小心的是**循环条件和右移**：用 `n != 0` 而不是 `n > 0`，并且不要用算术右移 `>>`。如果一定要在 Java 里用『右移直到 0』的写法，必须换成逻辑右移 `>>>`。」
