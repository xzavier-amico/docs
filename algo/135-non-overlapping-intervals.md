## 135.1 题目

**原题链接**：<https://leetcode.cn/problems/non-overlapping-intervals/>

### 题意重述（把隐含条件补齐）

给你一个区间数组 `intervals`，其中 `intervals[i] = [start_i, end_i]`。你要**移除最少数量的区间**，使得剩下的区间**两两互不重叠**。返回需要移除的区间数量。

「不重叠」的定义是本题第一个必须读准的地方：两个区间 `[1,2]` 与 `[2,3]` 在端点 `2` 处相接，**算作不重叠**。也就是把区间看成**左闭右开**的 `[start, end)`。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **端点相接不算重叠** | 「区间 `[1,2]` 和 `[2,3]` 在 2 处不重叠」 | 用 `>` 而不是 `>=` 判断 → `[[1,2],[2,3]]` 会错答成移除 1（正确是 0） |
| **求「移除数」，不是「保留数」** | 「返回需要移除的区间的最小数量」 | 忘记 `n - keep`，直接返回 `keep` → 全错 |
| **可以移除任意区间** | 「移除区间」 | 误以为只能移除末尾 → 变成另一道题 |
| **不要求输出方案** | 「返回…数量」 | 多写回溯反而增加复杂度 |
| **区间个数可为 1** | 约束 `1 <= n` | 答案 `0`；不特判会访问 `intervals[1]` 越界 |
| **端点可为负、可重复** | `-5·10^4 <= start < end <= 5·10^4` | 用「值域当桶」的写法会踩负数下标 |

> 第二条与第三条合起来定义了问题的**形状**：这是一个「最大化保留」问题（`n - 最大不重叠子集大小`），而「最大化保留」恰好有一个 O(n log n) 的贪心解 —— 这就是 §135.3.3 要抽象成模型的东西。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= intervals.length <= 10^5` | 最多 10 万 | **O(n²) 的 DP 是 `10^10`，必超时**；O(n log n)（排序主导）才是目标 |
| `intervals[i].length == 2` | 每组恰好两个数 | 无「退化区间」 |
| `-5·10^4 <= start_i < end_i <= 5·10^4` | 端点范围小、且 `start < end` | 严格不等式保证每个区间非空；端点值小到可以当数组下标，但**负数下标**要偏移 |
| 区间个数与端点值差别很大 | `n` 高达 `10^5`，端点只有 `10^5` 个取值 | 说明「桶排」也是一种可选的 O(n + V) 排序，但没必要 |

> 💡 **量级反推**：`n = 10^5` ⟹ 只能 O(n log n) 或 O(n)。而本题的 O(n log n) 那 `log n` 只来自排序 —— 也就是说：**排序之后必须只用线性扫描，不能有任何「回头看」的环节**。这个限制直接决定了贪心的形状。

### 示例

```
输入：intervals = [[1,2],[2,3],[3,4],[1,3]]
输出：1
解释：移除 [1,3] 后，剩下的 [[1,2],[2,3],[3,4]] 两两不重叠

输入：intervals = [[1,2],[1,2],[1,2]]
输出：2
解释：三个完全相同的区间最多保留 1 个

输入：intervals = [[1,2],[2,3]]
输出：0
解释：端点相接 → 不重叠 → 不需要移除
```

### 我自造的四个反例

```text
① [[1,2]]                        → 答案 0（单区间；不特判会越界）
② [[1,2],[2,3]]                  → 答案 0（端点相接必须判为不重叠）
③ [[1,100],[2,3],[3,4]]          → 答案 1（保留后两个）。这组是「按左端点排序」的死刑判决书
④ [[1,2],[1,2],[1,2]]            → 答案 2（完全相同也要正确去重计数）
⑤ [[-5,-4],[-3,-2],[-1,0]]       → 答案 0（负端点；用值域桶排序时要偏移）
```

第 ③ 条必须记住：按左端点排序会先选 `[1,100]`（最左起点），于是一个都容不下，答案变成 2。**排序键选错，贪心直接错，而且错得理直气壮。**

## 135.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有子集

问题等价于「在区间集合里找**最大的两两不重叠子集**」：

```text
best = 0
for 每个子集 S（2^n 个）:
    if S 内两两不重叠: best = max(best, |S|)
return n - best
```

- 时间 **O(2ⁿ · n²)**，空间 **O(n)**。
- `n = 30` 时 `2^30 ≈ 10^9` 个子集，已经不可能跑完；`n = 10^5` 完全是另一个宇宙。

稍微像样一点的暴力是 DP：把区间按右端点排序，`dp[i] = 「以第 i 个区间结尾的最大不重叠子集大小」`，转移要回头看所有 `j < i` 且 `end_j <= start_i` 的区间：

```
dp[i] = 1 + max{ dp[j] : j < i 且 end_j <= start_i }
```

- 时间 **O(n²)**，空间 **O(n)**。
- `n = 10^5` 时 `5·10^9` 次比较 —— **必超时**。

> 注意这个 DP 已经用到了「按右端点排序」这个观察！它的问题是：每次都要回头找 `max dp[j]`。而**贪心做的事情就是把这次「回头找最大值」变成「不需要找」**。

### 第二步：卡点在哪

把 DP 的转移看清楚，会发现一个奇怪的现象：`dp[i]` 的转移里，我们只关心「`j` 的 `dp` 值最大」。而 `dp` 是**随 `i` 单调不减**的（区间越多，能凑出的子集不会变小）。于是：

```
最大的 dp[j]（j 满足 end_j <= start_i） 就是「最后一个满足 end_j <= start_i 的 j」的 dp 值
```

而那个 `j` 恰好就是贪心选出来的「上一个被保留的区间」。**卡点不是「怎么选」，而是「能不能证明选最靠左结束的那个就够了」**。

### 第三步：灵感的来源 —— 交换论证

先看一个直觉：区间之间的冲突，**只由「谁先结束」决定**。一个区间结束得越晚，它挡住的后续区间就越多。所以：

> 在所有候选区间里，**结束最早的那个**，是「对后续伤害最小」的选择。

把它写成可证的命题：**若某个最优解没有选「结束最早的区间 `g`」，那么把它的第一个区间换成 `g`，解不会变差**。这就是交换论证（exchange argument）—— 贪心正确性的标准武器。

```
不变量（本章核心）：贪心选出的前 i 个区间的右端点，
                  都不大于「任何最优解的前 i 个区间的右端点」
                  ⇒ 贪心「用掉的时间轴」永远不多于最优解 ⇒ 后续空间不少于最优解
```

## 135.3 原理拆解

### 135.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举子集（最大独立集） | O(2ⁿ·n²) | O(n) | 10 行 | `n ≥ 25` 就跑不完；只能当对拍判据 |
| DP（`dp[i] = 1 + max{dp[j] : end_j ≤ start_i}`） | O(n²) | O(n) | 10 行 | `n = 10^5` 必超时 |
| DP + 二分（在有序 `end` 上找最后一个 `≤ start_i`） | O(n log n) | O(n) | 15 行 | 能做对但代码更长；本质是「把贪心的证明藏进 DP」 |
| **按右端点排序 + 线性贪心** ✅ | **O(n log n)** | **O(1)** | **9 行** | 区间带权（每个区间有权重）时失效，那时必须回到 DP |
| 按左端点排序 + 贪心 | O(n log n) | O(1) | 9 行 | **错的**，见 §135.4.3 的反例 |
| 按区间长度升序 + 贪心 | O(n log n) | O(1) | 9 行 | **也是错的**，见 §135.6.2 坑 5 |

**为什么「按右端点」能贪、「按左端点」不能**：贪心能否成立，取决于「**你能不能用一个局部最优，安全地压缩掉以后的选择空间**」。右端点是「资源的消耗量」—— 越早结束，占用的时间轴越少，后续可行性只会更好（单调性）。左端点是「资源的起始位置」，它早并不代表省时间（`[1,100]` 起点最早，却几乎吃掉整条时间轴）。

### 135.3.2 为什么这个做法是对的（正确性论证 · 交换论证）

先把算法和记号写清楚：

```text
按 end 升序排序（end 相同则 start 升序，这个次序对正确性无影响但让结果稳定）
keep = 1, lastEnd = intervals[0].end            （n >= 1）
for i = 1 .. n-1:
    if intervals[i].start >= lastEnd:           # 端点相接也算不重叠
        keep++, lastEnd = intervals[i].end
return n - keep
```

**记号**：排序后的区间为 `1, 2, …, n`（下标从 1 开始），满足 `end_1 ≤ end_2 ≤ … ≤ end_n`。
贪心选出的区间按选中顺序记为 `g_1, g_2, …, g_k`（它们是 `1..n` 的一个上升子序列）。
最优解（保留数最多的一个两两不重叠子集）记为 `O`，把 `O` 里的区间**按右端点升序**排成 `o_1, o_2, …, o_m`。目标是证明 `k = m`。

**引理 1（贪心解自身合法）**
贪心每次只在 `start >= lastEnd` 时才收下新区间，而 `lastEnd` 就是上一次收下的区间的右端点，所以任意两个被收下的区间 `g_a, g_b`（`a < b`）满足 `start(g_b) >= end(g_a)`。由于排序保证 `end(g_a) = lastEnd` 当时的值 `<= start(g_b)`，两者不重叠。∎

**引理 2（`O` 按右端点排序后仍两两不重叠）**
`O` 两两不重叠；按右端点升序后，对 `i < j` 有 `end(o_i) ≤ end(o_j)`，且不重叠意味着 `start(o_j) >= end(o_i)`（否则两个区间相交）。所以排序不破坏不重叠性 —— 这个「规范形式」让后面的交换论证只需要对准右端点。∎

**引理 3（核心交换：`end(g_i) ≤ end(o_i)`，且 `g_i` 一定存在）**
对每个 `i = 1, 2, …` 直到 `m`，强归纳证明：① 贪心至少能选出 `i` 个区间（即 `k ≥ i`）；② `end(g_i) ≤ end(o_i)`。

- **基础 `i = 1`**：`g_1` 是**全局**右端点最小的区间（排序后的第 1 个），所以 `end(g_1) ≤ end(o_1)`。① ② 同时成立。
- **归纳步**：设对 `i-1` 成立，即 `k ≥ i-1` 且 `end(g_{i-1}) ≤ end(o_{i-1})`。
  1. 由引理 2，`start(o_i) >= end(o_{i-1})`。结合归纳假设 `end(o_{i-1}) >= end(g_{i-1})`，得 `start(o_i) >= end(g_{i-1})`。
  2. 也就是说：`o_i` **与 `g_{i-1}` 不重叠**，它是贪心在第 `i-1` 次收下区间之后的一个**合法候选**。
  3. 贪心按 `end` 升序依次考察，遇到第一个候选就收下。`o_i` 是候选 ⟹ 贪心不会「无区间可选」⟹ `k ≥ i`（① 成立）。
  4. 贪心收下的 `g_i` 是**第一个**满足 `start >= end(g_{i-1})` 的区间；而 `o_i` 也满足该条件，所以 `g_i` 在排序中的位置不晚于 `o_i`，即 `end(g_i) ≤ end(o_i)`（② 成立）。

  归纳完成。∎

**定理（贪心解最优）**
由引理 3，`k ≥ m`（取 `i = m`）。又由引理 1，贪心解是一个合法的两两不重叠子集，所以 `k ≤ m`（`m` 是最优值）。于是 `k = m`，最大保留数就是 `m`，答案 `n - k`。∎

> **这个论证的关键一步在哪**：第 4 条「`g_i` 的位置不晚于 `o_i`」。它把「贪心选了什么」和「最优解选了什么」对齐成两个**同序序列**，然后逐个比较右端点 —— 这就是交换论证的标准骨架：**不改变最优解的大小，只把它改造成「和贪心前缀一模一样」的形态**。改完之后，剩下的问题自然就归约到更小的实例上。
>
> 顺带回答一个常见疑问：**为什么交换之后 `O` 仍然是合法解？** 因为换掉的是 `o_i`（换成 `g_i`），而 `g_i` 的右端点更小（`≤ end(o_i)`）、且 `start(g_i) >= end(g_{i-1}) >= end(o_{i-1})`（第 3 条保证了它不会与 `o_{i-1}` 冲突），对它后面的 `o_{i+1}` 也没有影响（`end` 变小只会更容易）。**「换完不变差」才是「敢换」的全部理由。**

### 135.3.3 通用解题思路（可迁移的那一层）

本题是 **「区间图的最大独立集 = 按右端点贪心」** 模型：

```
原始问题：从一堆区间里选最多的、两两不重叠的区间（区间图最大独立集）
         ↓ 观察：两个区间冲突只取决于「谁先结束」
建模：    把区间看成区间图（顶点 = 区间，边 = 相交），求最大独立集
         ↓ 区间图是完美图：最大独立集 = 按右端点贪心（不需求一般图算法）
贪心：    排序后线性扫描，能塞就塞
证明：    交换论证 —— 把最优解逐项改造成贪心前缀
```

**与「按右端点」这把钥匙相关的题**：

| 题 | 用什么做「约束」 | 贪心键 |
| --- | --- | --- |
| [LC 435 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/) | 区间互不重叠 | 右端点升序（本章） |
| [LC 452 用最少数量的箭引爆气球](https://leetcode.cn/problems/minimum-number-of-arrows-to-burst-balloons/) | 一个点覆盖尽可能多的区间 | 右端点升序（下一章，与本章同构） |
| [LC 646 最长数对链](https://leetcode.cn/problems/maximum-length-of-pair-chain/) | 数对首尾相接成链 | 右端点升序（本质是同一个问题，只是问「最多能选几个」） |
| [LC 763 划分字母区间](https://leetcode.cn/problems/partition-labels/) | 同一字母不能跨段 | 「该字母最后出现位置」= 右端点 |
| [LC 1024 视频拼接](https://leetcode.cn/problems/video-stitching/) | 覆盖整段时间 | 起点升序 + 分层推进（另一种端点用法） |
| [LC 253 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/) | 同时占用的最大数量 | 扫描线（不排序端点而是排序事件） |

**共同点**：只要问题能写成「占用一段资源、要求互不冲突」，答案几乎总是**按右端点（结束时间）排序后贪心**。这是一把通用的钥匙。

### 135.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 每个区间带**权重**，求最大权重不重叠子集 | 贪心失效 | 加权区间调度：按右端点排序 + `dp[i] = max(dp[i-1], w_i + dp[p(i)])`，`p(i)` 用二分求，O(n log n) |
| 求「**最多**能被几个区间覆盖的点」 | 换问题 | 扫描线 / 差分计数，O(n log n) 或 O(n + V) |
| 要求输出**具体保留哪些**区间 | 要输出方案 | 贪心时记录下标即可，仍是 O(n log n)，额外 O(k) 空间 |
| 区间是**闭区间**（`[1,2]` 与 `[2,3]` 算重叠） | 判据变严 | 把 `start >= lastEnd` 改成 `start > lastEnd`；这是本题最容易「改一个符号」的地方 |
| 区间加上「**必须覆盖某个点**」的约束 | 加入覆盖需求 | 变成加权/带覆盖约束的区间调度，通常要 DP 或网络流 |
| 动态增删区间 | 无法重排 | 用平衡树维护「按右端点有序的独立集」，插入/删除 O(log n)（进阶，少见） |

**进阶延伸（自己写代码验证）**：

- **LC 646 最长数对链**：把「移除最少」换成「最多能选几个」，代码几乎一样 —— 亲手体会「同一个贪心，两种问法」。
- **LC 1235 规划兼职工作**：带权版本，做完就明白「贪心为什么在权重出现时失效」。
- **LC 253 会议室 II**：从「互不重叠子集」换成「同时占用的最多个数」，是同一张区间图的另一个参数（色数）。

## 135.4 图解推演

### 135.4.1 区间重叠的样子

```text
intervals = [[1,2],[2,3],[3,4],[1,3]]      端点相接 = 不重叠

时间轴    0   1   2   3   4   5
          ├───┼───┼───┼───┼───┤
[1,2]         ●━━━○               ← 占据 [1,2)
[2,3]             ●━━━○           ← 占据 [2,3)：与 [1,2) 只在 2 相接 → 不重叠
[3,4]                 ●━━━○       ← 占据 [3,4)：与 [2,3) 相接 → 不重叠
[1,3]         ●━━━━━━━○           ← 与 [1,2)、[2,3) 都真正相交

冲突关系（区间图）：
      [1,2] ──── [1,3] ──── [2,3]
                             │
                           [3,4]     ← [3,4] 与 [1,3] 也不重叠？[1,3) vs [3,4)：相接 → 不冲突
最大独立集 = { [1,2], [2,3], [3,4] }  → 保留 3，移除 1
```

### 135.4.2 按右端点扫描的逐轮状态表

`intervals = [[1,3],[1,2],[2,3],[3,4]]`，按 `end` 升序排序后：

| 轮次 i | 区间（排序后） | start | lastEnd | `start >= lastEnd` ? | keep | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `[1,2]` | 1 | — | — | 1 | 起点：全局最早结束的区间，无条件收下 |
| 1 | `[2,3]` | 2 | 2 | **是**（2>=2） | 2 | 端点相接 → 不重叠 → 收下 |
| 2 | `[1,3]` | 1 | 3 | 否（1<3） | 2 | 与上一个保留区间相交 → 丢弃（这就是要移除的那个） |
| 3 | `[3,4]` | 3 | 3 | **是**（3>=3） | 3 | 相接 → 收下 |
| — | — | — | — | — | **3** | 移除 `4 - 3 = 1` ✓ |

### 135.4.3 「按左端点排序」为什么错（反例轨迹）

```text
反例：intervals = [[1,100], [2,3], [3,4]]

按左端点升序排序后正是：[1,100], [2,3], [3,4]

贪心（按左端点）：
  ① 收下 [1,100]                    keep = 1，lastEnd = 100
  ② [2,3] 的 start=2 < 100 → 丢弃
  ③ [3,4] 的 start=3 < 100 → 丢弃
  ⇒ keep = 1，移除 2 个            ✗

真实最优：
  保留 [2,3] 和 [3,4]（端点 3 相接，不重叠）⇒ keep = 2，移除 1 个 ✓

图上一目了然：
  时间轴  1    2    3    4   …… 100
          ●━━━━━━━━━━━━━━━━━━━━━━━━○    ← [1,100]：起点最早，却吃掉整条时间轴
               ●━━○                       ← [2,3]
                    ●━━○                  ← [3,4]
  「起点最早」= 最早开始占用资源，但它结束得最晚 = 占用资源最多。
  贪心排在第一个被选，等于把整条时间轴一次性烧掉。
```

**一句话总结**：左端点是「**开始**得早」，右端点是「**结束**得早」。本题要最大化「能塞进多少段」，所以真正稀缺的资源是「**还剩下多少时间轴**」—— 只有右端点能衡量它。

## 135.5 双语言实现

### 135.5.1 Java

```java
import java.util.Arrays;

class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        int n = intervals.length;
        if (n == 0) {
            return 0;   // 约束保证 n >= 1，这行是给「通用函数」留的兜底
        }

        // 按右端点升序。用 Integer.compare 而不是 (a,b)->a[1]-b[1]：
        // 后者在极端端点下会溢出成负数，导致排序结果错乱（本题端点最多 ±5e4，
        // 不会溢出，但这是必须养成的习惯）。
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));

        int keep = 1;                        // 第一个区间（全局最早结束）无条件保留
        int lastEnd = intervals[0][1];       // 上一个被保留区间的右端点

        for (int i = 1; i < n; i++) {
            // >= 而不是 >：端点相接算不重叠（左闭右开语义）
            if (intervals[i][0] >= lastEnd) {
                keep++;
                lastEnd = intervals[i][1];
            }
            // 否则这个区间与「当前保留链」冲突 → 丢弃它（等价于「移除」）。
            // 为什么丢弃它而不是丢弃 lastEnd？这是交换论证的结论：右端点更小者留下。
        }
        return n - keep;
    }
}
```

### 135.5.2 Go

```go
package main

import "sort"

func eraseOverlapIntervals(intervals [][]int) int {
	n := len(intervals)
	if n == 0 {
		return 0
	}

	// 与 Java 同构：按右端点升序。
	// Go 的 sort.Slice 是不稳定排序，但本题只需要「右端点有序」，
	// 右端点相同的区间谁在前都不影响结果（见 §135.6.2 坑 6 的说明）。
	sort.Slice(intervals, func(i, j int) bool {
		return intervals[i][1] < intervals[j][1]
	})

	keep := 1
	lastEnd := intervals[0][1]

	for i := 1; i < n; i++ {
		if intervals[i][0] >= lastEnd { // 端点相接 = 不重叠
			keep++
			lastEnd = intervals[i][1]
		}
	}
	return n - keep
}
```

### 135.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 排序 API | `Arrays.sort(arr, comparator)` | `sort.Slice(s, less)` | 语义一致；Go 的 `less` 只给 `i, j` 下标，要自己取 `[1]` |
| 比较器溢出 | `(a,b)->a[1]-b[1]` 可能溢出 | `a[1] < b[1]` 不会溢出 | **Java 必须用 `Integer.compare`**，Go 天然安全 |
| 排序稳定性 | `Arrays.sort` 对对象数组是稳定排序（TimSort） | `sort.Slice` 不稳定 | 本题只需右端点有序，右端点相同者内部顺序不影响答案 |
| 二维表示 | `int[][]` | `[][]int`（每行是独立切片） | Go 里 `intervals[i]` 是切片，取 `[0]`/`[1]` 时同样没有越界检查 |
| 空输入 | `null` 与 `length==0` 要注意 | `nil` 切片的 `len` 为 0 | 约束保证 `n >= 1`，两语言都只是兜底 |

### 135.5.4 对拍测试（小 `n` 枚举子集）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举所有子集，取「两两不重叠」的最大大小，O(2^n * n^2)。
// 判据与贪心完全独立（不排序、不贪心），是本题最可信的对拍来源。
func bruteErase(intervals [][]int) int {
	n := len(intervals)
	best := 0
	for mask := 0; mask < (1 << n); mask++ {
		cnt := 0
		ok := true
		chosen := make([]int, 0, n)
		for i := 0; i < n && ok; i++ {
			if mask&(1<<i) == 0 {
				continue
			}
			// 与已选区间逐个检查：左闭右开语义 → 重叠当且仅当 max(l) < min(r)
			for _, j := range chosen {
				if intervals[i][0] < intervals[j][1] && intervals[j][0] < intervals[i][1] {
					ok = false
					break
				}
			}
			chosen = append(chosen, i)
			cnt++
		}
		if ok && cnt > best {
			best = cnt
		}
	}
	return n - best
}

func TestEraseOverlapRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024135))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(9) // n <= 9 才能让 2^n 枚举跑得动
		intervals := make([][]int, n)
		for i := 0; i < n; i++ {
			l := r.Intn(10)
			length := 1 + r.Intn(4)
			intervals[i] = []int{l, l + length}
		}
		// 深拷贝：贪心会原地排序，若不拷贝就会污染暴力用的数据
		cp := make([][]int, n)
		for i := range intervals {
			cp[i] = []int{intervals[i][0], intervals[i][1]}
		}
		got, want := eraseOverlapIntervals(cp), bruteErase(intervals)
		if got != want {
			t.Fatalf("iter=%d intervals=%v got=%d want=%d", iter, intervals, got, want)
		}
	}
}

// 边界：单区间、全部重叠、全部不重叠、完全相同、负端点、端点相接
func TestEraseOverlapEdge(t *testing.T) {
	cases := []struct {
		intervals [][]int
		want      int
	}{
		{[][]int{{1, 2}}, 0},
		{[][]int{{1, 2}, {2, 3}}, 0},
		{[][]int{{1, 5}, {2, 3}, {3, 4}}, 1},          // 按左端点排序会错答 2
		{[][]int{{1, 2}, {1, 2}, {1, 2}}, 2},
		{[][]int{{1, 10}, {2, 3}, {4, 5}, {6, 7}}, 1}, // 全部落在 [1,10] 里
		{[][]int{{-5, -4}, {-3, -2}, {-1, 0}}, 0},
		{[][]int{{1, 4}, {2, 3}}, 1},
	}
	for _, c := range cases {
		cp := make([][]int, len(c.intervals))
		for i := range c.intervals {
			cp[i] = []int{c.intervals[i][0], c.intervals[i][1]}
		}
		if got := eraseOverlapIntervals(cp); got != c.want {
			t.Fatalf("intervals=%v got=%d want=%d", c.intervals, got, c.want)
		}
	}
}

// 规模测试：n = 1e5 时必须瞬间返回（排序主导），并且不能暴露出越界/死循环。
// 这里不比对答案，只验证「大规模下不崩、且答案落在合法区间 [0, n-1] 内」。
func TestEraseOverlapLarge(t *testing.T) {
	r := rand.New(rand.NewSource(99))
	n := 100000
	intervals := make([][]int, n)
	for i := 0; i < n; i++ {
		l := r.Intn(50000)
		intervals[i] = []int{l, l + 1 + r.Intn(1000)}
	}
	got := eraseOverlapIntervals(intervals)
	if got < 0 || got > n-1 {
		t.Fatalf("答案越界: got=%d", got)
	}
	// 全部重叠的极端输入：n 个相同区间 → 必须移除 n-1 个
	same := make([][]int, n)
	for i := 0; i < n; i++ {
		same[i] = []int{1, 2}
	}
	if got := eraseOverlapIntervals(same); got != n-1 {
		t.Fatalf("全部重叠应移除 %d 个，实得 %d", n-1, got)
	}
}
```

> 注意测试里的**深拷贝**：贪心会**原地排序** `intervals`。如果直接把它交给 `eraseOverlapIntervals` 再拿同一份数据跑暴力，暴力看到的是「已排序的数据」—— 虽然答案恰好不变，但这是「测试互相污染」的典型隐患。**对拍的两份输入必须是独立副本。**

## 135.6 复杂度与常见坑

### 135.6.1 复杂度推导

- **时间 O(n log n)**：排序 O(n log n)；扫描一遍 O(n)。Java 的 `Arrays.sort` 对对象数组用 TimSort（`O(n log n)` 最坏），Go 的 `sort.Slice` 用 pdqsort（平均 `O(n log n)`、最坏 `O(n log n)`）。
- **空间 O(log n) ~ O(n)**：排序栈空间（TimSort 需要 `O(n/2)` 临时空间，pdqsort 是 `O(log n)` 栈）。贪心本身只用 `keep / lastEnd / i` 三个变量，**O(1)**。
- **对照**：DP 版 O(n²) 时间 + O(n) 空间；`n = 10^5` 时是 `5·10^9` 次比较，与 `10^5 log(10^5) ≈ 1.7·10^6` 次相差 3 个数量级。

### 135.6.2 七个真实踩过的坑

1. **贪心没有证明 = 猜** —— 本章的坑几乎都长在这上面。会写「按右端点排序 + 能塞就塞」的人很多，能说清「为什么第一个区间无条件选、为什么冲突时丢当前区间而不是丢 `lastEnd`」的人很少。而一旦题目变成「带权」，同一段代码立刻失效 —— 这正是「没有证明就不知道适用边界」的代价。
2. **把 `>=` 写成 `>`** —— `[[1,2],[2,3]]` 会答成 1（正确 0）。端点相接 = 不重叠，这是题目明确定义。
3. **返回 `keep` 而不是 `n - keep`** —— 题目问「移除数」。这是最纯粹的低级错误，但面试里真实发生。
4. **排序键写成 `a[0]`（左端点）** —— `[[1,100],[2,3],[3,4]]` 上错答 2。**左端点是「开始得早」，右端点是「结束得早」，只有后者省资源。**
5. **排序键写成「区间长度」** —— 也是错的。反例：`[[3,5],[1,4],[4,7],[7,9]]`，按长度升序先选 `[3,5]`（长度 2），它同时挡住 `[1,4]` 和 `[4,7]`，最后只能保留 2 个（`[3,5]`、`[7,9]`）；而最优保留 `[1,4]`、`[4,7]`、`[7,9]` 共 3 个。**「短」不等于「结束早」。**
6. **右端点相同时的次序** —— 本题不需要关心（右端点相同，选谁 `lastEnd` 都一样，后续可行性也相同）。但如果题目改成「输出字典序最小的方案」，次序就变得关键，那时要显式规定 tie-break。**不同问题对 tie-break 的敏感度不同，别把「这题不需要」当成「永远不需要」。**
7. **原地排序污染调用方数据** —— `Arrays.sort` 会直接改 `intervals`。生产代码里要么先拷贝，要么在文档里注明「本函数会修改入参」。对拍测试里这一点尤其致命。

### 135.6.3 面试官最爱追问的三个问题

**Q1：为什么冲突时丢掉「当前区间」，而不是丢掉上一个保留的区间？**

> 「因为排序后 `end(当前) >= end(上一个)`。丢掉右端点更小的、留下更大的，只会让后续区间更难塞进来（可行性单调变差）；反过来留下更小的那个，后续只会更容易。这一步就是交换论证里『换完不变差』的具体形式 —— 引理 3 的第 4 条。」

**Q2：如果给每个区间加一个权重，求最大权重的不重叠子集呢？**

> 「贪心失效。反例：`[[1,2] w=1, [2,3] w=1, [1,3] w=100]` —— 贪心按右端点先选 `[1,2]`，只能再选 `[2,3]`，权重 2；最优是单取 `[1,3]`，权重 100。正确做法是加权区间调度：按右端点排序，`dp[i] = max(dp[i-1], w_i + dp[p(i)])`，其中 `p(i)` 是最后一个 `end <= start_i` 的区间下标，用二分查找，总 O(n log n)。」

**Q3：这题和 LC 452（引爆气球）有什么关系？**

> 「同构。435 问『最多保留几个互不重叠的区间』；452 问『最少用几个点把所有区间都打中』。这两个量在区间族上是对偶的：**任意一组两两不重叠的区间，每个都必须占用一个不同的点** ⟹ 点数 ≥ 不重叠区间数；而『按右端点选点』的贪心恰好达到这个下界。所以 435 的 `keep` 就是 452 的答案（细节见下一章）。」
