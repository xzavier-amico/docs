## 015.1 题目

**原题链接**：<https://leetcode.cn/problems/longest-substring-without-repeating-characters/>

### 题意重述（把隐含条件补齐）

给你一个字符串 `s`，请找出其中**不含重复字符**的**最长子串**的长度。

注意是**子串**（连续）而不是**子序列**（可跳着选）。这一个词决定了整道题的解法——子序列要 DP，子串才能用窗口。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **子串必须连续** | 「子串（substring）」 | 你按子序列做 → `"abcabcbb"` 会算出 3（恰好一样）从而误判正确，`"pwwkew"` 才算得出 4（错） |
| **要的是长度，不是子串本身** | 「最长子串的**长度**」 | 返回 `String` → 类型错；但面试常追问「改成返回子串」，要能改 |
| **无重复 = 子串内每个字符至多出现一次** | 「不含重复字符」 | 你理解成「不出现连续相同字符」→ `"abca"` 会返回 4 |
| **可以是空串** | `0 <= s.length` | `""` 不处理 → 返回 `-1` 或越界；正确是 0 |
| **字符集是 ASCII（含空格、数字、符号）** | 「`s` 由英文字母、数字、符号和空格组成」 | 你用 `s[i] - 'a'` 当下标 → 空格 `' '`（32）和 `'A'`（65）算出负下标或错位 |
| **字符可能重复出现多次** | 一般性 | 「上次出现位置」必须**每轮更新**，忘记更新 → 窗口越界变长 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= s.length <= 5·10⁴` | n 最多 5 万 | 子串总数 `n(n+1)/2 ≈ 1.25·10⁹`，任何 O(n²) 枚举都是十亿级操作，**必挂** |
| `s` 由英文字母、数字、符号和空格组成 | 字符集 ≈ 128 个（ASCII 可打印字符 + 空格） | **可以用 `int[128]` 当哈希表**，常数极小；如果是任意 Unicode 就要 `map[rune]int` |
| 答案 ≤ n | 最长就是整个串 | 答案用 `int` 足够 |
| 允许空串 | 边界 | 必须返回 0 |

> 💡 量级 → 算法：`n = 5·10⁴` 只接受 O(n) 或 O(n log n)。而「最长合法子串」这个问题形状（连续 + 单调扩张）天然属于**滑动窗口**：两个指针各自只往右走，总移动次数 O(n)。

### 示例

```
输入：s = "abcabcbb"
输出：3
解释：最长无重复子串是 "abc"，长度 3。注意 "abcabcbb" 里还有 "bca"、"cab" 也都是 3。

输入：s = "bbbbb"
输出：1
解释：最长是 "b"。

输入：s = "pwwkew"
输出：3
解释：最长是 "wke"（下标 2..4）。注意答案不是 "pwke" ——那是子序列，不是子串。

输入：s = ""
输出：0
```

### 我自造的四个反例（写完必须打一遍）

```text
① ""            → 暴露"ans 初始化为 0"和循环边界
② " "（一个空格）→ 暴露"用 s[i]-'a' 当下标"（空格是 32，会算成负数或错位）
③ "abba"        → 暴露 last[c] >= left 里的 >= 写成 >（这题碰巧不错，见 ④）
④ "pwwkew"      → 真的能打死 >= / > 的判断：写成 > 会返回 4（窗口 "wkew" 含两个 w）
```

第 ③ 条值得单独说：`"abba"` 在两种写法下都得 2，**它验证不出这个 bug**。真正能打死的是 `"pwwkew"`：我实测 `>=` 得 3（正确）、`>` 得 **4**（错误，因为窗口 `"wkew"` 里有两个 `w`）。这就是为什么随机对拍必须配一组「手工构造的毒样例」——**样例选错，测了等于没测**。

## 015.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来）

枚举每个起点，向右扩展到出现重复为止：

```java
int ans = 0;
for (int i = 0; i < n; i++) {
    Set<Character> seen = new HashSet<>();
    for (int j = i; j < n; j++) {
        if (!seen.add(s.charAt(j))) break;   // 重复了，以 i 开头的窗口到此为止
        ans = Math.max(ans, j - i + 1);
    }
}
```

- 时间 **O(n²)**（内层每次 `add` 是 O(1) 摊销），空间 **O(字符集)**。
- `n = 5·10⁴` 时最坏 `n(n+1)/2 ≈ 1.25·10⁹` 次操作 —— 秒级到十秒级，必挂。

注意这已经是**优化过的暴力**了（用 `Set` 而不是三重循环逐个比对）。很多人到这里就停了，因为「每个起点单独扩展」看起来天经地义。

### 第二步：它为什么不够 —— 相邻起点的信息被全部丢弃

看 `"abcabcbb"`：

```
i=0: 窗口 "abc" 撞到第 2 个 a 停住     → 长度 3
i=1: 从 'b' 重新开始建 Set，又扫 "bca" → 长度 3   ← 前一轮的 {a,b,c} 全扔了
i=2: 又从 'c' 重新开始建 Set，扫 "cab" → 长度 3   ← 又扔一次
```

**从 `i` 到 `i+1`，窗口内部几乎没变**，但 `Set` 被清空重建了。这就是 O(n²) 的来源：**每个起点都从头扫一遍自己那段窗口**。

### 第三步：卡点 —— 「以 right 结尾的窗口」可以复用

换一个视角：不再固定左端点，而是**固定右端点**。

> 对每个 `right`，问：**以 `right` 结尾的、无重复的最长子串有多长？**

这个视角的好处是：当 `right` 从 `r-1` 挪到 `r` 时，候选窗口的左端点**只会往右移，不会往左移**。为什么？

设 `s[r]` 上一次出现的位置是 `p`（`p = last[s[r]]`，没出现过则为 −1）。

- 如果 `p < left`：`s[r]` 在**当前窗口之外**出现过，窗口内没有重复，`left` 不用动。
- 如果 `p >= left`：`s[r]` 在**当前窗口内**已经出现过一次。那么任何以 `r` 结尾的无重复窗口，左端点都必须 `> p`——否则这个窗口会同时包含位置 `p` 和位置 `r` 的两个 `s[r]`。

所以 `left` 的新值就是：

```
left = max(left, p + 1)
```

**关键结论：`left` 单调不减。** 这是滑窗能 O(n) 的全部理由：两个指针都只往右走，总移动次数 `≤ 2n`。

### 第四步：为什么「跳过」是安全的（这是本题最该想清楚的一步）

逐格收缩版（`while (窗口内有重复) left++`）也对，但它一格一格地挪。跳跃版直接跳到 `p+1`，跳过了 `left … p` 这些起点。**凭什么能跳过？**

```
假设 s = ... a ... a ...，前一个 a 在 p，后一个 a 在 right = r，当前 left <= p。

    left      p            r
     ↓        ↓            ↓
  ┌──┬──┬──┬──┬──┬──┬──┬──┐
  │  │  │  │ a│  │  │  │ a│
  └──┴──┴──┴──┴──┴──┴──┴──┘
     └───┬───┘
     这些起点 i ∈ [left, p]
     窗口 [i, r] 里同时含 s[p] = a 和 s[r] = a  → 一定有重复 → 全部非法

     只有 i > p 时，[i, r] 才"有可能"合法
```

**所以 `p+1` 不是「一个更好的选择」，而是「唯一可能的最优左端点下界」。** 跳过 `[left, p]` 不会漏掉任何合法解，因为它们全都非法。这句话就是「窗口收缩为什么安全」的标准答案，后面 016、019 会以不同形式重复它。

## 015.3 原理拆解

### 015.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 三重循环（枚举 i, j，再判重） | O(n³) | O(1) | 10 行 | 只在纸上出现 |
| 枚举起点 + `Set` 扩展 | O(n²) | O(字符集) | 10 行 | `n = 5·10⁴` 时 1.25·10⁹ 次，必挂 |
| 滑窗 + `while` 逐格收缩 | O(n) | O(字符集) | 12 行 | 不错，但每格都要判断一次，常数大 2~3 倍 |
| **滑窗 + `last` 表一次跳跃** ✅ | **O(n)** | **O(字符集)** = O(128) | **11 行** | 只有在需要「知道窗口内每个字符出现次数」时才要换成计数版（如 016） |
| 滑窗 + `HashMap<Character,Integer>` | O(n) | O(字符集) | 14 行 | 字符集大时才是必需；ASCII 场景下比数组慢（哈希 + 装箱） |

**为什么「跳跃版」严格优于「逐格版」**：两者都是 O(n)，但逐格版在最坏情况（如 `"aaaa…a"`）每轮要挪 `left` 一次，总挪动 `n` 次；跳跃版直接赋值，一次到位。**渐进复杂度一样时，比的就是这种「每个元素被碰几次」。**

### 015.3.2 为什么这个做法是对的（正确性论证）

**不变量**（每轮 `right` 处理完之后成立）：

```
[left, right] 是「以 right 结尾的所有无重复子串中最长的那一个」，
等价地：left = 最小的、使 [left, right] 无重复的左端点。
```

**归纳证明**：

*基础*：`right = 0` 时，`last[s[0]] = -1 < left = 0`，`left` 保持 0，单字符窗口 `[0,0]` 只有一个元素，不存在重复，且长度已经无法更短。∎

*归纳步*：设处理 `right-1` 后不变量成立，现在处理 `right`，记 `p = last[s[right]]`（在本轮更新 `last` 之前的值）。

1. **若 `p < left`**：说明 `s[right]` 在 `[left, right-1]` 中没出现过，于是 `[left, right]` 无重复。又因为 `[left, right-1]` 是上一轮的最长窗口，`left` 不能再左移（左移会引入重复），所以 `[left, right]` 也是以 `right` 结尾的最长窗口。
2. **若 `p >= left`**：任何以 `right` 结尾、左端点 `i <= p` 的窗口都同时含 `s[p]` 与 `s[right]`（两者相等），非法。所以合法左端点必须 `>= p+1`；而 `[p+1, right]` 本身无重复（`p` 是 `s[right]` 在 `[left, right-1]` 中的最后一次出现，`p+1` 之后没有 `s[right]`），故它是最长的。

两种情况下 `left = max(left, p+1)` 都给出了「最小合法左端点」，窗口长度 `right - left + 1` 即为「以 `right` 结尾的最长无重复子串长度」。对 `right` 取最大值即得全局最优。∎

> **注意归纳里用到的两个事实**：①`left` 单调不减（否则第 2 种情况的论证不成立）；②`last[c]` 存的是**最后一次**出现位置（否则 `p+1` 之后可能还有 `c`，`[p+1, right]` 就不合法了）。这两个事实分别对应代码里的 `max` 和「每轮都更新 `last`」。

### 015.3.3 通用解题思路（可迁移的那一层）

本题是**滑动窗口家族的开篇**，所以这里要把整个家族的「共同语言」立起来。拿到任何一道滑窗题，先回答三个问题：

```
① 窗口里维护什么？          → 一个"能增量更新、能增量撤销"的量
② 什么时候扩张（right++）？  → 无条件扩张，或扩张到"可行"为止
③ 什么时候动 left，为什么安全？ → 这一步是全部难点，安全性来自"单调性"
```

**「为什么收缩是安全的」只有两种合法理由**：

| 理由 | 形式 | 例子 |
| --- | --- | --- |
| **左端点下界单调** | 存在一个只增不减的下界 `L(right)`，`left` 可以直接跳到它 | 015：`L = p+1`（重复字符的下一位）；019：`L` 由 `sum >= target` 决定 |
| **目标单调（越短越好 / 越长越好）** | 收缩只会让当前候选更接近目标，且不会丢失「以当前 right 结尾的更优解」 | 016：只要还覆盖就继续缩，因为要最短；019 同理 |

而滑窗成立**必须**有的前提，是「**可行性关于窗口的某种单调性**」：

```
固定 right，随着 left 右移（窗口变短）：
    若题目要"最长" → 可行 → 不可行，一旦不可行就不用再试（015：遇到重复就停）
    若题目要"最短" → 不可行 → 可行 → 再 → 不可行（016/019：一旦可行就停）
```

**本批五道滑窗题的「窗口语义对照表」**（这是本章最该带走的东西）：

| 章节 | 窗口长度 | 目标 | 窗口里维护什么 | 何时动 left | 安全性来自 |
| --- | --- | --- | --- | --- | --- |
| **015** | **变长** | 最长 | `last[c]`：每个字符最后出现的位置 | 出现重复 → `left = max(left, p+1)` | 左端点下界 `p+1` **单调不减**，跳过的起点全非法 |
| [016](016-minimum-window-substring.md) | 变长 | **最短** | `need[c]` + `missing`：还差几个字符 | 已覆盖（`missing == 0`）→ 持续左缩 | 目标是「最短」，只要还覆盖就该继续缩 |
| [017](017-find-all-anagrams-in-a-string.md) | **定长** | 全部起点 | `diff[26]`：`p` 与窗口的词频差 | 无决策：`left = right - m + 1` | 长度由题目固定，**left 是 right 的函数** |
| [018](018-permutation-in-string.md) | **定长** | 是否存在 | 同 017（完全同构） | 同 017 | 同 017 |
| [019](019-minimum-size-subarray-sum.md) | 变长 | **最短** | `sum`：窗口内元素和 | `sum >= target` → 左缩 | **正数**保证 `sum` 关于 left 单调递减 |

**一句话总结这五章的差别**：015 是「**变长求最长**」，016/019 是「**变长求最短**」，017/018 是「**定长**」。`变长求最长` 靠「不可行就修」，`变长求最短` 靠「可行就更短」，`定长` 根本不用决策。

属于同一模型的题：`016`（最小覆盖子串，难度上一个台阶）、`017`/`018`（定长）、`019`（正数前提）、[LC 340 至多 K 个不同字符的最长子串](https://leetcode.cn/problems/longest-substring-with-at-most-k-distinct-characters/)、[LC 424 替换后的最长重复字符](https://leetcode.cn/problems/longest-repeating-character-replacement/)、[LC 1004 最大连续 1 的个数 III](https://leetcode.cn/problems/max-consecutive-ones-iii/)。

### 015.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **字符集是任意 Unicode** | `int[128]` 不够 | 换 `Map<Character,Integer>` / `map[rune]int`；注意 Java 的 `char` 是 UTF-16 码元，emoji 要按 `codePoint` 处理 |
| 要求**返回子串本身** | 需要起点 | 记录 `bestStart`、`bestLen`，最后 `substring(bestStart, bestStart+bestLen)` |
| 改成「至多 **K** 个不同字符」 | 窗口维护的量变了 | 维护「字符 → 出现次数」+ `distinct` 计数；`distinct > K` 时左缩（LC 340） |
| 改成「至多 **K** 次替换后最长重复子串」 | 收缩条件变成「窗口长 − 众数频次 > K」 | 注意这题有个著名技巧：**left 不需要真的缩**（窗口只增不减），见 LC 424 |
| 输入是**数据流**，要求每来一个字符就报当前答案 | 不能回退 | 滑窗天然适配：状态只有 `left`、`last`、`ans`，都是 O(1) 空间 |
| 改成「无重复**子序列**」 | 连续性没了 | 窗口彻底失效：「无重复子序列」中每种字符至多取一次，所以答案就是**不同字符的种数**，一趟计数即可（O(n) / O(1)），双击滑窗纯属浪费 |

## 015.4 图解推演

### 015.4.1 两个指针的移动轨迹

```
s = "abcabcbb"

right = 0..2：一路扩张，窗口 "abc"，无重复，ans = 3

   left
     ↓
   ┌────┬────┬────┬────┬────┬────┬────┬────┐
   │ a  │ b  │ c  │ a  │ b  │ c  │ b  │ b  │
   └────┴────┴────┴────┴────┴────┴────┴────┘
                    ↑
                  right

right = 3（字符 'a'，last['a'] = 0 >= left = 0）→ left 跳到 1

        left
          ↓
   ┌────┬────┬────┬────┬────┬────┬────┬────┐
   │ a  │ b  │ c  │ a  │ b  │ c  │ b  │ b  │
   └────┴────┴────┴────┴────┴────┴────┴────┘
                    ↑
                  right
        └──────────────┘
        新窗口 "bca"，长度 3
```

### 015.4.2 「逐格收缩」与「一次跳跃」的对比

```
出现重复（p = last[c] >= left）时，left 有两种走法：

① 逐格版 while(hasRepeat) left++        ② 跳跃版 left = max(left, p+1)
        left: 0 → 1 → 2 → …                     left: ──────────→ p+1
        每步判断一次窗口是否仍有重复             一次赋值
        总挪动次数 O(n)，常数大                  总挪动次数 O(n)，常数小

   ┌────────────────────────────────────────────────────────┐
   │ 能跳过的理由：对任何 i ∈ [left, p]，窗口 [i, right] 同时  │
   │ 含 s[p] 和 s[right] 两个相同字符 → 一定非法               │
   │ 所以"最小合法左端点"就是 p+1，中间那些起点一个都不用试     │
   └────────────────────────────────────────────────────────┘
```

### 015.4.3 逐字符状态表（`"pwwkew"`，可以手推验证）

`last` 初始全为 −1。

| right | `s[right]` | `p = last[c]` | `p >= left`？ | 新 `left` | 窗口 | 长度 | `ans` | 更新后 `last` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | p | −1 | 否 | 0 | `"p"` | 1 | 1 | `{p:0}` |
| 1 | w | −1 | 否 | 0 | `"pw"` | 2 | 2 | `{p:0, w:1}` |
| 2 | w | 1 | **是** | 2 | `"w"` | 1 | 2 | `{p:0, w:2}` |
| 3 | k | −1 | 否 | 2 | `"wk"` | 2 | 2 | `{p:0, w:2, k:3}` |
| 4 | e | −1 | 否 | 2 | `"wke"` | 3 | **3** | `{p:0, w:2, k:3, e:4}` |
| 5 | w | 2 | **是** | 3 | `"ke"` | 2 | 3 | `{p:0, w:5, k:3, e:4}` |

盯住 `right = 5` 这一行：`p = 2`，`left` 从 2 跳到 3。如果写成 `p > left`（严格大于），`p = 2` 不满足，`left` 留在 2，窗口变成 `"wkew"`（长度 4）——**这是错的**，因为 `"wkew"` 里有两个 `w`。这就是 §015.1 里说的那个必须用 `"pwwkew"` 才能打死的 bug。

### 015.4.4 `last` 表为什么必须每轮更新

```
s = "abba"

若不更新 last（把 last 只当"第一次出现位置"）：
  right=3（'a'），last['a'] 还是 0（第一次出现），left = 1
  → 窗口 [1,3] = "bba" 含两个 b → 非法

每轮更新 last（最后一次出现位置）：
  right=2（'b'），last['b'] = 2；right=3（'a'），last['a'] = 0 < left=2 → left 不动
  → 窗口 [2,3] = "ba" ✅

  ┌──────────────────────────────────────────────┐
  │ last[c] 的语义必须是"最后一次出现的位置"       │
  │ 因为 left 只需要跨过"最近的那个重复"           │
  └──────────────────────────────────────────────┘
```

## 015.5 双语言实现

### 015.5.1 Java

```java
import java.util.Arrays;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        // last[c] = 字符 c 上一次出现的下标；-1 表示"还没出现过"
        // 用 -1 而不是 0 当哨兵：下标 0 是合法位置（001 里已经踩过这个坑）
        int[] last = new int[128];
        Arrays.fill(last, -1);

        int left = 0, ans = 0;
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            // 只有"上一次出现在当前窗口内"时才需要跳；用 >= left 而不是 > left：
            // 若 last[c] == left，说明窗口左端就是这个字符，窗口内已经有两个 c 了
            if (last[c] >= left) {
                left = last[c] + 1;
            }
            last[c] = right;                 // 每轮都更新，保证语义是"最后一次出现"
            ans = Math.max(ans, right - left + 1);   // left 调整之后再算长度
        }
        return ans;
    }
}
```

### 015.5.2 Go

```go
package main

func lengthOfLongestSubstring(s string) int {
	// 长度 128 的定长数组，直接按下标索引字符（byte）
	// Go 的数组零值是 0，必须显式填 -1，否则"没出现过"和"在下标 0 出现"会混淆
	last := [128]int{}
	for i := range last {
		last[i] = -1
	}

	left, ans := 0, 0
	for right := 0; right < len(s); right++ {
		c := s[right] // 注意：这里是 byte，不是 rune
		if last[c] >= left {
			left = last[c] + 1
		}
		last[c] = right
		if right-left+1 > ans {
			ans = right - left + 1
		}
	}
	return ans
}
```

### 015.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 字符类型 | `charAt` 返回 `char`（16 位，可当 int 下标） | `s[i]` 是 **`byte`**，`range` 给的是 `rune` | Go 用 `s[i]` 恰好是 ASCII 单字节；若用 `for _, c := range s`，`c` 是 `rune`（int32），不能直接索引 128 大小的数组 |
| 数组填初值 | `Arrays.fill(last, -1)` | `for i := range last { last[i] = -1 }` | Go 没有 `fill`；也可以用 `[128]int{-1, -1, …}` 但写 128 个太多 |
| 数组 vs 切片 | `new int[128]` 定长 | `[128]int` 是**数组**（值类型），`[]int` 是切片 | 本题用数组：长度编译期固定、无堆分配、无扩容，比切片更快 |
| 字符串长度 | `s.length()` 返回 `char` 数（UTF-16 码元） | `len(s)` 返回**字节数** | ASCII 下两者一致；含中文时 `len(s)` 是 3 倍，`s[i]` 会切到半个字符 |
| 空串 | 循环不执行，返回 0 | 同 | 都天然正确，不需要 `if` |
| 越界 | `last[c]` 中 `c > 127` 会抛异常 | 数组下标越界 panic | 题目限定 ASCII；若要支持 Unicode 必须换 `map[rune]int` |

### 015.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举起点，用 set 向右扩展
func brute(s string) int {
	best := 0
	for i := 0; i < len(s); i++ {
		seen := map[byte]bool{}
		for j := i; j < len(s); j++ {
			if seen[s[j]] {
				break
			}
			seen[s[j]] = true
			if j-i+1 > best {
				best = j - i + 1
			}
		}
	}
	return best
}

func TestLengthOfLongestSubstringRandom(t *testing.T) {
	// 毒样例：能打死 >= / > 混用、last 不更新、空格当字符这几类 bug
	fixed := []struct {
		s string
		w int
	}{
		{"abcabcbb", 3},
		{"bbbbb", 1},
		{"pwwkew", 3}, // 写成 last[c] > left 会得 4
		{"", 0},
		{" ", 1},      // 空格：不能用 s[i]-'a' 当下标
		{"dvdf", 3},   // left 跳到 p+1 而不是 p
		{"abba", 2},   // last 必须是"最后一次出现"
		{"tmmzuxt", 5},
	}
	for _, f := range fixed {
		if got := lengthOfLongestSubstring(f.s); got != f.w {
			t.Fatalf("s=%q got=%d want=%d", f.s, got, f.w)
		}
	}

	r := rand.New(rand.NewSource(15))
	for iter := 0; iter < 30000; iter++ {
		n := r.Intn(14)
		b := make([]byte, n)
		for i := range b {
			b[i] = byte('a' + r.Intn(4)) // 只用 4 种字符：重复更频繁，窗口频繁收缩
		}
		s := string(b)
		if got, want := lengthOfLongestSubstring(s), brute(s); got != want {
			t.Fatalf("iter=%d s=%q got=%d want=%d", iter, s, got, want)
		}
	}
}
```

> **为什么只用 `a..d` 四种字符**：字符种类越少，`last[c] >= left` 的分支越常被走到，`left` 跳动越频繁，`>=` / `>` 的差别、`last` 忘记更新这些 bug 才会暴露。用 26 种字母时几乎不会有重复，测了等于没测。

## 015.6 复杂度与常见坑

### 015.6.1 复杂度推导

- **时间 O(n)**：`right` 从 0 走到 `n-1`，共 `n` 轮；每轮内部是常数次数组访问与比较。`left` **不是**每轮都动，但因为 `left = max(left, p+1)` 且 `p < right`，`left ≤ right` 且单调不减，所以 `left` 的总移动量 `≤ n`。
  - 换个说法：`left` 和 `right` 都只往右走，两个指针各走 `n` 步，总步数 `2n` —— 这就是所有滑窗题 O(n) 的统一证法。
- **空间 O(128) = O(1)**：`last` 是定长数组（字符集大小），与 `n` 无关。注意这是「O(字符集)」，**不是**「O(n)」——这也是滑窗优于哈希存全量的地方。

### 015.6.2 八个真实踩过的坑

1. **`last[c] >= left` 写成 `> left`** —— `"pwwkew"` 会返回 4（窗口 `"wkew"` 含两个 `w`）。`last[c] == left` 时窗口左端就是这个字符本身，窗口内必有两个，必须跳。
2. **`last` 初始化成 0 而不是 −1** —— 下标 0 是合法位置。`"a"` 会在第 0 轮误判「重复」，`left` 变成 1，窗口长度算成 0。这和 `001` 里用 0 当「没找到」的哨兵是**同一个 bug 的两个面孔**。
3. **`last[c]` 忘记每轮更新** —— 语义退化成「第一次出现位置」，`"abba"` 会算错。
4. **`ans` 在调整 `left` 之前更新** —— 会用到上一轮的非法窗口长度，答案偏大。
5. **用 `s[i] - 'a'` 当下标** —— 空格（32）、数字（48-57）、大写字母（65-90）全部错位甚至负下标。**本题字符集是「字母 + 数字 + 符号 + 空格」，直接用 ASCII 码当下标**。
6. **数组开 26** —— 只够小写字母。开 128（ASCII）最稳；要支持任意字节就开 256。
7. **Go 里用 `for _, c := range s` 拿到 `rune`** —— `c` 是 int32，ASCII 下值相同没问题，但一旦是中文/emoji，`c` 可能 > 127 导致数组越界 panic。要么用 `s[i]` 取 byte，要么换 `map[rune]int`。
8. **把「子串」当「子序列」** —— `"pwwkew"` 的答案是 3 不是 4，`"pwke"` 不是子串。这个错在样例 `"abcabcbb"` 上不暴露，非常阴。

### 015.6.3 面试官最爱追问的三个问题

**Q1：为什么左指针可以一次跳到 `last[c] + 1`，而不是一格一格挪？**
> 「因为任何以 `right` 结尾、左端点在 `[left, p]` 之间的窗口，都会同时包含位置 `p` 和位置 `right` 的两个相同字符 `s[right]`，一定不合法。所以『合法左端点』的下界就是 `p+1`，中间那些起点连试都不用试。安全性完全来自这个**下界单调不减**：随着 `right` 右移，`p` 只会变大，`left` 也只会右移，不会回退。」

**Q2：这个解法的复杂度为什么是 O(n)，`left` 不是可能每轮都动吗？**
> 「`left` 确实可能每轮都动，但它是单向的：`left = max(left, p+1)`，而 `p < right` 且 `right` 递增，所以 `left` 单调不减，全程最多移动 `n` 步。`right` 移动 `n` 步，`left` 移动不超过 `n` 步，总步数 `2n`。这是**摊还分析**：不要看单轮，要看总移动量。」

**Q3：如果要「至多 K 个不同字符」的最长子串呢？**
> 「维护`字符 → 出现次数`的哈希表和 `distinct` 计数。`right` 扩张后如果 `distinct > K`，就左缩直到 `distinct == K`。正确性来自单调性：窗口变长只会让 `distinct` 不减，所以一旦超了，只能靠左缩修复。注意这里 `left` 也是一格一格地缩，因为**没有「跳到哪」的先验知识**——015 能跳是因为知道重复字符的确切位置，K 个不同字符没有这个信息。这就是 LC 340。」

## 附：本章小结（可背走的三句话）

```
① 固定右端点看问题：以 right 结尾的最长无重复窗口，左端点下界是 last[s[right]] + 1
② 下界单调不减 → left 只往右走 → 总移动 O(n)；跳过的起点全都非法，所以安全
③ last 的语义是"最后一次出现"、初值必须是 -1、判断必须是 >= left
```
