## 086.1 题目

**原题链接**：<https://leetcode.cn/problems/rotting-oranges/>

### 题意重述（把隐含条件补齐）

给你一个 `m × n` 的网格 `grid`，每个格子有三种取值：

- `0`：空；
- `1`：新鲜橘子；
- `2`：腐烂橘子。

**每分钟**，任何一个**与腐烂橘子四邻接**的新鲜橘子都会腐烂。请返回**直到网格中不再有新鲜橘子为止所经过的最小分钟数**；如果**永远不可能**让所有新鲜橘子都腐烂，返回 `-1`。

这里有五个必须自己读出来的隐含条件：

| 隐含条件 | 出处 | 读漏了会怎样 |
| --- | --- | --- |
| **腐烂会「同时」发生** | 「every minute, any fresh orange that is 4-directionally adjacent to a rotten orange becomes rotten」 | 理解成「一分钟只传染一个」会让答案大得离谱 |
| **每个新鲜橘子**只需一次腐烂 | 同上 | 已腐烂的格子不再是 `1`，不会再次传染 |
| **一开始没有新鲜橘子 → 返回 0** | 「If there are no fresh oranges... return 0」 | 常见错误：返回 `-1`（因为队列是空的） |
| **腐烂源可能有很多个（也可能 0 个）** | 网格里任意位置都可能是 `2` | 这是「多源」的由来 |
| **无解要返回 `-1`** | 「if possible... otherwise return -1」 | 只算 `max` 而不复查剩余新鲜橘子数，会返回一个偏小的错误答案 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `m == grid.length` | 1 ≤ m ≤ 10 | 总格数 `N ≤ 100` |
| `n == grid[i].length` | 1 ≤ n ≤ 10 | **极小**，连暴力都能过 |
| `grid[i][j]` ∈ `{0,1,2}` | 三值 | 可以用 `2` 当「已访问」标记 |
| 时间限制约 1 s | — | `O(N) = 100` 与 `O(N²) = 10⁴` 都快得看不出来 |

> 💡 **量级 → 算法**：本题规模小到**任何正确解法都能过**，所以它的价值完全在**方法论**上：
> 这是「**多源 BFS + 层计时**」这个模型的母题，一旦理解，[LC 542 01 矩阵](https://leetcode.cn/problems/01-matrix/)、[LC 1091](https://leetcode.cn/problems/shortest-path-in-binary-matrix/)、[LC 1162](https://leetcode.cn/problems/as-far-from-land-as-possible/) 全部是一个模子。
> **面试里要说的是「这是 0-1 无权图上从多个源出发的最短路问题的最大值」，而不是「我跑了个队列」。**

### 示例

```text
输入：grid = [
  [2,1,1],
  [1,1,0],
  [0,1,1]
]
输出：4

逐分钟推演（● 腐烂，○ 新鲜，· 空）：
t=0        t=1        t=2        t=3        t=4
● ○ ○      ● ● ○      ● ● ●      ● ● ●      ● ● ●
○ ○ ·      ● ● ·      ● ● ·      ● ● ·      ● ● ·
· ○ ○      · ○ ○      · ● ○      · ● ●      · ● ●
                                        ↑ 第 4 分钟才全部烂完

输入：grid = [
  [2,1,1],
  [0,1,1],
  [1,0,1]
]
输出：-1       ← 左下角 (2,0) 被两个 0 隔开，永远烂不了

输入：grid = [[0,2]]          → 输出 0（没有新鲜橘子）
输入：grid = [[1]]            → 输出 -1（一个新鲜橘子，没有任何腐烂源）
输入：grid = [[2]]            → 输出 0（没有新鲜橘子，队列里那个 2 什么也不做）
输入：grid = [[0]]            → 输出 0
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [[1]]                        → 无源，必须 -1。检验「队列空 + fresh > 0」分支
② [[0,2]]                      → 无新鲜，必须 0。检验「一开始 fresh == 0」分支
③ [[2,1,1,2,1]]                → 多源：正确答案 1
                                 错解 A（只从第一个 2 出发）：算成 4
                                 错解 B（对每个源取 max）：算成 2
④ [[2,1,1],
    [1,1,1],
    [1,1,1]]                   → 单源但要走满全场，答案 4（对角线最远格 (2,2)）
                                 检验层计时是否每层只 +1
```

第 ③ 条是本变量身：一行、两个源、一个新鲜橘子——**任何「单源」或「取 max」的错误都会在它上面露馅**，而正确答案只要 1 分钟。

## 086.2 从暴力到最优：第一个念头为什么错

### 第一个念头 A：逐分钟模拟整张网格

```java
// 出生版：每分钟扫一遍全图，把"有腐烂邻居的新鲜橘子"记下来，下一分钟统一腐烂
while (true) {
    List<int[]> newly = new ArrayList<>();
    for (每个格子 (i,j))
        if (grid[i][j] == 1 && 四邻中至少一个 == 2) newly.add((i,j));
    if (newly.isEmpty()) break;
    for (int[] p : newly) grid[p[0]][p[1]] = 2;
    minutes++;
}
```

- 时间 **O(答案 × N)**：答案最大可达 `m + n - 2`（对角线），本题最多 `18`，所以是 `O(18 × 100)`——**能过**。
- 但它有一个必须指出的**正确性风险**：`newly` 必须**先收集完再统一置 `2`**。如果边扫边置 `2`，同一分钟内新腐烂的橘子会被当成「本分钟就能继续传染」的源，答案被压小。**「同一层必须一起处理」是这个模型的灵魂**，而这段代码把它藏在一个容易被删掉的临时列表里。

> 这个暴力其实是「多源 BFS 的一层」的手写版本。它没错，只是把「层」写成了「每分钟全图重扫」，多了一个 `N` 的因子。

### 第一个念头 B（真正会错的那个）：只从**一个**腐烂橘子做 BFS

```java
// ❌ 常见错解：随便挑一个 '2' 当唯一源
int[] src = 找到第一个 '2';
int minutes = BFS从(src);      // 得到每个新鲜橘子"到 src 的距离"
```

这**在你以为答案就是最大距离**时立刻出错。反例就是 §086.1 的 ③：

```text
grid = [2, 1, 1, 2, 1]        正确答案 1（两个源同时各传染一格）
源下标：      0        3

只从 (0,0) 出发：
  (0,1)=1, (0,2)=2, (0,3) 是源跳过, (0,4)=3
  取最大 → 3   ❌ 正确答案是 1

从两个源分别出发，但要"取最小"：
  dist from 源0:  [0, 1, 2, 2(源), 3]
  dist from 源3:  [2, 1, 1, 0,     1]
  逐格取 min:     [0, 1, 1, 0,     1]      ← 最大值 1 ✅

若错写成"逐格取 max"：
  max:            [2, 1, 2, 2,     3]      ← 最大值 3 ❌
```

**于是这里有三个层次的错误，必须分清楚：**

| 写法 | 单行例子的输出 | 错在哪 |
| --- | --- | --- |
| 只从第一个源 BFS，取 max | 3 | 漏掉了其它源 |
| 每个源各 BFS，逐格取 **max**，再取 max | 3 | 用「最晩到达」代替「最早到达」 |
| 每个源各 BFS，逐格取 **min**，再取 max | 1 ✅ | 正确，但需要 `R` 次 BFS |
| **多源 BFS 一次，层数就是答案** | 1 ✅ | 正确且只做 1 次 |

### 卡点在哪：「取最小」这件事，为什么要多源 BFS 才自然

把问题翻译成一句话：

> **求所有新鲜橘子 `v` 的 `min_k dist(源_k, v)` 的最大值**，其中 `源_k` 是所有腐烂橘子。

「取最小」是 `min` 运算，而单个 BFS 只能给出**一个源**的距离场。要拿到 `min`，你有两条路：

1. **算 R 次 BFS，逐格取 min** —— 正确，但代价 `O(R·N)`，且每次都要重置 `visited`。本题 `R` 最多 50、`N` 最多 100，`5000` 次操作——**能过，但把模型讲歪了**。
2. **把 R 个源同时放进队列，一起扩散** —— 队列是按距离（时间）从小到大出队的，第一个到达某格的源**必然是最近的那个源**，所以「同时扩散」天然实现了 `min`。代价 `O(N)`。

#### 一句话回答：为什么不能「单源 BFS 取最小」

```text
┌───────────────────────────────────────────────────────────────────────┐
│ 单源 BFS 只能回答「某个源到所有格的距离」。                          │
│ 题目要的是「所有源里的最小距离」——这是一个 min over 源的量，           │
│ 单个距离场里根本没有"别的源"这个信息，所以"取最小"无从谈起：          │
│                                                                       │
│   · 只跑 1 次 BFS，就把"最小"退化成了"到那一个源的距离" → 偏大 ❌     │
│   · 想真的取 min，必须跑 R 次（每源一次），再逐格 min → O(R·N) ❌     │
│   · 多源 BFS = 把 R 个源放进同一个队列 → min 由出队顺序免费实现 ✅     │
└───────────────────────────────────────────────────────────────────────┘
```

换句话说：**「取最小」不是一次后处理，而是搜索本身的一种性质**。把多个源放进同一个 BFS，队列的先进先出顺序就等价于「按时间取最小」，你不需要写任何 `min`。

### 灵感的来源：虚拟超级源 + 层数 = 时间

对多源 BFS 最好的解释是**加一个虚拟顶点**：

```text
新增一个超级源 S，S 到每个腐烂橘子连一条"权 0"的边
        │
        ├──0──→ 源₁
        ├──0──→ 源₂
        └──0──→ 源₃

则：dist_S(v) = min_k (0 + dist(源_k, v)) = min_k dist(源_k, v)
```

**在一张边权全为 1 的图上，把多个源在「第 0 层」一起入队，与加一个超级源是完全等价的**——因为超级源的 0 权边不消耗层数。这就是「多源 BFS 一次 = 所有单源 BFS 取最小」的严格解释。

第二层洞察是**「层数 = 时间」**：BFS 每次把一整层（距离为 `d` 的全部顶点）处理完，而题目恰好是「每分钟一起扩散一格」。**层与分钟的对应关系是天然的**，只要你在循环里**按层的长度弹出**，就根本不需要维护每格的 `dist`。

### 不变量

```
不变量 I：外层每一轮开始时，队列里恰好是"第 t 分钟刚腐烂完的全部橘子"，
         队外所有已腐烂橘子都属于更早的层（≤ t-1 分钟），
         所有新鲜橘子都属于更晚的层（≥ t+1 分钟）或不可达。
```

## 086.3 原理拆解

### 086.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐分钟全图扫描（暴力模拟） | O(mn × 答案) | O(mn) 临时列表 | 30 行 | 答案可能很大时（如 675 那种 `m·n` 级答案）会退化 |
| 每个源各 BFS + 逐格取 min | O(R·mn) | O(mn) | 50 行 | 源很多时；且实现里最容易把 `min`/`max` 弄反 |
| **多源 BFS + `size` 层计时** ✅ | **O(mn)** | O(mn) 队列 | **30 行** | 队列宽度最坏 `O(mn)`（本题 `100`，无所谓） |
| 多源 BFS + `dist` 数组（不用层计时） | O(mn) | O(mn) | 35 行 | 多一个数组；但「求每个橘子腐烂时刻」的变体必须用它 |
| DFS 求最短时间 | ❌ 不正确 | — | — | **DFS 不能保证最先到达**，最短距离必须用 BFS |

**为什么 DFS 在这题上直接出局**（这一点面试很爱问）：

> BFS 保证「第一次访问某顶点时的距离就是最短距离」，因为它按距离**从小到大**扩展。
> DFS 会沿一条路走到底，第一次访问某格时走的是**任意一条**路径，距离可能是 3 也可能是 7。在一张有权图（这里是边权 1 的图）上求最短距离，**只有 BFS（或 Dijkstra）成立**。

```
                 ┌──── 多个源，边权都是 1 ────┐
                 │                            │
      ┌──────────▼───────────┐    ┌───────────▼────────────┐
      │ 多源 BFS（同时扩散）   │    │ 单源 BFS × R 次 + 取 min│
      │ 1 次遍历，层 = 时间    │    │ R 次遍历，需要逐格 min  │
      └──────────┬───────────┘    └───────────┬────────────┘
                 │                            │
          O(mn) ✅ 首选                  O(R·mn)，容易把
                                         min 写成 max ❌
```

### 086.3.2 为什么这个做法是对的（正确性论证）

**引理 1（超级源等价性）**：设所有腐烂橘子为 `S = {s₁, …, s_R}`，边权全为 1，令 `d(v) = min_k dist(s_k, v)`。则「把 `S` 全部以距离 0 入队，然后做一次 BFS」得到的距离场恰好是 `d`。

- 由 BFS 的层序性质：第 `t` 层恰好是所有「距离 ≤ t 但尚未在更早层出现」的顶点。
- 归纳：第 0 层 = `S`（`d = 0` 的顶点）。若第 `t-1` 层 = `{v : d(v) = t-1}`，则第 `t` 层 = 第 `t-1` 层的未访问邻居 = `{v : d(v) = t}`。
  - `d(v) = t` 意味着存在 `s` 使 `dist(s, v) = t`，因此 `v` 有一个邻居 `u` 满足 `d(u) = t-1`（沿最短路回退一步），故 `v` 在第 `t` 层。
  - 反过来，第 `t` 层的 `v` 有一个第 `t-1` 层的邻居 `u`，`d(u) = t-1`，于是 `d(v) ≤ t`；而 `v` 不在更早的层，所以 `d(v) = t`。∎

**引理 2（层数 = 真实时间）**：把腐烂扩散看成离散时间过程，第 `t` 分钟结束时腐烂的橘子集合恰好等于 `{v : d(v) ≤ t}`。

- 对 `t` 归纳。`t = 0` 时腐烂集合 = `S` = `{d = 0}`，成立。
- 若第 `t-1` 分钟末为 `{d ≤ t-1}`，则第 `t` 分钟内新腐烂的正是「与 `{d ≤ t-1}` 四邻接的新鲜橘子」，也就是 `{d = t}`（因为 `d = t` 的格子必有邻居 `d = t-1`）。∎

**定理（答案 = 最大层号）**：全部新鲜橘子腐烂所需的最小分钟数 = `max_{v ∈ 新鲜} d(v)`。

- **上界**：由引理 2，第 `max d` 分钟结束时所有新鲜橘子都已腐烂。
- **下界**：设 `v*` 取得最大值 `D`。任何传染过程都必须沿一条四邻接路径从某个源走到 `v*`，长度至少 `D`，而每分钟最多前进一条边，所以至少需要 `D` 分钟。∎
- 若存在 `d(v) = ∞`（不可达），则该橘子永远不会腐烂，返回 `-1`。∎

**终止性**：每个格子最多入队一次（入队时 `grid` 被置 `2`），队列有限。∎

### 086.3.3 通用解题思路（可迁移的那一层）

三要素在本题有了新的形态——**边带上了「时间」这个权，虽然权恒为 1**：

| 要素 | 本题的答案 | 与前面章节的差异 |
| --- | --- | --- |
| **顶点（vertex）** | 每个格子 `(i, j)` | 不变 |
| **边（edge）** | **无向**边 `(i,j) — (i',j')` 当且仅当四邻接（**不**看取值） | 注意：边的存在与格子是什么无关；能否通过取决于**状态**（`1` 才能被传染）。这与 082（边要求两端都是 `1`）不同——**这里过滤发生在「访问时」，而不是「建边时」** |
| **状态（state）** | `0` 空 / `1` 新鲜 / `2` 腐烂（其中「已入队的新鲜」被直接改成 `2`） | 第三态复用 `2`：因为**时机已被队列编码**，不需要额外状态 |
| **额外维度：时间** | `t` = BFS 层号 | 这是本章与前四章最大的区别：答案不是某个集合，而是**层号的极值** |

抽象成模型：

```
多源 BFS + 层计时（Multi-Source BFS with Layer Timing）
  ① 把所有源在第 0 层一起入队（= 加一个超级源）
  ② while 队列非空：
        size ← 当前层的元素个数       ← 关键：先冻结长度，才能按层处理
        处理 size 个元素，把新发现的顶点入队（它们属于下一层）
        t ← t + 1
  ③ 答案通常是：最大层号 / 某个顶点的层号 / 不可达判断
```

**「冻结长度」是全部技巧所在**：

```java
int size = q.size();        // 必须先存下来
for (int k = 0; k < size; k++) { ... }   // 只处理这一层
// 循环体内的 q.add 属于下一层，不会被本轮处理
```

如果不冻结，就会变成「一直处理到队列空」，层号信息彻底丢失——这是本题最常见的翻车点。

### 086.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**每个橘子**的腐烂时刻 | 不再只要极值 | 用 `dist[][]` 数组代替层计数：入队时 `dist[ni][nj] = dist[ci][cj] + 1` |
| 腐烂**需要 k 分钟**才传染一次 | 边权从 1 变 k | 层数乘 `k`；或把时间当状态做 DAG 上 DP（`k` 不同则不能用朴素 BFS） |
| 每个橘子的**传染速度不同** | 边权不同 | 变成带权最短路 → Dijkstra（`PriorityQueue`），BFS 失效 |
| 允许**八连通** | 边定义变化 | 方向表 4 → 8 |
| 网格**动态变化**（每分钟随机新增腐烂源） | 无法一次 BFS | 时间轴离散化：每分钟把新源加入队列继续跑（增量 BFS） |
| 要证明**为什么答案是最小值** | 需要下界论证 | 用 §086.3.2 的「路径长度 ≥ D」下界，或交换论证：任何合法的传染序列都不能比 BFS 层更快 |

### 086.4.3 单源 vs 多源：一行网格的三种算法对照

```text
grid = [2, 1, 1, 2, 1]
         0  1  2  3  4

① 只从下标 0 出发（单源 BFS）
   dist:  0  1  2  ·(源) 3
   答案 = 3  ❌

② 两个源各跑 BFS，逐格取 max
   从 0： 0  1  2  ·   3
   从 3： 2  1  1  0   1
   max ： 2  1  2  ·   3
   答案 = 3  ❌  (「最晚到达」没有物理意义)

③ 两个源各跑 BFS，逐格取 min
   从 0： 0  1  2  ·   3
   从 3： 2  1  1  0   1
   min ： 0  1  1  ·   1
   答案 = 1  ✅  （但用了 2 次 BFS）

④ 多源 BFS（两个源同时入队）
   q = [0, 3]  ──第1轮──→ 新入队 1（来自0）、4（来自3）
               ──第2轮──→ 新入队 2（来自1）
   dist:  0  1  1  ·   1        ← 与 ③ 完全一致，但只跑了 1 次
   答案 = 1  ✅
```

> **这张图解释了本章标题里那句话**：多源 BFS 不是「对每个源跑一遍再合并」，而是**「一次遍历里天然取到了最小」**——因为队列的出队顺序就是时间顺序。

## 086.5 双语言实现

### 086.5.1 Java

```java
import java.util.ArrayDeque;

class Solution {
    private static final int[][] DIRS = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};

    public int orangesRotting(int[][] grid) {
        int m = grid.length, n = grid[0].length;

        // 多源：把所有腐烂橘子在第 0 层一次性入队
        ArrayDeque<int[]> q = new ArrayDeque<>();
        int fresh = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 2) {
                    q.add(new int[]{i, j});
                } else if (grid[i][j] == 1) {
                    fresh++;                       // 统计新鲜数：既用于"全烂完"判断，也用于提前退出
                }
            }
        }
        // 一开始就没有新鲜橘子 → 0 分钟就完成了（不是 -1，这是本题第一个坑）
        if (fresh == 0) return 0;

        int minutes = 0;
        while (!q.isEmpty()) {
            // 冻结本层长度：循环体里 add 的元素属于下一层，本轮不能碰
            int size = q.size();
            boolean rotted = false;                // 本轮是否真的传染出去了

            for (int k = 0; k < size; k++) {
                int[] cur = q.poll();
                for (int[] d : DIRS) {
                    int ni = cur[0] + d[0], nj = cur[1] + d[1];
                    if (ni < 0 || ni >= m || nj < 0 || nj >= n || grid[ni][nj] != 1) continue;
                    // 入队即置 2：既是"已访问"标记，也保证同一格不会被两个邻居重复入队
                    grid[ni][nj] = 2;
                    fresh--;
                    q.add(new int[]{ni, nj});
                    rotted = true;
                }
            }
            // 只有"这一分钟确实有橘子腐烂"才推进时间；
            // 否则最后一层纯属"出队收尾"，会多算 1 分钟
            if (rotted) minutes++;
        }

        // 还有新鲜橘子说明它们不可达（被 0 隔开）
        return fresh == 0 ? minutes : -1;
    }
}
```

### 086.5.2 Go

```go
package main

func orangesRotting(grid [][]int) int {
	if len(grid) == 0 || len(grid[0]) == 0 {
		return 0
	}
	m, n := len(grid), len(grid[0])

	// 多源：所有腐烂橘子同时作为第 0 层
	queue := make([][2]int, 0, m*n)
	fresh := 0
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			switch grid[i][j] {
			case 2:
				queue = append(queue, [2]int{i, j})
			case 1:
				fresh++
			}
		}
	}
	if fresh == 0 {
		return 0
	}

	minutes := 0
	head := 0
	for head < len(queue) {
		// 冻结本层长度：queue[head:headEnd] 是本轮要处理的全部元素
		headEnd := len(queue)
		rotted := false
		for head < headEnd {
			ci, cj := queue[head][0], queue[head][1]
			head++
			for _, d := range [4][2]int{{-1, 0}, {1, 0}, {0, -1}, {0, 1}} {
				ni, nj := ci+d[0], cj+d[1]
				if ni < 0 || ni >= m || nj < 0 || nj >= n || grid[ni][nj] != 1 {
					continue
				}
				grid[ni][nj] = 2 // 入队即标记
				fresh--
				queue = append(queue, [2]int{ni, nj})
				rotted = true
			}
		}
		if rotted {
			minutes++
		}
	}

	if fresh > 0 {
		return -1 // 有橘子不可达
	}
	return minutes
}
```

### 086.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 队列实现 | `ArrayDeque<int[]>`，`poll()` 从头弹出 | `[][2]int` + `head` 游标（**不要用 `queue = queue[1:]`**） | Go 里 `queue = queue[1:]` 每次都会移动切片头，虽然摊还 `O(1)`，但底层数组不释放；用 `head` 游标更清晰，也避免与「冻结长度」的逻辑打架 |
| 冻结长度的写法 | `int size = q.size();` | `headEnd := len(queue)` | 语义完全一致：都是「本轮处理的右边界」 |
| 三值分派 | `if / else if` 或 `switch` | `switch grid[i][j]`（Go 的 `switch` 不需要 `break`） | 两者都能读；Go 的 `switch` 少写一行 `else if` |
| 坐标表示 | `new int[]{i, j}`（每次都是一个新对象） | `[2]int{i, j}`（栈上的值类型） | 本题 `N ≤ 100`，两者差别看不出来；但在 542 那种 `10⁴` 规模上 Go 省下大量 GC 压力 |
| 返回 `-1` 的位置 | 用三元表达式收尾 | 显式 `if fresh > 0 { return -1 }` | Go 没有三元运算符，必须写显式 `if` |
| 空输入 | `grid.length == 0` 必须手写防御，否则 NPE | 同样要手写 | LeetCode 保证 `m,n ≥ 1`，但工程代码里这个防御是必要的 |

## 086.6 复杂度与常见坑

### 086.6.1 复杂度推导

- **时间 O(mn)**：每个格子最多入队一次（入队即把 `grid` 改成 `2`，之后判据 `!= 1` 拦住），出队时检查 4 个邻居，因此总操作数 `≤ 5mn`。初始化扫描 `O(mn)`。合计 `O(mn)`。
- **空间 O(mn)**：队列最坏情况（多源填满）存 `O(mn)` 个坐标。
- **对比暴力**：逐分钟全图扫描是 `O(答案 × mn)`；答案上界 `m + n - 2`，所以是 `O((m+n)·mn)`——本题 `m,n ≤ 10` 时只有 `18 × 100`，量级看不出差别，但**在 675（切树）那种「答案可达 `mn`」的题上会差出一个数量级**。

### 086.6.2 八个真实踩过的坑

1. **忘记「一开始没有新鲜橘子返回 0」**：直接走 while 循环也能得到 0，但如果你一开始就 `return -1`（因为源可能为 0 个），就错了。最稳的写法是：`fresh == 0` 直接返回 0。
2. **层计时多算 1**：先 `minutes++` 再扩展，最后一层会多算。本题示例 1 会从 4 变成 5。修法：用 `rotted` 标志，只在真正传染时 +1。
3. **不冻结层长度**：写成 `while (!q.isEmpty()) { int[] cur = q.poll(); ... }` 而中间没有 `size` 循环，层号信息全丢，`minutes` 变成「出队次数」。
4. **入队才标记 vs 出队才标记**：出队才置 `2`，同一格会被多个邻居重复入队，`fresh` 被重复扣减，答案可能变成 `-1` 或负数。**入队瞬间标记**。
5. **忘记最终复查 `fresh`**：只返回 `minutes` 会把无解的情况返回成一个正数（§086.1 的示例 2 会返回 4 而不是 `-1`）。
6. **用 DFS 求最短时间**：DFS 第一次到达某格的路径不一定最短，答案会偏大。**最短距离类问题只能用 BFS（或 Dijkstra）。**
7. **多源写成了「多源排队但只从一个源开始扩散」**：例如只在 `found first 2` 之后 `break` 出双层循环，源就只剩一个。**必须扫完整个网格，把所有 `2` 都入队。**
8. **在 Go 里用 `queue = queue[1:]` 配合 `len(queue)` 冻结长度**：`queue[1:]` 之后 `len` 已经变了，`headEnd` 的语义会被破坏。这两个技巧**不要混用**：要么纯 `head` 游标，要么纯 `q.removeFirst()`。

### 086.6.3 面试官最爱追问的三个问题

**Q1：为什么不分别对每个腐烂橘子做 BFS，然后取最小？**
> 「能取到正确答案，但要跑 `R` 次 BFS，`O(R·mn)`，而 `R` 可能和 `mn` 同阶，最坏退化成 `O((mn)²)`。而且『取最小』这一步非常容易写错——我见过很多人写成取 `max`，那等于算『最晚被传染的时间』，物理上没意义。多源 BFS 只跑一次，而且**『取最小』是队列顺序自然带来的，不需要显式写 `min`**：队列按时间顺序出队，第一次到达某格的源必然最近。等价的说法是给所有源加一个超级源、边权 0。」

**Q2：为什么分层？不分层直接 BFS 不行吗？**
> 「如果只问『能不能全部腐烂』，不分层也行。但本题要的是**时间**，而时间正好等于 BFS 的层号，所以必须知道『现在处理到第几层』。分层的方式有两种：① 冻结层长度（`size = q.size()`），处理完一层就 `t++`；② 让每个队列元素带自己的层号，或者维护一个 `dist[][]` 数组。我选 ①，因为它不用额外空间，而且代码里『一层 = 一分钟』的对应关系一眼可见。」

**Q3：如果每个橘子的腐烂速度不同（比如有些需要 2 分钟才传染一次），怎么办？**
> 「那就不再是边权全 1 的图，BFS 的『第一次到达即最短』失效——因为走 2 条快边可能比走 1 条慢边更快。这时要把『经过的分钟数』当成边权，用 Dijkstra（Java `PriorityQueue`、Go `container/heap`）。极端情况下如果边权是 0/1 混合，用 0-1 BFS（双端队列）就够。**判断标准永远是：边权是否相同。**」
