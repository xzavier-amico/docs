## 134.1 题目

**原题链接**：<https://leetcode.cn/problems/gas-station/>

### 题意重述（把隐含条件补齐）

有 `n` 个加油站围成一圈，第 `i` 个站有 `gas[i]` 升汽油。你有一辆**油箱无限大**的车，从第 `i` 个站开往第 `i+1` 个站（`n-1` 的下一站是 `0`）要消耗 `cost[i]` 升油。你从某个站出发（**该站可以免费加满 `gas[i]` 升**），初始油箱为**空**。若能绕环一圈回到起点，返回出发站的编号；否则返回 `-1`。**若存在解，输入保证它唯一。**

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **环形** | 「围成一圈」「返回起点」 | 当成线性数组 → 漏掉「从后面出发、跨过末尾回到开头」的解 |
| **初始油箱为空** | 「开始时油箱为空」 | 提前加上 `gas[start]` 或给一个非零初值 → 答案偏移 |
| **油箱容量无限** | 「如果油箱容量无限」 | 误以为要在中途丢弃多余油 → 变成完全不同的题 |
| **每个站只能加一次** | 「你可以在第 i 个站加油」 | 绕两圈来补油 → 题意被曲解 |
| **总消耗必须能被总油量覆盖** | 「若存在解返回下标」 | 忘记 `-1` 分支（本输入有 `-1` 的情况，`gas=[2,3,4], cost=[3,4,3]`） |
| **解若存在则唯一** | 「如果存在解，它保证唯一」 | 这是**输入保证**，不是数学定理 —— §134.3.2 会给出反例，说明为什么必须靠这条保证 |

> 最后一条是本章最容易被忽视、也最能体现水平的地方：多数题解写的「总油量 ≥ 总消耗 ⇒ 解唯一」其实是**假命题**。本章会把它拆成两个真命题来证，并给出反例。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `n == gas.length == cost.length` | 两个数组等长 | 不会出现长度不匹配的边界 |
| `1 <= n <= 10^5` | 最多 10 万 | **O(n²) = 10^10 次**，按 10⁸/s 要 100 秒 → **必然超时**；只有 O(n) 才能过 |
| `0 <= gas[i], cost[i] <= 10^4` | 单项最多 1 万 | 总和最大 `10^5 × 10^4 = 10^9`，**在 `int32` 上界 2.147·10⁹ 之内但只剩 2 倍余量**；用 `long` / `int64` 累加更稳 |
| `gas[i]` 可以等于 `0` | 有零油站 | 「本站加了 0 升」是合法情况，`d[i] = gas[i] - cost[i]` 可以为负很多 |
| `cost[i]` 可以等于 `0` | 有零消耗 | 会出现「白走」的边，也正因如此 `total` 可能恰好等于 0 |

> 💡 **量级反推**：`n = 10^5` 是一道**硬门槛** —— 枚举起点（O(n²)）必死，O(n) 才活，O(n log n) 也活但没有已知的自然解法。这就把「怎么一次扫完」变成题目唯一的核心问题。

### 示例

```
输入：gas  = [1, 2, 3, 4, 5]
      cost = [3, 4, 5, 1, 2]
输出：3
解释：从 3 号站出发：油箱 0+4=4 → 到 4（花 1）剩 3 → 4 号加 5 → 到 0（花 2）剩 6
      → 0 号加 1 → 到 1（花 3）剩 4 → 1 号加 2 → 到 2（花 4）剩 2 → 2 号加 3 → 到 3（花 5）剩 0 ✓
      沿途任何时刻油箱非负，绕回起点时恰好为 0

输入：gas = [2, 3, 4], cost = [3, 4, 3]
输出：-1
解释：总油量 9 < 总消耗 10，无论从哪出发都不可能绕完一圈
```

### 我自造的四个反例

```text
① gas=[1], cost=[1]          → 答案 0（单个站，加 1 花 1 恰好绕回自己）
② gas=[1], cost=[2]          → 答案 -1（单站也可能无解，别漏总量判断）
③ gas=[0,0,0], cost=[0,0,0]  → 答案 0（全 0：total = 0 恰好不为负，必须返回一个合法起点而不是 -1）
④ gas=[2,0,0], cost=[0,1,1]  → 答案 0；注意油箱是可以「攒」的，0 号站攒的 2 升要够走完两段
⑤ gas=[1,1], cost=[0,0]      → 两个起点都合法（0 和 1）。
                               题目保证唯一，所以这组输入不会出现在测试里；
                               但它正是「总油量≥总消耗 ⇒ 解唯一」这个说法的反例（见 §134.3.2）
```

第 ③ 条最阴险：`total == 0` 时**不能**返回 `-1`。判据必须是 `total < 0`，不是 `total <= 0`。

## 134.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举起点，逐站模拟

```text
for start in 0 .. n-1:
    tank = 0
    for k in 0 .. n-1:
        i = (start + k) % n
        tank += gas[i] - cost[i]     # 先加本站的油，再开往下一站
        if tank < 0: break           # 半路断油 → 这个起点不行
    if tank >= 0: return start       # 走满 n 段都没断 → 合法
return -1
```

- 时间 **O(n²)**，空间 **O(1)**。
- `n = 10^5` 时是 `10^10` 次循环 —— 即使每次只做两次加法和一次比较，也要 100 秒量级，**必然超时**。
- 即使 `n = 10^4`（`10^8` 次），也要接近 1 秒，面试官会直接说「换个更好的」。

**暴力的浪费在哪**：每次换一个起点，都要把整段路重新走一遍。而实际上，从 `s` 出发失败的那一刻，**你已经获得了大量关于 `s+1, s+2, …` 的信息**，却被全部扔掉。

### 第二步：卡点在哪

把问题翻译成前缀和：

```
d[i] = gas[i] - cost[i]          （第 i 段的净收益）
P[0] = 0,  P[k] = d[0] + d[1] + … + d[k-1]      （前 k 段的总净收益）
S = P[n]                         （绕一整圈的净收益）
```

于是「从 `s` 出发、走完第 `j` 段后的油箱」可以写成**两个前缀和之差**：

```
油箱(j) = P[j+1] - P[s]        （s ≤ j ≤ n-1，即还没绕回开头）
油箱 绕回后 = S - P[s] + P[j]  （0 ≤ j < s）
```

此时「每个时刻油箱非负」就变成一个纯粹的**前缀和比较**：

```
合法起点 s  ⟺  min{ P[j] : s < j ≤ n } ≥ P[s]
                且  min{ P[j] : 0 ≤ j < s } ≥ P[s] - S
```

**卡点不是「怎么模拟」，而是「怎么一次性知道哪些 `s` 不可能」。** 而前缀和给了一个非常强的线索：**一旦从某个 `s` 出发在 `k` 处断油，那么 `P[k+1] < P[s]`，这意味着 `s` 是一个「局部低点」，而 `s+1 … k` 全都在它右边、值都不低于它** —— 于是可以整段排除。

### 第三步：灵感的来源 —— 反证「整段排除」

这是本章真正的技术核心。先看一个具体片段：

```
从 s 出发，走到 k 时才第一次断油：

  下标   s        s+1        s+2     …      k
  d     +3        -1         -1      …     -3
  油箱   3         2          1       …     -1   ← 断油

那么 s+1 能作为起点吗？
  从 s+1 出发：油箱从 0 开始，走的正是 [s+1..k] 这一段，
  而这一段的净收益 = (s..k 的总和) - (s 这一段) = -1 - 3 = -4 < 0
  ⇒ 走完 k 时油箱必然为负 ⇒ s+1 也不行。
同样的推理给出 s+2 也不行：它要走的 [s+2..k] 净收益只会更差。
```

一般化：**若从 `s` 出发在 `k` 处首次断油，则 `s+1, s+2, …, k` 全都不可能作为起点。** 这就是「整段排除」，它让暴力里内层的那 `n` 次循环被整体跳过 —— 每个下标在整个算法里只会被「走过」一次，总时间 O(n)。

```
不变量（本章核心）：start 始终满足 P[start] = min{ P[j] : 0 ≤ j ≤ start }
                  （即 start 是一个「前缀最小值的位置」）
```

## 134.3 原理拆解

### 134.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举起点 + 模拟 | O(n²) | O(n) 或 O(1) | 12 行 | `n ≥ 10^5` 必超时；这是「正确答案但错误复杂度」的典型 |
| 前缀和 + 找「最后一个全局最小值的位置 + 1」 | O(n) | O(n) | 10 行 | 空间 O(n)；需要额外说明 `S ≥ 0` 与「取最后一个最小值」的理由 |
| **单次扫描 + 起点重置（`tank < 0` 就换起点）** ✅ | **O(n)** | **O(1)** | **9 行** | 需要 `total ≥ 0` 的全局判断；对「解唯一」这条输入保证有依赖（返回的是最小合法起点） |
| 倍增数组 + 滑动窗口最小值 | O(n) | O(n) | 25 行 | 纯属把前缀和方案写复杂，没有收益 |
| 二分答案（求「最少初始油量」变体） | O(n log n) | O(n) | 30 行 | 那是另一道题（见 §134.3.4） |

**为什么选「单次扫描 + 起点重置」**：它把 `O(n)` 的空间也省掉了 —— 不需要真的算出前缀和数组，只需要维护**当前候选起点以来的净收益** `tank` 和**全局净收益** `total`。两个累加器就能同时回答「这个起点行不行」和「有没有解」。

### 134.3.2 为什么这个做法是对的（正确性论证 · 反证法）

先把记号钉死（后面所有证明只用这套记号）：

```
d[i]  = gas[i] - cost[i]
P[0]  = 0，  P[k] = d[0] + … + d[k-1]      （0 ≤ k ≤ n）
S     = P[n]                               （绕一圈的净收益）

「走完第 j 段后的油箱」（从 s 出发）：
    j ∈ [s, n-1] → 油箱 = P[j+1] - P[s]
    j ∈ [0, s-1] → 油箱 = S - P[s] + P[j+1] （绕回后）
```

**命题 A（`S ≥ 0` 是存在解的必要条件）**

*反证*：设存在合法起点 `s`。合法意味着「任何时刻油箱非负」，把绕完一整圈回到 `s` 的那一刻也算在内 —— 此时油箱 = 出发时的 0 加上这一圈的总净收益，即 `S`。若 `S < 0`，这一刻油箱为负，与合法性矛盾。故 `S ≥ 0`。∎

> 命题 A 决定了 `-1` 的判据是 `total < 0`（而不是 `<= 0`）。`gas=[0,0,0], cost=[0,0,0]` 时 `S = 0` 且起点 0 合法，返回 `0` 才对。

**引理 B（整段排除 —— 本章的核心反证）**

> 设从起点 `s` 出发时，**第一次**断油发生在「走完第 `k` 段」之后（即 `Σ_{i=s}^{k} d[i] < 0`，且对一切 `j ∈ [s, k-1]` 有 `Σ_{i=s}^{j} d[i] ≥ 0`）。则对每个 `t ∈ (s, k]`，`t` 都不可能作为合法起点（在本题的环形结构下）。

*反证*：取 `t ∈ (s, k]`，假设 `t` 是合法起点。注意从 `t` 出发时，它会依次经过 `t, t+1, …, k` 这几段（还没绕回开头，因为 `t ≤ k < n`），走完第 `k` 段后油箱为

```
Σ_{i=t}^{k} d[i]  =  ( Σ_{i=s}^{k} d[i] )  −  ( Σ_{i=s}^{t-1} d[i] )
```

- 第一项 `< 0`（断油的定义）；
- 第二项 `≥ 0`（因为 `t-1 ≤ k-1`，而断油是**第一次**，之前的每一段前缀和都非负；`t = s+1` 时该项就是 `d[s] ≥ 0`）。

所以 `Σ_{i=t}^{k} d[i] < 0`：从 `t` 出发走到 `k+1` 时油箱为负，与「`t` 合法」矛盾。∎

**推论 B'**：`s` 自己在 `k` 处断油，所以 `s` 也不合法。于是**整段 `[s, k]` 全部不合法**，可以一次性跳到 `k+1`。

**引理 C（不变量：`start` 始终是一个前缀最小值的下标）**

> 算法每次重置后，新的 `start` 满足 `P[start] = min{ P[j] : 0 ≤ j ≤ start }`。

*归纳*：

- **基础**：一开始 `start = 0`，而只有一个元素的集合 `{P[0]}` 的最小值就是 `P[0]` 本身，成立。
- **归纳步**：设当前 `start = s` 满足 `P[s] = min_{j≤s} P[j]`，并在「走完第 `k` 段」后断油。由引理 B 的推导过程，对一切 `j ∈ (s, k+1]`（即 `s+1 ≤ j ≤ k+1`）都有 `P[j] ≥ P[s]`（这正是「在此之前没断油」）；而断油本身给出 `P[k+1] < P[s]`。于是

```
P[k+1] = min{ P[j] : 0 ≤ j ≤ k+1 }
```

  新 `start = k+1`，不变量保持。∎

**引理 D（循环结束时，`start` 是**全局**最小值的下标）**

循环正常结束（中途没再断油）意味着对 `j ∈ (s, n]` 都有 `P[j] ≥ P[s]`；结合引理 C，得 `P[s] = min{ P[j] : 0 ≤ j ≤ n }`。∎

**定理 E（存在性：`S ≥ 0` 时算法给出的 `start` 是合法起点）**

由引理 D，`P[start] ≤ P[j]` 对所有 `j` 成立。于是：

- 对 `j ≥ start`（还没绕回）：油箱 `= P[j] - P[start] ≥ 0`；
- 对 `j < start`（绕回之后）：油箱 `= S - P[start] + P[j] ≥ S - P[start] + P[start] = S ≥ 0`（用了 `P[j] ≥ P[start]` 与 `S ≥ 0`）。

所以沿途油箱从不为负，`start` 合法。∎

**定理 F（最小性：`start` 是**最小的**合法起点）**

把 `0, 1, …, n-1` 看成候选集。算法每次断油时，由引理 B + 推论 B'，把 `[s, k]` 整段**证明为不合法**并跳过；其余下标从未被跳过。算法结束时返回的 `start` 既没被证明非法（它被定理 E 证明合法），也没漏掉任何更小的下标。所以 `start` 是最小的合法起点。∎

**定理 G（关于「唯一性」的真相）**

题面说「若存在解则唯一」。这句话是**输入保证**，不是「`S ≥ 0` 就能推出」的定理：

- **反例 1**：`gas = [1, 1]`，`cost = [0, 0]` → `d = [1, 1]`，`S = 2 > 0`。起点 0：走完 0 段油箱 1、走完 1 段油箱 2，合法；起点 1：走完 1 段油箱 1、走完 0 段油箱 2，也合法。**两个解**。
- **反例 2**：`gas = [0, 1, 0, 1]`，`cost = [1, 0, 1, 0]` → `d = [-1, 1, -1, 1]`，`S = 0`。起点 1 与 3 都合法。

真正能证的唯一性刻画来自 §134.2 末尾那组不等式：

```
合法起点集合 = { s : P[s] = min{ P[j] : s ≤ j ≤ n }  且  P[s] ≤ S + min{ P[j] : 0 ≤ j < s } }
```

当「全局最小前缀值只被一个下标取得」时，这个集合只有一个元素。本题的测试数据恰好满足这一点，**而算法返回的最小合法起点在唯一的前提下自然就是答案** —— 这也解释了为什么算法不需要额外处理「多个解该返回哪个」。∎

> **这一节想教的东西**：读题时必须分清三件事 ——
> ① 数学结论（`S ≥ 0` ⇒ 存在解，定理 E）；
> ② 算法性质（返回最小合法起点，定理 F）；
> ③ 输入保证（解唯一）。
> 把 ③ 当成 ① 的推论，是这道题最常见的「讲不清」，一旦面试官追问反例，整套说法就崩了。**贪心没有证明 = 猜；证明写错 = 更糟的猜。**

### 134.3.3 通用解题思路（可迁移的那一层）

本题是 **「环上的前缀和 + 单调机会点」** 模型：

```
原始问题：环上有 n 个候选起点，每个起点要模拟 n 步 → O(n²)
         ↓ 把「沿途油箱」写成「前缀和之差」
建模：    合法性 = 一组前缀和不等式（区间最小值 ≥ 某个阈值）
         ↓ 断油处 ⇒ P[k+1] < P[s] ⇒ [s, k] 整段非法
贪心：    一次扫描，断油就整段跳过，O(n) / O(1)
工具：    反证法（证明「整段非法」），这是「跳过」类贪心的通用许可证
```

属于这一模型的题：

| 题 | 「前缀和」是什么 | 「整段跳过」的依据 |
| --- | --- | --- |
| [LC 134 加油站](https://leetcode.cn/problems/gas-station/) | `gas - cost` 的环形前缀和 | 断油处的前缀和低于起点 ⇒ 中间全非法 |
| [LC 53 最大子数组和](https://leetcode.cn/problems/maximum-subarray/) | 累加和 | 前缀和变成负时就该重开（Kadane） |
| [LC 121 买卖股票的最佳时机](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/) | 历史最低价 | 价格跌破历史低点就更新「最优买入点」 |
| [LC 918 环形子数组的最大和](https://leetcode.cn/problems/maximum-sum-circular-subarray/) | 环形前缀和 | 「环」的两种切法：不跨越末尾 / 跨越末尾 |
| [LC 871 最低加油次数](https://leetcode.cn/problems/minimum-number-of-refueling-stops/) | 可达距离的前缀 | 油不够就「回溯性加油」（最大堆） |

**共同点**：都在做「用前缀和把一段区间的整体性质压成两个数」，都在做「一旦发现不可能就跳掉一整段」。

### 134.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 不保证解唯一，要求返回**所有**合法起点 | 输出变大 | 先把 `P[]` 算出来，用「后缀最小值 + 前缀最小值」逐个判，O(n) 输出全部 |
| 求「**最少需要多少初始油量**」才能从 0 出发绕一圈 | 换问法 | 环形前缀和的最小值：答案 = `max(0, -min{P[k] - P[0]})`，O(n) |
| 油箱**有容量上限** `C` | 「无限油箱」被打破 | 不再能用前缀和判断（多余的油会溢出），必须模拟 + 决策，通常是堆/DP |
| 允许**中途掉头**或重复经过某站 | 环上行走不再单调 | 图模型（顶点=站，边=两方向），变成最短路 |
| 站数**动态增删** | 无法重扫 | 线段树维护前缀和最小值 + 区间加，O(log n) 每次 |
| 每站的油量与消耗都很大（超过 `int32`） | 溢出 | 全部换 `long`/`int64`（本章代码已用 `long` 累加） |

**进阶延伸（自己写代码验证）**：

- **LC 871 最低加油次数**：「油不够就回溯性补给」——把本章的「整段排除」换成「最大堆回溯」，体会「贪心 + 反悔」的另一种形态。
- **LC 918 环形子数组的最大和**：把「环」的两种切法（跨末尾/不跨）分别处理，是本章前缀和技巧的直接亲戚。
- **LC 213 打家劫舍 II**：环形问题的另一条通用套路 —— **破环成链，枚举两种切断方式**。

### 134.4.1 问题是一圈

gas  = [1, 2, 3, 4, 5]
cost = [3, 4, 5, 1, 2]
d    = [-2, -2, -2, +3, +3]

        ┌──────────────────────────────────────────┐

        │                                          │
        │    0 ──→ 1 ──→ 2 ──→ 3 ──→ 4            │

        │    └────────────────────────┘            │
        │                                          │
        │  括号里是净收益 d[i]：                    │
        │    0(-2)  1(-2)  2(-2)  3(+3)  4(+3)     │
        └──────────────────────────────────────────┘

答案 = 3：从 3 出发先攒 3 升，才有本钱穿过开头那三个亏空站

### 134.4.2 前缀和的「谷底」就是答案

```text
P = [0, -2, -4, -6, -3, 0]
      ↑              ↑
     P0  P1  P2  P3  P4  P5=S
                  │
             全局最小值 -6 出现在下标 3
             ⇒ 起点 = 3

  0 ─┐
      │
 -2 ──┤
      │
 -4 ───┤
       │
 -6 ────●  ← 谷底（下标 3）
          │
 -3 ───────┤
      0 ──────────●（回到 0：总量刚好为 0）
```

> 直观解释：从谷底之后出发，你走的每一段都「在谷底之上」，所以油箱永不为负；而绕回开头时，因为 `S ≥ 0`，油箱只会更高。**「最低点之后」就是最安全的起点。**

### 134.4.3 逐轮状态表（`d = [-2, -2, -2, 3, 3]`）

| 轮次 i | d[i] | tank（加完本站后） | tank < 0 ? | start | total | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | -2 | -2 | **是** | 0 → **1** | -2 | 从 0 出发第一段就断油 ⇒ 整段 `[0,0]` 排除 |
| 1 | -2 | -2 | **是** | 1 → **2** | -4 | 同上，`[1,1]` 排除 |
| 2 | -2 | -2 | **是** | 2 → **3** | -6 | 同上，`[2,2]` 排除 |
| 3 | +3 | 3 | 否 | 3 | -3 | 从 3 出发，开始攒油 |
| 4 | +3 | 6 | 否 | 3 | 0 | 攒够 6 升，足以穿过开头三个亏空站 |
| — | — | — | — | — | **0 ≥ 0** | 返回 `start = 3` ✓ |

### 134.4.4 「整段排除」到底省了什么

```text
暴力的候选覆盖（n = 5，每个起点都要走一圈）：
  start=0: ■ ■ ■ ■ ■        ← 5 步
  start=1: ■ ■ ■ ■ ■        ← 5 步
  start=2: ■ ■ ■ ■ ■        ← 5 步
  start=3: ■ ■ ■ ■ ■        ← 5 步
  start=4: ■ ■ ■ ■ ■        ← 5 步

  ┌─ 起点 0 试 1 步就断 → 顺便证明起点 0 也不合法
  │  ┌─ 起点 1 试 1 步就断 → 同样被排除
  │  │  ┌─ 起点 2 试 1 步就断 → 同样被排除
  │  │  │  ┌────────────── 起点 3 一路走完 → 找到答案
  ■  ■  ■  ■ ■ ■ ■ ■
  合计 5 步 = O(n)
```

## 134.5 双语言实现

### 134.5.1 Java

```java
class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int n = gas.length;

        // total：绕一整圈的净收益 Σ(gas-cost)。它 < 0 ⇒ 无论如何都无解（命题 A）。
        // 用 long：n * max(gas) 可达 1e9，虽然 int 勉强装得下，但留足余量更安全。
        long total = 0;

        // tank：从当前候选起点 start 出发，走到「当前站之后」的油箱。
        // 一旦为负，说明从 start 到 i 这一段整段都不能作为起点（引理 B）。
        long tank = 0;

        int start = 0;   // 当前候选起点；语义上满足 P[start] = min{ P[j] : j <= start }

        for (int i = 0; i < n; i++) {
            int d = gas[i] - cost[i];
            total += d;
            tank += d;

            if (tank < 0) {
                // 整段排除：start..i 全部非法，下一个候选直接跳到 i+1。
                // 注意这里不能是 tank <= 0 —— 油箱恰好为 0 是合法的（可以继续走）。
                start = i + 1;
                tank = 0;
            }
        }

        // total < 0 ⇒ 无解。注意不能写 total <= 0：
        // gas=[0,0,0], cost=[0,0,0] 时 total = 0，起点 0 是合法答案。
        return total < 0 ? -1 : start;
    }
}
```

### 134.5.2 Go

```go
package main

func canCompleteCircuit(gas []int, cost []int) int {
	n := len(gas)

	total := 0 // 绕一圈的净收益
	tank := 0  // 从当前候选起点出发以来的油箱
	start := 0 // 当前候选起点

	for i := 0; i < n; i++ {
		d := gas[i] - cost[i]
		total += d
		tank += d
		if tank < 0 {
			// 从 start 出发在 i 处首次断油 ⇒ start..i 整段非法
			start = i + 1
			tank = 0
		}
	}

	if total < 0 {
		return -1 // 总量不够，无解
	}
	return start // 唯一解的前提下，最小的合法起点就是答案
}
```

> **Go 里为什么不需要 `int64`**：`gas[i] ≤ 10^4`、`n ≤ 10^5`，`total` 的最大绝对值是 `10^9`，而 Go 的 `int` 在 64 位平台是 64 位、在 32 位平台是 32 位（`2.147·10⁹`）。本题在 32 位平台上**也刚好安全**，但若把约束任一放大 2 倍就会溢出。写库代码时用 `int64` 更稳妥。Java 的 `int` 恒为 32 位，所以本章 Java 版直接用了 `long`。

### 134.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 累加器类型 | 显式写 `long` | `int` 在 64 位平台是 64 位，可写 `int64` | 本题都安全；这是「同一份逻辑、两种溢出边界」的典型对比 |
| 三元表达式 | `total < 0 ? -1 : start` | **没有三元运算符** | Go 必须写成 `if`，这是最常见的「翻译卡点」 |
| `start` 的越界可能 | `start` 可能等于 `n` | 同 | 此时 `total` 必然 `< 0`（见本节下方的说明），所以返回 `-1`，不会把越界下标交出去 |
| 数组长度 | `gas.length` | `len(gas)` | 一致 |
| 两个平行数组 | `int[] gas, int[] cost` | `gas []int, cost []int` | 一致；Go 里没有「等长」的编译期保证，仍要靠约束 |

> **为什么 `start == n` 时 `total` 必然 `< 0`**：在引理 C 的不变量下 `P[start] ≤ P[0] = 0`；若最后一次断油发生在 `i = n-1`，则 `start = n` 且 `P[n] < P[start-1] ≤ 0`，即 `S < 0`。所以「越界」与「无解」是同一件事，`return total < 0 ? -1 : start` 一行同时兜住了。

### 134.5.4 对拍测试（枚举起点 O(n²) 作为判据）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举每个起点，逐站模拟，O(n²)。语义最直白，最适合当判据。
func bruteGasStation(gas, cost []int) int {
	n := len(gas)
	for start := 0; start < n; start++ {
		tank := 0
		ok := true
		for k := 0; k < n; k++ {
			i := (start + k) % n
			tank += gas[i] - cost[i]
			if tank < 0 {
				ok = false
				break
			}
		}
		if ok {
			return start // 暴力返回「最小合法起点」，与贪心的返回语义完全一致
		}
	}
	return -1
}

func TestGasStationRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024134))
	for iter := 0; iter < 50000; iter++ {
		n := 1 + r.Intn(8)
		gas := make([]int, n)
		cost := make([]int, n)
		for i := 0; i < n; i++ {
			// 值域压到 [0,3]：大量重复、大量 0 消耗、大量恰好为 0 的边界
			gas[i] = r.Intn(4)
			cost[i] = r.Intn(4)
		}
		got, want := canCompleteCircuit(gas, cost), bruteGasStation(gas, cost)
		if got != want {
			t.Fatalf("iter=%d gas=%v cost=%v got=%d want=%d", iter, gas, cost, got, want)
		}
	}
}

// 边界：单元素、全 0（total == 0 但合法）、总量不够、总量恰好够。
func TestGasStationEdge(t *testing.T) {
	cases := []struct {
		gas, cost []int
		want      int
	}{
		{[]int{1}, []int{1}, 0},
		{[]int{1}, []int{2}, -1},
		{[]int{0, 0, 0}, []int{0, 0, 0}, 0},      // total == 0，合法起点 0
		{[]int{2, 3, 4}, []int{3, 4, 3}, -1},     // total = -1
		{[]int{5, 1, 2, 3, 4}, []int{4, 4, 1, 5, 1}, 4}, // 需要绕回开头那段
		{[]int{2, 0, 0}, []int{0, 1, 1}, 0},
	}
	for _, c := range cases {
		if got := canCompleteCircuit(c.gas, c.cost); got != c.want {
			// 注意：有的用例存在多个合法起点，此时用暴力确认「至少有一个解且贪心返回的也是合法解」
			if bruteGasStation(c.gas, c.cost) != got {
				t.Fatalf("gas=%v cost=%v got=%d want=%d", c.gas, c.cost, got, c.want)
			}
		}
	}
}
```

> **为什么暴力返回「最小合法起点」而不是「第一个随便的合法起点」**：本章算法返回的是**最小**合法起点（定理 F）。如果判据只要求「任意一个合法起点」，那些「贪心多跳了一格」的 bug 就会被漏掉。**对拍判据要尽量贴合算法的输出语义，而不是只贴合题目的验收标准。**

## 134.6 复杂度与常见坑

### 134.6.1 复杂度推导

- **时间 O(n)**：`i` 从 `0` 到 `n-1` 各走一次，每次 O(1)。看起来「`start` 会跳」，但 `i` 只会前进、从不回退 —— 这就是整段排除的收益：被排除的下标不会再被任何起点重走，所以总工作量与 `n` 同阶。
- **空间 O(1)**：只有 `total`、`tank`、`start`、`i`、`n`。**连前缀和数组都不需要**（这是它相对「前缀和 + 找谷底」方案的唯一优势，后者是 O(n) 空间）。
- **对照**：暴力 O(n²)；`n = 10^5` 时是 `10^10` 次，与 `10^5` 次相差 5 个数量级。

### 134.6.2 六个真实踩过的坑

1. **贪心没有证明 = 猜** —— 本章是「整段跳过」最容易被误用的模板。很多人背了 `tank < 0 就 start = i+1`，却说不出「为什么 `start` 到 `i` 全部非法」。「跳到 `i+1`」而不是「`i`」还是「`i+2`」？凭什么？答不出就是猜。引理 B 的反证才是这段代码的许可证。
2. **判据写成 `total <= 0` 返回 `-1`** —— `gas=[0,0,0], cost=[0,0,0]` 时 `total = 0`，正确答案是 `0`。必须是 `total < 0`。
3. **`tank < 0` 写成 `tank <= 0`** —— 油箱恰好为 0 **是合法的**（还能继续走）。写成 `<= 0` 会在「刚好走完一圈回到起点、油箱为 0」时误判。
4. **忘记处理 `gas[i]` 与 `cost[i]` 的加法顺序** —— 本题 `d[i] = gas[i] - cost[i]` 表示「到 `i` 站加油、再从 `i` 开往 `i+1`」。如果写成 `d[i] = gas[i+1] - cost[i]`（即「先开再加油」），在环上会让起点偏移一位。**用一句话校验：`d[i]` 必须是「第 i 段」的净收益。**
5. **`int` 溢出** —— `n × max(gas) = 10^9`，Java 的 `int` 上界是 `2.147·10⁹`，本题**刚好不溢出**；但把它抄到 `gas[i] ≤ 10^5, n ≤ 10^5` 的变体上立刻溢出。本章 Java 用 `long`、Go 用默认 `int`（64 位平台安全）。
6. **把「解唯一」当成方法论的一部分** —— 见定理 G 的两个反例。写题解时声称「总油量够则解唯一」，一旦被追问反例就崩。正确处理：算法返回**最小**合法起点（定理 F），唯一性由题面保证。

### 134.6.3 面试官最爱追问的三个问题

**Q1：为什么断油之后可以直接把起点跳到 `i+1`，而不是 `i`？**

> 「因为断油发生在『走完第 `i` 段』之后，即从 `start` 到 `i` 这一段的总净收益为负；而在此之前每一段的前缀和都非负，所以去掉任意前缀（起点右移）之后，剩下的 `[t..i]` 净收益只会**更负**。于是 `start, start+1, …, i` 全部非法，下一个候选只能从 `i+1` 开始。这个结论正是引理 B 的反证。」

**Q2：如果要求返回**所有**合法起点，怎么办？**

> 「先算前缀和 `P[0..n]`，再预处理『后缀最小值』`sufMin[s] = min{P[s..n]}` 与『前缀最小值』`preMin[s] = min{P[0..s-1]}`。于是 `s` 合法 ⟺ `sufMin[s] ≥ P[s]` 且 `preMin[s] ≥ P[s] - S`。两遍 O(n) 就能输出所有合法起点。复杂度仍是 O(n)，但空间从 O(1) 变成 O(n)。」

**Q3：这题能不能用「从谷底之后出发」一句话解决？**

> 「可以，这是等价方案：若 `S ≥ 0`，令 `P[k]` 为 `P[0..n-1]` 的最小值（取**最后**一次出现的位置），则 `k+1` 是合法起点。它比重置法更容易一眼看懂，但需要 O(n) 空间存前缀和，而且『取最后一次出现』这个细节很容易写成『第一次』出错（`gas=[0,0,0], cost=[0,0,0]` 上两者都对，但 `d=[1,-1,0]` 这类输入上会分岔）。工程上我更喜欢重置法：O(1) 空间、且每一行都能对上一条反证结论。」
