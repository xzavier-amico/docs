## 106.1 题目

**原题链接**：<https://leetcode.cn/problems/generate-parentheses/>

### 题意重述（把隐含条件补齐）

数字 `n` 代表生成括号的对数，请设计一个函数，用于能够生成所有可能的并且**有效的括号组合**。要求：

- 每个串长度恰好 `2n`：`n` 个 `(` 与 `n` 个 `)`；
- 串**有效**：任意前缀中 `(` 的数量 `>=` `)` 的数量，且总数量相等；
- 解集顺序任意，不能重复。

一句话：「用 `n` 对括号拼出所有合法的括号序列」。

五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **恰好 `n` 个左括号** | 「`n` 代表生成括号的对数」 | 少于或多于 `n` 个 `(` → 长度不对或数量不匹配 |
| **任意前缀左括号不少于右括号** | 「有效的括号组合」 | 只在最后检查总数相等 → 输出 `"())("` 这类非法串（总数对但前缀非法） |
| **不能出现 `)(` 开头的串** | 上一条的推论 | 这是「前缀条件」的直接体现：任何前缀都必须 `open >= close` |
| **解的数量是卡特兰数** | 数学事实 | `n = 8` 时是 `1430` 个（不是 `2^16 = 65536`）；数量对不上就说明剪枝写错了 |
| **顺序任意** | 「按任意顺序返回答案」 | 对拍需规范化；本题因枚举顺序固定，实际上天然稳定 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 8` | n 至多 8 | 答案数 = 卡特兰数 `C_n`：`1, 2, 5, 14, 42, 132, 429, 1430`（`n = 1..8`）。本机实测 `n = 8`：**Java ≈ 0.9 ms、Go ≈ 0.7 ms** |
| 暴力上界 `2^(2n)` | `n=8` 时 65536 | 是答案数（1430）的 **46 倍** —— 这就是剪枝要赚回的差距 |
| 输出规模 | `O(n · C_n)` | `n=8`：`1430 × 16 ≈ 22880` 个字符，输出本身是主要开销 |
| 递归深度 | 恰好 `2n = 16` | 极浅，不会爆栈 |

> 💡 **量级反推**：`n ≤ 8` 说明指数级可接受；但**答案数是卡特兰数而非 `2^(2n)`**，这两者差 46 倍。**这道题的分数全在「如何只生成合法的那些」上，而 `open` / `close` 两个计数器就是全部答案。**

### 示例

```text
输入：n = 3
输出：["((()))","(()())","(())()","()(())","()()()"]     ← 5 个 = C_3

输入：n = 1
输出：["()"]                                             ← 1 个 = C_1

输入：n = 2
输出：["(())","()()"]                                     ← 2 个 = C_2
```

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① n = 1             → 只有 "()"，检验 close < open 在最后一步仍成立
② n = 2             → 只有 "(())" 与 "()()"，不能出现 "())(" / ")()("
③ n = 3             → 5 个，少一个就说明某个剪枝过紧
④ n = 4             → 14 个（卡特兰数），是"能不能写对"的分水岭
⑤ n = 8             → 1430 个，是"剪枝对不对"的终检
```

第 ⑤ 条是量化自检：**只要有一个剪枝写错（过松或过紧），数量必然偏离 1430。** 这比肉眼检查字符串快得多。

## 106.2 从暴力到最优：第一个念头为什么错

### 第一步：第一个念头 —— 枚举所有 `2^(2n)` 个括号串，再验证

长度为 `2n` 的串，每一位是 `(` 或 `)`，共 `2^(2n)` 个：

```text
for mask in 0 .. 2^(2n)-1:
    按 mask 生成括号串 s
    检查 s 是否合法（一个计数器：遇 '(' +1，遇 ')' -1，中途不得为负，最终必须为 0）
    合法 → 收集
```

| n | `2^(2n)` | 合法串数 `C_n` | 浪费倍数 |
| --- | --- | --- | --- |
| 3 | 64 | 5 | 12.8× |
| 5 | 1,024 | 42 | 24.4× |
| 8 | 65,536 | 1,430 | **45.8×** |
| 12 | 16,777,216 | 208,012 | 80.6× |

**它错在哪**：绝大部分位串从第一位就已经注定非法（例如以 `)` 开头的所有串）。**验证发生在最后，而非法性在很早就能看出来**——这正是「回溯 + 剪枝」要解决的形状。

### 第二步：第二个念头 —— 先保证数量对，再保证顺序对

合法性其实由**两条独立的约束**组成：

| 约束 | 一句话 | 什么时候能检查 |
| --- | --- | --- |
| **C1：数量** | 恰好 `n` 个 `(`、`n` 个 `)` | 每放一个就能维护 |
| **C2：顺序（前缀条件）** | 任意前缀里 `open >= close` | 每放一个就能维护 |

于是搜索树只需要**两个计数器** `open`、`close`：

```text
dfs(open, close):
    若 open == n 且 close == n → 收集
    若 open < n                 → 可以放 '('
    若 close < open             → 可以放 ')'
```

**注意这两个条件的写法差异**，它们是本章的全部技术含量：

- `open < n`：左括号**总量**不能超 `n`。
- `close < open`：右括号**任何时候**不能多于左括号（这就是前缀条件！）。

### 第三步：卡点 —— 为什么 `close < open` 就等价于「前缀合法」

这是本题唯一需要想通的地方。先看一个事实：

```text
把 '(' 记 +1，')' 记 -1，令 bal(k) = 前 k 个字符的和。
「任意前缀 open >= close」 ⟺ 「∀k, bal(k) >= 0」
```

而 `bal(k) >= 0` 这件事**只需要在一个位置检查**：因为每放一个字符，`bal` 只变化 ±1，所以「放 `)` 之后 `bal >= 0`」等价于「放之前 `bal >= 1`」，即 `open - close >= 1`，也就是 `close < open`。

**这就是「局部条件 ⟺ 全局条件」的转化**：

| 全局条件（在末尾验证） | 局部条件（每步验证） |
| --- | --- |
| 整个串的所有前缀都满足 `open >= close` | 每一步放 `)` 之前满足 `close < open` |

**为什么必须用 `close < open` 而不是 `close <= n`**：后者只保证「右括号不超总数」，会允许 `"())("`——在第三个字符处 `close = 2 > open = 1`，前缀非法。**`close <= n` 是必要的但远不充分；`close < open` 才是充分必要的局部形式。**

### 第四步：树形状 —— 为什么它是「二叉决策树」而不是「起点递增」

本题每层的候选**永远是两个**（`(` 或 `)`），与「数组的下标」无关，所以它属于 096 §2 讲的**定义 A（二叉决策树）**：

| 决策树形态 | 结点状态 | 每层边数 | 本题 |
| --- | --- | --- | --- |
| 定义 A（二叉：选/不选） | `(i, path)` | 2 | 106（每层两条边：`(` 与 `)`） |
| 定义 B（起点递增） | `(start, path)` | `n - start` | 096–100、105 |
| 序列型（`used`） | `(used, path)` | `n - len` | 101、102、104 |

**判据**：候选集合与「已用下标」无关、而是由**固定的两个动作**组成 → 定义 A。这也解释了为什么 106 的代码里根本没有 `for` 循环——两条边是写死的一个 `if` / 一个 `if`。

## 106.3 原理拆解

### 106.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（不含输出） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举 `2^(2n)` + 末尾验证 | `O(n·4^n)` | `O(n)` | 20 行 | 浪费 46 倍（`n=8`）；`n` 稍大立刻不可行 |
| 递归 + 只判「数量」`close <= n` | — | — | 15 行 | **错解**：输出 `"())("` 等非法串 |
| **递归 + 双计数剪枝** ✅ | `O(n · C_n)` | `O(n)` 栈 | **12 行** | `n` 很大时答案数（卡特兰数）本身爆炸 |
| 递归 + 生成后过滤（先枚举后缀再筛） | `O(4^n)` | `O(n)` | 18 行 | 同第一行，效率差 |
| 卡特兰 DP（`dp[i] = Σ dp[j]·dp[i-1-j]`） | `O(n²·C_n)` | `O(n·C_n)` | 20 行 | 代码更长；本质与回溯等价（枚举所有括号化方式） |
| 位运算 / 卡特兰公式直接构造第 k 个 | `O(n²)` | `O(n)` | 25 行 | 只能求「第 k 个」，不能枚举全部 |

**为什么选第三行**：它用两个整数 `open`/`close` 就把「前缀条件」变成了「边的可行性」，于是**每个非法串从一开始就不存在**，而不是先生成再删。代码只有 12 行，复杂度与答案数同阶。

### 106.3.2 为什么这个做法是对的（正确性论证）

**引理 1（算法只产生合法串）**：算法生成的每个长度 `2n` 的串都满足「`n` 个 `(`、`n` 个 `)`、任意前缀 `open >= close`」。

> 证明分三点：
> ① **数量**：只有 `open < n` 时才放 `(` → 至多 `n` 个 `(`；而总长度到 `2n` 时必须已放满（否则会停在更短的长度上，见 ②），故恰好 `n` 个 `(`。同理 `close` 至多到 `open <= n`，总数 `2n` 减去 `n` 个 `(` 得到恰好 `n` 个 `)`。
> ② **不会提前卡死**：若 `open < n` 可以放 `(`；若 `open == n` 且 `close < open` 可以放 `)`；只有当 `open == close == n` 时才两者都不满足，此时长度恰为 `2n`。所以每条路径都能走满 `2n`。
> ③ **前缀条件**：只有在 `close < open`（即当前 `bal = open - close >= 1`）时才放 `)`，放完 `bal >= 0`；放 `(` 只会让 `bal` 增加。所以任意前缀的 `bal >= 0`。∎

**引理 2（算法不重）**：每个合法串只被生成一次。

> 证明：长度 `2n` 的串由「每一步放什么」唯一决定，而决策树是一棵**树**（每个结点只有一条路径从根到达），所以同一串不可能由两条路径产生。∎

**引理 3（算法不漏）**：任何合法串 `s` 都会被生成。

> 归纳：设 `s` 合法。沿 `s` 的字符逐个走：
> - 若第 `k+1` 个字符是 `(`：因为 `s` 里一共恰有 `n` 个 `(`，所以此前放的 `(` 个数 `< n`，满足 `open < n`，该边可用。
> - 若第 `k+1` 个字符是 `)`：因为 `s` 合法，前 `k` 个字符的前缀满足 `open >= close`，且第 `k+1` 个是 `)` 后仍需 `bal >= 0`，故此前必有 `open > close`，满足 `close < open`，该边可用。
> 于是 `s` 的每一步都走得通，最终被收集。∎

**定理**：算法输出恰好是所有合法括号串，每个一次。∎

**数量自检（卡特兰数）**：

```text
C_n = (1/(n+1)) · C(2n, n) = C(2n,n) - C(2n,n+1)
n :  1   2   3   4    5    6     7     8
C :  1   2   5  14   42  132   429  1430
```

> **为什么答案数是卡特兰数**：合法的括号序列与「`n` 个结点的二叉树形态」一一对应（`(` = 进入左子树，`)` = 回溯），而后者正是 `C_n`。这条联系在 §106.3.4 的追问里会用到。

### 106.3.3 通用解题思路（可迁移的那一层）：把全局条件拆成局部计数

本章要装进工具箱的是「**计数式合法性剪枝**」：

```text
┌──────────── 全局合法性 → 两个计数的翻译表 ────────────┐
│                                                      │
│  全局条件：整个串合法                                  │
│      ↓ 找不变量（每步都能更新的量）                     │
│  计数器：open（已放左括号）、close（已放右括号）          │
│      ↓ 把每个全局约束写成「边的可行性」                  │
│  边 '('：可行 ⟺ open < n        （总量约束）            │
│  边 ')'：可行 ⟺ close < open    （前缀约束，核心）      │
│      ↓                                                │
│  收集：length == 2n（此时 open == close == n）          │
│                                                      │
│  记忆点：close < open ⇔ 「放 ')' 之后 bal 仍 >= 0」      │
└──────────────────────────────────────────────────────┘
```

统一骨架（二叉决策树 + 计数剪枝）：

```text
void dfs(int open, int close, path) {
    if (path.length() == 2*n) { ans.add(copy(path)); return; }   // 解在叶子
    if (open < n) {                       // 边 1：放 '('
        path.add('('); dfs(open+1, close, path); path.removeLast();
    }
    if (close < open) {                   // 边 2：放 ')'（注意不是 close < n）
        path.add(')'); dfs(open, close+1, path); path.removeLast();
    }
}
```

属于「计数剪枝」这个模型的题：

| 题 | 计数器是什么 | 剪枝条件 |
| --- | --- | --- |
| [LC 22 括号生成](https://leetcode.cn/problems/generate-parentheses/) | `open` / `close` | `open < n`、`close < open` |
| [LC 301 删除无效的括号](https://leetcode.cn/problems/remove-invalid-parentheses/) | 需要删除的左右括号数 | 删除数不超上限 + 前缀合法性 |
| [LC 921 使括号有效的最少添加](https://leetcode.cn/problems/minimum-add-to-make-parentheses-valid/) | 当前 `bal` 与已补数 | 只求最小添加数 → 贪心，不必回溯 |
| [LC 32 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/) | `bal` 与栈 | 求最长长度 → DP/栈，不是枚举 |
| [LC 17 电话号码的字母组合](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/) | 已处理位数 | 位数用尽即收集（无其它剪枝） |
| [LC 89 格雷编码](https://leetcode.cn/problems/gray-code/) | 已生成集合 | 相邻只差一位 |

### 106.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 只要**方案数** | 只数不枚举 | 直接算 `C_n = C(2n,n)/(n+1)`（注意用 `long` 防溢出），`O(n)` |
| 换成 `[` `]`、`{` `}` **多种括号** | 需要匹配类型 | 必须用**栈**记录未匹配的开启符号，剪枝变成「栈顶是否匹配」 |
| 要求第 **k** 个合法串（字典序） | 定位 | 用卡特兰数做「计数 + 跳转」：`(` 分支下的方案数 = `C_{n-open-1, ...}`，逐位决定 |
| 给一个串，求**所有**删除最少括号后的合法串 | 从零构造变修改 | LC 301：先算要删几个 `(` 与 `)`，再回溯删除（需同层去重避免重复） |
| 括号可**加颜色**（每对括号 k 种颜色） | 计数变体 | 答案数乘 `k^n`；剪枝不变，收集时区分颜色 |
| `n` 涨到 `20` | 答案数 `6564120420` | 只能计数（`BigInteger`），不能枚举 |

## 106.4 图解推演

### 106.4.1 `n = 3` 的完整决策树

```text
                        dfs(open=0, close=0)  ""
        ┌───────────────────────┴───────────────────────┐
      '(' open<3                                    ')' close<open? 
      open=1,close=0                                0 < 0 假 → ⊘ 剪
        │
   dfs(1,0)  "("
   ┌────┴─────┐
 '(' open<3  ')' close<open
   │            │
dfs(2,0)"(("  dfs(1,1)"()"
 ┌──┴──┐      ┌──┴───┐
'('   ')'    '('    ')' close<open?
 │     │      │      1 < 1 假 → ⊘
 │     │      │
 ▼     ▼      ▼
dfs(3,0) dfs(2,1) dfs(2,1)
"((("    "(()"    "()("
 │        │        │
 only ')' only ')'  ┌┴──────┐
        (close<open) '(' ⊘ open=3 不行   ')' close<open (1<2) ✓
 ▼        ▼          ▼
dfs(3,1) dfs(3,2)  dfs(2,2)
"((()"   "(()))"?  "()()"
 ...
 最终 5 个叶子：
   ((()))   (()())   (())()   ()(())   ()()()
   对应 open/close 走到 (3,3) 的五条路径
```

**图上的两个 ⊘ 说明了两条剪枝各自的语义**：

- 根的 `)` 分支被剪：`close < open` 为假（`0 < 0`），表示「还没有左括号就不能放右括号」；
- `"()"` 之后的 `)` 分支被剪：`close < open` 为假（`1 < 1`），表示「左括号用完了，右括号不能再加」。

### 106.4.2 逐层状态表（`n = 3`，只跟踪一条路径 `"(()())"`）

| 步 | 动作 | `open` | `close` | `bal = open - close` | `path` | 判定依据 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 放 `(` | 1 | 0 | 1 | `(` | `open(0) < 3` |
| 2 | 放 `(` | 2 | 0 | 2 | `((` | `open(1) < 3` |
| 3 | 放 `)` | 2 | 1 | 1 | `(()` | `close(0) < open(2)` |
| 4 | 放 `(` | 3 | 1 | 2 | `(()(` | `open(2) < 3` |
| 5 | 放 `)` | 3 | 2 | 1 | `(()()` | `close(1) < open(3)` |
| 6 | 放 `)` | 3 | 3 | 0 | `(()())` | `close(2) < open(3)` → 长度 6 → **收集** |

**第 6 步是关键**：`close = 2 < open = 3` 成立，所以最后一个 `)` 可以放；放完 `bal = 0`，正好配对。

### 106.4.3 三种剪枝写法的对照（`n = 3`）

| 写法 | 剪枝条件 | 输出数量 | 是否正确 |
| --- | --- | --- | --- |
| 无剪枝（只判长度） | 无 | `64` 个长度 6 的串 | ❌ 大量非法 |
| 只判总数 | `open < n`、`close < n` | `20` 个 | ❌ 含 `"())("`、`")()("` 等 |
| **正确剪枝** | `open < n`、`close < open` | **5** 个 | ✅ 等于 `C_3` |

第二行的 `20 = C(6,3)` 是「选 3 个位置放 `(`」的组合数；把它降到 `5` 的那一步，正是 `close < open` 这条前缀约束的贡献。

## 106.5 双语言实现

### 106.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> res = new ArrayList<>();
        // 用 StringBuilder 当容器型状态：append / deleteCharAt 成对
        StringBuilder path = new StringBuilder(2 * n);
        dfs(0, 0, n, path, res);
        return res;
    }

    /** open = 已放左括号数；close = 已放右括号数；两者就是决策树的全部状态 */
    private void dfs(int open, int close, int n, StringBuilder path, List<String> res) {
        // 解在叶子：长度到 2n 时必然 open == close == n
        if (path.length() == 2 * n) {
            res.add(path.toString());     // toString 生成新字符串，天然安全
            return;
        }

        // 边 1：放 '('。条件 open < n 来自「总共只能有 n 个左括号」
        if (open < n) {
            path.append('(');
            dfs(open + 1, close, n, path, res);
            path.deleteCharAt(path.length() - 1);   // ③(b) 撤销：删最后一个字符
        }

        // 边 2：放 ')'。条件 close < open 是「前缀里右括号不能多于左括号」的局部形式
        // 注意：绝不能写成 close < n —— 那样会放过 "())(" 这类前缀非法的串
        if (close < open) {
            path.append(')');
            dfs(open, close + 1, n, path, res);
            path.deleteCharAt(path.length() - 1);   // ③(b) 撤销
        }
    }
}
```

### 106.5.2 Go

```go
package main

func generateParenthesis(n int) []string {
	res := make([]string, 0)
	buf := make([]byte, 0, 2*n) // 用字节切片当容器型状态：append / 截断成对

	var dfs func(open, close int)
	dfs = func(open, close int) {
		if len(buf) == 2*n {
			// string(buf) 会复制一份新的字符串，所以这里天然安全
			// （如果直接存 buf 这个 []byte，就会踩切片别名坑，见下）
			res = append(res, string(buf))
			return
		}

		if open < n { // 边 1：左括号总量不足 → 可以放 '('
			buf = append(buf, '(')
			dfs(open+1, close)
			buf = buf[:len(buf)-1] // ③(b) 撤销：缩回一位
		}

		if close < open { // 边 2：右括号少于左括号 → 可以放 ')'（不是 close < n！）
			buf = append(buf, ')')
			dfs(open, close+1)
			buf = buf[:len(buf)-1] // ③(b) 撤销
		}
	}
	dfs(0, 0)
	return res
}
```

### 106.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 容器型状态 | `StringBuilder` + `append` / `deleteCharAt(len-1)` | `[]byte` + `append` / `buf[:len-1]` | 两边都是「加一个字符 / 删最后一个字符」 |
| 存进结果 | `path.toString()`（**新对象**） | `string(buf)`（**复制**） | **两边都天然安全**：都产生独立的值，不是引用 |
| 存放可变序列的诱惑 | `List<char[]>` | `[][]byte` | **一旦这么写就要深拷贝**，否则踩别名坑（见下） |
| 字符类型 | `char`（16 位） | `byte`（8 位） | `(`/`)` 都是 ASCII，等价；若换成中文括号则必须用 `rune` |
| 递归参数 | 显式传 `open/close/n/path/res` | 闭包捕获 `n/buf/res` | Go 少传参数；`res = append(...)` 改的是捕获变量，正确 |

#### ⚠️ Go 切片别名：本章的「侥幸安全」与「真实陷阱」

本章之所以**默认写法安全**，是因为 `string(buf)` 会**复制**字节。一旦有人为了「省一次转换」把结果存成 `[][]byte`，坑立刻回来。我实测 `n = 3`：

```text
写法 A（本章的写法，安全）：res = append(res, string(buf))
  ["((()))" "(()())" "(())()" "()(())" "()()()"]        ✓ 5 个，全部正确

写法 B（把 []byte 直接存起来，错误）：res = append(res, buf)
  [[40 40 40 41 41 41] [40 40 40 41 41 41] [40 40 40 41 41 41] ...]
  ↑ 5 个结果全指向同一块底层数组，内容都是最后一次写入的 "()()()"：
    [40 40 41 40 41 41] 才对，但打印出来 5 行一模一样

写法 C（正确但啰嗦）：res = append(res, append([]byte(nil), buf...))
  5 个字节切片内容各自正确
```

**判据依然是那句**：只要一个 `[]T` 会被存进容器、且之后还会被 `append`/截断，就必须拷贝。本章因为用 `string(buf)` 做了一次**值转换**，等于自动做了拷贝，所以安全；**这不是「本题没有别名问题」，而是「本题恰好用了一个带拷贝的操作」**。

```go
// 本章推荐写法（值转换 = 隐式拷贝）
res = append(res, string(buf))

// 如果非要存 []byte，两种正确写法任选：
res = append(res, append([]byte(nil), buf...))          // 深拷贝
res = append(res, buf[:len(buf):len(buf)])              // 三下标截断（只能挡住通过该头的后续写）
```

### 106.5.4 对拍测试（写完必须跑）

参考实现用**「枚举所有 `2^(2n)` 位串 + 独立的前缀扫描验证」**——与「双计数剪枝」完全独立。

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// 独立校验：前缀平衡 + 最终归零
func isValidParen(s string) bool {
	bal := 0
	for i := 0; i < len(s); i++ {
		if s[i] == '(' {
			bal++
		} else {
			bal--
		}
		if bal < 0 {
			return false
		}
	}
	return bal == 0
}

// 参考实现：枚举 2^(2n) 个串，筛出合法的
func bruteGenerate(n int) []string {
	out := []string{}
	total := 2 * n
	for mask := 0; mask < 1<<total; mask++ {
		b := make([]byte, total)
		for i := 0; i < total; i++ {
			if mask>>i&1 == 1 {
				b[i] = '('
			} else {
				b[i] = ')'
			}
		}
		if isValidParen(string(b)) {
			out = append(out, string(b))
		}
	}
	return out
}

func TestGenerateParenthesisRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2026106))
	catalan := []int{1, 1, 2, 5, 14, 42, 132, 429, 1430} // 下标 n
	for iter := 0; iter < 4000; iter++ {
		n := 1 + r.Intn(8) // n ∈ [1,8]，覆盖上界
		got := generateParenthesis(n)
		want := bruteGenerate(n)
		sort.Strings(got)
		sort.Strings(want)
		if len(got) != len(want) {
			t.Fatalf("iter=%d n=%d 数量 %d != %d", iter, n, len(got), len(want))
		}
		if len(got) != catalan[n] {
			t.Fatalf("iter=%d n=%d 数量 %d，卡特兰数应为 %d", iter, n, len(got), catalan[n])
		}
		for i := range got {
			if got[i] != want[i] {
				t.Fatalf("iter=%d n=%d 第%d项 %q vs %q", iter, n, i, got[i], want[i])
			}
			if !isValidParen(got[i]) || len(got[i]) != 2*n {
				t.Fatalf("iter=%d n=%d 非法串 %q", iter, n, got[i])
			}
		}
	}
}
```

## 106.6 复杂度与常见坑

### 106.6.1 复杂度推导（写结论不算本事，要能推）

**时间 `O(n · C_n)`，其中 `C_n = C(2n,n)/(n+1)` 是卡特兰数。**

1. **叶子数**：每个叶子对应一个合法串，所以叶子数 `= C_n`。
2. **结点数**：这是一棵二叉树，内部结点数 `< 叶子数`，所以总结点数 `≤ 2·C_n = O(C_n)`。
3. **每结点工作量**：收集时拷贝字符串 `O(n)`；每层只有两条边，判断 `O(1)`。

所以 `O(n·C_n)`。**若只数个数不构造，时间可降到 `O(C_n)`** —— 拷贝是唯一带 `n` 因子的开销。

用斯特林公式展开：`C_n ~ 4^n / (n^{1.5} √π)`，所以也常写成 `O(4^n / n^{1.5})`。对比暴力 `O(n·4^n)`，剪枝把 `4^n` 的底数前面加了个 `n^{1.5}` 的分母 —— `n = 8` 时是 `65536` 对比 `1430`。

**空间 `O(n)`（不含输出）**：递归深度恰好 `2n`，`path` 长度 `≤ 2n`。输出 `O(n·C_n)`。

### 106.6.2 七个真实踩过的坑

1. **`close < open` 写成 `close < n`** —— 输出 `C(2n,n)` 个串（`n=3` 时 `20` 个），其中大量前缀非法。**这是本题最高频的错误。**
2. **`close <= open` 忘了只在有左括号时才成立** —— 起点 `open = close = 0` 时 `0 <= 0` 为真，会允许第一个字符是 `)`。必须用严格 `<`。
3. **收集条件写成 `open == n && close == n`** —— 正确，但要保证另一条边（长度够）也成立；若只写 `open == n` 就收集，会把 `"((("` 之类当解。稳妥写法是 `len == 2n`。
4. **忘了撤销 `path`** —— 路径越滚越长，长度判断 `len == 2n` 只在少数分支触发，且收集到的串互相污染。
5. **Java 用 `path.deleteCharAt(0)`** —— 删的是**第一个**字符而不是最后一个，路径彻底错乱。必须 `path.length() - 1`。
6. **Go 里把 `buf` 当 `[]byte` 直接存结果** —— 所有结果指向同一底层数组（§106.5.3 实测）。用 `string(buf)` 或深拷贝。
7. **以为 `n = 0` 等于「没有答案」** —— 空串是唯一的合法串（`""`），所以 `n = 0` 时应返回 `[""]`。本题约束 `n ≥ 1`，但被追问时要答得出。

### 106.6.3 面试官最爱追问的三个问题

**Q1：为什么 `close < open` 就够，不需要用栈检查合法性？**
> 「因为这里只涉及一种括号。把 `(` 记 +1、`)` 记 -1，合法性等价于『任意前缀和非负且总和为零』。而每走一步和只变化 ±1，所以『放 `)` 之后非负』等价于『放之前和 ≥ 1』，也就是 `open - close >= 1` 即 `close < open`。**如果有多种括号（`[]`、`{}`），这个转化就不成立了——那时必须用栈记录未匹配的开启符，剪枝变成『栈顶是否匹配』。**」

**Q2：答案数量为什么是卡特兰数？**
> 「有两层理解：① 组合证明：`n` 对括号的合法序列数等于 `C(2n,n) - C(2n,n+1) = C(2n,n)/(n+1)`，即总选法中减去『存在前缀非法的那些』（用反射原理一一对应到 `C(2n,n+1)`）；② 结构证明：每个合法序列与『`n` 个结点的二叉树形态』一一对应（`(` = 进入左子树，`)` = 回到父结点），而 `n` 个结点的二叉树恰有 `C_n` 种形态。**这两种理解在面试里能说出来一个就够。**」

**Q3：如果要求生成第 k 个（字典序）合法串呢？**
> 「不需要枚举前 `k-1` 个。可以『逐位定位』：站在某个状态 `(open, close)` 上，如果放 `(`，那么后续能完成的方案数是一个卡特兰相关量（可以用 `f[a][b]` 的 DP 表预先算好『已有 a 个左括号、b 个右括号时还剩多少种合法补法』）。若 `k` 落在 `(` 分支的数量里，就选 `(`；否则 `k` 减去它，选 `)`。时间 `O(n²)` 预处理 + `O(n)` 定位。**这就是『能计数就能定位』的典型用法。**」
