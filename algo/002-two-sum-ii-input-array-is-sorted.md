## 002.1 题目

**原题链接**：<https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/>

### 题意重述（把隐含条件补齐）

给你一个**下标从 1 开始计数**的整数数组 `numbers`，它已经**按非递减顺序排列**。请你在数组中找出**两个不同的元素**，使它们的和等于 `target`，返回它们的下标 `[index1, index2]`（`1 <= index1 < index2 <= n`）。

题目保证**有且仅有一个答案**，并且要求你**不能重复使用同一个元素**，也**不允许使用额外的 O(n) 空间**（这条不是判题硬约束，但它是本题的设计意图，面试官会问）。

把约束一条条拆开：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **下标从 1 开始** | 「`1` 开始计数」 | 返回 `[0, 3]` 而不是 `[1, 4]` → 答案错误（最常见的一分丢在这里） |
| **恰好一个答案** | 「保证有且仅有一个答案」 | 允许「找到就 `return`」，不必收集全部解 |
| **同一元素不能用两次** | 「两个不同的元素」 | `numbers = [1,1], target = 2` 返回 `[1,1]` → 非法 |
| **数组已非递减有序** | 题干第一句 | 这是**全部优化空间的来源**，不利用它就只能 O(n) 空间做哈希 |
| **返回值不是原下标** | 「返回下标 `index1, index2`」 | 有序 + 不要求原下标 → 可以放心在数组上对撞，不必备份 |

> ⚠️ 注意「非递减」三个字：它允许**相等元素**（如 `[2,2,3]`），这和「严格递增」是两回事。把「有序」误读成「元素互不相同」是后面去重类问题的头号 bug 来源。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `2 <= numbers.length <= 3 * 10^4` | n 至多 3 万 | **O(n²) ≈ 4.5·10⁸ 次配对**。本机 2 核容器实测（JDK 17 / Go 1.19，n=3·10⁴ 且构造为「必须扫满」的输入）：**Java ≈ 131 ms，Go ≈ 205 ms** —— 属于「赌判题机不抖就能过」的写法，面试里不能当正解 |
| `-1000 <= numbers[i] <= 1000` | 值域很小 | `numbers[l] + numbers[r]` 最坏 `±2000`，**Java 的 `int` 完全安全**；但若你在面试里被改成 `±10^9`，就必须换 `long`（§002.6 会专门讲） |
| `-1000 <= target <= 1000` | 同上 | 同上 |
| `numbers` 按**非递减**排序 | 输入保证 | 单调性 → **对撞双指针**；不需要额外空间 |
| **答案唯一** | 输入保证 | 可以提前 `return`；对拍测试时也必须按「唯一性」写判据（见 §002.5.4） |

> 💡 **量级 → 算法** 的条件反射继续沿用：`n ≤ 3·10⁴` 其实 O(n log n) 和 O(n²) 都能过，**所以这题不靠复杂度卡人，靠「空间」和「正确性论证」卡人**。如果一个候选解需要 O(n) 额外空间，而题目给了有序，那它在这个语境下就是次优解。

### 示例

```
输入：numbers = [2, 7, 11, 15], target = 9
输出：[1, 2]
解释：2 + 7 = 9，对应 1-based 下标 1 和 2（0-based 是 0 和 1）

输入：numbers = [2, 3, 4], target = 6
输出：[1, 3]
解释：2 + 4 = 6；注意 3 + 3 = 6 但那是同一个元素用了两次，非法

输入：numbers = [-1, 0], target = -1
输出：[1, 2]
解释：下标从 1 开始，负数也一样处理；没有任何「非负」假设可以偷
```

### 我自造的三个反例（写完解法必须拿它们打一遍）

```text
① [2,3,4], 6            → 暴露 "l 和 r 可以重合" 的误判（3+3 不是合法解，l<r 而非 l<=r）
② [1,2,3,4,4,9], 8      → 暴露 "遇到重复值就跳过" 的错误去重（4+4 是合法解，且必须取两个不同的 4）
③ [-5,-3,-1,2,4], -1    → 暴露 "假设数组非负" 的写法（如把 r 初始化成 target 的某个函数）
```

第 ② 条最阴：很多人从 003 三数之和带过来「遇到相同值就 `l++` / `r--`」的习惯，在 167 里一加上去就把 `4+4` 这种**合法且唯一**的解直接跳过了。**去重是三数/四数之和的需求，不是两数之和的需求。**

## 002.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```java
// 暴力：枚举所有 (i, j), i < j
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (numbers[i] + numbers[j] == target) return new int[]{i + 1, j + 1};
```

- 时间 **O(n²)**，空间 **O(1)**。
- `n = 3·10⁴` 时是 `n(n-1)/2 ≈ 4.5·10⁸` 次加法比较。**能过，但每一步都在浪费「有序」这个免费的礼物。**
- 面试官问「能不能更快」时，如果你答「不能」，这题就废了 —— 因为这题的正解就是用来教「有序 → 单调性 → 排除法」的。

### 第二步：卡点在哪

把暴力画成一棵决策树：外层固定 `i`，内层扫 `j`。对每个 `i`，你都在**线性地**找「有没有 `target - numbers[i]`」。

```
i=0  → 找 target-a[0]  →  扫 j=1..n-1   （n-1 次）
i=1  → 找 target-a[1]  →  扫 j=2..n-1   （n-2 次）
...
共 n(n-1)/2 次
```

问题不在于「找」，而在于**找的方向是盲的**。数组有序，意味着「`j` 往右走，`numbers[i] + numbers[j]` 单调变大」。既然和是单调的，那么对固定的 `i`，**你不用一个个试，你可以直接判断「当前这对是太大还是太小」，然后整排整排地砍掉候选**。

**卡点不是「配对」，而是「候选集没有被结构化地排除」。** 这是本题和 001 的分水岭：

- 001 的卡点是「查找被做成了线性」→ 换哈希结构。
- 002 的卡点是「候选集没有单调结构」→ 用有序性做**排除**。

### 第三步：灵感的来源 —— 对撞双指针

取两个指针放在数组两端：`l = 0, r = n - 1`。看它们的和 `s = a[l] + a[r]`：

| 情况 | 结论 | 动作 |
| --- | --- | --- |
| `s == target` | 找到了 | 返回 |
| `s < target` | **`a[l]` 配任何 `a[j] (j <= r)` 都太小** | `l++` |
| `s > target` | **`a[r]` 配任何 `a[i] (i >= l)` 都太大** | `r--` |

关键在中间两行：`s < target` 时，`a[l]` 和 `a[r]` 已经分别是「和它配对的最大的那个」了，还是不够 —— 所以 **`a[l]` 和区间内任何一个元素配对都不可能等于 `target`**，这一整排候选可以整批删掉。同理 `s > target` 时删掉 `a[r]` 的整列。

```
候选集从 n(n-1)/2 个配对，每一步删掉一整排 → 步数从 O(n²) 降到 O(n)
```

这就是「用单调性换指数级（这里是平方级）剪枝」的母题。

### 另一条路：逐元素二分

有序 + 「找某个值」= 二分。对每个 `i`，在 `[i+1, n-1]` 上二分找 `target - a[i]`：

- 时间 **O(n log n)**，空间 **O(1)**。
- 比暴力好，比双指针**差一个 log**，而且代码更长、边界更多（`lo/hi` 闭合性、找不到时的 `-1`）。
- 但它有一个双指针没有的能力：**它不需要数组整体有序，只要「能二分」**。如果数据是**分段有序**或者你要在**静态有序数组上做 m 次不同 target 的查询**，二分才是对的。

> ⚠️ 「算法没有优劣，只有匹配约束」在这里第二次出现：**单次查询 + 全局有序 → 双指针；多次查询 + 静态数据 → 预处理/二分；无序 → 哈希（001）。**

## 002.3 原理拆解

### 002.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力枚举 | O(n²) | O(1) | 5 行 | n ≥ 10⁵ 直接 TLE；面试直接扣分 |
| 哈希表（001 的写法） | O(n) | **O(n)** | 10 行 | 题目明确不要额外空间；值域巨大时内存吃紧 |
| 逐元素二分 | O(n log n) | O(1) | 12 行 | 单次查询时比双指针多一个 log，边界更易错 |
| **对撞双指针** ✅ | **O(n)** | **O(1)** | **8 行** | 数组**无序**时（此时必须排序 O(n log n)，或退回哈希） |

**为什么双指针在本题严格支配哈希**：两者时间同为 O(n)（哈希常数更大：装箱、求模、冲突探测），但双指针空间 O(1)。在「输入有序」这个前提下，哈希的 O(1) 查找**根本没有买到任何东西** —— 因为有序数组的「查找」可以靠移动指针**顺带**完成，而指针的移动次数总额被 `l` 单调增、`r` 单调减卡死在 `n` 次。

### 002.3.2 为什么这个做法是对的（正确性论证）

这里给出两个层次的论证，面试里讲第一个就够了，讲第二个能加分。

**论证一：循环不变量（排除法的严格版）**

> **不变量**：在每一轮循环开始时，若存在解 `(i*, j*)`，则必有 `l <= i* < j* <= r`。

- **初始**：`l = 0, r = n-1`，任何下标对都落在区间内，成立。
- **保持**：设当前轮 `s = a[l] + a[r]`。
  - 若 `s < target`：反设 `i* == l`。由有序性，`a[j*] <= a[r]`（因 `j* <= r`），于是 `a[l] + a[j*] <= a[l] + a[r] = s < target`，与 `(l, j*)` 是解矛盾。所以 `i* != l`，把 `l` 加一后 `l+1 <= i*` 仍成立。
  - 若 `s > target`：反设 `j* == r`。由有序性，`a[i*] >= a[l]`（因 `i* >= l`），于是 `a[i*] + a[r] >= a[l] + a[r] = s > target`，矛盾。所以 `j* != r`，`r` 减一后 `j* <= r-1` 仍成立。
- **终止**：`l` 只增、`r` 只减，且每次至少移动一格，循环必然结束。当 `s == target` 时返回的正是解；若直到 `l >= r` 都没命中，则由不变量「解必须满足 `l <= i* < j* <= r`」与 `l >= r` 矛盾，说明初始假设「存在解」为假 —— 而题目保证有解，所以**这个分支在合法输入上不会发生**。∎

> **这个论证的价值**：它把「为什么 `s < target` 时只能移动左指针」从「感觉对」变成「排除了所有反例」。而且它顺带解释了 §002.6 的一个坑：`s < target` 时移动 `r` 是**错的**，因为 `a[r]` 明明是当前能配出的最大值，把最大值换小只会让和更小。

**论证二：交换论证（等价说法，更直观）**

任取一个解 `(i*, j*)`。算法在某个时刻第一次遇到 `l == i*` 或 `r == j*`：

- 若先遇到 `l == i*`，则此时 `r >= j*`，`a[l] + a[r] >= a[i*] + a[j*] = target`。若取等则直接返回；若严格大于，算法执行 `r--`，`r` 朝 `j*` 收拢，**不会被跳过**。
- 若先遇到 `r == j*`，则 `l <= i*`，`a[l] + a[r] <= target`。取等返回，严格小于则 `l++`，`l` 朝 `i*` 收拢。

两种情况都不会把 `i*`、`j*` 同时甩在区间外，所以「真正的解一定被检查到」。∎

### 002.3.3 通用解题思路（可迁移的那一层）

本题是 **「有序 → 单调性 → 双指针对撞排除」** 这个模型的母题：

```
问题：在有序序列里找一对满足 f(i,j) 关系的下标
        ↓ 关键观察：固定一端，f 关于另一端单调
单调性：a[l] + a[r] 随 l 增大而增大、随 r 减小而减小
        ↓ 于是「当前这对偏大/偏小」能直接判定「某一整排候选可以整批删掉」
每步排除：要么删掉 a[l] 所在的整排，要么删掉 a[r] 所在的整列
        ↓ 候选集从 O(n²) 缩到 O(n) 步
代价：0 额外空间
```

属于同一模型的题（**核心都是「每步证明一整排/一整列不可能」**）：

| 题 | 单调量 | 每步排除掉什么 |
| --- | --- | --- |
| [LC 167 两数之和 II](https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/) | `a[l]+a[r]` | 一整排（左端）或一整列（右端） |
| [LC 11 盛最多水的容器](https://leetcode.cn/problems/container-with-most-water/) | `min(h[l],h[r]) * (r-l)` | 短的那根柱子的全部剩余配对 |
| [LC 15 三数之和](https://leetcode.cn/problems/3sum/) | 固定 `i` 后退化成 167 | 外层固定值的全部剩余配对 |
| [LC 977 有序数组的平方](https://leetcode.cn/problems/squares-of-a-sorted-array/) | 平方值从两端向中间递减 | 两端中较大者必然进结果末尾 |
| [LC 125 验证回文串](https://leetcode.cn/problems/valid-palindrome/) | 字符相等 | 不等则整串不是回文 |

**共同点**：都有一个「随指针移动单调变化」的量，且能由「当前状态不满足」推出「某一侧的整批候选都不满足」。

### 002.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要输出**所有**数对（不止一个） | 不能提前 `return` | 命中后左右各走一步并**跳过重复值**（把 003 的去重逻辑搬进来）；`O(k)` 输出 |
| 数组**无序**但要求 O(1) 空间 | 有序前提消失 | 排序 O(n log n) + 双指针；若必须保原下标，回到 001 的哈希 |
| 值域放大到 `±10^9` | 加法可能溢出 | Java 用 `long s = (long) a[l] + a[r]`；Go 的 `int` 在 64 位平台已是 64 位，但跨平台代码写 `int64` 更稳 |
| 变成「差为 `target`」 | `a[r] - a[l]` | **仍然可以双指针同一方向**（快慢）：差小则 `r++`，差大则 `l++`，但边界与「同一元素」判据要重推 |
| **多次查询**（静态有序数组，m 个 target） | 一次 O(n) 不够 | 预处理成哈希 O(1)/次；或保持二分 O(log n)/次；**对撞双指针不适合重复查询**，因为它不缓存任何中间结论 |
| **数据流**输入 | 只有单向 | 双指针失效（右端点未知）→ 哈希在线维护（即 001） |

**进阶延伸（自己写代码验证）**：

- **LC 170 两数之和 III（会员）**：`add` / `find` 交替。体会「有序数组 + 二分」与「哈希」在动态场景的取舍。
- **LC 1099 小于 K 的两数之和**：把判定从 `==` 换成 `<`，双指针仍成立，且要利用单调性**数个数**（固定 `l`，合法的 `r` 是一个前缀）。
- **LC 653 两数之和 IV - BST**：中序遍历得有序序列，直接复用本章。

## 002.4 图解推演

### 002.4.1 一次完整执行轨迹

```
numbers = [2, 3, 4, 7, 11, 15]   target = 13
下标(0-based)  0  1  2  3   4   5

第 1 轮
┌────┬────┬────┬────┬────┬────┐
│  2 │  3 │  4 │  7 │ 11 │ 15 │
└────┴────┴────┴────┴────┴────┘
  ↑l                        ↑r     s = 2+15 = 17 > 13  →  a[5]=15 配谁都太大  →  r--

第 2 轮
┌────┬────┬────┬────┬────┬────┐
│  2 │  3 │  4 │  7 │ 11 │ 15 │
└────┴────┴────┴────┴────┴────┘
  ↑l                   ↑r         s = 2+11 = 13 == 13 →  返回 [1+1, 4+1] = [1, 5] ✓
```

再看一个需要「砍掉左边」的例子：

```
numbers = [1, 2, 5, 8, 10]   target = 13

第 1 轮  l=0 r=4  s=1+10=11 < 13   1 配 [0..4] 里最大的 10 都不够 → l++  (删掉 a[0] 整排)
第 2 轮  l=1 r=4  s=2+10=12 < 13   2 配 10 也不够               → l++
第 3 轮  l=2 r=4  s=5+10=15 > 13   10 配 [2..4] 里最小的 5 都超了 → r--  (删掉 a[4] 整列)
第 4 轮  l=2 r=3  s=5+ 8=13 == 13  返回 [3, 4] ✓
```

### 002.4.2 每一步到底删掉了多少候选（这张表是本章的核心）

`n = 5` 时共有 `5·4/2 = 10` 个候选配对，按 `(i, j)` 排成三角：

| 步 | l | r | s | 判定 | 本步删掉的候选 | 剩余候选数 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 4 | 11 | `< 13` | `(0,1) (0,2) (0,3) (0,4)` 共 4 个 | 6 |
| 2 | 1 | 4 | 12 | `< 13` | `(1,2) (1,3) (1,4)` 共 3 个 | 3 |
| 3 | 2 | 4 | 15 | `> 13` | `(2,4) (3,4)` 共 2 个 | 1 |
| 4 | 2 | 3 | 13 | `== 13` | — | 命中 `(2,3)` |

```
候选三角（✓ = 被删, ★ = 答案）
        j=1  j=2  j=3  j=4
 i=0 │   ✓    ✓    ✓    ✓     ← 第 1 步 l=0 全排删
 i=1 │        ✓    ✓    ✓     ← 第 2 步 l=1 全排删
 i=2 │             ★    ✓     ← 第 3 步 r=4 删 (2,4)(3,4) 中的 (2,4)
 i=3 │                  ✓     ← 第 3 步同时删掉 (3,4)
```

> **看到这张图，你就懂了为什么是 O(n) 而不是 O(n²)**：每一步不是「前进一格」，而是「**划掉一整行**」。`l` 和 `r` 各自最多走 `n` 步，合起来 `2n` 步，每步删掉一整排。

### 002.4.3 两条路线对比图


## 002.5 双语言实现

### 002.5.1 Java

```java
class Solution {
    public int[] twoSum(int[] numbers, int target) {
        // 循环不变量：若解存在且为 (i*, j*)，则始终有 l <= i* < j* <= r
        // 依据：每轮要么证明 a[l] 配谁都太小（l++），要么证明 a[r] 配谁都太大（r--）
        int l = 0, r = numbers.length - 1;

        // 必须是 l < r 而不是 l <= r：题目要求两个「不同」的元素，
        // l == r 时 numbers[l] + numbers[r] 用的是同一个元素，非法
        while (l < r) {
            // 本题值域只有 ±1000，int 不会溢出；换成 ±10^9 的题面就必须写 (long)
            int s = numbers[l] + numbers[r];

            if (s == target) {
                // 题目下标从 1 开始计数，所以两个下标都要 +1（这是本题最常丢的分）
                return new int[]{l + 1, r + 1};
            }
            if (s < target) {
                // 和偏小：把右端换小只会更小，所以只能让左端变大
                l++;
            } else {
                // 和偏大：把左端换大只会更大，所以只能让右端变小
                r--;
            }
        }

        // 题目保证有解，走到这里说明输入违反约定；返回 -1 让调用方明确看到「异常」，
        // 比返回 new int[0] 更容易在调试时被发现
        return new int[]{-1, -1};
    }
}
```

### 002.5.2 Go

```go
package main

// twoSum 返回 1-based 下标。变量名与 Java 版逐行对齐，方便对照阅读。
func twoSum(numbers []int, target int) []int {
	// 不变量：若解存在且为 (i*, j*)，则始终有 l <= i* < j* <= r
	l, r := 0, len(numbers)-1

	// l < r 而非 l <= r：两个下标必须指向不同元素
	for l < r {
		// Go 的 int 在 64 位平台是 64 位，本题不会溢出；
		// 但若移植到 32 位平台或值域放大，这里应显式用 int64
		s := numbers[l] + numbers[r]

		switch {
		case s == target:
			// 切片下标本就 0-based，返回值要求 1-based
			return []int{l + 1, r + 1}
		case s < target:
			l++ // 和偏小 → 左端必须变大
		default:
			r-- // 和偏大 → 右端必须变小
		}
	}

	// 题目保证有解；返回 nil 语义上表示「没有得到有效答案」
	return nil
}
```

### 002.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 数组长度 | `numbers.length`（字段） | `len(numbers)`（内建函数） | Go 的 `len` 对 nil 切片返回 0，不会 panic；Java 对 null 会抛 NPE |
| 返回值构造 | `new int[]{a, b}` | `[]int{a, b}` | Go 直接字面量；Java 必须 `new` 且指定类型 |
| 分支写法 | `if / else if / else` | `switch { case ... }`（无表达式 switch） | Go 的 `switch` 天然不穿透（不需要 `break`），三个分支比 `else if` 链更平 |
| 整数宽度 | `int` **恒为 32 位** | `int` 随平台（64 位平台是 64 位） | 同一份代码在 Go 上「碰巧」不溢出、在 Java 上溢出 —— 这类 bug 跨语言移植时最阴 |
| 数组越界 | 抛 `ArrayIndexOutOfBoundsException` | 抛 `panic: runtime error: index out of range` | 两者都是运行时崩溃，不会静默返回错值；所以 `l < r` 的边界写错会立刻暴露 |
| 空返回值 | `new int[]{-1, -1}` 或 `new int[0]` | `nil` | LeetCode 两种都接受；对拍时注意 `len(nil) == 0` |

### 002.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"sort"
	"testing"
)

// bruteCount 返回解的个数（0/1/2...）。
// 为什么要返回「个数」而不是「第一个解」：随机数据经常造出多组解，
// 而双指针返回的是「某一组」合法解，直接和暴力的第一组比较会误报失败。
func bruteCount(a []int, target int) int {
	cnt := 0
	for i := 0; i < len(a); i++ {
		for j := i + 1; j < len(a); j++ {
			if a[i]+a[j] == target {
				cnt++
			}
		}
	}
	return cnt
}

// isValid 校验返回值是不是一组合法解（1-based 下标）
func isValid(a []int, target int, got []int) bool {
	if len(got) != 2 {
		return false
	}
	i, j := got[0]-1, got[1]-1 // 转回 0-based
	if i < 0 || j < 0 || i >= len(a) || j >= len(a) {
		return false
	}
	if i >= j { // 必须严格递增且不同元素
		return false
	}
	return a[i]+a[j] == target
}

func TestTwoSumSortedRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20240216)) // 固定种子，失败可复现
	for iter := 0; iter < 20000; iter++ {
		n := 2 + r.Intn(20)
		a := make([]int, n)
		for i := range a {
			a[i] = r.Intn(21) - 10 // 值域 [-10,10]：重复值密集，专逼 l<r 与去重 bug
		}
		sort.Ints(a) // 题目保证有序，这里必须真的排序

		// 造一个「保证至少一解」的 target
		i := r.Intn(n)
		j := r.Intn(n - 1)
		if j >= i {
			j++
		}
		target := a[i] + a[j]

		got := twoSum(a, target)
		if !isValid(a, target, got) {
			t.Fatalf("iter=%d a=%v target=%d got=%v 不是合法解", iter, a, target, got)
		}
		// 解唯一时，要求它就是我们造出来的那一组（允许同值不同下标，所以只比「值对」）
		if bruteCount(a, target) == 1 && a[got[0]-1]+a[got[1]-1] != target {
			t.Fatalf("iter=%d 唯一解却返回错值", iter)
		}
	}
}
```

> **为什么值域设成 `[-10, 10]` 而 `n` 只有 20**：这样「重复值 + 多解」几乎每轮都出现，`l < r` 写成 `l <= r`、或者照抄 003 的去重逻辑，都会在几百轮内被抓出来。**测试的价值在于频繁制造边界，不在于覆盖正常情况。**

## 002.6 复杂度与常见坑

### 002.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：`l` 从 `0` 单调增到至多 `n-1`，`r` 从 `n-1` 单调减到至少 `0`，每轮至少移动其中一个指针，所以**总轮数 ≤ 2n**。每轮做一次加法、至多两次比较，常数 O(1)。故 `T(n) = O(n)`。
  - **注意这个分析的关键**：不是「一次循环走一格所以 n 步」，而是「**两个指针的移动总量有上界**」。这个视角能直接迁移到 005 盛水容器、003 三数之和的内层循环（内层总移动量 ≤ n）。
- **空间 O(1)**：只用了 `l`、`r`、`s` 三个标量，不随 `n` 增长。
- **对比哈希版**：哈希版时间 O(n) 但需要 O(n) 个 entry；Java 的 `HashMap<Integer,Integer>` 每个 entry 约 48 字节，`n = 3·10⁴` 时约 1.4 MB —— 在 LeetCode 上无所谓，但在「嵌入式 / 内存受限流处理」的真实场景里，这就是双指针胜出的全部理由。

### 002.6.2 七个真实踩过的坑

1. **忘掉下标 +1** —— 题目要 1-based，你返回 0-based。**这是本题最高频的 WA**，且样例 `[2,7,11,15] → [1,2]` 一眼能看出来，很多人却只盯着「和算对了没」。
2. **`while (l <= r)`** —— `l == r` 时用的是同一个元素，`[2,3,4], target=6` 会返回 `[2,2]`。必须是 `l < r`。
3. **在 167 里做去重** —— 从 003 带过来的「`a[l] == a[l-1]` 就跳过」会把 `[1,2,3,4,4,9], target=8` 的合法解 `4+4` 跳过。**去重是「求所有解」的需求，本题只要一组。**
4. **`s < target` 时移动了 `r`** —— 方向搞反。记住一句话：**和偏小 → 让小的变大（`l++`）；和偏大 → 让大的变小（`r--`）。**
5. **假设数组非负** —— 有人把 `r` 初始化成「最后一个 `<= target` 的位置」，用二分或线性扫确定。`[-5,-3,-1,2,4], target=-1` 上直接错。
6. **加法溢出** —— 本题值域 ±1000 安全，但同一份代码被改成 LC 1 的 `±10^9` 后，`int s = a[l] + a[r]` 会溢出成负数，导致「和偏大」被误判成「和偏小」，指针朝错误方向走，最后返回错解而不是崩溃 —— **这是最危险的一类 bug：静默错误。**
7. **认为「必须先用两遍循环找边界」** —— 有些人为了「安全」先线性扫描跳过开头的负数和结尾的大数，白白多写 10 行。双指针从两端出发，自然会在过程中把该排除的排除掉。

### 002.6.3 面试官最爱追问的三个问题

**Q1：为什么 `s < target` 时只能移动左指针，不能移动右指针？**
> 「因为 `a[r]` 已经是当前候选区间里**最大**的元素，`a[l]` 配它都不够，配区间里其他任何元素只会更小 —— 所以 `a[l]` 这一整排候选全部不可能。移动右指针等于把当前最大值换得更小，和只会更小，方向是反的。」

**Q2：如果数组无序，你还能用双指针吗？代价是什么？**
> 「不能直接用，因为排除法依赖「右端是区间最大」这条性质。要么先排序 O(n log n) 再双指针（代价是丢失原下标，本题不要求原下标所以可行），要么退回哈希 O(n)/O(n)。所以本题给「输入有序」这个条件，本质上是**把 O(n) 空间买成了 0 空间 + 省掉排序**。」

**Q3：如果要求输出所有数对，复杂度怎么变？**
> 「输出本身可能是 O(n²) 个（例如全 0 数组、target=0），所以时间下界就是 O(答案个数)，不能低于 O(k)。做法是命中后 `l++` 且 `r--`，并且**跳过所有相同值**避免重复输出；总时间 O(n + k)，空间 O(1)（不算结果数组）。这里的难点从「找」变成了「去重」，也就是 003 要解决的问题。」
