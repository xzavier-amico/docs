## 023.1 题目

**原题链接**：<https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/>

### 题意重述（把隐含条件补齐）

一个长度为 `n` 的数组，原本按**严格升序**排列，随后在某个未知下标处旋转了 `1 ~ n` 次（也就是把末尾若干元素整体搬到开头）。请返回数组中的**最小元素**。

五条必须读出来的隐含条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 值**互不相同** | 「数组中的元素值互不相同」 | 这条让 `nums[mid] > nums[hi]` 只有真/假两态，判定精确。有重复时出现第三种「相等」，判定失效 → LC 154，最坏 O(n) |
| 旋转次数 `1 ≤ k ≤ n` | 「旋转 1 到 n 次」 | `k = n` 时数组**恢复原样**（完全升序），最小值在下标 0。这是最容易漏的一类 |
| 数组**非空** | 「`n == nums.length`，`1 <= n <= 5000`」 | 不用处理空数组，但 `n == 1` 要返回 `nums[0]` |
| 返回**值**不是下标 | 「请你找出并返回数组中的**最小元素**」 | 返回 `lo` 是 022 的习惯，本题会判错 |
| 要求 **O(log n)** | 「你必须设计并实现时间复杂度为 O(log n) 的算法」 | 线性扫一遍是 O(n)，明文禁止 |

> **注意「旋转 1 到 n 次」和 022 的「旋转 0 到 n-1 次」是同一件事的两种说法**：旋转 `n` 次 = 旋转 0 次 = 数组没变。所以本章必须处理「数组本来就是升序」这个退化情形 —— 而它恰恰是「与左端点比较」这套写法翻车的地方，见 023.2 第三步。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 5000` | n 很小 | 线性扫描 5000 次，实测 Java ≈ 0.01 ms —— **能过**。所以这题和 022 一样：**考的是复杂度，不是通过率** |
| `-5000 <= nums[i] <= 5000` | 值域小 | 无溢出风险。但**比较运算永不溢出**，所以本模板天然可以搬到 `long` / `double` 值域 |
| 值互不相同 | 严格单调 | `nums[mid] > nums[hi]` 与 `nums[mid] < nums[hi]` 穷尽了所有情况，不需要第三分支 |
| 数组「升序 + 旋转」 | 一个断点 | 最小值就是断点处的元素，**找最小值 = 找断点位置** |
| 要求 O(log n) | 硬性 | `n = 5000` → 13 轮。每轮只做 **1 次比较**，比 022 的 4 次更省 |

> 💡 **量级 → 算法**：这题的 `log₂ 5000 ≈ 12.3`，所以「13 轮」。如果你写出 20 轮以上的二分，说明每轮没砍掉一半，回去检查 `mid` 的取整方向。
> **二分的轮数是硬指标**：`n = 5000` 就是 13 轮，多一轮都说明有问题。

### 示例

```
输入：nums = [3,4,5,1,2]
输出：1
解释：原数组为 [1,2,3,4,5]，旋转 3 次得到 [3,4,5,1,2]，最小值为 1

输入：nums = [4,5,6,7,0,1,2]
输出：0

输入：nums = [11,13,15,17]
输出：11          ← 旋转 4 次 = 没旋转，最小值在下标 0

输入：nums = [2,1]
输出：1          ← 旋转 1 次，长度 2，最小值在下标 1
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① nums = [1]              → n == 1，while 一次都不进，直接返回 nums[0]
② nums = [2,1]            → 旋转 1 次、长度 2：mid == lo，右半只有 1 个元素
③ nums = [1,2]            → 旋转 2 次 = 没旋转：最小值在下标 0，检验"与左端比"的写法
④ nums = [1,2,3,4,5]      → 完全升序（旋转 n 次）：同上，最容易翻车
⑤ nums = [3,4,5,6,7,1,2]  → 最小值恰在 mid 右侧一格，检验 lo = mid+1 会不会跳过它
⑥ nums = [5,1,2,3,4]      → 最小值在下标 1，mid 一开始落在 2（值 2）上
```

④ 是本章的第一号杀手。用 `nums[mid] > nums[lo]` 判「最小值在右边」的写法，在 `[1,2,3,4,5]` 上：`lo=0, hi=4, mid=2`，`nums[2]=3 > nums[0]=1` → 判「最小值在右边」→ `lo=3`；再 `mid=3`，`4 > 1` → `lo=4`；返回 `nums[4] = 5`。**答案应该是 1，它返回了最大值。** 这个 bug 在 `[3,4,5,1,2]` 上不会暴露 —— 因为它确实旋转过，`nums[lo]` 不是最小值。**这就是「边界用例」的价值。**

## 023.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（线性找最小）

```java
int min = nums[0];
for (int i = 1; i < n; i++) min = Math.min(min, nums[i]);
return min;
```

- 时间 **O(n)**，空间 **O(1)**，绝对正确。
- `n = 5000` 时 **5000 次比较**，Java ≈ 0.01 ms，Go ≈ 0.015 ms —— 全员通过。
- 题目要求 `O(log n)`。**又一次「能过 ≠ 对」。**

### 第二步：第一个念头 —— 「最小值在断点处，那我去找断点」

这个念头本身**完全正确**：最小值就是断点（`nums[p-1] > nums[p]` 的那个 `p`，或 `p = 0` 表示没旋转）。问题在于：

- 「找断点」如果用**线性扫描**（找第一个满足 `nums[i] > nums[i+1]` 的 `i`），是 **O(n)**，违规。
- 「找断点」如果用**二分**，那问题就变成：**二分需要一个「`mid` 在断点左边还是右边」的判据**。

**卡点就在这个判据上。** 022 有 `target` 可以比，本题没有。你得自己造一个。

### 第三步：两个看起来都对的判据，一个会翻车

这是本章最值得看的一段。两个候选判据：

| 判据 | 含义 | 在 `[3,4,5,1,2]` 上 | 在 `[1,2,3,4,5]`（未旋转）上 | 判决 |
| --- | --- | --- | --- | --- |
| A：`nums[mid] > nums[lo]` | 「比左端大 ⇒ 我在左段 ⇒ 最小值在右边」 | `nums[2]=5 > 3` ✔ 判对 | `nums[2]=3 > 1` ✔ 判「在右边」，**但最小值其实在左边**（下标 0） | ❌ **翻车** |
| B：`nums[mid] > nums[hi]` | 「比右端大 ⇒ 我在左段 ⇒ 最小值在右边」 | `nums[2]=5 > 2` ✔ 判对 | `nums[2]=3 > 5`？否 ⇒ 判「最小值在左边或就是 mid」 ✔ 判对 | ✅ **永远对** |

**为什么 A 会翻车**：`nums[lo]` 是**当前区间**的左端，而「左段」是从下标 0 开始的那一段。当 `lo > 0` 时，`nums[lo]` 可能已经在右段里了，此时「比左端大」只说明「`mid` 在 `lo` 右边且值更大」，**说明不了它在哪一段**。更致命的是未旋转的情形：整个数组就是一个升序段，`nums[mid] > nums[lo]` 恒成立（除 `mid == lo`），你会一路向右跑到数组末尾。

**为什么 B 永远对**：`nums[hi]` 是**当前区间**的右端，而右段一定延伸到 `n-1`（因为旋转把「小的那些」放在末尾）。所以只要 `hi` 还在右段里（`hi ≥ p`），`nums[hi]` 就是右段的一个元素，而右段的所有元素都小于左段的所有元素。**于是「`nums[mid] > nums[hi]`」精确等价于「`mid` 在左段、`hi` 在右段」** —— 这就是判据 B 的全部秘密。

> ⚠️ **但这要求 `hi` 一直在右段里**。如果某次更新让 `hi` 落到了左段（`hi < p`），判据 B 也会失效。本章的更新方式（`hi = mid`，且只在「`mid` 不在左段」时才动 `hi`）恰好保证了 `hi ≥ p` 恒成立 —— 这就是 023.3.2 里不变量要证的东西。

### 第四步：灵感 —— 把「找最小值」变成「问一个 0/1 问题」

不看数组，只看**位置** `i`，定义：

```
check(i) = (nums[i] > nums[hi])     // i 在左段吗？
```

它的真值形状（以 `[3,4,5,1,2]`，`hi = 4` 为例）：

```
下标 i :   0    1    2    3    4
nums   :   3    4    5    1    2
nums[hi]:  2    2    2    2    2
check  :   T    T    T    F    F
           └── 左段（大值）──┘└ 右段（小值）┘
                             ↑
                       第一个 F 的位置 = 4？
```

**注意！第一个 `F` 的位置是 3，不是 4。** 我们想要的答案是「最小值的位置 = 3」，也就是 **`check(i)` 第一次为假的位置**。

于是：

```
二分的语义：找最小的 i，使 check(i) == false
           = 找最小的 i，使 nums[i] <= nums[hi]
```

这正是 020 的**模板 B / 模板 C**：`check` 为真就往右推（`lo = mid+1`），为假就往回收（`hi = mid`）。**023 是「二分答案」的第一个实例** —— 它二分的对象不是「值」，而是「位置」，`check` 是一个「这个位置是不是还在大值区」的 0/1 判定。

> 💡 **这里必须澄清一个常见误解**：很多人说「023 是二分查找」。**不完全对。** 它是**二分答案**：答案（最小值的位置）本身是一个整数，`check(i)` 告诉我们「`i` 太大了还是太小了」。二分查找是「在数组里找一个给定的值」，二分答案是「在一个单调的判定上找跳变点」。**正因为 023 是二分答案，它才不需要 `target`。**

## 023.3 原理拆解

### 023.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 线性扫最小值 | O(n) | O(1) | 4 行 | **明文要求 O(log n)** |
| 线性找断点（`nums[i] > nums[i+1]`） | O(n) | O(1) | 6 行 | 同上 |
| 二分 + **与左端点比**（判据 A） | 声称 O(log n) | O(1) | 8 行 | **未旋转时答案错**（返回最大值）。不是复杂度问题，是正确性问题 |
| 二分 + **与右端点比**（判据 B） ✅ | **O(log n)** | **O(1)** | **8 行** | 有重复元素时判定失效（→ LC 154，最坏 O(n)） |
| 二分 + 与「区间中点值」三分 | O(log n) | O(1) | 12 行 | 用三分找极小值也能做，但比较次数更多，且需要凸性论证 —— **杀鸡用牛刀** |
| 先 022 找到任意元素，再从它往左推到最小 | O(log n) + O(k) | O(1) | 15 行 | `k` 是「从任意点到最小值」的距离，最坏 O(n) |

**为什么「与右端点比」是唯一正解**：它只依赖**一个**事实 —— 「右段一直延伸到数组末尾，且右段的每个值都小于左段的每个值」。这个事实不依赖「是否旋转过」，所以未旋转时也成立（此时右段就是整个数组，判据永远为假，一路 `hi = mid` 收敛到 0）。**判据 A 依赖「`nums[lo]` 一定是全局最小」，而这只在旋转过时成立** —— 这就是两者唯一的、也是致命的差别。

### 023.3.2 为什么这个做法是对的（正确性论证）

#### (a) 记号与两个基本事实

设数组长为 `n`，最小值位置为 `p`（`0 ≤ p ≤ n-1`，`nums[p]` 是全局最小）。若 `p > 0`，则 `nums[p-1] > nums[p]`，`p` 称为**断点**。

**事实 1（两段结构）**：`nums[0..p-1]` 升序（称为**左段 / 大值段**），`nums[p..n-1]` 升序（称为**右段 / 小值段**）。若 `p = 0` 则左段为空。

> 这是因为旋转等价于把升序数组 `A` 切成 `A[k..n-1] + A[0..k-1]`，左段 = `A[k..n-1]`，右段 = `A[0..k-1]`，`p = n-k`。

**事实 2（跨段严格大）**：左段的**每个**元素都大于右段的**每个**元素。

证明：左段最小值是 `nums[p-1] = A[n-1]`，右段最大值是 `nums[n-1] = A[k-1]`。由 `A` 严格升序且 `k ≤ n-1`（`p ≥ 1`），有 `A[k-1] < A[k] ≤ A[n-1]`，故 `A[k-1] < A[n-1]`；再逐元素比较即得。∎

> **事实 2 是整章的支点。** 没有它，`nums[mid] > nums[hi]` 只是一个大小比较；有了它，这个比较就变成了「`mid` 在哪一段」的**精确探测器**。

#### (b) 核心引理：判据的精确性

**引理**：设 `0 ≤ mid < hi ≤ n-1`。则

```
nums[mid] > nums[hi]   ⟺   p ∈ (mid, hi]
```

**证明**：

**(⇒)** 设 `nums[mid] > nums[hi]`。

- 若 `p ≤ mid`：`mid` 与 `hi` 都在右段 `[p, n-1]` 内，右段升序且 `mid < hi`，故 `nums[mid] < nums[hi]`，矛盾。所以 **`p > mid`**。
- 若 `p > hi`：`mid` 与 `hi` 都在左段 `[0, p-1]` 内，左段升序且 `mid < hi`，故 `nums[mid] < nums[hi]`，矛盾。所以 **`p ≤ hi`**。

合并得 `p ∈ (mid, hi]`。✔

**(⇐)** 设 `p ∈ (mid, hi]`。则 `mid ≤ p-1`，即 `mid` 在左段；`hi ≥ p`，即 `hi` 在右段。由事实 2，左段元素 > 右段元素，故 `nums[mid] > nums[hi]`。✔

> **注意引理要求 `mid < hi`**。在模板 B（`while lo < hi`）里，`mid = lo + ⌊(hi-lo)/2⌋ < hi` 恒成立，所以条件天然满足。**这就是为什么本模板只能用 `lo < hi` 而不能用 `lo <= hi`** —— 后者在 `lo == hi` 时 `mid == hi`，`nums[mid] > nums[hi]` 恒为假，引理的前提被破坏。

#### (c) 主命题：不变量 + 分支

**不变量 I（最小值位置不丢）**：每轮循环开始时，`p ∈ [lo, hi]`。

**初始**：`[0, n-1]` 含 `p`。✔

**保持**：本轮 `mid` 满足 `lo ≤ mid < hi`，由引理：

- 若 `nums[mid] > nums[hi]`：`p ∈ (mid, hi]`，即 `p > mid`。代码令 `lo = mid+1`，新区间 `[mid+1, hi]` ⊇ `p`。✔
- 否则（`nums[mid] < nums[hi]`，由值互不相同排除等于）：`p ∉ (mid, hi]`，又 `p ∈ [lo, hi]`，故 `p ∈ [lo, mid]`。代码令 `hi = mid`，新区间 `[lo, mid]` ⊇ `p`。✔

**终止**：`lo == hi` 时区间退化为单点 `{lo}`，由不变量 `p = lo`，返回 `nums[lo]` 即全局最小值。∎

#### (d) 为什么不会死循环

这是本章**最需要小心**的地方，因为本模板用了 `hi = mid`（不 ±1）。逐条检查：

1. **`lo < hi` 时 `mid < hi` 恒成立**：`mid = lo + ⌊(hi-lo)/2⌋`，而 `hi - lo ≥ 1` 时 `⌊(hi-lo)/2⌋ ≤ hi-lo-1`（因为 `x-1 < 2⌊x/2⌋` 对 `x ≥ 1` 不总成立... 直接验算：`hi-lo = 1` → `⌊1/2⌋ = 0` → `mid = lo = hi-1 < hi` ✔；`hi-lo = 2` → `⌊2/2⌋ = 1` → `mid = lo+1 = hi-1 < hi` ✔；`hi-lo = 3` → `⌊3/2⌋ = 1` → `mid = lo+1 < hi` ✔；一般地 `mid = lo + ⌊(hi-lo)/2⌋ ≤ lo + (hi-lo)/2 < hi` 当 `hi > lo`）。✔
2. **分支 1（`lo = mid+1`）**：因为 `mid < hi`，有 `mid+1 ≤ hi`，所以新 `lo ≤ hi`，**区间非空且长度至少减半**。✔
3. **分支 2（`hi = mid`）**：因为 `mid < hi`，新 `hi` **严格小于**旧 `hi`，**长度至少减 1**。✔
4. 两个分支都让长度 `hi - lo` **严格递减**；长度是自然数 ⇒ 有限步退出。✔

**如果写错成 `lo = mid`**，第 1 条就救不了你：`hi = lo+1` 时 `mid = lo`，`lo = mid` 让 `lo` 原地不动，长度恒为 1，**死循环**。这是本模板唯一的死循环陷阱。

**为什么 `hi = mid` 是安全的、`hi = mid - 1` 是危险的**：`mid` 可能是 `p` 本身（当 `nums[mid] < nums[hi]` 且 `p == mid` 时）。`hi = mid` 保留了它，`hi = mid - 1` 会把它扔掉 —— 于是 `[1,2]` 这种输入返回 `nums[0] = 1`（碰巧对）但 `[2,1]` 返回 `nums[0] = 2`（错）。**「`mid` 有没有被排除」这条规矩，本章的答案是「没有」，所以不 ±1。**

### 023.3.3 通用解题思路（可迁移的那一层）

本章提炼出二分的**第四条方法论**：**「选对锚点」**。

```
问题：需要一个判据，告诉我 mid 在「分界」的哪一侧
   ↓ 分界是断点 p，但 p 未知
问：数组里哪一个位置的元素，能代表"某一侧"？
   ↓ 左端点 nums[lo]：只在"左段一定非空"时才有代表性 → 未旋转时失效
   ↓ 右端点 nums[hi]：右段一定延伸到末尾，一定"在右段里" → 永远有代表性 ✅
结论：用"不会失效的那一端"做锚点
```

**「锚点选择」的四条经验法则**：

| 情形 | 选谁当锚点 | 理由 |
| --- | --- | --- |
| 找旋转数组的**最小值**（本题） | **右端点 `nums[hi]`** | 右段一定包含末尾，右端点一定在右段 |
| 找旋转数组的**最大值** | 左端点 `nums[lo]` | 对称：左段一定包含开头，左端点一定在左段 |
| 山脉数组找**峰顶**（LC 852） | `nums[mid+1]`（右邻居） | 峰顶两侧的坡度符号相反，比较相邻两点就能定方向 |
| 找「第一个 ≥ x」 | 不需要锚点，直接和 `x` 比 | 有外部参照物 |
| 二分答案（025 / 026） | 不需要锚点，`check(mid)` 就是判据 | 判定函数自带方向 |

> **这张表是本章最值钱的东西**。面试时如果被问「你为什么和右端点比，不和左端点比」，答案就是「因为右端点一定在右段内，左端点不一定在左段内」。

**本章与前三章的层级**（本批统一术语）：

```
020：有外部 target    → 直接比较
021：target 多对一    → 谓词化成 >= / >
022：分段单调         → 定位有序半 + 值域判定
023：没有 target      → 选一个"一定有代表性"的锚点，把位置本身当判定对象  ← 二分答案的雏形
025：连数组都没有     → 在答案空间上二分，check(x) 由问题定义
```

**属于同一模型的题**：

| 题 | 锚点 / 判据 | 「分界」是什么 |
| --- | --- | --- |
| [LC 153](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/) | `nums[mid] > nums[hi]` | 断点（最小值位置） |
| [LC 154](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array-ii/) | 同上 + 相等时 `hi--` | 同上（有重复） |
| [LC 852 山脉数组的峰顶索引](https://leetcode.cn/problems/peak-index-in-a-mountain-array/) | `nums[mid] < nums[mid+1]` | 峰顶 |
| [LC 162 寻找峰值](https://leetcode.cn/problems/find-peak-element/) | 同上 | 任一局部极大 |
| [LC 278 第一个错误的版本](https://leetcode.cn/problems/first-bad-version/) | `isBadVersion(mid)` | 版本由好变坏的位置 |
| [LC 875 珂珂吃香蕉](https://leetcode.cn/problems/koko-eating-bananas/) | `canFinish(mid)` | 能吃 / 不能吃的分界速度 |

### 023.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 数组**有重复元素**（LC 154） | 出现 `nums[mid] == nums[hi]` | 无法判断 `p` 在 `mid` 左边还是右边（左边可能，`mid` 本身也可能）。只能 `hi--` 收缩一格，**最坏 O(n)**，全相同数组必然触发 |
| 要返回**最大值** | 完全对称 | 锚点换成左端点 `nums[lo]`，判据 `nums[mid] < nums[lo]` 表示「mid 在右段」→ 最大值在左边 |
| 要返回**下标**而不是值 | 只需改返回 | `return lo`。但面试时要说清「返回下标」这个契约变了 |
| 数组**旋转了多次**（不是标准旋转） | 可能有多个断点 | 二分失效，只能 O(n) 扫描。可以先把数组 `sort`（O(n log n)）再取首元素 —— 反而更慢 |
| 求**第 k 小** | 需要完整排序信息 | 二分 + 计数（值域二分），或用快速选择；单纯二分最小值不够 |
| 数据是**流式**的（不断加入新元素） | 结构会变 | 二分失效（每次插入都可能改变 `p`）；用平衡 BST 维护最小值或用小顶堆 |

**进阶延伸（自己写代码验证）**：

- **LC 154 寻找旋转排序数组中的最小值 II**：在 `nums[mid] == nums[hi]` 时只能 `hi--`。自己构造 `[1,1,1,1,1,1,1,1,2,1]` 验证它退化到 O(n)，并想清楚「为什么无法避免」。
- **LC 852 / 162 峰值**：把「断点」换成「极值点」，判据从「与端点比」换成「与右邻居比」，代码结构完全相同。**写一遍就能感到「模板不改、判据换掉」的复用感。**
- **LC 33 / 022 的对照**：022 找 target 用的是「判有序半」，023 找最小值用的是「与右端点比」。**同一个数组结构，两个不同的问题，两种不同的判据。** 对照读能看清「判据是为问题服务的，不是为数组服务的」。

### 023.4.2 判据的真值形状


### 023.4.3 完整收缩轨迹

```
nums = [4, 5, 6, 7, 0, 1, 2]      n = 7, 最小值 0 在下标 4
        0  1  2  3  4  5  6

第 1 轮
  lo=0                      hi=6
   │                         │
   ▼                         ▼
  [4] [5] [6] [7] [0] [1] [2]
            ↑
          mid=3   nums[3]=7    nums[hi]=nums[6]=2

  nums[3]=7 > nums[6]=2  ⇒  mid 在左段（大值区）⇒ 最小值在 mid 右边
  ⇒ lo = mid+1 = 4                区间 [4,6]

第 2 轮
                  lo=4   hi=6
                   │      │
                   ▼      ▼
  [4] [5] [6] [7] [0] [1] [2]
                    ↑
                   mid=5   nums[5]=1    nums[6]=2

  nums[5]=1 > nums[6]=2 ? 否  ⇒  mid 不在左段 ⇒ 最小值 ≤ mid
  ⇒ hi = mid = 5                  区间 [4,5]

第 3 轮
                  lo=4 hi=5
                   │   │
                   ▼   ▼
  [4] [5] [6] [7] [0] [1] [2]
                   ↑
                  mid=4   nums[4]=0    nums[5]=1

  nums[4]=0 > nums[5]=1 ? 否  ⇒  hi = mid = 4        区间 [4,4]

  lo == hi == 4  ⇒  退出，返回 nums[4] = 0 ✅

  ┌────────────────────────────────────────────┐
  │ 区间长度轨迹： 7 → 3 → 2 → 1 → 0            │
  │ 每一轮严格递减 ⇒ 最多 ⌈log2 7⌉ = 3 轮      │
  └────────────────────────────────────────────┘
```

### 023.4.4 「与左端比」为什么在未旋转数组上翻车

```
✅ 正确判据：nums[mid] > nums[hi]
   nums = [1, 2, 3, 4, 5]（旋转 5 次 = 未旋转），hi = 4，nums[4] = 5

   lo=0  hi=4  mid=2  nums[2]=3 > 5 ?  否  →  hi = 2     区间 [0,2]
   lo=0  hi=2  mid=1  nums[1]=2 > 5 ?  否  →  hi = 1     区间 [0,1]
   lo=0  hi=1  mid=0  nums[0]=1 > 5 ?  否  →  hi = 0     区间 [0,0]
   lo == hi == 0  →  返回 nums[0] = 1 ✅

❌ 错误判据：nums[mid] > nums[lo]
   同一数组，lo 一直是 0，nums[0] = 1

   lo=0  hi=4  mid=2  nums[2]=3 > 1 ?  是  →  lo = 3     区间 [3,4]
   lo=3  hi=4  mid=3  nums[3]=4 > 1 ?  是  →  lo = 4     区间 [4,4]
   lo == hi == 4  →  返回 nums[4] = 5 ❌ 返回了最大值！

   根因：nums[lo] 只在"左段非空"时才是大值段的代表；
        未旋转时左段为空，nums[lo] 就是全局最小，判据恒真 → 一路向右。
```

### 023.4.5 逐轮状态总表

| 轮次 | `lo` | `hi` | `mid` | `nums[mid]` | `nums[hi]` | `nums[mid] > nums[hi]`? | 动作 | 新区间 | `p` 在哪 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 7 | 2 | 是 | `lo = 4` | `[4,6]` | `(3,6]` |
| 2 | 4 | 6 | 5 | 1 | 2 | 否 | `hi = 5` | `[4,5]` | `[4,5]` |
| 3 | 4 | 5 | 4 | 0 | 1 | 否 | `hi = 4` | `[4,4]` | `[4,4]` |
| 退出 | 4 | 4 | — | — | — | — | — | — | `p = 4` ✅ |

### 023.4.6 为什么这里不能写 `lo = mid`

```
                        hi = lo + 1（区间只剩 2 个元素）
                                  │
                    ┌─────────────┴─────────────┐
                    │                           │
              mid = lo + ⌊1/2⌋ = lo        （下取整）
                    │
        ┌───────────┴────────────┐
        │                        │
   lo = mid + 1              hi = mid
   = lo + 1                  = lo
   （向右跨 1 格）✅          （向左收 1 格）✅
   长度 1 → 0                长度 1 → 0

   ────────────────────────────────────────────
   如果写成 lo = mid：
   lo = mid = lo        ← 原地不动！
   长度恒为 1，下一轮还是 lo=lo, hi=lo+1
   ┌──────────────────────────────────────┐
   │ 死循环。这就是"mid 下取整 ⇒ 禁写 lo=mid" │
   └──────────────────────────────────────┘
```

## 023.5 双语言实现

### 023.5.1 Java

```java
class Solution {
    public int findMin(int[] nums) {
        int lo = 0, hi = nums.length - 1;   // 闭区间，答案（最小值位置）在 [lo, hi] 内

        // 用 lo < hi 而不是 lo <= hi：因为 hi = mid 不排除 mid，
        // 若允许 lo == hi 进循环，mid == hi，nums[mid] > nums[hi] 恒假 → hi = mid 原地不动 → 死循环
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;   // 下取整，保证 mid < hi（这是"不会死循环"的前提）

            if (nums[mid] > nums[hi]) {
                // mid 在左段（大值区）⇒ 最小值位置 p > mid
                // 所以 mid 本身不可能是答案，可以跨过去
                lo = mid + 1;
            } else {
                // mid 不在左段 ⇒ p <= mid，mid 自己可能就是答案
                // 所以只能收到 mid，绝不能 -1（否则 [2,1] 会返回 2）
                hi = mid;
            }
        }
        // 退出时 lo == hi，由不变量 p ∈ [lo, hi] 得 p == lo
        return nums[lo];                     // 题目要"值"，不是"下标"
    }
}
```

### 023.5.2 Go

```go
package main

func findMin(nums []int) int {
	lo, hi := 0, len(nums)-1
	for lo < hi {
		mid := lo + (hi-lo)/2
		// 与右端点比较：右段一定延伸到末尾，所以 nums[hi] 一定有代表性
		if nums[mid] > nums[hi] {
			lo = mid + 1 // mid 在左段，答案在右边，mid 可排除
		} else {
			hi = mid // mid 可能是答案，不能减 1
		}
	}
	return nums[lo]
}

func main() {
	// 只为了让 `go run .` 可执行；LeetCode 上不需要 main
	println(findMin([]int{3, 4, 5, 1, 2}))       // 1
	println(findMin([]int{4, 5, 6, 7, 0, 1, 2})) // 0
	println(findMin([]int{11, 13, 15, 17}))      // 11（未旋转）
	println(findMin([]int{2, 1}))                // 1
}
```

### 023.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 循环条件 | `while (lo < hi)` | `for lo < hi` | Go 的 `for` 是唯一的循环关键字，`while` 要写成 `for cond`，**少了括号，但语义完全一致** |
| `mid` 计算 | `lo + (hi - lo) / 2` | 同形 | Go 的 `/` 对非负数与 Java 一致；两者都**必须**这么写防溢出（虽然本题值域小） |
| 返回值 | `nums[lo]` | `nums[lo]` | 完全一致。**注意不要返回 `lo`** —— 题目要值 |
| 空数组 | `hi = -1`，`lo < hi` 为假，`nums[0]` **越界** | `hi = -1`，循环不进，`nums[0]` **panic** | 两个语言都会崩。本题约束保证 `n ≥ 1`，但**如果你把它当成通用模板，必须加 `if (n == 0) return ...`** |
| 无 `else if` | 需要 `else if` 链 | `switch { case ... }` 更清爽 | 本题只有两路，无差别 |
| 类型宽度 | `int` 32 位 | `int` 64 位 | 比较运算不会溢出，无差异 |

```go
func bruteMin(nums []int) int {
	m := nums[0]
	for _, v := range nums[1:] {
		if v < m {
			m = v
		}
	}
	return m
}

// 造一个「升序 + 旋转 k 位」的合法输入，k ∈ [0, n-1]（等价于题目说的 1..n 次）
func makeRotated(r *rand.Rand, n int) []int {
	base := make([]int, n)
	perm := r.Perm(n)
	copy(base, perm)
	sort.Ints(base)
	k := r.Intn(n)
	out := make([]int, n)
	for i := 0; i < n; i++ {
		out[i] = base[(i+k)%n]
	}
	return out
}
```

## 023.6 复杂度与常见坑

### 023.6.1 复杂度推导

**时间 O(log n)**：

- 每轮做 **1 次数组访问 + 1 次比较**（比 022 的 4 次少），区间长度至少减半。
- 轮数 `≤ ⌈log₂ n⌉`。`n = 5000` → **13 轮**；`n = 10^5` → 17 轮；`n = 10^9` → 30 轮。
- 精确地说，`hi - lo` 每轮变成 `⌊(hi-lo)/2⌋` 或 `⌈(hi-lo)/2⌉`（减 1 之后），所以轮数是 `⌈log₂(hi-lo+1)⌉`。

**空间 O(1)**：`lo / hi / mid` 三个变量。**别写递归** —— 递归版是 O(log n) 栈空间，白送劣势。

### 023.6.2 八个真实踩过的坑

1. **判据用 `nums[mid] > nums[lo]`** —— 本章第一号 bug。未旋转时（`k = n`）恒真，一路向右，返回最大值。**必须与 `nums[hi]` 比。**
2. **`hi = mid - 1`** —— `mid` 可能就是最小值位置。`[2,1]` 上 `lo=0, hi=1, mid=0`，`nums[0]=2 > nums[1]=1` → `lo=1`，此时 `lo==hi` 退出，返回 `nums[1]=1`（这个例子碰巧对）；但 `[2,3,1]`：`lo=0,hi=2,mid=1`，`nums[1]=3 > nums[2]=1` → `lo=2`，返回 `nums[2]=1`（也对）... 真正翻车的是「`nums[mid] < nums[hi]` 且 `p == mid`」的情形：`[3,1,2]`，`lo=0,hi=2,mid=1`，`nums[1]=1 < nums[2]=2` → 走 `hi = mid - 1 = 0`，区间 `[0,0]`，返回 `nums[0] = 3` ❌。**这就是「`mid` 没被排除就不能 ±1」的具体代价。**
3. **用 `nums[mid] >= nums[hi]`** —— 本题值互不相同，`==` 不会发生，多一个 `=` 无害；**但如果你把这行代码抄到 LC 154（有重复），`>=` 会让你在 `[1,1,1]` 上一路 `lo = mid+1` 冲出边界。** 记住：无重复时用 `>`，有重复时要单独处理 `==`。
4. **`while (lo <= hi)`** —— 本模板的致命写法。`lo == hi` 时 `mid == hi`，`nums[mid] > nums[hi]` 恒假 → `hi = mid` 不变 → **死循环**。必须 `lo < hi`。
5. **`lo = mid`** —— 另一个死循环源。`hi = lo+1` 时 `mid = lo`，`lo` 原地踏步。**下取整的 `mid` 只能配 `lo = mid+1`。**
6. **返回 `lo` 而不是 `nums[lo]`** —— 题目要的是值。返回下标的题（如 LC 33）才会返回 `lo`。**面试读题时把「返回什么」圈出来。**
7. **把「旋转 1 到 n 次」理解成「一定旋转过」** —— `k = n` 时数组恢复原样，这就是「未旋转」。**漏了这类，判据 A 的 bug 就藏在里面。**
8. **空数组没判** —— 本题约束 `n ≥ 1`，但如果你把这个模板抄去做通用工具函数（比如「在可能为空的数组里找最小值」），`nums[0]` 会越界/panic。**Go 会 `panic: index out of range`，Java 会 `ArrayIndexOutOfBoundsException`，都不好调试。**

### 023.6.3 面试官最爱追问的三个问题

**Q1：为什么和右端点比，不和左端点比？**
> 「因为右段一定延伸到数组末尾。旋转把『小的那些值』放在了末尾，所以 `nums[n-1]` 一定在右段里（不管旋转了几次，包括 0 次——此时右段就是整个数组）。于是 `nums[mid] > nums[hi]` 精确等价于『`mid` 在左段、`hi` 在右段』，也就是『最小值在 `mid` 右边』。而 `nums[lo]` 只在左段非空时才有代表性；未旋转时左段为空，`nums[lo]` 就是全局最小值，判据恒真，会一路向右跑到末尾返回最大值。」

**Q2：为什么循环条件必须是 `lo < hi`，`lo <= hi` 不行？**
> 「因为 `hi = mid` 不排除 `mid`。如果允许 `lo == hi` 进循环，那么 `mid == hi`，`nums[mid] > nums[hi]` 恒为假，代码走 `hi = mid`，`hi` 一点没变，下轮还是同样状态 —— 死循环。用 `lo < hi` 保证循环内恒有 `mid < hi`，于是 `hi = mid` 至少让 `hi` 减 1，区间严格收缩。」

**Q3：有重复元素怎么办？最坏复杂度是多少？**
> 「`nums[mid] == nums[hi]` 时无法判断 `p` 在 `mid` 左边还是右边。例子：`[1,1,1,2,1]`，`mid=2, hi=4`，两端都是 1，`p` 可能是 4（右边），也可能 `mid` 左边还有更小值。唯一安全的做法是把 `hi` 收缩一格（`hi--`），因为 `nums[hi]` 与 `nums[mid]` 相等且 `mid < hi`，`nums[hi]` 一定可以被 `nums[mid]` 替代。最坏复杂度 O(n)——全相同数组每次都只能缩一格。而且可以证明：重复元素下不存在 O(log n) 的比较算法，因为一次相等比较不能排除任何候选。」

## 附：本章小结（可背走的三句话）

```
① 找最小值 = 找断点；判据必须与"永远在右段"的右端点比：nums[mid] > nums[hi]
② lo = mid+1（mid 被排除）配 hi = mid（mid 是候选）—— 这是「下取整 mid」的唯一安全组合
③ lo < hi 保证 mid < hi，于是 hi = mid 至少减 1，区间严格收缩 ⇒ 不会死循环
```
