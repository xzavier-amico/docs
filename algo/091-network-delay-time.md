## 091.1 题目

**原题链接**：<https://leetcode.cn/problems/network-delay-time/>

### 题意重述（把隐含条件补齐）

有 `n` 个网络节点，编号 `1..n`。给你一个有向边列表 `times`，其中 `times[i] = (u_i, v_i, w_i)` 表示「信号从 `u_i` 传到 `v_i` 需要 `w_i` 个单位时间」。现在从节点 `k` 发出一个信号，问：**最少需要多久，才能让所有 `n` 个节点都收到信号？** 如果有节点根本收不到，返回 `-1`。

它藏了四个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **有向边** | 「`u_i` 传到 `v_i`」 | `1→2` 可达不代表 `2→1` 可达，反图要另算 |
| **边权为正**（`1 <= w_i <= 100`） | 约束 | 这是 Dijkstra 合法的**唯一前提**；一旦有负权，本章的核心论证就崩（§091.3.2 给反例） |
| **要所有节点都收到** | 「所有节点都收到信号」 | 答案不是 `dist[k]`，而是 `max_v dist[v]`；任一不可达即 `-1` |
| **同时传播** | 「信号可以同时沿多条边传播」 | 这不是「一次走一条路串起来」，所以不需求「访问顺序」，只需求「每个点的最早到达时间」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= k <= n <= 100` | 最多 100 个点 | `O(n³) = 10⁶` 的 Floyd **也能过**，所以本题真正考的是「选型理由」，不是「能不能过」 |
| `1 <= times.length <= 6000` | 最多 6 千条边 | 平均每个点 60 条出边 → 稠密图；数组版 `O(n²)` Dijkstra 与堆版 `O((V+E)log V)` 都轻松 |
| `1 <= u_i, v_i <= n`，`u_i != v_i` | 无自环 | 不用特殊处理自环 |
| `(u_i, v_i)` 互不相同 | 无重边 | 不用处理「同一对点多条边取最小」 |
| `1 <= w_i <= 100` | 正权 | 最短路最长 `99 × 100 = 9900`，远小于 `int` 上界，但仍建议用「半量程 INF」防溢出 |

> 💡 **量级 → 算法**：本题的 `n ≤ 100` 是个**陷阱式的宽松**。把它换成 `n ≤ 10⁵, m ≤ 2·10⁵`（真实的网络拓扑），Floyd 的 `10¹⁵` 次操作直接判死，`O(n²)` 的数组版 Dijkstra 也死（`10¹⁰`），只有堆优化的 `O((V+E) log V) ≈ 2·10⁶` 能活。**面试里必须按「大输入」来选型，而不是按题面给的 `n = 100`。**

### 示例

```
输入：times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2
输出：2
解释：2→1 用 1；2→3 用 1；2→3→4 用 2。最远的 4 号点 2 个时间单位到，
      所以答案 = max(1, 0, 1, 2) = 2。

输入：times = [[1,2,1]], n = 2, k = 2   （注意起点是 2！）
输出：-1
解释：2 号点没有任何出边，1 号点永远收不到。

输入：times = [[1,2,1]], n = 2, k = 1
输出：1
```

### 我自造的四个反例（写完代码必须拿它们打一遍）

```text
① [[1,2,100],[1,3,1],[3,2,1]], n=3, k=1   → 1 号到 2 号：直达 100，绕 3 号只要 2
                                            答案 2。这条专杀「BFS 按边数分层」的写法
② 无任何边, n=1, k=1                        → 答案 0（单点图，信号原地已收到）
③ [[1,2,1]], n=3, k=1                      → 答案 -1（3 号点不可达）
④ [[1,2,7],[1,2,3]]                        → 约束外（重边），但代码要能取 3 而不是 7
```

第 ① 条是本章的核心：**它说明「跳数少」不等于「时间短」**，BFS 在这张图上会返回 `100`。

## 091.2 从暴力到最优：第一个念头为什么错

### 第一个念头 A：「从 `k` 做 BFS，层数就是时间」

这是最自然、也最错的念头。BFS 求的是**边数最少的路径**，而题目要的是**边权之和最小的路径**。两者只在「所有边权相等」时一致。

用反例 ① 打它：`[[1,2,100],[1,3,1],[3,2,1]]`，从 1 出发。BFS 认为 2 号点在**第 1 层**，时间是 `100`；而真正的最早到达是 `1 → 3 → 2 = 2`（2 跳）。**BFS 多跳了一层，却快了 50 倍。**

> 这不是「BFS 写错了」，而是「**BFS 解的模型不对**」。判环、连通块、网格最短路这类「每步代价一样」的问题，BFS 才是那把锤子（082–089 全都在用）。一旦边上出现权重，就必须换工具。

### 第一个念头 B：「跑一遍 Floyd-Warshall，取 `max(dist[k][*])`」

`O(n³)`，`n = 100` 时是 `10⁶` 次，本机 5 ms 以内，**能过本题**。它甚至是「最不容易写错」的解法。那它输在哪？

- **量级不通用**：`n = 1000` 就是 `10⁹`（秒级），`n = 10⁵` 是 `10¹⁵`（永远跑不完）。而单源最短路只需要做「一个源点」，Floyd 却把所有点对都算了——**浪费了 `n` 倍**。
- **它不能处理「边是流式给出的」**：Floyd 需要完整图才能开始。

结论：Floyd 是**全源最短路**在 `n ≤ 400` 时的最优选（也是本书对拍时最常用的参考实现），但它不是这题的正解方向。

### 第一个念头 C：「从 `k` 做一遍 DFS 枚举所有路径，取最小值」

指数级，且在有环图上有无穷多条路径。可以作为「正确性 xoracle」在极小图上用（比如 5 个点以内），不能当解法。

### 卡点在哪

一句话：

> **我需要「到所有点的最短路」，而 BFS 只能回答「每步代价都为 1」时的最短路。**

把 BFS 推广到「边权不同」的情况，会立刻撞上一个矛盾：BFS 按「层」扩张，是因为**第 `d` 层里任何一个点，都不可能比第 `d-1` 层的点更早被到达**。边权不等之后，这个「层」就不存在了。

### 灵感的来源 —— 把「层」换成「距离」，把队列换成「按距离排序的容器」

Dijkstra 的关键观察：

> 如果所有边权都**非负**，那么**当前已知距离最小的那个未确定点，它的距离已经不可能再被改小了**。

理由很直白：任何别的到达方式都要「先走到某个未确定的点 `x`、再走到它」，而 `dist[x] ≥ dist[u]`（`u` 是当前最小），`x → u` 的边权又非负，所以「绕经 `x`」的路径长度 `≥ dist[x] ≥ dist[u]`，不可能更短。

于是算法变成了一个非常干净的不变量维护：

```
未确定集合 S = 全部点
循环：
    从 S 里取出 dist 最小的点 u      ← 它此刻的 dist 就是最终答案
    确定 u，从 S 移除
    松弛 u 的每一条出边 (u,v,w):     dist[v] = min(dist[v], dist[u] + w)
```

「取出 `dist` 最小的点」这件事，用**小顶堆**做是 `O(log V)`；用「线性扫描整个数组」做是 `O(V)`。前者在稀疏图上赢，后者在稠密图上未必输（§091.3.1 的表里会算账）。

## 091.3 原理拆解

### 091.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| BFS（按层数当距离） | O(V+E) | O(V) | 25 行 | **边权不全相等时答案是错的**（反例 ①），不是慢，是错 |
| DFS 枚举所有路径 | 指数 | O(V) | 20 行 | 有环即无穷；只能当小规模 oracle |
| Floyd-Warshall（全源） | O(V³) | O(V²) | 20 行 | `V > 400` 就慢；单源问题浪费 `V` 倍 |
| Dijkstra（数组版，线性找最小） | O(V² + E) | O(V) | 30 行 | `V = 10⁵` 时 `10¹⁰`；**稠密图（`E ≈ V²`）时反而优于堆版** |
| **Dijkstra（堆优化）** ✅ | **O((V+E) log V)** | O(V+E) | 45 行（Go 要写堆） | 有负权边时**结论直接错**；图的规模极小时堆的常数更大 |
| Bellman-Ford | O(V·E) | O(V) | 20 行 | 稠密图上 `10⁸` 起步；能处理负权，但本章不需要 |
| SPFA（队列版 BF） | 平均 O(E)，最坏 O(V·E) | O(V) | 30 行 | 被网格图卡到最坏复杂度；面试里要能说出「最坏仍是 `O(VE)`」 |

**稠密 vs 稀疏的选择，用数字算一遍**（这张表要能现场推）：

| 图形态 | `V = 100` | 堆版 `O((V+E)log V)` | 数组版 `O(V²)` | 谁赢 |
| --- | --- | --- | --- | --- |
| 稀疏 `E = 3V = 300` | — | `(100+300)·7 ≈ 2800` | `10⁴` | **堆版** |
| 稠密 `E = V²/2 = 4950` | — | `(100+4950)·7 ≈ 3.5·10⁴` | `10⁴` | **数组版** |
| 超稠密 `V = 1000, E = 5·10⁵` | — | `(10³+5·10⁵)·10 ≈ 5·10⁶` | `10⁶` | **数组版** |

结论：**堆版赢在边上，数组版赢在点上**。本题 `V = 100` 而 `E` 最多 6000，两者都远低于限制——正因为如此，本题真正考的才是「你知不知道为什么选 Dijkstra」。

### 091.3.2 为什么这个做法是对的（正确性论证）

**不变量**：每次从堆里弹出 `(d, u)` 时，如果 `d == dist[u]`（不是过期条目），则 `dist[u]` 已是 `k → u` 的**最终最短距离**。

**证明**（反证 + 交换论证）：设第一次出错发生在弹出点 `u` 时，此时存在一条更短的路径 `P: k → … → u`，其长度 `|P| < dist[u]`。

1. 沿 `P` 从 `k` 出发，走到第一个「尚未确定」的点 `x`（它一定存在，因为 `u` 自己就还没确定）。设 `x` 的前驱是已确定的 `p`。
2. 由于 `p` 已确定且算法对 `p` 做过松弛，`dist[x] ≤ dist[p] + w(p,x) ≤ |P 中 k→x 这一段|`（这里用到**边权非负**，所以这段长度不超过 `|P|`）。
3. 于是 `dist[x] ≤ |P| < dist[u]`，也就是说堆里存在一个距离比 `u` 更小的未确定点——这与「`u` 是当前最小」矛盾。∎

**推论（答案的形式）**：所有点都弹出过一次之后，`dist[v]` 是 `k → v` 的最短距离；问题的答案是 `max_v dist[v]`，任一为 `INF` 则返回 `-1`。

### 为什么「不能有负权」——给一个具体反例

```
     (k)──2──▶(a)
      │        ▲
      5        │
      ▼        │
     (b)──-10──┘       真实最短路：k → b → a = 5 + (-10) = -5

Dijkstra 的执行：
  弹出 k(0)        松弛 a=2, b=5        堆：(2,a) (5,b)
  弹出 a(2)  ← 认定 dist[a]=2 是最终值，a 出局
  弹出 b(5)        松弛 b→a：5 + (-10) = -5 < 2，但 a 已确定，不再更新
  结果 dist[a] = 2  ❌ 正确答案是 -5
```

崩在哪一步？崩在**第 2 步**。那里的论证用了 `dist[x] ≥ dist[u]` 与「边权非负 ⇒ 绕经 `x` 不会更短」。一旦有负边，一条「先走远、再倒着拉回来」的路径可以比当前最小还小，**「已确定」就不再是最终结论**。

> 所以 Dijkstra 的前提不是「图是稠密的」也不是「权重是整数」，而是**所有边权非负**（严格说是 `≥ 0`，这样「绕路不减分」）。约束里 `1 <= w_i <= 100` 就是这条前提的书面保证。**面试里被问「为什么不能负权」，就要能画出上面这张图并指出崩在哪一步。**

### 091.3.3 通用解题思路（可迁移的那一层）——★ 全书图算法选型决策表

本章是图形结构部分的收口中枢。**下面这张表是全书图算法的选型决策表**，其余各章（090、092、093、094、095）都引用它：

| 你观察到的条件 | 该用的算法 | 复杂度 | 关键前提 / 陷阱 | 章节 |
| --- | --- | --- | --- | --- |
| 边权全相同（等价于**无权**），问最少几步 | **BFS** | `O(V+E)` | 只对「每步代价相等」成立 | 082–089 |
| 边权**非负**，问单源最短路 | **Dijkstra（堆优化）** | `O((V+E) log V)` | **不能有负权**；有负权时结论错，不是慢 | 本章 091 |
| 有**负权边**，问单源最短路 | **Bellman-Ford / SPFA** | 最坏 `O(V·E)`（SPFA 平均 `O(E)`，最坏 `O(V·E)`） | 能检测负环（第 `V` 轮仍能松弛即有负环）；SPFA 的最坏情况现实存在 | 092 |
| 限制「**最多 k 条边**走完」 | **分层图 Dijkstra** 或 **Bellman-Ford 迭代 `k+1` 轮** | `O(k·E log(kV))` / `O(k·E)` | 必须用**上一轮快照**，否则同一轮内会串联（等价于「边数不设限」） | 092 |
| 答案是「路径上**最大值最小** / 瓶颈」 | **二分答案 + BFS** 或 **Dijkstra 变形（转移取 max）** | `O(V E log C)` / `O((V+E) log V)` | 转移不满足「相加」而是「取 max」，单调性仍在 | 093 |
| 全源最短路，且 `V` 很小（`≤ 400`） | **Floyd-Warshall** | `O(V³)` | 代码最短；对拍神器 | 092 / 093 |
| 「把所有点连起来，总代价最小」 | **Kruskal（并查集）** / **Prim（堆或数组）** | `O(E log E)` / `O(V²)` | 稀疏用 Kruskal，稠密用 Prim | 094 |
| 判环 / 判连通 / 动态加边 | **并查集** | `O(α(n))` ≈ O(1) | 只加不删；删边要离线倒序或可回滚 | 090 |
| **一笔画**：把所有边走且只走一次 | **欧拉路径 Hierholzer** | `O(E log E)`（含排序） | 存在性判定：除起点终点外所有点入度 = 出度 | 095 |
| DAG 上求最短路（可带负权）/ 判依赖 | **拓扑排序 + 松弛** | `O(V+E)` | 有环则无拓扑序 | 089 |

用一张「三问三分」的决策树把它压缩成能背走的东西：

```
拿到一道图题
   │
   ├─ 问「能不能到 / 有几个块 / 是否成环」？ ────────────▶ 并查集 or BFS/DFS         (090, 082)
   │
   ├─ 问「代价最小」？
   │     ├─ 每步代价一样？        ────────────────────▶ BFS                        (086, 088)
   │     ├─ 代价带「最陡一步」的语义？ ────────────────▶ 二分答案 or Dijkstra-max   (093)
   │     ├─ 代价相加、边权非负？
   │     │     ├─ 要「整个连通」的总代价 → MST           ──▶ Kruskal / Prim          (094)
   │     │     └─ 要「点到点/点到全体」的最短 → 最短路    ──▶ Dijkstra                (091)
   │     └─ 有负权 / 限制边数 k？  ──────────────────▶ Bellman-Ford / 分层图       (092)
   │
   └─ 问「把每条边走一次的排列」？ ───────────────────▶ 欧拉路径 Hierholzer         (095)
```

**可迁移的那一层**：Dijkstra 的本质是一个**通用框架**——

```
框架 = 「按代价从小到大确定」+ 「一旦确定永不回改」+ 「用松弛传播」
换成「按边数从小到大确定」   → BFS
换成「按代价 + 边数两个维度确定」→ 分层图 Dijkstra（092）
换成「按路径最大边确定」     → 瓶颈路径 Dijkstra 变形（093）
换成「按权从小到大挑边」     → Kruskal / Prim（094）
```

认清了「`x` 维度有序 + 贪心确定」这套骨架，091–094 就是同一个模板换四次「排序键」。

### 091.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 边权变成**负数** | Dijkstra 前提被破坏 | 换 Bellman-Ford（`O(VE)`）或 SPFA；若有负环，最短路无意义 → 092 |
| 限制**最多 `k` 站中转** | 状态多一维 | 分层图 Dijkstra：`dist[v][已用边数]` → 092 |
| 要输出**路径本身**而不是距离 | 需要回溯 | 松弛成功时记录 `parent[v] = u`，最后从终点倒推 |
| 边权是**实数 / 浮点** | 精度问题 | Dijkstra 照样成立（只用到比较），但要用 `float64` 并设定 `eps` 判等 |
| 图**动态加边**，反复问 `k` 到各点的距离 | 无法重跑全部 | 在线维护很贵；实践中要么用「重跑 + 缓存」，要么用增量最短路算法（研究向） |
| 要「第 2 短路 / `k` 短路」 | 排序键要扩展 | `k` 短路：每个点存前 `k` 个距离，堆里弹出第 `k` 次即为答案（Yen / Eppstein 算法） |

## 091.4 图解推演

### 091.4.1 堆的弹出顺序（含过期条目）

以 `times = [[1,2,1],[1,3,4],[2,3,2],[2,4,6],[3,4,3]], n = 4, k = 1` 为例。`dist = [0, INF, INF, INF]`（下标 0 不用）。

```
     ①(1) ──1──▶ ②(2) ──6──▶ ④
       │           ▲          ▲
       4           2          3
       │           │          │
       └──▶ ③(3) ─┴──────────┘
```

逐步推演（`push` 的是 `(dist, 节点)`）：

| 步 | 堆中内容（按弹出顺序） | 弹出的 `(d,u)` | 是否过期 | 松弛动作 | 之后 `dist[1..4]` |
| --- | --- | --- | --- | --- | --- |
| 1 | `(0,1)` | `(0,1)` | 否 | `2` 号 `=0+1=1`；`3` 号 `=0+4=4` | `[0,1,4,INF]` |
| 2 | `(1,2) (4,3)` | `(1,2)` | 否 | `3` 号 `1+2=3 < 4` ✅；`4` 号 `1+6=7` | `[0,1,3,7]` |
| 3 | `(3,3) (4,3) (7,4)` | `(3,3)` | 否 | `4` 号 `3+3=6 < 7` ✅ | `[0,1,3,6]` |
| 4 | `(4,3) (6,4) (7,4)` | `(4,3)` | **是**（`dist[3]=3 < 4`） | 跳过，什么都不做 | 不变 |
| 5 | `(6,4) (7,4)` | `(6,4)` | 否 | 无出边 | `[0,1,3,6]` |
| 6 | `(7,4)` | `(7,4)` | **是**（`dist[4]=6 < 7`） | 跳过 | 不变 |

答案 `max(0,1,3,6) = 6`。

**这张表要读出两件事**：

1. **`dist` 只在「变小」时被写**，所以每个点的最终值是单调下降的；
2. **堆里会留旧副本**（第 4、6 步）。这叫「懒惰删除」——不用真的去堆里删元素，只要在弹出时用 `d > dist[u]` 一句话把它认出来。代价是堆大小变成 `O(E)` 而不是 `O(V)`，换来的是「不用实现 decrease-key」。

### 091.4.2 官方样例的推演

`times = [[2,1,1],[2,3,1],[3,4,1]], n = 4, k = 2`：

```
弹出 (0,2) → 松弛 2→1：dist[1]=1；2→3：dist[3]=1
弹出 (1,1) → 1 号无出边
弹出 (1,3) → 松弛 3→4：dist[4]=2
弹出 (2,4) → 无出边
堆空。dist = [1, 0, 1, 2] → max = 2 ✅
```

注意 `dist[2] = 0` 也参与了 `max`，但它不会影响结果（起点总是最小）。

## 091.5 双语言实现

### 091.5.1 Java

```java
import java.util.*;

class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        // 邻接表：adj.get(u) = {v, w} 的列表。节点编号 1..n，所以开 n+1 个桶
        List<List<int[]>> adj = new ArrayList<>(n + 1);
        for (int i = 0; i <= n; i++) {
            adj.add(new ArrayList<>());
        }
        for (int[] e : times) {
            adj.get(e[0]).add(new int[]{e[1], e[2]});
        }

        final int INF = Integer.MAX_VALUE / 2; // 用 MAX_VALUE 会让 dist + w 溢出成负数
        int[] dist = new int[n + 1];
        Arrays.fill(dist, INF);
        dist[k] = 0;

        // 优先队列存「(距离, 节点)」，按距离升序；距离相等时比编号，只为让弹序确定
        PriorityQueue<int[]> pq = new PriorityQueue<>(
                (a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]);
        pq.offer(new int[]{0, k});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int d = cur[0], u = cur[1];
            if (d > dist[u]) {
                continue;              // 过期条目（懒惰删除）：这个副本已不是最优
            }
            for (int[] e : adj.get(u)) {
                int v = e[0], w = e[1];
                if (d + w < dist[v]) { // 只有松弛成功才入堆 → 堆内条目数 O(E)
                    dist[v] = d + w;
                    pq.offer(new int[]{dist[v], v});
                }
            }
        }

        int ans = 0;
        for (int v = 1; v <= n; v++) {
            if (dist[v] == INF) {
                return -1;             // 有节点到不了
            }
            ans = Math.max(ans, dist[v]); // 全部送达所需时间 = 最远节点的最短距离
        }
        return ans;
    }
}
```

### 091.5.2 Go

```go
package main

import "container/heap"

// Item：堆元素 = (节点, 当前已知最短距离)
type Item struct {
	node int
	dist int
}

// minHeap：Go 标准库没有内置优先队列，必须自己实现 container/heap.Interface 的 5 个方法
type minHeap []Item

func (h minHeap) Len() int           { return len(h) }
func (h minHeap) Less(i, j int) bool { return h[i].dist < h[j].dist } // 小顶堆：距离小的先出
func (h minHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *minHeap) Push(x interface{}) {
	*h = append(*h, x.(Item)) // 参数是 interface{}，必须自己做类型断言
}
func (h *minHeap) Pop() interface{} {
	old := *h
	n := len(old)
	it := old[n-1] // heap 包已经把堆顶换到了末尾，这里只需摘掉末尾
	*h = old[:n-1]
	return it
}

func networkDelayTime(times [][]int, n int, k int) int {
	adj := make([][]Item, n+1) // 1-based：题目节点编号 1..n
	for _, e := range times {
		adj[e[0]] = append(adj[e[0]], Item{node: e[1], dist: e[2]})
	}

	const INF = 1 << 60 // 足够大；不用 math.MaxInt32 是因为加法要留余量
	dist := make([]int, n+1)
	for i := range dist {
		dist[i] = INF
	}
	dist[k] = 0

	pq := &minHeap{{node: k, dist: 0}}
	heap.Init(pq) // 首次建堆必须调用，否则堆性质不成立

	for pq.Len() > 0 {
		cur := heap.Pop(pq).(Item)
		if cur.dist > dist[cur.node] {
			continue // 过期条目
		}
		for _, e := range adj[cur.node] {
			if nd := cur.dist + e.dist; nd < dist[e.node] {
				dist[e.node] = nd
				heap.Push(pq, Item{node: e.node, dist: nd})
			}
		}
	}

	ans := 0
	for v := 1; v <= n; v++ {
		if dist[v] == INF {
			return -1
		}
		if dist[v] > ans {
			ans = dist[v]
		}
	}
	return ans
}
```

### 091.5.3 双语言差异批注（重点：Go 的 `container/heap` vs Java 的 `PriorityQueue`）

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 数据结构 | `PriorityQueue` 是**内置类**，默认小顶堆 | **没有内置优先队列**，`container/heap` 只是一组要求实现 `heap.Interface` 的函数 | 同一套算法，Go 要多写 5 个方法（`Len/Less/Swap/Push/Pop`） |
| 比较器 | 构造时传 `Comparator`（lambda） | 实现 `Less(i, j)` 方法，比较的是**下标**而非元素 | Java 比的是元素，Go 比的是 `h[i]` 与 `h[j]`，写错成「比较 i、j」会静默出错 |
| `Push`/`Pop` 签名 | `offer(e)` / `poll()` 返回元素 | `heap.Push(h, x)` / `heap.Pop(h)`，参数与返回值都是 `interface{}` | Go 必须写 `x.(Item)` 类型断言；断言错类型会在运行时 panic |
| 在哪一层建堆 | 逐次 `offer` 自动维护 | **必须**先 `heap.Init(pq)`；直接 `Push` 进一个字面量切片而不 `Init`，堆性质不保证 | 忘记 `Init` 是 Go 版本头号 bug |
| `Pop` 的实现义务 | 不需要写 | 必须自己处理「摘掉末尾」：`old[n-1]` 并 `*h = old[:n-1]` | 有人写成摘掉 `old[0]`，会破坏底层数组并漏元素 |
| 头文件 | `java.util.*` | `container/heap` | Go 的堆**不是泛型版**（Go 1.18+ 的 `heap` 仍靠 `interface{}`），有装箱成本 |
| 值 vs 指针接收者 | 无所谓 | `Push/Pop` 必须用**指针接收者** `*minHeap`，`Len/Less/Swap` 用值接收者即可 | 全用值接收者时 `append` 的新切片头写不回调用方，堆会「丢元素」 |

### 091.5.4 对拍测试：与 Floyd-Warshall 互拍

```go
package main

import (
	"math/rand"
	"testing"
)

// Floyd-Warshall 参考实现：O(V³)，与 Dijkstra 完全不同的思路
func floydRef(times [][]int, n, k int) int {
	const INF = 1 << 40
	d := make([][]int, n+1)
	for i := range d {
		d[i] = make([]int, n+1)
		for j := range d[i] {
			if i != j {
				d[i][j] = INF
			}
		}
	}
	for _, e := range times {
		if e[2] < d[e[0]][e[1]] {
			d[e[0]][e[1]] = e[2] // 重边取最小（约束里没有，但参考实现顺手处理）
		}
	}
	for m := 1; m <= n; m++ {
		for i := 1; i <= n; i++ {
			for j := 1; j <= n; j++ {
				if d[i][m]+d[m][j] < d[i][j] {
					d[i][j] = d[i][m] + d[m][j]
				}
			}
		}
	}
	ans := 0
	for v := 1; v <= n; v++ {
		if d[k][v] >= INF {
			return -1
		}
		if d[k][v] > ans {
			ans = d[k][v]
		}
	}
	return ans
}

func TestNetworkDelayTime(t *testing.T) {
	r := rand.New(rand.NewSource(20240743))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(7) // 1..7，刻意包含单点图
		m := r.Intn(14)    // 0..13 条边，刻意包含完全不连通
		times := make([][]int, 0, m)
		for i := 0; i < m; i++ {
			times = append(times, []int{1 + r.Intn(n), 1 + r.Intn(n), 1 + r.Intn(9)})
		}
		k := 1 + r.Intn(n)
		if got, want := networkDelayTime(times, n, k), floydRef(times, n, k); got != want {
			t.Fatalf("iter=%d n=%d k=%d times=%v got=%d want=%d", iter, n, k, times, got, want)
		}
	}
}
```

> ⚠️ **随机数据里为什么允许自环与重边**：题面排除了它们，但对拍的目的是「让两条完全不同的算法在尽可能多的形态上对话」。自环（`u→u`）会让 `dist[u] + w` 大于 `dist[u]`，天然被忽略；重边会逼出「取最小」的路径。**如果 Dijkstra 的松弛写成了 `dist[v] = dist[u] + w`（不加 `min`），重边会立刻把它打出来。**
> 另外注意参考实现里 `if i != j` 的初始化：对角线设 0、其余设 `INF`，这是 Floyd 唯一容易写错的一行。

## 091.6 复杂度与常见坑

### 091.6.1 复杂度推导

- **时间 `O((V+E) log V)`**：
  - 每条边最多触发一次成功的松弛，所以 `push` 至多 `E` 次（外加起点的 1 次）；每次 `push`/`pop` 是 `O(log(堆大小))`，堆大小不超过 `V + E`。
  - 所以总代价是 `O((V+E) log(V+E))`，通常简写成 `O((V+E) log V)`（`E ≤ V²` 时 `log(V+E) = O(log V)`）。
  - 注意「每条边只入堆一次」的前提是「只在松弛成功时 `push`」；如果写成「每条边无条件 `push`」，常数会变大但复杂度量级不变。
- **空间 `O(V + E)`**：邻接表 `O(V+E)`，`dist` 数组 `O(V)`，堆最坏 `O(E)`（每个点可能留多个过期副本）。
- **对照：Floyd 是 `O(V³)` 时间 + `O(V²)` 空间**，本题 `V = 100` 时 `10⁶ / 10⁴`，能过；`V = 1000` 时 `10⁹` 就慢了 1000 倍。

### 091.6.2 七个真实踩过的坑

1. **写成 BFS**：边权不等时答案是错的（反例 ①）。判断依据：题目里出现了「时间 / 花费 / 权重」这样的字眼，就不能默认为 1。
2. **忘了跳过过期条目**：`if (d > dist[u]) continue;` 少写一句，答案通常仍然正确（多算几轮而已），但在「有环 + 负权」或者大规模图上会显著变慢；更糟的是它会掩盖 `decrease-key` 逻辑上的错误。
3. **`INF` 用 `Integer.MAX_VALUE` 然后做加法**：`MAX_VALUE + w` 溢出成负数，于是「不可达」被误判成「极小距离」，答案变成一个荒唐的负数。**用 `MAX_VALUE / 2` 或 `1 << 60`。**
4. **节点编号当成 0-based**：题面是 `1..n`，`new int[n]` 会越界；`dist[0]` 永远 `INF` 也会让你误判「不可达」。
5. **`max` 时把 `dist[0]` 算进去**：若循环写成 `for (int v = 0; v <= n; v++)`，`dist[0]` 恒为 `INF`，直接返回 `-1`。必须从 `1` 开始。
6. **Go 里忘记 `heap.Init`**：`pq := &minHeap{{k, 0}}` 只有一个元素时看不出问题，元素一多就弹出乱序。**建堆必须显式调用。**
7. **Go 里 `Push` 用值接收者**：`func (h minHeap) Push(x interface{})` 里 `append` 产生的新切片头写不回去，堆会「越推越空」。必须是 `*minHeap`。

### 091.6.3 面试官最爱追问的三个问题

**Q1：为什么 Dijkstra 不能处理负权边？**
> 「它的正确性靠一条论证：当前 `dist` 最小的未确定点 `u`，任何别的到达方式都要经过某个未确定点 `x`，而 `dist[x] ≥ dist[u]`，再加上边权非负，绕路不可能更短。有负边时这条不等式断了——一条『先走远再倒着拉回来』的路径可以比 `dist[u]` 更小，于是『已确定』不再是最终答案。要处理负权，得换成 Bellman-Ford（`O(VE)`），或者用 Johnson 算法先把边权重赋为非负。」

**Q2：SPFA 和 Bellman-Ford 什么关系？面试里能写 SPFA 吗？**
> 「SPFA 是 Bellman-Ford 的队列优化：只有被松弛过的点才可能继续松弛别人，于是用它维护一个待松弛队列。平均接近 `O(E)`，但**最坏仍是 `O(VE)`**——网格状或刻意构造的图能把它卡到最坏。面试里可以写，但必须主动说出最坏复杂度，并说明『如果题目有负权且要求最坏有保证，我会写朴素的 `V` 轮 Bellman-Ford』。」

**Q3：如果边权是浮点数 / 很大的整数，会有什么问题？**
> 「Dijkstra 只用到比较和加法，浮点也成立，但要注意两点：① `dist + w` 的累加误差会随路径长度增长，判等要加 `eps`；② 如果用 `double` 表示『不可达』，`INF` 不能取 `Double.MAX_VALUE`，因为加上任何数都会保持不变，`dist + w < dist` 永远假，松弛静默失效——取 `1e18` 这类有限大值更安全。整数的话用好 `long` / `int64` 即可，`V·maxW` 的上界要提前算出来确认不溢出。」
