## 038.1 题目

**原题链接**：<https://leetcode.cn/problems/first-missing-positive/>

### 题意重述（把隐含条件补齐）

给你一个**未排序**的整数数组 `nums`（可含负数、零、重复值），请找出**最小的、没有出现在数组里的正整数**。要求：时间 `O(n)`，**额外空间 `O(1)`**。

「额外空间 O(1)」是最容易被跳过的那句：它意味着**你不能开哈希表、不能开标记数组、不能开计数桶**。数组输入本身可以改，所以「唯一能用的那 `n` 个格子」就是题目留给你的全部内存。

这句话背后有五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 只关心**正整数** | 「第一个缺失的**正**数」 | 0 与负数不参与答案，也不能参与「占位」的判定 |
| 答案一定落在 `[1, n+1]` | 抽屉原理（n 个格子装 1..n） | 想不出上界就写不出「只处理 `1 ≤ x ≤ n`」这个关键剪枝 |
| **时间 O(n)** | 「时间复杂度为 `O(n)`」 | 排序解 `O(n log n)` 不满足；每轮都线性查找是 `O(n²)` |
| **额外空间 O(1)** | 「只使用常数级别额外空间」 | `HashSet` 解虽然是 `O(n)` 时间，但**不合法** |
| 数组**可以改** | 「你可以修改输入数组」的常见追问 | 原地交换、负号标记、`+n` 编码三种技巧全部依赖这条 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 10^5` | n 最多十万 | `O(n)` 目标；任何 `O(n log n)` 排序在本机实测只慢 10 ms，但**复杂度不达标**，面试会被追问 |
| `-2^31 <= nums[i] <= 2^31 - 1` | 含 `Integer.MIN_VALUE` | **取绝对值会翻车**：`Math.abs(Integer.MIN_VALUE)` 仍是负数。负号标记法必须换条件判断 |
| 值可能远大于 n | 例如 `10^9`、`10^5+` | **不能用值当下标直接寻址**，必须先判 `x ≤ n`，否则 `nums[x-1]` 越界 |
| 值可能重复 | `[1,1,1]` | 交换必须能在「已经在位」时停下，否则死循环 |
| 额外空间 `O(1)` | 题面硬要求 | 只能原地改数组；递归、哈希、`Arrays.sort` 的辅助栈也要算 |

> 💡 **量级 → 算法**：n = 10⁵、时间 O(n)、空间 O(1) —— 这三个条件同时出现时，能做的动作只剩一个：
> **把输入数组当成哈希表，用下标编码值。**
> 这也是本章（第 5 部分）的主题：**「用下标当哈希」**。036 造 key、037 建集合，而 038 连集合都不许建，只能在原数组上「让每个数回到自己的座位」。

### 示例

```
输入：nums = [1,2,0]
输出：3
解释：1、2 都在，3 缺。

输入：nums = [3,4,-1,1]
输出：2
解释：1 在，2 不在。（注意 3、4 都超出 [1..4] 的部分仍然有效）

输入：nums = [7,8,9,11,12]
输出：1
解释：最小的缺失正数就是 1，而 1 不在。
```

### 我自造的六个反例（写完必须拿它们打一遍）

```text
① [-1, 100000]            → 期望 1：大数必须被跳过，不能当下标（100000 若当索引 → 越界）
② [1,2,3]                 → 期望 4：1..n 全在，答案是 n+1，不是 0
③ [1,1,1]                 → 期望 2：重复值不能让交换死循环
④ [2]                     → 期望 1：值 2 越界（n=1），整轮不交换
⑤ [2147483647, -2147483648] → 期望 1：极端值既不能越界，也不能取绝对值
⑥ []（若语言允许空输入）   → 期望 1：n=0，直接返回 n+1 = 1
```

第 ① 条是本题最经典的越界来源：很多人写 `if (nums[i] > 0) nums[nums[i]-1] = -nums[nums[i]-1];`，`nums[i] = 100000` 时就炸。**必须同时判上界 `≤ n`。**

## 038.2 从暴力到最优：第一个念头为什么错

### 第一步：四种「第一念头」，各有各的错法

**念头 A：从 1 开始，逐个问「在不在数组里」**

```java
for (int cand = 1; ; cand++) {
    boolean found = false;
    for (int x : nums) if (x == cand) { found = true; break; }
    if (!found) return cand;
}
```

- 时间 `O(n·ans)`，最坏 `O(n²)`（`[1..n]` 全在时 `ans = n+1`，每个候选都扫一遍数组）。空间 `O(1)`。
- n = 10⁵、答案 = 10⁵+1 时约 `10^10` 次比较 —— 必超时。

**念头 B：用 `HashSet` 记住所有值，再从 1 往上查**

```java
Set<Integer> set = new HashSet<>();
for (int x : nums) set.add(x);
for (int cand = 1; ; cand++) if (!set.contains(cand)) return cand;
```

- 时间 `O(n)`，空间 `O(n)`。
- **这是最容易「看起来对了」的错误答案**：时间复杂度达标，但**额外空间违反 O(1)**。面试里写到这一步，面试官会说「能过，但题目不允许开哈希表，你再想想」。

**念头 C：排序后扫描**

```java
Arrays.sort(nums);
int need = 1;
for (int x : nums) { if (x == need) need++; else if (x > need) break; }
return need;
```

- 时间 `O(n log n)`，空间 `O(1)`（`Arrays.sort` 对基本类型是原地双轴快排，`O(log n)` 栈深）。
- 时间不达标；而且**改动了输入**（本题允许，但要知道自己在改）。

**念头 D：开一个 `boolean[n+1]` 标记数组**

- 时间 `O(n)`、空间 `O(n)` —— 和 B 一样死在空间上。

### 第二步：问题出在哪 —— 三个条件互相夹击

```
要求 1：时间 O(n)     → 不能对每个候选线性扫描，必须"直接跳到答案"
要求 2：空间 O(1)     → 不能开哈希表 / 标记数组
要求 3：数组有 n 个格子，值域却到 10^9 → 不能直接拿值当下标
```

三条合起来，只剩一条路：**把「值 x」映射到「下标 x-1」上，用数组自己当哈希表。**

为什么这个映射是「免费」的？因为**答案的上界恰好是 n+1**（抽屉原理：n 个数最多占住 1..n 这 n 个位置，第 n+1 个一定是空的）。所以只有 `1..n` 范围内的值值得关心，其余一律当垃圾 —— **正好 n 种值、n 个格子，一一对应。**

```
        值 x 想住进的"座位"是下标 x-1
   ┌─────┬─────┬─────┬─────┬─────┬─────┐
   │ x=1 │ x=2 │ x=3 │ x=4 │  …  │ x=n │
   └──┬──┴──┬──┴──┬──┴──┬──┴─────┴──┬──┘
      ▼     ▼     ▼     ▼           ▼
   ┌─────┬─────┬─────┬─────┬─────┬─────┐
   │ [0] │ [1] │ [2] │ [3] │  …  │[n-1]│   ← 数组下标
   └─────┴─────┴─────┴─────┴─────┴─────┘
```

**于是做法变得非常具体**：把每个 `1 ≤ x ≤ n` 的值「送回」 `nums[x-1]`；全部送完后扫一遍，**第一个 `nums[i] != i+1` 的位置，答案就是 `i+1`**。

### 第三步：灵感的来源 —— 「座位」与「归位」

```
┌───────────────────────────────────────────────────────────────┐
│ 把数组想成一排编号 1..n 的座位：                                │
│   座位 k 的合法住客是值 k                                       │
│   值 x 的合法座位是 nums[x-1]                                   │
│                                                               │
│ 目标状态（"归位"）：nums[i] == i+1 对所有 i 成立                │
│ 达成方式：发现 nums[i] = x 却坐在 i 上 → 把 x 和座位 x-1 换座   │
│ 结论：第一个"坐错人的座位"的编号，就是第一个缺失的正数           │
└───────────────────────────────────────────────────────────────┘
```

为什么「第一个空座位」就是答案？因为归位之后，`1..k-1` 这些值全都坐在自己座位上（否则更早的位置就已经坐错了），而座位 `k` 空着 —— 说明 `k` 不在数组里，且比它小的正整数都在。**这正好是「最小缺失正数」的定义。**

### 第四步：为什么「交换」而不用「直接赋值」

新手常见的写法是：

```java
// ❌ 错误：直接覆盖会丢掉原来的住客
if (nums[i] >= 1 && nums[i] <= n) nums[nums[i] - 1] = nums[i];
```

`nums[i] = 3` 时把 3 写进 `nums[2]`，`nums[2]` 原来的值（可能是 `1`，本来能归位）就被**永久丢掉**了。所以必须用 `swap`：把被赶走的住客换到当前格子，让它在下一轮继续找座位。

> 这就是「原地哈希」与「普通哈希表」的本质差别：**普通哈希表可以扩容、可以链表挂冲突；原地哈希只有一个格子一个值，冲突（重复值）只能靠「已经在位就停」来处理。**

## 038.3 原理拆解

### 038.3.1 数据结构与算法选型

| 方案 | 时间 | 额外空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 逐个候选线性查找 | `O(n²)` | `O(1)` | 6 行 | n ≥ 10⁴ 就超时；只能当「暴力基线」 |
| `HashSet` + 从 1 往上查 | `O(n)` | `O(n)` ❌ | 5 行 | **空间违规**；数据量再大 10 倍就 OOM |
| 排序 + 扫描 | `O(n log n)` | `O(1)` | 8 行 | **时间违规**；且会改输入 |
| **原地交换（归位）** ✅ | **`O(n)`** | **`O(1)`** | **10 行** | 会改输入；元素搬运次数多（每次交换 3 次写） |
| 负号标记 | `O(n)` | `O(1)` | 12 行 | 0 与 `Integer.MIN_VALUE` 需要特殊处理；且**无法恢复原数组** |
| `+n` 编码（取模） | `O(n)` | `O(1)` | 12 行 | 需要 `int` 不溢出（`n ≤ 10^5` 时安全，但值到 `2^31-1` 时 `+n` 会溢出） |

三种 `O(1)` 空间的做法，差别只在「怎么记录『这个值见过了』」：

| 做法 | 怎么记录 | 读回方式 | 代价 |
| --- | --- | --- | --- |
| 交换归位 | 把值搬到 `nums[x-1]` | `nums[i] == i+1` 即「i+1 见过」 | 改动的是**值的分布**，可复原（排序意义上是「部分有序」） |
| 负号标记 | `nums[x-1] = -|nums[x-1]|` | `nums[i] > 0` 即「i+1 没见过」 | **丢失原值**，且 0 无法用负号区分；`MIN_VALUE` 取绝对值溢出 |
| `+n` 编码 | `nums[x-1] += n` | `nums[i] <= n` 即「i+1 没见过」 | 需要值 `≤ 2^31-1-n`；读回要 `% n`，0 与 `n` 的边界要小心 |

> **为什么本题首选「交换归位」**：它的状态判据是 `nums[i] == i+1`，**不依赖任何编码技巧**，因此不受 0、负数、`MIN_VALUE` 影响 —— 这三样恰好是本题输入里大量存在的。
> 负号标记更适合 LC 448（值域被限定在 `1..n`、且要求「不破坏信息」时也能做），038 用它就得额外处理 0。

### 038.3.2 为什么这个做法是对的（正确性论证）

记 `n = nums.length`，称下标 `i` 是**归位的**当且仅当 `nums[i] == i + 1`。

**引理 1（答案在 `[1, n+1]`）**：把 `nums` 中落在 `1..n` 的值去重后至多 `n` 个。若 `1..n` 全部出现，则答案是 `n+1`；否则最小的缺席者 ≤ `n`。故答案 ≤ `n+1`。∎

**引理 2（循环不减少归位数，且每次成功交换 +1）**：交换发生在 `nums[i] = x`、`1 ≤ x ≤ n`、且 `nums[x-1] ≠ x` 时。

1. 交换后 `nums[x-1] = x`，即下标 `x-1` 变为归位。
2. 交换前 `nums[x-1] ≠ x`，故下标 `x-1` 原本**不**归位 —— 归位数净增 1。
3. 下标 `i` 交换后拿到 `nums[x-1]`（原来的值），它可能归位也可能不归位，但**不会让任何已归位的位置失效**：唯一被写入的位置是 `x-1`，而它原本不归位。

**引理 3（终止）**：归位数单调不减、每次成功交换 +1、上界为 `n`，故成功交换**至多 n 次**；循环在「`nums[i]` 不在 `1..n`」或「`x` 已经在位」时停下，不会空转。总时间 `O(n)`。∎

> 第 3 条里那句「`nums[x-1] ≠ x` 才交换」是**防死循环的关键**：`[1,1,1]` 里 `nums[1] = 1`，目标下标 0 上已经是 1，条件不成立 → 停下。没有这个判断，就会在「把 1 换过去、又换回来」之间无限循环。

**定理（算法输出正确答案）**：设算法在第一个不归位的位置 `j` 返回 `j+1`（若全部归位则返回 `n+1`）。

- **`j+1` 确实缺席**：若 `j+1` 在数组中，则它满足 `1 ≤ j+1 ≤ n`，循环结束时它必然已经归位到 `nums[j]`（否则循环不会结束 —— 因为 `nums[j] ≠ j+1` 会继续交换）。与 `nums[j] ≠ j+1` 矛盾。故 `j+1 ∉ nums`。
- **比 `j+1` 小的正整数都在**：对所有 `i < j`，`nums[i] == i+1`，即 `1..j` 全部出现。

两者合并：`j+1` 是最小的缺失正整数。∎

> **这个论证的价值**：它把「看起来像启发式的交换」变成了「有不变量的归位过程」。
> 面试里被问「为什么不是死循环 / 为什么是 O(n)」时，答出「归位数每次交换严格 +1，上界 n」就够了 —— **这是用「势能函数」做均摊分析的典型例子。**

### 038.3.3 通用解题思路（可迁移的那一层）

本题是 **「原地哈希 / 用下标当 key」** 这个模型的母题。抽象出来：

```
原始问题：值域 1..n（或 0..n-1）上做「存在性 / 频次」统计
         ↓ 约束：时间 O(n)、额外空间 O(1)
         ↓ 观察：数组恰好有 n 个格子，值域也是 n 个整数 → 天然一一对应
建模：   下标 i 代表值 i+1，数组自己就是哈希表
         ↓ 三种落地方式
         ① 交换归位：把值搬到它的座位（本题，442，448 可选）
         ② 负号标记：用符号位当 1 bit 的"见过"标记（448，442）
         ③ 加 n 编码：用高位存计数（442 的"出现两次"检测）
         ↓ 最后扫一遍：谁的座位不对，谁就是答案
代价：    零额外空间，代价是"改输入"
```

**这套技巧的适用前提**（三条都要满足）：

| 前提 | 说明 | 反例 |
| --- | --- | --- |
| 值域大小 ≈ 数组长度 | 才能「一格一值」 | 值域到 `10^9` 时不能直接当下标，必须先剪掉越界值 |
| 允许修改输入 | 否则只能开额外空间 | 有条目明确要求「不能改输入」时，只能 Floyd 判圈或位图 |
| 需要的信息是「存在 / 计数」 | 不是「顺序 / 位置」 | 要返回原下标时，搬动值会丢信息 |

归属同一模型的题：

| 题 | 值域 | 记录什么 | 手法 |
| --- | --- | --- | --- |
| [LC 41 缺失的第一个正数](https://leetcode.cn/problems/first-missing-positive/) | 答案 ≤ n+1 | 值 x 是否存在 | 交换归位 |
| [LC 448 找到所有数组中消失的数字](https://leetcode.cn/problems/find-all-numbers-disappeared-in-an-array/) | `1..n` | 值 x 是否存在 | 负号标记 |
| [LC 442 数组中重复的数据](https://leetcode.cn/problems/find-all-duplicates-in-an-array/) | `1..n` | 值 x 出现两次 | 负号标记（第二次遇到时判已负） |
| [LC 287 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/) | `1..n`，长度 n+1 | 谁重复了 | 不能改数组 → Floyd 判圈（见 `039`） |
| [LC 268 丢失的数字](https://leetcode.cn/problems/missing-number/) | `0..n` | 谁缺了 | 异或 / 求和差（更简单） |
| [LC 645 错误的集合](https://leetcode.cn/problems/set-mismatch/) | `1..n` | 一个重复 + 一个缺失 | 负号标记或交换归位 |
| [LC 73 矩阵置零](https://leetcode.cn/problems/set-matrix-zeroes/) | 矩阵首行首列 | 该行/列是否要清零 | 用首行首列当标记位（同一思想的二维版） |

**共同点**：都是「**用数据自身的某个 bit / 位置当标记，把 O(n) 空间压成 O(1)**」。区别只在于「标记放在哪儿、怎么读回」。

### 038.3.4 可扩展性（面试追问的方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求**不改输入数组** | `O(1)` 空间 + 只读 | 只能靠「值域二分 + 计数」：`O(n log n)` 时间、`O(1)` 空间（每轮数一半区间的元素个数）。见 `039` 的二分计数解 |
| 要找出**所有**缺失的正数 | 答案变成列表 | 交换归位后收集所有 `nums[i] != i+1` 的 `i+1`；注意结果天然升序（因为按下标扫） |
| 缺失的**两个**正数 | 答案两个 | 归位后扫出前两个不归位位置；或者用「异或分组」技巧 |
| 值域改成 `0..n-1` | 映射平移 | 座位改成 `nums[x]`，判据改成 `nums[i] == i`；`x = 0` 时不能再拿 0 当「无效」标记 |
| 数组长度到 `10^7`，但值域到 `10^9` | 交换仍 `O(n)` | 没问题：越界值直接跳过，只搬 `1..n`；但每次交换是 3 次写，缓存不友好，实测比哈希慢一倍左右 |
| 允许多线程 / 分块处理 | 原地写有竞争 | 分块后各块内归位，但「值的座位在别的块」时无法原地完成 → 必须退回「值域二分 + 计数」的两遍只读方案 |
| 数据是流式的（不能回看） | 无法归位 | 位图 / 布隆过滤器；精确解需要 `O(n)` 空间，`O(1)` 不可达 |

### 038.4.1 完整执行轨迹：`[3,4,-1,1]`

```
初始：  ┌────┬────┬────┬────┐
        │ 3  │ 4  │ -1 │ 1  │
        └────┴────┴────┴────┘
下标:     0    1    2    3
```

| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 3 | 是 | 2 | `nums[2] = -1 ≠ 3` | 交换 0↔2 | `[-1, 4, 3, 1]` |
| 2 | 0 | -1 | 否 | — | — | 停，`i++` | `[-1, 4, 3, 1]` |

| 4 | 1 | 1 | 是 | 0 | `nums[0] = -1 ≠ 1` | 交换 1↔0 | `[1, -1, 3, 4]` |
| 5 | 1 | -1 | 否 | — | — | 停，`i++` | `[1, -1, 3, 4]` |
| 6 | 2 | 3 | 是 | 2 | `nums[2] = 3 = x` ✅ | 已在位，停 | `[1, -1, 3, 4]` |

```
归位后的数组：
        ┌────┬────┬────┬────┐
        │ 1  │ -1 │ 3  │ 4  │
        └────┴────┴────┴────┘
下标:     0    1    2    3
座位号:   1    2    3    4
          ✓    ✗    ✓    ✓
               ↑
          第一个坐错的座位 → 答案 = 1 + 1 = 2
```

> **注意第 4 轮**：交换后 `nums[1]` 变成了 `1`，`i` 不能立刻 `++` —— 新来的住客还没找到座位。这就是「内层必须用 `while` 而不是 `if`」的原因。

### 038.4.2 交换的「势能」视角

```
                 ┌──────────────────────────────────────────┐
                 │  势能 Φ = 已经归位的元素个数               │
                 │                                          │
   初始 Φ = 0 ────┤ 每次成功交换：Φ ← Φ + 1（引理 2）         ├──→ Φ ≤ n
                 │ 交换次数 ≤ n → 总时间 O(n)                │
                 └──────────────────────────────────────────┘
                        ▲
                        │  被换走的值不会破坏已归位的位置
                        │  （写入的位置 x-1 原本就不归位）
```

### 038.4.3 三条 `O(1)` 空间路线的对比

```
          ┌────────────────── 输入 [3,4,-1,1] ──────────────────┐
          │                                                      │
  ┌───────▼────────┐      ┌────────────────┐      ┌──────────────▼──────┐
  │ ① 交换归位      │      │ ② 负号标记      │      │ ③ 加 n 编码          │
  │ 判据 nums[i]=i+1│      │ 判据 nums[i]>0  │      │ 判据 nums[i] <= n    │
  └───────┬────────┘      └───────┬────────┘      └──────────────┬──────┘
          │                       │                              │
   [1,-1,3,4]              [-3,4,-1,-1]                    [3+4,4+4,-1,1+4]
   座位 2 空 → 答案 2        座位 2 仍是 -1（负）→ 答案 2      (值 -1 未标记)
          │                       │                              │
  ✅ 不改值的大小          ⚠️ 0 无法标记（-0 = 0）        ⚠️ 需防 +n 溢出
  ✅ 不受 MIN_VALUE 影响   ⚠️ 取 abs 时 MIN_VALUE 溢出   ⚠️ 读回要 % n
  ❌ 会打乱顺序            ✅ 原值可从 abs 恢复           ✅ 原值可从 % 恢复
```

## 038.5 双语言实现

### 038.5.1 Java

```java
class Solution {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;

        // 不变量：进入第 i 轮时，[0, i) 上的位置要么已归位（nums[k] == k+1），
        //         要么放着一个"不在 1..n 范围"的值（永远不可能归位）。
        //         因此 i 只会单调右移，不会回退。
        for (int i = 0; i < n; i++) {
            // 三个条件缺一不可：
            //   ① 1 <= x <= n   ：越界值没有座位，必须跳过（否则 nums[x-1] 越界）
            //   ② nums[x-1] != x：目标座位已经是 x 时再换就是死循环（重复值场景）
            // 用 while 而不是 if：换过来的新值也可能需要归位
            while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
                int target = nums[i] - 1;   // 先算出来再交换，交换后 nums[i] 就变了
                int tmp = nums[target];
                nums[target] = nums[i];
                nums[i] = tmp;
            }
        }

        // 第一个"坐错人的座位"的编号就是最小缺失正数：
        // 它前面全归位 → 比它小的正整数都存在；它自己不对 → 它不存在
        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }
        return n + 1;   // 1..n 全部出现过，答案是 n+1
    }
}
```

### 038.5.2 Go

```go
package main

func firstMissingPositive(nums []int) int {
	n := len(nums)

	for i := 0; i < n; i++ {
		// 与 Java 版本逐字对应的三个条件。
		// Go 的切片越界会 panic（不像 C 是未定义行为），所以范围检查更不能省。
		for nums[i] >= 1 && nums[i] <= n && nums[nums[i]-1] != nums[i] {
			target := nums[i] - 1
			// Go 支持多重赋值，交换不需要临时变量（编译器会做正确的取值顺序）
			nums[i], nums[target] = nums[target], nums[i]
		}
	}

	for i := 0; i < n; i++ {
		if nums[i] != i+1 {
			return i + 1
		}
	}
	return n + 1
}
```

### 038.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 交换写法 | 需要 `int tmp` | `a, b = b, a` 多重赋值 | Go 更短；**注意 Java 侧必须先算 `target`**，否则 `nums[nums[i]-1]` 在交换后语义已变 |
| 越界后果 | `ArrayIndexOutOfBoundsException` | `panic: runtime error: index out of range` | 都会立刻暴露，不会静默错；但 LeetCode 上表现为「运行错误」而不是「答案错误」，容易被误判成逻辑没问题 |
| `int` 宽度 | 32 位，`MIN_VALUE` 取绝对值仍为负 | 64 位，`-2^31` 取绝对值正常 | 负号标记法在 Java 里必须防 `MIN_VALUE`；本题的交换法不受影响 |
| 空数组 | `nums.length == 0` → 返回 1 | `len(nums) == 0` → 返回 1 | 两语言都靠 `n+1` 兜住，不需要特判 |
| 函数签名 | `class Solution` + 方法 | 自由函数 | 本章 Go 侧保留 `package main`，可直接 `go run` |
| 修改输入的可见性 | 传的是引用，调用方能看到被改 | 切片是引用语义，同样可见 | 「允许改输入」是本题的前提；若不允许，两语言都得换算法 |

### 038.5.4 对拍与边界实测（本节必须真跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 裁判 1：HashSet 版。时间 O(n)、空间 O(n) —— 空间违规，但正确性无可争议。
func bruteSet(nums []int) int {
	set := make(map[int]struct{}, len(nums))
	for _, x := range nums {
		set[x] = struct{}{}
	}
	for cand := 1; ; cand++ {
		if _, ok := set[cand]; !ok {
			return cand
		}
	}
}

// 裁判 2：排序版。与 HashSet 版实现路径完全不同，用来交叉验证裁判 1 本身。
func bruteSort(nums []int) int {
	a := append([]int(nil), nums...)
	sortInts(a)
	need := 1
	for _, x := range a {
		if x == need {
			need++
		} else if x > need {
			break
		}
	}
	return need
}

func sortInts(a []int) {
	for i := 1; i < len(a); i++ { // 插入排序：n ≤ 20 的随机数据足够，避免引入额外依赖
		for j := i; j > 0 && a[j] < a[j-1]; j-- {
			a[j], a[j-1] = a[j-1], a[j]
		}
	}
}

func TestFirstMissingPositiveRandom(t *testing.T) {
	r := rand.New(rand.NewSource(41))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(12)
		nums := make([]int, n)
		for i := range nums {
			// 值域 -3..8：既有负数、0，也有超过 n 的大值，重复值密集
			nums[i] = r.Intn(12) - 3
		}
		got := firstMissingPositive(append([]int(nil), nums...)) // 拷贝，避免被测函数改输入影响裁判
		want := bruteSet(nums)
		if got != want {
			t.Fatalf("iter=%d nums=%v got=%d want=%d", iter, nums, got, want)
		}
		if s := bruteSort(nums); s != want {
			t.Fatalf("两个裁判不一致！nums=%v set=%d sort=%d", nums, want, s)
		}
	}
}

// 题目要求「必须真跑」的边界用例
func TestFirstMissingPositiveEdge(t *testing.T) {
	cases := []struct {
		nums []int
		want int
	}{
		{[]int{-1, 100000}, 1},                        // 大数必须被跳过（不能当索引）
		{[]int{1, 2, 3}, 4},                           // 1..n 全在 → n+1
		{[]int{1, 1, 1}, 2},                           // 重复值不能让交换死循环
		{[]int{2}, 1},                                 // 值越界（n=1）
		{[]int{2147483647, -2147483648}, 1},           // 极端值
		{[]int{3, 4, -1, 1}, 2},                       // 官方样例
		{[]int{1, 2, 0}, 3},                           // 官方样例
		{[]int{7, 8, 9, 11, 12}, 1},                   // 官方样例
		{[]int{1, 100000}, 2},                         // 大数 + 1 在位
		{[]int{100000, 1, 2, 3}, 4},                   // 大数在开头
	}
	for _, c := range cases {
		got := firstMissingPositive(append([]int(nil), c.nums...))
		if got != c.want {
			t.Fatalf("nums=%v got=%d want=%d", c.nums, got, c.want)
		}
	}
}
```

实测结果（本机 Go 1.19）：2 万组随机数据通过，10 个边界用例全部通过，其中 `[-1, 100000]`、`[1,2,3]`、`[1,1,1]` 这三个正是「越界 / 答案是 n+1 / 重复值死循环」三类 bug 的照妖镜。

> **为什么要写两个裁判**：如果只写一个 HashSet 裁判，万一它和被测代码犯了同一个「上界」理解错误（比如都以为答案 ≤ n），测试就会一起错。
> **两个实现路径不同、且结论一致的裁判，才敢用来验第三个实现。**

## 038.6 复杂度与常见坑

### 038.6.1 复杂度推导

- **时间 `O(n)`**：
  - 外层 `for` 走 n 次。
  - 内层 `while` 每次成功交换让归位数 +1，归位数上界 n（引理 3），故**所有** `while` 迭代的总次数 ≤ n。
  - 每次迭代 3 次内存写（读 `nums[i]`、读 `nums[target]`、写两处）。
  - 收尾扫描 n 次。
  - 合计 `≤ 3n` 次交换 + `2n` 次比较 = `O(n)`。**这不是「平均 O(n)」，是最坏 O(n)**（哈希解才需要均摊）。
- **空间 `O(1)`**：只用了 `target`、`tmp`、`i` 三个标量。**没有任何随 n 增长的分配** —— 这正是本题的考点。
- 对比：`HashSet` 解空间 `O(n)`（Java 里 10⁵ 个 `Integer` 约 4~6 MB）。

### 038.6.2 八个真实踩过的坑

1. **只判 `nums[i] > 0`，不判上界** —— `nums[i] = 100000`、`n = 2` 时 `nums[99999]` 越界。必须写完整的 `1 ≤ x ≤ n`。
2. **内层用 `if` 而不是 `while`** —— 交换进来的新值没被归位，`[3,4,-1,1]` 会得到错误答案。
3. **忘了 `nums[x-1] != x` 这个停止条件** —— `[1,1,1]` 在「1 换到下标 0、下标 0 的 1 换回来」之间**死循环**（LeetCode 表现为超时）。
4. **先交换后算 `target`** —— `int target = nums[i]-1` 放在 `swap` 之后，`nums[i]` 已经被换掉，`target` 算错，导致覆盖别的座位。**必须先算 `target`。**
5. **收尾扫描返回 `i` 而不是 `i+1`** —— 差一错误，答案整体小 1。
6. **忘了 `return n+1`** —— `[1,2,3]` 时循环走完没有 return，Java 编译不过（缺 return 语句），Go 编译不过（缺 return）。**编译器会救你，但要知道为什么。**
7. **用负号标记法却撞上 `0`** —— `0` 取负还是 `0`，无法区分「见过」与「没见过」；本题输入允许 0，所以负号标记不是好选择。
8. **用负号标记法却撞上 `Integer.MIN_VALUE`** —— `Math.abs(Integer.MIN_VALUE)` 仍为 `-2147483648`，`-abs` 还是负数，标记失效且判断混乱。

### 038.6.3 面试官最爱追问的三个问题

**Q1：为什么答案一定不超过 `n+1`？**

> 「抽屉原理。数组只有 `n` 个数，把落在 `1..n` 范围内的值去重后最多 `n` 个。如果 `1..n` 全都出现了，那正好占满 `n` 个位置，最小的缺失正数就是 `n+1`；否则一定有某个 ≤ n 的值缺席。所以答案的上界是 `n+1`，这也解释了为什么只需要关心 `1 ≤ x ≤ n` 的值 —— 更小的值（≤0）不是正数，更大的值不可能成为『最小缺失』。」

**Q2：这个 `while` 嵌在 `for` 里，为什么不是 O(n²)？**

> 「用势能函数算：令 Φ = 已归位的元素个数，每次成功交换严格让 Φ 加 1（写入的座位 `x-1` 原本不归位，交换后变成 `x`），而 Φ ≤ n，所以成功交换总次数 ≤ n。`while` 的每次迭代要么成功交换（消耗一次势能增量），要么退出。因此内层总迭代 ≤ n，加上外层 n 次和收尾 n 次，整体 O(n)。这和 037 的『只从起点扩展』是同一类论证：**复杂度记在元素头上，不记在循环层数上。**」

**Q3：如果要求不能修改输入数组，还能做到 O(1) 空间吗？**

> 「不能同时做到 O(n) 时间和 O(1) 空间。可行的折中是**值域二分 + 计数**：在 `[1, n+1]` 上二分答案 `mid`，统计有多少个元素落在 `[1, mid]`；如果个数等于 `mid`，说明 `1..mid` 都在，答案在右半，否则在左半。每轮扫一遍数组，共 `log n` 轮，时间 `O(n log n)`、空间 `O(1)`、**只读**。这条思路也正是 LC 287 的二分计数解（见 `039`），因为那道题明令禁止改数组。」

