## 048.1 题目

**原题链接**：<https://leetcode.cn/problems/add-two-numbers/>

### 题意重述（把隐含条件补齐）

给你两个**非空**链表，表示两个非负整数。它们每位数字都是**逆序**存储的（个位在头结点），并且每个结点只存一位数字。请把这两个数相加，并以**同样形式**（逆序、每位一个结点）返回一个链表。

四个必须读出来的条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **逆序存储**（个位在前） | 「数字是按照逆序的方式存储的」 | 这是本题最大的红利：**从低位到高位正好是遍历顺序**，不需要反转链表 |
| **每个结点只存一位** | 「每个节点只存储一位数字」 | 不存在「一个结点存两位」的省事写法 |
| **两个数都没有前导零** | 「除了数字 0 之外，这两个数都不会以 0 开头」 | 所以 `[0]` + `[0]` 是唯一的「单个 0」情况，结果不允许出现多余的高位 0 |
| **长度可达 100 位** | `1 <= 结点数 <= 100` | **绝对不能用 `int` / `long` 转数值**：10¹⁰⁰ 远超 int64（≈9.2·10¹⁸） |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= 每条链结点数 <= 100` | 最多 100 位十进制数 | 任何 O(n) 都过；但 `10^100` 必须用「逐位模拟」或大整数库 |
| `0 <= Node.val <= 9` | 单个十进制位 | 加法规则简单：`sum % 10` 与 `sum / 10` |
| 链表逆序 | 关键前提 | **不需要反转链表**：遍历方向 = 加法方向 |
| 允许结果比两个数都长一位 | `99 + 1 = 100` | 循环条件必须带 `carry != 0`，否则丢最高位 |

> 💡 **量级 → 算法**：`100 位` 是一个精确的信号。它告诉你两件事：① 数值转成 `long` 一定溢出（`long` 只有 19 位十进制精度）；② 但 `100` 又小到「逐位模拟」绝对够快。**这类题的出题意图就是逼你放弃数值运算，改用「和手算一样的模拟」。**

### 示例

```text
输入：l1 = [2,4,3], l2 = [5,6,4]
输出：      [7,0,8]
解释：342 + 465 = 807，逆序存成 7 → 0 → 8

输入：l1 = [0], l2 = [0]
输出：      [0]

输入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
输出：      [8,9,9,9,0,0,0,1]
解释：9999999 + 9999 = 10009998，逆序为 8,9,9,9,0,0,0,1
```

### 我自造的七个反例（写完必须逐个跑）

```text
① [0] + [0]                     → 结果必须是单个 0，不能是 [] 也不能是 [0,0]
② [5] + [5]                     → 10：最后还要额外进一位，验证 carry != 0 的循环条件
③ [9,9,9] + [1]                 → 1000：一条链只有 1 位，另一条 3 位，长度差极大
④ [1] + [9,9,9]                 → 与 ③ 对称，验证「谁是 l1」不影响结果
⑤ [9,9,9,9,9,9,9] + [9,9,9,9]   → 连续进位链，carry 一路传 4 次
⑥ [0,1] + [0,2]                 → 值 10 + 20 = 30 → [0,3]；验证「高位单个 0」不会被误判成前导零
⑦ [1,0,0,...,0]（100 位）+ [1]  → 100 位规模，绝对不能转 int64
```

第 ② 条是最经典的：`5 + 5 = 10`，两个一位数相加却得到两位数。**只要循环条件写成 `l1 != null || l2 != null` 而漏了 `carry != 0`，这一条必然错。**

第 ⑥ 条容易被「去前导零」的习惯误伤：注意本题的「前导零」在**链表尾部**（高位），而题目保证输入没有；输出也不该有。但 `[0,1]` 表示 10，其高位是 1，是合法的，不是前导零。

## 048.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（把链表还原成数字再相加）

```text
n1 = 0; p = 1
for x in l1: n1 += x * p; p *= 10
n2 = 0; p = 1
for x in l2: n2 += x * p; p *= 10
sum = n1 + n2
把 sum 拆成数字，逆序建链
```

- 时间 O(n)，空间 O(n)。
- **`n = 100` 时直接崩**：`10^100` 需要约 333 个二进制位，`int` 只有 31 位、`long` 只有 63 位。**溢出不是精度丢失，是彻底的错误答案。**
- 即使用 `BigInteger` / `big.Int`（Java 的 `BigInteger`、Go 的 `math/big`）能算出来，它也**绕过了这道题的全部考点**：面试官想看的是你自己实现逐位进位，而不是调库。

> **量化一下**：`2^63 - 1 ≈ 9.22·10^18`，即 `long` 最多表示 19 位十进制数。题目给 100 位。**差了 81 个数量级**。所以这条路在 n ≥ 20 时就死了。

### 第二步：卡点在哪 —— 不是「相加」，是「进位要跨轮传」

如果真的写出逐位相加，你会发现真正的麻烦只有一处：

```text
  3 4 2
+ 4 6 5
-------
  8 0 7      ← 个位 2+5=7；十位 4+6=10 写 0 进 1；百位 3+4+1=8
```

**「十位算出来的 1 要留给百位用」**。也就是说：**第 i 轮的结果依赖于第 i-1 轮的输出**。这叫**跨轮状态**。

这就是本类题和 047（合并有序链）的本质差别：

| | 047 合并 | 048 相加 |
| --- | --- | --- |
| 每一轮依赖 | 只依赖当前两个结点的值 | 依赖当前两个结点的值 **+ 上一轮的进位** |
| 状态 | 无 | `carry ∈ {0, 1}` |
| 额外终止条件 | 一方走完即可 | 双方都走完**还不够**，`carry` 必须为 0 |

一个 `int carry` 就解决了全部问题。**难的不是「加法」，是「想到把进位提取成一个显式变量」**，以及「把 `carry` 也写进循环的终止条件」。

### 第三步：灵感的来源 —— 三个观察

**观察 1：逆序存储 = 遍历顺序就是加法顺序。**

手算加法是从个位开始的，而链表的头就是个位。所以**不需要反转链表**，直接正序遍历就是「从低位到高位」。这是题目故意设计的红利 —— 对比 445 题（正序存储）就得多一个反转或栈。

**观察 2：循环条件要写三条。**

```text
while (l1 != null || l2 != null || carry != 0)
```

- `l1 != null`：`l1` 还有位
- `l2 != null`：`l2` 还有位
- `carry != 0`：**两个都走完了，但还有进位没落地**（`5 + 5 = 10` 的情形）

少写第三条，`[5] + [5]` 会输出 `[0]` 而不是 `[0,1]`。

**观察 3：每轮先取 `carry`，再累加。**

```text
int sum = carry;               // ① 先把上一轮的进位放进来
if (l1 != null) { sum += l1.val; l1 = l1.next; }
if (l2 != null) { sum += l2.val; l2 = l2.next; }
tail.next = new ListNode(sum % 10);
carry = sum / 10;
```

顺序很重要：`sum` 必须从 `carry` 起步。如果写成 `sum = 0` 然后忘了加 `carry`，进位的效果就丢了；如果写成先加结点值再加 `carry`，也能对，但「`sum` 的初值是什么」在面试时更难解释清楚 —— **从 `carry` 起步是最不容易错的写法**。

> 顺带一个细节：`carry` 只可能是 0 或 1，因为 `9 + 9 + 1 = 19 < 20`。所以 `sum` 最大 19，`int` 完全够。

### 另一条路：递归

```text
add(l1, l2, carry):
    if l1 == null && l2 == null && carry == 0: return null
    sum = carry + (l1 ? l1.val : 0) + (l2 ? l2.val : 0)
    node = new ListNode(sum % 10)
    node.next = add(l1 ? l1.next : null, l2 ? l2.next : null, sum / 10)
    return node
```

它把「进位」从变量变成了**函数参数**，递归结构极干净。代价：深度 = 结果长度（最多 101），完全无压力。**这题的递归版是安全的**（不像 044 / 047 有长链风险），所以可以作为「两种解法都行」的正面例子。

## 048.3 原理拆解

### 048.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 转 `int` / `long` 再相加 | O(n) | O(n) | 15 行 | **n ≥ 20 就溢出**，本题 100 位直接错 |
| 转字符串 + 大整数库 | O(n²)（库内部） | O(n) | 10 行 | 面试禁用；且掩盖了考点 |
| **逐位迭代 + carry** ✅ | **O(n)** | **O(n)**（结果链） | **18 行** | 几乎不会输；注意循环条件三条 |
| 递归 | O(n) | O(n)（栈 + 结果） | 10 行 | 无（本题深度 ≤ 101，安全） |
| 先反转链表再逐位算 | O(n) | O(1) | 25 行 | **多余**：本题已是低位在前，反转纯属自找麻烦 |

**为什么迭代版最优**：一次遍历、O(1) 额外空间（不算结果链）、无递归、进位语义显式。递归版同样正确，可作为对照答案。

### 048.3.2 为什么这个做法是对的（正确性论证）

先把「链表表示的数」形式化：链表 `l = [d0, d1, …, dk]` 表示 `N(l) = Σ di·10^i`。

**循环不变量**（每轮开始前）：

> ① 已经挂到 `tail` 上的结点序列为 `r0, r1, …, r_{t-1}`；
> ② `carry` 满足 `carry·10^t + Σ_{i<t} ri·10^i = (l1 已消耗的低 t 位之和) + (l2 已消耗的低 t 位之和)`；
> ③ `l1`、`l2` 分别指向各自尚未处理的最低位数字（或 `null`）。

**初始化**（t = 0）：两侧都是 0，`carry = 0`。成立。

**保持**：设本轮取出 `d1`（`l1` 当前位，若无则 0）、`d2`（同理）。令 `s = carry + d1 + d2`，写出 `s = 10·carry' + r`（`r = s % 10`，`carry' = s / 10`）。

- 挂上 `r`：新序列为 `r0..r_{t-1}, r`。
- 代入 ②：`carry'·10^{t+1} + Σ_{i≤t} ri·10^i = 10·carry'·10^t + (carry·10^t + Σ_{i<t} ri·10^i) + r·10^t`
  = `(10·carry' + carry)·10^t + ...`。而 `s = 10·carry' + r`，其中 `carry·10^t` 里的 `carry` 正是上一轮传下来的 —— 把 `carry·10^t` 与 `(d1 + d2)·10^t` 合并即得 `s·10^t = (10·carry' + r)·10^t`。于是 ② 在新 t+1 上成立。

**终止**：循环退出时 `l1 == l2 == null` 且 `carry == 0`。由 ②，`Σ ri·10^i = N(l1) + N(l2)`（因为双方所有位都已消耗）。所以结果链表示的数正好是两数之和。

**再无多余前导零**：`ri = s % 10`，而每轮 `s ≥ 1`（因为进入循环时至少有一项非零：要么有位可取，要么 `carry = 1`）。数字 0 的情况是 `[0] + [0]`：第 1 轮 `s = 0`，挂 `0`，`carry = 0`，双方已空 → 循环结束，结果是 `[0]`，正确；不会挂出第二个 0。∎

**关于「最高位不能为 0」的补充**：如果 `l1`、`l2` 的最高位加起来没有进位，则最后一轮 `carry = 0`，不会多挂结点 —— 因为 `carry != 0` 是进入循环的必要条件之一。∎

> **这个论证的价值**：它把「`carry` 的语义」写成了一个等式 `s = 10·carry' + r`，而这个等式恰好就是小学竖式加法的定义。**凡是「低位在前 + 逐位进位」的题（正序版 445、字符串版 415、K 进制版），正确性论证都是同一个模子。**

### 048.3.3 通用解题思路（可迁移的那一层）

**链表章的统一语言：哑结点 + 指针三件套（prev/cur/next）+ 先存后断。** 048 加了第四样东西：**跨轮状态**。

```
原始问题：两个大整数相加
         ↓ 数值运算会溢出（100 位 > long 的 19 位）
降级：    改成「逐位模拟 + 进位」
         ↓ 需要一个变量承载「跨轮信息」
关键：    int carry —— 上一轮的输出变成下一轮的输入
         ↓ 三条终止条件（两个链表 + carry）
终止：    l1 != null || l2 != null || carry != 0
         ↓ 答案容器
外壳：    dummy + tail 尾插
```

**「跨轮状态」是这一类题的通用零件**，它出现在很多看起来无关的题里：

| 题 | 跨轮状态 | 状态的意义 |
| --- | --- | --- |
| [LC 2 两数相加](https://leetcode.cn/problems/add-two-numbers/) | `carry` | 上一轮的进位 |
| [LC 445 两数相加 II](https://leetcode.cn/problems/add-two-numbers-ii/) | `carry`（+ 栈反转顺序） | 同上，但方向反了 |
| [LC 415 字符串相加](https://leetcode.cn/problems/add-strings/) | `carry` | 同上，容器换成字符串 |
| [LC 1290 二进制链表转整数](https://leetcode.cn/problems/convert-binary-number-in-a-linked-list-to-integer/) | `ans` | 每一轮 `ans = ans*2 + bit` |
| [LC 2 的乘法版 43](https://leetcode.cn/problems/multiply-strings/) | `carry` + 位置数组 | 进位位置不止一处 |
| [LC 67 二进制求和](https://leetcode.cn/problems/add-binary/) | `carry` | 同构，进制从 10 换成 2 |

**判断标志**：如果第 i 轮的计算需要第 i-1 轮的结果（不是只依赖输入），那就抽一个状态变量出来。**这就是「状态机」这把尺子在链表题里的最小形态。**

属于同一模型的题：

| 题 | 容器 | 状态 | 方向 |
| --- | --- | --- | --- |
| [LC 2](https://leetcode.cn/problems/add-two-numbers/) | 链表（尾插） | carry | 低位 → 高位（天然） |
| [LC 445](https://leetcode.cn/problems/add-two-numbers-ii/) | 链表（头插或先反转） | carry | 低位 → 高位（需反转） |
| [LC 415](https://leetcode.cn/problems/add-strings/) | 字符串 | carry | 低位 → 高位（从尾部） |
| [LC 66 加一](https://leetcode.cn/problems/plus-one/) | 数组 | carry | 低位 → 高位 |
| [LC 989 数组形式的整数加法](https://leetcode.cn/problems/add-to-array-form-of-integer/) | 数组 | carry | 低位 → 高位 |

### 048.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **正序**存储（445 题） | 遍历方向与加法方向相反 | 两条链各自反转一次（或压栈），算完再反转回来；或递归到底部再回溯进位 |
| 改成**K 进制** | `% 10` → `% K`，`/ 10` → `/ K` | 逻辑不变，常量换成 K；`carry` 范围变成 `[0, K-1]` |
| 要求**减法** | 会出现负数 | 先比较大小定符号，再用「借位」代替进位；借位状态是 `-1 / 0` |
| 要求**乘法**（43 题） | 进位位置不唯一 | 结果数组 `res[i+j+1] += a[i]*b[j]`，最后统一处理进位 |
| 链表**只读**（不能改原链） | 已经在新建结点，天然满足 | 注意不要复用输入结点 |
| **超长**（10⁶ 位） | 递归会爆 | 只能迭代；且要考虑分配 10⁶ 个结点本身的开销 |

## 048.4 图解推演

### 048.4.1 进位怎么跨轮传递（`[2,4,3] + [5,6,4]`）

```text
l1:  2 ──→ 4 ──→ 3 ──→ ∅        表示 342
l2:  5 ──→ 6 ──→ 4 ──→ ∅        表示 465

第 1 轮：carry=0
   sum = 0 + 2 + 5 = 7
   挂 [7]，carry = 7/10 = 0
   dummy → [7]

第 2 轮：carry=0
   sum = 0 + 4 + 6 = 10
   挂 [0]，carry = 1          ← 这就是「跨轮状态」
   dummy → [7] → [0]

第 3 轮：carry=1
   sum = 1 + 3 + 4 = 8
   挂 [8]，carry = 0
   dummy → [7] → [0] → [8]

第 4 轮：l1、l2 都空，carry = 0 → 循环结束
结果：7 → 0 → 8   即 807 ✅
```

### 048.4.2 最后还要额外进一位（`[5] + [5]`）

```text
l1: 5 → ∅       l2: 5 → ∅

第 1 轮：sum = 0+5+5 = 10 → 挂 [0]，carry = 1
第 2 轮：l1、l2 已空，但 carry = 1 ≠ 0 → 继续！
        sum = 1 + 0 + 0 = 1 → 挂 [1]，carry = 0
第 3 轮：全空且 carry = 0 → 结束

结果：0 → 1   即 10 ✅

如果循环条件漏掉 carry != 0：
  第 2 轮不会执行，结果只剩 [0]，输出 0 ❌
```

### 048.4.3 每轮状态表（`[9,9,9,9,9,9,9] + [9,9,9,9]`）

| 轮 | `l1.val` | `l2.val` | 进入时 `carry` | `sum` | 挂上的位 | 出去时 `carry` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 9 | 9 | 0 | 18 | 8 | 1 |
| 2 | 9 | 9 | 1 | 19 | 9 | 1 |
| 3 | 9 | 9 | 1 | 19 | 9 | 1 |
| 4 | 9 | 9 | 1 | 19 | 9 | 1 |
| 5 | 9 | ∅ | 1 | 10 | 0 | 1 |
| 6 | 9 | ∅ | 1 | 10 | 0 | 1 |
| 7 | 9 | ∅ | 1 | 10 | 0 | 1 |
| 8 | ∅ | ∅ | 1 | 1 | 1 | 0 |
| 9 | ∅ | ∅ | 0 | — | 循环结束 | — |

结果：`8,9,9,9,0,0,0,1` → 表示 10009998 ✅（`9999999 + 9999 = 10009998`）

### 048.4.4 三条终止条件的必要性

```text
                    ┌──────── 循环继续吗？ ────────┐
                    │                              │
       l1 还有位 ────┤                              ├──── 需要继续
       l2 还有位 ────┤                              │
       carry ≠ 0 ────┘                              │
                                                    ↓
                            三者全为假 → 退出，结果已完整

┌────────────────── 少写一条会怎样 ──────────────────┐
│ 少 l1 != null   → l1 比 l2 长时，高位全丢           │
│ 少 l2 != null   → 对称，l2 长时高位全丢             │
│ 少 carry != 0   → 5+5=10 变成 0，最高进位丢失        │
└────────────────────────────────────────────────────┘
```

## 048.5 双语言实现

### 048.5.1 Java

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}

class Solution {
    public ListNode addTwoNumbers(ListNode l1, ListNode l2) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        int carry = 0; // 两个一位数相加，进位只可能是 0 或 1

        // carry != 0 这一项专门处理 99 + 1 = 100 这种「最后还要进一位」
        while (l1 != null || l2 != null || carry != 0) {
            int sum = carry; // ① 必须从 carry 起步，否则进位丢失
            if (l1 != null) {
                sum += l1.val;
                l1 = l1.next;
            }
            if (l2 != null) {
                sum += l2.val;
                l2 = l2.next;
            }
            tail.next = new ListNode(sum % 10); // ② 本位
            tail = tail.next;
            carry = sum / 10;                   // ③ 进位，跨轮状态
        }
        return dummy.next;
    }

    // 递归版：carry 变成函数参数，结构最干净
    public ListNode addTwoNumbersRec(ListNode l1, ListNode l2) {
        return addRec(l1, l2, 0);
    }

    private ListNode addRec(ListNode l1, ListNode l2, int carry) {
        if (l1 == null && l2 == null && carry == 0) {
            return null; // 三条终止条件与迭代版一一对应
        }
        int sum = carry;
        if (l1 != null) {
            sum += l1.val;
        }
        if (l2 != null) {
            sum += l2.val;
        }
        ListNode node = new ListNode(sum % 10);
        node.next = addRec(l1 == null ? null : l1.next,
                           l2 == null ? null : l2.next,
                           sum / 10);
        return node;
    }
}
```

**四处「为什么」**：

1. `int sum = carry;` 放在最前面：让「进位」天然参与本轮计算，避免忘了加。
2. `sum % 10` 与 `sum / 10` 配对：`sum` 最大 19（9+9+1），所以商只可能是 0 或 1，`int` 完全安全。
3. 循环条件三条全要：少一条就丢位或丢进位。
4. 递归版里 `l1 == null ? null : l1.next` 不能省：`l1` 为空时直接 `.next` 会 NPE。

### 048.5.2 Go

```go
package main

type ListNode struct {
	Val  int
	Next *ListNode
}

// 逐位相加 + 进位状态；链表是「低位在前」，所以正序遍历就是从低位到高位
func addTwoNumbers(l1 *ListNode, l2 *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	carry := 0 // 进位只有 0 / 1
	for l1 != nil || l2 != nil || carry != 0 {
		s := carry // 循环条件里的 carry != 0 就是为了处理「最后还进一位」
		if l1 != nil {
			s += l1.Val
			l1 = l1.Next
		}
		if l2 != nil {
			s += l2.Val
			l2 = l2.Next
		}
		tail.Next = &ListNode{Val: s % 10}
		tail = tail.Next
		carry = s / 10
	}
	return dummy.Next
}

// 递归版：carry 作为参数往下传
func addTwoNumbersRec(l1, l2 *ListNode) *ListNode {
	return addRec(l1, l2, 0)
}

func addRec(l1, l2 *ListNode, carry int) *ListNode {
	if l1 == nil && l2 == nil && carry == 0 {
		return nil
	}
	s := carry
	var n1, n2 *ListNode
	if l1 != nil {
		s += l1.Val
		n1 = l1.Next
	}
	if l2 != nil {
		s += l2.Val
		n2 = l2.Next
	}
	return &ListNode{Val: s % 10, Next: addRec(n1, n2, s/10)}
}
```

### 048.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 取「下一结点」 | 直接 `l1.next`（已判空） | 直接 `l1.Next`（已判空） | 一致；但 Go 的递归版若在 `if` 内赋值会污染外层变量，所以用 `n1`/`n2` 中转 |
| 结点构造 | `new ListNode(sum % 10)` | `&ListNode{Val: s % 10}`（字面量） | Go 支持一次写 `Val` + `Next`，递归版可以单行返回 |
| 三元表达式 | 有 `? :` | **无** | Go 递归版改用 `n1`/`n2` 变量绕过，比嵌套 if 更清楚 |
| `int` 宽度 | 恒 32 位 | 64 位平台上 64 位 | 本题 `sum ≤ 19`，两者都安全；但如果改成 K = 10⁹ 进制，Java 需换 `long` |
| 空切片 / 空指针 | `null` | `nil` | 判空写法不同 |
| `dummy` 的 `Val` | 构造器必须传参，顺手给 0 | `&ListNode{}` 零值即可 | 本题不读 dummy 的 `Val`，无影响 |

func build(a []int) *ListNode {

		t.Next = &ListNode{Val: v}

	}

func dump(h *ListNode) []int {
	out := []int{}

			panic("疑似成环")
		}
	}
	return out

// bigFromDigits 把「低位在前」的数字切片转成大整数
func bigFromDigits(a []int) *big.Int {
	s := ""
	for i := len(a) - 1; i >= 0; i-- {
		s += string(rune('0' + a[i]))
	}
	v := new(big.Int)
	v.SetString(s, 10)
	return v

func TestAddTwoNumbersRandom(t *testing.T) {
	r := rand.New(rand.NewSource(48))
	for iter := 0; iter < 20000; iter++ {
		n1 := 1 + r.Intn(10)
		n2 := 1 + r.Intn(10)
		a := make([]int, n1)
		b := make([]int, n2)
		for i := range a {
			a[i] = r.Intn(10)
		}
		for i := range b {
			b[i] = r.Intn(10)
		}
		// 题目保证没有前导零：在「低位在前」的表示里，就是尾部不能有多余 0
		for len(a) > 1 && a[len(a)-1] == 0 {
			a = a[:len(a)-1]
		}
		for len(b) > 1 && b[len(b)-1] == 0 {
			b = b[:len(b)-1]
		}

		}

		if len(got) > 1 && got[len(got)-1] == 0 {

		}

		{[]int{1}, []int{9, 9, 9}, []int{0, 0, 0, 1}},
		{[]int{9, 9, 9, 9, 9, 9, 9}, []int{9, 9, 9, 9}, []int{8, 9, 9, 9, 0, 0, 0, 1}},
		{[]int{0, 1}, []int{0, 2}, []int{0, 3}},

		got := dump(addTwoNumbers(build(c.a), build(c.b)))

## 048.6 复杂度与常见坑

### 048.6.1 复杂度推导

- **时间 O(max(m, n))**：循环次数 = `max(m, n) + 1`（最后可能多一轮处理进位）。每轮常数次加法与取模。
  - 精确地说，是 `max(m, n)` 轮处理所有位，再加最多 1 轮处理最终进位。
- **空间 O(max(m, n))**：结果链最多 `max(m, n) + 1` 个结点。这是**输出本身的成本**，不是额外空间。
  - **额外空间**：`dummy`、`tail`、`l1`、`l2`、`carry`，共 O(1)。
  - 如果题目要求「不能新建结点、必须复用输入」，那就在长链上原地改值（但本题要求返回新链，不适用）。
- **`sum` 不会溢出**：最大 `9 + 9 + 1 = 19`，`int`（32 位）绰绰有余。这一点要能主动说出来，因为它决定了「不需要 long」。

### 048.6.2 八个真实踩过的坑

1. **循环条件漏 `carry != 0`** —— `5 + 5` 输出 `0`。最高频错误。
2. **`sum` 初值写成 0 忘了加 `carry`** —— 所有进位丢失，`[9,9,9] + [1]` 输出 `[0,9,9]`。
3. **先写 `l1 = l1.next` 再取 `l1.val`** —— 取到的是下一位，整体错位。必须「先取值，再前进」。
4. **`l1 == null` 时直接取 `l1.next`** —— NPE / nil 解引用。必须先判空再取。
5. **用 `int` 或 `long` 还原数值** —— 100 位直接溢出。这是本题的头号「降级陷阱」。
6. **结果链用了输入链的结点** —— 题目可以接受（不影响判题），但如果后续还要用输入就会出问题；更重要的是，复用结点会让「结果比输入长」时无处安放。
7. **误以为结果要去掉「尾部的 0」** —— 本题的 0 在尾部是**高位 0**，输入保证没有，输出也不会有；但 `[0] + [0] = [0]` 的 0 是合法结果，不能去掉。
8. **正序 / 逆序搞混** —— 把 `[2,4,3]` 当成 243 而不是 342，结果反着算，几乎必然错。**读题第一件事是确认方向。**

### 048.6.3 面试官最爱追问的三个问题

**Q1：为什么不能把链表转成整数再相加？**
> 「因为位数。`long` 只有 63 位二进制，约 19 位十进制，而题目给到 100 位，`10^100` 比 `long` 的上限大 81 个数量级，溢出后不是精度损失而是完全错误的结果。就算用 `BigInteger` 能算，也绕过了这道题的考点 —— 面试要看的是你自己实现进位。所以正确做法是把『数值运算』降级成『逐位模拟』，用 `carry` 串起来。」

**Q2：`carry` 会不会超过 1？需要 `long` 吗？**
> 「不会。每一位最大 9，两个 9 加一个进位是 19，所以 `carry ∈ {0, 1}`，`sum ≤ 19`。`int` 完全够，不需要 `long`。如果换成 K 进制（比如 K = 10⁹ 的「块状」表示），那 `sum` 最大 `2K - 1`，这时 Java 的 `int` 就可能溢出，需要 `long` —— 所以『要不要 long』取决于进制，不取决于位数。」

**Q3：如果链表是正序存储的（445 题）怎么办？**
> 「三条路：① 两条链各自反转一次，算完再反转结果 —— O(n) 时间、O(1) 空间，最直接；② 把两条链压进两个栈，弹出时就是从低位到高位 —— O(n) 空间但代码最短；③ 递归到链尾，在回溯时做加法并向上返回进位 —— O(n) 栈。我会选 ①，因为它是唯一 O(1) 额外空间的，而且复用了第 044 章的反转模板。」
