## 118.1 题目

**原题链接**：<https://leetcode.cn/problems/perfect-squares/>

### 题意重述（把隐含条件补齐）

给一个正整数 `n`，问：最少用**几个完全平方数**（`1, 4, 9, 16, …`）**相加**能得到 `n`？返回这个个数。

一句话就完了，但它藏了七个必须读出来的约束：

| 隐含条件 | 出处 | 读错了会怎样 |
| --- | --- | --- |
| **`1` 算完全平方数** | 「完全平方数是一个整数，其值等于另一个整数的平方」→ `1 = 1²` | 把 `1` 排除掉 → `n = 2` 会答无解，而正确是 `1 + 1 = 2` 个 |
| 求的是**最少个数**，不是方案数 | 「返回和为 `n` 的完全平方数的**最少数量**」 | 用加法转移 → 算成方案数（`n = 12` 会给出「多少种拆法」，那是另一个数） |
| 允许**重复使用**同一个平方数 | 「完全平方数」无使用次数限制 | 按 01 背包（每个平方数最多用一次）→ `n = 12` 会答 4（`9+1+1+1`），正确是 3 |
| 必须**恰好**等于 `n` | 「和为 n」 | 允许「不超过 `n`」→ 答案恒为 0（一个都不用） |
| 顺序不同**算同一种** | 求和与顺序无关 | 对 `min` 而言顺序天然无差别，但如果误按排列数写，`n = 12` 会算出几十种；本题根本不问方案数 |
| `n` 至少为 1 | `1 <= n <= 10000` | `n = 0` 是「0 个平方数」的边界（本题不出现，但变体里常见） |
| **答案一定在 `{1,2,3,4}` 里** | 拉格朗日四平方定理 | 不知道这条也能做 DP，但你就答不出「为什么最大是 4」以及 §118.2 的数学解法 |

> 📌 **本题的独特之处**：它是整个背包家族里唯一一个**答案值域被数论完全锁死**的题。116 的答案可以大到 `amount`，117 的答案可以大到天文数字，而本题的答案**只可能是 1、2、3、4**。这个「值域极小」的事实就是数学解法全部的空间。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 10^4` | 容量很小 | 背包可行的硬前提：`Σ_{i≤n} √i ≈ (2/3)·n^{1.5} = 6.7·10^5` 次比较，本机实测 **≈ 0.8 ms** |
| 物品集合固定为 `{j²}` | 不用输入 | 物品数是 `⌊√n⌋ = 100`，不是 `n`；这决定了内层循环只有 100 轮 |
| 答案 ∈ `{1,2,3,4}` | 数论结论 | 可以用「判据」直接定位答案，不需要填整张表 → `O(√n)` |
| 无取模 | — | 答案最大 4，任何语言都不溢出 |

> 💡 **量级 → 算法**：`n ≤ 10^4` 时 O(n√n) 的背包又快又好写，**面试首选**。但请注意这里有两把完全不同的尺子：
> - **按容量看**：`n` 小 → 伪多项式背包可行；
> - **按答案看**：答案只有 4 种取值 → 存在「不需要 DP」的数论判定。
>
> 面试官问「`n = 10⁹` 怎么做」时，考的就是你脑子里有没有第二把尺子。

### 示例

```text
输入：n = 12
输出：3
解释：12 = 4 + 4 + 4（三个平方数）。
      ← 贪心会给出 9 + 1 + 1 + 1 = 4 个，这是本题最经典的错误，见 §118.2

输入：n = 13
输出：2
解释：13 = 4 + 9

输入：n = 1
输出：1
解释：1 = 1²   （「1 是平方数」这条隐含条件在这里第一次起作用）

输入：n = 7
输出：4
解释：7 = 4 + 1 + 1 + 1（三个平方数凑不出 7，必须四个）—— 答案 4 的最小例子
```

### 我自造的七个反例（写完解法必须拿它们打一遍）

```text
① n = 1      → 1；暴露「1 不是平方数」的错法
② n = 12     → 3（4+4+4）；**贪心答 4**（9+1+1+1）—— 本章核心反例
③ n = 7      → 4（4+1+1+1）；答案 4 的最小例子，任何「最多 3 个」的假设在这里崩
④ n = 28     → 4（28 = 4·7）；暴露「漏掉 4^a 这一步」的数学解错法
⑤ n = 13     → 2（4+9）；暴露「判完 1 就直接落到 3」的错法
⑥ n = 9999   → 4（9999 = 8·1249+7）；`n` 很大时答案仍然是 4，检验数学解不依赖表
⑦ n = 10000  → 1（100²）；暴露浮点开根在「恰好是完全平方数」时的误差
```

第 ⑦ 条特别容易踩：`Math.sqrt(10000.0)` 在某些平台上可能返回 `99.99999999999999`，直接 `(int)` 截断就变成 99，于是 `99² ≠ 10000`，答案算错。§118.6.2 第 4 条给出修正写法。

## 118.2 从暴力到最优：第一个念头为什么错

### 第一个念头：贪心 —— 每次减掉最大的平方数

```text
n = 12：先减 9（剩 3），再减 1、1、1
        9 + 1 + 1 + 1 = 12，共 4 个     ❌

最优：  4 + 4 + 4 = 12，共 3 个         ✅

n = 18：贪心 16 + 1 + 1 = 3 个          ❌
最优：  9 + 9 = 2 个                    ✅
```

贪心输的原因和 116 里 `[1,3,4]` 凑 6 完全一样：**「每一步取最大的物品」是局部最优，而这个问题的最优解要求的是「总个数最少」**。用掉一个大平方数之后，剩下的余数可能特别难凑（只能靠一堆 1），反而亏。

> ⚠️ 这条错误值得单独记：**贪心在「完全背包求最少个数」这个模型里几乎总是错的**（除非物品系统是 canonical 的）。116 的硬币系统有 canonical 的特例，平方数系统没有 —— `n = 12` 与 `n = 18` 就是两个反例。

### 第二个念头：DFS 枚举所有拆法

```java
// 枚举「最后一个平方数」，不做记忆化
int f(int rest) {
    if (rest == 0) return 0;                       // 拆完，0 个
    int best = Integer.MAX_VALUE;
    for (int j = 1; j * j <= rest; j++) {
        best = Math.min(best, f(rest - j * j) + 1);
    }
    return best;
}
```

- 时间 `O(√n ^ √n)` 量级（每层最多 `√rest` 个分支，深度最多 `n`）：`n = 12` 时只几千次调用，`n = 100` 时就已经是 `10⁷` 量级，`n = 10⁴` 完全不可能。
- 空间 `O(n)`：递归深度最坏是 `n`（一路减 1）。

**重复子问题有多严重**：`f(12)` 会调 `f(11)`、`f(8)`、`f(3)`；`f(11)` 又会调 `f(10)`、`f(7)`、`f(2)`…… 同一个 `f(k)` 被不同路径反复求解，而它**只依赖 `k`**（与你「怎么走到 `k`」无关）—— 这就是无后效性。状态只有 `n + 1` 个，访问次数却是指数级。

### 第三步：卡点在哪 —— 「最少个数」到底等价于什么

卡点不是「想不出转移」，而是**没有认出这道题的两个等价面孔**：

> **面孔一（背包）**：`dp[i]` = 凑出 `i` 的最少平方数个数，`dp[i] = min_{j²≤i}(dp[i-j²] + 1)`。
>
> **面孔二（最短路）**：把 `0..n` 每个整数看成一个顶点；对每个 `a` 和每个 `j`（`a + j² ≤ n`）连一条 `a → a + j²`、边权 1 的边。问题是「从 0 到 `n` 的最短路径长度」。边权全为 1 ⇒ **BFS 的层数就是答案**。

这个等价关系和 116 章 §116.3.3 是**同一条**，只是把「加一枚硬币」换成「加一个平方数」。认出它之后，两件事同时到手：

1. 为什么 `n = 10⁴` 时 DP 不会 TLE（状态数 `10⁴`，每个状态 `100` 种转移）；
2. 为什么答案最大只有 4 —— 因为 BFS 只需 **4 层**就能覆盖 `[0, 10⁴]` 里的所有数（`n = 10⁴` 时第 4 层的顶点数已经超过 10⁴）。这实际上是拉格朗日四平方定理的**计算版证据**。

### 第四步：灵感的来源（一）—— 按「最后一个平方数」分类

设 `dp[i]` = 和为 `i` 的最少平方数个数。取和为 `i` 的最优方案，看它的**最后一项**，必是某个 `j²`（`j² ≤ i`）。去掉它，剩下的是「和为 `i - j²` 的最优方案」：

```text
dp[0] = 0
dp[i] = min over j ≥ 1, j² ≤ i of  ( dp[i - j²] + 1 )
```

**为什么只需要 `dp[i-j²]` 的最优值，而不枚举它所有的拆法？** 因为「个数」这个代价**可加**：任何更差的方案再加一项，仍然更差。这就是最优子结构，与 116 的「替换论证」逐字相同。

### 第五步：灵感的来源（二）—— 数论把答案锁死在 4 以内

上面第五步（面孔二）已经提示了：BFS 4 层就走完了。把这件事写成定理：

- **拉格朗日四平方定理（1770）**：每个非负整数都能表示成 **4 个**整数的平方和（允许 `0²`）。⇒ **答案 ≤ 4**。
- **答案 ≥ 1**（`n ≥ 1` 时不可能用 0 个平方数）⇒ 答案 ∈ `{1, 2, 3, 4}`。
- 再细分：
  - 答案是 1 ⟺ `n` 本身是完全平方数（定义）；
  - 答案是 2 ⟺ `n = a² + b²`（枚举 `a` 检验 `n - a²` 是否平方，这是充要的）；
  - 答案是 3 ⟺ 既不是 1 也不是 2，且**不是** `4^a(8b+7)` 型（勒让德三平方定理）；
  - 答案是 4 ⟺ `n = 4^a(8b+7)`。

**于是整张表都不需要了。** §118.3.2 会用「平方数模 8」和「除以 4 的下降论证」把这个判据说清楚。

## 118.3 原理拆解

### 118.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 贪心（每次减最大平方数） | `O(log n)` | `O(1)` | 6 行 | **答案就是错的**：`n = 12` 答 4（正确 3）、`n = 18` 答 3（正确 2） |
| DFS 枚举（无记忆化） | 指数级 | `O(n)` 栈 | 8 行 | `n ≥ 100` 就秒级；`10⁴` 不可能 |
| 记忆化 DFS | `O(n√n)` | `O(n)` + 栈 | 14 行 | 栈深度最坏 `n = 10⁴`（尚可，`10⁶` 会爆栈） |
| **完全背包（容量在外层，内层枚举 `j²`）** ✅ | **O(n√n)** | **O(n)** | **10 行** | `n ≥ 10⁷` 时表开不下 |
| 完全背包（物品在外层，内层容量正序） | `O(n√n)` | `O(n)` | 10 行 | 与上一行**结果完全相同**（`min` 可交换），只是中间表不同 |
| BFS（按层扩展） | `O(n√n)` | `O(n)` | 20 行 | 最坏情况（答案 4，要铺满 4 层）与背包同量级；但**能提前返回**，所以通常更快 |
| **四平方和定理判定（本题第二解）** ✅ | **O(√n)** | **O(1)** | **20 行** | 需要数论知识；且无法直接推广到「平方数改成别的东西」 |

**为什么正文给两个解**：
① 背包版是**通用模型**（换成硬币、立方数、任意物品集合都能用），面试必答；
② 定理版是**本题专属的降维打击**，`O(√n)` vs `O(n√n)` 在 `n = 10⁴` 上差距是 6700 倍（理论上），更重要的是它展示了一个可迁移的判断：**当「物品集合」有强数论结构时，先问有没有定理**。

### 118.3.2 为什么这个做法是对的（正确性论证）

#### （A）背包解的正确性

**命题**：设 `dp[i]` 为和为 `i` 的最少平方数个数，则 `dp[0] = 0`，且对 `i ≥ 1`：

```text
dp[i] = min_{j ≥ 1, j² ≤ i} ( dp[i - j²] + 1 )
```

**证明（按最后一项分类 + 替换论证）**：设 `s` 是 `i` 的最优方案，其最后一项为 `j*²`。去掉它得到和为 `i - j*²` 的方案 `s'`，项数为 `|s| - 1`。

**断言 `s'` 最优**：若存在项数更少的方案 `s''` 同为 `i - j*²`，则 `s''` 加上 `j*²` 是 `i` 的、比 `s` 更少的方案，与 `s` 最优矛盾。

于是 `|s| ≥ 1 + dp[i - j*²] ≥ min_j(dp[i-j²]+1)`；反向，对任意 `j`，把 `dp[i-j²]` 对应的方案接上 `j²` 就是 `i` 的合法方案，故 `dp[i] ≤ min_j(dp[i-j²]+1)`。两边夹得等号。∎

**遍历序的正确性**：转移只读 `dp[i - j²]`，下标严格小于 `i`。因此外层 `i` 从 1 **递增**就够（算到 `i` 时 `i-j²` 已经算好）。这一点与 116 的「内层正序、读本行新值」是同一件事的两种写法 —— **本题的「内层正序」被展平成了「外层 `i` 递增、内层枚举物品」，而因为求的是 `min`，两个循环谁在外层结果都一样**（见 §118.3.3 的判据）。

#### （B）定理解的判定顺序

先给出三个集合的**包含链**，它是「判定顺序可以随便排」的全部依据：

```text
{ n = 1 个平方 }  ⊂  { n = 2 个平方 }  ⊂  { n = 3 个平方 }  ⊂  { n = 4 个平方 } = 全部正整数
    (加 0²)             (加 0²)              (加 0²)                    ← 拉格朗日定理
```

因为每层都是「补一个 `0²`」（`0` 是整数，`0²` 允许），所以**一个数若能用 `k` 个平方表示，就一定能用更多个表示**。于是四个集合**两两不交地切分**了正整数（按「最少用几个」分类），任一 `n` 只属于其中恰好一个。

**必要条件（这一半是可验证的硬功夫）**：

**引理 1（模 8 障碍）**：若 `n ≡ 7 (mod 8)`，则 `n` 不能表示成 3 个平方数之和。
**证明**：平方数模 8 只能是 `0, 1, 4`（偶数平方 ≡ 0 或 4，奇数平方 ≡ 1）。三个这样的数相加，模 8 的可能取值穷举如下：

| 三个平方数模 8 | 和模 8 |
| --- | --- |
| `0+0+0` | 0 |
| `0+0+1` | 1 |
| `0+1+1` | 2 |
| `1+1+1` | 3 |
| `0+0+4` | 4 |
| `0+1+4` | 5 |
| `1+1+4` | 6 |
| `0+4+4` | 0（8） |
| `1+4+4` | 1（9） |
| `4+4+4` | 4（12） |

取值集合是 `{0,1,2,3,4,5,6}` —— **唯独没有 `7`**。∎

**引理 2（提出 4 的因子）**：若 `n = 4m` 且 `n = x²+y²+z²`，则 `x, y, z` 全是偶数。
**证明**：平方数模 4 只能是 `0` 或 `1`。三个这样的数相加 ≡ 0 (mod 4) 只有两种可能：三个都是 `0`，或者三个都是 `1`。若是三个都是 `1`，则 `x, y, z` 全为奇数，于是 `x² ≡ y² ≡ z² ≡ 1 (mod 8)`，和 `≡ 3 (mod 8)`；但 `n = 4m ≡ 0` 或 `4 (mod 8)`，矛盾。所以只能三个全为 `0`，即 `x, y, z` 都是偶数。∎

由引理 2，`n = 4m` 能用 3 个平方表示 ⟺ `m` 能用 3 个平方表示（除以 2 与乘以 2 互逆）。反复用，就把「4 的因子」全部剥掉：

```text
n 至少需要 4 个平方  ⟺  剥光 4 的因子后剩下的 m 满足 m ≡ 7 (mod 8)
                     ⟺  n = 4^a · (8b + 7)
```

**充分性（这一半是数论的深水区，这里如实说明）**：勒让德三平方定理的完整证明（即「若 `n ≠ 4^a(8b+7)`，则 `n` 一定能写成 3 个平方数之和」）需要二次型 / 高斯三元二次型理论，属于《算术研究》级别的结果，不在面试考察范围内。而拉格朗日四平方定理的证明路线是「欧拉四平方恒等式（两个四平方和之积仍是四平方和）把问题归约到素数 + 对每个素数 `p` 用鸽笼论证找出 `a²+b²+c²+1 ≡ 0 (mod p)`，再用下降法得到 `p` 本身是四平方和」。**知道结论、知道「模 8 与除以 4」这两个可自行验证的必要条件、知道证明属于哪条路线，就是面试的合理标准。**

#### （C）判定顺序表

| 答案 | 判据 | 依据 | 代价 |
| --- | --- | --- | --- |
| **4** | `n = 4^a(8b+7)`，即「反复除以 4 之后 `m % 8 == 7`」 | 勒让德三平方定理 | `O(log n)` |
| **1** | `⌊√n⌋² == n` | 完全平方数定义 | `O(1)` |
| **2** | 存在 `a ≥ 1` 使 `n - a²` 是完全平方数 | 二平方和定义（枚举是充要判定） | `O(√n)` |
| **3** | 以上都不成立 | 拉格朗日（≤4）+ 勒让德（排除 4）+ 前三条（排除 1、2） | `O(1)` |

**为什么这个顺序是安全的**：由上文的包含链，「答案是 1 / 2 / 4」三类**两两不交**，所以先后顺序不影响正确性。但**必须全部检查过再落到 3**：

```text
❌ 只写「1 → 2 → else 3」   n = 7 会走到 else ⇒ 答 3，正确是 4
❌ 只写「1 → 4 → else 3」   n = 13 会走到 else ⇒ 答 3，正确是 2
✅ 「4 → 1 → 2 → 3」       三条判据 + 一个兜底，缺一不可
```

> 🔑 **把「4 的判定」放在最前的两个理由**：① 它是 `O(log n)` 的，最便宜；② 它是**唯一一条能把 `7, 23, 28, 9999` 这类数从「3」里捞出来**的判据 —— 一旦漏掉，答案会系统性地偏低（`1..10⁴` 里有 **1665** 个数会被判错，占 16.65%，见 §118.5.4 的实测分布）。

### 118.3.3 通用解题思路（可迁移的那一层）

**模型一：完全背包求最少个数**（本题第一解）

```text
状态：dp[i] = 和为 i 的最少项数
转移：dp[i] = min(dp[i], dp[i - j²] + 1)        ← 完全背包，物品可重复
初值：dp[0] = 0；其余取一个「够大且能安全 +1」的界（本题直接用 i，见 §118.6.2 第 1 条）
答案：dp[n]
```

**这里有个和 117 直接对照的结论**（面试高频追问）：**求 `min` 时两个循环顺序等价，求方案数时不等价。**

| 求什么 | 外层 | 内层 | 为什么 |
| --- | --- | --- | --- |
| 最少个数（本题 / 116） | 物品 | 容量正序 | `min` 可交换，且不区分「用到哪些物品」 |
| 最少个数（本题 / 116） | 容量递增 | 物品 | 同样正确：读的 `dp[i-j²]` 下标更小，已算好 |
| 方案数（117） | **物品** | 容量正序 | 数的是**多重集**（组合） |
| 方案数（377） | **容量** | 物品 | 数的是**有序序列**（排列） |

**判据一句话**：`min` / `max` / `or` 这类**幂等且可交换**的聚合**不关心顺序**；`+` 这类计数聚合**关心顺序**，因为「先放谁」会改变被枚举的对象。

**模型二：「答案值域极小 ⇒ 用判据而不是用表」**

这是本题最值得带走的一层。当你发现某道最优化题的**答案可能取值极少**（比如只有 4 种），就先问：**能不能用一组充要判据直接定位？** 同类的还有：

| 题 | 答案值域 | 判据式解法 |
| --- | --- | --- |
| 本题 | `{1,2,3,4}` | 四平方 + 三平方定理 |
| [LC 633 平方数之和](https://leetcode.cn/problems/sum-of-square-numbers/) | `{true,false}` | 双指针 / 费马二平方和定理（`4k+3` 型素因子的指数必须为偶） |
| [LC 367 有效的完全平方数](https://leetcode.cn/problems/valid-perfect-square/) | `{true,false}` | 整数开根（或牛顿迭代） |
| 汉明重量类（141 章） | `0..32` | 位运算逐位统计 |

**套用 DP 四步法（第一解）**：

| 四步 | 本题的答案 |
| --- | --- |
| ① 状态定义 | `dp[i]` = 和为 `i` 所需的最少完全平方数个数 |
| ② 转移方程 | `dp[i] = min(dp[i], dp[i - j*j] + 1)`（按「最后一个平方数」分类） |
| ③ 初始化 | `dp[0] = 0`；`dp[i]` 先置为 `i`（全用 `1` 凑，一定可行，且是天然上界） |
| ④ 遍历序 | `i` 从 1 到 `n` 递增；内层 `j*j ≤ i`（物品在外层时：内层 `i` 从 `j*j` 到 `n` 正序） |

### 118.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 改成**求方案数** | `min` → `+` | 就变成「平方数版的 117」：`dp[i] += dp[i-j*j]`，且要**平方数在外层**才是组合数；这是 LC 117 与本题的交叉点 |
| 改成**恰好 `k` 个平方数** | 加一维 | `dp[k][i] = Σ_j dp[k-1][i-j²]`，复杂度 `O(k·n·√n)`。注意 `0²` 允许使用，于是「恰好 `k` 个」有解 ⟺ `k ≥ 最少个数`；而最少个数 `≤ 4`（拉格朗日），所以 `k ≥ 4` 时任何 `n` 都有解 —— **定理版在这里又省掉了一整维** |
| 平方数换成**立方数** | 物品集合变 | 背包照样 `O(n·n^{1/3})`；但**没有**类似四平方的和干净结论 —— 立方数模 9 只能是 `0, ±1`，三个立方之和模 9 落在 `-3..3`，于是 `n ≡ ±4 (mod 9)` 至少要 4 个；上界则是「每个整数都是 9 个非负立方之和」（Waring 问题 `g(3) = 9`） |
| `n = 10⁹` | 表开不下 | 定理版：`O(√n) = 31623` 次二平方和检验；再快可用「费马二平方和定理 + 试除到 `n^{1/4}`」判定 2；4 的判定是 `O(log n)` |
| 允许用 `0²` 与负数 | 语义变化 | 答案不变（`0²` 只会增加项数）；负数平方等于正数平方，等价 |
| 要求输出**具体拆法** | 求值 → 枚举 | DP 表里存 `choice[i] = j`，从 `n` 回溯；或定理版直接给出构造（1 的情形平凡，2 的情形回溯枚举的那个 `a`，3/4 用下降法） |

### 118.4.2 容量在外层：同一张表，另一条填充路径

```text
for i = 1..n:  dp[i] = i;  for j = 1; j*j <= i; j++:  dp[i] = min(dp[i], dp[i-j*j] + 1)

i=1:  dp[1]=1                       （j=1 → dp[0]+1=1）
i=2:  dp[2]=min(2, dp[1]+1=2)=2
i=3:  dp[3]=min(3, dp[2]+1=3)=3
i=4:  dp[4]=min(4, dp[3]+1=4, dp[0]+1=1)=1        ← j=1 得 4，j=2 得 1
i=5:  dp[5]=min(5, dp[4]+1=2, dp[1]+1=2)=2
i=6:  dp[6]=min(6, dp[5]+1=3, dp[2]+1=3)=3
i=7:  dp[7]=min(7, dp[6]+1=4, dp[3]+1=4)=4        ← 从这里能看出 7 需要 4 个
i=8:  dp[8]=min(8, dp[7]+1=5, dp[4]+1=2)=2
i=9:  dp[9]=min(9, dp[8]+1=3, dp[5]+1=3, dp[0]+1=1)=1
i=10: dp[10]=min(10, dp[9]+1=2, dp[6]+1=4, dp[1]+1=2)=2
i=11: dp[11]=min(11, dp[10]+1=3, dp[7]+1=5, dp[2]+1=3)=3
i=12: dp[12]=min(12, dp[11]+1=4, dp[8]+1=3, dp[3]+1=4)=3

```

| 对比项 | 物品在外层（`.4.1`） | 容量在外层（`.4.2`） |
| --- | --- | --- |
| 中间表长什么样 | 每轮「加一种平方数」，表单调变小 | 每格一次算完，永不再改 |
| 内层在做什么 | 更新整条容量轴 | 枚举「最后一项是哪个 `j²`」 |
| 最终答案 | 相同 | 相同 |
| 能否推广到方案数 | **能**（组合数，117 口径） | 会变成排列数 |
| 是否有「读本行」问题 | 有（正序 vs 倒序决定完全/01 背包） | 无（天然读更小下标） |

> ⚠️ **「求 `min` 时两个顺序等价」不是可以随便写的护身符**：它只对「幂等 + 可交换」的聚合成立。**一旦题目改成求方案数，两版立刻给出不同的数**（§118.3.3 的表）。**先把「求什么」钉死，再决定能不能偷懒。**

### 118.4.3 定理版：`n = 28` 的判定轨迹

```text
判定链（按「4 → 1 → 2 → 3」的顺序走，命中即返回）：

  输入 n
   │
   ├─【判 4】剥掉所有 4 的因子得 m；若 m % 8 == 7 ⇒ 返回 4
   │           n = 28: 28 → 14 → 7，7 % 8 == 7  ✅ ⇒ 立刻返回 4
   │           （28 = 4 · 7，属于 4^a(8b+7) 家族；28 = 25+1+1+1 确实要 4 个）
   │
   ├─【判 1】isSquare(n) ⇒ 返回 1
   │
   ├─【判 2】枚举 a = 1, 2, … 直到 a² > n；若 n - a² 是平方 ⇒ 返回 2
   │
   └─【兜底】返回 3
```

`n = 28` 在第一步就返回，后面三步不执行。下面两个数把剩下的分支走完：

对照 `n = 13`（答案 2，走完判 4、判 1、判 2 三步）：

```text
13 % 4 ≠ 0 ⇒ m = 13，13 % 8 = 5 ≠ 7          ⇒ 不是 4
isqrt(13) = 3，3² = 9 ≠ 13                    ⇒ 不是 1
a = 1: 13 - 1  = 12，12 不是平方
a = 2: 13 - 4  =  9，9 = 3²  ✅                ⇒ 返回 2（4 + 9）
```

对照 `n = 12`（答案 3，四个判据全部走完，落到兜底）：

```text
12 % 4 = 0 ⇒ m = 12/4 = 3，3 % 8 = 3 ≠ 7      ⇒ 不是 4   ← 注意必须是 while 循环
isqrt(12) = 3，3² = 9 ≠ 12                    ⇒ 不是 1
a = 1: 11 ✗   a = 2: 8 ✗   a = 3: 3 ✗（a² ≤ 12）⇒ 不是 2
                                              ⇒ 兜底返回 3（4 + 4 + 4）
```

对照 `n = 7`（答案 4，最容易被漏判的点）：

```text
7 % 4 ≠ 0 ⇒ m = 7，7 % 8 = 7  ✅ ⇒ 直接返回 4
      ↑ 如果漏掉「判 4」这一步，会一路走到兜底答 3 —— 而 7 = 4+1+1+1 需要 4 个
```

### 118.4.4 BFS 视角：为什么「最少个数」= 层数，且层数 ≤ 4

```text
n = 12，平方数 {1, 4, 9}

第 0 层： {0}
第 1 层： {1, 4, 9}                                    ← 用 1 个平方数能到的
第 2 层： 1→{2,5,10}  4→{5,8,13}  9→{10,13,18}
          并集 ≤12 = {2, 5, 8, 10}
第 3 层： 2→{3,6,11}  5→{6,9,14}  8→{9,12 ★}
          第一次遇到 12 ⇒ 层数 3 = 答案

    ┌────────┐  +1   ┌────────┐  +4   ┌────────┐  +9   ┌────────┐
    │   0    │ ────→ │   1    │ ────→ │   5    │ ────→ │  14    │ ...
    └────────┘       └────────┘       └────────┘       └────────┘
        │ +4             │ +4             │ +1
        ▼                ▼                ▼
    ┌────────┐       ┌────────┐       ┌────────┐
    │   4    │ ────→ │   8    │ ────→ │  12 ★  │   层数 3 ⇒ 4+4+4
    └────────┘       └────────┘       └────────┘

图的边永远指向更大的整数 ⇒ 是 DAG ⇒ BFS 层数 = 最短路径 = 最少个数
且每个整数都在第 1~4 层内被首次到达（拉格朗日定理的计算版观察）
```

## 118.5 双语言实现

### 118.5.1 Java

```java
class Solution {
    public int numSquares(int n) {
        // dp[i] = 和为 i 的最少完全平方数个数
        // 初值写成 i 而不是 INF：全用 1 凑一定是合法方案（1 = 1²），
        // 所以 i 本身就是答案的一个天然上界，且永远不会在 dp[i-j*j]+1 里溢出
        int[] dp = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            dp[i] = i;                                  // 上界：i 个 1
            for (int j = 1; j * j <= i; j++) {          // 枚举「最后一个平方数」j*j
                dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
            }
        }
        return dp[n];
    }

    // 第二解：拉格朗日四平方定理 + 勒让德三平方定理，O(sqrt n)
    public int numSquaresMath(int n) {
        // ① 判 4：n = 4^a(8b+7)。先剥 4 的幂，再判模 8 是否为 7
        int m = n;
        while (m % 4 == 0) m /= 4;
        if (m % 8 == 7) return 4;

        // ② 判 1：本身是完全平方数
        if (isSquare(n)) return 1;

        // ③ 判 2：n = a² + b²。枚举 a 检验 n - a² 是否平方（充要判定，不是启发式）
        for (int a = 1; a * a <= n; a++) {
            if (isSquare(n - a * a)) return 2;
        }

        // ④ 兜底：不是 1/2/4 ⇒ 只能是 3（拉格朗日保证 ≤ 4，勒让德排除 4）
        return 3;
    }

    // 整数开根：必须修正浮点误差，不能用 (int) Math.sqrt(x) 一步到位
    private boolean isSquare(int x) {
        int r = (int) Math.sqrt((double) x);
        while ((long) (r + 1) * (r + 1) <= x) r++;      // 向上逼近
        while ((long) r * r > x) r--;                   // 向下回退
        return r * r == x;
    }
}
```

### 118.5.2 Go

```go
package main

import "math"

// numSquares：完全背包求最少个数 —— 与 Java 的 numSquares 逐行对应
func numSquares(n int) int {
	dp := make([]int, n+1)
	for i := 1; i <= n; i++ {
		dp[i] = i // 上界：全用 1 凑，需要 i 个；同时也是「不可达」的安全替代品
		for j := 1; j*j <= i; j++ {
			if dp[i-j*j]+1 < dp[i] {
				dp[i] = dp[i-j*j] + 1
			}
		}
	}
	return dp[n]
}

func isqrt(x int) int {
	if x <= 0 {
		return 0
	}
	r := int(math.Sqrt(float64(x))) // 浮点开根可能有 ±1 误差，下面两步修回来
	for (r+1)*(r+1) <= x {
		r++
	}
	for r*r > x {
		r--
	}
	return r
}

func isSquare(x int) bool {
	r := isqrt(x)
	return r*r == x
}

// numSquaresMath：拉格朗日四平方 + 勒让德三平方定理，O(sqrt n)
func numSquaresMath(n int) int {
	m := n
	for m%4 == 0 { // 剥掉 4 的幂：n = 4^a(8b+7) ⇔ 答案 4
		m /= 4
	}
	if m%8 == 7 {
		return 4
	}
	if isSquare(n) {
		return 1
	}
	for a := 1; a*a <= n; a++ {
		if isSquare(n - a*a) {
			return 2
		}
	}
	return 3
}

func main() {}
```

### 118.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 浮点开根 | `(int) Math.sqrt((double) x)` | `int(math.Sqrt(float64(x)))` | **两边都必须修 ±1 误差**。`n = 10000` 时结果可能落在 `99.999…`，直接截断成 99 → 判定失败。修法是「先向上逼近、再向下回退」两个 `for` |
| 数组初始化 | `new int[n+1]` 为零 | `make([]int, n+1)` 为零 | 本题靠 `dp[i] = i` 覆盖，零值不可用；**漏写这一行会让 `dp[i]` 一直停在 0，最终答案恒为 1** |
| 乘方 | `j * j` | `j * j` | `n ≤ 10⁴` 时 `j ≤ 100`，`j*j` 安全。若把 `n` 放大到 `2³¹`，两边的 `j*j` 都会溢出 `int` → 改 `long` / `int64`，或写 `j <= i/j` |
| `min` 的写法 | `Math.min(a, b)` | `if a < b { … }`（Go 1.21 前无内置 `min`） | Go 1.19 没有 `min` 内建函数，只能手写 `if`；这反而是我们展示「比较后赋值」的位置 |
| 类型提升 | `(long)(r+1)*(r+1)` 显式提升后比较 | `(r+1)*(r+1)` 在 amd64 上是 64 位 | Java 的 `int*int` 会溢出，必须 `(long)`；Go 的 `int` 是 64 位，但 `int32` 平台上就错了 —— **生产代码应显式用 `int64`** |
| 提前返回 | `return 4;` | `return 4` | 一致；定理版**每个分支都立刻返回**，不像 DP 那样需要跑完整张表 |

### 118.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"
)

// 独立参考实现：BFS 按层扩展，层数就是「最少个数」—— 与 DP、定理都不共享任何推理
func bfsSquares(n int) int {
	if n == 0 {
		return 0
	}
	dist := make([]int, n+1)
	for i := range dist {
		dist[i] = -1 // -1 = 未访问
	}
	dist[0] = 0
	q := []int{0}
	for head := 0; head < len(q); head++ {
		cur := q[head]
		for j := 1; cur+j*j <= n; j++ {
			next := cur + j*j
			if dist[next] == -1 { // BFS 第一次到达即最短
				dist[next] = dist[cur] + 1
				if next == n {
					return dist[next]
				}
				q = append(q, next)
			}
		}
	}
	return dist[n]
}

// 与 BFS 对拍：背包版 + 定理版 三方一致
func TestNumSquaresVsBFS(t *testing.T) {
	r := rand.New(rand.NewSource(279_0001))
	for iter := 0; iter < 12000; iter++ {
		n := 1 + r.Intn(2000)
		want := bfsSquares(n)
		if got := numSquares(n); got != want {
			t.Fatalf("dp iter=%d n=%d got=%d want=%d", iter, n, got, want)
		}
		if got := numSquaresMath(n); got != want {
			t.Fatalf("math iter=%d n=%d got=%d want=%d", iter, n, got, want)
		}
	}
}

// 全区间穷举 1..10000（覆盖 LC 上界），同时验证答案 ∈ {1,2,3,4}
func TestNumSquaresExhaustive(t *testing.T) {
	for n := 1; n <= 10000; n++ {
		want := bfsSquares(n)
		if got := numSquares(n); got != want {
			t.Fatalf("dp n=%d got=%d want=%d", n, got, want)
		}
		if got := numSquaresMath(n); got != want {
			t.Fatalf("math n=%d got=%d want=%d", n, got, want)
		}
		if want < 1 || want > 4 {
			t.Fatalf("n=%d 答案 %d 超出 {1,2,3,4}", n, want)
		}
	}
}
```

**实测结果**（本机 2 核容器 / Go 1.19.8）：

- `go vet .` 无告警；
- **12000 轮随机 `n ∈ [1, 2000]`**：背包版与定理版都与 BFS 层数一致；
- **全区间穷举 `n = 1..10000`**：两版全部一致，且答案恒在 `{1,2,3,4}`，耗时 **≈ 4 s**（三种实现各跑一遍，共 `3·10⁴` 次求解）。
- 边界用例（含答案 1/2/3/4 的代表点与 `n` 取到上界）：

| 2 | 2 | `1+1`，无解版会在这里崩 |
| 3 | 3 | `1+1+1` |

## 118.6 复杂度与常见坑

### 118.6.1 复杂度推导（写结论不算本事，要能推）

- **背包版时间 `O(n√n)`**：外层 `i` 从 1 到 `n`；对每个 `i`，内层执行 `⌊√i⌋` 次。总次数
  `Σ_{i=1}^{n} √i ≈ ∫₀ⁿ √x dx = (2/3)·n^{3/2}`。
  `n = 10⁴` → `(2/3)·10⁶ ≈ 6.7·10^5` 次比较与加法，本机实测 **≈ 0.8 ms**。
- **背包版空间 `O(n)`**：`int[10001] = 40 KB`。二维版会是 `n × √n = 10⁶` 个 `int`（`4 MB`），没有收益。
- **定理版时间 `O(√n)`**：判 4 是 `O(log₄n)` 次除法；判 1 是 `O(1)`（整数开根 + 两次修正）；判 2 最多 `√n` 次 `isSquare`。`n = 10⁴` → 最坏 `100` 次。
- **BFS 版 `O(n√n)`**：每个顶点最多入队一次、每次出队扫 `√n` 个平方数。与背包同量级，但**第一次到达 `n` 就立刻返回**，所以实测比背包快：`n = 10⁴`（答案 1，第 1 层就命中）**25 µs**；`n = 9999`（答案 4，要铺满 4 层，BFS 的最坏形态）**342 µs**，而同一输入下背包版是 **774 µs**。
- **三者全区间累计实测**（`n = 1..10⁴` 各跑一遍，本机 2 核容器 / Go 1.19.8）：

  | 实现 | 累计耗时 | 相对最慢 |
  | --- | --- | --- |
  | 背包（容量在外层） | **3.27 s** | 1× |
  | BFS（提前返回） | **0.64 s** | 5.1× 更快 |
  | 定理判定 | **1.4 ms** | **约 2370× 更快** |

  这张表把「选型」讲完了：**`n = 10⁴` 时三者都能过，但定理版快三个量级；`n = 10⁷` 时只有定理版能过。**
- **暴力 DFS**：分支因子 `√rest`、深度最坏 `n` → 远超多项式；`n = 100` 时已经不可接受。

### 118.6.2 七个真实踩过的坑

1. **`dp[i]` 初值用 `Integer.MAX_VALUE`** —— 然后算 `dp[i-j*j] + 1` 时 `MAX_VALUE + 1` 溢出成 `Integer.MIN_VALUE`，`Math.min` 取到它，最终返回一个巨大的负数。修法：本题直接用 `dp[i] = i`（全用 1 凑，天然上界，且永不溢出）；要用 `INF` 就用 `n + 1`（同 116 的口径）。
2. **漏写 `dp[i] = i`** —— Java / Go 的数组默认值是 0，`dp[i]` 一直是 0，内层 `dp[i-j*j]+1` 永远 ≥ 1，于是 `dp[i]` 停在 0 或 1，最终答案恒为 1。**这个坑在 `n = 1` 上侥幸正确**，`n = 7` 立刻露馅。
3. **数学解漏掉「判 4」** —— `n = 7` 答 3（正确 4）；在 `1..10⁴` 上有 1665 个数会错。**这是本题最致命的坑**，因为它只影响约 1/6 的输入，随机小样例有 5/6 的概率测不出来。
4. **`(int) Math.sqrt(x)` 直接用** —— 浮点误差 ±1，`n = 10000` 这类「恰好是完全平方」的输入最危险。修法：`int r = (int) Math.sqrt(x); while ((long)(r+1)*(r+1) <= x) r++; while ((long)r*r > x) r--;`；Go 版用 `math.Sqrt` 也要写同样的两行修正。
5. **跳过「判 1」直接判 2** —— 因为「1 个平方数」本身就是「2 个平方数之和补一个 `0²`」，所以二平方和检验对答案是 1 的数**也会返回真**。若删掉「判 1」这一行，`n = 4` 会被答成 **2**（`4 = 2² + 0²`），而正确是 1。**判据之间有包含关系，删任何一行都会让答案整体上移一档。**
6. **「剥 4 的幂」写成 `if` 而不是 `while`** —— 判据是 `n = 4^a(8b+7)`，`a` 可以是任意非负整数，必须**反复**除。只除一次的话 `n = 112 = 16·7`（`a = 2`）会算成 `112 / 4 = 28`，而 `28 % 8 = 4 ≠ 7`，于是漏判、落到兜底答 3（正确是 4）。再看 `n = 448 = 64·7`（`a = 3`），需要除三次才剥干净。**修法：从「带 `a` 的参数」出发想循环次数，不要凭一眼印象写 `if`。**
7. **贪心当解法** —— `n = 12` 答 4（正确 3）、`n = 18` 答 3（正确 2）。平方数系统**不是** canonical 的，贪心在这个模型里几乎总是错的（与 116 的 `[1,3,4]` 凑 6 同一个病）。

### 118.6.3 面试官最爱追问的四个问题

**Q1：为什么答案只能是 1、2、3、4？**
> 「上界来自**拉格朗日四平方定理**（1770）：每个非负整数都是 4 个整数平方之和，所以答案 ≤ 4。下界是 1（`n ≥ 1` 时至少要一个平方数）。两端一夹，答案只能落在 `{1,2,3,4}`。这个定理不是『技巧』，它把本题从『最优化问题』变成了『四分类问题』——**分类的边界由数论给出，不由算法给出**。它的证明路线是欧拉四平方恒等式（把问题归约到素数）+ 鸽笼论证 + 下降法。」

**Q2：`n = 4^a(8b+7)` 为什么恰好需要 4 个？**
> 「两步。第一步（模 8 障碍）：平方数模 8 只能是 0、1、4，三个这样的数相加模 8 的可能取值是 `{0,1,2,3,4,5,6}`，**永远取不到 7**，所以 `n ≡ 7 (mod 8)` 不能用 3 个平方表示。第二步（下降）：若 `n = 4m` 且能被 3 个平方表示，则三个平方数都必须是偶数（否则和 ≡ 3 (mod 8)，与 `4m ≡ 0 或 4` 矛盾），于是可以整体除以 4 得到 `m` 的 3 平方表示。反复用就得到『剥掉所有 4 的因子后模 8 为 7 ⇒ 需要 4 个』。反方向（不是这种形式就一定能用 3 个）是勒让德三平方定理，属高斯二次型理论，面试里说清前半段的两个可验证引理就足够。」

**Q3：为什么这题求「最少个数」时，两个循环顺序随便写都对；而 117 求「方案数」就必须讲究？**
> 「因为聚合运算的性质不同。`min` 是**幂等且可交换**的：同一种物品被考虑多次不会改变最小值，两个循环谁在外层只是换了计算顺序，`dp` 的最终语义都是『取遍所有组合后的最小值』。而 `+` 不幂等，它数的是**被枚举对象的个数**：物品在外层枚举的是『多重集』（组合），容量在外层枚举的是『有序序列』（排列）——**循环顺序决定了你在数什么**。判据：`min`/`max`/`or` 不关心顺序，`+` 关心。」

**Q4：`n = 10⁹` 怎么做？**
> 「DP 表 `O(n√n)` 直接死。走定理版：判 4 是 `O(log n)`，判 1 是 `O(1)`，判 2 需要枚举 `a ≤ √n ≈ 31623` 次 —— 完全可接受。想再快，判 2 可以换成**费马二平方和定理**：`n = a²+b²` ⟺ `n` 的标准分解里，每个 `4k+3` 型素因子的指数都是偶数。这只用到试除到 `n^{1/2}`（判完偶指数后还可只用 `4k+3` 型素因子试除到 `n^{1/2}` 以内），实践中比枚举 `a` 快得多。**这题的『大 `n`』通道就是数论，没有伪多项式的替代方案。**」
