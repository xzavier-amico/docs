## 061.1 题目

**原题链接**：<https://leetcode.cn/problems/daily-temperatures/>

### 题意重述（把隐含条件补齐）

给定一个整数数组 `temperatures` 表示每天的气温，返回一个数组 `answer`，其中 `answer[i]` 表示：从第 `i` 天开始，**还要再等几天**才会出现一个**更高**的温度；如果之后都不会更高，则 `answer[i] = 0`。

一句话说完，但它藏着五个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **要求「更高」，不是「不低于」** | 「下一个更高温度」 | `[30, 30, 30]` 若把相等也当更暖，会返回 `[1, 1, 0]`，正确答案是 `[0, 0, 0]` |
| **返回的是「天数差」不是下标** | 「至少需要等待的天数」 | 返回 `answer[i] = j` 而不是 `j - i`，样例全错 |
| **找不到就是 0，不是 -1** | 「如果气温在这之后都不会升高，在该位置用 0 来代替」 | 全 0 初始化的数组天然正确；若初始化为 -1 就得在最后补一次遍历 |
| **`n >= 1`** | 约束 `1 <= temperatures.length` | 不必处理空数组的返回语义，但自测时最好还是覆盖它 |
| **只与「右侧」有关** | 「之后的某个日子」 | 左侧更暖的日子不算答案；这意味着扫描方向只能是「从左往右（用栈等）或从右往左（记录最近出现位置）」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 10⁵` | n 最大十万 | **O(n²) 必死**：最坏（严格递减）是 `5·10⁹` 次比较。本机实测 `n = 4·10⁴` 的递减序列，暴力已需 **408 ms**，按平方外推到 `n = 10⁵` 约 **2.5 s**；而单调栈只需 **0.8 ms**（约 3000 倍差距） |
| `30 <= temperatures[i] <= 100` | **值域只有 71 种** | 这是一条被大多数人浪费的隐藏信息：值域小时可以「记下每种温度最近一次出现的下标」，做到 O(71·n)。这是本章的**第二条正解**（方案 B） |
| 返回值是 `int[]`，长度 n | 一一对应 | 必须为每一天都产出一个答案，包括「没有更暖」的那些 |
| 只需要「第一个」更暖 | 不要求所有更暖的日子 | 一旦结算完就可以把下标永久丢出栈 —— 这正是 O(n) 的来源 |

> 💡 **量级 → 算法**：`n = 10⁵` 是「O(n) 或 O(n log n)」的分水岭。看到 10⁵ 就要立刻放弃「每个位置再扫一遍」；看到「值域 30~100」就该知道「第二种 O(值域 · n) 的解法合法存在」，至于选哪个，取决于面试官问的是「通用性」还是「常数」。

### 示例

```
输入：temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
输出：[1, 1, 4, 2, 1, 1, 0, 0]

逐位解释：
 i=0  73 → 第 1 天 74 更高            → 1
 i=1  74 → 第 2 天 75 更高            → 1
 i=2  75 → 第 6 天 76 更高            → 4
 i=3  71 → 第 5 天 72 更高            → 2
 i=4  69 → 第 5 天 72 更高            → 1
 i=5  72 → 第 6 天 76 更高            → 1
 i=6  76 → 右边再没有更高的            → 0
 i=7  73 → 右边没有                    → 0

输入：temperatures = [30, 40, 50, 60]
输出：[1, 1, 1, 0]

输入：temperatures = [30, 60, 90]
输出：[1, 1, 0]
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [30, 30, 30]                             → [0, 0, 0]
   暴露「相等也弹出」：写成 while 栈顶 <= 当前，就会得到 [1, 1, 0]

② [30, 40, 50, 60]（严格递增）              → [1, 1, 1, 0]
   暴露「栈永远不会变深」—— 每次 push 前都把栈弹空了，
   此时若在 pop 后忘记用「新栈顶」而用了「已弹元素」，答案就会算错

③ [90, 80, 70, 60]（严格递减）              → [0, 0, 0, 0]
   暴露两点：① 这是暴力解法的最坏输入（O(n²/2)）；② 栈会一直涨到 n，
   收尾时栈里剩下的全部是「没有答案」的元素，绝不能忘

④ [55, 38, 53, 81, 61, 93, 97, 32, 43, 78]  → [3, 1, 1, 2, 1, 1, 0, 1, 1, 0]
   这是题面第二个样例：它同时包含「弹出多个」「弹完立刻入栈」「收尾残留」三类动作
```

第 ① 条是本章**唯一**一个「改了半个字符就错」的地方：`<` 与 `<=`。这个 `<` 与 `<=` 的选择，会在后面 062（柱状图）里以「相等时留谁」的形态再出现一次，是本批最值得建立的条件反射。

## 061.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

```java
// 暴力：对每一天 i，向右线性扫描到第一个更高温
int[] ans = new int[n];               // 默认 0，天然处理"后面没有更暖的日子"
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        if (temperatures[j] > temperatures[i]) {
            ans[i] = j - i;
            break;                    // 找到就停
        }
    }
}
```

- 时间 **O(n²)**，空间 **O(1)**（不计返回数组）。
- 具体数字：**最坏**输入是严格递减序列（每天都要扫到末尾）：`n(n-1)/2` 次比较。本机实测：

| n | 暴力（递减序列） | 单调栈 | 倍数 |
| --- | --- | --- | --- |
| 5·10³ | 7.9 ms | 37 µs | 215× |
| 2·10⁴ | 119 ms | 76 µs | 1560× |
| 4·10⁴ | 408 ms | 305 µs | 1340× |
| 10⁵（外推） | ≈ 2.5 s | ≈ 0.8 ms | ≈ 3000× |

- 为什么「平均情况」会骗你：随机数据（值域 30~100）里，几乎每一天都能在 `O(100)` 步内找到更暖的日子，所以随机对拍时暴力看起来很快（`n = 2·10⁴` 只要 5.9 ms）。**面试官不会给你随机数据，他会给你递减序列。**

### 第二步：卡点在哪

把暴力翻译成一句话：

> **对每个 `i`，找它右边第一个 `> temperatures[i]` 的下标 `j`。**

暴力的浪费在于**同一段右区间被反复扫描**。递减序列 `[90, 80, 70, 60]` 里，`i = 0` 扫了 1~3，`i = 1` 又扫了 2~3，`i = 2` 又扫了 3 —— 每个位置被扫 O(n) 次。要消掉这份重复，必须**一次扫描就把多个人同时解决**。

### 第三步：灵感的来源 —— 把「我去找」翻成「它来解决我」

难点在于：从 `i` 的视角往外看，你不知道答案在哪。那就**换个视角**：

```
视角 A（暴力）：i = 0 问："我右边第一个比我高的是谁？"   → 得自己扫
视角 B（栈）  ：i = 6 出现 76 时说："所有比我矮、还在等的人，今天集体结案。"
```

谁的「等待」是可以被批量解决的？**所有温度比我低、并且还没找到答案的人。** 而且他们有一个关键结构性质：

> 若 `j1 < j2` 且 `temperatures[j1] <= temperatures[j2]`，那么 `j1` 的答案不可能晚于 `j2` 的答案 —— 一旦 `j2` 被解掉，`j1` 早就被解掉了。也就是说：**「还在等待」的下标，其温度必然从栈底到栈顶单调不增。**

这就是栈的形状。于是算法：

```
栈里存「还在等待答案的下标」，栈内温度单调不增。
第 i 天温度 t：
    只要栈非空 且 栈顶温度 < t  →  栈顶那个人的答案就是 i - 栈顶下标，弹掉
    （弹完了，说明栈里剩下的都比 t 高，他们继续等）
    把 i 压栈，让 i 也开始等
```

**「弹出时结算被弹出者的答案」** —— 本批的统一语言，在这一章第一次变成了「产生答案」，而不是 060 的「恢复状态」。

### 第四步（另一条路）：值域只有 71 种，用「最近出现位置」表

题目给了 `30 <= temperatures[i] <= 100`，这个信息可以直接用：**从右往左**扫，用一个 `next[温度]` 数组记住「该温度最近一次出现的下标」。对每个 `i`，在 `temperatures[i]+1 … 100` 里找最小的那个下标：

```
next = 全 -1 的数组，长度 101
for i = n-1 downto 0:
    best = min{ next[t] : t in (temperatures[i], 100] }
    ans[i] = (best == -1) ? 0 : best - i
    next[temperatures[i]] = i            ← 必须最后更新，否则会把自己当成答案
```

- 时间 O(n · V) 其中 `V = 71`，空间 O(V)。
- **什么时候输**：值域一大（比如温度到 `10⁹`）就死；而单调栈对值域完全没有要求。
- **什么时候赢**：`n` 小、值域极小、且要求常数因子低时，它比栈快（没有 push/pop，全是对一个小数组的扫描，缓存友好）。
- 面试里的正确态度：**先给单调栈（通用），再说值域方案（体现了你读到了约束）**。

## 061.3 原理拆解

### 061.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| A 暴力向右扫 | O(n²) 最坏 | O(1) | 8 行 | `n = 10⁵` 递减序列 ≈ 2.5 s，必 TLE |
| B 从右往左 + `next[值域]` 表 | O(n·V)，V = 71 | O(V) | 14 行 | 值域大就死（`V = 10⁹` 直接爆炸）；本质是「用值域换结构」 |
| **C 单调递减栈（从左往右）** ✅ | **O(n)** | **O(n)** | 12 行 | 需要 O(n) 栈空间；值域无关，通用 |
| D 单调栈（从右往左，「栈顶就是我的答案」） | O(n) | O(n) | 12 行 | 思维方向相反：弹出的是「比我矮的」，答案取「栈顶」；初学者容易把两种写法混成一锅 |
| E 分治 / 线段树（区间第一个大于） | O(n log n) | O(n) | 40 行 | 代码量是 C 的 3 倍，除非题目还要求动态修改 |

**为什么 C 优于 D（虽然两者都是 O(n)）**：C（从左往右，弹出时结算）有一个巨大的工程优势 —— **每个元素的答案在它被弹出的那一刻就被写死，之后永不修改**。这种「一次写定」的性质在推广到 062（柱状图）时至关重要：那里弹出一个柱子要同时用到它的左边界和右边界，从左往右扫天然能拿到「右边界 = 当前 i」。

**为什么 B 值得写进书里**：它是「读约束」的证明。同一道题，看到「值域 30~100」就该意识到可以开一个 101 长的数组；看到「n 到 10⁵」就该意识到 O(n²) 不行。**两个约束一起读，才会得出「O(71n) 是合法解」这个结论。**

### 061.3.2 为什么这个做法是对的（正确性论证）

**定义两个不变量**（处理完下标 `i` 之后成立）：

- **I1（栈的形状）**：栈中下标自底向顶严格递增，且对应的温度**单调不增**。
- **I2（等待集合）**：栈中下标恰好是「`0..i` 中尚未找到答案」的全部下标，且栈外每个下标的 `ans` 都已写定。

**证明 I1**：设入栈前栈中温度自底向顶单调不增（允许相等）。若 `temperatures[i] > 栈顶温度`，则栈顶被弹掉；重复到 `temperatures[i] <= 栈顶温度` 或栈空为止。于是剩下的新栈顶温度 `>= temperatures[i]`（或栈空），再把 `i` 压上，单调不增性保持 —— 注意这里保留相等，所以栈的形状是「不增」而不是「严格递减」。∎

**证明 I2**：只需看「被弹出的 `j` 的答案确实是 `i - j`」。设 `j` 在被 `i` 弹出（即 `temperatures[i] > temperatures[j]`，且 `j` 在 `i` 之前一直留在栈中）。取任意 `k` 满足 `j < k < i`：

1. `k` 入栈之前，`j` 一定仍在栈中（否则 `j` 会被某个 `m <= k` 弹出，`ans[j]` 就已写定，与「`j` 在 `i` 时刻仍在栈中」矛盾）。
2. `k` 入栈时 `j` 没被弹，说明弹出条件不成立，即 `temperatures[k] <= temperatures[j]`。

所以 `[j+1, i-1]` 内没有任何温度大于 `temperatures[j]`，而 `temperatures[i] > temperatures[j]` —— **`i` 就是 `j` 右侧第一个严格更高的位置**，`ans[j] = i - j` 正确。由于 `j` 弹出后永不回栈，每个下标最多被写一次答案，不会写错也不会漏写。∎

**收尾**：扫描结束后仍在栈中的下标，说明其右侧没有任何更大的温度（若存在，它会被那个位置弹出），默认值 0 正是题目要求。∎

> **这个论证的副产品**：它顺便解释了「为什么必须弹 `<=` 而不是 `>=`」。若弹栈条件写成 `temperatures[top] <= temperatures[i]`，那么第 2 步就变成「相等的也被弹了」，`j` 会被一个**温度相同**的 `k` 结算，`ans[j] = k - j`，而题目要的是**严格更高**，于是错。

### 061.3.3 通用解题思路（可迁移的那一层）

本章是本批统一判定语言的**第 1 课**，也是「单调栈」这个名字的由来。把它压成一张判定表：

```
┌──────────── 单调栈的统一判定语言（本批 060–064 共用）────────────┐
│ ① 栈里存什么？ 存下标。只有下标能算出「距离/宽度」，存值就把跨度丢了。│
│ ② 栈内保持什么单调？保持「还在等待的候选」的单调性 —— 被支配的立刻淘汰。│
│ ③ 什么时候结算？弹出那一刻。被弹出者的答案在那一刻定稿，永不修改。    │
│ ④ 弹栈条件的 `<` / `<=` 决定了：严格 / 非严格，以及相等元素归谁结算。 │
└──────────────────────────────────────────────────────────────────┘
```

「下一个更大 / 更小」这一族题的**完整对照表**（这是最值得背走的一张表）：

| 题目要什么 | 扫描方向 | 栈内单调性 | 弹栈条件 | 结算方式 |
| --- | --- | --- | --- | --- |
| **下一个严格更大**（本章） | 左 → 右 | 单调不增 | `栈顶 < 当前` | `ans[栈顶] = i - 栈顶` |
| 下一个「大于或等于」 | 左 → 右 | 单调不增 | `栈顶 <= 当前` | 同左（相等的也结算） |
| 上一个严格更大 | 左 → 右 | 单调不增 | 入栈前把 `<=` 当前的全弹掉 | 弹完后 `栈顶` 就是答案（或弹栈时结算） |
| 下一个严格更小 | 左 → 右 | 单调不增（换成「不增」的反面：不降） | `栈顶 > 当前` | 同「下一个更大」，符号整体取反 |
| 柱状图最大矩形（062） | 左 → 右 | **单调递增（不降）** | `栈顶 > 当前` | `h[栈顶] × (i - 左边界 - 1)` |

**注意第 5 行与第 1 行的镜像关系**：061 求「更大」用递增不入栈（栈内不增），062 求「更矮的边界」用递减不入栈（栈内递增）。**同一个骨架，把比较符号反过来，就是另一道题。**

### 061.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 数组变成**循环**的（末尾接回开头） | 答案可以绕一圈 | 扫 `2n` 次，下标取 `i % n`；只在 `i < n` 时写答案（LC 503 的手法） |
| 要「所有」更大的位置，不只是第一个 | 不能立刻弹出 | 单调栈失效，退回「每个位置二分 / 归并排序求逆序对」那一类 |
| 要求 `O(1)` 额外空间 | 栈不能开 | 用返回值数组 `ans` 当作栈的存储（它本来就有 n 个格子）；此时栈里存的是「已写入答案的临时槽」 |
| 数据流输入（每天来一个，随时要问某天的答案） | 不能回头扫 | 单调栈天然适合：新的一天到来时立刻结算一批，`ans` 边算边输出 |
| 值域极大 / 是浮点温度 | `next[]` 数组方案作废 | 只能用单调栈（值域无关），这正是它「通用」的含义 |
| 要求「答案之和」而不是答案数组 | 只需累加 `i - j` | 弹栈时直接累加，空间可以省掉 `ans` 数组 → O(n) 栈空间仍在，但省掉输出 |
| 温度可变（区间加法后再查询） | 静态结构失效 | 换线段树维护区间最大 + 线段树上二分找「第一个大于」 |

## 061.4 图解推演

### 061.4.1 主样例的完整轨迹

`temperatures = [73, 74, 75, 71, 69, 72, 76, 73]`，栈里存**下标**，栈内温度单调不增：

```
下标:     0     1     2     3     4     5     6     7
温度:    73    74    75    71    69    72    76    73
答案:    1     1     4     2     1     1     0     0

i=0  t=73   栈[ ]  →  无人可弹  →  压入 0
            ┌────┐
            │ 0  │  (73)                   ans = [_,_,_,_,_,_,_,_]
            └────┘

i=1  t=74   73 < 74 → 弹 0，ans[0] = 1-0 = 1  →  压入 1
            ┌────┐
            │ 1  │  (74)                   ans = [1,_,_,_,_,_,_,_]
            └────┘

i=2  t=75   74 < 75 → 弹 1，ans[1] = 2-1 = 1  →  压入 2
            ┌────┐
            │ 2  │  (75)                   ans = [1,1,_,_,_,_,_,_]
            └────┘

i=3  t=71   75 > 71 → 不弹  →  压入 3
            ┌────┐
            │ 3  │  (71)                   ans = [1,1,_,_,_,_,_,_]
            ├────┤
            │ 2  │  (75)
            └────┘

i=4  t=69   71 > 69 → 不弹  →  压入 4
            ┌────┐
            │ 4  │  (69)                   ans = [1,1,_,_,_,_,_,_]
            ├────┤
            │ 3  │  (71)
            ├────┤
            │ 2  │  (75)
            └────┘

i=5  t=72   69 < 72 → 弹 4，ans[4] = 5-4 = 1
            71 < 72 → 弹 3，ans[3] = 5-3 = 2
            75 > 72 → 停      →  压入 5
            ┌────┐
            │ 5  │  (72)                   ans = [1,1,_,2,1,_,_,_]
            ├────┤
            │ 2  │  (75)
            └────┘

i=6  t=76   72 < 76 → 弹 5，ans[5] = 6-5 = 1
            75 < 76 → 弹 2，ans[2] = 6-2 = 4
            栈空 → 停          →  压入 6
            ┌────┐
            │ 6  │  (76)                   ans = [1,1,4,2,1,1,_,_]
            └────┘

i=7  t=73   76 > 73 → 不弹  →  压入 7
            ┌────┐
            │ 7  │  (73)                   ans = [1,1,4,2,1,1,_,_]
            ├────┤
            │ 6  │  (76)
            └────┘

扫描结束，栈里剩 6(76)、7(73)：右侧没有更暖的日子 → 保持默认 0
最终 ans = [1, 1, 4, 2, 1, 1, 0, 0]   ✓
```

### 061.4.3 反例 ①：相等温度的处理（`<` 与 `<=` 的一字之差）

```
temperatures = [30, 30, 30]

✅ 弹栈条件 `栈顶 < 当前`（正确）：
i=0 → 栈[0]
i=1 → 30 < 30 不成立 → 不弹 → 栈[0,1]
i=2 → 不弹 → 栈[0,1,2]
收尾全部留着 → ans = [0,0,0]                              ✓

❌ 弹栈条件 `栈顶 <= 当前`（错误）：
i=0 → 栈[0]
i=1 → 30 <= 30 → 弹 0，ans[0] = 1 - 0 = 1 → 栈[1]
i=2 → 弹 1，ans[1] = 1 → 栈[2]
收尾 → ans = [1,1,0]                                       ✗ 题目要"严格更高"
```

### 061.4.4 两种视角的对比图（这张图是本章的灵魂）

```
【视角 A：暴力】每个 i 自己向右找           【视角 B：单调栈】每个新值批量解决"等待者"

  i=0 ──扫描──→ 1  2  3 ... n-1              77 ┐
  i=1 ──扫描──→    2  3 ... n-1               76 │ 谁在等 76？
  i=2 ──扫描──→       3 ... n-1               ↓ │
  ...                                          栈
  ┌─────────────────────────┐               ┌────┬────┬────┐
  │ 每一行都是一次完整的扫描  │               │ 5  │ 3  │ 4  │ ← 都在等更大的
  │ 总工作量 O(n²)           │               │ 72 │ 71 │ 69 │
  └─────────────────────────┘               └────┴────┴────┘
                                             ↑     ↑    ↑
  "我去找答案"（主动，各扫一遍）        "答案来找我"（被动，一次结算一批）
                                          —— 每个下标只入栈一次、出栈一次
```

### 061.4.5 为什么这份「等待」一定能放进一个单调栈

```
若 j1 < j2 且 temp[j1] <= temp[j2]:
    任何能让 j1 结算的位置，也一定能先让 j2 结算
    ⇒ j1 的答案 ≥ j2 的答案，且 j1 一定比 j2 更早被弹走
    ⇒ 栈里「还没结算」的温度必然单调不增（越靠栈顶越矮）
```

反过来说：如果栈顶的温度比下面某个还高，那下面那个早就该被结算了 —— **这种形态不可能出现**，所以「用一个栈装下全部等待者」是合法的。

## 061.5 双语言实现

### 061.5.1 Java

```java
class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] ans = new int[n];    // 默认 0：右侧没有更暖的日子时，这就是题目要的答案
        int[] st = new int[n];     // 手写数组栈：存下标，省掉 Deque<Integer> 的装箱
        int top = -1;

        for (int i = 0; i < n; i++) {
            // 严格小于：相等不算"更暖"，写成 <= 会把答案算成 1
            while (top >= 0 && temperatures[st[top]] < temperatures[i]) {
                int j = st[top--]; // 被弹出的下标当场结算，之后永不回栈
                ans[j] = i - j;    // 返回的是天数差，不是下标
            }
            st[++top] = i;         // 自己也加入"等待"队列
        }
        return ans;
    }
}
```

### 061.5.2 Go

```go
package main

// dailyTemperatures 单调递减栈（栈内温度单调不增）：栈里存下标，
// 每来一天 i，把「等待中被解决的」栈顶逐个弹出并结算答案 i - j。
func dailyTemperatures(temperatures []int) []int {
	n := len(temperatures)
	ans := make([]int, n)   // 零值就是 0，正好等于"右边没有更暖的日子"
	st := make([]int, 0, n) // 存下标，对应温度从栈底到栈顶单调不增

	for i := 0; i < n; i++ {
		// 严格小于：温度相等不算「更暖」，弹了答案就会错成 1
		for len(st) > 0 && temperatures[st[len(st)-1]] < temperatures[i] {
			j := st[len(st)-1]
			st = st[:len(st)-1] // 弹出
			ans[j] = i - j      // 弹出那一刻结算「被弹出者的答案」
		}
		st = append(st, i)
	}
	return ans
}
```

### 061.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 栈的载体 | `int[]` + `top` 指针，或 `ArrayDeque<Integer>` | `[]int` + `append` / `[:len-1]` | Go 的切片写法最短；Java 用 `int[]` 免装箱，用 `ArrayDeque` 则每次 push 装箱 |
| 数组初始化 | `new int[n]` 自动为 0 | `make([]int, n)` 自动为 0 | 两语言都白拿「默认答案 0」，不用额外填 |
| 空栈判定 | `top >= 0` | `len(st) > 0` | 语义一致；Java 若用 `Deque` 要改成 `!st.isEmpty()` |
| `Deque` 的坑 | `ArrayDeque.push()` = `addFirst()`，`pop()` = `removeFirst()` | 无对应问题 | Java 里混用 `push/pop` 与 `addLast/removeLast` 会变成队列语义，答案全错 |
| 返回值语义 | `int[n]` 定长一次分配 | `make([]int, n)` 定长；若用 `append` 则要预留 cap | 本题长度确定，两语言都该一次性开好 |
| 空输入 | `new int[0]` | `make([]int, 0)` 或 `nil` | 题目保证 `n >= 1`；对拍时仍要跑一遍空输入 |

```go
// brute 参考实现：对每个 i 往右扫到第一个更暖的日子，O(n^2)
func brute(temperatures []int) []int {
	n := len(temperatures)
	ans := make([]int, n)
	for i := 0; i < n; i++ {
		for j := i + 1; j < n; j++ {
			if temperatures[j] > temperatures[i] {
				ans[i] = j - i
				break
			}
		}
	}
	return ans
}

		return false
	}

		if a[i] != b[i] {
			return false
		}
	}
	return true
}
```

## 061.6 复杂度与常见坑

### 061.6.1 复杂度推导（摊还分析，必须能自己推）

- **时间 O(n)**：外层循环 `n` 次；内层 `while` 每次执行都会**弹出一个下标**。而每个下标**最多入栈一次**，因此「弹出总次数 ≤ 入栈总次数 = n」。把内层循环的全部执行次数加起来 ≤ n，所以总代价 O(n)。
  - 这是**摊还**（amortized）分析的标准形态：单次迭代最坏可以是 O(n)（比如递减序列末尾突然来个最高温，一次弹 n 个），但**总代价被「入栈 n 次」这个上界卡死**。
  - 面试里别说「每次 O(1)」，要说「**均摊 O(1)**，总量 O(n)」。
- **空间 O(n)**：栈最多同时装 `n` 个下标（严格递减序列），输出数组 `n`。不额外开别的结构。
- **方案 B 的复杂度**：时间 O(n·V)（V = 值域跨度 = 71），空间 O(V)。`n = 10⁵` 时约 `7·10⁶` 次操作，比栈慢一个数量级但常数极小。

### 061.6.2 七个真实踩过的坑

1. **弹栈条件写成 `<=`** —— 相等温度被结算，`[30,30,30]` 返回 `[1,1,0]`。**判据**：题目说「更高」→ 严格 → 用 `<`；说「不低于」→ 用 `<=`。
2. **栈里存温度而不是下标** —— 存值就只能得到「谁被我解决」，拿不到「相隔几天」；而且重复温度无法区分。**栈里永远存下标。**
3. **返回 `j` 而不是 `j - i`** —— 样例一眼就能看出来，但匆忙时很容易写成「记录下一个更高温的下标」就 return。
4. **默认值写成 `-1`** —— 题目要 0。改法：`make([]int, n)` / `new int[n]` 的零值正好是 0，别自作聪明去填 -1 再补一遍。
5. **Java 里把 `push/pop` 与 `addLast/removeLast` 混用** —— `ArrayDeque` 的 `push` 是 `addFirst`。混着写就悄悄变成了栈底操作，`while` 循环比较的对象都不是栈顶。**统一用一套命名，并在注释里写明「这端是栈顶」。**
6. **收尾忘了「栈里还有残留」** —— 其实收尾不需要做任何事（默认值就是答案），但如果你的默认值是 `-1` 且收尾忘了刷新成 0，递减序列 `[4,3,2,1]` 会返回 `[-1,-1,-1,-1]`。
7. **方案 B 的 `next[]` 更新顺序写反** —— 必须「先算答案、再把 `next[自己的温度] = i`」，否则会把自己当成「右侧最近的出现位置」，得到 `ans[i] = 0`（甚至负数）。

### 061.6.3 面试官最爱追问的三个问题

**Q1：为什么栈里存下标而不是温度？**

> 「因为答案要的是**距离**，`i - j` 必须有 `j`。存温度只能算出『谁被我解决了』，算不出跨度；而且温度会重复，重复值在栈里无法区分是谁。下标还顺便把『左边界/右边界』这类位置信息一起带进了结构，这就是后面柱状图（062）能直接复用的原因。」

**Q2：为什么这是 O(n)？内层 `while` 看起来可能弹很多次。**

> 「是**摊还** O(n)。每个下标只入栈一次，所以出栈总数不超过入栈总数 n；把内层循环的总执行次数加起来不超过 n，加上外层 n 次，一共 O(n)。单次迭代最坏确实可能是 O(n)（前面 n-1 个递减、最后来个最高温），但那种情况只可能发生一次。这就是 monotonous stack 类题目的标准复杂度证明：**用『入栈次数』给『出栈次数』封顶**。」

**Q3：如果温度不是整数、或者值域到 10⁹，你的第二种解法还成立吗？**

> 「`next[温度]` 那个方案立刻作废 —— 它要求值域小到能开数组。这时只剩单调栈：它对值域完全无要求，只依赖『下一个更大』这个偏序关系。这也说明方案选择的分界线：**值域小 → 桶/计数可以换常数；值域大 → 只能靠结构（栈/树）维护顺序。** 如果温度还会被修改（区间加 + 查询），那就得再往上换成线段树上二分。」

