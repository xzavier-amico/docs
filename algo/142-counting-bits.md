## 142.1 题目

**原题链接**：<https://leetcode.cn/problems/counting-bits/>

### 题意重述（把隐含条件补齐）

给你一个非负整数 `n`，返回一个长度为 `n + 1` 的数组 `ans`，其中 `ans[i]` 是整数 `i` 的二进制表示里 **`1` 的个数**，`i` 从 `0` 取到 `n`（**两端都包含**）。

进阶要求原话是「很容易想到时间复杂度为 `O(n·log n)` 的解决方案，你可以想出 `O(n)` 的解决方案吗」。这句话藏着四个条件：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 要算 **`0` 到 `n`**，共 `n + 1` 个数 | 「对于每个 `i`（`0 <= i <= n`）」 | 数组开成 `n` 长 → 越界/少一个元素；截至本章仍是最高频的错 |
| `i = 0` 也要算 | `0 <= i` | `0` 的答案是 `0`，容易在「从 1 开始循环」时把 `ans[0]` 忘掉（Java 默认值恰好是 0，侥幸正确；但若初值逻辑变了就露馅） |
| 进阶要 **O(n)** | 「你可以想出 `O(n)` 的解决方案吗」 | 「对每个数调 `141` 的解法」是 `O(n·32)`，能过题但答不到进阶 |
| 不要求你**不调用内建函数**，但面试会问 | 题面无此限制 | 用 `Integer.bitCount` 一行过题可以，但面试官会追问「自己实现一遍」 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `0 <= n <= 10^5` | 最多 10 万个数字 | `O(n·32) = 3.2·10⁶` 次位运算，本机实测 Java ≈ 3 ms、Go ≈ 2 ms —— **能过**。所以这题的难点**不是**能否通过，而是能否把 `32` 这个常数也去掉 |
| `ans` 长度 `n + 1` | 输出本身就要 `O(n)` 空间 | 「额外空间」在这里只算得清：输出必须占 `n+1` 个 `int`，除此之外只用 `O(1)` 个变量 |
| 值域 `0 ~ 10^5` | 17 位二进制（`2^17 = 131072`） | 每个数的 1 的个数的上界只有 17，所以结果可以用 `byte` 存；但 Java 的 `int[]` 签名固定，不用优化 |

> 💡 **量级 → 算法** 的一条新经验：
> **当输出是一整张表、而表里每一格都能由「更小规模」的格子算出时，就该想 DP（递推），而不是「对每格独立算一遍」。**
> 这题的特征非常典型：`n + 1` 个格子，格子之间有 `i >> 1` 这条清晰的「父子边」。

### 示例

```text
输入：n = 2
输出：[0, 1, 1]
解释：0 → 0；1 → 1；2 → 10（1 个 1）

输入：n = 5
输出：[0, 1, 1, 2, 1, 2]
解释：0 → 0
      1 → 1
      2 → 10
      3 → 11
      4 → 100
      5 → 101
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① n = 0            → 答案 [0]。数组长度必须是 1，不是 0
② n = 1            → 答案 [0, 1]。暴露「循环从 2 开始」的写法（漏掉 1）
③ n = 7            → 答案 [0,1,1,2,1,2,2,3]，最后一个是 2³−1，全 1
④ n = 131071 (2¹⁷−1) → 答案最后一位是 17。暴露「结果当 4 位 / 8 位存」的溢出式错误
```

第 ① 条要特别记：**空输入不存在，但「最小输入」存在**。`n = 0` 是这题唯一一个「答案长度为 1、循环一次都不跑」的输入，所有 off-by-one 的错都会在它身上第一次显形。

## 142.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来，别急着优化）

最直白的做法：把上一章的函数当黑盒，对每个 `i` 各调一次。

```java
int[] ans = new int[n + 1];
for (int i = 0; i <= n; i++) {
    int x = i, cnt = 0;
    while (x != 0) { x &= x - 1; cnt++; }   // 141 章的消位法
    ans[i] = cnt;
}
return ans;
```

- 时间 **O(n · popcount)** ≤ **O(n · 32)**，空间 **O(1)** 额外（不含输出）。
- `n = 10^5` 时最坏约 `3.2·10⁶` 次位运算，**能过**。
- 它的病根是两条，都必须说出来：
  1. **32 这个常数被重复付了 `n` 次**：每个数都要重新「消到 0」，而 `i` 与 `i >> 1` 的答案其实只差一位。
  2. **信息被丢掉了**：算完 `ans[3] = 2` 之后，`ans[7]`、`ans[6]` 其实可以直接从它得到，但暴力把这张现成的表扔了。

### 第二步：卡点在哪

把问题翻译成一句话：

> **我要填一张 `n + 1` 格的表，而每一格的答案与「另一个更小的数」的答案只差一丁点。**

于是卡点变得非常具体：

> **有没有一条「从 `i` 指向更小的数」的边，使得两格的答案关系是 `ans[i] = ans[小] + 已知常数`？**

一旦找到这条边，填表就变成「按顺序从左往右推」，每格 **O(1)**，总共 **O(n)**。

### 第三步：灵感的来源 —— `i` 和 `i >> 1` 只差一个最低位

把 `i` 写成二进制，右移一位就是「**把最低位砍掉**」：

```
i      = 1 0 1 1 0 1
i >> 1 = 0 1 0 1 1 0      ← 少了最低位，其余位整体右挪
```

砍掉最低位，`1` 的个数只会少 `0` 个或 `1` 个——少的那个 `1` 就是被砍掉的那一位本身。所以：

```
popcount(i) = popcount(i >> 1) + (i & 1)
```

又因为 `i >> 1 < i`（对 `i ≥ 1`），**算 `ans[i]` 的时候 `ans[i >> 1]` 已经在表里了**。于是：

```java
int[] ans = new int[n + 1];
for (int i = 1; i <= n; i++)
    ans[i] = ans[i >> 1] + (i & 1);
return ans;
```

**五行。这就是进阶要求的那条 `O(n)`。**

### 第二条同样漂亮的递推：`ans[i] = ans[i & (i-1)] + 1`

上一章的恒等式给了另一条边：`i & (i-1)` 是「把最低位的 1 抹掉」，比 `i` 小，且 1 的个数正好少 1。于是

```
popcount(i) = popcount(i & (i - 1)) + 1
```

两条递推都正确、都是 O(n)。它们的差别值得在面试里主动讲：

| 递推式 | 「更小的数」是 | 循环次数内的操作 | 适合谁 |
| --- | --- | --- | --- |
| `dp[i] = dp[i >> 1] + (i & 1)` | `i` 的**父亲**（去最低位） | 一次移位 + 一次与 + 一次加 | 想建立「二叉树」直觉时；它与 `141` 无关，纯看位串 |
| `dp[i] = dp[i & (i-1)] + 1` | `i` 的**兄弟链**（去最低位 1） | 一次减一 + 一次与 + 一次加 | 承接 `141` 的 `n & (n-1)`，记忆负担最小 |

### 为什么「`ans[i] = ans[i-1] + 1`」是错的

因为 `i - 1` 与 `i` 的二进制关系不是「删一位」，而是**一串进位**：`7 = 111 → 8 = 1000`，1 的个数从 3 掉到 1。所以「相邻数」之间**没有**稳定的加减关系，必须用 `i >> 1` 或 `i & (i-1)` 这种「真的删掉一位」的边。

> 这正是 DP 的核心判据：**要的是「规模严格更小、答案已知」的边，而不是「下标更小」的边。**

## 142.3 原理拆解

### 142.3.1 数据结构与算法选型

| 方案 | 时间 | 空间（额外） | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 每个数各跑一遍 141 的消位法 | O(n · popcount) ≤ O(32n) | O(1) | 5 行 | 面试追问「能 O(n) 吗」时；`n` 放大到 `10⁸` 时 |
| 每个数各跑一遍逐位扫描 | O(32n)，**固定 32 次/数** | O(1) | 4 行 | 稀疏输入时最浪费（哪怕最坏与消位法一样） |
| **`dp[i] = dp[i>>1] + (i&1)`** ✅ | **O(n)** | **O(1)** | **4 行** | 需要「按最高有效位分段」的变体时不如 offset 法直观 |
| `dp[i] = dp[i & (i-1)] + 1` | O(n) | O(1) | 4 行 | 与上一式等价；无额外缺点 |
| offset（最高有效位）法 | O(n) | O(1) | 7 行 | 要额外维护 `offset`，多一个变量、多一处更新时机 |
| `Integer.bitCount` / `bits.OnesCount` | O(n) 级，内建 | O(1) | 2 行 | 面试要求手写；但生产代码里这是**首选** |

> **这份表的价值**：`O(32n)` 与 `O(n)` 在 `n = 10^5` 时的差只有 32 倍，肉眼几乎看不出。**所以这题考的不是「能不能过」，而是「你知不知道常数也是可以优化的对象」。**

### 142.3.2 为什么这个做法是对的（正确性论证）

**命题**：设 `f(x) = x` 的二进制中 `1` 的个数，则对一切 `i ≥ 1`，`f(i) = f(i >> 1) + (i & 1)`。

**证明**：把 `i` 的二进制写成 `b_k b_{k-1} … b_1 b_0`（`b_0` 是最低位）。那么：

1. `i >> 1` 的二进制是 `b_k b_{k-1} … b_1`，即把最低位 `b_0` 砍掉。
2. `i & 1 = b_0`。
3. 两边的「1 的个数」是同一串位在「砍掉一位」前后的计数，被砍掉的那一位贡献恰好 `b_0`：
   `Σ_{j=0..k} b_j = Σ_{j=1..k} b_j + b_0`。∎

**命题（DP 正确性，用归纳法而非逐点证明）**：

```
不变量：填第 i 格之前，ans[0 .. i-1] 全部正确
```

- 初始化：`ans[0] = 0`（Java/Go 的数组默认值就是 0，逻辑上也确实如此：`0` 没有 1）。此时「已填区间」是 `[0, 0]`，正确。
- 保持：填 `ans[i] = ans[i >> 1] + (i & 1)`。因为 `i ≥ 1` 时 `i >> 1 ≤ i - 1`，索引落在「已正确」的区间内，由上面的命题，`ans[i]` 正确。区间扩为 `[0, i]`。
- 终止：`i` 走到 `n`，`ans[0..n]` 全部正确。∎

**顺带把另一条递推也证掉**：`i & (i-1) < i`（`141` 章命题 1 说的是「清掉一个 1」，清掉必然变小，且 `i ≥ 1` 时至少清掉一个 1），所以 `ans[i & (i-1)]` 也已经在表里；由同一命题，`f(i) = f(i & (i-1)) + 1`。∎

> **两条递推的共同骨架**：先证「值的关系」，再证「下标的偏序（小 → 大）」，两者合起来才构成 DP。**只证前者、不证后者，就可能读到还没算的格子（例如 `dp[i] = dp[i+1] + 1` 这种方向反了的递推）。**

### 142.3.3 通用解题思路（可迁移的那一层）

本章的核心可迁移物是这条**递推模板**：

```
规模为 i 的答案 = 规模更小的某个 j（j < i）的答案 + 一次 O(1) 的增量
     ↓ 找到这条「边」的所有候选
位级三种「把 i 变小」的方式：
    i >> 1       砍掉最低位          → popcount 少 0 或 1
    i & (i - 1)  抹掉最低位的 1      → popcount 少 1（141 章）
    i ^ (i & -i) 同上去掉最低位 1 的另一种写法（与上式结果相同）
    再配合「最高有效位」分段：offset = 2^⌊log₂i⌋
```

**这套模板能做的题远不止 338**：

| 题 | 递推的「边」 | 递推式 |
| --- | --- | --- |
| [LC 338](https://leetcode.cn/problems/counting-bits/) | `i >> 1` | `dp[i] = dp[i>>1] + (i&1)` |
| [LC 70 爬楼梯](https://leetcode.cn/problems/climbing-stairs/)（本书 108 章） | `i-1`、`i-2` | `dp[i] = dp[i-1] + dp[i-2]` |
| [LC 120 三角形最小路径和](https://leetcode.cn/problems/triangle/)（本书 120 章） | 上一行两个相邻格子 | `dp[i][j] = min(dp[i+1][j], dp[i+1][j+1]) + a[i][j]` |
| [LC 647 回文子串](https://leetcode.cn/problems/palindromic-substrings/) | `(i+1, j-1)` | 中心扩展 / 区间 DP |

**共同点**：都是「先找一个能把问题规模压小的结构，再按这个结构的拓扑序填表」。338 的特殊之处在于：**这个结构是「二进制位串的父子关系」，天然形成一棵以 0 为根的二叉树**（见 §142.4.2 的图）。

### 142.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| `n` 放大到 `10⁹`（打不下表） | 内存爆 | 不建表：① 单点查询用 `141` 的 O(popcount) ② 区间查询 `[0, n]` 里 1 的**总和**有闭式公式（按位统计：第 `k` 位在 `0..n` 中出现 `⌊n/2^{k+1}⌋·2^k + max(0, n mod 2^{k+1} − 2^k + 1)` 次） |
| 只要**总和**不要每个值 | 输出变小 | 用上面的按位统计公式，`O(log n)` 时间、`O(1)` 空间 |
| 输入变成 **64 位** | 表长度爆掉 | 位宽 64 时递推式不变，`dp` 存 `int`；若 `n` 到 `10⁶` 以上，`dp` 改 `byte` 省 4 倍内存（1 的个数 ≤ 64，`byte` 装得下） |
| 要**流式输出**（边算边给，不许存表） | 不能回头读 `ans[i>>1]` | 两条递推都只依赖「比自己小的下标」——可以只保留最近 `2^k` 个值做窗口，但跨窗口就失效；更稳的是 `i & (i-1)` 这条边（它跳跃可能很大，同样需要历史）。结论：**流式场景只能退回单点算法 O(popcount)** |
| 要 **`ans[i]` 的下标列表**（哪些数的 popcount 等于 k） | 反向索引 | 边填边把下标追加到 `bucket[ans[i]]`，一次遍历完成分组 |
| 要求**不改输入、多线程** | 无副作用 | 递推的每格只依赖 `ans[i>>1]`，在**同一层**（`2^k ≤ i < 2^{k+1}`）内可以并行；跨层必须同步。这是「按层并行 DP」的最小例子 |

## 142.4 图解推演

### 142.4.1 `i → i >> 1` 形成的二叉树

把 `i >> 1` 看成「父亲」，`2i`、`2i+1` 看成「儿子」，`0..15` 就长成一棵**满二叉树**，父亲的答案加上「自己是奇数还是偶数」就是儿子的答案：

```
                             0 (0)
                    ┌────────┴────────┐
                   0 (0)            1 (1)          i = 0..1
              ┌──────┴─────┐    ┌─────┴─────┐
            0 (0)       1 (1) 1 (1)       2 (2)   i = 0..3
          ┌───┴──┐   ┌───┴──┐ ┌──┴───┐  ┌───┴──┐
         0(0)  1(1) 1(1) 2(2) 1(1) 2(2) 2(2) 3(3) i = 0..7
```

每个节点的值 = 父亲的值 + (自己是最低位为 1 的右儿子 ? 1 : 0)。**这就是 `dp[i] = dp[i>>1] + (i&1)` 的全部含义。**

用箭头写出「读表方向」：

```
  dp[0] ──► dp[1] ──► dp[2] ──► dp[3] ──► dp[4] ──► ...
    │         │         │         │         │
    └─────────┴─────────┴─────────┴─────────┘
      每条边只从「小」指向「大」，所以从左往右一遍填完
```

### 142.4.2 逐步填表（n = 5）

| `i` | 二进制 | `i >> 1` | `i & 1` | `dp[i>>1]` | `dp[i]` |
| --- | --- | --- | --- | --- | --- |
| 0 | `000` | — | — | —（初值） | **0** |
| 1 | `001` | 0 | 1 | 0 | **1** |
| 2 | `010` | 1 | 0 | 1 | **1** |
| 3 | `011` | 1 | 1 | 1 | **2** |
| 4 | `100` | 2 | 0 | 1 | **1** |
| 5 | `101` | 2 | 1 | 1 | **2** |

结果 `ans = [0, 1, 1, 2, 1, 2]`，与示例一致。

### 142.4.3 同一张表的两条递推对照

```
n = 8，两条递推各填一遍

i :            0   1   2   3   4   5   6   7   8
popcount(i) :  0   1   1   2   1   2   2   3   1
               │   │   │   │   │   │   │   │   │
边 A (i>>1) :  ─   0   1   1   2   2   3   3   4     ← 父亲下标
边 B (i&(i-1)):─   0   0   2   0   4   4   6   0     ← 抹掉最低位 1 后

A 读法：dp[6] = dp[3] + (6&1) = 2 + 0 = 2 ✓
B 读法：dp[6] = dp[4] + 1     = 1 + 1 = 2 ✓
```

> 两条边都只指向**更小**的下标，这是它们能用来填表的唯一原因。**注意边 B 的跳跃可以很大**（`8 → 0`），但永远向左。

## 142.5 双语言实现

### 142.5.1 Java

```java
class Solution {
    public int[] countBits(int n) {
        // 长度必须是 n + 1：题目要算 0..n 共 n+1 个数（n = 0 时长度为 1）
        int[] ans = new int[n + 1];
        // 从 1 开始：ans[0] = 0 是逻辑事实（0 的二进制里没有 1），
        // Java 数组默认初始化为 0，正好省掉显式赋值。
        for (int i = 1; i <= n; i++) {
            // i >> 1 恒 < i，所以 ans[i >> 1] 一定已经算好 → 一遍从左到右即可
            // (i & 1) 取出最低位：它是奇数就多一个 1
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }
}
```

### 142.5.2 Go

```go
package main

func countBits(n int) []int {
	// make 会把切片元素零值初始化，所以 dp[0] = 0 天然成立
	dp := make([]int, n+1)
	for i := 1; i <= n; i++ {
		// 与 Java 完全同一套流程：i 恒为非负，>> 的符号问题在这里不存在
		dp[i] = dp[i>>1] + i&1
	}
	return dp
}
```

> Go 里 `+` 的优先级高于 `&`，`dp[i>>1] + i&1` 实际解析为 `(dp[i>>1] + i) & 1` 吗？**不是。** Go 的运算符分组中 `&`（乘法级）优先级**高于** `+`（加法级），所以它解析成 `dp[i>>1] + (i & 1)`，结果正确；但为了不给读者留考题，正式代码里应当显式写括号。

### 142.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 数组/切片声明 | `new int[n+1]`，**默认全 0** | `make([]int, n+1)`，**零值初始化** | 两者都白送了 `dp[0] = 0`；若换成长度 `n` 就都会越界 |
| 长度语义 | `length` 字段 | `len()` 函数 | 容易在 Go 里把 `make([]int, n)` 当成「n+1 个数」 |
| 返回类型 | `int[]` | `[]int`（切片，带 cap） | 切片的 `cap` 可能大于 `len`，若后续 `append` 会共享底层数组（本题不 append，安全） |
| 运算符优先级 | `+` 高于 `&`：`a + i&1` 编译不过（`int & int` 得 int，但 `+` 先算 → 其实 `a+i` 再 `&1`） | `&` 高于 `+`，语义正好是想要的 | **两边都必须显式加括号**，否则同一行代码在两种语言里语义相反 |
| 位宽 | `int` 恒 32 位 | `int` 在 64 位平台是 64 位 | `i ≤ 10^5 < 2³¹`，两者一致 |

### 142.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/bits"
	"math/rand"
	"testing"
)

// 参考实现：对每个数独立数 32 位（与 141 章的暴力同构，不说技巧）
func bruteCountBits(n int) []int {
	ans := make([]int, n+1)
	for i := 0; i <= n; i++ {
		cnt := 0
		for k := 0; k < 32; k++ {
			if (i>>uint(k))&1 == 1 {
				cnt++
			}
		}
		ans[i] = cnt
	}
	return ans
}

func equalInts(a, b []int) bool {
	if len(a) != len(b) {
		return false
	}
	for i := range a {
		if a[i] != b[i] {
			return false
		}
	}
	return true
}

func TestCountBitsRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20260215))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(600) // 覆盖 0..599，其中 n = 0 一定会被抽到若干次
		got := countBits(n)
		want := bruteCountBits(n)
		if !equalInts(got, want) {
			t.Fatalf("iter=%d n=%d\ngot =%v\nwant=%v", iter, n, got, want)
		}
		// 第三方交叉验证：标准库（bug 方向与上面两者都不同）
		if len(got) != n+1 {
			t.Fatalf("iter=%d n=%d 长度错：%d", iter, n, len(got))
		}
		for i := 0; i <= n; i++ {
			if got[i] != bits.OnesCount(uint(i)) {
				t.Fatalf("iter=%d n=%d i=%d got=%d stdlib=%d", iter, n, i, got[i], bits.OnesCount(uint(i)))
			}
		}
	}
}

func TestCountBitsEdge(t *testing.T) {
	cases := []struct {
		n    int
		want []int
	}{
		{0, []int{0}},                          // 最小输入：长度 1
		{1, []int{0, 1}},                       // 两格
		{2, []int{0, 1, 1}},
		{5, []int{0, 1, 1, 2, 1, 2}},
		{7, []int{0, 1, 1, 2, 1, 2, 2, 3}},     // 2³−1，最后一格全 1
		{8, []int{0, 1, 1, 2, 1, 2, 2, 3, 1}},  // 跨越 2³：从 3 掉回 1
	}
	for _, c := range cases {
		if got := countBits(c.n); !equalInts(got, c.want) {
			t.Fatalf("n=%d got=%v want=%v", c.n, got, c.want)
		}
	}
}
```

> **`n = 8` 这个用例是特意加的**：它跨越了 `2³` 的边界，`popcount(7) = 3` 而 `popcount(8) = 1`。任何「`ans[i] = ans[i-1] ± 常数`」的错误递推都会在它身上立刻崩掉。

## 142.6 复杂度与常见坑

### 142.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：循环 `i` 从 `1` 到 `n`，共 `n` 次；每次只做「一次右移 + 一次与 + 一次加 + 一次数组读写」，都是固定代价。注意这**与位数无关**——这正是相对 `O(32n)` 的改进所在：`32` 这个常数被彻底消掉了。
- **空间 O(1) 额外**：除了必须返回的长度 `n+1` 的数组，只用了一个循环变量。严格写是「**O(n) 输出 + O(1) 辅助**」。
- **推广到一般位宽 `w`**：暴力是 `O(w·n)`，递推仍是 `O(n)`。所以 `w` 越大（64 位、128 位），递推的优势越明显。
- **和「一次遍历 + 内建 popcount」比**：内建 `popcnt` 是单条指令，实测常数更小（`n=10^5` 时约 0.05 ms），但那是**硬件**帮你做到的 `O(n)`；面试问的是**算法**层面能不能 `O(n)`。

### 142.6.2 七个真实踩过的坑

1. **数组长度写成 `n`** —— 少一格，`ans[n]` 越界（Java 抛 `ArrayIndexOutOfBoundsException`，Go 直接 panic）。必须 `n + 1`。
2. **循环从 `2` 开始** —— `n = 1` 时返回 `[0, 0]`，`ans[1]` 漏填。必须从 `1` 开始。
3. **漏掉 `ans[0] = 0` 的语义** —— Java/Go 的默认零值恰好正确，但如果把数组换成「先填 -1 表示未算」的写法（比如做记忆化），就会在 `ans[0]` 上出问题。
4. **写成 `ans[i] = ans[i-1] + 1`** —— `7 → 8` 会从 3 掉到 1，进位使相邻数没有稳定关系。必须用 `i >> 1` 或 `i & (i-1)`。
5. **`i & (i-1)` 那条递推忘了 `+1`** —— 写成 `ans[i] = ans[i & (i-1)]`，结果全变成 `ans[0] = 0`，整张表全 0。
6. **运算符优先级** —— Go 里 `&` 高于 `+`、Java 里 `+` 高于 `&`：`dp[i>>1] + i&1` 这行在两种语言里**语义相反**。永远加括号。
7. **在结果里存 `byte` 忘了强转** —— `n = 10^5` 时 popcount 最大 17，`byte` 装得下；但 Java 里 `byte[]` 与签名要求的 `int[]` 不兼容，硬改签名会判题失败。

### 142.6.3 面试官最爱追问的三个问题

**Q1：为什么 `dp[i] = dp[i>>1] + (i&1)` 是 O(n) 的？**

> 「因为每个 `i` 只花一次「移位 + 与 + 加」，与 `i` 的值大小、位数都无关；而且 `i >> 1 < i`，所以从左往右一遍扫过去，每一格读到的都是已经算好的格子，不需要任何重算。相比『对每个数各跑一遍数 1 的算法』，它把那个 32（或 `w`）的因子整个消掉了。」

**Q2：还有别的递推吗？怎么想到的？**

> 「有，`dp[i] = dp[i & (i-1)] + 1`，它用的边是『抹掉最低位的 1』，比 `i` 小，所以也能填表。想到它的方法是：问『把一个数变小、并且能说清 popcount 变化量的操作有哪些』——右移砍最低位（变化 0 或 1）、`& (n-1)` 抹最低位的 1（变化 −1）、以及按最高位取模（`i - 2^⌊log₂i⌋`，变化 −1，这就是 offset 法）。三条边都对。」

**Q3：如果 `n` 是 `10⁹`，你还能这么做吗？**

> 「不能建表了，`10⁹` 个 `int` 就是 4 GB。分两种需求：① **单点查询**直接退回 `O(popcount)` 的消位法，最多 30 步；② 若只要 `[0, n]` 里 1 的**总数**，可以按位统计闭式求解：第 `k` 位在 `0..n` 中出现 `⌊n/2^{k+1}⌋·2^k + max(0, n mod 2^{k+1} − 2^k + 1)` 次，把所有位加起来是 `O(log n)` 时间、`O(1)` 空间。」
