## 137.1 题目

**原题链接**：<https://leetcode.cn/problems/partition-labels/>

### 题意重述（把隐含条件补齐）

给你一个只含小写英文字母的字符串 `s`。把它划分成**尽可能多**的片段，使得**同一个字母最多出现在一个片段中**（也就是说：如果字母 `x` 在 `s` 里出现了多次，那么所有 `x` 必须落在同一个片段里）。返回一个整数数组，表示每个片段的长度（按从左到右的顺序）。

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **划分必须连续、完整** | 「划分成尽可能多的片段」 | 以为是「挑出子序列」→ 变成另一个问题 |
| **同一字母只能落在一段** | 「同一个字母最多出现在一个片段中」 | 只保证「每段内部不重复」→ 会切出跨段重复的非法解 |
| **要求「尽可能多」段** | 「尽可能多的片段」 | 不追求极值 → 直接返回 `[n]` 也是合法划分，但不是答案 |
| **按原顺序拼接** | 「将这些字符串连接起来」 | 允许重排 → 问题失去意义 |
| **只含小写字母** | 约束 | 可以用 `new int[26]`；若含大写或 Unicode，`s[i] - 'a'` 的写法会崩（Go 里 `s[i]` 是 byte） |
| **`n` 可以等于 1** | `1 <= s.length` | 答案 `[1]`；漏判会返回空数组 |

> **本章的题眼**：前两条合起来意味着 —— **切点不能落在一个字母的两次出现之间**。把每个字母看成一个区间 `[first, last]`，「不能切开它」= 「切点必须在它右边」。这就是 §137.2 灵感的全部来源。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= s.length <= 500` | 只有 500 | **本题的约束非常宽松**：O(n²) 甚至 O(n² · 26) 都能过。所以这里考的不是「能不能过」，而是「能不能给出线性且可证的解」 |
| `s` 只含小写英文字母 | 26 种字符 | `last[26]` 计数表 → 额外空间 O(1)（与 `n` 无关） |
| 可能出现「全部相同」的串 | `"aaaa"` | 答案 `[4]`（一个片段），不是 `[1,1,1,1]` |
| 可能出现「全部不同」的串 | `"abcd"` | 答案 `[1,1,1,1]`（每个字符自成一段） |

> 💡 **量级反推**：`n ≤ 500` 说明出题人**故意**放水 —— 他要看的是「你有没有识别出区间结构」。如果你交出 O(n²) 的 DP，能过，但讲不出「为什么贪心对」；而这种「结构识别题」恰恰是面试里最容易被追问到底的。

### 示例

```
输入：s = "ababcbacadefegdehijhklij"
输出：[9, 7, 8]
解释：
  "ababcbaca" | "defegde" | "hijhklij"
   ↑ 前 9 个字母包含了 a、b、c 的全部出现
                        ↑ 7 个字母包含 d、e、f、g 的全部出现
                                    ↑ 8 个字母包含 h、i、j、k、l 的全部出现

输入：s = "eccbbbbdec"
输出：[10]
解释：只有一个 e 和 c 的首尾把整个串都串起来 → 必须一刀不切

输入：s = "ab"
输出：[1, 1]
解释：两个字母毫无瓜葛，各成一段
```

### 我自造的四个反例

```text
① "a"                 → [1]（单字符，别返回 []）
② "aaaa"              → [4]（不是 [1,1,1,1]：同一字母必须同段）
③ "abac"              → [3, 1]（"aba" 必须同段，因为 a 出现在 0 和 2；剩下的 "c" 独立）
④ "qwertyuiopasdfghjklzxcvbnm"  → 26 个 1（全不同，每字符一段）
```

第 ③ 条最能验证「不动点」这个概念：扫到 `i=0`（`a`）时 `end = last[a] = 2`；扫到 `i=1`（`b`）时 `end = max(2, last[b]=1) = 2`；扫到 `i=2`（`a`）时 `end = 2`，`i == end` → 在这里切。**切点不是「猜」出来的，是被 `last[a] = 2` 逼出来的。**

## 137.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 枚举所有切法

`n` 个字符之间有 `n-1` 个空隙，每个空隙「切 / 不切」，共 `2^(n-1)` 种切法。

```text
best = +∞
for 每个切法（n-1 个空隙的各子集）:
    if 每段内没有「跨段的重复字母」:
        best = min(best, 段数)
return 段数与最长的那组切法对应的各段长度
```

- 时间 **O(2ⁿ · n)**，空间 O(n)。
- `n = 30` 时 `2^29 ≈ 5·10^8`，已经跑不动；`n = 500` 完全不可能。

另一条更靠谱的暴力是 DP：`dp[i] = 把前缀 s[0..i] 切成合法片段的最多段数`（注意题目要的是「尽可能多」），转移要枚举最后一段的起点 `j`：

```
dp[i] = 1 + max{ dp[j-1] : 段 s[j..i] 自洽（该段内每个字母的最后出现 ≤ i） }
```

- 时间 **O(n²)**（每对 `(j, i)` 只要 O(1) 判定「段内最大 `last` 是否 ≤ i」），空间 **O(n)**。
- `n = 500` 时 `2.5·10^5` 次，轻松通过 —— **所以本题的 O(n²) 是能过的**。那为什么还要优化？

### 第二步：卡点在哪

因为**题目想考的不是「能不能过」，而是「你有没有看出这个结构」**。看 DP 的合法性判据：

> 段 `s[j..i]` 自洽 ⟺ 对段内每个字母 `c`，`last[c] ≤ i`。

也就是说，**合法性完全由「段内字母的最远出现位置」决定**，跟别的信息毫无关系。既然如此，「上一段的起点 `j` 是多少」其实并不重要 —— 重要的是「当前扫到的位置，和已开区间的最远右端，谁先到」。

把每个字母看成一个区间：

```
s = "abac"
a → [0, 2]
b → [1, 1]
c → [3, 3]

  0    1    2    3
  ●━━━━━━━━━○         ← 区间 a
       ●○              ← 区间 b
                 ●○    ← 区间 c

问题变成：最少切几刀，使每个区间都完整落在某一段里？
```

### 第三步：灵感的来源 —— 「不动点」扫描

从位置 `L` 开始，先把 `end` 设成 `L`；然后从左往右扫，每看到一个字母 `c`，就把 `end` 更新为 `max(end, last[c])`：

- 如果某个字母的最后出现位置在 `end` 右边，说明**这一段必须延长**，否则该字母会跨段；
- 扫到 `i == end` 时，说明 `[L, end]` 里所有字母的最后出现都 `≤ end`（每个都被 `end` 兜住了），**这一段可以在这里收口**，且这是能收口的**最早**位置。

```
不变量（本章核心）：扫描到 i 时，end = max{ last[s[t]] : L ≤ t ≤ i }
                  「[L, end] 内的所有字母，最后出现位置都 ≤ end」是能切的条件
```

**关键结论**：这个 `end` 不只是「一个可行切点」，而是「**任何合法切分的第一段右端都 ≥ end**」。§137.3.2 会用反证把这句话钉死 —— 这才是「凭什么敢切」的全部理由。

## 137.3 原理拆解

### 137.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举所有切法（`2^(n-1)`） | O(2ⁿ·n) | O(n) | 15 行 | `n ≥ 30` 就跑不完；只能当对拍判据 |
| DP（`dp[i] = 1 + min dp[j-1]`） | O(n²) | O(n) | 15 行 | 本题能过；但 `n = 10^5` 的变体立刻超时，且证明更绕 |
| 按「字母区间」合并（先排序再合并，56 的写法） | O(n log n) 或 O(n + 26) | O(n) | 20 行 | 多一次排序；而且「区间重叠」的判据要自己推 |
| **最远出现位置扫描（不动点贪心）** ✅ | **O(n)** | **O(1)**（26 计数表） | **10 行** | 若字符集变成任意 Unicode（不是 26 个），计数表要换成哈希，空间不再是 O(1) |
| 后缀判重（`sufMask[i]` 位运算） | O(n) | O(n) | 12 行 | 需要 26 位掩码 + 两次扫描，可读性差，收益为零 |

**为什么最后的方案是 O(1) 额外空间**：`last[26]` 与 `n` 无关；扫描只用 `start / end / i` 三个变量。这是「识别结构」带来的收益 —— 连「所有区间」都不需要显式构造出来。

### 137.3.2 为什么这个做法是对的（正确性论证 · 归纳法 + 反证引理）

先写清算法：

```text
last[c] = c 在 s 中最后一次出现的下标
start = 0, end = 0
for i = 0 .. n-1:
    end = max(end, last[s[i]])
    if i == end:                      # 收口
        记录长度 end - start + 1
        start = i + 1
```

**记号**：对位置 `L`（一段的起点），定义

```
f_L(r) = max{ last[ s[t] ] : L ≤ t ≤ r }        （段 [L, r] 内所有字母的最远出现位置）
end*(L) = 最小的 r ≥ L 使得 f_L(r) ≤ r           （「不动点」，一定存在：r = n-1 时必然满足）
```

注意 `f_L` 单调不减（`r` 变大，取 max 的集合变大），且 `end*` 的定义与贪心中「`end` 一路涨到 `i == end` 那一刻」完全相同。

**引理 1（合法性判据）**
段 `[L, r]` 可以单独成段（不与它右边共享任何字母）⟺ `f_L(r) ≤ r`。

*证明*：`f_L(r) ≤ r` 意味着 `[L, r]` 内出现的每个字母，其**所有**出现位置都 `≤ r`（`last[c]` 是最后出现位置）。于是这些字母在 `(r, n)` 中一次都不出现，段的左右两侧不会共享字母；反之，若某个字母 `c` 在 `[L,r]` 出现且 `last[c] > r`，则 `c` 也出现在右边，两侧共享 ⟹ 非法。∎

**引理 2（切点的下界 —— 反证）**
设 `[L, r]` 是某个合法划分的第一段，则 `r ≥ end*(L)`。

*反证*：设 `r < end*(L)`。由 `end*` 的**最小性**，任何 `r' < end*(L)` 都**不是**不动点，即 `f_L(r) > r`。于是存在字母 `c`，它在 `[L, r]` 中出现过，且 `last[c] > r`：这个 `c` 同时出现在 `[L, r]` 与 `(r, n)` 中，即第一段和后面某段共享字母 `c`，与「合法划分」矛盾。∎

> 这一步是本章的**全部技术含量**：它把「贪心切得早」翻译成「任何合法解都不可能更早」。没有它，`i == end` 就只是一个碰巧跑得通的写法。

**引理 3（切在 `end*` 处一定合法）**
由 `end*` 的定义，`f_L(end*) ≤ end*`，由引理 1 段 `[L, end*]` 自洽；而它右侧的每个字母在 `[L, end*]` 中都没出现过（因为段内字母的最后出现 ≤ `end*`），所以右侧的划分与本段完全解耦。∎

**引理 4（贪心的每一刀都不晚于任何合法解 —— 归纳 + 反证）**
设贪心各段的右端为 `c_1 < c_2 < … < c_k`，任一合法划分为 `r_1 < r_2 < … < r_m`（都是段右端下标）。则对每个 `i <= m` 都有 `c_i <= r_i`。

*证明（对 i 归纳）*：

- **基础 `i = 1`**：由引理 2，`r_1 >= end*(0) = c_1`。
- **归纳步**：设 `c_{i-1} <= r_{i-1}`，反设 `c_i > r_i`。注意 `r_i > r_{i-1} >= c_{i-1}`，所以 `r_i >= c_{i-1}+1`，即 `r_i` 落在贪心第 `i` 段 `[c_{i-1}+1, c_i]` 的内部（严格早于 `c_i`）。由 `c_i = end*(c_{i-1}+1)` 的**最小性**，`r_i` 不是不动点，即

  ```
  f( r_i ) = max{ last[s[t]] : c_{i-1}+1 <= t <= r_i }  >  r_i
  ```

  于是存在字母 `x`：`x` 在 `[c_{i-1}+1, r_i]` 中出现过（某个位置 `p <= r_i`），且 `last[x] > r_i`（另一次出现在位置 `q > r_i`）。合法划分要求 `x` 的所有出现落在**同一段**里，而包含 `p` 与 `q` 的那一段是区间，必须跨过边界 `r_i` —— 与「第 `i` 段在 `r_i` 处收口」矛盾。故 `c_i <= r_i`。∎

**定理（贪心给出段数最多的划分）**
由引理 3，贪心切出的每一段都自洽，所以贪心是一个合法划分；由引理 4 取 `i = m`，得 `k >= m`。而 `m` 是**任意**合法划分的段数（特别地，取到最大值时也成立），于是贪心段数 `k` 不小于任何合法划分的段数，即 `k` 就是最大值。∎

**补充说明（为什么「切得早」反而段数多）**
直觉上容易搞反：既然每段都要「撑到不动点」，为什么贪心反而能得到**最多**的段？
因为**段数是被切点位置决定的，而不是被段长决定的**：切得早 ⇒ 剩下的后缀更长 ⇒ 后续能切出的段数不会更少。引理 4 正是把这句话变成了「`c_i <= r_i` 对每个 `i` 成立」—— 贪心的每一刀都不晚于任何合法解的对应那刀，所以它一定能切出不少于对方的段数。反过来，如果某一刀切晚了（把尾巴上的字母提前吞进当前段），后面就少了一切再切的机会。

> **这个论证的骨架**：先定义「不动点」这个可算的量（引理 1、3 说明它给出可行切点），再用**反证**证明它不是「一种」可行切点、而是「**最小**的可行切点」（引理 2），最后用**归纳**证明「每一刀都比任何合法解更早」（引理 4）→ 段数最多（定理）。

### 137.3.3 通用解题思路（可迁移的那一层）

本题是 **「区间 → 连通分量 → 不动点扫描」** 模型：

```
原始问题：把字符串切成最多的段，使同一字母不跨段
         ↓ 等价变形：每个字母 c 对应区间 [first[c], last[c]]，要求切点不落在任何区间内部
建模：    所求的每一段 = 这些区间「重叠/相邻连通」后的一个连通分量
         ↓ 连通分量的右端 = 该分量内所有区间右端的最大值
贪心：    扫描 + end = max(end, last[c])，i == end 时收口
为什么对：end 是所有合法切点的下界（反证），贪心恰好取到下界
```

### 137.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要求**每段长度 ≤ k** 且字母不跨段 | 加了长度上界 | 不动点可能超过 `k` → 需要判「无解」；贪心不再直接可用，要 DP |
| 允许**切开的字母**付出代价（加权） | 变优化问题 | DP：`dp[i] = min(dp[j] + cost)`，O(n²) 或带预处理 O(n·26) |
| 要求**恰好 k 段** | 加约束 | DP 二维状态，贪心不再适用 |
| 字符集不是 26 个小写字母（含大写/Unicode） | `last[26]` 不够 | 换成 `map[rune]int`；Go 里必须 `[]rune(s)`，否则 `s[i]` 是 UTF-8 字节 |
| `n` 放大到 `10^7`（数据流） | 无法两遍扫描 | 必须边读边记录，但「最后出现」本质上需要读完整串 → 要么落盘再扫，要么先建索引 |
| 要求**每段内部字符都不重复**（而不是「跨段不重复」） | 换了约束 | 那是 [LC 2405](https://leetcode.cn/problems/optimal-partition-of-string/)，贪心变成「见到重复就切」 |

- **LC 2405 子字符串的最优划分**：同一句话「切最少段」，但约束从「跨段不重复」变成「段内不重复」，贪心判据完全不同，很适合对比训练。

### 137.4.2 逐轮扫描状态表（`s = "abac"`）

| 轮次 i | s[i] | last[s[i]] | end（更新后） | i == end ? | 动作 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | a | 2 | 2 | 否 | — | `a` 的最后出现是 2，这一段至少要撑到 2 |
| 1 | b | 1 | 2 | 否 | — | `b` 的最后出现是 1，`end` 不变（被 `a` 兜住） |
| 2 | a | 2 | 2 | **是** | 记录长度 `2-0+1=3`，`start=3` | `[0,2]` 收口：`a` 和 `b` 都已了结 |
| 3 | c | 3 | 3 | **是** | 记录长度 `3-3+1=1`，`start=4` | `[3,3]` 收口 |
| — | — | — | — | — | 答案 `[3, 1]` ✓ |

### 137.4.3 为什么不能「更早切」——反证图解

```text
反例：s = "abac"，若在 i = 1 处就把第一段收口（r = 1 < end* = 2）

  段 1: [0, 1] = "ab"        段 2: "ac"
                    ▲
                    └── 字母 a 同时出现在段 1（下标 0）和段 2（下标 2）
                        ⇒ 违反「同一字母只能出现在一个片段中」

反过来说：只要 r < end*，就必然存在某个字母「左边出现过、右边还会再出现」，
因为它把一个区间劈成两半。**「切早了」不是「可能不优」，而是「一定非法」。**
```

## 137.5 双语言实现

### 137.5.1 Java

```java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> partitionLabels(String s) {
        int n = s.length();

        // last[c] = 字母 c 在 s 中最后一次出现的下标。
        // 26 个格子与 n 无关 → 额外空间 O(1)。
        int[] last = new int[26];
        for (int i = 0; i < n; i++) {
            last[s.charAt(i) - 'a'] = i;   // 顺扫 + 覆盖 = 天然留下最后一个下标
        }

        List<Integer> res = new ArrayList<>();
        int start = 0;   // 当前段的起点
        int end = 0;     // 当前段的「最晚必须收口」位置 = max{ last[s[t]] : start <= t <= i }

        for (int i = 0; i < n; i++) {
            int c = s.charAt(i) - 'a';
            if (last[c] > end) {
                end = last[c];          // 这个字母在更右边还出现 → 这一段必须延长
            }
            // i 追上了 end：说明 start..end 里所有字母的最后出现都 <= end，
            // 这一段自洽，且这是能收口的**最早**位置（引理 2：任何合法切分都必须 >= end）
            if (i == end) {
                res.add(end - start + 1);
                start = i + 1;          // 下一段的起点
            }
        }
        return res;
    }
}
```

### 137.5.2 Go

```go
package main

func partitionLabels(s string) []int {
	n := len(s)

	// 只含小写字母，所以 s[i] 是单字节，可以直接做 byte 运算。
	// 若输入可能含中文/emoji，必须先转 []rune，否则 s[i] 只是 UTF-8 的一个字节。
	last := make([]int, 26)
	for i := 0; i < n; i++ {
		last[s[i]-'a'] = i
	}

	res := make([]int, 0, 8)
	start, end := 0, 0

	for i := 0; i < n; i++ {
		if c := int(s[i] - 'a'); last[c] > end {
			end = last[c]
		}
		if i == end { // 收口：这是最早可行的切点
			res = append(res, end-start+1)
			start = i + 1
		}
	}
	return res
}
```

### 137.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 取第 `i` 个字符 | `s.charAt(i)` 返回 `char`（16 位） | `s[i]` 是 `byte`（UTF-8 单字节） | **只含小写字母时两者等价**；若含中文，Go 必须先 `[]rune(s)`，否则会把一个汉字拆成 3 个字节处理 |
| 下标运算 | `s.charAt(i) - 'a'` 结果为 `int` | `s[i] - 'a'` 结果是 `byte`，要与 `int` 比较需显式转换 | Go 里出现 `int(s[i]-'a')` 不是啰嗦，是为了避免 `byte` 溢出的隐式行为 |
| 结果容器 | `List<Integer>` + 自动装箱 | `[]int` + `append` | Go 无装箱，`[]int` 更省；`make([]int, 0, 8)` 预分配能少几次扩容 |
| 长度 | `s.length()` | `len(s)` | `len(s)` 对字符串是**字节数**，不是字符数 —— 这是 Go 的经典坑 |
| 返回空 | `new ArrayList<>()` | `nil` 或 `[]int{}` | 本题 `n >= 1` 不会为空，但通用函数要注意 `nil` 与空切片的 `len` 都是 0 |

### 137.5.4 对拍测试（暴力枚举切点）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：枚举 2^(n-1) 种切法，保留「合法且段数最多」的那一个，返回段数。
// 判据只看「段数是否相等」+「贪心给出的划分是否合法」，不比较具体切法
// （因为「数组逐项相等」比「段数相等」脆得多）。
func bruteParts(s string) int {
	n := len(s)
	best := 0
	for mask := 0; mask < (1 << (n - 1)); mask++ { // mask 的第 k 位 = 在下标 k 之后切一刀
		// 按 mask 切段
		parts := make([]int, 0, n) // 每段的起始下标
		parts = append(parts, 0)
		for k := 0; k < n-1; k++ {
			if mask&(1<<k) != 0 {
				parts = append(parts, k+1)
			}
		}
		// 校验：每个字母只能落在同一段里
		seg := make([]int, n) // seg[i] = 下标 i 属于第几段
		for id := 0; id < len(parts); id++ {
			from := parts[id]
			to := n
			if id+1 < len(parts) {
				to = parts[id+1]
			}
			for i := from; i < to; i++ {
				seg[i] = id
			}
		}
		ok := true
		seenSeg := map[byte]int{}
		for i := 0; i < n && ok; i++ {
			if id, exists := seenSeg[s[i]]; exists && id != seg[i] {
				ok = false
			}
			seenSeg[s[i]] = seg[i]
		}
		if ok && len(parts) > best {
			best = len(parts)
		}
	}
	return best
}

// 校验贪心给出的划分是否合法（防止「段数对但切错位置」）
func validPartition(s string, parts []int) bool {
	sum := 0
	for _, v := range parts {
		if v <= 0 {
			return false
		}
		sum += v
	}
	if sum != len(s) {
		return false
	}
	seg := make([]int, len(s))
	idx := 0
	for id, v := range parts {
		for k := 0; k < v; k++ {
			seg[idx] = id
			idx++
		}
	}
	seen := map[byte]int{}
	for i := 0; i < len(s); i++ {
		if id, ok := seen[s[i]]; ok && id != seg[i] {
			return false
		}
		seen[s[i]] = seg[i]
	}
	return true
}

func TestPartitionLabelsRandom(t *testing.T) {
	r := rand.New(rand.NewSource(2024137))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(12) // n <= 12 → 2^11 = 2048 种切法，可枚举
		alpha := 1 + r.Intn(3)
		b := make([]byte, n)
		for i := range b {
			b[i] = byte('a' + r.Intn(alpha)) // 字母表很小 → 大量跨段重复
		}
		s := string(b)
		got := partitionLabels(s)
		if !validPartition(s, got) {
			t.Fatalf("iter=%d s=%q 划分非法: %v", iter, s, got)
		}
		if len(got) != bruteParts(s) {
			t.Fatalf("iter=%d s=%q got=%v 段数=%d want=%d", iter, s, got, len(got), bruteParts(s))
		}
	}
}

// 边界：单字符、全相同、全不同、首尾同字母（必须整串一段）
func TestPartitionLabelsEdge(t *testing.T) {
	cases := []struct {
		s    string
		want []int
	}{
		{"a", []int{1}},
		{"aaaa", []int{4}},
		{"abcd", []int{1, 1, 1, 1}},
		{"abac", []int{3, 1}},
		{"eccbbbbdec", []int{10}},
		{"ababcbacadefegdehijhklij", []int{9, 7, 8}},
		{"ab", []int{1, 1}},
	}
	for _, c := range cases {
		got := partitionLabels(c.s)
		if len(got) != len(c.want) {
			t.Fatalf("s=%q got=%v want=%v", c.s, got, c.want)
		}
		for i := range got {
			if got[i] != c.want[i] {
				t.Fatalf("s=%q got=%v want=%v", c.s, got, c.want)
			}
		}
	}
}
```

> 注意 `bruteParts` 里对 `n = 1` 的处理：`1 << (n-1)` 在 `n = 1` 时是 `1`，只枚举「不切」这一种切法，结果正确。**在写指数级对拍时，`0` 位掩码、`1` 个元素这些边界必须逐个推一遍，否则会得到「参考实现自己错」的假通过。**

## 137.6 复杂度与常见坑

### 137.6.1 复杂度推导

- **时间 O(n)**：第一遍求 `last` 是 `n` 次赋值；第二遍扫描 `n` 次，每次一次比较、一次可能的赋值。总字符访问 `2n`。
  - 注意：这**不是**「双重循环的均摊 O(n)」，而是实打实的两遍线性扫描 —— 因为 `end` 只增不减，`i` 也只增不减。
- **空间 O(1)**：`last[26]` 与 `n` 无关；`start / end / i` 三个标量。结果数组 `O(k)`（`k` 为段数），是输出本身的开销，不计入额外空间。
- **对照**：DP 版 O(n²) 时间 + O(n) 空间；本题 `n ≤ 500` 时两者都能过，但 `n = 10^5` 的变体只有 O(n) 活。

### 137.6.2 六个真实踩过的坑

1. **贪心没有证明 = 猜** —— 这题的模板太短，几乎人人会背。但「为什么 `i == end` 就能切」这个问题的标准答案是**引理 2 的反证**：「切早了必然有字母跨段」。答不出这句话，就等于在用「我试过几组数据都对」当证明。而一旦题目加上「每段长度 ≤ k」，这个模板立刻失效，你却不知道边界在哪。
2. **把「尽可能多」理解成「尽量多切几刀」** —— 有人写「见到重复就切」，得到的是「段内不重复」的解（那是 [LC 2405](https://leetcode.cn/problems/optimal-partition-of-string/)），不是本题。本题的约束是「跨段不重复」，切点只能落在**没有区间跨越**的空隙上。
3. **`end` 初值或更新写错** —— `end` 必须初始化为 `0` 并以 `max` 更新。若写成 `end = last[s[i]]`（不取 max），`"abac"` 上第一轮的 `end` 会被 `b` 的 `1` 覆盖回 2？不会 —— 但 `"aab"` 这类输入会被打乱（`i=1` 时 `end` 被覆写成 `last[a]=1`，提前收口，切出非法解）。
4. **忘记 `start` 的更新** —— 只记得记录长度、忘记 `start = i + 1`，会让所有段的长度累加成「从 0 开始的长度」，答案变成 `[9, 16, 23]`。
5. **Go 里对非 ASCII 字符串直接 `s[i]`** —— `s[i]` 是字节；含中文时会按 UTF-8 字节切分，`last` 表会越界/错乱。本题只含小写字母所以安全，但**这个习惯要标记为「已知风险」**。
6. **对拍时忘了「段数相同但切法不同」也可能都合法** —— 判据要写「段数相等 + 划分合法」，而不是「数组逐项相等」才勉强安全。本题最小段数的划分唯一，但依赖这一点会让测试变脆。

### 137.6.3 面试官最爱追问的三个问题

**Q1：为什么切在 `i == end` 处是最优的？**

> 「因为它是**最早**的可行切点。设当前段起点是 `L`，`end*` 是不动点 `min{r : max_{t∈[L,r]} last[s[t]] ≤ r}`。任何合法划分的第一段右端 `r` 若小于 `end*`，就意味着 `max_{t∈[L,r]} last[s[t]] > r`，即有字母在 `[L,r]` 出现过、之后还会出现 —— 这个字母被切成了两段，非法。所以合法切点 `≥ end*`；而切在 `end*` 处又恰好合法（不动点定义）。**既然每一刀都被逼到最早位置，段数自然最多**。」

**Q2：如果要求「每段长度不超过 k」，还能贪心吗？**

> 「不能直接贪。不动点 `end*` 可能超过 `L+k-1`，此时 `[L, L+k-1]` 内必然有字母跨段 —— 这组输入**无解**。如果允许付代价（比如允许字母跨段但要计惩罚），就变成 DP：`dp[i] = min_{j} dp[j] + cost(s[j..i])`，而 `cost` 的合法性判定可以用「不动点」的结论快速筛掉不可能的 `(j, i)`。」

**Q3：能不能不用 `last` 数组，一遍扫描解决？**

> 「不行（单遍『读写同时』）。`last` 是全局信息，必须先把整个串读完才知道每个字母的最后出现位置，所以至少需要两遍（或用外部索引）。但两遍都是 O(n)，空间 O(26)。如果输入是流式的、且必须先回答，那唯一办法是落盘/缓存后再扫 —— 这是「信息下界」问题，不是算法技巧问题。」

## 附：本章小结（可背走的三句话）

```text
① 每个字母是一个区间 [首次出现, 最后出现]；所求每段 = 区间族的连通分量
② 切点被逼到不动点 end* = min{ r : max last[段内字母] ≤ r }；更早切一定非法（反证）
③ 每段都取最早可行切点 ⇒ 段数最多；复杂度 O(n) 时间 / O(1) 额外空间
```
