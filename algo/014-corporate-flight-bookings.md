## 014.1 题目

**原题链接**：<https://leetcode.cn/problems/corporate-flight-bookings/>

### 题意重述（把隐含条件补齐）

这里有 `n` 个航班，编号 `1 … n`。给你一个预订列表 `bookings`，其中 `bookings[i] = [first, last, seats]` 表示「第 `i` 笔预订在航班 `first` 到航班 `last`（**含两端**）的每一班上，订了 `seats` 个座位」。请返回长度为 `n` 的数组 `ans`，`ans[j]` 是**航班 `j+1`** 上的总座位数。

看清下面五条，这题就没有陷阱了——但没有一条是可以猜出来的：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| **航班编号从 1 开始** | 「第 `i` 笔预订…从 `first` 到 `last`」+ 示例 | 你把 `first` 当成 0-based 下标 → 整体错位一位，全错 |
| **区间含两端** | 「从 `first` 到 `last`」 | 你按 `[first, last)` 处理 → 每个末班都少算一笔 |
| **返回数组是 0-based** | 「`answer[i]` 是第 `i+1` 个航班」 | 你把结果也按 1-based 输出 → 长度变 `n+1`，判错 |
| **多笔预订会叠加** | 示例里航班 2 被三笔预订覆盖 | 你「后写覆盖前写」→ 只留了最后一笔 |
| **答案可能到 10⁸ 量级** | `m, seats` 的上限相乘 | 你用 `int` 但把上限估小了 → 溢出风险判断失误（详见约束表） |
| **`bookings` 可能为空** | 约束允许 `m = 0` | 不初始化 `ans` 就返回 → 长度错 |

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 2·10⁴` | 航班数 | 暴力「每笔预订遍历其区间」最坏 `m·n`；`m = n = 2·10⁴` 时是 **4·10⁸ 次加法** |
| `1 <= bookings.length <= 2·10⁴` | 预订数 m | 同上 |
| `1 <= first <= last <= n` | 区间合法 | **不需要**判空区间，也保证 `last + 1 <= n + 1` —— 这一条直接决定了差分数组要开多大 |
| `1 <= seats <= 10⁴` | 单笔座位数 | `ans` 的上界 = `m · seats = 2·10⁴ × 10⁴ = 2·10⁸`，**`int32` 安全**（上限 2.147·10⁹） |
| 答案是「所有预订的叠加」 | 语义 | 必须累加，不能覆盖 |

> 💡 量级 → 算法：`m · n = 4·10⁸` 在 1 秒预算里是**赌博**（Java 可能勉强过、Go 更快一点，但这不是能依赖的东西）。
> 更要紧的是**信号**：题目给的是「**很多次区间加 + 最后一次性要全部结果**」这个形状。看到这个形状，就该想到差分 —— 它把每次区间加从 O(len) 压到 O(1)。

### 示例

```
输入：bookings = [[1,2,10],[2,3,20],[2,5,25]], n = 5
输出：[10, 55, 45, 25, 25]

逐航班看：
  航班 1: 只有第 1 笔           → 10
  航班 2: 第 1、2、3 笔都有     → 10 + 20 + 25 = 55
  航班 3: 第 2、3 笔            → 20 + 25 = 45
  航班 4: 只有第 3 笔           → 25
  航班 5: 只有第 3 笔           → 25

输入：bookings = [[1,2,10],[2,2,15]], n = 2
输出：[10, 25]
       ↑ 航班 2 被两笔都覆盖：10 + 15

输入：bookings = [[1,1,3]], n = 1
输出：[3]
       ↑ 最小规模：n = 1，且 last = n（这是差分数组越界的边界）
```

### 我自造的四个反例（写完必须打一遍）

```text
① [[1,1,3]], n = 1        → last = n 时 last+1 = n+1，diff 开小了直接越界
② [[1,5,10]], n = 5       → 整段覆盖，答案每位都是 10，检验"含两端"
③ [[2,3,5]], n = 4        → 航班 1 没有任何预订，答案第一位必须是 0（不是漏填）
④ m = 0（空列表）          → 返回 n 个 0
```

第 ① 条几乎每个人都会踩一次：**`diff` 数组的长度必须是 `n + 2`，不是 `n` 也不是 `n + 1`**。原因见 §014.4.2 的越界示意图。

## 014.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力（先写出来）

```java
int[] ans = new int[n];
for (int[] b : bookings) {
    for (int f = b[0]; f <= b[1]; f++) {
        ans[f - 1] += b[2];        // 注意 f 是 1-based，要减 1
    }
}
```

- 时间 **O(m · n)**：每笔预订最坏覆盖全部 `n` 个航班。
- `m = n = 2·10⁴` 时是 **4·10⁸ 次加法**（外加同样多数组写入）。
- 空间 **O(n)**（输出）。

### 第二步：它为什么不够 —— 卡在「重复的整段累加」

把每笔预订看成一次「在数轴上盖一段 +c 的台阶」：

```
预订 [1,2]+10   ██
预订 [2,3]+20     ██
预订 [2,5]+25     █████
─────────────────────────────────→ 航班号
        1    2    3    4    5
暴力做法：每次盖台阶，都逐格 +c —— 一次盖 5 格就要写 5 次
```

问题在于：**「第 3 笔预订覆盖了 4 个航班」这件事，只有『端点在哪』是有信息量的，中间那段『一直保持 +25』完全可推导。** 暴力把可推导的部分也逐个写了一遍。

用更准确的话说：区间加 `[l, r] += c` 对应的数组，是一个**分段常数函数**；它只有两个「变化点」（`l` 处上升、`r+1` 处下降）。暴力记录了每一格的取值，而其实**只要记录变化点**就够了。

### 第三步：灵感 —— 记录「变化量」而不是「值」

设 `diff[k] = a[k] - a[k-1]`（`a` 是答案数组，`a[0]` 之前视为 0）。那么「`a[l..r]` 全部 +c」对 `diff` 的影响只有两处：

```
a:     0   0   0   0   0   0       （初始）
对 a[2..4] += 5 之后：
a:     0   5   5   5   0   0
       ────┬───────────┬──────
diff:  0  +5   0   0  -5   0
          ↑           ↑
        第 2 位 +5   第 5 位 -5
```

**一次区间加 = 差分数组上的两次单点修改。** 于是：

```
m 次区间加 → O(m) 次修改（每次 O(1)）
最后 → 对 diff 做一次前缀和，还原出 a：O(n)
总代价 O(m + n)
```

对比暴力的 `O(m·n)`：`2·10⁴ + 2·10⁴ = 4·10⁴` vs `4·10⁸` —— 差了**一万倍**。

### 第四步：为什么这是「前缀和的逆运算」

这是本章最该带走的一句：

```
   差分                                前缀和
a ──────────→ d                 d ──────────→ a
   d[i] = a[i] - a[i-1]           a[i] = d[0] + d[1] + … + d[i]
              └────────── 互为逆运算 ──────────┘
```

- `013` 里我们**从数组算出前缀和**，用来快速回答「区间和」；
- `014` 里我们**在差分数组上做修改**，最后**从差分算出原数组**，用来快速完成「区间加」。

同一个东西，两次使用方向相反。这就是为什么 `013` 和 `014` 必须放在一起读：**前缀和是查询端的技术，差分是更新端的技术。**

## 014.3 原理拆解

### 014.3.1 数据结构与算法选型

| 方案 | 预处理 | 每次区间加 | 最终还原 | 总代价 | 什么时候会输 |
| --- | --- | --- | --- | --- | --- |
| 暴力逐格加 | — | O(len) ≤ O(n) | 无需还原 | **O(m·n)** | m、n 同时到 2·10⁴（本题）就是 4·10⁸ |
| **差分数组** ✅ | O(n) 开空间 | **O(1)** | O(n) 前缀和 | **O(m + n)** | 需要**在线**查询中间结果时（差分不保存当前值）；`n` 极大且稀疏时空间浪费 |
| 差分 + 有序表（`TreeMap`） | O(1) | O(log m) | O(m log m) | O(m log m) | `n` 到 10⁹ 时用这个（只会访问端点）；本题 `n ≤ 2·10⁴` 用数组更快 |
| 线段树（带 lazy） | O(n) | O(log n) | O(n) | O(m log n) | 本题属于**过度设计**：能在线查询，但代码 60 行，面试里除非被追问否则不写 |
| 树状数组 + 差分 | O(n) | O(log n) | O(n log n) | O(m log n + n log n) | 需要「边改边查」时的标准解，比线段树短，但不支持区间最值 |

**选型判据（一句话）**：**离线（改完才问）+ 只需最终值 → 差分；在线（边改边问）→ 树状数组 / 线段树。** 本题明确「最后返回整个数组」，是纯离线，差分完胜。

### 014.3.2 为什么这个做法是对的（正确性论证）

先明确 1-based 表示：`ans[p]` 表示航班 `p`（`1 ≤ p ≤ n`）的座位数，并约定 `ans[0] = 0`，`diff[k] = ans[k] - ans[k-1]`（`k = 1..n+1`）。

**引理（一次区间加的差分贡献）**：对 `ans[l..r]` 全体 `+c`，则 `diff[l] += c`、`diff[r+1] -= c`，其余位置不变。

*证明*：只有当 `k` 使得 `ans[k]` 与 `ans[k-1]` 的**差**发生变化时，`diff[k]` 才变。变化只可能发生在区间的两个断点上：

- `k = l`：`ans[l]` 增加了 `c`，而 `ans[l-1]` 没变 → 差增加 `c`；
- `k = r+1`：`ans[r+1]` 没变，而 `ans[r]` 增加了 `c` → 差减少 `c`；
- 其他 `k`：要么两端都在区间内（都 +c，差不变），要么都在区间外（都不变，差不变）。

∎

**定理**：执行完所有预订后，对 `p = 1..n` 有 `Σ_{k=1}^{p} diff[k] = ans[p]`。

*证明*（用**贡献法**，这是差分题最标准的证法）：把 `ans[p]` 写成「所有覆盖 `p` 的预订的 `seats` 之和」，即

```
ans[p] = Σ_i seats_i · 1[ l_i ≤ p ≤ r_i ]
```

而算法对 `diff` 的写入，让第 `i` 笔预订对 `diff` 的贡献是 `+seats_i` 于 `l_i`、`−seats_i` 于 `r_i + 1`。于是它对前缀和 `Σ_{k≤p} diff[k]` 的贡献为：

| `p` 的范围 | 两个断点是否已计入 | 贡献 |
| --- | --- | --- |
| `p < l_i` | 都没计入 | `0` |
| `l_i ≤ p ≤ r_i` | 只计入了 `+seats_i` | `seats_i` |
| `p ≥ r_i + 1` | 两个都计入 | `seats_i − seats_i = 0` |

三种情况正好等于 `seats_i · 1[l_i ≤ p ≤ r_i]`。对所有 `i` 求和即得 `ans[p]`。∎

> **注意这个证明用的是「每条预订的贡献相互独立」**，所以「多笔预订叠加」自动成立 —— 不需要任何归纳。这也是差分比线段树更容易讲清正确性的原因。

### 014.3.3 通用解题思路（可迁移的那一层）

本题是 **「批量区间更新 + 最后一次读取 → 差分」** 模型的母题。它的可迁移形式：

```
问题：m 次「把区间 [l, r] 整体改变 c」，最后要整个数组
     ↓ 观察
区间改变在"差分域"里只有两个断点
     ↓ 换坐标系
在差分数组上做 O(1) 单点修改；最后做一次前缀和回到原坐标系
     ↓ 代价
时间 O(m + n)，空间 O(n)
```

**「坐标变换」是这里的核心思想**：同一个操作，在 `a` 的坐标系里是 O(len)，在 `diff` 的坐标系里是 O(1)。这不是「优化常数」，是**换了一个让操作变简单的坐标系**。类似的思想还有：树状数组的二进制下标、FFT 的频域、`011` 里「区间和」换成「前缀和之差」。

**前缀和 / 差分 / 滑窗 三者的统一视图**（本部分的主线表）：

| 模型 | 在哪个域上工作 | 支持的操作 | 前提 | 章节 |
| --- | --- | --- | --- | --- |
| 前缀和 | 原数组 → 前缀域 | 区间**查询** O(1) | 静态 | 013 |
| 前缀和 + 哈希 | 边扫边建前缀域 | 流式「历史命中次数」 | 有负数也对 | 011 |
| **差分** | **原数组 → 差分域** | 区间**修改** O(1) | 修改全部发生在读取之前 | 014 |
| 变长滑窗 | 直接在原数组上 | 区间查询 + 增量撤销 | 可行性单调 | 015 / 016 / 019 |
| 定长滑窗 | 直接在原数组上 | 等长区间查询 | 窗口长度固定 | 017 / 018 |

一句话总结：**要查询就上前缀和，要修改就上差分，要「边走边看且能撤销」就上滑窗。**

属于同一模型的题：

| 题 | 差分的变形 |
| --- | --- |
| [LC 1109 航班预订统计](https://leetcode.cn/problems/corporate-flight-bookings/) | 最裸的差分：区间加、最后还原 |
| [LC 1094 拼车](https://leetcode.cn/problems/car-pooling/) | 差分后检查**任意位置是否超容量**（还原过程中取最大值） |
| [LC 253 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/) | 求「最大重叠数」= 差分数组前缀和的**最大值** |
| [LC 2381 字母移位 II](https://leetcode.cn/problems/shifting-letters-ii/) | 字符上的区间加，差分量是「位移次数」 |
| [LC 1943 描述绘画结果](https://leetcode.cn/problems/describe-the-painting/) | 稀疏差分（`map` 存端点）+ 合并同色段 |
| [LC 2536 子矩阵元素加 1](https://leetcode.cn/problems/increment-submatrices-by-one/) | **二维差分**：四个角做四次单点修改 |

### 014.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **在线查询**（每次预订后就要结果） | 差分不保存当前值 | 树状数组（差分 + 前缀和）O(log n)，或线段树 lazy |
| 区间**赋值**而不是加 | 叠加语义变了 | 普通差分失效（赋值不可加），需要「区间赋值 + 区间和」的线段树（Segment Tree Beats 或普通 lazy 也行） |
| **二维**区间加 | 矩阵 | 二维差分：`(r1,c1)+c`、`(r1,c2+1)-c`、`(r2+1,c1)-c`、`(r2+1,c2+1)+c` |
| `n` 极大（10⁹）但 `m` 小 | 数组开不下 | 稀疏差分：用 `map` / 有序表只存端点，最后排序扫一遍（LC 1943 就是这个形状） |
| 要「区间加之后求区间和」 | 两个域都要 | 两个树状数组（分别维护 `d[i]` 和 `i·d[i]`），或线段树 |
| 要「区间加之后求最大值」 | 需要最值 | 差分前缀和可以求**最大重叠**（如 253 / 1094），因为最大值出现在端点处；但一般的最值查询要线段树 |
| 修改是「乘 c」 | 乘法不可逆 | 差分失效（除非 c ≠ 0 且允许除法），要线段树 |

## 014.4 图解推演

### 014.4.1 一次区间加 = 两个断点

```
把 ans 想成"高度"，一次 [2,4] += 5 的操作：

   高度
    5 │      ┌───────┐                    ← 区间内整体抬高
    0 │──────┘       └───────
      └──┬───┬───┬───┬───┬───→ 航班号
         1   2   3   4   5

   差分（相邻高度之差）
    5 │      ↑       ↓
    0 │──────┴───────┴───────
    -5 │
      └──┬───┬───┬───┬───┬───→ 下标
         1   2   3   4   5
             ↑       ↑
        diff[2] += 5   diff[5] -= 5      ← 只动两个格子
```

### 014.4.2 `diff` 为什么要开 `n + 2`（越界图）

```
n = 5，某笔预订是 [1, 5]（last = n，最右端）

  diff 下标:   1     2     3     4     5     6
             ┌─────┬─────┬─────┬─────┬─────┬─────┐
   需要写:   │ +10 │     │     │     │     │ -10 │   ← 第 6 格 = last + 1
             └─────┴─────┴─────┴─────┴─────┴─────┘
               ↑                             ↑
             first                       last + 1 = n + 1

  若 diff = new int[n + 1]（长度 6，合法下标 0..5）：
      diff[6] → ✗ ArrayIndexOutOfBoundsException / panic

  若 diff = new int[n + 2]（长度 7，合法下标 0..6）：
      diff[6] → ✓ 而且这一格永远不会被前缀和读到（循环只到 n）
```

```
┌──────────────────────── 记住这个数 ────────────────────────┐
│ 差分数组长度 = n + 2                                        │
│   多出的 1 格给 last + 1（可能等于 n + 1）                   │
│   开头那 1 格给 1-based 的下标 0（不用，但对齐更省心）        │
└─────────────────────────────────────────────────────────────┘
```

### 014.4.3 完整执行轨迹（示例 `[[1,2,10],[2,3,20],[2,5,25]], n = 5`）

**第一步：只写断点（不累加中间）**

| 处理到 | 写入操作 | `diff[1]` | `diff[2]` | `diff[3]` | `diff[4]` | `diff[5]` | `diff[6]` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 初始 | — | 0 | 0 | 0 | 0 | 0 | 0 |
| `[1,2]+10` | `diff[1]+=10`，`diff[3]-=10` | **10** | 0 | **−10** | 0 | 0 | 0 |
| `[2,3]+20` | `diff[2]+=20`，`diff[4]-=20` | 10 | **20** | −10 | **−20** | 0 | 0 |
| `[2,5]+25` | `diff[2]+=25`，`diff[6]-=25` | 10 | **45** | −10 | −20 | 0 | **−25** |

**第二步：一遍前缀和还原**

| 航班 `p` | `diff[p]` | 累计 `cur` | `ans[p-1]` | 校验（手算） |
| --- | --- | --- | --- | --- |
| 1 | 10 | 10 | **10** | 10 ✓ |
| 2 | 45 | 55 | **55** | 10+20+25 = 55 ✓ |
| 3 | −10 | 45 | **45** | 20+25 = 45 ✓ |
| 4 | −20 | 25 | **25** | 25 ✓ |
| 5 | 0 | 25 | **25** | 25 ✓ |

```
   一次"写 6 个格子 + 读 5 个格子"就完事了，全程没有一次"逐航班遍历区间"
```

### 014.4.4 差分与前缀和的对称性

```
        原数组 a = [1, 3, 6, 10, 15]

  差分方向  ──────────────────────────────→
   d[i] = a[i] - a[i-1]
   d = [1, 2, 3, 4, 5]

  前缀和方向 ←──────────────────────────────
   a[i] = d[0] + … + d[i]
   a = [1, 3, 6, 10, 15]

  ┌──────────────────────────────────────────────────────┐
  │ 差分 和 前缀和 是同一对互逆运算，只是方向相反：         │
  │   要做"区间查询"  → 先算前缀和，再用减法（013）        │
  │   要做"区间修改"  → 先改差分，再用前缀和还原（014）    │
  └──────────────────────────────────────────────────────┘
```

## 014.5 双语言实现

### 014.5.1 Java

```java
class Solution {
    public int[] corpFlightBookings(int[][] bookings, int n) {
        // 长度 n+2：多出的那一格装 last + 1（last 可能是 n，则写到 n+1）
        int[] diff = new int[n + 2];

        for (int[] b : bookings) {
            int first = b[0], last = b[1], seats = b[2];
            diff[first] += seats;        // 区间起点 +seats（first 是 1-based，直接当 diff 下标用）
            diff[last + 1] -= seats;     // 区间之后一个位置 -seats，抵消掉
        }

        int[] ans = new int[n];
        int cur = 0;
        for (int i = 1; i <= n; i++) {
            cur += diff[i];              // 前缀和还原：cur 就是航班 i 的总座位数
            ans[i - 1] = cur;            // 输出是 0-based，所以写 i-1
        }
        return ans;
    }
}
```

### 014.5.2 Go

```go
package main

func corpFlightBookings(bookings [][]int, n int) []int {
	// 与 Java 一致：长度 n+2，下标范围 0..n+1
	diff := make([]int, n+2)

	for _, b := range bookings {
		first, last, seats := b[0], b[1], b[2]
		diff[first] += seats
		diff[last+1] -= seats
	}

	ans := make([]int, n)
	cur := 0
	for i := 1; i <= n; i++ {
		cur += diff[i] // 前缀和还原
		ans[i-1] = cur // 输出 0-based
	}
	return ans
}
```

### 014.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 二维数组的遍历 | `for (int[] b : bookings)` | `for _, b := range bookings` | 都不需要下标 `i`，写 `_` / 增强 for 更清楚 |
| 二维数组的元素类型 | `int[][]`（每行都是新的 `int[3]`） | `[][]int`（**行是切片，长度不保证是 3**） | Go 里理论上可以传 `[][]int{{1,2}}`，访问 `b[2]` 会 panic；LeetCode 保证格式，但生产代码要判 `len(b) >= 3` |
| 数组初始化 | `new int[n+2]` 全 0 | `make([]int, n+2)` 全 0 | 差分的初始值是 0（"没有变化"），两语言一致，这是零值语义帮上忙的一次 |
| 越界 | `ArrayIndexOutOfBoundsException` | panic | 两种都是运行时才发现；`n = 1, last = 1` 的用例必须手写 |
| 整数宽度 | `int` 恒 32 位，本题上限 2·10⁸ 安全 | `int` 64 位平台 64 位 | 若 `seats` 上限提到 10⁹（`m·seats` 到 2·10¹³），**Java 必须 `long[]`，Go 也要显式 `int64`**（不要靠平台） |
| 返回值 | `int[]` | `[]int` | `ans` 长度必须是 `n`，不是 `n+1`，也不是 `len(diff)` |

### 014.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"

// 暴力参考：每笔预订逐航班加，唯一真相
func brute(bookings [][]int, n int) []int {
	ans := make([]int, n)
	for _, b := range bookings {
		for f := b[0]; f <= b[1]; f++ {
			ans[f-1] += b[2]
		}
	}
	return ans
}

func TestCorpFlightBookingsRandom(t *testing.T) {
	// 固定用例：last = n、n = 1、空预订、部分航班无预订
	fixed := []struct {
		bk   [][]int
		n    int
		want []int

		{[][]int{{1, 5, 10}}, 5, []int{10, 10, 10, 10, 10}},     // 整段覆盖
		{[][]int{{2, 3, 5}}, 4, []int{0, 5, 5, 0}},              // 首尾都留空
		{nil, 2, []int{0, 0}},                                    // 空预订
	}
	for _, f := range fixed {
		got := corpFlightBookings(f.bk, f.n)
		if len(got) != len(f.want) {
			t.Fatalf("bk=%v n=%d len(got)=%d want=%d", f.bk, f.n, len(got), len(f.want))
		}

			if got[i] != f.want[i] {
				t.Fatalf("bk=%v n=%d got=%v want=%v", f.bk, f.n, got, f.want)
			}
		}
	}

	r := rand.New(rand.NewSource(14))
	for iter := 0; iter < 20000; iter++ {
		n := 1 + r.Intn(10)
		m := r.Intn(10)
		bk := make([][]int, m)
		for i := range bk {
			f := 1 + r.Intn(n)
			l := f + r.Intn(n-f+1) // 保证 first <= last <= n
			bk[i] = []int{f, l, r.Intn(50)}
		}
		got, want := corpFlightBookings(bk, n), brute(bk, n)
		for i := range want {
			if got[i] != want[i] {

			}
		}
	}
```

## 014.6 复杂度与常见坑

### 014.6.1 复杂度推导

- **时间 O(m + n)**：写入 `2m` 次（每笔预订两次数组访问），还原读 `n` 次并写 `n` 次。没有嵌套循环，与区间长度无关。
  - 对比暴力：`Σ_i (r_i - l_i + 1) ≤ m·n`，最坏 `4·10⁸`。差分的 `2m = 4·10⁴`，两者相差**一万倍**，而且是**结构性的**（不随输入分布改善）。
- **空间 O(n)**：`diff` 长 `n+2`、`ans` 长 `n`，共 `2n+2` 个 `int`。若允许原地改写（把 `diff` 的前 `n` 项当作答案），还能省一半，但不值得为此牺牲可读性。

### 014.6.2 七个真实踩过的坑

1. **`diff` 开成 `n` 或 `n+1`** —— `last = n` 时写 `diff[n+1]` 越界。**必须 `n+2`**。这是本题第一大坑，`n=1` 的用例一秒暴露。
2. **1-based / 0-based 混淆** —— `bookings` 里的 `first`/`last` 是 1-based，直接用作 `diff` 下标（`diff` 的第 0 格空着不用）；而**输出**是 0-based，写 `ans[i-1]`。两套下标混着用，错一位就全错。
3. **忘记 `diff[last+1] -= seats`** —— 区间变成「从 `first` 一直到数组末尾」，后面的航班全部变大。
4. **还原时忘记累加（写成 `cur = diff[i]`）** —— 每个位置只剩「变化量」，答案全错，而且错得很有规律（相邻差分），容易被误认为「差一个偏移」。
5. **还原循环的边界写错** —— 写成 `i < n` 会漏掉最后一个航班；写成 `i <= n+1` 会多读一格（这一格是 `diff[n+1]`，通常非 0）。
6. **以为答案一定在 `int` 内** —— 本题 `2·10⁸` 确实安全，但这是**算出来的**，不是默认的。凡是「多次累加」的题，先算 `最大单值 × 次数`。
7. **`bookings` 为空时忘了初始化 `ans`** —— 有些语言/写法会返回 `nil` 或长度不对的数组。`new int[n]` / `make([]int, n)` 必须在循环之外先建好。

### 014.6.3 面试官最爱追问的三个问题

**Q1：为什么差分能把区间修改降到 O(1)？**
> 「因为在差分域里，『区间整体加』只改变相邻元素的**差**在两个位置上的取值：起点处差增加 c，终点后一处差减少 c，中间所有相邻差都不变。这不是常数优化，是换了个坐标系 —— 在『值』的坐标系里区间有长度，在『差』的坐标系里区间只有两个端点。代价是：差分不保存当前值，想知道任意时刻的值都要做前缀和，所以只适合『改完再读』的离线场景。」

**Q2：如果每笔预订一提交就要立刻能查到某个航班当前的总座位数呢？**
> 「那就从离线变成在线，差分数组不够用了（单次查询要 O(n) 前缀和）。两条路：① 树状数组维护差分数组，区间加 O(log n)、单点查 O(log n)，代码 20 行，最实用；② 线段树带 lazy，区间加和区间查都是 O(log n)，能顺便支持区间最大值，但代码 60 行。选择看是否还需要区间查/区间最值。」

**Q3：二维矩阵的区间加怎么做？**
> 「二维差分，四个角各改一次：`(r1,c1) += c`、`(r1,c2+1) -= c`、`(r2+1,c1) -= c`、`(r2+1,c2+1) += c`，最后做二维前缀和还原。原理和一维完全一样 —— 二维前缀和在矩形内部的『二阶差分』是 0，只有四个角非零。要注意行列都要多开一格，否则 `c2+1`、`r2+1` 越界，和本题 `last+1` 是同一个坑。」
