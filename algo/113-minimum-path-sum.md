## 113.1 题目

**原题链接**：<https://leetcode.cn/problems/minimum-path-sum/>

### 题意重述（把隐含条件补齐）

给一个 `m × n` 的非负整数矩阵 `grid`，从**左上角** `(0,0)` 出发，每次只能**向右**或**向下**走一格，走到**右下角** `(m-1,n-1)`。路径的代价是**经过的所有格子（含起点和终点）的数字之和**，求最小代价。

五个必须读出来的约束：

| 隐含条件 | 出处 | 读错了会怎样 |
| --- | --- | --- |
| 代价**包含起点和终点**两个格子 | 「路径上所有数字的总和」 | 漏算一个端点 → 样例答 5（正确 7） |
| 只能**向右 / 向下** | 「每次只能向下或者向右移动一步」 | 允许四方向 → 变成带权最短路（有环，DP 失效，要用 Dijkstra） |
| 元素**非负** | `0 <= grid[i][j] <= 200` | 这是「贪心 / 单调性」讨论的前提：一旦出现负数，很多直觉都垮掉 |
| 问的是**最小**，不是条数 | 「最小路径和」 | 沿用 112 章的「加法」转移 → 算成路径条数 |
| 至少一个格子 | `m, n ≥ 1` | `1 × 1` 网格答案就是 `grid[0][0]`，不是 0 |

> 📌 **为什么「非负」这么重要**：因为非负，走更长的路径**不会**带来额外收益（多走一格只会加钱），而且「全局最优」具有单调性 —— 这使得「只保留最小的那个到达代价」是充分的（最优子结构成立）。若允许负数，环形绕路就可能倒赚，问题性质完全改变。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= m, n <= 200` | 最多 `200 × 200 = 4·10^4` 格 | `O(mn) = 4·10^4` 次加法，纳秒级；而枚举路径数 `C(398,199)` 是天量 → 只能 DP |
| `0 <= grid[i][j] <= 200` | 单格小、且非负 | 答案最大 `200 × (200+200-1) = 79800`，远小于 `2³¹-1` → **`int` 完全安全**，不需要 `long` |
| 路径长度固定为 `m+n-1` 格 | 只能右 / 下 | 这就是 112 章「路径 = 下与右的序列」的直接推论；本题不利用这一点，但它是组合解法的入口 |
| 无取模 | — | 答案真实可比，`min` 运算不会被取模破坏 |

> 💡 **量级 → 算法**：`200 × 200` 与 112 章的 `100 × 100` 是同一档 —— 「二维小表 + 相邻转移」→ 网格 DP，`O(mn)`。**注意：这题的 `O(mn)` 也是下界**，因为至少要读一遍所有格子。

### 示例

```text
输入：grid = [[1,3,1],
              [1,5,1],
              [4,2,1]]
输出：7
解释：路径 1 → 3 → 1 → 1 → 1 的和最小，为 7。
      （注意：它**不走**中间那个 5，也不走左下角那个 4）

输入：grid = [[1,2,3],
              [4,5,6]]
输出：12
解释：唯一可行的最优是 1 → 2 → 3 → 6（或 1 → 4 → 5 → 6？后者是 16），故 12。

输入：grid = [[1]]
输出：1
```

**慢着 —— 官方样例的答案 7 恰好能证明「贪心会输」**，见下一节。

### 我自造的五个反例（写完解法必须拿它们打一遍）

```text
① [[1]]                    → 答案 1；暴露「dp 初值写 0」和「漏算起点」两种错
② [[1,2,3]]                → 单行：答案 6，必须累加而不是取最小
③ [[1],[2],[3]]            → 单列：答案 6，同上（第一列要累加，不能一律置 0/1）
④ [[0,0],[0,0]]            → 全 0：答案 0；用「哨兵 0 表示没算过」的写法会崩
⑤ 200 × 200 全 200         → 答案 200 × 399 = 79800，检验溢出与边界
```

第 ② ③ 条直击本章最核心的坑：**112 章里「第一行全置 1」是对的（每条路都只有 1 条），但这里必须「第一行做前缀和」**（每条路都必须把所有格子走一遍，没有「跳过」的选项）。同一个压缩框架，初始化完全不同。

## 113.2 从暴力到最优：第一个念头为什么错

### 第一个念头：贪心 —— 每一步选「下 / 右」中较小的那个

```text
grid = [[1, 3, 1],
        [1, 5, 1],
        [4, 2, 1]]

贪心轨迹（每步选相邻较小的格）：
  (0,0)=1  →  下(1,0)=1  还是 右(0,1)=3？  选下 → (1,0)=1
  (1,0)=1  →  下(2,0)=4  还是 右(1,1)=5？  选下 → (2,0)=4
  (2,0)=4  →  只能右 → (2,1)=2
  (2,1)=2  →  只能右 → (2,2)=1
  总代价 = 1 + 1 + 4 + 2 + 1 = 9      ❌

最优路径（走上面一行）：
  (0,0)=1 → (0,1)=3 → (0,2)=1 → (1,2)=1 → (2,2)=1
  总代价 = 1 + 3 + 1 + 1 + 1 = 7      ✅

  为什么贪心输？因为「(1,0) 比 (0,1) 小」只说明**这一步**便宜，
  但走 (1,0) 之后就进了「左边那堵墙」—— 后面必须穿过 4 和 2；
  而走 (0,1) 虽然贵 2，却换来了右边一列全是 1。
  ⇒ 局部最优 ≠ 全局最优，这是「最短路径」类问题的经典陷阱。
```

- 贪心时间 `O(m+n)`、空间 `O(1)` —— 但它**答案是错的**。`[[1,3,1],[1,5,1],[4,2,1]]` 上答 9（正确 7）。

### 第二个念头：暴力 —— 枚举所有路径

路径条数 `C(m+n-2, m-1)`，每条路径 `m+n-1` 格：

```java
// 指数级暴力：递归枚举所有路径，取最小和
int dfs(int i, int j) {
    if (i == m - 1 && j == n - 1) return grid[i][j];
    int best = Integer.MAX_VALUE;
    if (i + 1 < m) best = Math.min(best, dfs(i + 1, j));
    if (j + 1 < n) best = Math.min(best, dfs(i, j + 1));
    return best + grid[i][j];      // 加上自己的代价
}
```

- 时间：与路径条数同阶 `O(C(m+n-2, m-1))`。`m = n = 20` 时 `3.5·10^10` 次调用 → **几十秒**；`m = n = 200` 时完全不可能。
- 空间：`O(m+n)` 递归栈。

### 第三步：卡点 —— 「同一个格子被从不同路径反复计算」

与 112 章一样：`dfs(i,j)` 的值只与 `(i,j)` 有关，与「我是怎么来到这里的」无关。但递归里，`(i,j)` 会被从上方和左方**两条不同的路径**各调用一次，于是整棵树指数膨胀。

> **「从 `(i,j)` 到终点的最小代价」是一个可复用子问题**。它只依赖 `(i,j)` —— 这就是无后效性。

### 第四步：灵感的来源 —— 最后一步从哪来

站在 `(i,j)`，最后一步只可能来自**上方** `(i-1,j)` 或**左方** `(i,j-1)`：

```
dp[i][j] = grid[i][j] + min( dp[i-1][j], dp[i][j-1] )
```

**为什么可以只取 `min` 而不枚举所有路径？** 因为「到达 `(i-1,j)` 的代价」与「从 `(i-1,j)` 走到终点」这两段是**独立可分的**：一旦确定了入口 `(i-1,j)`，到达它的最优值就是 `dp[i-1][j]`（任何更差的到达方式都不会改善全局）。这就是最优子结构 + 无后效性。

```text
不变量：dp[i][j] = 从 (0,0) 走到 (i,j) 的最小路径和（含两端格子）
        它只依赖「上方」与「左方」两个已算好的状态
```

### 第五步：与 112 章的唯一差别 —— 初始化

| 项 | 112（计数） | 113（最优化） |
| --- | --- | --- |
| 第一行 `dp[0][j]` | **恒为 1**（每条路只有 1 条） | **前缀和** `Σ grid[0][0..j]`（必须把走过的格全加上） |
| 第一列 `dp[i][0]` | **恒为 1** | **前缀和** `Σ grid[0..i][0]` |
| 转移 | `+` | `min` |
| 语义 | 方案数（会累加） | 最小代价（取更优） |

**这个差异不能靠「记住」**，必须靠「第一行只有一条路可走」这个事实推出来：既然只有一条路，那代价自然就是“一路加过来”的前缀和。

## 113.3 原理拆解

### 113.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 贪心（每步选小） | O(m+n) | O(1) | 6 行 | **答案就是错的**，官方样例 `[[1,3,1],[1,5,1],[4,2,1]]` 答 9（正确 7） |
| 递归枚举所有路径 | O(C(m+n-2, m-1)) | O(m+n) 栈 | 8 行 | `m,n ≥ 20` 就几十秒；`200 × 200` 不可能 |
| 记忆化搜索 | O(mn) | O(mn) + 栈 | 14 行 | 栈深度 `m+n`，`m,n` 上万时栈溢出；不如递推直接 |
| 二维递推表 | O(mn) | O(mn) | 12 行 | `m,n` 大时内存吃紧；但**最直观、最适合调试** |
| **一维压缩** ✅ | **O(mn)** | **O(n)** | **10 行** | 要「回滚输出路径」时不行 |
| 原地复用 `grid` 当 dp | O(mn) | **O(1)** 额外 | 8 行 | **会破坏输入**（生产代码一般不允许）；且要求格子里没有「哨兵值」冲突 |
| Dijkstra / A* | O(mn log(mn)) | O(mn) | 40 行 | 本题网格是 DAG（只能右下），用最短路是杀鸡用牛刀 |

**为什么正文选一维压缩**：`O(n)` 空间、`O(mn)` 时间、10 行代码，兼顾可读性与效率；而且它把 112 章学到的「压缩后内层正序」判据**原样复用**。原地修改版虽然空间更省，但**破坏入参**，且面试里容易被追问「如果调用方还要用这个矩阵呢」。

### 113.3.2 为什么这个做法是对的（正确性论证）

**命题**：设 `dp[i][j]` 为「从 `(0,0)` 到 `(i,j)` 的最小路径和」，则

```
dp[0][0] = grid[0][0]
dp[0][j] = dp[0][j-1] + grid[0][j]     （j ≥ 1，第一行只有一条路）
dp[i][0] = dp[i-1][0] + grid[i][0]     （i ≥ 1，第一列只有一条路）
dp[i][j] = grid[i][j] + min( dp[i-1][j], dp[i][j-1] )   （i, j ≥ 1）
```

答案 `= dp[m-1][n-1]`。

**证明（按最后一步分类 + 最优子结构）**：

任取一条从 `(0,0)` 到 `(i,j)`（`i,j ≥ 1`）的最优路径 `p`（代价最小）。看它的最后一步：

1. **最后一步来自上方**：去掉 `(i,j)` 后，得到一条从 `(0,0)` 到 `(i-1,j)` 的路径 `p'`。**断言 `p'` 是到 `(i-1,j)` 的最优路径**：若存在更优的 `p''`，用它替换 `p'` 就得到一条比 `p` 更便宜的到 `(i,j)` 的路径，与 `p` 最优矛盾。故这一类的代价下界是 `dp[i-1][j] + grid[i][j]`，且可取到。
2. **最后一步来自左方**：同理，代价下界 `dp[i][j-1] + grid[i][j]`，且可取到。

两类互斥穷尽，`p` 必属其一，于是 `p` 的代价 `≥ grid[i][j] + min(dp[i-1][j], dp[i][j-1])`；又因两类各自可取到该下界，等号成立。∎

> 🔑 **「断言 `p'` 最优」这一步是「最优子结构」的标准证法**：反证 + 替换。**替换论证（exchange argument）** 是 DP 与贪心证明的通用武器。

**边界**：`dp[0][0] = grid[0][0]`（起点自身代价，不是 0）；第一行 / 第一列没有「min」的余地 —— 只能一路走过来，所以是前缀和。

**一维压缩的正确性（归纳法）**：

> **循环不变量**：处理第 `i` 行、第 `j` 列**之前**，`dp[j] = dp[i-1][j]`（上一行同列），`dp[j-1] = dp[i][j-1]`（本行左邻，刚更新）。

于是 `dp[j] = grid[i][j] + min(dp[j], dp[j-1])` 恰好实现二维转移。**正序是关键**：只有正序，`dp[j-1]` 才是本行的新值。∎

### 113.3.3 通用解题思路（可迁移的那一层）

本题是 **「网格最优化 DP + 行滚动」** 的母题，与 112 是同一个模板换运算：

```text
原始问题：网格上从左上到右下，每步只能右下，求「代价最小」的路径
         ↓ 锚定「最后一步从哪来」
状态：    dp[i][j] = 到 (i,j) 的最小代价（含该格）
         ↓ 分类：从上 / 从左
转移：    dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
         ↓ 初始化：第一行 / 第一列只能一路走过来 ⇒ 前缀和
压缩：    一维 dp[j]，内层 j 正序（与 112 判据完全相同）
```

**套用 DP 四步法**：

| 四步 | 本题的答案 |
| --- | --- |
| ① 状态定义 | `dp[i][j]` = 从 `(0,0)` 走到 `(i,j)` 的**最小路径和**（含两端格） |
| ② 转移方程 | `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`（按最后一步「下 / 右」分类） |
| ③ 初始化 | `dp[0][0] = grid[0][0]`；第一行 / 第一列做**前缀和**（唯一一条路） |
| ④ 遍历序 | 外层 `i` 递增、内层 `j` **递增**；压缩后内层正序（`dp[j-1]` 须是本行新值） |

**这个模型的家族**：

| 题 | `dp` 的含义 | 转移里的运算 |
| --- | --- | --- |
| [LC 64 最小路径和](https://leetcode.cn/problems/minimum-path-sum/) | 到 `(i,j)` 的最小代价 | `min`（本题） |
| [LC 62 不同路径](https://leetcode.cn/problems/unique-paths/) | 到 `(i,j)` 的条数 | `+` → 见 112 章 |
| [LC 931 下降路径最小和](https://leetcode.cn/problems/minimum-falling-path-sum/) | 到 `(i,j)` 的最小降序代价 | `min`（三个来源） |
| [LC 120 三角形最小路径和](https://leetcode.cn/problems/triangle/) | 到 `(i,j)` 的最小代价 | `min`（两个来源，行内错位） |
| [LC 174 地下城游戏](https://leetcode.cn/problems/dungeon-game/) | 从 `(i,j)` 出发所需最小初始血量 | `min` 但**必须倒推** |
| [LC 741 摘樱桃](https://leetcode.cn/problems/cherry-pickup/) | 往返两趟的最大收集 | `max` + 状态升维 |

**共同点**：都是「`dp[i][j]` 由上方 / 左方（或三方向）推出」，都能行滚动压缩。

### 113.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 允许**四个方向**移动（LC 1368 类） | 有环 | DP 失效 → 0-1 BFS / Dijkstra（边权是格子代价） |
| 要求**输出具体路径** | 求值 → 求方案 | 另存 `from[i][j] ∈ {上, 左}`，从终点回溯；或从终点往起点贪心回退（每步走向 `dp` 更小的邻居） |
| 允许**修改 k 个格子的代价为 0** | 加约束 | 状态升维 `dp[i][j][k]`，`O(mnk)` 时间；压缩后三维变二维 |
| 元素**可能为负** | 单调性被破坏 | 最优化 DP 仍成立（转移不依赖非负性）；但「路径长度固定」这一点要注意：负值会让「多走一格」有利，而网格里从 `(0,0)` 到 `(m-1,n-1)` 的**长度恒为 `m+n-1`**，所以其实不受影响 —— **能这么说清楚是关键** |
| `m × n` 极大但只有**少量障碍** | 稀疏网格 | 把「关键点」提出来做坐标压缩 DP；或用「组合数 + 容斥」 |
| 要求**最小代价的同时路径字典序最小** | 多目标 | 先 DP 求最小代价，再在等代价的边上做贪心回溯（此时贪心是**正确的**，因为只在最优解集合里选） |

**原地修改版（`O(1)` 额外空间）的写法**，面试里常被要求「不加额外空间」：

```text
把 grid 自己当 dp：
  grid[0][j] += grid[0][j-1]              // 第一行前缀和
  grid[i][0] += grid[i-1][0]              // 第一列前缀和
  grid[i][j] += min(grid[i-1][j], grid[i][j-1])
返回 grid[m-1][n-1]

代价：破坏了入参。若调用方还要用原矩阵，必须复制一份（那又回到 O(mn) 空间）。
所以「O(1) 空间」在这里是**以副作用为代价**的，面试时要主动说明。
```

## 113.4 图解推演

### 113.4.1 二维 DP 表 + 计算顺序箭头（官方样例）

```text
grid = [[1,3,1],
        [1,5,1],
        [4,2,1]]

            j=0       j=1       j=2
        ┌─────────┬─────────┬─────────┐
  i=0   │ 1 (=1)  │ 4 (=1+3)│ 5 (=4+1)│  ← 第一行：前缀和（只有一条路）
        ├─────────┼─────────┼─────────┤
  i=1   │ 2 (=1+1)│ 7       │ 6       │
        ├─────────┼─────────┼─────────┤
  i=2   │ 6       │ 8       │ 7       │  ← 答案 dp[2][2] = 7
        └─────────┴─────────┴─────────┘
           ▲         ▲         ▲
           │         │         │
        第一列    需要 min  需要 min
        前缀和

计算顺序：i 从上到下，j 从左到右（先「→」再「↓」）

  dp[1][1] = grid[1][1] + min(dp[0][1], dp[1][0]) = 5 + min(4, 2) = 5 + 2 = 7
                                      ▲          ▲
                                      │          └── 左方（本行，已算）
                                      └───────────── 上方（上一行，已算）

  dp[1][2] = 1 + min(dp[0][2], dp[1][1]) = 1 + min(5, 7) = 1 + 5 = 6
  dp[2][1] = 2 + min(dp[1][1], dp[2][0]) = 2 + min(7, 6) = 2 + 6 = 8
  dp[2][2] = 1 + min(dp[1][2], dp[2][1]) = 1 + min(6, 8) = 1 + 6 = 7   ← 答案

最优路径回溯（选 min 的那一支）：
  (2,2) ← 上方 (1,2)=6
  (1,2) ← 上方 (0,2)=5
  (0,2) ← 左方 (0,1)=4
  (0,1) ← 左方 (0,0)=1
  ⇒ 路径 (0,0)→(0,1)→(0,2)→(1,2)→(2,2)，代价 1+3+1+1+1 = 7 ✅
```

### 113.4.2 一维压缩：逐行滚动（含「第一列要累加」这个坑）

```text
dp 长度 = n = 3

初始化（第一行 = 前缀和，不能全置 0 或 1）:
  dp = [1, 4, 5]
        ▲  ▲──── dp[1] = dp[0] + grid[0][1] = 1 + 3 = 4
        │  └──── dp[2] = dp[1] + grid[0][2] = 4 + 1 = 5
        └─────── dp[0] = grid[0][0] = 1

处理 i = 1（grid[1] = [1,5,1]）:
  dp[0] += grid[1][0]  →  1 + 1 = 2        ← 第一列必须累加！不能保持 1
  j=1: dp[1] = grid[1][1] + min(dp[1], dp[0])
             =     5       + min( 4  ,  2  ) = 5 + 2 = 7
                          ▲(上方旧值) ▲(左方新值)
  j=2: dp[2] = grid[1][2] + min(dp[2], dp[1])
             =     1       + min( 5  ,  7  ) = 1 + 5 = 6
  ⇒ dp = [2, 7, 6]

处理 i = 2（grid[2] = [4,2,1]）:
  dp[0] += 4  →  2 + 4 = 6
  j=1: dp[1] = 2 + min(7, 6) = 8
  j=2: dp[2] = 1 + min(6, 8) = 7
  ⇒ dp = [6, 8, 7]        ← dp[n-1] = 7 ✅

⚠️ 若把 dp[0] 写成「遇到新行就置 grid[i][0]」而不是累加：
   dp[0] 会变成 1（而不是 2、6）→ 后续所有格子偏小 → 答案错。
```

| 行 `i` | `grid[i]` | 进入时 `dp`（=`dp[i-1][*]`） | 更新了 `dp[0]` | `dp[1]` | `dp[2]` | 离开时 `dp`（=`dp[i][*]`） |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `[1,3,1]` | —（初始化） | `1` | `1+3=4` | `4+1=5` | `[1, 4, 5]` |
| 1 | `[1,5,1]` | `[1,4,5]` | `1+1=2` | `5+min(4,2)=7` | `1+min(5,7)=6` | `[2, 7, 6]` |
| 2 | `[4,2,1]` | `[2,7,6]` | `2+4=6` | `2+min(7,6)=8` | `1+min(6,8)=7` | `[6, 8, 7]` |

### 113.4.3 「内层正序 vs 倒序」的判据（与 112 完全一致）

```text
未压缩转移：  dp[i][j] = grid[i][j] + min( dp[i-1][j] , dp[i][j-1] )
                                            └─ 上一行 ─┘   └─ 本行 ─┘

压缩后 dp[j] 承担两个角色：
  写入前 dp[j]   = dp[i-1][j]   （上一行同列，必须还是旧值）  ⇒ 要求「先读后写」
  写入后 dp[j-1] = dp[i][j-1]   （本行左邻，必须已是新值）    ⇒ 要求 j 正序

正序（✅）：                   倒序（❌）：
  dp[j] = g + min(dp[j], dp[j-1])   dp[j] = g + min(dp[j], dp[j-1])
                  旧      新                          旧      旧(上一行 j-1)
  = 上 + 左                         = 上 + 左上（斜着走，含义变了）

两者对比（3×3 官方样例）：
  正序正确答案 7
  倒序会算出 1 + 1 + ... （走「上 + 左上」的路径集合不同）⇒ 结果不一致
  ⇒ 判据：读取「本行」的格子 ⇒ 正序；读取「上一行」的格子 ⇒ （见 114 章）倒序
```

| 题目 | 内层依赖的是哪个格子 | 顺序 |
| --- | --- | --- |
| 112 不同路径 / 113 最小路径和 | `dp[i][j-1]`（**本行**左邻） | **正序** |
| 114 分割等和子集（01 背包） | `dp[i-1][j-x]`（**上一行**更小容量） | **倒序** |
| 116 / 117 / 118（完全背包） | `dp[i][j-x]`（**本行**更小容量，可重复取） | **正序** |

> 🔑 **一句话总结**：「用**本行**的新值」→ 正序；「必须用**上一行**的旧值」→ 倒序。**先写未压缩的转移式、再给每一项贴「本行 / 上一行」标签**，顺序问题就不再需要死记。

## 113.5 双语言实现

### 113.5.1 Java

```java
class Solution {
    // 主解：一维压缩，O(mn) 时间 / O(n) 空间
    public int minPathSum(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int[] dp = new int[n];

        dp[0] = grid[0][0];                                  // 起点自身代价
        for (int j = 1; j < n; j++) {
            dp[j] = dp[j - 1] + grid[0][j];                  // 第一行：前缀和（唯一一条路）
        }

        for (int i = 1; i < m; i++) {
            dp[0] += grid[i][0];                             // 第一列：前缀和（不是置 0！）
            for (int j = 1; j < n; j++) {
                // dp[j] 仍是上一行（上方），dp[j-1] 已是本行（左方）→ 内层必须正序
                dp[j] = grid[i][j] + Math.min(dp[j], dp[j - 1]);
            }
        }
        return dp[n - 1];
    }

    // 变体：原地复用 grid 当 dp，额外空间 O(1)（副作用：破坏入参）
    public int minPathSumInPlace(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        for (int j = 1; j < n; j++) grid[0][j] += grid[0][j - 1];
        for (int i = 1; i < m; i++) grid[i][0] += grid[i - 1][0];
        for (int i = 1; i < m; i++)
            for (int j = 1; j < n; j++)
                grid[i][j] += Math.min(grid[i - 1][j], grid[i][j - 1]);
        return grid[m - 1][n - 1];
    }
}
```

### 113.5.2 Go

```go
package main

// 主解：一维压缩，与 Java 同一套变量名与流程
func minPathSum(grid [][]int) int {
	m, n := len(grid), len(grid[0])
	dp := make([]int, n)

	dp[0] = grid[0][0]
	for j := 1; j < n; j++ {
		dp[j] = dp[j-1] + grid[0][j] // 第一行：前缀和
	}
	for i := 1; i < m; i++ {
		dp[0] += grid[i][0] // 第一列：前缀和
		for j := 1; j < n; j++ {
			best := dp[j] // 上方（上一行的旧值）
			if dp[j-1] < best {
				best = dp[j-1] // 左方（本行新值）
			}
			dp[j] = grid[i][j] + best
		}
	}
	return dp[n-1]
}

// 变体：原地复用 grid（额外空间 O(1)，但破坏入参）
func minPathSumInPlace(grid [][]int) int {
	m, n := len(grid), len(grid[0])
	for j := 1; j < n; j++ {
		grid[0][j] += grid[0][j-1]
	}
	for i := 1; i < m; i++ {
		grid[i][0] += grid[i-1][0]
	}
	for i := 1; i < m; i++ {
		for j := 1; j < n; j++ {
			if grid[i-1][j] < grid[i][j-1] {
				grid[i][j] += grid[i-1][j]
			} else {
				grid[i][j] += grid[i][j-1]
			}
		}
	}
	return grid[m-1][n-1]
}

func main() {}
```

### 113.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| `min` | 内置 `Math.min` | 1.21 前手写 `if` | Go 多 4 行；**别用 `math.Min`**（它只有 `float64`） |
| 二维长度 | `grid.length` / `grid[0].length` | `len(grid)` / `len(grid[0])` | Go 若 `grid` 为空切片，`len(grid[0])` 会 panic；Java 抛 `ArrayIndexOutOfBoundsException` → 生产代码先判空 |
| 原地修改入参 | `int[][]` 是引用，函数内改会影响调用方 | `[][]int` 同理（外层切片共享内层数组） | **两种语言的「副作用」是一样的**，但 Go 里更隐蔽：`grid[0][j] += …` 改的是底层数组，调用方立刻可见 |
| 整数宽度 | `int` 32 位；本题答案 ≤ 79800 | `int` 64 位 | 两边都安全；若格子值放大到 `10^9` 且 `m=n=200`，Java 必须 `long` |
| `make` 与零值 | `new int[n]` 全 0 | `make([]int, n)` 全 0 | 本题第一行会被覆盖写入，所以零值无所谓；但**若跳过初始化直接进循环，`dp[0]` 会是 0 而不是 `grid[0][0]`** —— 两边都错 |
| 增强 for | `for (int[] row : grid)` | `for _, row := range grid` | 想原地改 `row` 的元素，两边都能改到原数组（切片 / 数组引用共享） |

// 指数级暴力：枚举所有从左上到右下的路径，取最小和
func bruteMinPathSum(g [][]int) int {
	m, n := len(g), len(g[0])
	const inf = 1 << 30
	var dfs func(i, j int) int
	dfs = func(i, j int) int {
		if i == m-1 && j == n-1 {
			return g[i][j]
		}
		best := inf
		if i+1 < m {
			if v := dfs(i+1, j); v < best {
				best = v
			}
		}
		if j+1 < n {
			if v := dfs(i, j+1); v < best {
				best = v
			}
		}
		return best + g[i][j] // 加上自己这一格
	}
	return dfs(0, 0)
}

		} else if j == n-1 { // 只能下

## 113.6 复杂度与常见坑

### 113.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(mn)**：状态数 `mn`，每格 1 次 `min` + 1 次加法。`m = n = 200` 时是 `4·10^4` 次，实测 **≈ 0.15 ms**。这已是最优量级 —— **至少要读一遍所有格子**（`Ω(mn)`），所以 `O(mn)` 是紧的。
- **空间 O(n)**：一维压缩只保留当前行。为什么不能像 108 章那样压到 `O(1)`？因为 `dp[i][j]` 需要**整行**的 `dp[i-1][*]`（每个 `j` 都要读同列的上一行），不是常数个历史值。
- **原地版空间 O(1)（额外）**：把 `grid` 自身当表，但**总空间仍以输入为代价**；时间复杂度完全不变。**再次强调：空间压缩从不改变时间复杂度。**
- **暴力 O(C(m+n-2, m-1))**：`m = n = 7` 时 `C(12,6) = 924` 次调用（对拍用这个尺寸正合适）；`m = n = 20` 时 `3.5·10^10`，几十秒。

### 113.6.2 七个真实踩过的坑

1. **第一行 / 第一列没有做前缀和** —— 沿用 112 章「全置 1」或「全置 0」，答案偏小。修法：第一行 / 第一列必须**累加**。
2. **`dp[0]` 在每行开头被重置成 `grid[i][0]`** —— 正确是 `dp[0] += grid[i][0]`（第一列只有一条路）。这是「一维压缩 + 第一列」最隐蔽的错，`[[1],[2],[3]]` 上会答 3（正确 6）。
3. **内层写成倒序** —— 读到的是 `dp[i-1][j-1]`，等价于允许斜走。修法：用「本行 / 上一行」标签判据（见 §113.4.3）。
4. **把起点代价漏掉** —— `dp[0] = 0`，于是样例答 6（正确 7）。修法：`dp[0] = grid[0][0]`。
5. **`min` 的初值写 0** —— 写成 `best = 0` 再 `min(best, dp[j], dp[j-1])`，等价于允许「白嫖」一步，答案偏小。修法：`best` 用两个候选之一初始化，而不是 0。
6. **原地版破坏了入参还被复用** —— 第一次调用后 `grid` 已经变成 `dp`，第二次调用结果就完全不同。修法：要么复制，要么在文档里写明「会修改入参」。
7. **用 `int` 当 `inf` 哨兵并参与加法** —— `best = Integer.MAX_VALUE` 再 `best + grid[i][j]` 会溢出成负数。本题第一行 / 第一列必须单独初始化，正是为了避免「没有合法前驱」的情形；若一定要用哨兵，用 `(1<<30)` 而非 `Integer.MAX_VALUE`。

### 113.6.3 面试官最爱追问的三个问题

**Q1：为什么不能用贪心（每步选较小的邻居）？**
> 「因为贪心只看一步，而路径的总代价是**整条链**的和。官方样例就是反例：`(0,0)=1` 之后，下方是 `1`、右方是 `3`，贪心选下方 1，看似省了 2，但接下来只能贴着左墙走，必须付出 `4 + 2`；而走右边那条 `3` 之后整列都是 1，总代价 7 反而更小。**贪心成立需要『交换论证』：交换任意两步的局部选择不会变差。** 本题里交换会改变后续可走集合，论证不成立。DP 用『按最后一步分类 + min』把全部路径的影响一次性纳入，不需要局部选择。」

**Q2：和一维压缩相比，原地修改 `grid` 不是更省空间吗？为什么正文主推一维压缩？**
> 「原地版的**额外**空间确实是 `O(1)`，但有三点代价：① **破坏入参** —— 调用方拿到的矩阵被改写了，这在生产代码里通常是不可接受的，要复制就又回到 `O(mn)`；② 可读性差，调试时无法对比原始数据；③ 面试时容易被追问『如果矩阵是只读的呢』。一维压缩 `O(n)` 空间、不改入参、代码只多 3 行，是更好的工程权衡。**『最省空间』不等于『最好』**。」

**Q3：如果格子里的数字可以是负数，你的 DP 还成立吗？**
> 「成立。转移 `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` 只用到了『最后一步从哪来』的分类与最优子结构，**不依赖非负性**。非负性在这里的作用是另外两件事：① 它让『路径长度固定为 `m+n-1`』不影响最优性（其实长度本来就恒定，所以这条冗余）；② 它让『贪心 / 单调性』类直觉看起来成立（实际上并不成立，见 Q1）。**真正会被破坏的是『用贪心替代 DP』的想法**，以及『答案一定能用前缀和 / 单调队列优化』这类额外结论。」

## 附：本章小结（可背走的三句话）

```text
① 最小路径和 = dp[i][j] = grid[i][j] + min(上方, 左方)；第一行/第一列必须做前缀和，不能置 1 或 0
② 压缩成一维后内层正序（dp[j-1] 是本行新值）；判据是"被读的格子属于本行还是上一行"
③ 贪心会输（官方样例答 9 vs 7）：路径代价是整条链的和，局部最小 ≠ 全局最小
```
