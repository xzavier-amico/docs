## 073.1 题目

**原题链接**：<https://leetcode.cn/problems/path-sum-iii/>

### 题意重述（把隐含条件补齐）

给你一棵二叉树的根节点 `root` 和一个整数 `targetSum`，统计**有多少条路径**满足「沿父节点到子节点的方向走下来、路径上所有节点值之和等于 `targetSum`」。

六个必须读出来的约束：

| 隐含条件 | 出处 | 违反了会怎样 |
| --- | --- | --- |
| 路径**不必从根开始** | 「不需要从根节点开始」 | 只按 072 的思路找根到叶路径 → 漏掉大量解 |
| 路径**不必到叶子结束** | 「也不需要在叶子节点结束」 | 只在叶子处结算 → 漏解 |
| 路径**只能向下**（父 → 子） | 「路径方向必须是向下的」 | 统计跨左右子树的「拐弯路径」→ 多数（那是 124 的题） |
| 路径**至少含一个节点** | 路径的定义 | 把「空路径」（和 0）也算进去 → `targetSum = 0` 时答案虚高 |
| 节点值**可以是负数** | 约束 `-10⁹ <= Node.val <= 10⁹` | 用「和已超目标就剪枝」→ 漏解 |
| 返回**条数**，不是路径 | 「返回路径和等于给定数值的路径**数目**」 | 返回路径列表 → 判错（那是 113，即 072 的题） |

> 📌 **本章在全书里的位置**：072 的路径限定「根 → 叶」，所以一次 DFS 就能枚举所有路径；
> 本章把起点和终点都放开，如果还按 072 那样「枚举起点再做一次 DFS」，复杂度就是 **O(n·h)**。
> **本章的正解是把 011（数组前缀和 + 哈希）搬到树上**：一次 DFS，用 `prefix[cur] − target` 查「有多少个祖先能作为起点」。
> 而 072 学会的「撤销」，在这里从「删掉列表最后一个元素」变成了「**把计数减一**」—— 同一个思想，换了个载体。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| 节点数 `[0, 1000]` | 最多 1000 | O(n²) = 10⁶ **能过**；所以要靠「说服力」而不是「能不能过」来推动优化 |
| `-10⁹ <= Node.val <= 10⁹` | 值极大 | **前缀和会到 10¹² 量级 → Java 必须 `long`、Go 必须 `int64`**，用 `int` 直接溢出（本章第二失分点） |
| `-1000 <= targetSum <= 1000` | 目标很小 | 不要被「目标很小」误导去用桶计数：前缀和仍然是大数 |
| 树不保证平衡 | 可能是全左链 | 链状树 `h = n = 1000`，两两配对路径数可达 `n(n+1)/2 ≈ 5·10⁵`，答案本身可能很大（`int` 够，最大 `5·10⁵`） |

> 💡 **量级 → 算法**：`n ≤ 1000` 时 O(n²) 完全能过 —— 所以面试里如果只写出双重 DFS，**不会挂，但会被追问「能不能 O(n)」**。
> 本章真正要带走的是那句转化：
> **「一条向下的路径和 = 两个『根到节点的前缀和』之差」**，于是「找路径」变成「查表」。

### 示例

```
示例 1
输入：root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8
输出：3
解释：和为 8 的路径有三条（图中用 ★ 标出端点）：
   ① 5 → 3                 （5+3 = 8）
   ② 5 → 2 → 1             （5+2+1 = 8）
   ③ -3 → 11               （-3+11 = 8）

示例 2
输入：root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
输出：3
解释：除了 072 里那两条「根到叶」路径（5→4→11→2、5→8→4→5），
```

### 我自造的三个反例（写完必须拿它们打一遍）

```text
① [1], targetSum = 0
   → 正解 0（只有一个节点，和为 1）；错解：把"空前缀"当成一条路径 → 返回 1
   → 专治「忘记初始化 map[0] = 1 / 或反过来把空路径算进去」

② [1,-1], targetSum = 0
   → 正解 1（路径 1 → -1）；错解常见为 2（把 [-1] 与 [1] 也算上）或 0（负数被剪枝）
   → 专治「不判前缀和相等」与「负数剪枝」

③ [10⁹, 10⁹, 10⁹, ..., 共 1000 个], targetSum = 1000
   → 前缀和会累加到 10¹²，Java 的 int（上限约 2.1·10⁹）直接溢出
   → 专治「用 int 存前缀和」
```

第 ① 条最容易错：`map[0] = 1` 是**必要的**（它代表「根之前的空前缀」，让「从根开始的路径」也能被统计），但它**不等于**把空路径算成答案 —— 这两件事的差别见 §073.3.2 的第 3 条。

## 073.2 从暴力到最优：第一个念头为什么错

### 第一个念头：照搬 072，只找「根到叶」的路径

```java
// 072 的做法：只统计从根开始、到叶子结束的路径
if (node.left == null && node.right == null && rest == 0) cnt++;
```

- 反例：示例 1 的三条答案里，只有「5→3」「5→2→1」「-3→11」—— **它们都不从根开始**（起点是 `5` 和 `-3`），而且「5→3」的终点 `3` 还是叶子但起点不是根，另外两条连叶子都不是（`3` 有孩子；`11` 是叶子但起点 `-3` 不是根）。
- 所以照搬 072 只能得到 `0` 条答案。**题目第一句话就把 072 的前提推翻了。**

### 第二个念头：每个节点都当一次起点，向下 DFS 累加（暴力 O(n·h)）

```java
int count = 0;
void dfsStart(TreeNode start, long sum) {          // 以 start 为起点向下走
    if (start == null) return;
    sum += start.val;
    if (sum == targetSum) count++;
    dfsStart(start.left, sum);
    dfsStart(start.right, sum);
}
void walk(TreeNode node) {                          // 每个节点都当一次起点
    if (node == null) return;
    dfsStart(node, 0);
    walk(node.left);
    walk(node.right);
}
```

- 时间 **O(n·h)**：每个节点被「以自己为起点」走一遍自己子树，链状树退化成 `O(n²)`；本题 `n = 1000` 时是 **5·10⁵ 级别**，**能过**。
- 它**完全正确**（这就是官方题解里的「双重递归」），问题只在**规模**：`n = 10⁵` 时是 `10¹⁰` 次加法，约 30 秒，必然 TLE。
- 它也是本章最好的**对拍裁判**（§073.5.4 正是用它）。

### 第三个念头：用前缀和，但忘了「计数也要撤销」

```java
Map<Long, Integer> cnt = new HashMap<>();     // 全局只有一张表
cnt.put(0L, 1);
void dfs(TreeNode node, long cur) {
    if (node == null) return;
    cur += node.val;
    ans += cnt.getOrDefault(cur - targetSum, 0);
    cnt.merge(cur, 1, Integer::sum);          // ❌ 登记了，但离开时没有减一
    dfs(node.left, cur);
    dfs(node.right, cur);
}
```

- 这张表的语义本该是「**当前 DFS 路径上、所有祖先节点的前缀和**」，可一旦不撤销，它就退化成「**整棵树里出现过的所有前缀和**」。
- 后果：统计到的路径**起点不一定是当前节点的祖先** —— 可能是另一个分支里的节点，而那种「路径」在树里根本不存在（要先上后下才能连起来）。

```
反例：
        1
       / \
      2   3        targetSum = 3
根到 2 的前缀和 = 1、3；根到 3 的前缀和 = 1、4

正确语义（含撤销）：处理节点 3 时，表里只有 {0:1, 1:1}
    查 4-3 = 1 → 有 1 个（那就是根 1）→ 路径 1→3 的和 = 4-0? 不，是 3 ✓ 记 1 条
处理完左子树时 3(?)，若忘了撤销：处理 3 时表里还有 {3:1}（来自左分支的节点 2）
    查 4-3 = 1 → 仍是 1，但若 targetSum = 1 呢？就会把「2」当成 3 的祖先 → 凭空多出路径
```

### 第四个念头：用前缀和，但忘了 `map[0] = 1`

```java
Map<Long, Integer> cnt = new HashMap<>();      // ❌ 空表起步
```

- 此时「**从根开始**」的路径全部统计不到，因为它们的起点没有父节点（对应前缀和 `0`）。
- 反例：`root = [5], targetSum = 5` → `cur = 5`，查 `5 - 5 = 0`，表里是空的 → 返回 `0`，正确答案是 `1`。

### 卡点在哪

> **卡点：路径的起点和终点都不固定，配对数量是 `O(n²)` 级别的，怎么在一次遍历里数完？**

把路径写成公式就很清楚了。设 `P(v)` 表示「根到节点 `v` 的路径上所有节点值之和」（前缀和）。对一条「从 `a` 向下到 `v`」的路径（`a` 是 `v` 的祖先或 `v` 自己）：

```
sum(a ⇝ v) = P(v) − P(parent(a))
```

于是「`sum(a ⇝ v) = targetSum`」等价于：

```
P(parent(a)) = P(v) − targetSum
```

**这就是全部转化**：与其枚举 `(a, v)` 这一对，不如在遍历到 `v` 时问一句 —— 「**在我到根这条链上，有多少个位置的前缀和等于 `P(v) − targetSum`？**」

### 灵感的来源 —— 「把祖先链做成一张计数器」

- 「祖先链」正好是 DFS 走到 `v` 时**递归栈里**的全部节点；
- 要在 O(1) 内回答「链上有多少个前缀和等于某个值」，天然就是**哈希表计数**（这正是 011 在数组上用过的技巧）；
- 而「链」会随 DFS 进出而变化，所以表里的内容必须跟着**进出同步更新** —— 这就把 072 的「撤销」借了过来。

```
进入 v： cur = 父的前缀和 + v.val
         ans += cnt[cur - targetSum]      ← 数「有多少个祖先能当起点」
         cnt[cur] += 1                     ← 把 v 自己登记进"祖先链"
   …… 递归两支 ……
离开 v： cnt[cur] -= 1                     ← 撤销：v 不再是任何节点的祖先了
```

**四行代码，一次遍历，O(n)。**

## 073.3 原理拆解

### 073.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| **树上前缀和 + 哈希计数（含撤销）** ✅ 首选 | O(n) | O(h) | 15 行 | 需要理解「表 = 祖先链」，写错撤销就静默出错 |
| 每个节点当起点向下 DFS（双重递归） | O(n·h) | O(h) | 12 行 | `n = 10⁵` 时 `10¹⁰` 次，TLE；但**代码最直白，适合作裁判** |
| 前缀和 + `ArrayList` 线性查找 | O(n·h) | O(h) | 15 行 | 每次查询扫一遍祖先链，等于没优化 |
| 用 `Map` 但不撤销 | O(n) | O(n) | 13 行 | **答案错**：把「非祖先」的前缀和也算进来 |
| 两遍 DFS：先存所有前缀和再配对 | O(n²) | O(n) | 25 行 | 需要额外结构，且配对时还要判祖先关系，得不偿失 |
| 前缀和 + 平衡树 / 有序数组 | O(n log n) | O(h) | 20 行 | 只在「要求区间计数」这类变体里才有必要；本题只需精确匹配 |

**为什么哈希是天然选择**：查询语句是「**等于** `cur − targetSum` 的键有几个」，属于精确等值查询；哈希给 O(1) 均摊。若题目改成「和落在某个区间」，才需要用有序结构。

**为什么必须用 `long` / `int64`**：`n ≤ 1000`、`|val| ≤ 10⁹` ⇒ 前缀和最大 `10¹²`，**远超 `int` 的 2.1·10⁹**。这不是「理论上可能」，而是**测试用例里就会出现**（例如一条 1000 个 `10⁹` 的链）。

### 073.3.2 为什么这个做法是对的（正确性论证）

**定义**：`P(v)` = 根到 `v`（含两端）的节点值之和；规定 `P(根的父亲) = 0`（一个虚构的「空前缀」，代表「根之前」）。

**引理 1（路径和的差分表示）**：设 `a` 是 `v` 的祖先或 `v` 本身，则

```
sum(a ⇝ v) = P(v) − P(parent(a))
```

**证明**：`P(v)` 是「根 ⇝ v」的和，`P(parent(a))` 是「根 ⇝ parent(a)」的和。后者是前者的一个**前缀**（因为 `a` 在根到 `v` 的链上，`parent(a)` 也在），两者相减正好留下「`a` ⇝ `v`」这一段。∎

**引理 2（配对不漏不重）**：所有满足 `sum(a ⇝ v) = targetSum` 的向下路径与所有满足「`v` 为终点、`P(v) − targetSum` 出现在祖先链前缀和里」的配对**一一对应**。

**证明**：
- **不重**：一条向下路径由「起点 `a` + 终点 `v`」唯一确定；不同路径的终点可以相同，但起点不同（对应不同的 `P(parent(a))` 取值位置），在哈希表里被分别计数。更准确地说：每个 `(a, v)` 对在遍历到 `v` 时恰好被计一次。
- **不漏**：任取一条合法路径 `a ⇝ v`，遍历到 `v` 时 `a` 的父节点一定还在递归栈上（因为 `v` 在 `a` 的子树里，DFS 尚未返回），其前缀和已被登记；由引理 1，`P(parent(a)) = P(v) − targetSum`，所以这一次查询一定把它数进去。
- 因此计数恰为答案。∎

**引理 3（`map[0] = 1` 的作用，且不等于把空路径算成答案）**：

当 `a` 就是根时，`parent(a)` 是那个虚构的空位置，`P = 0`。为了统计「从根开始」的路径，必须预先令表中 `0` 出现 1 次。

它**不会**把「空路径」算成答案，原因是查询发生的时机：进入 `v` 后先 `cur += v.val`，再查 `cur − targetSum`。若把「空路径」当作答案，等价于某条路径不含任何节点、和为 `0`；而这里查的是「某个祖先的前缀和」，只有在**真实存在那个祖先前缀和**时才计数。对单结点树 `[1]`、`targetSum = 0`：`cur = 1`，查 `1 − 0 = 1`，表里只有 `{0:1}` → 查不到 → 答案 `0` ✅（正确，因为没有任何和等于 0 的路径）。∎

**引理 4（登记的时机：先查后记）**：必须先查询、再把 `cur` 登记进表。

若先登记，则「`targetSum = 0` 时，`cur − targetSum = cur` 会命中自己」，从而把「长度为 0 的空路径」计成一条合法路径。**先查后记**保证了查询时表里只有**真祖先**，不含 `v` 自己。∎

**引理 5（撤销的必要性）**：离开 `v` 时必须 `cnt[cur] -= 1`。

表的语义要求是「**恰好是当前递归栈上的祖先前缀和**」。若不撤销，表里会残留 `v` 及其子树的登记，于是后续处理的节点（`v` 的兄弟分支）会把这些**非祖先**当前缀和，统计出「先上后下」的非法路径。撤销之后，不变量「进入 `dfs(v)` 时表中恰为 `v` 的所有祖先（含虚构空前缀）的前缀和计数」在整棵树上都成立。∎

> **这五条引理合起来，就是本章的全部正确性**。注意引理 3/4/5 全都是「**时机**」问题：`map[0]=1` 的时机、查询与登记的先后、登记与撤销的配对。这类 bug 的共同特点是**不报错、只在特定输入上错**，所以 §073.5.4 的对拍里专门造了 `targetSum = 0` 与含负数的用例。

### 073.3.3 通用解题思路（可迁移的那一层）

#### ① 「前缀和 + 哈希」从一维搬到树上（与 011 的对照）

| 维度 | 011 和为 K 的子数组（数组） | **073 本章（树）** |
| --- | --- | --- |
| 前缀和定义 | `P(i) = a[0]+…+a[i]` | `P(v)` = 根到 `v` 的和 |
| 路径形式 | 连续子数组 `[i+1..j]` | 向下的路径 `a ⇝ v` |
| 转化 | `P(j) − P(i) = k` | `P(v) − P(parent(a)) = targetSum` |
| 哈希键 | `P(j) − k` | `P(v) − targetSum` |
| 表的生命周期 | **整个数组存活**（只增不减） | **只在当前递归链上存活**（进出要同步） |
| 撤销 | **不需要** | **必须**（出栈时减一） |
| 复杂度 | O(n) / O(n) | O(n) / O(h) |

> 🧭 最后两行是本章唯一的新东西：**数组是"一条直线走到底"，所以表只增不减；树是"走进去还要退出来"，所以表必须跟着栈进出。**
> 这句话可以推广成一句判据：**只要遍历存在「回溯」，共享的计数结构就必须在回溯时恢复。**

#### ② 与 072 的对照：同一个「撤销」，两种载体

| 维度 | 072 路径总和 II | 073 本章 |
| --- | --- | --- |
| 路径约束 | 必须根 → 叶 | 任意向下的一段 |
| 共享状态 | `List<Integer> path` | `Map<Long,Integer> cnt` |
| 进入时做什么 | `path.add(val)` | `cnt[cur]++` |
| 查询什么 | `rest == 0`？ | `cnt[cur − targetSum]` 是多少 |
| 离开时做什么 | `path.remove(末尾)` | `cnt[cur]--` |
| 复杂度 | O(n + 输出) | O(n) |
| 输出 | 全部路径本身 | 只要条数 |

> **一句话**：072 是「**把路径物化**」（所以必须撤销列表），073 是「**把路径压缩成一个数**」（所以只需撤销计数）。
> 压缩带来 O(n) 的效率，代价是**丢掉了路径的具体形状** —— 所以 073 只能回答「有几条」，回答不了「是哪几条」。

#### ③ 树上前缀和的通用模板（四行核心，值得背）

```text
cnt = {0: 1}                        # 虚构空前缀：让"从根开始"的路径也能被数到
dfs(node, cur):
    if node == null: return
    cur += node.val
    ans += cnt[cur - target]         # ① 先查：数"有多少个祖先能当起点"
    cnt[cur] += 1                    # ② 再登记：把自己放进"祖先链"
    dfs(node.left,  cur)
    dfs(node.right, cur)
    cnt[cur] -= 1                    # ③ 最后撤销：自己不再是任何人的祖先
```

**这套模板的四个变换方向**（对应 §073.3.4）：

| 想求什么 | 把 `cnt[cur - target]` 换成什么 |
| --- | --- |
| 和为 `target` 的路径**条数** | 累加 `cnt[cur - target]`（本章） |
| 和**最大**的向下路径 | 维护 `minPrefix`（找最小前缀和）或单调结构 |
| 是否存在和为 `target` | 只查 `cnt[cur - target] > 0`，命中即返回 |
| 路径和**在区间内** | 有序结构（平衡树 / 树状数组）做范围计数 |

### 073.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 要返回**路径本身** | 不只条数 | 表中 value 从「计数」改成「前缀和 → 节点列表」，命中时按节点回溯；空间升到 `O(n·h)` |
| 路径允许**拐弯**（124） | 端点之间的路径可以经过 LCA | 换成 071/124 的「返回单边最优 + 全局结算」范式，前缀和不再适用（因为不再是根到点的一段） |
| 边上有**权**（不是点权） | 和的定义变了 | 把边权记到「子节点」上：`P(v)` 定义为「根到 `v` 的所有入边之和」，其余不变 |
| 树是 **N 叉** | 孩子不定 | `for c in children: dfs(c, cur)`，撤销仍在末尾一次 |
| 节点值域更大 / 更多节点 | 溢出风险 | Java 用 `long`、Go 用 `int64`；若还溢出，用 `BigInteger`（但哈希变慢） |
| **动态**插删节点并反复查询 | 不能每次 O(n) | 需要树链剖分 + 前缀和数据结构（远超本题范围，答出方向即可） |
| 只查**一条**路径是否存在（112 的放宽版） | 早停 | 命中即 `return true`，省掉后续遍历 |

## 073.5 双语言实现

### 073.5.1 Java

**主解（树上前缀和 + 哈希计数 + 撤销）**：

```java
import java.util.HashMap;
import java.util.Map;

// LeetCode 判题环境已内置 TreeNode，粘贴到网页时不要重复定义：
// class TreeNode {
//     int val;
//     TreeNode left, right;
//     TreeNode(int val) { this.val = val; }
// }

class Solution {
    private int ans = 0;
    // key = 某个祖先的前缀和，value = 这样的祖先有几个
    // 用 Long 而不是 Integer：节点值可达 1e9、深度可达 1000，前缀和可到 1e12
    private final Map<Long, Integer> cnt = new HashMap<>();

    public int pathSum(TreeNode root, int targetSum) {
        // 虚构的"根之前的空前缀"：让"从根开始"的路径也能被数到
        cnt.put(0L, 1);
        dfs(root, 0L, targetSum);
        return ans;
    }

    private void dfs(TreeNode node, long cur, int target) {
        if (node == null) {
            return;
        }
        cur += node.val;                       // 根到当前节点的前缀和

        // ① 先查：有多少个祖先的"前缀和"恰好差 target
        //    查询必须在登记之前 —— 否则 target == 0 时会把自己配对成一条空路径
        ans += cnt.getOrDefault(cur - target, 0);

        // ② 再登记：把自己加入"祖先链"，供后代查询
        cnt.merge(cur, 1, Integer::sum);

        dfs(node.left,  cur, target);
        dfs(node.right, cur, target);

        // ③ 最后撤销：离开后自己不再是任何节点的祖先
        //    少了这一行不会报错，只会把兄弟分支的路径也算进来（静默错误）
        cnt.merge(cur, -1, Integer::sum);
    }
}
```

**备解（双重 DFS，O(n·h)，作为理解与对拍的基准）**：

```java
class Solution {
    public int pathSum(TreeNode root, int targetSum) {
        if (root == null) {
            return 0;
        }
        // 三种情况互不重叠：以 root 为起点、在左子树里、在右子树里
        return countFrom(root, (long) targetSum)
             + pathSum(root.left, targetSum)
             + pathSum(root.right, targetSum);
    }

    // 从 node 出发、一路向下、和为 target 的路径条数（用 long 防溢出）
    private int countFrom(TreeNode node, long rest) {
        if (node == null) {
            return 0;
        }
        rest -= node.val;
        int hit = (rest == 0) ? 1 : 0;      // 路径可以在这里结束（不必到叶子）
        return hit + countFrom(node.left, rest) + countFrom(node.right, rest);
    }
}
```

### 073.5.2 Go

**主解（前缀和 + 哈希 + 撤销）**：

```go
package main

// LeetCode 判题环境已内置该定义，本地编译时保留即可
type TreeNode struct {
	Val   int
	Left  *TreeNode
	Right *TreeNode
}

func pathSum(root *TreeNode, targetSum int) int {
	ans := 0
	// key = 祖先前缀和，value = 出现次数
	// 必须用 int64：节点值可达 1e9，深度可达 1000，前缀和可到 1e12，int32 会溢出
	cnt := map[int64]int{0: 1}

	var dfs func(node *TreeNode, cur int64)
	dfs = func(node *TreeNode, cur int64) {
		if node == nil {
			return
		}
		cur += int64(node.Val)

		// ① 先查：有多少个祖先的前缀和 = cur - target
		ans += cnt[cur-int64(targetSum)]

		// ② 再登记
		cnt[cur]++

		dfs(node.Left, cur)
		dfs(node.Right, cur)

		// ③ 撤销。注意：计数减到 0 时最好 delete，避免 map 里堆积大量 0 值键
		//    （不 delete 也不影响正确性，但会让"祖先链"的规模悄悄膨胀到 O(n)）
		if cnt[cur] == 1 {
			delete(cnt, cur)
		} else {
			cnt[cur]--
		}
	}

	dfs(root, 0)
	return ans
}
```

**备解（双重 DFS，O(n·h)）**：

```go
package main

func pathSumBrute(root *TreeNode, targetSum int) int {
	if root == nil {
		return 0
	}
	return countFrom(root, int64(targetSum)) +
		pathSumBrute(root.Left, targetSum) +
		pathSumBrute(root.Right, targetSum)
}

func countFrom(node *TreeNode, rest int64) int {
	if node == nil {
		return 0
	}
	rest -= int64(node.Val)
	hit := 0
	if rest == 0 {
		hit = 1 // 路径不必到叶子，随时可以结束
	}
	return hit + countFrom(node.Left, rest) + countFrom(node.Right, rest)
}
```

```go
package main

import "fmt"

// 按 LeetCode 层序数组建树：nil 表示空位
func build(a []interface{}) *TreeNode {
	if len(a) == 0 || a[0] == nil {
		return nil
	}
	root := &TreeNode{Val: a[0].(int)}
	q := []*TreeNode{root}
	i := 1
	for i < len(a) && len(q) > 0 {
		cur := q[0]
		q = q[1:]
		if i < len(a) && a[i] != nil {
			cur.Left = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Left)
		}
		i++
		if i < len(a) && a[i] != nil {
			cur.Right = &TreeNode{Val: a[i].(int)}
			q = append(q, cur.Right)
		}
		i++
	}
	return root
}

func main() {
	cases := []struct {
		tree   []interface{}
		target int
	}{
		{[]interface{}{}, 0},                                                          // 空树
		{[]interface{}{1}, 1},                                                         // 单结点命中
		{[]interface{}{1}, 0},                                                         // 单结点不命中（防"空路径"误计）
		{[]interface{}{1, -1}, 0},                                                     // 负数：1→-1 和为 0
		{[]interface{}{10, 5, -3, 3, 2, nil, 11, 3, -2, nil, 1}, 8},                    // 官方样例
		{[]interface{}{5, 4, 8, 11, nil, 13, 4, 7, 2, nil, nil, 5, 1}, 22},             // 072 的树，多出"不经过根"的那条
	}
	for _, c := range cases {
		root := build(c.tree)
		fmt.Printf("tree=%v target=%d\n   前缀和版=%d\n   双重DFS=%d\n",
			c.tree, c.target, pathSum(root, c.target), pathSumBrute(root, c.target))
	}
}
```

### 073.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 前缀和的类型 | `long`（必须） | `int64`（必须） | 用 `int` 在 1000 层 × 10⁹ 的链上直接溢出，答案静默出错 |
| 哈希的类型 | `Map<Long,Integer>` | `map[int64]int` | 两边都涉及装箱：Java 每个 entry 两个对象，Go 的 `int64` 键无装箱 |
| 取不到时 | `getOrDefault(k, 0)` | `cnt[k]` 直接给零值 | Go 读不存在的键不报错，直接返回 0，写起来更短 |
| 撤销 | `cnt.merge(cur, -1, Integer::sum)` | `cnt[cur]--`（计数到 0 时 `delete`） | Java 里 `get` 到 `null` 会 NPE，务必用 `merge` 或先判空 |
| 全局答案 | 字段 `ans` | 闭包捕获的局部变量 `ans` | Java 字段在同实例多次调用时要清空；Go 闭包每次新建 |
| map 增长 | 不删键会留下大量 `0` 值条目 | 不 `delete` 也会留下 `0` 值键 | 正确性不受影响，但「祖先链」语义会退化成「全树前缀和的键集合」，键数升到 O(n) |

### 073.5.4 对拍测试（O(n²) 枚举所有向下路径，真跑 20000 次 + 边界专测）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：对每个节点当起点，向下 DFS 累加，数命中个数。
// 它完全不涉及"前缀和/哈希/撤销"，是本章最干净的裁判。
func brutePathSumIII(root *TreeNode, target int) int {
	total := 0
	var from func(node *TreeNode, acc int64)
	from = func(node *TreeNode, acc int64) {
		if node == nil {
			return
		}
		acc += int64(node.Val)
		if acc == int64(target) {
			total++ // 路径可以在此结束（不必到叶子）
		}
		from(node.Left, acc)
		from(node.Right, acc)
	}
	var walk func(node *TreeNode)
	walk = func(node *TreeNode) {
		if node == nil {
			return
		}
		from(node, 0) // 以 node 为起点
		walk(node.Left)
		walk(node.Right)
	}
	walk(root)
	return total
}

func randTreeVals(r *rand.Rand, n int) *TreeNode {
	if n == 0 {
		return nil
	}
	root := &TreeNode{Val: r.Intn(7) - 3} // 值域 [-3,3]：负值多、prefix 重复值多，最容易暴露撤销 bug
	slots := []**TreeNode{&root.Left, &root.Right}
	for i := 1; i < n; i++ {
		j := r.Intn(len(slots))
		p := slots[j]
		*p = &TreeNode{Val: r.Intn(7) - 3}
		slots[j] = slots[len(slots)-1]
		slots = slots[:len(slots)-1]
		slots = append(slots, &(*p).Left, &(*p).Right)
	}
	return root
}

func TestPathSumIIIRandom(t *testing.T) {
	r := rand.New(rand.NewSource(437))
	for iter := 0; iter < 20000; iter++ {
		n := r.Intn(14)
		root := randTreeVals(r, n)
		// target 覆盖 0、正、负三种情况：0 专门抓"先登记后查询"和"空路径"这两类 bug
		target := r.Intn(11) - 5
		want := brutePathSumIII(root, target)
		if got := pathSum(root, target); got != want {
			t.Fatalf("iter=%d target=%d got=%d want=%d", iter, target, got, want)
		}
		if got := pathSumBrute(root, target); got != want {

// 边界专测：空树、单结点、全左链（答案数最多）、大值抗溢出、targetSum = 0
func TestPathSumIIIEdge(t *testing.T) {
	if got := pathSum(nil, 0); got != 0 {
		t.Fatalf("空树应为 0，got=%d", got)
	}
	if got := pathSum(&TreeNode{Val: 3}, 3); got != 1 {
		t.Fatalf("单结点命中应为 1，got=%d", got)
	}
	if got := pathSum(&TreeNode{Val: 3}, 0); got != 0 {
		t.Fatalf("单结点 target=0 应为 0（不能把空路径算进去），got=%d", got)
	}

	// 全左链，值全为 1，targetSum = 3 → 每 3 个连续节点算一条：n-2 条
	for n := 1; n <= 60; n++ {
		var chain *TreeNode
		for i := 0; i < n; i++ {
			chain = &TreeNode{Val: 1, Left: chain}
		}
		want := 0
		if n >= 3 {
			want = n - 2
		}

	}

		big = &TreeNode{Val: 1000000000, Left: big}

		t.Fatalf("大值链不应命中，got=%d", got)
	}

// 专门针对"忘记撤销"的定向测试
//
// 关键形状：让"左兄弟的前缀和"恰好等于"右兄弟所缺的那个值"。
//
//	        5                 P(根)=5，P(左孩子)=6，P(右孩子)=7
//	       / \
//	      1   2              targetSum = 1
//
// 正确计数（含撤销）：
//   处理右孩子 2 时，表里只有 {0:1, 5:1}（左孩子已撤销）
//   查 7-1 = 6 → 0 个 → 不计数
//   全树唯一命中是单结点路径 1（和为 1）→ 答案 = 1
//
// 若忘记撤销：右孩子 2 查 7-1 = 6 时，表里还残留着左孩子的 {6:1}
//   → 凭空多出 1 条"路径 1 → 2"（而 1 和 2 是兄弟，这条路径在树里根本不存在）→ 答案 = 2
func TestPathSumIIINoUndo(t *testing.T) {
	root := &TreeNode{Val: 5, Left: &TreeNode{Val: 1}, Right: &TreeNode{Val: 2}}
	if got := pathSum(root, 1); got != 1 {
		t.Fatalf("应为 1，got=%d（若为 2，说明把兄弟分支的前缀和当成了祖先前缀和）", got)
	}
	if got := brutePathSumIII(root, 1); got != 1 {
		t.Fatalf("暴力也应为 1，got=%d", got)
	}

	// 再深一层：左链 10→3、右链 10→6，targetSum = 5
	//   P(3)=13、P(6)=16；查 16-5=11 不该命中任何东西（11 不是任何祖先的前缀和）
	root2 := &TreeNode{Val: 10, Left: &TreeNode{Val: 3}, Right: &TreeNode{Val: 6}}
	if got := pathSum(root2, 5); got != 0 {
		t.Fatalf("应为 0，got=%d", got)
	}
	if got := brutePathSumIII(root2, 5); got != 0 {
		t.Fatalf("暴力也应为 0，got=%d", got)
	}
}
```

> **对拍设计的三处用心**：
> ① 值域取 `[-3,3]`、`target` 覆盖 `0` 与负数 —— 让前缀和大量重复、命中 `targetSum = 0` 的边界，正好命中「先查后记」「必须撤销」这两类静默 bug；
> ② 加了**定向测试**（两兄弟子树放同样的前缀和）：这正是「忘记撤销」会翻车的形状，随机树里不一定能稳定造出来；
> ③ 加了**大值链**：1000 个 `10⁹` 会把「用 `int` 存前缀和」直接打爆。

## 073.6 复杂度与常见坑

### 073.6.1 复杂度推导

- **时间 O(n)**：每个节点进入一次、离开一次；每次做两次哈希操作（一次查询、一次登记、一次撤销 = 常数次），均摊 O(1)。总计 O(n)。
- **空间 O(h)**：
  - 递归栈深 `= h`；
  - 哈希表里最多有 `h + 1` 个键（当前祖先链上的不同前缀和 + 那个虚构的 `0`）；
  - 两者同阶，故 O(h)。链状树 `h = n`，即最坏 O(n)。
- **暴力对照 O(n·h)**：每个节点当一次起点，向下走遍自己的子树。链状树退化为 `O(n²)`：`n = 1000` 时 `5·10⁵` 能过，`n = 10⁵` 时 `5·10⁹` 必然 TLE。

| 方案 | 时间 | 空间 | `n = 1000` 全左链（值全 1，target=3） |
| --- | --- | --- | --- |
| 前缀和 + 哈希 | O(n) | O(h) = O(n) | 1000 次哈希操作，瞬时完成 |
| 双重 DFS | O(n²) | O(h) | `≈5·10⁵` 次加法，仍很快 |
| 前缀和 + 线性扫祖先 | O(n·h) | O(h) | 同上量级，且常数更大 |
| 缺撤销 / 缺 `map[0]=1` | O(n) | O(n) | **速度快但答案错** —— 最危险的一类 |

### 073.6.2 八个真实踩过的坑

1. **忘记撤销（`cnt[cur]--`）** —— 表退化成「全树前缀和集合」，统计出跨分支的假路径，答案偏大且不报错。
2. **忘记 `cnt[0] = 1`** —— 所有「从根开始」的路径都统计不到；`[5], targetSum = 5` 会返回 0。
3. **先登记后查询** —— `targetSum = 0` 时 `cur - 0 = cur` 命中自己，把「空路径」算成一条答案。**必须先查后记。**
4. **用 `int` 存前缀和** —— `1000 × 10⁹ = 10¹²` 溢出成负数，答案随机错。Java 用 `long`、Go 用 `int64`。
5. **Java 里 `cnt.get(...)` 直接拆箱** —— 键不存在时返回 `null`，`int x = cnt.get(k)` 直接 NPE。必须 `getOrDefault` 或先判空。
6. **Go 里计数减到 0 却不 `delete`** —— 正确性不受影响，但哈希表会积累整棵树的所有前缀和，空间从 O(h) 涨到 O(n)，且可能拖慢后续查询（键多了冲突概率上升）。
7. **以为 `targetSum` 小就可以用数组当桶** —— `targetSum ≤ 1000` 是**目标**的范围，不是**前缀和**的范围；前缀和能到 10¹²，桶必然越界。
8. **把「路径不必到叶子」写成「到叶子才结算」** —— 只在叶子处判断 `cur - target` 是否存在，会漏掉大量在中途结束的路径（示例 1 的 `5→3` 就结束在非最深节点上）。

### 073.6.3 面试官最爱追问的三个问题

**Q1：为什么复杂度能从 O(n·h) 降到 O(n)？**

> 「核心是把『枚举起点』换成『查表』。一条从 `a` 向下到 `v` 的路径和 = `P(v) − P(parent(a))`，所以『和为 target』等价于『`P(parent(a)) = P(v) − target`』。遍历到 `v` 时，它的所有祖先都在递归栈上，把它们的 `P` 放进哈希计数，一次查询就能知道『有多少个祖先能当起点』。每个 `v` 查一次，总计 O(n)。**这也说明『前缀和』的威力：它把『区间求和』变成『两个前缀相减』，从而把配对问题变成查找问题。**」

**Q2：为什么一定要撤销？不撤销会多算什么？**

> 「这张表的语义是『**当前 DFS 路径上的祖先前缀和**』。DFS 退出一个节点后，它就不再是后续节点的祖先了，所以必须减一。不撤销的话，表会变成『全树出现过的所有前缀和』—— 于是处理右子树时，左子树里那些节点的前缀和也会被当成祖先，统计出『先上到 LCA 再下来』这种**在树里不存在**的路径。它不会报错，只会让答案偏大，所以我专门用『两兄弟子树放相同前缀和』的定向测试来抓它。」

**Q3：如果节点值小、规模也小，还能怎么优化？**

> 「其实没有更快的渐进算法了 —— O(n) 已经是下界（至少要看每个节点一眼）。可以优化的是**常数**：比如把 `Map` 换成 `HashMap` 预设容量、把 `long` 键换成开地址哈希、或者用『前缀和数组 + 二分』在特定分布下减少哈希开销。**面试里更好的答法是主动说清楚边界：O(n) 时间 + O(h) 空间已是这道题的最优，剩下的都是常数级取舍。**」

**Q4（常见追问）：如果要返回具体的路径，还能 O(n) 吗？**

> 「不能。返回路径意味着每条命中的路径都要物化输出，成本下界是 `O(总输出长度)`；而且表里的 value 要从『计数』变成『前缀和对应的节点列表』，空间也会升到 `O(n·h)`。**本质上这是 072 与 073 的分工：要路径就用 072 的回溯（但路径必须从根开始才好枚举）；只要条数就用 073 的前缀和。**」
