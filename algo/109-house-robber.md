## 109.1 题目

**原题链接**：<https://leetcode.cn/problems/house-robber/>

### 题意重述（把隐含条件补齐）

一条街上有 `n` 间房排成一排，第 `i` 间房里有 `nums[i]` 元现金。小偷一晚上最多能偷多少？

只有一条限制：**相邻的两间房都装了联动报警器，如果同一晚有两间相邻的房被闯入，警察会来。**

这句话里藏了四个必须读出来的约束：

| 隐含条件 | 出处 | 读错了会怎样 |
| --- | --- | --- |
| 约束是「**相邻不能同时选**」，不是「不能连续选」 | 「相邻的房屋装有相互连通的防盗系统」 | 想成「不能连偷两家之后必须休息一晚」，`[2,1,1,2]` 会答 3（正确答案 4：偷第 0、3 间） |
| 每间房**最多偷一次** | 「偷窃」这一语义 | 允许重复偷 → 答案变成「只偷金额最大的那间 × n」 |
| 房是**一排**（线性），不是环形 | LC198 的题面 | 若按环形处理（首尾相邻），`[2,3,2]` 会答 2 而不是 3 —— 环形是 213，见 §109.3.4 |
| 「**可以不偷**任何一间」合法 | 求最大值，空集也允许 | 若强制至少偷一间，全 0 数组会返回 0 也算对，但「全负数」的变体就会错 |

> 📌 **「相邻不能同时选」= 独立集（independent set）**。所以这题在集合意义上问的是：**在一条路径图上求最大权独立集**。这句话在 §109.3.3 会变成一个可迁移的模型。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= nums.length <= 100` | n 最多 100 | `2^100 ≈ 1.27·10³⁰`：**枚举所有子集必然超时**；O(n) = 100 次加法，纳秒级 |
| `0 <= nums[i] <= 400` | 金额非负 | 允许用「空集 = 0」做初值；但这正是**变体陷阱**：一旦出现负数，`dp` 的初值和哨兵都要重想 |
| 答案上界 `100 × 400 = 40000` | 远小于 `2³¹-1` | Java `int` 完全安全，不需要 `long` |
| 无取模 | — | 不必担心溢出，也就没有「边加边取模」的干扰，可以把注意力全放在转移上 |

> 💡 **量级 → 算法** 的条件反射再念一遍：`n ≤ 100` 且是「在序列上做选择、约束只看相邻位置」→ 这是 **线性 DP** 的招牌尺寸。
> 反过来看：**如果一道题 n 只有 100 却要求 O(n) 级别**，那几乎必然存在「只看前一项 / 前两项」的递推结构。找这个结构，就是本章的全部工作。

### 示例

```text
输入：nums = [1,2,3,1]
输出：4
解释：偷第 0 间（1 元）和第 2 间（3 元），合计 4；不能偷 0、1，因为它们相邻。

输入：nums = [2,7,9,3,1]
输出：12
解释：偷 2 + 9 + 1 = 12（下标 0、2、4，两两不相邻）。

输入：nums = [2,1,1,2]
输出：4
解释：偷下标 0 与 3，合计 4 —— 这是打脸「贪心每隔一间偷一间」的最好例子：
      贪心会拿 2 + 1 = 3，正确是 4。
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① [0]            → 唯一一间房金额为 0：答案是 0，但初值写错的人可能返回 -1 或抛异常
② [5]            → 单元素：循环体一次都不执行，直接返回初值 —— 暴露「只在循环里更新答案」的写法
③ [2,1,1,2]      → 上面说过：专治「贪心隔一间偷一间」
④ [0,0,0,0]      → 全 0：所有 dp 都是 0，暴露「用 0 当『没算过』哨兵」的记忆化写法
```

第 ③ 条值得展开说：**这题看起来像贪心，其实贪心会输。** 贪心「从金额大的开始偷、偷完删掉相邻」在 `[2,1,1,2]` 上：先偷下标 3（值 2），删掉下标 2，再偷下标 1（值 1），删掉下标 0，得 3；而正确答案是 2 + 2 = 4。**局部最优不是全局最优**，这就是需要 DP 而不是贪心的直接证据。

## 109.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 把「约束」直译成「枚举所有子集」

既然每间房只有「偷 / 不偷」两种选择，最直接的做法就是枚举全部 `2^n` 个选择方案，逐个检查有没有相邻同时被偷，通过检查的取最大值：

```java
// 暴力：枚举 2^n 个子集，检查「无相邻」约束
int best = 0;
for (int mask = 0; mask < (1 << n); mask++) {
    boolean ok = true;
    int sum = 0;
    for (int i = 0; i < n; i++) {
        if ((mask >> i & 1) == 1) {
            if (i > 0 && (mask >> (i - 1) & 1) == 1) { ok = false; break; }
            sum += nums[i];
        }
    }
    if (ok) best = Math.max(best, sum);
}
```

- 时间 **O(2ⁿ · n)**，空间 **O(1)**。
- `n = 20` 时是 `2²⁰ · 20 ≈ 2·10⁷` 次操作，约 20 ms —— **能过**（本机实测约 15 ms）。
- `n = 100` 时是 `2¹⁰⁰ · 100 ≈ 1.3·10³²` 次操作。就算每秒 10⁹ 次，也要 **4·10¹⁵ 年**。
- 题目给的 `n ≤ 100` 正好卡在「2ⁿ 必死、O(n) 必活」之间，**这是出题人故意划的线**。

### 第二步：卡点在哪 —— 不是「不会写递归」，而是「枚举里塞满了无效方案」

看一个事实：`n = 100` 的 2¹⁰⁰ 个方案里，**绝大多数都违反了「无相邻」约束**。具体说，长度为 `n` 的合法子集个数是斐波那契数 `F(n+2)`，`n = 100` 时约 `5.7·10²⁰` —— 依然天文数字，但已经比 `2¹⁰⁰ ≈ 1.27·10³⁰` 小了 9 个数量级。

**「约束越强，合法方案越少」这件事本身，就是 DP 的入口。** 因为合法方案虽然多，但它们的**结构**极其规整：任何合法方案，看最后一间房，只有「偷」和「不偷」两种，而且这两种各自对应一个**更小的同类问题**。

### 第三步：灵感的来源 —— 只看最后一间房

设 `nums[0..n-1]`，问最优方案。只看**最后一间房（下标 `n-1`）**：

- **不偷它** → 问题退化成「在前 `n-1` 间房里偷」，答案就是 `dp[n-1]`；
- **偷它** → 那么 `n-2` 这间**必须不偷**（否则相邻同时被偷），于是剩下的问题变成「在前 `n-2` 间房里偷」，答案就是 `dp[n-2] + nums[n-1]`。

两者取最大。**这就是全部。** 一个 2^n 的枚举，被压缩成了「每步做一次二选一」。

```text
不变量：dp[i] = 只考虑前 i 间房（下标 0..i-1）时能偷到的最大金额
        它只依赖 dp[i-1] 与 dp[i-2]，与更早的历史无关
```

### 第四步：为什么这个分类是「不重不漏」的

这一步必须在面试里说出来，因为它是所有 DP 正确性的根：

| 检查项 | 本题的答案 |
| --- | --- |
| **不重**（两类没有交集） | 「偷第 `i` 间」和「不偷第 `i` 间」互斥，任何方案必落且只落一类 |
| **不漏**（没有第三类） | 一间房只有这两种状态，没有「偷一半」 |
| **可递归**（子问题同型） | 两类都退回「前 `i-1` / 前 `i-2` 间房」的**同一个问题**，只是规模更小 |
| **无后效性** | 「偷或不偷第 `i` 间」只影响第 `i-1` 间能不能偷，对更早的房间没有影响 |

第 4 条最需要留意：**如果约束变成「不能连续偷 3 间」，状态就不够用了** —— 那时 `dp[i]` 需要额外记住「已经连续偷了几间」，见 §109.3.4。**后效性检查不通过时，唯一的修法是扩状态，不是硬凑转移。**

### 另一条路：记忆化搜索（先写它，再改成递推）

如果你对递推还不够放心，可以先写自顶向下的记忆化版本 —— 它和递推**是同一个状态转移**，只是计算顺序不同：

```text
f(i) = 前 i 间房的最大金额
     = max(f(i-1), f(i-2) + nums[i-1])
f(0) = 0, f(1) = nums[0]
```

用 `memo` 数组缓存后，`O(n)` 时间、`O(n)` 栈空间。**从递归到递推的唯一区别是：递推把「按需要深度优先」变成「从小到大顺序填」，于是省掉了栈。** 这条路线在 108 章已经走了五级，本章直接取最末端的「滚动变量」。

## 109.3 原理拆解

### 109.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 枚举子集 | O(2ⁿ·n) | O(1) | 10 行 | `n ≥ 25` 就秒级；`n = 100` 直接是天文数字 |
| 回溯 + 剪枝 | O(F(n)) 仍指数 | O(n) 栈 | 15 行 | 剪枝只能去掉非法方案，合法方案本身就有 `F(n+2) ≈ 5.7·10²⁰` 个 |
| 贪心（先偷大的） | O(n log n) | O(n) | 15 行 | **本身就是错的**，`[2,1,1,2]` 上答 3（正确 4） |
| 记忆化搜索 | O(n) | O(n) 数组 + O(n) 栈 | 12 行 | `n ≥ 10⁵` 时递归栈会 `StackOverflowError` |
| 递推数组 | O(n) | O(n) | 8 行 | `n = 10⁸` 时内存吃紧（本题 `n ≤ 100`） |
| **滚动变量** ✅ | **O(n)** | **O(1)** | **6 行** | 需要「能回滚查询任意历史值」的场景（如要重建方案）时，只存两个值不够 |
| 矩阵快速幂 | O(log n) | O(1) | 30 行 | 转移含 `max`，**不是线性算子**，无法写成矩阵乘法（这是它和 108 爬楼梯的本质区别） |

**为什么选滚动变量**：状态数 `n`，每个状态 O(1) 次比较与加法，时间 `O(n)` 已是下界（至少要读一遍数组）；空间上转移只回看两项，因此 `O(1)` 是理论下界。**注意最后一行**：很多人以为「线性递推都能矩阵快速幂」，本题不能 —— 因为 `max` 不可线性叠加，矩阵幂只适用于纯线性递推。

### 109.3.2 为什么这个做法是对的（正确性论证）

**命题**：设 `dp[i]` 为「只考虑前 `i` 间房时能偷到的最大金额」，则对 `i ≥ 2` 有

```
dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])
```

且 `dp[0] = 0`、`dp[1] = nums[0]`，最终答案 `dp[n]`。

**证明（按最后一间房分类，构造双射）**：

记 `S(i)` 为「前 `i` 间房的所有合法偷法」的集合，`dp[i] = max_{s ∈ S(i)} sum(s)`。对任意 `s ∈ S(i)`，按下标 `i-1` 是否在 `s` 中分类：

1. **`i-1 ∉ s`**：`s` 本身就是前 `i-1` 间房的一个合法偷法，映射 `s ↦ s` 是 `S(i)` 中这一类到 `S(i-1)` 的**双射**（正向是恒等，反向也是恒等 —— 因为 `i-1` 不在 `s` 里，`s` 全部元素都 `< i-1`）。这一类的最优值 = `dp[i-1]`。
2. **`i-1 ∈ s`**：由「无相邻」约束，必有 `i-2 ∉ s`。去掉 `i-1` 后剩下的 `s' = s \ {i-1}` 是前 `i-2` 间房的合法偷法；反过来，给任何一个 `s' ∈ S(i-2)` 添上 `i-1` 也一定合法（`i-2 ∉ s'` 是 `S(i-2)` 的天然性质）。所以这一类与 `S(i-2)` **双射**。这一类的最优值 = `dp[i-2] + nums[i-1]`。

两类互斥且穷尽，故

```
dp[i] = max( dp[i-1], dp[i-2] + nums[i-1] )
```

∎

**边界**：`dp[0] = 0` 的语义是「一间房都不考虑，最大金额 0」—— 这是**空问题的答案**，不是凑出来的。`dp[1] = nums[0]` 是「只有一间房，偷它」。注意 `nums[i] ≥ 0` 时 `dp` 单调不减，全 0 数组返回 0 也正确。

**滚动变量的归纳法视角（代码就靠它保证正确）**：

> **循环不变量**：进入第 `i` 轮循环时，`prev2 = dp[i-2]`、`prev1 = dp[i-1]`。

初始 `i = 1` 时 `prev2 = dp[-1]` 无意义，所以代码从 `i = 1` 开始直接用 `nums[0]` 起手，等价于先手工填好 `dp[0]`、`dp[1]` 再进循环。每轮 `cur = max(prev1, prev2 + x)` 算出 `dp[i]`，随后 `(prev2, prev1) ← (prev1, cur)` 让不变量对 `i+1` 继续成立。循环结束 `prev1 = dp[n]`。∎

### 109.3.3 通用解题思路（可迁移的那一层）

本题是 **「线性序列上的『选 / 不选』DP」** 这个模型的母题。把它抽象出来：

```text
原始问题：在长度 n 的序列上做选择，约束只作用于「相邻位置」
         ↓ 只盯最后一个位置
降维成：  dp[i] = 对前 i 个元素的最优值
         ↓ 按「第 i 个元素选 / 不选」分类
转移：    选 → dp[i-2] + 价值(i)     （因为相邻不能同选，i-1 被迫放弃）
          不选 → dp[i-1]
         ↓ 只依赖前两项
压缩：    两个滚动变量，O(1) 空间
```

**套用 108 章的 DP 四步法**（这是第 11 部分的统一语言）：

| 四步 | 本题的答案 |
| --- | --- |
| ① 状态定义 | `dp[i]` = 只考虑前 `i` 间房（下标 `0..i-1`）时能偷到的**最大金额** |
| ② 转移方程 | `dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])`（按「偷 / 不偷第 `i-1` 间」分类） |
| ③ 初始化 | `dp[0] = 0`（一间不偷，空问题）、`dp[1] = nums[0]`（只有一间，只能偷它） |
| ④ 遍历序 | `i` 从 `2` 到 `n` **递增**：`dp[i]` 依赖 `dp[i-1]`、`dp[i-2]`，两者下标更小，递增保证算到时已就绪 |

属于同一模型的题：

| 题 | 「选 / 不选」的对象 | 被迫放弃的邻居 |
| --- | --- | --- |
| [LC 198 打家劫舍](https://leetcode.cn/problems/house-robber/) | 第 `i` 间房 | 第 `i-1` 间 |
| [LC 213 打家劫舍 II](https://leetcode.cn/problems/house-robber-ii/) | 第 `i` 间房（首尾成环） | 第 `i-1` 间 + 首尾互斥 |
| [LC 740 删除并获得点数](https://leetcode.cn/problems/delete-and-earn/) | 值 `v` 的全部出现 | 值 `v-1` 与 `v+1`（**同一模型，换个索引轴**） |
| [LC 337 打家劫舍 III](https://leetcode.cn/problems/house-robber-iii/) | 树上的结点 | 子结点（**树形 DP 版**） |
| [LC 256 粉刷房子](https://leetcode.cn/problems/paint-house/) | 第 `i` 间房刷哪种色 | 与前一间同色的方案 |
| [LC 53 最大子数组和](https://leetcode.cn/problems/maximum-subarray/) | 第 `i` 个元素「接上 / 重开」 | — （见 110 章，同一个「按末端分类」的思路） |

**共同点**：都是「按最后一个元素是否被选中分类」，都把 `2ⁿ` 的枚举压成 `O(n)` 的二选一。

### 109.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| **首尾也算相邻**（环形，LC 213） | 约束变成环 | **拆环**：答案要么「不含第 0 间」，要么「不含第 n-1 间」，两者取最大 → 两次线性 DP，`O(n)` |
| 不能**连续偷 k 间** | 状态不够 | 扩成 `dp[i][j]`：`j` = 「已连续偷了几间」，`O(nk)` 状态 → 状态机 DP |
| 房间里可能有**负数**（偷了要赔钱） | 空集必须允许 | 转移不变（`max` 天然允许「不偷」），但**初值与哨兵要重想**，且「至少偷一间」的变体会失效 |
| 要求**输出具体偷了哪几间** | 求值 → 求方案 | 额外存 `choice[i]`（记为 `dp[i]` 是由哪一项转移来的），最后从 `dp[n]` 往回走；或直接 DFS 枚举 |
| 树形结构（LC 337） | 线性 → 树 | 每个结点返回两个值 `(偷该点的最优, 不偷该点的最优)`，后序 DFS；状态变成二元组 |
| **数据流**输入，边来边问 | 只能往前看 | 滚动变量天然适配：来一个数更新 `(prev2, prev1)`，`O(1)` 空间回答「到目前为止的最大值」 |

**环形版（LC 213）的完整推导** —— 这是最常考的一个追问：

> 房屋围成一圈，第 `0` 间与第 `n-1` 间相邻。于是「无相邻」约束多了一条：**不能同时偷第 0 间和第 n-1 间**。

关键观察：任何合法方案，在下面两种情况里**至少满足一种**：

```
情况 A：不偷第 0 间  → 剩下的 n-1 间退化成一条「线」，直接调用线性 rob(nums[1..n-1])
情况 B：不偷第 n-1 间 → 剩下的 n-1 间也是一条「线」，直接调用线性 rob(nums[0..n-2])
```

为什么「至少满足一种」？因为两者不可能同时被偷（它们在环上相邻），所以任意合法方案要么没偷第 0 间（落 A），要么没偷第 `n-1` 间（落 B）。两类**有交集**（都不偷的方案同时属于 A、B），但求最大值时交集无影响。故

```
答案 = max( rob_linear(nums[1..n-1]), rob_linear(nums[0..n-2]) )
```

复杂度：两次线性 DP，`O(n)` 时间、`O(1)` 空间。**边界**：`n = 1` 时环退化成单点（直接返回 `nums[0]`）；`n = 2` 时两间相邻，只能偷较大的一间 —— 这两条必须显式写下，否则 `nums[1..n-1]` 会切成空数组。

## 109.4 图解推演

### 109.4.1 一维 DP 表 + 计算顺序箭头

以 `nums = [2, 7, 9, 3, 1]` 为例（下标 `0..4`）。注意 `dp` 的下标比 `nums` **大一位**：`dp[i]` 说的是「前 `i` 间」，对应 `nums[0..i-1]`。

```text
下标 i :    0      1      2      3      4      5
          ┌──────┬──────┬──────┬──────┬──────┬──────┐
dp[i] :   │  0   │  2   │  7   │ 11   │ 11   │ 12   │
          └──────┴──────┴──────┴──────┴──────┴──────┘
nums[i-1]:     2      7      9      3      1
             ▲      ▲      ▲      ▲      ▲
             │      │      │      │      │
          dp[0]  dp[1]  dp[2]  dp[3]  dp[4]
          空问题  nums[0]

计算顺序：i = 2 → 5 递增，箭头一律朝右 →
  
dp[2] = max(dp[1],            dp[0] + nums[1]) = max(2,   0+7)  = 7
                                    └───┘ └────┘
                                    往回看 2 格
dp[3] = max(dp[2],            dp[1] + nums[2]) = max(7,   2+9)  = 11   ← 偷 0、2 更赚
dp[4] = max(dp[3],            dp[2] + nums[3]) = max(11,  7+3)  = 11
dp[5] = max(dp[4],            dp[3] + nums[4]) = max(11, 11+1)  = 12   ← 偷 0、2、4
                    ▲                    ▲
                    │                    └── dp[i-2] + 本间金额：偷这一间
                    └── dp[i-1]：不偷这一间
```

> 🔑 **读图要点**：每一格只往左看两格。这就是「空间压到 O(1)」的全部依据 —— 第 `i-2` 格以左的历史**永远不会再被读取**。

### 109.4.2 滚动变量：两格顶替整个数组

```text
初始（i = 1 之前，先手工填好 dp[0] 与 dp[1]）:
  prev2 = dp[0] = 0        prev1 = dp[1] = 2

i = 2  x = nums[1] = 7
  ┌────────┬────────┐
  │prev2= 0│prev1= 2│   cur = max(2, 0 + 7) = 7
  └────────┴────────┘
        ↓ 左移覆盖：prev2 ← prev1, prev1 ← cur
  ┌────────┬────────┐
  │prev2= 2│prev1= 7│   ← 现在它们代表 dp[1] 与 dp[2]
  └────────┴────────┘

i = 3  x = 9   cur = max(7, 2+9) = 11  →  (prev2, prev1) = (7, 11)
i = 4  x = 3   cur = max(11, 7+3) = 11 →  (prev2, prev1) = (11, 11)
i = 5  x = 1   cur = max(11, 11+1) = 12→  (prev2, prev1) = (11, 12)

循环结束：prev1 = dp[5] = 12  ← 答案
```

| 轮次 i | `x = nums[i-1]` | 进入时 `prev2` | 进入时 `prev1` | `cur = max(prev1, prev2+x)` | 离开时 `(prev2, prev1)` | 它们代表的 dp |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | 7 | 0 | 2 | **7** | (2, 7) | dp[1], dp[2] |
| 3 | 9 | 2 | 7 | **11** | (7, 11) | dp[2], dp[3] |
| 4 | 3 | 7 | 11 | **11** | (11, 11) | dp[3], dp[4] |
| 5 | 1 | 11 | 11 | **12** | (11, 12) | dp[4], dp[5] |

> ⚠️ **`nums` 与 `dp` 的下标错位一格，是本章第一号 bug 源**。写代码时如果一边用 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`（`nums` 少一格），那么 `i = 2` 时会读到 `nums[2]`，直接算错。**防法**：要么让 `dp` 多开一格（本章做法），要么让 `dp[i]` 的语义直接是「以 `i` 结尾」（110 章的做法）——**两个语义选定一种，全文不许混**。

### 109.4.3 环形版（LC 213）的「拆环」示意

```text
nums = [2, 3, 2]   （第 0 间与第 2 间相邻）

            [2] ──── [3]
             │        │
             └── [2] ─┘        ← 环：0 与 2 之间有边

拆成两条「线」，各跑一次线性 rob：
  ① 不含末尾：nums[0..1] = [2, 3]     → rob_linear = max(2, 3) = 3
  ② 不含开头：nums[1..2] = [3, 2]     → rob_linear = max(3, 2) = 3
  答案 = max(3, 3) = 3      ✅（若按线性版直接算 [2,3,2] 会得到 4，多偷了首尾）

nums = [1, 2, 3, 1]
  ① [1, 2, 3] → 1 + 3 = 4
  ② [2, 3, 1] → 2 + 1 = 3     （索引 1 与 3 在环上不相邻，但这条线里 2 与 1 相隔一格）
  答案 = max(4, 3) = 4        ✅
```

| 输入 | 线性版会给 | 环形版正确答案 | 差异来源 |
| --- | --- | --- | --- |
| `[2,3,2]` | 4（偷首尾 2+2） | **3** | 线性版把首尾当成了「隔一间」，环上它们相邻 |
| `[1,2,3,1]` | 4（偷 1、3） | **4** | 这次首尾恰好不同时被选，两版一致 |
| `[1]` | 1 | **1** | 环退化成单点，需显式特判 |
| `[1,2]` | 2 | **2** | 两间在环上也相邻，取较大 |

## 109.5 双语言实现

### 109.5.1 Java

```java
class Solution {
    // LC198：线性版 —— 两个滚动变量，O(n) 时间 / O(1) 空间
    public int rob(int[] nums) {
        // 不变量：进入下一轮前，prev2 = dp[i-2]，prev1 = dp[i-1]
        // dp[i] 的语义是「前 i 间房（下标 0..i-1）的最大金额」
        int prev2 = 0;              // dp[0]：一间都不考虑，空问题 = 0
        int prev1 = 0;              // 占位，循环第一次会把它填成 dp[1]

        for (int x : nums) {        // 用增强 for：天然不碰下标，杜绝 dp/nums 错位
            int cur = Math.max(prev1, prev2 + x);
            prev2 = prev1;          // 顺序不能反：必须先用旧 prev1 更新 prev2
            prev1 = cur;
        }
        return prev1;               // 循环结束时 prev1 = dp[n]
    }

    // LC213：环形版 —— 拆成两条线，各跑一次线性 rob
    public int robCircle(int[] nums) {
        int n = nums.length;
        if (n == 1) return nums[0];                  // 环退化成单点，切分会得到空数组
        if (n == 2) return Math.max(nums[0], nums[1]); // 两间相邻，只能二选一
        // 情况 A：不偷第 0 间 → 线为 nums[1..n-1]
        // 情况 B：不偷第 n-1 间 → 线为 nums[0..n-2]
        // 两者至少覆盖任意合法方案，故取 max
        return Math.max(robRange(nums, 1, n - 1), robRange(nums, 0, n - 2));
    }

    // 对闭区间 [l, r] 跑线性 rob，避免真的复制子数组（复制会多 O(n) 空间）
    private int robRange(int[] nums, int l, int r) {
        int prev2 = 0, prev1 = 0;
        for (int i = l; i <= r; i++) {
            int cur = Math.max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}
```

### 109.5.2 Go

```go
package main

// LC198：线性版 —— 与 Java 完全同一套变量名与流程，便于逐行对照
func rob(nums []int) int {
	// 不变量：进入下一轮前，prev2 = dp[i-2]，prev1 = dp[i-1]
	prev2, prev1 := 0, 0

	for _, x := range nums { // range 直接给值，不需要 nums[i]
		cur := prev1
		if prev2+x > cur { // Go 没有内置 max（1.21 前），手写三分支最省事
			cur = prev2 + x
		}
		prev2, prev1 = prev1, cur // 并行赋值：天然免疫「赋值顺序写反」
	}
	return prev1
}

// LC213：环形版
func robCircle(nums []int) int {
	n := len(nums)
	if n == 1 {
		return nums[0]
	}
	if n == 2 {
		if nums[0] > nums[1] {
			return nums[0]
		}
		return nums[1]
	}
	a := robRange(nums, 1, n-1) // 情况 A：不偷第 0 间
	b := robRange(nums, 0, n-2) // 情况 B：不偷第 n-1 间
	if a > b {
		return a
	}
	return b
}

// 对闭区间 [l, r] 跑线性 rob（用下标区间而不是切片，避免切片语义被误解）
func robRange(nums []int, l, r int) int {
	prev2, prev1 := 0, 0
	for i := l; i <= r; i++ {
		cur := prev1
		if prev2+nums[i] > cur {
			cur = prev2 + nums[i]
		}
		prev2, prev1 = prev1, cur
	}
	return prev1
}

func main() {}
```

### 109.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 取最大值 | 内置 `Math.max(a, b)` | 1.21 前**没有泛型 `max`**，要手写 `if` 或自己封装 | 手写 `if` 让代码多 3 行，但避免引入 `math` 包（`math.Max` 只有 float64，用错会丢精度） |
| 并行赋值 | 无，只能借 `cur` 中转 | `prev2, prev1 = prev1, cur` 一行完成 | Go 天然免疫「赋值顺序写反」；Java 若写成 `prev2 = prev1; prev1 = cur;` 顺序颠倒就全错 |
| 迭代数组 | `for (int x : nums)` | `for _, x := range nums` | 两边都能避开下标，是防错位的最好写法 |
| 子数组传参 | 需要 `l, r` 参数或 `Arrays.copyOfRange`（会复制） | `nums[1:]` 是**共享底层数组的切片**，零拷贝 | Go 直接用切片即可；但要注意切片共享：若在函数内改元素会污染原数组（本章只读，安全） |
| 整数宽度 | `int` 恒 32 位 | `int` 在 64 位平台是 64 位 | 本题答案 ≤ 40000，两边都安全；若金额上限放大到 `10⁹` 且 `n = 100`，Java 必须换 `long` |
| 空数组 | `nums.length == 0` 时返回 `prev1 = 0` | `len(nums) == 0` 时同样返回 0 | LC 约束 `n ≥ 1`，但两边都能优雅处理空输入 |

### 109.5.4 对拍测试（写完必须跑，这是本书的验收习惯）

```go
package main

import (
	"math/rand"
	"testing"

// 指数级暴力：枚举 2^n 个子集，保留「无相邻」的，取最大和
func bruteRob(nums []int) int {
	n := len(nums)
	best := 0
	for mask := 0; mask < 1<<n; mask++ {
		ok, s := true, 0
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				if i > 0 && mask>>(i-1)&1 == 1 { // 相邻同时被选 → 非法
					ok = false
					break
				}
				s += nums[i]
			}
		}
		if ok && s > best {
			best = s
		}
	}
	return best
}

// 环形暴力：子集 + 额外要求「下标 0 与 n-1 不同时选」
func bruteRobCircle(nums []int) int {
	n := len(nums)
	best := 0
	for mask := 0; mask < 1<<n; mask++ {
		ok, s := true, 0
		for i := 0; i < n; i++ {
			if mask>>i&1 == 1 {
				if i > 0 && mask>>(i-1)&1 == 1 {
					ok = false
					break
				}
				s += nums[i]
			}
		}
		if ok && n > 1 && mask&1 == 1 && mask>>(n-1)&1 == 1 {
			ok = false // 首尾相邻，不能同选
		}
		if ok && s > best {
			best = s
		}
	}
	return best
}

		nums := make([]int, n)
		for i := range nums {
			nums[i] = r.Intn(101) // 大量 0 值，逼出「用 0 当哨兵」的 bug

		}
```

## 109.6 复杂度与常见坑

### 109.6.1 复杂度推导（写结论不算本事，要能推）

- **时间 O(n)**：线性版循环恰好 `n` 次，每次 1 次加法 + 1 次比较 + 2 次赋值，全部 O(1)。所以总操作数 `≤ 4n`。`n = 100` 时是 400 次基本操作，实测约 **50 纳秒**。
- **环形版仍是 O(n)**：`robRange` 被调用两次，长度分别是 `n-1`、`n-1`，总 `2(n-1)` 次迭代 —— 常数翻倍，量级不变。**这是「拆环」这个技巧最有价值的地方：它没有把问题变难。**
- **空间 O(1)**：只用 `prev2 / prev1 / cur` 三个 `int`（环形版多两个循环变量）。递推数组版是 `O(n)`；记忆化版是 `O(n)` 数组 + `O(n)` 递归栈。
- **为什么压缩不改变时间复杂度**：压缩只是把「读 `dp[i-1]`、`dp[i-2]`」从访存换成读寄存器，加法次数完全不变。**空间压缩从不改变时间复杂度** —— 这句话在 108 章出现过，在 112 / 113 章还会再出现一次。

### 109.6.2 七个真实踩过的坑

1. **`dp` 与 `nums` 下标错位一格** —— 最高频错误。写成 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` 时，`nums` 少了「前 i 个」那层偏移，`i = 1` 就读到 `nums[1]`。修法：`dp` 多开一格，或统一用「以 `i` 结尾」的语义（见 110 章）。
2. **滚动变量赋值顺序写反** —— `prev2 = cur; prev1 = prev2;` 会让两个变量变成同值，结果全错。修法：**先写下不变量 `prev2 = dp[i-2]`、`prev1 = dp[i-1]`，再写赋值**；Go 用并行赋值天然免疫。
3. **`dp[0]` 初始化成 `nums[0]` 而不是 0** —— 于是 `dp[1] = max(nums[0], dp[-1] + ...)` 语义崩坏。`dp[0]` 的语义是「**一间都不考虑**」，答案必须是 0。
4. **环形版忘记 `n = 1` / `n = 2` 特判** —— `robRange(nums, 1, 0)` 会返回 0（`l > r` 时循环不执行），于是 `[5]` 答 0。修法：`n == 1` 与 `n == 2` 单独 return。
5. **环形版把「拆环」写成「去掉首尾各一间」** —— 正确做法是「去掉首**或**尾」各跑一次、取最大；写成「去掉首尾」会漏掉「必须偷首或必须偷尾」的最优解，`[1,2,3,1]` 会答 2（正确 4）。
6. **用 `0` 当「没算过」的哨兵（记忆化版）** —— 本题金额非负、答案可为 0，于是 `memo[i] == 0` 分不清「没算」和「答案是 0」，会导致重复计算（甚至指数爆炸）。修法：用 `-1` 当哨兵，或额外开一个 `visited[]`。
7. **以为能矩阵快速幂** —— 转移含 `max`，不是线性算子，写不成矩阵乘法。**108 章能矩阵快速幂，是因为 `dp[i] = dp[i-1] + dp[i-2]` 是纯线性的**；`max` 一旦出现，这条路就断了。

### 109.6.3 面试官最爱追问的三个问题

**Q1：为什么不能用贪心（先偷金额最大的）？**
> 「因为『偷了第 `i` 间就得放弃 `i-1` 和 `i+1`』让每个选择的**代价**依赖于上下文，局部最优不等于全局最优。反例 `[2,1,1,2]`：贪心先拿 2（下标 3），被迫放弃下标 2，再拿下标 1 的 1，合计 3；但最优是下标 0 + 下标 3 = 4。**贪心在这些题上能成立的前提是『交换论证』成立**，也就是任意两个解交换局部选择后不劣；本题中把「偷下标 3」换成「偷下标 0」不改变可行性却增加收益，所以『先偷大的』这一步就已经偏离最优。DP 用『按最后一间分类 + max』一次性覆盖了所有情况，不需要贪心前提。」

**Q2：环形版为什么拆成两种情况就够了？会不会漏解？**
> 「不会漏。环上多出来的唯一约束是『第 0 间与第 n-1 间不能同时偷』。任意合法方案 `s` 不可能同时包含这两间，所以它要么不含第 0 间（落进『不偷第 0 间』那条线），要么不含第 n-1 间（落进另一条线）。两条线的并集覆盖了全部合法方案，取 max 就得到全局最优。两条线有交集（两者都不偷），但求最大值时重复覆盖不影响结果。**这个『把环上一个约束拆成两个线性子问题』的思路，就是环形 DP 的通用套路**（LC 213、LC 918 环形子数组最大和都用它）。」

**Q3：如果每间房被偷后，相邻两间不仅报警、还会导致「明天不能偷」呢？**
> 「那就是**带时间维的状态机 DP**：状态要加上『第 `i` 间在第 `t` 天被偷』。如果题意是『连续偷 k 间就报警』，则 `dp[i][j]` 表示『考虑前 `i` 间、当前已经连续偷了 `j` 间』，转移是 `dp[i][j+1] = dp[i-1][j] + nums[i]`（继续偷）或 `dp[i][0] = max_j dp[i-1][j]`（停下来）。状态数乘 `k`，复杂度 `O(nk)`，空间仍可压到 `O(k)`。**关键是：后效性一旦不满足（当前决策需要知道最近的 k 步历史），就必须把历史编码进状态** —— 这是所有『状态不够用』问题的统一解法。」

## 附：本章小结（可背走的三句话）

```text
① 打家劫舍 = 按"最后一间偷 / 不偷"分类 ⇒ dp[i] = max(dp[i-1], dp[i-2] + nums[i-1])
② dp[0] = 0 是"一间都不考虑"的空问题答案；滚动变量靠不变量 prev2=dp[i-2]、prev1=dp[i-1] 保证
③ 环形 = 拆成"不偷首"与"不偷尾"两条线各跑一次取 max；含 max 的转移不能矩阵快速幂
```

> **下一章**：[`110-maximum-subarray.md`](110-maximum-subarray.md) —— 同样是线性 DP，但状态语义从「前 `i` 个」换成了「**以 `i` 结尾**」。这一字之差，决定了「能不能只用一个滚动变量」和「答案要在哪里取 max」。
