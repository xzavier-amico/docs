## 108.1 题目

**原题链接**：<https://leetcode.cn/problems/climbing-stairs/>

### 题意重述（把隐含条件补齐）

你面前有一个 `n` 阶的楼梯。每次你可以爬 **1 阶**或 **2 阶**。问有多少种**不同的方法**可以爬到楼顶。

这句话里藏了四个必须读出来的约束，任何一条读错，代码就会给出另一个数：

| 隐含条件 | 出处 | 读错了会怎样 |
| --- | --- | --- |
| 「不同方法」= **顺序不同就算不同** | 「多少种不同的方法」 | 若把 `1+2` 和 `2+1` 当成同一种，`n=3` 会答 2（正确答案 3）——那是「整数拆分」不是「爬楼梯」 |
| 每次**只能** 1 或 2 阶 | 「每次你可以爬 1 或 2 个台阶」 | 允许 3 阶就变成 tribonacci（`dp[i]=dp[i-1]+dp[i-2]+dp[i-3]`） |
| 必须**恰好**到顶，不能越过去 | 「爬到楼顶」 | 若允许越过，`n=3` 时 `2+2` 也合法，答案从 3 变成 5 |
| `n ≥ 1`，且**答案在 int 内** | 约束表 | 见下一节：`n = 45` 这个上界不是随便取的 |

> 📌 **爬楼梯与斐波那契的关系**：设答案 `f(n)`，则 `f(n) = F(n+1)`（`F(1)=F(2)=1`）。所以「n ≤ 45」这个约束等价于「`F(46) = 1836311903` 刚好不超过 `2³¹-1 = 2147483647`，而 `F(47) = 2971215073` 溢出」。这解释了为什么出题人偏偏给 45，而不是 50 或 100。

### 约束与「量级反推」

| 约束 | 值 | 它对算法的含义 |
| --- | --- | --- |
| `1 <= n <= 45` | 极小 | **O(n) 递推就够**；O(2ⁿ) 在 `n=45` 时约 **3.7·10⁹ 次函数调用**，按每秒 1 亿次算要 **37 秒**，直接 TLE |
| 答案上界 `1836311903` | `< 2³¹-1` | Java `int` / Go `int` 都安全 —— 但这是**题目帮你算好的**，换个变体（走 1..k 阶）立刻溢出，要换 `long` |
| **没有取模** | — | 不能靠「边加边取模」来规避溢出，必须真的确认值域 |
| 无输入数组 | — | 空间复杂度可以做到 O(1)（滚动变量），这是本题的加分点 |

> 💡 **量级 → 算法**：看到 `n ≤ 45` 且是「计数」问题，第一反应应该是「**有没有递推式**」。45 这个数小到 O(n) 秒过、大到 O(2ⁿ) 必死，是典型的「递推题签名」。

### 示例

```text
输入：n = 1
输出：1
解释：只有 1 这一种

输入：n = 2
输出：2
解释：1+1、2

输入：n = 3
输出：3
解释：1+1+1、1+2、2+1     ← 注意 1+2 与 2+1 是两种，这是本题最容易读错的地方
```

### 我自造的四个反例（写完解法必须拿它们打一遍）

```text
① n = 1        → 循环体一次都不执行，直接返回初值。dp[0] 初值写错的人在这里侥幸过关，
                 但到 n = 2 就会暴露
② n = 2        → 唯一一个「两个前驱都是 dp[0] / dp[1]」的边界；dp[0]=0 会让它答 1

④ n = 4        → 手推校验：1+1+1+1、1+1+2、1+2+1、2+1+1、2+2 = 5 种，与 f(3)+f(2)=3+2 一致
```

## 108.2 从暴力到最优：第一个念头为什么错

### 第一步：暴力 —— 把「定义」直接抄成代码

题目已经给了递推结构：**要爬到第 `k` 阶，最后一步只能是 1 阶或 2 阶**。于是：

```java
// 暴力：把定义直译成递归
int f(int k) {
    if (k <= 1) return 1;          // 第 0 阶（地面）与第 1 阶各只有 1 种到达方式
    return f(k - 1) + f(k - 2);    // 最后一步：跨 1 阶，或跨 2 阶
}
```

- 时间 **O(φⁿ)**，`φ = (1+√5)/2 ≈ 1.618`（因为 `T(n) = T(n-1) + T(n-2) + O(1)`，与斐波那契同阶）。
- 空间 **O(n)**（递归栈深度）。
- 在 `n = 45` 时：**≈ 3.67·10⁹ 次函数调用**。本机实测（2 核容器 / JDK 17）：`n = 40` 已经要 **≈ 1.1 秒**，`n = 45` 要 **≈ 12 秒** —— **TLE**。

### 第二步：递归树长什么样（这是本章最重要的一张图）

`f(5)` 的完整递归树，`★` 标出**被重复计算**的子树：

```text
                          f(5)
                 ┌──────────┴──────────┐
               f(4)                   f(3)★
          ┌──────┴──────┐        ┌──────┴──────┐
        f(3)★         f(2)★   f(2)★         f(1)
     ┌────┴────┐    ┌───┴───┐  ┌───┴───┐
   f(2)★     f(1) f(1)   f(0) f(1)   f(0)
  ┌──┴───┐
 f(1)   f(0)

叶子（f(0) 与 f(1)）共 8 个 = f(5) 的答案
整棵树节点数 = 15 = 2·f(6) - 1 = 2·8 - 1
```

看 `f(3)`：它在**左边的子树里算了 2 次**，`f(2)` 算了 3 次，`f(1)` 算了 5 次。**同一张子问题的答案被反复重算**，这就是 DP 的第一识别信号。

### 第三步：把「重复」量化 —— 一个子问题被算了几次

| 子问题 | f(5) | f(4) | f(3) | f(2) | f(1) | f(0) |
| --- | --- | --- | --- | --- | --- | --- |
| 被调用次数 | 1 | 1 | **2** | **3** | **5** | **3** |
| 规律：等于 `f(n-k)` | f(0)=1 | f(1)=1 | f(2)=2 | f(3)=3 | f(4)=5 | — |

规律很干净：**`f(k)` 被调用的次数 = 从 `n` 走到 `k` 的走法数 = `f(n-k)`**。所以总调用次数 `≈ 2·f(n+1) - 1`。

`n = 45`：`2·f(46) - 1 = 2·1836311903 - 1 ≈ 3.67·10⁹`。
按「每秒 1 亿次函数调用 + 栈操作」的乐观估计，**≈ 37 秒**。这还没算栈溢出的风险。

### 第四步：卡点在哪（不是「想不出转移」，而是「重复」）

很多人以为自己卡在「不知道怎么推」，其实转移式第一分钟就写出来了。真正的问题是：

> **同一张子表被反复填了。** 递归天然是「按需求的深度优先」，它不知道 `f(3)` 已经算过。

于是优化方向只有一个：**让每个 `f(k)` 一辈子只算一次**。这一点决定了后面全部四级递进 ——

### 第五步：灵感的来源 —— 五级递进（本章的主线）

```text
① 暴力递归      O(φⁿ)  时间 / O(n) 空间   ← 树里有重复子树
      ↓ 给树「记账」：算过就存下来
② 记忆化搜索    O(n)   时间 / O(n) 空间   ← 自顶向下 + 缓存，形状还是树，但每个点只展开一次
      ↓ 既然每个点都要算，为什么不从小往大按顺序算？
③ 递推（填表）  O(n)   时间 / O(n) 空间   ← 自底向上，树变成了链
      ↓ 转移只依赖前两项，前面那些用完就可以扔
④ 滚动变量      O(n)   时间 / O(1) 空间   ← 两个变量顶替整个数组
      ↓ 线性递推 ⇒ 可以写成矩阵幂
⑤ 矩阵快速幂    O(log n) 时间 / O(1) 空间 ← n = 10¹⁸ 也能算（本题 n ≤ 45 用不上，但这是「真懂」的标志）
```

每一级都在回答同一个问题：**「上一级里，哪些东西是浪费的？」**

- ①→②：浪费在「重复计算」→ 加缓存。
- ②→③：浪费在「递归开销与栈」→ 换成循环。
- ③→④：浪费在「存了不再用的历史」→ 只留两个变量。
- ④→⑤：浪费在「线性地走 n 步」→ 用矩阵幂把 n 步并成 log n 步。

**第 ② 级记忆化的代码**（注意哨兵的选择）：

```java
class SolutionMemo {
    private int[] memo;

    public int climbStairs(int n) {
        // 大小 n+1：下标 0..n；0 表示「还没算过」
        // 为什么能用 0 当哨兵：答案恒 ≥ 1，0 不可能是一个真实答案
        memo = new int[n + 1];
        return f(n);
    }

    private int f(int k) {
        if (k <= 1) return 1;
        if (memo[k] != 0) return memo[k];   // 命中缓存 → 整棵子树被剪掉
        return memo[k] = f(k - 1) + f(k - 2);
    }
}
```

**第 ⑤ 级矩阵快速幂的核心推导**（细节在 §108.3.4，代码在 §108.3.4 末尾）：

```text
[f(k)    ]   [1 1]   [f(k-1)]
[f(k-1)  ] = [1 0] · [f(k-2)]

所以  [f(n)]   [1 1]^(n-1)   [f(1)]   [1 1]^(n-1)   [1]
      [f(n-1)]=[1 0]       · [f(0)] = [1 0]       · [1]
```

## 108.3 原理拆解

### 108.3.1 数据结构与算法选型

| 方案 | 时间 | 空间 | 代码量 | 什么时候会输 |
| --- | --- | --- | --- | --- |
| 暴力递归 | O(φⁿ) ≈ O(1.618ⁿ) | O(n) 栈 | 4 行 | `n ≥ 40` 就秒级 → 几十秒；`n ≥ 10⁵` 直接爆栈 |
| 记忆化搜索 | O(n) | O(n) | 10 行 | `n` 大到数组开不下（`n = 10⁹` 内存爆）；有递归栈 |
| 递推数组 | O(n) | O(n) | 8 行 | 同上；但无栈风险，可以处理 `n = 10⁷` |
| **滚动变量** ✅ | **O(n)** | **O(1)** | **8 行** | `n ≥ 10⁹` 时线性也不够（本题 `n ≤ 45` 无此问题） |
| 矩阵快速幂 | O(log n) | O(1) | 30 行 | 常数大（8 次乘法/次迭代），`n ≤ 10⁶` 时反而比滚动慢；无取模时**会溢出** |
| Binet 通项公式 | O(1)（理论上） | O(1) | 3 行 | **浮点误差**：`n = 45` 时 `φⁿ/√5` 的双精度结果已可能差 1，`n ≥ 70` 必错 |

**为什么最终选「滚动变量」**：题目 `n ≤ 45`，O(n) 的 45 次加法在任何语言里都是纳秒级；而滚动变量把空间压到 O(1)，代码也不比数组版长。**矩阵快速幂在这个约束下是过度设计** —— 但面试官问「`n = 10¹⁸` 怎么办」时，你必须能立刻说出它，这就是「选型」与「知道有这条路」的区别。

### 108.3.2 为什么这个做法是对的（正确性论证）

**命题**：设 `dp[i]` 为爬到第 `i` 阶的方法数，则 `dp[i] = dp[i-1] + dp[i-2]`，且 `dp[0] = dp[1] = 1`。

**证明（用「最后一步」做分类，构造双射）**：

把「爬到第 `i` 阶的全体走法」记作集合 `S(i)`。对任意一条走法 `w ∈ S(i)`，看它的**最后一步**：

1. **最后一步是 1 阶**：去掉这一步，剩下的是「爬到第 `i-1` 阶」的一条合法走法。这个映射 `w ↦ w'` 是 `S(i)` 中「末步为 1」的子集到 `S(i-1)` 的**双射**（正向去掉末步、反向接上一个 1 阶，互为逆）。
2. **最后一步是 2 阶**：同理，与 `S(i-2)` 双射。

于是：

- **不重**：任何走法的末步只能是 1 或 2，两类互斥；
- **不漏**：没有第三种末步；
- 因此 `|S(i)| = |S(i-1)| + |S(i-2)|`，即 `dp[i] = dp[i-1] + dp[i-2]`。

**边界**：`dp[0] = 1` 的语义是「**站在地面、一步不走，也是一种（空）走法**」。这不是为了凑公式，而是双射的需要：`i = 2` 时「末步 2 阶」去掉后剩的是空走法，必须有 1 种。`dp[1] = 1` 显然只有「跨 1 阶」这一种 —— 等等，这里要严谨：`dp[1]` 若按同一公式算 `dp[1] = dp[0] + dp[-1]`，需要 `dp[-1] = 0`，等价于「`dp[1] = 1` 单独定义」。两种写法结果一样，本书取「直接定义 `dp[1] = 1`」，因为负数下标在代码里是灾难。∎

**归纳法视角（等价，但更适合代码）**：设循环不变量「进入第 `i` 轮时，`prev2 = dp[i-2]`、`prev1 = dp[i-1]`」。初始 `i = 2` 时 `prev2 = dp[0] = 1`、`prev1 = dp[1] = 1`，成立。每轮算出 `cur = dp[i]` 后把 `(prev2, prev1) ← (prev1, cur)`，不变量对 `i+1` 继续成立。循环结束时 `prev1 = dp[n]`。∎

### 108.3.3 通用解题思路 —— DP 四步法（**本章定义，后续 23 章全部引用**）

这是整个第 11 部分的统一语言。任何一道 DP 题，先在纸上填完这四行，代码只是把它们翻译成循环：

```text
① 状态定义：dp[i]（或 dp[i][j]）到底表示什么？
            必须能用一句话说清「表示前 i 个…的…」
            —— 说不清就是没定义好，后面一定写崩

② 转移方程：每个状态由哪些「更小的」状态推出？
            —— 这一步的关键是「分类不重不漏」：按最后一步 / 最后一个物品 / 最后一个字符分类

③ 初始化：dp[0] 是什么？边界为什么取这个值？
            —— 边界值不是凑出来的，是「空问题」的答案

④ 遍历序：为什么这个顺序保证「用到的状态已经算好」？
            —— 一维看下标递增方向，二维看「依赖在左上还是右上」，
               背包看内层正序还是倒序（114 / 116 / 117 会反复用到）
```

**套到本题**：

| 四步 | 本题的答案 |
| --- | --- |
| ① 状态定义 | `dp[i]` = 爬到第 `i` 阶的**方法数** |
| ② 转移方程 | `dp[i] = dp[i-1] + dp[i-2]`（按最后一步是 1 阶还是 2 阶分类） |
| ③ 初始化 | `dp[0] = 1`（空走法）、`dp[1] = 1`（一步跨 1 阶） |
| ④ 遍历序 | `i` 从 2 到 n **递增**：因为 `dp[i]` 依赖 `dp[i-1]`、`dp[i-2]`，两者下标都更小，递增保证算到时已就绪 |

**四步法在后续章节的对应关系（这张表是第 11 部分的目录）**：

| 章 | 状态定义的那句话 | 转移的关键动作 | 遍历序的坑 |
| --- | --- | --- | --- |
| 109 打家劫舍 | 前 `i` 间房能偷到的最大金额 | 分类：偷 / 不偷第 `i` 间 | 一维递增 |
| 110 最大子数组和 | **以 `i` 结尾**的最大和 | 接上前面 / 自己重开 | 一维递增 |
| 111 乘积最大 | 以 `i` 结尾的最大 / 最小积 | 负数会把 min 变 max | 同时维护两个值 |
| 112 不同路径 | 走到 `(i,j)` 的路径数 | 从上 / 从左 | 二维，行优先 |
| 114 分割等和子集 | 前 `i` 个物品能否凑出 `j` | 选 / 不选 | **内层倒序** |

### 108.3.4 可扩展性（面试追问的六个方向）

| 追问 | 变化 | 应对 |
| --- | --- | --- |
| 每次可走 **1..k** 阶 | 转移从 2 项变 k 项 | `dp[i] = dp[i-1] + … + dp[i-k]`：朴素 O(nk)；用**滑动窗口维护后 k 项之和**降到 O(n) |
| `n = 10¹⁸` | 线性都不够 | **矩阵快速幂 O(k³ log n)**（k=2 时就是 O(log n)）；或 Binet 公式 + 高精度 |
| 不允许**连续两次**跨 2 阶 | 状态不够用 | 加一维状态：`dp[i][0/1]` 表示「到第 i 阶且上一步是 1/2 阶」→ 见 129 的三状态机 |
| 某些台阶**不能踩** | 转移被切断 | `dp[i] = 0`（`i` 是坏台阶时）；对应 LC 746 的「最小花费」变体 |
| 要求**输出所有走法** | 求值变求方案 | DP 失效（要枚举），改用回溯 + 剪枝 → 见 096–107 |
| 带**取模**（`1e9+7`） | 数值无界 | 每步 `% MOD`；此时矩阵快速幂才有实用价值（模乘不溢出） |

**矩阵快速幂的完整实现**（`n` 上限能顶到 `10¹⁸`，本题用不上，但要知道怎么写）：

```java
// 递推 [f(k), f(k-1)]ᵀ = M · [f(k-1), f(k-2)]ᵀ，M = [[1,1],[1,0]]
// 于是 [f(n), f(n-1)]ᵀ = M^(n-1) · [f(1), f(0)]ᵀ = M^(n-1) · [1, 1]ᵀ
class SolutionMatrix {
    private static final long MOD = 1_000_000_007L;   // 真正的 O(log n) 场景必须取模，否则 long 也会溢出

    public int climbStairs(int n) {
        if (n <= 2) return n;                          // f(1)=1, f(2)=2
        long[][] m = {{1, 1}, {1, 0}};
        long[][] p = pow(m, n - 1);                    // p = M^(n-1)
        // 答案 = p[0][0]*f(1) + p[0][1]*f(0) = p[0][0] + p[0][1]
        return (int) ((p[0][0] + p[0][1]) % MOD);
    }

    private long[][] pow(long[][] a, long e) {
        long[][] r = {{1, 0}, {0, 1}};                 // 单位矩阵，等价于「乘法的 1」
        while (e > 0) {
            if ((e & 1) == 1) r = mul(r, a);           // 二进制拆分：e 的最低位为 1 就吃掉这一份
            a = mul(a, a);                             // a ← a²，为下一位准备
            e >>= 1;
        }
        return r;
    }

    private long[][] mul(long[][] x, long[][] y) {
        long[][] z = new long[2][2];
        for (int i = 0; i < 2; i++)
            for (int j = 0; j < 2; j++)
                for (int k = 0; k < 2; k++)
                    z[i][j] = (z[i][j] + x[i][k] * y[k][j]) % MOD;
        return z;
    }
}
```

> ⚠️ **矩阵快速幂的陷阱**：不取模时，`M^(n-1)` 的元素会以 φⁿ 的速度膨胀，`n = 90` 左右就溢出 `long`。所以「矩阵快速幂」与「取模」几乎总是成对出现；本题无取模，正是出题人故意把 `n` 卡在 45 的原因。

## 108.4 图解推演

### 108.4.1 递推表：一行填完（一维 DP 的标准画法）

```text
下标 i :   0     1     2     3     4     5     6
dp[i]  :   1     1     2     3     5     8    13
           │     │     │     │     │     │     │
           │     │     │     │     │     │     └─ dp[6] = dp[5] + dp[4] = 8 + 5 = 13
           │     │     │     │     │     └─────── dp[5] = dp[4] + dp[3] = 5 + 3 = 8
           │     │     │     │     └───────────── dp[4] = dp[3] + dp[2] = 3 + 2 = 5
           │     │     │     └─────────────────── dp[3] = dp[2] + dp[1] = 2 + 1 = 3
           │     │     └───────────────────────── dp[2] = dp[1] + dp[0] = 1 + 1 = 2
           │     └─────────────────────────────── dp[1] = 1  （边界，直接定义）
           └───────────────────────────────────── dp[0] = 1  （空走法）

计算顺序：i 从 2 → n 递增（箭头一律朝右）
依赖方向：dp[i] 只看左边两格 ⇒ 递增即可，绝不会用到「还没算的」
```

### 108.4.2 滚动变量：两个格子顶替整个数组

```text
初始（i = 2 之前）:
  prev2 = dp[0] = 1     prev1 = dp[1] = 1

i = 2:
  ┌───────┬───────┐
  │prev2=1│prev1=1│   cur = 1 + 1 = 2
  └───────┴───────┘
      ↓ 左移覆盖：prev2 ← prev1, prev1 ← cur
  ┌───────┬───────┐
  │prev2=1│prev1=2│   ← 现在它们代表 dp[1] 与 dp[2]
  └───────┴───────┘

i = 3:
  cur = 1 + 2 = 3   →  prev2=2, prev1=3    （代表 dp[2], dp[3]）
i = 4:
  cur = 2 + 3 = 5   →  prev2=3, prev1=5    （代表 dp[3], dp[4]）
i = 5:
  cur = 3 + 5 = 8   →  prev2=5, prev1=8    （代表 dp[4], dp[5]）

循环结束：prev1 = dp[n] ← 就是答案
```

| 轮次 i | 进入时 prev2 | 进入时 prev1 | cur = prev2+prev1 | 离开时 (prev2, prev1) | 它们代表的 dp |
| --- | --- | --- | --- | --- | --- |
| 2 | 1 | 1 | 2 | (1, 2) | dp[1], dp[2] |
| 3 | 1 | 2 | 3 | (2, 3) | dp[2], dp[3] |
| 4 | 2 | 3 | 5 | (3, 5) | dp[3], dp[4] |
| 5 | 3 | 5 | 8 | (5, 8) | dp[4], dp[5] |
| 6 | 5 | 8 | 13 | (8, 13) | dp[5], dp[6] |

> 🔑 **滚动变量的正确性靠的是「不变量」而不是直觉**：进入第 `i` 轮时 `prev2 = dp[i-2]`、`prev1 = dp[i-1]`。§108.3.2 已用归纳法证过。写代码时**先写下这个不变量**，再去写赋值顺序，能避免 90% 的「赋值顺序写反」的 bug。

## 108.5 双语言实现

### 108.5.1 Java

```java
class Solution {
    public int climbStairs(int n) {
        // 不变量：进入第 i 轮循环时，prev2 = dp[i-2]，prev1 = dp[i-1]
        // dp[0] = 1 是「空走法」的计数，不是「0 种」——写成 0 会让 n=2 答 1
        int prev2 = 1;
        int prev1 = 1;

        // n = 1 时循环体一次都不执行，直接返回 prev1 = dp[1] = 1，边界天然正确
        for (int i = 2; i <= n; i++) {
            int cur = prev1 + prev2;   // 题目保证答案 ≤ 1836311903 < 2^31-1，int 安全
            prev2 = prev1;             // 顺序不能反：必须先用旧 prev1 更新 prev2
            prev1 = cur;
        }
        return prev1;
    }
}
```

### 108.5.2 Go

```go
package main

func climbStairs(n int) int {
	// 与 Java 完全同一套变量名与流程，便于逐行对照
	// dp[0] = 1（空走法）、dp[1] = 1
	prev2, prev1 := 1, 1

	for i := 2; i <= n; i++ {
		cur := prev1 + prev2 // Go 的 int 在 64 位平台是 64 位，本题不会溢出
		prev2 = prev1
		prev1 = cur
	}
	return prev1
}
```

### 108.5.3 双语言差异批注

| 点 | Java | Go | 对本题的影响 |
| --- | --- | --- | --- |
| 多返回值 / 并行赋值 | 无，只能逐条赋值 | `prev2, prev1 = prev1, prev1+prev2` 一行搞定 | Go 的元组赋值**天然避免赋值顺序写反**；Java 必须借 `cur` 中转，这是本题最易错的一行 |
| 整数宽度 | `int` 恒 32 位 | `int` 在 64 位平台是 64 位 | 本题都安全；若改成「走 1..3 阶」且 `n = 100`，Java 必须换 `long`，Go 在 amd64 上仍安全 —— **这种「平台相关」是 Go 的可移植性隐患，生产代码应显式写 `int64`** |
| 栈深度 | 递归版 `n = 10⁴` 就可能 `StackOverflowError` | goroutine 栈会自动增长，`n = 10⁶` 的深递归也可能活着 | 但**都不要写成递归**：递推版没有这个问题 |
| 空输入 | 必须传 `int`，不存在 null | 同 | 本题无空输入语义 |
| 大整数 | `BigInteger`（重） | `math/big`（重） | 若要算 `n = 10⁵` 的答案（天文数字），两边都要上大整数 |

### 108.5.4 对拍测试（写完必须跑）

```go
package main

import (
	"math/rand"
	"testing"
)

// 暴力参考：不做任何记忆化的递归 —— 指数级，用它当「真值」
// 这就是 §108.2 第一步那段代码的直译
func brute(n int) int {
	if n <= 1 {
		return 1
	}
	return brute(n-1) + brute(n-2)
}

func TestClimbStairsRandom(t *testing.T) {
	r := rand.New(rand.NewSource(20260211))
	for iter := 0; iter < 10000; iter++ {
		// n 只取到 22：brute(22) 约 5.7 万次调用，1 万轮总和仍在秒级
		// 关键不是「跑大 n」，而是「跑足够多的 n + 覆盖所有边界」
		n := 1 + r.Intn(22)
		got, want := climbStairs(n), brute(n)
		if got != want {
			t.Fatalf("iter=%d n=%d got=%d want=%d", iter, n, got, want)
		}
	}
}

// 边界必须单独立测：随机很难恰好抽到 n=45 这种「答案贴着 int 上界」的点
func TestClimbStairsEdge(t *testing.T) {
	cases := []struct{ n, want int }{
		{1, 1}, {2, 2}, {3, 3}, {4, 5},
		{45, 1836311903}, // int 正区间附近，任何取模/溢出都会在这里露馅
	}
	for _, c := range cases {
		if got := climbStairs(c.n); got != c.want {
			t.Fatalf("n=%d got=%d want=%d", c.n, got, c.want)
		}
	}
}
```

> 📌 **对拍的两个设计要点**：
> ① 暴力必须是**真·指数级**（`brute` 不记忆化），否则两边一起错你也发现不了；
> ② 边界用例要**单独列**，因为随机取值几乎永远不会命中 `n = 45` 这种「贴着溢出线」的点。这正是「随机对拍 + 定点边界」双管齐下的原因。

## 108.6 复杂度与常见坑

### 108.6.1 复杂度推导（写结论不算本事，要能推）

- **暴力递归 O(φⁿ)**：`T(n) = T(n-1) + T(n-2) + O(1)`。这是斐波那契型递推，其特征方程 `x² = x + 1` 的根是 `φ ≈ 1.618`，所以 `T(n) = Θ(φⁿ)`。具体地 `T(n) = 2·F(n+1) - 1`。
- **记忆化 / 递推 / 滚动 O(n)**：状态数 `n+1` 个，每个状态 O(1) 次加法 → `Θ(n)` 次加法。循环版实测 `n = 45` 约 **40 纳秒**（40 次加法）。
- **滚动变量空间 O(1)**：只用 `prev2 / prev1 / cur` 三个 `int`。递推数组版是 `O(n)`；记忆化版是 `O(n)` 数组 + `O(n)` 栈。
- **矩阵快速幂 O(log n)**：`e` 每次右移一位，共 `⌊log₂(n-1)⌋+1` 轮；每轮 2 次 2×2 矩阵乘法，每次 8 次乘 + 4 次加 → 常数约 24 次乘。`n = 10¹⁸` 时约 60 轮 ×24 ≈ 1440 次乘。
- **为什么滚动变量不改变时间**：它只把「读 `dp[i-1]`、`dp[i-2]`」换成「读两个寄存器」，加法次数不变。**空间压缩从不改变时间复杂度** —— 这句话在第 112 / 113 章会再次出现。

### 108.6.2 七个真实踩过的坑

1. **`dp[0] = 0`** —— 最经典的错。`n = 1` 时侥幸返回 1（循环没跑），`n = 2` 时答 1（正确 2），`n = 3` 时答 2。修法：把 `dp[0]` 理解成「空走法 = 1 种」。
2. **赋值顺序写反** —— `prev1 = cur; prev2 = prev1;` 会让 `prev2` 永远等于 `cur`，序列变成 1,1,2,2,4,4…。修法：**先写不变量，再写赋值**；Go 用并行赋值天然免疫。
3. **记忆化用 `0` 当哨兵但答案可能为 0** —— 本题答案恒 ≥ 1 所以安全；但在 110（最大子数组和）里答案可以是负数，`0` 当哨兵就会漏算。**哨兵必须选一个「不可能出现的值」**，常见做法是 `-1`（计数题）或 `Integer.MIN_VALUE`（最值题）。
4. **写成递归 + `n = 45` 却仍然 TLE** —— 因为忘了记忆化。看到 TLE 先算调用次数，别急着怀疑语言慢。
5. **矩阵快速幂不取模** —— `long` 在 `n ≈ 90` 时溢出，结果变成随机数。要么取模，要么本题这种「`n` 小」的场景别用矩阵。
6. **把「顺序不同」算成同一种** —— 用组合数 `C(n, ⌊n/2⌋)` 得 3（`n=3` 应为 3，恰好对上）但 `n=4` 得 5（应为 5，也对上）… `n=5` 时组合数得 8，正确也是 8 —— 这个错误在本题**因为恒等式 `Σ C(n-j, j) = F(n+1)` 而恰好不暴露**，但在 91（解码方法）里会立刻错。**「碰巧对」比「错」更危险**。
7. **Go 里 `for i := 2; i <= n; i++` 但 `i` 未使用** —— 现代 Go 编译器对「声明未使用」只报变量错，循环变量可以只用一次；但如果写成 `for i := 2; i < n; i++`，答案差一位（少算 `dp[n]`）。边界 `<` vs `<=` 是本题第一个要检查的地方。

### 108.6.3 面试官最爱追问的三个问题

**Q1：为什么 `dp[0] = 1` 而不是 0？**
> 「因为 `dp[0]` 的语义是『爬到第 0 阶（也就是站在地面）的方法数』，语义上确实只有『一步不走』这 1 种空走法。从递推看，`n = 2` 时『末步跨 2 阶』这条走法去掉末步后剩下的是空走法，它必须被计 1 次，所以 `dp[0]` 必须是 1。写成 0 的直接后果就是 `n = 2` 答 1。」

**Q2：如果每次可以爬 1 到 k 阶，怎么做？n 到 10⁵ 呢？**
> 「转移变成 `dp[i] = dp[i-1] + … + dp[i-k]`。朴素写法是 O(nk)，`n = 10⁵, k = 100` 就是 10⁷ 次加法，能过但不优。观察到这是『长度 k 的滑动窗口和』，维护一个 `window` 变量：加 `dp[i-1]`、减 `dp[i-k-1]`，就降到 O(n)。这题（LC 746 的推广形态）本质是『带窗口的线性递推』。」

**Q3：`n = 10¹⁸` 怎么办？为什么这时不能用 Binet 公式？**
> 「用矩阵快速幂，O(k³ log n)，`k=2` 时就是 O(log n)。Binet 公式 `F(n) = (φⁿ - ψⁿ)/√5` 理论上 O(1)，但双精度浮点只有 53 位尾数，`φⁿ` 在 `n ≈ 70` 时就超过 2⁵³，取整会差 1；而且负数幂项 `ψⁿ` 会把误差放大。要用就得用高精度（等于自己实现大数），比矩阵慢得多。所以『数学公式最快』这句话在浮点世界里不成立。」
