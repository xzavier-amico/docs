## 46.1 教学事故：数据没有穿越，模型与撮合器却穿越了

### 46.1.1 三张漂亮报表背后的五个漏洞

假设“研衡 Agent”在旧财报上生成买卖提案，回测净收益显著高于基准，随后 Paper 连续盈利。
团队宣称“所有 RAG 都按公告时间过滤，Paper 又跑了一个月，可以直接放大资金”。
以下事件不对应任何已证实的公司损失，数字仅服务工程复盘。

| 阶段 | 表面证据 | 实际缺口 |
|---|---|---|
| 历史研究 | 财报 `available_at ≤ decision_at` | 模型预训练可能见过后续破产、并购或复盘文章 |
| 多轮调参 | 最终样本外 Sharpe 很高 | 研究员反复查看同一测试集，实际已变成验证集 |
| L2 回放 | 限价一触及就全成 | 忽略前方队列，撤单量全部错误算成可成交量 |
| Paper | 手续费后为正 | 没有真实冲击、券源约束，推理延迟被设为零 |
| 审计导出 | 每行都有 `prev_hash` | 管理员重写整条链后，把数据库内链头一起替换 |

上线后的第一次跳空行情中，模型推理耗时上升，报价过期，撤单确认又发生延迟。
本地将“撤单请求已提交”视为无风险，释放预算后再下新单，原单却在撤单前成交。
这同时暴露实验污染、成交模型失真、义务管理错误与审计独立性不足，不能归结为“市场突然变了”。

### 46.1.2 先写可以被推翻的断言

1. 输入证据必须满足当时可得，但不能据此断言模型没有历史记忆污染。
2. 测试集首次揭盲后就登记为已使用，不因结果不佳而换名继续称盲测。
3. 撮合器不制造不存在的流动性，不把同一笔历史成交分给多个模拟订单。
4. 新增风险只有通过确定性闸门才可发送，Paper 不能持有实盘凭据。
5. 每次决策可追溯到输入、输出、模型、数据、工具、策略与执行回执的确切版本。
6. 审计验证同时检查内容、顺序、完整性边界和独立锚点，不能只验证链内自洽。

## 46.2 PIT 仍不足：预训练记忆、封存盲测与真正的新样本

### 46.2.1 四种不同的泄露渠道

| 泄露类型 | 示例 | 能做什么，不能证明什么 |
|---|---|---|
| 数据时间穿越 | 用修订后财报替换原始披露值 | PIT 版本可约束读取；仍须验证供应商修订历史 |
| 标签穿越 | 特征窗口含未来收益或持仓标签 | 按事件区间隔离；只按自然日切分可能不足 |
| 研究流程污染 | 看完测试结果再改 prompt、标的池、费用 | 冻结方案和登记试验；不能只保存赢家 |
| 模型记忆污染 | 模型知道历史公司最终退市 | PIT 检索无法抹除参数中的知识；免责声明不是隔离措施 |

即使提示“你现在处于 2018 年”，模型仍可能从公司名、日期、人物和文风关联后续事件。
知识截止日期通常是供应商描述，不是可审计的完整训练数据清单，更不是“截止前历史回测无泄露”的保证。
SFT、偏好优化、蒸馏、联网工具与跨会话记忆也可能带入标签；仅记录基础模型名称不够。
移除公司名、置换代码、扰动日期、只给当时财务数值可以做消融，但会破坏任务语义，且不能证明彻底去记忆。
要求模型回答自己是否见过样本也不是检测器：自述缺乏可靠的训练样本溯源能力。
历史基准可以揭露显著异常与工程错误，不能单独识别“推理能力”和“记住结局”的贡献。

### 46.2.2 盲测协议：封存方案，而不只是封存 CSV

研究集用于设计，验证集用于选型，最终样本外集只用于事先约定的一次确认性评估。
时间相关任务采用滚动训练/验证/测试，按标签覆盖区间 purge，并按任务依赖设置 embargo。
embargo 长度依据持有期、特征窗口和事件重叠确定，不存在通用的“隔一天就安全”。
同公司、多证券映射、新闻转载、同一财报拆片及相邻标签要按组隔离，避免近重复跨集合。
标的池包含当时退市、停牌和失败公司，不能使用今天的指数成分反推过去组合。

封存清单至少包括：

- 假设、基准、主要指标、失败条件、样本纳排、交易日历、资金及费用口径。
- 模型快照标识、提示词、工具白名单、检索索引、重试策略、推理预算和选择规则。
- 数据原始版本、PIT 查询规则、标签生成代码、拆分边界、随机种子及撮合假设。
- 允许试验次数、多重比较处理、提前停止规则、揭盲权限、揭盲时间和审批人。

独立评估者保管标签，先登记方案摘要，再接收不可变预测，最后揭盲计算约定指标。
仅封存摘要不隐藏内容；保密需要访问隔离与加密，摘要用于之后核验没有换样本或换方案。
发现代码 bug 时保留原结果和缺陷记录，修订实验另编号；已揭盲样本不再恢复为“未见”。
比较许多 prompt/模型/参数后，应报告试验规模与选择过程，不能只给最优曲线及朴素显著性。
置信区间采用适合序列相关的分块方法，并披露区块选择；样本不足时明确不确定性。

### 46.2.3 前瞻新样本比历史改名更有说服力

在模型与方案冻结之后，持续采集未来新公告、行情和不可预知事件，按到达时点封存预测。
预测须在目标结果形成前落盘并取得独立时间证据，不能到日终再补写“当时本来想买”。
供应商滚动模型可能在评估期间更新；应固定可固定版本，不能固定时记录响应元数据并分层报告。
禁止在新样本标签形成后把复盘内容送回同一轮在线记忆，再声称后续评价完全独立。
即便如此，供应商内部训练时间、潜在数据渠道和版本细节仍可能不可验证，报告须披露边界。
前瞻性降低既往结局记忆风险，不消除市场漂移、在线反馈污染或未来盈利的不确定性。

## 46.3 L2 盘口模拟：队列、成交、延迟与成本必须成为显式参数

### 46.3.1 L2 不是逐订单队列录像

L2 常给价位聚合量，未必给每笔订单身份、排队次序、隐藏量或撤单位置；具体以市场数据协议为准。
先用快照和增量序号重建盘口，发现缺口、乱序、重复、校验失败时暂停该区间并重取快照。
不得在缺失区间内插一个平滑盘口后仍称“真实逐笔回放”；隔离区间和影响都应进入报告。
事件记录交易所时间、接收时间、策略可见时间；策略不能在接收前消费交易所事件。
同时间戳使用来源序号及明确的跨流合并规则，不用数据库返回顺序决定谁先成交。
逐订单 L3 也不能自动解决隐藏流动性、私有路径、丢包、撮合优先规则和反事实冲击问题。

### 46.3.2 队列假设及其不可识别性

对 FIFO 市场的被动买单，可令 `Q_ahead` 为订单到达交易所时同价前方可见量。
初始位置必须按**到达时间**盘口计算，而不是按信号生成时盘口计算。
后续同价新增量通常排在后面；改价、加量、改单是否丧失优先权，以具体场所规则为准。
若是 pro-rata、拍卖或混合优先机制，必须换模型，不能把 FIFO 参数微调后继续使用。

| 假设档 | 撤单如何影响前方量 | 用途与风险 |
|---|---|---|
| 保守 | 无法识别位置的撤单不减少 `Q_ahead` | 可低估成交，也不是全市场严格下界 |
| 比例 | 按估计前后队列比例分摊撤单 | 需要校准，相关撤单会造成系统误差 |
| 乐观敏感性 | 假定撤单优先来自前方 | 仅作边界比较，不能当已证实成交 |

单个简化事件内，若主动卖出量为 `V`，可模拟成交 `min(leaves, max(0, V-Q_ahead))`。
随后将 `Q_ahead` 更新为 `max(0, Q_ahead-V)`；只有确认该笔交易消耗本价队列时才适用。
trade print 与盘口减量可能是同一事件的不同视图，不能各扣一次；撤单不等于主动成交。
多个模拟订单共享同一行情时由统一分配器按优先级消耗事件量，禁止每单各自获得完整 `V`。
历史回放没有我们这笔订单，真实加入后会改变后续盘口；模拟须标记这一反事实限制。

### 46.3.3 可手算的队列与净损益例子

合成 FIFO 场景：在 100.00 元挂买 100 股，到达时前方可见量为 300 股，无隐藏量。
随后该价撤单 80 股、主动卖出 250 股、再主动卖出 100 股；假设新增量均排在后面。

| 步骤 | 保守：撤单不减前方量 | 乐观：80 股全来自前方 |
|---|---|---|
| 初始 | 前方 300，剩余 100 | 前方 300，剩余 100 |
| 撤单 80 | 前方仍 300 | 前方变 220 |
| 卖出 250 | 前方剩 50，本单成交 0 | 前方清零，本单成交 30 |
| 卖出 100 | 本单成交 50，剩余 50 | 本单再成交 70，剩余 0 |

同一段 L2 可得到成交 50 或 100 股，差异来自假设，不是策略能力提升。
仅为对比，假设保守情形成交的 50 股之后以 100.10 元卖出，双边均按成交额收 2bp、无最低费。
买入额 `50×100.00=5,000.00`，卖出额 `50×100.10=5,005.00`，毛利为 5.00 元。
费用分别为 `1.000`、`1.001` 元，按每腿四舍五入到分得 1.00、1.00，净利 3.00 元。
若压力场景退出成交价额外不利 0.08 元，则卖出额 5,001.00，毛利 1.00，费用仍各 1.00，净亏 1.00 元。
0.08 元是**另设的额外冲击压力**，不是已计入成交价的滑点再扣一次；不能重复计费。
未成交的 50 股不得算收益，也不得在下一时刻自动补成；库存期末按约定估值并单列未实现盈亏。

### 46.3.4 延迟、费用与冲击拆开建模

- 延迟链：行情传播 → 入队 → 特征/RAG → LLM 首次及重试 → 风控 → 网关 → 场所接收。
- 使用分布和尾部场景，不只使用平均值；记录超时后的跳过、降级及最大报价年龄。
- 撤单到达和确认分开建模，撤单途中仍可成交；拒单、部分成交、熔断、停牌必须进入状态机。
- 主动单沿到达时盘口吃量；超出可见深度时拒绝估计或显式外推，不能假定无限最优价成交。
- 成本包括买卖价差、佣金、交易所费/返佣、税费、融资、借券、资金费率及推理/数据开销。
- 费率、最小费、舍入、币种换算、maker/taker 资格必须按历史有效版本应用。
- 小单静态回放与大单冲击模型分开；压力测试参与率、深度折扣、恢复速度与不利选择。

冲击参数从可比市场、规模及执行方式校准，外推范围写清；固定“扣 5bp”不是普适冲击模型。
同时报告成交率、撤单率、执行偏差、持仓暴露、容量曲线和成本敏感性，而不只报告 Sharpe。
用非 LLM 规则基线、同风险基准与消融实验对比，才能检验模型相对于执行假设增加了什么。

## 46.4 Paper 与实盘：四级放量及不可绕过的 kill

### 46.4.1 Paper 能验证连通性，不能创造真实经济约束

| 维度 | Paper / shadow | 实盘 |
|---|---|---|
| 意图与风控 | 可走相同编译器、闸门、幂等协议 | 还承担真实预算及在途义务 |
| 成交 | 模拟器或券商沙箱约定结果 | 场所真实排队、拒绝、部分成交 |
| 资金与券源 | 往往为虚拟余额、简化借券 | 可用购买力、抵押、借券召回和结算限制 |
| 冲击与对手 | 通常不改变真实市场 | 自身订单与对手反馈改变后续轨迹 |
| 故障与费用 | 可能简化拥塞、限频、杂费 | 不同路由、账单、尾部延迟和人工操作成本 |

shadow 只产生实时决策及反事实评估，不向场所发送订单；Paper 可发送到隔离仿真端点。
Paper 与 LIVE 使用不同凭据、账户、网络出口和显式 mode；不能靠一个易误设的布尔值隔离。
真实接口字段兼容不代表撮合行为一致，必须列出沙箱不支持的订单类型与错误码。
线上 replay 输入、Paper 填单结果与实盘回执分别标注，不能混在一条“累计收益”里。

### 46.4.2 四级闸门：预算上限不是承诺放量表

以下四级是教学发布协议，百分比均指预先审批的**策略风险预算**上限，不是客户资产建议。

| 级别 | 模式与上限 | 进入下一层所需证据 |
|---|---|---|
| L0 | 离线回放与封存盲测，实盘预算 0 | 数据/模型污染说明、成本敏感性、事件与账本不变量通过 |
| L1 | 实时 shadow / Paper，实盘预算 0 | 覆盖代表性市场状态，版本锁定，故障与 kill 演练通过 |
| L2 | 限域小额 LIVE，例：不超过预算 1% | 人工审批，成交/费用/延迟校准，零未解释重大对账差异 |
| L3 | 分批扩容，例：1%→5%→10%，仍受总上限 | 每次审批与观察窗，容量及尾部风险复核，可自动降回前级 |

不是“Paper 连赢 N 天就升级”；观察期限、最小事件覆盖和最大容忍差异须事前定义。
上线权限、账户授权、适当性和法域义务由合格责任人确认，本章的四级表不替代任何许可程序。
更换模型、prompt、工具、风险参数或数据管线可能改变风险，按变更等级重走相应闸门。
预算不只限制名义本金，还限制持仓、杠杆、集中度、损失、订单速率及 UNKNOWN 在途暴露。

### 46.4.3 kill 状态机必须独立于模型

运行态可定义为 `ACTIVE → HALT_NEW → CANCEL_PENDING → RECONCILING → PAUSED`。
触发条件包括行情缺口/陈旧、预算异常、回撤越界、审计积压、身份异常、外部回报长期未知。
规则由确定性服务执行，LLM 无权关闭 kill、提高阈值或把失败状态解释为“可忽略”。
首先拒绝增加风险的新单；撤单、查询、对账与已审批的减险路径仍须可用且单独受限。
撤单不是回滚：保留在途冻结，处理撤单前后成交，直到有充分证据证明剩余义务已经消失。
强平不是无风险默认动作；减仓会产生冲击、滑点或因停牌失败，需独立策略和授权。
网关使用递增 fencing epoch 拒绝旧 worker；已离开本地系统的订单仍须向场所查单和撤单。
每个阶段记录触发证据、操作者、epoch 和时间；恢复需完成对账、原因修复与独立人工批准。
演练应测“最后一个允许的新单”及所有在途单，而不是只测控制台按钮是否变红。

## 46.5 WORM 审计：链内自洽、链外锚定与决策引用

### 46.5.1 证据包与版本清单

每次决策生成唯一 `decision_id`，保存可授权审计者读取的输入证据、结构化输出和后续执行引用。
证据引用至少包含对象版本、摘要、源标识、有效/可得时间、检索片段范围及访问权限域。
保存最终策略结论、可核对的理由摘要与工具轨迹，不要求或依赖模型隐藏思维链。
订单、拒单、人工审批、成交、kill 和账本事件均反向引用该决策；不通过自然语言模糊关联。

版本清单必须覆盖：

- 模型供应商、不可变版本/部署标识、分词器、适配器、解码参数、seed 和供应商请求标识。
- system/prompt 模板摘要、实际输入输出、记忆快照、RAG 查询、检索结果与引用原文版本。
- 数据集与 PIT 快照、标的池、标签、日历、复权与汇率、撮合器及成本模型配置。
- 工具 schema、适配器镜像/提交、依赖锁、权限策略、风控与审批规则版本。
- 超时、重试、fallback、人工修改、时钟来源、运行环境及所有不能固定的外部依赖。

同样的 seed 不保证托管模型逐字重现；必须区分“记录可追溯”“计算可重放”和“输出逐字一致”。
缺少历史模型快照时可以重放已记录输出验证下游，而不能声称已复现原模型推理。
敏感输入按最小必要保存和加密，密钥、个人数据不得无选择永久写入不可删除存储。
保留期限、legal hold、密钥生命周期与删除义务存在冲突时，须由法务和安全共同设计。

### 46.5.2 WORM 不等于普通数据库 append-only

数据库禁止 UPDATE 的触发器只能约束部分角色；超级用户、备份恢复和基础设施权限另有攻击面。
对象 WORM 保护的是指定版本及其保留策略，不自动保证日志没有漏写、源数据真实或对象永远可读。
以 S3 为例，governance 模式存在带权限的绕过路径；compliance 模式在保留期内限制更强。
对象锁仍允许同名新版本和 delete marker，因此审计引用必须绑定 `version_id`，不能只用最新 URL。
记录锁模式、保留到期日、legal hold、写后读取校验、跨域副本和访问日志；定期做恢复读取演练。
密文未删但密钥丢失同样会导致证据不可用，不能把“对象还在”当成完成留存要求。

### 46.5.3 链外锚点防止整链替换，但不证明事实真伪

单运行事件按序链接：`H_i = SHA256(规范编码(version, run, seq, H_(i-1), payload, manifest, decision))`。
周期性把 `(run_id, last_seq, head_hash, count, 时间区间)` 提交到独立安全域并保留可验证回执。
链外指审计哈希链之外，不要求上公链；独立时间戳服务、隔离审计账户或外部见证可作为方案组件。
若用 RFC 3161，验证 token、消息摘要、签名、证书链、时间策略和长期验证材料，不能只保存一个时间字符串。
若锚点与生产库由同一管理员同时可改，其独立性不足；仅把链头再复制进同一库不能防整链重写。
锚点约束已提交前缀，两个锚点之间仍有未锚定窗口；公开锚定频率、最大积压及失效处理。
验证者要拿独立预期链头及数量，才能发现尾部截断；仅拿攻击者提供的短链会验证出“通过”。
多分片分别锚定序号范围和链头，再锚定分片清单；不得以单条全局锁牺牲全部写入吞吐。
签名密钥、轮换、时钟及审计服务故障也须记录；哈希不代替来源认证，时间戳不证明内容在该时刻为真。

## 46.6 可核验协议：Go 与 Java 输出同一事件摘要

### 46.6.1 `audit46-v1` 字节定义

协议依次编码七个 UTF-8 字段：`audit46-v1, run_id, seq, prev_hash, payload_hash, manifest_hash, decision_hash`。
每个字段前缀是 **4 字节无符号大端字节长度**，随后是原文字节；没有 BOM、分隔符和结尾换行。
run_id 限 ASCII `[A-Za-z0-9_-]{1,64}`；seq 为 1 到 `2^63-1` 的十进制，无前导零、正号和空白。
四个 hash 均是 64 位小写十六进制文本，不是原始 32 字节；首事件 prev 为 64 个字符 `0`。
payload、manifest、decision 的摘要都基于各自封存的**确切字节**；任意 JSON 重新序列化不得冒充原文。
最后 SHA-256 全部编码字节，输出小写十六进制；以后增加字段须新协议版本，不得静默追加。
该练习的 decision 字节只放引用占位，生产须保存完整引用结构；摘要绑定不能代替引用权限校验。

### 46.6.2 Go：编码、摘要与一个黄金输入

```go
package main

import (
    "bytes"
    "crypto/sha256"
    "encoding/binary"
    "encoding/hex"
    "fmt"
    "regexp"
    "strconv"
    "strings"
)

func digest(s string) string {
    h := sha256.Sum256([]byte(s))
    return hex.EncodeToString(h[:])
}

func event(run, seq, prev, payload, manifest, decision string) (string, error) {
    if !regexp.MustCompile(`^[A-Za-z0-9_-]{1,64}$`).MatchString(run) {
        return "", fmt.Errorf("bad run")
    }
    n, err := strconv.ParseInt(seq, 10, 64)
    if err != nil || n <= 0 || strconv.FormatInt(n, 10) != seq {
        return "", fmt.Errorf("bad seq")
    }
    for _, h := range []string{prev, payload, manifest, decision} {
        if !regexp.MustCompile(`^[0-9a-f]{64}$`).MatchString(h) {
            return "", fmt.Errorf("bad hash")
        }
    }
    var b bytes.Buffer
    for _, s := range []string{"audit46-v1", run, seq, prev, payload, manifest, decision} {
        raw := []byte(s)
        var size [4]byte
        binary.BigEndian.PutUint32(size[:], uint32(len(raw)))
        b.Write(size[:])
        b.Write(raw)
    }
    return digest(b.String()), nil
}

func main() {
    h, err := event("R46", "1", strings.Repeat("0", 64),
        digest("paper-order:buy:10"), digest("model=M1;data=D1;tool=T1"),
        digest("decision=D1;evidence=E1"))
    if err != nil { panic(err) }
    fmt.Println(h)
}
```

### 46.6.3 Java 21+：同字段、同边界、同摘要

```java
import java.io.ByteArrayOutputStream;
import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.HexFormat;

public class Audit46 {
    static String digest(byte[] bytes) throws Exception {
        return HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(bytes));
    }
    static String hash(String s) throws Exception {
        return digest(s.getBytes(StandardCharsets.UTF_8));
    }
    static String event(String run, String seq, String prev, String payload,
                        String manifest, String decision) throws Exception {
        if (!run.matches("[A-Za-z0-9_-]{1,64}")) throw new IllegalArgumentException("bad run");
        long n = Long.parseLong(seq);
        if (n <= 0 || !Long.toString(n).equals(seq)) throw new IllegalArgumentException("bad seq");
        for (String h : new String[]{prev, payload, manifest, decision}) {
            if (!h.matches("[0-9a-f]{64}")) throw new IllegalArgumentException("bad hash");
        }
        var out = new ByteArrayOutputStream();
        for (String s : new String[]{"audit46-v1", run, seq, prev, payload, manifest, decision}) {
            byte[] raw = s.getBytes(StandardCharsets.UTF_8);
            out.writeBytes(ByteBuffer.allocate(4).putInt(raw.length).array());
            out.writeBytes(raw);
        }
        return digest(out.toByteArray());
    }
    public static void main(String[] args) throws Exception {
        System.out.println(event("R46", "1", "0".repeat(64),
            hash("paper-order:buy:10"), hash("model=M1;data=D1;tool=T1"),
            hash("decision=D1;evidence=E1")));
    }
}
```

两个程序只校验单事件字段，没有校验 seq 与数据库前驱的关系，也没有实现签名、锚点和对象锁。
完整验证器还须重读原对象，重算三个内容摘要，检查 manifest 固定值、引用可解析及事件链连续性。
然后比对独立锚点中的 last_seq/head_hash/count，拒绝缺段、分叉、截断、替换和未知协议版本。

**本地已核验范围**：提取上述 Go/Java 代码独立编译运行，并用 Python 按协议重新计算，三者一致。
该输入编码长度为 298 字节，黄金摘要为 `01f9eee551a8908ba9fd4a4c9f223e70e837389a7102184c3c776128769e913b`。
两种语言另通过序号非规范/溢出拒绝、long 最大值接受、非法 run/hash 拒绝及 payload 改动摘要变化测试。
这些结果不覆盖数据库并发、完整链验证、WORM 配置、锚点验签或任何真实交易行为。

## 46.7 手算测试、故障注入、压测对账与面试自检

### 46.7.1 测试不只问“曲线是否更好看”

| 测试夹具 | 断言 |
|---|---|
| 46.3 队列样本 | 保守累计 50、乐观累计 100；总成交不能超过共享可用事件量 |
| 46.3 费用样本 | 基线净利 3.00，额外不利退出后净亏 1.00，不重复扣冲击 |
| seq 为 `01`、`+1`、`0`、超 long 上界 | 两种语言都拒绝；边界内 `9223372036854775807` 可编码 |
| run 含换行，hash 含大写或少一位 | 两种语言都拒绝，避免模糊编码 |
| 改 payload 一个字节，或交换 manifest/decision | 重算事件摘要与原值不同；原事件不能通过内容复核 |
| 删除中间事件或截掉尾部 | 前驱/连续性检查失败；尾部须由独立锚点发现 |
| 用相同 key 写新对象版本 | 原版本仍可读取；“读取最新版本”测试应暴露错误引用 |
| 标签提前可读、测试集重复揭盲 | 访问告警且实验失格，不自动重命名为新盲测 |
| kill 时发送队列中存在旧 epoch | 未发送新增风险被拦；已发送订单继续查撤与保留义务 |
| Paper 配置了 LIVE endpoint 或凭据 | 启动或出站策略拒绝；不靠模型自行识别环境 |

对记忆污染加入知名历史事件与匿名数值版的配对消融，结果差异只作为风险信号，不是定罪或免责证据。
主指标之外报告失败试验、参数搜索次数、成本分解、分时期表现、基准与样本量，避免挑选性展示。

### 46.7.2 压测与分层对账

隔离环境计划：100 个合成运行、每运行 10,000 事件，注入重复写、乱序、对象写成功后断库和锚点超时。
另设单热分片、行情突发、LLM 尾延迟、回报洪峰、存储限流和只读恢复场景；不向真实市场压测。
测编码/持久化 p50/p95/p99、对象落盘延迟、链头锁等待、待锚定事件数及最老未归档年龄。
性能验收由容量与 SLO 决定，本章不提供未经实测的 TPS 或恢复秒数。
安全断言：重复经济事件数为 0、链分叉数为 0、越权新增风险数为 0，所有孤儿与积压可被检测。
超出锚点或归档积压阈值时暂停新增风险，但不得阻断成交回报、撤单和必要减险证据。

按决策 → 意图 → 风控预占 → 订单 → 成交 → 费用 → 账本 → 券商/场所结算单逐层核对。
比较数量、价格、金额、币种、事件时间、唯一键与证据版本，不能只比总收益或总订单数。
Paper 对模拟器事实对账，实盘对外部真实回执和结算事实对账；Paper 对平不能证明实盘正确。
差异按来源和账龄分桶，保留修复审批；冲正/补记有独立幂等键，不删除旧证据来“修好”链。
模型版本重放失败、数据许可导致原文不可导出、外部供应商字段缺失，都作为显式验证限制报告。

### 46.7.3 术语与面试自检

| 术语 | 本章含义 | 容易误解成什么 |
|---|---|---|
| PIT | 只访问当时已可得的特定数据版本 | 模型参数中绝无未来知识 |
| OOS / blind | 样本外 / 标签隔离且方案先冻结 | 研究员从未见过的同义改名测试集 |
| Paper / shadow | 仿真成交 / 只观察不发送 | 小额真实成交或真实市场冲击实验 |
| queue position | 特定撮合规则下的前方竞争量 | 触价必然全额成交 |
| WORM | 约定保留规则下限制对象版本改删 | 源事实真实、永不丢失或监管认证 |
| external anchor | 哈希链之外独立保存的前缀承诺 | 在同一个数据库再存一个链头 |
| reproducibility | 在声明范围内可重建输入与计算 | 同 seed 必定重现托管模型输出 |

1. PIT 回测为何仍可能“知道未来”？分别指出参数记忆、检索、标签与人工选型泄露。
2. 谁保管盲测标签？揭盲后修 bug 的结果如何命名，如何避免同一测试集无限再利用？
3. 只有 L2 能否知道撤单来自前方？不能；应给出假设、校准和敏感性而非伪造精确位置。
4. 解释队列手算为何是 50/100 股；两笔模拟单共享历史成交时如何防止重复分配？
5. Paper 全成后实盘部分成交，哪几层需要复核？至少涵盖延迟、队列、路由、券源和费用。
6. kill 后有哪些操作仍须继续？为何停止进程、撤单请求成功或模型说已平仓都不够？
7. 管理员重写整条链后为何仍可自洽？独立锚点如何发现替换和尾部截断，窗口风险是什么？
8. 仅交付三个数据库表与云厂商产品评估报告，能否声称系统符合某监管留存要求？不能。
