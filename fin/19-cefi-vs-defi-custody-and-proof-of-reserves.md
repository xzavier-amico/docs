# 19. CeFi 与 DeFi：托管、效率与储备证明到底证明了什么

> **状态**：已完成（基础篇初稿）｜本章作为第二部分收束章，比较中心化平台与链上协议的信任边界，并建立“资产证明 + 负债证明 + 权利证明 + 流动性证明”的完整审计框架。

## 19.1 引子：资产在链上，不等于客户拥有可兑付权

2022 年 11 月 FTX 申请破产，公开调查和诉讼材料揭示了客户资产隔离、关联实体、风险控制和治理失效等问题。这里最重要的工程教训不是“中心化一定坏、去中心化一定好”，而是必须回答：客户资产记在谁的账上、谁能移动它、平台是否把它借给关联方、客户索赔在破产时排第几、以及外部观察者能否独立验证。

DeFi 把部分规则公开写入合约，减少了“平台声称有余额但不让验证”的问题；但它仍可能依赖升级管理员、预言机、桥、前端、流动性提供者和法律体系。公开代码不是自动的偿付承诺。

## 19.2 八维比较

| 维度 | CeFi 交易平台 | DeFi 协议 |
|---|---|---|
| 账户 | 平台内部数据库余额 | 钱包与合约状态 |
| 执行 | 平台撮合与风控 | 链上交易和共识排序 |
| 托管 | 平台/托管人控制私钥 | 用户或合约控制资产 |
| 交易速度 | 可内部记账，快 | 受区块和 Gas 约束 |
| 纠错 | 可人工冻结、冲正或回滚内部账 | 通常只能按合约和升级规则处理 |
| 透明性 | 依赖报表、审计和对账 | 状态公开，但语义和负债不一定完整 |
| 监管 | KYC、牌照、破产法和客户协议 | 协议、前端、治理和司法边界复杂 |
| 主要故障 | 挪用、权限、内部账漂移 | 代码、预言机、桥、治理和流动性 |

CeFi 的“内部余额”不是链上资产，DeFi 的“合约余额”也不是所有者法律权利的完整证明。两者都需要资产负债表和权限矩阵。

## 19.3 储备证明的四层结构

### 1. 资产证明（Proof of Assets）

证明平台控制的链上地址、银行账户、托管账户或证券资产。例如链上地址签名、托管人确认和银行对账单。它回答“平台控制多少资产”，不回答这些资产是否已质押、被借出或属于客户。

### 2. 负债证明（Proof of Liabilities）

列出所有客户应付款、借款、未结算订单、负余额、保证金和表外承诺。仅做资产证明而不列负债，无法判断偿付能力。

### 3. 成员包含证明

把用户负债汇总进 Merkle Tree 或 Merkle Sum Tree，让用户验证自己的余额被纳入报告。普通 Merkle Tree 只证明“某个数在树里”，不能证明总和；Merkle Sum Tree 在节点中保存子树和，才能验证总负债总额，但仍需防止平台隐藏账户、负余额和关联债务。

### 4. 权利和流动性证明

客户是平台的信托受益人、普通债权人还是抵押债权人？资产能否在 24 小时内变现？是否有锁仓、再质押、借出、冻结或法律争议？这是储备证明最容易遗漏的层。

## 19.4 Merkle Sum Tree 手算

设三个用户的净负债分别为 100、250、50 单位，平台报告总负债 400。叶节点保存 `(hash, sum)`，父节点的 sum 为子节点之和：

```text
                 Root: sum = 400
                 /              \
          A+B: 350             C: 50
          /       \
      A:100       B:250
```

用户 B 收到 A 的哈希和、C 的哈希和及各节点 sum，可以验证自己路径上的总和为 400。若平台偷偷把 B 记为负 250，数学上总和会变小，但这并不代表平台可以合法抵销负债；审计规则必须定义负余额是否允许、保证金账户如何净额化、是否包含未实现盈亏。

**sum 必须被哈希承诺绑定。** 父节点哈希应覆盖域标签、左右子哈希、左右子树金额、币种和快照身份；如果只哈希子哈希而不绑定 sum，平台可以向不同验证者提供不同的求和声明。叶子也不能只哈希公开用户名加余额，否则可被字典枚举；应使用高熵用户承诺并对金额采用固定编码，禁止字符串拼接歧义。包含证明仍不能证明平台没有遗漏其他客户。

### zk-PoR 可以隐藏什么，不能证明什么

零知识电路可以证明：对一组已承诺账户，余额满足范围约束、按规则计算的负债总和等于某值，或受限净额抵销后资产覆盖负债，而不公开每个用户的数值。必须对叶子非负性或明确的净额规则做约束，防止用虚构负账户抵销真实负债；还需防整数溢出、模域绕回、重复叶子和快照错配。

但电路只能证明**输入集合满足约束**，无法凭空知道银行担保、法院冻结、关联实体借款或被平台排除的客户是否存在。资产控制签名、链上快照、全量客户负债、第三方托管确认和财务审计是互补证据，不是任选其一。让全部客户逐一查包含证明也不等于保证 100% 客户参与核验。

若平台有 400 的客户负债和 430 的链上资产，简单覆盖率为 107.5%。假设其中 200 被第三方优先权约束、100 在压力窗口内完全无法变现、30 依法不属于客户隔离资产，且三者互不重叠，则本窗口内无争议可动用资产只有 `430−200−100−30=100`。这里算的是**给定权利边界下的即时可用资产**；长尾资产不流动不代表没有价值，平台自有资产也不能在未核对完整负债和法律地位前一律剔除或一律算作客户储备。

## 19.5 CeFi 与 DeFi 的资金流图

```text
CeFi：客户入金 ─► 托管地址/银行 ─► 平台内部账本 ─► 撮合、借贷、提币
                         │                │
                         └─权限/关联方──► 未披露资产负债与流动性风险

DeFi：用户钱包 ─► 合约状态 ─► 借贷池/AMM/清算器 ─► 链上可验证状态
          │             │             │
          └─私钥风险    └─代码/预言机  └─流动性与治理风险
```

CeFi 要做内部账本、链上余额、托管余额和渠道流水四方对账；DeFi 要做合约状态、事件日志、代币实际余额、权限变更和预言机输入对账。无论是哪一种，余额都不能只由一张可编辑的报表决定。

## 19.6 证明的盲区与极端情况

1. **时间点错觉**：储备证明是某一时点快照，平台可以在拍照前短借资产，之后又失去流动性。
2. **表外负债**：未结算衍生品、借入资产、客户负余额、保证金亏损和担保承诺可能不在简单用户余额表中。
3. **资产质量**：一个长尾代币的账面价格不等于大额出售后的可实现价格。
4. **权限与冻结**：链上地址有余额不代表平台当前有签名权，或代币发行方不会冻结。
5. **法律权利**：链上地址归平台控制不代表破产时客户自动优先受偿。
6. **DeFi 治理**：升级管理员、多签、预言机和前端被攻破后，代码公开仍不能抵消权限风险。
7. **交叉平台风险**：平台资产存放在另一家交易所、桥或借贷协议时，储备证明会把风险传递到外部主体。

压力测试应至少包括：客户同时提取 30%、主要资产价格下跌 30%、稳定币脱锚 10%、桥暂停 7 天、银行结算暂停 2 个工作日、链拥堵导致 Gas 增加 20 倍以及关联方违约。结果要输出可兑付比例、完成时间和无法兑付的优先级，而不是只有一个“储备率”。

## 19.7 工程审计清单

| 检查项 | 必须回答的问题 |
|---|---|
| 资产主数据 | 每种资产的链、合约、托管账户和法律所有者是什么？ |
| 客户负债 | 是否包含小数余额、负余额、冻结余额、未结算和衍生品？ |
| 权限 | 谁能签名、暂停、升级、转移或借出资产？是否有时间锁？ |
| 对账 | 内部账、链上余额、托管报表和交易渠道是否逐项匹配？ |
| 流动性 | 压力情境下几小时或几天可变现多少？ |
| 证明 | 用户能否验证自己和总额，审计者能否验证完整性？ |
| 纠错 | 差异如何挂账、调查、冲正和通知，是否保留不可变证据？ |

对账系统应把 `available`、`frozen`、`pending`、`borrowed`、`collateralized` 和 `disputed` 分开，不能把所有链上余额一栏相加。每次快照都要有区块高度、时间、价格来源、签名者和报告版本。

## 19.8 速记与自检题

**速记**：PoR 不是完整审计；资产证明必须与负债证明配套；Merkle Tree 证明包含关系，Merkle Sum Tree 才能进一步证明求和；偿付能力与流动性不同；CeFi 和 DeFi 只是把信任边界放在不同位置。

1. 平台客户负债 1,000，链上可验证资产 1,200，其中互不重叠的 500 被质押且**无法在压力窗口内解锁**、300 为低流动性资产且压力变现率为 40%；其他资产可全额动用。求该窗口可变现资产和覆盖率。
2. 为什么“签名证明平台控制某个地址”仍不能证明客户拥有该地址资产的优先受偿权？
3. 一个只给出 Merkle Root、不公开负债总额的报告，用户最多能验证什么？

**答案**：1. 可变现资产为 \(1,200-500-300+300\times40\%=520\)，覆盖率为 52%；还需进一步扣除质押解锁和法律争议。2. 因为控制权、受益所有权、客户协议和破产法上的债权顺位是不同层次。3. 只能验证某个被提供的叶子路径是否属于该 Root，不能验证所有负债是否被纳入，也不能验证总额。
