## 0. 方法论：每个主题必须回答的五问

这套书的每一章都按同一套五问展开，缺一问都不算讲透：

```
① 到底是什么    给出精确定义 + 反例（什么不是幂等、什么不是最终一致）
② 为什么需要    不做会怎样？用事故形态和金额/条数说话
③ 怎么实现      3~5 种方案对比：原理、成本、适用边界、代码
④ 会在哪炸      失效模式清单（并发窗口、超时边界、框架陷阱、跨库不同步…）
⑤ 怎么验证      如何测试（并发压测/故障注入/对账核对）+ 如何观测（指标/日志/告警）
⑥ 用什么工具    开源组件与自研边界：Sentinel/Seata/Temporal/Redis/Outbox/…
```

**反冗余公约**：一个机制只在一章深挖；其它章只给结论 + `详见第 N 章`。

## 1. 全书骨架：三层防线

任何生产系统的可靠性都可以拆成三层，**从上往下任何一层缺了，事故都会向下穿透**：

```
┌──────────────────────────────────────────────────────────────┐
│ 第一层  正确性 Correctness                                    │
│ 幂等 · 事务 · 一致性 · 对账        ← 「账不能错、单不能重」    │
│ 缺了它：出错就是资金损失与法律风险，且往往事后才发现          │
├──────────────────────────────────────────────────────────────┤
│ 第二层  韧性 Resilience                                       │
│ 限流 · 熔断 · 降级 · 压测 · 容量   ← 「流量来了不崩」          │
│ 缺了它：高峰期整体不可用，恢复时间不可控                      │
├──────────────────────────────────────────────────────────────┤
│ 第三层  可运营性 Operability                                  │
│ 监控 · 告警 · 运维 · 运营 · 排障   ← 「出事 5 分钟能定位」     │
│ 缺了它：同样的故障反复发生，客户比你先知道                     │
└──────────────────────────────────────────────────────────────┘
        ↑ 贯穿三层：异步与消息（解耦与最终一致）· 存储（状态的落点）
        ↑ 横切能力：编排与状态机（谁在推进流程）· 选型方法论（用什么造）
```

**三条铁律**（全书反复回到它）：

1. **幂等不解决一致性，只解决重复**。真正的端到端正确性 = 幂等 + 对账。
2. **限流不是「挡住请求」，而是「保住系统里更重要的部分」**——挡错了比不挡更糟。
3. **运维解决「服务活着」，运营解决「客户满意」**；混在一起做的团队，两边都做不好。
