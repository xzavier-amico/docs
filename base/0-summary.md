# 《计算机系统基座：从 bit 到内核到协议栈》· 总纲

> **一句话**：这一套不解释「进程是什么」「TCP 为什么三次握手」这类**你已经背过的定义**，而是把每个定义按回物理层问一句「**不这样会怎样**」——于是概念重新变成推论，你不再需要记，只需要推。
>
> **读者画像**：大学修过操作系统 / 计算机网络 / 计算机组成原理，考试能过、八股能背；但被追问「缺页发生时 CPU 到底在干嘛」「TIME_WAIT 多到底要不要调」「GPU 为什么显存大而主频低」「`malloc(100)` 到底向内核要了内存吗」「`write()` 返回成功是不是就落盘了」时，只剩「就是那样的」。
>
> **阅读目标**：把「慢、丢、崩、泄漏」转成可以检验的跨层假设，再选择适合当前环境的工具取证。工具看得见什么、看不见什么，与读数同样重要。

## 0.1 这套书要解决的那个问题：三层「会背不会推」

```
「TIME_WAIT 太多，调小 tcp_tw_reuse」  → 不知道 TIME_WAIT 是主动关闭方对「旧包还能活多久」的估算，调它等于赌网络上没有迟到包
「内存不够加 swap / 调 JVM 堆」        → 不知道虚拟内存是「页表 + 缺页」维持的幻觉，也不知道 malloc 大多数时候根本没找内核
「GPU 主频低但显存大，所以适合 AI」     → 不知道 GPU 是把控制逻辑换成并行度的机器，也不知道瓶颈常常是显存带宽而不是算力
```

三句话对应三种断层：**只记住了结论，不知道结论由哪条物理约束推出来**。

而 `go/`、`comp/`、`eng/`、`architect/` 这几套都是在**这个断层之上**盖的楼。楼越高，地基上那道裂缝越致命——**你无法判断「这条最佳实践在我的场景还成不成立」，因为你不知道它当初在防什么**。

**所以本套只干一件事：把「现代计算机」这台机器从晶体管一路拆到 TLS 证书，每一层都给出三样东西——它承诺什么、它为此付了什么钱、它什么时候失效。** 而「实例剖析」11 篇就是这一整套的**验伪出口**：能不能用一条命令把上面的话量出来，是「懂」与「背过」的唯一分界。

## 0.2 四条贯穿全书的主线（不是点缀，是判据）

| 主线 | 一句话 | 用它能一眼解释掉的东西 |
| --- | --- | --- |
| **① 没有魔法，只有位与约定** | 从晶体管到 TLS，全部是「同一批字节 + 一套约定」，约定在哪一层，责任就在哪一层 | 补码 / 大小端 / 对齐 / 编码 / 序列化 / TCP 头部 / TLS 证书链 |
| **② 先分服务时间与等待时间** | 同一个延迟值可能来自处理慢、排队、重试或跨层往返；先量区间，再找瓶颈 | 软中断 / 网卡队列 / socket 缓冲区 / 锁等待 / runqueue |
| **③ 每层抽象的单价 = 跨界次数 × 单次成本** | 系统调用的价、缺页的价、上下文切换的价、网络 RTT 的价，都是固定量级，架构设计就是在买这些单 | `read` 一次 1 字节 / `mmap` / 零拷贝 / epoll 批量 / 用户态协议栈 / batch 化 |
| **④ 安全要按层核对** | 分别问认证、完整性、机密性由谁提供、覆盖哪一段，以及该层不保证什么。可用性和业务授权另算 | 基础 ARP 不提供密码学身份；DNSSEC 验证签名数据的来源与完整性，不加密；DoH 用 HTTPS 保护客户端到解析器的一跳，不代替 DNSSEC |

> 全篇反复回到这四条。凡是不能用它们解释的「优化经验」和「安全实践」，基本是过时的。**11 篇实例剖析每篇必须写出「本篇量到的是哪条主线」；每个协议篇必须写出「这个协议天生缺哪一样」（主线④）。**

### Part I · 计算的物理真相（8 篇）

| 编号 | 标题 | 唯一真问题 |
| --- | --- | --- |
| 02 | bit 是什么：从晶体管到「一个字节为什么是 8 位」 | 二进制不是数学选择而是**器件选择**：两个稳定电平最便宜；补码、掩码、位运算全是这条事实的推论 |
| 03 | 补码与 mod 2ⁿ：减法为什么可以白送 | 补码不是「取反加一」的口诀，而是**在 mod 2ⁿ 环里 `-x ≡ 2ⁿ-x`**；溢出、无符号比较、类型提升三大坑都长在这里 |
| 04 | 整数运算陷阱：位宽、移位、溢出与隐式转换 | 每次整数运算都是**在固定位宽上做模运算**——「值」与「位模式」必须分开看，C/Java/Go 的差异全是「谁在何时扩宽或截断」 |
| 05 | 浮点数：IEEE 754 的字段分配与「0.1+0.2≠0.3」 | 浮点是**科学计数法的硬件定点版**，精度由「尾数几位」预先决定；相等比较、累加顺序、大数吃小数都不是 bug 是数学 |
| 06 | 字节序、编码与序列化：多字节的「数」本身就是约定 | 内存里只有字节，**跨字节的一切含义都是约定**；大小端、对齐 padding、UTF-8、网络字节序、序列化协议是同一件事的不同层 |
| 07 | 存储层次与延迟量级：程序为什么慢 | 快慢不取决于代码好不好看，取决于**数据在第几层 + 有没有连续**；cache line、局部性、预取、NUMA 就是这一层的全部物理约束 |
| 08 | 器件物理：DRAM 刷新、SSD 擦除块与写放大、HDD 寻道 | 页大小、`fsync`、随机写惩罚、日志结构，都是**器件约束翻译出来的设计**；不懂擦除块就永远不懂为什么随机写慢两个数量级 |
| ◆09 | 实例剖析：一次「表示层」事故复盘——浮点、编码、对齐 | 这三类事故的共同形态是**「你看到的值」和「机器里的位」不是一回事**；复盘一遍，05/06 的所有推论都变成可复现的红字 |

### Part II · CPU 与 GPU：算力的物理形状（11 篇）

| 编号 | 标题 | 唯一真问题 |
| --- | --- | --- |
| 10 | CPU 的执行环：时钟、流水线、超标量、乱序与分支预测 | CPU 不是「一条条执行指令」，是**一条流水线上同时飞着几十条**；分支预测错、数据依赖、乱序窗口解释了几乎所有「莫名其妙变慢」 |
| 11 | 指令集、寄存器与调用约定：x86 vs ARM | 指令集是**硬件与编译器的合同**；寄存器数量与调用约定决定了函数调用开销、递归深度上限与 ABI 兼容 |
| 12 | 读汇编：一个函数调用在机器码里到底长什么样 | 只要会读 `mov/cmp/jne/call/ret` 与栈帧，**语言里的概念就全部落地成地址与偏移**；这是全书的验伪器 |
| 13 | 缓存与缓存一致性：组相联、MESI、false sharing 与内存屏障 | 多核**并不共享内存**，只有一堆各自缓存 + 一套协议在假装共享；所有可见性、重排、伪共享问题都从这里出生 |
| 14 | 总线、DMA、中断与 MMIO：数据怎么在设备与内存之间搬 | CPU 最贵的资源不是算力是**搬数据的次数**；DMA、零拷贝、批处理全都在减少「CPU 碰数据」的次数 |
| 15 | 特权级与虚拟化：ring、微内核 vs 宏内核、VM vs 容器 | 隔离不是「软件上禁止」，是**硬件权限级 + 页表**；微内核之争、容器之争，本质是「隔离边界画在哪层、每次跨界付多少钱」 |
| 16 | GPU 的物理结构：SIMT、warp、SM 与显存层级 | GPU 是**用控制逻辑换并行度**的机器：一个取指单元带 32/64 条通道，于是它只能跑「同一段代码处理不同数据」 |
| 17 | 显存、浮点与 roofline：为什么 GPU 显存大而主频低 | 功耗 ∝ f·V² 且散热有上限，所以**提频最贵、堆核最便宜**；GPU 选「低频 × 海量核 × 高带宽」，于是它「算得快」常常是「等得少」 |
| 18 | CPU vs GPU：判据只有一条，以及它推出来的所有场景 | 唯一判据：**同一段代码是否作用于成千上万份互相独立的数据**；由此推出图形/矩阵/推理去 GPU，事务/分支密集/低延迟留 CPU |
| ◆19 | 实例剖析：RingBuffer——缓存行、伪共享与屏障的物理账 | 它能到千万级 TPS 不是因为「无锁」这个标签，而是**指针天然落在预取得到的位置、每个写者独占一条 cache line**；去掉 padding 立刻掉一个数量级 |
| ◆20 | 实例剖析：GEMM 优化阶梯——从 memcpy 到张量核 | 每一级优化都在做同一件事——**减少「数据在层与层之间搬一次」**；于是分块、向量化、多线程、张量核、上 GPU 是同一条推论的五个台阶 |

### Part III · 操作系统：Linux 视角（17 篇）

| 编号 | 标题 | 唯一真问题 |
| --- | --- | --- |
| 21 | 内核与两种态：一次系统调用的全过程 | 内核不是「更底层的库」，是**另一个特权级里的一套代码**；每次跨界有固定成本，这决定了 API 为什么长成批处理 / `mmap` / `io_uring` |
| 22 | 从源码到进程：编译、链接、ELF、装载与地址空间 | `./a.out` 不是「运行一个文件」，是**内核把一个 ELF 映射进新地址空间再跳到入口**；动态链接、`PLT/GOT`、ASLR 都长在这个动作上 |
| 23 | 进程：`task_struct`、`fork` / COW 与状态机 | 进程 = **地址空间 + 一堆内核簿记**；`fork` 便宜是因为 COW；僵尸是「死后没人收尸」而不是「没死」 |
| 24 | 线程与调度单元：`clone`、用户态线程与协程 | Linux 里线程与进程是**同一个东西的不同参数组合**（共享哪些资源）；「协程快」不是因为名字，是因为把切换从内核挪到了用户态 |
| 25 | CPU 调度：CFS→EEVDF、nice、亲和性与 cgroup 配额 | 调度器只在**「要跑的比核多」**时才存在；nice 是权重不是优先级；`load average` 是排队长度不是 CPU 使用率 |
| 26 | 虚拟内存与页表：缺页时 CPU 到底在干什么 | 每个进程的「独占内存」是**页表 + 缺页中断**维持的幻觉；三类缺页决定了你的程序是「慢」还是「炸」 |
| 27 | 内存分配与 mmap：`malloc` 究竟做了什么、RSS 为什么不降 | `malloc(100)` 大概率**没向内核要内存**；brk vs mmap、arena、page cache、OOM killer 才是「内存去哪了」的答案 |
| 28 | 文件系统与「一切皆文件」：inode、dentry、fd 与 VFS | 文件不是内容，是**一个 inode + 目录里的一条名字映射**；「一切皆文件」是「一切都能 read/write/ioctl」的接口统一，不是「一切都是磁盘文件」 |
| 29 | 落盘与崩溃：ext4 日志、页缓存回写与 fsync 的三层谎 | `write()` 成功只代表**数据进了页缓存**；「提交成功」到「数据在盘上」之间隔着页缓存、日志、磁盘写缓存三层谎 |
| 30 | IPC 与内核同步原语：管道、共享内存、信号与 futex | 进程之间不共享内存，共享的是**同一段被映射进来的物理页**；锁在无竞争时不进内核，靠的是 futex「先自旋、打不过再找内核」 |
| 31 | IO 模型全景：阻塞/非阻塞、select/poll/epoll、ET/LT 与 io_uring | 所谓「异步」只是**「谁来等」**的问题；epoll 快不在读得更快，而在**一次问一万个 fd 谁就绪**，免掉一万次系统调用 |
| 32 | socket 与收包全路径：硬中断、软中断、NAPI、缓冲区与零拷贝 | 一次收包要穿过**网卡→硬中断→软中断→协议栈→socket 缓冲区→唤醒进程**六道门；带宽上不去几乎总是「某一层队列满了」 |
| 33 | 操作系统安全与攻防：权限位、缓冲区溢出、ASLR、seccomp 与逃逸 | 内核安全只有三根柱子——**权限模型、地址空间隔离、代码完整性**；每一次提权或逃逸，都是其中一根被绕过 |
| ◆34 | 实例剖析：手搓一个容器——`unshare` + `cgroup` + `pivot_root` | 容器不是轻量虚拟机，是**三个内核功能的组合**：命名空间（看得见什么）、cgroup（能用多少）、根切换（以为自己在哪）；没有新内核魔法，所以隔离强度也就那样 |
| ◆35 | 实例剖析：内存账本现场——RSS 只涨不降，到底涨在哪 | 内存问题的答案永远在**「谁持有」而不是「谁分配」**；`pmap`/`smaps`/`proc` 三本账能把泄漏、碎片、页缓存、巨页四件事彻底分开 |
| ◆36 | 实例剖析：epoll 与 io_uring 的 syscall 账 | 用本地回声演示逐条与合批的调用计数；区分就绪、完成、系统调用和调度次数，不用调用数外推吞吐 |
| ◆37 | 实例剖析：零拷贝四实现——`read/write`、`mmap`、`sendfile`、`splice` | 四种实现功能一模一样，**差的是「数据被拷了几次、上下文切了几次」**；`strace -c` 与 `perf` 把差距摆在同一个屏幕上 |

### Part IV · 网络：从一根网线到一张证书（15 篇）

| 编号 | 标题 | 唯一真问题 |
| --- | --- | --- |
| 38 | 分层：为什么是四层，每层的头部在替谁擦屁股 | 分层不为好看，是为了**把不可靠的物理信道逐层包装成可用抽象**；每层头部就是它替下层补的窟窿 |
| 39 | 链路层：MAC、ARP、交换机、VLAN 与 MTU/分片 | IP 路由选下一跳，ARP 解析链路地址，交换转发查 MAC 和 VLAN；用包长与反馈证据判断路径 MTU |
| 40 | IP 与路由：头部位图、CIDR、NAT、转发与 ICMP | IP 只承诺一件事——**尽力而为地送到某个地址**；不保顺序不保到达，所以「可靠」必须由上层自己补 |
| 41 | TCP 建立与关闭：三次握手、状态机与 TIME_WAIT | 三次不是为了「两次确认不够」，而是**双方都要确认对方收发能力并同步序列号**；TIME_WAIT 是主动关闭方的义务，不是待调参数 |
| 42 | TCP 可靠与拥塞：重传、SACK、滑动窗口与拥塞控制 | TCP 同时被两个上限卡死——**接收窗口（流量控制）与拥塞窗口（拥塞控制）**；延迟与吞吐的取舍全在这两个数字的博弈里 |
| 43 | UDP 与 QUIC：为什么要在用户态重造一个 TCP | QUIC 不是「更快的 UDP」，而是**把 TCP 的队头阻塞与内核僵化一起解决**：用户态拥塞控制、流级多路复用、连接迁移、0-RTT |
| 44 | DNS 协议剖析：12 字节头部、递归 vs 迭代、TTL 缓存与 EDNS | DNS 的**全部语义都写在那 12 字节头部和十几种记录里**；它是带 TTL 的全球最终一致数据库，所以「改了不生效」不是故障是设计 |
| 45 | DNS 安全剖析：一个三缺协议怎么被攻击、又怎么被补 | 区分查询匹配、签名数据验证与加密解析；解释缓存、解析策略和应用授权的防御边界 |
| 46 | HTTP 三代：1.1 → 2 → 3，每次都在解决同一个队头阻塞 | HTTP 每次升级都在解**同一个队头阻塞**：连接复用 → 流复用 → 丢包级复用；帧、HPACK、推送的失败都是这个目标的副作用 |
| 47 | TLS 与证书：密钥交换、证书链、SNI、1-RTT 与「为什么还是会被抓包」 | TLS 可以保护记录并认证预期对端；校验不到正确对端时，加密记录本身不能排除主动中间人 |
| 48 | 网络攻防与应用层认证：一张「缺失的认证」总表 | 常见 HTTPS 校验服务器；mTLS 可认证客户端证书主体，应用层还需用户认证、资源授权与防重放。区分 OAuth2、OIDC、JWT 和会话的职责 |
| ◆49 | 实例剖析：VLESS + Reality + Vision——加密边界与字节流 | 分开两段连接的信任、记录层重组和代理封装的开销；机制推演不等于实现实测 |
| ◆50 | 实例剖析：TLS 1.3 + HTTP/2，从握手消息到 DATA 帧 | 本地 `MemoryBIO` 实测 TLS 记录和 HTTP/2 帧，区分端点明文与被动观察；不把内存中的记录当作抓包 |
| ◆51 | 实例剖析：`tc netem` 注入 1% 丢包——CUBIC 与 BBR 的分道扬镳 | 对照指定实验条件下的吞吐与 RTT；结果不是固定倍率，解释时要考虑算法版本、队列、反馈和竞争流 |
| ◆52 | 实例剖析：手工解析与重组——手写 DNS/IP/TCP/UDP 头、分片与粘包 | 协议解析器是最诚实的老师：**错一个位域、漏一次重组，数据就是错的**；写完它，大小端、位域与字节序才算真的会 |

## 0.7 每篇固定骨架（写作公约）

**机制篇**

```
① 反直觉开头   一句「你以为……其实……」，配一个真实故障或一段真实命令输出
② 物理事实     图（ASCII）+ 尺寸 + 量级；只写能推算的部分，不写「大概很快」
③ 一次完整路径  从一次调用/一个包/一条指令出发，逐跳走完，每跳标成本（ns/μs/ms/RTT）
④ 三列账       承诺了什么 / 为此付了什么 / 从哪里开始失效
⑤ 跨层连接     这条机制在 go/ llm/ comp/ 里长成什么样（锚点引用，不重写）
⑥ 踩坑清单     现象 → 根因（指回物理事实）→ 怎么定位（命令）→ 怎么修 → 怎么防复发
⑦ 一页速记 + 自检 3 题（含答案要点）+ 延伸阅读
```

**实例篇** = §0.6.5 的五问 + 机制篇的 ⑥⑦（踩坑清单与速记）。

**纪律（违反即返工）**

1. **可复现**：每篇至少一个能贴真实输出的实验（`objdump -d` / `perf stat` / `strace -T` / `tcpdump -i any` / `openssl s_client` / `bpftrace` / `tc` 之一）。
2. **数字要有出生证明**：量级必须能推导（如「一次 L3 命中 ≈ 40 cycle ≈ 13 ns @3 GHz」），禁止「很快 / 大量 / 一般」；算例末尾标明是**量级结论**还是**承诺值**。
3. **不背定义**：凡是能背到的东西，只出现在「它由哪条物理约束推出」的句子里；单个定义不许单独成段。
4. **代码纪律**：单段 ≤ 40 行，C 为主、Go/Java 只做对照；不贴内核源码全文，最多贴结构体字段与一行关键判断。
5. **锚点冻结**：跨集引用写 `→ go/19`、`→ comp/49`，禁写「上文」「前一篇」；编号一旦发布不改。
6. **实例篇只贴自己跑出来的输出**，不抄博客截图；跑不出来就换案例，不许编。
7. **协议篇必带「三缺表」**：每个协议篇（39–47）结尾必须有一行——**认证 / 完整性 / 机密性，缺哪一样**，并指向 48 篇的总表。这一行写不出来，说明该篇没讲透。
8. **无占位**：`TODO`、「待补充」、「此处省略」不许进仓库（`check.sh` 会拦）。

## 0.9 明确不写什么（防膨胀纪律）

- Go runtime 源码（`g`/`p`/`m`、GC、channel）→ `go/17`–`go/28`，本套只讲**它依赖的 OS 原语**。
- 组件内核（InnoDB 页、WAL、Kafka 段、ES 倒排、vLLM PagedAttention）→ `comp/`，本套只讲**页缓存 / inode / 零拷贝这些公共底座**。
- 分布式共识、注册中心、消息语义、限流算法 → `comp/37`、`eng/15`–`eng/28`。
- 平台治理（路由、配额、计费、沙箱档位、多租户）→ `llm/`。
- 系统形态与容量换挡 → `architect/`。
- 数字电路 / 组成原理课的计算题（卡诺图、触发器时序、Cache 映射算地址位数）→ 只保留「能解释工程现象」的那一小块。
- x86 / ARM 指令手册式罗列、汇编语法大全 → 只讲 12 篇里读函数所需的那 20 条指令。
- Linux 命令大全、Shell 脚本、运维手册 → 只在排障篇按「查哪一层」列命令。
- 容器编排（K8s 调度器、Operator）、eBPF 全谱 → `go/52`，本套只在 15 / 54 篇给一刀。
- 前端渲染、浏览器内核、图形学管线 → 53 篇只给链路位置，不展开。
- 密码学数学推导（椭圆曲线、格）→ 47 篇只给「它保证了什么、怎么被用错」。
- **◆49 篇的边界**：讨论信任模型、加密与重组、可观测性的局限，不写部署、绕过检测或改变流量特征的操作。
- DNS 篇不写「域名注册 / 备案 / CDN 厂商选型」→ 44 篇只讲协议与缓存，45 篇只讲信任模型与攻击面。
- 合规与等保、渗透测试流程与工具教程 → 33 / 48 篇只给机制层。

| Redis / Nginx 单线程为什么够快 | 事件循环 + 内存 + 无锁批处理 | 与 `comp/12`、`comp/39` 重叠 |
