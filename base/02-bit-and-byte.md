## 02.1 引子：同一段 4 字节，四种真相

一份网关的「重试风暴」复盘文档里，最刺眼的是这一行日志：

```
2025-04-11T03:12:44Z WARN retry_gate client_ip=… retry_after=1078530011s
```

`1078530011` 秒 ≈ **34.2 年**（1078530011 / 86400 / 365.25 = 34.19）。客户端把这个值直接灌进定时器，这条连接 34 年内不会重试；而退避算法本来只想让它等 **3.14 秒**，容量是按「每 3 秒退避一次」估的，于是同一时刻被判「可重试」的请求在 30 秒内积到 4.1 万条，全部打到已经半死的下游。

根因一行就能说清：上游算出的退避是一个 `float`，值 `3.14159`；它被 `memcpy` 进一个 4 字节字段发出去，而下游 protobuf 把这个字段声明成了 `int32`。**这 32 个 bit 一个都没坏**，坏的是「谁来解释它们」。

把这段位 `0x40490FDB` 在本机用四种方式读出来（代码见 §02.8，以下是真实输出）：

| 读法（类型） | 得到什么 | 判词 |
| --- | --- | --- |
| 位模式本身 | `0x40490FDB` | 唯一的事实，没有语义 |
| `uint32_t` | `1078530011` | 位对，语义错：因为值 < 2³¹，与 `int32_t` 读数相同 |
| `int32_t` | `1078530011` | 位对，语义错：它在补码里没有变成负数，所以**不会报错、不会崩，只会安静地错** |
| `float` | `3.141592741`（`%a` → `0x1.921fb6p+1`） | 唯一正确的解释，多出来的 0.0000027 是 binary32 的固有精度 |
| `unsigned char[4]` | `DB 0F 49 40` | 位对，但顺序是小端约定：先吐低位字节 |
| UTF-8 文本 | `UnicodeDecodeError: invalid continuation byte` | 这 4 个字节根本不是合法 UTF-8：`0xDB` 是双字节首字节，`0x0F` 不是合法续字节 |
| 指针低半 | 一个地址的低 32 位，高 32 位丢失 | 直接是野指针 |

**这就是本篇要拆穿的两件事。**

第一件，反直觉：**机器里没有「十进制」，也没有「三进制」，更没有「类型」。** 一颗 5 nm 的 CPU 里没有「数」这个东西，只有一堆只有两个稳定状态的器件；`int`、`float`、`string`、`utf-8` 全部活在编译器、ABI 和你的 `printf` 格式符里。位模式是物理事实，类型是**约定**——所以「值不对」这类事故，99% 的定位动作应该是先问「谁有解释权」，而不是先怀疑数据传坏了。

第二件，更反直觉：**为什么偏偏是二进制？** 如果一进制信息密度是 1 bit/线，三进制就是 log₂3 = 1.585 bit/线，理论上「更省线」；十进制（ENIAC 真的用过）在账面上更贴近人类。但这三种方案在 1943–1958 年都被造出来了，最后活下来的只有最「浪费」的那一种。§02.5 会用噪声容限把它算清楚：**在器件层，「可靠 + 便宜」永远压过「信息密度」**——这条判据在本套书里会以各种形态重演（SSD 的 SLC/MLC、GPU 的低频多核、协议的冗余校验）。

## 02.2 一句话定位与唯一真问题

> **二进制不是数学选择，是器件选择：两个稳定电平最便宜；补码、掩码、位运算、字节、对齐，全是这条物理事实的推论。**

把它拆成一条可检查的推论链，本篇就是逐段把箭头补上：

```
   器件只有"通/断"两个稳定态（成本最低）
        │
        ├─► 一位 = 一根线上的两个电平 ─────────────► 为什么不是三进制（§02.5）
        │        │
        │        └─► 噪声容限 = 电平之间的距离 ÷ 噪声幅度 → 位数越多，裕量越薄
        │
        ├─► 门（与/或/非）→ 半加器 → 全加器 → 进位链 ──► 加法的单价（§02.3–02.4）
        │
        ├─► 8 位一捆（够用 + 有校验位 + 2 的幂）─────► 字节与寻址（§02.6）
        │        │
        │        └─► 2 的幂 → 乘法变移位 → 掩码/对齐/页内偏移全是走线（§02.7）
        │
        └─► 位宽固定，语义外置 ────────────────────► 类型只是解释函数（§02.8）
                 │
                 └─► 崩点：越界 / 错解释 / 字节序（§02.9）
```

这条链为什么值得背下来：它把「补码、掩码、对齐、字节序、类型转换」这五组你分别背过的知识点，压成了同一个事实的五个切面。**面试里被追问「为什么用补码」，答案不在数学里，在本篇 §02.3 的电压走廊里**（补码让加法器不用区分符号位，因为它就是 mod 2ⁿ 的天然坐标系——细节推演在 `base/03`）。

## 02.3 从器件到逻辑：两个电平、一条走廊、一道再生

### 一个开关：MOSFET 的三根线

MOSFET 是四端器件（栅 G、源 S、漏 D、衬底 B），工程上只用三根：**栅极电压控制「源–漏之间有没有沟道」**。nMOS 栅压高于阈值（约 0.3–0.4 V）时沟道形成、导通；低于阈值时关断。pMOS 反过来。它不是一个理想的机械开关：导通时有电阻（决定充放电速度），关断时有漏电（决定静态功耗），切换过程中有一段「既不算通也不算断」的区间（决定延迟与短路功耗）。**数字电路的全部设计，都是在绕着这三件事做交易。**

### CMOS 反相器：为什么「停在 0 或 1」是免费的

```
             Vdd (例如 0.75 V)
              │
         ┌────┴────┐
         │  pMOS   │  ← 输入低时导通，把输出拉到 Vdd
         └────┬────┘
   in ────┬───┤
          │   ├─────────── out
         ┌┴───┴────┐
         │  nMOS   │  ← 输入高时导通，把输出拉到 0
         └────┬────┘
              │
             GND
```

关键点只有一句：**输入是 0 或 1 时，两个管子恰好一个通一个断，Vdd 到 GND 之间没有直流通路**，静态电流只剩 nA 级的漏电。只有输入在中间、或者输出正在翻转时，才有一条电流给负载电容充放电——这部分能量 `E = C·Vdd²` 每次翻转结结实实付一次。

一个可算的账（**量级算例**，假设扇出 1 的负载电容 1 fF、Vdd = 0.75 V）：单次翻转 ≈ 1 fF × 0.75² V² ≈ **0.56 fJ**。一颗大核每 cycle 实际翻转的有效电容在 0.3–1 nF 量级，代入得每 cycle 约 0.1–0.5 nJ，@3.5 GHz 就是 **0.4–1.8 W/核**——这就是「功耗 ∝ f·V²·C」这张老脸的真身。它顺手解释了两件事：① 位宽翻倍，参与翻转的电容近似翻倍，所以 64 位 ALU 比 8 位 ALU 贵得多（`base/17` 会用它推 GPU 为什么提频最贵）；② 想省电，最有效的动作不是「少算」，而是**让位不要翻转**（掩码、压缩、稀疏化）。

### 两个稳定电平与那条「不许停留」的走廊

器件造出来不是「理想 0/1」，而是**一片连续的电压**。之所以能当离散用，是因为接收端自己划了一条界线：

```
 V
 1.0 ┌────────────────────────┐  Vdd
     │   ● 逻辑 1 的合法窗     │   VOH ≥ 0.7·Vdd  ← 发送端承诺不低于此
 0.7 ├────────────────────────┤  VIH ← 接收端认 1 的最低门槛
     │                        │
     │   ▓▓ 禁止停留区 ▓▓      │   这里的一切都"不是 1 也不是 0"：
     │   （过渡 + 噪声 + 亚稳态）│   只能路过，任何试图在这里判值的设计都会失效
     │                        │
 0.3 ├────────────────────────┤  VIL ← 接收端认 0 的最高门槛
     │   ● 逻辑 0 的合法窗     │   VOL ≤ 0.3·Vdd  ← 发送端承诺不高于此
 0.0 └────────────────────────┘  GND
```

两个数字决定了整个数字世界的可靠性：

- **噪声容限（noise margin）= VIL − VOL = VIH − VOH**。上例中两侧各 0.3 V，即「叠加在信号上的干扰只要不到 0.3 V，逻辑值就不会被读错」。
- **再生（regeneration）**：反相器的小信号增益 > 1，所以任何落在合法窗内的偏差，经过下一级都会被**推回轨道**。这意味着**噪声不跨级累积**：级联 100 级反相器，第 100 级的电平仍然干净；而模拟链路级联 100 级，信噪比就掉 100 次。

> 这一条是「位可以复制、可以纠错、可以沿着一条烂线传很远」的全部物理根据。你之所以能 `cp` 一个文件 10 次得到完全相同的结果，是因为每一级都在**重新量化**，而不是在搬运一个连续量。模拟信号没有这个特权——这也是为什么「录音翻录 10 次就废，文件拷贝 10 次无损」。

反向的代价出现在**采样时刻**：如果时钟沿恰好采在禁止停留区里，触发器会进入**亚稳态**——输出既不是 0 也不是 1，出口时间不确定。这就是跨时钟域必须打两拍、异步 FIFO 必须用格雷码的物理原因（工程解法在 `base/13`）。**「离散」不是免费的，它要求你在时间上也买一份保险**：时钟周期必须大于最坏路径延迟 + 建立/保持时间余量。

### 三种门、四种更基本的门

| 门 | 布尔式 | 静态 CMOS 晶体管数 | 物理行为 | 工程味道 |
| --- | --- | --- | --- | --- |
| 非 NOT | `~a` | 2 | 一个 pMOS + 一个 nMOS | 唯一「免费」的门：它同时是放大器 |
| 与非 NAND | `~(a&b)` | 4 | 2 串 nMOS + 2 并 pMOS | CMOS 的**原生**门，面积最省 |
| 或非 NOR | `~(a\|b)` | 4 | 2 并 nMOS + 2 串 pMOS | 管数相同但**更慢更占面积**：pMOS 靠空穴导电，迁移率约为电子的 1/2–1/3，必须加宽补偿 |
| 与 / 或 | `a&b` / `a\|b` | 6 | NAND / NOR 再串一个反相器 | 「与」和「或」在硅上都是二阶公民，不是原语 |
| 异或 XOR | `a^b` | 8–12 | 传输门结构，或 4 个 NAND | 它同时是「可控反相器」，§02.7 的本体 |

两个必须记住的推论：

1. **NAND 是原语，AND 不是。** 所有标准单元库以 NAND/NOR/INV 为基元综合，因为「先与再取反」比「先与」少一级门。
2. **速度差不是玄学，是载流子。** 电子迁移率约为空穴的 2–3 倍，所以 pMOS 要做得更宽才能与 nMOS 等速；多输入的 NOR 需要把 pMOS 串联，串得越多越慢。这就是为什么教科书上的公式化到硬件上会变成「NAND 优先、NOR 慎用」——**同一个布尔式，两种物理实现，价格不同**。

## 02.4 从门到加法器：一条进位链的账

### 半加器 → 全加器

半加器只处理两个位：`s = a ^ b`（本位和），`c = a & b`（进位）。它的问题是不能接受低位送来的进位，所以不能级联。全加器多一个 `cin`：

```
      a ──┬────────────────────┐
          │                    │
          ├──►[XOR]──p─────────┼──►[XOR]──► s = a ^ b ^ cin
      b ──┘        │           │      ▲
                   │           │      │
                   └──►[AND]───┼──┐   cin
                               │  │
          a ──┬──►[AND]────────┴──┴──►[OR]──► cout = (a&b) | ((a^b)&cin)
          b ──┘
```

三个公式，一句人话：**`p = a^b` 表示「这一位会不会传播进位」，`a&b` 表示「这一位会不会自己产生进位」，`cout = generate | (propagate & cin)`。** 静态 CMOS 全加器约 28 个晶体管——把这个数字记住，下面要用它算一笔「晶体管根本不值钱」的账。

### 8 位加法器：进位链就是关键路径

```
 c0=0
  │
  ▼
┌──────┐ c1  ┌──────┐ c2        c7  ┌──────┐ c8 ──► 无符号溢出位（CF），有符号溢出看 c7^c8
│ FA0  │────►│ FA1  │──► … ────►────►│ FA7  │────►
│      │     │      │                │      │
└──┬───┘     └──┬───┘                └──┬───┘
   │s0          │s1                    │s7        ← 结果位
  a0 b0        a1 b1                  a7 b7
```

关键路径只有一条：**`c0 → cout(FA0) → cout(FA1) → … → cout(FA7)`**。每一位的进位都是「一次 AND + 一次 OR」（假设 `p`、`g` 已并行算好），所以：

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 单门延迟 @5 nm | ≈ 10 ps | 扇出 4 的典型值，工艺不同可差 2 倍 |
| 每位进位传递 | 2 个门 = 20 ps | `cout` 从 `cin` 出发只走 AND→OR |
| 8 位进位链 | 2 + 8×2 = **18 个门 ≈ 180 ps** | 另加输入端的 `p/g` 生成 |
| 3 GHz 的时钟周期 | 333 ps | 单位换算：1/3×10⁹ |
| 64 位进位链 | 2 + 64×2 = **130 个门 ≈ 1.3 ns** | 约为周期上限的 **3.9 倍** |
| 晶体管总数（8 位） | 8 × 28 = **224 个** | 对比：一颗 5 nm 芯片约 10¹¹ 个晶体管 |

这张表推出三个工程结论：

1. **「位」的宽度在硬件上是被延迟卡住的，不是被晶体管卡住的。** 224 个晶体管在一颗 10¹¹ 管的芯片里是可以忽略的噪声，但 180 ps 的串行进位链不能忽略。
2. **8 位加法在 3 GHz 里塞得下（180 < 333 ps），64 位塞不下（1300 > 333 ps）。** 所以现代 64 位 ALU 不会用行波进位，而是用超前进位 / 前缀树（Kogge-Stone 把链变成 log₂64 = 6 级），用面积换延迟——**这正是「位宽 × 1 个 cycle = 面积换来的」这句话的物理含义**。
3. 由此可以预判一条纪律：**加法几乎免费（1 cycle），乘法要 3–5 cycle（部分积阵列 + 压缩树），除法要几十 cycle（迭代）**。所以工程上「用移位和加法替代乘除」「用掩码替代除余」不是微优化洁癖，是在买这条链的价格差（`base/04` 会给出常量的除法如何被编译器改写成乘法）。

### 实验：手写的进位链 ≠ 机器里的进位链

写一个只用 `&`、`^`、`<<` 的加法器（`/tmp/b02/adder.c`，`gcc -O2 -c adder.c && objdump -d --no-show-raw-insn -M intel adder.o`）：

```c
uint32_t add_bits(uint32_t a, uint32_t b) {
    while (b != 0) {
        uint32_t carry = a & b;      /* 与门：两个 1 才进位 */
        a ^= b;                      /* 异或门：本位和 */
        b = carry << 1;              /* 交叉走线：进位左移一位 */
    }
    return a;
}
```

真实反汇编（节选）：

```
0000000000000000 <add_bits>:
   0:	mov    eax,edi
   2:	test   esi,esi
   4:	je     1c <add_bits+0x1c>
  10:	mov    edx,eax          ← 循环体：每一圈 = 进位链的一级
  12:	xor    eax,esi
  14:	and    edx,esi
  16:	mov    esi,edx
  18:	add    esi,esi          ← carry << 1 被编译成 add（左移一位 = 自己加自己）
  1a:	jne    10 <add_bits+0x10>
  1c:	ret
```

`-O2` **没有**把它识别成加法：它老老实实是一个最多跑 32 圈的循环，每圈一次 `xor` + `and` + 分支。对比一下真实加法：

```
0000000000000040 <plain_add>:
  40:	lea    eax,[rdi+rsi*1]     ← 连 add 都不用：地址计算单元顺手做了加法
  43:	ret
```

`a + b` 在硬件上被拆成两种形式：能塞进寻址模式的直接走 `lea`（地址生成单元 = 一个加法器阵列，顺便免费），需要落寄存器或带进位的才用 `add`。再放三个数进去（`add4`），`gcc -O2` 给出的是**两条串行 `add` + 一条 `lea`**：

```
0000000000000010 <add4>:
  10:	add    rdx,rcx
  13:	add    rdx,rsi
  16:	lea    rax,[rdx+rdi*1]
  1a:	ret
```

> **这张反汇编就是「位宽固定」的物证**：32 位的 `xor`/`and`/`add` 各自是一条指令，硬件里各有各的进位链；你不能让一条 `add` 处理 100 位，就像你不能让 8 位加法器一次算完 64 位——**不是软件不想，是那条链上要多串 56 个门**。这就是 `base/04` 里所有「溢出」「截断」故事的地基。

## 02.5 为什么不是三进制：一条走廊容不下三个房间

### 三态的物理代价

假设供电 1.0 V 不变，要把「两个房间」改成「三个房间」，走廊立刻变窄。用一个可算的模型：每个合法电平窗至少宽 `W`（= 噪声容限），房间之间至少留宽 `G` 的禁止停留区（必须 ≥ `W`，因为过渡波形与噪声峰值都要吃这块地），n 个电平要求 `n·W + (n−1)·G ≤ Vdd`：

| 方案 | 每线比特 | 电平数 | 不等式 | 解出的噪声容限 | 阈值检测器个数 | 相对二进制 |
| --- | --- | --- | --- | --- | --- | --- |
| 二进制（NRZ） | 1.000 | 2 | 2W + G ≤ 1.0，取 G = W | **W = 0.33 V** | 1 | 基准 |
| 三进制（三态） | 1.585 | 3 | 3W + 2G ≤ 1.0，取 G = W | **W = 0.20 V**（−40%） | 2 | 信息密度 +58.5%，裕量 −40% |
| 四进制 | 2.000 | 4 | 4W + 3G ≤ 1.0，取 G = W | W = 0.14 V（−58%） | 3 | 密度 +100%，裕量 −58% |

算式本身没有争议，争议在「裕量少了 40% 意味着什么」：噪声幅度是**统计量**（电源纹波、串扰、热噪声、工艺偏差），裕量减少 40% 不是「错误率涨 40%」，而是把误码率从 `erfc` 曲线的深尾搬到了**曲线上翘的膝盖附近**——从「一千年错一次」变成「一天错几次」。**位之所以能当离散值用，全部押在裕量上；砍裕量的方案，砍掉的是「离散」这件事本身。**

三进制还额外欠三笔账：

1. **两个参考电平**。二进制只需一个判决门限（Vdd/2，一个分压就能造）；三进制要 1/3·Vdd 和 2/3·Vdd 两个**精确且随温度、电压、工艺一起漂移**的参考。参考错了，三态就变成「错位的三态」，错误率随参考误差指数上升。
2. **检测器翻倍**。每一位要两个比较器而不是一个，接收端面积和功耗同比例上涨——省下的那点线，从接收端还回去。
3. **不能复用现成的二值生态**。所有 EDA 工具、单元库、时序分析、测试方法学都是为二值建立的；三态要把整条工具链重写。**这是三进制真正的死因，而且它不是物理问题**。

### 历史：三套方案都造出来了，只剩一套活着

| 年份 | 机器 | 进制 | 结局与原因（史料值，非推导） |
| --- | --- | --- | --- |
| 1945 | ENIAC | **十进制** | 累加器用 10 个真空管的环形计数器表示一位十进制数；整机约 17,468 只电子管、150 kW、2 000 只/秒的加法速度。用十进制是为了直接对接人工计算表，代价是每个数字位要 10 个有源器件 |
| 1958 | Setun（莫斯科大学） | **平衡三进制**（−1/0/+1） | 共造出约 50 台。三进制在算术上有真实优势（对称舍入、无需符号位），单机成本据说低于同期二进制机；但无标准、无生态、无后续芯片，随项目终止而消失 |
| 1950s 起 | 几乎所有后续机器 | **二进制** | 只需要「通/断」一个判决门限；一个器件 = 一个 bit；工具链、存储器、接口全部沿二值构建 |

一条必须澄清的误解：ENIAC 用十进制**不是因为它更优，而是因为它的存储元件是十进制计数器**（环形计数器天然数十）。一旦存储从「计数环」换成「双稳态触发器」，二进制就是以「一个器件一个 bit」的绝对性价比碾压——**决策跟着器件走，不跟着数学走**。

### 唯一的反例，恰好证明了规则

多值存储真的成功过，就在你手机里：**NAND 闪存的 TLC 单元用 8 个电压电平存 3 bit/单元**。它为什么能成，而 CPU 里的三态逻辑不能成？因为它同时满足了三个条件——**慢**（一次读 40–100 µs 量级）、**有 ECC**（LDPC/BCH 把误码率按块纠回来）、**有空间做参考追踪**（读时用参考单元校准漂移）。它为此付的钱也很直白：P/E 寿命从 SLC 的 10⁵ 次量级掉到 TLC 的 10³ 次量级，写延迟和写放大同步上涨（`base/08` 会把这笔账连到 SSD 的随机写惩罚上）。

> **判据提炼**：多值 = 用「速度 + 纠错 + 校准」去买「密度」。凡是买不起这三样的地方（CPU 组合逻辑、DRAM、总线），二值永远是最终答案；凡是买得起的地方（闪存、SerDes 的 PAM-4），多值就会赢。`base/40` 讲的 PAM-4 与 `base/08` 讲的 TLC 是同一个判据的两次开花。

## 02.6 一个字节为什么是 8 位

这件事**没有任何物理必然性**，它是一串商业与技术妥协被冻结成标准的结果。把时间轴摆开，每一步的动机都清楚：

| 年份 | 事件 | 位数 | 它解决了什么 / 留下了什么 |
| --- | --- | --- | --- |
| 1870s | Baudot 电报码 | 5 | 32 个码位，字母/数字靠「换档」共享；这就是 5 位时代的遗产 |
| 1963 | ASCII（X3.2-1963） | **7** | 128 个码位：95 个可打印字符 + 33 个控制码。2⁶ = 64 装不下 95 个可打印字符（大小写 + 数字 + 标点），2⁷ = 128 刚好够 |
| 1956 | IBM Stretch 项目备忘录 | 「byte」一词 | Werner Buchholz 用它称「一次处理的位组」，最初可以是 1–6 位；原拼写 *bite*，为防手写误读成 *bit* 改成 *byte* |
| 1964 | IBM System/360 | **8** | 第一个把「字节 = 8 位、地址按字节编址」写进体系结构的主流机；字符集用 EBCDIC（8 位、256 个码位），同时留出 1 位给奇偶校验 |
| 1980s | POSIX / 各语言 | 8 | POSIX 强制 `CHAR_BIT == 8`；ISO/IEC 80000-13 定义 **octet** = 恰好 8 bit |
| 1981 | RFC 791（IPv4） | 8 | 头部图与长度字段全部以 **octet** 计数——因为「byte」在标准语境里曾经不是 8 位，telecom 只好沿用 octet |

三重合流解释了 8，而不是 7 或 9：

1. **7 位不够**：ASCII 要 7 位，但传输要 1 位奇偶校验 → 8。且 EBCDIC 这类字符集本身就要 256 个码位 → 8。
2. **9 位浪费**：2⁹ = 512 个码位，多出来的 256 个在存储和传输上全是纯浪费。**8 = 2⁸ = 256 是「装得下所有字符集」与「不浪费」的交点。**
3. **8 是 2 的幂，这一条最贵**：字节宽度若为 7，`第 i 个元素地址 = base + i*7` 需要一个真乘法器；宽度为 8 时就是 `i << 3`，**一根交叉走线**。整个「按字节编址 + 2 的幂宽度」的选择，把数组寻址、结构体布局、页内偏移全部变成了移位和掩码（§02.7）。

再往下推一层，你会看到一个精确得可怕的自相似链——**「一页 4 KB」和「虚拟地址 48 位」都是从「1 字节 = 8 位」长出来的**：

```
  1 字节 = 8 bit
      └─► 页表项（PTE）= 8 字节 = 64 bit
             └─► 一页 4096 B ÷ 8 B/项 = 512 项/页
                    └─► 索引位宽 = log₂(512) = 9 bit
                           └─► x86-64 四级页表 = 4 × 9 = 36 bit
                                  └─► 36 + 页内偏移 12 bit（4096 = 2¹²）= 48 bit 虚拟地址
```

**这不是巧合，是设计的自洽性要求**：页表项长度必须是 2 的幂、一页必须装整数个页表项、索引位宽必须正好是 log₂(项数)。改掉「8 位一字节」，这条链会在第一环就断。所以「字节 = 8 位」在工程上已经不是一个可以重新投票的选择题——它是整个地址空间的公理（细节推到 `base/26`）。

（顺带把「为什么是 4 KB 页」也定个位：4 KB 是 12 位偏移，页表项 8 字节刚好 512 项/页，而页太大则内部碎片与缺页代价上涨、页太小则页表级数与 TLB 压力上涨。这个折中在 `base/26` 详细算。）

**一个必须知道的边界**：C 标准只要求 `CHAR_BIT >= 8`，不要求恰好 8。某些 DSP 上 `char` 是 16 位甚至 32 位——所以 C 里「字节 = 8 位」是 POSIX 与所有主流 ABI 的约定，不是语言标准。写可移植代码时用 `CHAR_BIT`、`uint8_t`（若不存在说明该平台没有 8 位类型）和 `octet` 这个词，比用「byte」安全。

## 02.7 位运算的物理直觉：全是走线，全是一个门层

位运算看起来像「数学技巧」，实际上是**电路图直接画出来的形状**。记住这张对照表，以后看到任何掩码/移位代码，脑子里应该出现的是走线而不是公式：

| 运算 | 硬件形状 | 规模（32 位） | 在系统里的形态 |
| --- | --- | --- | --- |
| `<<` / `>>`（变量） | **交叉走线**：一个桶形移位器（barrel shifter）= log₂32 = **5 级 2:1 选择器**，每级 32 个 mux，共 160 个 mux、约 10³ 个晶体管 | 1 个门层深（5 级选择） | 数组下标、`i*8`、页号、对齐 |
| `&` | **与门阵列**，一位一个与门 | 32 个门，1 层 | 掩码、位图、取模（2 的幂） |
| `\|` | **或门阵列** | 32 个门，1 层 | 置标志、合并权限位 |
| `^` | **可控反相器**：一位一个「当控制位为 1 就翻转」的结构 | 32 个 XOR，1 层 | 交换、校验、加解密、`i ^= 1` |
| `~` | 反相器阵列 | 32 个门，1 层 | 清位 `x &= ~mask` |

三个可以直接落到工程上的推论：

**① 掩码 = 一个与门层，成本近乎为零。** 所以「低 12 位是页内偏移」这种设计极其自然：`offset = addr & 0xFFF`，`pfn = addr >> 12`。这两个表达式在硬件上各是一个门层 + 一段走线，和「取一个整数」同价。**把语义切成 2 的幂的位段，是唯一一种「免费的类型系统」**——网络协议头（`base/40`）、文件权限位、页表项、指令编码全部这么做。

**② 位图 = 用 1/64 的空间做「在不在」的判定。** 100 万个对象的「是否已访问」标记：用 `uint8_t` 数组要 1 MB；用位图要 10⁶/8 = **125 KB**（64 倍差）。代价是「读一个标记」要 `word = map[i>>6]; bit = (word >> (i & 63)) & 1;`——一次移位 + 一次与，仍然是 1 个门层。这正是 `fd_set`（`select` 的 1024 位 = 128 字节位图）、内存分配器的空闲页位图、`base/13` 里的 MESI 状态位、`base/30` 的 epoll 就绪位图共用的形态。

**③ 对齐 = 把一次内存访问压进一次 cache line。** 结构体里的 `padding` 不是编译器在浪费，是它在保证**每个成员都落在自身尺寸的整数倍上**，于是任何成员都只需要一次对齐的 8 字节读。实测（`/tmp/b02/align.c`，`gcc -O2`）：

```
packed_order: sizeof=12  c@0 i@4 d@8      ← 声明顺序：char, int32, char
sorted_order: sizeof=8   i@0 c@4 d@5      ← 大成员先：int32, char, char
malloc 返回 0x55bb41e472b0：低 4 位 = 0，页内偏移 = 688（页 4096 B）
```

同一份数据，**仅改声明顺序，从 12 字节变 8 字节（省 33%）**。这不是编码风格，这是每 KB 缓存、每次 DMA 传输都在付的钱（`base/26` 会把它接到「一个 cache line 是 64 B，浪费的 padding 会把有效带宽按比例吃掉」上）。

**④ 标志位 = 一个字节存 8 个布尔。** TCP 头部第 13 字节就是 8 个标志（CWR/ECE/URG/ACK/PSH/RST/SYN/FIN），IPv4 头部的第 7–8 字节是 3 位标志 + 13 位分片偏移。之所以能这么干，是因为 `& 0x02` 就是一个与门——**「用一个 bit 表示一件事」之所以成为系统设计的默认动作，是因为查询它不花钱**（`base/40`、`base/41` 会逐个用到）。

## 02.8 「类型」只是位宽 + 解释函数

### 实验：同一批 32 个 bit，四种读法

```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

union view {                 /* 四个成员共用同一块 4 字节存储 */
    uint32_t      u;         /* 解释 1：无符号整数 */
    int32_t       i;         /* 解释 2：有符号整数（补码） */
    float         f;         /* 解释 3：IEEE 754 binary32 */
    unsigned char b[4];      /* 解释 4：4 个独立字节 */
};

static void show(uint32_t bits) {
    union view v; v.u = bits;
    printf("bits = 0x%08" PRIX32 " | u = %-10" PRIu32 " | i = %-12" PRId32
           " | f = %-14.6g %%a = %a\n", v.u, v.u, v.i, (double)v.f, (double)v.f);
    printf("        bytes[0..3] = %02X %02X %02X %02X\n",
           v.b[0], v.b[1], v.b[2], v.b[3]);
}

int main(void) {
    printf("sizeof(union view) = %zu 字节\n", sizeof(union view));
    show(0x40490FDBu);   /* π 的 binary32 位模式 */
    show(0x00000041u);   /* 十进制 65 / 'A' 的最高字节 */
    show(0xFFFFFFFFu);   /* 全 1 */
    show(0x00000001u);   /* 最小次正规数，同时也是整数 1 */
    return 0;
}
```

真实输出（`gcc -O2 -Wall -Wextra union4.c && ./union4`，x86-64 小端）：

```
sizeof(union view) = 4 字节
bits = 0x40490FDB | u = 1078530011 | i = 1078530011   | f = 3.14159        %a = 0x1.921fb6p+1
        bytes[0..3] = DB 0F 49 40  (小端机器：低位字节在前)
bits = 0x00000041 | u = 65         | i = 65           | f = 9.10844e-44    %a = 0x1.04p-143
        bytes[0..3] = 41 00 00 00  (小端机器：低位字节在前)
bits = 0xFFFFFFFF | u = 4294967295 | i = -1           | f = -nan           %a = -nan
        bytes[0..3] = FF FF FF FF  (小端机器：低位字节在前)
bits = 0x00000001 | u = 1          | i = 1            | f = 1.4013e-45     %a = 0x1p-149
        bytes[0..3] = 01 00 00 00  (小端机器：低位字节在前)
```

把这四行读三遍，你会得到三个可以直接进架构评审的结论：

1. **`sizeof(union view) == 4`**：四个成员没有额外的头、没有 tag、没有长度。**机器里没有任何一位用来记录「这是 float」**——`0x40490FDB` 与 `1078530011` 是同一批触发器上的同一个电平组合，只是被送进了不同的解释器。
2. **`0x00000041` 同时是整数 65、`'A'`、和浮点 `9.1e-44`（次正规数）**：所以「类型错了」这件事**不会崩、不会报错、不会触发任何硬件异常**，它只会安静地给你一个荒谬但自洽的值——这正是 §02.1 那 34 年退避的产生机制。
3. **`%a` 是唯一诚实的浮点格式**：`0x1.921fb6p+1` 直接告诉你「尾数 0x921fb6、指数 +1」，比 `%f` 的十进制近似更接近位本身。调试浮点问题时用 `%a`，别用 `%.20f`。

### 为什么机器不存类型：tag 的钱

「类型」若真存进机器，就要占位。三种方案的账：

| 方案 | 额外开销 | 代表 | 代价 |
| --- | --- | --- | --- |
| 值内嵌 tag（tagged pointer / NaN-boxing） | 值域少几位（如 3 bit tag → 整数只剩 29 位） | 动态语言、部分 JS 引擎 | 值域变窄；每个算术操作要 `& mask` + `>> tag` 两次位运算 |
| 独立对象头 | 一个 `int32` 变 16 字节（对象头 8 B mark word + 4 B class 指针 + 4 B 值），**4 倍** | Java `Integer`（JOL 测量值） | 内存与缓存全按 4 倍付，一次指针追踪还多一次访存 |
| 不存（静态类型 + ABI 约定） | 0 | C / C++ / Rust / Go 的基础类型 | **解释权交给编译期**：`union`、`void*`、序列化边界上全部信任调用方 |

C 选了第三种，代价就是你得自己保证「谁发谁收用的是同一个解释函数」。**这就是为什么「类型安全」在系统编程里值钱：不是禁止你出错，而是把错误从「安静的 34 年」变成「编译不过」。**

### 类型甚至决定数据走哪条总线

在 x86-64 SysV ABI 里，整数参数走通用寄存器（`rdi/rsi/rdx/rcx/r8/r9`），浮点参数走 SSE 寄存器（`xmm0–xmm7`）。这意味着**「类型」在调用约定这一层改变了物理路径**：同一段 4 字节，声明成 `int` 就从 GPR 传入、走整数流水线；声明成 `float` 就从 XMM 传入、走浮点单元。所以 §02.1 里那个事故，不只是「值算错了」，而是**两边的数据根本走了不同的物理通道**——这也是为什么这类 bug 用 `memcpy` / 二进制协议最容易发生：序列化边界正是「解释权交接」的地方，而那里通常只有一个字段编号，没有类型检查（`base/06` 专讲这一层）。

## 02.9 三列账：位层

| 承诺了什么 | 为此付了什么 | 从哪里开始失效 |
| --- | --- | --- |
| **离散**：任意电平都被归到 0/1，噪声只要不超过容限就不影响结果（§02.3 走廊） | 供电必须在容限内；采样必须在合法时刻（否则亚稳态）；每翻转一次付 `C·V²` 的能量 | 电压越界、时钟沿采到过渡区、高速 SerDes 眼图闭合 → 误码，且误码是**概率事件**，只能降不能消 |
| **可纠错/可复制**：每级重新量化，噪声不跨级累积，所以文件能无损复制、总线能加校验、闪存能靠 ECC 救 | 每级都要重新整形（repeater/寄存器），长链路要插中继；纠错要额外位（HDD 的 ECC 约 8%、DDR5 的 on-die ECC） | 一旦误码率越过纠错能力（例如 TLC 老化、DRAM 行翻转 Rowhammer），纠正变成**放大**错误：把错的当对的用 |
| **位宽固定**：所有运算在 2ⁿ 上闭合，于是加法器/寄存器/总线宽度可以硬连线（§02.4） | 值域被位宽封死；跨宽度必须显式扩宽或截断；n 位只装得下 2ⁿ 个值 | 溢出环绕（补码的 `INT_MAX+1` 变负数）、截断丢高位、混合位宽时的隐式提升（全是 `base/03`/`base/04` 的活） |
| **解释权在调用方**：同一批位可以当整数、浮点、文本、指针、位图，零额外开销（§02.8） | 没有 tag，没有运行时检查；正确性完全依赖「双方约定一致」 | 三类崩点：**越界**（写超出分配的位，`base/33` 的缓冲区溢出）、**错解释**（`int`↔`float`、`char` 有符号性）、**字节序**（小端机写的多字节数被大端方读，`base/06`） |

一句话总结这三列：**位层把「物理的连续」换成了「约定的离散」，代价是全部正确性都押在约定上，而约定不在硬件里。**

## 02.10 踩坑清单（现象 → 根因 → 定位 → 修 → 防）

| 现象 | 根因（指回物理事实） | 定位 | 修 | 防 |
| --- | --- | --- | --- | --- |
| `printf("%f", 65)` 打出 `3.900000`（不崩，值荒谬） | 格式符与实参类型不匹配：`%f` 要求 double，从 `xmm0` 取；而 `65` 在 `esi` 里，`xmm0` 里留着**上一次**的残值 | `gcc -Wall -Wextra` 会直接报警（`-Wformat`）；出问题用 `-fsanitize=address` 抓不到，只能靠编译器 | 用对格式符；`printf` 家族加 `PRIu32`/`PRId64` 宏 | 编译选项 `-Werror=format` 进 CI；打印 `size_t` 用 `%zu` 而不是 `%lu` |
| 同样的 `0x80` 字节，一处判成 128、一处判成 −128 | `char` 的符号性是**实现定义**：x86-64 有符号，ARM64 Linux 也有符号，但 ARM 历史上默认无符号 | `printf("%d", (char)0x80)` → `-128`；或 `gcc -funsigned-char` 对比 | 显式写 `unsigned char` / `int8_t` / `uint8_t`，别裸用 `char` 存二进制 | 二进制缓冲区一律 `uint8_t*`；`char` 只用于文本（`base/06`、`go/13`） |
| 位域跨字节后值错乱，跨编译器不一致 | 位域的位序（从低位还是高位开始填）与跨存储单元规则**实现定义**；实测 GCC/x86-64 从低位填：`a:3=5, b:5=17, c:8=0xA5` → 首字节 `0x8D` = `5 \| 17<<3` | `xxd` / `od -An -tx1` 看真实字节；或打印 `*(unsigned char*)&v` | 涉及线格式（协议/磁盘）**不用位域**，改用手写移位与掩码 | 位域只用于进程内紧凑标志且不跨编译器；序列化一律显式 `x >> n & mask` |
| 结构体 `sizeof` 比字段之和大，`memcpy` 到文件后换平台读错 | 对齐填充：成员按自身尺寸对齐，结构体总大小补到最大对齐的倍数；实测 12 B vs 8 B（省 33%） | `offsetof` 逐个打印；`pahole` 或 `gcc -Wpadded` | 大成员排前面；确需紧凑用 `#pragma pack` 或逐字段序列化 | **永远不要用 `fwrite(结构体)` 当序列化**：padding 里是脏数据，且跨 ABI 不一致（`base/06`） |
| `float` 与整数比较「看起来相等却不相等」，或大整数转 `float` 后末位变了 | binary32 只有 24 位有效连接（含隐含位），2²⁴+1 无法表示：实测 `(float)16777217 == 16777217` 为 `false`，位模式 `0x4B800000` vs `0x01000001` | 用 `%a` 打印；对比 `memcmp` 位模式；`-Wfloat-conversion` | 需要精确整数就用整数类型；金额用整数分或 decimal；比较浮点用容差 | 别把浮点当「能装更大范围的小数版整数」；超过 2²⁴ 的整数一律不回浮点（`base/05`） |
| 从网络收的 4 字节数解析成天文数字 | 字节序：小端机按小端解大端发来的数（`0x00000041` 被读成 `0x41000000`） | `xxd` 看原始字节；`ntohl`/`htons` 前后各打一次 | 线格式统一 `htonl/htons`，或用 `memcpy` + 显式按字节拼 | 协议边界一律「显式拼装 + 显式转换」，禁止 `memcpy` 结构体直读（`base/06`） |

## 02.11 一页速记

| 记什么 | 数值 / 结论 |
| --- | --- |
| 为什么是二进制 | 两个稳定电平 → 一条判决门限 → 噪声容限最宽；三进制裕量 −40%、检测器 ×2、生态为零 |
| 噪声容限 | `VIL − VOL = VIH − VOH`；上例各 0.3 V；容限之内的偏差被下一级**重新量化**，所以噪声不跨级累积 |
| 数字 vs 模拟 | 数字每级重新量化（噪声不累积），模拟每级叠加误差；代价是采样必须在合法时刻 |
| 一次翻转的能量 | `C·Vdd²`；1 fF @0.75 V ≈ **0.56 fJ**（量级）；大核 0.3–1 nF/cycle → 0.4–1.8 W/核 @3.5 GHz |
| 门的晶体管数 | INV 2 / NAND2 4 / NOR2 4（但 pMOS 要加宽）/ AND2 6 / XOR2 8–12；全加器 ≈ 28 |
| NAND 是原语 | 因为 pMOS 靠空穴，迁移率约为电子的 1/2–1/3；NOR 串 pMOS 更慢更宽 |
| 8 位进位链 | 每位 2 个门 → 2+8×2 = **18 个门 ≈ 180 ps @10 ps/门**；64 位 ≈ 1.3 ns，约为 3 GHz 周期的 3.9 倍 → 必须用前缀树 |
| 晶体管不值钱 | 8 位加法器 224 个晶体管，一颗芯片 10¹¹ 个；**卡住位宽的是延迟，不是面积** |
| 一个字节 = 8 位 | ASCII 7 位 + 1 位校验 = 8；2⁶ 装不下 95 个可打印字符，2⁸ = 256 够用且不浪费；8 是 2 的幂 → 寻址变移位 |
| 8 位的自相似链 | PTE 8 B → 4096/8 = 512 项 → 索引 9 位 → 4 级页表 = 36 位 + 12 位偏移 = 48 位虚拟地址 |
| 移位 = 走线 | 32 位变量移位 = 5 级 × 32 个 mux（log₂32 = 5）；`&`/`\|`/`^` 各是一个门层 |
| 位图 | 10⁶ 个标记 → 125 KB（`uint8_t` 数组要 1 MB，64 倍差）；`fd_set` 1024 位 = 128 字节 |
| 类型是什么 | 位宽 + 解释函数；机器里零 tag；`sizeof(union{u,i,f,b[4]}) == 4` 就是铁证 |
| tag 的钱 | 对象头方案：`int32` 变 16 B（4 倍）；值内嵌方案：值域少几位 + 每次运算两次位运算 |
| 崩点三件套 | 越界 / 错解释 / 字节序；全部**不报错、不崩溃、安静地错** |

**如果只记三句：**

1. **二进制是器件选择，不是数学选择**——两个电平买到的噪声容限，是「位」这个概念唯一的地基；多值只在「慢 + 可纠错 + 可校准」的地方赢（TLC 闪存、PAM-4）。
2. **位宽固定 + 解释权外置**：机器只承诺「这 32 个触发器现在的电平」，至于它是 `3.14159` 还是 `1078530011` 秒，取决于谁在读。
3. **凡是被 2 的幂切开的东西都是免费的**（移位/掩码/对齐/页内偏移/位图/标志位），凡是跨过 2 的幂边界的东西都要记账（进位链、溢出、padding、字节序）。

## 02.12 自检题（3 题）

**Q1.** 有人提议做三进制 CPU，理由是「信息密度高 58.5%，同样的线能多传一半的数据」。请用噪声容限、器件成本、工具链三个角度各给一条反驳，并指出在什么条件下多值方案**确实**会赢，给出至少两个真实例子。

<details><summary>答案</summary>

① **噪声容限**：供电 Vdd 固定时，n 个电平等分电压走廊。要求每个电平窗宽 ≥ W、禁止停留区宽 ≥ G（且 `G ≥ W`），则 `n·W + (n−1)·G ≤ Vdd`。二进制取 `2W+G = Vdd` 得 `W = Vdd/3`；三进制要 `3W+2G = Vdd`，得 `W = Vdd/5`，即裕量掉 40%。裕量是误码率 `erfc` 曲线的纵深，掉 40% 等于从「千年一错」挪到「曲线膝部」，从可靠性问题变成概率问题。

② **器件成本**：三进制每位要**两个**阈值（Vdd/3、2Vdd/3）做检测，接收端比较器 ×2；两个参考电平必须随温度/电压/工艺一起精确跟踪（二进制只需一个分压出 Vdd/2）。省下来的线宽，从接收端面积和校准电路上还回去。

③ **工具链**：单元库、时序分析、测试方法学、存储器接口、EDA 流程全部为二值建立；三进制要重写整条链。Setun 的失败很大程度上是这个原因，不是算术原因。

**多值会赢的条件**：**慢 + 有纠错 + 有校准空间**，即「时间便宜、位贵」的场合。真实例子：① NAND 闪存 TLC/QLC（8/16 个电平，靠 LDPC 纠错 + 参考单元校准，代价是 P/E 从 10⁵ 掉到 10³）；② 高速 SerDes 的 PAM-4（每个符号 2 bit，用 DSP 做均衡与 FEC，以太网 112G/224G 用它就是因为 PCB 走线比误码更贵）。
</details>

**Q2.** 一个 8 位加法器在 3 GHz 时钟下工作。假设单门延迟 10 ps、每位进位传递 2 个门。请问 8 位行波进位能不能塞进一个周期？64 位呢？如果某天工艺进步让单门延迟降到 5 ps，8 位和 64 位的结论分别变成什么？由此推出「位宽」在硬件里被什么约束着。

<details><summary>答案</summary>

周期 = 1/3 GHz = **333 ps**。

8 位：`2 + 8×2 = 18` 个门 → 180 ps < 333 ps，**能塞进一个周期**，还剩 153 ps 给建立时间、布线、其他逻辑。64 位：`2 + 64×2 = 130` 个门 → **1 300 ps**，是周期的 3.9 倍，**塞不进**——所以 64 位 ALU 必须换成超前进位/前缀树，把链变成 `log₂64 = 6` 级，用面积和布线换延迟。

工艺降到 5 ps/门：8 位 = 90 ps（仍有 243 ps 余量），64 位 = 650 ps（仍超周期，但差距从 3.9× 缩到 1.95×）。若同时提频到 5 GHz（周期 200 ps），8 位 = 90 ps 仍然合格，64 位 = 650 ps 依旧不合格，**结论不随工艺改变方向**：串行进位链的长度线性于位宽，而周期只要不是线性下降，宽加法器就必然需要并行前缀结构。

推出的约束：**位宽由「最坏路径的门数 × 单门延迟」与「时钟周期」的比值决定，即延迟约束，不是面积约束**（8 位加法器只有 224 个晶体管，面积上完全不是瓶颈）。这条约束的工程外推就是：加法 1 cycle、乘法 3–5 cycle、除法几十 cycle，所以「移位替代乘法」「掩码替代取模」是真实的硬件价格差。
</details>

**Q3.** 一段从 socket 收到的 4 个字节 `DB 0F 49 40`（按接收顺序）。已知发送方在 x86-64 小端机上把它当作 `float` 写出。请写出把它还原成 `3.14159` 的完整步骤，并说明如果接收方是大端 ARM（或 Java 的 `DataInputStream` 默认大端）会读到什么、错在哪一层。

<details><summary>答案</summary>

第一步看**字节序**：发送方小端存储时，`float` 的 4 个字节按「低位字节在前」排，所以 `DB 0F 49 40` 对应位模式 `0x40490FDB`（要把顺序反过来）。验算：`0x40490FDB` 的符号 0、指数 `0x80`(=128) − 127 = 1、尾数 `0x490FDB` → 1.5707963×2¹ = `3.14159274`，与 §02.8 的 `%a = 0x1.921fb6p+1` 一致。

第二步看**解释函数**：把这 4 字节按 `float` 解释（`memcpy` 进 `float`，或用 `ntohl` 先转成主机序再 `memcpy`）。

大端方读到的是：先得到位模式 `0xDB0F4940`（把收到的字节当大端拼），符号位 = 1 → 负数，指数 `0xB6` = 182 → 182−127 = 55，值约 **−6.6×10¹⁶**（量级）。错在**两层叠加**：① 字节序层——「字节的排列」是约定，不是硬件事实（`base/06`）；② 解释层——同一个位模式既可以当 `float` 也可以当 `int32`，机器不检查（§02.8）。

正确做法：线格式显式约定字节序（网络字节序 = 大端），两端都用「逐字节拼装 + 显式转换」（`ntohl` 对整数，`memcpy` 对浮点位模式），永不 `memcpy` 整个结构体跨机器直读。
</details>
