## 56.4 跨层术语：看起来相同，不代表承诺相同

| 常被混叫的词 | 必须再问一句 |
| --- | --- |
| 页 | 是虚拟内存页、文件系统块、数据库页，还是 NAND 编程页？对齐、单位和寿命分别是什么？ |
| 缓存 | 是 CPU 缓存行、页缓存、分配器空闲块还是 DNS TTL 缓存？谁失效它，读到旧值是否许可？ |
| 队列 | 是可运行任务、socket 字节、存储请求还是业务任务？满了是等待、降速、拒绝还是丢弃？ |
| 窗口 | 传输流控、拥塞上限还是业务去重时间？由谁维护，实际限住了什么？ |
| 确认 | 是 TCP ACK、TLS 完成、HTTP 状态，还是业务事务持久化？收到哪一层就只认哪一层？ |
| 连接 | 是 TCP 四元组、TLS 会话、HTTP/2 连接还是池里的句柄？换一路由或重连后哪些状态保留？ |
| 原子 | 是一次内存读改写、名字替换的可见性、事务原子性还是业务幂等？其中哪些需要掉电持久性？ |
| 时间 | 是持续时间、墙钟时间还是跨节点因果顺序？采样点、时钟域和误差有何区别？ |

## 56.5 工程验收：先写判据，再写结论

```text
现象 → 明确起点、终点和计量单位
     → 列出这条路径与各层的承诺
     → 写出一个支持证据、一个可能推翻结论的反例
     → 固定负载与环境，只改一个变量
     → 记录结果、未覆盖边界、回退条件
```

例：一次 HTTPS 请求花 250 ms，服务端 handler 只有 40 ms。两者的差值只说明有 210 ms **不在该 handler 的计时区间**。不能直接把它叫作网络延迟。最小的核验是用同一请求 ID 对齐客户端 DNS、连接、TLS、首字节、响应完成与服务端入队、获得连接、处理、写出这些事件；跨机只对齐事件或使用有误差上界的同一时钟域，不能直接相减两台机器的单调时间。重用连接和新建连接分别测，且不要用“整体 P99 减 handler P99”当作每次请求差值的 P99。

| 证据种类 | 应标注什么 |
| --- | --- |
| 规范/接口承诺 | 标准或手册、适用条件、哪些例外仍成立 |
| 本机观测 | 环境、方法、输入规模、统计口径，不外推为通用结果 |
| 算式/推演 | 假设、单位、变量、换前提后哪些结论会变 |
| 教学案例 | 标成假设或复合场景，不写成无来源的生产事故 |

<details><summary>答案 1–20</summary>

1. 两种解释都成立，前提分别是无符号 8 位和补码有符号 8 位。
2. 在模 `2⁸` 的数学模型中，`−b ≡ ~b+1`，舍掉超出位宽的进位即可。硬件模型不替代语言溢出规则。
3. 不可；通常是未定义行为。用无符号运算、检查或明确的语言接口。
4. 乘法已经在原类型计算，扩宽结果不能补救原运算。
5. 约分后分母有 5；有限二进制小数约分后的分母只能是 2 的幂。
6. 每次加法舍入；改变中间结果的量级就改变 ulp 和舍入点。
7. 数值比较可相等，但 IEEE 除法和位模式可区分两者，例如倒数的符号。
8. 不变。变的是同值的字节在地址或线路上的排列规则。
9. ABI padding、端序、位域布局与字段版本都可能变。线格式须明确。
10. 先看需求。存储限额常按字节，Unicode 解析按码点，用户可见编辑通常按字素簇。
11. 可并行访问、预取、缓存行利用率和依赖链都不同，不是算法复杂度一个量决定。
12. SSD 没有机械寻道，但擦除粒度大于编程粒度，FTL 映射、垃圾回收和写放大会改变延迟。
13. 不能。先看瓶颈是核内周期、访存、I/O 还是等待。
14. 不能；它可在等待时推进不依赖该结果的指令。
15. 可预测分支少付预测失败成本，而且无分支方案可能计算本可不执行的路径。
16. 不一定。还要一致的调用约定、布局、符号与平台规则。
17. 优化会改变布局、寄存器、内联与指令选择。没有选项无法复现观察。
18. 写不同字节仍竞争同一一致性单元；同一行的变动可能让另一核的副本失效。
19. 一致性维护地址的副本，不提供 C 内存模型规定的同步关系；未同步的并发冲突访问仍可能是数据竞争。
20. 不是。还有总线带宽、描述符、地址映射、缓存协作与完成通知。

</details>

## 56.11 一页速记

```text
描述与实现分开：一个位模式不等于一个固定含义。
开销与事件分开：一次 syscall 不等于一次上下文切换。
就绪与完成分开：fd 可读不等于请求已经读完。
确认与持久分开：收到 ACK 不等于业务数据落盘。
通道与授权分开：TLS 正常不等于当前调用方具有操作权限。
算式与实测分开：先公开假设，再据实际证据修正。
```

## 56.12 如何用这 100 题复盘

不要以记住所有数字为目标。任选一题，先写下一句话结论，再补齐观察点、适用前提和一个反例。例如第 87 题，不止要说“检查证书”，还要说明客户端期望哪个名字、服务端证明了哪个名字、经过代理时究竟校验的是哪一段。第 73 题不止要算出 1.25 MB，还要说明由在飞字节与 RTT 推出来的是持续吞吐的必要条件，不是单个请求的耗时承诺。

| 复盘卡 | 检查项 |
| --- | --- |
| 能否从单位推导 | 把比特与字节、速率与存量、单向与往返明确分开 |
| 能否指出实验边界 | 是同机、跨机，还是内存里的两端？工具看到的是哪个层次？ |
| 能否给出反例 | 如果改变连线、硬件、拓扑、并发或信任前提，原结论还成立吗？ |

把答错的题按类型记录。读错协议字段，回到头部和状态机；把估算误当测量，回到方法与统计；对着一个正确指标找错层，回到请求链路。下一次见到相同结构的故障，先拿出原来那张卡核对，不从工具清单重新试一遍。

复盘时可以从同一个连接连答四题：先回答 79，说明一个被截断的 DNS 应答为什么不能充当完整证据；再回答 87，指出解析给出 IP 后客户端仍然校验哪个名字；再答 88，指出服务端接受某张客户端证书并不能授权它操作任意资源；最后答 96，解释上述步骤哪些存在于当前请求的首字节时间，哪些在复用连接时已提前完成。这样练习比记忆四条互不相干的结论更接近真实排障。
