# 01 · LLM 是什么：分清模型、应用与 Agent

> **状态**：已完成（初稿）
>
> **本篇定位**：看清屏幕上的一条回答是谁做出来的；区分模型学到的东西、本轮收到的材料和外部查到的信息。
>
> **读法**：先看三种交付的区别，再拿一段市集草稿做核验；只想排错，可以直接看边界表。

## 同一句请求，为什么做出来的事不同？

周五下班前，你接手一份周末市集的交接。群里有人还在转发旧图，报名表也有重复项。你把同一句话交给三个应用：「按最新规则整理报名清单和通知草稿，先别发。」第一个给清单模板，第二个列出两个公告出处，第三个读取报名表、标记疑似重复项，再交回通知草稿。看起来是三个 AI 能力不同，但也可能是同一类模型放在了三套不同的应用里。

**贯穿全书的市集案例为虚构。** 市集原定周六；现行 v2 改为**周日 14:00**，雨天是否改室内**待确认**，旧 v1 **已失效**。交付物仅是整理后的报名清单和通知草稿，**不发送**。这是我们作为验收人掌握的事实；模型本轮是否知道，要看材料有没有交到它面前。

**本篇的真问题：屏幕上的一条回答，到底是谁做出来的？**

```text
用户：定任务、给资料、说清允许做什么
                         ↓
应用：整理本轮材料 ──→ 模型：用训练得到的权重处理输入
        ↑                        ├─ 产出文字 → 应用展示 → 人验收
        │                        └─ 提议查证 → 应用判断权限、调用工具
        └──────────── 工具结果（如果应用将它交回模型）←────┘

发送、发布、写入外部系统：不是写一句话，需要另行授权和实际执行。
```

这是一种常见分工，不是所有聊天应用的内部流程图。没有工具时，上面的查证回路就不存在。应用也可能自己先查，再把结果交给模型，并不总是等模型提议。

| 同一任务的三种交付 | 这一轮发生了什么 | 不能由此推出什么 |
| --- | --- | --- |
| 普通聊天给清单模板 | 模型读到请求，没有报名表或现行规则；可以先给栏目、列出所缺材料 | 不能推出它看过报名数据，或知道市集何时开场 |
| 联网应用给公告出处 | 应用查找可访问的公告，把结果带给模型；草稿可以标明依据 | 能联网不等于能读私有报名表，也不等于每个链接都支持对应结论 |
| Agent 整理名单并起草 | 应用允许查阅相关资料；一种做法是遇到重名先比对授权字段，仍不确定就留待人工核对 | 草稿不是已经发布的通知；能提议一个动作，也不等于可以或已经执行 |

工作量不大时，第一种并不逊色：把 v2 和去掉多余个人信息的报名表一起交给普通聊天，就可能起出合格草稿。第三种的价值在于能根据看到的结果调整下一步，不在于界面上写着「Agent」，更不在于把所有动作都交出去。

## 模型、聊天应用、搜索和 Agent 各是什么？

**LLM** 是大语言模型（Large Language Model）。可以先把它理解为一个从大量数据中学到许多语言规律、能根据输入处理和生成语言的模型。常见文本生成模型会按当前内容逐步预测并选出接下来的文本片段。这个过程能产出摘要、表格和自然的解释；但预测出像公告的句子，与核实公告真这么写，是两件事。

**聊天应用**是你实际打开的产品。它负责界面、附件处理、把哪些消息交给模型，以及展示哪些结果。同一个模型可以嵌在不同产品里；同一产品也可以切换模型。界面看得见一份附件，不代表它的每一页都进了模型这一轮的输入。

**搜索**负责找材料。找到旧版海报、公开转发和主办方现行公告，是三类结果，不是三张同等有效的选票。搜索也可能漏掉不公开的文件。**Agent** 在这里指围绕一个目标反复读结果、决定下一步的应用流程。例如，遇到两份规则先核有效性，再按现行版起草；碰到仍未确认的场地信息就标为待确认，必要时把问题交还给用户。事先固定写死的「先读、再排、最后填模板」，可以很实用，但并不一定要叫 Agent。

### 模型是从哪里得到这句话的？

| 信息从哪来 | 市集里像什么 | 核查时问什么 |
| --- | --- | --- |
| **权重**：训练中调出来的内部数值，影响模型长期怎样处理输入 | 知道通知通常有主办方、时间、地点和须知，能写成自然语句 | 能力从训练来，不代表这句话对应一条可查到的训练记录，更不能证明这次改期 |
| **本轮材料**：应用实际交给模型的指令、消息、附件摘录等 | 你贴上的 v2、报名表摘录和「不发送」 | v2 关键页和边界要求是否真的在这次材料里？ |
| **外部工具结果**：查询后被应用带回的资料 | 主办方公告、以往记录、只读报名表的查询结果 | 结果来自哪里，适用于哪场活动，哪一段支持结论？ |

后两类不是互斥的盒子：工具查到的内容一旦带回，就成为某次模型调用的本轮材料。区别是**来源和进入路径**。用完这份资料也不等于模型自动改了权重或以后都记得。

## 把「写得像真的」和「有依据」分开

假设草稿写：「市集改到周日 14:00，如遇下雨请直接前往室内场地。」前半句对，后半句却把待确认写成了行动指引。核对时不要给整段一个笼统的「真」或「假」，而是把每项会影响读者行动的说法拆开：

| 草稿里的说法 | 验收时看什么 | 判定 |
| --- | --- | --- |
| 改为周日 14:00 | 主办方现行 v2 中的时间一句 | 有依据；保留 |
| 周六仍可到场 | 这只出现在旧 v1；v1 已作废 | 不能并列成备选日期 |
| 下雨就去室内 | v2 只说雨天是否改室内待确认 | 不支持；改成「雨天是否改至室内，待主办方确认」 |
| 通知已发送 | 是否有授权，是否有实际记录 | 任务明确不发送；不应执行，也不能把草稿说成已发 |

核验找的是**有权确定本场规则、仍然有效、且支持这条说法**的材料。某个网页比 v2 更新，也可能只是在转发旧图；渠道、适用范围和生效状态要一起看。原文没有，就标成未知；「待确认」不是不够聪明，而是没有替主办方决定。报名清单也类似：两个重名的人可能不是同一位摊主，缺少可靠依据时，列为待核对比静悄悄删掉一行更有用。

## 手工练习：给草稿做一张交接卡

拿一张纸分成三栏：「事实及依据」「可以交付」「留待人工」。你手上有现行 v2、旧 v1 和一张含两条同名记录的报名截图；截图里没有足够信息确认是否同一人。现在假定应用只会普通聊天，不会搜索，也不会发送。

1. 圈出通知里必须准确的三件事：有效时间、雨天状态、文档是草稿。时间和雨天状态分别对照 v2；草稿状态来自用户授权。
2. 列出清单可交出的部分：照录已看见的报名记录，给同名两条加「可能重复，待核」。未看到完整表，就不要称它为完整名单。
3. 写一句交接语，例如：「已按现行 v2 整理可见记录及通知草稿；两条同名记录待复核，雨天是否改室内待确认，未发送。」

还可以做反向练习：拿走 v2，只留下 v1 和「按最新规则」一句。此时合格输出应承认缺少现行材料，先给待填模板，而不是沿用周六，也不能靠猜写出周日。这样就能测出它是在凭依据工作，还是只碰巧答对。

## 边界与速记

| 现象 | 先检查哪一层 | 改动与代价 |
| --- | --- | --- |
| 草稿写错日期 | 材料版本和应用实际提供的内容 | 补现行原文、剔除失效规则，再重做；联网会增加延迟，也可能引入更多旧资料 |
| 名单漏人或擅自合并 | 附件覆盖范围、模型整理结果与验收 | 对照原表逐行抽查；不必上传与核对无关的个人信息 |
| 语气生硬但事实正确 | 模型和写作指令 | 加一段语气示例或比较模型；不要让范例里的日期变成事实来源 |
| 看见「已发送」 | 应用的权限与行动记录 | 检查有无实际动作，停用不需要的发送能力；只起草不需要开放发送 |

**速记：** 用户定目标和权限，应用供料并执行已授权的外部动作，模型处理材料、生成文字或提出建议，事实由有效来源和实际记录来验。需要的是草稿，就不用把发送也交出去。

### 自检（含简答）

1. **同一个模型为什么在一个应用里能列出处，在另一个里不能？** 前者可能有检索工具或已把出处送进本轮，后者没有；列出链接还要查链接能否支持结论。
2. **模型第一次就说「周日 14:00」，但没看过 v2，可以直接采用吗？** 不行。结果碰巧一致不是证据，应回查现行 v2。
3. **一条草稿有一处没确认，是否整件事都得停？** 不必。可以交付已能核验的部分，把雨天安排和疑似重复项单列给人确认，仍不发送。
