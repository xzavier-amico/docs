# 12. 它「记得你」：系统替你保管了什么

> **状态**：`已完成（初稿）` ｜ **所属**：Part II · 材料 ｜ **编号**：12 / 33
> **本篇定位**：把「记忆」从一个器官拆成四层存储加四个动作——会话历史、跨会话偏好、任务状态、模型权重；由此回答「它为什么记得」「为什么记错」「删了为什么还在」三个问题，并给出一个十分钟能做完的记忆审计。
> **不在本篇**：工作台如何组装 → 05；权重如何固化、为什么会过期 → 07；检索的三道关 → 10；压缩丢了哪五类东西 → 11；隐私与数据边界 → 23

## 12.1 引子：同一段回答里，一半记得，一半忘了

**虚构场景**。10 月 8 日傍晚，秋季团建的筹备到了核预算这一步。你新开了一个会话——上一次聊这件事是三天前，那个会话早就关了。你只打了一句话：

> 帮我核一下团建预算。

它回得很快：39 人，人均 400，合计 15,600；A 方案 13,740，余 1,860；B 方案 15,690，超 90。金额一律不带小数，结论放在最前面，最后附一张三列表。末尾还补了一句：「按你的习惯，不确定的项单独列出来，不并进结论。」

你没有在这一轮说过「不带小数」，也没有说过「结论放前面」。三天前那个会话里，你提过一次，只有一次。

你往下看，表格第二行写着：**活动日期 10 月 18 日（周六）**。

同一段回答里，一半是「记得」的，一半是「忘了」的。而且忘掉的那一半，恰好是更要紧的那一半——金额错一位还能改，日期错了会直接发进群里。

这件事用「记性好不好」解释不了。因为记性好坏是一个刻度，而这里发生的是两种完全不同的机制同时在场：

- 「金额不带小数」被**存到了某个地方**，新会话开始时又被**搬了回来**；
- 「10 月 25 日」从来没有被存成偏好，它是一件事的**当前状态**，属于三天前那个会话；会话一关，它就没有被搬回来；
- 「结论放前面」可能根本不是记忆，而是这个产品对所有人的默认排版。

三种来源，在屏幕上长得一模一样。你又去设置里翻了一圈，发现真的有一栏叫「记忆」，里面躺着三条句子，其中一条是三个月前的「我在做 A 项目」——那个项目上个月就结了。你想删掉它，界面上只有一个总开关，没有单条删除。

这就是这一篇要处理的现场：**「它记得你」这句话里，至少藏着四个不同的东西；它们各自被谁保管、什么时候回到桌上、能不能删，全都不一样。** 分不清，你就会在错误的那一层反复修——删了聊天记录，发现它还记得；换了模型，发现旧偏好还在；对它说「忘掉」，它答应得很痛快，下次照旧。

## 12.2 唯一真问题：换个会话它还知道我的偏好，这是模型的记忆吗

**不是。** 模型这一轮能看见的，仍然只有这次被放到桌上的东西（P2）。变的不是它多了一个器官，而是**桌上多了几张从别处搬来的纸**。搬纸的不是模型。

四句话把它拆开：

1. **模型没有存储，也没有「取回」这个动作。** 它不查库、不翻记录、不回想。它读的是这一轮递给它的序列；序列之外，对它来说不是「想不起」，是「不存在」（→ [05](05-context-workbench.md)）。
2. **四层里只有一层在模型身上，就是权重。** 其余三层——会话历史、跨会话偏好、任务状态——都是应用或运行时替它保管的，存在模型外面。所以标题问的是「系统替你保管了什么」，不是「模型记住了什么」。
3. **「记得」是三个条件的合取：写进去了、这次取到了、取到的是现在这一版。** 缺任何一个，表现都叫「忘了」或「记错了」，但修法完全不同。
4. **四层的删除方式互不通用。** 删聊天记录，偏好条目还在；删偏好条目，那句原话还在历史里；删账号，权重不会少一个数。

由 P2 可以直接推出本篇的反直觉命题：

> **记忆的失败，多数不是「存不下」，而是「没更新」和「没删旧的」。**
>
> 因为取回发生在工作台上，而工作台上没有「哪条更新」这个变量——除非有人替它标好。

这不是经验总结，是结构推论。取回是组装的一部分：按当前问题挑几条、按预算挑几条、按位置摆进去。这三个动作里没有一个需要知道「这条是三个月前写的，那条是昨天写的」。新旧不是它天然能看见的属性，是必须由人或系统额外标注的信息。

于是得到一条很硬的判据：

> **评价一套记忆，不要问「它能记多少条」，要问「旧的那条怎么退场」。**
>
> 加一条谁都会；撤一条才见设计。

这条判据能解释很多「越用越笨」的观感：不是它变笨了，是它同时记着三个版本的你，而取回时挑中了最早的那一个。

四个定位问题在这一篇各有具体形态：

| # | 问 | 在记忆这一篇里问什么 |
| --- | --- | --- |
| 1 | 这句话是谁说的？ | 是模型说「我记得」，还是应用里真有一条可查看的条目 |
| 2 | 它这一轮看见了什么？ | 这一轮的工作台上，到底有没有那条偏好 |
| 3 | 这是提议、事实，还是已经执行？ | 「已记住」是它写了一句，还是条目真的落了盘 |
| 4 | 我拿什么独立验证？ | 设置里的条目列表、来源、时间，而不是它的复述 |

第 3 问是这一篇的主问：**「记住」是一个写动作，不是一句话。** 模型没有写权限（P5），它只能说「我记住了」；真正落盘的是应用。这个形状在 16 篇会再出现一次，那里叫「回执」——同一个道理，换了一个动作。

## 12.3 一张图：四层 × 四动作

先看全景。横着看是一层，竖着看是一个动作。

```text
              ① 写入             ② 取回              ③ 更新             ④ 删除
            谁放进去           何时回到桌上        旧的那条怎么办      删的是哪一层
  ┌────────┬─────────────────┬──────────────────┬──────────────────┬──────────────────┐
  │会话历史│应用逐轮追加      │每轮重放最近几轮   │不更新，只变长     │删会话＝删这层     │
  │一次会话│你的话＋它的回答  │超长则截断或摘要   │旧错误变成新前提   │偏好层不受影响     │
  ├────────┼─────────────────┼──────────────────┼──────────────────┼──────────────────┤
  │跨会话  │应用抽取／你手写   │新会话开始时注入   │多半是「再写一条」 │能逐条删           │
  │偏好    │有时由模型提议    │或按相关取几条     │不是「改那一条」   │入口因产品而异     │
  ├────────┼─────────────────┼──────────────────┼──────────────────┼──────────────────┤
  │任务状态│应用／运行时记录   │恢复任务、定下一步 │每步覆盖           │删任务＝删状态     │
  │一次任务│已做／待做／结果   │压缩后重建也用它   │可回到某个检查点   │已发动作不回滚     │
  ├────────┼─────────────────┼──────────────────┼──────────────────┼──────────────────┤
  │模型权重│训练流程          │每次请求都在用     │只能再训练一次     │不能定点删         │
  │一个版本│预训练／后训练／微调│不是「取一条」    │连带改别处         │只能重训／换模型   │
  └────────┴─────────────────┴──────────────────┴──────────────────┴──────────────────┘
     寿命      写入最容易          取回最不可见        更新最难            删除最贵
```

这张图有三个读法，每个都值得记住。

**第一，四层里只有最后一层在模型身上。** 前三层都是「把纸存在别处，下次再搬回桌上」——它们是 P2 的延伸，不是模型的能力。第四层是 P4 的地盘：改的是写字的人，不是桌上的纸。所以「记忆」这个词其实横跨两个原语：**三层是携带的变体，一层是固化。**

**第二，四个动作的成本是反的。** 写入最容易：一句话就能写，甚至不用你写，系统会自己抽。取回最不可见：没有任何界面告诉你这次取了哪几条。更新最难：大多数实现只会「再写一条」。删除最贵：要找到入口，要知道删的是哪一层，还要接受权重那一层根本没有删除这个动作。

**第三，竖着看会发现一个规律：越往下，寿命越长，可撤性越差。** 会话历史活一次会话，任务状态活一个任务，偏好活几个月到一直，权重活一个模型版本。「记久一点」听起来是好事，但它同时意味着「撤掉更难」。**记忆的深度和可逆性是同一根轴的两端。**

把责任摊开，四层各自归谁管：

| 谁 | 在记忆这件事上负责什么 | 不负责什么 | 出问题先看什么 |
| --- | --- | --- | --- |
| **人** | 决定哪些偏好值得存、哪些必须删；定期核对 | 记不记得住（那不是意志问题） | 你自己那张偏好清单 |
| **应用** | 写入、存哪、什么时候取、给不给删除入口 | 这条偏好现在还对不对 | 条目列表、来源、时间 |
| **模型** | 就着取回来的几条续写 | 存储、取回、删除 | 这一轮前文里到底有哪几条 |
| **工具 / 运行时** | 任务状态的读写与回滚；动作的执行与回执 | 偏好该不该存在 | 检查点、任务记录 |

模型那一行的「不负责」里写着三个动作：**存储、取回、删除。** 三个都不是它。这就是为什么「你跟它说忘掉」不可靠——你在要求一个没有写权限的东西去执行删除。

## 12.4 机制一：四层，各自的四个问题

下面逐层过。每层都问四件事：谁写的、存哪、什么时候取、能不能删。这四个问题答不全，这一层就还是黑的。

### 12.4.1 第一层：会话历史——最容易看见，也最容易误会

**谁写**：应用。你每说一句，它追加一句；模型每答一句，也追加一句。不是你写，也不是模型写。

**存哪**：应用的会话记录里，一个会话一条线。它不在模型里，也不在你的电脑上——在你和模型之间的那一层。

**什么时候取**：下一次请求时，应用把最近若干轮**重新拼进工作台**。拼多少、从哪一头拼、超长怎么办，由应用决定。

**能不能删**：能。删这个会话，或者清空对话，删掉的就是这一层。

这一层看起来最像「记忆」，其实最不像。因为**它不是「记住」，是「重放」**。每一轮，前面的话被重新搬回桌上；搬不搬得动、搬得动多少，取决于桌子的面积和应用的策略。05 篇那句话在这里最贴切：它并没有记住上一轮，上一轮之所以看起来被记得，是因为被重新搬了回来。

三个后果，每个都很常见：

- **越聊越长，早期内容被截断或摘要。** 你以为它「忘了开头」，其实是开头没上桌（→ 11）。压缩还会把「v1 作废」这类否定句剪掉，于是它拿着一份看起来完整、其实缺了关键否定的材料，非常自信地答错（→ 05）。
- **旧错误变成新前提。** 第三轮写错的日期，到第十轮仍然在历史里；后面的回答不会去质疑它，只会为它服务。你越聊越觉得它「固执」，其实是你把那个错误一轮一轮搬了回去。
- **换个会话就没了。** 这不是缺陷，是这一层的定义：它的寿命就是一个会话。

所以「昨天它还记得」这句话，严格讲不成立。成立的说法是：**昨天的会话还在，应用今天又把它搬了上来。** 这两句话的差别在于，前者让你以为存在一个「它」，后者让你知道该去哪里找那几张纸。

### 12.4.2 第二层：跨会话偏好——「它记得你」的主要来源

**谁写**：三种来源，可靠性完全不同。

1. **你显式说「记住：……」**，应用把它写成一条。这是最可控的一种。
2. **应用从对话里自动抽取**，可能不经你确认。这是最隐蔽的一种：你没有做过「保存」这个动作，但条目已经在了。
3. **别人替你写**：团队管理员配的组织级默认、共享模板、角色预设。这是最容易误判的一种——它看起来像「它了解我」，其实是「我的组织这样规定」。

**存哪**：账户级的一份条目列表。有的产品每条带来源和时间，能看到「这句话是什么时候、从哪轮对话来的」；有的产品只给一个总开关，你看不见里面有什么；有的干脆没有这个界面，偏好混在每次请求的一段固定文本里。**这些差异因产品与版本而异，本文不指认具体产品。**

**什么时候取**：常见的是新会话开始时注入；有的每次请求都带；有的按当前问题的相关性挑几条。**具体策略因产品而异。** 但有一件事是共通的：**取回要占工作台面积**，所以写得越多，越可能挤掉别的材料，也越可能自己都没被取到。

**能不能删**：能，但要看有没有入口。这是这一层最实际的风险：**你有写入的入口，不一定有删除的入口。** 写入只需要在对话框里说一句话；删除可能需要翻三层设置，或者根本不存在单条删除。

三个判据，用来判断这一层是不是「可控」：

| 判据 | 是 | 否 |
| --- | --- | --- |
| 它是不是一条**可查看的文本**？ | 你能逐条审 | 只能从行为反推里面有什么 |
| 它有没有**来源和时间**？ | 两条矛盾时你能仲裁新旧 | 只能猜哪条是后来的 |
| 它是不是**每次都被取**？ | 你可以指望它 | 它会和别的材料抢面积，可能被挤掉 |

第三行是最容易被忽略的。很多人以为「设了偏好」等于「以后每轮都生效」，其实它只是「以后每轮都可能被取」。差别就是 12.5.2 那一整节。

这一层最像档案，也最容易腐化。因为它记录的是**「当时的你」**，而档案不会自己更新。

### 12.4.3 第三层：任务状态——不是关于你，是关于这件事做到哪了

**谁写**：应用或运行时。一个任务跑到一半，它需要记住「已经查了 A 场地」「B 的档期还没回」「通知不能发」。这些不是偏好，是进度。

**存哪**：任务记录、检查点、待办清单。有的产品叫「项目」，有的叫「任务」，有的藏在运行日志里（因产品而异）。

**什么时候取**：恢复任务时；决定下一步时；上下文被压缩、需要重建「我们做到哪了」时。这一层是 11 篇那五类必须保留（决定、否决、依据、未决、边界）的实际存放处——**摘要剪掉的，往往就是这里最需要的。**

**能不能删**：能删任务、清空检查点。但有一句必须单独记：**状态可以回滚，副作用不能。** 你把任务状态删了，已经发出去的那条消息不会回来（→ 16）。这是「删除」在第三层和第四层之间的一个关键差别：第三层删得掉记录，删不掉后果。

这一层最容易出的错，是**串台**：把上一件事的状态带进下一件事。

昨天那个任务是「团建」，今天这个任务是「季度复盘」，但状态里还留着「预算 15,600、不可群发、雨天待确认」。于是它在你写复盘时提醒你「注意不要群发」，在你写总结时问「要不要按 39 人算场地费」。听起来像贴心，其实是它把两个任务的边界弄混了。

区分方法很土但有效：**问它「这是在哪个任务里说的」。** 如果它答不出任务边界，或者把两个任务的材料混着引用，说明状态没有边界。没有边界的任务状态，比没有状态更危险——因为它会把一件已经结束的事，当成现在的前提。

### 12.4.4 第四层：模型权重——唯一在模型身上的那一层

**谁写**：训练流程。预训练、后训练、微调。不是应用，不是界面上那个「记住」按钮。

**存哪**：一堆数里。没有条目、没有地址、没有版本号。这条规则的痕迹分散在成千上万个数的组合里，和语法、语气、领域词汇混在一起。

**什么时候取**：不是「取一条」，是每一次请求都整体参与。它不挑，也不报「我这次用了哪部分」。所以严格讲，这一层没有「取回」这个动作，只有「参与」。

**能不能删**：不能定点删。只能重训、换模型，或者用可撤的适配层整块摘掉——而整块摘掉不等于「删掉第三条第 2 款」。

这一层的详细机制在 [07](07-weights-vs-carried.md) 篇，这里只留三句结论：

- 它买的是**默认倾向**，不是条目库存；
- 它会过期，而且过期时不报警，只是同样自信地错；
- 「它记住了我的偏好」这句话，如果指的是权重，那多半是误判：**几轮对话改不了权重。**

**那为什么还要把它算进「记忆」？** 因为它解释了一种最常见的错觉：你没设过任何偏好，它却「像懂你」。

那可能不是记忆，是这一层带来的通用倾向——它见过大量类似的人，于是对「你这样的人」有一套默认说法。这套说法不需要认识你，也不需要存过你。它的证据是「对很多人都这样」，不是「对你特别这样」。

区分方法和第二层正好相反：**第二层是「只有你有」，第四层是「很多人都有」。** 你换个新账号、换个新会话、什么材料都不给，它还是那样说话——那多半是第四层。

### 12.4.5 四层的分界表

| 层 | 一句话 | 寿命 | 谁能删 | 最典型的误判 |
| --- | --- | --- | --- | --- |
| **会话历史** | 这一轮之前说过的话，被重新搬回来 | 一个会话 | 你（删会话） | 以为它「记住」了，其实是重放 |
| **跨会话偏好** | 关于你的几条结论，跨会话保留 | 几个月到一直 | 你（若有入口） | 以为「记住」= 这次会用上 |
| **任务状态** | 这件事做到哪了 | 一个任务 | 你或运行时 | 以为上一件事的状态会自动退场 |
| **模型权重** | 训练留下的默认倾向 | 一个模型版本 | 只有训练流程 | 以为聊几次就「训」进去了 |

最右一栏是这张表的用处：**四种误判的形状不同，修法也不同。** 第一种去查历史长度和截断；第二种去查取回；第三种去查任务边界；第四种只能换模型、改材料，或者接受它。

## 12.5 机制二：四个动作，成本完全不对称

**写入最容易，取回最不可见，更新最难，删除最贵。** 这一节就是把这句话拆开。

### 12.5.1 写入：一句话就能写，但「写进去了」你看不见

先说来源的可靠性。对「你」的准确度而言，排序通常是：**你显式写的 > 应用自动抽取的 > 别人替你配的。** 第三种不是不准，是它描述的是「这个组织的人」，不是「你」。

但真正的问题不是准不准，是**你不知道它写没写**。你说「记住，我不吃香菜」，它答「好的，我记住了」。这句话可能是：

- 真的写了一条，落在账户的条目列表里；
- 只在这一轮的前文里生效，会话结束就没了；
- 什么也没发生，它只是接了一句最顺的话。

三种情况在屏幕上长得一模一样。这就是第 3 问：**这是提议、事实，还是已经执行？** 而验证方法只有一个——去能看见条目的地方看。看不见条目，就只能用「新开会话再问」来间接验（12.9 给做法）。

写入还有一个隐蔽的代价：**每一条偏好都要在以后每一轮里占面积。** 写得越多，工作台越挤，关键材料越容易被挤掉（→ 05）。所以「多记一点总没坏处」在记忆这件事上同样不成立。记十条风格偏好，可能换来的是某次核预算时，报价单被挤出了桌子。

### 12.5.2 取回：记得 ≠ 这次会取

这是本篇最要紧的一句，也是「记忆」这个词最容易骗人的地方。

取回不是一个「查档案」的动作，是**组装工作台时的一次挑选**。它要回答四个问题：这次带几条？带哪几条？放在哪个位置？和这次的材料冲突时谁靠后？——每一个问题都有预算，都有取舍，而且大多数产品不会把这个过程显示给你。

于是有四种「明明记得却没用上」：

| 现象 | 机制上发生了什么 | 怎么验 |
| --- | --- | --- |
| 它明明知道我不吃香菜，这次却推荐了 | 这条没被取到，或被更长的材料挤掉了 | 新会话单问一句，看它是否知道 |
| 它取到了，但取的是旧的那条 | 两条并存，挑中的是旧条 | 问它「关于这条你记了几版」 |
| 它取到了，但被本轮材料盖过 | 本轮指令更近、更显著 | 把偏好写进本轮任务里，再试一次 |
| 它根本没这条，是在顺着你说 | 这是续写，不是取回 | 换一个它没听过的说法再问 |

四行的修法完全不同：第一行要减材料或改取回策略；第二行要删旧条；第三行要把偏好提到更近的位置；第四行要补写入。**如果不分，你会一直在第四行上修第一行的问题**——反复说「你要记住啊」，而它其实早就存了，只是这次没被取到。

这里有一个反直觉的推论：**取回失败，会伪装成写入失败。** 因为两者的表现都是「它不知道」。所以验证顺序应该反过来：**先确认条目在不在，再谈它这次用没用。** 条目在而没用，是取回问题；条目不在，才是写入问题。顺序反了，你就会在写入那一侧做无用功。

### 12.5.3 更新：为什么「改一条」比「加一条」难

大多数系统对「更新」的实现，是**再写一条**，而不是**改那一条**。

原因不难推：条目是一段自然语言，没有主键、没有字段、没有「这一条讲的是金额格式」这种结构。系统无法判断「新这条」和「旧那条」说的是不是同一件事——两句话可能字面完全不同（「保留两位小数」与「一律整数元」），却指向同一个槽位。于是它最省事的做法是两条都留着，让取回去决定。

结果就是「它记得的是上一版」：

```text
  三月   你说：金额都保留两位小数
          → 写入条目 A
  九月   财务要求：预算表一律整数元
          → 写入条目 B（A 没删）
  十月   你问：帮我核预算
          → 取回时 A、B 都被取到，或只取到 A
          → 输出 13,740.00
          → 你说：这都什么时候的规矩了
```

这条链上没有一步是「它坏了」。写入了、也取回了，甚至取回的可能正是最新那条——错在**没有人让 A 退场**。

更麻烦的是，两条并存的条目会让输出**摇摆**：这次整数，下次两位小数，再下次两位小数但货币符号变了。你在 04 篇见过这种形状，那里叫抽样；在 07 篇也见过，那里叫「两版并存等于固化摇摆」。这里是第三种：**记忆层的版本冲突，看起来像情绪不稳定。**

所以「更新」的正确动作不是「再告诉它一遍新规矩」，而是：**先删旧的，再写新的；或者写新的时明确说「此前关于金额的那条作废」。** 后半句能不能被系统识别，因产品而异——这就是为什么第一步永远是「先看有没有条目列表」。没有列表，你就只能靠「新开会话验证」来判断旧的有没有退场。

### 12.5.4 删除：这个词在四层里指四件不同的事

「帮我删掉」是记忆这件事上最危险的一句话，因为它没说删哪一层。

| 你说的 / 做的 | 实际删掉的 | 没删掉的 |
| --- | --- | --- |
| 删除这条聊天记录 | 会话历史里的这一条 | 已经写进偏好的条目——它可能就是从这句抽出来的 |
| 清空所有对话 | 会话历史全部 | 偏好条目、任务状态、权重（因产品而异） |
| 在设置里删掉一条偏好 | 偏好层的这一条 | 会话历史里的原话；下次可能又被抽出来 |
| 删除账号 | 账户级数据，通常含偏好与任务 | 备份与日志的保留期、以及权重（因产品而异） |
| 对它说「忘掉我说过 X」 | 这一轮它可能不再提 | 任何一层。模型没有删除权限 |

最后一行要单独说：**「它说它忘了」和「它真的删了」是两件事。** 它能做的是「这一轮不再提」，这属于生成行为；删除属于应用的写操作（P5）。这和第 16 篇「它说已经办好了」是同一个形状——一句措辞被当成了一个已执行的动作。

再说权重那一层。如果对话被用于训练（是否用于训练、保留多久，因产品与版本而异，见第 23 篇），那么「删除」在那一层**没有对应动作**。你只能等下一个模型版本，或者换一个没训过这批数据的模型。这不是厂商偷懒，是结构决定的：权重里没有「这一条」，也就没有「删这一条」。**这是「删除」这个词唯一失效的一层，也是它最需要被提前说清的一层。**

### 12.5.5 隐私：能记住，不等于应该记住

记忆这一篇必须谈一次隐私，因为「个性化」和「永久保存」经常被悄悄画上等号。

先把两个词分开：

- **个性化**：让输出更贴合当前这个人。它可以是这一轮读了你的材料，可以是权重里的通用倾向，也可以是长期存下来的偏好。**三者不必都发生。**
- **永久保存**：把关于你的信息留在一个可以被以后取用的地方。这是一个存储决定，不是一个体验决定。

> **个性化 ≠ 应该永久保存。** 你可以要「这一次贴着我说话」，而不必接受「关于我的十句话被长期存着」。

为什么这件事值得较真？因为记忆的收益是立刻可见的（少交代一句），成本是延迟的、分散的、不报警的（三个月后过期的条目、找不到的删除入口、被串台的任务状态）。这种「收益即时、成本延后」的结构，最容易让人做出后悔的决定。

三列账，用来判断一条信息该不该留在偏好层：

| 留下什么 | 换来什么 | 什么时候不该留 |
| --- | --- | --- |
| 稳定的表达偏好（语气、格式、称呼） | 少交代；输出风格一致 | 它开始被用在不适用的场景里（对外正式文件、给客户看的稿） |
| 稳定的工作背景（行业、角色） | 少解释；例子更贴切 | 换了岗位、换了项目，而你没有复核机制 |
| 具体的人与事（同事姓名、客户、健康、家庭） | 省事；上下文更完整 | 大多数时候都不该留——它是「这一次的上下文」，不是「关于我的档案」 |
| 一次性要求（这次要短、这次给三个人看） | 无 | 永远不该进偏好层；它只对这一轮有效 |

第三行是重点。**很多人把「这次方便」写成了「以后默认」。** 而记忆层没有「这一次」这个概念——它只有「存了」和「没存」。所以一条只对今天有效的信息，进了偏好层就会变成明天的错误前提。

还有一个更实际的判断：**这条信息如果被原样展示给一个陌生人，你会不会不舒服？** 会，就别让它进第二层。它可以是这一轮的材料，可以说完就散；不必变成一条长期档案。

## 12.6 冲突与过期：两条偏好打架，谁赢

### 12.6.1 三种冲突，三个不同的仲裁者

| 冲突 | 例子 | 谁仲裁 | 结果稳不稳 |
| --- | --- | --- | --- |
| 同层两条偏好矛盾 | 「不要用 emoji」与「重点用 emoji 标」 | 取回顺序与位置 | 不稳，可能这次这样下次那样 |
| 偏好层 vs 本轮指令 | 偏好说「结论前置」，本轮说「先给过程」 | 本轮通常更近、更响 | 较稳，但不保证 |
| 偏好层 vs 权重倾向 | 偏好说「不要三段式」，权重倾向是「首先其次最后」 | 看谁更显著 | 不稳，且你看不见竞争过程 |

三行里最常见的是第二行，它和 07 篇的「先验 vs 条件」是同一个结构：**近的那个通常更响。** 所以「我已经设了偏好，它怎么还这样」的常见答案是：这一轮的材料或指令把它盖过去了。这不是它不尊重你的设置，是它这一轮读到的最后一段话不是你的设置。

第一行最容易被误认为是「它笨」。其实是**同一层里两条规则权重相同**，谁先被取到谁赢。这种冲突没有正确答案，只有「你有没有让其中一条退场」。

第三行最难查，因为它没有对照物。你只能靠「换个说法再问一次」看它稳不稳：如果换三种问法都是同一个倾向，那多半在权重里；如果换一种问法就变了，那可能是取回或本轮材料在起作用。

### 12.6.2 过期：不是变旧了，是没人让它退场

偏好过期有三种典型形状：

- **事实型过期**：「我在做 A 项目」。项目结束了，条目还在。
- **口径型过期**：「金额保留两位小数」。财务口径变了，条目还在。
- **关系型过期**：「帮我写得更正式一点」。你现在换了个场景，需要口语。

三种都不是「它记错了」，是**「它记得的是上一版」**。区别很重要：前者要修准确性，后者要修退场机制。而退场机制的修法，不在提示词里，在「有没有一个能删条目的地方，以及你有没有定期去删」。

一个特别常见的连锁：**旧偏好 + 新任务 = 看起来像不懂你。**

你换了项目、换了角色、换了写作对象，它还在用半年前那套语气。你会觉得它「越来越不懂我」，其实是它一直很懂半年前的你——而且没人告诉它，那个人已经不在了。

### 12.6.3 一条可操作的规矩：偏好只存「不随任务变」的东西

由此可以给出一条很硬的划分：

| 东西 | 该不该进偏好层 | 理由 |
| --- | --- | --- |
| 写作语气、格式习惯、称呼方式 | 该 | 跨任务稳定，几个月不变 |
| 当前项目、当前角色、当前截止日期 | 不该 | 会变；进任务卡或材料（见第 25 篇） |
| 一次性要求（这次要短、这次给三个人看） | 不该 | 只对这一轮有效，写进本轮指令 |
| 硬约束（不能群发、不能付定金） | 不该只进偏好 | 它是权限，要有系统侧的闸门（见第 16 篇） |

最后一行尤其重要：**把权限写进偏好，是把闸门写成了建议。** 偏好会被盖过、会被挤掉、会被取不到；权限不能靠这些。你说过一百次「不要群发」，也不构成一道闸门——闸门在发送那一步的校验里。

这条规矩还可以反过来用，当作一次快速体检：**如果你想把一条信息放进偏好层，先问「它三个月后还会成立吗」。** 会，才放；不确定，就放进任务卡；只对今天有效，就写在这一轮的话里，说完就散。

## 12.7 边界：三列账

| 做法 | 能做什么 | 代价是什么 | 何时失效 |
| --- | --- | --- | --- |
| **会话历史** | 让同一件事在多轮里保持连贯；省掉重复交代 | 占面积；越滚越长；旧错误变成前提 | 换会话、超长截断、需要推翻早期结论 |
| **跨会话偏好** | 省掉重复交代；让输出风格稳定 | 会过期；会冲突；写入容易删除难；每条都占面积 | 任务性质变了；两条矛盾；取回没挑中 |
| **任务状态** | 让长任务可恢复、可交接、可审计 | 要维护边界；状态会串台；回滚不等于撤销副作用 | 换任务没清；动作已发出；状态被摘要压掉 |
| **模型权重** | 不用提醒就带着某种倾向；不占工作台 | 不可定点改；会过期；改一次影响所有人 | 需要按条管理；需要单独撤回；需要版本 |

这张表最贵的一行是「跨会话偏好」。它不是贵在钱，是贵在**维护**：写进去只要一句话，维护它要每个月回来看一次，删的时候还要先找到入口。很多人做到第一步就停了，于是偏好层变成一个只进不出的抽屉。

### 这个类比在这里失效

前面一直用「档案柜」来说记忆：一层一个抽屉，写进去、取出来、不要了撕掉。它在三个地方不成立。

**第一，档案柜里的文件夹不会自己变多，偏好条目会。** 你每说一次「记住」，就可能多一条；系统还会自动抽。柜子会满，而且没人告诉你满了——它只会在某次回答里表现得更迟钝。

**第二，档案柜的抽屉是分开的，四层不是。** 你说的一句话，可能同时进了会话历史、被抽成一条偏好、被写进任务状态。删一个抽屉，另外两个还在。这就是「删了为什么还在」的机制来源——不是删除没生效，是你删的不是它所在的那一格。

**第三，档案柜取东西不影响别的东西，取回要占工作台。** 你从柜子里拿一份文件，桌上不会因此少一块地方；但模型的桌上会。**在这一步，「存储」和「带宽」是同一件事。** 这正是记忆最反直觉的地方：记得越多，不一定用得越好，因为取回本身要花掉本来给材料的面积。

## 12.8 反例与正例：同一件事的两种记法

### 12.8.1 反例：把「记住」当成一个按钮

```text
错链：
遇到重复交代 ──▶ 说一句「记住：……」 ──▶ 它答「好的」
      │
      ▼
三个月里在七个会话里分别说过七次 ──▶ 没有任何清单
      │
      ▼
某次输出不对 ──▶ 问它「你记得我什么」 ──▶ 它列了五条，其中两条是编的
      │
      ▼
想删掉错的那条 ──▶ 找不到入口 ──▶ 只能说「以后别再这样」
      │
      ▼
下一个会话，同样的错又来一次
```

这条链的问题在第二步：**「好的」被当成了「已写入」。** 它只是一句最顺的接话。而第五步说明：没有条目视图，你连「删哪一条」都指不出来——你只能对着一团看不见的东西说「别这样」。

还有一个隐性代价：这七次里，可能有四次说的是同一件事的不同版本（「简洁一点」「别太长」「控制在一屏」「少说废话」）。它们会变成四条并存的偏好，取回时随机挑一条，于是输出在「极简」和「稍微详细」之间漂。**你以为在强调，其实在制造冲突。**

### 12.8.2 正例：把记忆当资产盘点

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| ① 分级 | 把「要它记住的」分成四栏：稳定偏好 / 本轮要求 / 任务状态 / 硬约束 | 四栏，不混 |
| ② 只写第一栏 | 只有稳定偏好进偏好层；其余进任务卡或本轮指令 | 一份不超过十条的偏好清单 |
| ③ 每条带来源 | 记下「什么时候、因为什么」设的这条 | 一张能仲裁新旧的表 |
| ④ 设一个复核点 | 每月或每次换项目时，逐条问「还要吗」 | 一份退场记录 |
| ⑤ 删在写之前 | 改口径时，先删旧条，再写新条 | 不留两版并存 |
| ⑥ 硬约束不进偏好 | 权限与不可逆动作走系统闸门 | 不靠记忆兜底 |

```text
对链：
分级 ──▶ 只写稳定项 ──▶ 每条带来源与日期 ──▶ 定期复核 ──▶ 先删后写 ──▶ 权限另设闸门
（有边界）  （有节制）      （可仲裁）          （会退场）    （不并存）    （不靠记性）
```

第③步最容易被跳过，但它决定了一切：**没有来源和时间，两条矛盾时你只能猜。** 而这正是「它记得的是上一版」最常见的成因——不是它选错了，是你没有给它一个能判断新旧的依据。

第④步是这套做法里唯一需要「定期」的，也是最容易被跳过的。但记忆这件事的性质就是：**它不会自己变干净。** 一个季度不看，偏好层就会变成一个混合了三个项目、两个岗位、四种写作要求的抽屉。

第⑥步再说一遍：**记忆不是权限。** 这句话在 12.6.3 出现过一次，在这里是它的操作版：凡是「做了就收不回」的动作，它的闸门必须在发送那一步，不能寄存在「它应该记得我说过」。

### 12.8.3 一个中间态：只用一个会话，也是一种策略

不是所有任务都需要跨会话记忆。反过来说，**大多数一次性任务，最好的记忆策略是「不记忆」**：开一个新会话，把这一轮需要的材料、约束、验收标准一次说清，做完就关。

这样做有三个好处：没有旧条目干扰；没有历史占面积；不需要维护退场机制。代价是每次都要重新交代——但这个代价是可见的、一次性的，而记忆腐化的代价是隐性的、累积的。

所以真正的分界不是「用不用记忆」，是：**这件事会不会重复到值得为它建一份档案？** 会重复、且要求稳定，才建；只做一次，就别建。

## 12.9 你可以自己做的检验

一个主检验，十分钟；两个补充，各五分钟。都不需要写程序。

### 12.9.1 主检验：让它自述记忆，再对照你设过的（10 分钟）

**准备**：一张纸，写下你在某个产品里**确实设过**的偏好——设过几条写几条，包括大概的时间和原因。没设过就写「无」。

**做法**：

1. 新开一个会话。不要用旧会话，旧会话里有历史，会污染结果。
2. 问三句，一次一句，不要合并：
   - 「你现在关于我，记住了什么？逐条列出来。」
   - 「每一条是从哪来的？是我明确说的，还是你推断的？」
   - 「每一条大概是什么时候记的？」
3. 拿它的回答，逐条对照你那张纸。

**四种结果，四个断点**：

| 它的回答 | 说明什么 | 下一步查什么 |
| --- | --- | --- |
| 条目基本对得上，来源和时间也对得上 | 这一层有可见条目，且被取到了 | 查更新：有没有已经该退场的旧条 |
| 条目对得上，但说不出时间和来源 | 条目在，元数据不在 | 你无法仲裁新旧；考虑自己维护一份清单 |
| 列出的比你设的多 | 有自动抽取的条目，或它在推断 | 去设置里找条目视图；找不到就按「不可控」处理 |
| 列出的比你设的少，或说「没有」 | 没写入，或这次没取到 | 新会话单问一条；仍然没有，就是没写入 |

**这个检验有一个陷阱，必须先说**：它的自述本身也可能是编的。

「我记得你喜欢简洁」这句话，可能来自权重里的通用倾向，可能来自本轮你说的话，也可能只是接得顺。所以**判据不在它说了什么，而在它说的和你纸上写的是否对得上**，以及你能不能在实际的条目列表里看到。这就是第 4 问：**不能独立验证的记忆自述，按「没有」处理。**

如果它列得头头是道、而你根本没设过——这个结果比「它忘了」更值得记下来。它说明这套系统在用「像记忆的措辞」填补空白，而空白被填满之后，你更难判断哪条是真的。

### 12.9.2 补充一：换会话，同一条偏好（5 分钟）

在 A 会话里说「记住：结论放最前面」。新开 B 会话，只问一个中性问题，看它是否结论前置。再新开 C 会话，问「你记得我什么」。

**判据**：B 做到了、C 列出来了 → 写入与取回都成立；B 没做到、C 列出来了 → 取回没挑中，或被这轮材料盖过；B、C 都没有 → 写入没发生。

**三种情况的修法完全不同，这就是为什么要分两步问。** 只问 B，你会把「取回失败」误判成「写入失败」，然后反复说「你要记住啊」——而它其实早就存了。

### 12.9.3 补充二：删一条，看它还在不在（5 分钟）

找一条你现在不想要的偏好，按产品给的入口删掉。然后新开会话，问同一个中性问题，看旧偏好是否还生效。

**判据**：还生效 → 你删的可能不是它生效的那一层（比如删了会话，没删条目）；不生效了，但旧会话里还提 → 正常，那是历史，不是偏好；完全不提了 → 这一层可删、可验，可以放心用。

这个检验还有一个副产品：**它会告诉你这个产品的删除入口是不是真的。** 有的入口删的是「显示」，不是「存储」——界面上不见了，行为还在。这种情况你只能按「不可删」处理，并相应减少写入。

### 12.9.4 记录表

| 检验 | 固定什么 | 只改什么 | 观察什么 | 什么结果会推翻文中结论 |
| --- | --- | --- | --- | --- |
| 自述对照 | 同一产品、同一账号 | 问法（分三问） | 条目、来源、时间能否对上 | 它每次都能稳定列出可核的条目与时间 |
| 换会话 | 同一句偏好 | 会话 | 是否跨会话生效 | 换会话后完全不生效，且条目列表里也没有 |
| 删一条 | 同一条偏好 | 删与不删 | 行为是否变化 | 删了之后旧偏好仍稳定生效，且找不到其他入口 |

## 12.10 术语考古：记忆、个性化、会话

三个词在会议里最容易被当成同义词。甲说「它的记忆不好」，可能指跨会话没生效；乙说「记忆不好」，可能指历史太长把开头挤掉了；丙说「记忆不好」，可能指它把三个月前的项目当成现在的。三个人在说三件事。

### 记忆

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 借自心理学与认知科学里的「记忆」：编码、存储、提取。工程与产品文档把它借过来，指「跨请求保留信息」。**属于跨领域借用的通行说法，没有统一规范定义，也没有单一发明人；本篇不指认具体年份与文献。** |
| 原义 | 一个分阶段的过程：先写入，再保持，再在需要时提取；提取会失败，也会被后来的信息改写。 |
| 现在被怎么用 | 混指四件不同的事：会话历史、偏好条目、任务状态、以及「微调过的模型」。产品界面上的「记忆」按钮管哪一层，**因产品与版本而异**，本文不指认。 |
| 本文怎么用 | 只指**应用层为跨会话保留的条目**（第二层），并且每次使用都必须回答「哪一层、谁写的、什么时候取、怎么删」。提到权重时会明说「权重」，不叫记忆。 |

### 个性化

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 推荐系统与营销领域的通行说法：按用户特征调整呈现内容。**社区与行业用语，没有统一定义；本篇不指认具体出处与年份。** |
| 原义 | 调整**呈现与排序**，让不同的用户看到不同的东西；它本身不承诺「保存」。 |
| 现在被怎么用 | 被等同于「AI 懂我」，进而被等同于「它把我的事都存下来了」。两个等号都不成立。 |
| 本文怎么用 | 指**按账户调整输出与取回策略**。个性化可以完全不依赖长期存储——它可能只是这一轮读了你的材料，或者用了权重里的通用倾向。**个性化 ≠ 永久保存。** |

### 会话

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 通信与网络里的「会话」（session）：一次有开始、有结束的连接。聊天产品借来表示一段对话线程。**工程惯例，无统一规范定义。** |
| 原义 | 一个有边界的交互单元：开始、进行、结束；结束后资源释放。 |
| 现在被怎么用 | 被当成「记忆的容器」和「记忆的边界」两种意思混用；「换个会话」有时指清空上下文，有时指换一个话题，有时指换一个账号。 |
| 本文怎么用 | 只指**对话线程这个容器**。它是四层里寿命最短的一层；换会话清掉的是第一层，不是第二层，更不是第四层。 |

三个词共同的毛病，和 05、07 那几组一样：**把「一个界面上的按钮」，说成了「一种能力」。** 按钮背后可能是四层里的任意一层，也可能只是一段拼进请求的固定文本。问清「它管哪一层」，比争论「它算不算记忆」有用得多。

## 12.11 一页速记

| 你看到的现象 | 最可能在哪一层 | 先做什么 |
| --- | --- | --- |
| 换个会话它还知道我的偏好 | 跨会话偏好 | 去设置里看有没有条目；有就查来源和时间 |
| 同一会话聊久了，开头的事它不认了 | 会话历史 | 查历史长度与截断；新开会话，把结论重述一遍 |
| 它用的是半年前的设定 | 偏好过期 | 找到旧条删掉，再写新条；不要只加新的 |
| 它把上个任务的约束带过来了 | 任务状态串台 | 查任务边界；新任务里显式写「与上一任务无关」 |
| 我没设过偏好，它却「很懂我」 | 权重倾向，或本轮材料 | 问它「这条从哪来」；答不出就是推断 |
| 它说「我记住了」，下次却没用 | 写入或取回 | 新开会话单问一条；再查这轮材料是否把它挤掉 |
| 删了聊天记录，它还记得 | 你删的是第一层 | 去删偏好条目；找不到入口就按「不可删」处理 |
| 它对「忘掉」答应得很痛快 | 这是一句措辞 | 去条目列表看；看不到就按「没删」处理 |

**五句话带走**

1. 记忆不是一个器官，是四层存储加四个动作；只有权重在模型身上，其余三层都是系统替它保管的。
2. 记得 ≠ 这次会取。取回是组装工作台时的一次挑选，有预算、有排序、会被挤掉。
3. 记忆的失败多数不是「存不下」，是「没更新」和「没删旧的」；加一条谁都会，撤一条才见设计。
4. 个性化不等于应该永久保存；「删除」要先问删的是哪一层，四层的删除方式互不通用。
5. 它的记忆自述不是证据；能对照的只有条目列表、来源、时间，以及你自己那张纸。

**三道自检**

1. 同事说：「我在设置里把聊天记录全删了，它现在应该什么都不记得了。」这句话漏了哪几层？你会怎么验？
2. 它在新会话里主动说「按你的习惯，金额保留两位小数」。你怎么判断这是偏好层、是权重倾向，还是这一轮材料里写的？
3. 你想把「金额一律整数元」这条新口径加进去。直接说「记住：金额用整数」有什么风险？正确顺序是什么？

1. 漏了至少三层。删聊天记录清的是会话历史（第一层）；偏好条目可能还在（第二层），任务状态可能还在（第三层），权重（第四层）从来不会因为删记录而改变。验法：新开会话，问「你现在关于我记住了什么，每条从哪来」；再对照设置里是否还有条目。如果它仍能说出偏好，而条目列表里也有，说明第二层没删；如果条目列表是空的、它却仍然「像记得」，那更可能是权重倾向或本轮材料，不是存储。三种结果对应三个不同的修法，不能用「再删一次」通吃。

2. 三种来源在行为上几乎一样，要靠三步分开：第一，看这一轮你有没有给材料——给了就先怀疑材料，尤其是你恰好贴过一张带金额的表；第二，看新会话、无材料时它是否还这样——还在，才轮到偏好或权重；第三，问它「这条从哪来、什么时候记的」——能指到条目和时间的，是偏好层；说不出、但你确实设过的，可能是偏好层但缺元数据；你从来没设过，那多半是权重带来的通用倾向，或者它在顺着「金额」这个词续写。**判据不在它说得多像，而在你能不能看到条目。** 另外要留意：如果它对所有人都这么说，那就是第四层，不是关于你的记忆。

3. 风险是「再写一条」而不是「改那一条」：旧条还在，两条并存，取回时挑中哪条不确定，于是它会在整数和两位小数之间摇摆——这正是 07 篇「两版并存等于固化摇摆」的同一个形状。正确顺序：先找到并删除旧条（或明确标注作废），再写新条；写完新开会话验一次，确认输出稳定；如果找不到条目入口，就别把它放进偏好层，改成每轮任务卡里的一句话，或写进材料。**先删后写，不是先写后忘。**
