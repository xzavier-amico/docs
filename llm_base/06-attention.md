## 06.1 引子：两句「苹果」

先把两句话放在一起：

> 甲：这个苹果很甜，你尝一口。
>
> 乙：苹果发了新品，门店排队到街角。

任何一个识字的人，都不会觉得这里有歧义。甲里的「苹果」是水果，乙里的「苹果」是一家公司。两个「苹果」写出来一模一样，读音一样，笔画一样，可你几乎没有停顿就分开了。你甚至说不出自己是怎么分的——大概是「甜」和「新品」替你分的。

模型也能答对。你把它俩放进同一条消息，问「两句里的苹果各指什么」，它通常会给出一份正确的对照。这件事看起来平平无奇，直到你追问一句：**它里面并没有两个「苹果」词条。** 词表里只有一个编号，查表得到的只有一个初始向量。那么，第二个「苹果」是从哪里变出另一层意思的？

这就是本篇要走的路线。不是从「苹果」讲到「水果公司」，而是从「同一个编号」走到「两次不同的上下文表示」，看看中间到底发生了什么。走完之后，你会得到一句能用来判断很多说法的话：

> **注意力是「加权取信息」的机制，不是「关注」、不是「思考」，也不是解释。**

这句话听上去像在抠字眼，但它决定你怎样看待那些很漂亮的热力图，决定你会不会把「模型关注了第三段」写进验收报告，也决定你在长材料答错时，第一步是去查输入，还是去怪它「没认真看」。

先提醒一个最常见的误会：**「苹果」的两种意思，不是模型内部存了两个释义，也不是它在某一刻查了一次词典。** 它没有一个叫「苹果」的条目，翻开写着「水果；亦指公司」。它有的是一串向量、一层一层的混合，以及最后用来给下一个片段打分的那个表示。意思是在这条路径上**长出来**的，不是被**取出来**的。这两种说法听起来只差一点，实际上决定了整篇文章的走向。

## 06.2 唯一真问题

**同一个词，在不同句子里为什么会得到不同的表示？**

短答案只有一句：**因为它在每一层，都只从允许看到的位置取信息，并按学出来的匹配程度混合；句子不同，能取到的那一圈信息就不同。**

拆成三步，每一步都不涉及公式：

1. **起点相同。** 同一个词对应同一个词表编号，查表得到同一行初始向量；如果位置也相同，那么它进入第一层时几乎是一样的。
2. **取法不同。** 每一层，这个位置都会向「允许它看的位置」提出一次取信息的请求，再按匹配程度，从那些位置取走不同比例的内容，混进自己的表示里。
3. **结果不同。** 甲句里，它能取到「甜」「尝一口」这一类信息；乙句里，它能取到「新品」「门店」「排队」这一类信息。混进来的东西不同，后面每一层再加工的基础就不同，最后用于判断「苹果指什么」的表示也就不同。

这里要立刻加一个限定，否则第三步会被误读：**「它自己那个位置」和「用来回答问题的那个位置」，不是同一个位置。** 在从左往右生成的模型里，一个词所在的位置只能看见它左边的内容；如果「苹果」是句子的第一个词，那么它那个位置的表示，在甲乙两句里其实可以是一样的。真正的区分发生在后面：读到「甜」的位置时，它回头把「苹果」取过来；读到「新品」的位置时，它也回头把「苹果」取过来。两个靠后的位置各自混出了不同的东西，答案从那里出来。

所以更准确的说法是：**同一个词本身没有变，变的是围绕它被汇总起来的那一圈信息。** 日常说「苹果的向量变了」，是一句方便的缩写；写验收、写解释时，最好把这句话拆开，否则你会以为模型里真有一个可以单独拎出来的「苹果含义」，而它并不存在。

由此得到本篇的判断句，也就是你要带走的那一句：

> **注意力是「加权取信息」的机制，不是「关注」、不是「思考」，也不是解释。**

三个否定，各挡一种常见的错法：

- **不是「关注」。** 「关注」暗示有一束光打过去，有一个主体在选择看哪里。这里没有光束，只有一组比例；每个允许看的位置都会分到一点，只是分多分少。
- **不是「思考」。** 它没有「先想一步、再想一步」的推理步骤。它是在一层里做一次混合，然后把结果交给下一层。多层叠加之后可以表现出像推理的行为，但那是许多次混合与生成累积出来的效果，不是这个动作本身。
- **不是「解释」。** 权重不是理由。权重只说明「这一层、这一次、这个头，把多少比例分给了谁」，不说明「模型为什么得出这个结论」。后者是另一件事，而且通常只能靠干预和外部证据来判断。

把全书的四问拿来对准「注意力」这个说法，会得到一张很实用的对照表：

| # | 问 | 用在「注意力」上 |
| --- | --- | --- |
| 1 | 这句话是谁说的？ | 热力图是可视化工具画的；模型说「我关注了第三段」，是它生成的一句话，不是内部记录 |
| 2 | 它这一轮看见了什么？ | 那句话在不在本轮输入里？被切成了哪些 Token？在第几位？ |
| 3 | 这是提议、事实，还是已经执行？ | 「模型看了这句」是解释性描述，不是可观测的事实；没有「已看」这个状态 |
| 4 | 我拿什么独立验证？ | 改掉、删掉或替换那一句，其他条件不变，看输出变不变；不听它自述 |

第 3 问在这里尤其容易被跳过。人会说「它看了」，是因为人习惯用「看」来解释别人的行为；但模型没有眼睛，也没有一个可以被读出的「看过了」的标记。你能查的是输入清单，你能做的是对照实验，你不能查的是「它的目光落在哪里」。

本篇的结论也可以用一句可操作的话来检验：**如果一张图不能预测「改动哪里会让输出变化」，它就不是因果解释。** 注意，是「预测改动后的变化」，不是「看起来很像人在看」。这两件事差得很远。

## 06.3 一张图：从两个字符到一次判断

先看整条链路里谁在做什么。这张图的作用不是让你记住每个方框的名字，而是让你看到：**「苹果」变意思这件事，横跨了人、应用、模型三个位置，任何一个位置出问题，最后的答案都可能不对。**

```text
人：写下「这个苹果很甜」与「苹果发了新品」
  │
  ▼
应用：把文本切成 Token，按模板拼成本轮输入
  │    〔指令〕〔第一句〕〔第二句〕〔问题〕
  ▼
模型：查表 → 加位置 → 第 1 层 → 第 2 层 → … → 第 N 层
  │        每一层大致做两件事：
  │        ① 从允许看到的位置取信息并混合（注意力）
  │        ② 对每个位置的内容再做一次加工（前馈）
  │        两条路都保留原来的自己（残差），避免越算越丢
  ▼
上下文表示：用来给「下一个片段」打分（P1）
  │
  ▼
应用：把选出的 Token 拼回文本
  │
  ▼
人：读到「甲指水果，乙指公司」，再决定信不信
```

图里最容易被忽略的是中间那一行小字：**每一层做两件事，不是只做注意力。** 很多人把 Transformer 讲成「一层注意力接一层注意力」，仿佛信息只在注意力里流动。实际上，注意力负责「从别处取」，前馈负责「在本地加工」，残差负责「别把原来的东西丢了」。这三条路一起决定下一层的输入。后面讲「权重高不等于重要」时，这一点是主要原因之一。

再把「一个 Token 怎么变成上下文表示」单独展开：

```text
Token「苹果」
   │  它在词表里的编号（一个整数，不是含义）
   ▼
查表 ──▶ 初始向量（一组数，示意：0.2、-0.1、0.7……）
   │
   │  加上「它在第几位」的信息
   ▼
第 1 层：向允许看到的位置取信息，混合
   │
第 2 层：在上一层的结果上，再取一次、再混一次
   │
  …
   ▼
第 N 层：这个位置的上下文表示
   │
   ▼
交给输出层，给「下一个片段」打分
```

这张图里的层数、箭头和「每一层只做一次取信息」都是示意。真实模型可能在注意力内部再有拆分，可能对位置采用不同的注入方式，也可能在层与层之间做归一化。**图的作用是让你分清顺序，不是让你以为所有模型都长这样。**

### 编号不是含义

词表是一张「编号到初始向量」的对照表。同一个词，编号相同，查到的行也相同。这件事很重要，因为它解释了为什么「同一个词」在起点上确实是一样的：模型并没有为每个句子准备一份不同的词表。

但编号本身不带含义。它只是一个门牌号。门牌号 4711 不代表「水果」，也不代表「公司」；它只告诉你「去第 4711 行取那组数」。

### 向量不是释义

查表得到的那组数，也不是一句可以读出来的解释。你没法指着某一维说「这一维是水果，那一维是公司」。意义分布在整组数的相对关系里，而且是训练过程中为了「预测下一个片段」慢慢调出来的，不是人手工标上去的。

这一点值得多说一句，因为它是很多误解的源头。有人会说「模型把苹果表示成了水果」，仿佛向量里写着一个标签。更准确的说法是：**这组数在模型的运算里，恰好能让它在这种情况下接出更合适的下文。** 它是不是「表示成了水果」，要看你怎么定义「表示」；但至少，它不是一条可以翻开的词典释义。

### 位置为什么必须单独加

注意力本身做的是「拿当前这个词去和别的位置比对」。如果只比对内容，不考虑顺序，那么「狗咬人」和「人咬狗」在它眼里就是同一袋词：都有「狗」「咬」「人」，只是摆放顺序不同。可这两句话的意思完全不同。

所以位置信息必须单独注入。不同模型的办法不一样：有的把位置编码加进初始向量，有的在比对时引入位置关系，有的用别的方式。本篇不展开这些差别，只需要记住结论：**同一个词出现在不同位置，进入第一层时的起点就不完全相同；而它能看到的位置范围，也由位置决定。**

### 多层：不是一次到位，而是反复改写

第一层取到的信息，不是最终答案。它只是让每个位置得到一份新的、混合过的内容；第二层再在这份内容上重新提问、重新取、重新混。层数越多，一个位置能间接利用到的范围通常越广，但这不是无条件的：信息可能在混合中被稀释，也可能被后续层覆盖。

所以「苹果指什么」不是在第一层就定死的。它是一个逐层汇总的结果。你在第一层看到的某个权重，和在最后一层影响输出的那个表示，中间隔着很多次再加工。这也是为什么「拿某一层的图当理由」特别危险：**你看到的是中途快照，不是判决书。**

## 06.4 机制一：查表只是起点

### 同一个编号，同一行数

假设「苹果」在词表里对应编号 4711。无论它出现在甲的「很甜」前面，还是乙的「发了新品」前面，查表都去第 4711 行，取同一组初始向量。模型不会因为句子不同，就去另一行取一个「公司版苹果」。

这一步经常被讲反。有人以为模型里有一个「多义词词典」，遇到不同上下文就查不同的义项。不是。**词表只负责把符号变成起点；消歧发生在后面，不在查表这一步。**

### 初始向量是学出来的，不是写出来的

这组数从哪来？从训练里来。训练时，模型不断调整这些数，让「在这个位置接出真实下文」这件事做得更好。调整的结果是：经常出现在相似上下文里的词，往往会在向量空间里靠得比较近；但这不是人给它们分的类，也没有一条规则保证「水果义」和「公司义」各占一块。

这里要小心一个流行的说法：「向量空间里，苹果离水果近，离公司远。」这句话在某些模型、某些测量方式下可能有它的道理，但它不能反过来当成解释：**你不能因为两个向量近，就断定模型在这个句子里取了「水果义」。** 近不近是一回事，这一轮实际混进了什么、最后输出了什么，是另一回事。

查表和查词典的差别，可以列成一张小表：

| | 查词典 | 查词表 |
| --- | --- | --- |
| 得到什么 | 一条可读的释义，可能还有例句 | 一组数，没有可读释义 |
| 有几个结果 | 一个词可能列多个义项 | 一个编号只对应一行初始向量 |
| 后面还会不会变 | 不会，释义就是终点 | 会，每一层都会改写它 |
| 谁写的 | 人编纂的 | 训练调出来的 |

最后一行是关键：**词典的条目是终点，词表的行是起点。** 把起点当终点，就会得出「模型里存着苹果的两种意思」这种结论；而实际上，模型里只有起点和一套取信息的规则。

### 位置的注入，不等于「第几个字」的标签

位置信息也不是简单地贴一个「我是第 3 个字」的纸条。模型需要从位置关系里学到「谁在前、谁在后、隔多远」这类可用于比对的东西。不同模型的做法不同，但目的相同：让「顺序」成为可计算的一部分。

这带来一个直接后果：**同一个词在不同位置，起点就不完全相同。** 甲句的「苹果」在句首，乙句的「苹果」也在句首，位置相同，起点可以一样；但如果换成「我咬了一口苹果」和「我买了一点苹果公司的股票」，两个「苹果」左边的东西不同，位置也不同，进入第一层时就已经分开了。

### 谁的表示变了：一个必须说准的细节

这是本篇最容易讲错、也最值得讲清的一处。

在从左往右生成的模型里，位置 i 的表示只能依赖位置 i 及它左边的内容。也就是说：

- 「苹果」自己那个位置，看不到它右边的「很甜」或「发了新品」。
- 如果「苹果」在甲乙两句里都是第一个词，那么它自己那个位置在每一层的表示，可以是一样的。
- 真正把「甜」和「新品」纳入进来的，是后面的位置：读到「甜」时，那个位置回头取「苹果」；读到「新品」时，那个位置也回头取「苹果」。取到的内容不同，后面混出来的表示就不同。

所以「同一个词得到不同表示」这句话，要分两种读法：

| 读法 | 准不准 | 说明 |
| --- | --- | --- |
| 苹果那个位置的向量在两句里不同 | 不一定 | 如果它是句首且左边没有内容，它自己看不到右边，位置也可能相同 |
| 围绕苹果汇总出来的上下文表示不同 | 准 | 后面的位置会把右边的新信息取进来，判断「指什么」用的是靠后的表示 |
| 模型里存了两个苹果词条 | 不准 | 词表只有一行；变的是取信息的范围和混合结果 |

这张表的意义不在抠字眼，而在防止一种很常见的错误：**把「上下文表示」说成「词的新释义」。** 前者是一个位置在某一层的状态，后者是一个可以独立保存、独立查询的条目。模型没有后者。你如果按后者去理解，就会以为「只要找到那个表示，就能读出它认为苹果是什么」；实际上，那个表示是跟整句话、整个位置绑在一起的，离开这一轮就不成立。

## 06.5 机制二：查询、键、值——加权取信息

现在讲三件套。名字听起来很技术，其实可以用一个资料室的比喻讲完。讲完之后，我会立刻说清这个比喻在哪一步不成立——那一步才是重点。

### 比喻：一张便条，一排标签，几个文件夹

想象一间资料室，墙上排着一排文件夹。

- 你手里拿着一张便条，上面写着「我这次想找什么」。这叫**查询**。
- 每个文件夹的脊背上贴着一张标签，写着「我这里大概装了什么」。这叫**键**。
- 标签对上了，你就从那个文件夹里抽出几页。抽出来的内容叫**值**。
- 抽多少，不按你的心情，按便条和标签的匹配程度分配：最对得上的抽得多，不太对得上的抽得少。
- 最后，你把抽到的几页订成一份，变成你这一轮的新材料。

换成模型的语言：

| 名字 | 在比喻里 | 在模型里 | 谁决定 |
| --- | --- | --- | --- |
| 查询 | 你手里的便条 | 当前这个位置在这一层「想取什么」 | 由当前表示经训练得到的变换算出 |
| 键 | 文件夹脊背上的标签 | 每个可看位置「我能提供什么」 | 由那个位置的表示经训练得到的变换算出 |
| 值 | 文件夹里的纸 | 那个位置真正被取走的内容 | 同样由训练得到 |
| 权重 | 每个文件夹抽多少页 | 匹配分数归一化后的比例 | 学出来的，不是人分配的 |

每个位置都会做这件事，而且是同时做：甲位置的「苹果」向它左边取，乙位置的「甜」也向它左边取。取完之后，每个位置都得到一份新的混合内容，成为下一层的输入。到下一层，便条会重新写——因为上一层混进来的东西，已经改变了这个位置「想找什么」。

把一次取信息画出来，大概是这样（数字是示意，不对应任何真实模型）：

```text
当前位置：第 L 层的「苹果」
  │  提出「我这次想找什么」= 查询
  ▼
┌──────────── 允许看到的位置 ────────────┐
│  词 1：标签与查询比对 → 0.5 → 取 50% 内容 │
│  词 2：标签与查询比对 → 0.3 → 取 30% 内容 │
│  词 3：标签与查询比对 → 0.2 → 取 20% 内容 │
└──────────────────┬────────────────────┘
                   ▼
        混合后的内容 ＋ 原来的自己（残差）
                   ▼
             第 L+1 层的输入
```

这里有两个容易被图掩盖的事实。

第一，**权重是比例，不是开关。** 三个位置加起来是 100%，不是「选一个、其余丢掉」。即使某个位置完全不相关，它也可能分到一点点；反过来，最相关的位置也未必拿到全部。这解释了为什么一句无关的话混进材料里，有时也会微妙地影响输出：它不是被「忽略」，而是被分到了一个不小的份额。

第二，**没有「这次不取」的按钮。** 便条和所有标签都不匹配时，它仍然要按现有比例把内容混进来。人可以说「这里没有我要的，我去别处找」；模型不能。它只能在允许看到的位置里分完这 100%。这一点是后面「长材料里看见却没取到」的机制根源之一。

### 这个比喻在哪一步失效

比喻好用，但它有五个具体的失效点。每一个都对应一个真实的误判。

**失效点一：便条是「算出来的」，不是「想要的」。** 资料室里的人是先有意图，再写便条；模型没有意图，它的查询是当前表示经过一组训练得到的变换算出来的。所以你不能问「它为什么想找这个」，只能问「在当前表示下，它算出的查询更接近哪些键」。前者是心理学问题，后者才是机制问题。

**失效点二：标签不是人写的摘要，可能和内容错位。** 资料室的标签通常准确；模型的键是学出来的，它可能对某些查询特别敏感，却不代表那个位置的内容真的有用。**匹配高，不等于内容对。** 一句格式漂亮但事实错误的材料，完全可能比一句措辞朴素但关键的真话更容易被取到。

**失效点三：不是查一次，是每层都重查。** 资料室的人查完一次就写报告；模型每一层都会重新发便条，而且上一层取回来的内容会改变下一层的问题。你在第一层看到的「它在找甜」，到第五层可能已经变成「它在找一种能接下去的食品描述」。**拿某一层的取法代表整个过程，是把中途站当终点。**

**失效点四：取回来还要再加工，不是直接拼进答案。** 资料室里抽出的几页会原样订起来；模型取回的值会经过前馈、残差、归一化，再进入下一层。也就是说，**取到 ≠ 保留 ≠ 影响输出**。中间还有两道加工，任何一道都可能改变最终结果。

**失效点五：它不能起身去别的房间。** 资料室的人可以出去找更多资料；模型只能在这次允许看到的位置里取。材料没送进来、被截断、被切碎，它就没有那一页。这是 P2 的地盘，详见 05；本篇只负责说清：**注意力不能凭空变出没在窗口里的信息。**

把这五条记住，你就能挡住大部分「它关注了所以它懂了」的说法。因为「关注」这个词，恰好把「有意图」「标签准确」「一次查找」「取到就用」这四个假设全带进来了，而它们一个都不成立。

## 06.6 机制三：因果遮罩——为什么看不见右边

生成是从左往右的。写到第 t 个位置时，第 t+1 个位置的内容还不存在——它正是接下来要被选出来的东西。所以模型在处理第 t 个位置时，不能让它看到右边。

这不是「设计者觉得这样比较好」，而是**任务本身决定的**。如果训练时让第 t 个位置看到第 t+1 个 Token，模型就会学会「抄答案」；而到了真正生成时，右边根本没有答案可抄，训练和使用的条件就对不上。为了让两边的条件一致，必须在训练时也把右边遮住。

遮罩的形状，可以画成一张「谁能看谁」的表。四个位置，行是「正在处理谁」，列是「能看谁」：

| 正在处理的位置 | 位置 1 | 位置 2 | 位置 3 | 位置 4 |
| --- | --- | --- | --- | --- |
| 位置 1 | 可看 | 遮住 | 遮住 | 遮住 |
| 位置 2 | 可看 | 可看 | 遮住 | 遮住 |
| 位置 3 | 可看 | 可看 | 可看 | 遮住 |
| 位置 4 | 可看 | 可看 | 可看 | 可看 |

这张表只表示「允许不允许」，不表示权重大小。对角线及其左下方是可看的，右上方是遮住的。位置越靠后，能看的东西越多；最后一个位置能看全部，因为它前面的一切都已经写出来了。

### 为什么整段输入还能一起算

有人会问：既然不能看右边，为什么处理一整段材料时，不是从左到右一个一个来，而是可以一起算？

因为「不能看右边」约束的是**每个位置能看到谁**，不是「必须等前一个位置算完」。在同一个层里，位置 2 要看的「位置 1 的上一层结果」已经存在了；它不需要等位置 1 在这一层算出新结果。所以多个已知位置可以在同一层里并行处理，同时各自遵守「只看左边」的限制。层与层之间仍然有先后：第 2 层要用第 1 层的结果。

但生成时情况不同：下一个位置的内容还没有被选出来。先选「甜」和先选「酸」，后面面对的输入就不同。**已知输入可以成批算，不等于未知的输出可以当成互相独立的题。** 这也是 08 篇讲 Prefill 与 Decode 时要分开的原因。

### 遮罩的直接后果：一个词自己看不到右边

回到「苹果」。如果它在句首，它自己那个位置在每一层都看不到「很甜」或「发了新品」。这不是模型的缺陷，是因果结构的必然。

那它怎么知道「苹果」指什么？答案是：**它自己那个位置不需要知道，后面的位置知道就够了。** 读到「甜」的位置时，它已经把「苹果」取进来了；读到「新品」的位置时，它也已经把「苹果」取进来了。最后用来判断「苹果指什么」的，是靠后的那个表示，不是「苹果」自己那一格。

这个细节能挡掉一种很常见的错误解释：「模型在苹果这个词上就已经决定了它是水果。」在句首的情况下，那个位置没有足够的信息做这个决定；决定是在后面形成的。你如果拿「苹果」那一格的注意力图去证明「它早就知道」，你证明的只是「它当时看了自己左边」，而左边可能什么都没有。

### 遮罩挡不住什么

因果遮罩只挡「位置」。它挡不住模型从训练里学到的「苹果后面通常接什么」这类统计倾向。也就是说：

- 它看不到右边的 Token，但它可以「猜」右边大概会出现什么；
- 遮罩不是事实过滤器，不会因为它看不见右边就变得更可靠；
- 遮罩也不等于「模型理解了时间顺序」，它只是一个信息流约束。

把这三条分开，就不会把「看不见未来」误读成「不会预测未来」。恰恰相反，**它之所以要预测下一个，就是因为它看不见下一个。** 如果它看得见，这个任务就没有意义了。

## 06.7 机制四：多头——同一层里并行几种比对

一层里不只做一次「查询—键—值」，而是同时做很多组。每一组有自己的查询、键、值变换，各自算出自己的一份混合结果；最后把这些结果合并起来，成为这一层的输出。这个「很多组」就叫多头。

为什么需要多头？因为一次比对只能表达一种「像不像」。同一个词在同一层里，可能同时需要判断几种不同的关系：它和前面的主语有没有关系、和最近的动词有没有关系、和某个否定词有没有关系、和远处的限定语有没有关系。用一组固定的比对方式，未必能同时装下这些不同的关系；多组并行，等于在同一层里提供了几种不同的「提问方式」。

可以用一个比喻：同一份档案，派几个人各拿一张不同的便条去查，回来把几份摘要合成一份。这个比喻抓住了「并行」和「合并」，但它在三步上不成立。

**失效点一：不是科室分工。** 没有人规定「第一组管语法、第二组管语义」。组的角色不是设计出来的，是训练中自己形成的；即使某些组在某些输入上表现出某种偏好，也不能推广成「这一组就是干这个的」。

**失效点二：不保证几组问得不一样。** 它们可能学到很相似的比对方式，做重复劳动。多组的存在提高了容量，不保证多样性。

**失效点三：合并不是投票。** 不是「三份摘要里有两份这么说，就采用这个结论」。合并是按训练得到的方式把几组结果拼起来、再变换一次；哪一组影响大，取决于后续的权重和输入，不取决于「少数服从多数」。

所以看到「有的头管语法，有的头管语义」这种说法，最好的反应不是记下来，而是问：**这是在哪一层、哪个模型、哪些输入上观察到的？换个输入还成立吗？把那个头关掉，输出变了吗？** 如果答不上来，它就是一个听起来很顺的故事，不是一个可用的结论。

多头还带来一个解释上的后果：**单个头的图，比整层的图更弱。** 整层的图已经是多个头合并后的结果；单个头的图只是其中一组比对。你从一组比对里看出「它在看甜」，不代表这一层最终用了甜，更不代表后面的层沿用了这个判断。

## 06.8 三条纪律：注意力图不能当证据

前面讲的是它怎么工作。这一节讲的是它不能被拿来证明什么。三条纪律是全篇的骨头，每一条都对应一种很常见的误用。

### 纪律一：注意力权重高 ≠ 因果重要

**常见说法**：「这个位置权重 0.8，说明模型最依赖它。」

**为什么不对**：权重是「当层、当次、当头」的混合比例。它只描述这一层这一个头分了多少比例给某个位置，不描述这个位置对最终输出的影响。原因有四条：

1. **后面还有加工。** 混合完还要过前馈、残差、归一化，再进下一层。权重高只说明「取进来的多」，不说明「留下来的多」。
2. **信息可能冗余。** 同一个信息可能分布在好几个位置。你把权重最高的那个位置遮掉，其他位置可能补上，输出几乎不变。反过来，一个权重不高的位置，可能装着唯一的否定词或限定词，删掉它整句意思就翻了。
3. **权重是相对的。** 可看的位置少时，每个位置分到的比例自然高；可看的位置多时，最高权重也可能不高。拿两个候选数量不同的位置比「谁更重要」，没有意义。
4. **头与头之间会重叠。** 一个头给出的高权重，可能被另一个头的相反结果抵消。单看一个头，等于只看一只手。

**怎么判断因果重要**：只能做干预。把那个位置遮掉、换掉、挪走，其他条件不变，看输出变不变。变，说明它有因果作用；不变，说明它可能被别的路径补上了。**权重图能告诉你「去哪里做干预」，不能告诉你「干预的结果」。**

这条纪律还解释了一个常见困惑：为什么有些高权重的位置看起来「没什么用」？因为它可能只是在提供一种格式、一个常见的连接词，或者它的信息在别处已经有了。**「取了很多」和「非它不可」是两件事。**

### 纪律二：注意力图 ≠ 模型的理由

**常见说法**：「图显示它关注了第三段，所以它是根据第三段得出结论的。」

**为什么不对**：图是人做出来的。选哪一层、哪个头、怎么归一化、用什么颜色、阈值定在哪，都会改变你看到的形状。换一层，高亮可能跑到别处；换一个头，可能完全不一样。你看到的不是「模型的理由」，是「你选择的那一层、那个头的一张快照」。

更根本的是：**模型没有「理由」这个内部字段。** 它不会在算出答案的同时，附上一份「因为 A 所以 B」的记录。它说的理由，是另一段生成出来的文字；那段文字和答案一样，都是按「下一个片段最可能」接出来的。所以「模型说它是因为第三段」和「图显示第三段权重高」，是两种不同的东西，而且都不能直接当成因果解释。

这里有一个很常见的确认偏误：先看到答案，再去找一张能支持答案的图。你总能找到——因为层数多、头数多，挑出一张「看起来合理」的图并不难。**难的是事先预测：如果改掉第三段，答案会不会变。** 前者是看图，后者是实验。

图不是完全没用。它可以帮你提出假设：「这一层可能把问题词和第三段联系起来了。」但它只能停在假设。要把它变成结论，需要行为对照，或者需要外部证据。**图是线索，不是判决。**

### 纪律三：「模型在看我指的那句话」没有依据

**常见说法**：「它肯定看了我标红的那句，不然怎么会这么答？」

**为什么不对**：这句话把三件事混在了一起。

第一，**它看到的不是「你那句话」，是 Token。** 你标红的是一个语义单位，它收到的是一串编号。那句话可能被切成好几块，只有其中一块和当前查询匹配；也可能整句都在，但被位置、格式、周围的材料稀释。你说的「那句」，在它那里没有对应的边界。

第二，**权重不等于使用。** 就算那句话的某一块分到了较高比例，也不代表它影响了最终输出；后面还有加工、还有别的头、还有别的层。**「取到了」和「用上了」之间隔着好几道门。**

第三，**「看」是一个意向动词。** 人看东西，意味着有一个主体、有一个方向、有一段时间。模型没有这些。你可以说「这句话在输入里」，也可以说「这个位置在这一层分到了较高权重」，但不能说「模型看了这句话」——因为没有一个可观测的「看」的状态可以被核对。

**怎么说才准确**：

| 想说的话 | 能不能说 | 换成什么说法 |
| --- | --- | --- |
| 这句话在这一轮输入里 | 能，可查 | 「送入清单里有这一句」 |
| 这个位置在这一层分到较高权重 | 能，可查 | 「第几层、第几个头、权重约多少」 |
| 模型看了这句话 | 不能 | 「这句话可能参与了混合」——仍然是假设 |
| 模型是因为这句话才这么答 | 不能，除非做过干预 | 「删掉这句后答案变了，说明它有影响」 |
| 它引用这句话，所以它看过了 | 不能 | 引用可能是生成的，回原文核对（→ 02、10） |

最后一行要单独强调：**引用不是「看过」的证据。** 引用本身也可能被生成、被错位、被拼接到一个不支持的结论上（→ 02 的第五源）。要证明它用了某句，得看那句原文是否真的支持结论，而不是看它有没有把文件名写对。

三条纪律合起来，其实就是一句话：**注意力图描述的是「混合比例」，不是「因果」、不是「理由」、不是「目光」。** 你可以用它提问，不能用它结案。

## 06.9 一个直接后果：长材料里「看见」不等于「取到」

现在可以解释一个很常见的现象了：一份很长的材料，关键那句明明在里面，模型却答错了。你问它，它甚至能复述出附近的内容，但就是没用上那一条。

这不是「它没看见」。更常见的情况是：**它看见了，但没取到，或者取到了但没留住。**

把三个说法分开：

| 说法 | 能观察到吗 | 要靠什么 |
| --- | --- | --- |
| 这句在窗口里 | 能 | 送入清单、切分结果、位置 |
| 这句被取到 | 不能靠图断言 | 需要干预或逐字引用核对 |
| 这句影响了答案 | 只能做对照 | 删掉、换掉、挪位置，看输出变不变 |

为什么「在窗口里」不等于「被取到」？因为取信息的匹配是**学出来的**，不是按「重要性」排序的。模型里没有一个字段叫「这段很重要」，也没有一个开关叫「优先看关键句」。它有的是一组查询和一组键的比对：当前这个位置的查询，和每个候选位置的键算出一个匹配程度，再按比例取内容。这个匹配程度来自训练，不来自你心里的重要程度。

于是会出现几种很具体的情况：

- **措辞不重合。** 关键句用的是另一套词，和问题的问法对不上，匹配分数就低。它可能是一句很准确的话，但在「像不像我要找的」这个维度上不占优势。
- **候选太多，份额被稀释。** 材料越长，可看的位置越多，每个位置分到的比例越少。关键句即使匹配得不错，也可能只拿到很小一份，被周围的材料盖过去。
- **干扰项更像。** 一段格式漂亮、用词贴近问题、但内容无关的文字，可能比关键句更容易被取到。**「像」和「对」不是一回事，这一点在取信息时同样成立。**
- **取到之后被后续层改写。** 第一层取到了，不代表最后一层还留着。后面的混合可能把它稀释，也可能把它覆盖。
- **位置和格式的影响。** 关键句埋在很长一段的中间，或者被表格、页眉、编号切断，都会改变它能不能被有效匹配。这一层属于工作台与材料组装，详见 05、09、10；本篇只解释「取」这一侧。

用一个示意的场景把这件事画出来：

```text
问题：「雨天备选场地确认了吗？」
材料里有三句候选：
  A「雨天方案：待确认」                     ← 关键句，措辞朴素
  B「场地交通、餐饮、保险均已确认」          ← 无关，但「确认」出现得多
  C「如遇雨天，请提前十分钟到场」            ← 相关，但不回答「确认没确认」

当前查询更接近「确认」这个模式
  → B 分到较多比例
  → C 分到一些
  → A 分到较少
  → 混合后的表示里，「待确认」这个信息不占优势
  → 答案可能写成「已确认」或含糊带过
```

图里的比例是示意，不对应任何模型。它要说明的是：**「在材料里」是一个事实，「被取到」是另一个事实，「影响答案」是第三个事实。** 三个事实各有各的查法，不能用一个「看见了」全包。

这也纠正了一个很自然的拟人化解释：「它没认真看」。模型没有「认真」这个旋钮。你能调的是：

- 把关键句单独拎出来问，别让它和一堆干扰项抢份额；
- 要求逐字引用，再用原文核对（引用仍然可能是生成的，见 02）；
- 减少无关材料，或把关键句放到更显眼、更靠前的位置；
- 把「有没有」这类判断拆成一次提取，而不是一次开放问答。

这些做法都不是「让它更专注」，而是**改变它要取的那圈信息**。前者是心理学词汇，后者才是机制层面的动作。

### 边界三列账

把这一篇讲的能力、代价和失效条件摆成一张表。第三列不能空，空了就说明你还没找到它的边界。

| 它能做到的 | 代价是什么 | 何时失效 |
| --- | --- | --- |
| 让同一个词在不同上下文里得到不同的可用表示 | 需要相关上下文真的在窗口里，且没有被切碎、截断、稀释 | 上下文缺失、被大量干扰项淹没，或这个词本身极少见 |
| 把相隔很远的信息拉到一起 | 每个位置、每一层都要做比对，长材料的计算与显存开销上升（→ 08、21） | 需要精确计数、逐位算术或符号操作（→ 03）；关系需要外部知识 |
| 用多头并行捕捉多种比对方式 | 参数与计算增加；头之间可能冗余；解释难度上升 | 把某个头当成固定的功能模块，或用一个头的图代表整层 |
| 用因果遮罩保证生成时不偷看右边 | 每个位置只能用左侧；对需要同时看两边的任务是限制 | 任务本身要求双向（完形、分类、整句改写），生成式架构未必最合适 |
| 用权重与热力图提供调试线索 | 图依赖层、头、阈值、颜色的选择，容易被误读 | 被当成因果证据、对外解释或验收依据 |
| 在长材料里定位到相关段落 | 相关不等于正确；匹配学出来，不按重要性排序 | 关键句措辞不匹配、干扰项更像、份额被稀释 |

这张表里最容易被忽略的是第二行的代价：**能把远距离信息拉到一起，不等于每次都能拉对。** 「能」是结构上的可能性，「对」是这一轮取信息的结果。把两者混为一谈，就会得出「上下文够长就应该答对」这种结论；而 05 已经讲过，装得下、送进去、用得上，是三件事。

## 06.10 反例与正例：把注意力图当解释的两种误用

### 反例一：发布会上的一张热力图

```text
输入：一份材料 + 一个问题
  → 打开注意力热力图
  → 最高权重落在材料第 3 段
  → 主持人：「大家看，模型确实关注了这段，所以答案有依据」
  → 台下点头，演示结束
```

这条链断在三处。

第一，**只展示了一层一个头。** 换一层，高亮可能落在别处；换一个头，可能完全不一样。观众看到的不是「模型的注意力」，是「被选中的那一层那个头」。

第二，**权重高不等于结论由这段支持。** 第 3 段可能只是因为用词和问题接近，才拿到高比例；它可能是一段无关的套话，甚至是错误的信息。**「像」被当成了「是」。**

第三，**「有依据」需要回原文，不需要看图。** 你要证明结论有依据，得指出结论的哪一句对应原文的哪一句；热力图不提供这个对应关系。

正例不是「不看图」，而是**把图降级成假设，再用对照去验**：

| 步骤 | 做什么 | 看什么 |
| --- | --- | --- |
| ① | 原样跑一次，记录答案 | 答案里有哪些断言 |
| ② | 删掉第 3 段，其他不变，再跑 | 答案变了吗？哪些部分变了？ |
| ③ | 把第 3 段换成相反说法，再跑 | 答案会跟着反吗？ |
| ④ | 对照三次结果 | 若答案稳定地跟着第 3 段变，才能说「这段有影响」 |
| ⑤ | 对外交付时附原文引用 | 结论—证据逐句对应，不用热力图当证据 |

第 ④ 步还有一个小陷阱：**「有影响」不等于「支持结论」。** 一段错误的材料也能影响输出。你证明的是「它被这段影响了」，不是「它的结论是对的」。后者仍然要回原文核。

### 反例二：一个头看出的「理解」

一个开发者在某一层某个头上看到：「苹果」对「甜」的权重很高，于是宣布：「模型理解了这里的苹果是水果。」

这句话的问题不在结论本身（模型很可能确实答对了），而在**证据的类型**。他拿的是一张单头、单层的图，而「理解」是一个关于内部状态的判断。换一层、换一个头，图可能就散了；换一个输入，这个头可能去做别的事。更要命的是，权重高只说明「取进来的多」，不说明「它据此得出了水果这个结论」。

正例是**最小对立对**：不改模型，只改输入，看输出是否稳定地跟着变。

| 输入 | 只改什么 | 你观察什么 |
| --- | --- | --- |
| 苹果成熟了，果农开始采摘 | 基准 | 「苹果」指水果 |
| 苹果发布了新品，股价上涨 | 把「果农采摘」换成「发布新品、股价」 | 是否稳定地指公司 |
| 苹果很甜，我买了三斤 | 换成味道与购买 | 是否稳定地指水果 |
| 苹果很贵，我修了两次 | 换成价格与维修 | 是否变得含糊，或指公司 |

这张表证明的是**行为层面的稳定关系**：某类上下文词出现时，答案会跟着变。它仍然不能证明「模型内部理解了」，但它至少是可重复、可验收的。**「换掉哪类词，答案会变」可以写进测试；「它关注了甜」不能。**

如果答案在你换掉「甜」之后完全不变，而在换掉另一个词之后变了，那它声称的依据就不是实际依据。**这就是把「事后解释」和「实际依据」分开的方法：不要问它为什么，去改它说过的原因，看结果。**

### 反例三：长材料里的「它看见了」

还有一种更隐蔽的误用：材料里有关键句，模型答错了；有人打开热力图，说「你看，这句权重不低，所以它肯定看见了，是它自己没用好」。

这句话一半对、一半错。对的一半是：那句确实可能在窗口里；错的一半是：**权重不低，不能证明它「用好了」，也不能证明它「没看见」。** 你需要的不是图，而是三个分开的检查：

1. 送入清单里有没有这句？（→ 05、09）
2. 它能不能逐字复述这句？（复述也可能是生成的，所以要回原文核）
3. 把其他材料删掉，只留这句再问一次，答案变不变？（→ 本篇的干预思路）

三个检查分别回答「在不在」「取没取到」「有没有影响」。热力图一个都回答不了。

## 06.11 你可以自己做的检验

不需要代码，一支笔、一张纸、一个聊天窗口就够。两组检验，加起来十五分钟。

### 检验一：指代、最小对立对与事后解释（10 分钟）

先准备四句话，不要解释，直接发给模型：

> 1. 苹果成熟了，果农开始采摘。
> 2. 苹果发布了新品，股价当天上涨。
> 3. 苹果很甜，我买了三斤。
> 4. 苹果很贵，我修了两次。

第一步，问它：「逐句说明，句中的『苹果』指水果、公司，还是说不清。只给结论，不要解释。」把四句的答案记下来。

第二步，做最小对照。只改每句里那个「起区分作用」的词，其他一字不动：

- 把「果农开始采摘」改成「大家开始准备」；
- 把「发布新品，股价上涨」改成「发布新品，大家开始准备」；
- 把「很甜，我买了三斤」改成「很酸，我买了三斤」；
- 把「很贵，我修了两次」改成「很贵，我买了两次」。

再问一次，看哪些答案跟着变、哪些不变。

第三步，问它：「你是根据哪几个字判断的？」把它说的依据记下来，和第二步里你实际改动的词对照。

**判据**：

- 如果答案随着「果农 / 股价 / 甜 / 修」这类词稳定地变，说明这些上下文确实在参与判断。这是行为证据。
- 如果它说「我根据『甜』判断」，但你改掉「甜」答案没变、改掉另一个词反而变了，那它的解释是事后叙述，不是它实际依据的可靠报告。
- 如果它在第三步说「我关注了『甜』」，这仍然是一句生成的话；**不要把它当成内省**。它没有「我刚才看了哪里」这个可读记录。

这个检验还有一个小变体：把两句放进同一条消息，问「第一句的苹果和第二句的苹果各指什么」。如果它能分开，说明同一轮里不同位置确实可以取到不同的上下文；如果它混了，也不奇怪——两个「苹果」在同一张桌上，份额会互相干扰。

### 检验二：如果你能看到注意力图（5 分钟，可选）

有些工具会显示注意力热力图。如果你手上有，做三件事：

1. 同一个输入，分别看两层或两个头，记下高亮位置。**它们一样吗？**
2. 选一张高亮最漂亮的图，把高亮最高的那句从材料里删掉，其他不变，再跑一次。**答案变了吗？**
3. 反过来，找一句高亮很低、但你认为关键的句子，把它删掉。**答案变了吗？**

**判据**：如果图变了而答案不变，说明这张图不是因果解释；如果图没变而答案变了，说明图漏掉了真正起作用的东西。两种情况都指向同一个结论：**图只能提示去哪里做干预，不能替代干预。**

如果你看不到图，这个检验可以跳过；前一个检验已经足够推翻「权重高就是理由」的说法。

### 一条补充：换模型之后

同一个问题，换一个模型再问一次。你可能会看到：答案差不多，但如果你能看图，图的形状完全不同。这很正常——不同的模型有不同的层数、头数和训练历史，内部权重没有可比性。**「这个模型关注这里，那个模型关注那里」不是稳定的知识，不能写进跨模型的结论。** 能用的是行为层面的对照：同一组最小对立对，两个模型是否都稳定地跟着上下文变。

## 06.12 术语考古：三个被用坏的词

### 注意力

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 「注意」是日常用语，也是认知科学里「选择性处理」的说法；作为序列模型里的操作，它在神经机器翻译的讨论中被系统化，后来在《Attention Is All You Need》这篇论文里成为整层的主结构（书目见总纲的常用入口）。本文不把某一篇论文当成唯一发明，也不引用它的数字。 |
| 原义 | 按相关性对一组表示做加权汇总：把资源偏向更相关的位置，但仍然是「汇总」，不是「挑选一个」。 |
| 现在被怎么用 | 被拟人化成「模型在看哪里」「模型在想什么」；产品把热力图直接叫「注意力」，于是图看起来像目光。 |
| 本文怎么用 | 只指「加权取信息」这个计算动作；不指意图、不指思考、不指理由。说「注意力」时必须能接一句：哪一层、哪个头、对谁取。 |

### 嵌入（embedding）

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 数学里的「嵌入」指把一个结构放进另一个空间，并尽量保持某些关系；在词表示里，指把离散符号映射成连续向量。具体谁最先这样用，本文不指认单一文献。 |
| 原义 | 让离散对象进入一个可计算的坐标空间，使相似、共现、类比等关系可以用几何关系来近似。 |
| 现在被怎么用 | 常被混成三种东西：查表得到的词向量、检索用的句向量、以及「模型记住的知识」。三者不是一回事。 |
| 本文怎么用 | 只指「查表得到的初始向量」这一层；它是起点，不是释义，不是记忆，也不是知识库里的条目。 |

### Transformer

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 一篇题为《Attention Is All You Need》的论文提出的架构名；「Transformer」是「变换器」的直译（书目见总纲）。 |
| 原义 | 一类以注意力为主、配合前馈与残差来处理序列的架构；它当时要解决的是「不靠循环结构也能做序列转换」。 |
| 现在被怎么用 | 被当成「大模型」的同义词，甚至一切现代模型的代称；于是「Transformer 的原理」被要求解释所有模型的所有行为。 |
| 本文怎么用 | 指这一类分层注意力架构；具体模型在层数、注意力变体、位置处理、训练方式上都可能不同，本文不假定它们完全一样。 |

三个词共同的毛病，是把三种东西说成了同一种：

- 把**操作**说成**意图**（注意力 → 关注）；
- 把**表示**说成**知识**（嵌入 → 记住）；
- 把**一类架构**说成**所有模型**（Transformer → 大模型）。

一旦说混，后面的判断就会跟着错：你会去问「它为什么关注」，而不是「它取到了什么」；你会去问「嵌入里存了什么知识」，而不是「这一轮的表示是怎么混出来的」；你会用一篇论文的结论去套一个完全不同的模型。**术语考古不是为了考据，是为了让问题问对。**

## 06.13 一页速记

| 你看到的现象 | 机制上发生了什么 | 该做什么 |
| --- | --- | --- |
| 同一个词在两句话里意思不同 | 初始向量可以相同，取到的上下文不同，混出来的表示不同 | 看句子，不要问「词向量里写了哪个释义」 |
| 某个位置注意力权重很高 | 这一层、这个头、这次查询分了较多比例给它 | 不等于因果重要；要删/换/挪做对照 |
| 热力图很好看 | 人选了层、头、阈值、颜色 | 当线索，不当证据 |
| 它说「我关注了第三段」 | 一句生成出来的解释 | 回原文核，不听自述 |
| 长材料里关键句被漏掉 | 匹配不到、份额被稀释、或后续层覆盖 | 单独问、逐字引用、减少干扰（→ 05、10） |
| 它看不见右边的词 | 因果遮罩，生成时右边还不存在 | 这是必要条件，不是缺陷 |
| 换一个头，图完全变了 | 头与头之间可能冗余、可能分工不同 | 不要用一个头代表整层 |

**五句话带走**

1. 同一个词的意思不在词里，在它被允许取到的那一圈信息里。
2. 注意力是加权取信息；权重是比例，不是目光。
3. 权重高不等于因果重要；图是快照，不是理由。
4. 因果遮罩保证它不偷看未来，也保证了它只能从左往右建表示。
5. 长材料里「在窗口里」和「被用上」是两件事。

**三道自检**

1. 热力图显示问题词对第 3 段权重最高。能不能据此断定「答案的依据就是第 3 段」？你会怎么做？
2. 同一个「苹果」在两句话里指不同东西。这是不是说明模型里存了两个「苹果」词条？
3. 一份长材料里，关键句在第 40 页，模型答错了。能不能说「它没看见」？应该先查什么？
