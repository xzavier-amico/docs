## 21.1 引子：他只是多问了几句

账单上最贵的一笔，通常不是它写出来的那段话，而是它为了写这段话，把同一批材料又读了一遍。

虚构现场，10 月 8 日下午，团建筹备的第五天。负责人已经有一份能用的材料：通知 v2、A 与 B 两份报价、系统导出的 42 条名单、上次会议记录。他连那封已经作废的 v1 也一并粘了进去。然后他开始问：

第一轮，要三行结论：日期、A 方案合计与是否超预算、B 场地档期状态。
第二轮，要一份完整的群通知草稿。
第三轮，问「日期再核对一下，是不是 25 号」。
第四轮，说「语气再正式一点」。
第五轮，说「把预算那段也加进去」。
第六轮，问「我们最后定了什么，帮我总结一下」。

他后来的原话是：「我只是多问了几句，怎么就贵了这么多。」

这句话里藏着一个默认假设：**一问 = 一份钱，多问几句 = 多几份小钱。** 实际发生的是另一件事。从第二轮开始，前面所有内容——通知、两份报价、42 条名单、会议记录、他自己写的要求、模型上一轮写的三行结论——都还在桌上。为了让它「记得上下文」，应用必须把这一整桌东西再送进去一次。第三轮再送一次，第四轮再送一次。

```text
（示意）同一个会话里的六轮，桌面在变大，而不是在换

第 1 轮   [通知 v1 v2][A/B 报价][42 条名单][会议记录][要求]        → 三行结论
第 2 轮   [上一轮全部] + [三行结论][起草要求]                      → 草稿
第 3 轮   [上两轮全部] + [草稿][核对要求]                          → 改一个日期
第 4 轮   [上三轮全部] + [改过的稿][语气要求]                      → 换措辞
第 5 轮   [上四轮全部] + [稿][补预算要求]                          → 加一段
第 6 轮   [上五轮全部] + [全部稿][总结要求]                        → 一段总结
              ↑ 每一轮都把整桌再买一次；桌面只会变大，不会自动变小
```

第六轮结束时，他采用的仍然是第一轮那三行结论，只把日期从 18 日改成 25 日。后面五轮里，只有一轮在起草，其余四轮分别在核对日期、改措辞、补一段、做总结。**这些钱没有变成更好的结果，它们变成了一段更长的对话记录。**

而且第三轮那句问法本身也有问题：答案已经写在问题里了，它只需要点头。**那不是核对，是把「25 号」又说了一遍。**

于是这一篇的结论可以先摆出来：

> **贵不贵，不看「一次多少字」，看「为了得到这一个结果，总共买了多少遍」。**

这句话从 P2 与 P1 直接推出来。P2 说模型只看得见这一次被放到桌上的东西，所以「记得上文」不是模型的本事，是应用把上文又放了一遍；每多一轮，就多买一遍整桌。P1 说它一次只决定下一个片段，所以写字只能一步一步来；产品通常把这段逐步生成按输出单独计价，而写出来的每个字，下一轮又会作为输入被再买一次。**一条是「桌子重买」，一条是「自己写的字还要再买」，两条叠在一起，就是越自动越贵。**

还要先说明一件事：书名里的三本账是质量、钱、时间。这一篇只把「钱」这一本拆细，但每算一笔，都要把另外两本摆在旁边。否则「便宜」会变成唯一目标，而最便宜的方案，往往只是把成本推给了时间和人。

## 21.2 唯一真问题：为了这一个结果，总共买了几遍

「这个模型贵不贵」是一句无法回答的话。同一个模型，问一句天气和跑一次三小时的调研，账单能差出几个数量级；同一个任务，一次问完和拆成十轮追问，也能差出几倍。差别不在单价，在**买法**。

所以本篇的唯一真问题是：

> **这次任务，同一份东西被买了几遍？哪几遍真的进入了交付物？**

它有一个更短的操作版本，后面的账本和检验都靠它：

> **把交付物摊开，逐字问：这个字是哪一次调用换来的？**

答不上来的那一次，就是白花。

### 先把三个量分开

| 量 | 怎么量 | 它回答什么 | 它不回答什么 |
| --- | --- | --- | --- |
| **净材料量** | 把重复的文件只算一次，量出这次任务真正需要的材料有多少 | 这件事本身有多大 | 你实际买了多少 |
| **总输入量** | 把所有调用的输入加总 | 桌子被买了多少遍 | 这些材料有没有被用上 |
| **总输出量** | 把所有调用的输出加总，包含不展示但计费的部分（若有） | 它写了多少 | 写的东西有没有进入交付物 |

三者一除，得到一个比单价更有用的数：

> **重复倍数 = 总输入量 ÷ 净材料量。**

它不精确，也不需要精确。它只回答一件事：**同一份材料，你平均买了几遍。** 如果净材料是 7,600 单位，总输入是 28,700 单位，重复倍数就是 3.8 左右——不是说有一份材料被完整复制了 3.8 次，而是说**你为这件事付出的阅读量，接近材料本身的四倍**。这个数一旦超过 2，就值得停下来问一句：多出来的那些遍，换到了什么。

### 用四问过一遍

第 1 问：**这句话是谁说的？** 在账单上格外容易答错。「这次花了多少」是平台用量页说的；「我很省」是模型说的，而模型根本不知道自己是第几次被调用。**模型没有账单意识**，它不会因为你在第五轮追问就少读一点。

第 2 问：**它这一轮看见了什么？** 用量页上的输入量，是「这一轮桌上东西」的计量证据——但它只是计费口径，不等于有效使用。桌上有一万字，不代表这一万字都被用上了。第 2 问在这里的作用，是把「买了」和「用上」分开。

第 3 问：**这是提议、事实，还是已经执行？** 重试尤其要问。一次超时，可能只是回执丢了，动作其实已经执行；这时再重跑一次，你付的不只是第二遍的钱，还可能是第二次副作用。钱和状态必须分开记。

第 4 问：**我拿什么独立验证？** 拿平台的用量明细，加上你自己的调用记录，再加上交付物里每个字段的来源。不能拿「它说它只读了一遍」当证据，也不能拿「这次感觉很快」当证据。

### 为什么「越自动越贵」

因为自动化增加的不是「每次的字数」，是四样乘数：

1. **轮次**。Agent 每走一步，都要把当前状态重新组装上桌；步数越多，整桌被买的次数越多。
2. **工具返回**。一次查询的原始返回可能很长，而它下一轮就变成输入，原样再买一遍。
3. **重试**。失败一次，整份输入再买一次；而失败往往发生在最贵的长材料调用上。
4. **分支复制**。并行时每个分支各带一份材料；分支越多，同一段前置被复制的次数越多（见第 20 篇）。

四样乘数叠在一起，就是「我什么都没多要，账单怎么翻了几倍」的答案。**你没有多要，你只是把同一件事买了很多遍。**

这也是全书六本账里「预算」那一本的填法。第 19 篇给的是上限：这一轮最多花多少；这一篇给的是归因：已经花掉的，分别买了几遍、哪几遍进了交付物。**只有上限没有归因，预算就只是一个事后才知道有没有超的数字。**

## 21.3 一张图：钱在四层手里各过了一遍

先把责任摊开。账单不是一个数字，是一条流水线；每一层都能让这条线变粗或变长，但没有一层能单独决定总账。

```text
（示意）一次团建任务里，同一份材料是怎么被反复买走的
（人不在流水线上，但这条线的形状由人定：几轮、哪些材料上桌、谁验收）

  材料仓                应用（P2）                     模型（P1）              账单
  ┌──────────┐   ① 这一轮桌上放什么             ③ 读入 → 逐段写出      ┌────────────┐
  │ 通知 v1  │──▶ 通知 v2 + A/B 报价 + 名单  ──▶ ┌────────────┐ ──▶  │ 输入：按量  │
  │ 通知 v2  │     + 会议记录 + 历史 + 工具返回     │   第 1 轮   │      │ 输出：按量  │
  │ A/B 报价 │                                    └─────┬──────┘      └────────────┘
  │ 42 条名单│    ② 把上一轮写过的字接回桌上              │ 写出的字
  │ 会议记录 │◀──────────────────────────────────────────┘
  └──────────┘    ④ 下一轮：整张桌子再买一次
        ▲
        │  ⑤ 工具/运行时：执行查询，把返回原样放回桌上
        └──────────────────────────────────────────────
```

这张图要读出四件事：

**第一，模型只在第 ③ 步出现。** 它读入、它续写，然后结束。它不知道第 ① 步塞了多少东西，也不知道第 ④ 步又要再塞一次。**「它读得太多」这句话，责任通常不在它。**

**第二，第 ② 步是账单真正的放大器。** 上一轮写出的每个字，这一轮都变成输入。所以输出有两个价格：写的时候按输出算一次，下一轮按输入再算一次。写得越长，这个回流越贵。

**第三，第 ⑤ 步是隐形入口。** 工具返回不是「一句话」，可能是一页网页、一份合同全文、一整张表。它一旦被原样放回桌上，就按输入计价，而且会跟着后面每一轮继续被买。

**第四，四层各自能动的部分完全不同。**

| 层 | 在钱这件事上做什么 | 能省哪一笔 | 改不了什么 |
| --- | --- | --- | --- |
| **人** | 定「最少几轮」「哪些材料不许上桌」「预算上限」「谁来验收」 | 轮次、范围、返工 | 分词、单价、模型的措辞习惯 |
| **应用** | 组装这一轮的材料、裁剪历史、决定工具返回留多少、做检索与摘要 | 重复输入、工具返回、摘要开销 | 模型愿不愿意写短 |
| **工具 / 运行时** | 决定返回多长、失败重不重试、并发多少、写操作是否幂等 | 失败重试、重复调用 | 材料对不对、答案对不对 |
| **模型** | 按权重续写、逐个抽样 | 几乎不直接省；只能通过「写短一点」间接影响 | 桌子有多满、自己被调用几次 |

这张表最有用的是最后一行：**模型层几乎不是省钱的杠杆。** 换一个更便宜的模型，改的是每一单位的价钱；但桌子还是那么满，轮次还是那么多，重试还是照旧。**先换模型，等于给一份没整理过的账单换了一个更便宜的计价器。**

### 谁在什么时刻决定这笔钱

把钱按时间顺序再排一次，会发现大部分支出在第一次调用之前就已经定了：

| 时刻 | 谁在做决定 | 已经锁定的成本 |
| --- | --- | --- |
| 任务开始前 | 人 | 要几轮、交付物是什么、哪些材料必须进 |
| 第一次组装 | 应用 | 第一桌有多满、历史带多少、工具说明多长 |
| 每次工具返回 | 工具 / 运行时 | 下一轮的输入会膨胀多少 |
| 每次失败 | 运行时 | 要不要整份再买一遍 |
| 每次并行派发 | 编排方 | 同一段前置会被复制几份 |
| 最后一次点击 | 人 | 是否真的需要这一轮 |

所以「事后看账单心疼」几乎没有用。**账单的形状在任务设计时就定了**；事后能做的只有归因，不能改写。

## 21.4 输入与输出：为什么「一次多少字」不是价钱

输入和输出是两条不同的计价线，常见的计费方式会把它们分开计价、分列。不同产品的单价不同，怎么定这两条线、有没有阶梯、有没有缓存价、有没有批处理价，差别很大，**本文不给任何单价，也不做产品之间的价格比较**。但方向是稳定的，可以从机制推出来。

### 输入为什么通常便宜一些

输入是读入。这一轮要送进去的东西，在调用开始前就已经给定；同一层里的大批位置可以一起算，机器容易吃饱（见第 08 篇）。所以单位成本通常低一些，也更容易被复用——同一段前缀如果没变，下一次可以少读一遍。

但「便宜」有两个陷阱。

**陷阱一：便宜不等于免费，而且它会跟着轮次重复。** 一段材料读一遍便宜，读五遍就是五份。单价低的东西，乘以一个大轮次，照样能超过单价高的东西。

**陷阱二：便宜让人舍不得裁。** 因为「反正输入不贵」，很多人把整份会议记录、整页网页都留着。可输入不贵是**单位**不贵，不是**总量**不贵；而且这些材料会挤占桌位，让真正重要的那几行更难被用上（见第 05 篇）。

### 输出为什么通常更贵，而且贵两次

输出是逐段生成。下一步的输入包含上一步刚选出来的片段，所以只能一步一步走（见第 08 篇）。这个「逐步」的物理形状，决定了输出的单位成本通常高于输入。

更少被注意到的是第二层：**输出的每个字，下一轮会作为输入再买一次。**

```text
（示意）同一段话，在账单上出现两次

第 2 轮： 模型写出 900 单位草稿
          → 按「输出」计价一次

第 3 轮： 这 900 单位被接回桌上，作为这一轮输入的一部分
          → 再按「输入」计价一次

所以「让它多写一点」不是只多付一次钱；
写出来的东西只要还留在会话里，就会跟着后面每一轮继续被买。
```

这解释了一个很常见的困惑：**为什么只是让它「再详细一点」，后面几轮都变贵了。** 因为详细的那一段没有消失，它变成了新的桌面。

### 三段式：总账由什么构成

不用公式，用一句话就能说清：

> **总账 ≈ 输入量 × 输入单价 ＋ 输出量 × 输出单价 ＋ 失败重试的重复 ＋ 并行分支的复制。**

四项里，只有前两项是「正常吃饭」，后两项是「打翻重买」。而输入量与输出量本身，又被轮次和每轮带上的材料决定：

> **输入量 ≈ 轮次 × 每轮带上的材料量。**

这就是为什么「一次多少字」不是价钱。同样是一千字，可能是：

- 一次输入里的一千字，按输入计价；
- 一次输出里的一千字，按输出计价；
- 三轮里各出现一次的一千字，按输入计价三次；
- 一次输出的一千字，再在下一轮按输入计价一次。

**四种情况的字数完全一样，账单可以差出好几倍。**

### 三个口径，不能互相换算

| 口径 | 它量的是什么 | 能回答什么 | 不能回答什么 |
| --- | --- | --- | --- |
| **可见字数** | 你在屏幕上看到的字符 | 读起来有多长 | 计费单位是多少；有没有不展示的生成 |
| **计费单位** | 平台账单上的计量单位 | 这次按什么量收钱 | 这些单位是输入还是输出；是不是重试 |
| **调用次数** | 发生了几次独立的模型调用 | 桌子被买了几次 | 每次桌子有多满 |

三个数经常被混着说。「这次回答很短」说的是可见字数；「这次很贵」说的是计费单位；「只问了一次」说的是调用次数。**短回答也可能很贵**，因为它前面带着一整桌材料；**一次调用也可能很便宜**，如果桌子很空。

### 不展示的推理 Token：看不见的输出

有一部分模型会在给出可见答案之前，先生成一段不直接展示的中间内容。这段内容是否计入输出、按什么口径计，**因产品、因版本而异**：有的产品把它算进输出，有的单独统计，有的在某些模式下不计。本文不给统一结论，也不给比例。

但它对记账有一个确定的后果：**你不能用「答案有多长」来估输出量。**

可观察的信号有三个，都不需要看内部：

1. 用量页上的输出量明显大于可见答案的长度；
2. 同一个问题，换成「多想一会儿」的档位后，可见答案差不多，计费却明显不同；
3. 输出量在不同轮次之间跳动，而你并没有要求它写得更长。

看到这三种，第一件事不是猜比例，而是去查该产品当前的计费说明，记下版本与查阅日期。**口径是产品行为，不是模型定律。**

这也带出一条记账纪律：**账单上至少要有三栏——输入、输出、调用次数。** 只记「这次花了多少」，你永远不知道钱花在「读」还是「写」，也就不知道该砍哪一头。

## 21.5 六种白花的钱

先把「白花」定义清楚，否则这六个词会变成六句骂人的话。

> **白花不是「没有输出」，而是：输出的东西没有进入交付物；或者本来用一小片材料就能换到，却买了整桌。**

按这个定义，一笔钱是否白花，不看它有没有产生文字，看它有没有改变最终那个东西。下面六种，是同一件事的六种长相。

### 白花一：重复输入

**现场。** 六轮对话，在默认设置下，每一轮都把通知、报价、名单、会议记录再送一遍。人感觉「我在同一个会话里继续聊」，账单上是「同一份材料买了六遍」。

**机制。** P2：模型没有跨轮的存储，所谓「记得上文」，是应用把上文又放回了桌上。这不是产品偷懒，是机制决定的——不放，它就真的看不见。所以重复输入不是 bug，是**默认行为**；你不主动裁，它就一定发生。

**识别信号。** 输入量随轮次近似线性上涨；输入占总账的绝大部分；把材料净量一除，重复倍数明显大于 2。

**减法。** 三件事按顺序做：第一，把「必须一起看的材料」和「只需要结论的材料」分开，后者只带结论；第二，把一次任务的要求一次写全，减少「再补一句」的轮次；第三，确实需要长会话时，把稳定不变的那一段放在最前面，让它可以被前缀复用（见 21.8）。

**最容易犯的错。** 为了「省 Token」把历史整段删掉，结果模型不知道前面定了什么，答非所问，又重来一轮。**裁的是重复，不是上下文。**

### 白花二：工具返回太长

**现场。** 让它查 B 场地的档期，工具把整页介绍、整份合同、全部条款都取了回来。它真正需要的只有四个字段：日期、单价、容量、状态。下一轮，这一整页按输入计价，而且跟着后面每一轮继续被买。

**机制。** 工具返回是输入，不是「系统消息」。它一旦被放进桌面，就和用户写的材料一样占位置、一样计费。更麻烦的是，它往往带着大量与任务无关的格式、导航、免责声明。

**识别信号。** 某一轮输入突然跳高，而增加的那部分你并没有写过；点开调用记录，发现是某次工具返回；后面每一轮都维持在这个高位。

**减法。** 让工具只返回**字段**，不返回原文：状态、日期、金额、来源。需要原文时，按字段回查一次，而不是把整页常驻。工具返回里必须保留「来源」和「取数时间」，否则省下的钱会变成一次无法核对的结论。

**边界。** 有些任务必须看全文（合同条款、审计底稿）。这时不能截，只能换一种方式：先让它只读其中一节，或者先做一次结构化提取，再把提取结果放上桌。

### 白花三：摘要自身的开销

**现场。** 听说「上下文太长会贵」，于是每一轮开始前都让模型把上文摘要一遍。摘要写出来 800 字，按输出计价；下一轮这 800 字又作为输入；再过一轮，又摘一次。

**机制。** 摘要是一次生成，不是免费的搬运。它按输出计价，会错，会把「未定」写成「已定」（见第 11 篇）。而且摘要常常**没有真正替换掉原文**：为了「保险」，原文还留在附件里，结果是摘要和原文各买一份。

**识别信号。** 账单里出现一段你没见过的输出；摘要的版本比原文还多；每一轮的输入并没有因为摘要而下降。

**减法。** 第一，只摘一次，然后冻结，不要每轮重摘；第二，能用结构化字段（日期、金额、状态、未决项）代替自然语言摘要的，用字段；第三，先问「这段材料能不能根本不上桌」，能，就别摘——**压缩是「已经决定要买」之后的省钱手段，不是「要不要买」的替代品。**

**一句话判据。** 如果摘要省下的输入，小于摘要本身的输出加上它带来的错误，这次压缩就是负的。这个判断要在自己的任务上做，不能靠一句「压缩能省钱」。

### 白花四：失败重试

**现场。** 一次长材料调用超时，界面转圈，人又点了一次发送。第二次成功。账单上是两份完整输入，第一份几乎没有产出。

**机制。** 重试不是「从断点继续」，是**整份再买一次**。输入越长，重试越贵；而长输入本身就更容易撞上超时，于是形成一个越贵越容易失败、越失败越贵的循环。**最容易失败的调用，恰好是最贵的调用。**

**识别信号。** 同一段前缀在很短时间内出现两次以上；其中一次的产出极短或为空；调用记录里有超时、限流、格式错误。更隐蔽的是「看起来失败、其实已执行」——钱花了两次，副作用也可能有两次（见第 16 篇）。

**减法。** 第一，先分类失败原因：超时、限流、格式、权限、材料缺失，五类的处理完全不同；第二，只有只读调用才自动重试，写操作必须先查原始系统；第三，给重试设上限，并把「重试了几次」记进预算账；第四，能一次说清的要求不要靠「再问一遍」补。

**最容易犯的错。** 把「再问它一次」当成重试。那不是重试，是新一轮调用，而且很可能带着更长的历史。

### 白花五：并行分支重复前置

**现场。** 三个分支同时开跑，每个分支都带上了同一份任务说明、同一份通知、同一份报价。三个分支的产出还要合并，合并本身又是一次调用；如果合并时发现口径不一致，再来一轮返工。

**机制。** 每个分支只看得见派发给它的那份快照（见第 20 篇）。为了让它「知道背景」，编排方通常会把同一段前置复制给每个分支。于是**同一段前置被买了分支数遍**，而它本来只需要在派发前组装一次。

**识别信号。** 输入量随分支数近似倍增，而各分支的产出并不互补；合并时大量内容重复；返工轮次比分支数还多。

**减法。** 第一，只并真正独立的只读查询；第二，每个分支只带自己需要的那一小节，不带全量；第三，共享前置在应用层组装一次，不要在每个分支的提示里重写；第四，先定合并规则再派发，减少返工。

**边界。** 有些任务的分支确实需要同一份全文（例如三条独立的审稿意见）。这时重复是必要的，但要在派发前就知道它贵，并把它算进预算，而不是事后惊讶。

### 白花六：为「保险」多问一遍，却没人看结果

**现场。** 草稿写完了，人不放心，又开一轮：「你再检查一遍有没有问题。」模型回：「整体没有问题，建议再润色一下。」人看了一眼，觉得安心，发出去了。这一轮的钱花了，但没有改变任何一个字段，也没有产生任何可引用的证据。

**机制。** 这是六种里最像「负责任」的一种，所以最难砍。它有两个问题。第一，**结果没有被使用**：没有进验收、没有改变决定、没有留下证据，它只是一段让人安心的措辞。第二，**同源错误不会被它发现**：同一批材料、同一个模型、同一个问法，第二遍只是又抽了一次；如果第一遍读的是作废的 v1，第二遍还会读 v1，甚至会更自信地说「已核对」（见第 04 篇与第 20 篇）。

**识别信号。** 调用记录里有，验收记录里没有；问完之后的动作和问之前一样；「检查」的结论是一段形容词，而不是「哪几个字段回了哪份原文」。

**减法。** 要么把复核写成**可执行的比对**——「日期回 v2、人数回名单去重、金额回报价与算式」；要么不做。复核的产出应该是一张带来源的对照表，而不是一句「没问题」。如果只是想要安心，那是人的情绪成本，不该记成模型的价值。

**一句话判据。** 这一轮如果删掉，交付物会变吗？不会，那它就是白花；会，那它就不是「保险」，是「生产」，应该被算进必要成本。

### 六种白花一览

| 白花 | 账单上的形状 | 一句话判据 | 先动哪一层 |
| --- | --- | --- | --- |
| 重复输入 | 输入随轮次线性上涨 | 同一份材料这轮又买了一次 | 应用（历史策略） |
| 工具返回太长 | 某轮输入突增，且不是你写的 | 返回里九成字段用不上 | 工具 / 应用 |
| 摘要自身开销 | 出现看不见的输出，且每轮都有 | 省下的输入小于摘要成本 | 应用（先问要不要） |
| 失败重试 | 同一前缀短时间出现多次 | 第一次的产出没进交付物 | 运行时 |
| 并行重复前置 | 输入随分支数倍增 | 各分支带的前置是同一份 | 编排 |
| 保险轮没人看 | 有调用、无证据、无改变 | 删掉它，交付物不变 | 人（定验收） |

六种里，只有第六种的根子在「人」。前五种都能靠应用或运行时改；第六种改不了，因为它的动力是「不放心」，而技术只能提供证据，提供不了安心。

## 21.6 示意账本：同一件事的四种买法

下面这本账是**虚构的**，数字是为了让算式走得通，不对应任何产品的分词、单价或实测。材料沿用团建那一套，净材料量按下面的口径估：

| 材料 | 示意用量 | 说明 |
| --- | --- | --- |
| 通知 v1 | 800 | 已作废，但仍在很多人的文件夹里 |
| 通知 v2 | 800 | 现行版本，写明 v1 作废 |
| A 场地报价 | 400 | 人均 260，含餐、场地、保险 |
| B 场地报价 | 600 | 人均 310，合同未签、档期未确认 |
| 名单导出 | 2,000 | 42 条记录，其中 3 条重复 |
| 会议记录 | 3,000 | 含两次日期讨论 |
| **合计** | **7,600** | 只算一次，不重复计 |

任务是同一件：**三行结论（日期、A 方案合计与是否超预算、B 档期状态）＋ 一份群通知草稿。** 四种买法，四种账单。

| 买法 | 调用 | 输入（单位） | 输出（单位） | 合计（示意） | 重复倍数 | 墙钟（示意） | 质量（示意） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A 单次问全 | 1 | 8,000 | 700 | **8,700** | 1.05 | 2.5 分钟 | 低 |
| B 三步循环 | 3 | 26,500 | 1,800 | **28,300** | 3.49 | 5.5 分钟 | 中 |
| C 三分支并行 | 5 | 28,700 | 3,400 | **32,100** | 3.78 | 6.5 分钟 | 低 |
| D 先查后写（对照） | 6 | 5,600 | 1,900 | **7,500** | 0.74 | 5.5 分钟 | 高 |

表里的「合计」就是这次任务的总 Token 量，只是用示意单位计；「重复倍数」是总输入除以净材料量 7,600，用来回答「同一份材料买了几遍」。「质量」一栏只看离可交付还差几处：A 差三处（日期、雨天、饮食），B 差两处（人数、场地状态），C 差三处且还要重合并，D 只差一个已经标注的未定项。

### 这四个数是怎么算出来的

**A 单次问全。** 一次调用，桌上放全部 7,600 材料，加 400 的指令，输入 8,000；输出 700，包含三行结论和一份偏短的草稿。它只买了一遍材料，所以最接近「净材料量」，但它没有核对步骤：草稿里的日期取了先出现的 v1，写成 18 日，雨天与饮食也只写了两句。

**B 三步循环。** 第一轮要三行结论：输入 8,000，输出 400。第二轮要草稿：把第一轮的 8,000 和 400 都带上，再加 300 的起草要求，输入 8,700，输出 900。第三轮只改日期：把前两轮的 8,700 和 900 都带上，再加 200 的核对要求，输入 9,800，输出 500。合计输入 26,500，输出 1,800。

**C 三分支并行。** 三个分支各自带全量材料加 400 的分支说明，每个分支输入 8,000，三份共 24,000；输出分别是 400、500、900。合并时读这三份产出（1,800）加 400 的合并规则，输入 2,200，输出 700。合并后发现人数、日期、场地状态三处对不上，返工一次：读合并稿 700、更正材料 1,300、指令 500，输入 2,500，输出 900。合计输入 28,700，输出 3,400。

**D 先查后写。** 四个只读查询各自只带自己那一小片：查版本 800、核名单 1,200、查 A 报价 900、问 B 档期 700，输入合计 3,600，输出各 200 到 300，合计 1,000。然后单点汇总并起草：读四份查询结论（1,000）、一张结论表（400）、通知模板（600），输入 2,000，输出 900。合计输入 5,600，输出 1,900。

### 从这张表里能读出什么

**第一，调用次数不是账单。**

D 调用了 6 次，是四者中最多的；总账却最低。B 只调用 3 次，总账是 D 的近四倍。差别不在次数，在**每一轮带了什么**：B 每一轮都带全量，D 每一轮只带自己需要的那一片。

这直接推翻了「少问几次就省钱」的直觉。少问几次但每次都带全桌，比多问几次但每次只带一小片更贵。

**第二，最贵的一次不是调用最多的那次，是「自动 + 重复」的那次。**

C 的总账最高，墙钟最长，质量仍不可直接交付。它贵不在分支多，在于**每个分支都买了一遍全量材料**，然后又用一次合并和一次返工把省下的时间还了回去。三本账全输，不是运气差，是切法错（见第 20 篇）。

**第三，多出来的轮次，买到的可能只是措辞。**

B 比 A 多花了近两万单位，质量只从「低」到「中」：日期在第三轮被改对了，但人数仍写 42，B 场地仍写「已确认」。因为多出来的两轮，一轮在起草，一轮只改了一个日期，**没有一轮回去查名单和合同**。钱花在表达层，问题在事实层。

**第四，最便宜且质量最高的，是那个「看起来多跑了几次」的方案。**

D 的重复倍数小于 1，说明它并不是每一段材料都读了——它只读了需要的那几片。它的质量最高，因为每个字段都带了来源，B 场地的「未定」被明确标出来，而不是被抹成「已确认」。

这就是本篇的核心判断在账本上的样子：**不是「买得少」就便宜，是「买得准」才便宜。**

### 这张表没算进去的两笔

**人的时间。** A 的低价有一部分是把核对推给了人：草稿短、缺雨天与饮食安排、日期取了作废的 v1，人要在发送前补一遍。如果人的十分钟也要记进账，A 不一定最便宜。**省钱的方案经常只是把成本挪到了账本外面。**

**返工与事故。** 如果 A 或 B 的错误被当成定稿交上去，代价不是 Token，是重发、解释、信任。这笔钱不在模型账单上，但它真实存在。所以「总账最低」不等于「最划算」，还要看它把多少风险留在了下游。

## 21.7 优化顺序：四步，以及为什么不能反

现在给出本篇唯一可执行的部分。顺序是固定的：

> **砍无用轮次 → 裁材料与工具返回 → 按需检索与压缩 → 再谈缓存与模型分工。**

四步不是四个建议，是一条**优先级**。前一步没做完，后一步的收益会被前一步的浪费吃掉。

```text
（示意）账单的四个层级：上一层决定下一层的乘数

  ① 结构：几轮        ← 轮次是乘数，决定「买几遍」
       ×
  ② 内容：每轮带什么   ← 材料是被乘数，决定「每遍多贵」
       ×
  ③ 表示：同样内容多短 ← 摘要、字段化，决定「每遍能不能更小」
       ×
  ④ 单价：每一单位多少 ← 缓存、模型档位，决定「每单位多少钱」

  先动上面的，下面的才有意义；先动下面的，等于让一个错的结构便宜一点。
```

### 第一步：砍无用轮次

**动作。** 把这次任务的所有调用列出来，逐轮问一句：**删掉这一轮，交付物会变吗？** 不会，砍。

**常见可砍项。** 追问措辞（「再正式一点」）、重复确认（「你确定吗」）、把一次能说清的要求拆成多轮、为保险加的自检轮、让模型「再想想」而没有新材料的轮。

**为什么排第一。** 因为轮次是乘数。一轮无用，不只是这一轮的钱，它还让后面每一轮都多带一段历史。砍掉一轮，等于同时砍掉了它自己、它在后续每轮里的复制、以及它可能引发的重试。

**注意。** 砍轮次不等于「所有事都塞进一轮」。有些轮次是生产性的：查一个字段、写一段交付、做一次有明确判据的核对。判据不是「次数少」，是「每一次都产出交付物里的东西」。

### 第二步：裁材料与工具返回

**动作。** 对每一轮桌上的每一段材料问：**这一轮真的需要它吗？** 不需要的移出；需要的，只带相关的那一节；工具返回只留字段与来源。

**三刀。** 第一刀砍版本：v1 已作废，就不该上桌；不是「标一句作废」再放进去，而是根本不放。第二刀砍重复：会议记录里已经进了结论的，不必再带全文。第三刀砍工具返回：整页网页只留状态、日期、金额、来源。

**不能砍的五类。** 决定、否决、依据、未决、边界（见第 11 篇）。这五类一旦被裁，省下的钱会变成一次返工，而返工是整轮重买。**裁材料是唯一一个「省对了省钱、省错了更贵」的步骤**，所以裁完必须复核。

### 第三步：按需检索与压缩

**动作。** 先问「这段材料能不能根本不上桌」，能，就用一次检索换一小片；不能，再问「能不能更短」，用结构化摘要或字段化代替全文。

**为什么「检索」在「压缩」前面。** 检索决定「要不要买」，压缩决定「买多短」。如果一段材料根本不需要，压缩它是纯支出：你花了输出价，换了一个更短的、可能失真的版本，然后发现还是不该放上桌。**能不买就不买，必须买才买小的。**

**压缩的三条纪律。** 只摘一次并冻结；摘要必须保留五类关键信息；摘要的成本要记进账，不能当成免费。摘要省下的输入如果小于它自己的输出加错误代价，这次压缩就是负的（见第 11 篇）。

### 第四步：缓存与模型分工

**动作。** 前面三步做完，桌面已经稳定、材料已经必要，这时才考虑：稳定的前缀能不能复用？重复的问题能不能用结果缓存？哪些步骤可以交给更便宜的档位？

**为什么排最后。** 三个理由。

第一，**缓存是系数，不是结构。** 它降低的是「同一段前缀重读」的单价，不改变你读了几遍。轮次没砍、材料没裁，缓存只是让浪费便宜一点。

第二，**缓存会把结构固化。** 前缀复用的前提是「从第一个 Token 起逐字相同」。一旦你为了命中率而冻结开头，那些本该更新的东西——作废的 v1、过期的档期、改了日期的模板——就会被钉在前缀里。**省下的重读，可能是一次答错旧版的开始。**

第三，**换模型的影响面最大。** 它会让你调好的提示词、格式约束、缓存前缀全部失效，必须重测（见第 22、23 篇）。在结构还没定的时候换模型，你无法判断变好是因为模型，还是因为这次材料碰巧对了。

### 为什么顺序不能反：四种反序的长相

| 先做的 | 看起来省了什么 | 实际发生了什么 | 最后账单 |
| --- | --- | --- | --- |
| 先买缓存 | 前缀命中率好看，首段更快 | 材料被冻结，v1 一直留在前缀里；该更新的不敢更新 | 省了重读，赔了返工与一次错版 |
| 先换便宜模型 | 单价立刻下降 | 精确步骤一旦出错，草稿要整份重写 | 省了单价，赔了整轮重买 |
| 先做压缩 | 输入变短 | 摘要本身是输出，还可能把「未定」压成「已定」 | 买了两遍，还是错的 |
| 先裁材料、不砍轮次 | 每轮输入看起来短了 | 等砍轮次时，那几轮本来就不需要材料；裁好的版本还要在每一轮重复维护 | 省了一点输入，几轮裁剪白做 |

四种反序有一个共同形状：**都在后面的层级上使劲，前面的乘数没动。** 而最前面的乘数（轮次）恰恰是「买了几遍」的直接体现。这一篇的核心判断是「看买了几遍」，所以优化必须从「遍数」开始；先动后面的层级，等于承认前面的量不改，只想把已经决定的量买得便宜一点。

### 顺序背后的验收逻辑

还有一个更硬的理由：**改动的影响面，从结构到单价是递增的。**

- 砍轮次、裁材料：只影响这一个任务，改完用同一组样例就能复核；
- 检索与压缩：影响材料完整性，要逐条核对五类关键信息；
- 缓存与模型：影响所有任务，且会改变输出的抽样与格式，必须用评测集重跑（见第 22 篇）。

所以顺序也是「先改小的、可复核的，再改大的、要重测的」。反过来做，你会在一堆没复核的改动上再叠一个全局改动，最后不知道是哪一个起了作用。

**唯一的例外，是前两步已经没有可砍的东西。** 如果任务本来就是一次短调用、材料只有一小段、输出也短，那么结构项已经最小，系数项自然成为主项。这时候先选模型、先看缓存是对的——不是顺序反了，是前两步已经做完了。**顺序是优先级，不是仪式。**

## 21.8 缓存：省的是「买过的」，不是「想过的」

缓存这个词在账单语境里至少指两件事，省的东西不一样，前提也不一样。机制细节见第 08 篇，这里只算钱。

还有一件不在账上、但常被混进来的东西：同一次生成内部的 KV Cache。它省的是显存里的重算，让生成更顺，却不直接减少账单上的计费单位。**它不是一个省钱条目，别把它和「少买一遍」混为一谈。**

| 缓存 | 省哪一笔 | 命中前提 | 失效时账单上的样子 | 什么时候不该用 |
| --- | --- | --- | --- | --- |
| **前缀复用** | 同一段前缀的重复读入 | 从第一个 Token 起逐字相同；同模型、同版本、同模板、同顺序 | 命中率下降，输入量回升，但不会报错 | 材料每轮都变；开头带时间戳或用户名 |
| **结果缓存** | 整次模型调用 | 键包含问题、材料版本、权限、时间窗，且都相同 | 直接返回旧答案，账单很低，答案可能过期 | 时效性强、权限相关、个性化、材料常变 |

一句话区分：

> **前缀复用省「重读」，结果缓存省「重答」。两者都不省「该不该问」。**

换一个更直白的说法：缓存省的是**「已算过的前缀」**与**「已答过的问题」**，不是「想过的东西」，也不是「该不该想」。所谓前缀，是上一次真的算过、且这一次逐字没变的那一段；所谓「答过的问题」，是上一次真的答过、且这一次键里每个维度都没变的那一个。**没算过、算过但变了、答过但材料更新了，都不算命中。**

### 命中不是自动的

前缀复用的条件比大多数人想的苛刻。下面任何一处不同，共享就从那一点断开：

- 系统指令里带了当天的日期；
- 聊天模板换了，角色标记的顺序变了；
- 附件顺序换了，或者同一份文件这次抽取出的文本不一样；
- 开头有一个用户名、一个随机 ID、一个时间戳；
- 模型换了版本，或者精度档位换了；
- 分词器对同一段文字的切法不同（见第 03 篇）。

这些动作都很小，小到不会有人在改的时候想到「这会让我多花钱」。而**未命中是静默的**：账单上不会写「这次没命中」，只会写一个更大的输入量。

所以「我们上了缓存」不等于「账单会降」。要验证，只能做对照：同一组请求，改一处，看输入量与首段怎么变（见第 08 篇的检验）。

### 命中率高，可能是负债

这是最容易被忽略的一点。命中率可以通过「什么都不改」刷高：材料不更新、模板不动、日期不写。数字很好看，代价是**你也不敢改**。

一个健康的前缀缓存，应该满足两个条件：**该稳定的部分稳定，该失效的部分能失效。** 版本更新时必须让旧前缀失效——这不是事故，是设计。反过来，一个靠「冻结材料」换来的高命中率，省下的钱迟早会以一次错版的形式还回去。

结果缓存更直接：它省的是整次调用，所以一旦键漏了维度，错得也最完整。**过期、越权、个性化错配**三种，任何一种都不是「多花一点钱」能补的，它们碰到的是事实、权限与隐私三条红线。

### 缓存什么时候才值得谈

三个条件同时满足：

1. 这段前缀**确实重复**，不是「我觉得它以后会重复」；
2. 它**应该稳定**，不会因为业务变化而频繁失效；
3. 它已经**通过了前两步**——轮次砍过、材料裁过，剩下的确实是必要内容。

三条缺一条，缓存就不是杠杆，是安慰剂。**给一份没整理过的桌子讨便宜，便宜只会让你更舍不得整理。**

## 21.9 边界：能做什么、代价是什么、何时失效

这张三列账是本篇能拿去做决定的部分。每一行都是一个动作，不是一个名词。

| 动作 | 能做什么 | 代价是什么 | 何时失效 |
| --- | --- | --- | --- |
| **砍无产出轮次** | 直接去掉乘数，后面每轮都变轻 | 可能砍掉必要的澄清；要求一次说清，对表达能力有要求 | 任务本身需要逐步澄清，或每一轮都在产出新字段 |
| **版本过滤与材料裁剪** | 减少每轮输入，去掉干扰项 | 可能剪掉依据、例外、未定项；裁完必须复核 | 任务要求通读全文、跨页对照、逐字审计 |
| **工具返回字段化** | 把一页缩成几栏，后续每轮都受益 | 可能丢掉上下文与限定条件；要额外维护字段口径 | 需要原文措辞、条款、引用出处时 |
| **按需检索** | 用一次查询换一小片，避免全量上桌 | 多一次检索调用；可能召回错或漏 | 答案必须通读全文才能得出，或检索本身不可靠 |
| **结构化摘要** | 同样内容用更短的形式带上 | 摘要是一次生成，会花钱、会错、会丢「未决」 | 需要逐字引用、需要审计链、摘要已经失真 |
| **前缀复用** | 重复前缀的读入变便宜 | 前缀必须冻结；跨用户要隔离 | 材料常变、开头带时间戳、模型或模板换版 |
| **结果缓存** | 重复问题直接返回，省整次调用 | 过期、越权、个性化错配；键漏一个维度就稳定错 | 时效、权限、个性化、材料版本相关的问题 |
| **降档模型 / 分工** | 降低每单位单价 | 能力下降可能带来返工；提示词与缓存要重测 | 任务需要多步推理、精确计算、对外措辞 |
| **只并只读查询** | 压缩等待，不复制全量前置 | 并发额度、下游压力、合并成本 | 分支之间有依赖，或合并成本高于省下的时间 |
| **自动重试** | 对瞬时失败省一次人工 | 整份输入再买一次；写操作可能重复执行 | 失败原因是权限、材料缺失、格式错误——重试不会变对 |
| **二次确认（保险轮）** | 可能发现一处措辞问题 | 同源错误发现不了；没人看就是纯支出 | 没有明确比对字段；结果不进验收 |
| **关闭不展示的推理** | 可能减少看不见的输出 | 复杂任务的答案质量可能下降，返工更贵 | 任务需要多步推演；或该产品本来就不额外计费 |

这张表有一个总顺序，和 21.7 一致：**先动结构，再动内容，再动表示，最后动单价。** 每一行做完，都要用同一组材料复核「关键依据还在不在」。

### 这个类比在这里失效

「账本」是这一篇最顺手的类比：每一笔都记上科目，月底一对，就知道钱去哪了。它在下面这一步不成立。

**账本记的是已经发生的支出，而 Token 账的大部分在第一次调用之前就已经由结构决定了。** 你按下发送的那一刻，轮次、每轮的材料、工具返回的长度、并行几路，已经把总账的形状定住了；事后记账只能解释它，不能改写它。更麻烦的是，账本上每一笔都能指认用途，而模型账单上可能有一段**不展示的生成**，你只能看到它被计了量，看不到它具体写了什么。**账本假设「每一笔都可归因」，这一点在这里只成立一半。**

失效带来的实际后果有两个：

1. **不能等月底再看账。** 要在任务设计时就把「几轮、带什么、返回多长」写进预算，而不是事后心疼。
2. **不能要求每一笔都有明细。** 对不展示的生成，只能记「这一段有额外输出」，不能假装知道它花在哪一句上。

## 21.10 反例与正例：同一件事，两种省法

### 反例：账单涨了，先动单价

这是最常见的三步错法，每一步看起来都很合理：

```text
（示意）三条典型的错误省钱链

① 账单涨 ──▶ 以为单价贵 ──▶ 换便宜档位 ──▶ 草稿要重写，返工一轮
                （其实钱花在六轮重复输入）

② 账单涨 ──▶ 以为上下文太长 ──▶ 每轮都做摘要 ──▶ 摘要成了新的输出
                （其实原文根本不必每轮都上桌）

③ 账单涨 ──▶ 以为并行能省 ──▶ 三个分支各带全量 ──▶ 输入三倍，合并再返工
                （其实能并的只有四个只读查询）
```

三条链的共同点：**动作本身都不算错，错在它们都绕过了「买了几遍」这个问题。** 换档位改的是单价，摘要改的是表示，并行改的是时间；没有一条在改「同一份材料被买了几遍」。

反例的账，最后会落成 21.6 里 B 与 C 那种形状：一个 28,300，一个 32,100，都比「一次问全」贵，交付物却仍要人重做。

### 正例：四步走完，再谈单价

还是那套材料，还是那个交付物。按 21.7 的顺序做：

**第一步，砍轮次。** 六轮追问压成两个交付节点：先出结论，再出草稿。砍掉的是五轮没有新产出的追问，不是所有调用。节点内部再拆成四次只读查询、一次汇总、一次起草——调用次数没有变少，但每一次只带自己那一小片。中间的「再正式一点」「再总结一下」并进任务卡，不单独占一轮。原来第三轮只为改一个日期，现在把「日期必须回 v2 核对」写进第一轮的验收要求。

**第二步，裁材料。** v1 不上桌，只在「版本状态」一栏写一句「v1 已作废，以 v2 为准」；会议记录只取三条已定结论，不带全文；名单只带「去重后 39 人、2 人素食、1 人花生过敏」，不带 42 条原始记录。

**第三步，按需检索。** B 场地的档期不靠模型记忆，单独查一次，只回四个字段：日期、单价、容量、状态。合并时按字段对，不按段落对。

**第四步，缓存与分工。** 通知模板这一段在多轮里稳定，才值得前缀复用；字段抽取这类工作可以交给更便宜的档位，起草与对外措辞留给信得过的档位。分工前用同一组样例对照，避免「便宜了但错了」。

结果就是 21.6 里的 D：总账 7,500，墙钟 5.5 分钟，质量高。它不是靠「买得少」，是靠**每一片材料只买了需要的那一次**。

### 两种省法的分界

| 维度 | 反例 | 正例 |
| --- | --- | --- |
| 先动什么 | 单价、表示、并行 | 轮次、材料、检索 |
| 对「买了几遍」的回答 | 不知道，也没问 | 每一片材料都说得清买了几次 |
| 省下的钱从哪来 | 更低的单价与更短的摘要 | 少买不需要的，少重买已买过的 |
| 质量 | 通常下降，且不易察觉 | 不降，关键字段还多了来源 |
| 可复核性 | 只看总账，无法归因 | 每一笔能对上交付物里的一个字 |

分界只有一句话：**反例在「怎么买得便宜」上用力，正例在「该不该买」上用力。**

## 21.11 你可以自己做的检验：给一次任务列账单

十分钟，一张纸，不需要代码，也不需要重新跑模型。你只需要最近一次用过 AI 的多步任务，以及产品里的用量记录（没有用量页也行，用调用次数和材料量估）。

**第一步：摊开交付物。** 把你最终交出去的东西放在左边——一封邮件、一份通知、一张表。**只算真正交出去的版本**，不算中间草稿。

**第二步：列调用。** 从记录里把这次任务的每次调用抄下来：时间、这一轮带了什么、输入量、输出量。没有精确数字就估，估的时候只求量级对。

**第三步：估净材料量。** 把所有材料去重，只算一次。重复的文件、同一份材料的旧版、被引用两次的段落，都只算一次。

**第四步：填表。**

| 调用 | 这一轮带了什么 | 输入（估） | 输出（估） | 它产出了交付物里的哪个字段/句子 | 归类 | 下次怎么办 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 |  |  |  |  | 产出 / 保险 / 重复 / 失败 |  |
| 2 |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |
| 4 |  |  |  |  |  |  |

**第五步：算两个数。**

- 重复倍数 = 总输入 ÷ 净材料量；
- 白花笔数 = 「产出」那一栏填不出来的调用数。

**怎么读结果：**

| 你看到的 | 说明什么 | 下一步 |
| --- | --- | --- |
| 重复倍数 > 3，且「产出」栏大多填得出 | 结构没错，但每轮带得太多 | 先裁材料与工具返回，再谈缓存 |
| 重复倍数不高，但「产出」栏多格空白 | 轮次里有白花 | 先砍无用轮次 |
| 单笔输入特别大，且不是你写的 | 工具返回或附件过长 | 字段化返回，原文按需回查 |
| 有那么一两笔，产出只是「再润色一下」 | 表达层在重复购买 | 把要求并进任务卡，别单开一轮 |
| 有调用、无证据、无改变 | 保险轮没人看 | 要么写成字段比对，要么砍 |
| 总账不高但返工多 | 省在了前面，赔在了后面 | 把复核成本算进账，再比较 |

**判据。** 如果「产出」那一栏你有三格以上填不出来，先不要谈缓存，也不要换模型——**你还没有一张能归因的账单，换什么都是在猜。**

**这个检验能推翻本文。** 如果你的任务本来就是一次短调用：材料只有一小段、输出也短、没有工具、没有重试，那么重复倍数接近 1，六种白花一种都不成立。这时候总账几乎只由单价决定，先比较模型与缓存才是对的。**记录下这个条件**——它不是「顺序反了」，是前两步已经没有可砍的东西了。

第二种能推翻本文的情形：**任务要求逐字通读全部材料**（合同全文核对、审计底稿、法条比对）。这时裁材料会直接伤正确性，第二、三步要让位；宁可多买，也不能少看。**省钱的边界是正确性，不是预算。**

## 21.12 术语考古：三个和账单有关的词

这三个词的共同点：**它们都听起来像「计量」，实际都混着产品行为。** 一旦把某个产品的口径当成行业标准，账就会算错。

| 词 | 最早出处 | 原义 | 现在被怎么用 | 本文怎么用 |
| --- | --- | --- | --- | --- |
| **Token 计费** | 「Token」借自分词与编译领域，指文本被切成的片段；按 Token 计费是商业化之后的产品做法。**社区用语，没有统一规范定义。** | 用「切出来的片段数」作为计量单位，输入与输出分开计价。 | 常被当成「字数」或「消息条数」；也有人以为一次回答只算一次钱。 | 只指账单上的计量单位。它不等于字数，不等于词数，也不等于调用次数；输入与输出是两条线。 |
| **缓存命中** | 借自计算机体系结构里的 cache hit：要用的数据已经在更快的一层。 | 请求的内容已在缓存里，可以直接取用，不必重算或重取。 | 混指三种东西：同一次生成内的中间结果、跨请求的前缀复用、应用层的结果缓存；甚至被说成「它记得我」。 | 三种分开说。在钱这一篇只关心它省掉的是「重算」「重读」还是「重答」，以及命中的前提是否成立。 |
| **推理 Token** | **社区用语**，随「会先想再答」的产品形态出现；没有统一规范定义，各产品口径不一。 | 模型在给出可见答案之前生成的中间片段，不直接展示给用户。 | 被当成「思考过程」本身，或被当成「不收费的部分」；两种都可能是错的。 | 只指「不展示、但仍可能被计量的生成量」。是否计入输出、按什么口径计，**因产品、因版本而异**，必须查该产品当前的计费说明并记查阅日期。 |

三个词放在一起，误读路径是同一条：**把「账单上的一个数」当成「事情的全部」。** Token 不是字数，命中不是免费，推理 Token 不是「看不见所以不算」。

还有一条纪律值得单独写：**任何关于计费的说法，都要能回答「谁的数、什么版本、哪天查的」。** 产品会改口径，社区会传旧图；一个没有版本与日期的单价，和一句「大家都这么说」是同一种东西。

## 21.13 一页速记

| 你遇到的情况 | 先问什么 | 该动哪里 |
| --- | --- | --- |
| 账单比预期高几倍 | 同一份材料买了几遍？ | 先算重复倍数，再归因 |
| 只是多问了几句就贵了 | 每轮是不是都带了全桌？ | 砍无用轮次，历史只带结论 |
| 输入量突然跳高 | 那一轮多了什么不是你写的东西？ | 工具返回字段化 |
| 为了省 Token 做了摘要，账单没降 | 摘要本身花了多少？原文真的移走了吗？ | 只摘一次并冻结，或改成按需检索 |
| 重试之后更贵了 | 第一次是真失败，还是回执丢了？ | 先查状态，只读才自动重试 |
| 开了并行，账单涨了 | 每个分支是不是都带了同一份前置？ | 只并只读查询，前置只组装一次 |
| 加了「再检查一遍」，没人看结果 | 这一轮改变了哪个字段？ | 写成字段比对，或砍掉 |
| 缓存命中率很高，账单没降 | 命中省的是重读、重答，还是本来就不该买？ | 先砍结构，再谈缓存 |
| 想换便宜模型 | 前面的轮次和材料整理过了吗？ | 先做前三步，最后才换档 |

**五句话带走**

1. 贵不贵，不看一次多少字，看同一个结果总共买了几遍。
2. 输入与输出分开计价；写出来的字，下一轮还会作为输入再买一次。
3. 六种白花：重复输入、工具返回太长、摘要自身开销、失败重试、并行重复前置、保险轮没人看。
4. 缓存省的是「已算过的前缀」与「已答过的问题」，各有前提，命中不是自动的；高命中率可能是负债。
5. 顺序不能反：砍轮次 → 裁材料 → 按需检索与压缩 → 再谈缓存与模型分工。

**最后一句**：这一篇不要求你记住任何单价。它要求你在看到账单时，先做一个动作——**把交付物摊开，问每一个字是哪一次调用换来的。** 答不上来的那些，就是下次要先砍的地方。

**三道自检**

1. 同事说：「这次 6 次调用、每次 2,000 单位，一共 12,000；上次 3 次调用、每次 8,000，一共 24,000。所以这次更便宜。」这段算术对吗？「更便宜」这个结论还缺什么？
2. 「我们开了前缀缓存，命中率很高，所以账单一定会降。」这句话至少漏了哪两个前提？
3. 「不展示的推理 Token 也算输出，所以只要让它别想，就能省钱。」这句话有哪两处需要限定？

<summary>查看参考答案</summary>

1. 算术对，结论不完整。第一，两次的输入/输出比例可能不同，输出单价与输入单价不是一条线，不能只比总量。第二，6 次里如果有 3 次是没人看的保险轮，12,000 里就有一半没有进入交付物；而 24,000 那次如果一次做对，总账可能反而更低。第三，还要看质量与返工：便宜但错了，返工是整轮重买。正确的比较是「每个交付字段花了多少」，不是「总单位数谁小」。

2. 漏了两个前提。第一，命中省的是「重读」，不是「该不该读」；如果轮次没砍、材料没裁，账单的大头还在，缓存只降低了其中一段的单价。第二，命中的前提是前缀逐字稳定；如果为了命中而冻结了本该更新的材料（作废的 v1、过期的档期），高命中率就是负债，省下的钱会以一次错版还回去。还要补一句：未命中是静默的，账单上不会写「这次没命中」。

3. 两处。第一，「算输出」因产品、因版本而异，不是所有产品都这样，必须查该产品当前的计费说明，不能拿一个产品的口径当行业标准。第二，「别想」是否能做到、是否值得，是产品行为与任务质量的取舍；对需要多步推演的任务，压掉中间生成可能换来更高的错误率与返工，而返工是整轮重买。正确动作是先确认计费口径，再用同一组样例对照不同档位的质量与总账。
