# 06 · 模型是怎么练出来的：预训练、后训练与微调

> **状态**：已完成（初稿）
>
> **本篇定位**：区分改变模型长期行为的训练，和只改变一次回答的指令与资料；判断什么时候值得微调。
>
> **读法**：先看训练时间线，再用市集的三种错误选不同修法；暂不考虑训练的读者，可直接看对照表和练习。

## 要让模型知道通知改期，得再训练一次吗？

一个社区运营团队经常用 AI 整理报名。周五，他们发现草稿还写着周六，于是有人提议：「把新公告拿去微调，模型以后就不会错了。」另一个人抱怨的却是：日期都对，模型总漏掉待核对栏。第一个问题是**新事实没用对**，第二个问题是**一种交付习惯不稳定**，它们不该用同一张处方处理。

虚构市集原定周六；现行 v2 改为**周日 14:00**，雨天是否改室内待确认，旧 v1 已失效。现在只整理报名清单和通知草稿，不发送。新时间是有来源、可能再变的事实；「遇到资料不足要标未知」才是希望模型多次复用的行为。

**本篇的真问题：什么会改变模型的长期行为，什么只影响当下这次？**

```text
训练： 常见预训练 ─────→ 后训练（例如 SFT、偏好优化） ─────→ 得到用于部署的模型
       学基础语言模式        让回答更符合指令与偏好              保存训练后的参数
       └────────────────── 可能更新内部权重 ──────────────────┘

使用： 已部署模型 + 本轮指令与材料（可含检索结果） ──→ 本轮回答 ──→ 验收
       这次回答可以不一样，但普通使用并不在现场更新这些权重。
```

这是一条教学时间线，不是所有模型的统一生产工序。有的只发布基础模型，有的后训练分好几轮；拿部署用的成品再微调，也可以产生另一个部署版本。应用保存历史或偏好，与模型权重当场更新，是不同的事。

## 训练的几个阶段各练什么？

| 阶段或手段 | 它练什么 | 市集例子的边界 |
| --- | --- | --- |
| **预训练** | 在大量数据上学习一般规律；常见生成模型的练习之一是根据前文预测下一片段 | 因此知道「时间、地点、注意事项」像一份通知，但不是现场查询本场最新时间 |
| **监督式微调（SFT）** | 给输入及期望输出的示例，练在某种请求下如何回答 | 可用示例展示「缺证据时列待核」，但不能用它代替现在这份 v2 |
| **偏好优化** | 用较受偏好的回答与较不受偏好的回答等反馈，促使模型更倾向某些行为 | 可偏好保留不确定性的草稿；若反馈总选最肯定、最流畅的那份，也可能奖励了胡猜 |
| **部署后的普通使用** | 应用交付请求，模型使用已有参数生成输出 | 刚补上的 v2 可改变本轮回答；下一轮仍要确保应用带来了有效材料 |

「学会怎么起草」与「记住那份公告」也不是泾渭分明的训练结果：训练可能让模型记住部分例子，不过不能保证它按要求准确取回、及时淘汰旧信息，或说出可靠出处。涉及时间、政策和权限，仍应让模型引用当前材料，不把权重当档案柜。

## 微调调哪里？调多了又会怎样？

**全量微调**通常在原模型上更新全部或几乎全部的可训练参数，有机会广泛改变行为，训练资源和管理成本一般更高。**LoRA** 这类参数高效做法通常保留原来的权重，只训练附加的小规模参数，用它们改变模型计算的结果。部署时采用对应的训练结果，才能获得调出来的行为；并不是原模型的每一份副本都因此变了。LoRA 降低的是需要更新的参数规模，效果、推理成本和维护负担还要看任务与部署方式，不能仅凭名字断定。

| 训练时常听到的词 | 把它理解成什么 | 可能带来的变化 |
| --- | --- | --- |
| 学习率 | 每次参数更新大致有多激进 | 太激进可能让已有能力退化或训练不稳；很小也可能改变不够 |
| 步数／轮数 | 走了多少次更新，或训练材料被完整遍历多少轮；两者不是一回事 | 太少可能学不到期望行为；重复学同一批例子太多，可能熟练背题但不会应对变式 |
| 批大小 | 一次更新通常综合多少训练样本的信息 | 影响更新波动和资源开销；同样轮数下换批大小，更新步数也可能改变 |
| 数据质量与覆盖面 | 示范是否准确、一致，是否包含真实的难例与边界 | 只给齐全记录，模型没机会学到如何处理缺字段；把未核草稿当范例会教错习惯 |

这些词不是让普通用户去背一组通用数字。更重要的是问训练团队：有没有不同来源的样本、重复项和矛盾版本怎么标、有没有留出没参加训练的例子、训练后旧任务是否退步。报名表范例应脱敏或虚构；能接触真实报名信息，不代表可以把它拿去做训练材料。

## 手工练习：给三个错误开不同的处方

把三张纸写成三种症状，先自己选择「改指令」「改资料」或「考虑训练」，再和右栏对照。三种动作不是替代关系，工作中可以组合；先选成本最低、最对症的一个做对照。

| 纸上的症状 | 首选做法与理由 | 怎样证明真的改善 |
| --- | --- | --- |
| 草稿仍写周六；这次只给了 v1 | 先补 v2 和有效状态。少量文件直接给原文；如果经常需要从许多更新的公告里找依据，可用 **RAG**（检索增强生成）先找材料再作答 | 给相同请求换上 v2，验周日 14:00 与雨天待确认；同时放入 v1，检查不会把旧时间复活 |
| 事实正确，但一次草稿没留待核栏 | 在提示词里写明必交字段，给一份不含本场日期的示例；必要时用格式约束和验收 | 同一模型、同一材料，对照有无清楚的交付要求；用缺字段、重名行再试几次 |
| 大量同类任务中，即使资料、指令和检查都到位，模型仍反复在多个变式漏标 | 先对比其他候选模型；若任务长期稳定、有足够高质量示例，且返工成本值得，再考虑微调 | 保留独立样本，比较微调前后事实、格式、未决项和人工返工；如果变得不承认未知，就不能只凭格式变好上线 |

在答案旁边写两条验收红线：「雨天是否改室内只是待确认」「不发送」。加一个反例：把 v2 拿走，再问同样问题。能承认缺少现行材料，比恰好背出周日更符合可核验的目标。是否开放发送工具要在应用权限层决定，微调得再听话也不能代替这个限制。

## 边界与速记

| 做法 | 持续影响什么 | 代价和常见失效处 |
| --- | --- | --- |
| 改提示词、示例或应用模板 | 改变采用这份指令的调用，不改模型权重 | 发布快、可撤回；过长规则难维护，示例里的日期可能被误抄 |
| 附当前原文或接 RAG | 改变送给模型的证据；文档更新取决于资料管理与检索 | 需要维护来源、版本和权限；找到旧 v1 照样会错 |
| 微调并部署新版本 | 改变采用该版本的模型长期行为 | 需要数据、训练、评测与回退；不能保证完全服从、事实最新或次次无误 |

**速记：** 新事实补来源，偶发格式问题先改指令和验收，重复且稳定的行为问题才考虑训练。同一份 v2 不必重新背一遍；版本、事实和行动权限始终单独核。

### 自检（含简答）

1. **你贴了 v2，模型立即改口，这算训练了吗？** 不算；本轮材料变了，不等于训练权重发生改变。
2. **LoRA 与全量微调最大的直观差别是什么？** 前者通常保留原权重并训练小规模附加参数，后者通常更新全部或几乎全部可训练权重。
3. **有五百份格式漂亮的草稿，就能练出更可靠的模型吗？** 不能仅凭数量判断。要看标签与事实是否正确、有没有待确认和冲突样本、留出的测试是否通过，也要看其他能力是否回退。
