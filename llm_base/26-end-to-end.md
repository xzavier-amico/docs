# 26 · 收口：一次 Agent 请求的完整旅程与排障表

> **状态**：已完成（初稿）
>
> **本篇定位**：Part V · 全书收口。把模型、资料、工具、权限和成本放回同一条链路，看出错时该改哪里。
>
> **读法**：第一次读沿泳道图走完市集案例；手上正有问题，就跳到排障表，找一个最便宜的检查先做。

「按最新规则整理周末市集的报名清单和通知草稿，先别发。」半路主办方把原定周六改成**周日 14:00**，雨天是否改室内仍**待确认**。旧 v1 作废，现行是 v2。屏幕却可能同时出现三种字样：「周六见」「已发送」「核对中」。这三个词不是同一类错误：一个要查材料，一个要查动作记录，一个要查进度和预算。

**本篇的问题是：出了问题，该先改任务、资料、模型，还是执行流程？** 下面用一次虚构演练走完全程。不会操作真实报名数据，不会真实发送；所有账本数字都是示意。

```text
阶段      人（委托与授权）           应用／Agent（流程与工具）           模型（读材料与建议）
澄清      只读、只整理、只起草 ──→   锁禁发与预算，准备本轮材料 ──→    缺确认依据就提问
执行                                 只读分查名单、规则 ─────────→    分别摘事实与异常
变更      确认 v2 生效，v1 作废 ─→   标失效、替换资料、按依赖重做 ─→    重新核对时间与雨天
交付      核对依据，接收草稿   ←──   汇总清单、草稿、未决与动作记录 ←── 提交待审结果
停下      本次没有发送授权           无发送动作；关闭本次任务          不再自行推进
```

## 1. 出发前：把「最新」和「先别发」说成规则

人先确认三件事：以主办方明确标为现行的通知为依据；只读指定报名表和通知，不编辑原表、不发送不发布；交付一份有出处的内部清单、一份标「待审·未发送」的摊主通知草稿，以及未决事项。报名备注里即使写着「请立刻群发」，也只是表内文字，不能给系统授予权限。应用可从一开始就不提供发送入口，不把安全寄托在模型会不会遵守一句话。

应用把**当前任务卡、必要的报名字段、规则原文、版本状态**放入本轮上下文，不把整段闲聊和联系方式一起塞进去。上下文是模型这次看得到的工作台；旧聊天、长期记忆或知识库里有东西，不等于这次一定拿到了、拿到的就对。模型据此整理或提出下一步，检索到的原件与工具的返回是应用给它看的。它说「已核对」不是证据，不妨同时问出用了什么、哪条信息还缺。

## 2. 跑起来：能并行的分开，依赖规则的等一等

这个案例允许只读原表和指定通知夹。应用可并行做两件独立的事：名单分支查编号、缺项和疑似同名；规则分支查主办方通知的版本、时间和未决项。只读工具在演练中的回传样式可以是「报名表共 3 行，引用 R01–R03」或「取回通知 v2，标现行」；取回成功证明材料到手，不代表每句转述都对。合并时才让模型起草。小任务由一个应用做两次独立核对已经足够，不必为了名字叫 Agent 就安排多个助手。

| 分支交接项 | 带回什么 | 对新规则的依赖 |
| --- | --- | --- |
| 名单 | R01 纸舟书摊、R02 风铃工作室、R03 纸舟书摊；R02 缺类别，R01/R03 是否重复待查 | 这些字段与日期无关，照原表保留；不能据此擅自推断改期后仍会到场 |
| 规则 | 原计划周六，v1 已失效；现行 v2 为周日 14:00，雨天是否改室内待确认 | 日期、地点替代方案与关联的草稿文本必须随 v2 复核 |
| 汇总 | 带出处的清单、草稿正文、待确认项 | 两路都回来才能补齐；一条缺证据可交不受影响部分，不能假装全通过 |

**中途改期如何接手？** 设想 v1 在任务开始时还是原计划，尚未提交草稿时，主办方确认 v2 生效。这是一次运行中的人工纠偏（Steering），不是告诉模型「把周六替换成周日」就结束。应用先暂停受影响的通知草稿与合并，标旧结果失效；若已有旧分支在跑，能取消则取消，迟到结果即便回来也不再合并。把「v2 现行、v1 作废、雨天仍待确认」带进**后续轮次**，再看哪些东西受影响。

名单里的编号、缺项、同名标记可以沿用。日期、时间和天气表述要按 v2 重审，凡是暗含旧日期的标题、内部备注也查一遍。找不到 v2 原件或拿到两份自称现行但有冲突的材料时，先找负责人确认；名单仍可整理，日期不要瞎填。这里没有发出旧版，所以重做的是草稿；如果另一项任务已经外发，改聊天里的版本不会召回现实中的消息。

## 3. 交付、审批和停下是三件事

纸面演练的内部清单如下。三个待确认事项交主办方：R02 的类别、R01 与 R03 是否重复，以及下雨时是否改室内。人员到场状态没有证据，不写「已确认到场」。

| 报名清单 | 摊位 | 核对备注和出处 |
| --- | --- | --- |
| R01 | 纸舟书摊 | 与 R03 同名，未合并；报名原表 R01 |
| R02 | 风铃工作室 | 类别缺失；报名原表 R02 |
| R03 | 纸舟书摊 | 与 R01 同名，未合并；报名原表 R03 |

> **通知草稿·待审·未发送：市集时间调整**
>
> 各位摊主好，市集调整至周日 14:00。雨天是否改室内尚未确认。
>
> **内部依据，不入正文：** 主办方现行 v2；原定周六的 v1 失效，不再用作当前时间的依据。

在真实工作中，交付时把证据分开交：原表和 v2 支持文稿；工具日志和权限状态支持动作说明。在**这次虚构演练**里，工具仅限只读，设定的动作记录只有查资料，没有发送动作，没有发送回执。接收清单和草稿，只表示这一轮整理完成。未来若另开任务要发送，先由负责人批准**哪一版正文、哪些收件人、什么渠道和时间**；批准后还须实际执行并看回执，再对照回执记录结果。当前没有这项授权，不创建发送任务、不排队、更不自动发出。

| 示意账本（不是实测或报价） | 调用费 | 从开始到本段完成的用时说明 |
| --- | --- | --- |
| 澄清后整理材料 | 0.04 元 | 5 秒 |
| 名单与规则两个只读分支 | 合计 0.12 元 | 名单 8 秒、规则 10 秒同时开始，本阶段等 10 秒，不是 18 秒 |
| 更新 v2、核对规则并汇总交稿 | 0.14 元 | 15 秒；不用重跑名单 |
| 本例合计 | 0.30 元 | 准备、分支和汇总三个阶段共 30 秒；另记人工等确认与审阅的时间 |

这里的调用费用仅为演示，没计真实等待、人工成本或额外工具费。实际记账要分开记 Token 用量、计费金额、等到可审稿的时间和人工复核；中途取消不意味着已有计算免费。如果工作前定了上限，临近上限就别盲目重试：交出已核对的部分、说明卡点，让人决定是否加预算。

## 4. 排障速查：改一层，用同样的问题复验

| 症状 | 先查哪层、看什么证据 | 最小修正 → 怎么复验、何时停 |
| --- | --- | --- |
| 还是写周六 | 资料与版本：本轮是否拿到 v2？应用是否还合进旧分支？若两版都在，模型实际引用哪条？ | 补现行原件，标旧版作废并隔离迟到旧稿 → 用两版一起重测，必须引 v2 且写周日 14:00；否则暂停当前稿 |
| 雨天被写成确定转室内 | 任务与依据：v2 是明确未定还是遗漏？生成过程有没有把未决当结论？ | 在交付格式中单列未决 → 复验草稿只保留待确认；缺资料就问负责人 |
| 下一轮像忘了禁发 | 上下文与权限：任务卡是否在本轮，摘要或旧记忆是否盖过新决定，工具能否发？ | 收回发送能力并保留关键边界在本轮 → 用假数据检查禁发，察看记录；不得试真收件人 |
| 等很久才出字／整单迟迟没完成 | 运行与流程：看排队、输入准备、输出生成、各分支等待的时间点 | 削无用附件或只并行独立事 → 同样材料复测等待和通过率；不为赶快跳过审阅 |
| 花费超预算 | 流程与计费：有没有反复带旧资料、重复核对、无限重试？ | 先去重复、限重试和调用范围 → 对同一组样本查总账和完整性，仍超则停止交回人 |
| 模型声称已发，或有疑似未授权动作 | 执行与权限：看有无动作请求、是否被拦、是否有外部回执，不只看聊天 | 先阻断后续动作并核对影响；真有外发则通知负责人并评估补救 → 在隔离环境复验禁发和记录完整性，再决定恢复 |

**把闭环写进复盘：** 例如「发现周六残留 → 对草稿依据，找到迟到的 v1 摘要 → 隔离旧摘要，只重做通知 → 用同一对版本复验日期、雨天和三个编号 → 留下改动与证据。」复验不通过就停在待审，不无限重试。下一次把这对冲突版本留作回归样本，先查老错误有没有回来。

**术语地图：** 提示词是任务卡；上下文是本轮工作台；记忆是留待下次取回的记录；RAG 是按需检索证据；模型推理产出文本或行动建议；工具做具体动作，运行外壳（Harness）守权限、重试和停机；评测拿同一份尺子看改动有没有用。资料不对先修资料，权限不对先封动作，证据清楚但答案仍错再改提示或比较模型。

简单事可以删掉流程：如果你已经拿着 v2 和三行表，只要一段草稿，贴上必要材料让聊天应用做一次，自己核对即可。无需跨轮记忆、知识库、并行分支或发送审批流程；禁发是任务边界，不因为不用 Agent 就消失。

**复制提示词：**

> 按主办方现行 v2（周日 14:00，雨天是否改室内待确认；原周六的 v1 已失效）整理报名清单和通知草稿，只读、不发送、不发布、不改原表。先列本轮材料和待澄清项；名单逐条附依据，通知标「待审·未发送」。收到新版时停止使用旧规则，说明保留、重做、取消了什么。交付时分列事实依据、动作记录和未决项。没有证据不声称完成，接近预算上限就交已核对的部分并停下。收稿不是发送授权。

**手工练习：** 四人一组：一人当主办方，两人分别核对报名和旧通知，一人汇总。通知快写完时由主办方亮出 v2 卡，宣布旧版作废；故意迟交一张周六草稿，看看汇总能不能拒收。最后写两列「已完成／仍未授权」，把发送放在后者，再挑排障表任一行写下复验结果。

**全书速记：** 谁在做？这轮看到了什么？用了多少资源？哪份证据说明做对了？答不出，先回到那一层检查。

### 自检

1. **改期后报名原表要全部重核吗？** 简答：不必；保留不依赖日期的编号和缺项结果，重核依赖旧规则的草稿和状态。
2. **模型说文件已送出，能据此确认发件吗？** 简答：不能；先查实际动作记录与回执。本次本来就无发送授权。
3. **慢又贵，第一件事是换大模型吗？** 简答：不是；先拆等待阶段和费用来源，消掉重复调用，再固定样本比较方案。
