# 17 · Agent 的记忆：写进去、找回来、改得掉

> **状态**：已完成（初稿）
>
> **本篇定位**：Part IV 第 3 篇。分清本轮知道、上次留档和跨会话记忆，学会决定资料保存到哪里、留多久。
>
> **读法**：先看五类信息对照，再用保存表模拟一次「换会话＋改决定＋撤回偏好」。

## 新会话里还记得你爱用表格，却忘了改期？

在虚构的周末市集案例里，你上次请 Agent 把报名清单做成表格，通知先起草，**不发送**。市集原定周六，旧 v1 已失效，现行 v2 写着**周日 14:00**，雨天是否改室内仍待确认。你关掉窗口，重新开一段对话说「继续做市集清单和通知」。它给了表格，却用回周六。也有另一种错误：换一场活动，它还把这次的周日 14:00 当成你的长期习惯。

两种表现并不矛盾。「喜欢用表格」可能是取回的个人偏好，也可能只是模型恰好这么写；本次市集的日期则属于有版本的任务事实。没有把任务状态带回来，助手就不能用个人偏好替代它；只记过一个日期，也不该在另一个任务里当作默认。**本篇的真问题：跨会话记忆是谁写的、何时拿出来、错了怎么改或删？**

## 1. 五样东西，看起来都像「它记得」

| 信息从哪来 | 它是什么 | 换会话时能指望什么 |
| --- | --- | --- |
| 本轮上下文 | 应用这次实际送给模型的指令、材料和消息 | 现在能用，不等于下次还有；看见一句也可能用错 |
| 会话历史 | 产品留存或界面显示的这一段对话 | 旧窗口可见不等于新窗口可读；同一窗口也不保证每轮带全 |
| 跨会话偏好 | 应用为这个人或授权范围保存的稳定选择 | 支持并启用时可按需取回，如「清单优先用表格」；不凌驾于本次明确要求 |
| 可恢复的任务状态 | 某个任务的版本、进度、约束、未决与产物指向 | 重新进入有权限的任务时可续做；须核对是否是最新状态，而非套进所有聊天 |
| 模型权重 | 训练后相对固定的参数，影响常见知识和行为 | 不是个人备忘录；应用保存一条偏好不等于立即改了模型权重 |

这里的「记忆」主要说应用或 Agent 管理的外部记录。一些产品可能从历史自动提取偏好，有些只在你明确保存时写入，有些不提供跨会话功能。「产品是否把数据用于另一个训练流程」是另一件事，需要看具体条款和设置，不能从聊天里一句「记住」或「忘掉」推断。会话历史也可能成为应用找回材料的来源，但**历史记录、个人偏好和任务状态的用途与清除范围不同**。

## 2. 记忆不是一个开关，而是一条可以反向走的路

```text
用户或任务负责者：说明目的、授权范围和保留期限
                     ↓
应用筛选：临时输入、个人偏好、任务状态，还是不保存？
                     ↓ 保存合适的记录，标来源、范围、时效
新会话或恢复任务 ──→ 核对身份和任务 ──→ 只取需要的有效记录
                                            ↓ 加入本轮上下文
                                       模型用来起草，交人核对
                                            ↓ 发现冲突或收到变更
        查来源、修正或删除对应记录 ←───── 用户／负责人提出更正
                     ↓
         下次取回时验证旧记录不再生效；复核已生成的产物
```

应用可能选错保存对象、没取到旧任务、拿到同名活动的记录，或把一条过期记录排在前面。模型也可能明明拿到正确记录却没按它写。关键事实最好让人能核对其来源、版本和有效期；如果看不到实际取回内容，要求它列出使用了哪份可打开的材料，并对照材料复核，而不是只问「你到底记不记得」。自述可能只是生成的一句话，不是系统确实保存、读取或删除的回执。

## 3. 先选范围，再决定写不写

| 候选信息 | 合适的处理 | 取回或隐私边界 |
| --- | --- | --- |
| 「以后做清单优先用表格」 | 若你明确同意且产品支持，可留为个人偏好 | 仅对约定的用户或空间可用；本次想用分组文本时，以这次为准 |
| 「现行 v2：周日 14:00；v1 已失效」 | 放市集任务状态，保留版本与来源位置 | 查对活动是否是这一场；不保存成用户的永久活动时间 |
| 「雨天是否改室内待确认」和「不发送」 | 放本次任务状态；续做时重核当前边界 | 未决有负责人和确认依据；更换窗口不消除限制，也不产生发送授权 |
| 原报名表、手机号、住址等 | 按任务实际需要与授权处理；能只用必要字段就不用完整原表 | 不写入通用偏好或通知；获准保存的名单只在受限处留存，并规定谁可取、何时清理 |
| 「今天这份草稿临时排成两列」 | 本轮用就好，通常不设长期记忆 | 一次性需求不是偏好；不确定先问，不替用户默认勾选 |

一个好用的选择题是：「只在本轮用、在这项任务内留、跨会话留为偏好，还是不留？」例如你可以说：「表格偏好只在我的空间使用；名单不存入个人记忆，日期只留在本次任务。」不过自然语言说明不等于产品已有对应控制能力。如果系统不能保证所需范围或期限，就不要上传那部分敏感资料；可改用脱敏字段，或者让有权限的人在受控位置人工处理。退出记忆功能，通常也不等同于取消聊天历史、日志或数据使用；按产品支持的控制项分别核查。

给任务状态设一个退出条件也有用：例如市集交付完成后，不再在普通聊天里主动取回名单；任务若还需留档，由负责人按适用规则保留必要记录。这样既不会把进行到一半的工作突然清空，也不会让一次性任务不断跟到新对话。共享空间还要问「是谁的偏好」：一位同事喜欢表格，不代表这个偏好应自动写给整支团队，团队约定也不应泄到成员的个人空间。

## 4. 两类冲突，两种纠正

**偏好冲突**：上次存了表格偏好，这次明确说「请按分组文本输出」。先尊重当前要求；「这次例外」不应自动覆写长期偏好。若你说「以后也不用表格了」，再要求更新或删除对应偏好，核查新会话是否还会取回旧版本。即使下一次模型碰巧用了表格，也不能仅凭样式断定删除失败；要结合可用的记忆管理记录来判断。

**事实冲突**：恢复市集时搜到周六和周日。不要一看到较新的聊天句子就覆盖。查活动身份、确认来源、现行有效版本；本例 v2 取代 v1，周日 14:00 生效，雨天仍待确认。把任务状态里的 v1 标成失效；需要保留旧版作审计时，限制它的可用范围，避免作为现行依据再次取回。已有草稿一并复核；删除旧记忆不会自动改掉别人已保存的副本或草稿。清除记忆、清除历史及附件、清除其他系统的保留副本可能涉及不同操作和保留义务，不能承诺一句「忘掉」就让所有副本消失。

## 5. 手工练习：把两种卡放进不同信封

拿三张纸：一张「偏好卡」写「用户明确同意以后清单优先表格」；一张「任务卡」写「这场市集：v2 周日 14:00、v1 周六失效、雨天室内待确认，仅整理清单和通知草稿，不发送」；一张「本轮纸条」写「这次请用分组文本」。把前两张装进不同信封，只在对应情境打开。让同伴分别模拟继续此任务、新起另一场活动，以及撤回偏好后的会话。

**参考检查**：续做时，取有效任务卡和用户本轮要求，输出可用分组文本但仍写周日 14:00；新活动不可使用旧日期或名单，可按授权取个人偏好；撤回长期偏好时，移除或更正偏好卡，不应误删本任务现行 v2。再故意把 v1 放在任务信封最上面，看看同伴是先看有效标记，还是拿到哪张就抄哪张。若找不到 v2，应该请提供现行版本，不凭旧卡续写确定时间。

**速记**：保存是选择，不是义务；有记录不代表会取回；取回不代表用得对；更正要落到对应记录和受影响的产物，删除须查清范围。

**自检（含简答）**

1. 说「记住周日 14:00」，应该写入模型权重或我的默认偏好吗？**都不应。** 它是这一场市集、由 v2 支持的任务事实。
2. 关了跨会话记忆，旧对话和所有副本也消失了吗？**不能这样推断。** 各类留存和删除由产品规则分别管理。
3. 保存了「不发送」，换会话自动取到了吗？**不保证。** 续做须核对任务状态，运行端仍应维持不发送的权限限制。
