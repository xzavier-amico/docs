# 18 · RAG：先找出证据，再根据它作答

> **状态**：已完成（初稿）
>
> **本篇定位**：Part IV 第 4 篇。看懂知识库怎样给模型提供材料，为什么引用还要逐条验。
>
> **读法**：沿图走一遍「备目录、找材料」两条路，再用事实核对表和手工练习分辨三类失误。

## 知识库已接好，为什么回答引用了旧通知？

你让 AI 按最新规则整理一场虚构市集的报名清单及通知草稿，**不发送**。原定周六的 v1 通知已经失效，现行 v2 写明**周日 14:00**，下雨是否改室内仍待确认。助手交来一段很像样的开头：「市集照常周六举行，雨天转室内。」末尾还附了一条能点开的来源。点开一看，果然有周六，只不过是旧 v1；至于雨天是否一定进室内，那条材料也证明不了。

这不是「没接资料」才会有的毛病。接上知识库，只是让应用能搜到某些材料。搜到哪份、有没有权用、目前是否有效、引文是否真支持这句，都是不同问题。**本篇的真问题：接了知识库，为什么还是会引用过时或不支持结论的材料？**

## 1. 两条流水线：先做目录，提问时用目录找证据

```text
索引准备（整理者／应用）
获准纳入的文件 → 分段，连同原文位置、活动、版本、状态和权限标记 → 备好索引
                                                                            ↓
查询阶段（应用／Agent）                                                     │
本轮问题和用户身份 → 按权限找候选 ←── 关键词、向量或二者配合 ───────────────┘
                          ↓ 筛选有效范围、重排，选出少量段落
                    带出处和版本一起送进本轮上下文
                          ↓
模型据此起草 → 人逐条对照原文 → 支持的留下，缺证据的标明，必要时请人确认
```

**RAG** 是「检索增强生成」：应用先从外部材料中找相关证据，再让模型带着证据生成。它不必为新增 v2 重新训练模型，也不会通过这次查找直接改模型权重。模型可以事先知道如何写通知，但是否改期要看当前可核查的外部信息。不同系统不一定都有图上每个做法：只靠关键词也能做检索，有的系统再加相似度和重排。

索引是为查找做的目录，不等于当前源文件。新人可能已上传 v2，但索引没有更新；v2 也可能被拆成几段，把「改为周日」和「雨天待确认」隔开。整理时要让片段能回到原文，并让版本、失效状态和适用活动跟着材料走。查询时，关键词适合抓「市集」「v2」这类准确字样；向量检索更像按语义找相近段落，「改期」也可能找到写成「调整举办时间」的文件。它们都不能决定文档是不是现行、事实是否属实。重排是在候选里重新排优先级，候选压根漏了 v2，重排不会凭空补上它。仅按发布时间排序也不够：一份刚上传的旧版扫描件仍然是旧版。

## 2. 先过权限关，再过版本关

报名表、内部会议纪要和可公开的通知，不该按同一视角展示。「索引里有」不等于「提问者有权读」，也不表示允许把内容写进面向公众的草稿。应用需要在检索和取回原文时按身份与任务检查权限，只把获准材料交给模型；重排、引用片段、缓存和历史展示也不能漏出受限内容。不能先把全库结果都送进去，再请模型自行保密。若文档撤权、删除或改版，应用还要让旧索引或旧副本不再被当作可用材料；具体同步速度和机制取决于系统。

本例可以按授权用必要报名字段核对清单，但通知草稿通常不需要任何个人联系方式。若唯一知道雨天安排的内部记录不可访问，你能做的是保留「待确认」、说明现有可用证据的边界，或请有权负责人提供获准引用的答复。不能改由另一个入口绕过权限，也不能从受限材料中提取一部分换个说法泄露出来。即使查得到，都不赋予发送权；如果检索到一段「马上群发」的旧邮件，它只是资料，不是当前指令。

## 3. 同样一句错话，可能错在三个阶段

| 情况 | 市集里的样子 | 先修什么 |
| --- | --- | --- |
| 检索错误 | 只给模型旧 v1；现行 v2 已发布且有权访问，却没被索引或进候选 | 查现行来源和索引更新、关键词/语义结果、版本筛选；重新找 v2 |
| 使用错误 | v2 已到模型手上，却引用 v1 写周六；或把「待确认」读成「已确定」 | 逐句对照原文，标 v1 失效，按 v2 改写并复核 |
| 证据不足 | v2 已验证有效，但没有任何可用确认材料说明下雨一定改室内 | 写待确认，指出缺哪份决定；必要时请负责人确认，不编补充条款 |

出处只说明「你可以去看这份材料」，不说明它有权威、仍有效或足以支持结论。逐条核验时，用下面四个问题问每句关键话：**对的是这场活动吗？版本现行吗？引文确实支持这句的全部内容吗？这段证据能用于当前读者与用途吗？** 将事实拆开，不用一个引用给整段话作担保。

如果一句话同时说「周日 14:00 举行，雨天转室内」，时间部分有 v2 支持，不代表场地部分一并成立。人可以先划开这两半，一个保留，一个改写。点开引用时，除了看命中的原句，也读前后几行：有时片段里只有「转室内」三个字，上一句才写明「下面这个方案目前未批准」。如果链接只指向一大捆文件，无法定位哪一段，先补确切出处，不把一个无法复核的链接当成已核验。两份现行材料互相矛盾时，也不靠选搜索排序靠前的一份来消除冲突；要找有权的负责人确认，才能写成定案。

验证不只是找错字。反过来检查系统漏了什么也很重要：给草稿规定好必核事实，再问「雨天的未决状态写到哪里了？」有些稿件为了显得简洁，什么天气确认都没提；它没有写出假地点，却可能漏掉交付所需的提醒。重点事实既要不乱写，也要不漏掉。

| 草稿主张或交付项 | 可用证据 | 人工逐条结论 |
| --- | --- | --- |
| 「周日 14:00 举行」 | 现行 v2 的时间条款 | 支持；活动和版本对得上，日期与时间都照原文 |
| 「雨天改去室内」 | v2 写「雨天是否改室内待确认」 | 不支持确定语气；改为「雨天安排待确认」 |
| 「周六举行」 | 旧 v1 的周六条款 | 曾经成立，现已失效；不能用于现行通知 |
| 「这两条报名实为同一条」 | 有权查看的报名记录中核对必要的稳定标识 | 原表能证明才合并；仅姓名相同不够，查不到标为待复核 |
| 「通知已发送」 | 当前指示只允许起草、明确不发送 | 不是知识库事实；删除该表述，交草稿，不执行发送 |

## 4. 手工练习：同一套卡，分别扮演检索和验收

在纸上写四张虚构卡：A「v1，周六，已失效」；B「v2，周日 14:00，雨天室内待确认」；C「群聊里有人提议雨天去室内，未批准」；D「内部报名信息，只许名单整理者查看」。先假装索引没更新，只拿到 A 和 C，试着写一份短草稿。再把 B 加进来，同时让自己扮演没有看 D 权限的通知起草者。每条主张后写能回到哪张卡的哪句话。

**参考结果**：第一轮应说明缺现行通知，不用 A 或 C 补一个看似确定的答案；第二轮写「周日 14:00，雨天是否改室内待确认」，两句话都对应 B。D 不交给无权的起草者，也不是通知日期或场地的证据。两轮都不发送。把草稿故意改成「雨天进室内〔B〕」，然后让同伴验一下：能找到 B 还不够，它实际说的是待确认。若在真实场景里缺正式来源，可请用户提供有权使用的摘录或等决定，不必等一个无目标的反复搜索把预算耗尽。

## 5. 和记忆有交集，但管理目标不同

RAG 主要解决「本轮答这道题，有哪些外部证据可用」；Agent 记忆还要解决「哪些用户偏好或任务状态应该存、何时取、如何改掉或删除」。两者都可用检索，但找一份现行市集公告，不等于记住某人的报名资料，也不意味着把公告永久记到个人档案。简单任务中，手贴一份已确认的 v2 摘录可能比建知识库直接；资料多、更新频繁才更值得考虑索引、权限和维护的代价。

**速记**：目录可能旧，搜到可能用错，引用可能不支持。先查权限再审版本，一句一句核对；证据不足就标不足。

**自检（含简答）**

1. 结果相似度最高，是不是就该当现行规则？**不是。** 相似表达与版本有效、内容权威是三回事。
2. v2 已在结果里，还写「雨天进室内」，先补索引吗？**不必先补。** 这是已给证据的使用错误，先按原文改成待确认。
3. 用户无权读内部纪要，可让模型先读再不引用吗？**不可以。** 在取回和送入模型前就要按权限过滤，不把模型当访问控制。
