## 07.1 引子：一条三个月改一次的规则

虚构场景。一家公司的内容运营组有一条规则：

> 对外发布的活动信息，日期与场地只能取自现行版本；发布前必须由有权限的人确认，确认人当天是谁，以值班表为准。

这条规则不是随口一说，它写在《对外发布规范》里，有版本号，有生效日期，也有作废标记。而它**每季度会改一次**：报备的提前量会调，确认人从「行政负责人」换成「值班主管」，有时还会加一句「雨天方案未确认时，通知里必须写明待确认」。

三个月前，有人提了一个想法：**把它训练进模型里，让它永远记住，以后就不用每次交代了。**

这个想法听起来很自然。我们日常说「记住」，指的就是「下次不用再说」。人靠记忆做到这件事，所以很自然会假设模型也一样：多说几遍，或者「拿去训练一下」，它就记住了。

接下来发生的事，几乎每次都一样：

- 第一版规范贴进系统提示词，效果不错；
- 一个季度后规范改成第二版，新的一版被追加在后面，旧的那段没人敢删——因为「删了怕它忘」；
- 两个版本在提示词里并存，模型开始在「前一天报备」和「当天上午报备」之间摇摆；
- 有人提议：「要不微调一下，让它彻底记住。」
- 微调做完，旧版本的行为确实少了；但两个月后规范又改了，这次没有人知道该去哪里改——**因为那条规则已经不在任何一份文件里，它在一堆数里。**

这条链上，每一步都很合理，合起来却是一次典型的**层错配**：把一个「需要按版本管理、随时能撤」的东西，放进了「没有版本、不能撤」的那一层。

这就是本篇要解决的问题。它不涉及任何实现细节，但它决定你在「提示词、知识库、微调、换模型」这四个选项之间怎么选——而且**选错的代价不是效果差一点，是以后改不动。**

先看一个更小的现场，它把「规则」和「事实」的区别摆得很清楚。

团建这条线上，「**日期以现行版本为准**」是一条规则；「**10 月 25 日**」是一个事实。规则的寿命以季度计，事实的寿命以天计——它今天对，明天可能因为一场雨、一个档期而变。把规则和事实一起塞进同一段提示词，是最常见的做法，也是最容易一起烂掉的做法：三个月后规则改了，那句话还留在原地；而日期这种一天一变的东西，本来就不该由提示词来担保。

**「记住」这个词，把两件完全不同的事混成了一件。** 本篇要做的，就是把它们重新拆开。

## 07.2 唯一真问题：什么能长期改变它

**想让 AI 永远记住公司新规，该改提示词、接知识库，还是重训？**

短答案有两句，第二句比第一句重要：

1. **能长期改变它行为倾向的，只有一类东西：改变了权重的那些动作。** 其余全部是「每次带上」，改的只是这一次的条件。
2. **但「记住一条会变的规则」这件事，恰恰不该走改权重那条路——因为权重里没有「这一条」，也没有「撤回这一条」。**

第 1 句是机制，第 2 句是判据。两句合起来，就是本篇的反直觉命题：

> **能改的都不持久，持久的都改不动。**
>
> 所以「该放哪一层」的正确问法，不是「哪一层更高级、更彻底」，而是「**这条东西以后要不要单独撤掉、单独改一版**」。要，就放携带层；不要，才可以考虑固化。

它由 P4 直接推出。P4 说「有些东西烧进权重，有些只能每次带上」——这句话本身只是分类。但加上一个观察——**权重是整体训练的产物，没有条目、没有地址、没有版本号**——分类就变成了判据。

这个观察值得先说透，因为整篇都靠它。

### 权重不是数据库

我们用「记住」这个词时，借的是人的记忆模型：一条一条存进去，需要时取出来，不要了删掉。权重不是这样。

训练做的事，是拿大量文本，反复调整一大堆数，让「下一个片段」的预测误差小一点。训练结束后，那堆数里**没有任何一格对应「报备要提前一天」这句话**。这条规则的效果，分散在成千上万个数的组合里，和语法、语气、领域词汇、标点习惯混在一起。

于是有四个「做不到」：

| 你想做的 | 权重层能不能做 | 为什么 |
| --- | --- | --- |
| 只写入这一条，别的不动 | 不能 | 没有「这一条」的位置；任何一次训练都会同时动到很多别的东西 |
| 只读出这一条，看它还在不在 | 不能 | 你只能看它的输出，不能查它的存档 |
| 只删掉这一条，别的保留 | 不能 | 没有删除接口；想让它「忘」，只能再训练，而再训练会连带改别的 |
| 给这一条打上版本号和生效日期 | 不能 | 权重里没有元数据这一层；它不知道自己属于第几版 |

第四行最致命。因为**「新规」的本质不是一段知识，而是一条带生效日期、带适用范围、带撤回机制的约束。** 它天生需要版本管理。而权重恰恰是全书里最不具备版本管理能力的一层。

把一条规则放进权重，等于把一份需要盖章的文件，抄进了一本没有页码、没有目录、也不能撕页的书里。

**这就是「多背一遍」注定失败的机制原因**：不是它背得不够多，是它没有一个可以被「背」的格子。

### 「烧进去」也不等于「一定照做」

还有第二层失败，很多人没意识到：**即使它真的学进去了，也不保证这一次会服从。**

因为生成时，权重只是先验，本轮的材料和指令是条件。模型看到的是「指令 + 材料 + 已写出的前文」，它接的是这个前文的下文。当权重里的倾向和本轮材料冲突时，谁赢**不确定**——取决于材料有多显著、措辞有多直接、位置有多靠后。

这解释了一个常见困惑：

> 「我明明微调过，它怎么还是按老规矩来？」

答案可能是：微调确实把新规矩写进了先验，但这一轮的系统指令里还留着旧规矩的一句话，而那句话离生成位置更近。**先验和条件打架时，近的那个通常更响。**

所以固化买到的是「默认倾向」，不是「保证服从」。而「保证」这件事，从来不在模型层——它在权限、校验、回执那里（→ 16、17）。

用四个定位问题里的一问收一下：

> **第 1 问：这句话是谁说的？** 当有人说「已经训练过了，它现在知道我们的规矩了」，要接着问：是**训练流程**说的，还是**应用配置**说的？训练流程能保证「数据喂进去了、损失降下来了」，它不能保证「这条规则在每一次请求里都被执行」。后者要靠材料、指令和校验。

### 一条推论：越会变的东西，越要放外面

由上面两句可以直接推出一张排序，它比任何选型建议都稳：

| 东西的性质 | 该放哪 | 理由 |
| --- | --- | --- |
| 每天/每周在变（日期、价格、名单、档期） | 材料层，每次带上 | 它变的时候，你必须能立刻换掉 |
| 每季度在变（审批人、报备时限、口径版本） | 文件 + 指针 + 过滤 | 要能单独改、单独撤、单独签字 |
| 一年以上不变，且需要「不用提醒」 | 可以考虑固化 | 稳定到值得付出「撤不回」的代价 |
| 几乎不变，但也不影响行为（比如某段历史） | 放不放都行，但别为它训练 | 训练的钱应该花在行为上 |

这张表没有一行写着「能力越强越好」。它问的是**变化频率**和**撤回需求**，因为那才是决定「放哪」的两个变量。

## 07.3 一张图：两栏，一条分界线

把「能改变它的东西」按生效范围画成两栏，分界线一眼可见：一边改一次、全体生效、撤不回；一边改一次、只影响这一次、随时可换。

```text
            ┌──────────────── 固化：改一次，长期生效 ────────────────┐
            │                                                        │
  语料 ──▶ │  预训练 ──▶ 后训练/指令微调 ──▶ 偏好优化 ──▶ 微调/LoRA │ ──▶ 权重
            │  （基座）     （学会听指令）     （学会取舍）    （适配） │      │
            └────────────────────────────────────────────────────────┘      │
                                                                             │
              改一次，影响所有用户的所有请求                                  │
              想单独撤掉某一条：没有接口                                        │
                                                                             ▼
   每一次请求 ──▶ 应用组装 ─────────────────────────────▶ ┌──────────────────────┐
                  系统指令 / 提示词 / 附件 / 检索 / 示例    │ 模型：按权重 + 本轮  │
                         │                                 │ 前文，续写并抽样     │
                         │ 改一次，只影响这一次             └──────────────────────┘
                         ▼
            ┌──────────────── 携带：每次带上，随时可换 ────────────────┐
            │  系统指令 · 任务卡 · 附件 · 检索结果 · 少样本示例 · 工具说明 │
            └────────────────────────────────────────────────────────────┘
```

这张图有三个要点，每个都值得单独说。

**第一，两栏不是「高级」和「低级」的关系。** 携带栏里放着系统指令、附件、检索结果——这些恰恰是决定一次任务对不对的关键材料。固化栏里放的往往是语言能力和表达倾向。**绝大多数「业务正确性」问题，答案都在下面那一栏。** 把它们想成「临时办法」和「根本办法」，是这套判断里最常见的一次误读。

**第二，两栏的修改成本差着量级。** 改一句系统指令是分钟级，换一份材料是分钟级，重建索引是小时级，做一次微调以天计，重训则是以周或月计。这个次序不是精确值，是**相对次序**，而它已经足够决定策略：**能用便宜的那一层解决的，不要用贵的那一层。**

**第三，也是最少人注意的一点：只有固化栏会「改不回去」。** 携带栏里的一切，删掉就没了；固化栏里的一切，想撤回只能再训练一次，而再训练一次又会带来新的不确定。**可逆性，是这两栏最本质的差别**，比成本差别更重要。

把「谁在做什么」摊开，责任也很清楚：

| 谁 | 在固化这一栏里做什么 | 在携带这一栏里做什么 | 最容易越界的地方 |
| --- | --- | --- | --- |
| **人** | 决定要不要训练、批准训练数据、签字验收 | 写任务卡、选材料、定验收标准 | 以为「批准训练」等于「批准了行为」 |
| **应用** | 几乎不参与，它只是调用训练好的权重 | 组装这一轮的指令、附件、检索结果 | 把「上传成功」当成「已送入」（→ 05、09） |
| **训练流程** | 洗数据、调四个旋钮、跑评估 | 不参与 | 用训练集上的表现代替真实任务的表现（→ 22） |
| **模型** | 承载结果，但不报告「我学到了什么」 | 按本轮前文续写 | 把它的自述当成「它知道自己会什么」 |
| **工具 / 运行时** | 不参与 | 执行动作、给回执 | 让「训练过了」代替权限校验（→ 16、17） |

这张表最右边一栏是重点：**每一层都有一个「以为自己做完了，其实没做到」的版本。** 而这些误会的共同形状，都是把上一层的动作，当成了下一层的保证。

## 07.4 机制一：五个阶段，各自改什么、不改什么

下面这条流水线，是最常见的一种组织方式。**它不是每个模型都必经的配方。** 不同厂商的流程不同，名字也不同：有的把后训练和偏好优化合成一步，有的先做偏好优化再做指令微调，有的只做其中两三个，有的对同一个模型反复跑好几轮。所以读这张表时，要看的是「**每一类动作改变的是什么性质**」，而不是「第几步到第几步」。

```text
   ① 预训练            ② 后训练/指令微调        ③ 偏好优化          ④ 微调          ⑤ LoRA
  大量通用文本   ──▶   指令—回答样例      ──▶   好/坏回答的比较  ──▶  领域数据   ──▶  小增量参数
  学「下一个片段」      学「被要求时怎么答」      学「哪种更受欢迎」     学「这个领域的活」   只训一小块
       │                    │                      │                   │                │
       ▼                    ▼                      ▼                   ▼                ▼
   语言规律、体裁      服从指令的形状         语气、长度、拒答边界    领域词汇、格式     同样的行为适配
   模糊的世界知识      任务模板               取舍倾向（含迎合）      稳定的输出习惯     可插拔、可撤
```

### ① 预训练：学会「话该怎么接」

**改什么**：语言规律（哪种搭配常见、哪种句式通顺）、体裁的形状（通知长什么样、合同长什么样）、以及大量事实的**模糊痕迹**。

**不改什么**：具体任务的格式要求（「给我三行、每行一个字段」这种）、你的公司规则、任何时效性内容。

**最容易误解的一点**：预训练带来的「知识」，是一堆统计相关性，不是一个可查询的条目库。所以它能说出「这类通知通常包含日期和地点」，却不能保证「这次通知的日期是最新那一版」。前者是形状，后者是状态。

**这一阶段的产物**常被叫「基座模型」。它像一个读了很多书、但没学过「怎么跟人配合干活」的人：能接话，不一定听得懂指令。

### ② 后训练 / 指令微调：学会「被要求时怎么答」

**改什么**：把「续写机器」调成「会应答的助手」。用大量「指令—回答」的样例，让它学会识别「这是一个要求」，并按要求的形状作答：列点、分步、先结论后理由、用指定语言。

**不改什么**：不会可靠地注入新事实。这一点常被误解，值得单独记住——**样例里出现的事实会被顺带学一点，但那是副作用，不是能力。** 你给它一百条「本公司报销上限是多少」的样例，它可能学会「回答这类问题时该提到一个上限」，却不一定记住那个数，更不一定在数变了之后跟着变。

**副作用**：它也会学到样例里的**风格与套路**，包括你不想要的那些，比如「首先/其次/最后」的三段式，比如每段结尾都来一句总结。这些会一路带到后面的所有输出里，「AI 味」的一个来源就在这里（→ 27）。

### ③ 偏好优化：学会「哪种回答更讨人喜欢」

**改什么**：给两个回答，标注哪个更好，让模型偏向被选中的那一类。改的是**取舍**：多长、多确定、多谨慎、遇到边界时是拒答还是给替代方案。

**不改什么**：知识边界。它不会因为偏好优化而多知道一件事。

**副作用，而且很重要**：如果标注的人偏好「确定、完整、顺着说」的回答，这一步就会把「迎合」从统计倾向变成稳定风格。02 篇讲的第六源（迎合式补全）有一半是这一步加固的。**偏好优化买来的是「讨人喜欢」，而「讨人喜欢」和「说得对」不是一回事。**

### ④ 微调：学会「这个领域的活怎么干」

**改什么**：在已有模型上，再用一批相对聚焦的数据训练一段。它能让领域词汇更准、输出格式更稳、某类任务的完成度更高。**它改的是「干活的熟练度」，不是「知识的库存」。**

**不改什么**：不会可靠地新增事实；不会自动带上版本管理；不会因为你训了它，它就优先相信训练数据而不是本轮材料。

**最常见的误用**：把「让它记住这批文档」当成微调的目标。这件事的正确工具是检索（→ 10），因为文档会更新、会有权限差异、会被撤回——而这三件事微调都处理不了。

### ⑤ LoRA：只训一小块，可插拔

**改什么**：冻结原来的权重，只训练一小块附加的参数，可以理解为「挂在原模型旁边的一层薄薄的适配」。改的仍然是行为倾向：风格、格式、领域表达。

**它的三个真实好处**：一是便宜，要动的参数少；二是可插拔，一个基座可以挂多个适配、按场景切换；三是**可撤**，把适配摘掉就回到原样。

**它做不到什么**（这三条最容易被「LoRA 很轻」这句话盖过去）：

- **它仍然是权重，不是数据库。** 不能定点写入一条规则，也不能定点删除一条规则——摘掉适配是「整块撤」，不是「删掉第三条第 2 款」。
- **它仍然会过期。** 训进去的领域说法会随外部世界变化而失效，而它不会提醒你。
- **它会互相干扰。** 多个适配同时挂上时，效果不是简单相加；训得越窄，越容易把别的能力挤歪。

### 五个阶段的一条共同结论

把上面五段横着看，会发现它们改的都是**倾向**：更可能这么说、更可能这么选、更可能这么组织。**没有一个阶段在做「存条目」。**

这带来一条非常好用的判据：

> **凡是需要「按条目管理」的东西——有版本、有生效日期、有适用范围、会被单独撤回——都不该进权重。**
>
> 反过来，凡是「希望它不用提醒就这么做」的稳定倾向——语气、节奏、格式习惯、领域表达——才值得考虑固化。

前者是「知识」和「规则」，后者是「风格」和「手艺」。这条分界，比记五个阶段的名字有用得多。

### 一个必须说清的类比失效

前面用过「抄进一本没有页码的书」这个说法。它抓住了「不能定点修改」，但有一步不成立，要说清：

**书的抄本可以「只查那一页」，权重不能。** 你可以翻到第 37 页只看那一段，同时不影响别的页；但一次模型调用是整套参数一起参与，**没有「只调用这一条」的开关**。所以「它记住了这条规则」这个说法，严格讲是不准的——准确的说法是「它的输出分布在这类情境下偏向了这个方向」。

这个差别有实际后果：如果它偏了，你没法「只纠正这一条」；你只能改材料、改指令，或者再训练一次——而那会连带改别的。

## 07.5 机制二：四个旋钮，没有单旋钮

只要涉及训练，就一定会有人问「参数怎么设」。这一节不给数值，因为**给数值是不负责任的**：同一组数在不同的数据、不同的基座、不同的目标上，效果完全不同，任何具体推荐都会在下一个场景里变成误导。这一节要说的是更根本的一件事：

> **训练里有四个旋钮，它们互相纠缠。没有「只调一个」这回事。**

四个旋钮是：

| 旋钮 | 它决定什么 | 调大之后通常发生什么 | 调小之后通常发生什么 |
| --- | --- | --- | --- |
| **数据质量与覆盖** | 能学到什么、学不到什么 | 覆盖广，泛化好，但针对性弱 | 覆盖窄，针对性强，但容易「只认这一种问法」 |
| **学习率** | 每一步改多少 | 学得快，但容易震荡、冲掉旧能力 | 学得稳，但慢，且可能停在一个不够好的位置 |
| **步数 / 轮数** | 同一批数据看多少遍 | 记得牢，但会背答案、格式僵化、忘掉别的 | 学不牢，欠拟合 |
| **批大小** | 一步看多少条 | 方向稳，但泛化可能变差、更吃资源 | 噪声大，但有时反而有正则效果 |

### 为什么它们不能分开调

举三个具体的纠缠。这里给的是**方向**，不是精确等式——任何「调多少补多少」的说法都不可信。

**例一：数据变少，等于同一个「步数」下多看了很多遍。**
原来一批数据跑固定轮数；现在数据只剩一小撮，同样跑那么多轮，等于每一条被反复看了很多倍。**过拟合的风险立刻上升**，你会看到「训练集上完美、换个问法就崩」。这时正确的动作不是「再调学习率」，而是先把步数降下来——可步数一降，学习率的最优值又跟着变。**你动了 A，B 的答案就换了。**

**例二：学习率减半，通常需要更多步才能走到同一个位置。**
但「更多步」又会让模型在同一批数据上多看几遍，于是过拟合风险上升。**所以「学得稳一点」这个动作，会顺手把「背答案」的风险推高。** 这就是为什么「把学习率调小」不是万能药：它买来的是稳定，卖出的是欠拟合与训练不足之间的那段余量。

**例三：批大小一变，「一步」的定义就变了。**
批大小翻倍，一步看到的样本翻倍；同样的「步数」，实际训练的样本量也翻倍。所以单独说「我训了 500 步」几乎没有信息量——**你还得说一步是多少条。** 步数和批大小必须一起看。

还可以加一条更隐蔽的：**数据质量一变，另外三个旋钮的最优值全部作废。** 把作废的旧规范混进训练数据，模型会稳定地学会「两套规则都提一下」。这时你调学习率、调步数、调批大小，都是在把一个错误目标优化得更彻底。

### 「没有单旋钮」对使用者的意义

这条机制听起来很技术，但它对非技术读者的用处非常直接：**它给你一个反驳的话术，和一个正确的追问顺序。**

当有人说「效果不好，把学习率调一下」，你要问的是：

1. **数据对不对？** 覆盖了真实的问法吗？有没有把「不该学的」也喂进去，比如作废的旧规范？
2. **如果数据变了，步数跟着变了吗？** 数据量减半而步数不变，等于多看了两倍。
3. **评估用的是什么？** 是训练集上的表现，还是一批没参与训练的样例？（→ 22）

**顺序不能倒**：先问数据，再问步数，再问评估，最后才轮到学习率和批大小。因为前三个错了，后两个怎么调，都是在给一个错误的目标做优化。

还有一条更硬的边界：**没有人能保证「只学会这一条」。** 训练是整体调整，你喂进去的每一条数据都会顺带影响别的东西。所以「我就训它一条规则，别的都不动」这个要求，在机制上无法满足——这是本篇反复说「规则不该进权重」的第二个理由。

### 这套说法在哪儿失效

「四个旋钮」是一个有用的简化，但它会在一种情况下失灵：**当训练方式本身不同时，四个旋钮的意义也跟着变。** 只训一小块适配参数时，「学习率」作用的对象和全量训练不同；有些方法还会引入额外设置，有些流程干脆把多个阶段合并成一次。所以这张表应该被当成**思考顺序**，不是**操作手册**。真正做训练的人看的是自己那套流程的文档，不是这四条。

## 07.6 机制三：过期有三种形态，修法完全不同

「它说的东西过时了」是一句笼统的话。拆开看，至少三种，而且**它们存在不同的地方，要用不同的工具修**。

```text
   形态一：权重里的知识过时
   ┌──────────────────────────────────────────────────────┐
   │ 训练截止之后，世界变了                                 │
   │ 修它：重训 / 换模型 / 用检索绕开这一块                 │
   │ 成本：最高        撤得回吗：撤不回                     │
   └──────────────────────────────────────────────────────┘

   形态二：检索库里的文档过时
   ┌──────────────────────────────────────────────────────┐
   │ 库里还躺着旧版，或者新版没进索引                      │
   │ 修它：更新文档、标状态、重建索引、召回前过滤           │
   │ 成本：中等        撤得回吗：能，且只影响被召回的部分   │
   └──────────────────────────────────────────────────────┘

   形态三：提示词里的规则过时
   ┌──────────────────────────────────────────────────────┐
   │ 提示词里写死了「提前一天」「找某某人」                 │
   │ 修它：改那一行，或把它外置成一份材料                   │
   │ 成本：最低        撤得回吗：能，改完即生效             │
   └──────────────────────────────────────────────────────┘
```

| 形态 | 它存在哪 | 谁改得动 | 怎么发现它过期了 | 修一次影响谁 | 修法 |
| --- | --- | --- | --- | --- | --- |
| **权重里的知识** | 一堆数里，没有地址 | 只有训练流程，或换模型 | 拿一件训练截止后发生的事去问，看它是否还按旧说法答 | 所有用户、所有请求 | 重训、换模型，或用检索绕开这一块 |
| **检索库里的文档** | 文档、索引、元数据 | 内容负责人 + 应用配置 | 问一个只有新版才有的细节，看它引的是哪一版 | 只有走到这条检索的请求 | 更新文档、补状态字段、召回前按状态过滤、重建索引 |
| **提示词里的规则** | 系统指令、任务卡 | 任何能改配置的人 | 逐条对照现行规范，看哪一句还在说旧规矩 | 只有用这份提示词的请求 | 改那一行；更好的做法是把它换成「指向现行版本」的一句 |

### 三条修法的成本差，决定了东西该放哪

这张表最有用的不是「三种形态」，而是右边那几栏的对比：

- 权重过期 → 修一次，**要动所有人**，而且撤不回；
- 文档过期 → 修一次，**只动被召回的那部分**，当天可改；
- 提示词过期 → 修一次，**只动这一个流程**，分钟级。

**成本差了几个量级，可逆性差了一个性质。** 于是得到一条几乎是算术的结论：

> **会变的东西，放在最便宜、最容易撤的那一层；只有确认「它不会再变、而且需要它变成默认反射」的东西，才往上放。**

这就是「该放哪」的判据。它不是口味问题，是成本与可逆性的直接推论。

### 提示词的腐化：第三种过期最常见的形状

第三种过期很少是「某天突然写错了」，它通常是**一层一层加上去的**：

```text
   第一步  写「提前一天报备」
   第二步  追加「如遇周末，提前两天」          （第一步那句没删）
   第三步  追加「值班主管确认即可，不必找行政」 （前两句都还在）
   第四步  追加「以上规则以最新版为准」        （一句试图收拾前三句的话）
   →
   结果：四句话并存，其中三句互相冲突；
         模型每次只在这四句里挑一句「最接得上」的，它不知道谁是第几步。
```

注意最后那一句「以最新版为准」——**这正是把版本管理交给模型的样子。** 它看起来在解决冲突，实际上是把「哪一版最新」这个判断，推给了最没有版本信息的那一层。模型手里只有这四句话，它没有生效日期，也没有作废标记。

正确做法在第七节的正例里展开，但可以先说一句：**提示词里不该出现会变的量，只该出现「去哪里取这个量」和「取不到怎么办」。**

### 三种过期的一个共同点

它们都会**安静地发生**。没有报错，没有警告，输出依然流畅——这正是 02 篇那条「流畅与可靠是两种属性」在时间维度上的版本。一份作废的规范、一条训进权重的旧口径、一句三个月没改的提示词，都不会让回答变卡；它们只会让回答**同样自信地错**。

所以对付过期，靠的不是「它看起来对」，而是一个**定期的、有对照的检查动作**：拿一件只有新版才成立的事去问，看它答什么（→ 22）。这一节后面会给具体做法。

## 07.7 决策表：四种需求，四条路

现在把前面的推导收成一张能当场用的表。四种需求，问的其实是四件不同的事：

| 需求 | 它长什么样（用团建这条线举例） | 它真正需要的性质 |
| --- | --- | --- |
| **新规则** | 「群发前必须有人确认」「日期以现行版本为准」 | 可撤回、有版本、有生效日期 |
| **新风格** | 「通知要克制，不要营销腔，不要三段式」 | 稳定，不用每次交代 |
| **新知识** | 「这次是 10 月 25 日」「A 场地人均 260 元」「39 人」 | 准确、可核、随时能换 |
| **新格式** | 「输出三行：时间、地点、未定事项」 | 结构稳定，能被下游解析 |

对应的四条路：

| 需求 | 走哪条路 | 为什么是这条 | 成本（相对） | 生效（相对） | 什么时候**不**该走这条 |
| --- | --- | --- | --- | --- | --- |
| **新规则** | **携带**：系统指令 + 外部规则文件 + 校验/审批 | 规则要能单独撤、单独改版；权重没有版本 | 最低 | 即刻 | 规则已多年不变，且需要它变成「不用提醒的反射」时，才考虑固化 |
| **新风格** | **先携带（示例 + 反例），稳定后再偏好优化/微调** | 风格是分布层面的；一句形容词推不动，示例能锚定形状，固化能让它长期稳定 | 低 → 中 | 即刻 → 以周计 | 风格本身还在试、还在变的时候；固化会把「暂定」变成「改不掉」 |
| **新知识** | **携带**：附件 / 检索 / 工具查询 | 知识是条目，需要准确、可核、可换；权重存不了条目，也删不掉 | 最低 | 即刻 | 几乎没有例外。勉强算例外的是「极小、永久不变、且必须离线」的常识，但即使那样，写进材料也更省心 |
| **新格式** | **携带**：少样本示例 + 结构化约束 + 下游校验 | 格式是形状问题，示例最直接；重训是为形状付出的最贵代价 | 低 | 即刻 | 格式极复杂、极稳定、且量大到「每次带示例」不划算时，才考虑微调 |

这里的「成本」与「生效」只给**相对次序**，不给数字：同样一次微调，在一个团队里可能一周走完，在另一个团队里可能要先过数据合规。**次序是稳定的，日历不是。** 任何承诺「几天就能上线」的说法，都要先问它说的是哪一段流程。

### 这张表的结论

**四条路里，三条的正确答案都是「带上」。**

- 新规则 → 带上。固化是纯亏：花了最贵的钱，买了一个改不动的东西。
- 新知识 → 带上。权重在结构上就不适合存条目。
- 新格式 → 带上。示例加校验已经够用，重训是杀鸡用牛刀。
- 新风格 → **唯一值得考虑固化的一项**，而且只在它已经稳定之后。

把这句话说得再直白一点：

> **训练不是「更彻底的提示词」，它是「另一种东西」。** 提示词改的是这一次的条件，训练改的是长期的先验。你要的是条件，就别去买先验。

### 一个小成本顺序

如果拿不准，按这个顺序往上走，每一级都先回答「上一级为什么不够」：

```text
   第 0 级  先改提示词与材料
            问：规则写清了吗？材料是现行版吗？示例给了吗？验收标准有吗？
            这一级能解决绝大多数「它不听话」的问题。
                 │
                 │ 只有当「材料是对的、指令是清楚的，它仍然稳定地做错」时才往下走
                 ▼
   第 1 级  补检索
            问：答案在库里吗？召回得到吗？版本过滤做了吗？权限过滤呢？
            这一级解决「它不知道」和「它用了旧版」。
                 │
                 │ 只有当「知识每次都对，但风格 / 格式 / 熟练度始终不稳」时才往下走
                 ▼
   第 2 级  考虑微调，优先可撤的方式
            问：这是行为问题，还是知识问题？如果是知识，退回第 1 级。
                 │
                 │ 只有当「连基座能力都不够，换模型也解决不了」时才往下走
                 ▼
   第 3 级  才谈重训
            问：真的没有别的路了吗？谁来做？做完怎么评估？以后怎么撤？
```

这个顺序的每一级都有一个**明确的「不往下走」的信号**：

| 级别 | 这一级的成本 | 什么信号说明「问题不在这」 | 误跳的典型后果 |
| --- | --- | --- | --- |
| 改提示词与材料 | 最低 | 材料本身是旧版；或者根本没有验收标准 | 加了十句「务必」，问题还在 |
| 补检索 | 低 | 库里有答案，但召回不到——这是检索问题，不是「不知道」 | 换更大的模型，仍然召回旧版 |
| 微调 | 中 | 错的是知识条目，不是行为倾向 | 训完发现「它还是不知道 10 月 25 日」 |
| 重训 | 最高 | 其实是任务设计问题：缺字段、缺权限、缺校验 | 花最大代价，修了一个流程漏洞 |

最后一行值得多说一句：**很多人走到第 3 级，是因为前几级没人认真做。** 而前几级加起来，通常还不到第 3 级的一个零头。

还有一个反向的提醒：这个顺序不是「永远不许往下走」。当第 0 级的材料已经足够、指令已经清楚，而它的**表达**仍然达不到你要的水准——那就是真正的行为问题，往下走是对的。**关键是「往下走的理由」，不是「往下走的次数」。**

## 07.8 边界：三列账，以及各自的保证上限

把四条路摆成三列账。这一栏的「何时失效」不能空——空着就等于说这个方法万能，而它显然不是。

| 做法 | 能做什么 | 代价是什么 | 何时失效 |
| --- | --- | --- | --- |
| **提示词 / 系统指令** | 立刻改变这一次的行为形状：格式、边界、语气、拒答方式 | 每轮都占工作台面积；越加越长、前后矛盾；换模型可能失效 | 规则会变却没人改；指令与材料冲突；要求的是「保证」而不是「概率」 |
| **附件 / 检索** | 把最新、最准的条目放到桌上，可引用、可核对 | 要维护文档、索引、权限、版本；召回可能失败；材料可能被忽略 | 库里没有；召回到了旧版；材料送进去了但模型没用上（→ 05、10） |
| **微调 / LoRA** | 让某种风格、格式、领域表达变成默认倾向，且不占工作台 | 要数据、要评估、要维护；会过期；会外溢到别的场景；难以单独撤某一条 | 目标是「记住会变的知识」；数据里混进了旧规范；没有能对照的评测集 |
| **重训 / 换模型** | 改变基座能力：语言、推理、通用知识覆盖 | 最贵、最慢；会把已有提示词的调校全部打乱；不可逆 | 问题其实在材料、口径、权限、流程；或者只是想让「一条新规则生效」 |

### 每一栏各自的「保证上限」

这四行有一个共同的形状：**每一行都只能买到「概率」，买不到「保证」。**

- 提示词让某类回答更可能出现，但它不能阻止一次越权发送；
- 检索让正确答案更可能被看到，但它不能保证模型一定采用；
- 微调让某种风格更稳定，但它不能保证在新场景里不跑偏；
- 重训让基座更强，但它不能让一条规则自动获得版本管理。

**「保证」这一层在权限、校验、回执、人审那里。** 这就是为什么 01 篇说「提示词写严一点」不是答案——它连自己那一栏的上限都没突破，更跨不到别的栏去。

### 第二个失效的类比：像肌肉一样练熟

「练一次就记住，像肌肉记忆」这个说法，抓的是「不用想就能做」，但有两个地方不成立：

- **肌肉记忆练一次就长期保留**，而权重会被后续训练挤占、覆盖、遗忘；
- **肌肉记忆不干扰别的动作**，而权重是整体调整，练这个可能歪了那个。

所以「像练肌肉一样训练它」这个类比，在「练一次就永久、且不影响其他能力」这一步断掉。它更像**同时调很多根弦**：你想让某根紧一点，手上这一拧会牵动旁边的。

### 三条必须承认的边界

1. **固化不能保证服从。** 先验会被本轮材料覆盖；材料越显著、越靠后，越容易赢。
2. **携带不能保证遵从。** 指令可能被忽略，材料可能被跳过，示例可能被后续内容冲淡（→ 05）。
3. **微调不能保证不遗忘。** 任何一次训练都在改整体，你没法只要「新的」不要「旧的」。

三条合起来是一句话：**没有任何一层能单独给你「稳定且可控」。** 稳定要靠固化，可控要靠携带；两者必须分工，不能互相替代。

这也解释了为什么「该不该训练」这个问题，问法本身就是错的。正确的问法是两个：**「这条东西以后会不会变」**，以及**「变了之后我要不要能单独撤掉它」**。两个答案都是「是」，就留在外面；都是「否」，才轮到固化。

## 07.9 反例与正例：「让模型记住新规」的两种做法

### 反例：把规范全文贴进系统提示词，然后每季度追加一版

```text
   错链：
   规范 v1 ──▶ 全文贴进系统提示词
        │
        ▼
   一个季度后，规范 v2 ──▶ 追加在 v1 后面（不敢删）
        │
        ▼
   两个版本并存 ──▶ 模型在「提前一天」和「当天上午」之间摇摆
        │
        ▼
   「怎么还不稳？」──▶ 提议微调 ──▶ 把 v1 和 v2 一起喂进去
        │
        ▼
   微调完成，行为看似稳定 ──▶ 规范 v3 发布
        │
        ▼
   没有人知道该改哪里：规则已不在任何一份文件里，它在一堆数里
        │
        ▼
   想撤掉 v1 的影响 ──▶ 只能再训练一次 ──▶ 又引入新的不确定
```

这条链上，每一步都在解决眼前的问题，但**方向是反的**：它不断地把「可变的东西」往「不可变的那一层」搬。搬到最后一格，就出现了那个最难处理的局面——**你知道它错了，但你找不到那句话。**

这条链还有两个隐性代价：

- **提示词越来越长**，每一轮都要为这些历史版本付工作台面积（→ 05、21）；
- **没有人敢删**任何一段，因为「删了怕它忘」——而这句话本身就说明了问题：**它在靠「出现过」维持行为，而不是靠「现行」维持行为。**

还可以补一个更隐蔽的：微调时把 v1 和 v2 一起喂进去，等于**把「两版并存」这个状态也一起教了**。模型学到的不是「v2 才是现行」，而是「这类问题有两种答法」。这时你以为在消除摇摆，其实在固化摇摆。

### 正例：把规则留在文件里，只把「怎么取」写进指令

```text
   对链：
   《对外发布规范》带版本号、生效日期、作废标记，放在检索库里
        │
        ▼
   系统指令只写三句：
     ① 以状态为「现行」的版本为准
     ② 引用时必须带文件名与条款号
     ③ 找不到现行版本，就停下来问，不要按印象作答
        │
        ▼
   规则变更 ──▶ 只改那一份文件，并把旧的标为作废
        │
        ▼
   检索按状态过滤 ──▶ 只有现行版能上桌
        │
        ▼
   验收：问一个只有新版才有的细节，看它引的是哪一版
        │
        ▼
   回归样例里加一条 ──▶ 下次改版时，先跑这一条
```

注意这套做法里，**提示词没有变长，反而变短了**：它从「承载全部规则」变成了「描述如何取规则」。变的只有那份文件，而文件是可以被单独审阅、单独签字、单独撤回的。

两种做法的对照：

| 维度 | 反例（贴进提示词再追加） | 正例（文件 + 指针 + 过滤） |
| --- | --- | --- |
| 规则存在哪 | 系统指令的正文里 | 一份带版本的文件里 |
| 改一次规则要动什么 | 改提示词，还要小心不破坏别的段落 | 改文件，把旧版标作废 |
| 旧版怎么撤 | 不敢删；删了怕「忘」 | 标作废 + 召回前过滤 |
| 谁有权改 | 能改配置的人，往往不止一个 | 内容负责人，有签字 |
| 怎么验证生效 | 靠「感觉稳了」 | 问一个只有新版才有的细节，看引用 |
| 换模型会怎样 | 整段提示词可能失效，要重调 | 文件与过滤照旧，只需重调那三句 |
| 三个月后再改一次 | 再追加一段，继续变长 | 改同一份文件，长度不变 |

最后一行是这套做法真正的价值：**它的维护成本不随改版次数增长。** 反例的成本是线性增长的，每季度加一段；正例的成本是常数，每次改同一处。

### 一个中间态，也值得说

有些东西确实需要「变成默认反射」——比如某个团队的写作风格、某个领域的术语习惯。这类东西可以走固化，但要按顺序走：

1. **先证明它稳定**：用示例加提示词跑一段真实任务，确认这个风格确实是你要的，而且短期内不会再改；
2. **再固化**：优先用可撤的方式，而不是一上来就重训；
3. **固化后留一个「关掉的开关」**：至少能回到没有这层适配的状态；
4. **把评测集建起来**：固化前后跑同一批样例，看「有没有变好」，不是「感觉像了」（→ 22）。

**顺序不能倒。** 先固化再观察，等于把一个还没定稿的东西刻进石头。

## 07.10 你可以自己做的检验

三个检验，都不需要写代码。

### 检验一：给你的规则做一张「归属表」（10 分钟）

挑一条你工作里**三个月内至少会变一次**的规则——审批人、报备时限、口径、模板版本都行。填这张表：

| 问题 | 你的答案 |
| --- | --- |
| 这条规则现在写在哪？（提示词 / 文档 / 某个人脑子里 / 说不清） |  |
| 上一次改它是什么时候？谁改的？ |  |
| 如果现在要改，改哪里？改完多久生效？ |  |
| 如果要**撤掉**它，怎么撤？撤完影响谁？ |  |
| 有没有一个动作，能证明它真的生效了？ |  |

**判据**：如果第 3、4 行你填不出来，或者填的是「要重新训练」，那这条规则就被放错了层。**一条三个月改一次的规则，必须有一个「分钟级能改、且能单独撤」的落点。** 找不到这个落点，就是本篇说的问题。

如果第 1 行填的是「在某个人脑子里」，那它现在连模型都没进去——先把它写成文件，再谈别的。这一步听起来琐碎，但它往往是整张表里最值钱的一步：**没有文件，就没有「现行」这个概念，后面所有的过滤都无从谈起。**

### 检验二：同一规则，两种放法，各跑五次（15 分钟）

选一条**有两个版本**的规则，例如「提前一天报备」与「当天上午报备」。做两组：

- **A 组（放进指令）**：把旧规则写进系统提示词或对话开头，再在材料里给一份写明「旧规则作废、改为新规则」的文件。
- **B 组（放进材料）**：指令只写「以材料里的现行版本为准」，材料里同时给新旧两版，并标明哪版作废。

每组用同一个问题跑五次，记录它按哪一版答。

**判据**：如果 A 组在新旧并存时**摇摆**——有时旧、有时新——而 B 组稳定跟着现行版走，说明这条规则该外置。反过来，如果 A 组五次都稳定按新规则答，那在本场景里，「一句指令撑不住」这个结论就被削弱了，**要承认它**，并记下来：你的场景里，指令的权重比一般情况高。

这个检验的价值不在证明谁对，在于让你看见：**同一个模型、同一批材料，只因为规则放在不同位置，稳定性就不一样。**

顺便，这个检验还能顺手验一件事：五次里如果**措辞在变、结论不变**，那是抽样（→ 04）；如果**结论在变**，才是本篇说的层错配。两种情况看起来都像「不稳定」，修法完全不同。

### 检验三：让它指认依据（5 分钟）

对任何一条它给出的规则性回答，追问一句：

> 这条规则的依据是哪份文件的哪一条？把那一句念出来。

看它给的是哪一种：

- **文件名 + 条款号 + 原句**：可以回原文核对；
- **一个文件名，但没有条款**：可能对，也可能只是「像来源」；
- **一段解释**（「根据公司规定……」），但指不到具体位置。

**判据**：第三种等于告诉你——**这条规则不在你能控制的任何一层里。** 它可能在权重里，也可能只是这次续写得像。无论哪种，你都不能改它，也不能撤它。

### 一条补充：如果它「训练之后还是不听」

先别加数据。按这个顺序查：

| 先查什么 | 为什么 |
| --- | --- |
| 本轮材料里是不是还有旧版 | 先验和条件冲突时，近的那个通常更响 |
| 系统指令里是不是还留着旧规则 | 你自己贴的那句话，可能比训练更靠后 |
| 训练数据里是不是混进了旧规范 | 喂进去什么就学什么；数据脏了，四个旋钮都救不了 |
| 评估是不是只在训练集上做的 | 「训练集上很准」不构成证据（→ 22） |

四问都过了，才轮到「是不是训得不够」。而多数时候，问题在前两行——**你以为在修模型，其实在修自己那份没删干净的旧材料。**

## 07.11 术语考古：三个被用坏的词

### 预训练

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 「pre-training」是机器学习里长期沿用的通用说法：先在大规模通用数据上训练，再针对具体任务做适配。**它不是某一家公司或某一篇论文的专有名词**；具体最早的使用场合，本篇不指认。 |
| 原义 | 强调**顺序**：先学通用表示，再做专门适配。它描述的是一个阶段在流程里的位置，不是一种能力。 |
| 现在被怎么用 | 常被说成「模型的知识来源」，好像预训练等于建了一个数据库；也常被当成「模型知道的一切」的同义词。 |
| 本文怎么用 | 指第一次大规模训练，产出「基座」。它固化的是语言规律与统计相关性，**不是可查询的条目**。所以「预训练里有这个知识」这句话，只能理解为「它的输出分布里带着这个痕迹」，不能理解为「它存了这条」。 |

### 微调

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 「fine-tuning」原意是「对已训练好的模型做小幅继续训练」，在迁移学习的语境里被广泛使用。**它长期是一个通用说法，没有唯一发明人**；后来被扩展到几乎一切「二次训练」。 |
| 原义 | 在已有权重上再训练一段，让模型更适配某个任务或领域。关键词是**改权重**。 |
| 现在被怎么用 | 被当成「教会它新知识」的同义词；更麻烦的是，有些产品界面把「上传文档、接知识库」也叫「训练」或「微调」，于是用户以为文档进了权重。 |
| 本文怎么用 | **只指改权重的二次训练。** 上传文档、接检索、加提示词，都不叫微调——它们一个字节的权重都没动。遇到这个词，先问：它说的是改权重，还是「让模型能用到这份资料」？这两件事的修法完全不同。 |

### LoRA

| 栏 | 内容 |
| --- | --- |
| 最早出处 | 一个有明确出处的技术方法名（Low-Rank Adaptation），由研究者在论文中提出。**本篇不指认具体年份与文献**，只确认它是一个技术名，不是产品按钮，也不是行业通称。 |
| 原义 | 冻结原来的权重，只训练一对小的低秩矩阵作为增量，用较小的代价实现行为适配。 |
| 现在被怎么用 | 被当成「轻量微调」的同义词，甚至被说成「便宜版的重新训练」，好像它能做到重训的一切、只是更便宜。 |
| 本文怎么用 | 指一种**改权重的方式**：可插拔、可整块撤、成本低于全量训练。但它仍然是权重——**仍然不能定点增删一条知识，仍然会过期，仍然会和别的适配互相干扰。** 「轻」说的是代价，不是能力边界。 |

三个词共同的毛病，和 02 篇那三个一样：**把「流程里的一个位置」，说成了「一种可以买到的能力」。** 预训练是一个阶段，微调是一类动作，LoRA 是一种方法；它们都不承诺「记住」或「学会」某个具体条目。谁承诺了，谁就在偷换。

## 07.12 一页速记

| 你听到的说法 | 机制上是什么 | 该做什么 |
| --- | --- | --- |
| 「训练一下让它记住新规」 | 规则是条目，权重没有条目 | 改成「文件 + 指针 + 过滤」，别训 |
| 「微调过了，它现在懂我们业务了」 | 改的是熟练度，不是知识库存 | 问：知识从哪来？检索接了吗？ |
| 「LoRA 很轻，随便挂」 | 轻的是代价，不是边界 | 仍然会过期、会干扰、不能定点删 |
| 「提示词里都写了，它应该照做」 | 指令只提高概率，不建立保证 | 关键动作加校验/审批，别只靠措辞 |
| 「加了样例，风格就固定了」 | 示例能锚定形状，但占工作台、会被冲淡 | 长期稳定才考虑固化，且先证明它稳定 |
| 「换个新模型，规则就更新了」 | 新模型的训练数据也有截止点 | 会变的规则永远走携带，不走权重 |
| 「它说它记住了」 | 这是续写，不是内省 | 问它依据哪份文件哪一条；指不出就是没落地 |

**五句话带走**

1. 能长期改变它的只有改权重；但正因如此，需要「单独撤」的东西都不该进去。
2. 权重不是数据库：没有条目、没有地址、没有版本号，所以「多背一遍」在结构上就不成立。
3. 固化买的是默认倾向，携带买的是这一次的条件；先验和条件冲突时，近的那个通常更响。
4. 四种需求里，三种的正确答案都是「带上」；唯一值得固化的是风格，而且只在它稳定之后。
5. 训练不是「更彻底的提示词」，它是另一种东西——你要条件，就别买先验。

**三道自检**

1. 同事说：「把这份《对外发布规范》喂进去微调一下，以后就不用每次贴了。」这句话至少有两处需要追问，是哪两处？
2. 一条规则三个月改一次。分别放在权重、检索库、提示词里，各会怎样过期？哪一种修起来最贵，为什么？
3. 你把规范 v1 和 v2 同时贴进了系统指令，模型在两种做法之间摇摆。加一句「以最新版为准」能解决吗？为什么？

<summary>查看参考答案</summary>

1. 第一处是「喂进去微调」：如果他的意思是「让模型能用到这份规范」，正确动作是接检索或附件，不是微调——微调改的是行为倾向，不是条目库存。第二处是「以后就不用每次贴了」：这句话假设「训过就等于每次都生效」，但先验会被本轮材料覆盖；而且规范会改版，改版后没有人知道该改哪里。**先问清他要的是「能用到」还是「变成默认反射」**，两者的路线完全不同。
2. 权重里过期：要重训或换模型，影响所有请求，且撤不回——最贵，不是因为技术难，是因为它没有「只改这一条」的接口。检索库过期：更新文档、标作废、重建索引，只影响被召回的部分，当天可修。提示词过期：改一行，分钟级，只影响这一个流程。**最贵的是权重**，它连「过期的是哪一条」都说不清。
3. 不能。这句话本身还是把版本判断交给模型——它手里只有 v1 和 v2 两段文字，不知道谁是第几版、谁已经作废。正确做法是把版本状态放到材料层（标生效日期与作废标记），并在召回前过滤。**「以最新版为准」是一句把责任推给最没有版本信息的那一层的话。**
