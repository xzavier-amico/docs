# 03 · Transformer 图解：Token 进来以后发生了什么

> **状态**：已完成（初稿）
>
> **本篇定位**：跟着「苹果」走过 Transformer 的输入、注意力和前馈处理，看懂上下文为什么能改变模型接下来的回答。
>
> **读法**：先沿图从上读到下，再用纸笔做连线；不需要认识公式，也不用记任何向量的数值。

## 都叫「苹果」，该放进哪一列？

市集报名备注里有两条：「水果摊带了两箱红苹果」和「数码体验摊带了两台苹果电脑」。如果要按商品类别整理报名清单，「苹果」在第一条指水果，在第二条是品牌的一部分。单独裁出两个字看不出来；放回完整记录，「两箱」「水果摊」和「电脑」「数码体验摊」给出的线索不同。

**本篇的真问题：同一个词在不同句子里，模型怎么用上周围线索？** 示意图先画轮廓，再拆里面的部件。

```text
原文：「水果摊带了两箱红苹果」／「数码体验摊带了两台苹果电脑」
                                  ↓
分词器：把文字变成 Token ID 序列（数字标签）
                                  ↓
模型入口：把编号变成输入向量，并让模型用到位置信息
                                  ↓
第 1 层：注意力汇入可见位置的线索 → 前馈变换各位置的表示
                                  ↓
第 2 层：用更新后的表示再交换线索 → 再变换各位置的表示
                                  ↓
更多层：重复类似处理，得到带上下文的表示
                                  ↓
任务出口：例如用读完这段记录后的表示，给下一步文本候选打分
```

图把一个 Transformer 简化成多层同类处理。不同模型的具体组件、次序和位置表示方式不完全相同；图也省略了保留原有信号、调整内部数值尺度等部件。它要解释的是信息怎样流动，不是教人从图里还原一款模型。

## 从一个标签到上下文里的表示

**Token ID** 像物品目录编号，只区分是哪一份片段。这里为好画，把「苹果」画在一个框里；实际分词可能拆开，也可能因为前方字符不同用上别的片段。即使两处恰好用了同一组 ID，最初查到的文字向量相同，也还没得到「水果」或「品牌」的最终结论。

**向量**可以暂时看成一张数字卡片：模型用一组数表示一个片段，不是给它写一段字典释义。这张卡片不是人手写的属性表，不能指着某一个数说「这格就是水果」。**位置信息**让模型有机会区分先后和相隔距离。有的设计把位置线索加到入口表示里，有的在注意力处理时引入；不论哪种，「周六改为周日」都不能只当作同一袋无序的字，掉换前后就会改变意思。

| 处理到哪一步 | 不变或可能变化的是什么 | 市集里的直观理解 |
| --- | --- | --- |
| 编号 | 同一分词器里，同一片段对应同一个编号 | 「苹果」的目录标签不是它在哪条报名里出现 |
| 输入向量和位置 | 文字对应的初始向量可相同；顺序信息另起作用 | 先知道写了什么片段，再区分它出现在什么位置附近 |
| 注意力与前馈 | 同一编号在不同环境中可有不同的内部表示 | 结合周围线索后，第一条和第二条不应分到同一类 |
| 任务出口 | 根据任务和可见上下文使用处理后的表示 | 生成分类说明是输出；表格里的分类是否正确另需核对 |

## 注意力：哪些位置的信息该多用一点？

把已经读完整条记录后、正用于判断分类的位置画在右边。这里粗线表示「在这个教学例子里，该线索权重较大」，不代表测到的注意力，更不是各条线贡献的因果排名。

```text
记录 A：      水果摊 ━━━━━┓
                两箱 ━━━━━╋━→ 读完整条后的表示 → 可能输出「水果」
                苹果 ─────┘

记录 B：  数码体验摊 ━━━━━┓
                电脑 ━━━━━╋━→ 读完整条后的表示 → 可能输出「数码」
                苹果 ─────┘
```

注意力常用来给**各位置**从其他可见位置挑取和混合线索。一个位置可以同时借到多处信息；同一层也常有多组注意力并行处理，俗称「多头」。不要把这些头想成各有固定职责的小员工，更不能说某个头永远负责判断品牌。经过层与层的处理，某位置接到的还可能是别的位置已经汇总过的线索。

**前馈处理**和注意力不同：在这一小步里，它在各位置分别变换已有的内部表示，不直接问隔壁位置借材料。可把一层粗略记成「先交换可见线索，再在各自位置加工线索」。多层之后，同一个片段在不同语境里可有明显不同的表示。模型并不必先形成一张给人看的语义表，再机械照表回答；我们为了好理解才画成几个步骤。

### 生成时，哪里算「可见」？

以常见从左到右的 Decoder-only 生成模型为例：在普通因果注意力下，一个位置能用到自己和此前位置的信息，不能往右偷看后面的位置。整段输入已经送到模型时，各位置仍按这条规则处理；模型用末尾已有上下文来预测下一块。一块被生成后，才会成为下一步的可见前文。「同时处理很多已经给出的输入位置」与「知道尚未生成的后文」不是一回事。

重回「苹果电脑」：如果我们只停在刚读到「苹果」的位置，不能直接给它画一条来自右边「电脑」的连线。上图选的是**已经读完备注后、用于做分类的表示**，因此这时可以利用「电脑」。有些 Encoder 的输入位置可以相互看见前后文，但那也只是看它们收到了什么，不是知道现实中尚未告诉模型的事。

## 手工练习：给能看的线索画线

在纸上写三行，先用纸条盖住每行方括号的部分：

1. 水果摊带了两箱红苹果［；品类：］
2. 数码体验摊带了两台苹果［电脑；品类：］
3. 原定周六，旧 v1 已失效［；现行 v2 改为周日 14:00，雨天是否改室内待确认。］

第一轮只看露出的字：从每行末端向左连线，粗线给最有帮助的线索。第二行已有「数码体验摊」和「两台」可参考，仍不要把看不见的「电脑」画进来。第三行只能知道周六旧安排失效，不能推出新时间。第二轮揭开纸条，把画线目标放到每行新的末端，检查新增材料是否改变判断。第三行现在应按 v2 记录周日 14:00，把雨天是否改室内保留为待确认。这个虚构任务只要求整理报名清单和通知草稿，不发送；无论哪一轮，都不会凭一条连线获得发送授权。

练习是在模拟「给定内容里有什么线索」，不是让人用纸笔算模型。把「电脑」换成「手机」或删掉「现行」再试：有的变动只换用词，有的会改变版本判断，人验收时该重点检查后者。

## 模型能联系上下文，不代表能核准事实

| 看到的现象 | 能说明什么 | 不能保证什么／怎么查 |
| --- | --- | --- |
| 同一片段能随上下文产生不同分类 | 模型可以组合已收到的线索 | 如果备注有歧义，去核对原表或保留待核，不凭自然语气定类 |
| 把整段话放进窗口 | 有机会使用多处材料；长材料通常增加处理成本 | 不保证每处都用对；把版本、时间、雨天状态单列出来验收 |
| 出现一张注意力可视化图 | 若说明测量条件，可以展示特定层和位置的一部分内部权重 | 无论是真图还是示意，都不能当模型的完整思考记录、事实证据或错误归因 |
| 输入没有雨天结论 | 模型仍可能写出格式像真的句子 | 无法靠网络内部匹配确认外部消息；只写待确认，等有权来源更新 |

**速记：** ID 是标签，向量是内部数字表示，位置帮忙保留顺序，注意力让各位置利用可见线索，前馈再分别加工。模型生成时往后接，不往未来看；注意力会用线索，不会替你证明事实。

### 自检（含简答）

1. **同一个 Token ID 会不会在两句话里得到不同的上下文表示？** 会。编号相同不妨碍后续层接收不同的上下文线索。
2. **从左到右的模型何时能用「苹果电脑」里的「电脑」？** 当这部分已经在可见前文里时，例如读完整条记录后进行分类；停在「苹果」的位置时不能直接看它。
3. **解释图画了一条粗线连到 v2，就能证明回答按 v2 办吗？** 不能。示意图不是实测；实测注意力值也不能代替逐条对照原文和草稿。
