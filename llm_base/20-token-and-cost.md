# 20 · Token 与成本账：省了字，不一定省了钱

> **状态**：已完成（初稿）
>
> **本篇定位**：Part IV 第 6 篇。用一张能手算的账本区分模型处理量、计费金额、等待时间与验收结果。
>
> **读法**：先看一轮请求怎样变成多笔账，再手算串行长循环、并行分支和缓存折扣；所有数字均为示意。

## 用户只点了一次，为什么账单不止一次？

在虚构的周末市集里，任务是**只整理报名清单及通知草稿，不发送**。原定周六的 v1 失效；现行 v2 为**周日 14:00**，雨天是否改室内仍待确认。如果资料已经备齐，可以一次出草稿。如果交给 Agent 找材料、整理、重试和复核，同一个按钮后面可能是多轮模型调用；各轮都可能把部分指令、材料、之前的结果再次作为输入。助手展示的最终草稿很短，并不能说明它前面读得少、花得少或等得少。

**本篇的真问题：同一个任务为什么越自动越贵，怎样知道省的是钱而不是质量？**

## 1. 先画出哪些东西进了账

```text
用户点一次「整理」
        ↓
应用组装输入 ──→ 模型输出计划或草稿 ──→ 应用判断是否要查询、复核、重试
      ↑                                              │
      └── 带回必要的工具结果和摘要，进入下一次模型调用 ─┘
        ↓
应用汇总用量与其他费用；人核验清单和通知草稿，任务止于草稿
```

**Token** 是内容经切分后的计数单位，不按字数直接换算。对一次模型调用，任务指令、应用附带的说明、文件摘录、检索与工具返回等，只要送进模型，就可能计入该调用的输入用量；模型生成的计划、摘要和草稿是相应调用的输出。举例说，上一轮生成的 300 Token 摘要，这一轮如果原样带回，就既出现在上一轮输出账，也出现在这一轮输入账。外部工具如果另收服务费，那笔钱还要另外记；工具查到一整份表但只把必要摘要送给模型时，模型这轮并没有接收整份表。

这里算的是一个假设的按量账本。有的平台可能按不同输入、输出或缓存档计价，也可能另算工具、检索、图像或内部生成用量；订阅看不见逐次金额，也不表示没有额度或等待限制。失败有时不计模型费用，有时已消耗的部分仍计费，不能一概而论。下面只演示怎样按明示的规则核账，不代表任何厂商报价或实测。

## 2. 纸上账本：三条路径，同一个交付标准

**假设规则**：每 100 输入 Token 收 1 个虚构账点；每 100 输出 Token 收 2 个账点。没有取整、起步价或额外工具费，暂不考虑缓存；账点不是人民币。以下每行是人为设定的一次调用，不是把市集文本实际切分后数出来的。几条路径都以有权访问必要资料为前提，且不能以少交清单、漏掉未决或跳过验收来换低账单。

| 路径 / 调用 | 输入 Token | 输出 Token | 本行账点 | 这一笔是怎么来的 |
| --- | ---: | ---: | ---: | --- |
| 单次：直接起草 | 1,200 | 400 | 20 | v2 与必要报名字段已备齐，一次产生两份草稿 |
| 长循环①：读任务、提出查询 | 1,200 | 200 | 16 | 读任务和已备材料，生成查找计划 |
| 长循环②：读返回、做摘要 | 1,600 | 300 | 22 | 重带 1,200，加上前轮计划 200 与工具返回 200；生成 300 的摘要 |
| 长循环③：尝试生成失败 | 1,500 | 100 | 17 | 重带 1,200 与摘要 300；按本例规则，已生成的 100 仍收费 |
| 长循环④：针对失败重试 | 1,600 | 400 | 24 | 重带 1,200、摘要 300，另补 100 的必要工具摘录；交草稿 |
| 并行①：报名清单分支 | 800 | 200 | 12 | 只带规则与获准字段，不带全部材料 |
| 并行②：通知事实分支 | 800 | 200 | 12 | 只带 v2 与待确认事项，不带报名联系方式 |
| 并行③：等分支后汇总 | 1,200 | 400 | 20 | 800 的汇总材料加两份各 200 的返回；交草稿 |

一行账点的手算法：长循环②，1,600 输入按每 100 收 1，得 16；300 输出按每 100 收 2，得 6；这一行共 22。全部加起来如下。这里的「总 Token」把每次输入与输出都加总，同一份文字出现两次就算两次；它不等于最终草稿的大小。

| 路径 | 总输入 | 总输出 | 总 Token | 无缓存金额 | 哪些代价还没从表里读出来 |
| --- | ---: | ---: | ---: | ---: | --- |
| 单次 | 1,200 | 400 | 1,600 | 20 账点 | 前提是资料已经齐备；整理资料的人工时间不在此账 |
| 长循环 | 5,900 | 1,000 | 6,900 | 79 账点 | 等查询、等前一步和重试，都是模型账点没体现的等待 |
| 并行 | 2,800 | 800 | 3,600 | 44 账点 | 分派与合并都要时间，还取决于必要分支中最迟的结果 |

再改一条条件：假定平台把**已命中的输入前缀**按普通输入的半价收费，且这一实例的并行账中有 800 输入 Token 实际命中。原本这部分是 8 账点，现在是 4，合计从 44 降到 **40 账点**；总 Token 仍记 3,600。若只是写了相同的开头却没有命中，不能把折扣先记上。缓存是否命中、计费是否折扣、是否连排队也变短，要看实际产品和记录，不能从「输入文字相同」直接推出。反过来，若少了 100 个输入却多生成 100 个输出，按本例规则总 Token 不变，账单反而多 1 账点。

## 3. 四列看板：不要让一列替代另一列

| 要记的量 | 怎样记录 | 常见误读 |
| --- | --- | --- |
| 总 Token | 按任务累加实际用量，分记输入、输出、命中部分 | 只看最终草稿字数，把中途输出和重复输入漏掉 |
| 计费金额 | 用对应价格核算，再加独立的服务费等；以实际账单为准 | 把缓存折扣当作少了 Token，或认为所有模型、产品都同价 |
| 等待时间 | 记从发起到可验收产物的时间；另记首字等待和需要时的人审耗时 | 看见首字就报完成，或把并行分支的时长直接全相加 |
| 最终通过率 | 对同一批任务按同一标准验收，记通过数和总数；失败与取消也记录 | 用省下的费用、流畅度、或者一份成功样稿代替通过率 |

举个纯算术的等待例子：若两个分支分别假设要等 4 秒和 5 秒，汇总要 3 秒，串行跑这三步是 12 秒；两支同时开始、又不争资源时，则约 8 秒，且还没算分派和人工验收。这只是在演示时间怎样重叠，不是说上面哪条路径实测几秒。评通过率也一样：同样 5 个任务，如果 4 个通过，就记 4/5；不能把超预算取消的一个移出总数，写成 4/4。市集验收至少确认 v2 的周日 14:00、雨天待确认、清单按授权字段可复核、不发送。便宜的流程如果把关键错误放了过去，就不能凭账点低给它判赢。

对比两种做法时，也要先说清各自从哪里起跑。单次路径从「资料已备齐」开始，若路径甲要先请同事找出 v2，路径乙能在授权资料里自行找到，别只拿后半段模型账点判断哪个总体更省。可以分别记人工准备、模型及外部服务用量、从任务发起到交付的总等待，再比通过率。没有记到的一栏写「未记录」，不要补成零。这样才知道省的是服务费，还是把工作转给了别人。

## 4. 优化顺序：先不做无用功，再换昂贵的做法

1. **去掉无用轮次与重复材料。** 已有现行 v2 就不用每轮全库查；先弄清哪一次调用产生了新价值，哪一次只是重复读资料。别连验收一起剪掉。
2. **按需取证、压缩历史、裁剪工具返回。** 保留必要字段、版本、权限、关键原句及出处。工具返回没有证据时标缺口；摘要要能找回原文，错了能修到草稿。
3. **再考虑复用前缀和模型分工。** 共同而稳定的材料有时能复用计算；简单格式整理可以试用较便宜的模型，关键事实还是要对应来源并经同一标准验收。别为了复用而塞回大段无关内容；模型便宜也可能因返工更贵。
4. **设上限并约定停法。** 开工前就约定总花费、时间和重试上限。到了限额，交已验证部分、标缺项并请求人决定，不自动升级花费，更不扩大权限。

## 5. 手工练习：怎样省下一笔，并证明没省坏？

拿纸盖住合计表，自己加长循环四笔账；再假设修好③的失败，不必做④，且③直接产出 400 Token 的合格草稿，其余两行不变。算新账，然后给草稿做同一份验收。**参考**：前两笔为 16 和 22，新③是 15 加 8，即 23，合计 **61 账点**，比 79 少 18；至于是否真的合格，要核对报名清单、现行时间、雨天未决与不发送，而不是用数字来证明。若把雨天写成「确定改室内」，账算对了，任务仍没过。

**速记**：Token 记处理量，价格记账单，钟表记等待，验收记成功。少重复、少空转，不能漏事实、越权限或跳检查。

**自检（含简答）**

1. 并行比长循环的账点低，说明并行总会更省吗？**不会。** 这里只比三套假设；分支也可能重复输入、增加汇总和重试。
2. 从 44 账点降到 40，是否一定少了 Token？**不一定。** 本例是缓存命中折扣，处理用量仍记 3,600 Token。
3. 为省一次查找，可直接把旧 v1 周六写进草稿吗？**不可以。** v1 已失效，必须用现行 v2，证据拿不到就标缺口。
