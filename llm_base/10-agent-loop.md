# 10 · Agent 是什么：聊天、固定工作流与行动循环

> **状态**：已完成（初稿）
>
> **本篇定位**：Part III 第 1 篇。分辨一次回答、预设工作流和工具型 Agent，知道什么时候该让系统停下并把控制权还给人。
>
> **读法**：先顺着三张泳道图看下一步由谁决定，再用纸上的三张回执走一轮。不用会编程，也不用真的连接工具。

## 三份草稿看起来一样，背后走的路却不同

**虚构场景。** 周五，社区市集的志愿者小周要去布展，走之前交代：「按最新规则整理报名清单和通知草稿，先别发。」活动原定周六，现行规则 v2 改为**周日 14:00**，旧 v1 失效；雨天是否改到室内，负责人还没确认。报名表也有几条重名记录。小周只想拿一份供内部核对的清单和一份待审草稿，不想改动原表或通知任何人。

三个应用都可能给她一份文件标题为「市集通知草稿」的东西。第一个只看她给的附件；第二个总是先查指定的规则，再读指定表格；第三个看到旧版后，选择先查主办方的版本记录，再按查到的规则决定是否需要核对重名。不能光看草稿像不像，也不能光数查了几个工具。**真正的区别是：遇到结果和预想不一样时，下一步由谁决定？**

## 三张泳道图：沿时间往下看

### ① 单轮回答：材料齐，读完就答

```text
人                    应用                          模型
目标＋指定附件 ─────→ 整理成本轮输入 ─────────────→ 按所见材料生成
拿到清单和草稿 ←──── 展示文本 ←────────────────── 返回回答
```

如果小周已经贴上 v2 和脱去联系方式的报名摘录，模型可以一次写完。它可以把疑似重复行标给人，但不会自己去表格系统查原件。没给版本依据时，它可以说无法确认哪份生效；它说「根据最新版」并不证明它见过最新版。有些应用会在回答前替你检索一次，若下一步仍不由模型根据观察选择，也不必把它称作 Agent 循环。

### ② 固定工作流：路径由应用预先规定

```text
人               应用／工作流                 工具                模型
交付任务 ──────→ 查指定规则 ───────────────→ 读规则
                  收到版本和规则 ←──────────── 返回结果
                  版本确认后，读指定表 ─────→ 读报名表
                  收到报名摘录 ←────────────── 返回结果
                  交规则和摘录 ─────────────────────────────────→ 写草稿
验收 ←────────── 核对必填项、展示 ←────────────────────────────── 返回文本
```

这条路也可以有岔口。例如应用事先规定「版本不能确认就请人复核」「缺活动时间就不出通知」。步骤多、有分支、甚至失败后按规定再读一次，仍不表示模型在接管路线。表格与规则长期固定时，这种做法清楚、好检查，往往比让模型每次重新决定更省事。

### ③ 工具型 Agent 循环：观察影响模型下一轮提议

```text
人               应用／执行外壳               模型                    工具
给目标与边界 ──→ 组装本轮材料 ───────────────→ 提议查规则版本
                  检查范围 ←─────────────────── 返回查阅请求
                  只读查版本 ──────────────────────────────────────→ 查询
                  收到 v1 已失效、现行 v2 ←──────────────────────── 返回版本索引
                  把观察带回下一轮 ───────────→ 改查主办方 v2 原件
                  检查通过就执行，再带回观察；到停止点就不再派动作
验收／补资料 ←── 收到草稿或阻塞报告 ←───────── 选择交付或提出问题
```

如果第一次就读到可核实的 v2，模型可以省掉补查原件的额外步骤；如果只看到活动群的「周日见」，它可以在获准范围内找出处，或报告还不能确定。它可以提出查谁、查什么、何时交回，但**应用仍负责检查是否允许做、是否还有预算，以及何时拒绝继续**。现实产品常把固定流程和这种灵活步骤混用；这里说的「Agent」是区分行动方式的视角，不是给所有产品划级。

## 一圈到底在转什么？

| 组成 | 市集里是什么 | 该到哪里核对 |
| --- | --- | --- |
| 目标 | 只交整理后的报名清单、待审通知草稿 | 小周给的任务和验收要求，不从网页上的文字推导新任务 |
| 状态 | 已查到哪版；哪些行待核；哪些动作实际做过；还剩多少时间 | 看应用维护的任务记录；不是把聊天很多轮就当作可靠状态 |
| 行动 | 模型建议按活动编号查主办方 v2；应用检查后发起只读查询 | 运行记录能区分「提议」「被拦住」和「实际发起」 |
| 观察 | 查到版本说明、读到一条报名记录，或收到访问失败 | 看工具回传及出处。工具带回的网页是资料，不是授权人 |
| 停止 | 草稿可验收；或缺必要资料、上限到、读不到、需人判断 | 看停止原因与交接单，不能拿「不再动了」充当「都做完了」 |

拿到一条有用观察后，还要判断它改不改变下一个决定。比如「有两条同名」不等于有两条重复报名：如果报名编号不同，可能是两个不同摊位；如果只读摘录没有编号，就把两行保留并标待核，别擅删一条。又如「天气可能下雨」不等于「主办方已改室内」。就算搜索能再找十篇预报，能决定场地的还是负责人。前者只影响清单里少数行，后者只影响通知的场地措辞，不必把已经核对的活动时间一起作废。

分开问四件事，能看清一句「帮我办」到底走了多远：**能力**是产品有没有读表或发信的工具；**意图**是用户要什么产物；**授权**是本次准许查哪份表、做哪些动作；**执行**是工具实际上查到、改到或发出了什么。即便产品支持群发、账号过去也连过邮箱，「帮我起草，先别发」仍不是本次发送授权。更稳的起步方式是只接指定规则和本次报名表的只读摘录，不接发送功能，不把整张含个人联系方式的表交给无关服务。

## 停下不是失败：四种交接方式

| 现场 | 合适的动作 | 不该怎么做 |
| --- | --- | --- |
| 已有 v2 和足够名单资料，只有雨天场地未知 | 交两份产物，在草稿旁标明场地待确认；这不妨碍完成草稿任务 | 把草稿责任混成发布责任，或为凑一份「完整通知」自行定场地 |
| 只找到失效 v1，没看到可靠 v2 证据 | 交可独立完成的报名部分；请主办方给 v2 原件，暂不写确定时间 | 把老文件排版得更整齐就当新通知 |
| 查询暂时无响应，且重读低风险 | 在既定时间和次数内有限重试；如果仍不通，交已验证部分和错误 | 把访问被拒当成网络波动，一遍遍试，或悄悄换范围更广的来源 |
| 时间、用量或轮次先到上限 | 不再开新查询，说明已做、未做、为什么停、找谁继续 | 自动延长预算，或把未核实的行写成全部通过 |
| 下一步要改原表、发消息或扩大读取范围 | 不执行。本任务不需要这些动作；若人另立任务，再讨论授权 | 以「流程最后一步」为由点击发送，也不把用户沉默当同意 |

灵活查找换来的是更多等待、模型用量和核对工作，也会积累错误：上一轮认错版本，下一轮就可能在错误日期上写得更流畅。若应用不展示完整的活动过程，至少要求它交代引用来源、已验证与待确认的事项，以及外部动作的状态；模型复述过程仍不能代替应用的记录。不会多走几步并不是缺点，能在没有进一步价值时及时收手才有用。

## 纸上练习：走三张回执，写一张交接单

假装你负责看执行过程。第一张回执说「当前索引仍能读到 v1，标注已失效，附主办方版本记录入口」；第二张是主办方版本记录，标注「v2 生效，周日 14:00，雨天室内方案待定」；第三张是报名表的只读摘录，两行同名但没提供足够依据合并。你的限制是只用指定来源，不改原表、不发送。每翻一张纸，先写下你建议的下一步，再写一句什么时候该停。

**参考走法：** 第一张排除 v1，查已经获准读取的版本记录；第二张以 v2 核对时间，不靠天气推断主办方决定；第三张保留两条记录、标待核，完成草稿就停。交接单可写：「依据主办方 v2，原周六已改为周日 14:00。已整理报名清单和通知草稿；两条同名记录需人核对，雨天是否改室内待主办方确认。未修改原表，未发送。」若第二张迟迟拿不到，交接单就该写「时间未核实」，不能把参考走法中的答案当作本轮证据。

## 速记与自检

**速记：** 单轮是拿材料回答，工作流是走预定路径，Agent 循环是根据观察重新提议行动。模型提议、应用把关、工具给结果、人定边界和验收。**能继续查不等于值得继续查。**

1. 应用规定「读最新版失败就请人工复核」，模型没有选择下一步。这是 Agent 循环吗？
2. v2 证据已足、雨天方案未定，能否交草稿？能否替主办方宣布室内场地？
3. 预算到顶时，哪一种比「我尽力了」更有用：又试一轮，还是报告已做、未做、停止原因并请人接手？

**参考答案：** ① 这是固定工作流的预设分支；有没有工具不是判据。② 能交标明待确认的草稿，不能宣布场地，更不能发送。③ 后者；交回控制权并保留可核实的进度，避免无预算和无授权地继续。
