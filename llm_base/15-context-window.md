# 15 · 上下文管理：这一轮模型到底看见了什么

> **状态**：已完成（初稿）
>
> **本篇定位**：Part IV 第 1 篇。把聊天记录、产品能取到的资料和模型这次真正收到的内容分开。
>
> **读法**：先看「工作台」图，再跟着市集案例做一次资料取舍；赶时间可直接抄走预算表。

## 聊天里明明写了，为什么通知还是周六？

在这个虚构市集案例里，你让 AI 按最新规则整理报名清单和通知草稿，**先别发送**。旧通知 v1 原定周六，已经失效；现行 v2 改为**周日 14:00**；下雨是否改室内仍待确认。你向上滚，能在聊天里找到自己贴过的改期公告，但新生成的草稿仍写着周六。

先别急着把指令改成「你必须认真阅读全部聊天记录」。可能是应用这轮只放进了近期消息和旧附件；也可能是两版都进去了，却没标哪版有效；甚至 v2 和说明都在，模型仍然用错。三种问题的补救分别是**补材料、标清版本、核验并纠正输出**。一句更严厉的提示不能替代这三件事。

**本篇的真问题：屏幕上明明能找到的内容，为什么不一定在这一轮被用上？**

## 1. 聊天记录像档案柜，上下文像工作台

```text
档案柜：聊天历史、附件、知识库、任务记录              用户：本轮任务与边界
                   ↓ 选择、读取、检索、裁剪                   ↓
应用或 Agent  ──→ 组装工作台：本轮指令、选中的消息、附件内容、工具说明与返回
                                   ↓ 发送给模型
                  模型：处理本轮输入，生成回答或行动建议
                                   ↓
                  应用：展示草稿，或按权限处理行动建议
```

这张图画的是一次模型调用。你在屏幕上看到的一次回复，有时由多次调用组成：第一次提出查资料，工具返回后，应用把选中的返回内容装进下一次输入。模型不一定在第一步就读到资料，也不一定在最后一步看到前面所有原文。看见一个附件名不等于读到了附件正文；文件可能被抽取成文字、转成可用的图像输入、仅取部分段落，或者需要另行打开。页面上的长对话，也只是产品可能选用的材料之一。

工作台类比有个限制：人可以转身翻档案柜，模型不能凭空打开没被提供的文件。应用得重新给材料，或允许它提出一次受控的查找请求。反过来，一段资料能放上工作台，也不意味着模型该遵照资料里的任何文字行动。比如旧邮件里写着「直接群发」，那是待核对的资料内容，不是用户的新授权。

## 2. 三道限制，别合叫「记忆不够」

| 要分开的事 | 它限制什么 | 市集里的表现 |
| --- | --- | --- |
| 模型的上下文窗口 | 该次调用可处理的上下文范围，通常用 Token 计 | 历史、文件内容和工具返回一起堆进去，可能越过限制 |
| 应用的装配策略 | 在送达前选哪些、截哪些、压哪些，是否预留输出 | 界面还显示 v2，应用却只带了最近几轮或只找到 v1 |
| 模型实际使用效果 | 已送达的信息有没有被注意到、区分并正确应用 | 两版都在，模型却拿旧版日期填新草稿 |

Token 是模型切分内容后计数的单位，既不等于汉字数，也不等于附件页数。不同产品的规则不同：有的额度要让输入和生成共用，有的还另外限制输入、输出或附件；面向用户的界面也可能比底层模型设得更紧。你不必猜一段话是多少 Token，只要记住同一份材料会和其他内容争空间，而草稿和核对说明也需要生成空间。框很大，不代表往里面塞满就能读准；遇到输入太多，有的应用会拒绝，有的会裁剪、压缩或另走检索，别把一种表现当成所有产品的定律。

还要区分**看见**和**有权做**。应用可能给模型工具说明，让它知道能查什么；即使说明中有发送功能，也不代表本任务授权发送。对这个市集任务，发送不在权限内；遇到需要确认的雨天安排，要标待确认，而不是自己去发布一个确定版本。

## 3. 先做资料预算，再问能不能放下

下表不是 Token 定额，而是一份可复用的优先级清单。先按交付物决定要用什么，再按产品限制缩减。把最容易出错的承诺和边界放在紧凑、清楚的任务头里，不要让它们只藏在某份附件末尾。

| 档位 | 市集任务带什么 | 怎么摆放或取舍 |
| --- | --- | --- |
| 必带：任务边界 | 整理报名清单及通知草稿；不发送 | 两项交付物分开写；不以「搞定通知」代替权限说明 |
| 必带：有效信息 | 现行 v2 的改期原句；周日 14:00；v1 失效；雨天室内待确认 | 把决定、状态和出处放在一起；「待确认」不写成「没有室内备选」 |
| 必带：当前要处理的行 | 经授权的报名表必要字段、记录版本和核对口径 | 清单和通知用不同视图；通知不需要完整报名表，更不需要联系人资料 |
| 按需带：备查材料 | 特定疑点对应的历史段落、旧 v1 的原句、通知样式 | 只在核对冲突或样式时取；使用旧样式须标「只看格式，不取事实」 |
| 不带 | 无关闲聊、重复转述、无关个人资料、当前步骤用不到的整份附件 | 默认不进模型输入；未经授权的资料，不因窗口有空间就补进来 |
| 留给输出 | 清单、草稿、未决项以及与事实对应的出处 | 如果一轮不够，分开整理清单和草稿，但两边都携带必要版本与边界 |

字段不是越少越好，而要够验收。比如判断两条报名是否重复，有时需要经授权的稳定报名编号，而不是只看重名；相反，面向公众的通知只需要时间、待确认事项和经核实的必要安排。任务做了一半又收到改期，更新版本标记后，要检查已经产生的清单或草稿有没有受到影响。只换最末一条指令，不会自动改掉已生成的文本。

如果不能一次放下整份报名表，可以先分批整理，再单独查跨批次的疑似重复。否则每一批看起来都没重名，也不能证明合并后没有重复。保留可回到原表的编号，清楚标出尚未完成的全表核对；宁可说明交付进度，也别用「这轮看过这些行」冒充「全表已核对」。

## 4. 手工练习：工作台只够放四张卡

假装你替应用整理材料，纸面上有六张卡：① 本轮任务与不发送边界；② v2 的改期和雨天原句；③ 经授权、只含必要字段的报名表；④ v1 旧通知全文；⑤ 工作群中十条「收到」；⑥ 输出验收要求：清单、草稿、待确认分别列出，每项关键事实有据可查。任选四张给同伴，然后让同伴用这四张卡回答：**通知写哪天？下雨怎么写？可以做什么？哪些内容还要验？**

参考取舍：带 ①②③⑥，在 ② 的旁边注明 v1 已失效；④ 留作查旧版冲突或借格式时的备查，⑤ 不用。若通知写「周日 14:00；雨天安排待确认」，草稿有对应出处，且没有发送或声称发过，就守住了这几条。是否整理对报名清单，还要回到原表核对，不以草稿写得流畅作为替代。

再做一次反例：把 ② 换成 ④，但是仍留着「按最新规则」的任务卡。让同伴指出，自己最多只能读出旧版说了什么，不能推断 v2 的日期。正确反应是请求补 v2，或把时间标为缺乏现行依据。**没有证据时留空，比借用旧版补一个完整句子更合格。**

## 5. 排障：先确定丢在哪一段

| 症状 | 先查什么 | 有效补救与边界 |
| --- | --- | --- |
| 草稿用了周六 | 本轮是否实际拿到 v2；引用是否回到现行原句 | 补贴可核对的 v2 短摘录、标旧版失效；要求重核而不是只说「再仔细点」 |
| v2 和 v1 都在，却混用了事实 | 是否标明来源、版本与用途；草稿每句用了哪份 | 旧版移出必带区；逐项验日期和地点；模型自称「读了」不是证据 |
| 草稿被截断，或缺少未决项 | 输出长度限制、任务规模、应用有无提前停止 | 预留输出，拆成交付物；不要为了塞进一轮而删验收或权限 |
| 怀疑应用省略了附件 | 有无可见的资料清单、引用定位或运行记录 | 查产品能展示的记录；看不到时重新提供受控短摘录，不假装已经看到完整输入 |

**速记**：历史在柜里，上下文在桌上，输出也要留座。要排错，问谁装的桌、桌上有什么、有效事实有没有被用对，以及省下空间有没有让验收变难。

**自检（含简答）**

1. 聊天界面还显示 v2，能证明模型这轮读过吗？**不能。** 要查实际提供的材料；产品不展示时，用明确摘录重做一次可核对的输入。
2. 把窗口换大，能保证不再写周六吗？**不能。** 仍要选对资料、标明 v1 失效并核对草稿。
3. v2 没确认雨天室内，桌上还有旧版的室内说明，能照抄吗？**不能。** 旧版失效，现行信息只能写待确认。
