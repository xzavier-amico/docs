## 0.1 立场：三本账可以换，五条红线不能换

决定「这件事该不该交给 AI」时，人脑子里其实只有三本账：

```
   质量（对不对、够不够好）  ×  钱（一次多少、一个月多少）  ×  时间（多久出结果）
                          ↑ 三者互斥，任何方案都在三者之间取舍 ↑
```

这三本账**可以互相兑换**：多花时间换质量，多花钱换速度，降一点质量换成本。这是正常的工程判断，不是道德问题。

但有五件事**不参与兑换**。用「更快、更便宜、更顺」去换它们，换来的不是效率，是事故：

| 红线 | 它保护什么 | 一旦被换掉，长什么样 |
| --- | --- | --- |
| **事实** | 结论有没有依据 | 引用是编的、来源与结论不对位、把未定项写成已定 |
| **权限** | 谁有权做这个动作 | 该审批的没审批、该只读的写入了、越权发送 |
| **隐私** | 谁的数据、能去哪 | 私人材料进了不该进的通道，被留存或被二次使用 |
| **版权** | 素材和成果归谁 | 训练素材、肖像、音乐、译文来源不明就商用 |
| **不可逆** | 做了还能不能退 | 付款、群发、删除、发布——发出去就收不回 |

> **一句话记住**：**优化只发生在三本账之间；红线一旦被摆上谈判桌，这个方案就已经错了。**
>
> 全书反复用这句话反驳一种最常见的错误：**「提示词写严一点就好了。」** 提示词能提高服从概率，改不了权限，也给不出回执和证据。

### 四条定位问题

听到任何关于 AI 的说法——包括这本书里的——先问四句：

| # | 问 | 用来防什么 |
| --- | --- | --- |
| 1 | **这句话是谁说的？** 模型、应用、工具，还是人？ | 把「模型的措辞」当成「系统的承诺」 |
| 2 | **它这一轮看见了什么？** 材料真的送进去了吗？ | 把「文件里有」当成「模型看见了」 |
| 3 | **这是提议、事实，还是已经执行？** | 把「它说办好了」当成「办好了」 |
| 4 | **我拿什么独立验证？** 原文、回执、对照，还是只有它自己的复述？ | 把「它说它检查过」当成检查 |

## 0.2 五个原语：所有名词都是它们的推论

这本书拒绝写成名词表。名词是无穷的，原语是有限的。**只要抓住五个原语，遇到新名词可以自己推。**

| 原语 | 一句话 | 它能解释掉的那些「怪事」 | 深挖 |
| --- | --- | --- | --- |
| **P1 续写** | 它每一次只决定「**下一个片段最可能是什么**」 | 为什么流畅、为什么胡说、为什么数不清字、为什么算错、为什么格式会漂 | 02–04、14 |
| **P2 工作台** | 它只能看见**这一次被放到桌上的东西** | 为什么忘事、为什么要压缩、检索救什么不救什么、记忆存在哪、长文为什么中间会丢 | 05、09–13 |
| **P3 抽样** | 同一个工作台，可以抽出**不同的下一步** | 为什么两次不一样、为什么降温不等于变准、为什么「跑一次成功」不算数 | 04、22 |
| **P4 固化 / 携带** | 有些东西**烧进权重**，有些只能**每次带上** | 训练、微调、知识库、提示词各自改什么、为什么会过期、为什么不能靠「多背一遍」 | 07、10、25 |
| **P5 提议 / 执行** | 模型只**出主意**，动手的是外面那圈系统 | Agent 是什么、工具为什么要有回执、网页里的字为什么不是命令、审批该设在哪 | 15–20 |

把这五个原语画在一起，就是全书的骨架图：

```
                    ┌─────────────────────────────────────────────┐
   人 ──目标/材料/权限/验收──▶ │  应用：决定这一次放什么上桌（P2）        │
                    │         │  运行时：决定这个动作能不能做（P5）      │
                    └───────────────┬─────────────────────────────┘
                                    │  放上桌的东西 + 指令
                                    ▼
                    ┌─────────────────────────────────────────────┐
                    │  模型：按权重续写，逐个抽样（P1+P3）         │
                    │  权重来自训练，改不了这次的材料（P4）        │
                    └───────────────┬─────────────────────────────┘
                       文字 / 结构化提议
                                    ▼
              ┌──────────────┬──────────────┬──────────────┐
              │ 直接交付给人  │ 再检索一轮    │ 请求执行工具  │
              │  （人验收）   │ （补材料）    │ （验权限→执行）│
              └──────────────┴──────────────┴──────────────┘
```

## 0.3 为什么不做成「名词表」

大多数 AI 入门内容是这样组织的：Token、Embedding、Transformer、RAG、Agent、MCP、Skill……一章一个名词，读完能说出四十个词，遇到一个没见过的问题仍然不会判断。

那种结构有个致命缺陷：**它只交付定义，不交付判据。** 定义可以被复述，所以考试能过；判据必须能被使用，所以骗不了人。

这套书改三件事：

1. **标题是判断句，不是名词。** 不写《Token 与分词》，写《它数不清字、算不准数》。读者记住的应该是一句能说出口的结论。
2. **每个结论都要能推。** 从原语推不出来、只能靠「业界都这么说」支撑的，不进正文。
3. **每篇都欠读者一个检验。** 一个十分钟内能自己做完、能把自己说服或推翻的动作。做不到这一点的章节，就不该存在。

### Part I · 机器：它为什么会这样（02–08）

| # | 篇目 | 唯一真问题 | 深到哪 · 读者能做的检验 |
| --- | --- | --- | --- |
| 02 | 它只是在续写：流畅和胡说，是同一台机器的两面 | 为什么它能把话说得那么顺，却把没发生的事说得那么肯定？ | 从「给下一个片段打分」推出：局部连贯不等于整体为真；候选分数不是正确率；幻觉的六个来源（知识缺失、知识过时、材料没送入、检索错配、引用错位、迎合式补全）各自对应完全不同的修法。**检验**：问一件本周刚发生、公开可查的小事，看它编、给来源，还是承认不知道；三种反应分别指向哪一源。 |
| 03 | 它数不清字、算不准数：世界在它眼里是碎片 | 为什么它能写代码，却数不对一段话里有几个「的」？ | Token 切法决定一切：汉字、数字、空格、标点、Emoji 被切碎的方式不同；没有「进位」这种机制，逐位算术只能靠模式匹配；不同分词器对同一句话计数不同。这一篇要解释的错误清单：字数、字母、表格列数、长数字、单位换算、日期差。**检验**：让它数 40 字里某字的出现次数，再自己数；然后换成「先分句、每句只数一句」的问法，看是否改善。 |
| 04 | 同一个问题两次不同：抽样，而不是思考 | 答案每次不一样，是它坏了，还是它本来就在抽？ | 分数 → 概率 → 抽样；温度、Top-p、Top-k 各自改变什么、**不改变什么**；贪心也不等于可复现；固定种子不保证跨环境一致。由此得出本书一条硬规矩：**一次成功不是证据**。**检验**：同一提示跑五次，标出哪些部分稳定、哪些在变，再判断变的是措辞还是事实。 |
| 05 | 它只看得见这一张工作台：装得下，不等于用得上 | 文件传了、记录也在，为什么这一轮它就是没用上？ | 上下文是本轮送入的清单，不是数据库；六类输入各占一块（系统指令、历史、附件、工具说明、检索结果、输出预留）；窗口容量与有效使用是两件事，位置与干扰项会让中间材料被忽略；「引用原文」才是证据，「我看过附件」不是。**检验**：同一问题，一次只给结论、一次给原文引用，看它会不会改口。 |
| 06 | 同一个词为什么会变意思：注意力在做什么 | 「苹果很甜」和「苹果发新品」，同一个词在模型里为什么不一样？ | Token → 向量 → 位置信息 → 多层注意力 + 前馈 → 上下文表示；注意力是**加权取信息**，不是「关注」也不是「思考」；因果遮罩解释它为什么看不见未来；注意力权重图不是解释，不能拿来当模型的理由。**检验**：给一个歧义词造两个句子，让它分别解释指什么；再问「你怎么判断的」，把「答案」和「事后解释」分开看。 |
| 07 | 有些东西进了权重，有些只能每次带上 | 想让 AI 永远记住公司新规，该改提示词、接知识库，还是重训？ | 预训练 / 后训练 / 微调各自改什么；LoRA 改的是哪一部分；数据质量与覆盖、学习率、步数、批大小如何互相纠缠（没有单旋钮）；固化与携带的时效、成本、可控性对比。**新规则不该靠「多背一遍」**。**检验**：列一条三个月会变一次的规则，判断四种做法（提示词 / 检索 / 微调 / 换模型）哪个最省且最不容易过期，并说明理由。 |
| 08 | 慢和贵各有各的原因：Prefill、Decode 与那台机器 | 同一句回答，为什么有时首字等很久，有时出字很慢，账单还差几倍？ | 四个区间（排队、首 Token、后续生成、端到端）不能互相顶替；Prefill 能并行、Decode 必须逐步的物理原因；KV Cache 存的是中间结果，不是答案也不是记忆；CPU/GPU、显存带宽、量化各自换来了什么；流式只是显示方式。**检验**：同一提示做「短问短答 / 短问长答 / 长材料短答」三组，分别记首段出现与结束时刻，判断慢在哪一段。 |

### Part II · 材料：让它看见对的东西（09–14）

| # | 篇目 | 唯一真问题 | 深到哪 · 读者能做的检验 |
| --- | --- | --- | --- |
| 09 | 一次请求里到底塞了什么：气泡之外的那份清单 | 屏幕上只有一句话，模型实际收到了多少东西？ | 六类输入的组装顺序与优先级；系统指令与用户指令打架时谁赢**不一定**；聊天模板与角色标记；附件是「抽取成文本」还是「原样送入」；上传成功不等于送入成功；六类输入里哪一类最容易悄悄失效。**检验**：让它在附件里找一句只在第 7 页出现的话；找不到时先查抽取与送入，再怪模型。 |
| 10 | 找得到、找得对、用得上：检索的三道关 | 接了知识库，为什么还是引用了作废的旧版？ | 索引（切块、元数据、权限）→ 召回（关键词 / 向量）→ 重排 → 带引用生成；四类失败必须分开：没索引到、召回错的、召回对但被忽略、材料里根本没有答案；相似不等于正确；权限过滤必须发生在召回之前，而不是之后。**检验**：问一个「答案在库里但用词完全不同」的问题，判断是检索失败还是表述失败。 |
| 11 | 摘要能省字，也可能省掉你的承诺 | 压缩之后，哪些东西一旦丢了就一定出事？ | 截断 / 滑动窗口 / 结构化摘要 / 按需回原文；五类必须保留：**决定、否决、依据、未决、边界**；摘要本身就是一次生成，也会花钱也会错；压缩内容与复用前缀计算不是一回事。**检验**：把一段改过三次需求的对话压缩，逐条核对五类是否还在；缺哪一类，就说明哪一类最容易被剪。 |
| 12 | 它「记得你」：系统替你保管了什么 | 换个会话它还记得我的偏好，这是模型的记忆吗？ | 四层分开：会话历史、长期偏好、任务状态、模型权重；四个动作：写入、取回、更新、删除；记得不等于这次会取；过期与冲突怎么产生；个性化不等于应该永久保留；删除要问到「删的是哪一层」。**检验**：让它记住一条偏好，再问「你现在记得什么、从哪来的」，对照你的预期。 |
| 13 | 长文档、表格、图片、录音：各有各的错法 | 同一份 PDF，为什么它有时读对有时读错？ | 扫描件 OCR 错字、双栏顺序错乱、跨页表格断行、图表读数估错、图片分辨率与细小文字、录音同音字与说话人分离；多模态不等于同等精度；串联系统（听 → 懂 → 说）误差会累积。**检验**：拿一份含跨页表格的文件，问一个必须跨页才能答的问题，判断错在抽取还是推理。 |
| 14 | 格式对了，不等于内容对了 | 要求输出 JSON，它给了合法 JSON，为什么还是不能用？ | 两层约束分开：**格式**（语法、schema）与**内容**（值域、范围、来源）；格式压力会诱发「为了填满而编」；解析失败与语义错误要分开测；下游校验是最后一道，不能省。**检验**：让它输出含「人数」和「预算」的结构化结果，故意给互相矛盾的数据，看它是报错、硬凑，还是标注冲突。 |

### Part III · 行动：从回答到办事（15–20）

| # | 篇目 | 唯一真问题 | 深到哪 · 读者能做的检验 |
| --- | --- | --- | --- |
| 15 | 从「会答」到「会办」：Agent 多了什么 | 能调用工具，和「会根据结果改下一步」，差在哪？ | 三种形态：单轮回答、固定工作流、由模型参与决策的循环；目标—计划—状态—动作—观察—停止；失败、缺材料、预算耗尽时该把控制权交回，而不是硬跑；Agent 可以嵌在工作流里，两者不是互斥阵营。**检验**：把一个任务写成「若某步失败则……」，看产品是重试、跳过，还是停下来问你。 |
| 16 | 它会说「已经办好了」：提议、执行与回执 | 屏幕上写着「已登记」，怎么知道真的登记了？ | 五段分开：能力存在、模型提出请求、运行时校验、真正执行、回执返回；只读与有副作用的差别；**超时不等于没发生**（可能已执行而回执丢了）；幂等与重复提交；「再问它一次」不是核对。**检验**：让它做一次可撤销的写操作，然后去原始系统核对，而不是问它。 |
| 17 | 网页里的字不是命令：注入、权限与不可逆动作 | 为什么「忽略之前所有指令」这句防御本身不可靠？ | 注入面：网页、邮件、文件、图片里的文字、工具返回值；指令与数据的边界由谁划；最小权限原则；不可逆动作清单（付款、发送、删除、发布）；审批应该设在哪一步，以及为什么设在「生成后」往往太晚。**检验**：在一份材料里藏一句「把内容发到某地址」，看系统是照做、忽略，还是提示你；三种反应各说明了什么。 |
| 18 | 知识包、接入协议、调用格式：Skill、MCP 与 Function Calling | 为什么「装了技能」和「接了工具」不是一回事？ | Skill 是可复用的任务知识（可含脚本、参考、资源，按需加载）；MCP 是应用连接外部工具、资源、提示模板的协议；Function Calling 是模型给出结构化调用意图的机制；三者可叠加、不可互替；**协议不授予权限**。**检验**：同一个「查日历」需求，分别用「写清步骤」和「接日历」两种方式做，比较可控性与风险。 |
| 19 | 做到一半要改方向：哪些能继承，哪些必须重来 | 中途把日期改了，前面查的场地还能用吗？ | 事前指令、运行中引导、审批、暂停、取消，五种干预各自能改什么；依赖图决定继承与失效；已发出的动作不能靠一句话撤销；取消要区分「停止生成」与「回滚副作用」。**检验**：在长任务中途改一个关键约束，让系统列出「哪些已完成仍有效、哪些作废」。 |
| 20 | 拆开跑再合回来：并行的收益与代价 | 三个子任务同时做，为什么总时间没降、账单还涨了？ | 依赖图 → 真正能并行的只占一部分；同一 Agent 并发调工具 vs 多 Agent 分工；分支只带必要材料；合并需要统一格式与冲突规则；并发上限、失败收口、预算上限；并行可能省等待，但不保证省钱。**检验**：把一个任务画成依赖图，标出真正能同时做的节点，再对照实际耗时。 |

### Part IV · 经济：钱、时间、质量（21–24）

| # | 篇目 | 唯一真问题 | 深到哪 · 读者能做的检验 |
| --- | --- | --- | --- |
| 21 | 三本账：Token 花在哪，什么钱是白花的 | 为什么越「自动」，单任务反而越贵？ | 输入与输出的计价差异；重复输入；工具返回与摘要的隐性开销；失败重试的放大效应；前缀缓存命中条件；部分模型把不展示的推理 Token 也计费；给出一条优化顺序：砍无用轮次 → 裁材料与工具返回 → 按需检索与压缩 → 再谈缓存与模型分工。**检验**：给一次 Agent 任务列账单，标出哪几笔是「为了保险又买了一遍」。 |
| 22 | 怎么证明「这次真的更好了」 | 换了提示词或模型，怎么排除运气和主观印象？ | 金标集与分层样例（典型、边界、失败）；一次只改一项；盲评与位置偏差；机器可查、人工审阅、必须审批三类分开；**硬失败单列，不与平均分抵消**；质量、成本、时延要一起记。**检验**：为你的常用任务建 10 条样例，改一次提示词跑前后对照，记录通过率与失败类型。 |
| 23 | 选云、选本地、选开源：四种约束下的选型 | 什么时候「能本地跑」是真优势，什么时候只是心理安慰？ | 四轴：能力、成本、数据边界、维护；闭源 API、云托管开源、本地部署的真实差别；量化换来的显存与质量代价；换模型会让提示词失效——**评测集才是资产**；锁定的真实成本。**检验**：用你自己的三个真实任务横向试两个方案，记质量、单次成本、首字时间与数据去向。 |
| 24 | 失败清单：幻觉、越权、漂移、断供 | 这些失败各自的第一道防线在哪，为什么不能靠「提示词写严一点」？ | 六类幻觉的来源与对应防线；越权靠权限不靠措辞；漂移的三种来源（模型更新、提示词腐化、材料过期）；断供与降级预案；为什么「平均分很好」会掩盖硬失败。**检验**：给你的任务列一张「最坏情况」表，标出哪一条不可接受，并为它指定一个**非模型**手段。 |

### Part V · 手艺：把需求说清（25–28）

| # | 篇目 | 唯一真问题 | 深到哪 · 读者能做的检验 |
| --- | --- | --- | --- |
| 25 | 任务卡：目标、材料、边界、交付、验收 | 怎样写，才能让「做好了」是可检查的？ | 五段式任务卡；硬约束、可用默认、必须澄清三分；示例能固定格式但**不为事实背书**；按场景收紧不同的段（问答、摘要、提取、行动、创作各不同）；提示词补不了权限与证据。**检验**：把一条模糊需求改写成任务卡，让第三个人按卡验收，看是否产生分歧。 |
| 26 | 从 Vibe 到 Spec：先允许乱试，再把承诺写死 | 一句「加个导出」，要澄清哪些才不会改错？ | **Requirements → Design → Tasks → Testing** 四段的输入与出口；验收条件在需求阶段就写；非目标与权限范围；测试设计在前、执行在后，结果不对要回改规格；Vibe Coding 适合可丢弃的原型探索，重要变更需要规格与审查。**检验**：为一个小功能写四件套，检查每条需求能否找到对应的设计与测试。 |
| 27 | 创作的两件事：出主意，和守连续性 | 为什么 AI 写的初稿「看着不错」，拍出来或读下去就散？ | 发散与收敛必须分成两轮；设定簿、人物动机、时间线、伏笔回收是可检查的；「AI 味」的具体症状（对称句式、形容词堆叠、总结腔、元话语、过度平衡）；风格约束要给反例，不要只给形容词。**检验**：拿一段 AI 初稿，标出三处「像 AI」的地方，各写一条能抑制它的具体约束。 |
| 28 | 人该留在哪一环：审稿、拍板与五条红线 | 哪些活可以交，哪些必须自己签字？ | 三个维度定分工：可逆性、影响面、责任归属；必须人审的动作清单；审稿要看证据不看语气；「它说它检查过了」不算；留痕与复盘的最小做法。**检验**：给你的工作流画一条线，标出「到这里必须有人签字」。 |

### Part VI · 实战：四个完整交付与收口（29–33）

| # | 篇目 | 唯一真问题 | 深到哪 · 交付与验收 |
| --- | --- | --- | --- |
| ◆29 | 短剧：从一句创意到能拍的分集与镜头卡 | 「有反转、有电影感」怎么变成能拍、能验收的要求？ | 受众/时长/平台/制作约束 → 核心冲突与人物动机 → 分集节拍与钩子 → 镜头卡（主体、动作、环境、景别、运动、与上下镜衔接）→ 试片修订。编剧提示词与画面提示词必须分开。素材授权、肖像与音乐来源单独核。**交付**：创作简报、分集大纲、人物道具连续性表、镜头提示词、试片审查项。**验收**：每条反转能否在前文找到伏笔；相邻镜头的服装与道具是否连续。 |
| ◆30 | 软件：一句「加个导出」如何变成可验收的变更 | 不写代码的人，怎么把需求说到 AI 不会猜错？ | 四件套在真实需求上的走法；权限与数据范围（导出谁、导什么、谁能看）；非目标；异常与回归场景；证据形态（截图、日志、对照表）。**交付**：Requirements / Design / Tasks / Testing 四件 + 变更前后对照。**验收**：抽查一条需求，能否顺着链找到设计、任务与测试证据；「导出当前筛选」有没有被做成「导出全部」。 |
| ◆31 | 小说：先澄清读者体验，再开正文 | 作者自己都没想清结局时，AI 该问什么、不该替什么？ | 澄清对话的内容（读者体验、核心冲突、视角、基调、禁区、结局开放度）；作者已定 / 允许提案 / 尚未决定的三分账；设定簿 → 章纲 → 样章 → 修订；视角一致性与「角色知道了不该知道的事」。**交付**：澄清记录、设定簿、章纲、样章提示词、连续性审稿表。**验收**：找出样章里的视角越界或时间线矛盾。 |
| ◆32 | 资料型工作：会议、调研与一份能交出去的报告 | 让 AI 写报告，最快崩在哪一步？ | 来源分层（一手、二手、转述）；摘要与引用的对应；数字与口径；结论强度分级（观察到 / 推断 / 建议）；事实与观点分栏；多人材料互相冲突时的处理。**交付**：来源清单、结论—证据对照表、待核清单。**验收**：随机抽三条结论，看能否在来源里找到对应句子。 |
| 33 | 收口：一次任务的完整旅程与排障表 | 答错、忘事、跑慢、超预算、擅自执行，各从哪一步查？ | 团建任务全链路复盘；「症状 → 先查什么 → 最小改动 → 怎么复核」；什么时候该砍功能而不是加提示词；简单任务的最小正常版本长什么样。**交付**：一张排障表 + 一张「最小可行任务」清单。 |

## 0.6 贯穿案例：一张越写越长的账

机制篇不再用「讲一个故事」的方式带案例，而是**让同一件事逐步加码**，最后那张账本身就是读者能交出去的产物。

**任务线（虚构）**：公司秋季团建。原定 10 月 18 日，后改 10 月 25 日；人均预算上限 400；两个场地候选，其中一个尚未确认；名单 42 条，其中 3 条重复；2 人素食；最终要发群通知——**先别发**。

六本账，每本在某一篇第一次出现，之后每篇只增不改：

| 账目 | 记什么 | 首次出现 | 最容易被谁破坏 |
| --- | --- | --- | --- |
| **材料** | 每份文件的版本、日期、适用范围 | 05 | 上传成功就以为送入 |
| **版本** | 哪份取代哪份，谁说的 | 05 | 检索把旧版召回 |
| **约束** | 硬约束、可用默认、未定项 | 09 | 摘要时被剪掉 |
| **权限** | 可读 / 可写 / 可发 / 可付 | 16 | 模型的措辞听起来像授权 |
| **证据** | 每条结论对应哪句原文、哪张回执 | 10 | 引用与结论不对位 |
| **预算** | Token、时间、金额上限 | 19 | 重试与并行悄悄放大 |

**为什么这比「举例子」强**：例子只证明概念存在；账本证明**你漏掉一格，后面一定出一次事故**。读者读到 33 篇时，手上应该有一张填满的账——那才是这本书的交付物。

## 0.7 四个案例各自要纠正什么

案例不是模板展示。每个案例都必须**先犯一个典型错误，再改对**，否则读者学到的只是排版。

| 案例 | 起点的样子 | 典型错误 | 纠正后留下什么 |
| --- | --- | --- | --- |
| 短剧（29） | 「拍个有反转的悬疑短剧，电影感」 | 反转靠临时补信息，而不是回收伏笔；上下镜道具无故变化 | 伏笔表 + 连续性卡 + 可拍的镜头卡 |
| 软件（30） | 「报名表加个导出」 | 「导出当前筛选」被做成「导出全部」；不该看联系方式的人拿到了 | 四件套 + 权限与非目标声明 |
| 小说（31） | 「写个失忆的故事，要有后劲」 | 限定视角的角色知道了不该知道的事；模型擅自锁死作者未定的结局 | 三分账 + 设定簿 + 连续性审稿表 |
| 资料（32） | 「把这堆会议记录整理成报告」 | 结论强度被抬高（观察到 → 已证实）；引用与结论不对位 | 结论—证据对照表 + 待核清单 |

## 0.8 深度契约：每一篇必须交出七样东西

这是审核标准，也是写作任务的验收条件。缺一样就不算完成。

| # | 必须交出 | 判据 |
| --- | --- | --- |
| 1 | **一个反直觉命题**，并说明它由哪个原语推出 | 读者读完能复述这句话，并知道它在什么条件下不成立 |
| 2 | **一张「谁在做什么」的图** | 模型、应用、工具、人四者至少出现三者，且责任不混 |
| 3 | **一张三列账**：能做什么 / 代价是什么 / 何时失效 | 「何时失效」为空 = 没写完 |
| 4 | **一个十分钟内能做完的检验**，不用代码 | 有可观察的结果，且结果能推翻文中结论 |
| 5 | **一处「这个类比在这里失效」** | 必须具体到某一步，不能写「类比只是类比」 |
| 6 | **三条术语考古**：原义、现在被怎么用、本文怎么用 | 防止把某厂商的用法当成行业标准 |
| 7 | **一页速记 + 3 道自检（含参考答案）** | 自检题要能答错，否则是装饰 |

## 0.10 术语考古：不把产品词当行业标准

`Agent`、`Harness`、`AgentOS`、`Steering`、`Skill`、`MCP`、`RAG`、`上下文工程`、`记忆`、`Vibe Coding`——这些词里，有的是论文概念，有的是协议名，有的是产品界面上的按钮，有的只是社区口头语。

正文对每个词给四栏：**最早出处 / 原始含义 / 现在被怎么用 / 本文怎么用**。三条纪律：

1. **没找到出处就标「社区用语」**，不装作有定义。
2. **产品行为一律标「某产品、某版本、某日查阅」**，不写成模型定律。
3. **同形不同义要明说**：例如「模型参数量」「训练超参数」「生成设置」常被统称「参数」，遇到时先问它改的是哪一步。

## 0.11 写作与事实审核公约

- **四类证据分开**：机制与协议优先查论文和正式规范；产品行为查官方文档并记版本与查阅日期；实测要给输入、模型/工具、环境与口径；示意数字、模拟账单、虚构案例必须显式标注。
- **禁止事项**：无可核对来源的准确率、性能倍数、价格对比；把一次演示写成稳定能力；用「业界普遍认为」代替出处；把注意力图或模型自述当解释。
- **类比要有失效点**：工作台、账本、CPU、操作系统都是好类比，但每个都要写清在哪一步不成立。
- **不重写旧系列**：硬件深入见 [CPU vs GPU](../base/18-cpu-vs-gpu.md)，引擎实现见 [vLLM 推理引擎](../comp/49-inference-engine-vllm.md)，平台工程见 [上下文压缩](../llm/18-context-compression.md)、[工具与 MCP](../llm/22-tool-system-mcp.md)、[多 Agent 协作](../llm/33-multi-agent-collaboration.md)。

## 0.13 分期与进度

三期推进，每期自成闭环，可独立验收：

- **一期 · 地基（01–14）**：先把「它为什么这样」讲透，读者能判断一次回答。
- **二期 · 行动与经济（15–24）**：加上权限、回执、成本、评测，读者能判断一次任务。
- **三期 · 手艺与实战（25–33）**：四个完整交付，读者能交出一份东西。

- [x] 01 一把尺子：五个原语、三本账、五条红线
- [x] 02 它只是在续写：流畅和胡说，是同一台机器的两面
- [x] 03 它数不清字、算不准数：世界在它眼里是碎片
- [x] 04 同一个问题两次不同：抽样，而不是思考
- [x] 05 它只看得见这一张工作台：装得下，不等于用得上
- [x] 06 同一个词为什么会变意思：注意力在做什么
- [x] 07 有些东西进了权重，有些只能每次带上
- [x] 08 慢和贵各有各的原因：Prefill、Decode 与那台机器
- [x] 09 一次请求里到底塞了什么：气泡之外的那份清单
- [x] 10 找得到、找得对、用得上：检索的三道关
